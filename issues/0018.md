## Description

Turn the green PCB badge (`Logo 2026.png`) into the asset set the site needs. The raster derivatives — transparent, per-theme tinted, plus a favicon-safe chip mark — are already produced in `assets/logo/`; what remains is the vector trace and wiring the assets into the SPA.

## Long Description

The black ground has been removed by luminance keying (alpha from `max(R,G,B)`, black point 6, white point 212), so edges keep their anti-aliasing and there is no fringe on light backgrounds. Two tints exist because the brand green `#68FF23` measures 14.8:1 on the dark ground but only **1.32:1 on white** — transparency alone does not make the logo theme-adaptive. Light contexts use `#30800C` (same hue and saturation, value reduced to clear 4.5:1 on white).

The full logo is illegible below roughly 96 px, so the central chip with the `>_` prompt is extracted as a separate mark that reads cleanly from 32 px.

Full derivation notes are in [`assets/logo/README.md`](../assets/logo/README.md).

## Acceptance criteria

- [x] Black ground removed by luminance key; no black fringe when composited on white

- [x] `logo-mask.png` — white alpha mask for `currentColor` tinting
- [x] `mark-*.png` — chip-only mark at 512/256/180/64/48/32/16 in both tints and as a mask
- [x] `apple-touch-icon.png` at 180×180, **opaque** dark ground
- [x] Derivation, contrast measurements, and CSS usage documented in `assets/logo/README.md`
- [ ] **`logo.svg` and `mark.svg`** — vector trace of the mark, `currentColor`-driven
- [ ] **`favicon.svg`** from the traced mark, with `favicon-32.png` as the raster fallback
- [ ] `site.webmanifest` with name, `theme_color`, and icon entries
- [ ] Assets copied from `assets/logo/` into `web/public/` and referenced from `index.html`
- [ ] Note the `file://` mask restriction in `docs/frontend.md` — masks silently render empty when a page is opened as a local file, which is confusing to diagnose
- [ ] Logo rendered in the site header via the mask technique, with `role="img"` and an `aria-label`
- [ ] Favicon verified in a browser tab at actual size, and the touch icon on an iOS home screen

## Notes

PRD §4.5. The blue hexagonal badge is **retired** — this mark replaces it and the green-UI / blue-mark conflict that PRD §14 Q4 tracked is resolved.

`assets/logo/` is the source-of-truth asset folder; `web/public/` holds what the site actually serves. Keep the distinction — the masters are 1254 px and should not be served.

The `-webkit-mask` prefix is still required for Safari. A masked element has no `alt`, so the accessible name has to come from `role="img"` + `aria-label`.

`apple-touch-icon.png` is deliberately opaque: iOS composites a transparent touch icon onto an unpredictable ground and it can come out black on black.

Tracing is the one genuinely open piece. Auto-tracing this level of detail is lossy — expect to hand-correct, or trace only the chip mark and keep the full logo as raster.
