## Description

Bing Webmaster Tools' first scan of the home page reported **"H1 tag missing"**
(2026-09-12). The page does have an `<h1>` — "Hands-on electronics workshops" in
`web/src/views/Home.svelte` — but only after JavaScript runs.

Measured on production: the server's HTML for `GET /` has **zero `<h1>` tags**,
and its whole `<body>` is `<div id="app"></div>`. Every public route is the same
shell. `#0019` injects per-route `<title>` and Open Graph tags server-side, but
nothing visible.

So any client that does not execute JavaScript sees a page with no heading, no
text, and no links: Bing's on-page checks, crawlers with limited rendering,
link-preview fetchers, and AI search crawlers. Even Google, which does render,
indexes rendered content on a delay and less reliably than raw HTML — and today
it cannot fetch the content at all (`#0518`).

The newsletter archive is the sharpest case: the whole point of `/archive/{slug}`
(`#0123`) is a permanent, indexable page, and its text exists only in a JSON
response.

## Options

1. **Inject per-route fallback content into `#app` server-side**, next to the
   meta injection `#0019` already does: an `<h1>`, the route's main text, and
   plain links. For `/archive/{slug}`, the same rendered body the API serves;
   for a workshop, its title, date, venue, and description.
2. **Prerender or server-render the public routes** with Svelte's SSR and hydrate
   on the client. More complete, and a bigger change to the build and deploy.

Record the choice and why.

**A constraint either way:** `web/src/main.ts` uses Svelte 5's `mount()`, which
**appends** to its target rather than replacing it. Injected content inside
`#app` would duplicate once the SPA mounts, unless it is cleared first or the app
hydrates instead.

## Acceptance criteria

1. Every public route — `/`, `/about`, `/privacy`, `/workshops`,
   `/workshops/{slug}`, `/subscribe`, `/archive`, `/archive/{slug}` — serves
   exactly one `<h1>` and its main text in the raw server HTML. Verify with
   `curl`, not a browser.
2. `/archive/{slug}`'s server HTML carries the newsletter body produced by the
   **same renderer** the API uses (`#0042`). The two must not diverge.
3. Internal navigation links are present as plain `<a href>` in the raw HTML.
4. **No duplicated content, flash, or second `<h1>` once the SPA mounts.** This
   matters beyond looks: `#0238` moves focus to the first `h1[tabindex="-1"]`,
   and `#0517` governs how that heading looks, so exactly one must exist after
   mount.
5. Token-bearing and private routes (`/confirm`, `/preferences`, `/unsubscribe`,
   `/admin`, `/account`, `/auth`) get **no** injected content.
6. Injected content is HTML-escaped where it comes from user or admin input, and
   adds no inline `<script>` (the CSP hashes the one bootstrap script).
7. Server-side caching and invalidation match the existing SEO renderer, so a
   withheld campaign's text disappears as promptly as its sitemap entry
   (`#0319`).
8. **Post-deploy, verified by the user:** Bing's re-scan no longer reports a
   missing H1, and Search Console's live test shows the content.
9. `ISSUE=NNNN scripts/check.sh` (Go and web) passes with no skips.

## Plan

Written 2026-09-12 by the phase-1 planning pass (Opus). No code written.

### 1. Decision: option 1, server fallback content inside `#app`, cleared before mount

**Chosen: option 1.** Option 2 (Svelte SSR or prerender, then hydration) is
ruled out for this codebase today, for four reasons:

- **There is no JavaScript runtime at request time.** The binary is Go, the
  SPA is `//go:embed`ded, and the box has no Node (and, per `#0509`, no Go
  toolchain either). Request-time SSR would need a Node sidecar. Build-time
  prerendering cannot produce `/archive/{slug}` or `/workshops/{slug}`,
  because that content changes when an admin publishes or withholds, not when
  someone runs a release.
- **The views are not hydration-shaped.** `Home.svelte` draws a canvas in
  `onMount`. Every data view fetches in `onMount`. `App.svelte` shows a
  `Loading…` placeholder until `GET /api/me` resolves, so its first client
  render never matches any server render. Hydrating would mean restructuring
  `App.svelte`, the router, and six views.
- **The release pipeline would change.** `scripts/release.sh` runs
  `npm run build` and then a cross-compiled `go build`. SSR adds a second build
  target and a new artifact to ship.
- **Option 1 reuses what already works.** `#0019`'s token substitution already
  runs on every HTML response, and its per-bucket cache and `Invalidate()`
  already cover exactly the data this issue needs.

**How duplication is avoided.** `mount()` appends, so the SPA must never mount
into a non-empty `#app`. `web/src/main.ts` will empty `#app` synchronously,
**before** calling `mount()`, through a new helper
`prepareMountTarget()` in `web/src/lib/mountTarget.ts`. The server's nodes are
gone before Svelte creates its first node. The two sets of content never share
the DOM or the accessibility tree, so a screen reader cannot hear either one
twice, and after mount the only `<h1>` is the view's own.

Rejected alternative: render the fallback *outside* `#app` and remove it on
mount. `App.svelte` renders `<Footer />` and the `Loading…` placeholder
immediately, so for the length of the `/api/me` call both would be visible
next to the fallback. Clearing `#app` is simpler and has no overlap window.

**Single-`<h1>` and focus rules (`#0238`, `#0517`).** The fallback `<h1>`
carries **no `tabindex`**. `App.svelte`'s focus effect selects
`h1[tabindex="-1"]`, and `#0517`'s styling hangs off the
`h1[tabindex='-1']:focus` rule in `app.css`. So even if fallback markup
somehow survived, it could never be a focus target or get the outline. The
fallback uses no `id` that a view also renders, except `main-content`, and
that one is removed before any view renders its own.

**Flash, disclosed rather than hidden.** Without JavaScript, or on a slow
connection while the bundle downloads, a visitor sees the fallback. Once the
module runs, the sequence is fallback, then `App.svelte`'s existing
`Loading…`, then the view. Today it is blank, then `Loading…`, then the view.
The fallback uses the same `app-shell` wrapper class and global typography, so
it reads as a plain version of the page, not as broken markup. Removing the
`Loading…` step for public routes is a follow-up (§8), not part of this slice,
because `#0238`'s focus timing depends on `sessionChecked`.

### 2. Server HTML shape

`web/index.html` and `web/dist/index.html` both change `<div id="app"></div>`
to `<div id="app">` + a new body token + `</div>`. The new token constant is
`tokenBody = "%%OC_BODY%%"` in `internal/seo/seo.go`. **Do not spell the token
literally in any HTML comment** — `TestSourceTemplate_EachTokenAppearsExactlyOnce`
counts it.

For a route that gets content, the substituted value is:

```html
<header class="app-shell"><nav aria-label="Site"><ul>
  <li><a href="/">Home</a></li><li><a href="/workshops">Workshops</a></li>
  <li><a href="/about">About</a></li><li><a href="/subscribe">Subscribe</a></li>
  <li><a href="/archive">Archive</a></li><li><a href="/privacy">Privacy policy</a></li>
</ul></nav></header>
<main id="main-content" class="app-shell">
  <h1>…</h1>
  … route content …
</main>
```

For every other route the value is the empty string, and the served HTML keeps
`<div id="app"></div>` byte-for-byte as today.

### 4. Go design (`internal/seo`)

New file **`internal/seo/fallback.go`**:

- `type pageKind int` with the values `pageNone` (zero), `pageStatic`,
  `pageWorkshopsIndex`, `pageArchiveIndex`, `pageWorkshop`, and
  `pageArchiveEntry`.
- `type pageContent struct { kind pageKind; path string; workshop Workshop; archive ArchiveEntry }`.
  This is plain data and comparable. Do not use a func field.
- `var staticPageCopy = map[string]staticCopy{…}`, keyed by route, with
  `type staticCopy struct { Source string; H1 string; Blocks []copyBlock }` and
  `type copyBlock struct { Heading bool; Text string }`. `Source` is the
  repo-relative `.svelte` path the guard reads. Put the `/workshops` and
  `/archive` headings, ledes, and empty-state strings here as well, as entries
  or named fields, so the guard covers them.
- `var fallbackNav = []navLink{{"/", "Home"}, {"/workshops", "Workshops"}, {"/about", "About"}, {"/subscribe", "Subscribe"}, {"/archive", "Archive"}, {"/privacy", "Privacy policy"}}`.
- One `html/template` set, parsed once with `template.Must` at package level.
  It produces the header, nav, `<main>`, and per-kind bodies. **Every value
  goes through `html/template`'s contextual escaping.** Titles, summaries,
  subjects, preheaders, and location strings are escaped as text, and slugs
  are escaped in `href` attribute context. The **only** `template.HTML`
  conversion is the string `mailing.RenderMarkdownHTML` returns. That is
  goldmark in safe mode (no raw HTML), the same bytes the SPA already inserts
  with `{@html}`. Say so in a comment next to the conversion.
- `func (r *Renderer) renderPage(p pageContent) (html string, cacheable bool)`:
  - `pageNone` returns `"", true`.
  - The index kinds call `r.workshop.Workshops()` or
    `r.archive.ArchiveEntries()`, handling a nil source as an empty list.
  - A **source error**, or a `RenderMarkdownHTML` error, still renders the
    `<h1>`, lede, and nav, and returns `cacheable=false`. A transient store
    failure must not freeze a list-less page for the whole TTL.

Changes to **`internal/seo/seo.go`**:

- Add the unexported field `page pageContent` to `RouteMeta`.
- Add `tokenBody`.
- **`defaultStaticRouteMeta`** sets `page`:
  - `pageStatic` with the path for `/`, `/about`, `/privacy`, and
    `/subscribe`.
  - `pageWorkshopsIndex` for `/workshops`.
  - `pageArchiveIndex` for `/archive`.

  `defaultFallbackMeta` and `defaultNotFoundMeta` leave `page` as the zero
  value.
- **`workshopRouteMeta`** sets `page` to `pageWorkshop` carrying `w`, in both
  the published return and the canceled branch, where it is set on the copied
  `m` after `m := r.fallback`.
- **`archiveRouteMeta`** sets `page` to `pageArchiveEntry` carrying `e`.
- `resolve`'s signature does not change.
- **`substitute`** becomes `substitute(m RouteMeta) (body []byte, cacheable bool)`.
  It calls `r.renderPage(m.page)` and adds `tokenBody, pageHTML` to the
  existing single `strings.NewReplacer` call, **unescaped**, like
  `tokenJSONLD`. Note in its doc comment that `strings.Replacer` makes one pass
  over the template and never rescans replacement text. That is why admin text
  containing a token-shaped string cannot trigger a second substitution.
- **`Render`** stores into the cache only when `cacheable` is true.

**Reads happen only on a cache miss.** `renderPage` runs only inside
`substitute`, which `Render` calls only on a miss. So `/workshops` and
`/archive` add at most one list read per TTL per bucket, and the detail pages
add zero store reads. `TestMountAndServe_WorkshopMutationInvalidatesSharedSEOSite`
pins the `WorkshopBySlug` call count, so do not add a lookup.

**Caching and invalidation** (acceptance criterion 7) need no new mechanism:

- The fallback lives inside the cached rendered bytes, so `Renderer.Invalidate`
  (reached through `Site.Invalidate`: `#0319`, `#0325`) clears it on the same
  call that clears the sitemap.
- A **withheld** `/archive/{slug}` drops its body immediately, even without
  invalidation. `resolve` runs on every request, and `archiveRouteMeta`
  returns ok=false once the entry is unpublished, so the request moves to the
  shared fallback bucket, which has empty page content.
- The `/archive` list is cached under its static key until `Invalidate` or the
  60s TTL, the same bound as the sitemap.

**CSP (acceptance criterion 6).** No inline script and no inline style
attribute are added. The page's only inline `<script>` stays the theme
bootstrap, and nothing in this plan touches its bytes. The Apache hash
`KLoCdoLOAQC6Tl5qFMi7s/7fwSxANUdbZFjnX7Vhau8=` stays valid. The command to
prove it is under Obstacles. Goldmark safe mode emits no `<script>`, and the
JSON-LD block is unchanged.

### 5. Web changes

- **New `web/src/lib/mountTarget.ts`** exports
  `prepareMountTarget(doc: Document = document): HTMLElement`. It gets
  `#app`, throws if it is missing, calls `el.replaceChildren()`, and returns
  `el`. Its doc comment says why: `mount()` appends, and the server's fallback
  must never coexist with the view (`#0519`, `#0238`).
- **`web/src/main.ts`** becomes
  `mount(App, { target: prepareMountTarget() })`, and the direct
  `getElementById('app')` is removed.
- No Svelte component changes.
