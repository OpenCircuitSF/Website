## Description

`internal/handlers/admin_pending.go`'s `QueueState` doc comment, and
`internal/subscribers/pending.go`'s header, both still enumerate the states as
**queued / sending / sent / abandoned**.

`#0365` made **`skipped`** reachable for `KindConfirmation` rows via `sendGate`
— and those rows are exactly what `QueueState` reports. The SPA side already
handles it: `queueStateLabel` renders "Skipped" and `queueStateBadgeClass`
gives it `badge-muted`.

**Stale since `#0365`**, not since `#0378`/`#0380`. Found by their review.

Same class as `#0379`'s finding: a doc comment describing a closed set that a
later change opened.

## Acceptance criteria

1. Both enumerations include `skipped`, and say what it means — a message the
   system **correctly withheld**, not a delivery failure. That distinction is
   the whole reason `#0378` moved `CancelQueuedTx` off `abandoned`.
2. **Re-derive the reachable set yourself** rather than trusting this issue:
   enumerate every writer of `outbound_queue.status` and confirm which states a
   `QueueState` row can actually hold. `#0378`'s review found exactly one SQL
   writer of `abandoned` and proved a third call site's abandoned branch is
   **unreachable by construction** (`welcomeAddressDeferMaxRetries =
   math.MaxInt32`). Expect surprises of that kind.
3. **Do not enumerate `failed`** unless your derivation shows a producer.
   `#0380`'s review verified four ways that nothing ever writes
   `outbound_queue.status = 'failed'` — it exists only in the CHECK constraint.
   Listing it would document a state that cannot occur.
4. The comments must not overstate: say what is reachable, not what the CHECK
   permits. **Five issues bounced this phase for doc comments claiming more than
   the code delivers**, and this phase has corrected the same file family three
   times.
5. Comment-only. Prove it structurally with your own tool, built to a binary
   (not sourced into a running process — §8's `#0258` trap), proved falsifiable
   first and failing closed on empty input. **Ten agents have found genuine
   fail-opens in their own instruments this phase**, including one whose
   `f.Comments = nil` missed `Doc`/`Comment` fields on declarations.
6. No `<file>.go:<int>` citation in any comment (`#0352`). Run
   `./internal/handlers/...` and `./internal/subscribers/...` — both own
   repo-wide guards (`#0381`). `gofmt` stability.

## Fix

**Criterion 2 — the reachable set was re-derived independently**, not
trusted from this issue's own table. Every writer of
`outbound_queue.status` lives in `internal/outbox/store.go` (the one file
that owns the table, per this project's convention — confirmed by grepping
the whole tree for `UPDATE outbound_queue`/`INSERT INTO outbound_queue`,
which returns matches only in that file):

| Method | Sets status to |
|---|---|
| `EnqueueTx`/`Enqueue` (INSERT) | `'queued'` (column default; no `status` column named in the INSERT) |
| `ClaimDue`, `ClaimRow` | `'sending'` (from `'queued'`) |
| `MarkSent` | `'sent'` (from `'sending'` or `'queued'`) |
| `MarkDone` | `'sent'` (from `'queued'` or `'sending'` — `KindSubscribeIntake` only) |
| `MarkSkipped` | `'skipped'` (from `'sending'`) |
| `CancelQueuedTx` | `'skipped'` (from `'queued'` — was `'abandoned'` before `#0378`) |
| `MarkRetryOrAbandon` | `'queued'` or `'abandoned'` (CASE on `attempts >= maxRetries`, from `'sending'`) |
| `Release`, `OrphanSweep` | `'queued'` (from `'sending'`) |

So the reachable set is **queued / sending / sent / skipped / abandoned**.
`'failed'` is declared (`StatusFailed = "failed"`) but referenced as an
argument at **zero** writer call sites — confirmed both by direct reading
of every method above and by the standalone tool described below, which
scans call sites mechanically rather than by eye.

**Two independent writers reach `skipped`** — `MarkSkipped` (`#0365`'s
send-time gate) and `CancelQueuedTx` (`#0378`, moved off `'abandoned'`),
both confirmed live in the current tree.

**`QueueState` specifically** reads `outbox.Row.Status` directly
(`internal/handlers/admin_pending.go`'s `List`: `state = r.Status`) off the
latest `outbox.KindConfirmation` or `outbox.KindImportInvite` row for the
address — so it can hold any value the column can hold, plus the two
handler-computed sentinels `"unknown"` (no outbox backing, `STORAGE=json`)
and `"none"` (no row exists). `skipped` is reachable for both kinds:
`sendGate` (`#0365`) gates `KindConfirmation` and `KindImportInvite`
directly, and `CancelQueuedTx` targets `KindImportInvite` specifically
(the only call site, in `subscribers.Store`'s self-after-invite branch).

**Criterion 3 — `failed` is deliberately not listed**, matching the zero
writer-call-sites finding above (also independently established by
`#0380`'s review). Both corrected comments say so explicitly rather than
silently omitting it, so a future reader who greps the CHECK constraint
and finds `failed` there does not conclude the comment missed it.

**Criterion 1 — both enumerations now include `skipped`**, with what it
means: a message the system *correctly withheld* — the subscriber's live
state, a suppression, or an address change made it ineligible by send
time, or (import invitations only) a queued invitation was superseded by
that address's own signup — never a delivery failure, which only
`abandoned` still means.

Edited:

- `internal/handlers/admin_pending.go` — the `QueueState` struct field's
  doc comment: added `"skipped"` to the quoted enumeration, explained its
  meaning, and stated `"failed"` is CHECK-permitted but unwritten.
- `internal/subscribers/pending.go` — the package doc comment's
  parenthetical: added `sending` (also missing, found during the
  re-derivation — the pre-existing text read `queued / sent / abandoned`)
  and `skipped`, with the same distinction.

**Criterion 5 — proved structurally, with a standalone compiled tool.**
Wrote a Go program (`main.go`, built with `go build -o 0385tool` — a real
binary, never `go run` inside this session's own process and never
sourced into a running shell, avoiding the `#0258` trap named in this
issue) that:

1. Parses `internal/outbox/store.go`'s AST, finds every `Exec`/`QueryRow`/
   `Query` call whose SQL literal contains `UPDATE outbound_queue` or
   `INSERT INTO outbound_queue`, and collects every `Status*`-named
   identifier referenced among that call's arguments, resolving each to
   its declared string value. This is the mechanical version of the table
   above, built independently of my by-hand reading.
2. Parses the `QueueState` field's doc comment and `pending.go`'s package
   doc comment via `go/ast` (by declaration, not "any comment in the
   file"), and checks each contains `skipped` in its own state-enumeration
   list, and that list does not contain `failed`.

**Falsifiability, proved before trusting a single PASS** (`-selftest`
mode, three probes, all required to pass or the tool refuses to report):

- **Probe A (fails closed on empty input):** an empty `package outbox`
  file produces an explicit error, not a silently-empty-but-plausible
  set. First run of this probe surfaced nothing wrong; passed cleanly.
- **Probe B (discriminates):** mutating away the `StatusSkipped` argument
  at *both* writer call sites and re-running the derivation — the first
  attempt at this probe mutated only `MarkSkipped`'s call and the
  derived set still contained `skipped` via `CancelQueuedTx`, which the
  tool correctly reported as a probe-setup defect (both sites must be
  mutated to isolate "does the tool see writes at all"), not a tool
  defect — itself independent confirmation of the two-writer finding
  above. With both mutated, `skipped` correctly drops out of the derived
  set.
- **Probe C (general, not hardcoded):** splicing a fabricated
  `MarkHypothetical` method binding a new `StatusHypothetical` constant
  into a scratch copy of `store.go` — the derivation picks it up without
  being told its name, proving the scan is not a hardcoded list of known
  call sites.

**Fails-without-the-fix / passes-with-the-fix, on the real files** (not
just synthetic ones): exported `git show HEAD:internal/handlers/
admin_pending.go` and `HEAD:internal/subscribers/pending.go` (the
pre-this-commit versions) into a scratch tree alongside the current
`store.go`, and ran the tool against it — **FAILED**, correctly reporting
the `QueueState` comment does not mention `"skipped"` at all. Ran the same
tool against the current working tree (post-fix) — **PASSED**. The tool
and its selftest were kept in scratchpad, not committed, per this
project's convention for a one-off verification instrument (`#0376`'s own
precedent).
