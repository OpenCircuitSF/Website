# 0121 — Three `internal/handlers` tests depend on the shared test database holding no other active subscribers, and fail under `-shuffle=on`

| | |
|---|---|
| **Status** | open |

| **First seen** | 2026-08-21 |

## Description

Three tests in `internal/handlers` assert an **exact** audience count computed
over the whole `subscribers` table, so each one silently requires that no other
test has left an `active` subscriber behind:

- `admin_campaign_preflight_test.go` — `TestAdminCampaignPreflight_UnmetCodesInPinnedOrder`
  asserts `summary.recipients == 1`
- `admin_campaign_audience_test.go` — `TestAdminCampaignAudience_Preview_Success`
  asserts `Count == 3` and `len(Sample) == 3`
- `admin_campaigns_test.go` — `TestAdminCampaigns_Send_DraftToScheduled`
  posts a `confirm_count` the server re-verifies against the live count

They pass under the project's documented verification command only because
`TestMain` `TRUNCATE`s `subscribers` at package start and Go runs test files in
sorted order, so these three happen to run before the files that seed `active`
subscribers without cleaning up.

Proven deterministically — this is an ordering dependency, **not** a load-related
flake (`CLAUDE.md` §5):

```
$ go test ./internal/handlers/ -count=1 -shuffle=on
--- FAIL: TestAdminCampaignAudience_Preview_Success
    admin_campaign_audience_test.go:85: Count = 5, want 3
--- FAIL: TestAdminCampaignPreflight_UnmetCodesInPinnedOrder
    admin_campaign_preflight_test.go:121: summary.recipients = 6, want 1
--- FAIL: TestAdminCampaigns_Send_DraftToScheduled
    admin_campaigns_test.go:355: status = 409, want 200
        (body={"error":"confirm_count does not match the current audience count (5); reload and try again"})
```

The upstream cause is seeds without cleanup. `admin_campaigns_test.go:570` seeds
an `active` subscriber via `seedSubscriberRow` and never deletes it;
`journey_testutil_test.go` leaves several more. A single ordered run finishes
with ~48 rows still in the shared `opencircuit_test` `subscribers` table.

## Acceptance criteria

- [ ] Every `seedSubscriberRow` call in `internal/handlers` registers a
      `t.Cleanup` deleting the row by its **captured id** (`CLAUDE.md` §8b —
      never a literal id). `admin_campaign_preflight_test.go` and
      `admin_campaign_preview_test.go` already do this and are the pattern.
- [ ] `journey_testutil_test.go`'s seeds clean up after themselves too.
- [ ] `go test ./internal/handlers/ -count=1 -shuffle=on` passes.
- [ ] An ordered run leaves the shared `subscribers` table as it found it.

## Notes

Found by `#0047`'s phase-3 review while probing the isolation fix the
implementer made to its own two new tests (that fix is complete and correct —
both rows it seeds are deleted by id in `t.Cleanup`). The finding is that the
*assertion style* joins an existing fragile family rather than that #0047 leaked
anything.

Distinct from `#0108`, which was one helper returning colliding addresses. This
is uncleaned rows plus whole-table count assertions.

Cheaper alternative if the cleanup sweep is not wanted: have these three tests
assert against a delta they measured themselves (count before, seed, count
after) rather than an absolute total. That makes them order-independent without
touching every seed site.
