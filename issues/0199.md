## Description

`#0196`'s phase-3 review planted 15 dangling citations across every context the
guard claims to cover — both comment syntaxes, doc and in-body, test and
non-test files, all three roots, and a line-wrapped identifier — and all 15 were
caught. It then deleted each discount rule in isolation and re-ran the tree.
Three blind spots came out of that.

**1. The preceding-`*` emphasis rule is too broad.** It silently swallows **any**
markdown-emphasised dangling citation. Deleting the rule turns up only three
real lines in the whole tree, all the bare word `TestPool` — two of them the
guard's own prose. So the rule is buying almost nothing and costing a whole
class of missed citations. An allowlist entry covers those three exactly.

The other four rules — trailing `*`, trailing `...`, `renamed from`, and the
`TestSentAt` allowlist — are **narrow and load-bearing**, verified by deletion.
`renamed from` correctly discounts only the name it introduces (a second
dangling citation in the same comment was still caught) and fails *toward*
firing when the separator exceeds its 20-byte window.

**2. A wrapped citation whose first line is itself a defined name is missed
entirely.** The line-break-join design asks whether the zero-separator join of
two lines names a defined function; normally an undefined join is discarded and
the fragment reported, so it fails safe. But when the line-1 fragment *is* a
real name, the citation vanishes. Six strict-prefix pairs already exist among
the tree's 885 test functions, so this surface **grows with the tree**.

The review's judgement — which I accept — is that the alternatives are worse and
the coupling is the right trade. What is missing is that the guard's own comment
says nothing about it. The `...` discount has the same shape at lower stakes:
`// TODO: write TestNotYetWritten... later` is silently accepted.

**3. For a multi-line `/* */` block comment the reported line is the block's
opening line, not the citation's** — measured four lines off. Latent: five
multi-line blocks exist in the tree and none carries a citation. But the failure
message exists to be pasted into a search, which `#0187` established for the
other guard.

## Implementation notes

Scope: `internal/handlers/dangling_test_citation_guard_test.go` only.
`internal/handlers/citation_guard_test.go` (`#0200`) was never touched —
checked `git status` before starting and again before committing.

**Item 1.** Removed `citationIsExcluded`'s preceding-`*` rule
(`if start > 0 && text[start-1] == '*' { return true }`) and added
`"TestPool": true` to `nonTestIdentifierAllowlist`. Confirmed both
directions live against the real tree, using the `cp`+`shasum` method
(§8a) rather than `git stash`:

- Planted `each of this package's *Test0199LivePlantMarkdownEmphasisMissing
  helpers does something imaginary` (leading-asterisk emphasis, no closing
  asterisk immediately after — matching main_test.go's real `*TestPool`
  shape, not the trailing-wildcard shape) into `settings_test.go`. The
  guard failed: `internal/handlers/settings_test.go:4:
  Test0199LivePlantMarkdownEmphasisMissing`. Reverted; `shasum -a 256`
  matched the pre-plant file and `git status` was clean.
- Restored `settings_test.go` to its original byte-identical state and
  reran the guard: **PASS** — the three real `TestPool` lines
  (`main_test.go:19`, and this file's own comments at lines 57 and 87)
  still do not fire.

Also extended `TestDanglingTestCitationPatternExcludesDiscountedShapes`
with a permanent, non-live proof of both directions (the existing
`TestPool` case now documented as allowlist-driven, plus a new
`emphasisedDanglingName` case proving a *different* leading-asterisk name
is no longer excluded).

**Item 2.** Added a paragraph to `collectTestCitations`'s doc comment
stating: the seam pass's answer depends on what `collectDefinedTestFuncs`
found elsewhere in the tree; a wrapped citation whose line-1 fragment is
itself a defined name disappears entirely (no punctuation difference from
an ordinary caught citation); six strict-prefix pairs already exist among
the tree's defined test functions (e.g. `TestDeleteSessionsForUser` /
`TestDeleteSessionsForUser_RemovesAllAndIsIdempotent`), so the candidate
count only grows as the tree does. Live-replanted this exact blind spot
(`// See TestDeleteSessionsForUser\n// AndAnImaginarySuffixThatDoesNotExistAnywhere
for details.` in `settings_test.go`) — guard **PASS**, confirming it is
still missed, as documented (not fixed; #0196's review judged the
alternatives worse and I agree).

Documented the `...` discount's TODO-placeholder blind spot alongside it
in `citationIsExcluded`'s comment rather than narrowing it — there is no
local, punctuation-based signal that distinguishes a genuine
family-wildcard reference (`TestFoo...`) from an unwritten placeholder
(`// TODO: write TestNotYetWritten... later`). Live-planted `// TODO:
write Test0199LivePlantEllipsisTodo... later.` — guard **PASS**, confirming
it is still silently accepted.

**Item 3.** `collectTestCitations` built one `lines[]`/`positions[]` entry
per `*ast.Comment`, using `fset.Position(c.Slash)` (the comment's opening
delimiter) as that entry's sole position. A `//` comment is always exactly
one physical line, so this was fine; a `/* ... */` block comment can span
many, and every citation inside one collapsed to the block's opening line.
Fixed by splitting each comment's stripped text on its own `"\n"` and
advancing `pos.Line` once per split — a no-op for `//` comments (never
multi-line) and correct for block comments.

Live-planted a real multi-line block comment into `admin_workshops.go`
(before the fix this would have reported line 28, the `/*`; after the fix
it correctly reported **line 31**, the physical line the citation sits
on — a 3-line difference, same bug #0196's review found 4 lines off
elsewhere). Reverted; `shasum` matched, `git status` clean. Also added a
permanent regression test,
`TestDanglingTestCitationPatternReportsBlockCommentLineNotItsOpeningLine`,
against a `t.TempDir()` fixture (block opens at line 3, citation at line
6) so this doesn't have to be rediscovered by hand again.

## Notes

Reported by `#0196`'s phase-3 review under `CLAUDE.md` §9.

Read that review's `## Review notes` first — the 15-plant table and the
rule-by-rule deletion results are there, and they are the regression suite for
this work. Item 1 is the one with real coverage consequence; items 2 and 3 are
about the guard telling the truth regarding what it does and does not catch.

Note the guard scans `_test.go` and so is **not** protected from itself the way
`#0181`'s is. Its string-literal exclusion is deliberate and structural — the
walk reads `file.Comments` only and never touches `ast.BasicLit` — and it is
load-bearing: the line-wrap fixture's raw string contains two undefined `Test…`
names, so a string-scanning guard would fail on its own fixture.
