## Description

`#0200` pinned the citation guard's walk-coverage invariant by diffing the
shipped walk against an independent, unrestricted `filepath.WalkDir`. Making the
ground truth independent of `skipVendoredDirNames` was the right call — reusing
the skip would have blinded it to the exact bug the test exists to catch.

But unrestricted means it walks `web/node_modules`. **So an npm dependency
shipping a non-test `.go` file now fails this test** — which re-opens, in a
different test, precisely the `npm install` breakage `#0194` added the skip to
prevent. `#0200`'s review demonstrated it incidentally: its vendored probe file
appears in the ground truth and not in `collected`.

Prospective only; there are zero `.go` files under `web/node_modules` today.

**A third option is strictly better than the two `#0200`'s notes weigh.** Exclude
by **anchored path prefix** (`web/node_modules`, `web/dist`) in the ground truth,
rather than by directory name. That stays independent of the name-based
predicate under test — so a real `internal/dist/foo.go` still fails the test,
which is the whole point — while vendored Go source no longer does.

**A second, smaller item.** The failure message's second direction reads
"collected but NOT present on disk (stale path, symlink, or duplicate walk
entry)". `#0200`'s review established that branch is **effectively
unreachable**: the ground truth is the shipped walk minus the `SkipDir`, so
`collected ⊆ onDisk` for any static filesystem state. It tested the named
causes — a `*.go` symlink lands in both sets since `WalkDir` lstats; a symlinked
directory is followed by neither; a dangling symlink or a directory named `*.go`
dies earlier at the shipped walk's parse `t.Fatalf`. Only a file vanishing
between the two walks could populate it.

The branch is not dead code — blinding the ground truth to a substring rendered
it correctly — but the parenthetical names causes that cannot actually produce
it.

## Implementation notes

`TestScanDirForCitationsCollectsExactlyDiskFiles`'s "on disk" enumeration in
`internal/handlers/citation_guard_test.go` now excludes two anchored path
prefixes — `filepath.Join(baseDir, "../../web/node_modules")` and
`filepath.Join(baseDir, "../../web/dist")` — computed once and checked by
exact match or `prefix + separator` match on the full walked path, rather than
by bare directory name. A directory hit under an excluded prefix returns
`filepath.SkipDir`; a file hit is simply not added to `onDisk`.

**Why this isn't circular.** `skipVendoredDirNames` (used by the shipped
`scanDirForCitations`, unchanged) matches a directory *name* at any depth
under any of `scanGoRoots`. The new ground-truth exclusion matches two full,
fixed *paths* instead. They agree on today's tree (only `web/node_modules`
and `web/dist` exist) but diverge on the case that matters:
`internal/dist/foo.go` does not share a path prefix with either excluded
path, so it is still counted `onDisk` and the shipped walk's
`skipVendoredDirNames["dist"]` match still narrows `collected` relative to
it — the test still fails and still names the file. A vendored
`web/node_modules/*.go`, by contrast, is now excluded from *both* sides
identically, so it no longer produces a mismatch.

**Criterion 5 (message fix).** The "collected but NOT present on disk"
parenthetical previously named "stale path, symlink, or duplicate walk
entry" — of which `#0200`'s review proved symlink and duplicate-walk-entry
cannot occur, since `collected` is structurally a subset of `onDisk` for any
static filesystem state. The message now reads "a file vanished between the
two walks of the same root during this run" — the one condition that could
actually populate that set. The branch itself is unchanged (not deleted);
only the doc comment and the message text were corrected to say what the
branch actually guards. The doc comment above the test was rewritten to
explain the anchored-prefix mechanism and the unreachability argument in
full, referencing `#0200`'s and `#0194`'s review notes rather than
re-deriving their proofs.

the shipped walk does. That is what would make the test circular and worthless.

`web/src/node_modules/` (the npm-workspaces shape, which is arguably the more
likely real-world occurrence). This is proof of independence by execution, not
by assertion: the two mechanisms genuinely disagree exactly where they must.

### The anchoring is genuinely anchored

Two checks, both by execution.

1. **Sibling directory.** Planted `web/node_modules_extra/sibling.go` — a
   directory the shipped walk does *not* skip (`"node_modules_extra"` is not a
   key in `skipVendoredDirNames`). Test **PASSES**, so the ground truth counts
   it: the `prefix + os.PathSeparator` guard is doing its job.

   Mutation proof that this check discriminates: replacing
   `path == prefix || strings.HasPrefix(path, prefix+string(filepath.Separator))`
   with a bare `strings.HasPrefix(path, prefix)` makes the same plant **FAIL**,
   reporting `web/node_modules_extra/sibling.go` under "collected but NOT
   present on disk". Source restored from a `cp` backup and verified
   byte-identical by `shasum -c`.

   That mutation is also a useful incidental result: the second branch is
   **live, not dead code** — a bug in the exclusion predicate reaches it.

2. **`../..` is cleaned.** `filepath.Join` calls `Clean`, so
   `filepath.Join(baseDir, "../../web/node_modules")` yields
   `<repo>/web/node_modules` with no `..` left in it — confirmed by running a
   standalone program over the real string. The walked `path` comes from
   `filepath.WalkDir(filepath.Join(baseDir, rel), …)`, which is likewise
   cleaned, so the two forms are directly comparable and the equality/prefix
   test is sound. `web/node_modulesX` and `web/node_modules_extra` are both
   correctly *not* matched.

### One inaccuracy worth fixing, not worth a bounce

The new doc comment contains a stale parenthetical. It reads:

> "on disk" is a superset of that same walk (it additionally counts the two
> vendored prefixes onDisk would otherwise miss)

The ground truth does **not** count the two vendored prefixes — excluding them is
the entire change. That clause describes the *pre-`#0201`* unrestricted walk and
was left behind when the sentence around it was rewritten. What `onDisk`
additionally counts, relative to the shipped walk, is name-matched directories
that lie *outside* the two anchored prefixes — `internal/dist/`,
`internal/node_modules/`, `web/src/node_modules/`: precisely the plants above.
The conclusion the sentence draws (`collected ⊆ onDisk`) is correct and was
confirmed by execution; only its stated justification is backwards.

The behavior is right and every acceptance criterion holds, so this resolves.
But this test's value lives almost entirely in that comment, and a clause
stating the opposite of what the code does will mislead the next reader.
Recommend the orchestrator file a follow-up to correct it (`CLAUDE.md` §9 —
reported, not filed).
