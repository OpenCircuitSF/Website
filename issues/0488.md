## Description

`scripts/go_file_visit_floor_guard_test.sh`'s `count_outbox_call_sites` doc
comment carries the same shape `#0483` and `#0487` just fixed, beside the same
population. It states the function "measures 42", and that the Go guard's own
doc comment "measures 36 by go/ast".

**Both numbers are the stale ones `#0487` corrected.** Measured twice
independently today — by an implementation pass and by its reviewer, each
running the two counting methods themselves:

| Method | Documented here | Actual |
|---|---|---|
| grep, this function run unmodified | 42 | **45** |
| go/ast, the Go guard's own scan | 36 | **39** |

Each stale by exactly three, from ordinary call-site growth that a floor cannot
see.

## Why this one is worse than its three siblings

It was already false before `#0487`. What `#0487` changed is that **the two
files now contradict each other**, and this one names the Go declaration it
mis-describes — so a reader who follows the pointer finds a comment saying
something different from what this one claims it says.

That is the failure mode these issues exist to prevent, one step compounded: not
merely a number that drifted, but a cross-reference asserting the content of
another file that has since been corrected.

## The pattern is not confined to two files

Found by `#0487`'s review, which was asked to look. The count now stands at
**four instances across three files**:

- `minLoaderVariables` — `#0483`
- `minScannedEnvExampleAssignments` — `#0483`
- `claimKindsGuardMinPlausibleCallSiteCount` — `#0487`
- this one

Every exact count written beside an inequality in this repository has drifted.
None was caught by the mechanism it stood next to, because a floor only catches
shrinks.

## Acceptance criteria

1. **Re-derive both numbers yourself**, with the two methods named — this
   function run unmodified, and the go/ast scan the Go guard performs. Three
   derivations agree on 45 and 39; treat that as a claim to check, not an
   authority.
2. **Apply `#0487`'s reframing rather than re-substituting.** It replaced the
   fragile pair with a relationship — the go/ast total plus six, where six is
   the fixture text in the guard's own file — which its review verified is
   invariant under ordinary call-site growth. Swapping 42→45 and 36→39 here
   would reset the clock on the identical defect. If the reframing does not
   transfer, say why.
3. **Resolve the cross-reference.** Decide whether this comment should restate
   the Go file's figures at all. A pointer that says "see that declaration" ages
   better than one that says what that declaration contains.
4. **Do not raise the floor.** `#0483` established a floor with slack is not a
   defect when a sibling closes the shrink, and `#0487`'s review proved that
   subsumption holds here by construction.
5. **Prove the guard still fails on a genuine shrink.** Mutate a copy, never
   `git stash` (`CLAUDE.md` §8a), and restore byte-identically with SHA-256.
6. **Sweep for a fifth.** Four instances in three files is a pattern; establish
   whether any remain. If the sweep is clean, say what you searched for, so the
   next reader knows the ground was covered rather than assumed.
