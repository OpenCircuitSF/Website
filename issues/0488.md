## Description

`scripts/go_file_visit_floor_guard_test.sh`'s `count_outbox_call_sites` doc
comment carries the same shape `#0483` and `#0487` just fixed, beside the same
population. It states the function "measures 42", and that the Go guard's own
doc comment "measures 36 by go/ast".

**Both numbers are the stale ones `#0487` corrected.** Measured twice
independently today — by an implementation pass and by its reviewer, each
running the two counting methods themselves:

| Method | Documented here | Actual |
|---|---|---|
| grep, this function run unmodified | 42 | **45** |
| go/ast, the Go guard's own scan | 36 | **39** |

Each stale by exactly three, from ordinary call-site growth that a floor cannot
see.

## Root cause

The same shape as `#0483` and `#0487`: an exact-count sentence sitting beside
a floor, describing a population that only ever grows unnoticed because the
floor it sits next to catches shrinks, not growth. What made this instance
worse, as the title says, is that `#0487` corrected the Go file's copy of
these same two numbers and this file's copy was never touched, so the two
files came to actively disagree with each other rather than merely both being
stale by the same amount.

## Fix

**Criterion 1 — re-derived both numbers myself.** Ran
`count_outbox_call_sites` exactly as written (extracted the function
unmodified from the tracked script, asserted the extraction non-empty before
sourcing it, then called it against the real tree): grep total **45**,
non-exempt **12**. Separately wrote a standalone Go program replicating the
guard's own walk — `filepath.WalkDir` over `internal/` and `cmd/`, pruning
`node_modules`/`dist`, parsing every `.go` file, and counting
`*ast.CallExpr` nodes whose selector name matches `ClaimDue`, `OrphanSweep`,
or `SelectDue` exactly as `nameMatchesGuardedMethod` does: go/ast total
**39**, non-exempt **12**. Both non-empty, both agree with the three prior
derivations this issue cites, and 45 − 39 = 6, the same gap `#0487`
established.

**Criterion 2 — applied `#0487`'s reframing rather than re-substituting.**
The reframing transfers to this file exactly as stated: whatever the go/ast
total is on a given day, the grep total is that plus six, because the six
extra occurrences are call-site-shaped text inside
`TestClaimKindsGuardFiresOnFixtureWithNoKinds`'s raw-string fixtures, which
live inside `internal/outbox`'s own file and inflate only the exempt,
grep-only side. Rewrote the paragraph around that relationship instead of
writing 45 and 39 in as the new absolute pair — doing that would leave the
next three call sites of ordinary growth free to make this exact paragraph
stale again, the identical defect this issue exists to fix.

**Criterion 3 — resolved the cross-reference by not restating either total
here at all.** The previous paragraph named the Go declaration
(`claimKindsGuardMinPlausibleCallSiteCount`) and then asserted what its
comment said, which is exactly what let the two files diverge — the shell
comment kept a duplicate copy of a fact that only needed to live in one
place. The rewritten paragraph keeps the invariant relationship ("plus six")
here, since that is genuinely this file's own concern (it explains why
`count_outbox_call_sites`' population differs from the Go guard's), but
points at that constant's own doc comment for whichever absolute figure is
current, rather than asserting a duplicate. A pointer cannot go out of sync
with the thing it points at; a restated number can and did, twice now.

**Criterion 4 — did not raise either floor.** Neither
`claimKindsGuardMinPlausibleCallSiteCount` (5) nor
`claimKindsGuardMinPlausibleNonExemptCallSiteCount` (8) changed. `#0487`'s
review proved the subsumption argument (the non-exempt floor's slice is a
filter of the total floor's slice, so clearing the non-exempt floor already
clears the total floor) holds structurally, independent of the population's
size, so it still holds unchanged here.

**Criterion 5 — proved in `## Verification` below.**

**Criterion 6 — swept the repo for a fifth instance.** Searched three ways:
every package-level floor constant matching `Min…Count`/`…Floor` naming
across `internal/` and `cmd/` (enumerated by grep on the declaration
pattern, then read each one's doc comment for an exact "today" figure
asserted without historical framing); every occurrence of `measures
[0-9]`, `exactly [0-9]+ (variables|lines|sites|files)`, `carries exactly`,
and `reads exactly` across `.go` and `.sh` files; and the only other
`.sh` file implementing this floor-plausibility pattern (there is exactly
one, `scripts/go_file_visit_floor_guard_test.sh` itself — the string
`floor` appears in three other scripts but only as an unrelated port-range
or coverage-floor concept, not this pattern). Every other floor constant
found (`claimCommentGuardMinPlausibleFileCount` and its two siblings,
`citedTestScanRootsMinPlausibleFileCount`, `lineCitationGuardMinPlausibleFileCount`,
`citationGuardMinPlausibleFileCount`, `auditEmailMetadataMinPlausibleFileCount`,
`issueLineCitationGuardMinPlausibleFileCount`, `knownConsumersAsOfWriting`)
already frames its measured figure as historical ("today", "as of writing",
or "at the time this guard was written") without a second file restating
the same number, so none carries this issue's specific defect: an
unqualified exact-count claim that a sibling file has since corrected. The
sweep is clean; found nothing to report.

## Why this one is worse than its three siblings

It was already false before `#0487`. What `#0487` changed is that **the two
files now contradict each other**, and this one names the Go declaration it
mis-describes — so a reader who follows the pointer finds a comment saying
something different from what this one claims it says.

That is the failure mode these issues exist to prevent, one step compounded: not
merely a number that drifted, but a cross-reference asserting the content of
another file that has since been corrected.

## Acceptance criteria

1. **Re-derive both numbers yourself**, with the two methods named — this
   function run unmodified, and the go/ast scan the Go guard performs. Three
   derivations agree on 45 and 39; treat that as a claim to check, not an
   authority.
2. **Apply `#0487`'s reframing rather than re-substituting.** It replaced the
   fragile pair with a relationship — the go/ast total plus six, where six is
   the fixture text in the guard's own file — which its review verified is
   invariant under ordinary call-site growth. Swapping 42→45 and 36→39 here
   would reset the clock on the identical defect. If the reframing does not
   transfer, say why.
3. **Resolve the cross-reference.** Decide whether this comment should restate
   the Go file's figures at all. A pointer that says "see that declaration" ages
   better than one that says what that declaration contains.
4. **Do not raise the floor.** `#0483` established a floor with slack is not a
   defect when a sibling closes the shrink, and `#0487`'s review proved that
   subsumption holds here by construction.
5. **Prove the guard still fails on a genuine shrink.** Mutate a copy, never
   `git stash` (`CLAUDE.md` §8a), and restore byte-identically with SHA-256.
6. **Sweep for a fifth.** Four instances in three files is a pattern; establish
   whether any remain. If the sweep is clean, say what you searched for, so the
   next reader knows the ground was covered rather than assumed.

### Criterion 3 — the restated pair is still there (must fix)

The paragraph promises one thing and does another, inside itself:

> #0488's fix: stop restating either total here as an absolute number at
> all, and keep the live figure in exactly one place --
> claimKindsGuardMinPlausibleCallSiteCount's own doc comment …

and then, four sentences on:

> … Re-derived directly for #0488 (2026-09-09), agreeing with the
> figure recorded in that file on the same date: 39 by go/ast, 45 by this
> function, a difference of six.

Both absolute figures survive, and the sentence additionally asserts what the
other file records — the compounded cross-reference shape this issue's own
"Why this one is worse than its three siblings" section identifies as the
failure mode. Dating it keeps it from going false, but it does not keep the two
files from showing a reader different numbers again, which is the confusion
`#0488` exists to end. The greater harm is the contradiction: a maintainer who
reads the promise will not think to look for numbers in this paragraph, and
there are two.

**Remedy.** In `scripts/go_file_visit_floor_guard_test.sh`, in
`count_outbox_call_sites`'s doc comment, delete that sentence and put in its
place one carrying no absolute figure — for example, rewrapped to the comment's
existing width:

    # tree. Both totals were re-derived independently for #0488
    # (2026-09-09) and their difference was exactly six; the absolute
    # figures themselves deliberately live only in that Go doc comment.

Then correct this issue's own criterion 3 paragraph, which currently claims a
resolution the file did not carry.

Two smaller observations on the same paragraph, offered rather than required.
The non-exempt figure is still stated flatly as "both methods agree exactly at
12", which is the same shape one population smaller and will drift the first
time a non-exempt caller is added; the durable half of that sentence is that the
two methods agree, not the value they agree on. And the historical pair at the
top of the paragraph (42 here, 36 there, attributed to `#0303`) is correctly
framed as history and should stay — it is what makes the drift legible.

**Remedy — record it, do not fix it in this pass.** Replace criterion 6's
