## Resolution notes

> 🟢 Resolved 2026-11-19 — one `publicapi.Limiter` (60/min per trusted client IP) fronts both `/mcp` and `/api/public/v1/`, `Registry.Invoke` logs one IP-free record per call, and the three list operations are cached for 60 s, cleared by `seo.Site.OnInvalidate` on every publish or edit.

## Description

The public MCP server (`#0729`) needs no auth, so it needs its own abuse protection. The handoff asks for:

- a per-IP rate limit;
- server-side caps (already in `#0729`);
- parameterized queries;
- logging of each tool call;
- short-lived caching for the list tools.

## Acceptance criteria

- [x] A per-IP limit of 60 requests/minute on `/mcp`, kept separate from the admin API-key limiter so the two budgets never interact. Reuse the existing limiter type if one fits. The client IP comes from the same trusted-proxy logic the rest of the service uses behind Apache, not a raw `X-Forwarded-For`. Over the limit, it returns HTTP 429 with `Retry-After`. A test drives that.
- [x] Each tool call logs, through `slog`, the tool name, its params (with `query` truncated) and latency. No new IP retention beyond what existing request logs do.
- [x] `list_upcoming_events`, `search_events` and `list_newsletter_issues` results are cached for 60 s. The cache is invalidated by the same `seo` invalidation hook that publishing or editing an event or campaign already fires, so an edit shows up immediately. A test proves the invalidation.
- [x] The limit and TTL are named constants in one place, with the handoff's numbers.

## Plan

Written 2026-11-19 against `f178724c`, on top of `#0729`'s implementation (`5a4d7f01`; under review as this is written). Read `#0729`'s **Design, decided** first. `publicapi.Registry.Invoke` is already the single call path both adapters use, so logging and the cache go there, and `#0734`'s REST adapter inherits both with no extra code. The rate limit is HTTP-level, in front of each adapter, built as a `publicapi.Limiter` that both constructors take as an explicit argument, so the mount guard can require it.

### Design, decided

**Limiter: reuse `middleware.RateLimiter`.** It is the per-key token bucket every IP limiter here uses (`internal/middleware/ratelimit.go`); `NewAPITokenRateLimiter` and `NewAPIAuthFailureLimiter` are just `NewRateLimiter(rate.Every(time.Minute/N), N)`. The public budget is a **new, separate instance** built in `mountAndServe`, never `apiTokenLimiter` or the auth-failure limiter, so the budgets cannot interact. Keys are `"public:" + middleware.ClientIP(r)`.

- **Client IP:** `middleware.ClientIP` (`internal/middleware/clientip.go`, `#0077`): X-Forwarded-For is trusted only when the TCP peer is loopback (Apache), and then only the rightmost entry. Never parse the header here.
- **Why a tiny `middleware` export:** `MiddlewareByKey` writes the old `{"error":"rate_limit_exceeded"}` body, which is wrong for this surface, and `RateLimiter.allow` is unexported. Add one method rather than copy the bucket logic.
- **429 shape, both adapters:** the v1 error envelope, written before the request reaches the SDK or the REST router: status 429, `Retry-After: <whole seconds, rounded up, ≥1>`, `Cache-Control: no-store`, `Content-Type: application/json`, body `{"error":{"code":"rate_limited","message":"too many requests; try again shortly"}}`. Build it as `api.RateLimited(msg, wait)` and write it with a local `writeError` that is a copy of `internal/api/http.go`'s unexported `writeError`. For `/mcp` this is a plain HTTP 429, not a JSON-RPC error, on purpose: the SDK never runs. `#0734` reuses this same `writeError` instead of writing its own `writeJSONError`.
- **Ordering:** the limiter is the outermost layer of each adapter, so cache hits count against the budget too.
- **IP retention:** the limiter's in-memory map holds IPs exactly as every other `RateLimiter` does (never logged, never persisted). Nothing in this issue logs an IP.

**Cache: in `Registry`, keyed by op name + the decoded input.**

- `Op` gains `Cached bool`. `BuildPublicRegistry` sets it on exactly `list_upcoming_events`, `search_events` and `list_newsletter_issues`.
- **Key:** `op.Name + "\x00" + string(json.Marshal(in))`. `in` is the value `op.Decode` (or `#0734`'s `api.BindURL`) returned, so both adapters produce the same key for the same arguments. JSON of a struct is deterministic (field order). Do not try to normalise further (`limit` nil vs 10 are two keys; harmless). If marshalling fails, skip the cache for that call.
- **TTL** `ListCacheTTL` (60 s). Only successes are cached, never errors.
- **Generation counter, so an edit shows up immediately even mid-call.** `Invalidate()` bumps `gen` and empties the map. `Invoke` reads `gen` on a miss and `put` stores only if `gen` is unchanged, so a call that started before an invalidation never re-caches pre-edit data.
- **Bound:** `MaxCacheEntries` (512). `search_events` keys on free text, so an unbounded map is a memory hole. On a `put` at the cap, drop expired entries; if still at the cap, empty the map.
- **The cached `out` is shared between callers.** Neither adapter mutates it (`json.Marshal`, `Summarize`, `json.Encoder`); say so in the doc comment.
- Staleness of "upcoming" up to 60 s (an event that started under a minute ago can still be listed) is accepted.

**Invalidation: a hook on `seo.Site`, wired in `main.go`.** Every publish or edit already calls the same `*seo.Site`'s `Invalidate()`: `AdminWorkshopsHandler` (create, patch, delete, publish, cancel), `AdminCampaignArchiveHandler` (the archive toggle), `AdminEventTypesHandler`, `AdminVenuesHandler`, and the send worker's archive-publish transition through `mailing.ArchiveCacheInvalidator` (`cmd/opencircuit/main.go` lines 329, 335, 336, 635, 1095). `seo` already imports `publicapi` (for `About`), so `publicapi` **cannot** import `seo`. Instead:

- `seo.Site` gains `OnInvalidate(fn func())`, which appends `fn` to a mutex-guarded slice; `Invalidate()` calls each hook after clearing its own caches, in registration order.
- `mountAndServe` calls `site.OnInvalidate(publicReg.Invalidate)`.
- Do **not** name the hook anything ending in a bare `Invalidate()` method on a new type, and do not wrap `site` in a composite invalidator: `invalidator_satisfier_guard_test.go` requires `*Site` (and `*Renderer`) to be the only satisfiers, and `seo_wiring_test.go` proves the handlers hold the identical `*Site`. `OnInvalidate(func())` changes neither.

**Logging: one `slog` record per call, in `Invoke`.** Level Info, message `public api call`, attributes in this order:

| Key | Value |
|---|---|
| `tool` | `op.Name` |
| `params` | `logParams(in)`: `json.Marshal(in)` → `map[string]any` → if `"query"` is a string longer than `LogQueryRunes` (64) runes, cut it there and append `…` → re-marshal to a string. nil `in` → `{}`; any failure → `"?"`. |
| `latency_ms` | `float64(elapsed.Microseconds())/1000` |
| `cached` | bool, true on a cache hit |
| `error` | only on failure: the `*api.Error`'s `Code` via `errors.As`, else `"internal"`. **Do not call `api.AsError` here**: it logs 500s itself, and the adapter already calls it, so the error would be logged twice. |

No IP, user agent or header is logged. The logger is `Registry.SetLogger(*slog.Logger)`; nil or unset means `slog.Default()`.

The admin limiters are separate instances. The 429 is the v1 envelope with `Retry-After` rounded up (`math.Ceil`) and `no-store`. On REST it carries CORS `*`, because `cors` wraps the inner mux. On `/mcp` every method counts, preflight included. On REST, `OPTIONS`, `openapi.json` and the 404/405 catch-all do not count. Both are sensible: they are cheap, static and do no store reads.
