# 0730 — The public MCP server has no rate limit, request logging or caching

| | |
|---|---|
| **Status** | open |
| **Platform** | Server |
| **Module** | mcp, middleware |
| **Phase** | 12 — Public MCP |
| **First seen** | 2026-11-19 |

## Description

The public MCP server (`#0729`) needs no auth, so it needs its own abuse protection. The handoff asks for:

- a per-IP rate limit;
- server-side caps (already in `#0729`);
- parameterized queries;
- logging of each tool call;
- short-lived caching for the list tools.

## Acceptance criteria

- [ ] A per-IP limit of 60 requests/minute on `/mcp`, kept separate from the admin API-key limiter so the two budgets never interact. Reuse the existing limiter type if one fits. The client IP comes from the same trusted-proxy logic the rest of the service uses behind Apache, not a raw `X-Forwarded-For`. Over the limit, it returns HTTP 429 with `Retry-After`. A test drives that.
- [ ] Each tool call logs, through `slog`, the tool name, its params (with `query` truncated) and latency. No new IP retention beyond what existing request logs do.
- [ ] `list_upcoming_events`, `search_events` and `list_newsletter_issues` results are cached for 60 s. The cache is invalidated by the same `seo` invalidation hook that publishing or editing an event or campaign already fires, so an edit shows up immediately. A test proves the invalidation.
- [ ] The limit and TTL are named constants in one place, with the handoff's numbers.
