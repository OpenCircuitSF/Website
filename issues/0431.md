## Description

`docs/deployment.md` carries a **class** of notes written before the 2026-08-25
deploy, each explaining that something could not be verified because the
infrastructure did not exist. The deploy falsified all of them at once, and they
were never swept.

Confirmed by the orchestrator:

| Where | Says | Reality (`CLAUDE.md` §7) |
|---|---|---|
| Production-facts table | `Currently served \| the static placeholder (`placeholder/`)` | **This project, since 2026-08-25. The static placeholder is gone.** |
| First-admin-login section | "no SES account exists to send the recovery email through yet… and **no live instance**" | SES is live; the instance serves the site |
| TLS section | "**Not run anywhere** — this needs a real, publicly resolvable hostname" | `www.opencircuitsf.com` resolves and serves |
| Backups limitations | "none of those AWS resources exist yet" | the account and instance role exist |

**Found by `#0426`'s review**, which called it *"a class, not an instance"* —
and noted the implementer neither fixed nor mentioned the first-admin-login one,
the only disclosure gap in an otherwise careful pass.

## Root cause

`docs/deployment.md` accreted its "not run / does not exist / cannot be
checked" language across many passes written before 2026-08-25, and each
subsequent correction pass (`#0414`, `#0418`, `#0421`, `#0423`, `#0426`)
fixed only the specific claim it was dispatched to fix, leaving sibling
occurrences of the same shape elsewhere in the ~2,100-line file untouched —
several of them directly contradicted by a correction already sitting a few
lines above or below them in the same section, which nobody had reconciled.

## Fix

Swept the whole file (not a string search) for the shape described in the
issue: any claim that something cannot be checked, does not exist, or has
not been run, premised on the pre-2026-08-25 state. For each genuine hit
outside the Backups section, added a dated `**Corrected `#0431`, ...**`
paragraph ahead of the original text (kept as an "Original note, left for
context" block) that re-derives the current state and explains the
per-occurrence judgement, per the issue's `#0271`/`#0072` framework:

- **Production-facts table** (`Currently served`, `Already on the box`): this
  table is explicitly a current-state record (the issue's own least-ambiguous
  call), so both rows were rewritten outright rather than left with an
  "original note" — updated to say the site is served by `opencircuit.service`
  since 2026-08-25, re-verified against a live request.
- **"SES is not configured yet" section**: genuinely ambiguous — the heading
  and "deliberate, at the user's direction" framing is historical, but "What
  this costs until SES is live" reads as current instruction and is now

## Why one pass rather than piecemeal

Five separate issues this session have each corrected one or two of these
(`#0414`, `#0418`, `#0421`, `#0423`, `#0426`), and each found more on arrival
than its filing named. The remainder share a single cause — **notes written
against a pre-deploy world** — so a sweep for the *shape* will finish the job
where another string-hunt will not.

The shape to search for: any claim that something cannot be checked, does not
exist, or has not been run, **premised on the pre-deploy state**. Not just
`us-west-2` or `hello@`.

## The judgement this needs

A pre-deploy verification note is genuinely ambiguous under this project's own
conventions:

- Under `#0271`'s `## Scope` it can be **historical** — an honest record of what
  was and was not verified at the time, which is exactly what a verification
  section is for.
- Under `#0072` it can be **maintained** — a runbook statement a reader will act
  on today.

**Decide per occurrence and say why.** The distinguishing question is whether a
reader today would take it as instruction or as history. A dated "verified as of
2026-08-24" reads as history; a bare "Not run anywhere" reads as current state.

The Production-facts `Currently served` row is the least ambiguous: that table is
explicitly a current-state record, and `CLAUDE.md` §7 already contradicts it.

### 1. A falsified premise the sweep missed, inside a section it edited

existing `never a production setting` clause; `MAILER_NOOP=true` is refused
outright on a production `BASE_URL` by `cmd/opencircuit/main.go`'s
`checkMailerNoOp` (`CLAUDE.md` §10), and the sentence should not read as
though it were an option on the box.
