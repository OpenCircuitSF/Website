## Description

`#0327` made `gc --all` refuse to drop `opencircuit_test_template`. `drop` was
not changed, and it still will: `name_for template` resolves to
`opencircuit_test_template` (and, since `#0208`, so does `name_for TEMPLATE`).

So `scripts/testdb.sh drop template` — which reads like "drop my scratch
database called template", the same shape as `drop 0324` — destroys the shared
template every agent clones from. Rebuilding it is `scripts/testdb.sh template`,
so this is recoverable rather than catastrophic, but it stops every concurrent
agent's `create` until someone notices and rebuilds.

The defect is **pre-existing**, not introduced by `#0327`. What `#0327` created
is the *inconsistency*: two commands with the same blast radius, one now
guarded and one not. An agent that reads `#0327` and concludes the template is
protected is wrong for exactly one command.

This is the same class as `#0207` (`db-reset.sh` refusing without `--force`)
and `#0150` (`gc` refusing without `--all`): a destructive default on a shared
resource, cured by requiring an explicit second signal.

## Acceptance criteria

1. `scripts/testdb.sh drop template` (and `drop TEMPLATE`) refuses by default,
   naming what it would destroy and how to rebuild it
   (`scripts/testdb.sh template`).
2. An explicit override flag performs the drop, consistent in spelling with the
   existing `--all` / `--force` conventions in `testdb.sh` and `db-reset.sh`.
3. Dropping an ordinary per-agent scratch database (`drop 0324`) is unaffected
   and still needs no flag.
4. The refusal reports live connections the way `#0150`'s `gc` guard does, so a
   template in use is never dropped out from under a running agent.
5. Covered by an assertion in `scripts/testdb_gc_guard_test.sh` (or a sibling
   external harness), following §8: mutate a COPY, assert exit code and output
   from OUTSIDE, prove the assertion is sensitive by mutation, fail closed on an
   empty extraction. Never run the destructive path against the real pool.
