## Description

`godotenv` strips a backslash escape; systemd's `EnvironmentFile=` keeps it.

    PRICE=cost\$FOO

loads as `cost$FOO` under godotenv and stays `cost\$FOO` under systemd. The
value-shape scan built by `#0441` and widened by `#0450` and `#0453` does not
flag it.

**This is the largest remaining hole in that scan, and it was measured, not
guessed.** `#0453`'s reviewer brute-forced **111,110** generated values through
both readings: the guard flagged 14,637 with **zero false positives**, and of
the values that genuinely diverge and go unflagged, **3,024 all contain a
backslash — and none of the unflagged divergences lack one.** The backslash is
the whole remaining family.

This is **distinct from the trailing-backslash continuation shape** the scan
already covers: that one is about a line ending in `\`, this one about a
backslash escaping a character mid-value.

## Why it matters

`.env.example` is copied verbatim onto production as
`/etc/opencircuit/config.env` (`#0423`), so both parsers read the same bytes. A
value that silently loses a character under one and keeps it under the other is
the **silently-wrong-value** half of this bug class — the service starts, and
something downstream is subtly wrong. That is harder to notice than a boot
failure, which is the half `#0429` already fixed.

`.env.example` holds zero `$` and zero `\` bytes today, so nothing is currently
wrong; this is about the next line someone writes.

## Acceptance criteria

1. The scan flags backslash-escaped values, naming which parser disagrees and
   what each reads.
2. **Verify the library behaviour by probing `godotenv.Unmarshal` at runtime**,
   not by reading its regex. Every question in this lineage that was settled by
   reading the pattern was settled *wrongly* — the orchestrator's own inverted
   table row in `#0441`, and the group-numbering bug in `#0453`. Read the module
   via `go list -m -f '{{.Dir}}' github.com/joho/godotenv`; never scan the
   filesystem (`CLAUDE.md` §5).
3. Distinguish this from the existing trailing-backslash continuation shape, in
   both the code and the failure message. Decide whether it is a fifth shape or
   an extension, and record which — `#0453` chose extension for `$(…)` because a
   fifth shape means a fifth branch and a fifth table row, which is structure
   criterion 4 protects.
4. **Do not touch** the floor (`minScannedEnvExampleAssignments`),
   `checkScannedFloor`, or the four-shape structure. Three reviews have verified
   that machinery, including that the fail-closed proof passes the **package
   constant** rather than a hardcoded number, which is why §8's external-harness
   rule does not apply.
5. **No false positives.** `#0453`'s review established the current scan has
   zero across 111,110 generated values; re-derive that number for your widened
   pattern and state it. A false positive here fires on the production template.
6. **No new mechanism** beyond the branch and its message (§8, `#0258`).
