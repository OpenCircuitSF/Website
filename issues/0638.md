## Resolution notes

> 🟢 Resolved 2026-11-05 — A workshop whose start time has passed gets no new hand-posted ShortLinks or drafts from opening it or from Start (server no-op, `hand_links_pending` false, SPA check), existing rows stay as they are, and upcoming workshops, including one starting exactly now, behave as before.

## Description

Since `#0627`/`#0628`, opening a workshop in Outreach automatically creates ShortLinks and hand-posted drafts for TikTok, Instagram Reels and YouTube Shorts (`POST /admin/workshops/{id}/outreach/hand-links`). That also happens for a workshop that has already started or ended, so **Post by hand** and Results count posts that will never be made.

**User's decision, 2026-11-05:** "yes to … 3" — past workshops skip the automatic ShortLinks.

## Root cause

The hand-links pass (`#0623`) and Start's link pass had no notion of the event date, so opening a past workshop made new hand-posted ShortLinks and drafts for an event that was already over.

## Fix

As planned: `eventStarted` (start before now; undated never started) gates `EnsureHandLinks` (empty 200), the panel's `hand_links_pending`, and Start's hand-posted channels; the SPA also checks `eventStarted` before calling. Done in one commit with `#0630` and `#0629`. One small deviation: `beforeEvent()` is called after every env in `admin_outreach_handlinks_test.go`, including those that also call `handSetup` (harmless repetition).

### Decisions

1. **"Past" means started: `starts_at` before now.** That is the codebase's existing rule. `workshops.Store.ListVisible` puts a workshop in past when `starts_at < now` and in upcoming when `starts_at >= now` or there is no date. `outreachList.ts` (`upcomingPublished`, `pastWithOutreach`) uses the same rule. So a workshop starting exactly now still counts as upcoming, and an undated one is never past. `ends_at` is not used.
2. **The server enforces it in three places.** (a) `EnsureHandLinks` returns a 200 report with nothing done for a started workshop. It is a 200, not a 409, so a tab loaded a minute before the start does not show the "could not be made" note. (b) The panel's `hand_links_pending` is false for a started workshop, so the SPA never asks. (c) **Start** leaves out the hand-posted channels for a started workshop. Opening a past workshop that has no outreach auto-starts it, and Start's link pass would otherwise make the same hand-posted links. Automatic-channel and flyer links from Start do not change. Existing rows are never touched: every path above only skips work.
3. **The SPA also checks the date** before calling the hand-links route. It uses a new pure helper, `eventStarted`, in `web/src/lib/outreachList.ts`. The call site is `OutreachPanel.svelte`, so **`OutreachWorkshop.svelte` is not edited**, which leaves it clear for the `#0632`/`#0633`/`#0634` batch.
4. **`#0630` item 1 (a client goes away mid-pass): fixed.** `EnsureHandLinks` runs the whole pass on `context.WithoutCancel(r.Context())`, covering both the link creation and the draft loop. The 45 s `outreachLinksTimeout` inside `ensureLinksFor` still bounds the ShortLinks part. A reload or closed tab then no longer cuts the pass between "link made" and "draft made", which was the only way to strand a slot.
5. **`#0630` item 2 (a deleted draft comes back): accepted, not fixed.** Fixing it needs a record of the delete, which means a new column or table, and so a migration. The trigger needs a Draft click while ShortLinks is down, then a delete, then the next pass. The result is one draft coming back, once; the user deletes it again and it stays deleted, because its slot now has a link. Production data cannot hit it today (`#0623`'s `## Fix`). Record the reason in the doc comment.
6. **`#0630` item 3 (two tabs making a duplicate upstream link): document it, don't fix it.** Locally, each slot still holds exactly one link and at most one draft: `outreach_links` is unique per slot, and drafts are only made for links the same pass inserted. The only cost is one ShortLinks link that nothing points to, has no clicks, and never appears on this site. A real fix belongs upstream, as a unique index in ShortLinks (a separate repo). A local fix would be a per-outreach lock, which brings a wait-or-busy path, a new report state and new SPA wording. That is not worth it for a zero-click orphan. Item 4 makes overlap a little more likely, because a reloaded tab's old pass keeps running beside the new one. The committed overlap test below pins the local guarantees.
7. **`#0629`: remove `GET`/`POST /admin/workshops/{id}/outreach/links` and their SPA helpers.** No SPA code calls them; only Go tests and the test mux do. No doc, PRD section or route-table guard names them (checked: `docs/`, `PRD.md`, `cmd/opencircuit/*_test.go`). `linksEmptyState`, `linkRowLabel`, `linkClicksLabel` and `draftAllMessage` in `outreachLinks.ts` are also dead (tests only). `draftAllMessage` and `linksEmptyState` name controls that no longer exist ("create the missing links first", "Create missing links"), so they go too. `linkReportMessage` stays, because it words Start's `link_report`, but its "use Create missing links" text is replaced.
