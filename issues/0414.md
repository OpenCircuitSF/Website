## Description

`#0271` moved the public contact address to `contact@`. Production now sends as
`contact@mailing.opencircuitsf.com` with `Reply-To: contact@opencircuitsf.com`,
verified read-only on the box.

**Three runbook lines still document the old local part**, and one commit wrote
both spellings at once:

| Where | Says | Should be |
|---|---|---|
| `docs/email-setup.md` (two places) | `hello@mailing.opencircuitsf.com` | `contact@mailing.opencircuitsf.com` |
| `docs/aws-iam-setup.md` | `hello@mailing.opencircuitsf.com` | same |

Commit `049dd4d` wrote those lines **and** wrote the correct
`contact@mailing.opencircuitsf.com` into `docs/configuration.md` in the same
change. So the runbooks contradict the reference doc, inside one commit.

### The PRD's configuration block is separately stale, and doubly so

`PRD.md` §9's environment block still reads:

	EMAIL_FROM=Open Circuit SF <hello@opencircuitsf.com>
	EMAIL_REPLY_TO=hello@opencircuitsf.com

Wrong local part **and** wrong domain — production's `From:` sits on the
`mailing.` subdomain because that is the verified SES identity. The apex form
cannot send.

The same block reads `AWS_REGION=us-west-2`; production is **`us-east-1`**
(`CLAUDE.md` §7). So two independent facts in one block are wrong.

**This block is maintained, not frozen.** `#0271`'s `## Scope` exempts the PRD's
*decision log* — `PRD.md` §14's Q2 row is correctly left alone — but §9's env
block was corrected in place by `#0072` with a dated note, precisely because a
stale value there is a defect. `#0271`'s reviewer reached the same verdict.

### Three softer stragglers, same cause

- `docs/deployment.md` open item 4 still says the identity is "undecided…
  defaults to `hello@`". Its items 2, 5, 6 and 7 are stale for the same reason —
  it is an unupdated mirror of `CLAUDE.md` §10's table.
- `docs/obstacles.md` says there is "no decision on who reads
  `hello@opencircuitsf.com`". Both halves are settled.
- `scripts/dev.sh` carries a parenthetical claiming production is `hello@`.

## Why this matters now

The user is about to send their first real newsletter. These are the documents
an operator reads while doing that, and the two that matter most — the SES
runbook and the IAM runbook — name an address that **cannot send**, because the
identity verified in SES is the `contact@` one.

## Acceptance criteria

1. `docs/email-setup.md` and `docs/aws-iam-setup.md` name the address production
   actually uses. **Verify it against the box, read-only, rather than copying it
   from this issue** — the whole failure class here is a documented value nobody
   re-measured.
2. `PRD.md` §9's env block matches production for **both** the sending identity
   and the region, following `#0072`'s dated-note convention for that block.
3. The three softer stragglers are corrected or explicitly left with a reason.
4. **Historical records stay intact** — `PRD.md` §14's decision-log row and the
   `issues/*.md` files quoting the old address must not be rewritten. `#0271`'s
   `## Scope` explains why: rewriting them falsifies the history the citation
   guards exist to protect. If you think §14's row should get the
   struck-plus-resolved-date convention some sibling rows use, say so rather
   than doing it silently.
5. **No mechanism** (`#0330`/`#0347`/`#0356`/`#0381`).
6. If any Go comment or a file cited by one changes, run `./internal/handlers/...`;
   editing `CLAUDE.md` means **both** that and `./internal/db/...` (§5's
   repo-wide-guard table). Editing `PRD.md` means `./internal/db/...`. Per §5
   name the specific tests that ran. No Go-file-plus-line-number citation
   (`#0352`), scanned with `python3` bytes rather than BSD `grep -P`.
