## Description

Brennan, 2026-10-18: "I need to delete these posts. Will I be able to post
the corrected post when this is fixed? We need a way to fix this."

Posts 1 (Bluesky) and 4 (Mastodon) went out with dead short links
(`#0603`). Once a post is `posted`, the app can't take it down or send it
again, and Reset refuses while anything is posted. Bluesky posts can't be
edited at all.

Three idempotency hazards make a naive "set it back to draft" wrong:
- **Bluesky:** `postBluesky` uses a deterministic record key,
  `bluesky.TID(job.CreatedAt, id)`. `Client.Post` first calls `getRecord`
  and treats an existing record as already posted. Re-creating with the
  same rkey after a delete is fragile, because the AppView caches by URI.
- **Mastodon:** `PostStatus` sends
  `Idempotency-Key: opencircuitsf-outreach-post-<id>`. Mastodon remembers
  that key for about an hour and would hand back the deleted status instead
  of posting.
- **Bodies:** a posted row's body keeps the old dead URL. `#0603`
  deliberately repairs only unsent bodies, so a re-sent body must be
  refreshed from the row's current (repaired) `short_url`.

## Resolution

"Delete and redo" is in place for posted Bluesky and Mastodon posts.
`POST /admin/outreach-posts/{id}/takedown` deletes the remote post, then
returns the row to draft with `attempt_generation` incremented and the body's
link refreshed to the repaired `short_url`. A post already gone counts as
deleted. A re-send uses a new Bluesky rkey and a new Mastodon
Idempotency-Key, so it creates a new post. Migration `000044` adds the
column.

## Resolution notes

- Production path for posts 1 and 4, which Brennan already deleted by hand:
  after the deploy applies 43 and 44, press Delete and redo on each.
  - Bluesky: the stored `at://did:plc:…/app.bsky.feed.post/<rkey>` parses.
    getRecord answers `400 RecordNotFound`, which counts as gone, and no

### How it works

- Takedown is two steps so no DB lock is held across a network call: `Store.CheckTakedown` (posted, has remote id, no live queue row), the remote delete, then `Store.CompleteTakedown`, which takes `FOR UPDATE`, re-checks status, remote id and live queue rows, and resets the row.
- Keys: `outreach.BlueskyRKey(createdAt, id, generation)` is the old `TID(createdAt, id&1023)` at generation 0 and adds one second per generation to the TID timestamp after that. `MastodonIdempotencyKey(id, generation)` is the old key at 0 and appends `-g<generation>` after. Both are used by the publisher.
- Body: `RefreshBodyLink` derives the old form from the row's `/u/` short_url, replaces it only as a whole URL (not before `[A-Za-z0-9_/-]`), and leaves `{link}` bodies and bodies already holding the current link alone.
- Already gone: Bluesky reads the record with getRecord first (a PDS may answer deleteRecord on a missing record with 200, so existence is checked, not assumed) and sends no write when it is missing; a RecordNotFound or 404 from deleteRecord also counts. Mastodon treats 404 and 410 as gone. The audit row records `already_gone`.
