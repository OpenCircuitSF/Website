## Description

The last three deploys (v0.14.0, v0.15.0, v0.16.0 on 2026-11-17) each ended with `✗ ERROR: https://www.opencircuitsf.com/health did not return healthy` and exit 1, although the deploy had succeeded: `/health` returned 200 `{"status":"ok","db":"ok"}` a few seconds later and the journal showed the new version listening with no errors. `scripts/deploy.sh` line 387 makes a single `curl -fsS --max-time 15 "$PUBLIC_URL/health"` immediately after `systemctl restart`; Apache answers 503 while the service is still starting.

A deploy that reports failure on success trains the operator to ignore the red line, which is the line that must be believed when the deploy really is broken.

Fix: retry the health check for a bounded window (e.g. up to ~30 s, a few seconds apart) and fail only if it never returns healthy; print the attempt count. Also confirm the healthy response comes from the new binary (the reported version or commit, as the earlier artifact step already prints) so a stale process can't satisfy it.

## Plan

Planned 2026-11-17 (Opus · medium). Three edits. Production is never touched by any test, and nothing is ever bound to a fixed port.

### What the live service can tell us about its version (findings)

- `GET /health` (`internal/handlers/health.go`) returns only `{"status":"ok","db":"ok"}` (200), or `{"status":"degraded",…}` (503). It carries no version.
- `GET /admin/version` (`#0516`) has version and commit, but it needs an admin session, so the script cannot use it.
- `GET /api/v1/openapi.json` is public and its `info.version` holds the **semver only**, with no commit. A redeploy at the same version (a fix that did not bump the version const) would pass a semver check against a stale process, so that check proves nothing here. **Do not use it, and add no new public version field.** A public commit hash is a fingerprint and would buy nothing that the ssh check below cannot.
- Today's line 390 check (`'$BIN_PATH' --version`) proves that the **file** on disk is the new build. It does not prove that the **running process** is. That is the gap the issue names.

**The identity check therefore runs over the existing ssh channel and compares the running process's executable bytes.** `systemctl show -p MainPID --value "$SERVICE"` gives the PID. `sudo sha256sum /proc/$pid/exe` hashes the image that process is actually executing. Reading `/proc/PID/exe` works even when the file has since been replaced, because it then reads the deleted inode. That hash must equal `sha256sum "$BIN_PATH"` and `sha256sum "$DEST/opencircuit"`. Line 331 has already shown that `$DEST/opencircuit --version` reports `$COMMIT`. So the chain is: running process = installed file = artifact that reported this commit. A process left over from before `install` maps the old inode, so its hash differs and the check fails. Passwordless sudo is already checked in `HOST_CHECK`, and the unit runs as `User=opencircuit`, so `sudo` is needed to read the exe link. Keep the existing `--version` check as well, since it is free and gives a readable commit line.

### 1. `scripts/deploy.sh`

**a. Health retry block.** Replace lines 386–389 with a marker-delimited block and a call to it. The markers follow the `GATE-0424` convention so that the guard can extract the file's own bytes:

```bash
# HEALTH-0712-BEGIN
HEALTH_ATTEMPTS="${HEALTH_ATTEMPTS:-10}"   # ~30s window at the default interval
HEALTH_INTERVAL="${HEALTH_INTERVAL:-3}"    # seconds between attempts (sleep accepts 0.1)
HEALTH_MAX_TIME="${HEALTH_MAX_TIME:-5}"    # per-attempt curl --max-time
LAST_HEALTH_CODE=""; LAST_HEALTH_BODY=""
wait_healthy() { … }
# HEALTH-0712-END
```

How `wait_healthy URL` behaves:
- It loops `i=1..HEALTH_ATTEMPTS`. Each pass runs `out="$(curl -sS --max-time "$HEALTH_MAX_TIME" -w '\n%{http_code}' "$1" 2>&1)" || true`, without `-f`, so that a 503's body is kept. Split the result with `code="${out##*$'\n'}"` and `body="${out%$'\n'*}"`. `$'\n'` works in bash 3.2. Do not use `mapfile` (§8).
- The response is healthy **only if** `code` is `200` **and** `body` contains `"status":"ok"`. A 200 with a degraded body is not healthy.
- It prints one `info` line per attempt: `attempt i/N: HTTP <code>`.
- It stores `LAST_HEALTH_CODE` and `LAST_HEALTH_BODY` every pass.
- It sleeps `HEALTH_INTERVAL` only **between** attempts, never after the last one.
- On success it prints `ok "healthy after i/N attempt(s)"` and returns 0. After N failed attempts it returns 1.
- Up front, check that `HEALTH_ATTEMPTS` is a positive integer (`case` on `''|*[!0-9]*`, then `-ge 1`). Otherwise `die`, because a zero would make the loop vacuous.

Call site:

```bash
if ! wait_healthy "$PUBLIC_URL/health"; then
  die "$PUBLIC_URL/health never returned healthy in $HEALTH_ATTEMPTS attempts ${HEALTH_INTERVAL}s apart — last response: HTTP ${LAST_HEALTH_CODE:-none}: $(printf '%s' "$LAST_HEALTH_BODY" | head -c 500) … inspect: ssh $DEPLOY_HOST journalctl -u $SERVICE -n 50"
fi
```

Keep the "may be up but unhealthy / something in front is stale" wording.

**b. Identity block** (`# IDENTITY-0712-BEGIN` / `# IDENTITY-0712-END`). It runs after the existing `--version` check and holds two things:

- `IDENTITY_CHECK`: a **single-quoted** remote script, sent the way `RESTORE_CHECK` is, so it needs no escaping. Values go in as positional args: `printf '%s' "$IDENTITY_CHECK" | ssh "$DEPLOY_HOST" bash -s -- "$SERVICE" "$BIN_PATH" "$DEST/opencircuit"`. Its body:

  ```
  set -e
  pid="$(systemctl show -p MainPID --value "$1")"
  case "$pid" in ''|0) echo "no MainPID for $1"; exit 3 ;; esac
  echo "pid $pid"
  sudo sha256sum "/proc/$pid/exe" "$2" "$3"
  ```

  Add `# shellcheck disable=SC2016` with the same justification `RESTORE_CHECK` uses.
- `confirm_live_identity OUTPUT`: a local, pure function with no ssh inside it.
  - From `sha256sum`'s three lines, it takes the hash for the `/proc/*/exe` line, the `$BIN_PATH` line and the `$DEST/opencircuit` line, using `awk '{print $1}'` by line order.
  - It requires all three to be non-empty, 64 hex characters, and equal.
  - On success it prints `ok "running process (pid N) is executing the deployed binary (sha256 <first12>…)"`.
  - On failure it `die`s and names which hash differs. If the exe hash differs, the message reads "a stale process is still serving; restart did not take".

  The call site is `ID_OUT="$(printf … | ssh … || true)"; confirm_live_identity "$ID_OUT"`. Keeping the comparison local and pure is what makes it testable without a host.

**c. Dry-run plan.** Replace line 306's single curl line with lines that print the retry parameters (`curl /health up to N attempts, Ns apart`) and the identity check (`ssh … bash -s -- <service> <bin> <dest>/opencircuit  # MainPID exe sha256 == installed == shipped`).

**d. Docs in the script.** Update header step 8 (lines 51–52) and the `PUBLIC_URL` config comment to mention the retry and the `HEALTH_*` overrides. In `docs/deployment.md` §"`scripts/release.sh` and `scripts/deploy.sh`", change "installs, restarts, and health-checks" to "…health-checks with a bounded retry, and confirms the running process is the shipped binary". That is a one-clause edit and is optional.

### 2. New `scripts/deploy_health_guard_test.sh`

Model it on `scripts/deploy_guard_test.sh`, in the same style:
- `set -uo pipefail`, not `-e`.
- Exit codes: 0 pass, 1 regression, 2 harness broken.
- `WORKDIR="$(mktemp -d "$REPO/.scratch/deploy_health_guard.XXXXXX")"`.
- A trap that kills **only the PID it recorded** and removes `WORKDIR`.
- `PASS:` and `FAIL:` lines.

It never runs `scripts/deploy.sh` as a whole and never reaches the network beyond 127.0.0.1.

- **Extraction.** Extract `die()`, `ok()` and `info()` with `grep -m1 '^die(){'` and friends, plus the awk sweep between each marker pair. Extraction producing nothing is exit 2. **Exactly-once anchors** (§8, `GUARD-0208`): the BEGIN and END markers of both blocks, and the `die()`, `ok()` and `info()` definitions, each appear exactly once. Otherwise exit 2.
- **Stub server.** Write a small `python3 -I` script into `WORKDIR`. It binds `127.0.0.1:0` (an ephemeral port, §8b) and writes its port to a file. Fixed ports are never used.
  - It serves `/health` according to `argv`: `fail_n body_mode`. The first `fail_n` requests get `503` with `{"status":"starting"}`, and the rest get `200`. With `fail_n = -1` it always returns 503. `body_mode=degraded` returns `200 {"status":"degraded","db":"error"}`.
  - It answers any other path with 404.
  - It overrides `log_message` to stay silent.
  - The harness starts it in the background, records `$!`, and waits for the port file with a bounded loop of at most 50 × 0.1 s. It confirms the server is its own by checking that `GET /health` answers with the stub's body shape.
  - Use one server instance per scenario, killed by PID afterwards.
- **Runner.** Write a standalone harness file of `#!/usr/bin/env bash`, `set -euo pipefail`, the extracted `die`/`ok`/`info` and the extracted HEALTH block, then `wait_healthy "$URL" || die "never healthy: HTTP $LAST_HEALTH_CODE: $LAST_HEALTH_BODY"`. Run it with `HEALTH_INTERVAL=0.1 HEALTH_MAX_TIME=2` set in its environment. That stand-in `die` call mirrors the real call site's content well enough. The assertions are about the loop.

Scenarios:

| # | Stub | Env | Assert |
|---|---|---|---|
| A | `fail_n=2` | `HEALTH_ATTEMPTS=5` | rc 0; output has `attempt 1/5: HTTP 503`, `attempt 3/5: HTTP 200`, `healthy after 3/5`; no `attempt 4/5` |
| A′ (non-vacuity) | `fail_n=2` | `HEALTH_ATTEMPTS=1` | rc ≠ 0. This proves A passes *because* of the retry: the same stub defeats a single attempt, which was the pre-fix behaviour. It is an env change, not a `sed` mutation, so the assertion stays falsifiable by what it measures (§8, `#0304`) and does not depend on the implementer's exact loop text. |
| B | `fail_n=-1` | `HEALTH_ATTEMPTS=3` | rc ≠ 0; `attempt 3/3`; output contains `503` **and** `starting` (last response shown); no `attempt 4/3`; wall time under 10 s (`SECONDS`), so the run is bounded |
| C | `degraded` | `HEALTH_ATTEMPTS=2` | rc ≠ 0. A 200 alone is not healthy; the body is checked. |
| D | none: a port taken from a stub that was started and then killed | `HEALTH_ATTEMPTS=2` | rc ≠ 0, `HTTP 000`, bounded |
| E | — | `HEALTH_ATTEMPTS=0` and `HEALTH_ATTEMPTS=x` | rc ≠ 0 (a vacuous loop is refused) |

Identity, with no server: run the extracted IDENTITY block plus `die`/`ok`/`info` with `confirm_live_identity "<fixture>"`. Build each fixture from `printf` with three `sha256sum`-shaped lines (`<hash>  /proc/123/exe`, …):
- three equal hashes → rc 0, and the output names the pid and hash prefix;
- an exe hash that differs → rc ≠ 0, and the message mentions the stale process;
- the installed hash differs from the shipped one → rc ≠ 0;
- empty output, or only `no MainPID…` → rc ≠ 0.

Also `bash -n` the extracted `IDENTITY_CHECK` remote-script text, which the harness obtains by sourcing the block and printing `$IDENTITY_CHECK`. That catches a syntax error in the part that only ever runs on the host.

Wire it into `scripts/check.sh`'s `guards` arm right after `deploy_guard_test.sh`, as `step "scripts/deploy_health_guard_test.sh (#0712)"; run scripts/deploy_health_guard_test.sh`, with a short comment: no database, ephemeral 127.0.0.1 port, about 2 s. Add it to the header comment's `guards` list (around line 32).

## Obstacles

- **No production access in tests.** This one is designed out: the HTTP check goes to a 127.0.0.1 stub, and the identity check is split into a host script (only `bash -n`'d locally) and a pure local comparison that is fed from fixtures. Nothing calls `ssh`.
- **Ports (§8b).** The stub binds an ephemeral port and reports it through a file. The harness checks the stub's body shape before trusting it and kills by recorded PID, never by `pkill`.
- **Tools.** `python3` and `shellcheck` are present (`/opt/homebrew/bin`). `curl` is already in `deploy.sh`'s workstation preflight. `sleep 0.1` works on macOS.
- **bash 3.2 / zsh (§8).** No `mapfile` or `${x,,}`. Run every ad hoc check through `bash -c` or the script itself, never pasted into the tool shell.
- **`scripts/check.sh guards`** binds `:5173` because of `dev_guard_test.sh`. Avoid it, as above.
- **Host-side assumptions to confirm on the next real deploy.** `systemctl show -p MainPID --value` (systemd ≥ 230; AL2023 ships 252) and `sudo sha256sum /proc/PID/exe` (root can read any process's exe) are standard, but they are only proven on the box. Note this in `## Verification`; it is not a blocker.
- **Concurrency.** Other agents are on `#0639`, `#0497` and `#0657`. Run `git status --porcelain -- scripts/check.sh` before editing `check.sh`, and stage only `scripts/deploy.sh`, `scripts/deploy_health_guard_test.sh`, `scripts/check.sh`, `docs/deployment.md` (if edited) and `issues/0712.md`.

## Implementation

Implemented 2026-11-17 (Opus · low), following the plan.

- `scripts/deploy.sh`: `HEALTH-0712` block (`wait_healthy`, `HEALTH_ATTEMPTS`/`HEALTH_INTERVAL`/`HEALTH_MAX_TIME`, default 10 × 3 s, 5 s per attempt; healthy = HTTP 200 and a body containing `"status":"ok"`; prints `attempt i/N: HTTP <code>`, sleeps only between attempts; refuses a non-integer or zero attempt count) and its call site, whose `die` shows the last code and body and the journalctl hint. `IDENTITY-0712` block after the existing `--version` check: single-quoted `IDENTITY_CHECK` remote script piped over ssh with positional args, and a pure local `confirm_live_identity` that requires the `/proc/<pid>/exe`, installed, and shipped hashes to be 64-hex and equal (distinct messages for installed≠shipped and for a stale process). Dry-run prints the retry parameters and the identity ssh line; header step 8 and the config comment updated.
- `scripts/deploy_health_guard_test.sh` (new): exactly-once anchors for both marker pairs and `die`/`ok`/`info`; extracts the file's own bytes; `python3 -I` stub on an ephemeral 127.0.0.1 port, ownership probed via a 404 path, killed by recorded pid; scenarios A, A′, B, C, D, E and the identity fixtures, plus `bash -n` of the remote script.
- `scripts/check.sh`: wired into the `guards` arm after `deploy_guard_test.sh`, and named in the header list.
- `docs/deployment.md`: one-clause update.

Deviations: scenario E tests `0` and `x` only. An empty `HEALTH_ATTEMPTS` takes the default via `${…:-10}`, which is the intended behaviour, not a vacuous loop. The identity hashes are picked by pattern (the `/proc/*/exe` line, then the first and second other hash lines), not purely by line order, so the `pid N` line cannot shift them.

## Review notes

Reviewed 2026-11-17 (Opus · medium). **Pass — resolved.**

The criteria were re-verified independently.

- **Retry (criterion 1).** `wait_healthy` treats a response as healthy only when it is HTTP 200 **and** the body carries `"status":"ok"`. It sleeps only between attempts. After the last attempt it returns 1, and the call site's `die` shows the last code, the first 500 bytes of the body and a journalctl hint. The loop is bounded. At the defaults (10 × 3 s, 5 s `--max-time`), fast 503s take about 27 s, and the worst case, where every attempt times out, is about 77 s. The inline comment "~30s window" describes only the fast-503 case. That is accurate enough, and nothing needs to change.
- **Identity (criterion 2).** The plan's substitution holds up. `/health` carries no version, and openapi's semver cannot tell two same-version builds apart. The `/proc/<MainPID>/exe` hash, compared to both the installed and the shipped binary, chains the running process to the artifact whose `--version` named `$COMMIT`. A stale process maps the old inode and fails with "stale process". A failed install makes the installed hash differ from the shipped one and fails with "install did not take". The orchestrator confirmed both host-side commands read-only on production (`systemctl show -p MainPID --value`, `sudo sha256sum /proc/<pid>/exe` = installed hash).
- **Remote quoting.** `IDENTITY_CHECK` is a single-quoted assignment piped to `ssh … bash -s -- "$SERVICE" "$BIN_PATH" "$DEST/opencircuit"`, the same pattern as `RESTORE_CHECK`. Nothing in it expands locally. Its `set -e` plus the local `|| true` hands any host failure to `confirm_live_identity`, which `die`s on missing or short hashes.
- **bash 3.2.** `/usr/bin/env bash` resolves to `/bin/bash` 3.2.57 here, so the harness run *is* the bash 3.2 proof. I also checked the `${out##*$'\n'}` / `${out%$'\n'*}` split separately under `/bin/bash`, with a multi-line body, and it gives the right result. There is no `mapfile`, `declare -A`, `${,,}`, `${^^}` or `&>>`.
- `bash -n` is clean on `deploy.sh`, `deploy_health_guard_test.sh` and `check.sh`. `shellcheck` is clean on the first two. On `check.sh` it reports only the existing SC2164 at line 78. `scripts/deploy_guard_test.sh` passes (VERIFICATION PASSED), and `scripts/check_guard_test.sh` reports 0 failures. The harness leaves no `.scratch/deploy_health_guard.*` directory and no stub process behind.

**Fix applied in review.** The harness proved the extracted functions correct, but it could not see whether `deploy.sh` still *calls* them. M10 is exactly the regression this issue fixes, and it left every scenario green. I added a call-site section to `scripts/deploy_health_guard_test.sh`. It pins three lines, each with whole-line fixed-string `grep -cxF`, to exactly one occurrence in `deploy.sh`: the `if ! wait_healthy "$PUBLIC_URL/health"; then` line, the `ID_OUT=…$IDENTITY_CHECK | ssh … bash -s -- …` line and `confirm_live_identity "$ID_OUT"`. The oracle lives in the guard file, so an edit to `deploy.sh` cannot also satisfy it (§8). After the fix, M10, M11 and M12 each fail naming the missing line. M1–M9 give the same results as before, and the unmutated tree passes with 17 PASS lines. A legitimate rewording of those call lines now needs a matching guard edit. That is the intended cost.

**Still unproven:** the end-to-end run on production. The next real deploy is the proof, and it should print `attempt i/10` lines and a `running process (pid N) is executing the deployed binary` line.
