## Description

`#0282` extended `collectKindConstants` to resolve four `Kind` declaration
styles. Its review confirmed the fix and the reproduction, and then found a
fifth style and one incompleteness in the third.

**1. An alias-annotated constant is invisible.**

```go
type KindAlias = Kind
const KindE KindAlias = "e"
```

`go/types` resolves `KindE` to `Kind`. The shipped detector returns
`detected=false`, because it matches the **spelling** `Kind` and a non-nil
`vs.Type` never reaches the bare-constant branch. Contrived, but it is a
fail-open in a guard whose whole purpose is to fail closed — a `Kind` declared
that way is claimed by no poller and stalls in `'queued'` forever.

**2. `isBare` does not propagate through the repetition rule.**

```go
const (
    KindA Kind = "a"
    KindB      = "b"
    KindC
)
```

`KindC` inherits `isKind` via Go's const-repetition rule but is missed, because
`isBare` is not carried forward. `go/types` also reports `untyped string` here,
so this is heuristic incompleteness rather than something type analysis would
fix.

**3. The "zero marginal precision" claim needs narrowing.** `#0282`'s work log
states `go/types` buys zero marginal precision over the AST walk. That is
strictly false — item 1 is a case where `go/types` gets the right answer and the
detector does not. The conclusion (that `go/types` is not worth its cost here)
may well stand; the *claim as written* should not, since a future reader will
rely on it. `#0282`'s reviewer flagged this as an overstatement rather than
bouncing for it.

**4. `intakeException` is a single `const`, not a set**, so adding a second
exception requires restructuring first. Minor friction, worth fixing while here.

Also measured and worth knowing: the same-block heuristic **does** false-positive
on an unrelated untyped constant sharing the `Kind` block (a
`defaultKindNote = "…"` fails the guard, naming it). It fails **loud** and in
the safe direction with an actionable message, and `internal/outbox` has no such
constant today — so this is acceptable behaviour, not a defect. Do not "fix" it
by weakening the detector.

## Acceptance criteria

1. A pre-pass collects `type X = Kind` and `type X Kind` names declared in the
   package, and `vs.Type` is matched against that set rather than the literal
   spelling `Kind`.
2. `isBare` propagates through the const-repetition rule, so `KindC` above is
   detected.
3. Each gap is **reproduced as a failing test before being closed** — per
   `#0282`'s criterion 2 discipline, which its review verified was followed.
4. `intakeException` becomes a set, with each entry carrying a written reason.
   An exception list that anyone can append to without argument is a guard with
   a hole — see [#0280](0280.md) for the same lesson on the web side.
5. The doc comment's "exact for styles 1-3 / zero marginal precision" wording is
   corrected to reflect item 1. State what `go/types` would and would not buy,
   accurately.
6. The false-positive behaviour on an unrelated block constant is **preserved
   and documented** as deliberate, not removed.
7. Fail-closed on a zero-constant parse and specific-kind naming both survive —
   `#0282`'s review verified both; do not regress them.
8. `ISSUE=NNNN scripts/check.sh go ./internal/mailing/... ./internal/outbox/...`
   passes with no skips.
