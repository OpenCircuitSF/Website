## Description

This is a child of `#0673`. With it, a tool can read the guides and work through guide posts without the admin UI.

## Endpoints

| Method and path | Scope | Notes |
|---|---|---|
| `GET /api/v1/guides` | `guides:read` | Every workshop and topic guide, with slug, kind, set, title, hook, minutes, tags, `post` copy and URL. Filters: `?set=` and `?kind=`. |
| `GET /api/v1/guides/{slug}` | `guides:read` | One guide, plus its post history summary: last posted, posts per channel, clicks and signups. |
| `GET /api/v1/guide-posts` | `guide_posts:read` | Filters: `?status=draft\|scheduled\|posted\|failed`, `?slug=`, `?channel=`, `?campaign=`, `?from=`, `?to=`. |
| `POST /api/v1/guide-posts` | `guide_posts:write` | Takes `{slug, channels: ["bluesky","mastodon"], body, campaign, scheduled_for?}`. It creates one post per channel, each with its own short link (as `#0665` does), and schedules them if `scheduled_for` is given. It returns every post created, with results for each channel. One channel failing doesn't undo the other. |
| `PATCH /api/v1/guide-posts/{id}` | `guide_posts:write` | Changes the body, campaign or schedule of a draft or scheduled post. |
| `POST /api/v1/guide-posts/{id}/schedule`, `/unschedule`, `/send`, `/again` | `guide_posts:write` | Same behaviour as the admin actions. |
| `DELETE /api/v1/guide-posts/{id}` | `guide_posts:write` | Draft posts only. |
| `GET /api/v1/guide-posts/overview` | `guide_posts:read` | Same data as `/admin/guide-posts-overview`. |
| `GET /api/v1/channels` | `guide_posts:read` | Which channels are connected, and each one's character limit and URL weighting, so a tool can size a post before creating it. |

## Rules

- The handlers reuse `internal/guideposts` (Store, Linker, Publisher) and the `#0659` validation, including the character limit for each channel. The validation is not duplicated.
- A create for an unconnected channel returns a `validation` error for that channel.
- `{link}` templating works exactly as it does in the UI.
- Writes are audited as `guide_post.*` against the token (`#0674`).

### The rule that shapes everything: one code path

The admin handler (`internal/handlers/admin_guide_posts.go`, `#0659`) currently mixes its business steps with `http.ResponseWriter`:

- the connected-channel and link gate is in `sendGate`;
- mint-after-create is in `mintAfterCreate`;
- audit writes go through `record(r, …)`;
- clicks and signups are in `clicks` and `signupRows`, which already take only a `ctx`.

The v1 ops must not copy any of that. **Refactor first, with no behaviour change to `/admin/guide-posts`**, so that transport-free methods on `*AdminGuidePostsHandler` hold each step. Then both the admin `http.HandlerFunc`s and the v1 ops call those methods.

| New method (unexported) | Replaces | Notes |
|---|---|---|
| `recordCtx(ctx, ip string, id int64, e audit.Entry)` | `record(r, id, e)` | Runs `e = middleware.AttributeAPIToken(ctx, e)` before `h.auditor.Record`. That call is a no-op for a session request, so admin rows are unchanged; a v1 row is `ActorID: nil`, with `actor: "token:{id}"` and `api_token{…}` in its metadata. Admin callers pass `clientIP(r)`; v1 callers pass `""`, because `#0675` puts no client IP in the op context (see Obstacles). |
| `createDraft(ctx, ip string, actorID *int64, slug, channel, body, campaign string) (guidePostLinkResponse, error)` | the body of `Create` plus `mintAfterCreate` | It runs `store.Create`, writes the `guide_post.created` audit entry, then `linker.Ensure`. A failed mint keeps the draft and sets `LinkError`, exactly as today. |
| `gate(ctx, ip string, actorID *int64, id int64) (guideposts.Post, error)` | `sendGate` | It returns errors instead of writing them. The "not connected" case becomes `errChannelNotConnected{label}`. A link failure returns the linker's error wrapped as `errShortLinks{err}`, so the admin side can still call `writeShortLinksError`. |
| `schedule(ctx, ip, actorID, id, at)`, `queueNow(…)`, `unschedule(…)`, `again(ctx, ip, actorID, id, campaign)`, `deleteDraftOrAny(ctx, ip, actorID, id, draftOnly bool)` | the bodies of `Schedule`, `Send`, `Unschedule`, `Again` and `Delete` | Each one writes the same audit action and metadata it writes today. |
| `overview(ctx) (guidePostsOverviewResponse, error)` | the body of `Overview` | |
| `guidePostErrInfo(err) (status int, field, msg string)` | the `switch` in `writeGuidePostError` | `writeGuidePostError` becomes `status, _, msg := guidePostErrInfo(err); writeError(w, status, msg)`, and the v1 mapper uses the same table. **The admin messages and statuses stay byte-for-byte**, and the existing `admin_guide_posts_test.go` tests guard that. |

Also in `admin_outreach_posting.go`, split `parseScheduleAt` into `checkScheduleLead(at, now time.Time) (time.Time, string)`. `parseScheduleAt` keeps its signature and calls it after `time.Parse`.

### Store and catalog changes (small, both paths benefit)

- **`internal/guides`.**
  - Add `Set string` to `Guide`, and `Set string \`json:"set"\`` to `entry`.
  - Parse the top-level `sets` array into a new `type Set struct{ ID, Title, Blurb string }`, and add `func Sets() []Set`.
  - `load` rejects an entry whose `set` is empty or is not a declared set id, and a duplicate set id.
  - Add `func (k Kind) String() string`, which returns `"workshop"` or `"topic"`.
  - Every current entry already has a valid `set` (checked 2026-11-15: all 32 do), so the embedded catalog still loads.
- **`internal/guideposts`.**
  - `Store.UpdateBody`: when the post is linked, first replace `outreach.LinkToken` with `*cur.ShortURL`. That way, `{link}` in an edited body means the post's own short link, both in the UI and over v1. Today it is refused, as a placeholder or as a removed link.
  - Add `Store.UpdateCampaign(ctx, id int64, campaign string) (Post, error)`. It uses `NormalizeCampaignSlug` and runs `UPDATE … SET campaign_slug=$2, updated_at=now() WHERE id=$1 AND status='draft' AND short_link_key IS NULL`. When no row matches it returns `classify`'s answer, or `ErrLinkFixed` (a new sentinel, "the campaign is fixed once the post has its short link") when the post is a linked draft.
  - Export `LinkMeasuredAs = sampleShortURL`, so `list_channels` can report how `{link}` is measured. Keep the unexported name as an alias, or rename its uses.

### Operations

All of them go in new `internal/handlers/v1_guides.go` (the first two) and `v1_guide_posts.go` (the rest). They are built by `func guideOperations(baseURL string, h *AdminGuidePostsHandler) []api.Operation`, and the closures read `h` only when called. `#0679`'s parity test calls `BuildV1Registry` with `V1Deps{}`, so building an op must never dereference `h`.

| Name | Method and path | Scope | Flags | In → Out |
|---|---|---|---|---|
| `list_guides` | `GET /api/v1/guides` | `guides:read` | — | `listGuidesIn{api.Page; Set *string query:"set"; Kind *string query:"kind"}` → `api.List[guideV1]` |
| `get_guide` | `GET /api/v1/guides/{slug}` | `guides:read` | — | `getGuideIn{Slug string path:"slug"}` → `guideDetailV1` |
| `list_guide_posts` | `GET /api/v1/guide-posts` | `guide_posts:read` | — | `listGuidePostsIn{api.Page; Status, Slug, Channel, Campaign *string; From, To *time.Time}` (all `query`) → `api.List[guideposts.Post]` |
| `create_guide_posts` | `POST /api/v1/guide-posts` | `guide_posts:write` | `Idempotency`, `Status: 201`, `PublicEffect: "with scheduled_for, the posts go out publicly on Bluesky and Mastodon at that time"` | `createGuidePostsIn` → `createGuidePostsOut` |
| `update_guide_post` | `PATCH /api/v1/guide-posts/{id}` | `guide_posts:write` | `PublicEffect: "a scheduled_at here makes the post go out publicly at that time"` | `updateGuidePostIn{ID int64 path; Body, Campaign, ScheduledAt *string}` → `guideposts.Post` |
| `schedule_guide_post` | `POST /api/v1/guide-posts/{id}/schedule` | `guide_posts:write` | `PublicEffect: "posts publicly to Bluesky or Mastodon at scheduled_at"` | `{ID path; ScheduledAt string}` → `guideposts.Post` |
| `unschedule_guide_post` | `POST /api/v1/guide-posts/{id}/unschedule` | `guide_posts:write` | — | `{ID path}` → `guideposts.Post` |
| `send_guide_post` | `POST /api/v1/guide-posts/{id}/send` | `guide_posts:write` | `Status: 202`, `PublicEffect: "posts publicly to Bluesky or Mastodon right away"` | `{ID path}` → `guideposts.Post` |
| `post_guide_again` | `POST /api/v1/guide-posts/{id}/again` | `guide_posts:write` | `Status: 201` | `{ID path; Campaign string omitempty}` → `guidePostLinkResponse` |
| `delete_guide_post` | `DELETE /api/v1/guide-posts/{id}` | `guide_posts:write` | `Destructive` | `{ID path}` → `deletedV1{ID int64; Deleted bool}` |
| `guide_posts_overview` | `GET /api/v1/guide-posts/overview` | `guide_posts:read` | — | `struct{}` → `guidePostsOverviewResponse` (the admin type, unchanged) |
| `list_channels` | `GET /api/v1/channels` | `guide_posts:read` | — | `struct{}` → `channelsV1{Channels []channelV1}` |

Every op has a one-line `Summary` that says what it does in the agent's terms. For example, `create_guide_posts` is "Create one draft per channel for a topic guide, each with its own tracked short link, and optionally schedule them all."

**Notes on each op.**

- **`guideV1`** has `slug`, `kind` (`workshop`/`topic`), `set`, `title`, `hook`, `description`, `minutes`, `tags` (never null), `url` (`baseURL + g.Path()`), and `postable` (topic only).
  - Topic guides also get `post` and `default_body` (`guideposts.DefaultBody`); these are omitted for a workshop guide.
  - `?kind=` other than `workshop`/`topic`, or a `?set=` not in `guides.Sets()`, gives `api.Validation{"kind"|"set": "must be one of …"}`.
  - The order is catalog order. The cursor is `{"slug": last}`, and a cursor naming a slug that no longer exists is a validation error.
- **`get_guide`**: an unknown slug gives `api.NotFound("guide")`. `guideDetailV1` embeds `guideV1` plus `history *guideHistoryV1` (null for a workshop guide). It is built by reusing `h.store.List`, `h.clicks` and `h.signupRows`, then `guideposts.Overview([]guides.Guide{g}, posts, …)[0]` for the share fields. It adds:
  - `posts_by_channel`: `{"bluesky": {"draft":n,"scheduled":n,"queued":n,"posted":n,"failed":n}, …}`;
  - `signups` (summed by guide, as `Overview` does);
  - `clicks_error` and `signups_error`.
- **`list_guide_posts`**:
  - It loads `h.store.List`, filters in Go, sorts by id descending, and paginates.
  - `from` and `to` bound the post's **time**, which is `posted_at`, else `scheduled_at`, else `created_at`, over `[from, to)`.
  - `status` must be one of the five `guide_posts_status_check` values, and `channel` must be `bluesky` or `mastodon`. Anything else is a validation error naming the field.
  - It makes no ShortLinks call. Clicks are in `get_guide` and `guide_posts_overview`.
- **`create_guide_posts`.**
  - `createGuidePostsIn{Slug string; Channels []string; Body string omitempty; Campaign string omitempty; ScheduledFor *string omitempty}`. `ScheduledFor` is a string on purpose: it goes through `parseScheduleAt` unchanged, with the same messages as the admin form. See the time-binding note under Obstacles.
  - **Validate everything before writing anything.** A failure is one `api.Validation` with every problem and creates nothing:
    - `slug`: must be a topic guide;
    - `channels`: 1 or 2 entries, each `bluesky` or `mastodon`, with no repeats;
    - `channels.<name>`: "<Label> is not connected", from `h.configured`;
    - `campaign`: `NormalizeCampaignSlug`;
    - `body.<name>`: `guideposts.ValidateDraft(ch, bodyOrDefault)`'s message, which already names the count and the limit;
    - `scheduled_for`: `parseScheduleAt`'s reason.
  - That makes "over the limit on one channel" and "unconnected channel" clean 400s. **"One channel failing doesn't undo the other" applies to failures after validation**: a ShortLinks mint, a database write, or a schedule step.
  - Then, for each channel in request order:
    1. `h.createDraft(…)`;
    2. if `ScheduledFor` is set and the draft is linked, `h.schedule(…)`.
  - `createGuidePostsOut{Results []channelResultV1}`, where `channelResultV1{Channel string; Post *guideposts.Post; LinkError *string; ScheduleError *string; Error *api.ErrorDetail}`.
    - A failed `createDraft` fills `Error` with `api.AsError(op, err)`'s code and message, and the loop continues.
    - A draft whose mint failed is kept, with `LinkError` set, and is not scheduled: `ScheduleError = "the post has no short link yet"`.
    - If **no** channel produced a post, the op returns the first channel's error, so the status reflects it. Otherwise the status is 201.
- **`update_guide_post`**:
  - It needs at least one field, otherwise `Validation{"body": "send body, campaign or scheduled_at"}`.
  - It parses `scheduled_at` first with `parseScheduleAt`, so a bad time changes nothing.
  - Then, in order: `UpdateCampaign` (a linked post gives a 409 `conflict` with `ErrLinkFixed`'s message), then `store.UpdateBody` (with `{link}` now filled), then `h.schedule` via `h.gate`.
  - Each step writes its existing audit action. Campaign uses `guide_post.updated` with metadata `{"campaign": …}`.
  - The response is the post after the last step.
- **`delete_guide_post`**: it loads the post and refuses a non-draft with `api.Conflict("only a draft can be deleted; unschedule it first")`. Then it runs the same store `Delete` and `guide_post.deleted` audit as admin, through `deleteDraftOrAny(…, draftOnly=true)`. The admin route keeps `draftOnly=false`.
- **`list_channels`**: for `bluesky` and `mastodon` from `outreach.ChannelByName`, it returns `name`, `label`, `char_limit`, `configured`, and `counting`:
  - Bluesky: `"graphemes"`, `url_weight` 0, `byte_limit` `bluesky.MaxTextBytes`;
  - Mastodon: `"code points; each URL counts as 23"`, `url_weight` 23, `byte_limit` 0.

  The response also has a top-level `link_token: "{link}"` and `link_measured_as: guideposts.LinkMeasuredAs`. That is enough for a tool to size a post before creating it.
- **Error mapping, `guidePostAPIError(err) error`.** It is used by every op and built from `guidePostErrInfo`:
  - 404 becomes `api.NotFound("guide post")`;
  - 409 becomes `api.Conflict(msg)`;
  - 400 and 422 become `api.Validation({field: msg})`, where `field` is `body`, `campaign`, `slug` or `channel` per sentinel;
  - `errChannelNotConnected` becomes `api.Conflict("<Label> is not connected")`;
  - `errShortLinks` becomes `&api.Error{Status: 503, Code: "unavailable", Message: "short link could not be made: " + linkFailureReason(err)}`. `api.Error`'s fields are exported. If `#0675` landed an `api.Unavailable` helper or a `CodeUnavailable` constant, use it.
  - Anything else is returned raw, so `AsError` logs it and answers 500.

### Shared v1 helpers (created here; `#0677` and `#0678` reuse them)

- **`internal/handlers/v1_page.go`:**

  ```go
  func paginate[T, K any](sorted []T, p api.Page, key func(T) K, after func(T, K) bool) (api.List[T], error)
  ```

  It resolves the limit with `p.Resolve()`. A non-empty cursor is decoded with `api.DecodeCursor` into `K`, and every item where `!after(item, k)` is skipped. It takes `limit` items, and sets `next_cursor` to `api.EncodeCursor(key(last))` only when more remain. Each list op loads its rows, sorts them and filters them in Go, then calls this. The tables are small.
- **`internal/handlers/v1_helpers_test.go`:**
  - `type fakeResolver map[string]apitokens.Token`, implementing `middleware.APITokenResolver`;
  - `newV1Router(t, ops ...api.Operation) http.Handler`, which builds `api.NewRegistry(api.Config{Version: "test", Idempotency: api.NewIdempotencyStore(pool)})` and `api.NewHTTPRouter` with a fresh `middleware.NewAPITokenRateLimiter()`;
  - `v1Do(t, h, method, path, bearer, body) (*httptest.ResponseRecorder, api.ErrorBody)`;
  - `tokenWith(scopes...) (secret string, tok apitokens.Token)`. It creates a real row with `apitokens.NewStore(pool).Create`, so audit rows can be checked by token id and no seeded id is ever targeted (AGENTS.md §8b).

## Assumptions (user may override)

- **Validation is all or nothing; delivery is per channel.** An over-limit body, an unconnected channel or a bad time is one 400 that names every problem, and nothing is created. A ShortLinks or database failure after that point affects only its own channel.
- **Guide-post times come back as stored (UTC).** The response reuses `guideposts.Post`'s JSON unchanged. Events (`#0677`) use Pacific offsets.
- **`list_guide_posts` has no clicks**, so it never calls ShortLinks. Clicks and signups are on `get_guide` and `guide_posts_overview`, through the admin handler's existing stats cache.
- **`delete_guide_post` deletes drafts only**, as the issue says. The admin UI can still delete scheduled or failed posts.
- **`{link}` in an edited body of a linked post means that post's short link**, in the admin UI too. Today the admin UI refuses it.
- **A campaign can change only before the post has its short link.** After that, use `post_guide_again` with a new campaign.
- **`get_guide` needs only `guides:read`**, even though its history shows post counts and clicks, as the issue's table says.
