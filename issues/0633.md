# 0633 — Unsaved Outreach text can carry over to another workshop when the address changes

| | |
|---|---|
| **Status** | open |
| **Platform** | All |
| **Module** | outreach |
| **Phase** | 10 — Outreach |
| **First seen** | 2026-11-05 |

## Description

Found in `#0625`'s second review, in Safari. `Outreach.svelte` has no key around `OutreachWorkshop`, so editing the address to another workshop keeps the same page nodes. Text typed for one workshop then appears in the next workshop's **Message**, ready to save to the wrong event.

If the second workshop's GET also fails, `load()` reads the first workshop's stale view and sends `POST /admin/workshops/7/outreach`. That harm is low, because the handler is idempotent and refuses an unpublished event.

No link on the page leads here, only an edited address.

Remaining polish from the same review:

- The failed-refresh banner reads `internal server error What is below may be out of date.`, with no full stop after the server's message.
- Selecting a section while the banner is up leaves its row and focus behind the banner.
- Focus falls to the body after **Retry**, after the Reset dialog closes on a successful reset, and after **Unschedule** removes its own button (`#0627`'s review).

## Plan

Planned with `#0634`, which holds the one `## Plan` and `## Obstacles` for the batch (`#0634`, `#0632`, `#0633`), **re-planned 2026-11-05 against `064b3ba7` after `#0640` landed** (the earlier plan of `604c5459` is superseded). This issue's parts there:

- **Key**: file 7, a `{#key}` on the workshop id around `OutreachWorkshop` in `Outreach.svelte`, with a new `Outreach.workshopKey.behavior.test.ts`.
- **Stale view**: file 10. `OutreachPanel`'s `load()` and `refreshQuietly()` ignore an answer for another workshop, and only this workshop's own view can start outreach, make hand links or load results.
- **Polish**: files 8 to 11 and 13. `asSentence` adds the missing full stop. Since `#0640` the section tabs are sticky under the sticky banner, so the tabs now pin below the banner through `--reload-banner-h` (decision 8, file 11) instead of a one-off scroll. Focus goes to the open section's tab after Retry and after a Reset, and to **Schedule…** after Unschedule (file 2).
- Tests and checks: `#0634`'s Tests, Verification and Safari checks 4 and 5.

## Acceptance criteria

- [ ] `OutreachWorkshop` is keyed on the workshop id, so no typed text or view state crosses workshops, with a test.
- [ ] A failed load cannot start outreach from another workshop's view.
- [ ] The banner sentence reads correctly, a selected row lands below the banner, and focus stays somewhere useful after **Retry** and Reset.
