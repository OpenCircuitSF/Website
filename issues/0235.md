## Description

`#0228` fixed **object** ownership after a restore — every table, sequence and
view is reassigned to `RESTORE_OWNER`. It did not fix the **schema**.

`public` resolves to `pg_database_owner`, which is whoever created the database
— `postgres` on the documented production path. Measured by `#0228`'s review:

```
create table … as opencircuit  ->  ERROR: permission denied for schema public
```

against a restored database, where the same probe succeeds on a database made
with `createdb -O opencircuit`.

**Why this is not covered by `#0228` passing.** Its criterion is that the app
can read and write its own tables, and that genuinely holds — `SELECT` and
`INSERT` as `opencircuit` both succeed. Serving traffic works. What fails is
`CREATE TABLE`, and therefore **`migrate up`** — so the first deploy after an
incident restore fails, and `scripts/deploy.sh` runs migrations as part of an
ordinary redeploy.

The shape of the failure is the problem: a restore appears to succeed, the site
comes back, and the breakage surfaces later at the next deploy, when nobody is
thinking about the restore any more. `#0228`'s note that "the app only needs to
read and write the objects" is true of serving and false of deploying.

## Acceptance criteria

- [ ] After a restore, the app role can create and drop objects in `public` — i.e. `migrate up` succeeds
- [ ] Proved end to end on a scratch database (§8b, never a shared one): restore, then run a real migration as the app role, not a `CREATE TABLE` probe standing in for one
- [ ] The `RESTORE_OWNER=""` opt-out still genuinely opts out of the schema change too
- [ ] `docs/deployment.md`'s restore drill includes the migration step, so the gap cannot reappear undetected

**Smaller items from the same review, all in this file's blast radius:**

- [ ] `RESTORE_OWNER` is validated *after* the restore runs, so a bad value costs a full restore before exiting 2 — validate first
- [ ] `reassign_ownership` covers tables, sequences and views but not materialised views, types or functions. Unreachable today (`migrations/` creates none) — either extend it or say in the script why the three are omitted
- [ ] The drill's step 4 says *see "Ownership"*; the bullet is titled "Roles and ownership"
