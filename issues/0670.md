Facts checked:
- arduino-esp32 `cores/esp32/HWCDC.h`: Serial is HWCDC only `#if ARDUINO_USB_MODE && ARDUINO_USB_CDC_ON_BOOT`.
- arduino-esp32 `boards.txt`: on the esp32c3, CDCOnBoot defaults to Disabled, and the default partition scheme is "Default 4MB with spiffs (1.2MB APP/1.5MB SPIFFS)", which has two app slots.
- PlatformIO espressif32 docs: OTA uses `upload_protocol = espota` and `upload_port` (an IP or `*.local`), and the password goes in `upload_flags = --auth=…`. The Arduino framework's default partition table is `default.csv`.

### Assumptions
- The ROM download-mode USB port enumerates on the C3's USB-Serial/JTAG, and the port goes away during reset and deep sleep. This comes from the C3 TRM and Espressif's general docs, not a page fetched this session.
- `while (!Serial && millis() < 2000) {}` waits for the host on HWCDC, because HWCDC's `operator bool` reports a host connection. The guide text also offers `delay(2000)` as a simpler option.
- The OTA demo models only a verify-then-switch failure (a dropped transfer leaves the old slot active). It does not claim boot-time rollback of firmware that boots and then crashes, because app rollback is not enabled by default in Arduino builds (unverified).
- The error strings are quoted from memory of esptool and PlatformIO output: "This chip is ESP32-C3 not ESP32", "Unknown board ID", "Could not exclusively lock port".

## Review notes

Reviewed 2026-11-15 (opus, medium). Verdict: **pass, with small fixes in `6555a4aa`**.

Facts checked:
- `HWCDC::operator bool()` returns `isCDC_Connected()`, and on the C3 that is true only while the host is polling the IN endpoint, which means a terminal has the port open. This was fetched from arduino-esp32 `cores/esp32/HWCDC.cpp` on master. So "wait for the monitor" with `while (!Serial && millis() < 2000)` is accurate, and the assumption is confirmed.
- PlatformIO's `esp32-c3-devkitm-1.json` sets `extra_flags` to `-DARDUINO_ESP32C3_DEV` only, with no USB flags. So the advice to add both flags stands.
- The standard `platformio/platform-espressif32` boards list has no SuperMini entry, but the pioarduino fork has `nologo_esp32c3_super_mini`. The wording is now scoped to the standard platform.
- The error strings are real, from source memory: esptool's `This chip is %s not %s. Wrong --chip argument?`, PlatformIO's `Unknown board ID '…'`, and pyserial's POSIX `Could not exclusively lock port …`. That last one is Mac/Linux only, so the text now adds Windows's "Access is denied".
- GPIO9 strapping (high → SPI boot, low → download), RST = CHIP_EN, UART0 on 21/20, and the port vanishing in reset and deep sleep are all correct. Download mode enumerates on the USB-Serial/JTAG. The OTA text (espota, `upload_port`, `--auth`, app0/app1 with the default partition table, verify-then-switch) makes no rollback claim, so it is correct.
- The hotspots line up with the BOOT and RST buttons on `esp32-c3-top.webp`. I checked this by drawing the circles with `magick` and viewing the result.

Fixes:
- `upload()` with BOOT still held now comes back up in download mode. The post-write reset samples GPIO9 low. A unit test was added.
- `checkIni()` gives the esp32dev "wrong chip" upload error only under espressif32. Under atmelavr the message was wrong. Test added.

Accessibility and layout: native controls, live regions that are always rendered, focus moves to the heading in UploadDoctor, and hotspots have `aria-pressed` with sr-only names. Everything uses theme tokens. At 360px everything fits in one column, or in 2×150px for the ini controls.

Verification: `ISSUE=6700 scripts/check.sh web` passed: 136 files, 5378 tests. `ISSUE=6700 scripts/check.sh go ./internal/guides/... ./internal/seo/...` passed with both packages `ok` and no skips. The load average was about 8.5 while this ran, and there were no timing failures. All evidence is from jsdom; no browser was launched.

Follow-ups (not filed): none required. Optional: the BOOT demo always asks for RST after a download-mode upload. On the C3, esptool's hard reset over USB-Serial/JTAG often starts the new code by itself, so the guide could say "if it doesn't start, press RST".
