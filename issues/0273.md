## Description

Measured against the live site, `/workshops/introduction-to-soldering` serves:

<meta property="og:title" content="Introduction to Soldering" />
<meta property="og:description" content="Join us to learn the basics…" />
<meta property="og:url"   content="https://www.opencircuitsf.com/workshops/introduction-to-soldering" />

### 0. What is already true, verified against the code

- `internal/seo/seo.go`'s `workshopRouteMeta` builds the per-workshop
  `RouteMeta`, and the `og:image` fallback is the two lines
  `image := absoluteURL(r.baseURL, w.CoverImage)` / `if image == "" { image =
  r.baseURL + "/og-default.png" }`. That is the only place a workshop's card
  URL is chosen.
- `internal/seo/site.go`'s `Site.Invalidate` is the single invalidation entry
  point; it calls `renderer.Invalidate()` and `sitemap.invalidate()`.
- `cmd/opencircuit/main.go`'s `buildSEOSite` builds the one shared `*seo.Site`;
  `mountAndServe` mounts `GET /sitemap.xml`, `GET /robots.txt`, and
  `site.Middleware(handlers.NewSPAHandler(web.DistFS()))` at `GET /`.
- `internal/handlers/routes.go`'s `workshopDetailPattern` is
  `^/workshops/[^/]+$`, so `/workshops/{slug}/og.png` does **not** match it and
  `IsKnownRoute` returns false for it. Combined with Go 1.22 `ServeMux`
  specificity, an explicit `GET /workshops/{slug}/og.png` pattern wins over

  `internal/handlers` is required by this issue** — which also keeps it clear
  of `#0405`'s concurrent work there.
- Production's CSP is `img-src 'self' data:`. A same-origin `/workshops/…/og.png`
  needs no CSP change.

### 1. Rendering — recommendation: `golang.org/x/image/font/opentype` over a pre-baked base PNG

**Recommended.** Compose the card in Go from three pieces:

1. A committed, pre-rendered **base card** — the dark ground, the tinted logo
   mark, and the rule — produced once by a Python script alongside the existing
   `assets/og/build-og.py`, and `//go:embed`ed into `internal/seo`. Decoded
   once at `Site` construction into an `*image.RGBA`; each render starts by
   `copy()`ing its `Pix` slice. Runtime Go never does alpha-mask tinting, and
   `assets/og/build-og.py` stays the one place brand-asset composition lives.
2. **Text drawn at request time** with `golang.org/x/image/font/opentype` +
   `font.Drawer`, from embedded static TTFs (§2 below).
3. `image/png` from the standard library to encode.

**Measured, not assumed** (throwaway spike, `darwin/arm64`; `uptime` read
immediately after the run gave a load average of 3.71, under §5's ~4 idle
threshold, so these are not numbers taken from a saturated machine):

| | |
|---|---|
| Binary cost of the dependency | **+442 KB** — a minimal `image/png`+`image/draw` program is 2,919,810 B; the same program with `x/image/font/opentype` + real text layout is 3,362,178 B |
| Embedded fonts | **~98 KB** (two static TTFs, sizes in §2) |
| Render time per card | **8–13 ms** (three cases: minimal, normal, long title) |
| Encoded PNG size | **19–53 KB** — comfortably under the 300 KB criterion |
| Heap for three renders | `TotalAlloc` 13.3 MB, process `Sys` 21.9 MB — and the spike re-parsed both fonts on every render, which production will not |
| New transitive modules | **zero** — `golang.org/x/image@v0.40.0`'s only requirement is `golang.org/x/text v0.37.0`, already in `go.mod` as an indirect at exactly that version |

So on the `t4g.nano` (§7: 418 MB, shared with Apache, PostgreSQL and three
other Go services) the whole feature costs about half a megabyte of binary,
one 1200×630 `RGBA` buffer (~3.0 MB) live only during a render, and 8–13 ms
of CPU once per slug per invalidation. Renders are serialized behind a mutex
(§3), so the 3 MB is a peak, not a per-request multiplier — and that same
mutex is required anyway, because `golang.org/x/image/font`'s `Face` is
documented as not safe for concurrent use.

**On §9.** The self-contained rule is about the *served page* — no third-party
analytics, ad trackers, external CDNs, or tracking pixels. A `golang.org/x`
module compiled into the binary makes the service *more* self-contained, not
less: the alternative that would violate §9 is an external card-rendering
service, and this is what avoids it.

**Alternatives weighed and rejected:**

| Option | Why not |
|---|---|
| Go standard library alone | There is no TrueType/OpenType rasterizer in the standard library. Doing this with no dependency means writing a glyph rasterizer — far more risk and far more code than a `golang.org/x` module. |
| `fogleman/gg`, `tdewolff/canvas`, cgo/Cairo | Heavier, more transitive modules, cgo in some cases, and none of it needed: the card is text on a flat ground. |
| Headless Chromium screenshotting an HTML template | Unthinkable on a 418 MB box shared with four services, and it walks straight into §8's ~485 px minimum-window trap. |
| Pre-render at workshop-save time to disk or a DB column | Needs a writable path or a blob column (**a migration**, plus a backfill for existing rows), and adds a failure mode where a restored database has no cards. Request-time rendering with an in-memory cache costs 13 ms once per slug and stores nothing. Keep this as the escape hatch if render cost ever matters; at a three-workshop catalog it never will. |
| Shell out to the existing `assets/og/build-og.py` per request | Production has no guarantee of Pillow/numpy/fontTools, and a Python subprocess per render is strictly worse than 13 ms in-process. |

### 2. Fonts

The project already self-hosts its brand faces at `web/public/fonts/` under SIL
OFL 1.1, with the licence beside them (`web/public/fonts/LICENSE`): Archivo
(variable) and JetBrains Mono 400/700. **Nothing needs downloading.**

Two facts force a conversion step, both verified against the module cache
rather than assumed:

- `golang.org/x/image/font/sfnt` cannot read `.woff2` — it parses bare
  SFNT/TTF/OTF only.
- It has no variable-font support either: `grep -rn fvar` over
  `golang.org/x/image@v0.40.0/font/sfnt/` returns nothing, so a variable font
  would render at its default instance, not at the site's `wght=800`.

So: decode each `.woff2` to a **static** `.ttf` with `fontTools`, exactly the
way `assets/og/build-og.py` already does at run time for the default card
(`_woff2_to_ttf`, including `instantiateVariableFont` for the weight), and
commit the results into `internal/seo/` (a `//go:embed` path cannot use `..`,
so the files must live under the package). Measured outputs from the repo's own
`.woff2` files:

| Face | Source | Size |
|---|---|---|
| Archivo `wght=800` (headline) | `web/public/fonts/archivo-variable-latin.woff2` | 40,856 B |
| JetBrains Mono 400 (prompt, date/venue line) | `web/public/fonts/jetbrains-mono-400-latin.woff2` | 57,404 B |

Add a small generator, `assets/og/build-card-fonts.py`, so the committed
binaries are reproducible from the committed `.woff2` files, and copy
`web/public/fonts/LICENSE` next to them — the OFL requires the licence to
travel with the fonts. Do **not** subset further: workshop titles are
admin-authored free text, so the whole latin subset is needed.

Parse each font **once** at `Site` construction (`opentype.Parse` on the
embedded bytes) and cache `font.Face` values per point size; do not re-parse
per request the way the spike did.

### 3. Caching and the invalidation seam

A new unexported type in `internal/seo` — say `cardCache` — holding
`map[string][]byte` (slug → encoded PNG), a `sync.RWMutex`, and the same
flush-at-bound eviction `Renderer.store` already uses. Bound it (64 is ample;
the keyspace is the published-workshop catalog, and the handler renders only
for published workshops, so it is never attacker-controlled).

**The seam, stated precisely, because §8 says to be.** `#0325` shortened
`InvalidateWorkshops` → `Invalidate` and silently recruited `*seo.Sitemap`
into `handlers.seoCacheInvalidator` and `mailing.ArchiveCacheInvalidator`;
`#0337` closed it by unexporting `Sitemap.invalidate`, and
`internal/seo/invalidator_satisfier_guard_test.go` (`TestInvalidatorSatisfierSet`,
now `#0349`/`#0353`'s `go/types.Implements` oracle) pins the satisfier set to
`{Site: true, Renderer: true, Sitemap: false}` and fails on any *new* type
joining it.

Therefore:

- The card cache's clear method is **`invalidate()`, unexported**, exactly like
  `Sitemap.invalidate`. It must not be named `Invalidate`, must not be
  exported, and must not be reachable by promotion from an embedded field.
- `Site.Invalidate()` gains one line — `s.cards.invalidate()` — beside the two
  it already has. **No new interface, no new seam, no new exported method
  anywhere in `internal/seo`.** Every existing caller
  (`handlers.AdminWorkshopsHandler`, `handlers.AdminCampaignArchiveHandler`,
  `mailing.Worker`) then invalidates the card cache through the identical call
  it already makes, on the identical shared `*seo.Site` instance
  `cmd/opencircuit/seo_wiring_test.go` already proves the identity of.
- Add `"cardCache": false` (whatever the final name is) to
  `TestInvalidatorSatisfierSet`'s `want` map. The guard would stay green
  without it — an unexported `invalidate()` does not satisfy `Invalidate()` —
  but an explicit `false` row records the intent, and it is the row that will
  fail loudly if someone later "tidies" the name to `Invalidate`.

**HTTP caching.** `Site.WorkshopCardHandler()` (a new method on `*Site`,
mounted next to `SitemapHandler`/`RobotsHandler`) serves:

- `Content-Type: image/png`
- `Cache-Control: public, max-age=3600`
- a strong `ETag` computed from the rendered bytes, with `If-None-Match` →
  `304`. The ETag is what makes an edit visible to a re-fetching crawler
  sooner than `max-age` would allow, and it is cheap because the bytes are
  already cached.

Rendering happens under a mutex, so a burst of concurrent first-requests for
one slug renders once and the rest read the cache (and, as noted, `font.Face`
requires this anyway).

Mount in `cmd/opencircuit/main.go`'s `mountAndServe`, beside the two existing
site routes:

    mux.Handle("GET /workshops/{slug}/og.png", site.WorkshopCardHandler())

### 4. Layout, and the two hard cases

The card is always the dark brand ground (`#0A0D0B`), so brand green
(`#68FF23`) is used at its 14.8:1 measurement, never the 1.32:1 light-ground
case §8 warns about. The logo comes from the `mark-*` assets or
`logo-mask-512.png` scaled to **≥ 96 px** — §8's illegibility floor — and is
baked into the pre-rendered base, so it is a resize decision made once in
Python with Pillow, not per request in Go.

Layout of the variable part:

- **Title**: Archivo 800, shrink-to-fit across a descending size ladder, then
  greedy word-wrap to at most three lines, then ellipsize the last line with
  U+2026 if content was dropped. (U+2026 is present in the Archivo latin
  subset — confirmed by rendering it, see below.)
- **Date · venue**: JetBrains Mono 400, one line, ellipsized to width. Built
  from `StartsAt` / `LocationName`, both of which `seo.Workshop` already
  carries and both of which the package already treats as independently
  optional (`jsonld.go`'s `eventLocation`). Omit the separator and the missing
  half rather than printing a placeholder — the same posture `buildEvent`
  already takes toward missing data.
- **Command line**: `$ opencircuitsf.com` in green, fixed.

**How the two hard cases get proved — by rendering, and the spike already
found a real defect this way.** A very long title and a title-only workshop
were both rendered in the spike; the long one wraps to three lines, shrinks,
and ellipsizes cleanly, and the minimal one is legible **but leaves a large
empty band through the middle of the card**, because everything is pinned to
fixed `y` offsets. So the plan is not "assume it degrades gracefully": the
title block must be **vertically centred within its band** so a one-line title
sits where the eye expects, and the mark must be present in the base so the
card is never mostly void.

The proof itself, in `internal/seo`:

1. A table test renders both cases (plus a normal one) to real PNGs in
   `t.TempDir()`.
2. It asserts on the **decoded image**, not on the layout code: dimensions
   exactly `1200×630`; encoded size < 300 KB; the ink bounding box of every
   non-background pixel lies wholly inside a safe-area inset (no glyph within
   N px of any edge); and at least one non-background pixel exists in each
   expected band, so a blank or all-background card fails rather than passing
   as "readable". These are measurements of the output, so a change to the
   layout constants moves the numbers — the in-package home is the right one
   per §8's falsifiability rule.
3. It asserts the long-title case's last line ends in U+2026 and the wrap
   produced ≤ 3 lines.
4. Separately, and recorded in `## Verification`: the implementer writes the
   same PNGs to its scratchpad and **looks at them** (the Read tool renders
   images inline). §8's "CSS masks fail silently under `file://`" gotcha does
   not apply — there is no CSS and no browser here — but the corollary does:
   view the PNG as an image, never through a `file://` HTML wrapper.

### 5. `og:type` — decision: keep `website` for workshop pages

Recorded deliberately, as the criterion asks.

`article` is rejected. The reasoning:

- Open Graph has **no `event` type**. The choice is between `website` and
  `article`, and `article` means editorial written content.
- The thing `article` "unlocks", `article:published_time`, is a *publication*
  timestamp, not the event date. Emitting the workshop's publication date on a
  page whose whole subject is a future date is more likely to mislead an
  unfurler than to help it — and the date a reader needs is now rendered
  *into the card image itself*.
- The event semantics are already carried correctly and machine-readably by
  `#0055`'s schema.org `Event` JSON-LD (`internal/seo/jsonld.go`), which is
  what actually consumes structured event data. `og:type` adds nothing there.
- `archiveRouteMeta` already emits `og:type: article` for `/archive/{slug}`,
  where it is accurate — those pages *are* articles. Reusing `article` for
  workshops would erase a distinction the codebase currently draws correctly.
- No consequence: Slack, iMessage, Bluesky and Mastodon render a
  `summary_large_image`-shaped card identically for `website` and `article`.

So: `website` stays, and the reason above is the record the criterion wants.
Tick the criterion on the *decision*, not on a code change.

### 6. The three smaller gaps

- **`og:site_name`** — add as a **static literal** in `web/index.html`, not a
  token: `<meta property="og:site_name" content="Open Circuit SF" />`. It never
  varies by route, so a token would add substitution surface and a
  `distPlaceholderTokens` entry for a constant. Record that reasoning in the
  markup comment.
- **`twitter:title` / `twitter:description`** — these *do* vary by route, so
  they need tokens: add `tokenTwitterTitle` and `tokenTwitterDescription` to
  `internal/seo/seo.go`'s const block and to `substitute`, filled from
  `m.OGTitle` / `m.OGDescription`. **Do not add fields to `RouteMeta`** — the
  criterion asks for them to be set explicitly, and mirroring the OG values at
  substitution time is explicit without creating two values that can drift.
- Both new tokens must be added in **four** places or the build breaks
  silently: the const block in `seo.go`, `substitute`'s `strings.NewReplacer`,
  `web/index.html`, and `web/dist/index.html` — plus
  `distPlaceholderTokens` in `internal/seo/dist_placeholder_guard_test.go`,
  which is a hand-listed slice, not a derived one.
- `twitter:image` is deliberately **not** added: Twitter/X falls back to
  `og:image`, and a second copy of the same URL is one more thing to drift.

### 7. Canceled, draft, and unknown — where the branch lives and how it is pinned

The branch is in `internal/seo/seo.go`'s `workshopRouteMeta`:

    if w.Status != WorkshopPublished {
        m := r.fallback
        m.JSONLD = jsonld
        return m, true
    }

Because it copies `r.fallback` **wholesale**, its `OGImage` is
`baseURL + "/og-default.png"` by construction. `#0135`'s ruling therefore holds
for free **provided the generated-card URL is assigned only in the published
branch below it** — which is exactly where the existing `cover_image` fallback
already sits. That is the whole change to this function: replace

    image = r.baseURL + "/og-default.png"

with the per-workshop card URL, inside the published branch only.

To make it structural rather than a coincidence of ordering, extract the
predicate both sides must agree on into one helper — something like
`func (r *Renderer) cardableWorkshop(slug string) (Workshop, bool)` returning
`ok` only for `Status == WorkshopPublished && Published` — and have **both**
`workshopRouteMeta`'s image branch and `WorkshopCardHandler` call it. The meta
side and the image side then cannot drift apart.

Pinned by a table test over the full cross-product, asserting the two halves
together:

| Status | `Published` | rendered `og:image` | `GET …/og.png` |
|---|---|---|---|
| `published` | true | the card URL | 200, `image/png` |
| `canceled` | true | `/og-default.png` | **404** |
| `canceled` | false | `/og-default.png` | 404 |
| `draft` | false | `/og-default.png` | 404 |
| `unpublished` | any | `/og-default.png` | 404 |
| unknown slug | — | `/og-default.png` | 404 |
| nil `WorkshopSource` | — | `/og-default.png` | 404 |

The `canceled`/`Published: true` row is the one that is specifically `#0135`'s
ruling, and it must assert both that the rendered HTML contains
`/og-default.png` and that it does **not** contain `/og.png` — an assertion on
the presence of the right URL alone would pass if both were emitted. The 404
rows are acceptance criterion 8 ("a draft or unknown slug produces no
workshop-specific card"): the handler answers 404, it does not fall back to
serving the generic PNG under a workshop-specific URL, because a 200 at
`/workshops/some-draft/og.png` is itself a leak of the slug's existence.

**Local end-to-end, which is genuinely available now:**

Build, run the binary on a port picked to avoid collision, seed a workshop in a
private database, and `curl` both the page and the image — §8b applies in full:
confirm the bind actually succeeded, and confirm a build-specific detail in the
response (a string this change introduced) before trusting a byte of it, since
a `curl` that returns 200 is not evidence the *right* server answered. Kill the
server by recorded pid, never by a shared `pkill -f` pattern.

Assert on the PNG bytes: PNG magic, `1200×630` from the IHDR, size < 300 KB,
and the `Cache-Control` / `ETag` / `304`-on-`If-None-Match` behaviour.
