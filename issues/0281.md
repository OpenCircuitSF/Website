## Description

`outbox.Store.ClaimDue` and `outbox.Store.OrphanSweep` both take a variadic
`kinds ...Kind` and both implement it as `cardinality($n) = 0 OR kind = ANY(...)`.
**An empty slice therefore means "every kind"** — the variadic makes the
dangerous case the default one.

This is exactly the omission `#0254` bounced on. `#0254` added the filter to
`ClaimDue` and not to `OrphanSweep`, gave `OrphanSweep` a second caller, and the
intake poller's 20s sweep began releasing live mail claims held legitimately for
up to 35s — releasing a claim mid-send so the row reverted to `'queued'` and was
sent again. A duplicate confirmation link.

The fix scoped both live call sites. `#0254`'s reviewer then enumerated every
call site and confirmed **no live instance of the dangerous default remains**:

| Call site | Passes |
|---|---|
| `internal/mailing/outbox_worker.go:364` | `mailKinds...` |
| `internal/handlers/subscribe_intake.go:174` | `KindSubscribeIntake` |
| `internal/outbox/store_test.go:412` | nothing — deliberately exercising the documented default |

So nothing is broken. What is missing is any mechanism stopping the *next* call
site from forgetting, which is the whole of how `#0254` happened.

## Acceptance criteria

1. A guard fails when a `ClaimDue` or `OrphanSweep` call **outside**
   `internal/outbox` passes no kinds. The package's own tests must still be able
   to exercise the unscoped default — scope the rule by caller package, not by
   forbidding the signature.
2. The guard names the offending file and line, and states that an empty
   variadic means every kind, so the failure explains itself.
3. Prove it fires: a fixture call site with no kinds must fail the guard. Per
   CLAUDE.md §8 the oracle must not be the same bytes as the subject.
4. The guard fails closed if its scan finds zero call sites — see
   [#0275](0275.md). A guard that silently measures nothing is worse than none.
5. Consider whether the variadic should become a required parameter with an
   explicit `AllKinds` sentinel, so the safe case is the default and the
   sweeping case has to be asked for by name. If rejected, record why.
6. `ISSUE=NNNN scripts/check.sh go ./internal/... ./cmd/...` passes with no skips.

**Design.** `ClaimDue(ctx, limit int, kinds ...Kind)` and `OrphanSweep(ctx,
staleAfter, kinds ...Kind)` both take exactly two required arguments before
the variadic tail, so a call with exactly 2 `ast.CallExpr` args passed no
kinds at all — the dangerous default — while 3+ means at least one `Kind`
was passed (individually or via a `kinds...` spread, indistinguishable by
count and both safe). The guard (`go/ast`/`go/parser`, no `go/types` —
same rejection reasoning as the sibling `#0282` mailKinds guard: no
marginal precision for real cost) walks `claimKindsGuardScanRoots =
[]string{"..", "../../cmd"}` (i.e. all of `internal/` and `cmd/`,
including `internal/outbox` itself — not pruned from the WALK, only
excluded from the VIOLATION check via an `inOwnPkg` flag computed by
resolving each file's directory against `filepath.Abs(".")`), finds every
`CallExpr` whose selector name is `ClaimDue` or `OrphanSweep`, and fails
listing file:line for any 2-arg call outside `internal/outbox`.

**Method-name collision, checked not assumed** (criterion 1's "scope by
caller package, not by forbidding the signature" plus a real wrinkle found
along the way): `internal/mailing.SendStore` also declares a method named
`OrphanSweep` (`worker_store.go:291`,
`OrphanSweep(ctx, campaignID int64, staleAfter time.Duration)`) — a
completely different, non-variadic signature with no `kinds` parameter at
all. A call to it always has exactly 3 required arguments and can
therefore never satisfy the guard's `argc==2` unscoped check. Verified by
grepping the whole tree for `.ClaimDue(` and `.OrphanSweep(`: the only
non-`internal/outbox` occurrences with `argc==3` are `worker.go:543` and
`worker_store_test.go`'s three `SendStore.OrphanSweep` calls, none of
which has `argc==2`. Documented in `nameMatchesGuardedMethod`'s doc
comment rather than left as an unstated assumption.

**Criterion 2** — failures name file:line and state the semantics

## Review notes

**Verdict: pass.**

### The four violations — each checked as genuinely unscoped before, correctly scoped now

The risk here is a call "fixed" by passing the *wrong* kind: it satisfies the
guard while quietly testing something else. Read each site's enclosing test in
full, not just the diff hunk.

| Site | Before | Kind(s) enqueued in scope | After | Semantics |
|---|---|---|---|---|
| `admin_dashboard_test.go:395` (`TestAdminDashboardOverview_OutboundQueue`) | `ClaimDue(ctx, 100)` | two rows, **both** `KindConfirmation` | `…, outbox.KindConfirmation` | unchanged — the `abandonedID` row is still claimed, and the test still asserts `attempts != 0` for it |
| `admin_dashboard_test.go:453` (`abandonOne` helper in `…AbandonedConfirmationsScopedToKind`) | `ClaimDue(ctx, 100)` | the helper's own `kind` parameter, enqueued one line above | `…, kind` | unchanged, and **more correct**: the test's entire point is per-kind isolation, which an unscoped claim contradicted |
| `admin_pending_test.go:186` | `ClaimDue(ctx, 100)` | one row, `KindConfirmation` | `…, outbox.KindConfirmation` | unchanged — the following `MarkSent` still asserts `done=true`, which only holds if the row was claimed |
| `outbox_worker_test.go:633` (`TestOutbox_Release_RequeuesClaimedRow`) | `ClaimDue(ctx, 10)` | one row, `KindConfirmation` | `…, outbox.KindConfirmation` | unchanged — the next assertion is `status == StatusSending` for that row's own id, so a wrong kind would fail loudly |

All four ran against a shared per-package database, so the scoping also removes
four opportunities for one test to claim a neighbour's rows — a real improvement,
not merely guard-satisfying. The implementer's characterisation ("none was
live-traffic dangerous, each was the `#0254` pattern") is accurate.

### Name-collision handling — no false positives, no false negatives

It does **not** skip anything named `OrphanSweep` in `internal/mailing`; it
evaluates every one by argument count. Verified the reasoning that makes that
safe: `mailing.SendStore.OrphanSweep(ctx, campaignID int64, staleAfter
time.Duration)` has three *required* parameters and no variadic, so `argc==2` is
not merely absent — it does not compile. A false positive is therefore
structurally impossible, not merely absent today. Enumerated the tree myself:
all four `SendStore.OrphanSweep` calls (`worker.go:543`,
`worker_store_test.go` ×3) are `argc==3` and are correctly left unflagged, while
the guard still passes at baseline with them present.

The converse also holds: an `outbox.Store.OrphanSweep` call from
`internal/mailing` would be `argc==2` and *would* be flagged — the collision is
handled without creating a blind spot in the package where it lives.

### Call-site census — the doc's arithmetic is exactly right

Counted independently. `grep` finds 35 textual `.ClaimDue(`/`.OrphanSweep(`
occurrences; three of them live inside the guard file's own fixture **string
literals** and one is prose in a comment, none of which the AST sees. 35 − 3 =
**32**, matching the constant's comment exactly, split 20 in `store_test.go` (in
package, exempt) + 12 outside — also matching. The floor of 5 is measured, not
fitted.

### Exemption and fail-closed

The exemption is `filepath.Abs(dir(file)) == filepath.Abs(".")` — physical
directory, resolved at runtime. Satisfying it requires relocating a file into
`internal/outbox`, which changes its package; there is no in-file marker,
comment, or name an edit could add to earn the exemption (CLAUDE.md §8). The
fixture test proves all three branches directly against in-memory sources:
unscoped-outside fires, scoped-outside does not, own-directory is exempt.

Fail-closed: `len(claimKindsGuardScanRoots) == 0`, `visited == 0`, and
`len(allSites) < 5` all `t.Fatal`. Criterion 4 is met.

### One residual, reported rather than bounced

The fail-closed floor counts **all** call sites, including the ~20 in-package
ones the guard deliberately exempts from evaluation. Measured: narrowing
`claimKindsGuardScanRoots` to `[]string{"."}` leaves 23 sites — comfortably above
the floor of 5 — **zero** of them evaluated, and the guard reports PASS. So the
floor proves the scan reached the *exempt* population, not the *checked* one.

Not a bounce: criterion 4 as written ("fails closed if its scan finds zero call
sites") is met, the constant's own doc comment admits that pruning a whole
package is what it takes, and CLAUDE.md §8 is explicit that stacking another
in-file check against an attacker who is editing the guard file buys another
bounce rather than a guarantee. The clean strengthening is a **second floor on
non-exempt sites** (12 measured today) — reported to the orchestrator as worth
its own small issue.

### Criterion 5 — deferring the `AllKinds` sentinel was right

Agreed, and `#0303` captures it well. The sentinel is the better long-term shape,
but it changes an exported signature and roughly 35 call sites, ~20 of which
exist specifically to exercise the unscoped default and would each need a
deliberate decision. Folding that into a guard-adding dispatch would have made
the guard's own review about an API migration. The guard closes the practical gap
now; `#0303` carries the structural fix with the "the omission has now been made
five times" evidence that justifies it.
