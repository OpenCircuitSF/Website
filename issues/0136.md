## Description

`#0052`'s admin editor previews the workshop body with `web/src/lib/markdown.ts`, a dependency-free Markdown→HTML renderer written for that issue and rendered through `{@html}`. Its first version shipped a live XSS hole — control characters smuggled `javascript:` past the scheme allowlist, past 22 passing tests — fixed in `b562800`.

Campaigns already solved this problem the other way: the body is rendered by **goldmark on the server**. That gives preview/publish parity for free and moves the attack surface out of the browser entirely.

`#0052`'s reviewer put it plainly: the library-vs-hand-rolled question is a false choice, because "no external CDNs" (`CLAUDE.md` §9) governs runtime loading, not npm build dependencies — but the right answer is neither. A `/preview` endpoint mirroring campaigns' means the preview a person sees is produced by the same renderer that will produce the published page.

## Acceptance criteria

- [x] A workshops preview endpoint renders the body with goldmark, mirroring however campaigns' equivalent is built and gated
- [x] The admin editor previews through that endpoint rather than through client-side rendering
- [x] Preview output and published output are produced by the same code path — demonstrate it, don't assert it
- [x] `web/src/lib/markdown.ts` and its tests are deleted once nothing imports them, **or** the issue records why they must stay
- [x] `web/src/views/WorkshopDetail.svelte` (`#0054`) is migrated too — it renders body Markdown through the same client module
- [x] Emphasis inside link text renders again — `[**bold**](/p)` currently emits literal asterisks inside the anchor. That is the cost of the single left-to-right scan `#0052`'s fix introduced to stop emphasis rewriting `href` attributes, and a server-side renderer makes it moot
- [x] `ISSUE=0136 scripts/check.sh go ./internal/handlers/...` and `scripts/check.sh web` both pass

## Root cause

`#0052` shipped `web/src/lib/markdown.ts`, a dependency-free Markdown->HTML
renderer, and rendered its output client-side via `{@html}` for the admin
editor's preview and (`#0054`) the public workshop detail page. Its first
version shipped a live XSS hole — control characters smuggling `javascript:`
past the scheme allowlist, past 22 passing tests — because a hand-rolled
sanitizer and a browser's URL-normalization algorithm can silently disagree
about what counts as a URL. `b562800` closed that specific hole, but every
future edit to the same hand-rolled renderer was a chance to reopen a
sibling bug — and it already had one: the fix's own left-to-right link/
emphasis scan broke emphasis *inside* link text (`[**bold**](/p)` emitted
literal asterisks), because links and emphasis were two separate regex
passes with no shared parse tree. Campaigns had already solved the general
problem the right way (goldmark on the server, `#0042`/`#0043`), and
`#0052`'s own reviewer named the fix as a follow-up rather than re-hardening
the client renderer a second time.

## Fix

- `internal/handlers/admin_workshop_preview.go` (new): `AdminWorkshopsHandler.Preview`
  serves `POST /admin/workshops/{id}/preview`, mirroring
  `AdminCampaignPreviewHandler.Preview` — admin-gated via the existing
  `adminRoutes` table, never calls `decodeJSON` (no override code path to
  forget to validate), loads the workshop by id, and renders `body_md`
  through `renderWorkshopBodyHTML`, a thin wrapper over
  `internal/mailing.RenderMarkdownHTML` (the exact goldmark instance
  `email_campaigns.body_md` already renders through — safe mode, no raw
  HTML, images stripped to an inert marker, dangerous-scheme hrefs
  dropped).
- `internal/handlers/public_workshops.go`: `publicWorkshopView` gained
  `body_html` (`omitempty`), computed by `toPublicView` calling the SAME
  `renderWorkshopBodyHTML` function the preview endpoint calls — there is
  now exactly one call site in this package that turns a workshop's
  `body_md` into HTML, which is what makes preview/publish parity provable
  rather than assumed (see `## Verification`). A render error degrades to
  an omitted `body_html` rather than a 500, matching `toPublicView`'s
  existing "degraded but safe" posture for a failed interest-tag lookup.
- `cmd/opencircuit/main.go`: registered the new route inside the existing
  `adminWorkshopsH != nil` block of `adminRoutes()` — no constructor or
  `mountAndServe` signature changes, same shape `#0056`'s Announce route
  used.
- `web/src/lib/markdown.ts`: `renderMarkdownPreview` and every helper it
  used (`escapeHtml`, `applyEmphasis`, `renderInline`, `renderBlocks`, the
  heading/list-item regexes, `LINK_RE`) are deleted. `isSafeLinkHref`
  survives, unmodified — `workshopDetail.ts`'s `hasExternalSignup` (`#0054`)
  and `admin_workshops.go`'s Go twin (`#0152`) both depend on it, and
  neither is a Markdown renderer.
- `web/src/lib/types.ts` / `web/src/lib/api.ts`: added `PublicWorkshop.body_html`
  and `WorkshopPreviewResponse`, plus `previewWorkshop(id)`.
- `web/src/views/admin/WorkshopEditor.svelte`: dropped the client-side
  `renderMarkdownPreview` derived value. `refreshPreview()` now calls
  `previewWorkshop(workshopId)` after `load()` and after every successful
  `save()` — this editor has explicit Save (not autosave), so the preview
  reflects the last-saved row, the same "never preview one thing and
  publish another" contract campaigns' autosave-then-preview flow
  established. Preview pane now handles loading/error states.
- `web/src/views/WorkshopDetail.svelte`: `bodyHTML` is now
  `workshop?.body_html ?? ''` — server-rendered, trusted HTML — instead of
  running `workshop.body_md` through the client renderer.

  emphasis-in-link anchor) is actually present — not two empty strings
  trivially matching.
- **Emphasis inside link text**:
  `TestAdminWorkshopPreview_EmphasisInsideLinkText` confirms
  `[**bold**](/p)` renders `<a href="/p"><strong>bold</strong></a>` — no
  literal asterisks, since a real parser has no left-to-right-scan conflict
  between link and emphasis parsing.
- **Safety payloads run, not assumed** (`TestRenderWorkshopBodyHTML_SafetyPayloads`,
  a pure-function test with no DB, plus `TestAdminWorkshopPreview_SafetyPayloads`
  end-to-end): raw `<script>`, `<img onerror>`, plain `javascript:`/`data:`
  schemes, and `#0052`'s five control-character disguises
  (`java\tscript:`, `java\rscript:`, `javascript\t:`, a leading `\x01`, a
  leading NUL byte). Before writing assertions, a temporary probe test
  against `internal/mailing.RenderMarkdownHTML` was run and its output
  inspected by hand (then deleted — never committed):
  - Raw `<script>`/`<img onerror>` render as an HTML comment
    (`<!-- raw HTML omitted -->`) — goldmark's safe mode, unmodified.
  - `javascript:`/`data:` destinations render with an empty `href=""`.
  - The three whitespace-spliced forms (`java\tscript:`, `java\rscript:`,
    `javascript\t:`) never parse as a link at all — CommonMark's own
    link-destination grammar rejects an unescaped control/whitespace
    character inside `(...)`, so the source falls back to literal
    paragraph text with no `<a>` tag.
  - The two non-whitespace control characters (`\x01`, NUL) DO parse as
    part of the destination, but goldmark's `util.URLEscape`
    percent-encodes them (`%01…`, `%00…`) rather than emitting the raw
    byte the way `markdown.ts`'s original bug did. Verified independently
    against Node's WHATWG `URL` parser: `new URL("%01javascript:alert(1)",
    "https://opencircuitsf.com/workshops/x")` resolves with
    `protocol: "https:"`, never `javascript:` — a percent-encoded `%01`
    cannot start a URL scheme (RFC 3986/WHATWG both require an ASCII
    letter first). The emitted HTML *does* contain the literal substring
    `javascript:` (as inert path text after the percent-encoded prefix),
    which is why the test asserts on `hrefStartsWithDangerousScheme`
    (checks `href="javascript:`/`href="data:`, etc.) rather than a bare
    substring search — a bare search would have failed on genuinely safe
    output.
  - A literal NUL byte in `body_md` can never reach the database at all:
    seeding a workshop with one via the real store fails with
    `SQLSTATE 22021` ("invalid byte sequence for encoding UTF8: 0x00"), so
    that specific case is only exercised via the pure-function test, not
    the DB-backed end-to-end one.
- **Admin gating**: `TestAdminWorkshopPreview_Unauthenticated` (401, no
  session) and `TestAdminWorkshopPreview_NonAdminForbidden` (403, non-admin
  session) both pass; the preview route was also added to
  `TestAdminWorkshops_NonAdminForbidden`'s existing table and to
  `cmd/opencircuit/admin_wiring_test.go`'s generic
  `adminRoutes(...)`-driven wiring test (which required no changes — it
  iterates the route table automatically) and
  `admin_routes_ast_test.go`'s AST check that no `/admin` route bypasses
  that table.

## Gotchas

- **Goldmark's safe mode does not reject a protocol-relative link
  (`//evil.host/x`) inside body Markdown text.** It only refuses a
  dangerous *scheme* (`javascript:`, `vbscript:`, `file:`, most `data:`);
  a `//host/path` destination survives as a live, off-site `<a href>`.
  This is **not a regression #0136 introduces** —
  `internal/mailing.RenderMarkdownHTML` is the exact function
  `email_campaigns.body_md` has rendered through since `#0042`/`#0043`,
  shipped and reviewed, with this same property; reusing it for workshops
  inherits campaigns' existing posture unchanged. It **is** a narrowing
  relative to the deleted client renderer specifically for workshop BODY
  content: `markdown.ts`'s `renderMarkdownPreview` ran every link through
  `isSafeLinkHref`, which has rejected protocol-relative destinations since
  `#0138`. `signup_url` and `cover_image` are unaffected — both are still
  gated by their own dedicated Go validators (`isSafeLinkHref`/
  `isSafeCoverImage`, `#0138`/`#0152`) at the API boundary, untouched by
  this change. Pinned by
  `TestAdminWorkshopPreview_ProtocolRelativeLinkInheritsCampaignBehavior`,
  which documents the current behavior rather than asserting a fix — left
  for the reviewer to judge whether a follow-up extending goldmark's link
  policy (which would also affect campaigns, an unrelated subsystem) is
  worth filing. Per `CLAUDE.md` §9, this implementer does not file it.
- **Workshop body preview is no longer "live while typing."** The editor
  has explicit Save (not autosave, unlike `CampaignEditor.svelte`), and the
  new preview endpoint always renders the STORED row — the same contract
  campaigns' preview already enforces. So the preview pane now shows the
  last-saved body, refreshed after `load()` and after each successful
  `save()`, not the in-progress unsaved buffer. This is a deliberate
  consequence of "preview must equal publish," not an oversight.
- **`web/dist/index.html` was not touched.** `npm run build` was never run
  during this issue (only `npm run check` and `npm test`), so the tracked
  placeholder (`#0141`) needed no restoring; `git status -- web/dist/index.html`
  stayed clean throughout.
- A temporary, uncommitted probe test
  (`internal/mailing/zz_probe_test.go`) was written and deleted during
  verification to inspect goldmark's actual output for the control-character
  payloads before writing assertions against them — see `## Verification`.
  It never touched `git add`/`git status` as tracked content; confirmed via
  `git status --porcelain internal/mailing` showing nothing both before and
  after.
