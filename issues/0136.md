## Description

`#0052`'s admin editor previews the workshop body with `web/src/lib/markdown.ts`, a dependency-free Markdown→HTML renderer written for that issue and rendered through `{@html}`. Its first version shipped a live XSS hole — control characters smuggled `javascript:` past the scheme allowlist, past 22 passing tests — fixed in `b562800`.

Campaigns already solved this problem the other way: the body is rendered by **goldmark on the server**. That gives preview/publish parity for free and moves the attack surface out of the browser entirely.

`#0052`'s reviewer put it plainly: the library-vs-hand-rolled question is a false choice, because "no external CDNs" (`CLAUDE.md` §9) governs runtime loading, not npm build dependencies — but the right answer is neither. A `/preview` endpoint mirroring campaigns' means the preview a person sees is produced by the same renderer that will produce the published page.

## Acceptance criteria

- [ ] A workshops preview endpoint renders the body with goldmark, mirroring however campaigns' equivalent is built and gated
- [ ] The admin editor previews through that endpoint rather than through client-side rendering
- [ ] Preview output and published output are produced by the same code path — demonstrate it, don't assert it
- [ ] `web/src/lib/markdown.ts` and its tests are deleted once nothing imports them, **or** the issue records why they must stay
- [ ] `web/src/views/WorkshopDetail.svelte` (`#0054`) is migrated too — it renders body Markdown through the same client module
- [ ] Emphasis inside link text renders again — `[**bold**](/p)` currently emits literal asterisks inside the anchor. That is the cost of the single left-to-right scan `#0052`'s fix introduced to stop emphasis rewriting `href` attributes, and a server-side renderer makes it moot
- [ ] `ISSUE=0136 scripts/check.sh go ./internal/handlers/...` and `scripts/check.sh web` both pass

## Notes

Filed from `#0052`'s phase-3 review. Not urgent — `b562800` closed the known hole and the input is admin-authored — but every future edit to a hand-rolled sanitizer is a chance to reopen it, and the server-side renderer already exists.

Worth reading before starting: the bypass table in `issues/0052.md`'s `## Review notes`. It is a good record of how a scheme allowlist fails when the checker and the browser disagree about what a URL is.
