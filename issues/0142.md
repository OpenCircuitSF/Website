## Description

`#0135` widened the partial index in `migrations/000020` from `WHERE status = 'published'` to `WHERE status <> 'draft'`, so it now covers published **and** canceled workshops. The name stayed `idx_workshops_published`.

That was a deliberate, defensible call — the implementer judged the Go method name (`ListPublished` → `ListVisible`) to be the misleading surface that mattered, and both the migration comment and `docs/database.md` explain the predicate. The residual risk is narrow: someone meeting the index through `\d workshops`, with no comment in sight, reasonably concluding the schema drifted from its own naming.

The reason to file rather than shrug: **this is a three-line edit only while the greenfield exception holds.** `CLAUDE.md` §1 lets `migrations/` be rewritten until the first deploy applies a migration to production. After that, renaming an index means a new migration, and nobody will bother — the name will be wrong for the life of the project.

## Acceptance criteria

- [ ] The index is renamed to something that describes its actual predicate — `idx_workshops_public` or similar — in `migrations/000020` directly, per the greenfield note
- [ ] `docs/database.md` and the store's doc comment follow
- [ ] The test template is rebuilt (`scripts/testdb.sh template`) so the rename is in effect, and `EXPLAIN` confirms the renamed index is still used by both halves of `ListVisible`'s query
- [ ] `ISSUE=0142 scripts/check.sh go ./internal/...` passes, doc-parity guards included
- [ ] If the first production deploy has happened by the time anyone picks this up, close it as `wontfix` rather than stacking a migration for a cosmetic rename

## Notes

Raised by `#0135`'s phase-3 review, which explicitly declined to block on it and left the call to the orchestrator. Filed at Phase 6 with no dependents; it is pure hygiene.

Worth knowing from that review: `EXPLAIN (ANALYZE)` on 6000 seeded rows confirms both queries ride this index, and restoring the old predicate inside a rolled-back transaction drops the new query to a `Seq Scan` — so the widening was load-bearing, not cosmetic. Only the name is cosmetic.
