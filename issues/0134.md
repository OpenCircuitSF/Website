## Description

Four surgical defects `#0051`'s phase-3 review found and proved. None was an unmet acceptance criterion, so `#0051` passed; the first is a real runtime bug and the other three are claims that contradict the code they sit next to.

**1. `Create` is not atomic.** Passing an unknown `interest_id` returns `ErrInterestNotFound` **and leaves the workshop row behind** — the reviewer measured `count(*) = 1` after the error. The slug-retry loop has to insert outside a transaction, so the insert survives the failed tag step. The result is a ghost draft that burns a slug and gets no audit row, reachable from `#0052`'s admin UI. `Update`, tested the same way, *is* atomic, and the precedent cited in `#0051`'s own `## Fix` — `mailing.CampaignStore.Create` — does the whole thing in one transaction.

**2–4. Three statements that are false as written**, each next to the code that disproves it:
- `internal/audit/actions.go`'s new comment says a `-> canceled` transition is recorded as `ActionWorkshopUpdated`. It is not: `ActionWorkshopCanceled` is declared three lines below and the shipped handler emits it — `#0051`'s own test observes `published, unpublished, published, canceled`.
- `NewAdminWorkshopsHandler`'s doc comment claims "every production call site passes a real `*seo.Site`". False — `main.go` passes `nil`, which is the deferral `#0051`'s review blessed and `#0054` now carries.
- `docs/database.md` gained a **new** wrong clause while `#0051` was fixing the two `#0050` flagged: it says `campaign_interests` lacks `ON DELETE CASCADE`, but `migrations/000017:55-56` sets it, and `#0050`'s ruling was about a missing *index*, which that row never mentions.

## Acceptance criteria

- [ ] `workshops.Store.Create` is atomic: a bad `interest_id` leaves **no** workshop row. Prove it the way the reviewer did — call `Create` with an unknown interest, assert the error, then assert `count(*) = 0` for that slug
- [ ] Slug collision handling survives the fix — two workshops with the same title still get distinct slugs, and the retry loop still works inside whatever transaction structure you choose
- [ ] The `actions.go` comment describes what the handler actually emits for `-> canceled`
- [ ] `NewAdminWorkshopsHandler`'s doc comment stops claiming every production call site passes a real `*seo.Site`, or is rewritten after `#0054` makes it true
- [ ] `docs/database.md`'s `campaign_interests` clause matches `migrations/000017:55-56`
- [ ] `ISSUE=0134 scripts/check.sh go ./internal/...` passes with zero skips, and the doc-parity guards run
