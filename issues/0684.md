## Description

These are follow-ups from `#0675`'s review.

1. **Abandoned rows block retries.** If `Complete` fails, or the process dies partway through an operation, the `api_idempotency_keys` row stays in flight. Every retry with that key then gets a 409 ("still in progress") for the full 24-hour TTL. Treat an in-flight row older than a few minutes (for example 5) as abandoned, and let the retry take it over.
2. **Expired rows linger.** Only `Begin` sweeps expired rows, so they stay until the next request that carries an `Idempotency-Key`. This is harmless, but a periodic sweep, or one at startup, would keep the table small.

Do this before or alongside `#0676`, which adds the first create operation.
