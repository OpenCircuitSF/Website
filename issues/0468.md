## Description

`#0435` recommends leaving `BACKUP_ALERT_WEBHOOK_URL` unconfigured for now,
because no notification channel exists anywhere in this project, and offers
`journalctl -p err` and `systemctl --failed` as the interim signal.

`#0435`'s reviewer agreed with the recommendation and rejected the
justification:

> Both are pull-based and **nothing is scheduled to pull them**, so a silent
> nightly failure stays silent in exactly the way this issue exists to fix.

That is right. `opencircuit-backup.service` carries `OnFailure=`, so a failed
run does mark the unit failed — but a mark nobody reads is not a signal.

## Why it matters more than it looks

The failure mode is **silent and slow**. A backup that stops working produces no
output; it produces the *absence* of output, which is the hardest thing to
notice. And the window in which nobody notices is exactly the window in which
the backup is needed.

`#0434`'s review found a version of this already: a media backup that would have
deleted its own last copy while **exiting 0**, so `OnFailure=` would never have
fired at all. The interim answer to that class cannot itself be "someone will
check the journal".

## Acceptance criteria

1. Decide what the interim signal actually is. **A pull-based command counts
   only if something is scheduled to pull it** — and if that is the answer, the
   schedule is part of the deliverable, not a note.
2. If the honest answer is that there is no signal until a channel exists, say
   so plainly in `deploy/systemd/README.md` rather than implying `journalctl`
   fills the gap. An accurate statement of a gap is worth more than a
   reassurance that does not hold.
3. Consider the cheap options before the expensive one: a `systemd` timer that
   reports non-empty `systemctl --failed`, mail to a local mailbox, or a
   heartbeat the user checks on their own cadence. **`#0271` settled that
   `contact@opencircuitsf.com` is a real Google Workspace mailbox** — check
   whether that is a usable destination before proposing a new channel.
4. **Do not build a notification channel** without the user's decision. §9's
   restricted areas cover outward-facing sends, and this project's mail path is
   SES, which is still sandboxed pending `#0415`.
5. **Nothing runs on the box** without approval (§5b, §9).
