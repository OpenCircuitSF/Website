## Resolution notes

> 🟢 Resolved 2026-10-19 — `scripts/check.sh browser-nav` now drives Safari only inside a disposable Tart clone, and all 17 navigation assertions pass there unchanged.

## Description

`scripts/browser_nav_guard_test.sh` (run by `scripts/check.sh browser-nav`,
`#0287`) starts `safaridriver` and Safari on the host. `AGENTS.md` §8 now
forbids launching any browser on the host; rendered checks run in a
disposable Tart VM clone. Until this moves into a guest, the check cannot be
run at all, and `issues/Issues.md` keeps it out of every tier.

## Root cause

`browser_nav_guard_test.sh` was written (`#0287`) before `AGENTS.md` §8
banned host browsers: it ran `open -a Safari` and `safaridriver` on the host
and served the build on two host loopback ports.

## Fix

Implemented the plan as written. Safari, `safaridriver` and the stub server
now run only inside a uniquely named Tart clone (`ocsf-browsernav-<pid>-<rand>`)
of the image `tart-golden path` names, booted `--no-graphics --no-audio` with
the build directory as a read-only share. The guest copies `dist/` out and
serves on its own loopback (8765); `safaridriver` binds guest loopback 4444.
All WebDriver traffic goes through `tart exec -i … curl` with JSON on stdin,
so the host binds nothing. Host port selection is gone. The EXIT trap deletes
the session, stops and deletes the clone by exact name, releases the lease,
and removes the build dir. Assertions, JS snippets, sleeps and expected values
are unchanged.

Deviation: **the `issues/Issues.md` tier edit (criterion 4) was not made
here.** `#0607` has that file open; the orchestrator will make the edit after
`#0607` lands.

## Plan

Written 2026-10-19 against the code as it stands. **The VM route is workable,
and it has already been done by hand on this project.** The 2026-10-17 outreach UX
walk (`docs/reviews/outreach-ux-2026-10-17/README.md`) and `#0561`'s review
both drove Safari 26.6.2 with `safaridriver` inside a clone of `uitest-golden`.
They copied a built `dist/` in through a read-only Tart share, served it on the
guest's own `127.0.0.1`, ran `sudo safaridriver --enable` and
`safaridriver -p 4444` in the guest, and drove it with `curl` through
`tart exec`. Nothing bound a host port. Neither rig was committed, which is
why this issue exists. This plan turns that shape into the script.

**Design in one paragraph.** The host still does the build: rsync `web/` into
`.scratch/`, then `npm run build`, unchanged. The host still runs every
assertion and all the `jq` parsing, unchanged. Only two things move into the
guest: the static/stub server and Safari plus `safaridriver`. Every WebDriver
HTTP call goes through `tart exec -i "$CLONE" curl … --data-binary @-`, which
reaches the guest's loopback, so the host binds nothing. `tart exec` carries
the request on stdin and the response on stdout.

### Approach: `scripts/browser_nav_guard_test.sh`

Keep these exactly as they are: `set -uo pipefail`, `fail`/`pass`/`note`/`step`,
the `node_modules` check, the whole BUILD section (rsync, symlink, `npm run
build`, `BUNDLE_JS` extraction), the `stub_server.py` heredoc contents,
`CAPTURE_JS`, `assert_eq`, `assert_contains`, `assert_nav_snapshot`, every JS
snippet, every `sleep`, every expected value, and the verdict block.

1. **Header comment.** Rewrite the TOOL CHOICE, PORTS, and CLEANUP paragraphs:
   - Safari and `safaridriver` run only inside a disposable Tart clone of the
     golden image named by `tart-golden path`, per `AGENTS.md` §8 and
     `~/Developer/Homelab/cameron/tart-ui-test-vm.md`.
   - Nothing listens on any host interface. The server and the driver bind
     fixed ports on the **guest's** loopback (`8765`, `4444`). That is
     collision-free because each run has its own clone.
   - Cleanup stops and deletes the clone and releases the lease.

   Delete the sentence about launching Safari.app on the host. Cite `#0609`.
2. **Tool check.** Change the loop to `rsync python3 jq npm tart tart-lease
   tart-golden`. Drop `safaridriver` and `curl`: neither runs on the host any
   more.
3. **Delete host port selection entirely.** That is `port_listeners`,
   `port_bound`, `pick_pbase`, `PBASE`, `SERVER_PORT`, and `DRIVER_PORT`. Keep
   `RUNID="${ISSUE:-$$}"` and `NOTFOUND_SLUG`. Add:
   ```bash
   GUEST_SERVER_PORT=8765
   GUEST_DRIVER_PORT=4444
   GOLDEN="$(tart-golden path)" || { echo "error: no Tart golden image (tart-golden path failed)" >&2; exit 1; }
   CLONE="ocsf-browsernav-$$-$RANDOM"
   ```
   Never write the literal `uitest-golden` in the script. The tart-golden
   protocol forbids that. Add a guard:
   `[ "$CLONE" != "$GOLDEN" ] || exit 1`.
4. **State and cleanup.** Add `LEASE_ID=""`, `RUN_PID=""`, and
   `CLONE_MADE=0`. Remove `SERVER_PID` and `DRIVER_PID`, since the guest
   processes die with the clone. The new `cleanup()`, with `set +e`, runs in
   this order:
   1. If `SID` is set, delete the WebDriver session through `gcurl -X DELETE
      "$WD_BASE"`.
   2. If `CLONE_MADE=1`, run `tart stop "$CLONE"`, then `kill "$RUN_PID"` and
      `wait` it if it is still alive, then `tart delete "$CLONE"`.
   3. If `LEASE_ID` is set, run `tart-lease release --id "$LEASE_ID"`.
   4. `rm -rf "$BUILD_DIR"`, as now.

   Never sweep other clones by pattern (`AGENTS.md` §5a). Never `tart` anything
   named `$GOLDEN`. Keep `trap cleanup EXIT INT TERM`, installed before the
   build as now.
5. **Guest curl helper.** Define this right after `cleanup`:
   ```bash
   # every WebDriver/HTTP call runs INSIDE the guest -- the host binds nothing (#0609)
   gcurl() { tart exec -i "$CLONE" curl -s "$@"; }
   ```
   Rewrite `wd_exec`, `wd_nav`, and `wd_back` to pipe their JSON body in on
   stdin. That way no JSON travels as an argv word:
   `printf '%s' "$body" | gcurl -X POST "$WD_BASE/execute/sync" -H
   'Content-Type: application/json' --data-binary @- --max-time 15`.
   `wd_nav` and `wd_back` follow the same pattern, with `{}` as `wd_back`'s
   body. A call with no body (`/status`, `DELETE`) uses `gcurl …
   </dev/null` so `-i` never waits on the terminal. `WD_BASE` becomes
   `http://127.0.0.1:$GUEST_DRIVER_PORT/session/$SID`.
6. **After the build, replace the "Starting the static/stub server" and
   "Starting safaridriver" sections** with a new section, `step "Starting a Tart
   guest ($CLONE from $GOLDEN)"`:
   ```bash
   LEASE_ID="$(tart-lease acquire --label ocsf-browser-nav --pid $$)" || { echo "error: tart-lease acquire failed" >&2; exit 1; }
   tart clone "$GOLDEN" "$CLONE" || { echo "error: tart clone failed" >&2; exit 1; }
   CLONE_MADE=1
   tart run "$CLONE" --no-graphics --no-audio --dir=run:"$BUILD_DIR":ro >"$BUILD_DIR/tart-run.log" 2>&1 &
   RUN_PID=$!
   booted=0
   for _ in $(seq 1 60); do               # ~180 s ceiling; a boot measured ~14 s
     tart exec "$CLONE" true </dev/null >/dev/null 2>&1 && { booted=1; break; }
     kill -0 "$RUN_PID" 2>/dev/null || break
     sleep 3
   done
   [ "$booted" -eq 1 ] || { echo "error: guest never answered tart exec" >&2; tail -20 "$BUILD_DIR/tart-run.log" >&2; exit 1; }
   ```
   Write the stub server file **before** this step, as now. It lands in
   `$BUILD_DIR` and so is visible in the share. Then run one guest setup
   script through `tart exec -i "$CLONE" bash -s <<GUEST` (unquoted delimiter
   on purpose, to expand the ports and slug; no backticks inside, per
   `AGENTS.md` §8):
   ```bash
   set -e
   rm -rf ~/bn && mkdir -p ~/bn
   cp -R "/Volumes/My Shared Files/run/web/dist" ~/bn/dist
   cp "/Volumes/My Shared Files/run/stub_server.py" ~/bn/
   (nohup python3 ~/bn/stub_server.py ~/bn/dist $GUEST_SERVER_PORT $NOTFOUND_SLUG >~/bn/server.log 2>&1 &)
   sudo -n safaridriver --enable
   (nohup safaridriver -p $GUEST_DRIVER_PORT >~/bn/safaridriver.log 2>&1 &)
   GUEST
   ```
   Copying out of the share matters. The share is read-only and is the host's
   `.scratch` copy, so the guest serves its own copy (criterion 2). Next, poll
   `gcurl "http://127.0.0.1:$GUEST_SERVER_PORT/" -o /dev/null -w '%{http_code}'
   </dev/null` until it reads `200`, and poll `gcurl
   "http://127.0.0.1:$GUEST_DRIVER_PORT/status" </dev/null` until it contains
   `"ready":true`. Use 50 tries 0.2 s apart, the same loop shapes as today. On
   failure, print `tart exec "$CLONE" cat ~/bn/server.log` or
   `~/bn/safaridriver.log` and exit 1.
7. **Session.** Use `printf '%s'
   '{"capabilities":{"alwaysMatch":{"browserName":"safari"}}}' | gcurl -X POST
   "http://127.0.0.1:$GUEST_DRIVER_PORT/session" -H 'Content-Type:
   application/json' --data-binary @- --max-time 60`. 60 s, because the first
   session launches Safari in a fresh guest. Parse `SID` with `jq` on the host,
   as now.
8. **URLs.** Replace both `http://127.0.0.1:$SERVER_PORT/...` with
   `http://127.0.0.1:$GUEST_SERVER_PORT/...`. Do not touch anything else in the
   test sequence. The server-identity check, which reads `BUNDLE_JS` back from
   `document.scripts`, stays. It now also proves the guest is serving this
   run's build.
