## Description

`scripts/browser_nav_guard_test.sh` (run by `scripts/check.sh browser-nav`,
`#0287`) starts `safaridriver` and Safari on the host. `AGENTS.md` §8 now
forbids launching any browser on the host; rendered checks run in a
disposable Tart VM clone. Until this moves into a guest, the check cannot be
run at all, and `issues/Issues.md` keeps it out of every tier.

## Acceptance criteria

- [ ] `browser_nav_guard_test.sh` runs Safari and `safaridriver` inside a Tart
      VM clone per `~/Developer/Homelab/cameron/tart-ui-test-vm.md`:
      `tart-lease acquire`, a uniquely named clone of `uitest-golden`,
      `tart run --no-graphics --no-audio`, and an `EXIT` trap that stops and
      deletes the clone and releases the lease. It never modifies a
      `*-golden` image and never starts a browser on the host.
- [ ] Nothing it serves binds a non-loopback host interface; the guest reaches
      the build by copying it in or by the VM's own network path, per the
      Tart doc.
- [ ] Its assertions (title, focus, `scrollY`, `history.state.scrollY` over
      the three navigation paths) are unchanged and pass in the guest.
- [ ] `issues/Issues.md`'s "Not in any tier" note is replaced by a row placing
      `browser-nav` in the full tier for changes to client-side navigation.
- [ ] Verified by one passing `scripts/check.sh browser-nav` run in the guest,
      with its PASS lines quoted.
