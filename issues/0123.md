## Description

Every campaign that has been sent gets a permanent, public, search-indexable page at `/archive/{slug}`, plus an index at `/archive` linked from Home and the footer. The slug is minted when the campaign is **created as a draft**, not when it is sent, so short links and promotional copy can be prepared against the final URL before the send goes out.

## Notes

PRD §6.8 is the specification; §5.1 and §8 carry the routes.

**Why the slug is assigned at draft time.** The user's requirement, and the reason this is not a detail: promotion for a campaign — a `go.opencircuitsf.com` short link, a Discord post, a Luma event description — is written before the send. If the slug were minted at send time the URL would not exist when the marketing needs it. Minting at draft time also means the campaign compose screen can show the copyable URL immediately.

**Attribution without tracking.** Archive URLs are the landing target for short links carrying `utm_source` / `utm_medium` / `utm_campaign`. `#0026` already captures those on signup, so promotion of a campaign gets per-channel attribution with nothing added to the email. The §2 non-goals stand: no open-tracking pixels, no per-recipient click tracking, no third-party analytics.

**`withheld` must be `410`, not `404`.** A published page that later goes away has been deliberately retracted; `410 Gone` tells crawlers to drop it, `404` invites re-crawling.

## Review notes

**2026-08-27 — review (Opus): bounced. Status stays `in-progress`.**

The public exposure surface, the migration, the renderer split, and the SEO
wiring are all correct and were verified by fetching and by measurement, not
by reading tests (details below). The bounce is for **one omission with three
distinct user-visible failures**: `AdminCampaignsHandler.Patch` was never
updated to carry the new `CampaignUpdate.Slug` field, so it calls `Update`
with the zero value on every request.

### Blocker — `PATCH /admin/campaigns/{id}` sends `Slug: ""`

`internal/handlers/admin_campaigns.go`'s `Patch` builds its
`mailing.CampaignUpdate{…}` (line ~547) with `Name/Subject/Preheader/BodyMD/
AudienceMode/InterestIDs` and **no `Slug`**. `CampaignStore.Update` then runs

```go
slug := in.Slug              // ""
if slug != current.Slug {    // "" != "the-real-slug"  -> true
    if current.Status != CampaignStatusDraft { return ErrCampaignSlugNotEditable }
}
```

Measured against a real database and the real mux (`httptest` server,
`adminCampaignsMux`, real stores), three failures fall out of that one line:

1. **A draft campaign's slug is destroyed by an ordinary save.** Created with
   `slug = "…-promo-subject"`; one `PATCH {"body_md":"new body"}` returned
   `200` with `"slug":""` in the body, and `GetByID` confirms the column is
   now the empty string. This is the exact feature the issue calls
   load-bearing: the compose screen's copyable URL becomes
   `https://www.opencircuitsf.com/archive/` (`web/src/lib/campaigns.ts`'s
   `archiveURL` interpolates the blank), the archive page becomes
   unreachable, and `RenderCampaign` silently drops the "View this email in
   your browser" link because it gates on `in.Slug != ""`. Short links and
   promo copy written against the reserved URL break the moment the operator
   edits the draft.
2. **`PATCH` of a *scheduled* campaign now returns `500`.** Editing a
   scheduled campaign is supported (`ErrCampaignNotEditable` fires only
   outside `draft|scheduled`). With `Slug: ""` it hits
   `ErrCampaignSlugNotEditable`, which is **not in `Patch`'s error switch**,
   so it falls to `default:` → `{"error":"internal server error"}`. Measured:
   `PATCH scheduled -> 500`.
3. **The second draft edited collides.** Only one row can hold `slug = ''`
   under the UNIQUE constraint. Measured: PATCH of draft A → `200` (slug
   blanked); PATCH of draft B → `500`. `ErrCampaignSlugTaken` is also
   unmapped in the switch, so a genuine collision is a `500` rather than a
   `409` too.

`ISSUE=0123r scripts/check.sh` is **green** with all three present — the
suite proves the store in isolation (every `CampaignUpdate` literal in
`campaign_archive_test.go` sets `Slug:` explicitly) and never asserts the
slug survives an HTTP `PATCH`. That coverage gap is part of what must change.

### Required remedy

1. `internal/handlers/admin_campaigns.go` — `patchCampaignRequest` gains
   a `Slug *string` field tagged `json:"slug,omitempty"`; `Patch` merges it the same way
   every other field is merged:
   ```go
   slug := current.Slug
   if req.Slug != nil {
       trimmed := strings.TrimSpace(*req.Slug)
       if trimmed == "" { writeError(w, 400, "slug cannot be empty"); return }
       slug = trimmed
   }
   ```
   and passes `Slug: slug` into `mailing.CampaignUpdate`.
2. Same file — map the two new sentinels in `Patch`'s error switch:
   `mailing.ErrCampaignSlugNotEditable` → `409` ("a campaign slug can only be
   changed while it is a draft"), `mailing.ErrCampaignSlugTaken` → `409`
   ("that slug is already in use").
3. `internal/mailing/campaigns.go` — make `Update` fail safe rather than fail
   destructive: treat an empty `in.Slug` as "keep the current value"
   (`if in.Slug == "" { slug = current.Slug }`) before the
   differs-from-current check. This is the guard that would have made all
   three failures impossible from one forgetful caller, and it costs one
   line.
4. `migrations/000025_add_campaign_archive_columns` — add
   `CHECK (btrim(slug) <> '')` alongside the existing archive_status CHECK
   (and the matching `DROP CONSTRAINT` in the `.down.sql`). `NOT NULL` does
   not stop `''`, and the whole package documents "Slug is never blank" as an
   invariant that the worker, the SEO adapter, and the email renderer all
   rely on. **000025 is not frozen**: production is at `schema_migrations.
   version = 22`, so 25 has never been applied to a database anyone cares
   about and may still be edited in place (CLAUDE.md §1). Rebuilding the
   shared test template is the coordination cost — check whether #0315 is
   still in flight in `scripts/testdb.sh` before doing it.
5. Tests that must exist, all through the real mux against a real database:
   - PATCH a draft → the `200` body's `slug` equals the create-time slug and
     is non-empty;
   - PATCH a *scheduled* campaign with no `slug` in the body → `200`;
   - PATCH two drafts in sequence → both `200`;
   - PATCH a scheduled campaign with an explicitly *different* `slug` → `409`,
     not `500`;
   - PATCH a draft with a slug already held by another campaign → `409`;
   - store-level: `Update` with a zero-value `CampaignUpdate.Slug` leaves the
     stored slug untouched.

### What passed, and how it was verified

**The public page, fetched rather than read about.** A campaign was seeded
with a hostile body (`<script>alert(1)</script>`, `<img src="https://evil.
example/pixel.gif">`, a remote `![]()` image, a raw `<a href="javascript:…">`,
a `{{first_name}}` token, and a link carrying `?token=SECRETTOKEN`), forced to
`sent`/`published`, and fetched over a real `httptest` server. The raw 200
body is exactly five keys — `slug`, `subject`, `preheader`, `body_html`,
`archived_at`. No `id`, `status`, `audience_mode`, `interest_ids`,
`recipients`, `manage_token`, `created_by`. §9 holds in the rendered HTML
too: every raw HTML node came back as `<!-- raw HTML omitted -->` and the
remote image as `<em>[image not included: remote]</em>`, so no third-party
pixel, tracker, or CDN reference can be smuggled through a campaign body onto
a public page. `{{first_name}}` survives as literal text, which is correct —
this project has **no** campaign-body merge substitution at all (`{{cta}}` is
a transactional-template token in `templates.go`, never a campaign body one),
so there is no per-recipient value that could have been left unsubstituted.
`ArchiveEntry.svelte` and `ArchiveIndex.svelte` contain no external URL, no
`<script>`, no remote font or image.

**Non-sent campaigns are unreachable by every route checked.** The JSON API
404s on any status other than `sent`, indistinguishably from an unknown slug
(no enumeration oracle — and a slug derives from the subject, so guessing one
tells an attacker nothing they did not already need to know). The sitemap and
the server-injected meta tags both gate on `Published`, so a draft's subject
never reaches an OG card. The SPA shell serves 200 for `/archive/{slug}` the
same way it does for `/workshops/{slug}`, with the API as the only content
source. `PATCH .../archive` is behind `requireAdmin` in `adminRoutes`, and
`SetArchiveStatus` cannot write `pending`.

**Migration, proved from production's actual version.** A scratch database
was migrated to **22** (production's `schema_migrations.version`), then
`migrate up` → 23, 24, 25, clean, `dirty = f`. `migrate down 1` → 24, clean.
A `pg_dump --schema-only` of that down-migrated database is **byte-identical**
to a fresh database migrated straight to 24, modulo pg_dump's random
`\restrict` nonce — so the down is genuinely indistinguishable, not merely
non-erroring. The up adds exactly `slug text NOT NULL`, `archive_status text
DEFAULT 'pending' NOT NULL`, `archived_at timestamptz`, the archive_status

2593834 -- migrations/` shows only the two new files. Both scratch databases

`html=8bb15d18…e8bb89`, `text=2b163e1b…c0ae74`. The claim holds; the added

**Renderer split.** `RenderMarkdownHTML` is the shared goldmark parse;

content-bearing lives only in the email path — the email adds the archive
link, the manage/unsubscribe footer, and the physical address, all of which

### Two findings to file separately, not part of this bounce

- **A `sent` campaign whose `archive_status` is still `pending` returns 200.**
  `GetBySlug` checks `Status != sent` then `ArchiveStatus == withheld`, and
  falls through to 200 for `pending`. Unreachable today (`CompleteIfDone`
  stamps both in one UPDATE, and `SetArchiveStatus` cannot write `pending`),
  but it disagrees with `ListArchived` and the sitemap, which both gate on
  `published`. Defence in depth: replace the withheld check with a switch on
  `ArchiveStatus` — `withheld` → 410, `published` → 200, anything else → 404.
- **The archive toggle does not invalidate the SEO caches.**
  `AdminWorkshopsHandler` calls `InvalidateWorkshops()` on every mutation;
  `AdminCampaignArchiveHandler` has no invalidator, and neither does the
  worker's send-completion. So `sitemap.xml` keeps advertising a just-withheld
  URL, and a just-published page stays out of it, for up to

### The `nil` vs `""` distinction — new API surface, checked

- `{"slug": null}` → `200`, slug untouched. Go unmarshals JSON `null` into a
  `*string` as `nil`, which the merge reads as "unchanged" — the same
  behaviour as omitting the key, which is the sensible reading.
- `{"slug": ""}` → `400 slug cannot be empty`, and the stored slug is
  **untouched** (verified by re-reading the row, not just the status code).
- `{"slug": "   "}` → `400`, because the handler trims before testing.
- `{"slug": "rr-renamed-8"}` on a **draft** → `200`, slug actually changes.
- The same on a **scheduled** campaign → `409 a campaign slug can only be
  changed while it is a draft`.
- A genuine collision → `409 that slug is already in use`.

**The fix does not trade a silent blanking for a user-visible 400.**
`web/src/lib/api.ts`'s `CampaignDraftFields` — the payload type for both
`createCampaign` and `updateCampaign` — declares exactly `name`, `subject`,
`preheader`, `body_md`, `audience_mode`, `interest_ids`. There is **no
`slug` key**, so the SPA cannot send one, explicit empty string or otherwise;
`req.Slug` is always `nil` on an ordinary save. `svelte-check` (0 errors)
would reject one being added by accident.

### "Empty means keep current" weakens a signal — nothing wants that signal

Confirmed rather than assumed: **clearing a slug is impossible at the
database**, so no caller can want to. The column is `NOT NULL` *and*, as of
this fix, `CHECK (btrim(slug) <> '')`. Every caller was checked —

`AdminCampaignsHandler.Patch` (which now passes the current value through),
and the worker and the SEO adapter only read. A caller that genuinely wanted
to clear one would have been writing a value the schema forbids.
