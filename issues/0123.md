# 0123 — Publish every sent campaign as a permanent public web page

## Description

Every campaign that has been sent gets a permanent, public, search-indexable page at `/archive/{slug}`, plus an index at `/archive` linked from Home and the footer. The slug is minted when the campaign is **created as a draft**, not when it is sent, so short links and promotional copy can be prepared against the final URL before the send goes out.

## Acceptance criteria

- [ ] Migration adds `email_campaigns.slug TEXT UNIQUE NOT NULL`, `archive_status TEXT NOT NULL DEFAULT 'pending'`, `archived_at TIMESTAMPTZ`
- [ ] Slug is generated on campaign creation from the subject, uniquified on collision, and editable while the campaign is `draft`; immutable once the campaign leaves `draft`
- [ ] Existing campaign rows are backfilled with slugs by the migration (no NOT NULL violation on an applied database)
- [ ] The compose UI (`#0047`) shows the full future archive URL as a copyable field, with a note that it is live only after sending
- [ ] `GET /api/archive` returns sent campaigns with `archive_status = 'published'`, reverse chronological: slug, subject, preheader, `archived_at`
- [ ] `GET /api/archive/{slug}` returns one campaign's web content. `404` when the campaign exists but is not yet `sent`; `410` when `archive_status = 'withheld'`; `404` when no such slug
- [ ] On the campaign's transition to `sent`, `archive_status` → `published` and `archived_at` is stamped, in the same transaction as the status change
- [ ] `PATCH /admin/campaigns/{id}/archive` toggles `published` / `withheld`, audited
- [ ] `ArchiveIndex` and `ArchiveEntry` Svelte views render inside the normal site shell — site header, footer, design tokens, fonts. Not an email frame embedded in a page
- [ ] The Markdown source renders through the **web** renderer, not the email renderer. Email HTML (`#0043`) and web HTML share the parse, not the output template
- [ ] `#0019`'s server-injected meta tags cover both routes: `<title>` from the subject, description from the preheader, canonical URL, OG card
- [ ] `sitemap.xml` (`#0020`) includes `/archive` and every published archive entry; withheld and unsent campaigns are excluded
- [ ] Home links to `/archive`; the site footer links to `/archive`
- [ ] Every campaign email carries a "View this email in your browser" link to its archive URL, in both the HTML and plain-text parts
- [ ] The archive page renders campaign body content only — never an unsubscribe token, a `manage_token`, a per-recipient substitution, or a recipient count. It is built from the `email_campaigns` row and never joins `email_sends`
- [ ] Both routes are unauthenticated and carry no `noindex`
- [ ] Go route table and the TypeScript route table stay in parity (`#0071`)

## Notes

PRD §6.8 is the specification; §5.1 and §8 carry the routes.

**Why the slug is assigned at draft time.** The user's requirement, and the reason this is not a detail: promotion for a campaign — a `go.opencircuitsf.com` short link, a Discord post, a Luma event description — is written before the send. If the slug were minted at send time the URL would not exist when the marketing needs it. Minting at draft time also means the campaign compose screen can show the copyable URL immediately.

**Attribution without tracking.** Archive URLs are the landing target for short links carrying `utm_source` / `utm_medium` / `utm_campaign`. `#0026` already captures those on signup, so promotion of a campaign gets per-channel attribution with nothing added to the email. The §2 non-goals stand: no open-tracking pixels, no per-recipient click tracking, no third-party analytics.

**`withheld` must be `410`, not `404`.** A published page that later goes away has been deliberately retracted; `410 Gone` tells crawlers to drop it, `404` invites re-crawling.

**Backfill.** `email_campaigns` already has rows on any applied database. Adding `slug TEXT UNIQUE NOT NULL` in one statement will fail. Add the column nullable, backfill from `name`/`subject`, then set `NOT NULL` — three statements in one migration.

**Renderer separation.** `#0042` split Markdown parsing from output rendering. Do not reach for `campaign_body_style.go` or the `#0043` table-based template for the web page: the email template exists to survive 2003-era mail clients, and the web page should look like the rest of the site.
