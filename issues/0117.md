# 0117 — `dev.sh` runs `kill -9` on whatever holds port 5173, including another agent's server

| | |

## Description

`scripts/dev.sh`'s `free_port 5173` sends `kill -9` to whatever is listening,
without checking whose process it is. Vite's port is fixed, so two agents — or
an agent and the user — running `dev.sh` concurrently means the second silently
destroys the first's dev server mid-session.

## Steps to reproduce

1. Start `./scripts/dev.sh` (or anything else bound to `5173`).
2. Start `./scripts/dev.sh` again from another session.
3. The first server is gone, with no warning to either party.

## Expected behavior

`dev.sh` either refuses to start when `5173` is held by a process it did not
launch, or says whose it is and asks, or picks another port.

## Actual behavior

It kills the process and continues, and the owner of the killed server sees
only that their server stopped answering.

## Notes

Found during `#0116`'s review (2026-08-21), which pre-checked the port by hand
and found it free. Pre-existing behaviour, not introduced by `#0116` — filed
separately rather than widening that issue's scope.

This is the same hazard class `CLAUDE.md` §8b already documents from the other
direction: an agent once bound a fixed shared port, its own bind failed, and
`curl` cheerfully returned 200 from *another agent's* server on that port. §8b
tells agents not to trust a shared port; this issue is the tooling doing the
destroying rather than the trusting.

Subagents frequently run concurrently in this repo (§5a permits two at once),
so this is reachable in normal use, not a hypothetical.
