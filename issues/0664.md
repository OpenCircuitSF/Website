## Description

From `#0662`'s review. `(*subscribers.Store).SignupsByGuide` counts a guide signup as confirmed if the subscriber confirmed at any time after the guide's `signup_requested` event. That includes a confirmation that only happened after a later restart from `/subscribe`. Bound the confirmation check at the subscriber's next `signup_requested` event, so each request is credited only with its own confirmation.

## Acceptance criteria

- [x] A test has a guide signup, no confirm, a later restart from /subscribe, and then a confirm. The guide's `Confirmed` count stays 0 and its `Requested` count stays 1.
- [x] The existing `SignupsByGuide` tests still pass. `ISSUE=0664 scripts/check.sh go ./internal/subscribers/...` passes.

## Relation

- Follow-up to `#0662`. `#0660` displays these counts.
- Milestone: Phase 10 — Outreach.

## Resolution

`internal/subscribers/guide_signups.go`: the `Confirmed` filter in `SignupsByGuide` now also requires that no later `signup_requested` event for the same subscriber falls in `(request, confirmation]`, so each request is credited only with a confirmation that precedes the subscriber's next request. Doc comments updated.

New test `TestSignupsByGuide_ConfirmAfterLaterRestartNotCounted` in `internal/subscribers/guide_signups_test.go`: guide signup → unsubscribe → `RestartSignup` with no guide → confirm with the restart's token; asserts `Requested 1, Confirmed 0`. It follows the existing tests: unique guide slug, `longAgo()` clock, and no writes to `subscriber_events`.
