## Description

Brennan, 2026-10-18, on the Programming LEDs (workshop 6) post cards in
production:

1. **The Bluesky card has no picture, but the Mastodon one does.** The
   workshop cover is `/media/colorful-leds.jpg`, 1,017,847 bytes on disk.
   `Publisher.thumbnail` (`internal/outreach/publisher.go`) drops any file
   over `bluesky.MaxThumbBytes` (1,000,000), so the card goes out with no
   picture, and the preview just says "No image: the card goes out without
   a picture." Mastodon fetches `og:image` itself and has no such limit.
2. **The hashtags are nearly invisible, and their case looks wrong.** Both
   preview components colour `.hashtag`/`.link` with
   `var(--accent-text, var(--accent))`. `--accent-text` is the colour for
   text *on* an accent fill: `#0A0D0B` in dark mode and `#FFFFFF` in light
   mode, so the tags vanish in both themes. Brennan also wants lowercase
   tags ("I typically see them in lowercase"). The default is
   `#SanFrancisco #Electronics`, and the help text tells admins to use
   CamelCase. Production has no saved `outreach_hashtags` row, so it uses
   the default.
3. **The Bluesky account shows as `@brennan@opencircuitsf.com`.** The saved
   `bluesky_handle` connection value in production is the sign-in email.
   Bluesky's `createSession` accepts an email as the identifier, so posting
   works. But `Manager.Account` (`internal/outreachconn/manager.go`) displays
   the stored value verbatim. The real handle is `@www.opencircuitsf.com`.

## Acceptance criteria

- [x] **Thumbnail fits under the limit.** When a local JPEG or PNG cover is
      over `bluesky.MaxThumbBytes` (or too large to decode sensibly), the
      publisher produces a JPEG that fits:
      - Re-encode, stepping the quality down. If that is not enough, scale
        it down, preserving the aspect ratio, until it fits.
      - `golang.org/x/image` is already in `go.mod`, so use its `draw`
        package for scaling.
      - Put a sane cap on the decoded pixel count, so a hostile image can't
        exhaust memory on the t4g.small. A file over the cap gets no picture.
      - Files already under the limit go out byte-identical, as today.
      - Still local-disk only, with no URL fetch.
      - The preview's `ThumbOK` uses the same path. Because the view is
        fetched often, the shrunk result is cached in memory, keyed on
        path, size and mtime, so a GET does not re-decode a 1 MB JPEG each
        time.
      - Tests cover: an oversized JPEG that comes out under the limit and
        still decodes; an oversized PNG that comes out as JPEG; an
        under-limit file that is unchanged; and a pixel-bomb that gets no
        thumbnail.
- [x] **The preview says why there is no picture.** When `thumb_ok` is
      false, the view carries a short, plain reason, and the Bluesky preview
      shows it. Reasons to cover:
      - no cover set;
      - the cover is not an uploaded /media/ file;
      - the file is missing;
      - the format is unsupported;
      - the cover couldn't be shrunk under 1 MB.

      Generic wording is fine for the last one. Keep it within the banned

## Resolution

- New `internal/outreach/thumbnail.go`: a local JPEG/PNG cover over
  `bluesky.MaxThumbBytes` is re-encoded as JPEG (quality 85/75/65/50, then
  0.8x Catmull-Rom scale steps to a 200px floor). The pixel count is checked
  from the header (`media.CheckDimensions`, 24 MP / 6000px edge) before any
  decode; reads are capped at 25 MB; still `/media/` + `filepath.Base` only,
  no URL fetch. Under-limit files go out byte-identical. Shrunk results
  (and failures) are cached, 8 entries, keyed on path, size and mtime.
- `Publisher.ThumbStatus` returns the reason; the panel view carries
  `thumb_reason`, which the Bluesky preview shows.
- Preview hashtags and links use `--accent`; a source guard forbids
  `--accent-text` in both previews.
- Default hashtags `#sanfrancisco #electronics`; help text and validation
  message use lowercase and no longer recommend CamelCase. No migration (no
  stored row; 000040/000042 write no value).
- `Manager.Account("bluesky")` shows the session handle, cached per `bsKey`
  (PDS, identifier, app password), fetched by Test connection and by a
  background reload lookup (5s timeout) whose stale result is discarded. An
  email identifier shows nothing until then. Field is "Handle or sign-in
  email".

## Resolution notes

- Shrinks run one at a time per publisher (review fix), so a cold-cache
  burst of preview GETs waits for one decode and then hits the cache.
- A re-encoded cover loses its EXIF data, including orientation (see
  Review notes, follow-up).

## Review notes

- **Verdict: approved** (Opus, 2026-10-18), with one review fix
  (`ae60ed82`).
- Every criterion checked against the code. Path handling is unchanged from
  #0593 (`/media/` prefix, `filepath.Base`, regular file only), and the only
  I/O is `os.Stat`/`os.Open`. The negative cache cannot mask a fixed file:
  the key includes size and mtime (`TestPublisher_ThumbnailCachedByPathSizeMtime`
  proves an mtime change misses). The default hashtags reach drafts through
  `serversettings` field `Default`; no migration writes a value. No CamelCase
  recommendation is left in user-facing copy (remaining `#SanFrancisco` hits
  are tests feeding explicit values, which validation still accepts).
- **Production case, simulated:** a 2400x1600 photo-like JPEG of 1,061,275
  bytes came out as a 515,134-byte JPEG at full size, quality 85, and
  `ThumbStatus` returned `true, ""` for the same cover (scratch test, not
  committed).
- **Contrast, computed with the WCAG formula from `app.css`:** light
  `--accent` #2F7D0C is 4.76:1 on `--bg-page` and 5.17:1 on `--bg-panel` (the
  previews sit on the page in post cards and on the panel in the dialog);
  dark #68FF23 is 13.76:1 or better. Both clear 4.5:1. (It would be 4.39:1
  on `--bg-subtle`, so the previews must not move onto that background.)
- **Bluesky lookup:** runs in a goroutine with `accountLookupTimeout` (5s),
  logs only the group name on failure, never the error or password. `bsKey`
  includes the PDS, identifier and app password, so changing any of them
  orphans the cached handle (Account also compares the key). createSession is
  called only when `bsKey` changes, not on every reload.
- **Review fix (`ae60ed82`):** (1) `go test -race ./internal/outreachconn/`
  failed: `TestBlueskyConnection` changed its handler flag while the new
  reload-time lookup was signing in against the same server. It now waits for
  the lookup first. (2) The pixel-bomb fixture could not catch a dropped
  header check, since it has no image data and fails to decode either way
  (mutation proved it: still green). Added
  `TestPublisher_ThumbnailOverPixelLimitRefused`, a decodable 6001x40 PNG
  padded past 1 MB, which fails when the check is removed. (3) A
  `shrinkMu` so only one shrink runs at a time; at the pixel cap one decode
  can hold a few hundred MB. (4) The colour guard's comment said "5:1"; it
  now gives the measured ratios.
- **Mutation tests** (copy aside, restored by sha256): returning the raw file
  regardless of size fails three thumbnail tests; dropping
  `CheckDimensions` fails the new over-limit test; removing the stale-key
  discard in `rememberBlueskyHandle` fails `TestStaleBlueskyHandleLookupIsDiscarded`.
- **Follow-up to file (not blocking):** re-encoding drops EXIF orientation
  and ICC profile, so a phone photo that relies on an orientation tag would
  go out sideways on Bluesky. Apply the orientation before encoding, or note
  it in the upload help.
