## Description

`#0349` replaced the AST satisfier scan in
`internal/seo/invalidator_satisfier_guard_test.go` with `types.Implements` over
every **named** type in `internal/seo`.

Under `gotypesalias=1` (the default), a package-scope alias resolves to
`*types.Alias`, **not** `*types.Named`, so the guard's type assertion skips it
silently. Therefore:

```go
type FeedCache = struct{ *Site; cached []byte }
```

is a real satisfier of both `handlers.seoCacheInvalidator` and
`mailing.ArchiveCacheInvalidator` — `var _ interface{ Invalidate() } =
FeedCache{}` compiles — while the guard reports `ok`.

**This is a measured loss relative to the guard it replaced.** The retired
`structTypesWithEmbeddedFields` tripwire inspected any `*ast.TypeSpec` whose
`Type` was a struct literal, alias or not. `#0349`'s reviewer ran the retired
file against this identical mutation and it **fails, naming `FeedCache`**.

Not a defect against any of `#0349`'s criteria, which say "every *named* type",
and the construct is exotic — which is why it was handed forward rather than
bounced, matching how `#0346`'s review disposed of `#0350` and `#0351`.

**Note the alias case that is NOT a defect**: `type FeedCache = Renderer` and
`type FeedCache = *Site` are merely new spellings of a type the loop already
checks, and `#0337`'s third review already ruled that a legitimate survival.
Do not "fix" those into failures.

## Acceptance criteria

1. In `TestInvalidatorSatisfierSet`'s scope loop, **before** the
   `*types.Named` assertion, add a `*types.Alias` branch calling
   `types.Unalias`, then:
   - `continue` if the result is a `*types.Named` or a `*types.Pointer` to one
     — a new spelling of a type the loop already checks, and `type FeedCache =
     Renderer` / `type FeedCache = *Site` must keep PASSing;
   - `continue` if its underlying is `*types.Interface` — the declared-seam
     rule, a declared interface is not a concrete type joining a seam;
   - otherwise increment `concreteTypesChecked` and record it in `got` if
     `types.Implements(target, invalidateOnly) ||
     types.Implements(types.NewPointer(target), invalidateOnly)`.
2. Two doc-comment claims that `#0349`'s review **falsified by measurement**
   are corrected in the same pass:
   - the parenthetical "**export-data backed**" is wrong. Measured:
     `GOOS=linux GOARCH=arm64 go list -export -deps ./internal/seo` costs
     **5,406 ms and 240 MB of build cache cold**, against the guard's
     **1,299 ms and 6.8 MB**. It **source**-type-checks. The phrase was
     inherited verbatim from `#0349`'s own criterion 1, so the implementation
     did not introduce it — correct it at the source.
   - "there is nothing left for a hand-reviewed allowlist to guard" is now
     overstated by exactly this alias case.
3. Re-run `#0349`'s full mutation set — the seven from `#0337`'s reviews plus
   the two correct survivals (declared interface, type alias to a named type) —
   and confirm no regression. Add the alias-to-type-literal mutation as a
   permanent standing case.
4. Mutations run in a `git archive` export or throwaway worktree, never the
   shared tree (§8b), with a whole-tree hash manifest diffed after each. Note
   `#0349`'s reviewer found that one mutation staged as described fails as
   `[build failed]` rather than by the guard's verdict — fix the companion call
   site too, so the guard's own assertion is what fails. That is the honest
   form.
5. **`GOFLAGS=-mod=readonly` on every loader run**, and
   `git status -- go.mod go.sum` checked before committing (§8b; the `-mod=mod`
   trap fired for real in this checkout on 2026-08-31).
6. `gofmt` stability: file sha256 equals sha256 of `gofmt` stdout (§8).

## Added by `#0351`'s review, 2026-08-31

That review resolved `#0351` and found a third false claim in the same doc
comment — one that must be fixed **in two files at once**.

**`"the exact failure #0319 was filed to fix"` overstates `#0319`.** The phrase
appears in both `internal/seo/invalidator_satisfier_guard_test.go` and
`internal/seo/sitemap.go`, attributing to `#0319` the
sitemap-cleared/meta-stale half-invalidation that a bare `*Sitemap` produces.

But `#0319` was filed because `AdminCampaignArchiveHandler` and the send worker
invalidated **nothing**, leaving *both* caches stale, and its headline symptom
is a stale **sitemap**. The half-invalidation *clears* the sitemap and reopens
only the **meta-cache** half. It is half of `#0319`'s staleness class — and not
the half `#0319` leads with.

The mechanism around it is correct and verified: `site.go:48`'s `Invalidate` is
`renderer.Invalidate()` + `sitemap.invalidate()`, so a bare `*Sitemap` runs only
the second. Only the `#0319` attribution is wrong.

**Both copies must change together.** They are byte-parallel by design —
`#0337` and `#0351` deliberately built that consistency, and `#0351` could not
fix this because it was barred from touching `sitemap.go` and criterion 2
required the guard's phrasing to match it. So this pass edits `sitemap.go` too.

Low severity, but this comment pair is the project's canonical record of the
`#0325` incident, and it has now been wrong in print twice.
