## Description

Small follow-ups that Phase 12's reviewers reported. None of them is broken in what the site serves today.

1. **The fallback's internal-vs-external link branch is not tested** (`#0735` review). A mutation that always adds `target="_blank"` to link-list links passes `TestRender_DocsCodeAndInternalLinks`, because that test only covers a paragraph link.
2. **`singleSourcePages`' docs rows are written by hand** (`#0735` review). Derive them from `docsPaths()`, so new docs pages get the full-text check without editing the test.
3. **`TestOpenAPIMatchesRegistry` runs only over stub registries** (`#0734` review). Add a test in `internal/handlers` that runs it over the real `BuildPublicRegistry`.
4. **`ical.EscapeText` passes control characters through** (`#0732` review). RFC 5545 allows only HTAB among the control characters in TEXT values. Strip or replace the others.
5. **`scripts/mcp-connect.sh` with `OCSF_MCP_URL` set to an old `…/mcp` URL** (`#0728` review). It strips nothing and the key check fails with a confusing status. Detect a URL that doesn't end in `/admin/mcp` and say the admin server moved.
6. **`docsAPIDrift` misses two kinds of drift** (`#0735` pass C review; added by the orchestrator, 2026-11-19). It does not check each `/docs/api` section's parameter list against the op's input schema. Its "keys at every depth" check compares one flattened set of key names, not the keys at each path, so a key moved to the wrong object still passes.
7. **The server-card and AI-catalog URLs are not on `/docs/feeds` or `/docs/mcp`** (`#0731`'s deferred plan step 9; added by the orchestrator, 2026-11-19). `/mcp/server-card` and `/.well-known/ai-catalog.json` are served, but the docs pages don't mention them. Checked at planning: `#0731`'s commits and both JSON files do not have them yet.

### Item 4: control characters in ICS TEXT (`internal/ical`)

**Files:** `internal/ical/ical.go`, `internal/ical/ical_test.go`.

- In `EscapeText`, after the CR/LF normalisation and before `textEscaper.Replace`, drop the ASCII control characters. RFC 5545 §3.3.11 TSAFE-CHAR excludes CONTROL (`%x00-08 / %x0A-1F / %x7F`) and allows HTAB. LF is kept here because it becomes the `\n` escape. Use:

      s = strings.Map(func(r rune) rune {
      	if r == '\t' || r == '\n' {
      		return r
      	}
      	if r < 0x20 || r == 0x7f {
      		return -1
      	}
      	return r
      }, s)

  Leave C1 (U+0080–U+009F) alone: RFC 5545 allows NON-US-ASCII.
- Extend the doc comment: "Other ASCII control characters (everything below 0x20 except HTAB, plus DEL) are removed, since TSAFE-CHAR excludes them (#0737)."
- **`TestEscapeText_StripsControlCharacters`** (new): a table.
  - `"a\x00b\x07c\x1bd\x7fe"` → `"abcde"`
  - `"a\vb\fc"` → `"abc"`
  - `"tab\there"` → `"tab\there"`, with HTAB kept
  - `"x\r\ny"` → `` `x\ny` ``, which is still the newline escape
  - `"semi;\x01colon"` → `` `semi\;colon` ``
  - Build the fixtures from Go `\x` escapes in double-quoted strings, as AGENTS.md §8 advises (never literal control bytes typed into the file).
- **Mutation proof:** delete the `strings.Map` call. The new test must fail. Revert.
