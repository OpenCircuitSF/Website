## Description

`scripts/check_guard_test.sh`'s `gotest_interrupted` row (`#0608`) starts
`check.sh` in its own process group under `set -m` and sends the group
`TERM`. The row passes, but bash's job-control status report for the killed
job, `Terminated: 15`, lands in the harness output between `PASS` lines. A
reader scanning `scripts/check.sh guards` output for trouble sees it and has
to work out that it is expected.

## Acceptance criteria

- [ ] `scripts/check.sh guards` output contains no `Terminated` line from this
      row, while the row still sends `TERM` to its own process group only
      (never by pattern, `AGENTS.md` §5a) and still asserts no `gotest.*` file
      survives, a non-zero exit and `NO VERDICT`.
- [ ] No other row's output is suppressed to achieve it — silence the job
      report (for example by redirecting the `wait`'s stderr or disowning the
      job), not the harness's stderr.
- [ ] `scripts/check.sh guards` passes; `shellcheck` and `bash -n` pass.
