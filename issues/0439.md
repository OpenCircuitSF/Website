## Description

`internal/seo` carries an idiom — *"nil until `#NNNN` lands"* — written when
those issues were open. `#0425` replaced two instances with the **real**
condition (nil only under `STORAGE=json`), which a review verified end to end
and endorsed, because a condition cannot go stale the way an issue reference
can.

**Two instances remain, and one is worse than stale.**

1. **`NewRenderer`'s doc comment** (`internal/seo/seo.go`) carries the same
   idiom. Left deliberately by `#0425`'s third pass — out of its prescribed
   scope, correct discipline.
2. **`WorkshopSource`'s interface doc** (`internal/seo/workshop.go`) states that
   `#0051` **"has not landed yet"** and that `#0054` **"is expected to wire the
   real implementation in"**.

Both issues are `resolved`, and **`workshopSEOSource` is what `#0054` wired**.

### Why the second is a different category

A stale issue reference is a pointer that has rotted. This is a **claim about
the present state of the system that is false** — an interface's own contract
telling a reader the implementation does not exist, when it does and is in the
same repository.

A reader trusting it would conclude the workshop source is unimplemented and
either duplicate it or work around a nil that never occurs in the Postgres path.

Confirmed by the orchestrator: `workshop.go` carries "`#0054` is expected to
wire the real implementation in."

## The fix, and the precedent to follow

`#0425` established the shape: **replace the issue-relative claim with the
condition it was standing in for.** `buildSEOSite`'s doc comment
(`cmd/opencircuit/main.go`) already carries the accurate form for the same fact,
and a review verified it: `DevMode()` is literally `Storage == "json"`;
`servePostgres` passes struct values, so non-nil unconditionally; `serveDevMode`
is the only other caller and passes `nil, nil`.

**Do not simply update the issue numbers.** That reproduces the defect with a
later expiry date.

## Leave these alone
The two **quotations** of `#0020`'s Notes — in `workshop.go` and
`sitemap_test.go` — are correct **as attributed quotations** of what that issue
said at the time. `#0425`'s reviewer confirmed this specifically. Rewriting a
quotation to match present reality would falsify a record, which is `#0271`'s
`## Scope` rule.

Distinguishing them from the defect above is part of the work.

## Acceptance criteria

1. Neither remaining instance asserts a state of the world that is false.
2. **The replacement states a condition, not an issue reference**, following
   `#0425`'s endorsed pattern — and **verify the condition yourself** rather
   than copying it from here.
3. The `#0020` quotations are untouched, and your notes say how you told them
   apart from the defect.
4. **Sweep the package for the idiom** using the technique `#0425`'s second
   review established, since two sweeps there missed an instance by keying on
   the token whose absence *was* the defect: net on a **set member or phrase any
   instance must contain**, then read the windows. Report the result even if
   empty.
5. **No mechanism** (`#0330`/`#0347`/`#0356`/`#0381`). Two reviews independently
   concluded a comment-versus-code guard here would store a copy of the answer
   next to the question (§8).
6. **gofmt stability** — these are doc comments, and §8 records gofmt rewriting
   them and collapsing doubled backticks, with backtick spans offering no
   protection. Prove it non-destructively, hashing `gofmt`'s stdout against
   on-disk bytes.
7. Run `./internal/seo/...`, `./internal/db/...` and `./internal/handlers/...`
   (§5's repo-wide-guard table). Per §5 name the specific tests that ran — real
   function names, not a `-run` prefix. No Go-file-plus-line-number citation
   (`#0352`), scanned with `python3` bytes rather than BSD `grep -P`.
