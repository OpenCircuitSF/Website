# 0619 — The Deliverability and CRT commands screens use a `.mono` class that has no rule in their scope

| | |
|---|---|
| **Status** | open |
| **Platform** | All |
| **Module** | web / admin |
| **Phase** | 6 — Workshops |
| **First seen** | 2026-11-04 |

## Description

`web/src/views/admin/Deliverability.svelte` (two uses) and
`web/src/views/admin/CrtCommands.svelte` (one use) put `class="mono"` on elements,
but `.mono` is scoped to `Admin.svelte`, so that text renders in the normal font.
This is the same defect `#0616` fixes on the Event types screen; its planning pass
found these two and left them out of scope.

## Plan

Add the same local rule `#0616` settled on to each screen, plus one small test per
screen. Written against the code on 2026-11-04.

### Files

- `web/src/views/admin/Deliverability.svelte`
- `web/src/views/admin/CrtCommands.svelte`
- `web/src/views/admin/Deliverability.monoCss.test.ts` (new)
- `web/src/views/admin/CrtCommands.monoCss.test.ts` (new)

### Approach

The markup stays as it is. Add this rule, with exactly these three declarations,
at the end of each component's `<style>` block, directly before `</style>`: after
`.history-table` in `Deliverability.svelte`, and after `.crt-fallback-note,
.crt-width-hint` in `CrtCommands.svelte`.

```css
  .mono {
    font-family: var(--font-mono);
    font-size: var(--fs-sm);
    overflow-wrap: anywhere;
  }
```

These are the declarations `Admin.svelte` and `EventTypes.svelte` already use.
`web/src/app.css` has no `.mono` rule, so nothing competes. Do not make
`Admin.svelte`'s rule `:global`, for the reason in `#0616`'s plan.

### Tests by name

Copy the shape of `web/src/views/admin/EventTypes.monoCss.test.ts`: read the
component source with `readFileSync`, and use the same file comment, saying that
this reads source because the rule is scoped CSS and does not prove the rendered
font. In both, assert that the part after `<style>` matches
`/\.mono\s*\{[^}]*font-family:\s*var\(--font-mono\)/`.

- `Deliverability.monoCss.test.ts`:
  `it('styles the email and diagnostic code cells with a local .mono rule')`. Also
  assert the source contains `<td class="mono">{item.email}</td>` and
  `<td class="mono">{ev.diagnostic_code ?? '—'}</td>`.
- `CrtCommands.monoCss.test.ts`:
  `it('styles the slug cell with a local .mono rule')`. Also assert the source
  contains `<td class="mono">{c.slug}</td>`.
