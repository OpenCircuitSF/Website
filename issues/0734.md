# 0734 — There is no public REST API, so a script without an admin key cannot read events or newsletter issues

## Description

The user decided on 2026-11-19 that the new Docs section (`#0735`) should document a **public, read-only REST API** that needs no key. That API serves the same data as the public MCP server (`#0729`). The only REST API today is `/api/v1` (`#0675`), and it needs an admin key.

**REST and MCP must not drift.** The admin side solved this by building both adapters over one operation registry (`internal/api`, `#0675`/`#0679`). The public side should do the same: one set of public read operations, with the MCP adapter and the REST adapter both built from it. This is a separate registry instance from the admin one, so `#0729`'s rule that the admin and public servers stay separate still holds.

## Acceptance criteria

- [ ] Read-only endpoints under **`/api/public/v1/`**, one for each `#0729` tool:
  - `GET events` (upcoming, with `limit`/`after`/`before`);
  - `GET events/search` (`query`, `from`, `to`, `include_past`, `limit`);
  - `GET events/{id-or-slug}`;
  - `GET newsletter`;
  - `GET newsletter/{id-or-slug}`;
  - `GET about`.

  They have the same fields, caps, time format and URLs as the MCP tools.
- [ ] The REST routes and the public MCP tools are generated from one definition. A test asserts that every public MCP tool has a REST route and every route has a tool, with matching schemas. If `#0729` has already shipped hand-written tools, this issue moves them onto the shared definition.
- [ ] No auth: an `Authorization` header is ignored, there is never a 401, and there is no OAuth metadata. These are `GET`-only. Any other method gets 405.
- [ ] Unknown, draft and unpublished items return the same 404 body (test). The data-exposure tests from `#0729` also cover every REST route.
- [ ] `GET /api/public/v1/openapi.json` is generated from the shared definition. A guard ties it to the routes.
- [ ] CORS `Access-Control-Allow-Origin: *` on these routes only, so browser apps elsewhere can read them. The admin `/api/v1` CORS behaviour is unchanged (test).
- [ ] `#0730`'s per-IP rate limit, logging and 60 s list cache apply. REST and MCP share one per-IP budget.
- [ ] `Cache-Control` suits public data. Responses are gzip-compressible through `#0716`.
- [ ] Route-table wiring tests. `docs/api.md` gets a short section separating the public API from the admin `/api/v1`.

## Relation

- Depends on `#0729` (the shared definition can land with it or after it) and `#0730`.
- Blocks `#0735`'s API section.
- Follows `#0675`'s registry pattern.
