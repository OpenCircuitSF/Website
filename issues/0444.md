## Description

`#0410` wired the archive slug into `CampaignEditor.svelte`. Its review traced
all three legs of that wiring and found them present and correct — but recorded
that the change made one regression shape **less** visible than it was before.

Remove `slug: slugToSend` from `saveDraft`'s `updateCampaign(...)` payload and:

- the field still accepts typing,
- autosave still reports "Saved",
- and the read-only Archive URL preview **still updates** to the new value —
  because `#0410` deliberately made the preview read the live buffer rather than
  the persisted `campaign.slug`.

So every visible signal says the slug was saved, and none of it was. The
preview improvement is correct and worth keeping; it just removed the last cue
that would have exposed a broken write.

Nothing in the tree would catch it. Nothing mounts `CampaignEditor.svelte` —
`web/src/lib/modalFocusWiring.structuralGuard.test.ts`'s own comment names it as
too network-dependent to mount cheaply — and `STORAGE=json` has no mailing
subsystem at all, so no end-to-end path exercises it either.

## Why a guard here, when this repo adds them reactively

`CLAUDE.md` records that `.svelte` structural guards are added **after** a review
finds a silent failure, not per field. `#0410`'s review followed that rule and
did **not** bounce for a guard, since there is no present defect. This issue is
the follow-up it recommended instead.

The distinguishing fact is the one above: the failure is silent in every channel
a human would check, including the one the same change introduced.

## Acceptance criteria

1. A structural guard modelled on
   `web/src/lib/modalFocusWiring.structuralGuard.test.ts` parses
   `web/src/views/admin/CampaignEditor.svelte` with `svelte/compiler` and
   asserts **over the AST, not with a regex over raw text**:
   1. the `updateCampaign(...)` call's object argument has a `slug` property —
      **this is the load-bearing one**, the leg whose loss is silent;
   2. `archiveURLValue`'s initializer passes the `slug` identifier, not a
      `campaign` member expression, to `archiveURL`;
   3. the input with `id="campaign-slug"` carries a `disabled` attribute whose
      expression reads `slugEditable`.
2. Prove it by mutation: delete each of the three legs in turn from a **copy**
   of the component, confirm the guard fails naming that leg, and restore.
   Never `git stash` or `git checkout --` (`CLAUDE.md` §8a).
3. Assertions 2 and 3 are cheap once the file is parsed — include them, but do
   not let them grow into a general component-shape checker. One guard file,
   three assertions.
4. **The oracle must not be the same bytes as its subject** (§8). A quoted copy
   of the expected source next to the component is satisfied by one edit that
   rewrites both; the AST is a different representation and is the right shape
   here. Do not add a text fixture alongside it.

## Added 2026-09-05 — `#0411` widened the unmounted surface

`#0411` added a **Delete campaign** control to the same component, and `#0411`'s
reviewer asked that this issue absorb it. Four more legs now exist that only
`CampaignEditor.svelte` reaches:

- the delete **offer gate** (draft-only),
- the **confirm-message binding**,
- the **confirm handler**, and
- its **`onBack()`** call.

`#0411` added five web tests, and all five cover the two **pure helpers** —
nothing exercises the wiring. So the same silent-write shape this issue was
filed for now applies to a **destructive** action: the button can stop being
wired to the handler, or the handler stop calling the API, with no test
noticing.

That raises the stakes but not the remedy. Add these to criterion 1's AST
assertions rather than building a second mechanism:

5. the delete confirm handler's `deleteCampaign(...)` call is present;
6. the delete control's `disabled`/offer expression reads the draft-only gate.

Keep it one guard file. `#0411`'s review separately confirmed the **server**
refuses a non-draft delete independently, so the offer gate is cosmetic and a
missing gate is a UI defect rather than a data-loss one — assertion 5 is the
load-bearing one here, as assertion 1 is above.

## Also fold in — three small findings from the same review

None is a defect; all three are one-line tidies in the files this issue already
opens:

1. `resyncCampaignStatus`'s doc comment enumerates **six** protected buffers.
   `slug` is now a seventh and belongs in the list. Behaviour is already
   correct; only the comment is short.
2. `saveDraft` trims the slug unconditionally, even when the field is disabled.
   A padded stored slug would then 409 on every autosave of a scheduled
   campaign. Unreachable today, since the server coerces an empty `in.Slug` to
   the current value — but falling back to `campaign.slug` when `!slugEditable`
   is tidier and removes the reasoning step.
3. The Copy button copies the **unsaved buffer's** URL. That is a direct
   consequence of `#0410`'s criterion 1 and may be exactly right; decide and
   record which, rather than leaving it unexamined.

Deliberately **not** in scope: clearing the field shows the "cannot be blank"
message alongside a successful "Saved" and a bare `/archive/` preview.
`#0410`'s review judged that a deliberate trade — blocking the whole autosave
would strand the name, subject, and body — and criterion 4 there only asked that
blank be rejected client-side, which it is, before the request.
