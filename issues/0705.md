## Description

Part of `#0695` (Agent API, part 2). v1 media: single-use upload URL, list.

## Plan
1. Extract the validation-and-write pipeline from `AdminMediaHandler.Upload` (`admin_media_upload.go`) into `storeImage(ctx, filename string, data []byte) (path string, err error)`: sniff, `DecodeConfig`, `CheckDimensions`, `Strip`, `VerifyStripped`, `Filename`, `WriteAtomic`. `Upload` then calls it, and the admin tests stay unchanged.
2. Add an in-memory `uploadTickets` store, safe for one process: a 32-byte random token mapped to `{tokenID, tokenName, expires: now+10m, used}`, single-use and swept on access.

| Tool | Method, path | Scope | Notes |
|---|---|---|---|
| `create_media_upload` | POST `/api/v1/media/uploads` | media:write | returns `{upload_url, upload_token, expires_at, max_bytes: 5 MiB, curl}` |
| `list_media` | GET `/api/v1/media` | media:read | names, sizes and mtimes in the media directory, newest first, paged |
| *(REST only)* | POST `/api/v1/media/uploads/{ticket}` multipart `file` | the upload token as a Bearer header | mounted in `cmd/opencircuit` outside the registry, with its own `mediaMaxUploadBytes` cap |

- The upload route authenticates with the ticket from the `Authorization` header, so nothing secret goes in the URL or the access log. Requests with an unknown or used ticket, or an expired one, get 401.
- The route audits `media.uploaded` against the API key that minted the ticket (`AttributeAPIToken` built from the ticket's token info).
- An empty `mediaDir` gives the same named 503 the admin returns.
- The returned `/media/x.png` goes into `update_event cover_image` or `update_flyer photo`.

**Tests:** ticket single use; ticket expiry (fake clock); upload with no ticket gives 401; HEIC gets the 415 message; the written file is stripped. Every test uses `t.TempDir()`.

## Resolution

- `storeImage` (`internal/handlers/admin_media_upload.go`) now holds the sniff → DecodeConfig → CheckDimensions → Strip → VerifyStripped → Filename → WriteAtomic pipeline; `AdminMediaHandler.Upload` calls it. Admin tests unchanged. The not-configured 503 text is now the shared constant `mediaNotConfiguredMessage`.
- `internal/handlers/v1_media.go`: `MediaV1` with an in-memory `uploadTickets` store (16-byte random id, 32-byte random secret, only its SHA-256 kept, 10-minute TTL, single use, expired ones swept on every access), ops `create_media_upload` (`media:write`, 201) and `list_media` (`media:read`, newest first, cursor `{mtime, name}`; dotfiles and directories skipped), and the REST-only `Upload` at `POST /api/v1/media/uploads/{id}`.
- Deviation from the plan, on purpose: the path segment is a **non-secret ticket id**, and the secret goes only in `Authorization: Bearer`. Both must match. So no secret reaches a URL or an access log. Failed attempts do not use up the ticket.
- Audit: reused the existing `audit.ActionMediaImageUploaded` (`media.image_uploaded`) rather than adding `media.uploaded`, attributed with `audit.AttributeAPIToken` to the key that minted the ticket. Metadata matches the admin row; the ticket is in neither the metadata nor any log line.
- Wiring: `APITokensHandler.SetMediaUpload`/`MediaUpload`; `cmd/opencircuit/main.go` builds `NewMediaV1(serverSettings.MediaDir, cfg.BaseURL, auditLogger)`, passes it as `V1Deps.Media`, and mounts `handlers.MediaUploadPattern` next to the v1 router.
- `expires_at` and `modified_at` are Pacific RFC 3339 (`announceLocation`), matching the v1 convention from #0697.
- Op names appended to `TestBuildV1RegistryListsOperations`, `specTools`, `docs/api.md` (a "Media" section) and `docs/mcp.md`.

## Review notes

Phase-3 review, 2026-11-17 (Opus · medium). **Pass.**

- **Secret never in a URL, log, audit row or error body.** The path carries only a 16-byte non-secret id; the 32-byte secret travels only in `Authorization: Bearer`, and only its SHA-256 is kept. No `slog` call in `v1_media.go` or `storeImage` takes the secret; the 401 bodies are fixed strings. `create_media_upload` does not set `Idempotency`, so its response (which must carry the secret) is never stored in `api_idempotency_keys`. The MCP adapter logs warn-and-above only and never a result. Added `TestV1MediaUpload_TicketNeverLoggedOrAudited` (DB-backed): it captures `slog` and `log` across a mint, a wrong-secret attempt, a HEIC refusal and a good upload, and asserts neither ticket secret appears; it also reads the `audit_log` row.
- **Audit departure accepted.** The route reuses `media.image_uploaded` through `audit.AttributeAPIToken`. The new test confirms there is exactly one row, `actor_id IS NULL`, `metadata.api_token.id` = the minting key, and no secret in the metadata.
- **Single use, expiry, mismatched id, constant time.** `redeem` deletes on success, with every access under one mutex and expired tickets swept on each mint and redeem. The hashes are compared with `subtle.ConstantTimeCompare`. A ticket presented on another ticket's id fails because the lookup is by id and the hash is then compared. The fake-clock expiry test covers the TTL boundary.
- **Size cap, HEIC, shared pipeline.** `http.MaxBytesReader` (5 MiB + 64 KiB) wraps the body before `ParseMultipartForm`, and the file is then held to 5 MiB exactly. HEIC gets the admin's `heicErrorMessage` 415. Both routes write through the same `storeImage`. The admin media tests are unchanged and green.
- **Scopes and times.** `create_media_upload` needs `media:write` and `list_media` needs `media:read`. `list_media` is cursor-paged, newest first. `expires_at` and `modified_at` are Pacific (the test pins `-07:00`).
- **Proved failing without the change** in a throwaway worktree at HEAD with the review test copied in: removing `delete(s.tickets, id)` fails `TestV1MediaUpload_StripsAndIsSingleUse` ("second use: 200, want 401"), and adding an `slog.Info` of the bearer fails the new test ("ticket secret was logged"). The worktree and its database were removed afterwards.
- **Verification:** `ISSUE=0705r scripts/check.sh go ./internal/handlers/... ./internal/media/... ./internal/mcpserver/... ./cmd/opencircuit/...` reported VERIFICATION PASSED, no skips, gofmt clean, with load 4.5 at the start. handlers ok 25.1s, media ok, mcpserver ok, mcptest ok, cmd/opencircuit ok 28.0s.

Follow-ups for the orchestrator to consider filing (not blocking):
1. The ticket is redeemed before the body is validated, so a HEIC, oversize or corrupt upload uses it up and the agent has to call `create_media_upload` again. That is safe, but the 415 body could say so, or the route could redeem only after `storeImage` succeeds (it would then need a lock against concurrent reuse).
2. No test covers the 5 MiB cap on the ticket route (one byte over gives 400). It mirrors the admin route, which has a test.
3. The upload route sits outside `AuthFailLimiter`. Given 128 + 256 bits of entropy this is harmless, but it is the one `/api/v1/` path without it.
