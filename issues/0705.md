## Description

Part of `#0695` (Agent API, part 2). v1 media: single-use upload URL, list.

## Plan
1. Extract the validation-and-write pipeline from `AdminMediaHandler.Upload` (`admin_media_upload.go`) into `storeImage(ctx, filename string, data []byte) (path string, err error)`: sniff, `DecodeConfig`, `CheckDimensions`, `Strip`, `VerifyStripped`, `Filename`, `WriteAtomic`. `Upload` then calls it, and the admin tests stay unchanged.
2. Add an in-memory `uploadTickets` store, safe for one process: a 32-byte random token mapped to `{tokenID, tokenName, expires: now+10m, used}`, single-use and swept on access.

| Tool | Method, path | Scope | Notes |
|---|---|---|---|
| `create_media_upload` | POST `/api/v1/media/uploads` | media:write | returns `{upload_url, upload_token, expires_at, max_bytes: 5 MiB, curl}` |
| `list_media` | GET `/api/v1/media` | media:read | names, sizes and mtimes in the media directory, newest first, paged |
| *(REST only)* | POST `/api/v1/media/uploads/{ticket}` multipart `file` | the upload token as a Bearer header | mounted in `cmd/opencircuit` outside the registry, with its own `mediaMaxUploadBytes` cap |

- The upload route authenticates with the ticket from the `Authorization` header, so nothing secret goes in the URL or the access log. Requests with an unknown or used ticket, or an expired one, get 401.
- The route audits `media.uploaded` against the API key that minted the ticket (`AttributeAPIToken` built from the ticket's token info).
- An empty `mediaDir` gives the same named 503 the admin returns.
- The returned `/media/x.png` goes into `update_event cover_image` or `update_flyer photo`.

**Tests:** ticket single use; ticket expiry (fake clock); upload with no ticket gives 401; HEIC gets the 415 message; the written file is stripped. Every test uses `t.TempDir()`.

## Resolution

- `storeImage` (`internal/handlers/admin_media_upload.go`) now holds the sniff → DecodeConfig → CheckDimensions → Strip → VerifyStripped → Filename → WriteAtomic pipeline; `AdminMediaHandler.Upload` calls it. Admin tests unchanged. The not-configured 503 text is now the shared constant `mediaNotConfiguredMessage`.
- `internal/handlers/v1_media.go`: `MediaV1` with an in-memory `uploadTickets` store (16-byte random id, 32-byte random secret, only its SHA-256 kept, 10-minute TTL, single use, expired ones swept on every access), ops `create_media_upload` (`media:write`, 201) and `list_media` (`media:read`, newest first, cursor `{mtime, name}`; dotfiles and directories skipped), and the REST-only `Upload` at `POST /api/v1/media/uploads/{id}`.
- Deviation from the plan, on purpose: the path segment is a **non-secret ticket id**, and the secret goes only in `Authorization: Bearer`. Both must match. So no secret reaches a URL or an access log. Failed attempts do not use up the ticket.
- Audit: reused the existing `audit.ActionMediaImageUploaded` (`media.image_uploaded`) rather than adding `media.uploaded`, attributed with `audit.AttributeAPIToken` to the key that minted the ticket. Metadata matches the admin row; the ticket is in neither the metadata nor any log line.
- Wiring: `APITokensHandler.SetMediaUpload`/`MediaUpload`; `cmd/opencircuit/main.go` builds `NewMediaV1(serverSettings.MediaDir, cfg.BaseURL, auditLogger)`, passes it as `V1Deps.Media`, and mounts `handlers.MediaUploadPattern` next to the v1 router.
- Op names appended to `TestBuildV1RegistryListsOperations`, `specTools`, `docs/api.md` (a "Media" section) and `docs/mcp.md`.
