## Description

The admin screen for writing a campaign: Markdown editor, live preview, interest targeting with a live recipient count, and the guarded send action.

## Acceptance criteria

- [ ] Markdown editor with a side-by-side rendered preview
- [ ] Subject and preheader fields with length guidance
- [ ] Interest targeting UI with the four audience modes and a live recipient count from `/audience`
- [ ] Test-send control, and a send button disabled until every pre-send check passes
- [ ] Sending requires typing the recipient count to confirm
- [ ] Unmet pre-send requirements are listed explicitly ("physical address not set", "no test send yet")
- [ ] Cancel action available while scheduled or sending, with copy stating it cannot recall sent mail
- [ ] `npm run check` and `npm test` pass

## Carried in from `#0044`'s plan (2026-08-21)

- [ ] **The audience endpoint returns `{mode, interest_ids, count, sample,
      warnings}`.** `sample` is capped at **20 server-side** and is not
      client-controlled.
- [ ] **Render `warnings` and `409` bodies verbatim** in the "unmet pre-send
      requirements" list. `#0044` returns a typed `409` for an empty interest
      set and for an unknown mode, and warns (rather than rejecting) when
      interests are attached to the `all` or `none_selected` modes.

## Notes

PRD §6.6, §8. The typed-count confirmation is deliberate friction on the one action in this system that cannot be undone. Do not soften it to a checkbox.

Listing *which* pre-send check failed beats a disabled button with no explanation — an operator staring at a greyed-out send button with no reason given will work around it or give up.
