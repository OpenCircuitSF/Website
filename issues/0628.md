## Description

~~`shownChannels` in `internal/handlers/admin_outreach.go` returns only enabled channels, so a channel turned off in Settings simply vanishes from the Outreach screen.~~ **Correction (#0628, 2026-11-05).** Measured against the code on planning day: `shownChannels` returns the switched-on channels **plus** any switched-off one that still has a visible post (scheduled, queued, posted or failed). So two cases exist. An off channel with no visible post vanishes with no explanation, as described. An off channel with a visible post keeps its board column, and that column says nothing about being off: its other cells read "Not written" as if the channel were on.

## Root cause

The client had no way to know a channel was off. `view.channels` holds the switched-on channels plus any off one with a visible post, and nothing marked which was which. So an off channel with no post vanished silently, and one with a post read as on: "Not written" in its empty cells, and counted as work to do in the section status, the not-scheduled note and "fully posted". Separately, `Prepare` had no channel check, so a page left open across the Settings change could create a ShortLink for an off channel.

The bounce found two more of the same kind: `waveRowStatus` asked `view.channels` whether anything sends itself, which stays true while an off automatic channel keeps its column, and `notScheduledNote` looked only at on channels for a post that had started, which hid the note when the only started post was on an off channel.

## Fix

As planned. The panel gains `off_channels`, the only new source of truth, with no schema change. The board names every off channel in one line with an Open Settings link, heads a kept column `TikTok (off)`, and fills its empty slots with Off while real posts keep their words and times. `onChannels` replaces `view.channels` wherever the question is "what is still to do". Empty cards for off channels are dropped, and `Prepare` returns 409 on a hidden draft. `PromoteDue` is unchanged, so a scheduled post on an off channel still goes out and the line says so.

No divergence from the plan. One small helper beyond it: the test file adds `testOffPanel`, `offPanel` and `offNames`, in line with the plan's "decode with a local struct".

**Second pass, `0c9367d3`, the review's remedy as written, no divergence.** `waveRowStatus` now takes its hand-only branch on `auto.length === 0 && !onChannels(view).some(sendsItself)`, and that branch's count is `handPosted.length + left`, so an off channel with no post in the section is not counted. `notScheduledNote` keeps `own` on `onChannels` but computes `started` from every channel in `view.channels` that sends itself, so a scheduled or posted row on an off channel still makes an on channel's gap worth a note. Four tests in `outreachMessage.test.ts` pin the review's four rows.

## Plan

**Design, decided here so the implementer only applies it.**

- `view.channels` keeps its meaning (`shownChannels` does not change). The server adds one new panel field, `off_channels`: every switched-off channel, in channel order. It is the only new source of truth. No schema change.
- **Every off channel is named once, in one line under the board**, with one link: "TikTok and YouTube Shorts are off in Settings, so new posts and links skip them. Open Settings". An off channel with no posts gets this line and no column. Three cells of "Off" for each channel would add height on the screen this series is shortening, and five extra rows on a phone.
- **An off channel with a visible post keeps its column**, headed `TikTok (off)` (and `TikTok (off)` as the stacked cell label). Its real posts keep their true words and times: Posted, Scheduled, On hold, Posting now, Failed. Its empty slots read **Off**, not "Not written". Hidden drafts never reach the client, so they read Off as well.
- **A scheduled post on an off channel still goes out** (`PromoteDue` has no channel check, and `#0588` chose this so nothing posts unseen, keeping Unschedule available). So the cell stays "Scheduled" with its time, and the line adds "Posts already scheduled there still go out." only when an off channel has a scheduled or queued post. Do not change that behaviour here.
- An off channel never counts as work to do: not "not scheduled", not "left to post by hand", no "Write" or "No post yet for" naming it, no empty card with a Draft button, and it does not stop a section counting as fully posted.

**The Settings link: right place, and reachable.** Use `adminSettingsHash('outreach')`, the same `#/settings?section=outreach` that `OutreachPanel`, `OutreachBulkActions` and `OutreachScheduleAllDialog` already use. It scrolls to `#settings-outreach`, the panel that renders the `outreach_channels` checkboxes (`Admin.svelte`, `ServerSettings scope="outreach"`). Anyone who can see the board can follow it: the whole admin view renders only when `currentUser.is_admin`, and both the outreach and settings APIs go through `requireAdmin` in the `adminRoutes` loop. No route or permission change.

**What already skips an off channel, and the one gap.**

- Hand-links route: `handPostedChannels` reads `enabledChannels`, covered by `TestAdminOutreachHandLinks_SwitchedOffChannelGetsNothing`. No change; a new test adds the case of an off channel that has a posted row.
- Schedule all: `enabledPosts` plus the skip filter, covered by `TestAdminOutreach_DisabledAutomaticChannel`. No change on the server.
- Start, Create links, Draft all and `CreatePost` use `enabledChannels` or `channelEnabled`. No change.
- **Gap: `Prepare` has no channel check.** `POST /admin/outreach-posts/{id}/prepare` on a hidden draft calls `CreateLink` for a switched-off channel. Reachable from a page left open across the Settings change. Criterion 2 says no ShortLinks for it, so this gets a guard.

      /** The channels switched on; view.channels also keeps an off one for its posts (#0628). */
      export function onChannels(view: Pick<WorkshopOutreach, 'channels' | 'off_channels'>): OutreachChannel[] {
        const off = view.off_channels ?? [];
        return view.channels.filter((c) => !off.some((o) => o.name === c.name));
      }

      /** A board column's name, saying so when the channel is off (#0628). */
      export function boardChannelLabel(label: string, off: boolean): string {
        return off ? `${label} (off)` : label;
      }

      /** The line under the board naming every off channel, '' when none is (#0628). */
      export function boardOffLine(view: Pick<WorkshopOutreach, 'off_channels' | 'posts'>): string {
        const off = view.off_channels ?? [];
        if (off.length === 0) return '';
        const labels = off.map((c) => c.label);
        const list = labels.length === 1 ? labels[0] : `${labels.slice(0, -1).join(', ')} and ${labels[labels.length - 1]}`;
        const line = labels.length === 1 ? `${list} is off in Settings, so new posts and links skip it.` : `${list} are off in Settings, so new posts and links skip them.`;
        const going = view.posts.some((p) => off.some((o) => o.name === p.channel) && (p.status === 'scheduled' || p.status === 'queued'));
        return going ? `${line} Posts already scheduled there still go out.` : line;
      }
