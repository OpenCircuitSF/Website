## Description

Structured data in each workshop page's server-injected head, making sessions eligible for rich results in search.

## Acceptance criteria

- [x] JSON-LD `Event` object injected server-side into `/workshops/{slug}`
- [x] Fields: name, startDate, endDate, eventStatus, eventAttendanceMode, location, description, organizer, image, url
- [x] Canceled workshops emit `EventCancelled` status
- [x] Organizer is Open Circuit SF with the site URL — no venue is named as organizer
- [ ] Validated against Google's Rich Results Test with no errors — **not run**; this environment has no access to Google's live tool. Validated instead against Google's documented Event requirements by hand (see `## Verification`) — the reviewer or user should paste a real rendered page (`curl`'d output below) into https://search.google.com/test/rich-results to close this box for real.
- [x] JSON string values escaped correctly; a title containing quotes does not break the block

## Notes

PRD §7.4. Structured data goes in the server-injected head, not the SPA — search crawlers that do render JavaScript are the exception, not the rule.

Escaping matters as much here as in #0019: an apostrophe or quote in a workshop title that breaks the JSON block silently invalidates the whole thing, and the failure is invisible without validation.

## Root cause

Nothing was wrong; this is new work. `internal/seo` (#0019/#0054) already
server-injects per-route `<title>`/`og:*`/`twitter:card` tags into the built
`index.html`, but nothing emitted schema.org structured data, so a workshop
page had no path into a Google Rich Result at all.

## Fix

Added a new `%%OC_JSONLD%%` token to `web/index.html` and `web/dist/index.html`
(placed right before `</head>`, alongside the existing `%%OC_OG_*%%` tokens),
and a new `internal/seo/jsonld.go` that builds the schema.org `Event` object
and substitutes it in via `Renderer.substitute` (`internal/seo/seo.go`).

**Which workshops get a block.** Only `published` or `canceled` workshops
(matching the public detail route's own "published OR canceled" visibility
rule, `internal/handlers/public_workshops.go`) that *also* have both a start
date and a location produce a block; `draft`, an unknown slug, or a
published/canceled workshop still missing a date or venue render nothing (no
`<script>` tag at all) rather than a block with a fabricated or empty
required field. `name`/`startDate`/`location` are schema.org/Google's
required `Event` fields for a non-virtual event — emitting an incomplete
block would fail Rich Results validation, which is worse than omitting
structured data for a workshop whose details aren't finalized yet.

**Canceled workshops — the deliberate divergence this issue's task flagged.**
`workshopRouteMeta` (renamed from `workshopMeta`) still serves a canceled
workshop's `<title>`/`og:*` tags from the generic site fallback, unchanged —
`#0135`'s review left that behavior standing so canceled workshops stay out
of link-preview cards and the sitemap. JSON-LD does the opposite on purpose:
it carries the workshop's *own* real title/dates with
`eventStatus: "https://schema.org/EventCancelled"`, because that field exists
specifically so a search result can say "this was scheduled and got
canceled" instead of either pretending the event never existed or silently
vanishing it — matching the fact that the detail page itself (#0054) still
renders a real, visible cancellation notice for anyone holding the link. This
resolves the tension the task named: the social card/sitemap stay generic
for a canceled workshop; the structured data does not.

**No online/virtual event concept exists in this schema.** `internal/
workshops.Workshop` has no is-virtual flag or meeting-link field — Open
Circuit SF is an in-person workshop space (PRD's own framing) — so
`eventAttendanceMode` is always `OfflineEventAttendanceMode` and `location`
is always a schema.org `Place` built from `location_name`/`location_address`.
If a virtual/hybrid workshop concept is ever added to the data model,
`jsonld.go`'s doc comment names exactly where to branch (emit
`OnlineEventAttendanceMode` + a `VirtualLocation` alongside/instead of the
`Place`).

**Organizer** is always a fixed `{"@type":"Organization","name":"Open Circuit
SF","url":"<baseURL>/"}`, built from `cfg.BaseURL`, never from the workshop's
own `location_name`/`location_address` — satisfies "no venue is named as
organizer" by construction, not by a check.

**Escaping.** The JSON body comes from `encoding/json.Marshal`, whose default
behavior HTML-escapes `<`, `>`, and `&` (Go does this unconditionally unless
`Encoder.SetEscapeHTML(false)` is explicitly set, which nothing here does).
That's what makes the JSON-LD token the *one* token `Renderer.substitute`
does **not** additionally run through `html.EscapeString` — the OG/title
tokens need it because they're plain text dropped into an HTML
attribute/text node, but the JSON-LD token is already a complete,
self-contained `<script>` element; a second HTML-escaping pass would corrupt
the JSON itself (turning a JSON-required `"` into `&#34;`) rather than
protect anything.

**A real bug this issue's own change would otherwise have introduced, caught
before it shipped: cache-bucket sharing.** Before this change, `resolve`
routed every workshop slug that wasn't a *published* match (draft, canceled,
unknown) into one shared `cacheKeyFallback` cache entry — safe only because
every one of those cases rendered a byte-identical generic body. Once a
canceled workshop started carrying its own per-workshop JSON-LD, two
*different* canceled workshops sharing that single cache entry would have
served one workshop's structured data on the other's page after the first
one primed the cache. Fixed by widening `workshopRouteMeta`'s "gets its own
cache key" condition from `status == published` to
`status == published || status == canceled`; draft and unknown slugs still
share the fallback bucket (their bodies are still identical — no per-workshop
data). Documented in `maxCacheEntries`' doc comment and covered by
`TestRender_JSONLD_DistinctCanceledWorkshopsDoNotShareCacheEntry`.

## Gotchas

- **`internal/seo.WorkshopStatus` still has a `WorkshopUnpublished` value**
  the real `internal/workshops` store never produces (only
  `draft`/`published`/`canceled` exist at the DB `CHECK` constraint level —
  "unpublish" transitions a row back to `draft`, not a separate
  "unpublished" status). `buildEvent`'s gate (`status != Published && status
  != Canceled`) treats it the same as draft — no block — which is the
  correct, conservative default if that value is ever actually produced, but
  it's effectively dead code today; not touched, since resolving that predates
  this issue and is out of scope.
- **Google's exact validation behavior is a matter of documented convention,
  not something this pass could confirm against the live tool** — see the
  unticked acceptance-criterion box above. The structural checks (valid JSON,
  correct field names/types per schema.org's `Event` docs, RFC 3339 dates
  with an offset) are the strongest verification available without outbound
  network access to Google's service.
- **`workshopRouteMeta`'s `ok=true` for canceled is a real behavior widening**
  worth the reviewer's attention: before this change, a canceled workshop's
  cache entry was indistinguishable from a draft's or an unknown slug's (all
  shared `cacheKeyFallback`). After this change it gets its own
  `"workshop:{slug}"` entry — same mechanism as published, just with the
  fallback `RouteMeta` instead of the workshop's own title/OG fields. Worth
  double-checking `TestRender_JSONLD_DistinctCanceledWorkshopsDoNotShareCacheEntry`
  actually would have caught the pre-fix behavior — confirmed by hand:
  reverting `workshopRouteMeta`'s canceled branch to `return RouteMeta{},
  false` (restored afterward; `diff` against a copy saved first confirmed
  byte-identical, no destructive git command used, `CLAUDE.md` §8a) makes the
  test fail immediately on workshop A's own body — `extractJSONLD` reports
  "no JSON-LD `<script>` block found", since with `ok=false` a canceled
  workshop falls all the way back to the shared, JSON-LD-less
  `cacheKeyFallback` entry (the pre-#0055 behavior) rather than getting its
  own per-slug block at all. That is itself the bug this test guards
  against, just caught at the first workshop rather than needing a second
  one to prove the leak.
