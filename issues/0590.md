## Resolution

All five items. SPA plus a small Go addition to the results handler; no migration.

1. **Posts cell.** `GET /admin/outreach-results` rows gain `posted_channels` (names, channel order) and `scheduled` (count). The overview cell reads "Posted: Bluesky, Mastodon · 4 scheduled", or "Nothing posted yet", via `postsCellText` in `lib/outreachResults.ts`. "3 of 15" is gone. **Enabled channels only:** per-channel enable toggles do not exist yet (#0588), so every channel the view reports counts today; `postsCellText` takes an `isEnabled(channel)` predicate (the view passes a constant `channelEnabled`), and #0588 only needs to supply the real one.
2. **One definition, labelled.** The legend is headed "Clicks in the chart (Oct 12 to Oct 17 (UTC))" and the channel table column "Clicks (all links in the window)". `clickDefinitionNote` prints an explanation only when a legend total and the same channel's table total differ, so two unlabelled numbers never sit side by side. `legendTotals` is the legend's own numbers; a test asserts legend = table for a fixture and that a disagreement is explained. The cause of the 40 versus 55 gap was not changed server-side. *(Reviewer: it turned out to be a dev-mock window bug, not two definitions. The mock is fixed in `1139da6`; see Review notes.)*
3. **Axis and flyer column.** The last x label is right-aligned (`anchor: 'end'`) and `padRight` went from 12 to 24, so "Oct 17" cannot clip. The flyer rows carry `workshops_at_location` (Go, distinct outreaches with a link at that location); the "Scans all workshops" column, and its "unavailable" message, show only when some row has more than one, and the other header reads "Scans".
4. **Collapsed links.** The per-link table sits in `<details class="links">` with summary "Every link (N)", closed by default, after the total, chart, legend and channel table.
5. **Phone.** Results and Locations are wrapped in a `.fit` element (`max-width:100%; min-width:0; overflow-x:hidden`) so a wide table scrolls inside its own `.table-scroll` and not the page. Locations rows become cards under 480px by CSS only (one DOM, so one set of buttons): header visually hidden, each cell shows its `data-label`, and the actions stack full width. Post card button rows (J3) stack under 480px through an `article.card > .row` rule in `app.css`'s existing 480px block, because `OutreachPostCard.svelte` is another agent's in-flight file; its markup order already puts the primary button first.

`types.ts`: three optional fields (`posted_channels`, `scheduled`, `workshops_at_location`); only those hunks were staged.

## Review notes

- **Items checked against the review's I1 to I5, J1 and J3.** 1 (I1): the posts cell is right. Manual "Mark posted" sets `status = 'posted'` (the same update as a real post), so it counts. `scheduled` is the `scheduled` status count from `ListSummaries`, which matches the `status` CHECK values. The `isEnabled` hook is in place for #0588. 3 (I3, I4): the last x label is right-aligned. `workshops_at_location` counts distinct outreaches among every flyer link at the location, the same link set the all-workshops column sums, so the column hides exactly when the two columns would be identical. 4 (I5): the link table is a closed `<details>` after the chart and the channel table. 5 (J1, J3): every table on Results and Locations sits in its own `.table-scroll`, the chart SVG is `width="100%"`, and mention text already wraps. So `.fit`'s `overflow-x: hidden` clips nothing a user needs: wide tables scroll inside their own box. The J3 rule `article.card > .row` matches only `OutreachPostCard`. It outranks the global `.row` utility.
- **Item 2: the 40 versus 55 gap was a dev-mock bug, so the two numbers now share one definition.** On the server, both numbers come from the same ShortLinks rollup for the same half-open window. The channel table sums `by_link`, and a channel's chart line sums `series_by_link`, but only for links ShortLinks charts by name (`exact` in `BuildResults`). Any other channel folds into "Other links" and gets no legend entry. So with real ShortLinks, a channel's legend total equals its table total. The gap came from `internal/devmocks`: its `rollup` returned `window_to` as the **last day** and not the day after it, which breaks the `[from, to)` contract in `shortlinks.CampaignRollup`. The handler passes the rollup's window to the SPA. The SPA's `utcDays` treats `to` as exclusive, so it dropped day 7 from the chart, and that day carries each link's rounding remainder. That is the 15 missing Bluesky clicks. **Fix (`1139da6`):** the mock now returns `window_to` as the day after the last bucket. `TestShortLinksRoundTrip` now checks that every series day lies inside `[WindowFrom, WindowTo)`. The labels stay and are true: the legend counts the days the chart shows, and the table counts all of the channel's links in the same window. `clickDefinitionNote` is now a safety net that should never show. The mock still ignores the requested `from`/`to` and always reports the last 7 days. That is why the walkthrough's chart started before any post. It is a follow-up, not a defect in this issue.
- **Fix: the Locations card buttons did not stack the way the CSS said.** Under 480px, `.loc-table td { display: block }` outranked the lone `.loc-row-actions { display: flex; flex-direction: column }`. With Svelte's scoping hashes the specificities are (0,3,1) against (0,2,0), so the flex rule never applied. The buttons still ended up full width, through `width: 100%`, but with no gap between them. The selector is now `.loc-table td.loc-row-actions`, and `OutreachLocations.cardCss.test.ts` asserts it.
- **Mutation test.** I put the mock's `window_to` back to `days[6]`. `TestShortLinksRoundTrip` failed with `series day 2026-10-18 outside [2026-10-12, 2026-10-18)`. I restored it by copy: `internal/devmocks/mocks.go` sha256 `cb811c47…fa750d` before and after.
- **Verification** (load 2.7 to 3.7): `ISSUE=0590R scripts/check.sh go ./internal/handlers/... ./internal/outreach/... ./internal/devmocks/...` passed. All three packages reported `ok`, with no skips and gofmt clean. `ISSUE=0590R scripts/check.sh web` passed: 77 files, 4598 tests. The 390px layout is still proven by jsdom and source reads only. A Tart render is still owed.
- **Follow-ups, not blocking:** (a) make the devmocks `rollup` honour the requested `from`/`to`, so demo data cannot start before outreach does. (b) `ResultsSummary` calls `ListPosts` once per workshop row (N+1). That is fine at this scale, but one grouped query beside `ListSummaries` would remove it. (c) `queued` posts (due and being sent) appear in neither "Posted" nor "scheduled".
