## Resolution

All five items. SPA plus a small Go addition to the results handler; no migration.

1. **Posts cell.** `GET /admin/outreach-results` rows gain `posted_channels` (names, channel order) and `scheduled` (count). The overview cell reads "Posted: Bluesky, Mastodon · 4 scheduled", or "Nothing posted yet", via `postsCellText` in `lib/outreachResults.ts`. "3 of 15" is gone. **Enabled channels only:** per-channel enable toggles do not exist yet (#0588), so every channel the view reports counts today; `postsCellText` takes an `isEnabled(channel)` predicate (the view passes a constant `channelEnabled`), and #0588 only needs to supply the real one.
2. **One definition, labelled.** The legend is headed "Clicks in the chart (Oct 12 to Oct 17 (UTC))" and the channel table column "Clicks (all links in the window)". `clickDefinitionNote` prints an explanation only when a legend total and the same channel's table total differ, so two unlabelled numbers never sit side by side. `legendTotals` is the legend's own numbers; a test asserts legend = table for a fixture and that a disagreement is explained. The cause of the 40 versus 55 gap (daily buckets versus the link rollup) was not changed server-side.
3. **Axis and flyer column.** The last x label is right-aligned (`anchor: 'end'`) and `padRight` went from 12 to 24, so "Oct 17" cannot clip. The flyer rows carry `workshops_at_location` (Go, distinct outreaches with a link at that location); the "Scans all workshops" column, and its "unavailable" message, show only when some row has more than one, and the other header reads "Scans".
4. **Collapsed links.** The per-link table sits in `<details class="links">` with summary "Every link (N)", closed by default, after the total, chart, legend and channel table.
5. **Phone.** Results and Locations are wrapped in a `.fit` element (`max-width:100%; min-width:0; overflow-x:hidden`) so a wide table scrolls inside its own `.table-scroll` and not the page. Locations rows become cards under 480px by CSS only (one DOM, so one set of buttons): header visually hidden, each cell shows its `data-label`, and the actions stack full width. Post card button rows (J3) stack under 480px through an `article.card > .row` rule in `app.css`'s existing 480px block, because `OutreachPostCard.svelte` is another agent's in-flight file; its markup order already puts the primary button first.

`types.ts`: three optional fields (`posted_channels`, `scheduled`, `workshops_at_location`); only those hunks were staged.
