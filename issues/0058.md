## Description

Fetch the message from S3, extract the subscriber, and unsubscribe them.

## Acceptance criteria

- [ ] `POST /api/ses/inbound` accepts SNS notifications, signature-verified by #0037
- [ ] Message fetched from S3 by key and parsed with `net/mail`
- [ ] Token extracted from a `unsubscribe:<token>` subject line — the preferred path
- [ ] Fallback: match the `From:` address against `subscribers.email`
- [ ] Neither matching → logged, object left in place for manual review, 200 returned
- [ ] Successful match unsubscribes and writes an audit row with `source = 'mailto'`
- [ ] Processed objects deleted from S3
- [ ] Auto-replies and bounce-to-sender messages ignored rather than treated as unsubscribe requests
- [ ] Tests cover subject-token match, From-address fallback, no match, and an auto-reply

## Notes

PRD §6.5 path 3. The `From:` fallback is genuinely spoofable, which is why the subject token is preferred. Unsubscribing on a spoofed From is a low-harm outcome (someone gets removed from a mailing list they can rejoin) but it should still be the fallback, not the primary path.

Auto-replies are the practical hazard: an out-of-office bouncing off a campaign can land in this mailbox and must not be read as an unsubscribe request.
