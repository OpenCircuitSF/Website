## Description

`#0478` and `#0479` added re-run steps to phases 2 and 3 so an agent's own notes
are scanned before they are committed. **The instruction is correct and should
stay.** What is wrong is the rationale attached to it: both steps name sections
the citation guards do not read.

Both citation guards share one section filter, `issueCitationSectionHeaders`,
and the line-citation guard reuses it rather than defining its own. Its nine
keys are `verification`, `implementation notes`, `fix pass`, `review notes`,
`review verification`, `review findings`, `bounce fix`, `bounce-fix completion`,
and `work log`.

Measured against what the two steps promise:

| Section a step names | In the citation guards' scope |
|---|---|
| `## Verification` | **yes** |
| `## Work log` | **yes** (added by `#0446`) |
| `## Review notes` | **yes** |
| `## Root cause` | no |
| `## Fix` | no |
| `## Files changed` | no |
| `## Gotchas` | no |
| `## Resolution notes` | no |

So phase 2's step 8 promises a scan of five sections and delivers it for one.
Phase 3's step 5 says the pre-flip run "lets both actually scan the
`## Resolution notes` you just wrote", and that section is outside the citation
guards' reach **at any status**.

## Why this still is not a bug in the behaviour

The steps remain worth following exactly as written, for three reasons:

1. **The section a reviewer actually writes on approve is `## Review notes`**,
   which *is* scanned — 393 issue files carry one. The instruction lands on the
   right artifact even though the sentence explaining it names the wrong one.
2. **`## Verification` is where citations concentrate**, and it is in scope. It
   is also the section that broke in `#0476`, which is what began this lineage.
3. **The citation guards are not the only guards in the package.** The
   `**Closed**` row check keys off status rather than prose, and the
   dangerous-fence family has its own reach. "Scanned" is not one predicate.

This is a documentation defect: an instruction justified by a claim that does
not hold, which will mislead the next person who reasons from it rather than
from the guard.

## Also fold in, all recorded verbatim by `#0479`'s review

4. **The approve path's second run is buried mid-paragraph**, after "Only once
   this run is clean…". An agent that reads the bolded lead, sees the command,
   and runs it does the right thing *once* and may never reach the
   flip-and-run-again instruction. Splitting the approve bullet into two ordered
   sub-steps removes the risk.
5. **The two-run cost is unstated.** Measured at 0.533s and 0.484s — nearly
   free. One clause saying so stops a future reader from optimising it away.
6. **"Run the same command a second time" leaves the `ISSUE=` suffix implicit**,
   and since the harness drops its database on exit the second run
   re-provisions. Half a second, invisible, but unanswered by the text.
7. **Phase 3's commit step says "stage the issue file"** without naming
   `CLAUDE.md` §8a's index check, which is what actually decides bare-commit
   versus pathspec.

## Acceptance criteria

1. **Correct both rationales to name only sections the guards read.** Do not
   weaken the instruction to run — the run is right; its stated reason is not.
2. **Re-derive the section list yourself** rather than trusting the table above.
   Read the filter and confirm the line-citation guard reuses it. This lineage
   has now had **six** false premises corrected by measurement; the table is a
   seventh candidate, not an authority.
3. Address items 4–7. Each has a verbatim remedy in `#0479`'s `## Review notes`.
4. **Prose only.** `#0478` criterion 3 and `CLAUDE.md` §8 both forbid building a
   mechanism to check prose; that boundary carries over unchanged.
5. **Say what "scanned" means**, since it is not one predicate — status filter,
   section filter, and per-guard reach are three different things, and conflating
   them is what produced this defect.

## This is the terminating pass on the re-run steps

`#0478` → `#0479` → this issue is three rounds of editing the same process
prose. `CLAUDE.md` §8 records `#0258`'s six-pass spiral and warns that each new
pass buys the next bounce. The shape here is milder — these are factual
corrections found by using the text, not mechanisms defending mechanisms — but
the cost curve is the same.

**So: fix all seven items in one pass, and stop.** If a later review finds
further imprecision in these steps, record it in that review's notes and leave
it there. Do not open a fourth round.
