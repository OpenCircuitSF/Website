## Description

The operator's all-writes-stay-inside-the-repo directive has been applied in
three passes — `#0537` (release/deploy), `#0538` (three guard harnesses),
`#0540` (five more shell sites). The `#0540` pass enumerated the last known
shell-layer offenders still writing under system TMPDIR or literal `/tmp`:

- `scripts/sim.sh` (default `/tmp` output path)
- `scripts/db-status.sh`
- `scripts/db/backup.sh`, `scripts/db/restore.sh`, `scripts/db/backup-media.sh` (`cd /tmp`)
- `scripts/check_guard_test.sh`'s comment-only `/tmp/x` payload string (cosmetic, but it teaches the pattern)

This is the tail: after this lands, the directive is enforced repo-wide and
the pattern stops propagating.

Related foot-gun observed live during `#0539` (not a TMPDIR issue, noted here
so it is not lost): `internal/db`'s citation guard parses every `.go` file it
finds repo-wide and FAILS on a parse-invalid Go file under `.scratch/` — a
broken scratch probe takes down every agent's run the same way the gofmt sweep
did. If the fix is a one-line `.scratch/` exclusion in that guard's walk,
fold it into this issue's pass; otherwise file it separately.

## Acceptance criteria

- [ ] All listed scripts create outputs/scratch under `.scratch/` inside the repository (or an explicitly documented operator-chosen location for backup artifacts, if the issue of durable backups argues for one — say which and why)
- [ ] Cleanup semantics preserved; backup/restore behavior byte-equivalent apart from location
- [ ] `bash -n` + `shellcheck` clean on every edited script
- [ ] The citation-guard parse foot-gun is either fixed here (with both directions proven: valid scratch Go file ignored, invalid one ignored too — the guard should skip `.scratch/` entirely) or split into its own issue with this one's resolution noting the split
- [ ] `scripts/check.sh guards` passes

## Resolution notes

> Drafted 2026-09-15, status left `in-progress` for review. Folded, not
> split: the citation-guard foot-gun met the one-line bar and its both-
> directions proof is included below.

- **`scripts/sim.sh`** — the default screenshot path moved from system
  TMPDIR to `.scratch/sim/opencircuit-sim-$$.png` (repo-internal, still
  pid-namespaced per its own concurrency note). The parent directory is
  created only on the default path; an explicit third argument behaves
  exactly as before. No cleanup added — sim.sh never cleaned up and still
  doesn't.
- **`scripts/db-status.sh`** — the `cd` moved from the old world-writable
  directory to the repo checkout root (`$SCRIPT_DIR/../..`), matching
  `deploy/systemd/opencircuit-backup.service`'s `WorkingDirectory=`.
  Purpose unchanged: suppressing the harmless "could not change directory"
  warning from peer-auth psql when the inherited cwd is unreadable. If an
  operator ever runs it from a checkout under a directory the postgres OS
  user cannot traverse, the cosmetic warning returns — no data effect.
- **`scripts/db/backup.sh`, `restore.sh`, `backup-media.sh`** — same `cd`
  relocation (checkout root, not system TMPDIR); `restore.sh` and
  `backup-media.sh` gained the `SCRIPT_DIR` derivation they lacked.
  `cd` position preserved, so relative dump-path handling is unchanged.
- **Backup artifact location — kept at `/var/backups/postgres` (documented
  operator-chosen location, not `.scratch/`).** PRD §10.6's design is
  nightly dump to a local tree on the database host + offsite rsync pull;
  the root is chmod 0700, symlink-and-prune managed, shared with the media
  backup leg, and is the restore point the redeploy runbook checks. Durable
  backups must not live in a gitignored scratch tree that agents treat as
  sweepable. The all-writes directive covers tooling scratch; it does not
  relocate the production backup root, and no default changed.
- **Citation-guard foot-gun — folded.** `issueGuardSkipDir` in
  `internal/db`'s issue-citation guard now prunes `.scratch/` from the
  repo-root walk, so throwaway Go probes there are never parsed. Proven
  both directions by a new fixture: a valid probe (with a planted
  test-named function) and a parse-invalid probe under `.scratch/` are
  ignored and nothing is collected from them; the same parse-invalid
  content outside `.scratch/` still hard-fails the walk (exercised in a
  subprocess, since the walk's failure path is a Fatal), and the failure
  names the offending file. The fixture was also run against the one-line
  exclusion removed: it fails naming the scratch probe, so the proof is
  not vacuous.
- **`scripts/check_guard_test.sh`** — the comment-only payload string now
  reads `.scratch/x` instead of the old absolute path; the `.` token it
  exists to cover is untouched and the row still asserts the benign
  comment does not trip a self-check. Drive-by in the same spirit:
  `scripts/db/restore-media.sh`'s restore-drill example (comment only, no
  code change) now points at a repo-internal scratch directory.
- **Nothing remains.** A sweep of `scripts/` and `deploy/` for literal
  old-path writes and unset `mktemp` finds only comments describing
  already-relocated sites; every `mktemp` now templates under
  `.scratch/`.
