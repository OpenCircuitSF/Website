## Description

The operator's all-writes-stay-inside-the-repo directive has been applied in
three passes — `#0537` (release/deploy), `#0538` (three guard harnesses),
`#0540` (five more shell sites). The `#0540` pass enumerated the last known
shell-layer offenders still writing under system TMPDIR or literal `/tmp`:

- `scripts/sim.sh` (default `/tmp` output path)
- `scripts/db-status.sh`
- `scripts/db/backup.sh`, `scripts/db/restore.sh`, `scripts/db/backup-media.sh` (`cd /tmp`)
- `scripts/check_guard_test.sh`'s comment-only `/tmp/x` payload string (cosmetic, but it teaches the pattern)

This is the tail: after this lands, the directive is enforced repo-wide and
the pattern stops propagating.

Related foot-gun observed live during `#0539` (not a TMPDIR issue, noted here
so it is not lost): `internal/db`'s citation guard parses every `.go` file it
finds repo-wide and FAILS on a parse-invalid Go file under `.scratch/` — a
broken scratch probe takes down every agent's run the same way the gofmt sweep
did. If the fix is a one-line `.scratch/` exclusion in that guard's walk,
fold it into this issue's pass; otherwise file it separately.

## Acceptance criteria

- [ ] All listed scripts create outputs/scratch under `.scratch/` inside the repository (or an explicitly documented operator-chosen location for backup artifacts, if the issue of durable backups argues for one — say which and why)
- [ ] Cleanup semantics preserved; backup/restore behavior byte-equivalent apart from location
- [ ] `bash -n` + `shellcheck` clean on every edited script
- [ ] The citation-guard parse foot-gun is either fixed here (with both directions proven: valid scratch Go file ignored, invalid one ignored too — the guard should skip `.scratch/` entirely) or split into its own issue with this one's resolution noting the split
- [ ] `scripts/check.sh guards` passes
