## Description

The revised workflow (`issues/Issues.md`, "Build / verify command", Tiers)
has the implementer check that the change compiles before running any tests.
`scripts/check.sh` has no mode for that, so an implementer either runs a
full scoped run and finds the compile error at the end, or hand-rolls
`go build`/`go vet`/`npm run check`.

## Acceptance criteria

- [ ] `scripts/check.sh build` runs `go build ./...`, `go vet ./...` and
      `(cd web && npm run check)`, through the existing `runpipe`/`run`
      accounting, and prints the usual `VERIFICATION PASSED`/`FAILED` verdict.
      It runs no tests, needs no database, and does not create one even when
      `ISSUE` is set.
- [ ] The header comment's mode list and `AGENTS.md` §5's command block name
      the new mode and say it never counts as verification.
- [ ] `scripts/check_guard_test.sh` covers the new arm: a sandbox copy with a
      Go compile error and one with a `svelte-check` error each report
      `VERIFICATION FAILED` with a non-zero exit.
- [ ] `issues/Issues.md`'s Tiers table drops the "until it lands" fallback.
- [ ] Verified with `scripts/check.sh build`, `scripts/check.sh guards`, and
      `ISSUE=0607 scripts/check.sh go ./internal/db/... ./internal/handlers/...`
      (`AGENTS.md` edit). Zero skips.

         local sb="$WORKDIR/sb/$1"

         cp "$2" "$sb/scripts/check.sh"; chmod +x "$sb/scripts/check.sh"
         printf 'module buildsandbox\n\ngo 1.22\n' > "$sb/go.mod"

           printf 'package main\n\nfunc main() {\n\tundefinedCall0607()\n}\n' > "$sb/main.go"

           printf '{"name":"buildsandbox","private":true,"scripts":{"check":"echo svelte-check found 1 error >&2; exit 1"}}\n' > "$sb/web/package.json"

           printf '{"name":"buildsandbox","private":true,"scripts":{"check":"exit 0"}}\n' > "$sb/web/package.json"

         printf '%s' "$sb"

## Obstacles

- **check.sh's self-checks.** The biggest risk. Avoided by touching none of the
  hashed functions or marker blocks and following the spelling rules above.
  If `self-check: ...` fires on `scripts/check.sh build`, read its message — it
  names the line — and fix the new text; never recompute a digest.
- **Tools.** `go`, `npm`, `shellcheck`, `psql` are on PATH (checked with
  `command -v` while planning). Without `npm`, Part 1c prints a SKIP; that is
  not acceptable as verification here — say so if it happens.
- **`guards` binds `:5173` and creates scratch databases** (`dev_guard_test.sh`,
  `testdb_gc_guard_test.sh`, `db_reset_guard_test.sh`). If another agent is
  running `dev.sh` or `guards`, `dev_guard_test.sh` fails for that reason;
  check `lsof -nP -iTCP:5173 -sTCP:LISTEN` first and wait rather than kill
  someone else's process (`AGENTS.md` §5a). Takes about a minute.
- **zsh vs bash.** Test snippets of the new arm with `bash -c` or by running
  the script, never by pasting into the tool shell (`AGENTS.md` §8).
- **Scratch files** go under `.scratch/` with `0607` in the name; the
  mutation copy above is yours to delete.
- No permissions, credentials or approval-gated steps.
