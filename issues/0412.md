## Description

`CLAUDE.md` §1's migration section ends by saying `#0293` **tracks correcting**
the remaining stale greenfield copies in `PRD.md` §6.2 and
`docs/deployment.md` — phrasing that describes open, pending work.

`#0293` is **resolved**, and those copies were corrected on 2026-08-27. So the
sentence sends a reader looking for an outstanding task that was finished a week
ago, in the same paragraph that just taught them the frozen range is a dated
snapshot.

**Reported by `#0407`'s review, which deliberately kept it out of scope** because
it was not introduced by that pass and widening a bounce to cover adjacent prose
is how a documentation fix turns into an open-ended edit. It is filed here
instead.

## The suggested wording, from that review

> `#0293` corrected the remaining copies in `PRD.md` §6.2 and
> `docs/deployment.md`.

## Acceptance criteria

1. The sentence describes completed work rather than pending work.
2. **Verify `#0293`'s status and closed date yourself** before writing them, and
   **verify the copies really were corrected** in both named files. Do not copy
   the date from this issue — `#0407` exists precisely because a fact in this
   section was asserted without checking, and its first fix attempt repeated the
   pattern with a different fact.
3. If either named file still carries an uncorrected copy, that is a finding:
   say so rather than writing a sentence claiming it was fixed.
4. **No mechanism** (`#0330`/`#0347`/`#0356`/`#0381`). This is one sentence.
5. Editing `CLAUDE.md` means running **both** `./internal/db/...` and
   `./internal/handlers/...` (§5's own repo-wide-guard table). Confirm the edit
   creates no second `docRangePattern` match — that pattern currently matches
   exactly once, at the Repository-layout row. Per §5 name the specific tests
   that ran.
