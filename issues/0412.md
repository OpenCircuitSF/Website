## Description

`CLAUDE.md` §1's migration section ends by saying `#0293` **tracks correcting**
the remaining stale greenfield copies in `PRD.md` §6.2 and
`docs/deployment.md` — phrasing that describes open, pending work.

`#0293` is **resolved**, and those copies were corrected on 2026-08-27. So the
sentence sends a reader looking for an outstanding task that was finished a week
ago, in the same paragraph that just taught them the frozen range is a dated
snapshot.

**Reported by `#0407`'s review, which deliberately kept it out of scope** because
it was not introduced by that pass and widening a bounce to cover adjacent prose
is how a documentation fix turns into an open-ended edit. It is filed here
instead.

derivation holds.

**A note on the derivation's shape, since this issue exists because of exactly
that.** A date read out of a commit is weaker evidence than a `Closed` row
would be, because a commit date says when bytes landed, not when an issue was
judged done. Here the two coincide and three sources agree, so the conclusion
is safe — but the reason it is safe is the corroboration, not the `git log`
line on its own. Worth noting that the corrected sentence as committed carries
**no date at all**, which sidesteps the question entirely and is the more
robust wording: the claim it makes ("`#0293` corrected these") cannot go stale
the way a date can.

**The sentence read as prose, in context (the part this issue is really
about).** The paragraph it closes says: check an issue's own greenfield
language before following it, because several issues filed before 2026-08-25
still carry the old note in their acceptance criteria. The corrected sentence
then draws the contrast that makes that warning coherent — the **documentation**
copies were fixed, so the stale copies a reader will still meet are the ones in
**issue files**. That is exactly right, and it matches `#0293`'s own scope
decision, which deliberately left seventeen resolved issue files' greenfield
mentions untouched as historical record. Under the old wording the paragraph
read as "issue files are stale, and the docs are pending too", which pointed a
reader at an outstanding task that had been finished a week earlier; under the
new wording it reads as "issue files are stale, the docs are not". The word
"remaining" survives from the old sentence and still scans, since its referent
is the copies left over after the main §1 note itself was corrected.

It also sits correctly against the dated-snapshot framing above it. §1's
frozen range is explicitly a re-derivable, dated measurement with a `ssh ec2`
command attached; this sentence is a statement about a past, completed edit,
which is not the kind of claim that decays with a later deploy. The two do not
pull against each other.
