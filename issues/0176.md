## Description

`#0173` added `sqlFencePattern`/`extractFencedSQL` to narrow `PRD.md` §6.2 to its fenced SQL before tokenizing — a regex over the section text.

**The same Go package already contains a CommonMark-aware fence state machine**: `docs_parity_test.go`'s `docTableRowLines`, which handles backtick *and* tilde fences, indented fences, and enforces that a closer must be at least as long as its opener (`fenceLen`, added by `#0086`'s review for exactly this bug class).

`#0173`'s review classified 21 extractor probes and found none wrong-and-silent — but five wrong-but-loud, all of them shapes the existing parser already handles:

- a second untagged or ` ```SQL `-tagged block is skipped;
- a bare ``` ``` ``` inside a four-backtick body truncates the tail;
- two over-capture cases leak prose back to the tokenizer.

It also noted that the four-backtick case only works **by accident** — ` ````sql ` happens to contain ` ```sql ` at offset 1.

Nothing is broken today: §6.2 has exactly one ` ```sql ` block holding all 13 `CREATE TABLE` and 16 `CREATE INDEX` statements, and a dropped block surfaces loudly through `#0148`'s one-directional scope. This is robustness, and it is cheap because the parser already exists.

## Acceptance criteria

- [ ] `extractFencedSQL` uses the existing CommonMark-aware fence logic rather than a second, weaker regex — extract or share `docTableRowLines`' machinery rather than copying it
- [ ] Tilde fences, four-backtick fences, indented fences, and a bare ``` ``` ``` inside a longer fence all behave correctly rather than merely loudly
- [ ] A second SQL block in §6.2 is either captured or refused loudly — decide which and record it. Silently skipping one is the only outcome that must not happen
- [ ] `#0173`'s 21 extractor probes all still hold, and none regresses from loud to silent
- [ ] **The standing regression bar**: `#0154`/`#0159`'s ~50 classification rows, `#0164`'s 27 span + 5 offset probes, live map `IDENTICAL, 91 columns`, no false positives including Phase 8 forward declarations, scope one-directional
- [ ] `ISSUE=0176 scripts/check.sh go ./internal/...` passes with all four doc guards observed

### Phase-2 decision (2026-08-23) — declined; left `open`

**Decision: do not build.** Status left `open` per this task's instructions and
`issues/Issues.md`'s critical rule — only the user sets `wontfix`. This is a
recorded recommendation, not a self-applied status change.

**1. Current behavior is genuinely inert against the tree — re-proved, not
assumed.** `sqlFencePattern`/`extractFencedSQL` are byte-identical to
`#0173`'s `4288ed8` (`git log --oneline -- internal/db/prd_index_parity_test.go`
shows `4288ed8` as the most recent touch). Independently re-derived §6.2's
fence census straight from the tracked `PRD.md` with a standalone Python
script (never through the Go extractor, never writing to `PRD.md`):

```
section bytes: 18660
fence delimiter lines: [(2, '```sql'), (287, '```')]
inline triple-backtick occurrences (not line-leading): 0
```

Identical to `#0173`'s review (§2: "exactly two: line 3 \`\`\`sql, line 288
\`\`\`", "0" inline occurrences). §6.2 has exactly one canonical, correctly
tagged, line-leading, unindented, backtick fence — none of the five defect
shapes (second block, inner short fence inside a 4-backtick body, tilde
fence, indented fence, inline mid-prose triple-backtick) occur anywhere in
the section. And per `#0173`'s review §4 (re-read, not re-run — the
mechanism is unchanged), any future block the extractor *did* drop would
surface through `#0148`'s one-directional parity check as a loud "does not
mention index/column X" failure, not silently — so the five defects this
issue would fix are all wrong-**but-loud** today, not wrong-and-silent. The
failure class the five prior passes existed to close (a guard that stops
guarding without saying so) does not apply here.

**2. Re-verified clean**, `ISSUE=0176 scripts/check.sh go ./internal/...`
(`uptime` `1.68 2.00 2.89`, well under the ~8 threshold): `go build`/`go vet`
clean, all 15 packages `ok` with real elapsed times, **zero skips**. Then, on
a throwaway `opencircuit_test_0176v` database (dropped after), ran the four
doc guards directly with `-v -count=1`: `TestDocTableRowLines` (14 leaf
subtests), `TestDatabaseDocMigrationParity` (2 subtests),
`TestPRDWorkshopAndMailingIndexParity`, `TestPRDWorkshopAndMailingColumnParity`
— all `PASS`. `gofmt -l` flags only the pre-existing `#0161` quirk on this
file, untouched.

**3. The "less code" bar, estimated rather than built.** The existing
`sqlFencePattern` + `extractFencedSQL` is one regex literal plus a ~12-line
function (excluding comments) — roughly 20 lines of actual logic. Reusing
`docTableRowLines`' fence tracking properly (not copying it) requires:
factoring its inline fence-open/fence-close branches into a shared
`fenceState`-style type both files can call (docTableRowLines's own state
transition is ~30 lines including `leadingRunLength`); a new accumulator
loop in `extractFencedSQL` that tracks capture state per fence, records the
opening line's info string, decides per-fence whether to capture (tag ==
`sql`) or refuse loudly (any other tag when a second fence appears — the
acceptance criterion's "capture or refuse" choice), and joins captured
bodies. Sketched by hand, that comes to roughly 45–55 lines of new/changed
logic across the two files versus ~20 today — **larger, not smaller**, even
after sharing the fence-transition machinery. That is the outcome the issue
itself flagged as evidence against the change ("if your implementation comes
out larger, that is evidence against the change, and worth saying").

**4. Verification-burden asymmetry.** The 21 extractor probes, the ~50
classification rows, and the 27+5 span/offset probes that gate any change to
this file were run as throwaway scratch tests during `#0173`'s review and
were not committed (consistent with `CLAUDE.md` §8b — scratch files, not
session-private, deleted after use). Reproducing all of them faithfully
before trusting a rewrite is itself close to a seventh pass's worth of work,
for a change whose only benefit is correctness on markdown shapes that (1)
this repo's PRD.md does not contain today and (2) would fail loudly rather
than silently if they ever did appear.

**Net:** no live bug, no silent-failure risk, and the fix is estimated larger
than what it replaces. Recommend the user set this `wontfix` if they agree;
left `open` in the meantime.
