## Description

`#0275` closed the empty-roots fail-open: all five `internal/handlers` guards
now assert they parsed a plausible number of files, and `#0275`'s review
verified every floor catches a real narrowing.

| Guard family | Parsed population | Floor | Largest single package |
|---|---|---|---|
| `citedTestScanRoots` × 3 | 255 (all `.go`) | 150 | 96 |
| `TestNoAdminFacingStringCitesInternalDocs` | 111 (non-test) | 80 | 40 |
| `TestAuditEntryEmailMetadataMatchesKnownSites` | 110 (non-test) | 80 | 40 |

**But the floors themselves are ordinary constants in the files they guard.**
Setting `citedTestScanRootsMinPlausibleFileCount`, `citationGuardMinPlausibleFileCount`,
or `auditEmailMetadataMinPlausibleFileCount` to `0` leaves the whole package
green.

`TestGoFileVisitCountGuardFiresOnEmptyOrLowCount` does not close this, and
deliberately so: it uses its own literals (`0`, `3`, `150`) rather than reading a
guard's constant, which is what makes it oracle-independent under CLAUDE.md §8.
It proves the *mechanism* fires. It cannot pin a *value*.

This is exactly §8's "a guard inside the file it guards becomes new mutable
surface", and §8 also names the remedy.

## The remedy is external, and explicitly not a seventh in-file check

`#0258` spent six passes hardening `scripts/check.sh`'s self-checks against
decoys added to `scripts/check.sh`, and by pass six the newest mechanism was
itself the target. The lesson recorded in §8 is that **adding another in-file
check buys another bounce**, and that the project already has the right shape:
`scripts/db_reset_guard_test.sh` and its siblings mutate a *copy* of the thing
under test and assert its exit code and output **from outside**, wired into
`scripts/check.sh guards`.

An external harness cannot be disarmed by editing its subject.

## Acceptance criteria

1. A shell guard of the `scripts/*_guard_test.sh` shape copies the guard files,
   sets each floor constant to `0` in the copy, runs the affected tests, and
   asserts the run **still fails**. One mutation per floor, each named.
2. It also asserts the committed values **pass** against the real tree, so the
   harness fails if a floor is raised above its population — the failure mode
   that forced `#0275` to lower 150 to 80.
3. It recomputes each floor's population **from outside Go** — the parsed
   population, not the walked one (`#0275` criterion 4a) — and fails if a
   committed floor is not below it by a sensible margin. State the margin and
   why.
4. Registered in `scripts/check.sh guards`, not in the default `go`/`web`/`all`
   scopes. Follow the precedent: `dev_guard_test.sh` alone costs ~48s, which is
   why that separate target exists.
5. **Not a seventh in-file check.** If you find yourself adding a Go test in
   `internal/handlers` that reads a floor constant, stop — that is the shape
   `#0258` proved does not work.
6. `bash -n` and `shellcheck` both pass, and the script runs under **bash
   3.2.57** — CLAUDE.md §8 records that `${var,,}` and other bash-4 syntax fails
   *silently* here, and that `bash -n` and `shellcheck` both pass on it. Use
   `tr` for case folding as `scripts/testdb.sh` does.
7. `scripts/check.sh guards` passes, and the existing four guard scripts still do.
