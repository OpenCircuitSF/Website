# 0632 — Outreach can lose an unsaved edit without warning in two more ways

## Description

Found in `#0625`'s review. Neither was caused by that issue.

1. **Confirmed by a jsdom test:** **Save message** replaces an unsaved Customize edit on a non-customized post in that section, with no warning, because the composer picks up the new server body.
2. **Read in the code, not run:** `web/src` has no `beforeunload` handler, so a reload or closed tab loses unsaved work with no warning. In-app links were not checked for a guard.

The open and closed triangles on the board and strips are also very small. The hit areas are fine, so this is cosmetic.

## Plan

Planned with `#0634`, which holds the one `## Plan` and `## Obstacles` for the batch (`#0634`, `#0632`, `#0633`), written 2026-11-05 against `adbdbc50`. This issue's parts there:

- **Item 1**: decision 4 and files 1, 2, 3 and 7. Save message and the section's Regenerate never write a post whose editor holds unsaved typing, whether Customize… or a hand row's Edit. A line says so while typing and the result line says so after.
- **Item 2**: decision 5, files 12 and 13. `beforeunload` for a reload or closed tab, and an in-app dialog for a same-site link. Back, Forward and an edited address cannot be stopped; with `#0633`'s key that work is discarded rather than carried over.
- **Triangles**: decision 7 and file 14.
- Tests and checks: `#0634`'s Tests, Verification (including `scripts/check.sh browser-nav` for the link guard) and Safari checks 2, 3 and 6.
