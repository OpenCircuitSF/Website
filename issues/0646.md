## Description

The user's request, 2026-11-06: "I feel like the home page of Outreach could list all scheduled posts for each upcoming event. That would help me see what will be done and what is missing. It could be presented on a timeline with the posts and events showing on this timeline."

Context: on 2026-11-05 the November newsletter fell back to a plain link for `hack-night-2` because Outreach had never been started for it. Nothing on the Outreach home made that gap visible.

## Acceptance criteria

- [ ] The Outreach home (`#/outreach`) shows a timeline of upcoming published events, with each event and its posts (Announce, Reminder and Final, by channel, including hand-posted video) placed at their scheduled or posted times.
- [ ] Each post shows its status: drafted, scheduled or posted. Gaps are obvious: an event with no Outreach started, a section with nothing scheduled, or a channel missing a post.
- [ ] Each event and post links to its Outreach page or section.
- [ ] Desktop only (user decision 2026-11-05): no phone layout work.

## Root cause

Not a bug: the Outreach home listed upcoming events with a count chip only, so a missing section or an event with no Outreach (`hack-night-2` on 2026-11-05) was not visible.

## Fix

Per the plan, as overridden by `## Decisions`:

- **Go.** New `GET /admin/outreach-timeline` (`AdminOutreachHandler.Timeline`, `internal/handlers/admin_outreach_timeline.go`). `panel()` now uses two extracted helpers, `workshopView` and `waveViews`; no behaviour change. `outreachWorkshopReader` gains `ListVisible`.
- **The 30-day cut is server-side**: the `timelineWindow` constant (30 days), documented on it and on `Timeline`. Only published, dated events with `starts_at` at or before now+30d come back. `outreachTimeline.ts` says so in its header and does no date filtering of its own.
- **Web.** `outreachTimeline.ts` builds the axis, lanes, markers, stacking and gap lines from `boardRows`/`sectionLine`, so there is no second set of status words. `OutreachTimeline.svelte` renders it in a new "Next 30 days" panel **above** the existing Outreach table. The table and the Past panel are unchanged. `adminOutreachWorkshopHash(id, section)` and `outreachSectionFromQuery` add the section deep link, and `OutreachWorkshop` opens and focuses the named section on its first load only.

Deviations from the plan:
- No undated lane and no "Date not set" heading: the 30-day decision means the endpoint leaves out undated events, so `timelineLanes` returns `{ axis, lanes }` with no `undated`. The planned test `'undated events are listed apart, with no track'` and the behaviour test for it were dropped.
- The table rework and its test changes were dropped (Decision 4). `OutreachList.behavior.test.ts` only gains a `getOutreachTimeline` mock and two new cases.
- The timeline panel is hidden when there are no events in the window. The table's existing empty state still covers "no upcoming events".
- No `a:focus-visible` outline in the component: `focusOutline.guard.test.ts` forbids an `--accent` outline on links, and the global underline indicator applies instead.
- `outreachRowButtonLabel` and `outreachRowAriaLabel` now accept `Pick<OutreachSummary, 'counts'>`, the same loosening as `outreachChip`. This is a type change only.

Second pass, after the 2026-11-06 bounce (all in or behind `OutreachTimeline.svelte`):
- Remedy 1: `.axis` now has `margin-left: calc(14rem + 3px + 2 * var(--space-2))`, with a comment naming the lane border, the lane padding and the row's label-column gap.
- Remedy 2: the `.pill` rule gains `background: var(--bg-panel); z-index: 1;`.
- The gap line says the hand-posted count once. The new `withHandNames` in `outreachSection.ts` puts the names after `sectionLine`'s own "N left to post by hand" ("· 3 left to post by hand: Instagram Reels, TikTok and YouTube Shorts"), or appends that phrase when the line has no count (for example "Not written"). `sectionGaps` uses it for `text`; the separate "Left to post by hand" span is gone.
- The sr-only table's column headers use `handChannelLabel`, so they say "Instagram Reels" like the visible rows.

**New `web/src/lib/outreachTimeline.ts`** (pure, no DOM). Every time is passed `now: Date`.

```ts
export type MarkerKind = 'posted' | 'scheduled' | 'drafted' | 'missing' | 'failed';
export interface TimelineAxis { startMs: number; endMs: number; ticks: { at: string; label: string; pct: number }[] }
export interface TimelineMarker {
  key: string; wave: string; waveLabel: string; channel: string | null;
  kind: MarkerKind; status: string; detail: string | null;
  at: string; suggested: boolean; earlier: boolean; pct: number; level: number;
  href: string; label: string;
}
export interface TimelineRow { channel: string | null; label: string; markers: TimelineMarker[] }
export interface TimelineGap { wave: string; label: string; text: string; handLeft: string[]; href: string }
export interface TimelineLane {
  event: OutreachTimelineEvent; started: boolean; eventPct: number | null;
  chip: OutreachChip; rows: TimelineRow[]; gaps: TimelineGap[];
}
export function timelineAxis(events: OutreachTimelineEvent[], now: Date): TimelineAxis;
export function timelinePct(iso: string, axis: TimelineAxis): number | null; // null = before the axis start
export function stackLevels(pcts: number[], minGap?: number): number[];
export function sectionGaps(ev: OutreachTimelineEvent, now: Date): TimelineGap[];
export function timelineLanes(t: OutreachTimeline, now: Date): { axis: TimelineAxis; dated: TimelineLane[]; undated: TimelineLane[] };
```

Rules, so the implementer only applies them:

- **Axis.** `startMs = now`, `endMs = max(dated starts_at) + 1 day`, and never less than `now + 14 days`. `pct = (t - startMs) / (endMs - startMs) * 100`, clamped to ≤ 100. Ticks: one at `pct 0` labelled `Today`, then one per Monday 00:00 Pacific after it, labelled with `formatPacificWeekday` ("Mon, Nov 10"). Step whole Pacific days from `toPacificInput(now.toISOString()).slice(0, 10)`, convert each with `fromPacificInput(`${day}T00:00`)`, and keep the Mondays, so DST cannot shift a tick.
- **Rows.** Dated and started events get one row per channel in `ev.channels`, in server order. The label is `boardChannelLabel(handChannelLabel(c), off)`, where `off` means the channel is in `off_channels`. A not-started event (`outreach === null`) gets a single row `{ channel: null, label: 'Suggested' }` with one `missing` marker per section.
- **One marker per channel and section**, from `boardRows(ev)` cells. Map `cell.kind` to the marker kind: `posted`→`posted`; `scheduled`, `on_hold` and `queued`→`scheduled`; `failed`→`failed`; `not_scheduled` and `manual`→`drafted`; `not_drafted`→`missing`; `off`→no marker. `status` and `detail` are the cell's own words. Time: posted → `posted_at ?? updated_at`; scheduled or failed → `scheduled_at ?? now`; drafted or missing → `defaultScheduleAt(wave, ev.waves, now) ?? now`, with `suggested = true` when the suggestion was used. A posted time before `now` sets `earlier = true` (drawn in the "Earlier" gutter, `pct` 0).
- **`label`** (the marker's `title`, and the source for the sr-only table): `${event title}: ${channel label} ${waveLabel}, ${status}${detail ? ' ' + detail : ''}`, plus `, suggested ${weekdayTime(at)}` when `suggested`.
- **`href`**: `adminOutreachWorkshopHash(ev.workshop.id, wave)` for markers and gaps; the event marker and lane title use `adminOutreachWorkshopHash(ev.workshop.id)`.
- **Stacking.** Within a row, sort markers by `pct`. `stackLevels` gives each one the lowest level whose last marker on that level is at least `minGap` (default `8`) away, so two close pills sit one above the other instead of overlapping. Earlier-gutter markers stack among themselves.
- **`sectionGaps`**: per wave, `text = sectionLine(ev, wave.name, now).text`. `handLeft` holds the `handChannelLabel`s of switched-on hand-posted channels with no posted post in that section, which names the missing channel and not just a count. For a not-started event, a single gap `{ wave: '', label: 'Outreach', text: 'Outreach not started', … }` linking to the event page.
- Undated events go to `undated` with `eventPct: null` and `rows: []` (gaps only).

Tests, new **`web/src/lib/outreachTimeline.test.ts`** (fixtures built like `outreachSection.test.ts`'s, `now` fixed at `2026-11-06T18:00:00Z`):

## Questions for the user

1. **How far ahead does the timeline go?** Recommended: every upcoming published event, with no cap; the axis runs from today to the day after the last dated one, and is never shorter than two weeks. The catalogue is small, so nothing needs a limit yet. Alternative: a fixed window, for example the next 60 days.
2. **Do posts already made for upcoming events show?** Recommended: yes. Each sits in a narrow **Earlier** column at the left of its row with its date, so a lane shows its whole story (Announce done, Reminder missing) without stretching the axis back weeks.
3. **Include draft (unpublished) events?** Recommended: no. Outreach cannot start until an event is published, and today's home list leaves drafts out too. A draft shows up here the moment it is published.
4. **Replace the current home list, or sit above it?** Recommended: **replace** the upcoming table. Each lane keeps everything the table row had (title, date, the status chip, the Promote/Open button), so two lists of the same events add nothing. The Past panel stays.
