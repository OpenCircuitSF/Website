## Description

`internal/db`'s `TestNoOpenIssueEvidenceCitesGoFileByLineNumber` enforces
`#0352`'s ban on Go-file-plus-line-number citations in issue evidence. It scans
only the sections named in `issueCitationSectionHeaders`, which holds
`verification`, `implementation notes`, `fix pass`, `review notes`, and three
older spellings.

**`## Work log` is not among them** — and `## Work log` is where this repo's
phase-2 convention puts implementer evidence. `Issues.md` asks for it there, and
every implementation pass this session has written one.

Found by `#0443`'s reviewer, which caught a banned citation sitting in that
issue's `## Work log` while the guard ran green over it. The reviewer removed
the citation by hand and disclosed it rather than bouncing, since the sentence
already named the enclosing declaration and nothing was falsified.

## Why this is a real gap and not a technicality

The guard exists because a line number goes stale the moment anything above it
moves, and a stale citation is worse than none — it points confidently at the
wrong code. The reviewer's characterisation is the right one: **the guard misses
exactly the text it exists for**, and there is no intent to dodge anywhere in
it. Implementers write their evidence in the conventional place and the guard
looks elsewhere.

It is also self-concealing. Because the section is out of scope rather than
exempt within it, a passing run is not evidence the issue file is clean — which
is precisely the fail-open shape `#0428` closed in a different guard this
session.

## Acceptance criteria

1. `## Work log` is scanned by `TestNoOpenIssueEvidenceCitesGoFileByLineNumber`
   alongside the existing sections.
2. **Sweep the tracker before you assume this is a one-line change.** Every open
   and in-progress issue's `## Work log` now becomes subject to the guard, and
   this session alone added dozens. Fix what the sweep finds — a citation is
   corrected by naming the enclosing declaration, which is what `#0352`
   prescribes, not by deleting the sentence.
3. Check whether `issueCitationSectionHeaders` is consulted by **more than one**
   guard. `TestIssueCitationGuardScansEvidenceSectionsNotSubjectMatter` and
   `TestNoOpenIssueVerificationCitesUndefinedTestFunction` are in the same
   family; widening a shared list widens all of them at once, and that may be
   right or may surface unrelated failures. Say which you found.
4. Consider whether the list should be **inverted** — scanning every section
   except an explicit exempt set (`## Description`, `## Relation`), rather than
   an allowlist that goes stale whenever the issue template gains a section.
   The allowlist's failure mode is silent under-scanning, which is this defect.
   Decide, record the decision, and do not build both.
5. **No new mechanism** beyond the change to the existing guard (`#0258`,
   `#0437`'s criterion 5). One list, one decision.
