## Review notes

Opus review, 2026-10-18. Passed, with one small fix committed by the reviewer (`e0b2a92`).

- **The 409 check.** `resetBlock` refuses on `status = 'posted' OR posted_at IS NOT NULL` (automatic and manual Mark posted both set `posted`; the `posted_at` check constraint makes the second term a belt-and-braces), a post `queued`, a `queued`/`sending` outbox row, and a flyer link with `put_up_at`. A post being sent stays `queued` until `MarkRemotePosted`/final `MarkSendError`, and a remote that accepted but failed to record leaves the post `queued`, so both refuse. `remote_id`/`remote_url` are only ever written together with `posted`. `failed` and `scheduled` do not refuse, as the criterion allows.
- **Race safety.** `QueueNow` locks the post `FOR UPDATE` before going `queued`, and `PromoteDue` uses `SKIP LOCKED`, so both serialise against Reset's post lock: whichever commits second either re-reads `queued` (Reset refuses; read-committed takes a fresh snapshot per statement) or finds the row gone (`ErrNotFound`). **Gap fixed in review:** that lock covers only rows that exist when it is taken. A post drafted after it and queued before the deletes would have been deleted with a live queue row, possibly while the worker was sending it. Reset now locks the `outreach` row `FOR UPDATE` first, which conflicts with the `FOR KEY SHARE` every insert into `outreach_posts`/`outreach_flyers` takes on its parent, and locks `outreach_flyer_links` so a concurrent put-up waits for the check. No test drives the concurrency; the fix rests on Postgres lock semantics.
- **Mentions.** `outreach_mentions.post_id ... ON DELETE SET NULL` is fine. A mention can attach to a post only once it has a `remote_id`, that is once it is `posted`, which already refuses. Mentions are account-wide rows and are kept.
- **Guard and CSRF.** The route is one more `adminRoute` entry beside draft-all/schedule-all, so it gets the same session + admin wrapping, and `TestMountAndServe_AdminRoutesRequireSessionAndAdmin` covers it without edits. The `/admin/workshops/{id}/outreach/reset` path (not `/admin/outreach/{workshop}/reset`) is the right call, since `/admin/outreach/{id}` means an outreach id.
- **Links reused.** The outreach row, `outreach_links` and `outreach_flyer_links` are kept. The success test asserts zero new `CreateLink` calls across Start, Draft all and Create links after reset, and unchanged link row counts.
- **`can_reset`** comes from `Store.CanReset`, which is `resetBlock` itself: one predicate, no copy.
- **SPA.** `OutreachResetDialog` copies `OutreachScheduleAllDialog`: `role="dialog"`, `aria-modal`, container focus via `tick()`, Escape via `isModalEscape`, backdrop dismiss blocked while busy. No `window.confirm` (the test spies on it). The button is hidden on `can_reset: false`, and a 409 message shows in the dialog's `role="alert"`.
- **Mutation testing** (private DB `opencircuit_test_0592r`, since dropped). Disabling each condition in turn: posted, live queue row and flyer put-up each fail `TestAdminOutreachReset_RefusesWhenPublic`. **The `status = 'queued'` term survived**, because the queued subtest also has a live queue row. Added the subtest "queued post without a live queue row" (the outbox row set to `abandoned`), and that mutation now fails. `reset.go` was restored by copy, with sha256 `b0eda518…faca4c` before and after.
- **Verification** (load average 3.4–4.4): `ISSUE=0592R scripts/check.sh go ./internal/outreach/... ./internal/handlers/... ./cmd/opencircuit/...` passed after the fix: all three packages ok, no skips, gofmt clean. `ISSUE=0592R scripts/check.sh web` failed in the shared tree on 5 tests in `OutreachFlyerEditor`/`OutreachLocations`, because another agent has uncommitted edits in those files. ## Resolution notes

> 🟢 Resolved 2026-10-18 — Reset outreach removes a workshop's posts and flyers while nothing is public, keeps the short links so redrafting creates none; reviewer closed a new-row race with an outreach-row lock (`e0b2a92`).

## Resolution

- **Route:** `POST /admin/workshops/{id}/outreach/reset` (keyed by workshop id like draft-all/schedule-all; `/admin/outreach/{id}/reset` would have meant an outreach id and collided in meaning). Admin-guarded like the other mutations. `outreach.Store.Reset` runs in one transaction: locks the outreach's posts `FOR UPDATE`, re-checks, deletes the finished `outbound_queue` rows for those posts, then the posts (engagement cascades, mentions go `SET NULL`) and flyers (flyer_locations cascade). 409 with a plain message for: a post `posted` (automatic or marked by hand), a post `queued` or a live (`queued`/`sending`) outbox row, a flyer link with `put_up_at`. Scheduled and failed drafts do not block. Audit action `outreach.reset` targets the outreach row with counts. The view exposes `can_reset` from the same check (`Store.CanReset`).
- **Links decision: kept.** I did NOT delete the `outreach` row (its cascades would remove `outreach_links`). The outreach row, `outreach_links` and `outreach_flyer_links` (with QR codes) stay, so the page returns to "started, nothing drafted" and Draft all reuses the same short links. No new ShortLinks links, so no key collision; Start after Reset returns 200 (already exists). The test asserts zero new `CreateLink` calls and unchanged link row counts.
- **SPA:** `OutreachResetDialog.svelte` (role="dialog", lists Removed/Kept, no window.confirm) and a Reset outreach button in `OutreachWorkshop.svelte`, shown only when `can_reset`. After reset the panel reloads. `OutreachWorkshop.behavior.test.ts` also carries #0584's one-line Open Settings href assertion, per the orchestrator.
- No migration.
