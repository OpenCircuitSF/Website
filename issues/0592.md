## Description

Brennan, 2026-10-18: "Since we have some data already populated I will have
to reset it. Add a reset button for a workshop which only shows if nothing has
been posted yet."

Production workshop 6 (Programming LEDs) holds drafts, links and possibly
flyers made before `#0570`–`#0579` changed the templates. There is no way to
start over except deleting rows by hand.

## Acceptance criteria

- [x] **Server:** `POST /admin/outreach/{workshop}/reset` (admin, CSRF as the
      other outreach mutations). It refuses with 409 and a plain message if
      anything for the workshop has gone public: any post `posted` or
      in flight (`sending`/queued in `outbound_queue`), any manual post marked
      posted, any flyer link marked put up. Otherwise it removes the
      workshop's posts and flyers (and their queue rows) in one transaction
      and records an audit event. Prefer deleting the `outreach` row and
      letting the cascades run, unless that breaks something below.
- [x] **ShortLinks:** the client has no delete, so short links already created
      in ShortLinks keep existing. Decide and state in `## Resolution` whether
      `outreach_links` rows are kept (so a later Start reuses the same keys and
      no orphan links are created — preferred) or removed, and prove a Start
      after Reset does not fail on a key collision.
- [x] **SPA:** a **Reset outreach** button on the workshop outreach page,
      shown only when the view reports nothing public (the server is the
      authority; the button hides from the same rule, exposed by the view as
      e.g. `can_reset`). It opens an in-app `role="dialog"` (not
      `window.confirm`) saying exactly what is removed and what is kept, and
      after reset the page shows the fresh not-started / re-drafted state.
- [x] Tests: Go handler tests for the 409 cases (posted post, queued post,
      manual marked posted, flyer put up) and the success path (rows gone,
      links per the decision, audit row), Start-after-Reset succeeds; jsdom
      tests that the button hides when `can_reset` is false and the dialog
      calls the endpoint.
- [x] Verified with `ISSUE=0592 scripts/check.sh go ./internal/outreach/... ./internal/handlers/... ./cmd/opencircuit/...` and `ISSUE=0592 scripts/check.sh web`. Zero skips. No migration unless strictly required.

## Resolution

- **Route:** `POST /admin/workshops/{id}/outreach/reset` (keyed by workshop id like draft-all/schedule-all; `/admin/outreach/{id}/reset` would have meant an outreach id and collided in meaning). Admin-guarded like the other mutations. `outreach.Store.Reset` runs in one transaction: locks the outreach's posts `FOR UPDATE`, re-checks, deletes the finished `outbound_queue` rows for those posts, then the posts (engagement cascades, mentions go `SET NULL`) and flyers (flyer_locations cascade). 409 with a plain message for: a post `posted` (automatic or marked by hand), a post `queued` or a live (`queued`/`sending`) outbox row, a flyer link with `put_up_at`. Scheduled and failed drafts do not block. Audit action `outreach.reset` targets the outreach row with counts. The view exposes `can_reset` from the same check (`Store.CanReset`).
- **Links decision: kept.** I did NOT delete the `outreach` row (its cascades would remove `outreach_links`). The outreach row, `outreach_links` and `outreach_flyer_links` (with QR codes) stay, so the page returns to "started, nothing drafted" and Draft all reuses the same short links. No new ShortLinks links, so no key collision; Start after Reset returns 200 (already exists). The test asserts zero new `CreateLink` calls and unchanged link row counts.
- **SPA:** `OutreachResetDialog.svelte` (role="dialog", lists Removed/Kept, no window.confirm) and a Reset outreach button in `OutreachWorkshop.svelte`, shown only when `can_reset`. After reset the panel reloads. `OutreachWorkshop.behavior.test.ts` also carries #0584's one-line Open Settings href assertion, per the orchestrator.
- No migration.
