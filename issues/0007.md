## Description

Rewrite `internal/config` for this project's variable set: AWS/SES API configuration replaces the SMTP credentials, sending controls are added, and the cache variables are removed.

## Acceptance criteria

- [ ] Removed: `CACHE_MAX_COST`, `CACHE_TTL_SECONDS`, `SES_SMTP_HOST`, `SES_SMTP_PORT`, `SES_SMTP_USERNAME`, `SES_SMTP_PASSWORD`
- [ ] Added: `AWS_REGION`, `SES_CONFIGURATION_SET`, `EMAIL_REPLY_TO`, `EMAIL_LIST_DOMAIN`, `SES_INBOUND_BUCKET`, `MAX_SEND_RATE`, `SEND_BATCH_SIZE`, `SEND_WORKER_ENABLED`
- [ ] Required set is `BASE_URL`, `DATABASE_URL`, `WEBAUTHN_RP_ID`, `WEBAUTHN_RP_ORIGIN`, `SESSION_SECRET`, `ADMIN_EMAIL`, `AWS_REGION`, `EMAIL_FROM`
- [ ] All validation errors are still collected in one pass and returned together
- [ ] `.env.example` regenerated to match exactly, with the section banners preserved
- [ ] Table in `docs/configuration.md` regenerated from the same source of truth
- [ ] `go test ./internal/config/...` passes, including cases for each newly required variable

## Notes

PRD §9. Keep ShortLinks' all-errors-at-once behaviour — a single startup attempt surfacing every misconfiguration is genuinely valuable on a fresh EC2 box.

No static AWS credentials in config: the EC2 instance role supplies them and the SDK's default credential chain finds them. Locally the chain falls back to `~/.aws/credentials`.

Runtime-editable values (`physical_address`, `max_send_rate`, `signup_enabled`, `registrations_enabled`, `default_from_name`) belong in the `settings` table, not here. `MAX_SEND_RATE` in the environment is the ceiling; the settings value is the operator dial beneath it.
