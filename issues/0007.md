## Description

Rewrite `internal/config` for this project's variable set: AWS/SES API configuration replaces the SMTP credentials, sending controls are added, and the cache variables are removed.

> 🟢 Resolved 2026-08-18 — `internal/config` now carries PRD §9’s variable set exactly, with the required set validated in one pass and a `MissingRequired` subtest per newly required variable; independently re-verified with `TEST_DATABASE_URL` exported — zero failures, zero skips, every DB-backed package reporting real elapsed time.

## Root cause

Feature work, not a bug fix. `internal/config` was still exactly ShortLinks' loader from the Phase 0 port: it required and parsed `SES_SMTP_HOST`/`PORT`/`USERNAME`/`PASSWORD` (SMTP transport credentials this project never has — there are no static AWS credentials anywhere in configuration, only the EC2 instance role) and `CACHE_MAX_COST`/`CACHE_TTL_SECONDS` for `internal/cache`, which `#0002` already deleted. None of this project's AWS/SES/sending variables from PRD §9 existed yet, so nothing downstream (`#0008`–`#0010`, `#0023`, `#0025`–`#0027`, `#0037`, `#0057`) had a config surface to build against.

## Fix

Rewrote `internal/config/config.go`'s `Config` struct and `loadFromFile`:

- Removed `SESSmtpHost`, `SESSmtpPort`, `SESSmtpUsername`, `SESSmtpPassword`, `CacheMaxCost`, `CacheTTLSeconds` and their defaults/env reads.
- Added `AWSRegion`, `SESConfigurationSet`, `EmailReplyTo`, `EmailListDomain`, `SESInboundBucket`, `MaxSendRate` (default 10), `SendBatchSize` (default 50), `SendWorkerEnabled` (default `true`), reading `AWS_REGION`, `SES_CONFIGURATION_SET`, `EMAIL_REPLY_TO`, `EMAIL_LIST_DOMAIN`, `SES_INBOUND_BUCKET`, `MAX_SEND_RATE`, `SEND_BATCH_SIZE`, `SEND_WORKER_ENABLED`.
- Added a `getBool` helper (mirrors `getInt`'s pattern: default on empty, collect an error on the same one-pass error slice on a parse failure) for `SEND_WORKER_ENABLED`.
- Extended the `required` table to `BASE_URL`, `DATABASE_URL`, `WEBAUTHN_RP_ID`, `WEBAUTHN_RP_ORIGIN`, `SESSION_SECRET`, `ADMIN_EMAIL`, `AWS_REGION`, `EMAIL_FROM` — the all-errors-in-one-pass behavior from ShortLinks (`errs []string` accumulator, single `strings.Join` at the end) is unchanged.
- Regenerated `.env.example` to the new variable set, preserving the `# ── Section ──` banner style, and rewrote `docs/configuration.md`'s variable table from the same source of truth, including a "Removed from the ShortLinks skeleton" section documenting why `SES_SMTP_*`/`CACHE_*` are gone.
- Updated `internal/config/config_test.go`: `setRequired` now sets the new eight-variable required set (was six — `AWS_REGION` and `EMAIL_FROM` are new), and `TestLoad_MissingRequired`'s table gained two subtests, `missing_AWS_REGION` and `missing_EMAIL_FROM`, so every newly required variable has its own failing-without-it case per the acceptance criteria and per `#0065`'s precedent (that issue fixed this exact helper falling out of sync with the required set once already). Also updated `TestLoad_AllRequiredPresent`/`TestLoad_DefaultsApplied`/`TestLoad_InvalidInteger` for the new/removed fields, added `TestLoad_InvalidBoolean` for the new `getBool` path, and added `TestLoad_RemovedVariablesIgnored` as a regression guard that a stale `SES_SMTP_*`/`CACHE_*` value left in a systemd `EnvironmentFile` has no effect.

Divergence from a literal reading of the issue: removing the four `SESSmtp*` fields broke compilation of `internal/auth/ses_mailer.go` (`SESMailer` read `host`/`port`/`username`/`password` straight off `config.Config`) and its two test call sites. Per the issue's explicit scope guidance, made the smallest change that keeps it building rather than migrating to the SES v2 API (`#0027`'s job) — see Gotchas.

## Gotchas

- **Removing `SES_SMTP_*` from config broke `internal/auth/ses_mailer.go`'s compilation**, exactly as flagged in this issue's brief. `SESMailer` previously read `host`/`port`/`username`/`password` straight off `cfg.SESSmtpHost` etc. Rather than rewrite the mailer to the SES v2 API (explicitly out of scope — that's `#0027`), `NewSESMailer` now derives a plausible SES SMTP host from `cfg.AWSRegion` (`email-smtp.<region>.amazonaws.com`) and leaves `username`/`password` permanently empty, since there is no SES-SMTP-credential concept left in configuration and no static AWS credentials anywhere (the instance role covers API calls, not SMTP AUTH, which needs its own derived secret). This mailer therefore cannot actually authenticate against SES right now; it compiles and its existing unit tests (which inject a fake transport or hit a local fake SMTP server, not real SES) still pass, but it is not wired into `main.go` any more for that reason — see below. `#0027` should replace this whole file's transport, not just its config plumbing.
- **`cmd/opencircuit/main.go`'s `servePostgres` no longer conditionally constructs `SESMailer`.** The old logic picked `SESMailer` over `NoOpMailer` when SMTP username/password were present; that signal no longer exists. Since `SESMailer` can't authenticate until `#0027`, always using `NoOpMailer` (stdout) is the honest behavior for now — the alternative (constructing `SESMailer` anyway) would silently attempt SMTP AUTH with empty credentials and fail every send. This is a behavior change in production-path code, not just test/config plumbing, and is worth the reviewer's attention even though it's a net-neutral one (mail sending doesn't actually work today either way — `#0027` is what makes it work).
- **`internal/handlers/logging_test.go`'s `TestAuthHandler_MailerErrorDoesNotLeakEmail`** depends on forcing a real, synchronous dial failure (previously via `SESSmtpHost: "127.0.0.1", SESSmtpPort: 1` in a `config.Config` literal) to prove the actual production error path doesn't leak the recipient's email (`#0097`'s regression guard). With those fields gone there was no way from outside `internal/auth` to point the mailer at a bad host, so added one exported test seam, `auth.NewSESMailerWithAddr(host, port, cfg)`, used only by this cross-package test and by `internal/auth`'s own `TestNewSESMailerWithAddr`. This is the one addition to the public `auth` API surface in this change; flagging it explicitly since the issue's scope is `internal/config` and `.env.example`.

### Hazards recorded at review (#0007 phase 3)

- **`NewSESMailerWithAddr` is a trap for `#0027`.** The seam is SMTP-shaped
  (`host string, port int`) and is meaningless once the transport becomes the
  SES v2 API. `#0027` must **delete** it along with the SMTP transport and
  rework `internal/handlers/logging_test.go`'s
  `TestAuthHandler_MailerErrorDoesNotLeakEmail` to force its deterministic
  failure some other way — porting the seam forward would leave an exported
  function on `internal/auth` that no longer means anything. The reviewer
  accepted it here because the cross-package test genuinely needs to exercise
  the *real* mailer's error string; an unexported seam or an `export_test.go`
  cannot reach `internal/handlers`, and a fake `auth.Mailer` would have made
  the PII-leak guard synthetic and therefore worthless.
- **Magic links now reach a human only through the server log.** `NoOpMailer`
  is not silent — it `log.Printf`s the full verification/recovery URL — but
  nothing is delivered to an inbox on any path until `#0027`. Dev mode
  (`STORAGE=json`) does not use the mailer at all: `serveDevMode` wires
  `devstore.DevRegistrar`/`DevRecoverer` and `middleware.DevAutoLogin`, so it
  bypasses the ceremony rather than surfacing a link. `#0008`'s browser
  registration and recovery runs must therefore go against the Postgres path
  and copy the link out of stdout/`journalctl`.
- **The `SESMailer` behavior change is net-neutral, not a regression.** The
  conditional it replaced (`cfg.SESSmtpUsername != "" && cfg.SESSmtpPassword
  != ""`) could never have fired: `876a8e6^:.env.example` shipped
  `SES_SMTP_USERNAME=`/`SES_SMTP_PASSWORD=` empty, and PRD §9 has no
  SES-SMTP-credential variables at all, so `NoOpMailer` was already the
  selected mailer for every realistic deployment of this repo.
- **Dangling ShortLinks tracker references live in code comments.** `#0097`
  (`internal/auth/ses_mailer.go:145`, `internal/handlers/auth.go:70`,
  `internal/handlers/logging_test.go` ×5) and `#0094`
  (`internal/auth/mailer.go:30,35`) point at issues that do not exist in this
  tracker — the highest here is `#0065`. `git blame` puts all of them in
  `34b80f3` (`#0001`, the skeleton copy), so this is Phase 0 residue, not
  `#0007`'s doing, and it was left in place rather than bounced. It needs its
  own issue alongside the other ShortLinks residue (`go.sstools.co` in
  `web/src/lib/webauthn.test.ts`, `internal/auth/registration_test.go`,
  `deploy/apache/go.sstools.co.conf`, `deploy/systemd/shortlinks.service`).
- **`.env.example`'s `SESSION_SECRET` placeholder is fail-open.**
  `replace_with_random_64_char_hex_string` is non-empty, so it satisfies the
  required-variable check and a copied template boots with a publicly known
  session HMAC key. PRD §9 specifies a *blank* value precisely so startup
  fails closed. Inherited verbatim from the ShortLinks template rather than
  introduced here, so it was not treated as a `#0007` defect — but it should
  be corrected.

## Notes

PRD §9. Keep ShortLinks' all-errors-at-once behaviour — a single startup attempt surfacing every misconfiguration is genuinely valuable on a fresh EC2 box.

No static AWS credentials in config: the EC2 instance role supplies them and the SDK's default credential chain finds them. Locally the chain falls back to `~/.aws/credentials`.

Runtime-editable values (`physical_address`, `max_send_rate`, `signup_enabled`, `registrations_enabled`, `default_from_name`) belong in the `settings` table, not here. `MAX_SEND_RATE` in the environment is the ceiling; the settings value is the operator dial beneath it.
