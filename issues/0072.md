# 0072 — .env.example sets BASE_URL to the apex, so the documented deploy publishes non-canonical URLs

## Description

`.env.example` line 3 sets `BASE_URL=https://opencircuitsf.com` — the **apex**. Since `#0019`, that value is the source of every `og:url`, every `og:image`, every sitemap `<loc>`, and the `Sitemap:` line in `robots.txt`.

Production canonicalizes to **www**: the apex 301s to `https://www.opencircuitsf.com` (`CLAUDE.md` §7, verified against the live host). `deploy/systemd/README.md` states that `/etc/opencircuit/config.env` "supplies every variable from `.env.example`", so following the documented deploy path publishes canonical URLs that contradict the site's own redirect.

Found during `#0019`/`#0020`'s review. `internal/seo` is correct — it faithfully uses whatever `BASE_URL` provides. This is a one-line config defect with disproportionate consequences.

## Why it matters

Social crawlers and search engines are the entire audience for `#0019`'s work. Publishing apex `og:url` values against a 301 means every shared link and every indexed page advertises a URL that immediately redirects — diluting the canonical signal at exactly the moment the site starts receiving traffic. It is cheap to fix now and expensive to unwind once links are in the wild.

The same file already gets `WEBAUTHN_RP_ORIGIN=https://www.opencircuitsf.com` right, so this is an internal inconsistency rather than a considered choice.

## Notes

Do **not** hardcode www in `internal/seo` — the package is right to trust `BASE_URL`. The defect is the template.

`#0064`'s runbook should call this value out explicitly when it documents `/etc/opencircuit/config.env`.
