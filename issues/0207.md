# 0207 — `db-reset.sh` kills every other connection and rebuilds the shared database, unconditionally

## Description

`#0150` fixed `scripts/testdb.sh gc`, which swept every agent's test database
because sweeping was the default. Its criterion 5 asked whether any other script
has the same shape — an unqualified destructive default that assumes the caller
is alone. **`scripts/db-reset.sh` does.**

A bare invocation targets the shared `opencircuit` (or `opencircuit_test`)
database, runs `pg_terminate_backend` against **every other connection to it**,
then drops and recreates it. No live-connection skip, no confirmation prompt.

It is the same class of bug as `#0150`, moved from the per-agent pool onto the
single shared name — and the blast radius is larger, because that database is
the user's dev database as well as the fallback any agent uses when it cannot
get its own (`CLAUDE.md` §5a). One agent's reflexive reset destroys another
agent's in-flight work *and* whatever the user had loaded.

**What it already gets right, and should keep:** it refuses non-localhost hosts
and refuses database names outside `opencircuit*`. Production is protected. The
gap is peer agents and the user, not production.

**But that name guard is wider than it looks.** `#0150`'s review read the script
and found the `opencircuit*` glob admits **`opencircuit_test_0055`** — so
`scripts/db-reset.sh opencircuit_test_0055` destroys another agent's per-agent
scratch database. That is precisely the `#0150` failure, reached through a
different script, and it is not hypothetical: per-agent databases are exactly
what `CLAUDE.md` §5a tells every agent to create. `$DB` is also interpolated
into the SQL unquoted.

**Nothing runs `#0150`'s guard test automatically.** `scripts/testdb_gc_guard_test.sh`
is not wired into `scripts/check.sh`, so it protects the `gc` refusal only when
someone remembers to run it. Whatever guard this issue adds needs a way to
actually run, or it has the same problem the day after it lands.

**Two smaller findings from the same sweep**, recorded here rather than
separately:

- `scripts/sim.sh` defaults `OUTPUT_PATH` to the fixed shared `/tmp/opencircuit-sim.png`, so two agents running with default arguments silently overwrite each other's screenshot. Low blast radius, same hazard class as the port-8099 incident in `docs/obstacles.md` §4.
- `scripts/deploy.sh` was checked and is **fine** — single production target, an interactive `[y/N]` gate before the one destructive step, `mktemp` rather than a fixed path. Assuming solitude is correct for a production deploy. Recorded so nobody re-audits it.

`scripts/dev.sh` has the same shape and is already filed as `#0117`.

Two nits in `#0150`'s guard test, worth fixing while modelling on it: Part 2
writes its capture to a PID-suffixed `/tmp` path instead of the `$WORKDIR` it
already owns, and `createdb_raw` discards `CREATE DATABASE` errors — so a role
missing `CREATEDB` surfaces as a loud but **misdiagnosed** "REGRESSION #0150".

## Acceptance criteria

- [ ] A bare `db-reset.sh` does not terminate connections it does not own — it refuses, reports what holds the database, and points at the safe alternative, the way `testdb.sh gc` now does
- [ ] Some explicit opt-in (a flag, matching `gc --all`) is required to force a reset that kicks other connections
- [ ] The existing non-localhost and non-`opencircuit*` refusals still hold — demonstrated, not assumed
- [ ] A guard test covers the refusal and the forced path, modelled on `scripts/testdb_gc_guard_test.sh`, including a mutation proving the refusal assertion is not vacuous
- [ ] The guard test operates only on databases it creates, under a prefix no real issue id can produce (`CLAUDE.md` §8b)
- [ ] `sim.sh`'s default output path is namespaced per invocation, or the collision is recorded as accepted
- [ ] A per-agent database name (`opencircuit_test_NNNN`) is refused by `db-reset.sh`, or requires the same explicit opt-in — demonstrated by attempting one
- [ ] `$DB` is not interpolated into SQL unquoted
- [ ] Both this guard test and `#0150`'s `scripts/testdb_gc_guard_test.sh` are reachable from a command someone actually runs, or the gap is recorded as accepted
- [ ] `CLAUDE.md` §5a's description of `db-reset.sh` matches the new behaviour

## Notes

Reported by `#0150`'s implementation pass under `CLAUDE.md` §9.

`scripts/testdb_gc_guard_test.sh` (added by `#0150`, commit `3615dd7`) is the
model for criterion 4 — including the part that matters: it neuters the refusal
on a **private copy** and confirms bare `gc` then sweeps, proving the assertion
detects the regression rather than passing vacuously.

This is now the fourth shared-resource assumption to fail under concurrency in
this project, after the shared git index, the tracked `web/dist/index.html`, and
`testdb.sh gc` itself. `docs/obstacles.md` §4 carries the pattern. Each one was
a tool written for one agent working alone, used by three.
