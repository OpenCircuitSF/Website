## Description

This is part of the request in `#0652`: Home Assistant checks once a day whether there's been any engagement on Bluesky or Mastodon.

The data already exists:
- `outreach_engagement` (migration 35) stores snapshots of likes, reposts, replies and quotes per post. Captures run hourly for a post's first week and daily up to 30 days (`internal/outreach/engagement.go`).
- `outreach_mentions` stores fetched mentions per channel.

The endpoint summarises the change over a window. It is shaped so a Home Assistant REST sensor can read it with a simple template.

Decisions:
- **Auth.** A bearer token with the `engagement:read` scope, from `#0652`.
- **Window.** Defaults to the last 24 hours. `?hours=N` accepts 1 to 168, or `?since=<RFC 3339>`. The response echoes the window it used.
- **"New" interactions** are the increase in each counter between the last snapshot before the window and the latest snapshot in it. They are never negative: a fall, such as an unlike, counts as 0. A post first captured inside the window counts its whole total.
- **Mentions** are the rows in `outreach_mentions` created or fetched within the window.
- **Response.** A flat top level so Home Assistant templates stay short, plus detail:

      {
        "since": "...", "until": "...",
        "has_engagement": true,
        "total": 7,
        "bluesky": {"likes": 3, "reposts": 1, "replies": 0, "quotes": 0, "mentions": 1, "total": 5},
        "mastodon": {"likes": 2, "reposts": 0, "replies": 0, "quotes": 0, "mentions": 0, "total": 2},
        "posts": [{"event": "Hack Night", "event_date": "2026-11-09", "wave": "reminder", "channel": "bluesky", "url": "...", "likes": 2, "...": 0}],
        "summary": "7 new interactions: Bluesky 5 (3 likes, 1 repost, 1 mention), Mastodon 2 (2 likes)."
      }

  `summary` is a plain sentence that Home Assistant can pass straight into a notification. When nothing happened, it reads `No new engagement on Bluesky or Mastodon in the last 24 hours.`
- **Read-only.** The endpoint doesn't trigger a capture; it reports what the existing pollers stored. Each response says when the latest snapshot was taken (`data_as_of`), so a stalled poller can be spotted.
- **Visible text.** The copy guard's banned words ("wave", "held") apply only to visible SPA text, and `wave` here is a JSON key. The planner confirms that.

## Acceptance criteria

- [ ] With a valid `engagement:read` token, the endpoint returns the shape above for the default 24 hours, for `?hours=`, and for `?since=`. Out-of-range or malformed values return `400`.
- [ ] Interaction deltas are correct across snapshots. An unlike never produces a negative count, and a first capture inside the window counts in full. Table tests cover each case.
- [ ] Mentions inside the window are counted per channel.
- [ ] `summary` and `has_engagement` are right for both the empty case and a mixed case.
- [ ] `data_as_of` reports the newest snapshot time.
- [ ] Without a token the endpoint returns `401`, and with the wrong scope `403`, as set up in `#0652`.
