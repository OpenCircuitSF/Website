## Description

`CLAUDE.md` §8a teaches `git commit -- <your-paths>` as the safe form: a
pathspec on the commit, not just on the `add`, so a concurrent agent's staged
work cannot be swept in. That advice is correct about *what it protects
against* and silently wrong about *what gets committed*.

With a pathspec, `git commit` **bypasses the index entirely** and commits the
named paths' **working-tree** content. It is the documented behavior —
"commit the contents of the files given on the command line, bypassing the
index" — but it is the opposite of what an agent that carefully staged a
subset expects.

`#0328`'s implementer hit this. It staged one issue's hunks with
`git apply --cached`, ran `git commit -F - -- <pathspec>`, and got a commit
containing **both** issues' full working-tree changes — `34147d4`, titled for
`#0327` alone but carrying `#0328` as well. The two commits that were meant to
be separate are now one, and the message describes half of it.

This is a sibling of the `#0268` hazard already in §8a (`-m` after `--` is
swallowed as a pathspec). Same construct, same section, opposite failure:
`#0268` is a commit that does not happen, this is a commit that happens and
contains more than intended.

### Why it matters here

The §8a guidance exists because several agents commit concurrently. An agent
following it exactly will:

- stage narrowly, believing the index is the thing being committed;
- pass a pathspec, believing it is a second safety net;
- and commit whatever is in the working tree at those paths — including
  changes it deliberately left unstaged.

The protection against sweeping *another agent's* work still holds, since a
pathspec still bounds which files are touched. What breaks is an agent's
ability to stage a subset of *its own* changes.

## Acceptance criteria

1. `CLAUDE.md` §8a gains an entry stating that `git commit -- <paths>` commits
   working-tree content at those paths and bypasses the index, so
   `git add`/`git apply --cached` staging is discarded.
2. It states the correct form for committing a staged subset: commit **without**
   a pathspec after verifying `git diff --cached --name-only`, or stash-free
   alternatives that do not violate §8a's prohibition on `git stash`.
3. It is placed adjacent to the existing `#0268` entry and cross-references it,
   since both are failure modes of the same `--` construct.
4. The entry names `34147d4` as the real instance, and notes that the commit
   was left in place rather than rebased under a concurrent agent's already
   landed commit.
5. No existing §8a guidance is weakened — the "pathspec on the commit" advice
   stays, since it still bounds the file set; only the index expectation is
   corrected.

## Fix

Checked §8a before writing anything (as instructed): the section already
carried an entry beginning "`git commit -- <paths>` commits the WORKING TREE
state of those paths, not the index," with the `#0305` example and the
"index tells you which form to use" table. That entry already satisfied
criteria 1, 2, and 5. It did **not** satisfy criterion 3 (no cross-reference
to `#0268`, even though it is already placed directly adjacent to it) or
criterion 4 (no mention of `34147d4`/`#0328`, since the entry's own example
is `#0305`, a different instance of the same construct). Rather than
duplicate the existing explanation, added only what was missing:

- A sentence appended to the entry's opening bold paragraph naming it as the
  sibling of the `#0268` entry immediately above, same `--` construct,
  opposite failure.
- A new paragraph after the `#0305` example naming `34147d4` as the second,
  independent instance — `#0328`'s implementer isolated one issue's hunks
  with `git apply --cached`, then `git commit -F - -- <pathspec>` swept in
  `#0328`'s working-tree changes alongside `#0327`'s, with no other agent
  involved. This complements `#0305`'s example (another agent's unstaged
  work swept in) by showing the same construct fails even when only the
  implementer's own work is at risk.

No existing text was altered or weakened; the "pathspec on the commit"
advice and the correct-form table are unchanged.
