## Description

In the live-region guard's `collectSites`, the `EachBlock` arm walks only `body`
with the each's own governing branch. Its `fallback` — the `{:else}` empty-state
branch — falls through to the generic loop, carrying the **outer** branch
instead.

Two consequences:

- A `role="status"` in an each's empty-state branch is attributed to the wrong
  governing branch, so the focus-target and placeholder checks are evaluated
  against the wrong subtree.
- At top level it would look **fully unconditional** and therefore never be
  checked at all — the site would silently join the four unconditional sites the
  guard exempts by design.

**This is latent, not live.** `#0299`'s reviewer scanned the whole tree and found
**zero** live regions currently sitting in an each-else. Filed so it is closed
before one appears, since the failure is silent.

An empty-state branch is a natural home for a status message ("No subscribers
match this filter"), so this is a shape the codebase is likely to grow.

## Root cause

`collectSites`' `EachBlock` arm walked `body` explicitly with its own
governing branch, then fell through (no `return`) to the generic
key-by-key walk for everything else on the node — including `fallback`
(the `{:else}` empty-list fragment), which was therefore walked with
whatever `governingBranch` was passed INTO the `EachBlock` itself (the
outer branch, or `undefined` at top level), not its own.

## Fix

- `collectSites`' `EachBlock` arm now walks `fallback` with itself as its
  own governing branch, the same as `body` — same fall-through pattern
  preserved for the block's other fields (`expression`/`context`/`key`),
  since those never carry template elements.
- Criterion 2 sibling sweep: `{#if}`'s `alternate` was already correct
  (handled with its own branch, explicit `return`). `AwaitBlock`'s
  `pending`/`then`/`catch` and `KeyBlock`'s `fragment` had **no** branch
  handling at all — same silent defect (a site inside one falls through to
  the outer/undefined branch), just via omission rather than an explicit
  fall-through. Fixed both the same way collectSites already fixes
  `EachBlock`/`IfBlock`. Checked against the real tree via a scratch AST
  scan rather than assumed: zero `{#each...}{:else}` sites carry a
  `role`/`aria-live` attribute anywhere in `web/src`; `{#await}` does not
  appear anywhere in the tree; the two real `{#key activeId}` blocks
  (`Workshops.svelte`, `Campaigns.svelte`) each wrap only a child
  component, not a live-region element directly. All three fixes are
  therefore latent-closing, not live-changing.
- Re-derived the real-tree counts after the fix (criterion 5):
  `filesScanned=38 alertSites=61 statusSites=32 loadingPlaceholders=20` —
  identical to the pre-fix figures, confirming no real site was
  mis-attributed.
