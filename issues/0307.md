# 0307 — An `{#each}` `{:else}` branch is attributed to the wrong governing branch

| | |
|---|---|
| **Status** | open |
| **Platform** | Web |
| **Module** | web / accessibility |
| **Phase** | 8 — Polish and follow-ups |
| **First seen** | 2026-08-27 |

## Description

In the live-region guard's `collectSites`, the `EachBlock` arm walks only `body`
with the each's own governing branch. Its `fallback` — the `{:else}` empty-state
branch — falls through to the generic loop, carrying the **outer** branch
instead.

Two consequences:

- A `role="status"` in an each's empty-state branch is attributed to the wrong
  governing branch, so the focus-target and placeholder checks are evaluated
  against the wrong subtree.
- At top level it would look **fully unconditional** and therefore never be
  checked at all — the site would silently join the four unconditional sites the
  guard exempts by design.

**This is latent, not live.** `#0299`'s reviewer scanned the whole tree and found
**zero** live regions currently sitting in an each-else. Filed so it is closed
before one appears, since the failure is silent.

An empty-state branch is a natural home for a status message ("No subscribers
match this filter"), so this is a shape the codebase is likely to grow.

## Acceptance criteria

1. `collectSites`'s `EachBlock` arm walks `fallback` with the each's own
   governing branch, the same as `body`.
2. Check the sibling block types for the same shape while there — `{#if}`'s
   `else`, `{#await}`'s `then`/`catch`, and any `{#key}` handling. Report what
   you found even if nothing. The defect is a fall-through, so it is likely to
   have siblings.
3. Prove it with a fixture: a `role="status"` inside an `{#each}`'s `{:else}`
   must be attributed to the each's branch, and a violating one must fail. Per
   CLAUDE.md §8 the oracle must not be the same bytes as the subject.
4. Add a fixture for the top-level case specifically — the one where the site
   currently looks unconditional — since that is the silent failure rather than
   the merely-wrong one.
5. Re-derive the site counts afterwards. If the fix changes any count, that
   means a real site was mis-attributed and the tree needs looking at, not just
   the number updating.
6. `ISSUE=NNNN scripts/check.sh web` passes.
