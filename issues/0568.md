## Description

Brennan, 2026-10-17, after deploying `#0566` and connecting Bluesky,
Mastodon and ShortLinks:

> Now tell me how I am supposed to get it to post on Bluesky and Mastodon?
> How do I get it to create the campaign with ShortLinks and every variant of
> the link to the URL for the workshop? I am not seeing it. This is pretty
> terrible UX.

What production showed at the time: outreach had been started for workshop
6 ("Programming LEDs", 2026-10-20). The ShortLinks campaign
`programming-leds-2` existed, with zero posts and zero links. Two causes:

1. **Discoverability.** The channel × wave grid (`OutreachPanel.svelte`) is
   only the last panel of `WorkshopEditor.svelte`, below the whole workshop
   form. The top-level Outreach page (`Outreach.svelte`) lists workshops but
   links each one to the workshop editor, not to its outreach.
2. **Links are lazy.** A post's tracked short link is created only when that
   one cell is opened and **Prepare link** (or Post now) is pressed. Start
   outreach creates an empty campaign, so the admin never sees "the campaign
   with every variant of the link".

## Acceptance criteria

- [ ] **A workshop outreach page.** A route such as
      `#/admin/outreach/workshop/<id>` shows, top to bottom:
      - workshop title, date and status, with a link back to its editor
      - the start button or campaign status
      - the links table
      - the channel × wave grid with the composer
      - a results summary

      The Outreach list's rows link here. The workshop editor's Outreach
      panel becomes a short summary with a prominent "Open outreach" link,
      or is moved above the form; the plan chooses. The Outreach sub-nav
      gains no dead ends.
- [ ] **Every link created at start.** Start outreach (and a "Create missing
      links" action for outreach already started, such as workshop 6's)
      creates, in the workshop's ShortLinks campaign, one tracked link per
      channel × wave and one per flyer location. Each carries its UTM tags
      (`#0543`'s scheme) and points at the workshop's public URL. Creation is
      idempotent, so a re-run creates only what is missing. A partial
      ShortLinks failure reports which links failed and leaves the rest.
- [ ] **Links table.** Shows each link's channel or location, wave, short
      URL, destination with UTM tags, click count and a Copy button.
- [ ] **Draft all.** One action drafts every empty cell from its template
      (Regenerate's text), with the link already in place. Existing edited
      drafts are never overwritten.
- [ ] **Schedule all.** One action schedules every drafted Bluesky and
      Mastodon post that is unscheduled and unposted, at its wave's
      suggested time. Times that have already passed are listed and skipped,
      not posted. A confirm dialog lists what will be scheduled. Manual
      channels (Instagram, TikTok, YouTube) are unaffected.
- [ ] **Empty states guide the next step:**
      - "Not connected" points to Settings.
      - "Workshop not published" points to the editor.
      - "No links yet" points to Create links.
- [ ] Go tests with fake ShortLinks (idempotency, partial failure, UTM
      correctness) and jsdom tests for the page, the table, draft-all and
      schedule-all. Never contact live services. Verified with
      `ISSUE=0568 scripts/check.sh` plus the AGENTS.md §5 guard packages
      reached. Zero skips.

### Decisions (so the implementer does not have to make them)

1. **Route.** Follow the Outreach tab's existing query convention rather than
   a new path segment: the page is `#/outreach?view=workshop&workshop=<id>`
   (`<id>` is the **workshop** id, as in `adminOutreachResultsHash`). Add
   `'workshop'` to `OutreachView` and a helper
   `adminOutreachWorkshopHash(workshopId)` in `web/src/lib/adminRouter.ts`.
   `view=workshop` with no valid `workshop` param falls back to the list.
2. **Page composition.** A new `web/src/views/admin/OutreachWorkshop.svelte`
   renders, top to bottom: header, then `OutreachPanel` (which already owns
   the unavailable messages, Start, the campaign line, the grid, the composer,
   polling and the results status), with the links table and the bulk actions
   injected **between the campaign line and the grid** through a new optional
   `beforeGrid` snippet prop. `OutreachPanel` stays self-loading so its 18
   existing behaviour tests keep passing; it gains three optional props only:
   `beforeGrid?: Snippet`, `reloadKey?: number` (read in the load effect next
   to `workshopUpdatedAt`) and `onLoaded?: (v: WorkshopOutreach) => void`
   (called after every successful `load`, `refreshQuietly`, `start` and
   `onChange`). `workshopUpdatedAt` becomes optional (default `''`).
3. **Workshop editor.** The editor's `<Panel title="Outreach">` stops
   embedding `OutreachPanel`. It becomes a short summary, **moved to directly
   under the editor heading row** (before `<form>`), rendered by a new
   `OutreachEditorSummary.svelte`: one line of state plus a prominent
   `Open outreach` link (a primary-styled `<a>` to
   `adminOutreachWorkshopHash(workshopId)`). Nothing else from the grid stays
   in the editor.
4. **Where post links live: a new table, `outreach_links` (migration
   `000039`).** The existing per-post fields cannot hold a link before a post
   exists (`body` is `NOT NULL`, and a post row is what the grid reads as
   "drafted"; creating empty posts would conflate Create links with Draft all
   and change every count). `outreach_posts.short_link_key/short_url` stay as
   they are: a post still carries its own copy, written by `SetPrepared`, so
   the publisher, `BuildResults` and everything else is untouched. Flyer
   links **reuse `outreach_flyer_links`** unchanged (it is already one row per
   (outreach, location)).
5. **Which flyer locations.** Every **active** row of `outreach_locations` —
   flyers are designed later, so "one per flyer location" cannot mean the
   locations a flyer has selected (at Start there are no flyers). Consequence,
   accepted: creating the link locks that location's code
   (`InsertFlyerLink` → `MarkLocationUsed`), exactly as Generate does today.
   Inactive locations get no new link; one that already has a link for this
   outreach still shows in the table.
6. **Idempotency key.** Locally: the slot — `(outreach_id, channel, wave)`
   for posts (`outreach_links_slot_unique`) and `(outreach_id, location_id)`
   for flyers (`outreach_flyer_links_slot_unique`). A slot with a row is
   skipped with **no ShortLinks call**. Upstream: `POST /api/links` with no
   custom `key` de-duplicates per (user, destination) (ShortLinks
   `internal/links/store.go` `CreateOrReactivateLink`), and every
   destination is unique per slot because `utm_source`+`utm_content` differ,
   so a crash between the ShortLinks call and the insert is healed by the
   next run returning the same key. ShortLinks has no lookup by destination
   and no idempotency header; none is needed. **Do not set `Key`** — a custom
   key turns de-duplication off.
7. **Adopting existing post links.** When an `outreach_links` row is missing
   but the slot's post already has `short_link_key` (posts prepared before
   this issue), insert the row from the post's key/URL — no ShortLinks call.
8. **One link-creation helper, three callers.** Start (after the campaign and
   the outreach row exist), the new Create links endpoint, and Prepare all go
   through the same code, so a link made by any path is the same row.
   `Prepare` uses the slot's `outreach_links` row when present (no ShortLinks
   call), otherwise creates the link, inserts the row, then `SetPrepared`.
   `CreatePost` (opening one empty cell) also applies the slot's row when one
   exists, so a newly opened cell already has its link.
9. **Partial failure.** Link creation never aborts on one failure: each failed
   link is reported by label and reason, and every success is already saved.
   It **stops early** only on `ErrRateLimited` or the context deadline; the
   links not attempted are reported with that same reason and
   `stopped: true`. Reasons are fixed strings, never upstream text (the error
   is logged, as `writeShortLinksError` does). Start returns `201` with the
   panel view plus `link_report` even when some links failed — outreach has
   started; the links table and its Create missing links button finish the
   job.
10. **Draft all makes no ShortLinks call.** It drafts every channel × wave slot
    that has **no post**, from `outreach.Draft` (the same text Regenerate
    produces), and applies the slot's `outreach_links` row through
    `SetPrepared` when present. An existing post is never touched, whatever
    its status or edits. Slots with no link row are still drafted (with the
    `{link}` token) and counted in `without_link`, so the UI can say "create
    the missing links first".
11. **Schedule all is two calls: preview then confirm.** `dry_run: true`
    returns what would be scheduled and what is skipped; the confirm dialog
    lists both; confirming sends `dry_run: false` with the previewed
    `post_ids`, and the server re-computes and schedules only ids that are
    still in its own `to_schedule` set (others come back skipped as
    `changed`). Eligible = automatic channel (Bluesky, Mastodon), status
    exactly `draft` (not `failed` — Retry is deliberate). Manual channels
    never appear in either list. Announce has no suggested time and is
    reported skipped (`no_suggested_time`), never invented.
12. **Click counts** come from the existing memoized
    `h.statsCache().Get(slug, from, to)` rollup's `ByLink`, over
    `outreach.ResultsWindow` — no new ShortLinks client method.

	PostID      *int64 // nil for a slot with no post
	Channel     string
	Wave        string
	Reason      string // see below
	SuggestedAt *time.Time
}
// PlanScheduleAll decides, for every automatic channel × wave, whether its
// post would be scheduled at the wave's suggested time. Manual channels are
// never listed. Posts whose status is not "draft" (scheduled, queued,
// posted, failed) are not listed either: they are not "unscheduled and

Order: `Channels()` order, then `Waves()` order. For each automatic channel ×
wave, the first matching rule wins:

| Condition | Result |
|---|---|
| no post in the slot | skip `not_drafted` |
| post status ≠ `draft` | not listed |
| `!configured(channel)` | skip `not_connected` |
| `!post.Prepared()` | skip `no_link` |
| `SuggestedAt` nil | skip `no_suggested_time` |
| at `< now+minLead` | skip `time_passed` (with `SuggestedAt`) |
| at `> now+maxLead` | skip `too_far` |
| `ValidateForSend(ch, body) != nil` | skip `invalid` |
| otherwise | schedule at `SuggestedAt` (UTC) |

  workshops.Workshop) (outreachLinkReport, error)` — the shared helper. The
  `error` return is for store failures only (→ 500). Body:
  1. `ctx, cancel := context.WithTimeout(r.Context(), outreachLinksTimeout)`.
  2. Load `ListPostLinks`, `ListPosts`, `flyers.ListFlyerLinks`,
     `locations.ListLocations` (filter `Active`).
  3. `base, err := h.shortLinksBase(ctx)`; on error every missing link is a
     failure with `linkFailureReason(err)` and `Stopped = true`; return.
  4. Post slots, `Channels()` × `Waves()` order: row exists → `Existing++`;
     post has a key → `InsertPostLink` from it, `Existing++`; else
     `CreateLink(postLinkRequest(...))` → `InsertPostLink(o.ID, ch, wv,
     link.Key, base+"/"+link.Key)`; `created` → `Created++` and audit
     `ActionOutreachLinkCreated` (target `TargetOutreachLink`, row id,
     metadata `outreach_id`, `channel`, `wave`, `short_link_key`).
  5. Active locations without a flyer link, ordered by `lower(name)` then id:
     `h.generateLink(ctx, o, wk, outreach.FlyerSelection{LocationID: l.ID,
     Name: l.Name, Code: l.Code}, base)`; created → `Created++` and
     `auditFlyerLink(r, actorID, audit.ActionOutreachFlyerLinkCreated, …,
     {"code", "short_link_key"})`. QR caching stays with flyer Generate.
  6. On `ErrRateLimited` or `ctx.Err() != nil`: stop; every remaining missing
     link is a failure with that reason; `Stopped = true`.
  7. Any other ShortLinks error: record the failure and continue.
