## Description

`#0402`'s criterion 6 asks that all the auto-login states be exercised through
the real `mountAndServe` route table. `TestNewDevAdminAutoLogin_RealRouteTable`
covers three — no credential, flag off, and the one-row session cache. The two
that matter most for `#0409`'s defect, **a stale cookie and a garbage cookie**,
are pinned a layer down against a fake resolver rather than through the real
table.

Both were exercised live, twice, by `#0402`'s review and again by `#0409`'s
verification pass. **A live run is not a regression pin.** Nothing in the suite
fails if the real route table stops healing them.

## The reason given for stopping does not hold

`#0409`'s implementation pass declined to extend the test and gave three costs.
Its reviewer checked them, and two do not survive:

1. **"Needs a real `sessions` row insert and delete."** It does not. A token
   that never existed and a token whose row was deleted are **the same
   server-side state** — `ResolveSession` fails identically. The insert/delete
   round trip buys nothing.
2. **"It is an ~8×-cost package."** That figure is the cost of *running*
   `cmd/opencircuit`, which the standard verification scope pays anyway
   (`CLAUDE.md` §5a). Adding two cases to a test already in that package costs
   approximately nothing extra.
3. The third — needing a cookie-jar-free client — is already satisfied:
   `TestNewDevAdminAutoLogin_RealRouteTable` **already holds** `pool`, the
   server URL, and a jar-less client.

So the remaining work is two `http.NewRequest` plus `client.Do` calls with
explicit `Cookie` headers, and their assertions. The reviewer put the real
remainder at **~20 lines**.

**Declining was still right on scope** — it was outside `#0409`'s bounce
remedy, and a pass that grows past its remedy is how `#0474` reached three
rounds. What is wrong is the recorded justification, which would stop the next
reader from attempting a cheap thing by telling them it is expensive.

## Acceptance criteria

1. **Extend `TestNewDevAdminAutoLogin_RealRouteTable`** to cover the stale-cookie
   and garbage-cookie states through the real route table, so both are pinned
   rather than only ever measured live.
2. **Verify the two-states-are-one-state claim** before relying on it. If a
   deleted row and a never-existing token are genuinely indistinguishable to the
   resolver, say so in the test's own comment, since that is what makes the
   cheap form correct.
3. **Prove the new cases can fail.** Restore the presence-only short-circuit in a
   throwaway worktree and confirm both new assertions fail. A test never seen to
   fail is not a test (`CLAUDE.md` §8). Never `git stash` (§8a).
4. **Do not grow the pass.** No new middleware behaviour, no new states beyond
   the two named. `#0258`'s spiral and `#0474`'s three rounds are both on record.
5. Check whether the **json-path sibling** deserves the same treatment, and say
   yes or no with a reason. `DevAutoLogin`'s healing tests live in
   `internal/middleware`; whether they warrant a real-route-table equivalent is
   a judgement, not an obvious yes.

## Root cause

The gap was scope, not a code defect: `#0409`'s implementation pass declined
to extend `TestNewDevAdminAutoLogin_RealRouteTable` and recorded three costs
for doing so, two of which do not hold up (criteria 1 and 2 above). The
declining was itself correct — extending it was outside that pass's bounce
remedy — but the recorded justification overstated the cost of the cheap
form, which is what this issue closes.

## Fix

Extended `TestNewDevAdminAutoLogin_RealRouteTable` with two more requests
against server A (the wired `DEV_ADMIN_LOGIN` route table), reusing the
existing `pool`, `urlA`, `adminID`, and jar-less `client` the test already
held — no new fixtures. One with an explicit `Cookie` header naming a token
that was never minted by any server (the "stale" case's client-observable
shape) and one naming a garbage value (`"nonsense"`), each asserting the
response is 200 rather than the pre-fix 401.

**Criterion 2's equivalence claim was verified, not assumed**, by reading
`(*auth.Store).ResolveSession` (`internal/auth/store.go`) rather than taking
`#0409`'s reviewer's word for it. Its first `UPDATE ... RETURNING` finds no
row for either a deleted row or a token that never existed — the row is
simply absent both ways — so both fall through to the same diagnostic
`SELECT`, which also finds no row either way, and both return
`ErrSessionInvalid` from the identical `case errors.Is(derr,
pgx.ErrNoRows)` branch. There is no code path a real insert-then-delete
round trip would reach that a bare nonexistent token does not already
reach. This is recorded in the test's own added comment, per criterion 2,
not only here.

**Criterion 5 — the json-path sibling does not warrant the same treatment.**
`DevAutoLogin` (the `STORAGE=json` path) has no analogue of
`newDevAdminAutoLogin`: its own call site, `serveDevMode` in
`cmd/opencircuit/main.go`, constructs it with one direct line —
`middleware.DevAutoLogin(ds, ds, cfg.DevMode())` — passing the same `ds`
value twice, with no intervening loopback gate, admin-email lookup, or
minter closure for a wiring bug to hide in. `DevAdminAutoLogin`'s real-route-
table test earns its keep because `newDevAdminAutoLogin` (`cmd/opencircuit`)
carries exactly that kind of logic, which only a DB-backed test through the
real table can prove wired correctly end to end. A `DevAutoLogin` equivalent would
stand `mountAndServe` up under `STORAGE=json`'s `internal/devstore` to guard a
call site with no comparable logic to miswire. (This paragraph originally
called that construction materially bigger; review measured it and found it is
not, and replaced the clause in place — see `## Review notes`, which records
both the original claim and what carries the verdict instead.) No such test was
added.

**Criterion 4 — nothing else changed.** No middleware behaviour was touched;
the two new cases are exactly the two named in criterion 1, both against
the already-wired server A.

## Review notes

**Approved.** Every criterion is met and the verification reproduces
independently; one recorded cost claim did not survive checking and was
corrected in place under `## Fix`, which is the only change review made to the
implementer's prose.

**The equivalence claim holds, read directly rather than taken on trust.**
`(*auth.Store).ResolveSession` matches its first `UPDATE ... RETURNING` on
`s.token = $1` alone, so a token whose row was deleted and a token that never
existed both fail to match it and both surface `pgx.ErrNoRows`. The diagnostic
`SELECT` beneath it keys on that same `s.token = $1`, so it also finds nothing
either way, and both states return `ErrSessionInvalid` from the one
`errors.Is(derr, pgx.ErrNoRows)` branch. The expired-row and inactive-user
branches further down are unreachable for both, precisely because no row
exists to carry an expiry or an owner. The claim is in fact stronger than the
test's comment needs it to be: `DevAdminAutoLogin` keys its pass-through on
`err == nil` and nothing finer, so the two states are indistinguishable to the
middleware as well as to the resolver. The finding is recorded in the test's
own comment, as criterion 2 requires, not only in the issue.

**The fail-first proof was reproduced, not accepted.** Review created its own
detached worktree at `3618e1e`, restored `#0409`'s presence-only short-circuit
by hand in that worktree's copy of `DevAdminAutoLogin`, and ran
`TestNewDevAdminAutoLogin_RealRouteTable` against its own scratch database —
never the shared one, and never `git stash` (`CLAUDE.md` §8a). Both new
assertions failed at 401 against a wanted 200 and nothing else in the test
failed, which is the right shape: the three pre-existing assertions are
insensitive to the mutation and the two new ones are exactly what pins it. The
worktree and the scratch database were removed afterwards, and
`cmd/opencircuit/devadmin_test.go` in the shared tree was confirmed
byte-identical by SHA-256 before and after the whole exercise. The other
agent's worktree branch was neither read into the change nor touched; both
worktree branches carry an older revision of this test file that predates the
extension, so nothing could have been lifted from either.

**Fifty insertions against a twenty-line estimate is proportionate, not
growth.** Twenty-two of them are the request loop and its assertions, which is
the estimate. Nineteen are the comment recording the `ResolveSession` finding,
which criterion 2 demanded be written there. The remaining nine replace six
lines of doc comment whose "three assertions" count the change invalidated. No
behaviour was touched, no state beyond the two named was added, and one file
changed — criterion 4 is satisfied.

**Criterion 5's answer is right, but it rests on its weakest reason.** The
verdict of no is endorsed. Of the two reasons given, the first survives:
`serveDevMode` really does construct the json-path middleware in one direct
line, with no loopback gate, admin lookup, or minter closure of the kind
`newDevAdminAutoLogin` carries. The second does not. Standing `mountAndServe`
up under `internal/devstore` is not a materially bigger construction: that
store already satisfies `handlers.Pinger`, so a json equivalent would need no
pool, no `TEST_DATABASE_URL` gate, no uniquely-named seeded admin, and no row
cleanup — the three costliest parts of the Postgres version. It would
plausibly be smaller. Repeating an unmeasured cost claim inside the resolution
of the issue filed against an unmeasured cost claim is the one thing this pass
should not have done, which is why the clause was corrected rather than left.

**What actually carries the no is a third reason neither pass named.**
`#0409`'s defect lived in `DevAutoLogin`'s own pass-through branch, not in its
wiring, and that branch is now pinned directly by
`TestDevAutoLogin_StaleCookieHeals` and `TestDevAutoLogin_GarbageCookieHeals`.
So the scepticism the dispatch asked for lands somewhere other than where it
was pointed: a real defect was found on that path, but a route-table test is
not the instrument that would have caught it. The one json-specific fact left
unpinned is narrow — that `serveDevMode` passes a non-nil middleware into
`mountAndServe`'s outer-middleware argument at all — and a whole HTTP server
is a disproportionate pin for one argument position; a wiring guard would be
the proportionate one. Review has reported that residual gap to the
orchestrator rather than filing it (`CLAUDE.md` §9).

**Five states are now pinned through the real route table**, all against
server A wired by `newDevAdminAutoLogin` and served by `mountAndServe`: no
credential at all heals to 200 and reports the seeded admin; a stale cookie
heals to 200; a garbage cookie heals to 200; the same credential-less request
against a server with the middleware unwired answers 401; and five repeated
credential-less requests leave exactly one `sessions` row for that admin. The
two new cases reach the server through `client.Do` on a jar-less client
against the same real chain as the other three, not through a fake resolver —
which was the entire complaint.

./internal/db/...` reported `VERIFICATION PASSED` with no skips and `gofmt -l`
clean, all three packages reporting real elapsed time (`cmd/opencircuit`
