### What the screen does today, in one paragraph

### Decisions

1. **The summary view is the status board, reworded.** Each row's heading carries the section's one line (its time, once); the cells say a status word. The vocabulary is the user's: `Not written`, `Drafted`, `Scheduled`, `Posted`, and only when true `Posting now`, `Failed`, `On hold`, `Off`. A hand-posted cell reads `Drafted · by hand` until marked, then `Posted <when>`. A line under the board says the three video channels are posted by hand and the site never posts them. No new component: `OutreachStatusBoard.svelte` changes.
2. **One section on the page.** The pinned element becomes a tab strip (`1 Announce · 2 Reminder · 3 Final`, an ARIA tablist) with the selected section's line under it, in a new `OutreachSectionTabs.svelte`. The three panels stay mounted under `hidden` exactly as today, so typed text survives switching (`#0625`) and the board's `Not saved yet` note keeps working; what goes is every visible trace of a closed section: its strip, its `Write it`, its unsaved-note line. `OutreachWaveRow.svelte` and `OutreachWaveStrip.svelte` are deleted. Board rows still select.
3. **One time per section, set in one server call.** New `POST /admin/workshops/{id}/outreach/schedule` and `…/unschedule` take the section name and (for schedule) one instant, and act on every automatic, connected post in that section that can still be scheduled, in one transaction, all or nothing. The SPA's only scheduling controls are in one block headed **When it goes out** in `OutreachAnnouncement.svelte`. The per-post `schedule`/`unschedule` routes stay (tests, fallback) but nothing on the page calls them.
4. **Per-channel scheduling is removed from the interface, not the server.** No real need was found: the user says both go out together; the templates differ only in wording; nothing in production has different times. A legacy section whose two posts carry different times reads `Scheduled at different times` and `Change time…` gives both one time. The composer's `Schedule…`/`Change time…`/`Unschedule` and notice go; the card's `Schedule…`/`Unschedule` (unreachable in production since `#0626`, per `#0634`) go.
5. **Schedule all goes from the page.** With a section scheduled in one click from its own block, a page-level dialog listing every post with its own `Change time` is the thing the user describes. `OutreachBulkActions.svelte`, `OutreachScheduleAllDialog.svelte`, their tests, `scheduleAllOutreach` in `api.ts`, the three `OutreachScheduleAll*` types and the three Schedule-all helpers in `outreachLinks.ts` are deleted. The Go route, handler and tests are **left exactly as they are** (no Go diff for this), so the removal is reversible and keeps 0640a small; a follow-up to retire the route is reported, not filed. **The user can veto this** (see the orchestrator's summary); if vetoed, keep the two components and only delete the per-row `Change time` and `Pick a time` controls from the dialog.
6. **Dates inside the open section appear once each.** The preview's `statusLine()` under each card is shown only for `posted` (with its link), `failed` and `queued`; a scheduled post's time is the block's, not the card's. The Video group says its day once in the intro line, not three times beside each row's title; a Video row's title line keeps only `Posted <when>` after it is marked.
7. **The section line is one pure function**, `sectionLine()` in a new `lib/outreachSection.ts`, used by the board row heading and the pinned tabs, so the two can never disagree. `waveRowStatus()`/`waveStrip()` in `outreachMessage.ts` are deleted with their tests. Its table (below) settles `#0636` items 4 and 5.
8. **Switched-off channels**: a draft on an off channel is hidden by the server and is never a target. A *scheduled* post on an off channel is visible (`#0588`) and still goes out (`boardOffLine`'s own words), so it **is** a target of the section's `Change time…` and `Unschedule`: the section keeps one time. `Post to …` keeps today's rule (`postableAutomatic`); whether it may include an off channel is `#0636` item 3 and stays with the user.

### 0640a — The server schedules and unschedules a section in one call

**`internal/outreach/publish_store.go`**

Add, after `Unschedule`:

    // PostRefusal says which post a many-post write refused and why (#0640).
    // Unwrap keeps errors.Is working against the sentinel it carries.
    type PostRefusal struct {
    	PostID int64
    	Err    error
    }

    func (e *PostRefusal) Error() string { return fmt.Sprintf("outreach: post %d: %v", e.PostID, e.Err) }
    func (e *PostRefusal) Unwrap() error { return e.Err }

    // ScheduleMany sets every post in ids to go out at `at`, in one transaction,
    // all or nothing (#0640): a section's Bluesky and Mastodon posts get one time
    // together or not at all. Each must pass Schedule's own gate (a prepared
    // draft, scheduled or failed post of a published workshop). When one does
    // not, nothing is written and the error is a *PostRefusal naming it with
    // classifySend's reason. Rows come back in id order.
    func (s *Store) ScheduleMany(ctx context.Context, ids []int64, at time.Time) ([]Post, error)

    // UnscheduleMany returns every post in ids from scheduled to draft, in one
    // transaction, all or nothing (#0640). A post that is not scheduled makes
    // the whole call fail with a *PostRefusal: ErrPostInFlight when it is
    // queued, ErrWrongStatus otherwise.
    func (s *Store) UnscheduleMany(ctx context.Context, ids []int64) ([]Post, error)

  Both: `tx, err := s.pool.Begin(ctx)`, `defer tx.Rollback(ctx)`. ScheduleMany runs one statement, `UPDATE outreach_posts p SET status = 'scheduled', scheduled_at = $2, last_error = NULL, updated_at = now() WHERE p.id = ANY($1) AND p.status IN ` + `sendableStatuses` + ` AND p.short_url IS NOT NULL AND ` + `publishedWorkshop` + ` RETURNING ` + `qualifiedPostColumns` (an `UPDATE … RETURNING` takes no `ORDER BY`, so sort the slice by id in Go with `sort.Slice`), scans with `scanPost` in a loop over `tx.Query`. If `len(rows) != len(ids)`: find the first id not returned, roll back, and return `&PostRefusal{PostID: id, Err: s.classifySend(ctx, id)}` (classifySend reads with `s.pool`, outside the transaction, which is fine after the rollback). Else `tx.Commit`. An empty `ids` returns `nil, nil` without touching the database. UnscheduleMany is the same shape with `UPDATE outreach_posts SET status = 'draft', scheduled_at = NULL, updated_at = now() WHERE id = ANY($1) AND status = 'scheduled' RETURNING ` + `postColumns`, and the refusal reason from a `GetPost`: `queued` → `ErrPostInFlight`, else `ErrWrongStatus`.

### 0640b — The summary: one line per section, the user's words, dates that do not wrap

**`lib/outreachSection.ts`** (new; pure; the copy guard scans it, so no banned word in a string). Exports:

    export type SectionKind = 'not_written' | 'drafted' | 'scheduled' | 'different_times' | 'mixed' | 'posting' | 'posted' | 'failed' | 'held' | 'hand_only';
    export interface SectionLine { kind: SectionKind; text: string; /** The one instant the automatic posts share, when they do. */ at: string | null; }
    export function sectionLine(view, wave, now = new Date()): SectionLine
    export function sectionHand(view, wave): { left: number; total: number }   // on-channel hand rows and how many are not yet posted
    export function scheduleTargets(view, wave): { post; channel }[]           // automatic, sendsItself, status draft|scheduled|failed, prepared; off-channel drafts are not in view.posts, a scheduled one is (decision 8)
    export function unscheduleTargets(view, wave): { post; channel }[]         // the subset with status scheduled
    export function sectionTimeText(view, wave): string                        // 'Scheduled for <when> on Bluesky and Mastodon.' etc., the block's line (0640d)
    export function hasVideoByHandLine(view): string                           // the line under the board, '' when no hand channel is on

`sectionLine` decides on the **automatic posts on channels that send themselves** (`sendsItself`), reading `view.posts` as the server filtered them, and appends the hand count; `view.waves[i].suggested_at` through `defaultScheduleAt` gives `ahead`. Rows of its table, each a test:

| State of the automatic posts | kind | text |
|---|---|---|
| no post in the section at all | `not_written` | `Not written` + (` · suggested <when>` when `ahead`) |
| posts exist, none scheduled/posted/queued/failed | `drafted` | `Drafted · not scheduled` + suggested, + hand |
| every automatic post scheduled, one instant, none held | `scheduled` | `Scheduled <when>` + hand; `at` set |
| scheduled at two instants | `different_times` | `Scheduled at different times` + hand; `at` null |
| any held | `held` | `Scheduled <first> · on hold until the event is published` |
| any queued | `posting` | `Posting now…` |
| any failed, none queued | `failed` | `A post failed` + hand |
| every automatic post posted | `posted` | `Posted <newest posted_at>` + hand; `at` = that |
| some posted, the rest scheduled or drafted | `mixed` | `<Label> posted · <Label> scheduled <when>` / `… not scheduled`, labels in channel order |
| no automatic channel on at all, hand posts exist | `hand_only` | `Drafted · N left to post by hand` or `Posted <newest hand posted_at>` when none left |

Hand suffix: ` · N left to post by hand` when `N > 0`; nothing when every on-channel hand row is posted. **`#0636` items 4 and 5**, as rows: every channel off and nothing written → `Not written` with no hand suffix (the hand count is over *on* channels) and no `suggested`; an automatic channel that is **not connected** (`configured=false`) but holds a scheduled post → its post is not an automatic post for this line (it cannot send itself), so with the other automatic channel posted the line is `Posted <when>` + ` · Bluesky is not connected`; with every other channel off, `Not written`; a disconnected channel's unposted row is **not** counted as a hand row either, so `Drafted · 1 left to post by hand` is never written for it.
