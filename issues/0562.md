## Description

From `#0561`'s review:

1. **Save stuck (user-visible).** In `OutreachFlyerEditor.svelte`, if an over-long description is typed under `full-photo` and the template is then switched, Save and Generate stay disabled. The error line that explains why is hidden along with the controls.
2. **`shortenAtBoundary`** (`web/src/lib/flyers.ts`) has two edge cases:
   - It counts UTF-16 code units rather than code points.
   - A first word of exactly `max` characters followed by more text returns `max + 1` characters.

   The CSS line clamp hides both on the printed flyer.
3. **Store default.** `TestFlyerCaptionFields` passes `TitlePosition: "auto"` explicitly, so the store's empty-to-`auto` default is covered only incidentally by older tests.

## Acceptance criteria

- [x] The description limits block Save and Generate only while the description controls are shown, that is, on the `full-photo` template. Switching away re-enables them. Choose whichever is simpler of ignoring or keeping the hidden values, and state the choice. A jsdom test covers the switch.
- [x] `shortenAtBoundary` counts code points, and never returns more than `max` code points including any ellipsis. Unit tests cover an emoji or astral-plane case and the exact-`max` first word.
- [x] A store test creates a flyer with an empty `TitlePosition` and reads back `auto`.
- [x] Verified with `ISSUE=0562 scripts/check.sh` (Go and web).

## Relation

- Follows `#0561`.

## Resolution

1. `OutreachFlyerEditor.svelte`: the description and short-description limits now count toward `textError` only while `template === 'full-photo'`. Choice: hidden values are kept locally (not cleared), ignored by validation, and not sent on save: `saveAll()` includes `description` and `description_short` only when `template === 'full-photo'`, because the server enforces 360/140 runes (`validateFlyerFields`, `CHECK` constraints in `000036`) and would reject a hidden over-limit value. Switching away re-enables Save and Generate; switching back re-applies the limit.
2. `shortenAtBoundary` works on code points and never returns more than `max`, ellipsis included. An over-long first word (including an exactly-`max` word followed by more text) is cut to `max - 1` code points plus the ellipsis. This replaces the old "keep an over-long token whole" behaviour, whose test was updated.
3. Added `TestCreateFlyerEmptyTitlePositionDefaultsToAuto` (create with empty `TitlePosition`, read back via `GetFlyer`).

## Review notes

**Bounced 2026-10-17 (Opus reviewer).** Parts 2 and 3 are correct. Part 1 swaps one stuck Save for a failing one.

**The defect.** The resolution says the hidden values are harmless to save because "the server has no length limit". That is wrong. `#0561` added the limits on the server. `validateFlyerFields` in `internal/handlers/admin_outreach_flyers.go` rejects a description over 360 runes and a short description over 140 runes with a 400. `migrations/000036` adds the matching `CHECK` constraints. `saveAll()` in `OutreachFlyerEditor.svelte` always sends `description` and `description_short`, whatever the template. So the sequence from the description, typing 361 characters under `full-photo` and then switching to `photo-top`, now enables Save. Pressing it returns "description must be at most 360 characters". The text that caused the error is hidden, so the user cannot fix it from that screen. Generate fails the same way, since it calls `saveAll()` first. The new jsdom test does not catch this because it checks only `disabled` and never presses Save against the server's rules.

**Remedy for the next pass. It is a transcription, so keep it on Sonnet.**

1. In `saveAll()`, send `description` and `description_short` only when `template === 'full-photo'`. For example, spread `...(template === 'full-photo' ? { description: description.trim(), description_short: descriptionShort.trim() } : {})` into the patch object in place of the two unconditional keys. `PatchFlyer` already treats an absent field as "leave unchanged", and the stored values pass the `CHECK` constraints, so the database stays valid. `adopt()` then replaces the local hidden edit with the stored value. That is acceptable, because the edit was never shown or saved. Do not trim or clear the text on the client. Leave `title_position` as it is: it has no length limit.
2. Extend the jsdom switch test. After switching to `Photo top`, press Save, wait for `updateOutreachFlyer` to be called, and assert that its patch argument has no `description` and no `description_short` property. Keep a positive case: the existing #0561 send test already shows both keys are sent under `full-photo`.
3. Correct the Resolution's choice sentence. Hidden values are kept locally, ignored by validation, and not sent on save.
4. Re-run `ISSUE=0562 scripts/check.sh`.

**The rest, reviewed and accepted.**

- `shortenAtBoundary` counts code points throughout, and every branch returns at most `max` of them. The sentence branch returns `sentence + 1 ≤ max`. The word branch returns at most `max - 1` plus the ellipsis. The single-token branch returns `max - 1` plus the ellipsis. Cutting inside a single word longer than `max` is the right call. Keeping the word whole cannot meet the `≤ max` guarantee this issue asks for, and the ellipsis shows the cut. In practice it only affects a pathological token such as a pasted URL. The CSS line clamp still covers the printed face. Returning an exactly-`max` first word whole would drop the following text without any sign of it, so the current output is better. One small nit, not a blocker: with `max` of 0 the function returns a single ellipsis, which is 1 code point. No caller passes 0.
- The Go store test is fine. It creates a flyer with an empty `TitlePosition`, then checks `auto` on the returned row and again through `GetFlyer`.
- Mutation test: I reverted `textError` to the pre-fix form, which is unconditional. The new jsdom switch test failed (1 failed, 9 passed in the file). I restored the file and confirmed it byte-identical by sha256.
