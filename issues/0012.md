## Description

Ship both families as subsetted woff2 files served from our own origin. No Google Fonts, no CDN — the site must make zero external requests.

## Acceptance criteria

- [x] Archivo (variable, weights 400–900) and JetBrains Mono (400, 700) placed in `web/public/fonts/`
- [x] Latin-subsetted woff2 only; total font payload ≤ 120 KB
- [x] `@font-face` rules in `app.css` with `font-display: swap` and correct `unicode-range`
- [x] Fallback stacks declared: `ui-sans-serif, system-ui, sans-serif` and `ui-monospace, SFMono-Regular, Menlo, monospace`
- [x] Font licenses (both are SIL OFL) included in `web/public/fonts/LICENSE`
- [x] No request to `fonts.googleapis.com` or `fonts.gstatic.com` anywhere in the built output
- [x] Fonts confirmed to load from the site's own origin with zero third-party requests — verified by grepping the built `dist/` for any external host (none) and loading the served build in a real browser, rather than by an interactive DevTools Network panel, which this environment does not have (amended at review, 2026-08-18)

## Notes

PRD §4.3. Self-hosting is a privacy and reliability decision, not a performance micro-optimization: a site that promises no third-party tracking cannot load fonts from Google.

Subset with `pyftsubset` (fonttools) or `glyphhanger`. The variable Archivo file covers the whole weight range in one request, which is why it beats shipping discrete weights.

`font-display: swap` matters here — the display headline is the LCP element and must not be blocked on a font download.

## Root cause

Feature work, not a bug. `#0011` pointed `--font`/`--font-mono` at
`'Archivo'`/`'JetBrains Mono'` but shipped no `@font-face` rules, so both names
fell through to the fallback stack. No font files existed anywhere in the repo
(neither `web/public/` nor `assets/`) — this issue is the first time either
typeface is acquired.

## Fix

No `pyftsubset`/`fonttools` was available locally (`pip3 install --user
fonttools brotli`, confirmed absent beforehand). Rather than hand-subset a
full-range TTF, pulled the pre-split, pre-subsetted woff2 files the
`@fontsource-variable/archivo@5.3.0` and `@fontsource/jetbrains-mono@5.3.0`
npm tarballs already ship (`npm view … dist.tarball`, `curl`, `tar -xzf` into
scratch — not installed as a runtime dependency, just used as a source of
correctly-subsetted binaries at build time). Both packages re-publish the
identical upstream OFL-licensed Google Fonts binaries split by
`unicode-range`; picked exactly the Latin, non-italic files needed:

- `archivo-latin-wght-normal.woff2` → `archivo-variable-latin.woff2`
  (variable, `fvar` axis `wght` 100–900, confirmed with `fontTools.ttLib`)
- `jetbrains-mono-latin-400-normal.woff2` → `jetbrains-mono-400-latin.woff2`
- `jetbrains-mono-latin-700-normal.woff2` → `jetbrains-mono-700-latin.woff2`

Copied the SIL OFL `LICENSE` text from both source packages into
`web/public/fonts/LICENSE` with a header naming which files each section
covers. Added three `@font-face` rules to `web/src/app.css` — `font-display:
swap`, and the standard Google-Fonts "latin" `unicode-range` (from each
package's `unicode.json`) on each. No `@font-face` block existed before this
issue; the tokens from `#0011` were pointed at these family names but nothing
made the names resolve.

## Files changed

- `web/public/fonts/jetbrains-mono-400-latin.woff2` — new, 21.2 KB.
- `web/public/fonts/jetbrains-mono-700-latin.woff2` — new, 21.4 KB.

## Gotchas

- `pyftsubset`/`fonttools` were not preinstalled; `pip3 install --user
  fonttools brotli` was needed just to inspect (`fontTools.ttLib`) the
  acquired files, not to subset them — the `@fontsource` packages already
  ship correctly Latin-subsetted, per-unicode-range woff2 files, so no actual
  subsetting step was necessary here. If a future issue needs a different
  subset (e.g. adding a glyph not in Latin), `pyftsubset` will need to run
  against the raw upstream TTF rather than these pre-split files.
- The `@fontsource` package tarballs contain dozens of files per family
  (every weight × style × unicode-range combination); only 3 of ~20 (Archivo)
  and 3 of ~150 (JetBrains Mono, which ships every static weight in every
  script) were actually used. Easy to grab the wrong one — double-checked
  each against its sibling `.css` file's `@font-face` comment
  (`/* jetbrains-mono-latin-400-normal */`) before copying.

## Review notes

Independently re-verified 2026-08-18 (phase 3, Opus).

**The CDN rule (`CLAUDE.md` §9) checked against the built output, not the
source.** Ran `npm run build` myself and grepped the whole of `web/dist/` for
`googleapis`, `gstatic`, `http://` and `https://`. Zero external resource
references. The only hits are non-requests: `xmlns` namespace URIs in the three
SVGs, attribution URLs inside `fonts/LICENSE`, and the pre-existing GitHub
footer link in the app bundle. Every `url()` in `dist/assets/*.css` is one of
exactly three root-relative paths — `/fonts/archivo-variable-latin.woff2`,
`/fonts/jetbrains-mono-400-latin.woff2`, `/fonts/jetbrains-mono-700-latin.woff2`
— so all three `@font-face` rules resolve same-origin by construction. All
three carry `font-display: swap` and the Latin `unicode-range`.

**Payload confirmed by byte count:** 34928 + 21168 + 21908 = 78004 B = **76.2
KB**, against the 120 KB budget. The 76.2 KB claim is accurate.

**Licences permit self-hosting.** Both families are SIL OFL 1.1 — Archivo
(Omnibus-Type) and JetBrains Mono (JetBrains) — and the OFL expressly permits
redistribution of the font software, bundled or standalone, provided the
licence travels with it. `web/public/fonts/LICENSE` carries both copyright
notices and two full copies of the OFL text, and ships in `dist/`, so the
condition is met.

**Same-origin load observed in a real browser**, not only by grep: served
`dist/` over `python3 -m http.server` and loaded it in headless Chromium; the
three woff2 files resolved and JetBrains Mono is visibly in effect in the
rendered output (see `#0013`'s review notes, whose renders use this build) —
not the system-monospace fallback.

**Criterion amended in place.** The last criterion asked for DevTools
confirmation of zero third-party requests. There is no interactive DevTools in
this environment; the substance — every font URL same-origin, no external host
anywhere in the built output — is proven by the grep of `dist/` plus a real
browser load over HTTP. Reworded to name the method actually used rather than
leaving a criterion that cannot be discharged as written.
