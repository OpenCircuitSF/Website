## Description

`#0432` corrected the workshop editor's cover-image hint to name `/media/`.
**The superseded `/assets/workshops/soldering.jpg` example survives in the
client-side validation error message**, which renders as a `role="alert"`
paragraph in that same editor, roughly twenty lines below the corrected hint.

	Cover image must be a site-relative path starting with "/"
	(e.g. "/assets/workshops/soldering.jpg") — an external URL is not accepted.

So an operator who mistypes a path gets the **old** example at the exact point
of entry, contradicting the hint immediately above it. The fix is undermined by
the error that fires when someone needs guidance most.

Confirmed by the orchestrator in `web/src/lib/workshopAdmin.ts` and pinned by an
identical string in `web/src/lib/workshopAdmin.test.ts`.

**This is a copy change, not a validation change.** The Go
`coverImageErrorMessage` carries no example at all, so the two messages already
differ and **no parity fixture constrains the wording** —
`url_validator_fixture_test.go` pins the *predicate*, not the prose. Do not
touch `isSafeCoverImage` or its TypeScript twin's logic; `#0432` verified both
byte-unchanged and `docs/media.md` explains why their breadth is deliberate.

## Two more instances of the same thread

**1. `workshopAdmin.ts` also quotes the erroneous migration comment.** `#0432`
put a correction paragraph in the Go `isSafeCoverImage`'s doc comment, reasoning
it was *"the one place in the source that already repeats the wrong string
verbatim."* **There are two** — the TypeScript twin carries the identical quote
and got no correction. The rationale was sound; the inventory was not.

**2. `PRD.md` §6.2 carries `-- path under /assets` and is NOT frozen.** The new
Go correction attributes the wrong quote to "PRD §6.2's own schema comment" and
then explains only that the *migration* cannot be edited — leaving its own
antecedent uncorrected in a file that **is** editable. `#0432` left it because
`#0425` owned `PRD.md` at the time; that is no longer a constraint.

Confirmed present at `PRD.md` line 702.

## Also fold in
A typography nit from the same review: the new hint uses ASCII `--` where
rendered copy across `web/src` uses an em dash on 121 lines without exception.

### Bounce 1 — the commit made a Go doc comment false

`internal/handlers/admin_workshops.go`'s `isSafeCoverImage` doc comment says,
as present fact, in the paragraph beginning `The accepted set mirrors the
TypeScript twin exactly`:

    // PRD §6.2's own schema comment ("cover_image TEXT, -- path under /assets")

At `b418b14^` that was **true** — §6.2 read `-- path under /assets`. After
`b418b14` it reads `-- path under /media`, so the sentence is now false. The
`Correction (#0432)` paragraph twelve lines below makes it worse rather than
better:

    // (CLAUDE.md §1) and cannot be edited to fix it, so the correction is
    // recorded here and in docs/media.md instead.

That tells a reader the quote cannot be fixed at its source because the
migration is frozen — but the antecedent it actually cites, `PRD.md` §6.2, was
just fixed by this very commit, and the file contains no `#0438` reference at
all. This is precisely the defect this issue's own "Two more instances" §2
described, now inverted: the Go correction still "attributes the wrong quote to
PRD §6.2's own schema comment and then explains only that the *migration*
cannot be edited."

The asymmetry is the tell. `workshopAdmin.ts`, edited in the same commit, has
the identical stale antecedent quote **and** discloses the fix directly beneath
it. The Go twin has the identical stale quote and no disclosure. The two doc
comments were deliberately kept parallel by `#0432`; `b418b14` broke that
parallel in the one direction that leaves a falsehood standing.

`TestNoCommentCitesUnresolvedPathOrSection` passes, correctly — it checks that a
cited *section* resolves, not that a *quotation* of it is accurate. Nothing
mechanical will catch this; a human reader is simply misled.

**This belongs to this issue, not a follow-up.** The commit introduced the
falsehood, the fix is one sentence, and the file is already inside the
verification scope AC7 mandates. Filing it out would make this the fourth pass
on one thread that AC6 exists specifically to end.

**Remedy (do exactly this).** In `internal/handlers/admin_workshops.go`, replace
the closing sentence of the `Correction (#0432)` paragraph — currently
`so the correction is recorded here and in docs/media.md instead.` — with text
that states both facts the TypeScript twin already states:

1. `PRD.md` §6.2's copy of the comment **was corrected** (by `#0438`), because
   unlike `migrations/000020` it is not frozen; and
2. the quotation above is therefore **history**, not `PRD.md`'s current text.

Mirror the phrasing of `web/src/lib/workshopAdmin.ts`'s `Correction (#0438)`
ending so the two comments read as twins again. Leave the antecedent quote
itself in place — a quoted-then-corrected rationale is legitimate history, and
that is the shape the TS side already has. Do **not** touch `isSafeCoverImage`.

   Bounce 1. The implementer identified it accurately and then declined it.
3. **The `WorkshopEditor.svelte` em dash — real, unique, and this issue's.**
