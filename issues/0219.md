## Description

`#0059` built and hardened `GET /admin/subscribers/export` — streamed at both
layers, admin-gated with the guard proven by mutation, audited even on client
disconnect, CSV-injection-guarded against nine probe shapes including the five
leading-whitespace bypasses its review found.

**Nothing in the admin UI links to it.** The endpoint is reachable only by
typing the URL, so the feature exists and is effectively undiscoverable.

Both `#0059`'s implementer and both of its reviewers flagged this as the natural
follow-up rather than widening that issue's diff into `web/` while `#0094`'s and
`#0120`'s work was landing there. That was the right call at the time; it is now
just missing.

## Acceptance criteria

- [x] The subscribers admin screen offers a download affordance that reaches `GET /admin/subscribers/export`
- [x] The current filters (status, interest, query) are carried into the request, so what downloads matches what the admin is looking at — the endpoint already accepts and audits that filter triple
- [x] The affordance is a real navigation to the endpoint, not a `fetch` that buffers the whole body in memory — `#0059` streams deliberately at both layers and a buffering client would discard that property
- [x] A test covers it. `#0094`'s jsdom harness makes this mountable — assert the link's `href` (and that filters appear in it) rather than only that an element renders
- [x] `#0120`'s `modalEscapeGuard` and `#0197`'s structural guard still pass
- [x] `scripts/check.sh web` passes

## Notes

Reported by `#0059`'s implementation pass and both review passes under
`CLAUDE.md` §9.

Criterion 3 is the one worth being deliberate about. A browser navigation (or an
anchor with `download`) streams straight to disk; `fetch(...).then(r => r.blob())`
holds the entire list in memory first, which quietly undoes the reason `#0059`
streams. For this project's list size either would work today — but the endpoint
was built streaming on purpose, and the client is where that gets thrown away.

Worth knowing while building it: the export sends
`Content-Disposition: attachment; filename="subscribers-export.csv"` with a
fixed literal filename, and `X-Content-Type-Options: nosniff`. A mid-stream
failure produces a `200` with a well-formed but short CSV and **no** truncation
signal — a deliberate, recorded decision in `#0059`, with the forensic evidence
in the audit row instead. If this UI ever grows a "your download failed" state,
that is the constraint it runs into.

## Implementation notes

Added `subscribersExportHref(filter)` to `web/src/lib/admin.ts`, a pure
function (no DOM) mirroring `listSubscribers`' own query-building in
`lib/api.ts` — same three params (`status`, `interest_id`, `q`), same
"only set a param when it's truthy" rule (so `interestId: 0` never emits
`interest_id=0`), just without `page`/`per_page` since the export is the
whole filtered list, not one page.

`Admin.svelte` renders it in the "Search & filter" panel (next to Apply/
Clear, inside the same `<form>` — harmless there since an `<a>` never
submits) as:

```svelte
<a class="link-button" href={subsExportHref} download>Export CSV</a>
```

`subsExportHref` is a `$derived` built from `subsStatusFilter`,
`subsInterestFilter`, and `subsQueryApplied` — the exact same triple
`loadSubscribers()` already sends, including the existing status/interest
"live" vs. query "applied-on-submit" split (the Clear button's visibility
condition on line ~1619 already mixes these the same way, so this matches
established behavior rather than inventing a new one: status/interest
update the link the instant the dropdown changes, the query text only
after Apply is clicked).

**Criterion 3 (real navigation, not `fetch`).** Used a plain `<a href
download>`, not a click handler. `download`'s presence (any value, empty
included) is exactly what the SPA's own click interceptor already treats
as "let the browser handle this" — `shouldIntercept()` in
`web/src/lib/router.ts` returns `false` whenever `c.download !== null`, so
this link bypasses client-side pushState routing entirely and reaches the
server as a real navigation, letting `#0059`'s streaming survive on the
client exactly as the issue's Notes asked for. No new router logic was
needed; this existing rule already covered it.

**Styling.** `Button.svelte`'s `.btn` class is Svelte-scoped to that one
file, so it doesn't reach an `<a>` written in `Admin.svelte` (confirmed by
precedent already in the tree: `CampaignEditor.svelte` duplicates its own
local `.btn`/`.btn-primary` for the same reason, for a native `<button>`
it couldn't route through the `Button` component). Added a small
`.link-button` rule in `Admin.svelte`'s own `<style>` block, using the
same CSS custom properties (`--border-strong`, `--bg-subtle`, `--radius`,
etc.) `Button.svelte` uses, so it looks consistent without depending on
Svelte-scoped class leakage. Focus-visible styling needed no extra work —
`app.css`'s `:where(a, button, summary, [tabindex]):focus-visible` rule
(using `--accent`, not `--border-strong`, per `CLAUDE.md` §8's gotcha)
already covers plain anchors.

**Criterion 4 (test).** Two levels, deliberately:

- `web/src/lib/admin.test.ts` — a fast unit test of `subscribersExportHref`
  in isolation (no params, each param alone, all three together, and the
  falsy-omission rule).
- `web/src/views/Admin.behavior.test.ts` (new file) — a jsdom-mounted
  behavioural test, per the criterion's explicit ask ("assert the link's
  `href` ... rather than only that an element renders"). Mounts the real
  `Admin.svelte`, switches to the Subscribers tab, and asserts the
  rendered `<a>`'s actual `href` attribute — proving the wiring between
  live filter state and the rendered link, not just that the pure
  function is correct in isolation. `Admin.svelte`'s `onMount` fires six
  loaders unconditionally regardless of which tab is showing (settings,
  users, audit, interests, subscribers, suppressions) and its default
  section mounts `Dashboard.svelte` underneath, which opens a real
  `EventSource` — so `../lib/api` and `../lib/events` are both mocked,
  following `CampaignSendDialog.behavior.test.ts` and
  `Dashboard.behavior.test.ts`'s established precedent for this repo's
  mounted-component tests.
