## Description

`#0059` built and hardened `GET /admin/subscribers/export` — streamed at both
layers, admin-gated with the guard proven by mutation, audited even on client
disconnect, CSV-injection-guarded against nine probe shapes including the five
leading-whitespace bypasses its review found.

**Nothing in the admin UI links to it.** The endpoint is reachable only by
typing the URL, so the feature exists and is effectively undiscoverable.

Both `#0059`'s implementer and both of its reviewers flagged this as the natural
follow-up rather than widening that issue's diff into `web/` while `#0094`'s and
`#0120`'s work was landing there. That was the right call at the time; it is now
just missing.

## Acceptance criteria

- [ ] The subscribers admin screen offers a download affordance that reaches `GET /admin/subscribers/export`
- [ ] The current filters (status, interest, query) are carried into the request, so what downloads matches what the admin is looking at — the endpoint already accepts and audits that filter triple
- [ ] The affordance is a real navigation to the endpoint, not a `fetch` that buffers the whole body in memory — `#0059` streams deliberately at both layers and a buffering client would discard that property
- [ ] A test covers it. `#0094`'s jsdom harness makes this mountable — assert the link's `href` (and that filters appear in it) rather than only that an element renders
- [ ] `#0120`'s `modalEscapeGuard` and `#0197`'s structural guard still pass
- [ ] `scripts/check.sh web` passes

## Notes

Reported by `#0059`'s implementation pass and both review passes under
`CLAUDE.md` §9.

Criterion 3 is the one worth being deliberate about. A browser navigation (or an
anchor with `download`) streams straight to disk; `fetch(...).then(r => r.blob())`
holds the entire list in memory first, which quietly undoes the reason `#0059`
streams. For this project's list size either would work today — but the endpoint
was built streaming on purpose, and the client is where that gets thrown away.

Worth knowing while building it: the export sends
`Content-Disposition: attachment; filename="subscribers-export.csv"` with a
fixed literal filename, and `X-Content-Type-Options: nosniff`. A mid-stream
failure produces a `200` with a well-formed but short CSV and **no** truncation
signal — a deliberate, recorded decision in `#0059`, with the forensic evidence
in the audit row instead. If this UI ever grows a "your download failed" state,
that is the constraint it runs into.
