> 🟢 Resolved 2026-09-10 — an AST structural guard over `Home.svelte` now

> discarded, or if the buffer it fills stops being read by the typing loop.

## Description

`#0393`'s first review bounced it on an untested seam: no test referenced
`web/src/views/Home.svelte`, so the fetch-and-fallback logic in its `onMount`
was unobserved, and the wiring could have stopped calling the tested code with
the suite staying green.

The remedy — the reviewer's own preferred one — extracted that logic into
`crtLoadScript()` in `web/src/lib/crtScreen.ts` and tested it across 404, 500,
a thrown fetch, an empty session and a failing live-source row. That is real
coverage of the decision logic and the bounce was correctly answered.

**But the seam shrank rather than closed.** No test fails today if
`Home.svelte` stops calling `crtLoadScript`, or stops using its result. What
was ~70 unobserved lines is now two.

`#0393`'s second review accepted this and recorded why, which is worth
repeating because it is what makes this a follow-up rather than a defect:
**the residual failure mode is the criterion's own pass condition.** `script`
is initialised from `crtFallbackScript()`, so dropping the call degrades toward
the compiled-in `CRT_SESSION` — never toward a blank block or an error string,
which is `#0274`'s standing rule.

What it still permits is quieter and is the reason to close it: **an admin's
edits silently never reaching the glass.** The screen would keep showing the
compiled-in session, correct-looking and stale, and every test would pass. That
is precisely the failure the whole of `#0393` exists to prevent.

## Acceptance criteria

- [x] A structural guard — `web/src/views/Home.crtWiring.structuralGuard.test.ts`, modelled on `CampaignSendDialog.structuralGuard.test.ts` — asserts `Home.svelte` calls `crtLoadScript` and assigns its result to the script the CRT draws from
- [x] The guard carries a **self-test that runs its own predicates over an in-memory mutated copy** of the file and asserts they fail on it — never against the file on disk (`CLAUDE.md` §8a: do not move the shared tree out from under other agents)
- [x] The self-test's oracle is not the same bytes as its subject — a single edit to `Home.svelte` must not be able to satisfy both the guard and its own expectation (`CLAUDE.md` §8, the `#0258` rule)
- [x] Deleting the `crtLoadScript` call from a mutated copy makes the guard fail; the guard passes against the real file unmodified
- [x] `scripts/check.sh web` passes

## Notes

Filed from `#0393`'s second review, 2026-09-03, which resolved that issue and
recommended this separately.

`#0393`'s first review named this guard as its acceptable alternative remedy
and the extraction as its preferred one. The two were never exclusive — the
extraction is what makes the logic testable, and this guard is what pins the
extracted function to the component that must call it. `CLAUDE.md` §8 already
records the general form: an in-file observer can be deleted by the same edit
it guards, so a fact worth pinning is often worth pinning in two places.

**jsdom cannot substitute for this.** `Home.svelte` cannot be mounted in this
project's jsdom — there is no canvas shim, so the CRT's `onMount` returns early
at its context check. A structural guard over the source text is the available
oracle, and its limits should be stated in its own doc comment rather than
discovered later.

## Verification

**Guard form and why.** `web/src/views/Home.crtWiring.structuralGuard.test.ts`
parses `Home.svelte` with `svelte/compiler` (the same technique
`CampaignSendDialog.structuralGuard.test.ts` and
`campaignEditorSlugAndDeleteWiring.structuralGuard.test.ts` already use) and
checks the real AST rather than source text, so the `#0064` hazard (a regex
finding `crtLoadScript` inside this very file's own header comment) does not
apply. **This rests on a source scan, not a mount** — `#0398`'s own Notes
record why a mount cannot substitute: this project's jsdom ships no canvas
shim, so `Home.svelte`'s CRT `onMount` bails out at its `getContext('2d')`
null-check before reaching any of the wiring under test, and `#0393`'s own
verification already established there is no mounted-`Home.svelte`
precedent to extend. `checkCrtWiring()` is the guard's whole oracle: it
finds the `let X = crtFallbackScript()` buffer declarator by shape, the
`crtLoadScript().then(...)` call by shape, asserts the `.then` callback
assigns its parameter to that buffer variable (catching a discarded result
as a distinct failure from a dropped call), and confirms `session()` — the
typing loop — actually reads that buffer, so a same-named decoy variable
could not satisfy it. Every match is by AST shape and hand-typed identifier
literals (`crtLoadScript`, `then`, `crtFallbackScript`, `session`), never by
comparing against a copied fragment of `Home.svelte`'s own source, so this
does not reproduce the `#0258` oracle-is-the-subject failure.

**Self-test (in-memory, never on disk).** The same `checkCrtWiring()` runs
against two in-memory mutated copies of the real source string
(`withoutCrtLoadScriptCall`, `withDiscardedResult`), each built by a plain
string `.replace()` on a copy of `componentSource` — nothing is written to
disk. Both mutation helpers assert `mutated !== source` before trusting the
result, so a stale text anchor fails loudly rather than producing a silent
no-op "copy". These text anchors are used only to locate where to inject
each mutation; the pass/fail oracle itself is `checkCrtWiring()`'s
AST/identifier matching, described above, which is why the self-test's
oracle is not the same bytes as its subject: nothing here compares
`Home.svelte`'s source against a retyped copy of itself.

**Mutation proof 1 — dropped call.** Copied `web/src/views/Home.svelte`
aside first (`shasum -a 256` recorded: `a09cb2af…21f60a`), then edited the
real file in place, replacing `void crtLoadScript().then((s) => {` with
`void Promise.resolve(crtFallbackScript()).then((s) => {`. Re-ran
`npx vitest run src/views/Home.crtWiring.structuralGuard.test.ts`: 3 of 4
tests failed, the main guard naming exactly the seam — `could not find a
` + "`crtLoadScript().then(...)`" + ` call -- Home.svelte no longer appears
to call crtLoadScript (#0398)`. Restored the file from the saved copy and
verified `shasum -a 256` matched the pre-mutation hash exactly; `git status
--porcelain -- web/src/views/Home.svelte` reported clean.

**Mutation proof 2 — discarded result.** Same copy-first discipline, then
replaced `      script = s;\n      void session();` with `      void
session();`. Re-ran the guard: 3 of 4 tests failed, the main guard naming
the seam precisely — `` crtLoadScript().then(...)'s callback does not
assign its resolved value to `script` -- the fetched session is being
discarded (#0398) ``. Restored and re-verified the SHA-256 hash matched and
`git status --porcelain -- web/src/views/Home.svelte` was clean again.

**`Home.svelte` behaviour is unchanged.** No edit to `Home.svelte` was
committed — only the new guard test file was added; `git diff --stat --
web/src/views/Home.svelte` against `HEAD` is empty.

## Review notes

Reviewed 2026-09-10, independently of the drafted `## Verification`. **Approved.**

**The form choice rests on a claim I re-derived rather than accepted.** The
guard is a source scan instead of a mount, justified by this project's jsdom
having no canvas shim, so I mounted `Home.svelte` under jsdom to test that.
With `@testing-library/svelte` and the workshops/interests API calls stubbed
the component mounts cleanly, and its CRT `onMount` demonstrably runs —
instrumenting `getContext` on the canvas prototype recorded two `2d` calls made
from inside that callback — before returning at its own context null-check,
leaving `crtLoadScript` called exactly zero times. The claim holds as written.

It is in fact understated. A counterfactual pass that supplied a working fake
2d context still could not reach the call, because `window.matchMedia` is also
absent from this jsdom and `IntersectionObserver` after it. Observing this seam
by mounting would mean fabricating three separate browser APIs, which would
demonstrate the wiring runs in an invented environment rather than a real one.
A structural scan is the right instrument here, and the file's doc comment
correctly names the canvas bail as the barrier actually reached first.

**The matching is genuinely shape-based, and it fails closed.** I extracted
`checkCrtWiring` verbatim from the committed file and drove it against ten
mutations of my own design, distinct from the two the guard ships. Renaming the
buffer from `script` to `crtBuf` throughout still passes, which is the positive
evidence that no check hard-codes that name. Dropping the call in a form
different from the shipped anchor fails, as does discarding the result by
binding it to a fresh local instead. A decoy that assigns the resolved value but
stops `session()` reading the buffer fails with its own distinct message, so the
`session()` read is load-bearing rather than decorative. Empty source, an
unparseable file, and a component with no instance script each fail rather than
silently finding nothing to assert.

**The `#0064` hazard does not apply.** I mutated the source to delete the real
call while leaving behind a comment containing that call's exact text, and the
guard still failed, because the AST walk never visits comment nodes.

**The in-file self-test is sound, and is not the start of `#0258`'s spiral.**
The two are different shapes. `#0258`'s failure was a guard defending the file
it lives in, where every added mechanism became fresh surface for the next edit
to neutralise. Here the subject is a different file entirely, so no edit to
`Home.svelte` can reach the oracle, and the self-test's job is narrower: it
proves `checkCrtWiring` is falsifiable rather than a function that returns true
unconditionally. By `CLAUDE.md` §8's rule about where a guard's proof belongs,
mutating the input source genuinely changes what the oracle computes, which is
the case that belongs in-package rather than in an external harness.

The mutation helpers' text anchors are not an oracle. They locate where to
inject and nothing more, and each asserts its own edit took effect, so a stale
anchor throws loudly instead of yielding an unmutated copy. A single edit to
`Home.svelte` cannot satisfy both the guard and its own expectation, because the
pass/fail decision never compares the source against a retyped copy of itself.

**What it catches and what it does not.** It catches the two failure shapes the
Description named — the call disappearing, and its resolved value being thrown
away — plus a third, the buffer being reassigned but never read by the typing
loop. It cannot observe runtime behaviour at all: that the fetch resolves, that
the reassignment reaches the canvas, or that the glass repaints are all outside
what a structural scan can see. It would also not notice the guard file itself
being deleted, which is the standing limit on every in-file observer.

**Nothing here constrains `#0397`.** Its draw-site edits sit inside `session()`'s
typed loop, which neither mutation anchor overlaps, and the identifiers those
anchors depend on stay where they are.
