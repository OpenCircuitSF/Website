# 0298 — An allowlist entry naming an unscanned file is validated by nothing

| | |
|---|---|

## Description

`#0280` gave the live-region guard's allowlists a required-justification rule
and a staleness check. Both are real and both fire — `#0286`'s review proved the
staleness check by re-adding a removed entry and watching the suite fail.

**But both checks are per-file.** `unjustifiedEntryViolations` and
`staleEntryViolations` each filter on `e.file === fileName`, so they only ever
run for entries whose file the scan actually visits. An entry naming a file that
does not exist is never examined by either.

Measured by `#0286`'s reviewer: adding

```js
{ file: 'web/src/views/DoesNotExistAnywhere.svelte', match: 'nothing', reason: '' }
```

to `KNOWN_STABLE_BRANCH_SITES` leaves the whole suite **green** — despite an
empty `reason`, which the justification rule exists to reject.

**It is inert rather than a bypass**, because `findAllowlistEntry` also matches
on file, so a bogus entry cannot excuse a real site. And the hole predates
`#0280`. But it is now the **likeliest way an entry goes stale in practice** — a
component rename, a deletion, or a typo in the path — and criterion 3's whole
point was that a stale entry must fail loudly.

## Acceptance criteria

1. Every allowlist entry is validated against the **union of scanned files**,
   once per run, rather than per file. An entry naming a file the scan never
   visits fails loudly, naming the entry and the path.
2. Both rules apply to that pass: an entry with an empty or missing `reason`
   fails even when its file does not exist, since a bogus path must not become a
   way to smuggle in an unjustified entry.
3. This covers **every** allowlist the guard carries — `KNOWN_LOADING_PLACEHOLDERS`,
   `KNOWN_STABLE_BRANCH_SITES`, and any successor. Do not fix one and leave the
   others.
4. Prove it with a fixture: an entry naming a non-existent file must fail, and
   the current real entries must all still pass. Per CLAUDE.md §8, the oracle
   must not be the same bytes as the subject.
5. The check must fail closed if the scanned-file set is empty — `#0275`'s
   lesson on the Go side, which applies identically here.
6. `ISSUE=NNNN scripts/check.sh web` passes.
