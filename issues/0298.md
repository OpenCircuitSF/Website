## Description

`#0280` gave the live-region guard's allowlists a required-justification rule
and a staleness check. Both are real and both fire — `#0286`'s review proved the
staleness check by re-adding a removed entry and watching the suite fail.

**But both checks are per-file.** `unjustifiedEntryViolations` and
`staleEntryViolations` each filter on `e.file === fileName`, so they only ever
run for entries whose file the scan actually visits. An entry naming a file that
does not exist is never examined by either.

Measured by `#0286`'s reviewer: adding

```js
{ file: 'web/src/views/DoesNotExistAnywhere.svelte', match: 'nothing', reason: '' }
```

to `KNOWN_STABLE_BRANCH_SITES` leaves the whole suite **green** — despite an
empty `reason`, which the justification rule exists to reject.

**It is inert rather than a bypass**, because `findAllowlistEntry` also matches
on file, so a bogus entry cannot excuse a real site. And the hole predates
`#0280`. But it is now the **likeliest way an entry goes stale in practice** — a
component rename, a deletion, or a typo in the path — and criterion 3's whole
point was that a stale entry must fail loudly.

## Acceptance criteria

1. Every allowlist entry is validated against the **union of scanned files**,
   once per run, rather than per file. An entry naming a file the scan never
   visits fails loudly, naming the entry and the path.
2. Both rules apply to that pass: an entry with an empty or missing `reason`
   fails even when its file does not exist, since a bogus path must not become a
   way to smuggle in an unjustified entry.
3. This covers **every** allowlist the guard carries — `KNOWN_LOADING_PLACEHOLDERS`,
   `KNOWN_STABLE_BRANCH_SITES`, and any successor. Do not fix one and leave the
   others.
4. Prove it with a fixture: an entry naming a non-existent file must fail, and
   the current real entries must all still pass. Per CLAUDE.md §8, the oracle
   must not be the same bytes as the subject.
5. The check must fail closed if the scanned-file set is empty — `#0275`'s
   lesson on the Go side, which applies identically here.
6. `ISSUE=NNNN scripts/check.sh web` passes.

## Work log

Added `unscannedFileViolations(list, allowlistName, scannedFiles)` in
`web/src/lib/liveRegionGuard.structuralGuard.test.ts`, called once per
allowlist (not per file) after the real-tree scan loop finishes, against
`scannedFiles` — the union of every `.svelte` file the scan actually visited
that run. For each entry in a list, if `!scannedFiles.has(e.file)` it fails
loudly (criterion 1), naming the entry's `match` and `file`; if the entry's
`reason` is also empty, a *second*, separate violation fires for that
(criterion 2) — so a bogus path cannot double as a way to dodge the
justification rule. Fails closed (criterion 5, `#0275`'s lesson) when
`scannedFiles` is empty, rather than treating an empty set as "nothing to
validate against, so nothing fails."

Wired into the real-tree test for all three allowlists
(`KNOWN_DYNAMIC_ROLE_SITES`, `KNOWN_LOADING_PLACEHOLDERS`,
`KNOWN_STABLE_BRANCH_SITES`) — criterion 3. Added a `scannedFileSet()` helper
so a fixture can validate the real entries against the real scan result
rather than a hand-typed stand-in.

Added a doc-comment block in the file header, next to the other allowlist
history notes, explaining why the per-file checks miss this case and what
the new once-per-run pass adds.

Four new fixtures (criterion 4): an entry naming a nonexistent file with an
empty reason fails on *both* rules; an entry naming a scanned file with a
real reason passes; an empty scanned-file set fails closed; and every entry
in all three real allowlists passes against the real `scannedFileSet()`.
Assertions read for independently written substrings, not a copy of the
message the function emits (CLAUDE.md §8).

Proved the fix against the issue's own repro: temporarily added
`{ file: 'web/src/views/DoesNotExistAnywhere.svelte', match: 'nothing',
reason: '' }` to the real `KNOWN_STABLE_BRANCH_SITES`, ran the real-tree
test, confirmed it now fails with both the unscanned-file violation and the
missing-justification violation (previously green, per the issue's own
Description), then restored the file and verified it is byte-identical to
before (`diff -q`, and a full suite re-run afterward).
