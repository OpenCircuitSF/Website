## Description

Part of `#0695` (Agent API, part 2). Guide-post engagement tracking.

**Problem.** `outreach.Store.EngagementTargets` reads `outreach_posts` only, so guide posts on Bluesky and Mastodon never get counts. That leaves "how did last week's guide posts do?" with clicks only.

## Plan (design-level, so the implementer should read `internal/outreach/tracker.go` first):
- `migrations/000057_create_guide_post_engagement`: `guide_post_engagement(id bigserial, post_id bigint REFERENCES guide_posts ON DELETE CASCADE, captured_at timestamptz, likes/reposts/replies/quotes int)` plus an index on `(post_id, captured_at desc)`.
- `internal/guideposts`: `EngagementTargets`, `RecordEngagement` and `LatestEngagement`, mirroring `outreach/engagement.go`.
- `outreach.TrackerDeps` gains an optional second target source (a small interface). The tracker polls both sources with the same due rule and the same 30-day window, and records each to its own table. Mentions stay event-only. The admin guide results view may show the counts, but that is optional and not required.

**Tests:** a tracker test with a fake source proves guide targets are polled and recorded, and nil means unchanged behaviour. The store tests are DB-backed.

## Resolution
