## Description

`#0131` removed `'bounced'` and `'complained'` from the `email_sends.status` CHECK, leaving five reachable values. `internal/mailing/progress_test.go` was not part of that change and still describes seven: comments at lines 20 and 44 say "the seven `email_sends.status` values", and the test itself is named `TestWorker_PublishProgress_SevenStatusArithmetic` (lines 59 and 61).

The test seeds only the five live statuses, so it passes and its arithmetic is right. Only the naming and the comments are stale — but a test named for a count the schema no longer permits is exactly the kind of thing a future reader trusts and a future change breaks.

## Root cause

`internal/mailing/progress_test.go` was written for `#0048` when `email_sends.status`
admitted seven values under `migrations/000018` (`queued`, `sending`, `sent`,
`failed`, `bounced`, `complained`, `skipped`). `#0131` dropped `'bounced'`/
`'complained'`, narrowing the CHECK to five, but that change touched only
`internal/handlers/admin_campaign_stats_test.go` (renamed its own
`SevenStatuses` test) and left this file's package doc comment, a helper
comment, and the test's own name still narrating the old count of seven
(and, in the package doc's history note, "the original six" predating
`'sending'` — actually four, per `000017`).

## Fix

- Package doc comment (`progress_test.go:4-7`): "gained a SEVENTH status" →
  "gained a FIFTH status"; "the original six statuses" → "the original four
  statuses" — matching `000017`'s four (`queued`, `sent`, `failed`, `skipped`)
  widened to five by `000018`'s `'sending'`.
- `seedSendWithStatus`'s comment (`:44`): "the seven `email_sends.status`
  values" → "the five `email_sends.status` values".
- Renamed `TestWorker_PublishProgress_SevenStatusArithmetic` to
  `TestWorker_PublishProgress_StatusArithmetic` everywhere the name appeared
  in this file (doc comment at old `:20`, doc comment and `func` at old
  `:59`/`:61`) — dropping the count from the name entirely, following
  `#0131`'s own precedent of renaming `BucketsAllSevenStatuses` to
  `BucketsAllValidStatuses` so a future CHECK change can't make the name
  stale again. No assertions changed; the test already seeded only the five
  live statuses and its arithmetic was already correct.
- Ride-along (criterion 4): verified `CampaignStats.svelte`'s
  `let hasFailedSends = $derived(failedSends.length > 0)` is at **line 55**
  directly (`grep -n "length >" web/src/views/admin/CampaignStats.svelte`),
  confirming `#0131`'s reviewer's correction of the earlier wrong `44`.
  Corrected both occurrences of "line 44" in `issues/0049.md` — one added by
  `#0049`'s own resolution review, one added by `#0131`'s ride-along — to
  `line 55`. Touched only those two lines.
- Left historical mentions of `TestWorker_PublishProgress_SevenStatusArithmetic`
  in `issues/0048.md`, `issues/0118.md`, and `issues/0131.md` untouched —
  those are work-log narration of what was true at the time each ran, not
  live references to the code, and rewriting them would misrepresent
  history rather than correct stale documentation.
