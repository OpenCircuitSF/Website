**single-line** comment fixture. So `strings.Join(strings.Fields(text), " ")` —
the flattening step `#0366` factored into `claimCommentGuardFlattenComment` — is

Measured by `#0366`'s review: replacing that function's body with
`return text` leaves the entire `internal/outbox` package **green**.

**Pre-existing, not introduced by the extraction.** The same review confirmed
the mutation passes identically on the pre-`#0366` file with both inline copies
mutated. The extraction neither created nor widened this.

It matters because the real corpus is not single-line: `internal/outbox/store.go`
wraps the phrase the `store.go` sentinel depends on across two comment lines, and
~~`#0342`'s site C was found only after joining wrapped text~~. Flattening is

**Criterion 5 / `#0358` criterion 4 — axis frozen, proved not read.** Built an
independent comment-only comparator (`astprint`): parse each side with
`parser.ParseFile(…, 0)` — mode 0, comments never attached — then render the
AST with `go/printer` and compare rendered **bytes**. A different mechanism
from the implementer's `go/scanner` token stream and from `#0366`'s
`go/printer` AST diff. Proved before use:

| probe | expected | got |
|---|---|---|
| file vs itself | IDENTICAL | IDENTICAL, 36904 bytes / 7850 AST nodes |
| empty second file | fail-closed | `ERROR (fail-closed)`, exit 2 |
| rename a real `func` declaration | DIFFERENT | DIFFERENT, names the token |
| **byte edit inside a `//`-prefixed line INSIDE a raw-string fixture** (`claimCommentGuardStaleFixtureSrc`) | DIFFERENT | DIFFERENT at byte 15854 |
| add a genuine new leading `//` comment | IDENTICAL | IDENTICAL |

The raw-string hazard is handled structurally: a raw-string `const` is a
`BasicLit` whose `Value` is the source text, printed verbatim, so a `//` line
*inside* one is real content and an edit to it is a real difference — while a
genuine comment is dropped by the mode-0 parse. **Instrument limit, disclosed:**
it over-reports on an *interior* comment added inside a function body (the
printer preserves the resulting line gap as a blank line). That is the
fail-closed direction — it can produce a false DIFFERENT, never a false
IDENTICAL — so an IDENTICAL verdict remains conclusive.

Verdict against the real pair `be1f08d^` → the final tree: **IDENTICAL**,
36904 rendered bytes and 7850 AST nodes on both sides, same sha256. So no
non-comment byte changed anywhere in the file: `claimCommentGuardDirWordRe`,
the window computation, the marker set, the clamp, and the every-identifier
loop are untouched a fortiori. Corroborated textually: 66 added lines, 0
removed, **every** added line begins `//` (checked programmatically).
