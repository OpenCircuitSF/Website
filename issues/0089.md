## Description

`#0086` rewrote `docTableRowLines` as a state machine tracking fence character, HTML-comment spans and 4-space indentation. It closed the three forms it targeted, and `#0086`'s reviewer probed **eighteen** markdown forms confirming no regression. Two residuals remain, both narrow, neither present in the docs today.

## 1. A tab-indented row is accepted

`strings.TrimLeft(line, " ")` counts spaces only. A tab is four columns of CommonMark indentation, so a tab-indented `|`-leading line inside what a renderer treats as a code block still satisfies the row check — the same drift mode `#0086` closed, reached via a different whitespace character.

## 2. A short closing fence ends a longer fence

A 4-backtick fence closed by a 3-backtick line: the inner ``` ``` ``` closes it early and following rows are accepted. CommonMark requires the closer to be at least as long as the opener. Same for a 4-tilde fence closed by `~~~`.

## Acceptance criteria

- [ ] A tab-indented `|`-leading line inside a code block is rejected
- [ ] A closing fence shorter than its opener does not close it
- [ ] **Each mutation-proven separately** — create the condition, watch its own assertion fail, revert, report the output
- [ ] The eighteen forms `#0086`'s reviewer verified still behave identically. In particular keep accepting: tight pipes, alignment colons, a nested table in a list item, a table inside `<details>`. Keep rejecting: prose, bullet lists, blockquoted rows, single-line HTML comments, fences inside list items at 2- and 4-space indent, rows inside `<details>` inside a fence
- [ ] Still filesystem-only — passes with `TEST_DATABASE_URL` set and unset
- [ ] `go build ./...`, `go test ./... -count=1` green, zero skips

## Notes

**Resist building a markdown parser.** `#0086`'s guidance still applies and these are two more state-machine conditions, not a reason to take a dependency. If the fix starts to look like a parser, stop and say so — accepting these two residuals is a legitimate outcome if the cure is worse.

Two behaviours confirmed correct and worth preserving deliberately: an unclosed fence suppresses to EOF and fails **loudly** via the forward check, and an unclosed HTML comment does the same. Both fail in the safe direction.
