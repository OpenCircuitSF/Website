## Description

This is a child of `#0673`. `#0652`'s tokens are read-only, and they never expire. This issue extends them so they can safely drive writes.

## Requirements

1. **Expiry.**
   - Add migration `000053`, which adds `expires_at TIMESTAMPTZ NULL` to `api_tokens`.
   - `Resolve` rejects a token once `now >= expires_at`, with the same 401 as a revoked token.
   - `Create` takes an optional expiry.
   - The admin UI offers 7 days, 30 days, 90 days (the default), 1 year, never, or a custom date. The list shows the expiry and marks expired keys.
2. **Scopes.**
   - Widen the `scopes` CHECK constraint, in the new migration and not by editing `000051`, to cover these scopes:
     - `engagement:read`
     - `guides:read`
     - `guide_posts:read` and `guide_posts:write`
     - `events:read` and `events:write`
     - `venues:read`
   - `write` implies `read` for the same resource.
   - The constant set lives in `internal/apitokens`, with `IsKnownScope` and a guard test asserting the Go list and the migration's array match.
   - The admin UI picks scopes with checkboxes grouped by resource, and offers a preset, "Agent (all guide and event scopes)".
3. **The token in context.** `RequireAPIToken` puts the resolved token in the request context. The scope check accepts a required scope or the matching write scope.
4. **Audit attribution.**
   - Writes made with a token record an actor of `token:{id}`, plus the token's name, display prefix and `created_by`, in audit metadata.
   - The audit UI shows "via API key «name»".
   - Never record the secret.
5. **Rate limit.** Use the existing rate-limit middleware, with a per-token bucket for v1, for example 120 requests a minute. Over the limit gets a 429 with `Retry-After`.

## Acceptance criteria

- Expired and revoked keys both get a 401 with an identical body.
- A scope a key lacks gets a 403.
- `last_used_at` throttling is unchanged.
- Migration `000053` up and down applies cleanly against a database at version 52. Production is at 52, so `000051` must not be edited.
- Tests:
  - store tests for expiry;
  - middleware tests for expiry and write-implies-read;
  - a guard test for the scope list;
  - a jsdom test for the admin create form, covering the expiry choice and scopes.

## Fix

Implemented per `## Plan`.

- `migrations/000053_api_tokens_v2`: `expires_at TIMESTAMPTZ NULL` with `api_tokens_expires_after_created`; `api_tokens_scopes_check` dropped and re-added over seven scopes. `000051` untouched. The down restores the `engagement:read`-only check and **refuses** (check violation, no schema or row change) while a token holds a newer scope; golang-migrate then records 52 dirty, so recovery is `migrate force 53`, delete those tokens, retry. Documented in the down file.
- `internal/apitokens`: `ScopeEngagementRead`, `ScopeGuidesRead`, `ScopeGuidePostsRead`, `ScopeGuidePostsWrite`, `ScopeEventsRead`, `ScopeEventsWrite`, `ScopeVenuesRead`; `KnownScopes`; `ScopeSatisfies(granted, required)`. `Token.ExpiresAt`; `Create(ctx, name, scopes, createdBy, expiresAt *time.Time, now)`; `Resolve` adds `AND (expires_at IS NULL OR expires_at > now)`, so expired → `ErrNotFound` → the identical 401. `last_used_at` throttling unchanged.
- `internal/middleware`: the `*APIToken` principal is gone; `APITokenFromContext(ctx) (apitokens.Token, bool)` and `WithAPIToken` (for handler tests). Scope check is `ScopeSatisfies`. `AttributeAPIToken(ctx, audit.Entry) audit.Entry`. `RateLimiter.MiddlewareByKey` (the per-IP `Middleware` delegates to it; both 429s now carry `Retry-After`), `NewAPITokenRateLimiter` (`APIv1RequestsPerMinute = 120`, burst 120), `APITokenRateLimit` keyed `token:{id}`.
- `internal/audit/apitoken.go`: `APITokenActor`, `AttributeAPIToken` — `ActorID` nil, metadata `actor: "token:{id}"` and `api_token: {id, name, prefix, created_by}` (`MetaActor`, `MetaAPIToken`). No secret field exists to fill.
- `internal/handlers/api_tokens.go`: optional `expires_at` on create (past → 400 "expiry must be in the future"); the view and the `api_token.created` audit row carry it.
- `cmd/opencircuit/main.go`: v1 routes are `RequireAPIToken → APITokenRateLimit(one shared limiter) → handler`; still GET-only (`#0675` widens methods).
- Web: `lib/apiTokens.ts` (scope groups, `AGENT_PRESET`, `EXPIRY_OPTIONS`, `expiryFromChoice`, `isExpired`, `expiresLabel`, "Expired …" status), `ApiTokens.svelte` (Expires select + custom date, grouped checkboxes, Agent preset button, Expires column, expired cell in the error colour), `admin.ts` `actorLabel` → "via API key «name»", `createApiToken(name, scopes, expiresAt)`.
- Docs: `docs/database.md` row + range, `AGENTS.md` §1 range, `docs/home-assistant.md` (create steps, expiry, 401/429 rows).

### Assumptions

- A token write's `actor_id` is NULL (a token is not a user); the attribution lives in metadata. `created_by` is recorded there, not as the actor.
- A custom expiry date expires at 23:59:59 on that day in the browser's time zone.
- No scope is pre-ticked in the create form; at least one must be chosen ("Choose at least one scope.").
- Requests that fail authentication are not counted against any bucket (the limiter sits inside `RequireAPIToken`, which needs the token id).
