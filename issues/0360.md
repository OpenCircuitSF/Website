## Description

`opencircuit_test` stamps `schema_migrations.version = 25, dirty = f`, while its
`subscribers` table has **24 columns** and is missing `soft_bounce_streak`,
`last_bounce_at`, and `last_delivery_at`. `opencircuit` — the user's dev
database, at version 24 — has the same gap.

**Confirmed independently by the orchestrator**: 24 columns, version 25, not
dirty.

**The version stamp does not detect this.** That is the whole problem: an agent
has no cheap signal that the database it is about to use disagrees with
`migrations/`.

### Why it matters, and what it already cost

Any run that falls back to the shared database — a bare `go test` with §5's
documented default `TEST_DATABASE_URL`, rather than
`ISSUE=NNNN scripts/check.sh` — gets `column … does not exist` errors that read
**exactly like flakes**. A read-only
`select soft_bounce_streak from subscribers limit 1` reproduces it verbatim and
deterministically; the same query against the template succeeds.

This already cost `#0356`'s fourth implementation pass a misattribution: it
recorded the failure as "concurrent schema drift from another session", which
was wrong in mechanism though right that it was not its own defect. `#0356`'s
third review ran it down: no migration changed today (newest `migrations/`
commit is `d9f877a`, 2026-08-27), and the per-agent template is **healthy** —
v25, clean, 27 `subscribers` columns, `soft_bounce_streak` present.

### A second, related half

`scripts/testdb.sh` now reports that the **template's content digest disagrees
with `migrations/`**, though both are at 25 — so every agent is silently
falling back to direct provisioning instead of the ~0.2s clone. `#0123` amended
`migrations/000025` in place on 2026-08-27, which fits the timing.

## Obstacles (§5b) — read before acting

**Neither repair is safe to run unilaterally**, which is why this is filed
rather than fixed:

- `scripts/db-reset.sh --force` targets `opencircuit` **and** `opencircuit_test`.
  `opencircuit` is the **user's dev database**. §5a records that `db-reset.sh`
  refuses without `--force` precisely because a bare invocation used to
  terminate every other connection unconditionally.
- `scripts/testdb.sh template` rebuilds the shared template. An agent cloning
  from it mid-run would be affected.

**Ask before running either, and confirm no other session is live.**

## Acceptance criteria

1. Both shared databases agree with `migrations/` — verified by **column
   census**, not by a version stamp.
2. The template's content digest agrees with `migrations/` again, so
   `scripts/testdb.sh` resumes cloning rather than silently falling back to
   direct provisioning. Confirm the clone path is actually taken, with timing.
3. **Consider extending `testdb.sh`'s digest check to the shared
   `opencircuit_test`.** A version stamp alone demonstrably does not detect
   this — that is the finding. If you judge it out of scope, say so with a
   reason; the judgement is part of the deliverable.
4. Whatever detection is added fails **closed** and names what disagrees, so
   the next agent gets a diagnosis rather than a column-not-found error that
   reads like a flake.
5. Nothing is run against `opencircuit` or the shared template without
   confirming no other session is live (§5a, §8b).
6. Guard-test changes, if any, respect §8's rules and the floor harness stays
   at **42 total / 12 non-exempt**.
