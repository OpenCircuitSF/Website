## Description

`#0181`'s pass-2 review measured the guard's coverage exactly — 82 glob keys against 82 files on disk, set-identical; 94 Go files collected against 94 non-test `.go` under `internal/` and `cmd/`, set-identical — and found four refinements worth making. None is a live leak.

**1. One non-test `.go` file is outside the walk's roots.** `web/embed.go` is the 95th; the walk covers 94. No exposure today (it is an embed directive), but "94 of 95" is an odd place for a guard whose whole purpose is not needing a boundary argument.

**2. `issues/NNNN.md` is absent from the pattern, though `docs/*.md` was added.** The widened pattern now catches `CLAUDE.md`, `PRD §`, `Issues.md`, `HANDOFF.md`, and `docs/*.md`. A path like `issues/0138.md` is the *least* readable of the set to an admin, and it is the one spelling not covered — an asymmetry rather than a decision.

**3. The `docs/\S*\.md` term would fire on an external URL** containing `/docs/x.md`. Nil in the tree today; worth a moment's thought about whether the pattern should require the path not be preceded by a scheme.

**4. The failure message's paths are inconsistent** — `./branding.ts` for `web/src/lib` files versus `views/...` for others. Cosmetic, but the message exists to be pasted into a search.

## Implementation notes

**Item 1 — Go walk widened to cover `web/`.** `web/embed.go` was the 95th
non-test `.go` file, outside both `scanGoRoots` entries (`..`, `../../cmd`).
Added `"../../web"`. Re-measured with a scratch probe reusing the shipped
`scanGoRoots` and walk predicate: **95 files collected, 95 non-test `.go` on
disk under `internal/` + `cmd/` + `web/`** (`find internal cmd web -name
'*.go' ! -name '*_test.go'`), set-identical in both directions (Python set
diff, both ways, empty). Before this change: 94 collected vs. 94 on disk
under `internal/` + `cmd/` only (the pre-existing pair), also set-identical
— confirming the widening added exactly the one file it should have and
nothing else. `_test.go` exclusion re-verified after widening: no
`_test.go` files exist under `web/` today, and the exclusion predicate
itself is unchanged, so the guard's own error string
(`"...#0172, #0175, #0178, #0181)"`) still cannot self-trip.

**Item 2 — `issues/NNNN.md` added to the pattern.** Both `citationPattern`s
(Go: `issues/[0-9]{4}\.md`; web: `issues\/\d{4}\.md`) gained the new
alternative. New tests added on both sides proving it fires
(`TestCitationPatternCatchesIssueFilePath` in Go; "fires on an
issues/NNNN.md citation" in web) and that it does not fire on ordinary
prose containing the word "issues".

**Item 3 — accepted, not tightened.** `docs/\S*\.md` (and now
`issues/[0-9]{4}\.md`) would fire on an external URL containing a matching
path segment (e.g. `https://example.com/docs/guide.md`). Decided to accept
the false positive rather than add a scheme exclusion, because: Go's
`regexp/syntax` (RE2) has no lookbehind, so the exclusion could only be
expressed in the web guard's V8 engine, not the Go one — tightening only
one side would leave the two guards' shared pattern text silently
diverged, which is a bigger maintenance hazard than the false positive it
prevents. The false positive is also nil today and structurally unlikely:
`CLAUDE.md` §9 forbids external CDNs, and the `#0181` pass-2 review's
whole-tree sweep found every existing `docs/*.md`-shaped occurrence in
scanned scope was a `//` comment, never a live literal. A documentation
test (`TestCitationPatternAcceptsDocsURLFalsePositive` / "documents the
accepted docs/*.md external-URL false positive") pins the accepted
behavior so a future change that silently closes or widens it shows up in
a diff. Both guards' `citationPattern` comment blocks record the same
reasoning in full.

**Item 4 — web guard's failure-message paths made consistent.** The old
normalization (`path.replace(/^\.\.\//, '')`) only stripped a leading
`../`, which is what `import.meta.glob('../**/*.{ts,svelte}')` yields for
files reached by going up from `web/src/lib/` (this file's own directory)
— but files in that *same* directory (e.g. `branding.ts`) yield a `./`
prefix instead (measured directly via a throwaway probe test: keys are
`../App.svelte`, `./branding.ts`, `../main.ts`,
`../views/admin/WorkshopEditor.svelte`), which the old code left
untouched. Result: `./branding.ts` vs `views/admin/WorkshopEditor.svelte`
in the same failure message — two different reference points (one
relative to `web/src/lib/`, one to `web/src/`), neither pasteable as a
repo path without knowing which. Added `toRepoRelativePath`, which
produces one consistent repo-relative form for both shapes:
`web/src/lib/branding.ts` and `web/src/views/admin/WorkshopEditor.svelte`.
Confirmed live in the Svelte real-string regression proof below — the
failure now reports `web/src/views/admin/WorkshopEditor.svelte:552`. The Go
guard's message paths were already one consistent form (absolute, since
`baseDir` from `runtime.Caller(0)` is absolute and every `scanGoRoots`
entry is joined onto it) — no change needed there.

### Item 2 — the two patterns are exactly equivalent

Extracted both `citationPattern`s verbatim into a Go program and a Node
module and ran them over a shared 38-case battery. `issues/[0-9]{4}\.md`
(Go) and `issues\/\d{4}\.md` (web) agree on every case, including the
Unicode-digit shapes the asymmetry between `[0-9]` and `\d` could have
produced: `issues/٠١٢٣.md` (Arabic-Indic), `issues/𝟎𝟏𝟐𝟑.md`
(MATHEMATICAL BOLD DIGIT), and `issues/０１２３.md` (fullwidth) are **missed by
both**. The web regex carries no flags at all (`flags: ""`, `unicode=false`,
`unicodeSets=false`), and JavaScript's `\d` is ASCII-only regardless of `u`
or `v` — there is no Unicode-digit surprise here. `issues/0138.md` fires on
both; `"see the issues tracker"` fires on neither.

**But the two patterns are not equivalent overall, in a term this pass did
not touch.** `PRD\s*§` diverges, because Go's `\s` is `[\t\n\f\r ]` while
JavaScript's includes the Unicode space separators. Five cases in the
battery disagree:

| Case | Go | web |
|---|---|---|
| `PRD<U+00A0>§6.6` (non-breaking space) | miss | catch |
| `PRD<U+2009>§6.6` (thin space) | miss | catch |
| `PRD<U+000B>§6.6` (vertical tab) | miss | catch |
| `PRD<U+FEFF>§6.6` (ZWNBSP) | miss | catch |
| `PRD<U+3000>§6.6` (ideographic space) | miss | catch |

Pre-existing — introduced with `PRD\s*§` in `#0181` pass 2, not by this
pass — and out of `#0187`'s scope, so not a bounce. It is worth filing: a
non-breaking space before `§` is exactly what pasting copy out of a word
processor produces, and it is the one shape where the two halves of a guard
built to be one guard silently disagree. Reported to the orchestrator
(§9).

### Item 3 — the decision stands; its stated reason does not

The decision itself is squarely inside the acceptance criterion, which
offers "accepting the false positive as vanishingly unlikely and cheaper
than the complexity" as one of two valid outcomes. It is nil in the tree,
would require a live string literal holding an external URL to a
`docs/*.md` path in admin-facing copy, and the cost of closing it is real
but small. Accepting it is a defensible call and it is recorded in three
places. **Not a bounce.**

The supporting argument, however, is wrong where it is most emphatic. Both
comment blocks say a scheme exclusion "could be added here in V8 but could
not be mirrored there" because RE2 has no lookbehind. RE2 having no
lookbehind is true; the inference is not. A scheme exclusion does not
require lookbehind — a **consumed** boundary expresses it, and the
resulting pattern is valid in both engines verbatim:

```
(?:^|[^:/\w])docs/\S*\.md|(?:^|[^:/\w])issues/[0-9]{4}\.md
```

Built and ran it in Go: it reports `docs/architecture.md`,
`(docs/architecture.md)`, `` `docs/architecture.md` ``,
`"docs/architecture.md"`, `see issues/0138.md`, and the bare forms, and
rejects `https://example.com/docs/guide.md`,
`see https://example.com/docs/guide.md for details`, and
`http://example.com/issues/0138.md` — intent matched on 13/13 cases. A
second RE2-compatible form (keep the shipped pattern, strip
`[a-zA-Z][a-zA-Z0-9+.-]*://\S*(?:docs/\S*\.md|issues/[0-9]{4}\.md)` and
re-test) also matched 13/13. So the divergence hazard the comment invokes
is not the reason to accept — cost against a nil risk is. That is enough
on its own, which is why this resolves; but the comment as written will
tell the next engineer something untrue about RE2, and the "the two guards
must not diverge" premise is undercut by the `PRD\s*§` divergence measured
above, which already exists. Reported as a filing candidate.

**The documentation test does pin behaviour, and is not a tautology.**
Proved by mutation: swapped the shipped Go pattern for the consumed-boundary
form above and re-ran the pattern tests —
`TestCitationPatternAcceptsDocsURLFalsePositive` **FAILED**, while
`TestCitationPatternCatchesIssueFilePath` and

### Reported for filing (§9 — not filed here)

1. **`PRD\s*§` means different things in the two guards.** Measured above:
   five whitespace shapes, non-breaking space among them, are caught by the
   web half and missed by the Go half. A shared character class on both
   sides closes it.
2. **Item 3's recorded reasoning is wrong about RE2.** The comment blocks
   in both guards claim a scheme exclusion is inexpressible without
   lookbehind; two RE2-compatible forms are demonstrated above. Either
   correct the comment or adopt the consumed-boundary form, which keeps the
   two patterns textually identical and costs 24 characters.
3. **The `web/` root walks `web/node_modules` and `web/dist`.**
   `filepath.WalkDir` descends into both. There is no `.go` file under
   either today (the 95/95 measurement confirms it), but an npm dependency
   shipping Go source would be parsed by the guard, and a parse error there
   is a `t.Fatalf` — an unrelated dependency bump could take the guard down.
   Skipping `node_modules` and `dist` in the walk predicate is a two-line
   change.
4. **The shape matrix should be committed, not re-derived.** `#0181`'s
   pass-2 review, `#0187`'s implementation, and this pass have each rebuilt
   the same 20–34 case matrix in a scratch probe and deleted it. The
   evidence for the guard's most contested property — what it deliberately
   misses — exists only in three sets of prose notes. Committing it as a
   fixture-driven table beside the existing tests would make the next pass a
   test run instead of an afternoon.

Minor, not worth an issue on its own: `toRepoRelativePath`'s else branch
assumes a `./` prefix (`globKey.slice(2)`) and would mangle a bare key.
Vite emits none today and the 83/83 check confirms it, so it is noted here
rather than filed.
