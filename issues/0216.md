## Description

`#0120`'s phase-3 review passed the fix and found three comment inaccuracies in
the two new test files. No behavioural impact — but the first one overstates
what the tree proves, which is the defect class this repo has now hit four times
(`#0190`, `#0192`, `#0196`, `#0199`).

**1. It cites three tests that do not exist.**
`web/src/lib/modalKeydown.test.ts` names
`Admin.escapeWiring.structuralGuard.test.ts`,
`CampaignEditor.escapeWiring.structuralGuard.test.ts`, and
`Campaigns.escapeWiring.structuralGuard.test.ts` as proving the panel wiring.
None exists.

**Worse than a dangling pointer: the claim itself is false.** Nothing asserts
the *positive* wiring — that each panel's `onkeydown` is bound to the same node
its focus effect targets. `modalEscapeGuard.test.ts` asserts only the **absence
of the bad shape**. So a reader is told the wiring is pinned when it is not.

`#0196` built a guard against exactly this — a comment citing a `Test*`
identifier no function defines — but it scans **Go** comments only. These are
TypeScript.

**2. A stale reason for a real conclusion.** `modalEscapeGuard.test.ts`'s header
says `CampaignSendDialog`'s panel `onkeydown` "was deleted outright". That
describes the **abandoned first attempt**; what shipped binds `handleKeydown` to
the panel, deliberately, so `#0197`'s pinned expression stays byte-identical.
The conclusion holds, the stated reason does not.

**3. A miscount.** The same header says "nine sites across three files". The
review enumerated from the pre-fix blobs: **8 sites across 4 files**
(`Admin.svelte` ×5, `CampaignEditor` ×1, `CampaignSendDialog` ×1, `Campaigns`
×1). The `WorkshopEditor`/`Workshops` hits a naive grep returns are comment text
inside `#0052`'s own notes describing the shape it removed.

**`#0094`'s new test file has two more of the same defect**, found by its own
review: its header cites `web/HANDOFF` (no such file — `web/` has no `.md` at
all) and "see this repo's `CLAUDE.md` §… discussion" with a literal unfilled
ellipsis. Same class, same commit family, so they are folded in here.

**The stale claim has already propagated once.** `#0094`'s implementation
notes repeat it — describing `CampaignSendDialog`'s panel `onkeydown` as
"deleted outright" — because it read `modalEscapeGuard.test.ts`'s header and
believed it. That is what a false comment costs: not the original error, but
every reader downstream. Check `issues/0094.md` when fixing item 2.

## Implementation notes

**Verified each false claim against the current source before rewriting it, per the
brief.** `CampaignSendDialog.svelte` (lines 105–156) binds `onkeydown={handleKeydown}`
on *both* the backdrop (146) and the panel (156) — its own doc comment already says so
("Fixed by binding this SAME function ... to the panel's own onkeydown too") and even
names the a11y rule (`a11y_click_events_have_key_events`) that made the abandoned
delete-outright attempt fail `svelte-check`. `modalEscapeGuard.test.ts`'s "was deleted
outright" line described that abandoned attempt, not what shipped. The miscount was
also confirmed directly: `Admin.svelte` x5 + `CampaignEditor.svelte` x1 +
`Campaigns.svelte` x1 + `CampaignSendDialog.svelte` x1 = 8 sites / 4 files; the two
`#0052` sites (`WorkshopEditor.svelte`, `Workshops.svelte`) are separate and predate
this issue, so folding them into "nine … three files" was simply arithmetic error in
the original header, now corrected to state both counts separately.

**The real work (criterion 3): `web/src/lib/modalFocusWiring.structuralGuard.test.ts`.**
Chose the structural/AST route over mounting, deliberately, over
`CampaignSendDialog.behavior.test.ts`'s worked example: `Admin.svelte` is 2200+ lines
with five independent modal branches, `CampaignEditor.svelte` is 1094 lines, and
`Campaigns.svelte`'s "New campaign" modal opens from a component whose own `onMount`
calls `listCampaigns()` over the network (flagged as a mounting complication in
`#0094`'s own notes). Mounting all three cheaply enough to cover every one of the
seven remaining sites was out of proportion to this issue; behavioural evidence stays
the stronger kind where it already exists (`CampaignSendDialog`), and the new guard
says so in its own header rather than silently picking one approach.

The guard's check, per `role="dialog" aria-modal="true"` panel that carries
`bind:this={V}`: (1) the SAME element must also carry `onkeydown` (an AST fact — two
attributes on one node), and (2) the file's source must contain
`tick().then(() => V?.focus())` using that exact bound identifier (a targeted regex,
not a generic "does `.focus()` appear anywhere" check). Chaining the two proves the
node carrying `onkeydown` is the node the focus effect targets, without needing to
parse the effect body itself. Ran against the real tree: found 11 sites (the 8 from
`#0120` + CampaignSendDialog's pre-existing wiring, plus `#0052`'s 3 earlier sites in
`WorkshopEditor.svelte`/`Workshops.svelte`, which the same shape happens to cover too),
zero violations.

**Vacuousness proof.** Edited `web/src/views/Admin.svelte` line 224 from
`if (deactivatingUser) void tick().then(() => deactivateModalEl?.focus());` to target
`editInterestModalEl` instead (a different modal's ref, still syntactically valid).
Reran the new guard: it failed at exactly that site
("`web/src/views/Admin.svelte:1171: panel's onkeydown lives on the element bound to
"deactivateModalEl", but no "tick().then(() => deactivateModalEl?.focus())" call was
found`"). Reverted the edit and confirmed byte-identity:
`shasum -a 256 web/src/views/Admin.svelte` before and after both hashed to

web/src/views/Admin.svelte` was empty throughout (the mutation was never committed or
left in a staged state).

**`modalKeydown.test.ts`'s comment now claims, accurately:** this file proves only

## Notes

Reported by `#0120`'s phase-3 review under `CLAUDE.md` §9.

Criterion 3 is the one with lasting value and the only one that is real work.
The review traced the Deactivate path by hand — `deactivateModalEl` bound on the
`role="dialog"` panel carrying `tabindex="-1"`, focused by the `$effect`, with
that same node's `onkeydown` calling `isModalEscape` — and confirmed it is one
DOM node. **Seven sites rest on that equivalence and one was checked.** A guard
asserting it would be worth more than the comment fix.

Two facts from the review worth keeping while working here:

- All five `Admin.svelte` panels carry `tabindex="-1"`, without which `focus()` is a silent no-op. That prerequisite is currently unguarded too.
- `dismissible` is **not threaded from any call site** — all seven pass the default, and the one site that would pass `false` is the one that does not call the helper. The parameter is exercised only by its unit tests today.

`#0120`'s AST guard has two deliberate narrownesses, recorded and accepted: it
requires **both** `role="dialog"` and `aria-modal="true"`, and globs `views/**`
only, so a future modal under `web/src/lib/` is out of reach.
