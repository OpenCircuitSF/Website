## Description

`issues/Issues.md`'s phase-3 approve step requires adding a `**Closed**` row
carrying the date. **23 of 377 `resolved` issues have none.**

Confirmed independently by the orchestrator: 377 files carry
`| **Status** | resolved`, and 23 of those have no `| **Closed**` line.

The list, from `#0413`'s review: `#0084`, `#0087`, `#0123`, `#0233`, `#0270`,
`#0274`, `#0291`, `#0292`, `#0293`, `#0300`, `#0301`, `#0304`, `#0308`, `#0309`,
`#0315`, `#0321`, `#0322`, `#0323`, `#0327`, `#0328`, `#0347`, `#0377`, `#0391`.
**Re-derive it rather than trusting it** — see criterion 1.

## Why it is worth closing

This is not tidiness. **It already cost a detour this session.** `#0412` needed
`#0293`'s resolution date to write one sentence; the field was absent, so the
date had to be reconstructed from `git log` on the resolution commit and then
corroborated against a same-day review commit before it could be trusted.

That is the shape this whole family keeps producing — a fact that should be
recorded in one obvious place instead being inferred, with the inference
sometimes going wrong. `#0407`, `#0414`, `#0418` and `#0419` are all the same
class.

**A commit date is not the same fact.** It records when bytes landed, not when
an issue was judged done. For most issues those coincide; for a bounced one they
need not.

## The important nuance, from the review that found it

**The guard matters more than the backfill.** Backfilling these 23 means taking
their dates from git — the very inference this issue exists to remove — so the
backfill inherits whatever uncertainty git leaves. What actually prevents
recurrence is a check that a `resolved` issue carries a `Closed` row.

So treat the guard as the deliverable and the backfill as the cleanup, not the
other way round.

## Acceptance criteria

1. **Re-derive the set of offending files yourself.** Do not trust the list
   above; it is transcribed, and this issue is about not trusting transcribed
   facts. Report the count you measure and any disagreement.
2. A guard fails when an issue is `resolved` and has no `Closed` row. `internal/db`
   already scans `issues/` and owns comparable parity checks — put it there.
3. **Prove the guard discriminates**: it must fail naming the offending file
   when a `Closed` row is removed from a resolved issue, and pass on the
   unmutated corpus. Score by `go test` exit code with a passing control. A
   check that cannot fail is this phase's recurring defect (`#0354`, `#0358`,
   `#0363`, `#0400`).
4. **Do not let the guard block on the backfill.** If the 23 are backfilled
   first, the guard has no live specimen and its own proof is a mutation — say
   which order you chose and why.
5. Backfilled dates are derived from git and **the derivation is stated** — for
   each, which commit and how it was corroborated. Where git is ambiguous, say
   so rather than picking a date. A wrong date recorded confidently is worse
   than an absent one.
6. **No mechanism beyond the one guard** (`#0330`/`#0347`/`#0356`/`#0381`).
   Note `#0347` is itself on the offending list, which is a small irony worth
   not compounding.
7. Run `./internal/db/...` and `./internal/handlers/...` (`#0381`). Per §5 name
   the specific tests that ran. `gofmt` stability. No Go-file-plus-line-number
   citation (`#0352`), scanned with `python3` bytes rather than BSD `grep -P`.
