## Description

`outreach_channels` defaults to `bluesky,mastodon,instagram`, and production has no saved value, so TikTok and YouTube never appear. The site cannot post to Instagram, TikTok or YouTube, but the user posts there by hand and needs a ShortLink for each.

## Plan

Written 2026-11-04 against `b685ffef`. `#0622` lands first and changes front-end files, so find the anchors below by name, not by line. Everything runs against the fake ShortLinks client and a local database: no production write and no outward call is part of this issue.

### What the code does today

**When ShortLinks are created for hand-posted channels, and by what call.** `h.links.CreateLink` runs in two places:

1. `ensureLinks` in `internal/handlers/admin_outreach_links.go`, for every enabled channel by every wave, plus flyers. It is reached from `Start`, only on the call that creates the outreach row (`POST /admin/workshops/{id}/outreach`), and from `CreateLinks` (`POST .../outreach/links`), which **nothing in the SPA calls**: `createWorkshopOutreachLinks` in `web/src/lib/api.ts` has no caller outside a test mock.
2. `Prepare` (`POST /admin/outreach-posts/{id}/prepare`), for that one post, when the composer's create-link action runs.

So a channel switched on after Start gets a link only when someone opens a drafted post and creates it by hand. Its links are never created ahead of a post. `Prepare` does not cover the criterion, because it needs a post row first and makes one link at a time.

**How existing workshops get drafts for a newly enabled channel.** Never on read and never on prepare. `GET` is read-only by design (the header comment in `OutreachPanel.svelte`). A draft comes from `DraftAll` (the Write button, shown for a wave only while it has no posts) or `CreatePost` (a card's Draft button). Once a wave has posts, a newly enabled channel just sits as a "Not drafted" card until someone clicks it.

**Could the existing paths touch posted or scheduled rows, or mark a draft stale?** No. `CreatePost` is an insert and returns `ErrPostExists` on a taken slot. `SetPrepared` updates one row by id, guarded by `short_link_key IS NULL AND status <> 'posted'`. `Fingerprint` reads only workshop facts and has no channel input, and a new draft stores the current fingerprint, so neither old nor new rows go stale. The new path below only ever calls `SetPrepared` on a row it just inserted.

**Does production need a data migration?** No. Production has no `outreach_channels` row, so `Manager.Value` returns the field's `Default` and the new default takes effect on the next deploy. The field has no `EnvVar`. `outreach_links` and `outreach_posts` accept these channels already, and a saved value still wins. Schema stays at 48. What the default change does not do is create links or drafts for existing workshops, so that needs the small new path below.

### Two traps this design avoids

- **A draft in an unwritten wave changes automatic behaviour.** `PlanScheduleAll` treats any post in a wave as "this wave is drafted" and then lists Bluesky and Mastodon as `not_drafted`. `waveRowStatus` flips the same wave from Write to open. So new hand-posted drafts go only into waves that already have a visible post. Links are still made for all three waves.
- **Re-creating a deleted draft.** Filling every empty slot on each page open would bring back a draft the user deleted, and there is no tombstone. So a draft is created **only in the same pass that creates that slot's link**. A slot whose link already exists is left alone. `Store.Reset` keeps `outreach_links`, so a reset outreach stays empty too.

**New `internal/handlers/admin_outreach_handlinks.go`**

- `handPostedChannels()`: `h.enabledChannels()` where `!ch.Automatic`. Use the static flag, never `channelConfigured`.
- `EnsureHandLinks` for `POST /admin/workshops/{id}/outreach/hand-links`. Guards in the same order and with the same messages as `CreateLinks`: 401, 503 when `!h.linksEnabled()`, `workshopOutreach`, 409 with no outreach, 409 when not published. Then:

```go
posts, err := h.store.ListPosts(ctx, o.ID) // before any write; store error is a 500
report, err := h.ensureLinksFor(r, actor.ID, *o, wk, h.handPostedChannels(), false)
// have[slot] from all posts, including hidden ones
// waveHasPost[wave] from h.enabledPosts(posts) only, matching what the panel shows
f := h.facts(wk)
for _, l := range report.createdLinks {
    if !waveHasPost[l.Wave] || have[[2]string{l.Channel, l.Wave}] { continue }
    ch, _ := outreach.ChannelByName(l.Channel)
    wv, _ := outreach.WaveByName(l.Wave)
    p, err := h.store.CreatePost(ctx, o.ID, l.Channel, l.Wave, outreach.Draft(ch, wv, f), outreach.Fingerprint(f))
    // outreach.ErrPostExists: continue. Any other error: 500.
    // h.store.SetPrepared(ctx, p.ID, l.Key, l.ShortURL, "manual"); error: 500.
    report.Drafted++
    // Audit as DraftAll does: ActionOutreachPostCreated with outreach_id, channel, wave, bulk: true, link_applied: true.
}
writeJSON(w, http.StatusOK, report)
```

A ShortLinks failure never reaches the status code. It is in `report.Failed`, as it is for `CreateLinks`. A failed slot has no link and so no draft, and the next pass does both.

## Obstacles

- **Tools and grants:** `psql`, `migrate` and `npm` are present. `CREATEDB` is already granted. Nothing to clear.
- **Credentials:** none needed. ShortLinks is the fake in the handler tests. No SES, Bluesky or Mastodon call.
- **Approval-gated steps:** none in this issue. The real ShortLinks calls happen only when the user opens the page after deploying.
- **Shared files:** `#0622` lands first and is expected to edit the Outreach view files. Re-read `OutreachPanel.svelte` and `OutreachScheduleAllDialog.svelte` before editing, and stage only your own hunks (`AGENTS.md` §8a).
- **Shared resources:** tests use the `ISSUE=0623` database. No server or port and no write to `web/dist`.
- **Citation guards:** Go comments describing the new path should not quote a banned shape. `internal/handlers` is in the scoped run, so a trip shows up there.
- **Production fact not proved from code:** v0.1.2 has no outreach migrations and v0.2.0 is the first tag with them, so every production outreach should have started under the three-channel default, with no TikTok or YouTube link rows. An untagged deploy in between would break that. Such a workshop would get its links' drafts only from the card's Draft button, under the rule that a draft comes only with a newly created link. The orchestrator can confirm this with the read-only query in its report. It does not block implementation.
