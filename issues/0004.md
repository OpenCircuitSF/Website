## Description

Keep only the migrations that build the auth and admin schema, renumber them to a contiguous `000001`–`000007`, and confirm a clean `up` and `down` against a real PostgreSQL database.

## Acceptance criteria

- [ ] Retained and renumbered: users, pending_registrations + passkey_credentials + webauthn_challenges, sessions, settings, audit_log, passkey backup flags, session-passkey NOT NULL enforcement
- [ ] Deleted: all links, clicks, campaigns, url_filter_rules, and UTM migrations
- [ ] The `settings` seed row set is reviewed — `registrations_enabled` stays, shortener-specific keys removed
- [ ] `migrate -path migrations -database $DATABASE_URL up` applies cleanly against an empty database
- [ ] `migrate ... down` reverses cleanly with no orphaned objects
- [ ] `scripts/db/` create/drop SQL updated for the `opencircuit` role and database name

## Notes

PRD §6.2 (bottom) lists which auth tables carry over. Squashing the two later fixups (backup flags, session NOT NULL) into the base migrations is acceptable and preferable here — there is no deployed database to migrate, so the history has no value.

Verify against real PostgreSQL, not the JSON dev store. `internal/testdb` exists for this.
