## Description

Copy rendered to an admin in the workshops editor cites this project's internal tracker and its agent-guidance file:

- the cover-image hint renders **"(#0138: no upload endpoint exists, by design — see PRD §5.2)"**
- and **"(CLAUDE.md §9: no external CDNs)"**

An admin has no idea what `#0138` is, has never read `CLAUDE.md`, and cannot act on either reference. The *facts* are useful — you must paste a path, images live on this site — but the citations belong in code comments, where the next engineer will look, not in the interface.

## Acceptance criteria

- [x] Admin-facing hint text states the rule and what to do about it, without issue numbers, `CLAUDE.md` sections, or PRD references
- [x] The reasoning and the citations move to a code comment beside the string, so nothing is lost for the next reader
- [x] Sweep the rest of the admin console's user-visible copy for the same thing — this was found in one hint, and copy tends to be written the same way twice
- [x] `scripts/check.sh web` passes

## Root cause

Two admin-facing strings were written the same way: state the rule, then cite the internal source for it, as if the reader could follow the citation. Neither citation is actionable to an admin — `#0138` and `#0038` are rows in this repo's issue tracker, and `CLAUDE.md §9`/`PRD §5.2` are sections of files an admin has never opened.

- `web/src/views/admin/WorkshopEditor.svelte`'s cover-image hint: `"...there is no upload control here (#0138: no upload endpoint exists, by design -- see PRD §5.2) and an external URL is not accepted (CLAUDE.md §9: no external CDNs)."`
- `web/src/views/Admin.svelte`'s empty email-event-history state (found during the sweep, not named in the issue body): `"No events recorded yet. SES bounce/complaint ingestion (#0038) fills this section in once it lands."`

## Fix

Rewrote both strings to state the fact and, where there is one, what to do about it, with no issue numbers or doc-section citations. Moved the reasoning and citations to a code comment directly beside each string (an HTML `<!-- -->` comment in both cases, since both sites are template markup, not `<script>` blocks):

- Cover-image hint now reads: *"A site-relative path (e.g. "/assets/workshops/soldering.jpg") to an image already hosted on this site. There is no upload control here, and external image URLs are not accepted."* The `#0138`/PRD §5.2/CLAUDE.md §9 citations moved to a comment immediately above the `<p>`.
- Email-event-history empty state now reads: *"No events recorded yet. Bounce and complaint tracking will appear here once it's set up."* The `#0038` citation moved to a comment immediately above the `{#if}` block.

**Sweep:** grepped `web/src` for `#0[0-9]{3}`, `CLAUDE.md`, `PRD §`, and `PRD.md`, then read every hit rather than trusting the grep. The pattern is extremely common in this codebase, but almost entirely as `<script>`/`<style>` code comments or file-header `<!-- -->` block comments — none of that is rendered to a user. Confirmed the only two user-visible occurrences were the ones above by extracting each admin `.svelte` file's markup (outside `<script>`) and re-checking, and by grepping specifically for the pattern inside quoted/template-literal strings across `web/src/lib/*.ts` (excluding `*.test.ts`) and `web/src/views/**/*.svelte`. Everything else found (`web/src/lib/workshopAdmin.ts`, `api.ts`, `campaignProgress.ts`, `campaigns.ts`, `subscribe.ts`, `Logo.svelte`, `PrivacyPolicy.svelte`, `SubscribeForm.svelte`, and others) is JSDoc or inline comments explaining *why* code is written a certain way — exactly where this kind of citation belongs, so left untouched.

**Duplicated bound:** folded in the `workshopAdmin.ts` nit while in the file. `MAX_WORKSHOP_CAPACITY = 2147483647` and the validation error message both hardcoded `2147483647`; the message now reads `` `Capacity must be a whole number between 1 and ${MAX_WORKSHOP_CAPACITY}.` ``. Confirmed byte-identical output (existing tests assert the literal string and still pass; also confirmed in the built bundle — see Verification).

### The independent sweep, on a different axis

Grepping for `#0NNN`/`CLAUDE.md`/`PRD §` finds citations; it cannot find copy
that leaks internal vocabulary *without* a citation. So the admin console's
rendered copy was extracted directly — `<script>`/`<style>`/`<!-- -->` stripped
from `Admin.svelte` and all six `views/admin/*.svelte`, text nodes and
`placeholder`/`title`/`aria-label`/`alt` attributes collected — and every
message string in the fourteen non-test `web/src/lib/*.ts` modules was read
with comments stripped. Findings:

- **No further tracker or doc citations exist in rendered copy.** The
  implementer's conclusion holds on this second axis.
- **No leak of the terms specifically looked for:** `goldmark`, `devstore`,
  `STORAGE=json`, a migration number, a Go type name, or an internal route
  path appear in no user-visible string.
- **But "the send worker" / "the worker" is rendered to admins in five
  places** — `Admin.svelte`'s physical-address hint ("the send worker refuses
  to start a campaign while this is empty"), `campaigns.ts`'s returned-to-draft
  explanation and both cancel-confirmation messages, `Campaigns.svelte`'s
  "Returned to draft — worker refused it" badge, and `CampaignEditor.svelte`'s
  "the worker may be paused or waiting on send-rate limits". This is the same
  family as this issue — naming an internal component at someone who cannot see
  it — reached by a different route, and it is invisible to a citation grep. It
  is outside this issue's acceptance criteria (which name citations), so it is
  reported rather than folded in.
- Judged fine on inspection: `admin.ts`'s `${entry.target_type} #${entry.target_id}`
  and the `e.g. email_campaign` placeholder render the audit log's own stored
  values, which the admin sees in that table anyway (`#0114`); `api.ts`'s
  `HTTP ${res.status}` fallback is a last-resort error string, not an
  explanation; "slug", "double opt-in", "draft", and "Markdown" are product
  vocabulary an admin meets in the interface itself; Gmail's 0.3% complaint
  limit is an external, checkable fact.

### Accuracy of the `Admin.svelte` empty state, against `#0038`'s real status

`#0038` is **`resolved`** (closed 2026-08-20), and the ingestion is wired —
`sesnotify.NewStore` and `sesnotify.NewVerifier` are constructed in
`cmd/opencircuit/main.go` with a wiring test beside them. So:

- The **user-visible** string is honest. "Bounce and complaint tracking will
  appear here once it's set up" reads as configuration, and the configuration
  genuinely is not done — `CLAUDE.md` §10 open item 2 (SES domain verification,
  DKIM, production access) is "not started", so no event can arrive yet. It is
  also strictly more accurate than the string it replaced, which asserted that
  `#0038` had not landed.
- The **comment** above it is not. "Empty today because SES bounce/complaint
  ingestion (`#0038`) hasn't landed yet" states something false about a
  resolved, wired issue — it carries forward the old string's stale premise
  into the one place this issue says the truth should live. Not grounds to
  bounce a change whose criteria are all met and whose user-visible copy is
  correct, but it should be corrected to say the code has landed and what is
  missing is the SES/SNS configuration.

### Smaller notes, none blocking

- `WorkshopEditor.svelte`'s new comment reads "(`#0051`'s API, struck by
  `#0138` — see PRD §5.2)". What `#0138` struck was `#0052`'s "upload or path
  entry" criterion, not `#0051`'s API; `workshopAdmin.ts`'s own comment states
  this correctly.
- The hint tells the admin to paste a path to an image "already hosted on this
  site", and there is still no product path to get an image there — `#0138`'s
  known, deliberate gap, not a regression here. The copy describes the
  validator correctly; the capability gap is elsewhere.
- User-visible copy is inconsistent about dashes: the two `WorkshopEditor.svelte`
  strings and two `workshopAdmin.ts` messages use `--` where the rest of the
  console uses an em dash. The new hint itself avoids the problem.
