## Description

Found by `#0735` pass A's review. The entry chunk `index-*.js` measures **60,445 B** gzipped after `#0735` pass A, up from 59,941 B before it. That is about 380 B over PRD §7.6's 60 KB budget, read in decimal KB as `#0717` read it. The Docs view is its own lazy chunk; what pushed the entry over is routing code that has to load up front. The earlier Raspberry Pi guide work had already left only about 120 B of headroom.

The reviewer found where the real headroom is. `about.json` and all of `privacy.json` load in the entry chunk, through `links.ts`, `pageTitle.ts` and the About and Privacy views, which are not lazy.

## Acceptance criteria

- [ ] About and Privacy become lazy routes through `routeViews.ts`, following `#0717`'s pattern, including recovery when a stale chunk fails to load.
- [ ] `links.ts` and `pageTitle.ts` no longer import `privacy.json` or the body of `about.json` into the entry. Take only the small fields they need, or move those fields into a small module.
- [ ] Measured with `vite build --outDir <scratch>`, never into `web/dist`: the gzipped entry chunk for `/` is at most 60,000 B, with the before and after numbers recorded.
- [ ] A size guard keeps it from creeping back: a test or script check that fails above the budget. It runs in `scripts/check.sh web` if that is cheap; otherwise in `guards`.
- [ ] `/about` and `/privacy` still render from a cold load and on reload. The single-source guards (`#0520`) stay green.

### Measured

Built with `npx vite build --outDir <scratchpad>` (never `web/dist`). Sizes are Node `zlib.gzipSync` at its default level; `gzip -c file` reads about 18 B higher because it stores the file name.

| Build | Entry `index-*.js`, gzip | Change |
|---|---|---|
| `1125d8f4` (HEAD) | **60,520 B** (`gzip -c`: 60,538) | 520 B over |
| About and Privacy lazy, JSON still imported by `pageTitle.ts` and `links.ts` | 58,966 B | −1,554 B |
| About and Privacy lazy, and neither `pageTitle.ts` nor `links.ts` imports content JSON | **55,397 B** (`gzip -c`: 55,415) | −5,123 B, **4,603 B headroom** |

The prototype built in a throwaway worktree. In it, `pageTitle.guard.test.ts`, `routeReload.behavior.test.ts`, `routeViews.test.ts` and `staticPage.test.ts` all passed (56 tests). The new chunks are `About` at 1.10 kB gzip, `PrivacyPolicy` at 3.37 kB, and a shared `StaticPage` chunk that `Docs` also uses.

The reviewer's claim holds. `about.json` (1,839 B minified, 917 B gzip alone) and the whole of `privacy.json` (7,862 B, 3,161 B gzip alone) are in the entry. Each has three importers: `pageTitle.ts` reads both `h1`s, `links.ts` reads `about.json`'s `links`, and the eager `About.svelte` and `PrivacyPolicy.svelte` read the whole files. Removing the JSON saves 3,569 B in place. Making the views lazy saves another 1,554 B, because `StaticPage.svelte`, `staticPage.ts` and the two view shells leave with them. The sourcemap does not show the JSON as its own source: Rollup leaves the JSON modules unmapped, so their bytes count toward the preceding mapped module. That is why the variant builds above are the measurement, not a sourcemap sum.

The rest of the entry is the Svelte runtime (about 25.6 KB gzip alone), `stores.ts`, `api.ts`, `branding.ts`, `router.ts`, `Home.svelte` and `crtScreen.ts`. None of that has to change for this issue.

### Files and approach

1. **`web/src/lib/routeViews.ts`.** Add two entries to `LAZY_ROUTE_LOADERS`, after `docs`:
   `about: () => import('../views/About.svelte'),`
   `privacy: () => import('../views/PrivacyPolicy.svelte'),`
   Nothing else changes. Stale-chunk recovery, `routeViewReady` (which `main.ts` waits on before mounting), hover prefetch and `preloadForRoute` all go through `lazyKeyForRoute`, so the two routes pick them up automatically.
2. **`web/src/App.svelte`.** Delete the `import About …` and `import PrivacyPolicy …` lines. Replace `<About />` with `<LazyView key="about" />` and `<PrivacyPolicy />` with `<LazyView key="privacy" />`. Do not touch any other line.
3. **`web/src/lib/pageTitle.ts`.**
   - Delete the two `../content/*.json` imports.
   - Set `about: \`About ${APP_NAME}\`,` and `privacy: 'Privacy Policy',`.
   - Rewrite the two entry comments. Say that each is "guarded": `pageTitle.guard.test.ts` follows the view, through `<StaticPage content>`, to the JSON's `h1`, and asserts it equals this literal. Say that it is a literal, not an import, so the JSON body stays out of the entry chunk (`#0736`).
   - `docsPages.ts` already uses this literal-plus-parity-test pattern; cite it.
4. **`web/src/lib/links.ts`.**
   - Delete the JSON import.
   - Write `export const DISCORD_URL = 'https://discord.gg/Fq9ug6QXV3';` and `export const LUMA_URL = 'https://luma.com/opencircuitsf';`, copied from `about.json`'s `links` map. Keep the same single quotes and exact spelling, because the Go test below matches them byte for byte.
   - Rewrite the `#0520` paragraph to say: these are literals so the entry does not carry `about.json`, `about.json` stays the source, and `internal/seo`'s `TestLinksTSMatchesAboutJSON` fails if either literal drifts from it.
5. **`internal/seo/staticpages_test.go`.**
   - In `TestStaticSourceIsTheOneSource`, delete the `{"web/src/lib/links.ts", "../content/about.json"}` row and fix its doc comment so it no longer says `links.ts` re-exports from the JSON.
   - Add `TestLinksTSMatchesAboutJSON`. It reads `repoPath("web/src/content/about.json")` with `encoding/json`, into a struct with `Links map[string]string \`json:"links"\``, and reads `repoPath("web/src/lib/links.ts")`. For `discord`→`DISCORD_URL` and `luma`→`LUMA_URL`:
     - `t.Fatalf` if the JSON value is empty. Fail closed.
     - Otherwise assert that the source contains `export const <NAME> = '<url>';`.
   - The message names the constant and both values.
6. **New: `web/scripts/entry-budget.mjs`**, the size guard.
   - Use Vite's JS API, `import { build } from 'vite'`, with `root` set to the `web/` directory derived from `import.meta.url`.
   - Set `logLevel: 'warn'` and `build: { outDir: <fs.mkdtempSync(os.tmpdir()/oc-entry-budget-)>, emptyOutDir: true, manifest: true }`.
   - Read `<outDir>/.vite/manifest.json` and find the chunk with `isEntry: true` whose key is `index.html`. Use the manifest, never a regex over `index.html`; see AGENTS.md §8 on the comment that contains a script tag.
   - Collect the JS files in that chunk's **static** `imports` closure, recursively. Skip `dynamicImports`. Today the closure is just the entry. Also collect the `css` files of the same closure.
   - Sum `zlib.gzipSync(readFileSync(f)).length` for each set.
   - Fail closed (exit 2, with a message) if no entry is found or the JS set is empty, per AGENTS.md §8's "assert the extraction produced something".
   - Print one line per file, then `initial JS (gzip): N B / 60000 B budget — headroom H B`, and the same line for CSS against 15000.
   - Exit 1 if JS > 60000 or CSS > 15000. Name the constants `JS_BUDGET_BYTES = 60_000` and `CSS_BUDGET_BYTES = 15_000`, with a comment citing PRD §7.6, decimal KB as `#0717` read it, and noting that Node gzip runs about 18 B under `gzip -c`.
   - Remove the temp dir in `finally`.
   - Never write to `web/dist`.
   - No env or CLI override of the budget: a guard with a bypass knob is a bypass.
   - Measured cost is about 3 s per build, well under the 15 s bar, so it belongs in `check.sh web`.
7. **`web/package.json`.** Add the script `"budget": "node scripts/entry-budget.mjs"`.
8. **`scripts/check.sh`.**
   - In `web_check()`, add a third line after `npm test`: `step "entry-chunk budget (#0736, PRD §7.6)"; runpipe "cd web && npm run budget 2>&1 | tail -$TAIL"`.
   - Update the header's usage comment, `# just npm run check + npm test`, to name the budget step.
   - Add nothing else. This file is heavily self-guarded (§8, `#0258`): no new functions, and no `.` or `source` in command position.

`About.svelte`, `PrivacyPolicy.svelte`, `StaticPage.svelte` and the content JSON do not change. Do **not** edit `web/src/lib/Footer.svelte`: another agent has it dirty, and nothing here needs it, because it imports the same exported names.
