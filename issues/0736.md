## Description

Found by `#0735` pass A's review. The entry chunk `index-*.js` measures **60,445 B** gzipped after `#0735` pass A, up from 59,941 B before it. That is about 380 B over PRD §7.6's 60 KB budget, read in decimal KB as `#0717` read it. The Docs view is its own lazy chunk; what pushed the entry over is routing code that has to load up front. The earlier Raspberry Pi guide work had already left only about 120 B of headroom.

The reviewer found where the real headroom is. `about.json` and all of `privacy.json` load in the entry chunk, through `links.ts`, `pageTitle.ts` and the About and Privacy views, which are not lazy.

## Acceptance criteria

- [ ] About and Privacy become lazy routes through `routeViews.ts`, following `#0717`'s pattern, including recovery when a stale chunk fails to load.
- [ ] `links.ts` and `pageTitle.ts` no longer import `privacy.json` or the body of `about.json` into the entry. Take only the small fields they need, or move those fields into a small module.
- [ ] Measured with `vite build --outDir <scratch>`, never into `web/dist`: the gzipped entry chunk for `/` is at most 60,000 B, with the before and after numbers recorded.
- [ ] A size guard keeps it from creeping back: a test or script check that fails above the budget. It runs in `scripts/check.sh web` if that is cheap; otherwise in `guards`.
- [ ] `/about` and `/privacy` still render from a cold load and on reload. The single-source guards (`#0520`) stay green.
