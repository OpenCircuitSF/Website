## Description

The admin MCP server (`#0679`, `internal/mcpserver`) is mounted at `/mcp` and needs an API key. The new public, read-only MCP server (`#0729`) takes `/mcp`, the address agents and directories expect. The user decided on 2026-11-19 that **public is `/mcp` and admin moves to `/admin/mcp`**.

This is a hard cutover at one deploy, with no period where both work. Once `#0729` ships, an admin client still pointed at `/mcp` reaches the public server: it gets no error, just a different and much smaller tool list. Updating every admin client is part of the deploy, not something to clean up later.

Admin clients known today:

- the user's Claude Code (`ocsf` server, user scope);
- this repo's `scripts/mcp-connect.sh`;
- any `.mcp.json` or agent setup copied from `docs/mcp.md`.

Home Assistant uses REST `/api/v1` and is not affected.

## Acceptance criteria

- [ ] `mcpserver.Mount` serves the admin handler at `/admin/mcp`, with the same auth, scopes, limiters and stateless Streamable HTTP as now. `/mcp` is no longer routed to it.
- [ ] `/admin/mcp` is matched by the Go mux ahead of the SPA's `/admin/*` fallback. A test proves a POST `initialize` there reaches the MCP handler, not `index.html`.
- [ ] `/admin/mcp` keeps today's `noindex` and API-style headers, and still answers 401 without a key.
- [ ] Until `#0729` lands, `/mcp` never reaches the admin handler: `GET` gets the SPA's 404, and `POST`/`DELETE` get the mux's 405 (no placeholder route). *(orchestrator, 2026-11-19: 405 accepted for POST/DELETE.)* A wiring test pins that the admin handler is mounted at exactly one path.
- [ ] `docs/mcp.md`, `docs/api.md`, `scripts/mcp-connect.sh`, `README.md` and every other repo mention of the admin MCP URL say `/admin/mcp`. `rg -n '/mcp\b'` comes back clean except for public-server references.
- [ ] `docs/mcp.md` gets a short "Moved on <deploy date>" note with the command to re-add the server: `claude mcp remove ocsf` then `scripts/mcp-connect.sh`.
- [ ] After deploy: the user's Claude Code `ocsf` server is re-pointed and `whoami` works through `/admin/mcp`.

## Root cause

`mcpserver.Path` was `/mcp`, the path `#0729`'s public MCP server needs.

## Fix

Followed the plan. `mcpserver.Path` is `/admin/mcp`; `Mount` is unchanged otherwise. The old path gets 404 (GET) / 405 (POST, DELETE) with no placeholder route. New `TestMountServesOnlyAdminPath`; the wiring test uses `mcpserver.Path`, pins it literally, asserts the no-key 401 is JSON and not the SPA, and checks all three methods on `/mcp` never reach the handler. `v1MountViolations` now also flags literal `/admin/mcp` patterns (with a `#0729 must revisit` note) and gains the `admin mcp rogue` case. Docs, `scripts/mcp-connect.sh`, the `ocsf-ops` skill and comments say `/admin/mcp`.

Orchestrator decisions applied: 405 accepted (criterion 4 reworded); no `X-Robots-Tag` change, since robots.txt's `Disallow: /admin` covers `/admin/mcp` (criterion 3's "today's noindex" was never a header on `/mcp`); the `docs/mcp.md` Moved note carries the literal placeholder `<deploy date>`, filled at deploy. Deviation: the plan's `rg` mention sweep hung (scans untracked trees), so `git grep -nE '/mcp([^a-z._-]|$)' -- ':!issues'` was used; the only survivors are the plan's expected ones (AST guard cases, old-path test assertions, Moved note, `docs/mcp.md`'s slash-command line, `Path`'s doc comment).

## Plan

### What the code does today

- `internal/mcpserver/mcpserver.go`: `const Path = "/mcp"`. `Mount` registers `POST`, `GET` and `DELETE` `Path` on the mux. `main.go` calls `mcpserver.Mount(mux, mcpserver.NewHandler(...))` once, inside the `settingsH.APITokens()` block, at about line 1926.
- **The SPA fallback is not a problem.** The SPA is registered only as `GET /`, and the admin console is the single SPA route `/admin`, with its tabs in the hash. A method-qualified `POST /admin/mcp` or `GET /admin/mcp` pattern beats `GET /` in Go's ServeMux. I measured this with a scratch mux: `POST`, `GET` and `HEAD /admin/mcp` reach the handler. The Vite dev proxy already forwards everything under `/admin/` to Go, so dev needs no change.
- **noindex.** `seo.NoIndexAPIMiddleware` adds `X-Robots-Tag` only under `/api/`, so today's `/mcp` gets no such header. The `noindex` it has comes from nothing. After the move, `/admin/mcp` is also covered by robots.txt's `Disallow: /admin`, so it gains coverage and loses none. Compress and NoIndex wrap the whole mux and match no path other than `/api/`. Nothing else (CSP, Apache vhost, `deploy/`) names `/mcp`. Do not change `NoIndexAPIMiddleware`: its doc comment says it must match only `/api/`.
- **`/mcp` after the move is 404 for GET, and 405 for POST and DELETE**, not 404 for every method (see Obstacles, conflict 1). With `/mcp` unregistered, `GET /mcp` falls to the SPA and gets its unknown-route 404. `POST /mcp` and `DELETE /mcp` match the path of `GET /`, so Go's mux answers `405` with `Allow: GET, HEAD`. Measured with the same scratch mux. Neither reaches the admin handler, and that is what the criterion protects. **Do not add a placeholder 404 route for `/mcp`.** `#0729` takes the path, and a placeholder would be throwaway code that the AST guard below also forbids.
- `TestAdminRoutesRegisteredOnlyViaTable` flags only *literal* `/admin...` patterns. `mcpserver.Mount` builds its pattern from `Path`, so the guard does not trip. Its doc comment still needs one sentence (below), because `/admin/mcp` is the one `/admin` path that deliberately does not sit behind `requireAdmin`.

## Obstacles

- **Conflict 1: criterion 4's "/mcp returns 404".** For `POST` and `DELETE` that is not what Go's ServeMux does without a placeholder route. It returns **405**, because `GET /` matches the path, and only `GET` gets the SPA's 404. Measured on a scratch mux. The plan keeps 405/404 and tests "never the admin handler", which is the criterion's intent. A literal 404 would need a throwaway `/mcp` route that `#0729` deletes, and the AST guard would have to allow it. **The reviewer should accept 405 for POST and DELETE.** If the orchestrator wants a strict 404, decide that before dispatch, not in implementation.
- **Conflict 2: criterion 3's "keeps today's noindex".** Today `/mcp` has no `X-Robots-Tag`, because `NoIndexAPIMiddleware` covers only `/api/`. After the move, robots.txt's `Disallow: /admin` covers `/admin/mcp`, which is more coverage than before. No header change is planned.
- **The deploy is user-gated.** After-deploy steps 1–3 (the date fill-in and re-pointing the user's own Claude Code `ocsf` server) need the user, so criterion 7 cannot be checked before deploy. Admin clients break at that deploy: ship `#0728` only when the user can re-run `scripts/mcp-connect.sh` right after.
- **Shared resources.** Only the per-issue test database (`ISSUE=0728`). No ports, no `web/dist`, no migrations.
- **Concurrency.** `cmd/opencircuit/admin_wiring_test.go` and `admin_routes_ast_test.go` are edited often. `#0729` must not be implemented at the same time, because it edits the same files and the same guard line. Nothing else is needed: no tools beyond `go`, `rg`, `bash`, and no credentials.
