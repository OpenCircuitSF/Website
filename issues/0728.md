## Description

The admin MCP server (`#0679`, `internal/mcpserver`) is mounted at `/mcp` and needs an API key. The new public, read-only MCP server (`#0729`) takes `/mcp`, the address agents and directories expect. The user decided on 2026-11-19 that **public is `/mcp` and admin moves to `/admin/mcp`**.

This is a hard cutover at one deploy, with no period where both work. Once `#0729` ships, an admin client still pointed at `/mcp` reaches the public server: it gets no error, just a different and much smaller tool list. Updating every admin client is part of the deploy, not something to clean up later.

Admin clients known today:

- the user's Claude Code (`ocsf` server, user scope);
- this repo's `scripts/mcp-connect.sh`;
- any `.mcp.json` or agent setup copied from `docs/mcp.md`.

Home Assistant uses REST `/api/v1` and is not affected.

## Acceptance criteria

- [ ] `mcpserver.Mount` serves the admin handler at `/admin/mcp`, with the same auth, scopes, limiters and stateless Streamable HTTP as now. `/mcp` is no longer routed to it.
- [ ] `/admin/mcp` is matched by the Go mux ahead of the SPA's `/admin/*` fallback. A test proves a POST `initialize` there reaches the MCP handler, not `index.html`.
- [ ] `/admin/mcp` keeps today's `noindex` and API-style headers, and still answers 401 without a key.
- [ ] Until `#0729` lands, `/mcp` returns 404, never the admin handler. A wiring test pins that the admin handler is mounted at exactly one path.
- [ ] `docs/mcp.md`, `docs/api.md`, `scripts/mcp-connect.sh`, `README.md` and every other repo mention of the admin MCP URL say `/admin/mcp`. `rg -n '/mcp\b'` comes back clean except for public-server references.
- [ ] `docs/mcp.md` gets a short "Moved on <deploy date>" note with the command to re-add the server: `claude mcp remove ocsf` then `scripts/mcp-connect.sh`.
- [ ] After deploy: the user's Claude Code `ocsf` server is re-pointed and `whoami` works through `/admin/mcp`.
