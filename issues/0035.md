# 0035 — Add List-Unsubscribe headers to campaign email

## Description

Every campaign message carries the RFC 8058 header set with a per-recipient token, plus a `List-Id`.

## Acceptance criteria

- [ ] `List-Unsubscribe` header with both an HTTPS URL and a `mailto:` URI, per recipient
- [ ] `List-Unsubscribe-Post: List-Unsubscribe=One-Click`
- [ ] `List-Id: Open Circuit SF <list.opencircuitsf.com>`
- [ ] The HTTPS URL carries the recipient's `manage_token`; the `mailto:` subject is `unsubscribe:<token>`
- [ ] Headers applied to campaign mail only — not to transactional confirmation or auth mail
- [ ] Footer of every campaign body contains both "Manage your interests" and "Unsubscribe from everything" links
- [ ] Tests assert the headers are present and correctly per-recipient on a multi-recipient send

## Notes

PRD §6.5 paths 1 and 2. `List-Unsubscribe-Post` without `List-Unsubscribe` does nothing, and an HTTPS URL without the `Post` header gets treated as the old two-click form — all three headers work as a set.

The `mailto:` address is on `lists.opencircuitsf.com`, not the apex, because #0057 points that subdomain's MX at SES.
