## Description

User report, 2026-11-08, with a screenshot of the ShortLinks campaign detail for `hack-night`: "I saw it listed Nov 10 as the start date for the Hack Night campaign. The date of the event is Nov 9, so Nov 10 makes no sense. And these campaigns should not even bother setting the start and end date. This needs to be fixed."

**What the screenshot shows.** The ShortLinks page for `hack-night` (event Nov 9, 7 PM PT) reads:
- Date range `Nov 10, 2026 – Nov 10, 2026`.
- Total clicks 30, but clicks in window 0 and `No clicks in this window`.
- Every link shows 0 clicks.

A range limited to the event itself also hides every click made before it. Promotion happens before the event, so the stats page is empty for exactly the clicks that matter.

**Cause.** `internal/handlers/admin_outreach.go`, in the start-outreach handler (~line 765), builds `shortlinks.CreateCampaignRequest` with `StartsAt` and `EndsAt` copied from the workshop, both in UTC. A 7 PM PT start is the next day in UTC, which is likely why "Nov 10" appeared. `internal/handlers/admin_outreach_test.go:455` asserts that `StartsAt` is set.

**Production state, read-only, 2026-11-08** (`shortlinks_ocsf.campaigns`):

| slug | starts_at (UTC) | ends_at (UTC) |
|---|---|---|
| hack-night-2 | 2026-11-17 03:00 | 2026-11-17 06:00 |
| programming-leds-3 | 2026-11-17 02:30 | 2026-11-17 04:30 |
| hack-night | 2026-11-08 00:00 | 2026-11-28 00:00 |
| programming-leds-2 | 2026-10-20 01:30 | 2026-10-20 02:30 |

Campaigns made by hand before Outreach existed have no dates. The stored `hack-night` row no longer matches the screenshot; it appears to have been edited since.

## Plan

1. In the start-outreach handler, stop setting `req.StartsAt` and `req.EndsAt`. Leave the `CreateCampaignRequest` fields in `internal/shortlinks/client.go`, since they are `omitempty` and harmless.
2. In `admin_outreach_test.go` (~line 455), change the assertion so it requires `StartsAt == ""` and `EndsAt == ""` on the created campaign. Name or comment the test for this issue.
3. Search for any other caller that sets campaign dates, for example `EnsureCampaign` callers in `admin_newsletter_events.go`, and clear those too.
4. Verify with `ISSUE=0651 scripts/check.sh go ./internal/handlers/... ./internal/shortlinks/...`.

Existing campaigns are **not** changed by this code. Clearing the four rows above is a production write, and it needs the user's approval or the user's own edit in ShortLinks.

## Resolution

`internal/handlers/admin_outreach.go`'s start-outreach handler no longer sets `StartsAt`/`EndsAt` on `shortlinks.CreateCampaignRequest`; only `Description` and `DefaultUTMCampaign` are sent. `TestAdminOutreach_StartRules` in `internal/handlers/admin_outreach_test.go` now fails if either date is non-empty. A repo-wide search found no other `EnsureCampaign` or `CreateCampaignRequest` caller that sets dates (`internal/outreachconn/liveshortlinks.go` passes the request through; `internal/devmocks/mocks_test.go` sends an empty one). Existing production campaigns are untouched; clearing them awaits the user.
