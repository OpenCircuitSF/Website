## Description

`#0352` and `#0356` settled that a `<file>.go:<int>` citation must be replaced
by a stable identifier, and `internal/handlers`'
`TestNoCommentCitesGoFileByLineNumber` enforces it — **but only over Go comments
in `internal/`, `cmd/` and `web/`.**

**Issue markdown is unscanned**, and it drifts the same way.

Two wrong line citations reached issue files in this phase alone, both traced by
`#0377`'s review:

- `#0377`'s own text cited `store_test.go:2455`. At HEAD that line is prose
  inside an unrelated `#0369` doc comment; the real INSERT is line **2529**. It
  was transcribed from `#0371` and had drifted since.
- **The same stale number sits in `#0377`'s acceptance criterion 3**, written by
  the orchestrator. The reviewer deliberately left it — a reviewer should not
  rewrite the criteria it is judging — but flagged that it must not be
  propagated.

That is the failure mode this class of citation has: it is copied forward
because it looks precise, and nothing checks it.

## Why this may be worth building, unlike `#0381`

`#0381` decided **record, don't build**, because widening every scoped run would
cost ~8× on the fast packages forever. **This case differs**, and the difference
should be verified rather than assumed:

`internal/db` **already walks `issues/*.md`** for
`TestNoOpenIssueVerificationCitesUndefinedTestFunction`. The walk and the
fixture machinery exist. The work is applying `lineCitationPattern` to issue
prose — so the marginal cost is close to zero rather than a new traversal.

**Verify that claim before relying on it.** If the existing walk turns out not
to be reusable, the calculus reverts to `#0381`'s and recording may be right.

## The exemption that makes this non-trivial

An issue **quoting a citation in order to correct it** must not be flagged.
`#0352`, `#0356`, `#0377` and this issue all quote the very strings they exist
to fix — and this issue quotes two.

That exemption is the whole design problem, and it is the same shape as
`#0356`'s three-predicate transcript exemption. **A naive rule fires on the
issues doing the fixing.** Decide it deliberately and prove the exemption cannot
be satisfied by an ordinary stale citation.

## A third instance, and a scope question — from `#0379`'s second review

`#0379`'s own `## Review notes` cite `store_test.go:1698` as the location of a
test's oracle. The **very next commit in that issue** added three comment lines
above the test, so 1698 now holds a `t.Fatalf` rather than the assertion. Its
`## Description` carries a stale `store.go:795` in the same way.

**It went stale within the same issue's own lifetime.** That is the sharpest
demonstration available that these citations do not survive.

The reviewer deliberately left both as written, on the reasoning that a review
note is **a historical record of a run at a specific tree state**, and silently
editing it would falsify the record. That reasoning is sound and this issue must
not override it.

### So the scope question is real, and belongs to this issue

Two candidate positions, and it must be **decided, not defaulted**:

1. **Guard only forward-looking prose** — descriptions, acceptance criteria,
   plans — and exempt `## Review notes` and `## Verification` transcripts as
   historical records.
2. **Guard everything, and change the convention instead**: issue prose cites
   *identifiers*, never line numbers, so the question of staleness never
   arises — which is exactly what `#0352` settled for Go comments.

Position 2 is the stronger analogue to `#0352`, but it is a convention change
affecting how every future issue is written, and a guard that flags historical
transcripts will be fought rather than obeyed. **Weigh both and record the
reason.**

If option 1 is chosen, the section-based exemption is itself the design problem
criterion 2 names — a section heading is easy to add, so a stale citation could
be "protected" by moving it. Prove the exemption cannot be satisfied that way.


## Acceptance criteria

1. A guard flags `<file>.go:<int>` citations in `issues/*.md`, reusing
   `internal/db`'s existing walk rather than adding a traversal. Measure the
   added runtime and record it.
2. The correcting-quotation exemption is **structural, not an allowlist** —
   `#0337`'s name-keyed `embeddingReviewed` allowlist was proved not to stay
   true, and `#0356` closed its equivalent with a three-predicate conjunction.
   Prove each predicate is load-bearing by disabling it in turn.
3. **Prove the guard discriminates**: plant a stale citation in a scratch issue
   file and confirm it fires, naming the file and line; confirm a correcting
   quotation does not. **A check that cannot fail pins nothing** — `#0354`,
   `#0358` and `#0363` each shipped exactly that this phase.
4. The existing population is surveyed and each hit classified: real stale
   citation, currently-accurate citation, or correcting quotation. **Report the
   classification**; do not bulk-rewrite issue history. Note `#0377`'s criterion
   3 is a known instance.
5. **If the enumeration comes back small, or the exemption cannot be made
   structural, record the limit and stop** — that is `#0330`, `#0347` and
   `#0356`'s repeated answer, and `#0381`'s. Say so explicitly rather than
   building anyway.
6. Any figure or citation this issue states is **re-measured**, not transcribed.
   **Eight unsupported details reached issues this phase**, several written by
   the orchestrator — including the `2455` above.
7. Run `./internal/db/...` **and** `./internal/handlers/...` (see `#0381`);
   `gofmt` stability; per §5 name the specific tests that ran.

## Decision

**Decision one — scope: position 2, but reachable in practice only where it
matters.** Nothing about "this citation sits under a Review notes heading"
makes it any less likely to drift than the same citation under Description —
a section-keyed historical-record exemption is not a property of the
citation, it is a property of where someone chose to put it, and a heading
costs nothing to add. So the new guard's scanned sections still include
Verification and Review notes, exactly where the sibling
`TestNoOpenIssueVerificationCitesUndefinedTestFunction` already looks.

This does **not** require overriding `#0379`'s reviewer, whose reasoning
(a review note is a record of a run at a specific tree state, and rewriting
it would falsify that record) is sound and stands. Both `#0377` and `#0379`
are `resolved`. The new guard, like its sibling, enforces the convention
only against `open`/`in-progress` files — the same scope `#0265` gave for
the sibling guard, for the same reason: a resolved issue's citation is no
longer actionable by the agent that wrote it, and re-litigating a closed
record is not this guard's business. So the reviewer's decision to leave
`#0379`'s record exactly as written is never disturbed — this guard would
never reach it either way, regardless of which position was chosen. The
"must not override" instruction is honored by the status filter, not by a
historical-section exemption.

**Decision two — build, having verified the reuse claim first.** Measured
directly against `internal/db/issue_citation_guard_test.go`: the walk
(`os.ReadDir("../../issues")`), the section extraction
(`extractNamedSections`, keyed on the existing `issueCitationSectionHeaders`
set) and the status filter (`issueStatus`) are all pre-existing, unmodified
by this issue, and directly reusable from a second test in the same
package. The new guard adds one pattern match and one exemption check per
already-extracted section — not a new traversal. Measured cost: the new
`TestNoOpenIssueEvidenceCitesGoFileByLineNumber` alone runs in **0.02s**
(the sibling `TestNoOpenIssueVerificationCitesUndefinedTestFunction` alone
runs in 0.08s — its own AST walk of `internal/`+`cmd/`+`web/` is the
expensive part, which the new guard does not need at all: it does not
resolve whether a citation is *true*, only whether one exists, matching
`#0356`'s own "convention, not truth" framing for the Go-comment guard).
The whole `internal/db` package, new guard included, runs in **0.414s**.
This is a different shape from `#0381`'s recurring, ~8x-per-run cost; it did
not recur here, so criterion 6's "record and stop" branch does not apply —
built.

**The exemption (criterion 2).** Inside a scanned section, a citation is
discounted only when its own local text proves it is a verbatim quotation
of real command output, via two independent, structurally sufficient
predicates:

1. A second colon-number pair immediately after the citation — the exact
   shape `go build`, `go vet` and `gofmt -l` use for every diagnostic they
   print, and a shape an ordinary prose citation does not produce by
   accident.
2. A `go test -v` output marker line (`=== RUN`, or `--- FAIL/PASS/SKIP:`)
   appearing anywhere inside the same fenced code block as the citation —
   the markdown analogue of `#0356`'s own "enclosing comment group" scope.

Each predicate was proved load-bearing by disabling it in turn (five
sub-cases: predicate 1 alone sufficient; predicate 2 alone sufficient;
neither present leaves the citation flagged; predicate 1 removed from an
otherwise-qualifying fixture un-excludes it; predicate 2 removed — either by
moving the citation outside any fenced block, or by leaving it inside a
fenced block that carries no marker line — un-excludes it too). See
`## Verification` for the test name.

**A first design of predicate 2 was wrong, and the real corpus caught it.**
The first draft copied the sibling Test-name-citation guard's fixed
backward-lookback-window shape (a marker must appear shortly *before* the
citation). Run against the real `open`/`in-progress` corpus, this
false-flagged a live, in-progress issue's own captured `go test -v`
transcript, because real `go test -v` output prints the file:line message
*before* the marker line it belongs to, not after — the opposite order the
borrowed shape assumed. Corrected to scan the whole enclosing fenced block
for a marker anywhere, matching what `#0356` actually does for Go comments
(scope over the whole comment group, not a fixed byte window) rather than
what a different, adjacent predicate in the same file happens to do for a
different citation shape. This is exactly the kind of thing criterion 6
asks for: self-testing the scanner against real content rather than trusting
a synthetic fixture alone.

**The correcting-quotation exemption is the existing section split,
reused — its residual is named, not hidden.** A citation quoting another
issue's bad citation to discuss or correct it — this issue's own
Description does that — is not caught by either predicate above; it is
caught by staying inside `#0268`'s existing evidence/subject-matter section
split (`issueCitationSectionHeaders`): Description, Notes, Plan and
Acceptance criteria are not scanned by this guard either, for the same
reason `#0268` gives for the sibling guard.

This is a location-based signal, and the amendment is right that nothing
stops a future citation from being written under an unscanned heading to
dodge the guard. Accepted rather than closed, for three measured reasons:
it is not new — it is the same split `#0268` already shipped and has
carried since without being gamed; the real corpus measured for this issue
carries zero citations relocated into an unscanned section to survive (the
three in this issue's own Description are corrective, in the file that
documents why the guard exists — the same legitimate use `#0268`'s own
motivating case already established for those sections); and a section
split is a convention-level control, not a cryptographic one — `#0356`'s own
transcript exemption carries an equivalent, explicitly accepted blind spot
(a fabricated name dressed as real test output is indistinguishable from a
genuine one). This guard's "convention, not truth" honesty applies here
exactly as it does there.

**Criterion 3 — discrimination proved.** A `t.TempDir()` fixture (never the
shared `issues/` tree, per §8a) plants a non-exempt citation under a
`## Verification`-equivalent heading and a correcting quotation of a
different, fictitious citation under Description in the same file: the
guard reports exactly the Verification-section citation, naming the file
and line, and does not report the Description one; replacing the flagged
citation with a stable identifier then clears the guard entirely. See
`## Verification` for the test name.

citations, zero non-exempt.**
