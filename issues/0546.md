## Description

Phase 3a of the Outreach design: read the workshop campaign's stats from
ShortLinks and show clicks per post in the Outreach panel and a per-workshop
results view on the Outreach tab (clicks per day by channel, with markers
where posts went out; posts table; all-workshops summary).

Design doc "Measuring impact"; mockup artboard 3:
https://claude.ai/artifact/4Ckwb6QmWYyfYyAEszAKa2

## Acceptance criteria

- [ ] Admin endpoint returns, for a workshop's outreach: totals (bot-excluded clicks), clicks per post (matched by short link key), daily series per channel, and the window used — from `GET /api/campaigns/{slug}/stats` via `#0543`'s client. Short server-side cache (e.g. 60 s) so the screen does not hammer ShortLinks.
- [ ] All-workshops summary endpoint (one row per workshop with outreach: posts, clicks).
- [ ] UI: clicks shown in each panel cell; Outreach tab results view with the line chart (series colors from `--series-*` tokens), post markers, posts table, all-workshops table. Chart-shaping logic in a tested `web/src/lib` module.
- [ ] ShortLinks unreachable → the screen says so and still renders posts; it never errors the whole page.
- [ ] Verified with `ISSUE=0546 scripts/check.sh`.

### What ShortLinks actually returns (read from its source, not its struct)

`GET /api/campaigns/{slug}/stats` writes `campaignStatsResponse`
(ShortLinks `internal/handlers/campaigns.go`), which **embeds**
`clicks.CampaignStats` — so the wire JSON is **flat**, not the
`{"stats": …}` nesting `clicks.CampaignRollup`'s own fields suggest:

```json
{
  "click_count": 42, "excluded_bot_count": 3,
  "by_source": [{"value":"bluesky","count":20}], "by_medium": [], "by_content": [], "by_referer": [],
  "window_from": "2026-10-01", "window_to": "2026-10-17",
  "timeseries": {"days": [{"date":"2026-10-03","count":5}]},
  "by_link": [{"link_id": 7, "key": "aB3x", "title": "…", "count": 12}],
  "series_by_link": [{"link_id": 7, "key": "aB3x", "title": "…", "is_other": false,
                      "days": [{"date":"2026-10-03","count":5}]},
                     {"link_id": null, "key": "", "title": "Other", "is_other": true, "days": […]}]
}
```

Facts that drive the design:
- Every count is **bot-excluded**; `excluded_bot_count` is the bots.
- Window is half-open `[window_from, window_to)`, UTC days, as resolved by
  ShortLinks. Zero-count days are **omitted** from every `days` array.
- `by_link` is **uncapped** (one row per link with ≥1 click; `key` is `""`
  when the link was deleted). `series_by_link` is capped at **6 named links +
  one `is_other` fold**, and the fold is present only when there is a
  remainder. Together the series sum exactly to `timeseries`.
- `by_source` is capped at 20 and keyed on the click's own `utm_source`
  (inbound query value wins over the link's stored one), so it is **not** a
  reliable per-channel total — use `by_link` matched on key instead.
- The only per-link daily data elsewhere is `GET /api/links/{key}`'s
  `timeseries`, which is a fixed trailing 30 days ending yesterday with no
  window parameter — it cannot be aligned with the campaign window, so it is
  **not used**.
- **Default-window trap:** with no `from`/`to`, ShortLinks uses the
  campaign's own `starts_at`–`ends_at`. `#0544` creates the campaign with the
  *workshop's* start/end, so the default window is the workshop session
  itself — hours long, and after all the outreach clicks. **Always send an
  explicit window** (decision 3).
- `#0543`'s `TestCampaignStatsWindow` fixture uses the nested
  `{"stats":{…}}` shape. Harmless while the client returns raw bytes; wrong
  once it decodes. Fix the fixture (step 1).

### Decisions

1. **Per-post clicks = `by_link[key]`**, matched on the post's
   `short_link_key`, over the results window. A prepared post with no
   `by_link` row has `0`; an unprepared post has `null`. `by_link` rows whose
   key matches no post (deleted links, `#0549`'s flyer links, links made by
   hand in ShortLinks) sum into `unmatched_clicks`.
2. **Per-channel totals are exact** — sum of `by_link` counts of that
   channel's posts' keys. **Per-channel daily lines are drawn only where
   exact**, never estimated:
   - A channel's line is *exact* when every one of its keys with clicks in
     `by_link` is a named (non-`is_other`) `series_by_link` entry. Its line is
     the per-day sum of those named series.
   - Everything else — the `is_other` fold, named series whose key is not a
     post, and named series belonging to a non-exact channel — sums into one
     **"Other links"** series, which carries the list of non-exact channels it
     contains.
   - Invariant (asserted in tests): the series sum per day equals
     `timeseries`. With ≤ 6 clicked links (typical: 5 channels × 3 waves, but
     only posted ones get clicks) there is no fold and every channel is exact.
     The UI says plainly when a channel is folded ("in Other links"); the
     channel's total is still shown exactly in the legend/table.
   - Rejected: estimating a folded channel's daily share (dishonest);
     N extra `GET /api/links/{key}` calls (wrong window, N× the load).
     Uncapped per-link series would need a ShortLinks change — out of scope;
     report it as a possible ShortLinks follow-up, do not file it here.
3. **Results window**, pure function `outreach.ResultsWindow(createdAt
   time.Time, startsAt *time.Time, now time.Time) (from, to time.Time)`, all
   UTC midnights, `to` exclusive:
   - `from` = UTC date of `outreach.created_at`.
   - `to` = tomorrow (UTC) — **includes today so far** (recency matters for
     "did that post land"); the chart marks the last day as partial.
   - If `startsAt != nil`, clamp `to` to at most UTC date of `startsAt` + 2
     days (the day after the workshop is the last day that matters).
   - If `to <= from`, `to = from + 1 day`. If `to - from > 120 days`,
     `from = to - 120 days`.
   - Pass both to `CampaignStats`; report ShortLinks' returned
     `window_from`/`window_to` (authoritative) in the response.
4. **Cache in `internal/shortlinks`**, keyed `slug|from|to`: success kept
   60 s, failure kept 15 s (so an unreachable ShortLinks is not hit on every
   render), a caller-context cancellation never cached. Lives on the handler,
   built in `NewAdminOutreachHandler` from the injected `shortLinker` — no
   `main.go`/`mountAndServe` signature change.
5. **ShortLinks failure never fails the request.** Both endpoints return 200
   for a known workshop with a `status` field; posts come from our own DB and
   always render. Status values: `ok`, `not_configured` (nil/disabled
   client), `not_started` (no outreach row), `campaign_missing`
   (`ErrNotFound`), `rejected` (`ErrUnauthenticated`/`ErrForbidden` — a token
   problem the operator must fix), `unreachable` (anything else, incl.
   `ErrRateLimited`, transport errors, 5xx, decode errors). Log non-`ok`
   upstream errors server-side (the client already redacts the token); never
   put upstream text in the response.
6. **Routes** (both GET, admin-only, in `#0544`'s `if adminOutreachH != nil`
   block via `adminRoute{…}` — never `mux.Handle`):
   - `GET /admin/workshops/{id}/outreach/results` — one workshop.
   - `GET /admin/outreach-results` — all-workshops summary. Hyphenated, like
     `#0544`'s `/admin/outreach-posts` and `#0548`'s
     `/admin/outreach-locations`, to stay clear of `/admin/outreach/{id}/…`.
7. **Colors are fixed per channel**, not per rank: the n-th channel in the
   server's `channels` order gets `var(--series-n)` (bluesky 1, mastodon 2,
   instagram 3, tiktok 4, youtube 5), "Other links" gets
   `var(--series-other)`. Same channel, same color on every workshop.
8. **Days and markers are UTC**, matching ShortLinks' buckets. A post marker
   sits on the UTC date of its `posted_at`. Axis labels say "(UTC)" once.

### Step 1 — typed rollup in `internal/shortlinks`

In `client.go`, add the types and change `CampaignStats` to decode:

```go
type Bucket struct { Value string `json:"value"`; Count int64 `json:"count"` }
type DayBucket struct { Date string `json:"date"`; Count int64 `json:"count"` } // "YYYY-MM-DD", UTC
type LinkBucket struct { LinkID *int64 `json:"link_id"`; Key string `json:"key"`; Title string `json:"title"`; Count int64 `json:"count"` }
type LinkSeries struct {
    LinkID *int64 `json:"link_id"`; Key string `json:"key"`; Title string `json:"title"`
    IsOther bool `json:"is_other"`; Days []DayBucket `json:"days"`
}
// CampaignRollup is GET /api/campaigns/{slug}/stats. ShortLinks embeds its
// CampaignStats in the response, so the stats fields are top-level.
type CampaignRollup struct {
    ClickCount       int64    `json:"click_count"`
    ExcludedBotCount int64    `json:"excluded_bot_count"`
    BySource, ByMedium, ByContent, ByReferer []Bucket // tags: by_source, by_medium, by_content, by_referer
    WindowFrom string `json:"window_from"` // inclusive
    WindowTo   string `json:"window_to"`   // exclusive
    Timeseries struct{ Days []DayBucket `json:"days"` } `json:"timeseries"`
    ByLink       []LinkBucket `json:"by_link"`
    SeriesByLink []LinkSeries `json:"series_by_link"`
}
func (c *Client) CampaignStats(ctx context.Context, slug string, from, to time.Time) (*CampaignRollup, error)
```

(Give each `By*` field its own tag line; the one-liner above is shorthand.)
Use `doJSON`. Drop the now-unused `encoding/json` `RawMessage` use only if
nothing else needs the import. Nothing else in the tree calls
`CampaignStats` today (checked).

New `internal/shortlinks/cache.go`:

```go
type StatsFetcher func(ctx context.Context, slug string, from, to time.Time) (*CampaignRollup, error)
type StatsCache struct { /* fetch, ttl, failTTL, now func() time.Time, mu sync.Mutex, entries map[string]statsEntry */ }
func NewStatsCache(fetch StatsFetcher, ttl, failTTL time.Duration) *StatsCache
// Get returns the cached or freshly fetched rollup and when it was fetched.
// The returned rollup is shared: callers must not mutate it.
func (c *StatsCache) Get(ctx context.Context, slug string, from, to time.Time) (*CampaignRollup, time.Time, error)
```

Key `slug + "|" + from.Format(date) + "|" + to.Format(date)`. On a miss,
fetch **without holding the mutex**. Do not cache an error when
`ctx.Err() != nil`. On every store, drop expired entries (the map stays
tiny). Export `const StatsCacheTTL = 60 * time.Second`,
`StatsCacheFailTTL = 15 * time.Second`. `now` is a field tests overwrite
(same package).

Tests (`client_test.go`, new `cache_test.go`):
- `TestCampaignStatsWindow`: fixture becomes the **flat** JSON above;
  assert `ClickCount`, `WindowTo`, one `ByLink` key, the `IsOther` series,
  and the query string as today.
- Decode error (`{"click_count":"x"}`) → non-sentinel error.
- Cache: hit within TTL makes one fetch; miss after TTL refetches; error
  cached for `failTTL` then retried; canceled-ctx error not cached;
  different window → different entry.

### Step 2 — results shaping in `internal/outreach/results.go` (pure)

```go
type ChannelClicks struct { Name, Label string; Clicks int64; HasDailySeries bool; Prepared int }
type Series struct {
    ID       string   // channel name, or "other"
    Label    string   // channel label, or "Other links"
    Channels []string // [name] for a channel; folded channel names for "other"
    IsOther  bool
    Days     []shortlinks.DayBucket // ascending, zero days omitted
}
type Results struct {
    ClickCount, ExcludedBotCount, UnmatchedClicks int64
    WindowFrom, WindowTo string
    PostClicks map[int64]int64 // post id -> clicks; only prepared posts
    Channels   []ChannelClicks // every channel, Channels() order
    Series     []Series        // channel series in Channels() order, then "other"
}
func ResultsWindow(createdAt time.Time, startsAt *time.Time, now time.Time) (from, to time.Time)
func BuildResults(posts []Post, r *shortlinks.CampaignRollup) Results
```

`BuildResults` algorithm, exactly:
1. `keyPost` := map key → post, for posts with a non-nil, non-empty
   `ShortLinkKey`. `PostClicks[p.ID] = 0` for each.
2. For each `ByLink` row: if `keyPost[row.Key]` exists (and `row.Key != ""`)
   → add to `PostClicks` and to that channel's `Clicks`; else add to
   `UnmatchedClicks`.
3. `named` := set of `Key` over `SeriesByLink` rows with `!IsOther`.
4. Channel `c` is exact iff every key of `c`'s posts whose `ByLink` count
   > 0 is in `named`.
5. Emit a `Series` for each channel that is exact **and** has at least one
   prepared post (a flat zero line is honest; a channel with nothing
   prepared gets no line): days = per-date sum over named series whose key
   maps to `c`.
6. "other" = `IsOther` row days + every named series whose key is not a
   post key or maps to a non-exact channel. Emit only if its total > 0.
   `Channels` = non-exact channel names, `Channels()` order.
7. `HasDailySeries` = channel has its own series. `Prepared` = count of its
   prepared posts.

Tests `results_test.go` (pure, no DB): window cases (normal; today partial;
clamp to workshop+2; outreach after workshop → 1 day; 120-day cap; nil
`startsAt`); `BuildResults` with no fold (all channels exact, sums
correct), with a fold where one channel's second link is in Other (that
channel not exact, its named days moved to Other, `Channels` lists it), an
unmatched named link and a `key:""` deleted link → `UnmatchedClicks`;
unprepared post absent from `PostClicks`, prepared zero-click post `0`;
**invariant** helper: per date, Σ series = `Timeseries` for every case.
