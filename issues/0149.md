## Description

`#0055` emits schema.org `Event` JSON-LD on workshop detail pages. Its acceptance criteria included validating the output against **Google's Rich Results Test**, and that criterion could not be met: the tool fetches a public URL, and nothing here is publicly reachable yet. No agent in this environment has outbound access to it either.

What *was* verified, thoroughly: the block parses as JSON, carries the required and recommended `Event` fields with correct types, uses RFC 3339 dates, shapes `location` as a real `Place`, and survives 18 escaping payloads without breaking out of the `<script>` element. `#0055`'s reviewer accepted that as sufficient to resolve the issue and asked that the live validation be carried here rather than left as a permanently unticked box.

## Acceptance criteria

- [ ] Once a workshop page is publicly reachable, run the URL through Google's Rich Results Test and record the result — including any warnings, not just errors
- [ ] Fix whatever it reports, or record why a warning is acceptable
- [ ] Check a **canceled** workshop too, not only a published one — `eventStatus: EventCancelled` is the field most likely to draw a complaint, and `#0055` deliberately emits real data for canceled workshops while their meta tags stay generic
- [ ] Note in `docs/` (or wherever SEO is documented) that this validation is a post-deploy step, so the next person adding structured data knows to repeat it

## Notes

Gated on the first production deploy — Phase 7 territory, alongside `#0064`'s deployment runbook. Filing it here so the unticked criterion in `#0055` has an owner rather than becoming a box nobody remembers.

Worth knowing: `#0055`'s structural verification is strong enough that a Rich Results failure would most likely indicate a *policy* disagreement (Google's expectations about `Event` beyond schema.org's own spec) rather than malformed output.
