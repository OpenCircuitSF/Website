## Description

`#0055` emits schema.org `Event` JSON-LD on workshop detail pages. Its acceptance criteria included validating the output against **Google's Rich Results Test**, and that criterion could not be met: the tool fetches a public URL, and nothing here is publicly reachable yet. No agent in this environment has outbound access to it either.

What *was* verified, thoroughly: the block parses as JSON, carries the required and recommended `Event` fields with correct types, uses RFC 3339 dates, shapes `location` as a real `Place`, and survives 18 escaping payloads without breaking out of the `<script>` element. `#0055`'s reviewer accepted that as sufficient to resolve the issue and asked that the live validation be carried here rather than left as a permanently unticked box.

## Resolution notes

> 🟢 Resolved 2026-09-12 by the user's decision. The user ran
> `https://www.opencircuitsf.com/workshops/programming-leds` through Google's
> Rich Results Test. Its only findings were **two missing optional
> properties**, which the user decided not to add.
>
> The user did not name the two properties. They are recorded here as
> **`offers`** and **`performer`** by comparison, not from the tool's output:
> the live block carries `description`, `endDate`, `eventAttendanceMode`,
> `eventStatus`, `image`, `location`, `name`, `organizer`, `startDate`, and
> `url`, and those two are the only properties on Google's recommended list
> for `Event` that it omits. Correct this note if the tool named others.
>
> **A canceled workshop was not tested** (criterion 3), so `EventCancelled`
> has still never been through the tool. `docs/seo.md` now records the
> validation as a post-deploy step and says to include a canceled workshop on
> the next run.

## Acceptance criteria

- [x] Once a workshop page is publicly reachable, run the URL through Google's Rich Results Test and record the result — including any warnings, not just errors — run by the user 2026-09-12; see `## Resolution notes`
- [x] Fix whatever it reports, or record why a warning is acceptable — both findings are optional properties the user decided not to add
- [ ] **Not performed — waived by the user when resolving (2026-09-12).** Check a **canceled** workshop too, not only a published one — `eventStatus: EventCancelled` is the field most likely to draw a complaint, and `#0055` deliberately emits real data for canceled workshops while their meta tags stay generic
- [x] Note in `docs/` (or wherever SEO is documented) that this validation is a post-deploy step, so the next person adding structured data knows to repeat it

## Notes

Gated on the first production deploy — Phase 7 territory, alongside `#0064`'s deployment runbook. Filing it here so the unticked criterion in `#0055` has an owner rather than becoming a box nobody remembers.

Worth knowing: `#0055`'s structural verification is strong enough that a Rich Results failure would most likely indicate a *policy* disagreement (Google's expectations about `Event` beyond schema.org's own spec) rather than malformed output.
