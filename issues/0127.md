# 0127 — Send a welcome email when a subscriber confirms

| | |
|---|---|

## Description

Nothing is sent after a successful double opt-in confirmation. The welcome message is the highest-engagement email the list will ever send and the natural place to set expectations about frequency and show the way out — both of which measurably reduce complaints later.

## Acceptance criteria

- [ ] `BuildWelcomeEmail` added to `internal/mailing/transactional_templates.go`, HTML and plain text, matching the existing template family's structure and brand tokens
- [ ] Enqueued via `#0126`'s outbound queue with `kind = 'welcome'`, inside the confirmation transaction
- [ ] Sent exactly once per subscriber. A second confirmation of an already-confirmed address does not re-send
- [ ] Content: what Open Circuit SF is, which interests they selected, roughly how often to expect mail, a link to `/archive` for past mailings, a link to the preference center, and a working unsubscribe link
- [ ] Carries `List-Unsubscribe` and `List-Unsubscribe-Post` headers (`#0035`)
- [ ] Includes the `physical_address` setting, like every other outbound message
- [ ] Writes a `welcome_sent` subscriber event (`#0126`)
- [ ] Golden-file tests for HTML and text, committed with **CRLF** line endings per `#0078`
- [ ] Imported subscribers (`#0125`) do **not** receive it — they never confirmed here, and a welcome to an imported address reads as unsolicited
- [ ] Addresses that accept an import invitation (`#0129`) do **not** receive it either — the invitation was their introduction
- [ ] A suppressed address never receives it, even if a confirmation somehow lands

## Notes

PRD §6.3 covers the subscription flow this hooks into; §6.8 is the archive it links to.

The `/archive` link is the reason this issue depends on `#0123` — a welcome email pointing at an empty or nonexistent archive is worse than one that does not link at all. If `#0123` slips, ship the welcome without the archive link rather than with a dead one.

`#0076` fixed two email-copy defects the template re-theme left behind; read it before writing new copy so the same mistakes are not reintroduced.

Golden files in `internal/mailing/testdata` must be CRLF — `#0078` cost a day when four tests failed on a clean checkout because git normalized them to LF.
