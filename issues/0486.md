## Description

`scripts/db-reset.sh` **drops and recreates `opencircuit`** — which is not a
scratch database. `CLAUDE.md` §5a says so plainly: it targets the two databases
every agent falls back to sharing, "and `opencircuit` is also the user's dev
database."

It is nonetheless offered as ordinary advice, unqualified, in several places:

- `CLAUDE.md` §5's command block — `# rebuild the local dev DB from migrations + seed admin`
- `docs/obstacles.md`'s **Clear** column, as the remedy for a missing schema
- `docs/configuration.md`'s `DEV_ADMIN_LOGIN` row, as the way to get an admin row
- `cmd/opencircuit`'s own startup error, which names it when `ADMIN_EMAIL` has
  no active row

Each phrasing describes the *outcome* — rebuilt, seeded, cleared — and none
mentions that everything currently in that database is deleted first. An agent
or developer reaching for it to fix a missing admin row is not told they are
about to discard their own local data.

`docs/dev.md` is the exception and shows the right shape: it says the script
refuses when another process holds the database.

## Where this came from

Found by the audit of the abandoned `#0402` branch. That branch's **first
review bounce** was precisely this: `scripts/dev.sh`'s banner advised a
database-destroying command as routine. The fix landed there, in commit
`8f289c3`, and **never reached `main`** — so the finding is real, was reviewed,
and the correction was stranded along with the rest of that branch.

`main` has since acquired more copies of the same unqualified advice, not fewer.

## Why the existing guard is not the answer

`#0207` already made the script refuse without `--force` when another
connection is live, and `scripts/db_reset_guard_test.sh` pins that. **That
protects other agents, not the person running it.** A developer alone on their
own machine — the common case — passes the guard and loses their data with no
warning at all.

## Acceptance criteria

1. **Say what it destroys, at each site that recommends it.** Outcome-only
   phrasing ("rebuild", "clear", "seed") is what makes it read as safe. One
   clause naming the drop is enough.
2. **Include the startup error.** `cmd/opencircuit` names the script when
   `ADMIN_EMAIL` has no active row, and that is the single most likely moment
   someone runs it without thinking. Note it already offers `opencircuit seed`
   as the non-destructive alternative — lead with that one.
3. **Check for sites this issue missed** rather than trusting the list above;
   re-derive it with a search. This lineage has had several false premises
   corrected by measurement.
4. **Do not weaken `#0207`'s refusal** or its guard. This is additive: a warning
   for the solo case, not a change to the multi-agent one.
5. Consider whether the script itself should say what it is about to do before
   doing it. Decide yes or no with a reason — a prompt is not obviously right
   for something agents invoke non-interactively, and `CLAUDE.md` §5a's
   concurrency rules are the constraint.
