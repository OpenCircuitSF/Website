# 0486 — `scripts/db-reset.sh` is advised as routine in four places without saying it destroys the dev database

## Description

`scripts/db-reset.sh` **drops and recreates `opencircuit`** — which is not a
scratch database. `CLAUDE.md` §5a says so plainly: it targets the two databases
every agent falls back to sharing, "and `opencircuit` is also the user's dev
database."

It is nonetheless offered as ordinary advice, unqualified, in several places:

- `CLAUDE.md` §5's command block — `# rebuild the local dev DB from migrations + seed admin`
- `docs/obstacles.md`'s **Clear** column, as the remedy for a missing schema
- `docs/configuration.md`'s `DEV_ADMIN_LOGIN` row, as the way to get an admin row
- `cmd/opencircuit`'s own startup error, which names it when `ADMIN_EMAIL` has
  no active row

Each phrasing describes the *outcome* — rebuilt, seeded, cleared — and none
mentions that everything currently in that database is deleted first. An agent
or developer reaching for it to fix a missing admin row is not told they are
about to discard their own local data.

`docs/dev.md` is the exception and shows the right shape: it says the script
refuses when another process holds the database.

## Where this came from

Found by the audit of the abandoned `#0402` branch. That branch's **first
review bounce** was precisely this: `scripts/dev.sh`'s banner advised a
database-destroying command as routine. The fix landed there, in commit
`8f289c3`, and **never reached `main`** — so the finding is real, was reviewed,
and the correction was stranded along with the rest of that branch.

`main` has since acquired more copies of the same unqualified advice, not fewer.

## Why the existing guard is not the answer

`#0207` already made the script refuse without `--force` when another
connection is live, and `scripts/db_reset_guard_test.sh` pins that. **That
protects other agents, not the person running it.** A developer alone on their
own machine — the common case — passes the guard and loses their data with no
warning at all.

## Acceptance criteria

1. **Say what it destroys, at each site that recommends it.** Outcome-only
   phrasing ("rebuild", "clear", "seed") is what makes it read as safe. One
   clause naming the drop is enough.
2. **Include the startup error.** `cmd/opencircuit` names the script when
   `ADMIN_EMAIL` has no active row, and that is the single most likely moment
   someone runs it without thinking. Note it already offers `opencircuit seed`
   as the non-destructive alternative — lead with that one.
3. **Check for sites this issue missed** rather than trusting the list above;
   re-derive it with a search. This lineage has had several false premises
   corrected by measurement.
4. **Do not weaken `#0207`'s refusal** or its guard. This is additive: a warning
   for the solo case, not a change to the multi-agent one.
5. Consider whether the script itself should say what it is about to do before
   doing it. Decide yes or no with a reason — a prompt is not obviously right
   for something agents invoke non-interactively, and `CLAUDE.md` §5a's
   concurrency rules are the constraint.

## Implementation notes

**Criterion 3 — re-derived the sites by search, not by trusting the issue's
list.** `grep -rn "db-reset" --include="*.go" --include="*.md" --include="*.sh"`
over the whole tree, with `issues/` excluded (291 hits, nearly all historical
issue prose), turned up five non-`issues/` sites that recommend running the
script rather than merely mentioning it as a fact:

1. `CLAUDE.md` §5's command block (matches the issue's list).
2. `docs/obstacles.md`'s **Clear** column (matches the issue's list).
3. `docs/configuration.md`'s `DEV_ADMIN_LOGIN` row (matches the issue's list).
4. `cmd/opencircuit`'s startup error in `newDevAdminAutoLogin` (matches the
   issue's list).
5. **`scripts/dev.sh`'s own header comment** — not on the issue's list. Its
   `--postgres/-p` description says "Requires a local database already
   migrated and seeded with an admin row — scripts/db-reset.sh does both,"
   which is exactly the outcome-only phrasing the issue describes, recommending
   the script to satisfy a prerequisite without naming what it destroys first.

Sites checked and left alone: `CLAUDE.md`'s §1 repository-layout table cell
(`db-reset.sh (rebuild a local DB)`) is part of a row where every script gets
a two-to-four-word gloss, not "advice offered as routine" the way the other
sites are — it names the tool, it does not tell a stuck reader to run it to
fix something. `docs/deployment.md`'s handful of mentions are either already
correctly scoped ("Local dev-database reset (never production)") or describe
what was already exercised locally, not advice pointing someone at the
command as a fix. `docs/dev.md` was already the right shape per the issue and
needed no change. `CLAUDE.md` §5a's own `db-reset.sh` bullet (added by
`#0207`) already fully describes the drop-and-recreate behavior and its
guard, so it was left as-is.

**Criterion 1 — the wording added at each site**, one clause per site, no
essay:

- `CLAUDE.md` §5: `scripts/db-reset.sh          # rebuild the local dev DB…`
  → `# drops and rebuilds the local dev DB from migrations + seed admin`.
- `docs/obstacles.md`: `` `scripts/db-reset.sh` (rebuild + seed) `` →
  `` `scripts/db-reset.sh` (drops the database, then rebuilds and seeds it —
  destructive) ``, and named `migrate ... up` as the non-destructive
  alternative in the same cell for contrast.
- `docs/configuration.md`'s `DEV_ADMIN_LOGIN` row: `` (`opencircuit seed` /
  `scripts/db-reset.sh`) `` → `` (`opencircuit seed`, which only creates the
  missing row, or `scripts/db-reset.sh`, which drops and rebuilds the whole
  database) ``.
- `scripts/dev.sh`'s header: added "but drops and rebuilds the target
  database first, so it is not a safe thing to run reflexively if that
  database already holds data you want."

**Criterion 2 — the startup error**, `cmd/opencircuit/main.go`'s
`newDevAdminAutoLogin`, now reads:

    opencircuit: DEV_ADMIN_LOGIN=true but ADMIN_EMAIL %q has no users row —
    run `opencircuit seed` to create just that row, or scripts/db-reset.sh if
    you want to drop and rebuild the whole database first

It leads with `opencircuit seed` (the non-destructive fix for the actual
problem the error describes — a missing row) and names the destructive
alternative second, with what it destroys spelled out rather than left
implicit. Checked against `TestNoAdminFacingStringCitesInternalDocs`: the new
text cites no `CLAUDE.md`/PRD §/`#NNNN`/`docs/*.md`/`issues/NNNN.md` — it
passed the same way the original string did, not by exemption.

**Criterion 4 — `#0207` untouched.** `scripts/db-reset.sh` itself was not
edited; its sha256 is unchanged (`scripts/db_reset_guard_test.sh`'s own
byte-identity check confirms this every run, including this one). No
assertion in `scripts/db_reset_guard_test.sh` was weakened, relaxed, or
removed.

**Criterion 5 — decided: no, the script should not print an announcement of
what it's about to do before doing it, in this pass or in general.**

- A blocking confirmation prompt is ruled out directly by `CLAUDE.md` §5a:
  agents invoke this non-interactively, sometimes as part of a scoped
  `check.sh` flow, and a prompt would hang rather than protect anyone.
- A non-blocking banner (print-then-proceed) doesn't add real protection
  either, and this issue's own framing shows why: the gap it identifies is
  that a developer reaches for the command *without having been told* what it
  does, and by the time the script is running, that decision is already made
  — a line of stdout after the decision point doesn't undo it, and an agent
  invoking the script programmatically doesn't "read" a banner at all. The
  leverage point is upstream, at the documentation and error-message layer,
  where a reader decides *whether* to run it — which is what this issue's
  other four criteria actually fix.
- The one case that *does* warrant an at-the-moment warning — another
  connection is live, i.e. the multi-agent case — already gets exactly that,
  from `#0207`'s refusal message naming the holder. That is the right model:
  say something when there is a decision left to make (`--force` or not),
  not when there is none (a bare invocation with no live connections has
  already resolved to "proceed").
- This pass is documentation-scoped per its own dispatch and was told
  explicitly not to change the script's behavior, which a bare-invocation
  announcement would be, however small. Nothing above is a workaround of that
  constraint — the reasoning stands independent of it.

### Judgement on the four sites deliberately left alone

- **`CLAUDE.md` §1's repository-layout table cell — call upheld, narrowly.**

  `(drop and rebuild a local DB)` is two words and strictly better, since

- **`docs/deployment.md` — call upheld, and measured rather than accepted.**
  Its five mentions are a file inventory, two historical what-was-exercised

  None is advice pointing a reader at the command as a fix, and the last one
  already satisfies criterion 1 without being touched.
- **`CLAUDE.md` §5a's own bullet — call upheld.** It already says the script
  drops and recreates the database and that `opencircuit` is the user's dev
  database. Nothing to add.
- **`docs/dev.md` — call overturned**, per item 2 above.

### Criterion 5 — the reasoned "no" is accepted, with one qualification

The argument holds on its two strongest legs. A blocking prompt is genuinely
ruled out by `CLAUDE.md` §5a's non-interactive invocation, and the case that
does warrant an at-the-moment warning — a live connection, meaning a decision
about `--force` is still open — already gets one from `#0207`.

The middle leg is weaker than it is written. "An agent would not read a banner"
is true and does not generalise: the developer running the command
interactively is precisely the person this issue was filed about, and they
would read it. The reason to still decline is narrower than "a banner does not
help" — it is that a banner after the decision point buys less than the same
sentence placed where the decision is made, and the six documentation sites are
where it is made. Recorded as a decision not to change the script, with the
reasoning corrected rather than the verdict.
