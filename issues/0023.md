## Description

The interest taxonomy is data, not a Go enum — new workshop themes appear constantly and adding one must not require a deploy.

## Acceptance criteria

- [ ] `interests` table per PRD §6.2: id, slug, name, description, sort_order, active, created_at
- [ ] The twelve seed interests from PRD §6.1 inserted with sensible `sort_order` and `ON CONFLICT DO NOTHING`
- [ ] `internal/interests` store with list-active, get-by-slug, and CRUD operations
- [ ] Slug format enforced: lowercase, hyphenated, unique
- [ ] Down migration drops cleanly
- [ ] `go test ./internal/interests/...` passes against a real database

## Notes

PRD §6.1, §6.2. Seed in the migration rather than in `seed` so a fresh database is immediately usable and the list is identical across environments.

Deactivating an interest must not delete it — existing `subscriber_interests` rows reference it and the historical record matters. `active = false` hides it from the signup form while preserving associations.
