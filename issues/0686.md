## Description

These are minor items from the `#0676`/`#0684` review.

1. **Bound the startup sweep.** Wrap the startup `api.SweepIdempotencyKeys` call in `cmd/opencircuit/main.go` in a `context.WithTimeout` of about 10 seconds, so a slow database can't hold up startup.
2. **Report every bad channel.** When `create_guide_posts` gets several bad `channels` entries, it reports only the last one. Report each one under its own field key.
3. **Close the delete race.** `delete_guide_post` checks that the post is a draft, then deletes it, and a post scheduled in between could still be deleted. Use a conditional `DELETE … WHERE status = 'draft'` and return a 409 when no row matches.

## Plan

The plan pass was folded into the implementation pass, at the user's "keep moving" direction. This plan was written before any code. Batched with `#0682` and `#0683`.

1. **Sweep.** In `servePostgres`, use a local `const startupSweepTimeout = 10 * time.Second` and run the sweep under `context.WithTimeout(ctx, startupSweepTimeout)`, cancelling right after. On a timeout the sweep fails and logs the existing warning. Startup carries on, and per-request sweeps still run. This is the only `main.go` hunk for this issue, kept small for the concurrent `#0678` merge.
2. **Channels.** In `createGuidePostsV1`, each bad entry is reported under `channels.<index>`: 0-based, in request order. Dot notation matches the existing `channels.<name>` and `body.<name>` keys. An empty list is still `channels`. The "lists more than bluesky and mastodon" length case is dropped: any list longer than the channel set necessarily repeats or misnames an entry, so the loop reports each offending entry instead of one summary.
3. **Delete.** Add `guideposts.Store.DeleteDraft(ctx, id) (Post, error)`, a single `DELETE … WHERE id = $1 AND status = 'draft' RETURNING …`.
   - With no row, it returns `ErrNotFound` if the id is unknown, and the new `ErrNotDraft` otherwise.
   - `deletePost`'s `draftOnly` path (v1 only) calls it and maps `ErrNotDraft` to the existing `errDraftOnly`, which is a 409 with the same message.
   - The audit row is unchanged, and takes its slug and channel from the returned row.
   - The admin path (`draftOnly == false`) is unchanged: Get, then `Store.Delete`, which already refuses queued and posted posts with a conditional delete.
   - `DeleteDraft` is added to the `guidePostStore` interface. No fake store implements it.
- **Tests.**
  - `guideposts.TestDeleteDraft_Conditional`: a draft is deleted and its row returned; a second call gives `ErrNotFound`; a post read as a draft and then scheduled is refused with `ErrNotDraft` and kept.
  - `handlers.TestV1GuidePosts_CreateReportsEveryBadChannel`: four entries, three of them bad, each named under its own key, and the valid one not flagged.
  - `TestV1GuidePosts_CreateValidation`'s two channel cases now expect `channels.0` and `channels.1`.
  - The existing `TestV1GuidePosts_DeleteDraftOnly` still covers the 409.
- **Verification tier.** Scoped guideposts, handlers and cmd/opencircuit, then the batch's full `ISSUE=0686 scripts/check.sh`.

## Obstacles

None. There is no migration: the delete is a statement change only.

## Fix

- `cmd/opencircuit/main.go`: the sweep runs under a 10-second `context.WithTimeout`.
- `internal/guideposts/guideposts.go`: `ErrNotDraft`.
- `internal/guideposts/store.go`: `DeleteDraft`.
- `internal/handlers/admin_guide_posts.go`: `guidePostStore.DeleteDraft`. `deletePost`'s `draftOnly` path is one conditional `DELETE`.
- `internal/handlers/v1_guide_posts.go`: per-entry `channels.<index>` keys. The length check is gone.
- Tests: `internal/guideposts/store_test.go`, `internal/handlers/v1_guide_posts_test.go`.

### Assumptions

- **The field key is `channels.<index>`**, not `channels.<value>`. A bad value can be any string, while an index is always a safe, unique key, and a repeated name needs its position anyway.
- **The admin UI's delete is unchanged**, so it may still delete a scheduled or failed post. The race it has is the one `Store.Delete`'s conditional statement already guards: it never deletes a queued or posted post.
