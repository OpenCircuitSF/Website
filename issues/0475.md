# 0475 — There is no supported way to change an interest's slug

## Description

An interest's **display name** can be changed at runtime; its **slug** cannot.
`Store.Update` takes no slug parameter, and `patchInterestRequest` has no slug
field under `DisallowUnknownFields`, so a `PATCH` carrying one returns **400**.
That immutability is deliberate — `#0023` designed it that way.

A migration could change a slug, but **nothing blesses or warns against that**,
and it is not obviously safe: preference-center links already issued to
subscribers encode interests, and `migrations/000009` is frozen so the seed
cannot be corrected at source (`#0471`).

Found by `#0471`'s review, which noted the gap matters most in exactly the case
that motivated the parent work.

## Why it is worth settling rather than leaving implicit

**`#0232`'s spinoff will hit this directly.** The user's scope for it includes
configurable domain nouns — "upcoming events which we are calling workshops for
this website but could be called something else". A second tenant with a
different taxonomy needs different slugs, not different display names, because
slugs appear in URLs and in the preference center's own semantics.

So the question "can a slug change, and at what cost" stops being hypothetical
the moment that work starts. Answering it now is cheap; answering it inside a
larger migration is not.

## Acceptance criteria

1. **Establish what actually breaks** when a slug changes. Trace every place a
   slug is persisted or transmitted — preference-center links, any stored URL,
   `subscriber_interests` if it references by slug rather than id, import
   mappings, campaign audience definitions. **Measure rather than reason**; this
   lineage has repeatedly found the code doing something other than what the
   prose said.
2. Decide the supported answer and record it: slugs are permanently immutable; or
   they may change by migration under stated conditions; or a rename path exists
   that also rewrites what depends on them. **Any of the three is acceptable — an
   unstated answer is not.**
3. If the answer is "immutable", say so where an operator will meet it — the
   admin API's own error, and `docs/mailing-list.md`'s taxonomy section, which
   `#0471` added.
4. **Do not weaken `#0023`'s design** to make a rename possible without deciding
   criterion 2 first. Slug immutability is a deliberate constraint, not an
   oversight.
5. Do not touch `000009` — it is frozen below production's applied version
   (`CLAUDE.md` §1, re-derived as `22|f` on 2026-09-08).
