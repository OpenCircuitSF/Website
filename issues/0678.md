## Description

This is a child of `#0673`. The user wants to "check if we are missing any events for next month". This issue adds a defined, checkable notion of "missing" and an endpoint that reports it.

## Requirements

1. **Cadence rules.** Admins describe what a normal month looks like, for example:
   - "Programming LEDs workshop: 1 a month";
   - "Hack night: every Tuesday".

   Each rule has an event type or title match, a frequency (weekly on a given weekday, or N per month), an optional venue, and an active flag. They are stored in a small table (new migration) and edited under Settings → Event cadence. Cadence rules are also readable and writable over v1 (`events:read` and `events:write`).
2. **`GET /api/v1/events/coverage?month=2026-12`** (`events:read`), with the month defaulting to next month. For each rule it returns:
   - the expected dates or count;
   - the events that match, with id and status;
   - any expected dates with no event;
   - events that exist but are only drafts.

   It also returns events that match no rule, and a Luma comparison for the month using `internal/luma`: which published events are missing from Luma, and where the details differ.
3. **An admin view** of the same report on the Events page: a "Next month" panel. It is optional but cheap, since the endpoint returns the data.

## Acceptance criteria

- Pure Go unit tests cover the coverage calculation: weekly and monthly rules, DST boundaries in America/Los_Angeles, months with five Tuesdays, cancelled events not counting, and drafts flagged.
- Handler tests cover the endpoint.
- The Luma part degrades to "unavailable" if the feed can't be fetched, and never fails the whole report.

## Assumptions (user may override)

- Rules are stated in Pacific time.
- A rule matches by event type first, then by a case-insensitive title prefix.

### Migration `000055_create_event_cadence_rules`

```sql
-- #0678: what a normal month of events looks like, so the coverage report
-- (GET /api/v1/events/coverage) can say what is missing. Rules are stated in
-- America/Los_Angeles. A rule matches by event type, by a case-insensitive
-- title prefix, or by both, and optionally by venue.
CREATE TABLE event_cadence_rules (
    id            BIGSERIAL PRIMARY KEY,
    name          TEXT NOT NULL,
    event_type_id BIGINT REFERENCES event_types(id) ON DELETE CASCADE,
    title_prefix  TEXT,
    frequency     TEXT NOT NULL,
    weekday       SMALLINT,
    per_month     SMALLINT,
    venue_id      BIGINT REFERENCES venues(id) ON DELETE SET NULL,
    active        BOOLEAN NOT NULL DEFAULT true,
    created_at    TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at    TIMESTAMPTZ NOT NULL DEFAULT now(),
    CONSTRAINT event_cadence_rules_name_check CHECK (char_length(btrim(name)) BETWEEN 1 AND 120),
    CONSTRAINT event_cadence_rules_prefix_check CHECK (title_prefix IS NULL OR char_length(btrim(title_prefix)) BETWEEN 1 AND 120),
    CONSTRAINT event_cadence_rules_match_check CHECK (event_type_id IS NOT NULL OR title_prefix IS NOT NULL),
    CONSTRAINT event_cadence_rules_frequency_check CHECK (
        (frequency = 'weekly'  AND weekday BETWEEN 0 AND 6 AND per_month IS NULL) OR
        (frequency = 'monthly' AND per_month BETWEEN 1 AND 31 AND weekday IS NULL))
);
```

- `weekday` uses Go's `time.Weekday` numbering, with 0 for Sunday.
- The down migration is `DROP TABLE event_cadence_rules;`.
- Deleting an event type deletes its rules. A rule whose type is gone describes nothing, and `eventtypes.Delete` needs no change. Deleting a venue only drops the rule's venue filter.

### New package `internal/cadence`

- **`rule.go`.**
  - `type Frequency string`, with `Weekly` and `Monthly`.
  - `type Rule struct{ ID int64; Name string; EventTypeID *int64; TitlePrefix string; Frequency Frequency; Weekday *time.Weekday; PerMonth int; VenueID *int64; Active bool; CreatedAt, UpdatedAt time.Time }`. `TitlePrefix` is `""` for none, and `PerMonth` is 0 for a weekly rule.
  - `func (r Rule) Validate() map[string]string` is pure. It applies the same rules as the CHECKs, with field-named messages, for example `"weekday": "a weekly rule needs a weekday"`. Admin and v1 both call it.
  - `func (r Rule) Describe() string` gives text like "every Tuesday" or "2 a month".
  - `func ParseWeekday(string) (time.Weekday, bool)` accepts lowercase English names; `WeekdayName` does the reverse.
- **`store.go`.**
  - `Store{pool}` with `List(ctx) ([]Rule, error)` (by id), `Get`, `Create(ctx, Rule)`, `Update(ctx, id, Rule)` (full replace, `updated_at = now()`) and `Delete`.
  - The sentinels are `ErrNotFound`, plus `ErrEventTypeNotFound` and `ErrVenueNotFound`, mapped from SQLSTATE 23503 by constraint name.
  - It also has `main_test.go`, a `testdb` `TestMain` copied from `internal/venues/main_test.go`.
- **`coverage.go`** is **pure**: no DB, no clock, no network.

  ```go
  type Month struct{ Year int; Month time.Month }
  func ParseMonth(s string) (Month, error)          // "2026-12"; anything else → error
  func NextMonth(now time.Time) Month               // the month after now's Pacific month
  func (m Month) Bounds() (from, to time.Time)      // time.Date(y, m, 1, 0,0,0,0, LA) and the next month's first midnight, in LA
  type Event struct{ ID int64; Slug, Title, Status string; StartsAt time.Time; EventTypeID int64; VenueID *int64 }
  type Report struct{ Month Month; From, To time.Time; Rules []RuleCoverage; Unmatched []Event }
  type RuleCoverage struct {
      Rule           Rule
      ExpectedDates  []string // weekly: every <weekday> date in the month, "2006-01-02"; nil for monthly
      ExpectedCount  int      // weekly: len(ExpectedDates); monthly: PerMonth
      Events         []Event  // matching, not canceled, in start order
      Canceled       []Event  // matching but canceled: listed, never counted
      MissingDates   []string // weekly: expected dates with no published or draft event
      DraftOnlyDates []string // weekly: expected dates covered only by drafts
      Drafts         []Event  // matching events still in draft
      Missing        int      // weekly: len(MissingDates); monthly: max(0, PerMonth - len(Events))
      State          string   // "ok" | "drafts" (covered, but some only by drafts) | "missing"
  }
  func Compute(m Month, rules []Rule, events []Event) Report
  ```

- **Matching** (`func (r Rule) Matches(e Event) bool`):
  - the event's type equals the rule's type when the rule has one;
  - `strings.HasPrefix(strings.ToLower(e.Title), strings.ToLower(strings.TrimSpace(r.TitlePrefix)))` when the rule has a prefix;
  - the venue is equal when the rule has one.

  All of the rule's set conditions must hold. An event counts toward **every** rule it matches. `Unmatched` is the non-canceled events in the month that match no **active** rule. Inactive rules are skipped entirely.
- **Dates.** An event's date is `StartsAt.In(LA)`'s calendar date, and only events with `StartsAt` in `[from, to)` are considered. Undated events are ignored, because a draft with no date isn't in any month. Weekly dates are enumerated with `time.Date(y, m, d, 12, 0, 0, 0, LA)`, which is noon, so DST never moves a date.
- **Weekly matches.** For a weekly rule, a matching event on a non-expected date is still listed in `Events`. It doesn't fill another date.

### Handlers: one service, two adapters

- **New `internal/handlers/event_coverage.go`.**

  ```go
  type cadenceRuleStore interface { List(ctx) ([]cadence.Rule, error); Get(ctx, int64) (cadence.Rule, error); Create(ctx, cadence.Rule) (cadence.Rule, error); Update(ctx, int64, cadence.Rule) (cadence.Rule, error); Delete(ctx, int64) error }
  type workshopLister interface { List(ctx) ([]workshops.Workshop, error) }
  type EventCadenceHandler struct { rules cadenceRuleStore; events workshopLister; luma lumaFeed; auditor *audit.Logger; baseURL string; now func() time.Time }
  func NewEventCadenceHandler(rules cadenceRuleStore, events workshopLister, luma lumaFeed, auditor *audit.Logger, baseURL string) *EventCadenceHandler
  func (h *EventCadenceHandler) report(ctx context.Context, month string) (coverageV1, error) // "" = NextMonth(h.now())
  func (h *EventCadenceHandler) setRule(ctx context.Context, ip string, actorID *int64, id *int64, r cadence.Rule) (cadence.Rule, error)
  func (h *EventCadenceHandler) deleteRule(ctx context.Context, ip string, actorID *int64, id int64) error
  ```

- **`report`**:
  1. List the rules and the workshops.
  2. Map each workshop with a start time to a `cadence.Event`.
  3. Run `cadence.Compute`.
  4. Add the Luma part.
- **The Luma part.** If `h.luma` is nil, the status is `off`.
  - Otherwise `snap := h.luma.Feed(ctx)`. **When `snap.Status != ok`, the section is `{status, last_good_at}` with empty lists and the report still returns 200.** The Luma part never fails the report.
  - When it is OK, `luma.Compare` runs over the month's **published** events, converted by a helper extracted from `AdminOutreachHandler.Luma`, `lumaWorkshopFor(wk workshops.Workshop) luma.Workshop`, which both routes then call.
  - `not_on_luma` and `differs` (with `luma_url`, `luma_title` and `diffs`) come from the results.
  - `only_on_luma` is the leftovers with `Start` in `[from, to)`. `Compare` already drops leftovers before `now`, so for a past month this list is partial; the response says so in a `note`.
- **`coverageV1`** holds `month` ("2026-12"), `zone` ("America/Los_Angeles"), and `from` and `to` (Pacific offsets), plus:
  - `rules`: each with `rule` (a `cadenceRuleV1`), `expected {dates, count}`, `events`, `canceled`, `drafts`, `missing_dates`, `draft_only_dates`, `missing` and `state`;
  - `unmatched_events`;
  - `luma {status, read_at, last_good_at, not_on_luma, differs, only_on_luma, note}`;
  - `summary {rules, missing, drafts, unmatched}`.

  Each event in it is `{id, slug, title, status, starts_at (Pacific), admin_url: "<base>/admin#/workshops/<id>", public_url}`, so an agent can act on the list. Every slice is non-nil.
- **`setRule`**:
  - It runs `Validate()`, then `Create` or `Update`.
  - It audits `event_cadence.created` or `event_cadence.updated`, with `TargetEventCadenceRule` and metadata `{name, frequency, weekday, per_month, event_type_id, title_prefix, venue_id, active}`, through `middleware.AttributeAPIToken`.
  - A validation failure returns `*cadenceFieldError{fields}`.
- **`deleteRule`** audits `event_cadence.deleted`.
- **Admin session routes** go in `admin_event_cadence.go`, on the same struct, mounted in `main.go`'s admin route table next to `/admin/workshops`:
  - `GET /admin/event-cadence` returns `{rules: [...]}`;
  - `POST /admin/event-cadence` creates;
  - `PATCH /admin/event-cadence/{id}` replaces the whole rule, since the form always sends all of it;
  - `DELETE /admin/event-cadence/{id}`;
  - `GET /admin/event-coverage?month=` returns the same `coverageV1` JSON as v1.

  Validation gives a 400 through the existing `writeError(w, 400, msg)` (`auth.go`; no admin helper carries `fields`) with the first message in field order. The form already shows `ruleFormErrors` before it submits, so the server message is only the backstop.
- **Audit constants** (`internal/audit/actions.go`): add `ActionEventCadenceCreated = "event_cadence.created"`, `ActionEventCadenceUpdated` and `ActionEventCadenceDeleted`, and `TargetEventCadenceRule = "event_cadence_rule"`.

| Name | Method and path | Scope | Flags | In → Out |

- **`event_coverage`**: a bad month gives `Validation{"month": "must be YYYY-MM"}`. The literal path `/api/v1/events/coverage` outranks `#0677`'s `GET /api/v1/events/{id}` in the Go 1.22 mux. `TestV1Coverage_PathNotShadowed` pins it.
- **`setCadenceRuleIn`**: `{ID *int64 omitempty jsonschema:"omit to create; an existing id to replace that rule"; Name string; EventTypeID *int64; TitlePrefix *string; Frequency string jsonschema:"weekly or monthly"; Weekday *string jsonschema:"weekly only: sunday … saturday"; PerMonth *int jsonschema:"monthly only: 1 to 31"; VenueID *int64; Active *bool jsonschema:"default true"}`.
  - An unknown `id` gives 404. A bad weekday name gives `Validation{"weekday": …}`.
  - Both create and replace answer 200, because `Status` is fixed per op.
- **`cadenceRuleV1`**: `{id, name, description, event_type {id, slug, name} | null, title_prefix, frequency, weekday, per_month, venue {id, name} | null, active, created_at, updated_at}`. The names come from one `EventTypes.ListAll` and one `Venues.ListAll`, the `#0677` deps.
- **No `delete_cadence_rule` tool.** Deleting stays admin-only, and `set_cadence_rule` with `active: false` retires a rule. This keeps `#0679`'s spec tool list exact.

## Assumptions (user may override)

- **Rules are stated in Pacific time** (issue default). Month bounds, weekdays and event dates are all America/Los_Angeles.
- **A rule matches by event type, by a case-insensitive title prefix, or by both.** When both are set, both must hold. An optional venue narrows the match further. One event can count toward several rules. This is how the issue's "type first, then prefix" is read: the type picks the kind of event, and the prefix narrows within or across types.
- **Frequencies are "weekly on a weekday" or "N a month".** "Every other week" and "first Tuesday" are out of scope; an "N a month" rule covers them as a count.
- **Drafts cover a date, but are flagged.** A date or count met only by drafts is `state: "drafts"`, not `"missing"`. Canceled events never count, and are listed separately.
- **Undated events are ignored** by the coverage report.
- **Luma covers published events only**, as outreach's Luma check does. For a past month, "only on Luma" is partial, because `luma.Compare` drops events before now, and the response says so.
- **There is no delete tool.** `set_cadence_rule` with `active: false` retires a rule, and delete is in the admin UI only.
- **Deleting an event type deletes its cadence rules. Deleting a venue clears a rule's venue filter.**
- **Rule edits are audited** as `event_cadence.*`, against the token for v1 writes.
