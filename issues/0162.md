## Description

`#0151`'s hint — *"Unsaved interest changes are not included — save first."* — inherits `class="text-muted"` from the paragraph it is appended to. So the one sentence in that panel most likely to change an admin's next action renders in the same de-emphasised grey as the surrounding explanation of what the button does.

`#0143`'s targeting sentence has the same treatment, and it carries the same weight: it is what tells an admin the draft will go to **everyone** rather than to a segment.

Both are correct, both are easy to skim past.

## Acceptance criteria

- [ ] The unsaved-changes hint is visually distinguished from the surrounding explanatory copy — a warning-styled element, not muted body text
- [ ] Consider the same for `#0143`'s "will target everyone on the list" sentence, which is the higher-stakes of the two. Decide whether one, both, or neither should change, and record the reasoning
- [ ] Whatever styling is chosen exists already in the design system rather than being invented here — check `app.css` for what `.badge-danger` and its siblings offer, and match the console's existing vocabulary for warnings
- [ ] Consider `role="status"` or an equivalent so the hint is announced when it appears, since it appears in response to an action rather than on load. Note `#0063` (accessibility audit) owns the console-wide version of this question — do not build a bespoke pattern here that it would then have to undo
- [ ] `scripts/check.sh web` passes
