## Description

Establish the project-wide guidance file and the `docs/` structure so every later phase has a documented home, and subagents dispatched against issues load consistent conventions.

## Acceptance criteria

- [ ] `CLAUDE.md` at the repo root: stack summary, build/verify commands, directory map, code conventions, and what lives where
- [ ] `README.md` rewritten for Open Circuit SF — features, stack table, quick start, production build
- [ ] `docs/README.md` index with a per-topic table
- [ ] Stub docs created with real headings: `architecture.md`, `configuration.md`, `database.md`, `auth.md`, `passkeys.md`, `frontend.md`, `design.md`, `mailing-list.md`, `email-setup.md`, `unsubscribe.md`, `seo.md`, `dev.md`, `deployment.md`
- [ ] `CLAUDE.md` states the rule that `go build` passing is not verification and names the actual test commands

## Notes

PRD §3.1. ShortLinks' `docs/` is the model — each subsystem gets one doc, and `architecture.md` carries the system diagram plus a "where to look" table.

`docs/email-setup.md` can start as a port of ShortLinks' `email_setup.md` with the domain swapped, then gets extended by #0027 and #0057.

The stubs are not filler: each phase's issues expect a place to write, and creating them now avoids a documentation-debt cleanup later.
