## Review notes

2026-10-17, phase 3 (Opus): approved.

- **Coverage.** Every `Mention` field `mastoMention` fills from the payload is now NUL-free. `RemoteID` and `Author` are stripped by the fix. `Text` goes through `mastodon.PlainText`, whose `x/net/html` parser drops NUL from body text and replaces it with U+FFFD in RCDATA, raw-text, CDATA and foreign content, so no text node it emits can hold one. `URL` goes through `httpsURL`, and `url.Parse` rejects a raw control byte, so a NUL-bearing link becomes nil; when `StatusURL` is empty the fallback is the already-stripped URI. `Kind`, `Channel` and the `"unknown"` fallback are constants; `QuotedStatusID` and `InReplyToID` are only map keys.
- **Order.** Stripping before the empty-URI check is right: a URI that is only NUL bytes has no identity to dedupe on, so it is skipped like an absent one rather than stored as an empty `remote_id`.
- **Test.** The new case uses `\x00` source escapes (checked by bytes with python3: two escapes, no raw NUL in the file), which Go turns into real NUL bytes at runtime. Mutation: with the one `stripNUL` line removed from a copy-aside of `tracker.go`, `TestMastoMention` failed on the new case (`NUL not stripped`); the file was then restored from the copy, and both SHA-256 hashes matched.
- **Verification.** Load average 2.72. `ISSUE=0557 scripts/check.sh go ./internal/outreach/... ./internal/db/... ./internal/handlers/...`: all three packages ok, no skips, VERIFICATION PASSED.
- **Follow-up (not in scope).** `mastoMentions` saves `items[0].ID`, the notification id taken from the JSON, with `SetMentionCursor` without stripping it. A NUL there would fail the cursor write, and the paged loop would then re-read the same page on every run. Our own instance issues numeric ids, so the risk is lower than this issue's. The fix would be to reject, not strip, an id that contains NUL, because a stripped id names a different notification. Worth checking whether the Bluesky cursor has the same gap.

## Description

From `#0555`'s review. `mastoMention` (`internal/outreach/tracker.go`) writes
`n.StatusURI` to `remote_id` and `n.Acct` to `author` straight from the JSON;
neither goes through `PlainText`, so an escaped NUL in either would fail the
insert and stall the Mastodon walk, as `#0555` fixed for Bluesky. Low risk
(our own instance validates both), one-line fix.

## Acceptance criteria

- [x] `stripNUL` is applied to every payload string `mastoMention` stores (or once, to every string column, inside `InsertMention`); a test case with NUL in `acct` and the status URI proves it.
- [x] Verified with `ISSUE=0557 scripts/check.sh go ./internal/outreach/... ./internal/db/...`.

## Fix

`mastoMention` now applies `stripNUL` to `n.StatusURI` and `n.Acct` at the top, so the empty-URI check also sees the stripped value. `Text` already passes through `PlainText`, the link goes through `httpsURL`, and the reply/quote lookups are map reads, so nothing else reaches a column unfiltered.
