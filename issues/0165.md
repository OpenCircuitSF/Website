# 0165 — `truncateAdminWiringTables` would corrupt a sibling test if any `cmd/opencircuit` test ever gained `t.Parallel()`

## Description

`cmd/opencircuit`'s wiring tests use five fixed literal session tokens (`"zz-events-nonadmin-token"`, `"zz-shutdown-budget-token"`, and three more without a `zz-` prefix). They do not collide today, and `#0163`'s review established *why* — but the stated reason was wrong on both counts, and the real one carries a trap.

**Not** because "each package truncates at `TestMain`": `cmd/opencircuit`'s `TestMain` truncates nothing, it only takes `testdb.Lock()`. And the tokens are in the *same* package, so a per-package truncate could not separate them even in principle.

The actual mechanism is `truncateAdminWiringTables`, which runs on entry **and** again in `t.Cleanup`. That is stronger than the claimed one: it does not depend on `-shuffle` ordering and does not depend on the tests living in different packages.

**But it does depend on `t.Parallel()` never appearing in `cmd/opencircuit`** — currently zero occurrences, verified. If any wiring test ever gains it, the per-test `TRUNCATE` would destroy a concurrently running sibling's rows mid-test. That failure is worse than a token collision and far more confusing: nothing in the package would attribute it correctly, and it would present as an unrelated test mysteriously losing its fixtures.

## Acceptance criteria

- [ ] A comment on `truncateAdminWiringTables` states that it truncates shared tables and is therefore incompatible with `t.Parallel()` in this package
- [ ] Decide whether a stronger guard is warranted than a comment — e.g. the helper failing loudly if it detects parallel execution — and record the reasoning. A comment is the cheap insurance; a guard is the one that survives someone not reading it
- [ ] Consider whether the five fixed literal tokens should draw from `testdb.Unique()` anyway, so correctness stops depending on the truncate at all. `#0163` left them alone as out of scope, which was right for that issue
- [ ] `ISSUE=0165 scripts/check.sh go ./cmd/opencircuit/...` passes

## Notes

Reported by `#0163`'s phase-3 review under `CLAUDE.md` §9. Nothing is wrong today; this is about a foot-gun left armed for whoever next reaches for `t.Parallel()` to speed the package up.

Worth noting the shape: the safety property here is real but *undocumented and unenforced*, which is the same condition that produced `#0140` (a checker that could not fail), `#0150` (a destructive default), and `#0141` (a tracked file a build overwrites). Each was safe until someone did the obvious thing.
