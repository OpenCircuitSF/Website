## Review notes

- **Items checked against the code and the review's A1 to A6 and J2.** 1: `ADMIN_NAV_GROUPS` matches A2's grouping exactly; `ADMIN_NAV_SECTIONS` is derived from it and still holds all 13 sections plus Overview, so every old `#/<section>` hash resolves as before (the Outreach sub-routes are unchanged). The select is a native `<select>` with an `aria-label`, so it is keyboard operable, and its `onchange` sets the hash. The wide links get `display:none` at 480px and below, so screen readers do not hear both. 2: done (see the fix below). 3: done; a failed `listOutreach` degrades to "Not started". 5: done. 6: done; the Settings link uses #0584's `?section=outreach` deep link.
- **Pagination is not a concern.** `GET /admin/workshops` returns every workshop (`workshops.Store.List`, no paging, by design), and `GET /admin/outreach` returns every summary. So the client-side join is complete.
- **Fix: "upcoming" excluded undated workshops.** `upcomingPublished` dropped any workshop with no `starts_at`. The server offers outreach for any published workshop, with no date check (`panel` in `admin_outreach.go`). The public list (`workshops.ListVisible`) counts an undated workshop as upcoming. So a published workshop with its date still TBD could not be reached from the Outreach list, and the row's "Date TBA" branch could never render. Now the rule is the public one: `starts_at >= now`, or no date. Undated rows sort last. Time zone is not a factor, since both sides compare instants. A workshop that started an hour ago drops off, which also matches the public list.
- **Fix: item 4's labels pointed at the wrong views.** The implementation labelled the global flyer list "Flyer spots" and kept "Locations" beside it. In the review, a "spot" is a saved location: "all four spots ticked", "a Spots table… a 'Put up' toggle each". So the link to `view=locations` now reads **Flyer spots**. The flyer list keeps its own link, **Flyers**, until batch 9 moves flyers into the workshop page (§4.1). The sub-nav now reads Posts · Flyer spots · Flyers · Results. The test asserts that the Flyer spots href goes to `locations`.
- **Dashboard isolation holds in one direction only.** If the outreach loads fail, the overview still loads (separate `try`, and on failure no items show). But the items render inside the overview's `{:else if overview}` block, so an overview failure hides them behind the error and Retry. That is acceptable. The comment claimed both directions and now says what is true.
- **Mutation test.** Replaced the select's `onchange` body with a no-op. The new test "navigates when the narrow-screen select changes" fails. Restored by copy: `Admin.svelte` sha256 `5876c4ecd62a2148…` before and after.
- **Verification** (load 3.4–4.1): `ISSUE=0586R scripts/check.sh web` gives `npm run check` 0 errors, and vitest 4581 passed, 3 failed. All three failures are in `src/lib/outreachResults.test.ts` `buildChart`, against `web/src/lib/outreachResults.ts`, which another agent has uncommitted edits in. Neither this issue nor this review touched it. The three files this issue owns ran alone: 17 of 17 passed. All of this is jsdom only. "No more than two rows at 390 px" is still not proven in a real browser. The select swap makes it one row by construction, but a Tart render is the evidence still owed.
- **Follow-ups, not blocking:** (a) every row's link is named only "Promote" or "Open". Add `aria-label="Promote <title>"` so a links list can tell rows apart. (b) Past workshops that have outreach no longer appear on the landing list. They are still reachable from the editor panel and Results, which follows §4.1, but a "Past" section or a link under Results would help. (c) The Locations and Flyers views' own panel titles still say "Locations" and "Flyers"; the Locations title could become "Flyer spots" to match the sub-nav. (d) In the Dashboard, a failed connections call also drops the unannounced count, because `Promise.all` couples them. `Promise.allSettled` would keep whichever half loaded.

## Resolution notes

> 🟢 Resolved 2026-10-18 — Grouped admin nav with a narrow-screen select, an Outreach list of every published upcoming workshop (undated included) with chip and one button, an Outreach column on Workshops, outreach items in Needs attention; the reviewer corrected the Flyer spots label (`0398701`).

## Resolution

1. Nav: `ADMIN_NAV_GROUPS` in `adminRouter.ts` (Mailing list / Workshops / System, Overview standalone); `ADMIN_NAV_SECTIONS` is now derived from it. `Admin.svelte` renders grouped links and, at 480px and below, a single `<select>` with optgroups in their place (one row). The #0584 Settings jump nav is untouched.
2. `Outreach.svelte` landing lists published upcoming workshops (`listAdminWorkshops` + `listOutreach`, joined client-side) with a chip and one Promote/Open link. The old empty state is gone; with no eligible workshop it says to publish one with a future date.
3. `Workshops.svelte` gains an Outreach column with the same chip (a failed `listOutreach` degrades to "Not started", never blocks the list).
4. Sub-nav: Posts · Locations · Flyer spots · Results (Locations kept: it is still a distinct view).
5. `OutreachEditorSummary.svelte`: "Promote this workshop" / "Open outreach · N posted".
6. `Dashboard.svelte` Needs-attention box adds "Not connected: … Connect in Settings → Outreach." and "N upcoming workshops not yet announced." ("announced" = nothing posted or scheduled). Loaded separately so a failure there never blanks the overview.

Pure logic is in the new `web/src/lib/outreachList.ts`.
