## Description

This is a child of `#0673`. It exposes the API to MCP clients such as Claude Code, Claude Desktop and others, so a session can say "schedule next week's guide posts" and do it.

## Requirements

1. **Transport.**
   - MCP Streamable HTTP at `POST/GET /mcp`, served by the existing binary.
   - Use the official Go SDK (`github.com/modelcontextprotocol/go-sdk`) unless the plan finds a blocking problem.
   - Apache already proxies everything except `/.well-known/`. Verify that `/mcp` gets through, and that streaming responses aren't buffered.
2. **Auth.**
   - `Authorization: Bearer ocsf_…`, resolved by the same `RequireAPIToken` path.
   - Every tool call checks the scope its operation needs.
   - A missing or invalid key gets an HTTP 401, so a client prompts for one.
3. **Tools.** Each tool is a thin adapter over the **same service functions as the v1 handlers**, not an HTTP call back to itself. Tool names and JSON schemas are generated from, or tested against, the v1 registry.
   - `whoami`
   - `list_guides`, `get_guide`
   - `list_guide_posts`, `create_guide_posts`, `update_guide_post`, `schedule_guide_post`, `unschedule_guide_post`, `send_guide_post`, `post_guide_again`, `delete_guide_post`, `guide_posts_overview`, `list_channels`
   - `list_events`, `get_event`, `create_event`, `update_event`, `publish_event`, `unpublish_event`, `cancel_event`, `duplicate_event`
   - `list_venues`, `list_event_types`, `list_interests`
   - `event_coverage`, `list_cadence_rules`, `set_cadence_rule`
4. **Descriptions.**
   - Each tool's description says what it does, which scope it needs, and any side effect. For example, `send_guide_post` posts publicly and right away.
   - Destructive or public tools say so first, so clients that ask before acting can ask.
5. **Tools follow the key.** The server registers only the tools the calling key's scopes allow, so a read-only key never sees write tools.
6. **Limits.** Tool calls count against the token's rate limit (`#0674`) and are audited as API-key actions.

## Acceptance criteria

- Go tests drive the MCP handler with the SDK's client over an in-memory or `httptest` transport. They cover:
  - `tools/list` filtered by scope;
  - a successful `create_guide_posts` and `list_events`;
  - a scope denial;
  - an invalid key getting a 401.
- A parity test asserts every v1 write operation has a tool, or is listed as deliberately excluded.
- A local smoke test with `claude mcp add --transport http ocsf http://localhost:8080/mcp --header "Authorization: Bearer <key>"` is recorded in the issue, with the key redacted.

Nothing calls back over HTTP, and no tool is written by hand.

### SDK facts (checked 2026-11-15)

- **Module.** `github.com/modelcontextprotocol/go-sdk` **v1.8.0**, tagged 2026-09-04. It is the latest stable release; `v1.8.0-pre.*` and earlier come before it. It declares `go 1.25.0`, and our `go.mod` is `go 1.26.3`, so there is no toolchain bump.
- **Dependencies it adds.** `github.com/google/jsonschema-go v0.4.3` (already added by `#0675`, same version), `github.com/segmentio/encoding v0.5.4` and `segmentio/asm`, `github.com/yosida95/uritemplate/v3 v3.0.2`, and `golang.org/x/oauth2 v0.35.0`.
- **Already satisfied.** Its `x/tools v0.42`, `x/time v0.15`, `x/sync`, `x/sys` and `golang-jwt/jwt/v5 v5.3.1` are already met by our `go.mod`, so nothing is downgraded or bumped.
- **Server:** `mcp.NewServer(&mcp.Implementation{Name, Title, Version}, &mcp.ServerOptions{Instructions: ...})`.
  - The low-level `(*Server).AddTool(*mcp.Tool, mcp.ToolHandler)` takes `ToolHandler = func(ctx, *mcp.CallToolRequest) (*mcp.CallToolResult, error)` and the raw `req.Params.Arguments` (`json.RawMessage`). Use this form, not the generic `mcp.AddTool[In, Out]`.
  - The generic form infers its own schema and unmarshals with its own decoder, which would make the second decoding path that `#0675`'s `op.Decode` exists to prevent.
  - The low-level form requires a non-nil `InputSchema` of type `object`, which `#0675`'s `Define` guarantees.
- **`mcp.Tool` fields:** `Name`, `Description`, `InputSchema`, `OutputSchema` (`any`, taking a `*jsonschema.Schema`), and `Annotations *mcp.ToolAnnotations{ReadOnlyHint bool, DestructiveHint *bool, IdempotentHint bool, OpenWorldHint *bool, Title}`.
- **Transport:** `mcp.NewStreamableHTTPHandler(getServer func(*http.Request) *mcp.Server, &mcp.StreamableHTTPOptions{...})`. The fields used:
  - `Stateless: true`: no `Mcp-Session-Id`, and a temporary session per request. GET and DELETE return 405, which Streamable HTTP allows.
  - `JSONResponse: true`: responses are `application/json`, never `text/event-stream`.
  - `MaxRequestBodyBytes`: the default is 4 MiB; set it to 64 KiB, matching v1.
  - `DisableLocalhostProtection`: see "Apache" below. This is the one setting production breaks without.
  - `Logger`.
- **`getServer` runs twice per request** in v1.8.0: once for protocol-version negotiation and once to serve. It must be cheap; hence the cache below.
- **Auth bridge.** `auth.RequireBearerToken(verifier auth.TokenVerifier, &auth.RequireBearerTokenOptions{AllowMissingExpiration: true})` puts an `*auth.TokenInfo{Scopes, Expiration, UserID, Extra map[string]any}` in the request context.
  - The transport copies it into every call's `req.Extra.TokenInfo`. That is the SDK-supported way for a tool handler to see the caller.
  - **Do not rely on the handler's `ctx` carrying our own context values.** The SDK documents that it detaches the context for long-running streams.
  - `TokenVerifier` is `func(ctx, token string, req *http.Request) (*auth.TokenInfo, error)`.
  - `AllowMissingExpiration` is required because a key may never expire (`#0674`).
- **Errors.** If a `ToolHandler` returns a Go error, the SDK turns it into a JSON-RPC error. Our handler instead returns `&mcp.CallToolResult{IsError: true, Content: ...}` with a nil error, which the spec treats as a tool error the model can read and act on.
- **Client, for tests:** `mcp.NewClient(&mcp.Implementation{...}, nil).Connect(ctx, &mcp.StreamableClientTransport{Endpoint: url, HTTPClient: c}, nil)` returns a `*mcp.ClientSession`, with `ListTools(ctx, nil)` and `CallTool(ctx, &mcp.CallToolParams{Name, Arguments})`. `HTTPClient` takes a custom `RoundTripper` that adds `Authorization` and can override `Host`.
  - `mcp.NewInMemoryTransports()` exists but bypasses HTTP, and with it auth.
  - Use `httptest.NewServer` over the real handler chain instead, since the auth path is what most of the acceptance tests check.

### Apache (checked 2026-11-15)

The repo copy `deploy/apache/installed-001-www.opencircuitsf.com-le-ssl.conf` and the live vhost were read read-only over `ssh photon` and compared.

- **`/mcp` gets through.** The only exclusions ahead of `ProxyPass / http://127.0.0.1:${PORT_OPENCIRCUIT}/` are `/.well-known/`, `/prototypes` and `/media`. **No vhost change is needed.**
- **The vhost sets `ProxyPreserveHost On`.** The Go service therefore receives `Host: www.opencircuitsf.com` on a connection whose local address is `127.0.0.1`.
  - The SDK's default DNS-rebinding protection rejects exactly that combination with **403 "Forbidden: invalid Host header"**: a loopback local address with a non-loopback Host.
  - Production `/mcp` would 403 on every request without `DisableLocalhostProtection: true`.
  - Disabling it is safe here, because every request must carry a valid `ocsf_` bearer before it reaches the SDK, and no cookie authenticates `/mcp`. The test `TestMCPAcceptsProxiedHost` pins it.
- **Buffering.** `mod_deflate` and `mod_brotli` are loaded, but no `AddOutputFilterByType` or `SetOutputFilter` appears anywhere under `/etc/httpd/conf*`. Only `/api/events` sets `flushpackets=on`.
  - An SSE response on `/mcp` might therefore be held in `mod_proxy`'s buffer.
  - `Stateless` + `JSONResponse` **sidesteps this entirely**: every response is one complete `application/json` body, and the stateless GET (the only long-lived stream) is a 405.
  - Apache's default `Timeout` of 60s applies (none is set), which is far above any tool call here.
- **Drift found, not in this issue's scope.** The live vhost differs from the repo's `installed-…` copy in three ways:
  - `${PORT_OPENCIRCUIT}` instead of `8080`;
  - per-site log paths with a `vhostlog` format;
  - a comment saying `CLAUDE.md` where the copy says `AGENTS.md`.

  Reported to the orchestrator to file as an issue.

### Design (new package `internal/mcpserver`)

```go
// mcpserver.go
type Deps struct {
    Registry *api.Registry
    Resolver middleware.APITokenResolver
    Limiter  *middleware.RateLimiter // the SAME instance the /api/v1/ router uses: one budget per key
    Logger   *slog.Logger
}
func NewHandler(d Deps) http.Handler
```

`NewHandler` composes this chain, outermost first:

1. `middleware.RequireAPIToken(d.Resolver, "")`. It gives the same 401 and `WWW-Authenticate` as v1, which makes a client prompt for a key. That satisfies requirement 2's "same `RequireAPIToken` path".
2. `middleware.APITokenRateLimit(d.Limiter)`. Each `initialize`, `tools/list` and `tools/call` is one POST, so each counts against the key's 120 a minute.
3. `auth.RequireBearerToken(verifyFromContext, &auth.RequireBearerTokenOptions{AllowMissingExpiration: true})`.
4. `mcp.NewStreamableHTTPHandler(s.serverFor, &mcp.StreamableHTTPOptions{Stateless: true, JSONResponse: true, DisableLocalhostProtection: true, MaxRequestBodyBytes: 64 << 10, Logger: d.Logger})`.

`d.Registry.Freeze()` is called before step 4.

The verifier is `verifyFromContext(ctx, _ string, r *http.Request)`. It does not resolve the token a second time: it reads `middleware.APITokenFromContext(r.Context())`, which step 1 set. If that is missing it returns `auth.ErrInvalidToken`, which cannot happen behind step 1. Otherwise it returns:

```go
&auth.TokenInfo{
    Scopes: tok.Scopes,
    UserID: "token:" + id,
    Extra:  map[string]any{"token": tok},
}
```

`Expiration` is `*tok.ExpiresAt` when the key has one.

`serverFor(r)` builds a server per scope set and caches it:

- It reads the token from the context.
- The cache key is `strings.Join(slices.Sorted(scopes), ",")`, stored in a `sync.Map` of `*mcp.Server`.
- On a cache miss, `newServer(scopes)` creates `mcp.NewServer(&mcp.Implementation{Name: "opencircuitsf", Title: "Open Circuit SF", Version: reg.Version()}, &mcp.ServerOptions{Instructions: instructions, Logger: d.Logger})`. It then adds `toolFor(op)` for each `op` in `reg.Operations()` with `op.MCPExcluded == ""` and `apitokens.ScopeSatisfies(scopes, op.Scope)`.
- Servers are safe to share across keys with the same scopes, because no tool handler closes over a key: each reads it from `req.Extra.TokenInfo`.
- **This is requirement 5**: a read-only key's `tools/list` never contains a write tool.

`instructions` is a constant. It says:

- times are RFC 3339 with an offset, and the site's zone is America/Los_Angeles;
- tools follow the key's scopes;
- call `whoami` to check the connection;
- tools marked PUBLIC act publicly right away.

`toolFor(op)` returns an `*mcp.Tool` plus a `mcp.ToolHandler`. The tool is:

- `Name`: `op.Name`.
- `Description`: `op.Describe()`, which already starts with `DESTRUCTIVE:` or `PUBLIC:` when that applies and ends with the required scope (requirement 4).
- `InputSchema`: `op.InputSchema()`.
- `OutputSchema`: `op.OutputSchema()`.
- `Annotations`:
  - `ReadOnlyHint`: `op.Method == GET`;
  - `DestructiveHint`: `&op.Destructive`;
  - `IdempotentHint`: `op.Method` is GET or DELETE;
  - `OpenWorldHint`: a pointer to `op.PublicEffect != ""`;
  - `Title`: `op.Summary`.

The handler does the following, in order:

1. Take `tok` from `req.Extra.TokenInfo.Extra["token"].(apitokens.Token)`. If it is missing, return `errorResult(api.Error{Status: 401, Code: "unauthorized", ...})`.
2. Check `apitokens.ScopeSatisfies(tok.Scopes, op.Scope)` again. This is belt-and-braces, because the cached server already filtered by scope; on failure return `errorResult(api.Forbidden(op.Scope))`.
3. Set `ctx = middleware.WithAPIToken(ctx, tok)`. This is what makes `middleware.AttributeAPIToken`, and with it `#0674`'s audit attribution (requirement 6), work for tool calls exactly as for REST.
4. Run `in, err := op.Decode(req.Params.Arguments)`. Nil or empty arguments are treated as `{}`. A failure returns `errorResult(err)`.
5. Run `out, err := op.Call(ctx, in)`. A failure returns `errorResult(api.AsError(op.Name, err))`; `AsError` logs the raw error and returns the safe message.
6. On success, return `&mcp.CallToolResult{StructuredContent: out, Content: []mcp.Content{&mcp.TextContent{Text: string(jsonOut)}}}`. The text block carries the same JSON for clients that ignore structured content.

`errorResult(e *api.Error)` returns `&mcp.CallToolResult{IsError: true, Content: []mcp.Content{&mcp.TextContent{Text: <api.ErrorBody JSON>}}}` and a nil Go error. It deliberately has no `StructuredContent`, so a client cannot validate an error against the tool's success `OutputSchema`.

The REST and MCP error bodies are therefore byte-identical envelopes. The text never contains the raw underlying error, and never contains the key.

```go
// mcptest/mcptest.go: shared by this package's tests and by #0676–#0678's handler tests
func Connect(t *testing.T, h http.Handler, bearer string) *mcp.ClientSession // httptest.NewServer(h); StreamableClientTransport with a RoundTripper adding Authorization; t.Cleanup closes both
```

**A tool that is called but not in the key's list** gets the SDK's own "unknown tool" error (a JSON-RPC invalid-params error). That is the scope-denial behaviour a client sees. The test asserts it, and asserts that the handler's step-2 forbidden result is reachable when a server is built directly with a wider tool set.

**Mount** (`cmd/opencircuit/main.go`, `mountAndServe`, inside the same `if t := settingsH.APITokens(); t != nil` block as `#0675`'s `/api/v1/` mount):

```go
// MCP (#0679): Streamable HTTP, stateless JSON, over the same registry and
// the same per-key rate limit as /api/v1/. Bearer only; no session cookie.
mux.Handle("/mcp", mcpserver.NewHandler(mcpserver.Deps{Registry: t.V1(), Resolver: t.Resolver(), Limiter: apiTokenLimiter, Logger: slog.Default().With("component", "mcp")}))
```

`"/mcp"` with no method matches POST, GET and DELETE, and only the exact path; `/mcp/x` falls to the SPA's `GET /`. In dev mode (`STORAGE=json`) there are no API tokens, so `/mcp` is not mounted, just as `/api/v1/` is not.

## Assumptions (user may override)

- **Stateless Streamable HTTP with JSON responses.** There are no sessions, no SSE, and no server-to-client requests (sampling or elicitation). Every tool here is request and response, so nothing is lost, and Apache buffering cannot affect it.
- **No `Idempotency-Key` for MCP calls in v1.** A client that retries a `create_guide_posts` call could create duplicates. If that turns out to matter, a later issue can add an optional `idempotency_key` tool argument that maps onto `#0675`'s store.
- **A tool outside the key's scopes is invisible**, rather than listed and refused. Calling one gets the SDK's "unknown tool" error.
- **`get_engagement` is also a tool**, since it is read-only and costs nothing. **`token_probe` is not**: it is a deprecated alias of `whoami`.
- **The MCP rate limit is shared with `/api/v1/`**: one budget per key, 120 requests a minute (`#0674`), counted per HTTP request.
- **No OAuth and no `/.well-known/oauth-protected-resource`.** Keys are admin-created bearer tokens (`#0673`). A 401 carries `WWW-Authenticate: Bearer realm="opencircuitsf"` with no `resource_metadata`, which Claude Code handles by using the configured header.
