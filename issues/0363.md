## Description

`claimCommentGuardDirWordRe` in
`internal/outbox/claim_comment_referent_guard_test.go` is `\b(below|above)\b`
with **no `(?i)` flag**. So a sentence-initial `Below,` or `Above,` — the most
natural way to write a forward reference in Go prose — **never enters the
directional axis at all**.

**This is not a calibration trade.** `#0358` exists to record the axis's
deliberate trades, each of which buys something against a real opposing error.
This one buys nothing: nothing is gained by excluding a capitalised direction
word.

**It has already misled a review.** `#0347`'s third review probed the fixture
`// Below, ClaimDue …` believing it measured the axis's backwards-only window
limit. It did not — the regex never matched, so the axis was never entered, and
the probe measured nothing. `#0358`'s review found this by mutation: adding a
forward-looking window, the exact change that fixture claims to guard, leaves
the whole calibration table **green**.

**The fix is measured free.** `#0358`'s reviewer flipped the flag and measured:
`go test ./internal/outbox/` stays green, the whole-tree scan stays at **0
findings** across 271 files and 30,843 comment groups, and `#0342`'s sites A and
C are still caught.

It was left unfixed there only because `#0358`'s criterion 4 forbids changing
the window logic — hence this issue.
