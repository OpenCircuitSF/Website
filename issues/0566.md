## Description

Brennan, 2026-10-17, after the image upload refused with "MEDIA_DIR is
unset": "Every ENV var really should be something I set in Settings."

`#0564` did this for the seven outreach connection variables. Apply the same
pattern to every remaining variable that can safely live in the database.
Some cannot, and the plan must say which and why. A variable is needed before
the database is reachable, or it protects the admin login itself, or it
names the host the passkeys are bound to.

`internal/config` reads today: `ADMIN_EMAIL`, `AWS_REGION`, `BASE_URL`,
`DATABASE_URL`, `EMAIL_FROM`, `EMAIL_LIST_DOMAIN`, `EMAIL_REPLY_TO`,
`MEDIA_DIR`, `SES_CONFIGURATION_SET`, `SES_EVENTS_TOPIC_ARN`,
`SES_INBOUND_BUCKET`, `SES_INBOUND_TOPIC_ARN`, `SESSION_SECRET`, `STORAGE`,
`WEBAUTHN_RP_ID`, `WEBAUTHN_RP_ORIGIN`, plus the `#0564` set, plus anything
`cmd/opencircuit` reads directly (`PORT`, `MAILER_NOOP`,
`SEND_WORKER_ENABLED`, `SES_SANDBOX`, dev flags). The planner re-derives the
full list from the code.

## Acceptance criteria

- [ ] **Classify every variable** in the plan as one of:
  - **Settings**: moves to admin Settings, with DB then env then default
    precedence as in `#0564`.
  - **Bootstrap**: stays in `config.env`, with a one-line reason. Expected
    examples: `DATABASE_URL`, `SESSION_SECRET`, `WEBAUTHN_RP_ID`,
    `WEBAUTHN_RP_ORIGIN`, `PORT`, `STORAGE`.
  - **Dev-only**.

  Treat safety guards with care. `MAILER_NOOP`'s production refusal (AGENTS.md
  §10) must not become something a Settings click can bypass.
- [ ] Settings variables appear in the admin Settings section, grouped (for
      example Email, Amazon SES, Media), following `#0564`'s UI and
      write-only-secret patterns where a value is sensitive. Each field shows
      its source (saved, environment, default, unset).
- [ ] Each setting takes effect without a restart where practical. Where a
      restart is unavoidable (for example a worker that only starts at boot),
      the UI says so next to the field.
- [ ] **`MEDIA_DIR`** gets a production default of `/var/www/media`, or is
      set in Settings. The upload error points to Settings and states that
      the directory must also be writable by the service
      (`scripts/enable-media-upload.sh`).
- [ ] Values are validated as `#0564` does; changes are audited by field
      name only.
- [ ] `docs/configuration.md` gains a column saying where each variable is
      set, and `.env.example` stays in step (its guard stays green).
- [ ] Go handler and store tests, plus jsdom SPA tests. Verified with
      `ISSUE=0566 scripts/check.sh` plus the AGENTS.md §5 guard packages the
      change reaches. Zero skips.

### Classification — every variable the binary reads

Re-derived from the code: `grep -rn 'Getenv\|LookupEnv\|os\.Environ' --include='*.go' . | grep -v _test.go`.
`internal/config/config.go` reads 30 variables; two more are read elsewhere.
Nothing in `cmd/opencircuit` calls `os.Getenv` directly: `PORT`, `MAILER_NOOP`,
`SEND_WORKER_ENABLED`, `SES_SANDBOX` and `DEV_ADMIN_LOGIN` all come through
`config.Load`.

**Settings, live** (new "Server settings" panel; takes effect on the next request):

| Variable | Group | Reason it is safe |
|---|---|---|
| `MEDIA_DIR` | Media | Read at upload time and when a post builds its thumbnail. Writes are images with generated names, and systemd's `ReadWritePaths=` confines them. Default `/var/www/media` (D5). |
| `SES_SANDBOX` | Amazon SES | Only a display flag: the dashboard's "still sandboxed" warning (`admin_dashboard.go:478`). It gates nothing. |
| `SES_INBOUND_BUCKET` | Amazon SES | Where a verified inbound notification's object is fetched from. The trust boundary is the topic ARN, which stays in `config.env`. IAM limits which buckets the role can read. |

**Settings, restart required** (saved now; read once at boot):

| Variable | Group | Why not live |
|---|---|---|
| `EMAIL_FROM` | Email | Consumed by the SES mailer, send worker, send store, preflight and preview, all built at boot. Live reload would mean threading a value source through six constructors in the most heavily guarded path, and a mid-campaign change would split one campaign across two From identities. A restart happens at every deploy. |
| `EMAIL_REPLY_TO` | Email | Same consumers as `EMAIL_FROM`. |
| `EMAIL_LIST_DOMAIN` | Email | Same, plus the outbox worker. A mid-campaign change would split the `List-Unsubscribe` mailto domain. |
| `SEND_BATCH_SIZE` | Sending | Read once by `mailing.NewWorker`. |

`EMAIL_FROM` and `EMAIL_LIST_DOMAIN` **stay required in `config.env`** as well
(`config.Load` is unchanged). The env value is the floor that a cleared
Settings value falls back to, so no Settings click can make the next boot fail
(D3). `#0105`'s "fail loud at boot when missing" decision is kept as it is.

**Already Settings** (`#0564`, unchanged): `SHORTLINKS_BASE_URL`,
`SHORTLINKS_API_TOKEN`, `BLUESKY_HANDLE`, `BLUESKY_APP_PASSWORD`,
`BLUESKY_PDS_URL`, `MASTODON_BASE_URL`, `MASTODON_TOKEN`.

**Bootstrap** (stay in `config.env`):

| Variable | Reason |
|---|---|
| `DATABASE_URL` | Needed to reach the database that Settings lives in. |
| `STORAGE` | Chooses whether there is a database at all. |
| `PORT` | The listener binds before any request can reach Settings, and the systemd drop-in pins it. |
| `BASE_URL` | Both loopback guards (`checkMailerNoOp`, `newDevAdminAutoLogin`) are decided by its host. If it were editable from Settings, one click plus a restart could turn on no-op mail or the dev-admin bypass in production. It is also baked into the SEO site at boot. |
| `WEBAUTHN_RP_ID`, `WEBAUTHN_RP_ORIGIN` | The passkeys are bound to these. A wrong value locks every admin out of the screen that would fix it. |
| `SESSION_SECRET` | A secret that protects admin auth. Note: today it is only *required*, never read. Sessions are random tokens stored in the database. Out of scope here; reported to the orchestrator. |
| `ADMIN_EMAIL` | Registration grants `is_admin` to this address (`auth/registration.go:62`), and the seed and the dev-admin login key off it. If Settings could change it, a hijacked admin session could plant a permanent admin for another address. |
| `AWS_REGION` | Paired with the instance's IAM role, and read by the AWS SDK's own default chain. The SES, S3 and SNS clients are built from it at boot. |
| `SES_CONFIGURATION_SET` | Half of the `#0472` recipe in `newSESSender`. If it lived in the database, a Settings clear plus a restart could crash-loop boot (`NewSESMailer` refuses without it) and lock the admin out of Settings. |
| `SEND_WORKER_ENABLED` | The other half of `#0472`. It is also a **per-instance** scaling knob ("exactly one instance sets this true"), and the database is shared by all instances, so it cannot express that. |
| `MAX_SEND_RATE` | The deploy-level ceiling over the `max_send_rate` dial, which already lives in Settings (the `settings` table). If the ceiling moved into Settings too, one screen could raise both, which defeats a cap that exists to match the SES quota. |
| `SES_EVENTS_TOPIC_ARN`, `SES_INBOUND_TOPIC_ARN` | SNS trust anchors: they decide which AWS topic may suppress or unsubscribe subscribers. They stay with the other trust anchors, outside the app's own write path. |

**Dev-only** (stay in the environment; never in Settings):

| Variable | Reason |
|---|---|
| `MAILER_NOOP` | Refused outside a loopback `BASE_URL` (AGENTS.md §10). That guard stays exactly as it is. |
| `DEV_ADMIN_LOGIN` | Refused outside a loopback `BASE_URL`. It is an authentication bypass. |
| `SES_INBOUND_OBSERVATION_LOG` | A temporary `#0500` diagnostic, read once in `handlers/ses_inbound.go:245`. |
| `TEST_DATABASE_URL` | Tests only (`internal/testdb`). |

The AWS SDK's own variables (`AWS_PROFILE`, static keys) are read by the SDK,
not by this code, and are out of scope.

### Decisions

**D1 — Parallel package `internal/serversettings` with its own table. Do not generalise `internal/outreachconn`.**
The core of `outreachconn.Manager` is client lifecycle: rebuilding only on a
key change, keeping the Bluesky session, `Test`, and `LiveShortLinks`. The part
the two packages would share is about 70 lines: a key/value store and the
precedence loop. Extracting it means either a table name passed in as a
parameter (dynamic SQL) or a new interface layer, and it would churn a package
reviewed the same day. A parallel copy of those 70 lines is cheaper and safer.
The new package has no clients, no listeners, no secrets, and no `Test`.
Reuse the outreach *shapes* (JSON layout, `Source` values, PATCH semantics,
the audit metadata form) so the SPA and the reviewers see one pattern.

**D2 — Table `server_setting_values` in `migrations/000038_create_server_setting_values`.**

```sql
CREATE TABLE server_setting_values (
    key        TEXT PRIMARY KEY,
    value      TEXT NOT NULL,
    updated_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    CONSTRAINT server_setting_values_key_check CHECK (key IN (
        'media_dir', 'email_from', 'email_reply_to', 'email_list_domain',
        'ses_sandbox', 'ses_inbound_bucket', 'send_batch_size')),
    CONSTRAINT server_setting_values_value_check CHECK (
        value <> '' AND char_length(value) <= 2048)
);
```

Down: `DROP TABLE IF EXISTS server_setting_values;`. The header comment says:
- why the table is not the `settings` table: `#0564` D1's three reasons, and
  "no row" means "fall back"
- that it is owned by `internal/serversettings`

If the comment cites a constraint, use the exact identifiers above (the
`#0459` guard checks them). None of these values is a secret, so there is no
at-rest question.

**D3 — Precedence and the no-lockout invariant.** Per field, as in `#0564` D4:
1. A database row wins (source `database`).
2. Otherwise a non-blank env value (source `environment`). An env value equal
   to the field's effective default is reported as `default`.
3. Otherwise the effective default (`default`).
4. Otherwise `unset`.

Clearing a field deletes its row. **Invariant: no value saved in Settings can
make the service fail to boot.**
- Every value is validated on write.
- The two required email fields keep their env floor.
- The restart-time overlay (D6) only copies values already validated.
- The only new boot failure is a failed database read in the first `Reload`,
  the same as `#0564`.

**D4 — Fields** (`internal/serversettings/fields.go`). `Field{Key, Group, EnvVar string; Default string; RestartRequired bool}`.
List them in this order: the CHECK list must match, and the SPA renders in it.

| Key | Group | EnvVar | Default | Restart |
|---|---|---|---|---|
| `media_dir` | `media` | `MEDIA_DIR` | `/var/www/media` (overridable, D5) | no |
| `email_from` | `email` | `EMAIL_FROM` | | yes |
| `email_reply_to` | `email` | `EMAIL_REPLY_TO` | | yes |
| `email_list_domain` | `email` | `EMAIL_LIST_DOMAIN` | | yes |
| `ses_sandbox` | `ses` | `SES_SANDBOX` | `true` | no |
| `ses_inbound_bucket` | `ses` | `SES_INBOUND_BUCKET` | | no |
| `send_batch_size` | `sending` | `SEND_BATCH_SIZE` | `50` | yes |

`Groups = []string{"media", "email", "ses", "sending"}`. Provide
`FieldByKey(key) (Field, bool)` and constants `KeyMediaDir`, `KeyEmailFrom`,
and so on.

**D5 — `MEDIA_DIR` default.** The effective default is `/var/www/media`,
**except** when `BASE_URL`'s host is loopback, where it is `""` (so the field
is unset). A dev laptop has no `/var/www/media`, and a default there would log
an unwritable-directory warning at every start. `cmd/opencircuit` computes it:

```go
// serverSettingsDefaults returns per-instance overrides of serversettings' static defaults.
func serverSettingsDefaults(cfg *config.Config) map[string]string {
    if baseURLIsLoopback(cfg.BaseURL) { return map[string]string{serversettings.KeyMediaDir: ""} }
    return nil
}
```

The manager's effective default for a key is `defaults[key]` when the key is
present in the map, otherwise `Field.Default`.

**D6 — Live and restart.**
- Live fields are read through manager getters on every use: `MediaDir()`,
  `SESSandbox()`, `SESInboundBucket()`.
- Restart fields are overlaid onto `cfg` once at boot by `applyBootSettings`
  (F6), before anything that reads them is built.
- The manager records the effective values from its **first** successful
  `Reload` as `boot`.
- A field is `pending_restart` when `RestartRequired` is set and its current
  effective value differs from `boot`. Saving the old value back clears the
  flag.
- The UI shows a restart note next to every restart field, and a stronger note
  when the field is pending (F9).

**D7 — Validation** (`internal/serversettings/validate.go`). Trim first.
`ValidationError{Key, Msg}` has `Error() == Key + ": " + Msg`. Messages are
fixed and never echo the value. All fields reject control characters
(`unicode.IsControl`) and anything over 2048 bytes; for the email fields this
also blocks header injection through CR/LF.

| Key | Rule | Stored as | Message |
|---|---|---|---|
| `media_dir` | `filepath.IsAbs`; `filepath.Clean(v) != "/"` | `filepath.Clean(v)` | `must be an absolute directory path other than /` |
| `email_from` | `mail.ParseAddress(v)` succeeds | `v` (trimmed, not re-rendered) | `must be an email address, optionally with a display name` |
| `email_reply_to` | same | `v` | same |
| `email_list_domain` | lowercase it and strip one trailing `.`; ≤253 chars; ≥3 labels; each label 1–63 of `[a-z0-9-]`, not starting or ending with `-` | lowercased | `must be a mail subdomain such as lists.example.org, never a bare domain` |
| `ses_sandbox` | `strconv.ParseBool` | `"true"` / `"false"` | `must be true or false` |
| `ses_inbound_bucket` | 3–63 chars of `[a-z0-9.-]`; first and last are alphanumeric | `v` | `must be an S3 bucket name (3 to 63 lowercase letters, digits, dots or hyphens)` |
| `send_batch_size` | `strconv.Atoi`, 1–500 | decimal string | `must be a whole number from 1 to 500` |

Do not restrict `media_dir` to an allow-list. The real confinement is systemd
(`ProtectSystem=strict` + `ReadWritePaths=`), and the thumbnail reader only
accepts files that sniff as JPEG or PNG. Writability is **not** a save-time
check: an admin may save the path first and run the script afterwards. It is
reported as a group error instead (D8).

**D8 — Media group error** (computed in `Snapshot`, fixed strings). The
manager takes `probe func(dir string) error`; main passes `media.CheckWritable`.

| Condition | Text |
|---|---|
| Effective `media_dir` is `""` | `No media directory is set, so image uploads are refused. Save one here; the service must also be able to write to it (scripts/enable-media-upload.sh).` |
| `probe(dir) != nil` | `The service cannot write to this directory, so image uploads are refused. Run scripts/enable-media-upload.sh on the server, or choose a directory the service can write to.` |

A nil probe skips the check. Never put `err.Error()` into the snapshot.

**D9 — API.** Both routes are admin-only, registered through `adminRoutes()`.

| Route | Purpose |
|---|---|
| `GET /admin/server-settings` | Current state |
| `PATCH /admin/server-settings` | Set and/or clear; returns the new state |

Body:

```json
{"groups":[{"name":"media","error":"…","fields":[
  {"key":"media_dir","env_var":"MEDIA_DIR","source":"default","value":"/var/www/media",
   "default":"/var/www/media","restart_required":false,"pending_restart":false}]}, …]}
```

PATCH semantics are identical to `#0564` D7. The request is
`{"values": {...}}`, decoded into `map[string]*string`.
- An absent key is unchanged.
- A non-blank value sets the field.
- Blank or whitespace clears it.
- `null` → 400 `values.<key> must be a string`.
- An unknown key → 400 `unknown key: <key>`.
- An empty or missing map → 400 `values is required`.
- Validation is all-or-nothing.
- A `*ValidationError` → 400 with `ve.Error()`.
- Any other error → 500 `internal server error`.
- Success → 200 with the GET body.

```go
type Source string // "database" | "environment" | "default" | "unset", constants as in outreachconn
type FieldState struct { Field; Source Source; Value, EffectiveDefault string; PendingRestart bool }
type GroupState struct { Name, Error string; Fields []FieldState }
type Snapshot struct{ Groups []GroupState }
type Applied struct{ Set, Cleared []string }
type store interface { All(ctx) (map[string]string, error); Apply(ctx, map[string]string, []string, time.Time) error }

type Manager struct {
    store store; env, defaults map[string]string; probe func(string) error; log *slog.Logger
    mu  sync.Mutex             // serialises Reload and Apply
    cur atomic.Pointer[state]  // state{values map[string]string; sources map[string]Source}; immutable
    boot atomic.Pointer[map[string]string] // effective values at the first successful Reload
}
func NewManager(st store, env, defaults map[string]string, probe func(string) error, log *slog.Logger) *Manager
func (m *Manager) Reload(ctx context.Context) error
func (m *Manager) Apply(ctx context.Context, values map[string]string, now time.Time) (Applied, error)
func (m *Manager) Snapshot() Snapshot
func (m *Manager) Value(key string) string     // current effective value
func (m *Manager) MediaDir() string
func (m *Manager) SESSandbox() bool             // ParseBool(Value); on error true (the safe assumption, matching config's default)
func (m *Manager) SESInboundBucket() string
```

- `NewManager` starts every value unset; a nil log means `slog.Default()`.
- `Reload` / `Apply`: same algorithms as `outreachconn` (`Apply`: normalise
  everything first; read `All`; compute the real set and clear; on no-op return
  `Applied{}` with no write; otherwise `store.Apply` then `reloadLocked`).
  Precedence is D3, with the effective default from D5.
- After a successful reload, if `boot` is nil, store a copy of the values.
- `Snapshot`:
  - groups and fields in D4 order
  - `PendingRestart = f.RestartRequired && boot != nil && values[k] != (*boot)[k]`
  - the media group's `Error` per D8
- Log `server settings: saved` with `"set", setKeys, "cleared", clearKeys` at
  Info on a real change. Keys only.

```go
// applyBootSettings copies the restart-time server settings into cfg. Values
// are already validated (saved values on write, env values by config.Load),
// and the two required fields keep their env floor, so this cannot leave cfg
// unbootable.
func applyBootSettings(cfg *config.Config, s interface{ Value(string) string }) {
    cfg.EmailFrom = s.Value(serversettings.KeyEmailFrom)
    cfg.EmailReplyTo = s.Value(serversettings.KeyEmailReplyTo)
    cfg.EmailListDomain = s.Value(serversettings.KeyEmailListDomain)
    if n, err := strconv.Atoi(s.Value(serversettings.KeySendBatchSize)); err == nil && n > 0 {
        cfg.SendBatchSize = n
    }
}
```
