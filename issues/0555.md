## Resolution notes

> 🟢 Resolved 2026-10-16 — `bskyMention` strips NUL from every string it stores, and both channels' page caps now have tests asserting the Warn line.

## Description

From `#0547`'s review. JSON allows an escaped NUL (`\u0000`) in a post's
text; Postgres rejects NUL in `text` columns ("null character not
permitted"). `InsertMention` fails on that item, the Bluesky walk stops there
every pass, its high-water mark never advances, and once the item ages past
the 10-page cap older mentions on those pages are skipped. Mastodon is not
affected (its HTML-to-text step drops NUL).

## Root cause

`bskyMention` copied the notification's URI, handle and text into a `Mention` unchanged; a JSON-escaped NUL reached Postgres, which rejects it, so `InsertMention` failed on that item every pass.

## Fix

New `stripNUL` helper applied to URI, AuthorHandle and Text at the top of `bskyMention`. The stored URL is built with `url.PathEscape`, which already encodes NUL, so it needs nothing.

## Review notes

Phase 3 (Opus), 2026-10-16, against `063f7a2`.

- **Bluesky columns.** Of the eight values `InsertMention` writes, the payload reaches `remote_id`, `author` and `text`, and all three now pass through `stripNUL` before use. `kind` is one of three fixed literals, `created_at` is a parsed time, and `url` is built with `url.PathEscape`, which encodes NUL. `httpsURL` adds a second barrier, since `url.Parse` refuses ASCII control characters and returns nil.
- **The TestBskyMention case** puts NUL in both the text and the handle and checks the stored text, the stored author, and that `RemoteID` holds no NUL. Sound.
- **Page-cap tests.** The Bluesky test serves 10 chained full pages (100 items each, every one carrying a cursor). The Mastodon test serves 10 chained full pages of 80 items, keyed by `min_id`. Each asserts exactly `maxNotificationPages` requests, which an uncapped walk would exceed by one because it would fetch an empty 11th page. Each also asserts `level=WARN`, the cap message and the channel attribute. Both genuinely hit the cap.
- **Verification, rerun independently.** Load average was 2.43 before the run. Because this is the last Phase 10 issue, the run was the full unscoped `ISSUE=0555 scripts/check.sh` (Go and web): VERIFICATION PASSED. 24 Go packages reported ok, including `internal/outreach`, with no skips; the only `[no test files]` entry is the `web` embed package. svelte-check reported 0 errors, and vitest passed 60 files and 4387 tests.
- **Follow-up, not filed by this pass:** the description's line "Mastodon is not affected" holds only for `text`. `mastoMention` writes `n.StatusURI` to `remote_id` and `n.Acct` to `author` straight from the JSON, without passing them through `PlainText`, so an escaped NUL in either field would stall the Mastodon walk the same way. The risk is low, because both come from our own instance, which validates account names and ActivityPub ids. A one-line fix is to apply `stripNUL` to those two fields in `mastoMention`, or to every string inside `InsertMention`, and add a test case for it.
