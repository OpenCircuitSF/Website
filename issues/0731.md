## Description

From the handoff's Discovery section. A docs page, a machine-readable server card and a footer link make the public MCP server (`#0729`) findable.

**Two repo facts shape this.**

1. **`/mcp` is the MCP endpoint itself.** Content negotiation there would mix SPA and MCP handling on one route, so the human docs go at **`/agents`**. A browser GET to `/mcp` (`Accept: text/html`, not an MCP request) may redirect to `/agents`. That is decided at plan time, without breaking MCP clients.
2. **`/.well-known/` is not served by the Go service.** Apache serves it from disk (`ProxyPass /.well-known/ !`, AGENTS.md §7) because it holds the domain's Bluesky `atproto-did`. So `/.well-known/mcp.json` needs one of:
   - a static file deployed into `/var/www/vhosts/www.opencircuitsf.com/.well-known/`, or
   - a single `ProxyPass /.well-known/mcp.json` exception ahead of the `!` rule.

   Either way, the `atproto-did` hash check (`4198e742…5948d`) must still pass after the change.

## Acceptance criteria

- [ ] An SPA view at `/agents` with an `internal/seo` static fallback, following `#0519`'s fallback-copy guard pattern. It shows:
  - the endpoint `https://www.opencircuitsf.com/mcp`;
  - `claude mcp add --transport http opencircuitsf https://www.opencircuitsf.com/mcp`;
  - an `mcpServers` JSON snippet;
  - the tool list;
  - a note that the server is read-only and needs no account.

  The tool list comes from the public server's own tool definitions, or a guard ties the two together, so they cannot drift.
- [ ] The route is in the sitemap. The `/agents` view goes through `routeViews.ts` like any other route (`#0717`), so the entry chunk stays within PRD §7.6's budget.
- [ ] A footer link "Use with AI agents" to `/agents`. `Footer.svelte` and the static fallback footer stay in parity (`TestFallbackNavCoversHeaderNav` and friends).
- [ ] `/.well-known/mcp.json` serves a small server card: name, description, endpoint, transport, auth `none`, tool names. Before implementing, check the current SEP-2127 / MCP Server Cards format at modelcontextprotocol.io and cite the version used in the file's generator or in `docs/`. Generate the card from the public server's tool list so it cannot drift. The Apache or deploy change goes in `deploy/apache/` and `docs/deployment.md`.
- [ ] After deploy: `curl` the card and `/agents` on production, and confirm the `atproto-did` hash is unchanged.
