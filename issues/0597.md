## Resolution

- **Mastodon account on reload:** `Manager.reloadLocked` starts a background `verify_credentials` (`lookupMastodonAccount`) whenever the Mastodon client is rebuilt, bounded by a 5s context, so neither startup nor a settings save waits on it. Success caches `@user@host` exactly as a manual Test does; failure keeps the bare host and logs only `group=mastodon`, never the token or upstream text. Hosts in the reserved `.test`/`.example`/`.invalid` TLDs are skipped (they cannot resolve). All inside `internal/outreachconn`; `cmd/opencircuit/main.go` is untouched.
- **`splitBody`:** resolved by documentation. A body carries no marker saying whether its final hashtag-only paragraph is template or typed, so it stays tail; Save message recomposes message + tail, so nothing is lost, only that paragraph is not editable from the Message field. A real fix needs the server to mark the appended paragraph. Documented on `splitBody` and pinned by a test (including the round trip).
- **Single alert:** in `ServerSettings.svelte` only the mount that owns the precedence note (`showNote`) renders `role="alert"` and Retry; the second mount shows the text quietly. A two-mount shared-store test asserts one alert and one Retry.
- **`thumbOK`:** named interface `thumbOKer` plus `var _ thumbOKer = (*outreach.Publisher)(nil)`.

## Review notes

Opus review, 2026-10-18. **Approved with a reviewer fix; resolved.**

- **Stale result, found and fixed (`5f135cf3`).** As committed, a slow reload lookup for a replaced token could finish after the newer token's lookup and overwrite `maAcct` with the old key; `Account` then fell back to the bare host until the next reload or Test. `rememberMastodonAccount` now discards a result whose URL+token key is not the current `maKey`, which covers the manual Test path too. The lookup is now started after `m.cur.Store(next)`, so a fast answer is compared with the config it was fetched under rather than discarded against the previous one. New `TestStaleMastodonAccountLookupIsDiscarded` (stubbed lookup, no network): the old lookup blocks until the new one has cached, then answers. Mutation: deleting the key check fails it (`Account ... = "127.0.0.1:…", want "@new@127.0.0.1:…" kept`); restored by sha256 `e2713b31…` matching.
- **Goroutine lifetime.** Bounded by the 5s timeout on `context.Background()`; it never outlives a production Manager by more than that, and shutdown need not wait for it. Tests: `newMgr` now registers `t.Cleanup(m.lookups.Wait)`, and the reload test's second manager does too, so no lookup outlives the test that started it (`#0470`). `status` in `TestMastodonAccountFetchedOnReload` became an `atomic.Int32`: the handler goroutine reads it and a socket is no happens-before edge for the race detector. The outreachconn Mastodon tests pass under `-race`. Outside this package, every test that configures Mastodon uses a `.example` host (skipped) or an unconfigured URL, so no test reaches a real instance.
- **Token never logged.** The failure log carries `group` only; the test checks a token canary is absent. **Reserved-TLD skip:** it skips only the background lookup; the group is still built and validated, Account shows the host, and a manual Test still runs, so it hides no misconfiguration.
- **`splitBody`.** The criterion allowed documenting instead; the doc is accurate (Save message recomposes message + tail) and the new test pins both the split and the round trip.
- **Single alert.** The `showNote` mount (Server settings) keeps `role="alert"` and Retry; the Outreach mount still shows the error text, just not announced. The two-mount test asserts one alert and one Retry. jsdom evidence only.
- **`thumbOKer`.** The compile-time assertion is in place, and `thumbOK` uses the named interface, so a rename fails to compile.
- Verification: `ISSUE=0597R scripts/check.sh go ./internal/outreachconn/... ./internal/handlers/... ./internal/outreach/...` all `ok`, no skips, gofmt clean; `ISSUE=0597R scripts/check.sh web` 84 files / 4708 tests and svelte-check pass.
- Follow-up suggestion (not filed): the Outreach mount's quiet error has no Retry of its own, so someone who deep-links to `#settings-outreach` has to scroll up to Server settings to retry. A one-line pointer there would help.
