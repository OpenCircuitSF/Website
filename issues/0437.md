## Description

`#0123` added `/archive` as a static route. **Neither test that covers static
routes includes it:**

- `TestRender_StaticRoutesGetDistinctTitles`' `paths` slice omits it.
- `TestSitemap_ContainsStaticRoutesWithLastmod`'s `want` map omits it.

So a **title collision** on `/archive`, or a **dropped `<loc>`** for it in the
sitemap, passes both tests today.

This is the coverage half of `#0425`'s finding. That issue is comments-only —
its four stale doc comments all miscount the same route set — and `#0425`'s
review kept the coverage gap out of it deliberately, which was the right call:
correcting a comment and adding an assertion are different work.

**Unverified by the orchestrator** — this is `#0425`'s reviewer's measurement.
Reproduce it before building on it.

## Why it is worth closing rather than recording

The archive index is a **public, indexable page** the user is about to rely on:
`#0405` gives the newsletter a stable `/archive/09-2026` URL, and the whole
point of the archive is that search engines find it. A missing sitemap entry for
the index itself would be silent and would not surface until someone checked
Search Console.

It is also cheap — two existing tables gain a row each.

## What makes this the same family, and why that matters

route set: `resolve`'s doc comment, the package doc's step 2,
`maxCacheEntries`' doc comment, `defaultStaticRouteMeta`'s doc comment, and

without a sweep of the prose and fixtures around it.

**So do not fix only the two named.** Sweep for anything else enumerating static

obvious reflex is to demand that the fixtures be *derived* from the production

### Oracle independence, checked per fixture rather than accepted

`CLAUDE.md` §8's rule is *can an edit to the subject also satisfy the oracle* —
not "does the fixture look like a list". Taking the four in turn:

- `TestRender_StaticRoutesGetDistinctTitles` — independent. The oracle is
  rendered HTML: an extracted `<title>` compared for collision, and an `og:url`
  substring compared against the requesting path. The fixture is a list of
  *inputs*, not a copy of the expected output.
- `TestRender_JSONLD_StaticRoutesHaveNoBlock` — independent, same shape. The
  oracle is the absence of `application/ld+json` in the rendered body.
- `TestSitemap_ContainsStaticRoutesWithLastmod` — independent. The `want` map is
  compared against `<loc>` elements unmarshalled from `Sitemap.Build()`'s real
  XML, not against `marketingRoutes`.
- `TestIsKnownRoute_StaticRoutes` — **the one worth arguing about, and it
  passes.** Its `known` slice is a hand copy of `knownStaticRoutes`' keys, and
  the implementer flagged it as "the closest to a literal-vs-literal shape".
  It is not the §8 failure shape, for a reason the implementer did not state:
  §8's hazard is an oracle an edit to the subject *also* rewrites — a copy of
  the answer stored next to the question. Here subject (`internal/handlers/routes.go`)
  and oracle (`internal/handlers/routes_test.go`) are separate files, so no
  single edit to the route table can satisfy the assertion. Nor did the
  implementer "edit one side to make the mutation fire": the fixture already
  held `/archive` from criterion 1, and the mutation was applied to the
  production map alone.

  Its real limitation is **directional, not circular** — it is a one-way
  membership assertion, so it catches a *removal* from `knownStaticRoutes` and
  not an *addition* to it. That is exactly the drift that produced this issue,
  and it is exactly what `TestRouteTableParity_StaticRoutes` already covers
  from the other side.

### The `og:url`-not-title finding: real, correctly recorded, and not a defect

Reproduced independently. Deleting the `/archive` entry from
`defaultStaticRouteMeta` fails `TestRender_StaticRoutesGetDistinctTitles`
through its `og:url` assertion (`og:url does not reference the requesting
path`, the rendered tag holding `https://www.opencircuitsf.com/`); neither the
title-collision check nor the trailing distinct-count check fires, because the
fallback bucket's title does not collide with any of the other five.

**This is the test behaving correctly, not weakly, and it is not this issue's
to fix.** The property the title assertion measures is *distinctness*, and
under that mutation distinctness genuinely still holds — the fallback title
really is different from the other five. The property actually violated is
"the route table supplies metadata for `/archive`", and that is what `og:url`
measures. An assertion firing for the property that was broken is the right
outcome; only the test's *name* suggests otherwise. The implementer wrote the
mechanism into `## Verification` so the next reader does not assume title
collision is what fires, which is the correct disposition.

One further probe this review ran, beyond the issue's four: setting
`/archive`'s `Title` to the empty string while leaving `OGURL` correct **passes**
the test. That is a genuine gap — distinctness is not non-emptiness — but it is
**route-agnostic and pre-existing**: the same mutation on `/about` or
`/privacy` would pass identically, and it predates `#0123`. It is not
`/archive` coverage, which is what this issue is about. Reported to the
orchestrator as a follow-up candidate rather than folded in here; the remedy,
if it is ever wanted, is one line asserting each static route's title is
non-empty and differs from the fallback route's title.
