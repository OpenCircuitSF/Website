## Description

`#0123` added `/archive` as a static route. **Neither test that covers static
routes includes it:**

- `TestRender_StaticRoutesGetDistinctTitles`' `paths` slice omits it.
- `TestSitemap_ContainsStaticRoutesWithLastmod`'s `want` map omits it.

So a **title collision** on `/archive`, or a **dropped `<loc>`** for it in the
sitemap, passes both tests today.

This is the coverage half of `#0425`'s finding. That issue is comments-only —
its four stale doc comments all miscount the same route set — and `#0425`'s
review kept the coverage gap out of it deliberately, which was the right call:
correcting a comment and adding an assertion are different work.

**Unverified by the orchestrator** — this is `#0425`'s reviewer's measurement.
Reproduce it before building on it.

## Why it is worth closing rather than recording

The archive index is a **public, indexable page** the user is about to rely on:
`#0405` gives the newsletter a stable `/archive/09-2026` URL, and the whole
point of the archive is that search engines find it. A missing sitemap entry for
the index itself would be silent and would not surface until someone checked
Search Console.

It is also cheap — two existing tables gain a row each.

## What makes this the same family, and why that matters

`/archive` has now been omitted from **five** independent accounts of the same
route set: `resolve`'s doc comment, the package doc's step 2,
`maxCacheEntries`' doc comment, `defaultStaticRouteMeta`'s doc comment, and
these two tests' fixtures. `#0425`'s review put it plainly — the route was added
without a sweep of the prose and fixtures around it.

**So do not fix only the two named.** Sweep for anything else enumerating static
routes or the sitemap's contents, in fixtures as well as comments.

## A third test, added 2026-09-05

`#0425`'s second review found one more in the same family:
`TestRender_JSONLD_StaticRoutesHaveNoBlock`'s doc comment claims **"every static
marketing route"** while its loop covers **five of six** — `/archive` again.

The honest fix is adding `/archive` to that slice, which is a **body** change and
therefore this issue's territory rather than `#0425`'s comments-only scope.
Treat it as a third row in criterion 1, with the same falsifiability proof
required by criterion 2.
