# 0105 — `EMAIL_LIST_DOMAIN` is neither required nor defaulted, so an unset value ships a malformed `mailto:` in `List-Unsubscribe`

| | |
|---|---|
| **Status** | open |
| **Module** | config / mailing |
| **Platform** | All |
| **First seen** | 2026-08-20 |
| **Phase** | 5 — Campaigns |

## Description

`config.Config.EmailListDomain` is read as a bare `os.Getenv("EMAIL_LIST_DOMAIN")`
with no default and no required-field check. `mailing.CampaignHeaders` (#0035)
interpolates it directly into the `mailto:` half of `List-Unsubscribe`, so if the
variable is ever unset in production the header goes out as
`<mailto:unsubscribe@?subject=unsubscribe%3A…>` — a syntactically invalid URI in
the one header Gmail's and Yahoo's bulk-sender rules actually parse.

## Steps to reproduce

Not yet reachable at runtime — `CampaignHeaders` has no caller until #0045's send
worker exists. Reproducible today at the unit level:

```go
mailing.CampaignHeaders("https://www.opencircuitsf.com", "", "SOME-TOKEN")
// List-Unsubscribe: <https://www.opencircuitsf.com/api/unsubscribe?token=SOME-TOKEN>, <mailto:unsubscribe@?subject=unsubscribe%3ASOME-TOKEN>
```

## Expected behavior

An unset or blank `EMAIL_LIST_DOMAIN` fails fast at boot, the same way `BASE_URL`,
`EMAIL_FROM`, and `AWS_REGION` already do — or `CampaignHeaders` omits the
`mailto:` form entirely and emits an HTTPS-only `List-Unsubscribe`, which is
still valid RFC 8058. Silently emitting a malformed URI is the one option that
should not be available.

## Actual behavior

`internal/config/config.go` line 126 reads the variable with no default, and its
`required` table (lines 138–152) does not list it. `docs/configuration.md` marks
it Required = no, Default = —. Nothing anywhere validates the value.

## Notes

Found during #0035's review (2026-08-20), not by #0035's code — `CampaignHeaders`
is a pure function that is correctly parameterised and takes the domain from its
caller. The gap is that its future caller (#0045) will pass a config value nobody
guarantees is set.

Two candidate fixes, decide deliberately:

1. **Add `EMAIL_LIST_DOMAIN` to the `required` table** in `config.Load`. Cheapest
   and most consistent with the other email variables, but it makes the variable
   mandatory for every deploy including dev — check `internal/devstore`/`STORAGE=json`
   runs and `scripts/dev.sh` before doing this, and consider `skipInDev: true`.
2. **Make `CampaignHeaders` drop the `mailto:` form when `listDomain` is empty.**
   RFC 8058 permits an HTTPS-only `List-Unsubscribe`, and `List-Unsubscribe-Post`
   still applies, so one-click keeps working. Belt-and-braces alongside (1).

Whichever is chosen, add a test pinning it — `internal/config`'s existing
`config_test.go` already asserts the loaded value, so the missing-variable case is
a small addition there, and `campaign_headers_test.go` is the place for (2).

Must be closed **before the first real campaign send**, not merely before #0045
merges — a malformed `List-Unsubscribe` on live mail is a deliverability problem
that costs sender reputation, which is exactly what PRD §6.5's opening paragraph
warns about.

Related but distinct: the `List-Id` header uses the *singular*
`list.opencircuitsf.com` as a hard-coded constant (PRD §6.5 gives it verbatim) and
is deliberately not derived from this variable, so it is unaffected.
