# 0319 — The archive toggle does not invalidate the SEO caches

| | |
|---|---|
| **Status** | open |
| **Platform** | Server |
| **Module** | seo / handlers |
| **Phase** | 8 — Archive, imports, and delivery health |
| **First seen** | 2026-08-27 |

## Description

`AdminWorkshopsHandler` calls `InvalidateWorkshops()` on every mutation.
**`AdminCampaignArchiveHandler` has no equivalent**, and neither does the send
worker's completion path.

So `sitemap.xml` keeps advertising a just-**withheld** campaign's URL, and omits
a just-**published** one, for up to `defaultCacheTTL` — 60 seconds.

Bounded, and the JSON API is immediately correct, so the page itself 410s at
once. But the sitemap is the one place a withheld campaign lingers after an
admin has withdrawn it, and "withdrawn" is exactly the state where a delay is
least welcome — an admin withholds a campaign because something in it should not
be public.

## Acceptance criteria

1. `AdminCampaignArchiveHandler` invalidates the SEO caches on every mutation,
   following `AdminWorkshopsHandler`'s existing pattern rather than inventing a
   second mechanism.
2. The send worker's completion path does the same when a campaign becomes
   archivable — a newly published campaign should appear in the sitemap without
   waiting out the TTL.
3. Check every other writer of a field the sitemap or meta-tag renderer reads,
   and report the full list. Two invalidators were missing; a third would not be
   surprising.
4. A test asserts the sitemap reflects a withhold immediately rather than after
   the TTL. Prove it fails against the current code.
5. Do not shorten `defaultCacheTTL` as the fix. The cache is doing its job; the
   defect is that nothing tells it to drop a stale entry.
6. `ISSUE=NNNN scripts/check.sh go ./internal/seo/... ./internal/handlers/... ./internal/mailing/...`
   passes with no skips.

### What must change — criterion 4

Criterion 4 reads: *"A test asserts **the sitemap** reflects a withhold
immediately rather than after the TTL."* What was delivered asserts that a
counting fake's `InvalidateWorkshops` was called once. No test in the tree
observes `sitemap.xml`, and none binds the `*seo.Site` the archive handler
holds to the one that serves `GET /sitemap.xml`.

This is not a pedantic reading of the criterion. This project has already
ruled on this exact substitution, and the ruling is written verbatim in
`cmd/opencircuit/seo_wiring_test.go`'s doc comment (`#0054`, carried in from
`#0051`'s review, Ruling 1):

> A counting fake inside `internal/handlers` (as `admin_workshops_test.go`
> already has) cannot show this — it only proves `InvalidateWorkshops` gets
> CALLED, never that the object it's called on is the one anything actually
> reads from.

The risk it closes is live here, and it is a fail-open. Both new parameters
are nil-tolerant by design, and `cmd/opencircuit/admin_wiring_test.go` and
`worker_wiring_test.go` already construct them with literal `nil`. A future
edit to `servePostgres` that passed `nil`, or that called `buildSEOSite` a
second time, would compile, would leave every test in `b575867` green, and
would silently restore the 60-second sitemap staleness this issue exists to
remove. Exactly the shape `#0051` shipped and `#0054` had to fix for
workshops.

**The remedy — one test, mirroring the one that already exists.** Add
`TestMountAndServe_CampaignArchiveMutationInvalidatesSharedSEOSite` to
`cmd/opencircuit/seo_wiring_test.go`, modelled directly on
`TestMountAndServe_WorkshopMutationInvalidatesSharedSEOSite` in that file
(same `registerWiringTest`/`truncateAdminWiringTables` fixture, same
ephemeral-port `mountAndServe` shape):

1. `site, err := buildSEOSite(cfg, source, campaignArchiveSEOSource{store: campaignsStore})`
   — the real archive adapter, not `nil` as the existing test passes.
2. Construct `adminCampaignArchiveH := handlers.NewAdminCampaignArchiveHandler(campaignsStore, auditLogger, site)`
   with **that same** `site`, and hand the same `site` to `mountAndServe`.
3. Seed a `sent` + `published` campaign; `GET /sitemap.xml` and assert it
   contains `/archive/{slug}`.
4. `PATCH /admin/campaigns/{id}/archive` with `{"status":"withheld"}`.
5. `GET /sitemap.xml` again, **well inside `defaultCacheTTL`**, and assert
   `/archive/{slug}` is gone. That assertion is criterion 4.

Prove it fails two ways, as `#0054`'s doc comment records for its own test:
once with the handler constructed with a `nil` invalidator, and once with
`mountAndServe` handed a *separate* `buildSEOSite` result. Both must fail at
step 5. Do the mutations in a throwaway worktree, not the shared tree.

Two things deliberately **not** required, so this does not turn into scope
creep:

- **No `servePostgres`-level wiring proof.** `#0054`'s own scope note already
  concedes its test rebuilds the wiring shape by hand and does not pin
  `servePostgres` itself. Holding the campaign archive to a stricter standard
  than the workshops precedent would be inconsistent; the gap is common to all
  three call sites and belongs in a follow-up issue, not here.
- **No `mountAndServe`-level proof for the send worker.** `Worker.archiveCache`
  is unexported and the worker cannot be driven from `cmd/opencircuit`'s
  wiring tests. `TestWorker_CompleteIfDone_InvalidatesArchiveCache` is the
  right test at the right level and is accepted as delivered.
