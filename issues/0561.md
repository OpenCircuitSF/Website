The scratchpad is not durable. The planner copies the facts the implementation needs (sizes, colours, alpha, insets, rules) into `## Plan`.

Layout B, in brief:

- **Photo:** full bleed, cropped around the focal point.
- **Title box:** placed just below the photo's subject.
  - Semi-transparent dark fill, `rgba(11,16,10,.72)`, with a green accent bar on the left edge.
  - Holds the big title, which is uppercase in the mockup, and the tagline.
- **Footer box:** semi-transparent, at the bottom left.
  - Holds the date and time (green mono), the venue (mono), and the workshop description.
  - Under a thin rule: `> open_circuit_sf` (green mono) at the bottom left and `OpenCircuitSF.com` at the bottom right.
- **QR box:** opaque white, at the bottom right, with the location label under the code.
- **Half-size double:** the same composition, scaled. A shorter description is used, with a line clamp as a backstop.

#### 3.3 Placement: `focalOnFace` and `captionPlacement`

`focalOnFace(img: Size | null, box: Size, focal: Focal): number` gives the
focal point's **displayed** y as a fraction of the face, after the cover
crop. With the same `s` and `dh = img.h*s` as `coverPosition`, and `p` equal
to its y result / 100, the value is `(p*(box.h - dh) + fy*dh) / box.h`.
Without the image size it falls back to `fy`, clamped.

`captionReserve(size)` returns `{ titleMax, footerMax }` in inches, computed
from `CAPTION`. A test re-derives the numbers, so they cannot drift from the
scale.

- `titleMax = 3 × titleSteps[0] × 0.92/72 + 3 × tagline × 1.2/72 + 0.12 × tagline/72 + capPad.T + capPad.B`
  → full **3.532**, half **2.382**. Title and tagline each get a 3-line
  `line-clamp` backstop so the reservation holds.
- `footerMax = max(details, qrBox)`, where:
  - `details = 2·detPadTB + 2 × date × 1.2/72 + 0.04 + 2 × venue × 1.3/72 + descLines × desc × 1.4/72 + 3·detGap + 1/96 + brand × 1.2/72`
  - `qrBox = 2·qrQuietIn(qr) + qr + 0.03 + 3 × label × 1.2/72`

  → full **3.33** (details dominates; qrBox ≈ 2.20), half **1.94** (qrBox
  ≈ 1.67). Date and venue each get a 2-line clamp and the label a 3-line
  clamp, so these reservations are upper bounds.

`captionPlacement(focal, img, size, mode: FlyerTitlePosition)` returns
`{ arrangement: 'below' | 'above', edge: 'top' | 'bottom', offset: number }`.
`offset` is in inches from that edge of the face, and the component writes
it as `top:` or `bottom:` on the title box.

- **Arrangement.** `mode === 'auto'` gives `focal.y < 0.5 ? 'below' :
  'above'`. This uses the raw focal y, matching the acceptance criterion's
  "focal.y in the top half". `'below'` and `'above'` force it.
- **below** (footer at the bottom, as in the mockup):
  `top = clamp(faceY + subjectClear, inset, H − inset − footerMax − boxGap − titleMax)`,
  where `faceY = focalOnFace(...) × H`. The ceiling is full **3.488in**, half
  **3.678in**. The mockup's 3.15in and 2.45in sit inside that.
- **above** (subject in the lower half): the footer flips to the top
  (`top: inset`, items aligned `flex-start`). The title box's bottom edge
  goes at `edgeY = clamp(faceY − subjectClear, inset + footerMax + boxGap + titleMax, H − inset)`,
  and it is returned as `edge: 'bottom', offset: H − edgeY`. Per NOTES:
  "then the details box moves to the top, QR with it". The wordmark stays at
  the bottom of the details box.

Because both bounds come from the reservations, title and footer cannot
overlap. A centred subject (y = 0.5) goes to `above`, and its title is
clamped to sit just under the top footer.

#### 3.4 Title fit: a measured width table, not a DOM measure

**Decision.** Use a pure function over the real glyph advances of the
bundled font. Do not measure at runtime. Reasons:

- jsdom has no layout, so a runtime measure is untestable in the suite the
  acceptance criteria require.
- A runtime measure depends on the font having loaded. In the editor preview
  it depends on the `scale()` transform, and it needs a measure → set →
  re-measure loop.
- Archivo is a variable font with only a `wght` axis (NOTES: no `wdth`), and
  the title is always uppercased, so a small exact table covers it.

The advances were measured from `web/public/fonts/archivo-variable-latin.woff2`.
The SHA-256 starts `8f704806dbedeaae`, the same file the mockup used. They
were instanced at `wght=900` with fontTools in a throwaway venv, in units per
1000 em:

    A 778 B 778 C 778 D 778 E 722 F 667 G 833 H 833 I 369 J 667 K 833 L 667 M 972
    N 833 O 833 P 722 Q 833 R 778 S 722 T 722 U 833 V 778 W 1000 X 778 Y 778 Z 722
    0-9 667 (all digits)   space 180   & 889   - 333   ' 278   . 333   , 333   : 333
    ! 333   ? 611   / 306   + 660   # 660   ( 389   ) 389   ’ 278   – 500   — 1000
    " 497   @ 1010

Cross-check: "PROGRAMMING" measures 8.481em with tracking, which is 6.36in at
54pt. The full render measures about 6.33in. At 62pt it is 7.30in, wider than
the 7.08in available, which matches NOTES' "62pt broke PROGRAMMING".

Functions:

- `ARCHIVO_900_ADVANCE: Record<string, number>`, the table above.
- `titleWidthEm(s)` returns `Σ (advance(c)/1000 − 0.02)` over the code
  points of `s.toLocaleUpperCase('en-US')`. Tracking applies after every
  character, as CSS `letter-spacing` does. Any character not in the table
  counts as **1000**, the widest glyph, which keeps the estimate
  conservative. Kerning is ignored, which can only over-estimate.
- `TITLE_FIT_SAFETY = 1.03`. Do not raise it: at 1.04 or more, "PROGRAMMING"
  at half size (4.37in vs 4.415in available) steps down from 36pt, unlike
  the approved render.
- `titleAvailIn(size) = W − 2·inset − capBar − 2·capPad.LR`, giving full
  **7.08**, half **4.415**.
- `titleFit(title, size)` returns `{ pt, lines, breakAnywhere }`. Split the
  uppercased title on whitespace. Try each `titleSteps` value in order, and
  take the first `pt` where the widest word × 1.03 × pt/72 ≤ avail **and** a
  greedy word wrap at that width (space = 0.16em after tracking, × safety)
  takes ≤ 3 lines. If no step passes, use the smallest step, with
  `breakAnywhere = widest word still does not fit`. Only then does the CSS
  allow `overflow-wrap: anywhere`. The mid-word ban holds for any word up to
  ~20 uppercase characters at full size.

Expected results, computed with exactly this algorithm. Pin them in the
tests as `[full pt, full lines]` / `[half pt, half lines]`:

|---|---|---|
| Programming LEDs | 54, 2 | 36, 2 |
| Soldering 101 | 54, 1 | 36, 1 |
| Microcontrollers | 42, 1 | 24, 1 |
| Introduction to Microcontrollers | 42, 2 | 24, 2 |
| Build a Synthesizer from Scratch with Arduino and Friends | 36, 3 | 24, 3 |
| Electroluminescent | 36, 1 | 20, 1 |

#### 3.5 Description text

- `MAX_FLYER_DESCRIPTION = 360` and `MAX_FLYER_DESCRIPTION_SHORT = 140`,
  mirroring Go.
- `validateFlyerDescription(text, max, what)` counts code points like
  `validateTagline` and returns an error string or null.
- `shortenAtBoundary(text, max)` trims and collapses whitespace runs.
  - If ≤ `max`, return it unchanged.
  - Otherwise cut after the last sentence end (`.`, `!` or `?` followed by
    a space) at or before `max`, provided that keeps ≥ `max/2` characters.
    No ellipsis.
  - Otherwise cut at the last whitespace at or before `max − 1` and append
    `…`.
  - It never cuts inside a word. If the first word alone is longer than
    `max`, return that whole word plus `…`; the CSS clamp is the backstop.
- `flyerDescriptions(factsDescription, override, overrideShort)` returns
  `{ full, half }`:
  - `full = shortenAtBoundary(override.trim() || factsDescription.trim(), 360)`
  - `half = overrideShort.trim() || shortenAtBoundary(full, 140)`

  An empty result means the component omits the paragraph.

#### 3.7 `flyers.test.ts` cases

- **Box.** `alpha` is exactly 0.72. Ink, muted and accent are each ≥ 4.5
  against `composite(fill, 0.72, '#ffffff')`, and the muted (tagline) ratio

  face, fy 0 and 1 map inside [0, 1] and are monotonic. For a wide image

## Obstacles

  refuses while the template has a live connection (`#0482`), for example
  while another agent is cloning. It is cleared by waiting and retrying. Do
  not use `drop template --force`. If pass B runs concurrently with pass A,
  pass B needs no database (web only), so there is no contention.
- **`CREATEDB`.** Already granted: `rolcreatedb` read `t` on 2026-10-17,
  which the up/down/up scratch DB needs. `migrate`, `psql` and `npm` are on
  PATH.
- **`CLAUDE.md` is shared.** Pass A edits one cell of it. Check
  `git diff -- CLAUDE.md` before committing and commit with an explicit
  pathspec (§8a). The orchestrator must not edit `CLAUDE.md` while pass A is
  out.
- **No glyph measurement in jsdom or on the host.** This is avoided by
  design: the Archivo 900 advance table above was measured once, off-browser,
  with fontTools in a throwaway venv (not in the repo). An implementer does
  not need to re-measure. If the font file ever changes (its SHA-256 no
  longer starts `8f704806dbedeaae`), the table must be re-derived the same
  way.
- **Rendered check needs the Tart VM, approval-free but slow.** Only the
  reviewer does it, per the acceptance criteria. It needs `tart-lease`, and
  stop and delete in an EXIT trap. The preview harness in the scratchpad
  (`flyer-preview-0559/`) may have been cleaned up. If so, the reviewer
  rebuilds a minimal one: a production `npm run build` in a throwaway
  worktree, not `dev.sh --built` in the shared tree (§8b).
- **`web/dist/index.html`.** Neither pass should build `dist` in the shared
  checkout. `scripts/check.sh` does not build.
- **No SES or ShortLinks dependency.** Designing and printing work without
  ShortLinks, and the tests use the existing fakes.
