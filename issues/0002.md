## Description

Delete every Go package that exists only to serve short links, along with the dependencies they pull in. The auth, config, db, audit, events, and middleware packages stay.

> 🟢 Resolved 2026-08-18 — Shortener packages, handlers, and dependencies are gone; the reduced tree builds, vets, and passes its tests, and the two repairs beyond the literal file list (`UserDetail.LinkCount`, the `credentials_test.go` TRUNCATE) were necessary to avoid shipping code that breaks silently at #0004.

## Root cause

Not applicable — feature/stripping work, not a bug. The copied ShortLinks tree (#0001) carries the entire shortener surface (links, clicks, campaigns, filters, cache, qr) that this project has no use for; it needed to come out before Phase 0 could be considered a clean foundation.

## Fix

Deleted `internal/links/`, `internal/clicks/`, `internal/campaigns/`, `internal/filters/`, `internal/cache/`, `internal/qr/` in full, plus the shortener-only handler files (`redirect.go`, `links.go`, `campaigns.go`, `campaigns_export.go`, `url_filters.go` and their tests) and the orphan `internal/handlers/qr_test.go`, exactly per the issue's Notes. Rewrote `cmd/opencircuit/main.go`'s route table and both `serve` paths (`servePostgres`/`serveDevMode`) to drop every construction and route registration for the deleted handlers — `/u/{key}`, `/api/links*`, `/api/campaigns*`, and `/admin/url-filters*` are gone. Rewrote `cmd/opencircuit/seed.go` to drop `ensureTestLink` (it used `internal/links.GenerateUniqueKey` and the `links` table) — `seed` now only bootstraps the admin user; `seed_test.go` follows suit. `go mod tidy` dropped `gozxing`, `go-qrcode`, `ristretto` and their now-unreferenced indirect deps once nothing imported them.

`internal/devstore/devstore.go` was cut from 1561 to ~380 lines: removed the `links`, `rules`, `campaigns` fields and every method/interface-assertion tied to them (roughly lines 372–1524 of the original file — filterRuleStore, campaignStore, linkStore, LinkResolver, statsProvider, campaignStatsProvider, ClickSink, cache/RuleCache shims, and their compile-time interface checks), keeping Pinger, SessionResolver, session CRUD, settingStore, credentialStore, userStore, auditReader, recordAudit, RegistrationsEnabled, the DevRegistrar/DevRecoverer auth stubs, and the devLoginService logout shim. `internal/devstore/campaigns_test.go` (entirely campaign-focused) was deleted outright; `devstore_test.go` was rewritten to drop every link/campaign test and keep/add coverage for what survives (admin seeding, ping, settings, sessions, session bulk-delete, deactivate/reactivate, empty audit log).

Beyond the issue's literal file list, three follow-on fixes were needed to reach a compiling, passing tree — all within the "strip the shortener" spirit rather than new scope:

1. **`clientIP`** (IP-attribution helper for audit logging) lived in the now-deleted `redirect.go` but is used by `auth.go`, `credentials.go`, and `settings.go` — none of which are shortener-specific. Re-homed to a new `internal/handlers/request.go`.
2. **`itoa`** (tiny int64→string test helper) lived in the now-deleted `url_filters_test.go` but is used by the retained `users_test.go` and `audit_test.go`. Re-homed to a new `internal/handlers/testutil_test.go`.
3. **`auth.UserDetail.LinkCount`** (and its `GET /admin/users/{id}` `link_count` JSON field) ran a correlated subquery against the `links` table. Since #0004 deletes that table entirely, leaving this in place would have shipped a #0002 that quietly breaks at #0004 with no compiler signal (it's a runtime SQL error, not a Go type error). Stripped the field from `auth.UserDetail`, `internal/auth/users.go`'s `GetUser` query, `internal/handlers/users.go`'s response struct, and the corresponding assertions/seeding in `users_test.go` (which also used the now-deleted `seedLink` helper and a `linkCountFor` query helper — both removed).

`events_test.go` and `audit_seams_test.go` (retained per the issue) both imported deleted packages (`cache`, `filters`, `links`) for link-broadcast and link/url-filter audit-seam tests that have no reason to exist in this project. Pruned each to keep only the parts that test the retained handlers: `events_test.go` keeps `TestEventsStream_DeliversFrameAndUnsubscribesOnCancel` and `TestEventsStream_Unauthenticated` (rewriting the published test event from `link.created` to a generic `test.event` so the SSE plumbing test carries no link semantics), dropping the link-broadcast end-to-end test and its mux/helpers. `audit_seams_test.go` keeps only `TestAudit_SettingsUpdated` (rewritten onto `credsTestPool` since the `filterTestPool` helper it used lived in the deleted `url_filters_test.go`), dropping the link-created/reactivated/denied/deactivated and url-filter audit-seam tests. Also dropped `campaigns, clicks, links` from `credentials_test.go`'s `truncateCredsTables` TRUNCATE list, since those tables won't exist once #0004 lands and a stray reference here would break every DB-backed handler test at that point, not just the ones already exercising those tables.

## Notes

PRD §3.2.

**There is no `internal/handlers/qr.go`** — verified against the ShortLinks tree. The QR endpoints are methods on the links and campaigns handlers (`linksH.QRSVG`, `linksH.QRPNG`, `campaignsH.QRZip`), so they disappear with those files. What does exist is a stray `internal/handlers/qr_test.go`; delete it too or the package will not compile. The real package is `internal/qr/`.

Keep `internal/events/` — the SSE broker is reused for live campaign send progress (#0048).

`internal/cache/` goes entirely: the Ristretto redirect cache and the filter rule cache both exist for a hot redirect path this project does not have. Do not preserve it "just in case".

ShortLinks' `campaigns` package groups short links; this project's `email_campaigns` is an unrelated concept that shares a word. Port none of it.
