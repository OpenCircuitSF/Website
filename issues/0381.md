## Description

Several guards in this family **scan the whole tree from a package other than
the one being edited**. `#0356`'s `TestNoCommentCitesGoFileByLineNumber` lives
in `internal/handlers` and scans every Go comment in the repo.

So `ISSUE=NNNN scripts/check.sh go ./internal/outbox/...` — a correctly scoped
run under §5a — **cannot see a violation an `internal/outbox` edit introduces.**

**This left HEAD red for roughly 18 minutes.** `be1f08d` added 61 comment lines
to `internal/outbox/claim_comment_referent_guard_test.go` recording two guard
limits (`#0374`, `#0375`). Two of them cited `store.go:463` and
`internal/mailing/outbox_worker.go:475` by line number. The implementer's scoped
run passed; `#0376`'s reviewer found the failure while verifying an unrelated
diff in `internal/handlers`.

**The irony is the point**: the records were doc comments *about a guard*, and
they violated the rule `#0352` and `#0356` settled — replace a line citation
with a stable identifier, never a corrected number.

**And the citation was already wrong.** `#0365`'s work moved that site from line
475 to line **517** within the hour, which `#0374`/`#0375`'s reviewer noted as
empirical vindication.

2. **Name which packages own repo-wide guards**, measured rather than assumed.

   is, say so and stop.
4. If you do consider a mechanism, weigh the obvious one honestly: making

5. Any figure or file path you state is **re-measured**, not transcribed —

6. Documentation only unless criterion 3's exception applies. `gofmt` stability
   if any Go file is touched.

`parser.ParseFile`, `packages.Load`, or a bare `os.ReadFile`/`filepath.Join`

that grep's output. Three packages reach outside their own directory by one

## Decision (criteria 3, 4) — recorded, nothing built

**Recording only; no mechanism built.** Per criterion 3's stop condition, and
matching the precedent it names (`#0330`, `#0347`, `#0356` each ended by
recording a limit rather than closing it): the deliverable is the sentence
added to `CLAUDE.md` §5 (see below) naming the seven owning packages and
their scan roots, plus this issue's own enumeration as the measured backing
for it. (Corrected from "four" to "seven" on the second implementation pass
— see `## Enumeration` above and the `## Review notes` bounce; this
correction does not touch the judgment below, which the review independently
verified and endorsed.)

**The obvious mechanism, weighed honestly (criterion 4).** Making
`scripts/check.sh`'s default `go` scope always append all seven owning
packages (`./internal/handlers/... ./internal/db/... ./internal/outbox/...
./internal/subscribers/... ./internal/seo/... ./cmd/...
./internal/mailing/...`) to every scoped run would guarantee the guards run,
but at a real cost: `internal/handlers` alone took **7.7s** in the first
pass's own `ISSUE=0377 scripts/check.sh` run (`cmd/opencircuit` took
**8.5s**; the review's independent re-measurement found **6.443s** and
**7.241s** respectively) against `internal/db`'s 0.3s–0.476s and
`internal/subscribers`'s 0.8s–0.937s — so a scoped run on an unrelated single
small package (say, `internal/audit`) would roughly double or more in wall
time to buy protection it usually does not need, on every run, forever.
§5a's whole point is that scoped runs are cheap and are the default;
automatically widening every one of them to include seven packages (two of
them slow) trades that away for a failure mode that a one-sentence lookup in
§5 already prevents an agent from hitting, provided the agent reads it. This
mirrors §8's `#0258` lesson the other direction: not every guard gap needs a
guard.

**Where it's recorded.** `CLAUDE.md` §5, immediately after "Always set
`ISSUE=NNNN`" — the sentence an agent choosing a verification scope will
meet right where it decides that scope (criterion 1's placement instruction).
No repo-wide guard's own doc comment was also edited; the issue's "and/or"
permits recording in one place, and duplicating the same seven-package list
into seven files is the "copy of the answer stored next to the question"
`#0356`'s planning pass and CLAUDE.md §8 both warn against — one is enough
for an agent to find via `grep -n "repo-wide guard" CLAUDE.md`.

`parser.ParseDir`, `packages.Load` — then read each hit's root.

means, and three do.** Measured at `HEAD`:

Three findings, in descending severity:

1. **`cmd/opencircuit` was ruled out on the wrong file.** The pass wrote that
   `TestNoWiringTestUsesParallel` "scans only its own directory and is **not**
   repo-wide … I did not include it on the strength of the grep hit alone." That
   reasoning is sound *about that file* — and `wiring_parallel_guard_test.go` is
   the only file in `cmd/opencircuit` the `filepath.WalkDir` grep surfaced. But
   its sibling `servepostgres_seo_instance_guard_test.go` reads **other packages'
   source**: `TestServePostgres_OneSEOSiteFlowsToEveryConsumer` resolves each of
   `servePostgres`'s module-local imports to `../../<pkg>` and parses those
   directories to check `*seo.Site` parameter flow. It uses `os.ReadDir`, so the
   grep never saw it. A signature change in `internal/seo` or any package
   `servePostgres` calls can therefore break a test in `cmd/opencircuit` — the
   exact failure this issue exists to prevent, in the one package the pass told
   future agents they may safely omit.

2. **`internal/seo` is missing, and it guards the file `CLAUDE.md` §8b warns about
   most.** `TestDistIndexPlaceholder` (`#0141`) reads `../../web/dist/index.html`
   and fails if a real `npm run build` has been committed over the tracked
   placeholder. §8b records that three agents have already overwritten that file
   with `./scripts/dev.sh --built`. An agent consulting the committed §5 paragraph
   after doing so is told `internal/handlers` covers `web/` — so it runs
   `internal/handlers`, which does not carry this guard, and concludes it is
   clean. **The paragraph as written actively misdirects for this case.**

3. **`internal/db`'s and `internal/outbox`'s guard lists are each missing the
   entry that matters most to the work in front of them.** For `internal/db` the
   pass named only `TestNoOpenIssueVerificationCitesUndefinedTestFunction`, omitting

   `internal/outbox` it named only `TestNoUnscopedOutboxClaimCallOutsidePackage`,
   omitting `claim_comment_referent_guard_test.go`'s two guards — the file whose
   edit in `be1f08d` **caused this issue**. Both packages are on the list, so
   `CLAUDE.md`'s actionable content survives for them; the enumeration reported

The stakes are the ones the issue itself names: this is documentation that tells
future agents which packages they must run, so an incomplete list is worse than
none. Criterion 5 ("any figure or file path you state is re-measured — seven

"four" is now the eighth.

### Criterion 3/4 — recording rather than building was right

I verified the timings independently in my own `ISSUE=0377r scripts/check.sh` run:
`internal/db` **0.476s**, `internal/subscribers` **0.937s**, `internal/handlers`
**6.443s**, `cmd/opencircuit` **7.241s**. The pass reported 0.3s / 0.8s / 7.7s /
8.5s — different absolute numbers on a differently-loaded machine, but the ratio
that carries the argument is reproduced exactly: the two slow packages cost
roughly **8×** the two fast ones.

The trade is a real one and the pass called it correctly. Appending the guard
packages to every scoped run would add ~15s to a run of a package like
`internal/audit` that finishes in well under a second — not a doubling, closer to
an order of magnitude — on every run, forever, to buy protection that is needed
only when the edit lands inside a scan root. §5a's cheap-scoped-run default is
load-bearing for the three-agent concurrency ceiling, and spending it on this
would be the `#0258` shape: adding mechanism where the gap is a knowledge gap.
`#0330`, `#0347` and `#0356` each ended the same way, and this case does **not**
differ from them. Keep the decision; it survives re-implementation unchanged.

**This bounce is about the enumeration only.** Nothing about criteria 3 or 4
needs revisiting, and no mechanism should be built.

> | Package | Reaches into |

> | `internal/subscribers` | all of `internal/` |
