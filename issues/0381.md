## Description

Several guards in this family **scan the whole tree from a package other than
the one being edited**. `#0356`'s `TestNoCommentCitesGoFileByLineNumber` lives
in `internal/handlers` and scans every Go comment in the repo.

So `ISSUE=NNNN scripts/check.sh go ./internal/outbox/...` — a correctly scoped
run under §5a — **cannot see a violation an `internal/outbox` edit introduces.**

**This left HEAD red for roughly 18 minutes.** `be1f08d` added 61 comment lines
to `internal/outbox/claim_comment_referent_guard_test.go` recording two guard
limits (`#0374`, `#0375`). Two of them cited `store.go:463` and
`internal/mailing/outbox_worker.go:475` by line number. The implementer's scoped
run passed; `#0376`'s reviewer found the failure while verifying an unrelated
diff in `internal/handlers`.

**The irony is the point**: the records were doc comments *about a guard*, and
they violated the rule `#0352` and `#0356` settled — replace a line citation
with a stable identifier, never a corrected number.

**And the citation was already wrong.** `#0365`'s work moved that site from line
475 to line **517** within the hour, which `#0374`/`#0375`'s reviewer noted as
empirical vindication.

## Acceptance criteria

1. Record, where an agent choosing a verification scope will meet it — CLAUDE.md
   §5, and/or each repo-wide guard's own doc comment — that **an edit to a file
   within a repo-wide guard's scan roots must also run that guard's owning
   package**.
2. **Name which packages own repo-wide guards**, measured rather than assumed.
   `#0356`'s line-citation guard in `internal/handlers` is one; enumerate the
   rest by finding the guards whose scan roots extend beyond their own package.
   Report the list.
3. **Do not build a mechanism** unless the enumeration shows it is warranted.
   §8's `#0258` case is six passes of adding checks, and `#0330`, `#0347` and
   `#0356` each ended by recording a limit rather than closing it. A sentence in
   §5 naming the owning packages may be the whole deliverable — if you think it
   is, say so and stop.
4. If you do consider a mechanism, weigh the obvious one honestly: making
   `scripts/check.sh` always include repo-wide guard packages would slow every
   scoped run, and §5a's whole point is that scoped runs are the default. Say
   what it would cost.
5. Any figure or file path you state is **re-measured**, not transcribed —
   **seven unsupported details reached issues this phase**, several written by
   the orchestrator.
6. Documentation only unless criterion 3's exception applies. `gofmt` stability
   if any Go file is touched.

## Enumeration (criterion 2) — measured, not assumed

Method: found every guard test file whose walk root is not its own package
directory, by grepping for `filepath.Walk`/`filepath.WalkDir` in `_test.go`
files repo-wide, then reading each file's own root/scan-roots variable:

```
$ grep -rln "filepath.Walk\|filepath.WalkDir" --include='*_test.go' .
cmd/opencircuit/wiring_parallel_guard_test.go
internal/outbox/claim_kinds_call_site_guard_test.go
internal/db/issue_citation_guard_test.go
internal/subscribers/events_append_only_guard_test.go
internal/handlers/dangling_test_citation_guard_test.go
internal/handlers/citation_target_guard_test.go
internal/handlers/citation_guard_test.go
```

(`internal/handlers/line_citation_guard_test.go` — `#0356`'s
`TestNoCommentCitesGoFileByLineNumber` — does not call `filepath.Walk`
itself; it reuses `citedTestScanRoots`, defined in
`dangling_test_citation_guard_test.go`, so it did not surface in the grep and
was found instead by `grep -rln TestNoCommentCitesGoFileByLineNumber .`)

Reading each file's root:

| File (package) | Root variable / value | Reaches beyond own package? |
|---|---|---|
| `cmd/opencircuit/wiring_parallel_guard_test.go` (`cmd/opencircuit`) | `baseDir := filepath.Dir(thisFile)` — its own directory only | **No** |
| `internal/outbox/claim_kinds_call_site_guard_test.go` (`internal/outbox`) | `claimKindsGuardScanRoots = []string{"..", "../../cmd"}` — `..` is `internal/` (every sibling package) | **Yes** |
| `internal/db/issue_citation_guard_test.go` (`internal/db`) | `issueGuardScanRoots = []string{"../.."}` — the repo root | **Yes** |
| `internal/subscribers/events_append_only_guard_test.go` (`internal/subscribers`) | `repoRootForEventsGuard(t)` then `filepath.Join(root, "internal")` — all of `internal/` | **Yes** |
| `internal/handlers/dangling_test_citation_guard_test.go`, `citation_target_guard_test.go`, `citation_guard_test.go`, `line_citation_guard_test.go` (`internal/handlers`) | `citedTestScanRoots`/`scanGoRoots` = `["..", "../../cmd", "../../web"]`, or (`citation_target_guard_test.go`) the full repo root | **Yes** |

**Four packages own repo-wide guards**: `internal/handlers`, `internal/db`,
`internal/outbox`, `internal/subscribers`. `cmd/opencircuit`'s
`TestNoWiringTestUsesParallel` scans only its own directory and is **not**
repo-wide, despite calling `filepath.WalkDir` — it does not belong on the
list, and I did not include it on the strength of the grep hit alone.

Guards owned by each, by name:

- `internal/handlers`: `TestNoAdminFacingStringCitesInternalDocs`,
  `TestNoCommentCitesUndefinedTestFunction`,
  `TestNoCommentCitesGoFileByLineNumber` (`#0356`),
  `TestNoCommentCitesUnresolvedPathOrSection` — scanning `internal/`, `cmd/`,
  and `web/` (nearly the whole tree, Go and Svelte).
- `internal/db`: `TestNoOpenIssueVerificationCitesUndefinedTestFunction` —
  scanning the repo root for `issues/*.md` citations resolved against Go test
  functions defined anywhere in the tree.
- `internal/outbox`: `TestNoUnscopedOutboxClaimCallOutsidePackage` — scanning
  all of `internal/` plus `cmd/`.
- `internal/subscribers`: `TestSubscriberEvents_AppendOnlyGuard` — scanning
  all of `internal/` for SQL text naming `subscriber_events` in an
  `UPDATE`/`DELETE`.

## Decision (criteria 3, 4) — recorded, nothing built

**Recording only; no mechanism built.** Per criterion 3's stop condition, and
matching the precedent it names (`#0330`, `#0347`, `#0356` each ended by
recording a limit rather than closing it): the deliverable is the sentence
added to `CLAUDE.md` §5 (see below) naming the four owning packages and their
scan roots, plus this issue's own enumeration as the measured backing for it.

**The obvious mechanism, weighed honestly (criterion 4).** Making
`scripts/check.sh`'s default `go` scope always append
`./internal/handlers/... ./internal/db/... ./internal/outbox/...
./internal/subscribers/...` to every scoped run would guarantee the guards
run, but at a real cost: `internal/handlers` alone took **7.7s** in this
pass's own `ISSUE=0377 scripts/check.sh` run (`cmd/opencircuit` took **8.5s**)
against `internal/db`'s 0.3s and `internal/subscribers`'s 0.8s — so a scoped
run on an unrelated single small package (say, `internal/audit`) would
roughly double or more in wall time to buy protection it usually does not
need, on every run, forever. §5a's whole point is that scoped runs are cheap
and are the default; automatically widening every one of them to include four
packages (one of them slow) trades that away for a failure mode that a
one-sentence lookup in §5 already prevents an agent from hitting, provided
the agent reads it. This mirrors §8's `#0258` lesson the other direction: not
every guard gap needs a guard.

**Where it's recorded.** `CLAUDE.md` §5, immediately after "Always set
`ISSUE=NNNN`" — the sentence an agent choosing a verification scope will
meet right where it decides that scope (criterion 1's placement instruction).
No repo-wide guard's own doc comment was also edited; the issue's "and/or"
permits recording in one place, and duplicating the same four-package list
into four files is the "copy of the answer stored next to the question"
`#0356`'s planning pass and CLAUDE.md §8 both warn against — one is enough
for an agent to find via `grep -n "repo-wide guard" CLAUDE.md`.
