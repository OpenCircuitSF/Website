## Description

`#0315` made `scripts/testdb.sh` fall back to provisioning from `migrations/`
when the shared template disagrees. Its freshness check — `template_matches_disk`
— compares `disk_version()` against `template_version()`, and **both yield
numbers**.

So **editing a migration in place is invisible to it.** The schema changes; the
version does not. `template_matches_disk` reports a match, `create` clones a
template built from the *old* file contents, and nothing says otherwise.

**This nearly went live during `#0315`'s own review.** `#0123`'s reviewer added a
`CHECK` constraint to `migrations/000025` with both sides still reading 25; only
its manual template rebuild kept them in step (the reviewer verified the template
carries `email_campaigns_slug_not_blank_check`).

**Pre-existing, not a regression from `#0315`** — the old hard-error path compared
the same numbers. `#0315` simply makes the mismatch survivable, which is what
brings this one into view.

## Why an edited migration is a real case here

CLAUDE.md §1 froze `000001`–`000024` because production is at 22, but a migration
created *after* the deploy and not yet applied anywhere that matters may still be
edited — `#0123`'s reviewer called `000025` "still-unfrozen", correctly. So
in-place edits are legitimate and will keep happening for the newest migration.

## Acceptance criteria

1. `build_template` records a **digest of `migrations/*.sql` contents**, not just
   the highest number — a settings row, `COMMENT ON DATABASE`, or a sidecar keyed
   to the template.
2. `template_matches_disk` compares that digest in addition to the version. A
   content mismatch routes to `#0315`'s existing `provision_from_migrations`
   fallback, introducing no new failure mode.
3. The digest covers both `.up.sql` and `.down.sql`, and is stable across
   machines — no absolute paths, no timestamps, no directory-order dependence.
4. Prove it: build a template, edit a migration in place without changing its
   number, and confirm `create` now provisions from disk rather than cloning
   stale contents. Demonstrate the **before** state too — today it clones.
5. Do not make rebuilding the template automatic (`#0315` criterion 4). A content
   mismatch routes to the fallback, exactly as a version mismatch does.
6. Keep the fast path fast — `#0315`'s review measured clone at 0.19s against
   0.29s for a full migrate. A digest computed per `create` must not erase that.
7. `ISSUE=NNNN scripts/check.sh guards` passes, and `scripts/testdb.sh`
   create/drop/gc/template all still behave.
