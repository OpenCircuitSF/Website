## Description

From `#0566`'s review. None blocks release.

1. **Saved rows aren't re-validated on load.** `reloadLocked` in
   `internal/serversettings` trusts every stored row. A value written outside
   the app, or saved before a validation rule is later tightened, would be
   used as is.
2. **`MEDIA_DIR` is effectively fixed in production.** Apache's `/media/`
   Alias, systemd's `ReadWritePaths=` and `backup-media.sh` all name
   `/var/www/media`. Saving any other path either fails the writability check
   or produces uploads that 404 and are never backed up. Neither the Settings
   help text nor `docs/media.md` says so.
3. **`SESSION_SECRET` is required but never read.** `config.Load` refuses to
   boot without it, but sessions are random tokens stored in the database and
   nothing uses the secret.

## Acceptance criteria

- [ ] `reloadLocked` runs `Normalize` on each stored row. A row that fails is
      ignored in favour of the env value or default, with one warning naming
      the key only. A test seeds an invalid row directly and proves the
      fallback and the log line.
- [ ] The Media group's help text and `docs/media.md` state that production
      serves, sandboxes and backs up only `/var/www/media`, and that changing
      the path also needs the Apache, systemd and backup changes.
- [ ] `SESSION_SECRET`: either remove the requirement (and its `.env.example`
      and docs entries, keeping the `internal/config` guard green), or
      document why it stays. State the choice.
- [ ] Verified with `ISSUE=0567 scripts/check.sh go ./internal/serversettings/... ./internal/config/... ./internal/handlers/... ./internal/db/...` plus `scripts/check.sh web` if the SPA changes. Zero skips.
