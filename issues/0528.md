## Description

`internal/seo`'s `archiveRouteMeta` sets a newsletter page's `<meta name="description">`, `og:description`, and `twitter:description` from the campaign's preheader, and falls back to a fixed string when there is none:

```go
description := e.Preheader
if description == "" {
	description = "Read this email from Open Circuit SF."
}
```

Measured on production, 2026-09-12: the September newsletter has no preheader, so `/archive/09-2026` carries that generic sentence. It is what search results show under the title and what a shared link shows under the card, for every newsletter sent without a preheader.

The newsletter's own first paragraph is a far better description and is already available: the body is rendered to HTML and plain text (`#0042`).

## Acceptance criteria

1. When a published campaign has no preheader, its description is derived from the body's **first paragraph of prose**, as plain text: no Markdown syntax, no HTML, whitespace collapsed.
2. Skip leading headings when choosing the paragraph — a body that opens with `# Heading` (the September newsletter does) must not produce the heading as its description.
3. Truncated at a word boundary to about 155 characters, with an ellipsis only when truncated. Deterministic for the same input.
4. **A preheader still wins** when set.
5. The generic sentence remains only as the last resort, for a body with no prose at all.
6. The text is HTML-escaped where it is injected, exactly as the preheader is today.
7. Consider nudging the admin compose screen to fill in the preheader, since it is also the email's inbox preview line. Record the decision.
8. `ISSUE=NNNN scripts/check.sh go ./internal/seo/... ./internal/mailing/... ./cmd/opencircuit/...` passes with no skips.
