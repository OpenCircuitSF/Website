## Description

`.env.example` carries trailing `#` comments **on the value line** for two
variables:

	MAX_SEND_RATE=10          # messages/second, keep below the SES quota
	SEND_WORKER_ENABLED=true  # false on a second instance to avoid double-sending

`deploy/systemd/opencircuit.service` loads that file with `EnvironmentFile=`.
**systemd treats `#` as a comment only at the start of a line** — an unquoted
value runs to end of line. So `MAX_SEND_RATE` becomes the whole string including
the comment, `getInt` hands it to `strconv.Atoi`, that fails, the loader appends
a validation error, and **the service refuses to start.**

Confirmed by the orchestrator: both lines are as shown, `opencircuit.service`
does use `EnvironmentFile=`, and production's own `config.env` carries both
variables **without** the comments — so what was installed was never a literal
copy of the template.

## Why this is now a defect rather than a wart

Both lines are **pre-existing**. What changed is `#0423`, which established that
`.env.example` **is the production template** — because `docs/deployment.md`'s
install step is a literal `sudo cp .env.example /etc/opencircuit/config.env`.

That decision converts a cosmetic inconsistency into a **boot failure on the
documented happy path**. An operator following the runbook exactly gets a
service that will not start.

**And no local workflow can reproduce it**: `scripts/dev.sh` loads env through
`godotenv`, which strips inline comments. So the failure appears only on a real
systemd host, which is the worst place to discover it.

## The fix

Move both comments to their own preceding lines. That is all — but check the
whole file for the same shape rather than only these two.

## Review notes

🟢 **Resolved 2026-09-04.** Reviewed independently — systemd's parser read from
source rather than from documentation, the two lines byte-compared, the new
test mutated three ways, and the whole-file sweep re-run.

**systemd semantics — verified from the implementation, not the man page.**
`src/basic/env-file.c`'s `parse_env_file_internal` is a state machine, and only
its `PRE_KEY` case tests `strchr(COMMENTS, c)`. Once `=` has been seen the
parser is in `PRE_VALUE`/`VALUE`, where `#` is an ordinary character appended to
the value; the only special cases in `VALUE` are `NEWLINE` (which terminates and
pushes) and `\` (escape). Interior whitespace is preserved — `last_value_whitespace`
is reset by every non-whitespace character, and only a whitespace run that
survives to end of line is chomped. So an unquoted value genuinely runs to end of
line, comment included. The implementer's characterisation is correct.

**The constructed strings are byte-exact, not a paraphrase.** Extracted the
pre-fix file from git and compared the post-`=` bytes against the test's two
constants:

    systemd-value: b'10          # messages/second, keep below the SES quota'
    test constant: b'10          # messages/second, keep below the SES quota'
    systemd-value: b'true  # false on a second instance to avoid double-sending'
    test constant: b'true  # false on a second instance to avoid double-sending'

Identical, including the ten- and two-space runs. Neither comment contains a
quote or a backslash, so no `SINGLE_QUOTE_VALUE`/`VALUE_ESCAPE` transition
applies and the value is exactly the remainder of the line. Nothing is stripped:
both lines end on a non-whitespace character, so the trailing-whitespace chomp is
a no-op.

**Mutation proof (throwaway worktree, per §8b) — the new test can fail.** Scored
by `go test` exit code with a passing control at both ends.

| | Mutation | Result |
|---|---|---|
| control | none | `EXIT=0`, all four subtests pass |
| A | `getInt`/`getBool` made lenient (cut the value at `" #"` before parsing) | `EXIT=1` — **both `pre-fix … is rejected` subtests fail** with "got nil error" |
| restore | — | `EXIT=0` |
| B | `getInt`/`getBool` made unconditionally strict (`if true` in place of `if err != nil`) | `EXIT=1` — **both `post-fix … is accepted` subtests fail**, reporting `invalid integer for MAX_SEND_RATE: "10"` and `invalid boolean for SEND_WORKER_ENABLED: "true"` |
| C | loader untouched; `.env.example` reverted to its pre-fix trailing-comment form | **`EXIT=0` for the whole `internal/config` package** |

A and B together show the assertions are falsifiable in both directions by the
thing they measure — the loader's strictness. Neither is a test that merely
agrees with itself.

**What C means, and it is the important caveat: this is a proof, not a
regression guard.** The new test hardcodes the two pre-fix strings; it never
reads `.env.example`. Re-introducing the exact defect in that file leaves the
entire `internal/config` suite green — measured, not inferred. That is the
correct outcome for criterion 2 as written (which asked for a proof and named
constructing the environment as the better of its two options), and criterion 5
is precisely where the durable guard was deferred to `#0428`. But it should be
recorded plainly: **as of this commit nothing in the repo prevents a trailing
comment from being added back to `.env.example`.**

**Whole-file sweep, re-run independently — and widened.** Read `.env.example` as
bytes in Python (not BSD `grep -P`, §8), skipping blank and `#`-opening lines,
checking every remaining line for seven shapes rather than one. All zero:

    {'hash': 0, 'dollar': 0, 'export': 0, 'quote': 0,
     'trailws': 0, 'backslash': 0, 'semicolon': 0, 'leadws': 0}

no line lacking `=`, no CR anywhere (no CRLF), and no non-ASCII byte on any
value line (the `─` and `§` bytes in the file are all inside comment lines,
which systemd ignores and which are valid UTF-8 regardless).

`#` is **not** the only shape that diverges between systemd and `godotenv`,
which is why the sweep was widened. The other live ones, all currently absent:

- **`$`** — the sharpest of them. `godotenv` expands `$VAR`/`${VAR}` in unquoted
  and double-quoted values (`expandVariables`); systemd's `EnvironmentFile`
  performs **no** expansion at all and would ship the literal `$`. A value
  containing `$` would therefore mean two different things on the two paths,
  with no error on either — a silent divergence, strictly worse than this
  issue's loud one.
- **`export ` prefix** — harmless to a shell and stripped by `godotenv`, but
  systemd's `KEY` state accumulates everything up to `=`, producing the invalid
  name `export FOO`; the assignment is logged and **dropped**, so the variable
  is simply unset and the loader silently falls back to its default.
- **Backslash** — a trailing `\` is a line continuation to systemd
  (`VALUE_ESCAPE` eats the newline), which `godotenv` does not do the same way.
- **Quotes and trailing whitespace** are the two that are *safe*: systemd strips
  surrounding quotes and trailing whitespace from unquoted values, matching
  `godotenv` closely enough not to matter here.

Nothing needs changing today; recorded so a future edit to this file knows what
to avoid.

**`godotenv` really is why this never reproduced locally — confirmed in the
dependency's source.** `github.com/joho/godotenv@v1.5.1`'s `extractVarValue`
walks an unquoted value backwards looking for `charComment` (`#`) preceded by
whitespace and truncates there, then trims. So the dev path yields `10` and
`true` and cannot fail. The test's use of `t.Setenv` plus `noEnvFile` (a path
guaranteed not to exist, so `loadFromFile`'s `os.Stat` short-circuits and
`godotenv.Load` is never called) is therefore genuinely the only way to reach
the loader with the systemd-shaped value. The analysis holds.

**Criterion 4 — sweep re-run, and widened to files the implementer did not
name.** Every `EnvironmentFile=` in the repo is `opencircuit.service`
(`/etc/opencircuit/config.env`) and `opencircuit-backup-alert.service`

On the templateless `backup-alert.env`: **not worth filing.** The `-` prefix

**Criterion 5 — the reading is correct, and now measured.** Confirmed
`env_example_guard_test.go`'s pattern is
`(?m)^([A-Z][A-Z0-9_]*)=` and that `TestEnvExampleCoversLoaderVariables` uses
only submatch 1, the key; the value is never examined. Mutation C is the
empirical form of the same conclusion — the guard passes against the poisoned
file. It is also the **only** test in the repo that reads `.env.example`.

I agree a parseability assertion belongs in that guard, and that `#0428` should
own it rather than this issue. Two notes for whoever takes `#0428`: the check
worth having is not "is the value `Atoi`-clean", which would require the guard to
know each variable's type, but the cheaper and more general **"does any value
line contain a shape systemd and `godotenv` disagree about"** — an unquoted
trailing `#`, a `$`, an `export ` prefix, a trailing `\`. That covers this defect
and the three silent siblings above in one assertion. And the guard should assert
against the *file*, since that is the artefact copied verbatim; the loader-level
test added here deliberately does not.
