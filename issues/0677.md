## Description

This is a child of `#0673`. With it, a tool can set up new events and tidy existing ones.

## Endpoints

| Method and path | Scope | Notes |
|---|---|---|
| `GET /api/v1/events` | `events:read` | Filters: `?from=`, `?to=`, `?status=draft\|published\|cancelled`, `?type=`, `?venue=`. Each event comes back with id, slug, title, type, starts and ends, venue, status, public URL, `luma_url` if known, and interests. |
| `GET /api/v1/events/{id}` | `events:read` | The full event, including its Markdown body. |
| `POST /api/v1/events` | `events:write` | Creates a **draft**, using the same fields and validation as the admin form: slug generation, type, venue, capacity, interests, body. |
| `PATCH /api/v1/events/{id}` | `events:write` | A partial update. |
| `POST /api/v1/events/{id}/publish`, `/unpublish`, `/cancel` | `events:write` | Same side effects as the admin actions: SEO cache, sitemap, and anything outreach does on publish. |
| `POST /api/v1/events/{id}/duplicate` | `events:write` | Copies to a new draft, with an optional `starts_at`. This is the fast way to set up a repeat workshop, and it follows the store's `-2` slug convention. |
| `GET /api/v1/venues`, `GET /api/v1/event-types`, `GET /api/v1/interests` | `venues:read` / `events:read` | Lookups, so a tool can fill in an event's fields with valid IDs. |

## Rules

- Publishing through the API goes through the same checks as the UI.
- Creating or updating an event never sends email by itself.
- The handlers reuse the `internal/events` and `internal/workshops` stores, whichever owns events after the unification, and the admin validation. Nothing is duplicated.
- Events are audited against the token.

## Acceptance criteria

- Handler tests cover:
  - creating a draft and then publishing it;
  - duplicating an event to a new date;
  - a validation error (bad venue, ends before it starts);
  - publish invalidating the SEO cache;
  - the scope checks.
- Test data never targets a seeded id (AGENTS.md §8b).
- The OpenAPI document includes every endpoint above.
