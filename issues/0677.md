## Description

This is a child of `#0673`. With it, a tool can set up new events and tidy existing ones.

## Endpoints

| Method and path | Scope | Notes |
|---|---|---|
| `GET /api/v1/events` | `events:read` | Filters: `?from=`, `?to=`, `?status=draft\|published\|cancelled`, `?type=`, `?venue=`. Each event comes back with id, slug, title, type, starts and ends, venue, status, public URL, `luma_url` if known, and interests. |
| `GET /api/v1/events/{id}` | `events:read` | The full event, including its Markdown body. |
| `POST /api/v1/events` | `events:write` | Creates a **draft**, using the same fields and validation as the admin form: slug generation, type, venue, capacity, interests, body. |
| `PATCH /api/v1/events/{id}` | `events:write` | A partial update. |
| `POST /api/v1/events/{id}/publish`, `/unpublish`, `/cancel` | `events:write` | Same side effects as the admin actions: SEO cache, sitemap, and anything outreach does on publish. |
| `POST /api/v1/events/{id}/duplicate` | `events:write` | Copies to a new draft, with an optional `starts_at`. This is the fast way to set up a repeat workshop, and it follows the store's `-2` slug convention. |
| `GET /api/v1/venues`, `GET /api/v1/event-types`, `GET /api/v1/interests` | `venues:read` / `events:read` | Lookups, so a tool can fill in an event's fields with valid IDs. |

## Rules

- Publishing through the API goes through the same checks as the UI.
- Creating or updating an event never sends email by itself.
- The handlers reuse the `internal/events` and `internal/workshops` stores, whichever owns events after the unification, and the admin validation. Nothing is duplicated.
- Events are audited against the token.

### What owns events today (checked 2026-11-15)

- **Store.** Events are `workshops` rows in `internal/workshops` (`Store`: `List`, `GetByID`, `Create`, `Update`, `Delete`, `ListVisible`). The statuses are `draft`, `published` and `canceled` (one L, per `000020`'s CHECK).
  - Create always makes a draft, with a slug from the title.
  - A collision gets `-2`, `-3` and so on (`internal/workshops/store.go`, `slugify` and the suffix loop).
  - `internal/events` is the SSE broker, unrelated to these events.
- **Admin.** The admin API is `internal/handlers/admin_workshops.go`, mounted at `/admin/workshops[/{id}]`. **Transitions are a `status` field in PATCH.** There are no publish routes.
- **Publish side effects.** The only ones are `h.invalidate()` (the same `*seo.Site` clears the meta cache and sitemap) and the audit row.
  - Nothing sends email or posts outward: Announce (`admin_workshop_announce.go`) is a separate admin route, and it only creates a *draft* campaign.
  - Outreach and Luma read published events at view time; neither hooks the transition.
  - So publish does not set an outward `PublicEffect`. It does make the event public on the site, which the description says (below).
- **Lookups.** These come from `internal/venues` (`ListAll`), `internal/eventtypes` (`ListAll`) and `internal/interests` (`ListAll`).
- **Ends before it starts.** **No validation for this exists anywhere** (handler, store or the `000020` schema), but the issue's acceptance requires it. It is added once, in the store, so the admin form and v1 both get it (below).

### Refactor first: one code path, admin behaviour unchanged

`AdminWorkshopsHandler.Create` and `.Patch` hold the validation, the store call, the error mapping, the invalidation and the audit inline with `http.ResponseWriter`. Extract them into transport-free methods. The admin `http.HandlerFunc`s then decode their request and call these methods, and so do the v1 ops.

```go
// admin_workshops.go
func (h *AdminWorkshopsHandler) createWorkshop(ctx context.Context, ip string, actorID *int64, req createWorkshopRequest) (workshops.Workshop, error)
func (h *AdminWorkshopsHandler) patchWorkshop(ctx context.Context, ip string, actorID *int64, id int64, req patchWorkshopRequest) (before, after workshops.Workshop, err error)
type workshopFieldError struct{ Status int; Field, Message string } // implements error
func workshopErrInfo(err error) (status int, field, msg string) // one table: workshopFieldError, workshops.Err*, else 500
func writeWorkshopError(w http.ResponseWriter, err error)       // admin: writeError(w, status, msg)
func workshopAPIError(err error) error                          // v1: 400→api.Validation{field: msg}, 404→api.NotFound("event"), 409→api.Conflict(msg), else err
```

- **Same validation and messages.** Every early `writeError(w, 400, …)` in `Create` and `Patch` becomes `return …, &workshopFieldError{400, "<json field>", "<the same message>"}`. That covers title, `starts_at`, `ends_at`, cover image, signup URL and capacity. The store sentinels keep their existing statuses and messages in `workshopErrInfo`, with fields `interest_ids`, `event_type_id`, `venue_id` and `status`. The `ErrDefault*Unset` errors are 409. **Every existing `admin_workshops*_test.go` must pass unchanged.**
- **Shared time parsing.** `parseOptionalTime(w, raw, field)` gains a pure twin, `parseOptionalTimeValue(raw *string, field string) (*time.Time, error)`, which returns a `*workshopFieldError` with the same message. The admin wrapper keeps its signature.
- **Audit.** Every audit write goes through `middleware.AttributeAPIToken(ctx, e)`, which is a no-op for a session. The `actorID` pointer is nil for v1, and `ip` is `""` (no client IP in the op context; see `#0676`'s Obstacles).
- **Invalidation.** `h.invalidate()` stays inside `createWorkshop` and `patchWorkshop`, after the store write commits, so v1 and admin cannot differ.
- **`internal/workshops`.** Add `ErrEndsBeforeStart = errors.New("workshops: ends_at is not after starts_at")`. `Create` and `Update` return it, with no query, when both times are set and `!EndsAt.After(*StartsAt)`. That is the rule the UI's clone dialog already enforces (`cloneWorkshopFields` in `web/src/lib/workshopAdmin.ts`: "The end must be after the start."). `workshopErrInfo` maps it to 400 with field `ends_at` and the message `"ends_at must be after starts_at"`. This is a new admin 400 too, on purpose: same validation everywhere.

They go in new `internal/handlers/v1_events.go` (events) and `v1_lookups.go` (venues, event types, interests), built by `func eventOperations(d V1Deps) []api.Operation`. The closures dereference `d.Workshops` and the rest only when called, because the parity test passes `V1Deps{}`.

| `list_interests` | `GET /api/v1/interests` | `events:read` | — | `{api.Page}` → `api.List[interestV1]` |

**Output shapes.** Times are converted with `.In(announceLocation)`, the existing America/Los_Angeles location in `admin_workshop_announce.go`, so they marshal with a Pacific offset. Add one helper, `inPacific(*time.Time) *time.Time`, in `v1_events.go`; `#0678` reuses it.

- `eventV1`:
  - `id`, `slug`, `title`, `summary`, `status`;
  - `type {id, slug, name}`;
  - `starts_at`, `ends_at`, `published_at`, `created_at`, `updated_at`;
  - `venue {id, name, address}`, or null (from the workshop row's `VenueID`/`Location*`, so no extra query);
  - `capacity`, `signup_url`, `interests [{id, slug, name}]` (never null);
  - `public_url` (`strings.TrimRight(baseURL,"/") + "/events/" + slug`) and `public` (true when `published_at` is set and the status is not draft, which is `ListVisible`'s rule);
  - `luma_url`: `signup_url` when its host is `lu.ma`, `luma.com` or a subdomain of either, else null. There is no feed fetch on a list; `#0678` does the real Luma comparison.
- `eventDetailV1` embeds `eventV1`, plus `body_md`, `location_note` and `cover_image`.
- The interest names come from one `Interests.ListAll` per call, mapped by id.
- `venueV1{id, name, address, note, enabled, is_default}`, `eventTypeV1{id, slug, name, enabled, is_default}` and `interestV1{id, slug, name, description, active}`. These are lookups, so they include disabled or inactive rows, flagged, letting a tool see why an id is refused. Each list is sorted by id, and the cursor is `{"id": last}`.

**Inputs.**

- **`createEventIn`.** The fields are `Title string`, `Summary`, `BodyMD`, `StartsAt`, `EndsAt`, `SignupURL`, `CoverImage *string`, `Capacity *int`, `InterestIDs []int64`, `EventTypeID *int64`, `VenueID *int64` and `NoVenue bool`, all `omitempty` except `title`.
  - The times are `*string` (RFC 3339 with an offset). This is deliberate: `parseOptionalTimeValue` gives the admin's exact messages, and a `time.Time` body field's parse error cannot name its field (see `#0676`'s Obstacles).
  - It maps onto `createWorkshopRequest`. `VenueID` set gives `Optional{Present, Valid, Value}`; `NoVenue` gives `Optional{Present: true}`, meaning null, no location; neither gives absent, meaning the default venue. Both together give `Validation{"venue_id": "send venue_id or no_venue, not both"}`.
  - There is no `slug` and no `status`, so `DisallowUnknownFields` rejects both, matching the admin's create.
- **`updateEventIn`.** It has `ID` (path) plus pointer fields: `Title`, `Summary`, `BodyMD`, `StartsAt`, `EndsAt`, `SignupURL`, `CoverImage` (`""` clears, as the admin does), `Capacity *int` with `ClearCapacity bool`, `InterestIDs *[]int64`, `EventTypeID *int64`, and `VenueID *int64` with `NoVenue bool`.
  - **There is no `status` field.** Transitions go through the three ops, so a PATCH can't publish by accident.
  - It maps onto `patchWorkshopRequest`, with the `Optional` capacity and venue built as above. An empty patch gives `Validation{"body": "send at least one field"}`.
- **Publish, unpublish and cancel** call `patchWorkshop` with `Status` set. First they apply the same offer rules as the UI (`web/src/lib/workshopAdmin.ts`):
  - publish needs a status other than `published`;
  - unpublish needs `published`;
  - cancel needs a status other than `canceled`.

  Otherwise the result is `api.Conflict("event is already published" | "only a published event can be unpublished" | "event is already canceled")`. The audit action follows `patchWorkshop`'s existing transition switch: `workshop.published`, `.unpublished` or `.canceled`.
- **`duplicate_event`**:
  - It loads the source (404 if missing) and builds a `createWorkshopRequest` that copies title, summary, `body_md`, capacity, cover image, interest ids, event type id and venue. A source with no venue gives `NoVenue`.
  - It copies the **same fields as the UI's "Clone with a new date"** (`cloneWorkshopFields`), and that includes `signup_url`.
  - With `starts_at`, the copy starts then. When the source has a positive duration, `ends_at` becomes the new start plus that duration, as `cloneDefaultEndLocal` does; otherwise `ends_at` is null. Without `starts_at`, the copy keeps the source's times.
  - It goes through `createWorkshop`, so the slug follows the store's `-2` convention, validation is the same, the cache is invalidated and `workshop.created` is written. Its audit metadata also gets `"copied_from": <source id>`: add an optional `extraMeta map[string]any` parameter, or set it from the op after the fact, using a `createWorkshopOpts` struct rather than a long parameter list.
- **`list_events`**:
  - It calls `Workshops.List`, filters in Go, sorts by `starts_at` ascending (undated last), then id, and paginates with cursor `{"s": "<RFC3339 or empty>", "id": n}`.
  - `status` must be draft, published or canceled. `type` is an event-type **slug**. `venue` is a venue id.
  - With `from` or `to` set, undated events drop out, and the range is `starts_at` in `[from, to)`.
  - A bad status gives `Validation{"status": "must be one of draft, published, canceled"}`.

**Narrow store interfaces** (in `v1_events.go`): `venueLister{ListAll}`, `eventTypeLister{ListAll}` and `interestLister{ListAll}`, each satisfied by the real store. `V1Deps` gains `Workshops *AdminWorkshopsHandler` (for `createWorkshop`/`patchWorkshop` and its `store`), `Venues venueLister`, `EventTypes eventTypeLister` and `Interests interestLister`. `BaseURL` already exists from `#0676`.

## Assumptions (user may override)

- **The status spelling is `canceled`**, the database value, everywhere in v1, including `?status=`. The issue's `cancelled` was a spelling slip.
- **Transitions have their own ops, and `update_event` has no `status`.** They follow the UI's offer rules: publishing a published event is a 409, not a silent no-op.
- **Publish and cancel are marked `PUBLIC`**, because they change what the public site shows right away. Nothing in this issue sends email or posts to social media. `TestV1Events_NoEmailOnWrite` pins that.
- **An end that isn't after the start is now refused in the admin form too.** Equal start and end count as refused, matching the clone dialog's rule.
- **`duplicate_event` copies what the UI's clone copies**, `signup_url` included, so the result matches what an admin would get in the UI. Update it with `update_event` if the new date has its own Luma page. Without `starts_at`, it keeps the source's times.
- **`luma_url` is read from `signup_url`** when that is a Luma link. No feed is fetched per list; `#0678` does the full comparison.
- **Event times are returned with a Pacific offset**, e.g. `2026-12-02T18:00:00-08:00`. Inputs accept any RFC 3339 offset.
- **`venues:read` covers venues only.** Event types and interests are under `events:read`, as the issue's table implies.
