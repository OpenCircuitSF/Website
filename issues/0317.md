## Description

`#0129` made `RestartSignup` clear `subscribers.import_id`, so a person whose
invite import was revoked and who later signs up on the website is not mistaken
for an unaccepted invitee. That fix is right and its review confirmed all four
misfire consequences fall out of it.

**A side effect: that row keeps `source='import'` and its `source_detail` while
`import_id` goes NULL.** The two fields now describe different moments —
`source` records where the address originally came from, `import_id` records
whether the *current* subscription derives from that batch.

Neither is wrong. `#0129`'s review was explicit that clearing `import_id` moves
`Revoke` targeting in the **right** direction: a resigned-up row escapes a later
revoke, which is the same carve-out PRD §6.10.1 already makes for a confirmed
invitee. And provenance survives on `subscriber_events`.

**What is missing is the decision being written down.** A reader encountering
`source='import'` with a NULL `import_id` has no way to tell whether that is
intentional or a bug, and the natural repair — "re-link them" — would reintroduce
`#0129`'s suppression misfire.

## Acceptance criteria

1. Record, in the code at both fields, what each one means and why they can
   disagree: `source`/`source_detail` are **historical provenance**, `import_id`
   is a **current-state link** whose absence means the subscription no longer
   derives from that batch.
2. State plainly that re-linking them would reintroduce `#0129`'s defect, so the
   next reader does not "fix" it. Name `#0129` so the reasoning is findable.
3. Decide whether anything should read `source='import' AND import_id IS NULL` as
   a meaningful state — a resigned-up former invitee is arguably worth
   distinguishing in the admin UI — and record the answer either way.
4. Check every consumer of `source` for an assumption that `import_id` is set
   alongside it, and report the list even if empty. `#0311` is open on
   `imported_30d`, whose proposed fix is to key on `source = 'import'` — the two
   issues must agree, so read it before deciding.
5. No behaviour change is required by this issue. If you conclude one is needed,
   say so rather than making it silently.
6. `ISSUE=NNNN scripts/check.sh go ./internal/subscribers/... ./internal/handlers/...`
   passes with no skips.

Implemented as the first of a three-issue batch (`#0317` → `#0311` → `#0316`),
per the batch's own instruction that `#0317` settle semantics before `#0311`'s

**Criteria 1 and 2 (record the semantics, name #0129).** Rewrote the doc
comment above `Subscriber.Source`/`SourceDetail`/`ConsentBasis`/`ImportID`/
`InvitedAt` in `internal/subscribers/store.go` (the block already covering
both fields) to state plainly: `Source`/`SourceDetail` are historical
provenance, fixed at INSERT and never rewritten (verified by grepping this
file for an UPDATE that touches `source` — there is none); `ImportID` is a
current-state link that `RestartSignup` clears (named, with a pointer to that
method's own `#0129` doc comment) when a row's current subscription no longer
derives from the batch. Spelled out explicitly that re-linking them —
whether by having `RestartSignup` leave `ImportID` set, or by having `Revoke`
key off `Source` instead of `ImportID` — reintroduces `#0129`'s suppression
misfire.

**Criterion 3 (is `source='import' AND import_id IS NULL` meaningful).**
Recorded: yes, it is a real and nameable state (a resigned-up former
invitee), distinguishable from an ordinary website signup by
`ConsentBasis == ConsentBasisDoubleOptIn` alongside it. No new admin-UI
filter or badge was built for it — no acceptance criterion here asked for
one, and `#0316` already restores the batch link at the event level, which is
the concrete "provenance stays reachable" need the two sibling issues share.

**Criterion 4 (every consumer of `source`).** Grepped every non-test read of
`.Source` / `SubscriberSourceImport` / `.ImportID` in `internal/handlers` and
`internal/subscribers`. None assume `ImportID` is set alongside `Source`:
`Confirm`, `Unsubscribe`, and `pending.go`'s invited-view all key the
"unaccepted invitation" inference off `ImportID != nil && ConsentBasis ==
nil` directly, never off `Source`. `admin_subscribers.go` and
`admin_pending.go` serialize both fields independently without cross-reading
one from the other. **List: empty** — nothing needed a change for this
criterion. Read `#0311` before deciding, per the issue's own instruction;
`#0311`'s revised predicate keys on `Source`, matching this issue's
"historical provenance" framing (see `#0311`'s own Work log for why
`Source` alone needed a `confirmed_at IS NULL` guard to stay mutually
exclusive with `confirmed_30d` — an addition, not a disagreement, with this
issue's semantics).

**Criterion 5 (no behaviour change).** None made by this issue. `#0311`'s
`Growth30Days` predicate change is that issue's own acceptance criterion, not
