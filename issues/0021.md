## Description

A 1200×630 image in the terminal style, used as the fallback preview card for every route that has no image of its own.

## Acceptance criteria

- [x] `og-default.png` at 1200×630 in `web/public/` — verified mechanically, see `## Verification`
- [x] Composed in the terminal language: dark ground, green prompt line, the group name in the display face, the logo mark
- [x] Text remains legible at the ~500 px width most feeds render — verified by downscaling and looking, see `## Verification`
- [x] File under 300 KB — 151,074 bytes (147.5 KB)
- [ ] Referenced as the default `og:image` by #0019's route table — **belongs to #0019**, which is not yet implemented. Not touched here (no `internal/seo/`, no route-table edits).
- [ ] Rendered preview checked in at least two of: Discord, iMessage, Slack — **cannot be done by an agent.** See `## Manual verification required`.

## Notes

A first-pass version already exists at `placeholder/og-default.png`, set in Arial Black as a stand-in for Archivo and generated by a measured-layout script (text is fitted to the available width rather than positioned by eye). This issue replaces it once the real display face is available.

PRD §4.5, §7.4. Feeds downscale aggressively — anything smaller than roughly 40 px tall in the source will be unreadable in a timeline. Favor a few large words over a dense composition.

## Fix

Added `assets/og/build-og.py`, a reproducible generator that supersedes
`placeholder/build-og.py` for the real site's card. `placeholder/build-og.py`
itself was left untouched — it's a separate deliverable (the temporary static
site at `opencircuitsf.com`, not `web/public/`) owned by a different issue's
lane, and its own header names #0021 as the issue that replaces it "once the
real display face is available," which this does for `web/public/`.

**Font decision (recorded per the task instructions):** rebuilt against the
project's actual self-hosted brand faces — Archivo (variable) and JetBrains
Mono — rather than keeping Arial Black / Menlo. Reasoning:

- The share card is the single most-seen brand artefact (every social
  preview across every route without its own image). Setting it in a
  non-brand system font while the rest of the site uses Archivo/JetBrains
  Mono (`web/src/app.css`, self-hosted under OFL per #0012) is a visible
  inconsistency in exactly the place inconsistency is most visible.
- The Arial Black / Menlo version only builds on macOS (`HANDOFF.md`: "will
  fail loudly elsewhere"), which is a real liability for a script meant to be
  reproducible in CI or on a Linux box later.
- The blocker named in `placeholder/build-og.py`'s docstring — "Issue #0021
  replaces it once the real display face is available" — is exactly this
  issue, and the face *is* available (`web/public/fonts/archivo-variable-latin.woff2`,
  landed by #0012).
- Pillow cannot load `.woff2` directly (needs TrueType/OpenType). `fontTools`
  is already an installed dependency in this environment (verified: `import
  fontTools` succeeds, version 4.60.2) and its `TTLib`/`varLib.instancer`
  modules decode `.woff2` to `.ttf` — confirmed working with `brotli` 1.2.0
  present, which `fontTools` needs for woff2's brotli-compressed tables. No
  new tool was installed; nothing heavyweight was needed. The script decodes
  to a `tempfile.TemporaryDirectory()` at run time and commits nothing
  derived — only the generator and its PNG output are checked in.
- Archivo is a variable font (`wght` axis, 100–900); it is instantiated at
  `wght=800`, matching the weight the rest of the site already uses for its
  hero headline (`placeholder/index.html` `.hero-word`, `font-weight: 800`),
  rather than picking a value by eye.

Layout keeps the placeholder script's measured-width discipline (nothing is
positioned by eye) and extends it to the headline block, which the original
didn't need to fit dynamically: `_fit_size()` shrinks the "CIRCUIT" headline,
and separately the `[ OK ]` row, until each fits the 600px text column,
because Archivo's metrics don't match Arial Black's and a fixed point size
carried over from the old script silently overflowed in an early draft.

Not verified at all: real-world crawler/renderer behavior in any of Discord,
iMessage, Slack, X, Facebook, or LinkedIn. A Pillow render and a downscale
are a proxy for "will this be legible," not a guarantee — actual OG-image
crawlers sometimes re-encode, crop to a different aspect ratio, or apply
their own scaling filter. See `## Manual verification required`.

## Manual verification required

A human needs to do the following before criterion 6 can be ticked — an
agent cannot post into these services:

1. **Get the image reachable at a public URL.** Until #0019/deploy work
   lands, the fastest path is a personal scratch page or a temporary paste
   host that serves `web/public/og-default.png` with correct
   `Content-Type: image/png`, since Discord/iMessage/Slack unfurl from a URL,
   not a local file.
2. **Discord**: paste the URL (or a page whose `og:image` points at it) into
   any channel/DM you control and check the embed. Look for: the full
   1200×630 card renders (not cropped to square), text stays sharp (Discord
   does not re-encode aggressively but does resize), colors are not
   washed out.
3. **iMessage**: send the URL to yourself or a test contact and check the
   link preview thumbnail. iMessage crops aggressively toward a squarer
   thumbnail on some devices — check that "OPEN CIRCUIT_SF" and the logo
   are not both cut off in the crop; if they are, the composition may need
   a squarer safe zone.
4. **Slack**: paste the URL into a channel/DM and check the unfurl. Slack
   respects the 1200×630 aspect ratio closely; check specifically that the
   `[ OK ]` row and command line (the bottom-most, smallest text) are not
   clipped by Slack's card height.
5. If any of the three shows unexpected cropping, re-run
   `python3 assets/og/build-og.py` after adjusting the composition (e.g.
   tightening the safe zone to account for that service's crop), rather than
   hand-editing the PNG.

## Gotchas

- **Font decision, restated for visibility:** kept the brand faces
  (Archivo + JetBrains Mono), not the placeholder's Arial Black/Menlo. See
  `## Fix` for the full reasoning — in short, the share card is the
  most-visible brand artefact, the brand faces are already self-hosted, and
  using system fonts made the old script macOS-only.
- Pillow cannot open `.woff2` directly; `fontTools.ttLib.TTFont(...).save()`
  after clearing `.flavor` decodes it to a loadable `.ttf`. This needs
  `fontTools`'s `brotli` extra (woff2 tables are brotli-compressed) — both
  were already present in this environment, so nothing new was installed.
  If a future environment lacks `brotli`, `fontTools` will raise an
  `ImportError` pointing at it (`pip install brotli`), not fail silently.
- Archivo is a variable font (`fvar` axis `wght`, range 100–900, default
  600). `fontTools.varLib.instancer.instantiateVariableFont` pins it to a
  static instance; `wght=800` was chosen to match the site's existing hero
  headline weight rather than guessed.
- `placeholder/build-og.py` and `placeholder/og-default.png` were **not**
  touched — they're a separate deliverable (the temporary static site) and
  explicitly out of this issue's lane per the task instructions ("as a
  reference"). Its own docstring/README already point at this issue as the
  eventual replacement for the real site's card, not for itself.
- `npm run build` overwrites `web/dist/index.html` with real built output as
  a side effect of any frontend build/verify step. Restored it by rewriting
  from `git show HEAD:web/dist/index.html` (never `git checkout`, per
  `CLAUDE.md` §8a) so it doesn't leak into this commit or collide with
  another subagent's in-flight `web/` changes.
- **Reviewer note (token role):** `FAINT = #4E6553`, used for the `_SF`
  suffix, is PRD §4.2's dark `--border-strong`, not `--text-faint`
  (`#7E8D82`) — which is what the site's own `.brand-name .sf` uses. It
  measures 3.08:1 on `#0A0D0B`, so it clears WCAG large-text 3:1 at the 52 px
  it is set at, and the value is inherited verbatim from
  `placeholder/build-og.py` rather than introduced here. Not a blocker for a
  decorative wordmark suffix; worth aligning if the card is ever revised.
- **Reviewer note (smallest text):** the `[ OK ]` row renders at 24 px in the
  source, below the `## Notes` guidance of "roughly 40 px tall". It read fine
  in the 500 px downscale, but it is the first thing that will suffer in a
  real feed — check it specifically during the manual pass.
