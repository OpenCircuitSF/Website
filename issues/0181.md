## Description

Citations of our own tracker and guidance files leaking into copy an admin reads has now been found **three times, on three different axes**:

- `#0172` swept `web/` and fixed two.
- `#0175`'s review swept **Go strings that render verbatim** and found three more, which `web/`-only sweeps structurally could not see.
- `#0178`'s review swept **backwards from the SPA** — tracing which response fields `api.ts` renders — and confirmed those were the last, while finding one more surface nobody had covered (below).

Each pass was thorough within its method and blind outside it. `#0178`'s reviewer proposed the durable fix: **one assertion that no admin-facing message literal contains `CLAUDE.md`, `PRD §`, or `#0NNN`.** It would have failed at `#0172` rather than requiring a third sweep on a fourth axis.

This is **not** the phrase-pinning `#0174` warns against. It does not assert what any message *says*; it asserts that none of them cites a document only we can read. The rule is stable even as the copy changes.

## Acceptance criteria

- [x] A test fails when an admin-facing message literal contains `CLAUDE.md`, `PRD §`, or an issue reference (`#0` followed by digits)
- [x] It is scoped to strings that actually reach a user. `#0178`'s review established the boundary precisely: only `internal/handlers`, `internal/middleware` (machine codes) and `internal/seo` (plain text, non-SPA) write HTTP bodies, and `api.ts`'s `request()` collapses non-2xx bodies to `err?.error ?? err?.message`. **Code comments must not trip it** — the same citations are correct and wanted there
- [x] **CAN-SPAM §7704 and env var names must still pass** — `#0175`'s review drew that line deliberately: a statute is something an admin can look up, and `EMAIL_REPLY_TO` is sometimes the entire actionable fact
- [x] Prove it fails against the pre-`#0178` strings — restore one temporarily and watch it fire
- [x] Decide whether the guard belongs on the Go side, the `web/` side, or both, and record why. The three leaks were all Go-authored, but `#0172`'s two were in Svelte
- [x] `ISSUE=0181 scripts/check.sh go ./internal/...` and `scripts/check.sh web` both pass

## Root cause

Three sweeps (`#0172` in `web/`, `#0175`'s review over Go strings that
render verbatim, `#0178`'s review tracing backwards from the SPA) each
found the same defect on a different axis and closed only the instances
they could see. Nothing asserted the *class*: that no string reaching an
admin cites a document only the team can read. `#0178`'s reviewer named
the fix — one assertion, not a fourth sweep — and this issue builds it.

## Fix

Two guards, one per language, both AST-based rather than a text grep so
comments (where these citations correctly live, per `#0172`/`#0178`) are
excluded structurally instead of by allowlist.

**Go — `internal/handlers/citation_guard_test.go`.** Walks every non-test
`.go` file's `*ast.BasicLit` string literals (via `go/parser`/`go/ast`,
never visiting comments) in four directories:

- `internal/handlers`, `internal/middleware`, `internal/seo` — the three
  packages `#0178`'s review established write an HTTP body directly.
- `internal/mailing` — **added after verifying rather than assuming the
  three-package boundary.** `PreflightFailure.Message` (the exact field
  `#0178` fixed a citation in) is authored entirely in
  `internal/mailing/preflight.go` and serialized untouched by a handler;
  a guard scoped to only the three body-writing packages would not have
  caught the original `#0178` leak at all, since the literal never lived
  in `internal/handlers`. Grepped every other `internal/` package for
  `Message string` fields and `.Error()` calls and found nothing else
  that threads a literal into a response body (the two near-misses —
  `internal/sesnotify`'s `rawMessage` parameter name and one `.Error()`
  hit in an `internal/auth/login.go` comment — are not admin-facing
  strings).

Pattern: `` CLAUDE\.md|PRD §|#0[0-9]{3}\b `` — the trailing `\b` matters:
without it, `internal/mailing/templates.go`'s `colorButtonText =
"#04140a"` false-positives, since `#0414` is a substring of `#04140a`.
CAN-SPAM §7704 and `EMAIL_REPLY_TO`/`EMAIL_LIST_DOMAIN` need no
allowlisting — neither matches the pattern, so they pass by construction.

**web — `web/src/lib/citationGuard.test.ts`.** Built even though the
three most recent leaks were Go-authored, because `#0172`'s original two
were in Svelte — a Go-only guard would not have caught the case that
started this. Uses the TypeScript compiler's AST for `.ts` files
(`StringLiteral`/`NoSubstitutionTemplateLiteral`/`TemplateHead`/`Middle`/
`Tail` nodes) and `svelte/compiler`'s `parse({ modern: true })` AST for
`.svelte` files (`Text` nodes in the template fragment; `Literal`/
`TemplateElement` nodes in the `<script>` instance/module content).
Comments are separate node types (`Comment` in the fragment tree) or a
separate array (`ast.comments`, for the script) in both ASTs, so neither
is ever visited by the literal/text collector. Required adding
`@types/node` (`web/package.json`) and `"node"` to `tsconfig.json`'s
`types` array so `svelte-check` can resolve the `node:fs`/`node:path`/
`node:url` imports the file-walk needs — without it `npm run check`
failed with "Cannot find module 'node:fs'" (TS7016-class error, the
`types` array restricts ambient global typings to an explicit allowlist
and Node wasn't in it).

Both guard files also carry synthetic-fixture unit tests (not dependent
on the current state of the real tree) proving each of the three
exclusions individually and proving the guard fires on a citation — see
Verification.

## Gotchas

- **The three-package boundary from `#0178`'s review is about who writes
  the HTTP body, not who authors the string.** `internal/mailing` writes
  no response body itself but is where `#0178`'s actual leak lived
  (`PreflightFailure.Message`, serialized untouched by a handler). A
  guard that trusted the "only handlers/middleware/seo write bodies"
  framing literally, without tracing where the *literals* originate,
  would have shipped with a hole exactly the shape of the bug it exists
  to prevent. Worth remembering for any future package that gains a
  similar "authored elsewhere, serialized here" field.
- **The `\b` word-boundary is load-bearing, not decorative.** Without it,
  `#0[0-9]{3}` alone matches inside `internal/mailing/templates.go`'s
  `colorButtonText = "#04140a"` (a real string literal, not a comment) —
  a false positive that would have broken the guard on the very first
  run had the pattern been written the more obvious way.
- **`svelte-check`'s `types` array is a strict allowlist, not a
  starting point.** Adding `@types/node` to `node_modules` alone did
  nothing; `tsconfig.json`'s `"types": [...]` array had to name `"node"`
  explicitly or `svelte-check` kept reporting `Cannot find module
  'node:fs'` even though the package was installed and `vitest` ran the
  file fine (Vite/esbuild don't type-check imports the way `tsc` does).
- **AST-based exclusion of comments has no failure mode a regex-based
  one would.** An earlier design considered stripping comments with
  regex before pattern-matching raw text; discarded because `//` inside
  a legitimate string (e.g. a URL) would have been misread as a comment
  start, silently under-scanning. Parsing properly (`go/ast`,
  TypeScript's compiler, `svelte/compiler`) sidesteps the whole class of
  edge case.
