## Description

Citations of our own tracker and guidance files leaking into copy an admin reads has now been found **three times, on three different axes**:

- `#0172` swept `web/` and fixed two.
- `#0175`'s review swept **Go strings that render verbatim** and found three more, which `web/`-only sweeps structurally could not see.
- `#0178`'s review swept **backwards from the SPA** — tracing which response fields `api.ts` renders — and confirmed those were the last, while finding one more surface nobody had covered (below).

Each pass was thorough within its method and blind outside it. `#0178`'s reviewer proposed the durable fix: **one assertion that no admin-facing message literal contains `CLAUDE.md`, `PRD §`, or `#0NNN`.** It would have failed at `#0172` rather than requiring a third sweep on a fourth axis.

This is **not** the phrase-pinning `#0174` warns against. It does not assert what any message *says*; it asserts that none of them cites a document only we can read. The rule is stable even as the copy changes.

## Acceptance criteria

- [ ] A test fails when an admin-facing message literal contains `CLAUDE.md`, `PRD §`, or an issue reference (`#0` followed by digits)
- [ ] It is scoped to strings that actually reach a user. `#0178`'s review established the boundary precisely: only `internal/handlers`, `internal/middleware` (machine codes) and `internal/seo` (plain text, non-SPA) write HTTP bodies, and `api.ts`'s `request()` collapses non-2xx bodies to `err?.error ?? err?.message`. **Code comments must not trip it** — the same citations are correct and wanted there
- [ ] **CAN-SPAM §7704 and env var names must still pass** — `#0175`'s review drew that line deliberately: a statute is something an admin can look up, and `EMAIL_REPLY_TO` is sometimes the entire actionable fact
- [ ] Prove it fails against the pre-`#0178` strings — restore one temporarily and watch it fire
- [ ] Decide whether the guard belongs on the Go side, the `web/` side, or both, and record why. The three leaks were all Go-authored, but `#0172`'s two were in Svelte
- [ ] `ISSUE=0181 scripts/check.sh go ./internal/...` and `scripts/check.sh web` both pass

## Notes

Reported by `#0178`'s phase-3 review under `CLAUDE.md` §9.

Worth noting what makes this worth building where `#0176` was not: that issue proposed hardening a guard against inputs the repo does not produce, five passes in. This one closes a class that has actually recurred three times, and the assertion is a few lines rather than a parser.
