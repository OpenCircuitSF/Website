## Description

`scripts/go_file_visit_floor_guard_test.sh` counts `ClaimDue`/`OrphanSweep` call
sites with **grep**; the Go guard it pins counts them with **`go/ast`**. `#0304`'s
review measured both:

| Population | grep | AST |
|---|---|---|
| **non-exempt** | **12** | **12** — agree exactly, one-for-one |
| total | **35** | **32** |

The three extras are all inside `internal/outbox` and are exactly the miscount
class grep is prone to: one occurrence in a **prose comment**
(`claim_kinds_call_site_guard_test.go:156`) and two inside **raw-string
fixtures** (lines 347 and 376, `fixtureSrc`/`scopedFixtureSrc`), where the AST
correctly counts zero.

Also worth recording: `grep -c` counts **lines**, so it under-counts when two
calls share one line.

## Why this is documentation rather than a bug

The divergence is in the **inflating** direction on the total, which only
loosens the upper bound — the safe direction. The number that governs the check
that matters, the non-exempt count, agrees exactly.

And `claimKindsGuardMinPlausibleCallSiteCount`'s doc comment says **32**, the AST
figure, while the harness measures 35. Neither is wrong for its own method; they
are simply counting different things and both call it "the population".

**Do not make the oracle parse Go.** Its independence from `go/ast` is the entire
point of the external harness (CLAUDE.md §8, `#0300`) — an oracle that used the
same parser as its subject would be the copy-of-the-answer shape that harness
exists to avoid.

## Acceptance criteria

1. Both the harness comment and `claimKindsGuardMinPlausibleCallSiteCount`'s doc
   comment record that the two counts are measured differently, state both
   numbers, and name the three divergent sites.
2. Record the direction — grep inflates the total, loosening only the upper
   bound — so a future reader knows which way an unexplained gap should move.
3. Record the `grep -c` line-versus-occurrence under-count risk.
4. **The oracle stays grep-based.** If you conclude the divergence must be closed
   rather than documented, say why and stop — closing it by parsing Go would
   defeat the harness.
5. Re-measure both numbers rather than copying them from this issue.
6. `ISSUE=NNNN scripts/check.sh guards` passes, run at least twice.

## Fix

Sequenced last, after `#0321` (`scripts/go_file_visit_floor_guard_test.sh`,
`5ef8830`) and `#0322` (`internal/outbox/claim_kinds_call_site_guard_test.go`'s
`claimKindsGuardMinPlausibleNonExemptCallSiteCount`, `0b781f2`). This issue
touches both files, but different regions of each — the header comment
already corrected by `#0321` and the margin comment it also corrected are
untouched; `#0322`'s `claimKindsGuardMinPlausibleNonExemptCallSiteCount`
doc comment is untouched; this issue only adds to
`claimKindsGuardMinPlausibleCallSiteCount`'s doc comment and to
`count_outbox_call_sites`'s header comment in the shell script.

Re-measured both populations fresh this session (criterion 5), the same way
as `#0321`/`#0322` — a throwaway `internal/outbox/zzz_scratch_count_test.go`
for the go/ast side (deleted before committing anything, `git status
--porcelain` confirmed empty afterward) and the harness's own
`count_outbox_call_sites` bash function, extracted and run standalone, for
the grep side:

| Population | grep | go/ast |
|---|---|---|
| total | **35** | **32** |
| non-exempt | **12** | **12** — agree exactly |

Matches `#0304`'s review numbers exactly; nothing has drifted.

**Named the three divergent sites** (criteria 1, 2, 3) in both places
acceptance criterion 1 asks for:

- `count_outbox_call_sites`'s header comment in
  `scripts/go_file_visit_floor_guard_test.sh` — added a paragraph stating
  both numbers, that they diverge only on the total (never the non-exempt
  count the second floor depends on), naming the three sites by symbol
  (`nameMatchesGuardedMethod`'s doc comment; `fixtureSrc` and
  `scopedFixtureSrc`, the two raw-string fixtures
  `TestClaimKindsGuardFiresOnFixtureWithNoKinds` builds), the direction of
  the error (grep inflates, loosening only `outbox_floor_plausible`'s upper
  bound), and the `grep -c` line-vs-occurrence under-count risk (criterion
  3), which is the opposite-direction risk from the one this issue is
  otherwise about.
- `claimKindsGuardMinPlausibleCallSiteCount`'s own doc comment in
  `internal/outbox/claim_kinds_call_site_guard_test.go` — added the
  matching paragraph, since that comment already stated 32 without ever
  mentioning the harness measures something different for the same
  population.
- **Criterion 4** — the oracle stays grep-based; both new paragraphs say
  explicitly why closing the divergence by having the harness parse Go
  would defeat the harness's independence (CLAUDE.md §8, `#0300`), and
  nothing was changed about `count_outbox_call_sites`'s mechanism.

**A self-referential wrinkle found and fixed during this pass**: an early
draft of the new paragraph in
`claim_kinds_call_site_guard_test.go` described the prose-comment divergent
site by literally reproducing the pattern text (`".ClaimDue("` and
`".OrphanSweep("`) it was describing — which is itself a line matching
`count_outbox_call_sites`'s grep pattern, so the total population became
**36**, not 35, the moment that sentence was saved. Caught by re-running
the harness after writing the comment rather than trusting the draft;
fixed by rephrasing the sentence to describe the divergent site without
reproducing its matched substring, and re-verified the population is back
to 35/12 before running any check. Left in this Fix section as a small,
concrete demonstration of exactly the phenomenon the issue is about: a
grep-based population is sensitive to what prose says, not just to what
code does.
