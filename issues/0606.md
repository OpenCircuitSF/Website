## Description

Brennan, 2026-10-18, 10:42 pm, on production after the deploy: "When I go to
this page I do not see any Delete and redo option at all!"

`#0604` added the button to `OutreachPostCard` via
`cardButtons().takedown`. But since `#0582`, automatic channels (Bluesky,
Mastodon) render in `OutreachAnnouncement.svelte`'s "How it will look"
previews. `OutreachWorkshop.svelte` passes
`channelFilter={(c) => !sendsItself(c)}` to `OutreachPostCards`, so a
posted Bluesky or Mastodon post never reaches a card with the button. The
jsdom tests mounted `OutreachPostCards` directly and missed this.

## Acceptance criteria

- [ ] In `OutreachAnnouncement.svelte`, each auto-channel preview whose post
      is `posted` shows **Delete and redo…**. It opens the same
      `OutreachConfirmDialog` copy and calls the same `#0604` API
      (`takedownOutreachPost` or the equivalent in `api.ts`). On success it
      calls `reload()`, so the post shows as a draft, the Post button and
      Reset return, and the posted summary updates. Errors show in the
      section's existing `role="alert"`.
- [ ] Apply the same check to the Reminder and Last call wave rows
      (`OutreachWaveRow.svelte`) if they show posted auto posts without
      the button.
- [ ] A behaviour test mounts **`OutreachWorkshop`**, not just the card,
      with a posted Bluesky post, and finds and uses the button. This is
      the gap that let `#0604` ship without it.
- [ ] Modal, no-native-confirm, live-region and jargon guards stay green.
- [ ] Verified with `ISSUE=0606 scripts/check.sh web`. Evidence is jsdom.
