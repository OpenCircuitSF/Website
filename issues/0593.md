## Resolution

### Part A

- Results: `devmocks` rollup honours `from`/`to` (half-open, at most 120 days;
  default last seven). `ResultsSummary` and `GET /admin/outreach` load posts
  with one `Store.ListPostsByOutreach` query instead of `ListPosts` per row.
  The summary row gains `queued`; the posts cell reads "... · 1 posting".
- Mastodon account: `Manager.Test` caches the verified `@user@host` in memory,
  keyed by the instance URL and token, and `Account("mastodon")` returns it,
  falling back to the host until a test has run (and again after the URL or
  token changes). No migration, no stored value; it is lost on restart.
- Previews: the panel carries `card_host` (`BASE_URL`'s host) and `thumb_ok`
  (`Publisher.ThumbOK`, which runs the publisher's own `thumbnail` check). The
  Bluesky preview uses both; `location.host` and the `/media/` prefix rule are
  gone. A posting seam that cannot answer reports `thumb_ok: false`.
- Manual channels: the links table shows rows for a switched-off channel's
  still-visible posts (not phantom rows for its other waves); `GET
  /admin/outreach` `counts` come from visible posts.
- Words: the Results table shows post status in plain words
  (`postStatusWords`); `TestOutreachServerLabelsAvoidBannedJargon` reads the
  SPA guard's own `BANNED` pattern and checks channel, wave and slot labels.

### Part B

- **Settings (#0584):** `lib/serverSettingsStore.svelte.ts` holds one shared load; `Admin.svelte` passes it to both `ServerSettings` mounts (`scope="server"` and `scope="outreach"`), so there is one `getServerSettings` call. The precedence note shows only on the Server mount (`showNote={false}` on Outreach). A test covers `#/settings?section=server`: scrolls to `settings-server`, one fetch, one `.srv-note`.
- **Reset (#0592):** `OutreachWorkshop.svelte` clears the "Outreach was reset" note on the next change (a post change, a post/wave reload, or a Schedule all confirm).
- **Flyers (#0589):** the preview has a Hide/Show preview toggle (collapses only under 64rem, `aria-expanded`); the location form focuses the first invalid field on a failed submit; new-flyer defaults apply only to a flyer created in this session (`markFreshFlyer` from the create flow, cleared on first save), so a flyer saved empty is not re-defaulted; description, title position and copies sit under a "More" disclosure (copies is now a per-location "Copies for X" list there; the disclosure opens by itself on a description error).
- **Navigation (#0586):** row buttons carry `aria-label` "Promote <title>" / "Open outreach for <title>"; a "Past" panel lists past workshops that had outreach (Open and Results links); the Locations panel title is "Flyer spots"; Dashboard uses `Promise.allSettled`, and a failed call drops only its own rows (without the outreach list the unannounced count is omitted rather than overstated).
- **Posting (#0581):** the native-confirm guard also catches `confirm(<identifier>)` and `confirm()`, excluding `function confirm(` declarations.
- **Announcement (#0582):** "Use shared message" restores the tail via `restoredTail` (own tail kept; lost hashtags come from a non-customized sibling; a lost link line, for channels whose text carries one, comes from a sibling with this post's short URL, or a plain "Sign up here" line); `splitBody` treats only the final hashtag paragraph as tail, so a message ending in a hashtag-only paragraph stays editable; the stale-draft warning shows on the Announcement section with a Regenerate button for non-customized posts; `OutreachLinks.svelte` and its test are deleted (nothing referenced them).
- **Scheduling (#0587):** the dialog's dead announce branch is gone; a `time_passed` skipped row has "Pick a time", sent as a `times` entry for its post id. `admin_outreach_links.go` ScheduleAll now schedules a post skipped as `time_passed` when the confirm names it and gives a time inside the usual window (other skip reasons are not rescued; audit metadata gains `rescued`).
- **Words (#0591):** `ComposerActions.canCopy` removed.
