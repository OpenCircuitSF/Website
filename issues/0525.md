## Description

`#0518` added `internal/seo.NoIndexAPIMiddleware`, which sets
`X-Robots-Tag: noindex` on responses under `/api/`, and wrapped the whole mux
with it in `cmd/opencircuit/main.go`'s `mountAndServe`.

The middleware itself is well tested: breaking its prefix check fails
`TestNoIndexAPIMiddleware_SetsHeaderOnAPIRoutesOnly`. **The wiring is not.**
`#0518`'s reviewer removed the wrap from `mountAndServe` in a throwaway worktree
and both `internal/seo` and `cmd/opencircuit` stayed green. The header works on
`HEAD` today — the reviewer proved it over the real wiring on a live socket — but
a future edit to `mountAndServe` could drop it silently.

This is the same unpinned-wiring shape as `#0326`, `#0490`, and `#0492`.

## Acceptance criteria

1. A `cmd/opencircuit` test runs the real `mountAndServe` and asserts
   `X-Robots-Tag: noindex` on a 401 from `GET /api/me`, a 405 from
   `POST /api/me`, and a 404 under `/api/`.
2. The same test asserts the header is **absent** on `/`, `/sitemap.xml`,
   `/robots.txt`, and a bare `/apiary`-style path that only shares the prefix
   textually.
3. **Prove it fails** with the wrap removed from `mountAndServe`, in a throwaway
   worktree, never the shared tree.
4. No fixed shared port (CLAUDE.md §8b).
5. `ISSUE=NNNN scripts/check.sh go ./cmd/opencircuit/... ./internal/seo/...`
   passes with no skips.
