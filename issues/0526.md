# 0526 — `robots.txt` leads with `Allow: /`, which a first-match crawler reads as allowing everything

## Description

`BuildRobotsTxt` (`internal/seo/robots.go`) emits `Allow: /` as its first rule,
a line from `#0020`. Google, Bing, and Python's `urllib.robotparser` resolve
rules by **longest match**, so for them it is harmless: every `Disallow` is more
specific. A crawler using **first-match** semantics, though, matches `Allow: /`
for every path — including `/admin`, `/confirm`, and `/api/me` — before it ever
reaches a `Disallow`.

`#0518`'s reviewer measured this. It is also why reordering `#0518`'s new
`Allow: /api/...` lines would have changed nothing for any crawler. Low priority:
the private routes are gated server-side regardless, and the major engines read
the file correctly.

`Allow: /` is redundant under longest-match too, since allowing everything is the
default.

While here, `docs/seo.md` says every non-allowed `/api` route is "gated,
token-bearing, state-changing, or a webhook". `/api/list-stats` and
`/api/crt-session` are none of those: they are public, read-only, and disallowed
because they only feed Home's `aria-hidden` canvas. `robots.go`'s comment gets
this right; the doc does not.

## Acceptance criteria

1. `Allow: /` is removed from `BuildRobotsTxt`, or moved after every `Disallow`.
   Record which and why.
2. `#0020`'s robots test assertion that requires `Allow: /` is updated to match,
   and still asserts every private namespace is disallowed.
3. The three `#0518` `Allow: /api/...` lines still grant access under
   longest-match — verify with a real parser such as Python's
   `urllib.robotparser`, not by reading.
4. `docs/seo.md`'s description of the disallowed `/api` routes is corrected to
   include `/api/list-stats` and `/api/crt-session` accurately.
5. `ISSUE=NNNN scripts/check.sh go ./internal/seo/... ./internal/handlers/...`
   passes with no skips.
