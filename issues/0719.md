**1. Imager (`pi-imager-setup`)**

```ts
export type SettingId = 'hostname' | 'user' | 'wifi' | 'locale' | 'ssh';
export interface ImagerSetting { id: SettingId; label: string; detail: string }
export const IMAGER_SETTINGS: ImagerSetting[];   // in this order:
//  hostname: 'Hostname'                  'the name it answers to, like mypi.local'
//  user:     'Username and password'     'there is no default pi user any more'
//  wifi:     'Wireless LAN'              'network name, password and WiFi country'
//  locale:   'Locale settings'           'time zone and keyboard layout'
//  ssh:      'Enable SSH'                'so you can log in over the network'
export type SshAuth = 'password' | 'key';
export interface ImagerChoice { on: Record<SettingId, boolean>; sshAuth: SshAuth; hostname: string }
export const DEFAULT_CHOICE: ImagerChoice;       // all on, 'password', hostname 'mypi'
export const DEMO_USER = 'maker';
export function isValidHostname(name: string): boolean; // 1–63 chars, a–z A–Z 0–9 and '-', not starting or ending with '-'
export function hostFor(c: ImagerChoice): string;       // `${hostname}.local` when on and valid, else 'raspberrypi.local'
export type BootTone = 'good' | 'meh' | 'bad';
export interface FirstBoot {
  tone: BootTone;
  joins: boolean;          // on the network at all
  canLogIn: boolean;
  title: string;           // headline, used as the demo's <h3>
  problems: string[];      // one line per setting that is off, in IMAGER_SETTINGS order
  terminal: string[];      // what the laptop shows (commands prefixed '$ ')
}
export function firstBoot(c: ImagerChoice): FirstBoot;
```

`firstBoot` precedence (the headline comes from the first that applies; `problems` lists every off setting):

1. wifi off → tone `bad`, joins false, title `Never joins the network`; terminal `$ ping <host>` then `ping: cannot resolve <host>: Unknown host`. Problem line: the Pi has no WiFi details, so it never joins (a Pi 4 with an Ethernet cable plugged in would; a Zero 2W has no Ethernet port).
2. ssh off → tone `bad`, joins true, title `On the network, but it refuses connections`; terminal `$ ping <host>` / `64 bytes from <host>: icmp_seq=0 …` (one reply line is enough), `$ ssh maker@<host>` / `ssh: connect to host <host> port 22: Connection refused`.
3. user off → tone `bad`, joins true, title `On the network, but there is no one to log in as`; terminal the ping reply, then a plain line `(no account to log in with)` rather than a quoted ssh error (see Assumptions). Problem line: it boots to a set-up prompt on its HDMI screen asking for a new user, and nobody is looking at that screen.
4. otherwise tone `good`, canLogIn true, title `Ready: log in over SSH`; terminal `$ ssh maker@<host>` then `maker@<host>'s password:` for `password`, or straight to `maker@mypi:~ $` for `key`.

Then notes that do not change the headline (and make tone `meh` only if it was `good`): hostname off → it answers to raspberrypi.local, fine for one Pi but two on one network clash; locale off → the clock is set to UTC and the keyboard layout is British (Assumption). `ssh` with `key` adds nothing to problems; the demo shows the key command (below).

```ts
export const ROUTERS: RouterSetup[];
//  one-name: 'One name for both bands'  networks [{ssid:'Home', bands:['2.4','5']}]
//  split:    'Separate 2.4 and 5 GHz names' [{ssid:'Home',bands:['2.4']},{ssid:'Home-5G',bands:['5']}]
//  only-24:  '2.4 GHz only'               [{ssid:'Home',bands:['2.4']}]
//  only-5:   '5 GHz only'                 [{ssid:'Home',bands:['5']}]
//  hotspot:  'Phone hotspot, 2.4 GHz'     [{ssid:'Phone',bands:['2.4']}]
export const FREQ_MHZ: Record<Band, number>;   // { '2.4': 2437 (channel 6), '5': 5180 (channel 36) }
export interface JoinOutcome {
  joins: boolean;
  band: Band | null;
  tone: 'good' | 'meh' | 'bad';
  title: string;
  reason: string;
  check: string[];   // '$ iwgetid -r', ssid, '$ iw dev wlan0 link', 'Connected to … (on wlan0)', '\tSSID: …', '\tfreq: 2437' — empty when not joined
}
export function joinOutcome(board: BoardId, router: RouterId, typed?: string): JoinOutcome;
```

Rules: the Pi joins the network whose ssid equals `typed` (default: the router's first network). If none of that network's bands is one the board hears → `joins:false`, tone `bad`, title `Never appears`, reason naming the board and band (for example: The Zero 2 W only has 2.4 GHz WiFi. It can’t see Home-5G at all, so there is no error, just no Pi). Otherwise it joins on 5 GHz when both the board and the network have it, else 2.4. `one-name` + a dual-band board → tone `meh`, title `Joins, usually on 5 GHz`, reason mentions band steering can cause odd drops; `one-name` + a 2.4-only board → tone `good` on 2.4. `hotspot` → good, reason: handy for first setup, then add the home network later. `typed` that is not one of the router's ssids is treated as the first network (the demo only offers real names).

### `TOPIC_BODIES` entries (draft text; keep the facts, polish the prose)

`pi-imager-setup` (demo `PiImagerDemo`) — tryIt: Everything starts switched on. Turn settings off one at a time and see what the first boot looks like from your laptop. Ideas:
1. `Do it before the first boot` — In Raspberry Pi Imager, choose the board, the OS and the SD card, then edit the OS customisation settings when it asks. They are written to the card and applied the first time the Pi starts. With no keyboard or screen, this is your only chance to tell the Pi anything.
2. `There is no default user` — Since April 2022, Raspberry Pi OS has no built-in pi user with the password raspberry. If you don’t set a username and password, the Pi waits for you to create one on a screen you don’t have.
3. `WiFi and SSH, or no way in` — Without WiFi details it never joins your network. Without SSH it joins but refuses connections. Give the first boot a few minutes, since it sets itself up and restarts once, then connect with ssh and the hostname you chose, plus .local. A public key means no password to type.
Takeaway: Set the hostname, a user, WiFi and SSH in Imager before you flash. Then ssh in to yourname.local.

`pi-wifi-2-4ghz` (demo `PiWifiBandDemo`) — tryIt: Pick how your router is set up and which Pi you have, and see whether it joins. Then try the Zero 2 W on a 5 GHz-only network. Ideas:
1. `Some Pis only hear 2.4 GHz` — The Pi Zero W, Zero 2 W and Pi 3 B only have 2.4 GHz WiFi. The Pi 3 B+, Pi 4 and Pi 5 do both 2.4 and 5 GHz. A 5 GHz-only network is invisible to a Zero 2 W, and headless there is no error message: the Pi just never shows up.
2. `One name for both bands usually works` — Most home routers broadcast the same name on both bands, and a 2.4 GHz Pi simply joins on 2.4. Band steering, where the router pushes devices between bands, can cause odd drops; if it does, give the 2.4 GHz band its own name. Set the right WiFi country too, or some channels are blocked.
3. `The fix, and how to check` — In Imager, enter a network the Pi can hear: turn on or split out the router’s 2.4 GHz band, or set a phone hotspot to 2.4 GHz just for first setup. Once connected, iwgetid -r shows the network name and iw dev wlan0 link shows the frequency: 24xx MHz is 2.4 GHz.
Takeaway: A Zero 2 W needs 2.4 GHz. If the Pi never appears, check the band before the password.

`pi-bookworm-changes` (demo `PiBookwormDemo`) — tryIt: Pick a step from an old tutorial. See what it does on Bookworm, and what to type instead. Ideas:
1. `Boot files moved` — config.txt and cmdline.txt now live in /boot/firmware/. The old /boot/config.txt is only a note pointing there, so edits to it do nothing.
2. `NetworkManager runs the network` — WiFi and IP addresses are handled by NetworkManager. Editing wpa_supplicant.conf or dhcpcd.conf no longer does anything. Use nmcli, or sudo nmtui for a menu.
3. `pip needs a virtual environment` — pip install outside a virtual environment stops with externally-managed-environment. Make one with python3 -m venv, or install the Debian package, python3- followed by the library name, with apt.
4. `The desktop is Wayland` — On a Pi 4 and Pi 5 the desktop runs Wayland, so tools that talk to X11, like xset and xdotool, may do nothing. Look for the setting in raspi-config first.
Takeaway: On Bookworm, look in /boot/firmware, use nmcli for the network, and a venv for pip.
