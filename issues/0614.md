## Description

Once listings have a type (`#0613`), the public site needs one place to show
them all. Add `/events` as the listing page and `/events/{slug}` as the canonical
detail page for every type, with the type shown on each card and detail page and
a filter by type. Because types are data, adding one must need no code change, so
there is one page with a filter, not one page per type.

The existing `/workshops` URLs are already in sent email, flyers, short links and
published social posts, so they must keep working through permanent redirects.

## Root cause

The public site had one listing page, named and worded for workshops, so a listing of any other type (`#0613`) had no page that described it correctly, and no server-rendered output carried a type at all.

## Fix

Followed the plan. `/events` and `/events/{slug}` replace the old routes on both sides of the route table; `MountLegacyWorkshopRedirects` answers the old paths with unconditional 301s, and `legacyRedirectTarget` does the same in the SPA. The type name reaches cards, detail pages, fallbacks, the social card and JSON-LD; `sort_order` reaches the wire so the filter follows the admin's order. Event type writes now invalidate the shared `*seo.Site`.

## Plan

Written 2026-11-04 against `086e7abe`. No migration: everything reads what `#0613`'s `000045` already added.

### Decisions already made, so the implementer does not have to

- **Identifiers keep their names** (same call as `#0613`, and `#0615` excludes them): route names `workshops` and `workshop-detail`, `WORKSHOP_DETAIL`, `WorkshopDetailSlug`, `workshopDetailPattern`, `pageWorkshopsIndex`, `WorkshopsIndex.svelte`, `WorkshopDetail.svelte`, `WorkshopCard.svelte`, `/api/workshops`, `/admin/workshops`. Only public paths, user-visible copy, and comments describing a public path change.
- **Redirects are unconditional and do no store lookup.** `/workshops/{slug}` 301s for any slug, then `/events/{slug}` answers 200 or 404 as usual (`#0522`). A lookup would make the redirect an existence oracle for drafts.
- **Index query:** `type=workshop` goes first and the incoming raw query is appended unchanged, so `/workshops?utm_source=x` becomes `/events?type=workshop&utm_source=x`. `URLSearchParams.get` returns the first value, so a stray `type=` in an old link cannot override it.
- **`/workshops/{slug}/og.png` keeps serving** through the same handler, and `/events/{slug}/og.png` is added beside it. New `og:image` values use the new path. The handler and cache key are shared.
- **The filter is client-side only.** The server render is cached per path and never sees the query, so the fallback at `/events?type=x` lists everything until the SPA mounts, and its canonical is `/events`. The fallback renders no filter links, because without JavaScript they would not filter. No filtered URL goes in the sitemap.
- **Filter options come from the listings themselves** (`upcoming` + `past`), so unused types never appear, and a disabled type with a visible listing still does: the public list ignores `enabled`, and `TestPublicWorkshops_DisabledTypeStaysVisible` already pins that.
- **Filter order honours the admin's order.** `event_type` on the wire gains `sort_order`, so reordering in Event types has a public effect. Ties sort by name.
- **Filter controls are plain links** (`<a href="/events?type=hack-night">`, with "All" as `/events`), inside `<nav aria-label="Filter by type">`, the selected one carrying `aria-current="true"`. `initRouter`'s click interception already handles them, `lastPathSearch` already treats a query change as a route change, and the view stays mounted, so there is no refetch and no router change. A click moves focus to the `<h1>` like any other link navigation (`App.svelte`), which is accepted. The filter sits at the top of the page, so the scroll reset costs nothing.
- **Unknown type:** the type filter still shows, Upcoming and Past are hidden, and the page says "No events of that type." with a "See all events" link. The URL value is not echoed. Empty `?type=` means All. Matching is exact.
- **Copy is generic, not type-derived:** "event". The type shows only as its name.
- **`/workshops` hardcodes the slug `workshop`.** Slugs are immutable. If an admin ever deletes that type, the old URL lands on the clear empty state, which is acceptable.
- **JSON-LD stays `@type: Event`**, which is correct for every type. The type name goes in schema.org's `keywords`, omitted when empty.

## Obstacles

Scanned `docs/obstacles.md` and checked on 2026-11-04.

- **Nothing needs clearing or approval before dispatch.** `tart`, `tart-lease`, `tart-golden`, `psql`, `migrate` and `npm` are all on `PATH`. No migration, so the test template stays valid, and no credentials are involved: mail is verified by golden tests and SES is not used.
- **Browser checks only in the Tart VM** (`AGENTS.md` §8): `scripts/check.sh browser-nav` does that. It needs a free lease. If none is free, wait; do not fall back to the host. Never use `dev.sh` with a host browser to look at the filter.
- **Shared resources:** `scripts/check.sh guards` binds `:5173` for about 48 seconds, and `browser-nav` runs `npm run build` on its own temp copy. Do not run a production build in the shared checkout: it overwrites the tracked `web/dist/index.html` (`AGENTS.md` §8b).
- **`STORAGE=json` has no workshops**, so `/events` shows its error state under plain `dev.sh`. That is existing behaviour, not a defect. Listing behaviour is proved by the Postgres-backed tests.
- **Bulk rewrite:** the `perl` above names files; skip any that `git status --porcelain` shows dirty (`AGENTS.md` §8a). `.opencode/` is untracked and not this issue's.
- **Citation and copy guards:** a repo-wide guard run is part of the full tier. Edits to Go comments can trip `internal/handlers`, and the copy constants must match the Svelte text exactly, or `internal/seo` fails.
- **Production reads were not available to this plan.** A read-only `ssh photon` query was refused by the session's permission check, so the plan assumes outreach link rows may exist in production and does not depend on their count. The public site was read with `curl`: `/workshops/hack-night` answers 200, its `og:image` is the `/media/` cover, and `/api/workshops` has no `event_type` yet. Implementation needs no production access.
