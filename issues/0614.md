# 0614 — The public site lists only workshops, so a Hack Night has nowhere to appear as what it is

## Description

Once listings have a type (`#0613`), the public site needs one place to show
them all. Add `/events` as the listing page and `/events/{slug}` as the canonical
detail page for every type, with the type shown on each card and detail page and
a filter by type. Because types are data, adding one must need no code change, so
there is one page with a filter, not one page per type.

The existing `/workshops` URLs are already in sent email, flyers, short links and
published social posts, so they must keep working through permanent redirects.

## Acceptance criteria

- [ ] `/events` lists upcoming and past listings of every type, with the same
      visibility rules as today (published and canceled are visible, drafts are
      not). Each card shows its type name.
- [ ] A type filter appears on `/events`, offering only types that have at least
      one visible listing, so an unused type is not an empty choice. The selection
      lives in the URL (`/events?type=hack-night`), so it survives reload and can
      be shared. An unknown type shows a clear empty state rather than an error.
- [ ] A listing of a disabled type stays visible, and its type stays usable as a
      filter while such a listing exists.
- [ ] `/events/{slug}` renders every type and shows its type name. Copy that says
      "workshop" on these pages is generic or follows the type.
- [ ] `GET /workshops` 301s to `/events?type=workshop`, and `GET /workshops/{slug}`
      301s to `/events/{slug}`, including a request for a hard-loaded page and
      client-side navigation to the old path. The query string is preserved, and
      a short link or flyer pointing at an old URL lands on the right page.
- [ ] `/workshops/{slug}/og.png` keeps serving, or redirects, so social previews
      of already-published posts do not break.
- [ ] The header nav shows **Events** in place of Workshops. Both the SPA and the
      server-rendered fallback (`internal/seo`) are updated.
- [ ] The sitemap lists `/events` and `/events/{slug}` URLs and no longer lists
      the old ones. Canonical tags, Open Graph tags, structured data and social
      cards use the new URLs and describe the listing's type correctly.
- [ ] URLs generated for new email announcements and outreach posts point at
      `/events/{slug}`.
- [ ] The homepage's next-up section shows upcoming listings of every type, with
      type names. Its headline is unchanged here; `#0615` covers remaining copy.

## Notes

- Client-side navigation changes require `scripts/check.sh browser-nav` (see
  "What only the full tier checks" in `issues/Issues.md`). Browser checks run only
  in the Tart VM, never on the host (`AGENTS.md` §8).
- Changing fallback copy or nav reaches `internal/seo`'s guards, so include that
  package in the scoped run (`AGENTS.md` §5's table).
- `/api/workshops` may keep its name; no public URL promises otherwise.
