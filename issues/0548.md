## Description

Flyers go on the same neighborhood bulletin boards every time. Save them once
— name, short code, address, notes, active — so each flyer run can make one
tracked link per location. Design doc "Flyers → Locations"; mockup artboard 7
(https://claude.ai/artifact/4Ckwb6QmWYyfYyAEszAKa2).

## Acceptance criteria

- [x] Migration for `outreach_locations`: `name`, `code` (unique, **short**: lowercase letters, digits and dashes, 2–16 chars), `address`, `notes`, `active`, timestamps. A code is immutable once any flyer link uses it.
- [x] Admin CRUD endpoints with audit rows; deactivate rather than delete when a location has links.
- [x] UI: Outreach tab → **Locations** sub-view (list with name/address/code/notes/status, add/edit form, code auto-suggested from the name). Validation logic in a tested `web/src/lib` module.
- [x] Verified with `ISSUE=0548 scripts/check.sh`.

### Decisions (so the implementer does not have to make them)

1. **Code immutability is a column, not a cross-table query.** `#0549`'s
   `outreach_flyer_links` does not exist yet, so a store check that queries it
   cannot be written today, and one that probes `to_regclass(...)` is fragile.
   Instead `outreach_locations` carries `code_locked_at TIMESTAMPTZ` — "the
   first time any flyer link used this location". This issue defines
   `Store.MarkLocationUsed(ctx, q, id)`; **`#0549` calls it inside the same
   transaction that inserts an `outreach_flyer_links` row**, and declares its
   FK as `location_id BIGINT NOT NULL REFERENCES outreach_locations(id) ON
   DELETE RESTRICT`. Every rule below ("code immutable once used", "deactivate
   rather than delete when it has links") reads `code_locked_at IS NOT NULL`,
   and works unchanged before and after `#0549`. The `RESTRICT` FK is the
   backstop: a delete that slips past the column still fails with SQLSTATE
   `23503`, which the store also maps to `ErrLocationInUse`.
2. **Code format, enforced in three places with the same rule:** 2–16
   characters, lowercase ASCII letters, digits and single interior dashes —
   regex `^[a-z0-9]+(-[a-z0-9]+)*$` plus the length bound. No leading,
   trailing, or doubled dash (they make ugly `utm_content` values and the
   suggester never produces them). DB CHECK, Go `outreach.ValidCode`, TS
   `validateCode`. No shared JSON fixture: a Go test reading a file outside
   its package would add `internal/outreach` to CLAUDE.md §5's repo-wide guard
   table (and trip `TestClaudeMDRepoWideGuardPackageSetParity`). Both test
   files carry the same case list by hand instead.
3. **Routes live under `/admin/outreach-locations`**, not
   `/admin/outreach/locations`, following `#0544`'s `/admin/outreach-posts`
   choice: `/admin/outreach/locations/{id}` and `#0544`'s
   `/admin/outreach/{id}/posts` are both four segments with a wildcard in
   different positions, and Go 1.22's mux panics at registration on two
   equally specific overlapping patterns with the same method.
4. **Same handler, same store.** Location methods go on `outreach.Store`
   (new file `internal/outreach/locations.go`) and the handler methods on
   `AdminOutreachHandler` (new file `internal/handlers/admin_outreach_locations.go`),
   through a **second narrow interface** `outreachLocationStore` added as a new
   constructor parameter. That avoids a new `mountAndServe` parameter and
   re-editing its seven test call sites; only `NewAdminOutreachHandler`'s
   callers change (main.go, `admin_wiring_test.go`, `admin_outreach_test.go`).
5. **Sub-view routing is a query parameter**: `#/outreach` (workshops list,
   `#0544`'s view) and `#/outreach?view=locations`. `parseAdminHash` already
   exposes `query` and `Admin.svelte` already reads it (campaign filter), so no
   `AdminRoute` shape change and no new not-found cases. `#0546`'s Results can
   take `view=results` the same way.
6. **Delete is allowed only while unused.** A used location is deactivated
   (`active=false`), never deleted; the DELETE endpoint returns 409 with the
   message `location has flyer links; deactivate it instead`. Inactive
   locations stay listed (status "Inactive") and can be reactivated.
7. **Code uniqueness is case-free by construction** (the CHECK forbids
   uppercase), so a plain `UNIQUE` suffices. Names are not unique.

### Step 2 — store (`internal/outreach/locations.go`)

```go
type Location struct {
    ID           int64
    Name, Code   string
    Address      string
    Notes        string
    Active       bool
    CodeLockedAt *time.Time
    CreatedAt    time.Time
    UpdatedAt    *time.Time
}
type LocationInput struct{ Name, Code, Address, Notes string; Active bool }
type LocationPatch struct{ Name, Code, Address, Notes *string; Active *bool } // nil = unchanged

var (
    ErrLocationNotFound = errors.New("outreach: location not found")
    ErrCodeTaken        = errors.New("outreach: location code already in use")
    ErrCodeLocked       = errors.New("outreach: location code is locked by flyer links")
    ErrLocationInUse    = errors.New("outreach: location has flyer links")
)

const CodeMinLen, CodeMaxLen = 2, 16
func ValidCode(s string) bool  // regex + length, decision 2

// Execer is satisfied by *pgxpool.Pool and pgx.Tx, so #0549 can pass its tx.
type Execer interface {
    Exec(ctx context.Context, sql string, args ...any) (pgconn.CommandTag, error)
}
```

Methods on `*Store`:
- `ListLocations(ctx) ([]Location, error)` — `ORDER BY active DESC, lower(name), id`.
- `GetLocation(ctx, id)` → `ErrLocationNotFound`.
- `CreateLocation(ctx, in LocationInput) (Location, error)` — `23505` →
  `ErrCodeTaken` (reuse the package's unique-violation helper; `#0544`'s
  store should already have one, else copy the 4-line `isUniqueViolation`
  from `internal/crt/store.go`).
- `UpdateLocation(ctx, id, p LocationPatch) (Location, error)` — one
  statement: `UPDATE outreach_locations SET name = COALESCE($2, name), code =
  COALESCE($3, code), … , updated_at = now() WHERE id = $1 AND
  (code_locked_at IS NULL OR $3::text IS NULL OR $3 = code) RETURNING …`.
  Zero rows → re-select: missing → `ErrLocationNotFound`, else
  `ErrCodeLocked`. `23505` → `ErrCodeTaken`. A patch that sets the code to
  its current value on a locked row succeeds (the SPA resubmits the whole form).
- `DeleteLocation(ctx, id) error` — `DELETE … WHERE id = $1 AND
  code_locked_at IS NULL`; zero rows → re-select → `ErrLocationNotFound` or
  `ErrLocationInUse`; `23503` (FK, after `#0549`) → `ErrLocationInUse`.
- `MarkLocationUsed(ctx, q Execer, id int64) error` — `UPDATE
  outreach_locations SET code_locked_at = COALESCE(code_locked_at, now())
  WHERE id = $1`; zero rows → `ErrLocationNotFound`. Idempotent; keeps the
  first timestamp. Doc comment says `#0549` calls it in its link-insert
  transaction. Nothing in this issue calls it outside tests.

### Step 3 — audit actions (`internal/audit/actions.go`)

Beside `#0544`'s outreach block, each with a doc comment in the file's style:

```
ActionOutreachLocationCreated = "outreach_location.created"
ActionOutreachLocationUpdated = "outreach_location.updated"
ActionOutreachLocationDeleted = "outreach_location.deleted"
TargetOutreachLocation        = "outreach_location"
```

Metadata as an **inline `map[string]any{…}` literal** at each `audit.Entry`
site: created → `code`, `name`, `active`; updated → `code` (after),
`changed` (sorted `[]string` of field names actually changed: `name`,
`code`, `address`, `notes`, `active`), plus `previous_code` only when the
code changed, and `active`; deleted → `code`, `name`. No address/notes
text, no key containing `email`/`from`/`sender`/`recipient`/`addr` (the
email-metadata guard — note `address` would trip `addr`; that is why the
changed-field list carries the string `"address"` as a **value**, never as a
key). An update that changes nothing returns 200 and writes no audit row.
Activation changes are `updated` with `"active"` in `changed` — no separate
deactivate action.

after `#0544`'s `store` parameter. Routes, registered in `#0544`'s
`if adminOutreachH != nil` block in `adminRoutes` (never `mux.Handle`
directly — `admin_routes_ast_test.go`):

| Method | Path | Behaviour |
|---|---|---|
| GET | `/admin/outreach-locations` | 200 `{"locations": [view…]}` |
| POST | `/admin/outreach-locations` | body `{name, code, address?, notes?, active?}` (active defaults true); 400 invalid; 409 `ErrCodeTaken` (`{"error":"code already in use"}`); 201 view + audit |
| PATCH | `/admin/outreach-locations/{id}` | any subset of the same fields; 400 invalid / empty body; 404; 409 `ErrCodeTaken` or `ErrCodeLocked` (`{"error":"code is locked: flyer links already use it"}`); 200 view (+ audit if anything changed — compute `changed` by comparing the pre-update `GetLocation` with the result) |
| DELETE | `/admin/outreach-locations/{id}` | 404; 409 `ErrLocationInUse` (`{"error":"location has flyer links; deactivate it instead"}`); 204 + audit (read the row first for its code/name) |

Validation (server-side, authoritative; trim name/address/notes first):
name 1–100 characters (runes); code `outreach.ValidCode`, **not** trimmed or
lowercased on the server — the SPA normalises, the server rejects (400
`{"error":"code must be 2–16 lowercase letters, digits or dashes"}`);
address ≤ 300 runes; notes ≤ 2000 runes. Bad `{id}` → 404, same as the
neighbouring handlers. Use the existing JSON decode/error helpers the other
admin handlers use.

View (snake_case, RFC 3339 UTC):
`{id, name, code, address, notes, active, code_locked, code_locked_at, created_at, updated_at}`
— `code_locked` is `code_locked_at != nil`, so the SPA never reasons about
timestamps.

`web/src/lib/outreachLocations.ts` (pure, no DOM):
- `CODE_MIN = 2`, `CODE_MAX = 16`, `CODE_PATTERN = /^[a-z0-9]+(-[a-z0-9]+)*$/`,
  `NAME_MAX = 100`, `ADDRESS_MAX = 300`, `NOTES_MAX = 2000`.
- `validateCode(code): string | null` — null when valid; distinct messages
  for empty, too short, too long, bad characters/dash placement.
- `normalizeCodeInput(raw): string` — lowercase, spaces/underscores → `-`
  (applied as the admin types, so "Mission Branch" typed into the code field
  becomes `mission-branch`); does not truncate (validation reports length).
- `suggestCode(name): string` — `name.normalize('NFKD')`, strip combining
  marks (`/\p{M}/gu`), lowercase, `&` → `and`, every run of non-`[a-z0-9]` →
  `-`, trim dashes; if longer than 16, cut at the **last dash at or before
  16** when that leaves ≥ 2 characters, else hard-cut at 16; trim trailing
  dash; result shorter than 2 → `''`. Examples to test: `"Mission Public
  Library"` → `mission-public` (cut at word boundary), `"Café Réveille"` →
  `cafe-reveille`, `"Bernal Heights Neighborhood Center"` → `bernal-heights`,
  `"A"` → `''`, `"!!!"` → `''`, `"Noe Valley — Martha & Bros"` → `noe-valley`
  (word-boundary cut of `noe-valley-martha-and-bros`), `"Supercalifragilisticexpialidocious"`
  → 16-char hard cut.
- `uniqueCode(base, taken: ReadonlySet<string>): string` — `base` if free,
  else `base-2`, `base-3`, … with `base` shortened (dash-trimmed) so the
  result stays ≤ 16. The form uses it so the suggestion never collides with
  an existing location (server still enforces with 409).
- `validateLocationForm(form: {name, code, address, notes}): Partial<Record<'name'|'code'|'address'|'notes', string>>`
  and `formIsValid(errors)`.
- `locationPatch(original: OutreachLocation, form): Partial<...> | null` —
  only changed fields; null when nothing changed; never includes `code` when
  `original.code_locked` and unchanged.
- `locationStatusLabel(loc)` → `Active` / `Inactive`; `canDelete(loc)` →
  `!loc.code_locked`; `canEditCode(loc | null)` → creating, or not locked.
