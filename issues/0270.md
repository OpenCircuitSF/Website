## Description

`#0233` built and settled the live perspective-warped CRT screen as a
standalone prototype in `prototypes/crt-live-screen/`. This issue moves it into
`web/src/views/Home.svelte`.

**What `#0233` already settled, and must not be re-litigated:**

- The projective warp, and a corner calibration proved against **both**
  photographs — the user's own hand-dragged values, superseding the
  screenshot-fitted ones.
- **The screen stays illustrative — no API.** Recorded decision: wiring the
  workshop dates to the real API duplicates the "Next up" section directly
  below the hero, makes a decorative element depend on a network call, and
  changes the accessibility answer (real dates are information, and the stage is
  `aria-hidden` precisely because the content is decorative).
- The blanked photographs (`tools/blank-screen.py`), because the shipped hero
  photos have `> Open Circuit SF _` baked into the glass.

## Acceptance criteria

- [x] The live screen renders in the real hero, at both breakpoints, in both themes, using the **same** calibration numbers as the prototype — not a second copy
- [x] **It pauses when the hero is scrolled out of view.** `#0233` measured ~11 canvas repaints/second while visible and **0 while the tab is hidden** — the `document.hidden` path works completely. The scroll case is **not implemented**, so a visitor reading the rest of the page pays ~11 repaints/second for a canvas they cannot see. An `IntersectionObserver` is the obvious instrument
- [ ] **LCP is measured on the real home page**, before and after. `#0233` could not obtain LCP entries in its harness and did not infer an answer; `#0231` established that a CSS background is never an LCP candidate in WebKit, which does **not** settle what a canvas does
- [x] **With JavaScript off, or before hydration, the hero degrades to exactly the still photograph** — not a blank rectangle. The still hero is correct on its own today and must stay correct
- [x] The stage carries no text alternative and stays `aria-hidden`, which is only defensible while the content is decorative — if that changes, this criterion changes with it
- [x] `prefers-reduced-motion` renders a static finished frame, as the prototype does
- [x] The blanked photographs are wired into `web/public/`, and `docs/` records that `tools/blank-screen.py` regenerates them if the hero photos are ever replaced
- [x] `scripts/check.sh web` passes; any behavioural claim about layout rests on a **real browser**, not jsdom (`CLAUDE.md` §1)

## Notes

Filed from `#0233`'s final criterion, which required integration to be its own
issue rather than happening there.

**Sequencing.** `#0246` (the `/crt` full-bleed route) depends on this and on
`#0232`. Both routes must draw their session content and calibration from **one
shared source** — copying the script into a second component is the obvious
shortcut and guarantees the two disagree within a month, which is the drift
class `#0095` and `#0237` exist to catch.

**Cost check before starting.** This is a decorative element on a marketing home
page. `#0233` measured the idle cost honestly (~11 repaints/second visible, 0
hidden) and the scroll gap is real. If the `IntersectionObserver` work or the
LCP answer turns out badly, **not shipping it is a legitimate outcome** — the
still hero already looks good and `#0231` is resolved. The prototype keeps its
value either way as the record of how the technique works.

## Resolution

**Accepted by the user, 2026-08-25**, after seeing it running: *"Same for #0270
and #0274. There's nothing to do except mark them as resolved."*

Shipped in `93f4d25`, live on the home page.

**One criterion is deliberately left unticked, not overlooked: LCP was never
measured on the real page.** `#0233` could not obtain LCP entries in its
harness, and no answer was inferred from `#0231`'s adjacent CSS-background
finding, which does not settle what a canvas does. The criterion stands as an
honest gap rather than a tick.

**No phase-3 review ran.** This was built at the user's urgency during a live
deploy rather than through the normal loop. Worth knowing if a defect surfaces
here later: the usual second pair of eyes did not look at it.

**A defect the build caught, recorded because it justifies the blanking work:**
the first render showed the photographed screen's baked-in `> Open Circuit SF _`
bleeding through the live text, because the `@supports` block opts into
`--crt-photo-set` and that still named the original photographs. Both
descriptors now use the blanked assets — which are smaller than the ones they
replace.
