## Description

`PRD.md` §6.10.1's approved-deviation paragraph reads:

> recorded in a write-once `subscribers.invite_resent_at` (§6.2, migration
> `000026`; `CHECK (invite_resent_at IS NULL OR invited_at IS NOT NULL)`)

That is the **same side-by-side placement** of "write-once" and the constraint
text which made `migrations/000026`'s heading misleading, and which `#0371`
corrected in §6.2. It is now **the last place in the tree** where the two sit
adjacent without saying which enforces which.

**It is milder than the cases already fixed**, and the issue should be sized
accordingly:

- the parenthetical reads as a **citation list**, not an attribution;
- it points directly at §6.2, which now states explicitly that the CHECK is
  **not** the enforcer — so a reader following the reference lands on the
  correct statement.

It was out of scope for `#0371`, which named §6.2's schema comment and
`AdminResendInvitation`'s doc comment as the homes for the correction. It is
**not a defect in the code**: write-once comes from `AdminResendInvitation`'s
guard 5 under `SELECT … FOR UPDATE`, confirmed independently **three times** now
(`#0312`'s review, `#0371`'s implementation, `#0371`'s review) — exactly one
production write site, at `internal/subscribers/pending.go:407`, inside the same
transaction as the guard, with `defer tx.Rollback()` meaning a refusal commits
nothing.

**Is "by code" specific enough (criterion 1)?** Yes, but it is one word short of
its best form. Criterion 1 is a disjunction — name guard 5 **or** reword so it
cannot be read as attributing write-once to the `CHECK` — and the second branch
is fully discharged: "write-once by code, **not by the `CHECK`** … which
enforces only …" leaves no reading in which the constraint is the enforcer, and
that ambiguity was the entire defect. Declining to write "guard 5" was also the
right instinct: a numbered position in an enumeration drifts the moment a guard
is inserted above it, which is the same family of hazard `#0352` settled against.
But the stable identifier that carries the specificity was available and unused —
`AdminResendInvitation` is a symbol name, cannot drift, and costs two words. I
did not require the change: the parenthetical cites §6.2 in the same breath, and
§6.2 names `AdminResendInvitation`'s guard 5 and the `FOR UPDATE` explicitly, so
a reader following the reference lands on the specific enforcer one hop away.
Recorded as a preference, not a defect.
