## Resolution notes

## Description

Found while planning `#0638`. Outreach handler tests seed their workshop on 2026-12-05 while the handlers read the real clock. `#0638` pins the clock for the hand-links tests (a `beforeEvent()` helper) and moves the SPA fixture to 2099, but other tests in the outreach suite may also quietly assume today is before 2026-12-05, and will fail on or after that date for no code reason.

## Plan

Planned 2026-11-17 (Opus · medium). Measured, not guessed: the whole Go suite and the whole web suite were run in a throwaway worktree at `4bb232d2` with the clock moved forward, against a private database (dropped afterward).

**How the clock was moved** (rerun it the same way if needed):

- Go: `go test -overlay overlay.json`, where the overlay replaces `$(go env GOROOT)/src/time/time.go` with a copy whose `Now()` adds a fixed number of seconds. Nothing in the repo changes.
- Postgres: in the private database only, `fake.now()` returns `pg_catalog.now() + interval 'N hours'`, `ALTER DATABASE … SET search_path = fake, public, pg_catalog`, and every column default using `now()` is pointed at `fake.now()`. Without this, Go and Postgres disagree about the time, and about 25 tests (guideposts, outbox, subscribers, mailing, sesnotify) fail for that reason alone. Use hours, not days: a `days` interval keeps local wall time across a DST change, so the two clocks end up an hour apart.
- Web: a vitest config adding a `setupFiles` entry that replaces `globalThis.Date` with a subclass whose `now()` and no-argument constructor add the offset.

Shifts tried: +20 days (2026-12-07), +60, +200 (June 2027, summer time), +410 (2028-01-01), +800 and +1500 (late 2030).

**Results.** Baseline (no shift): Go and web both clean.

| Test (all in `internal/handlers`) | Fails from | Why |

- **Web: none.** All 146 files and 5604 tests pass at every shift, including summer time.
- **Also found while measuring (not a date bug):** `TestV1OutreachResults_ForEvent` and `TestV1OutreachResults_Summary` fail on the **second** run against the same database, at any date. `seedPacificMention` uses a fixed `remote_id` (`at://mention-0708`, `at://mention-0708-summary`), `InsertMention` is `ON CONFLICT (remote_id) DO NOTHING`, and nothing deletes the row. On a rerun the new mention is never inserted, and the old one has `post_id` NULL because its post was deleted. `scripts/check.sh` makes a fresh database each run, which hides this. Reproduced at the real date: run `-run TestV1OutreachResults` twice against one database, and the second run fails. It is fixed here because the fix is one line and it looks exactly like a date failure.
- `internal/db`'s `TestMigration000047DefaultEventTypeSetting` failed under the shifted database at every offset, and also without any shift once `search_path` was changed. It is caused by the measurement setup. Ignore it.

**Fixes** (test files only; checked in the worktree: `internal/handlers` passes at +0, +200, +410 and +1500, and twice in a row against one database):

**`internal/handlers/admin_outreach_links_test.go`**

- `TestAdminOutreachLinks_PrepareAndCreatePostUseTheRow` and `TestAdminOutreachLinks_DraftAll`: add `e.beforeEvent()` right after `e := newOutreachEnv(t, true)`, the same as the other tests in this file (`#0638`). `DraftAll`'s second workshop `w2` is seeded on the same date, so the one pin covers it.

**`internal/handlers/v1_outreach_links_test.go`** (`TestV1OutreachLinks_PrepareIsIdempotent`) and **`internal/handlers/v1_outreach_posts_test.go`** (`TestV1OutreachWrite_UpdatePost`)

- Accept either Pacific offset, as `v1_outreach_test.go` already does at line 124 and as these tests intend (Pacific, not UTC):

      !strings.Contains(string(first), "-08:00") && !strings.Contains(string(first), "-07:00")

  (`b` in place of `first` in the posts test.) Pinning the handler clock would not cover it, because the time in the body comes from Postgres `now()`.

**`internal/handlers/v1_outreach_results_test.go`** (`seedPacificMention`)

- Make the remote ID unique: `RemoteID: fmt.Sprintf("%s-%d", remoteID, testdb.Unique())`, and add the `internal/testdb` import. Also add `t.Cleanup` that deletes that mention by its remote ID, so no stray rows are left behind. Leave the fixed `CreatedAt` (2026-11-10) alone: nothing filters mentions by age, and `assertPacificMention` pins that exact value.

**No guard.** A guard that moves the clock forward means overriding `time.Now` and Postgres `now()`, which is the harness above. That is too heavy for `scripts/check.sh` and is not repo code. The overlay recipe above is the record of how to rerun the check.

This is a problem with the measurement setup, not the code.
