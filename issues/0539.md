## Description

`#0537` relocated tooling scratch into gitignored `.scratch/` and `#0538`
moved the shell harnesses' mutation copies there too. Consequence: any agent
keeping a Go probe under `.scratch/` (e.g. `#0536`'s `shutdown_probe.go`)
makes `check.sh`'s repo-wide `gofmt -l .` name that file, failing **every**
agent's `check.sh go` run on code nobody intends to ship. Observed live
2026-09-14: `gofmt -l` named only `.scratch/0536/shutdown_probe.go` while the
tracked tree was clean.

This is unblocking work — the guard's intent is "tracked Go code is
formatted", and `.scratch/` is by definition not that.

## Acceptance criteria

- [ ] `gofmt -l` in `scripts/check.sh` excludes `.scratch/` (and nothing else changes about the formatting gate)
- [ ] `scripts/check.sh go` is green with an unformatted Go file present under `.scratch/` and still red when a TRACKED file is unformatted (both directions proven, not assumed)
- [ ] check.sh's own self-checks still pass untouched: `scripts/check.sh guards` and the in-file live run/runpipe verification (`#0258`/`#0262`) — the gofmt invocation may be pinned by them; if so, adjust the pin and say so, never weaken it
- [ ] The edit is minimal; `shellcheck scripts/check.sh` and `bash -n` stay clean

## Root cause

`gofmt_check` in `scripts/check.sh` ran `gofmt -l .` unfiltered, so gofmt's
output named any Go file anywhere in the walk — including gitignored
`.scratch/` — and the non-empty output flipped `FAILED` for every agent's run.

## Fix

One line changed: gofmt's output is piped through `grep -v '^\.scratch/'`
before the non-empty check. Measured first that both gofmt listing lines and
parse-error lines start with the path when the walk root is `.`, so the
anchored filter covers both; the anchor (slash after `.scratch`) cannot match
any tracked path. No pin needed adjusting: the FUNCDEF digests pin only
`run`/`runpipe`/`accounting_probe`, `check_guard_test.sh` exercises
`gofmt_check` behaviorally (its isolation sandbox puts the unformatted
`main.go` at the sandbox root, which the filter cannot touch), and the floor
guard's populations scan only `internal/`, `cmd/`, `web/` — never
`.scratch/`.
