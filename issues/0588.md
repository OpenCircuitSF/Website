## Review notes

Opus review, 2026-10-18. Items 1, 2, 4 and the link half of item 3 hold;
approved after the fixes below, made in `4f0dd7a`.

- **Migration `000042`** is a new file, not an edit; its down restores
  `000040`'s exact key list and deletes the row first. Proved on a scratch
  database: an `outreach_channels` row inserts at 42, `down 1` removes it
  and the CHECK refuses the key again, `up` returns to `42|f`. Docs row and
  the `000001`–`000042` range in `AGENTS.md` and `docs/database.md` agree.
- **Validation** is server-side: `NormalizeChannels` refuses empty, a bare
  comma, a trailing empty entry, unknown names and a semicolon list, and
  collapses duplicates, case and spacing. "At least one channel" therefore
  holds on the server, not only in the disabled last checkbox.
- **Design change (reviewer): hiding is limited to drafts.** The implementer
  hid every post on a switched-off channel. That hid a scheduled Bluesky post
  that `PromoteDue` would still send, which is posting unseen, and it hid
  posted posts that are public history (and still block Reset through
  `CanReset`, which counts every post, so the page would refuse a Reset with
  nothing visible to explain it). Now `postVisible` keeps a post whose status
  is scheduled, queued, posted or failed, and `shownChannels` keeps that
  post's channel in the panel and per-workshop results so its card renders
  and can be unscheduled. Counts (`posts_total`, `posts_posted`,
  `posted_channels`) follow the same rule; the overview's client filter was
  dropped so a posted switched-off channel is named.
- **Bug fixed: Schedule all leaked a switched-off channel.** `PlanScheduleAll`
  walks every automatic channel, so with Bluesky off and its drafts filtered
  out, the dry run listed "Bluesky Announce: not drafted". Its skips are now
  filtered by enabled channel.
- **Post now / Schedule** refuse a hidden draft on a switched-off channel
  (409 in `postingGate`); a shown scheduled post stays actionable.
- **Unmark** also refuses any post carrying a `remote_id` (store and handler),
  so a post the site really sent cannot be unmarked after its channel is
  disconnected.
- **Dashboard (#0586)** no longer reports "Not connected: Bluesky" for a
  network switched off in Settings: `GET /admin/outreach` returns
  `enabled_channels` and `outreachAttentionItems` takes it. ShortLinks is
  always reported. TikTok and YouTube have no connection group, so they could
  not nag.
- **Item 4:** the link row said "Put this in your bio" on a hand-posted
  Bluesky or Mastodon card too; it now reads "Link to paste" there and keeps
  the bio wording for Instagram, TikTok and YouTube.
- **Mutation tests**, each restored by sha256: `postVisible` reduced to the
  bare enabled check fails both disabled-channel tests (7 assertions); the
  Schedule all skip filter disabled fails on the Bluesky gap.
- **Verification (reviewer):** `ISSUE=0588R scripts/check.sh go` over
  outreach, serversettings, handlers, cmd/opencircuit and db, all ok, no
  skips, gofmt clean; `ISSUE=0588R scripts/check.sh web`, svelte-check
  clean, 84 files and 4686 tests passed. jsdom only; no browser was run.

**Carve-out:** item 3's downloadable PNG of the flyer face is not built. The
face is HTML and CSS, so a PNG needs a rasteriser that jsdom cannot check.
Acceptable as a follow-up next to batch 9's Print action (orchestrator to
file).

**Follow-ups (not blocking):** (a) the links table (`linksView`) still lists
only enabled channels, so a posted post on a switched-off channel has no
links row; (b) the outreach list's `counts` (landing chips, editor button)
are the store's raw counts and include switched-off drafts, harmless today
since the chips read posted and scheduled only.

## Resolution

1. **Channel toggle.** New server setting `outreach_channels` (comma list, default `bluesky,mastodon,instagram`) in `internal/serversettings`, migration `000042_outreach_channels_setting` (widens the key CHECK; `docs/database.md` row and the `000001`-`000042` range in it and `AGENTS.md`; test template rebuilt). Settings → Outreach shows one checkbox per channel; the last channel left on cannot be switched off. The handler reads it per request (`SetEnabledChannels`), so a save applies at once. Disabled channels are not drafted (Draft all), refused by `POST /admin/outreach/{id}/posts` (409), get no new tracked links (`ensureLinks`), and are left out of the panel's `channels` and `posts` (so the summary line, cards, Post by hand, Announce button and Schedule all need no client filter), the links table, the per-workshop results (channels and posts) and the overview (`posts_total`, `posts_posted`, `scheduled`, `posted_channels` recomputed from enabled posts; `enabled_channels` returned and fed to `postsCellText`'s `isEnabled`). **Existing posts and links for a disabled channel are kept**, only hidden and uncounted; switching the channel back on brings them back (tested). Click totals still include every real click.
2. **Mark posted / Unmark.** The dialog with the optional "Link to the post" field was already in place (#0581). Added `POST /admin/outreach-posts/{id}/unmark` (`Store.MarkUnposted`: status back to `manual`, `posted_at` and `remote_url` cleared; audited as `outreach_post.unmarked`). Refused (409) for a post whose channel the site posts itself (`channelConfigured`), since that post is really public, and for a post that is not posted. The card shows **Unmark** on a hand-posted posted card, through the in-app dialog (never `window.confirm`), which says nothing is removed from the network.
3. **Flyer link.** The Instagram card's link opens this workshop's newest flyer (`flyerLinkFor`, from `listOutreachFlyers` loaded once by the workshop page), else "Make a flyer", which opens the flyers page with the workshop preselected (`#/outreach?view=flyers&workshop=N`). **Not done: the downloadable PNG of the flyer face.** The flyer face is HTML and CSS drawn in the browser; a PNG needs a client-side rasteriser (a new dependency, or an SVG foreignObject round trip) that jsdom cannot exercise and I may not run a browser to check. Suggest a follow-up issue (orchestrator to file); it fits batch 9's single Print action.
4. **Caption and bio.** "Copy text" is "Copy caption" on hand-posted cards; the link row reads "Put this in your bio" and is hidden when the body already contains the short URL (`showBioLink`).
