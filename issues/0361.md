## Description

`scripts/go_file_visit_floor_guard_test.sh` prints, unconditionally:

> `PASS: tracked lineCitationIsExempt requires all three predicates`

**Measured false in one construction.** Rename the real
`lineCitationIsExempt` away, and plant a column-0 decoy signature plus a
three-conjunct return line **inside a raw string** — the file already holds
raw-string Go fixtures with column-0 declarations. `go vet` is clean, the
harness prints that PASS and exits 0, while the live exemption requires **one**
predicate.

**This is explicitly NOT a reason to reopen `#0356`**, and `#0356`'s third
review ruled it so with reasons worth preserving:

- It is a **forgery**, not a **drift**. No textual oracle over a Go file can
  tell a decoy from a declaration — this is CLAUDE.md §8's own "a regex that
  hunts for a tag finds the one inside a comment", one language over, and §8's
  stated remedy is a parser, which this harness deliberately does not use.
- `#0356` criterion 9's three named mutations are each now asserted from
  outside on a mutated copy. This construction is a mutation the criterion does
  not name.
- Everything the sub-check catches, the in-file Go tests catch **by name** —
  they do catch this forgery loudly. A fourth round on the harness buys §8's
  "seventh bounce".

**The terminating move is the one three separate agents converged on today**
(`#0330`, `#0347`, `#0356`): stop claiming more than the check establishes.

## Acceptance criteria

1. The sub-check's `PASS` line says what it actually establishes — **the text
   at the located signature** — rather than a property of the live function.
   Model it on the sibling fail-open-B comment in the same file, which `#0356`'s
   third review judged correctly scoped in both directions.
2. It records that **a textual oracle cannot distinguish a decoy from a
   declaration**, and that the in-file Go tests are what catch that class.
3. **No new mechanism.** Do not add a check, an anchor, or a fixture to chase
   the forgery — §8's `#0258` case is six passes of exactly that, and this
   issue exists because the terminating move was chosen deliberately.
4. A `go/parser`-based extraction **would** close it, but that changes the
   harness's deliberate "no Go toolchain as oracle" stance. If a pass wants
   that, it is a **decision to be raised**, not a transcription to be performed:
   stop and report rather than implementing it.
5. `bash -n` and `shellcheck` clean, and check bash-4-only syntax by eye (§8 —
   both tools pass on `${var,,}`, `declare -A`, `mapfile`, `&>>`, which fail
   silently under this machine's bash 3.2.57). The sole heredoc stays
   `<<'PYEOF'` so backticks remain inert.
6. All 4 of `#0356`'s tests and all 5 of `#0347`'s still pass; floor harness
   stays **42 total / 12 non-exempt**; no `.ClaimDue(` / `.OrphanSweep(` /
   `.SelectDue(` call syntax enters any comment (`#0323`).

## Review notes — 2026-09-01 (`claude-opus-5`)

**Verdict: RESOLVED.** Every acceptance criterion independently re-verified.
The one thing that could have sunk this issue — a rescoped claim that is
itself inaccurate, the same defect one round later — did not happen: every
clause of the new `pass` string and of the new header paragraph was read
against what the code does and each one holds.

### 1. The new claims, clause by clause (criteria 1 and 2)

The `pass` string:

- *"the text located at `lineCitationIsExempt`'s function signature"* — TRUE,
  and the definite article is licensed: this branch is reached only after the
  `EXEMPT_FUNC_SIG_COUNT -ne 1` guard has established the signature occurs
  **exactly once**.
- *"is followed by a three-conjunct return statement (2 `'&&'` in the line
  immediately after it)"* — TRUE. `grep -A1 <sig> | sed -n '2p'` is literally
  "the line immediately after"; the branch requires both a match on
  `EXEMPT_RETURN_PATTERN` (the three named identifiers, in order) and an
  ampersand count of exactly 2. If anything this understates — the pattern
  also pins *which* three predicates — but the preceding, unchanged paragraph
  and the `fail` message both carry that, so nothing is lost.
- *"this locates by matching the SIGNATURE's literal text, not by parsing or
  running Go"* — TRUE. Every metacharacter in `EXEMPT_FUNC_SIG_PATTERN` is
  escaped except the `^`/`$` anchors, so the ERE matches exactly that literal
  line, and the script never invokes the Go toolchain (its own file header
  says so under "WHY THIS SCRIPT NEVER RUNS `go test` AS ITS ORACLE").
- *"so it establishes what is WRITTEN there, not that it is the live
  function's actual body"* — TRUE, and **demonstrated**: under construction C
  below this exact sentence remains true of a tree whose live exemption
  requires one predicate. That is the test the old wording failed.
- *"(see the limit noted in this sub-check's header comment above)"* — the
  referent exists and is directly above.

The header paragraph:

- *"a construction that renames the real `lineCitationIsExempt` away **and
  then** plants a column-0 decoy … inside a raw string satisfies it too"* —
  TRUE, and the conjunction is load-bearing and correctly stated. The rename
  is **necessary**: leaving the real signature in place and merely adding a
  decoy takes the signature count to 2 and the guard FAILS. The paragraph does
  not overstate the hole.
- *"This file already carries raw-string Go-source fixtures with declarations
  at column 0, so the decoy is not exotic"* — TRUE, and checkable:
  `TestCollectLineCitationHitsFixtureExemption`'s `withMarker` /
  `withoutMarker` constants are raw strings containing `package fixture` and
  `func F() {}` at column 0.
- *"`go vet` stays clean and this sub-check still reports PASS while the live
  exemption (now under a different name) requires only one predicate"* — TRUE;
  reproduced, `gofmt -l` clean too.
- *"No textual oracle over a Go file can tell a decoy from a declaration"* —
  this is the claim criterion 2 asked for, attributed to `#0356`'s third
  review, and immediately qualified by the next clause naming a parser as the
  remedy. Read as written it is scoped, not absolute.
- *"That residue is not closable by **anchoring on more text**"* — this is the
  clause most at risk of over-claiming, and it is scoped exactly right. It
  says text cannot close it; the sentence before it says a parser is the
  stated remedy and that this harness deliberately declines one. So the
  paragraph does not contradict criterion 4, it sets it up.
- *"three of `TestLineCitationIsExemptRequiresAllThreePredicates`'s table
  rows, plus `TestCollectLineCitationHitsFixtureExemption`'s `withoutMarker`
  case"* — TRUE, and the count is exact. Against `return commentIsIndented`
  the boolean table fails on precisely `missing self-citation`,
  `missing transcript marker`, and `only indent` (the other five rows have
  `want == commentIsIndented`), and `withoutMarker` is the only fixture case
  whose expectation moves. Both reproduced, output quoted below.

**Nothing claimed that the check cannot deliver, and nothing material left
uncredited.** The exactly-once property is the one strength the `pass` line
does not restate, and correctly so — it belongs to a different branch, which
has its own message.
