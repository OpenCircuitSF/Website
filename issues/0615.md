## Description

After `#0613` and `#0614`, a Hack Night can still be announced in text that calls
it a workshop. Audit every user-visible string that says "workshop" and make it
either generic ("event") or derived from the listing's type name. Identifiers,
table names, comments and URL-independent internals are out of scope.

## Plan

Copy only. No identifier, table, column, JSON key, enum value, route, hash, element id, CSS class or comment changes name. One new migration, for two seeded CRT strings.

### Decisions

- **Announce subject is type-derived, using the type name as the admin wrote it:** `New Hack Night: X`, `New Workshop: X`. It is not lowercased, because an admin may name a type with an acronym. An empty name gives `New event: X`. The link in the body is generic: `View this event`.
- **Everything else is generic.** The listing's type is shown beside these strings already, so "event" is enough.
- **Outreach drafts need no change.** `outreach.Facts` has no type field and `Draft` writes no type word; it reads the title, date, venue and summary. New tests pin that. Flyers (`FlyerFace.svelte`, `FlyerPrint.svelte`) likewise print only listing fields.
- **The per-listing social card needs no change.** `internal/seo/card.go` draws the title and meta line, and `#0614` added the type name.
- **Sent and archived campaigns are not touched.** The announce shortcut writes `subject` and `body_md` once, into a new draft. No migration or code here reads or writes an existing `email_campaigns` row.
- **`Workshop` stays where it is the seeded name of a type**, including test fixtures. The test title below deliberately avoids the word so the check means something.
- **No new repo-wide "no workshop word" guard.** Brand copy would make it an allowlist of exceptions, and this issue does not ask for one.

   }
