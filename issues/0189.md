## Description

`#0186` wired `CampaignSendDialog.svelte` through `sendGuardState` and closed a
real UI-correctness gap in `handleSubmit`. Its phase-3 review passed the change
and reported three refinements. None is a live defect.

**1. The truth table's hand-rolled `normalizeCountInput` replica uses the wrong
separator class.** `CampaignSendDialog.guard.test.ts:93` writes `/[, ]/g` with an
**ASCII space (0x20)**; the real function at `web/src/lib/sendConfirm.ts:22` uses
**U+2009 thin space** (`e2 80 89`). The characters are visually identical — the
review found it by hex-dumping, which is the same trap `#0184`'s review
hex-dumped this line to avoid. It also omits the real function's
`Number.isSafeInteger` check. All 25 assertions are sound today because no case
contains a separator, and the review traced both directions to confirm it fails
*loudly* rather than silently if one is added. The fix is to stop replicating:
call `normalizeCountInput` directly, which is also what makes the old formula
genuinely "the old formula".

**2. `CampaignSendDialog` hardcodes `status: 'draft'` when calling the guard.**
Safe today — the mount gate (`sendDialogOpen && preflightSummary`),
`onOpenSend`'s `editorGuard.kind === 'ready'`, and `canSendCampaign` are all
draft-only, and nothing refetches `campaign` while the dialog is mounted. But
`CampaignStore.Send` accepts `failed` too, so the first reuse of this dialog for
a failed-campaign retry would silently feed the guard a false status. Thread
`status` in as a prop.

**3. In `blocked` and `needs-confirm`, the Send button is enabled but
`handleSubmit` silently returns.** Not a regression — it matches the component's
pre-existing `needs-confirm` pattern, and the blocked panel carries
`role="status"`/`aria-live`. But `#0119` solved exactly this in the parent with
`aria-disabled={!sendGateOpen}` plus an `aria-describedby` pointing at the
reason. Mirroring that here finishes the job `#0186` started.

## Acceptance criteria

- [ ] The truth table calls `normalizeCountInput` from `web/src/lib/sendConfirm.ts` rather than replicating it, and still demonstrates old-vs-new agreement
- [ ] A case containing a real U+2009 thin space is among those exercised, so the separator class is proven rather than assumed
- [ ] `CampaignSendDialog` takes `status` as a prop instead of the `'draft'` literal, and the parent passes the campaign's real status
- [ ] The Send button carries `aria-disabled` and an `aria-describedby` pointing at a real element in `blocked` and `needs-confirm`, following `#0119`'s treatment
- [ ] `#0186`'s two documented behaviour changes still hold, and the mutation it verified (swapping `sendGuardState`'s `inFlight`/`unmet` branches) still turns tests red
- [ ] `scripts/check.sh web` passes

## Notes

Reported by `#0186`'s phase-3 review under `CLAUDE.md` §9.

Item 1 is the one with teeth. It is not currently wrong, but it is the second
time a hand-rolled replica of `normalizeCountInput` has come within one test case
of being silently wrong about the same character — see `#0184`'s review notes.
Deleting the replica removes the class of bug rather than fixing this instance.
