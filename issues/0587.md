## Review notes

Reviewer (Opus), 2026-10-18. **Approved with small fixes; resolved.**

- **Items 1-4 hold against E1, E3, E4, E5.** A drafted Reminder or Last call starts ticked. Only chosen rows are listed. The heading names the waves ("Schedule the Reminder and Last call?", or "Schedule posts?" when nothing is chosen). With nothing chosen the button is a disabled "Nothing chosen", never "Schedule 0 posts". The by-hand line is there. Rows show `formatPacificWeekdayTime` (PT), and the Settings link is `adminSettingsHash('outreach')`. The per-row edit converts through `toPacificInput`/`fromPacificInput`. A past time, or an empty one, blocks Schedule.
- **Announce is never in Schedule all.** `PlanScheduleAll` skips it as `no_suggested_time`, which fits §4: Announce goes out now. The dialog's `wave === 'announce'` branch is dead but harmless.
- **§6 holds.** The dry run still changes nothing and returns exact ids. A confirm schedules only ids still in the server's own plan (`#0568`). Reminder and Last call stay opt-in on the page (`#0574`): only waves the admin drafted reach the dialog at all.
- **Fix 1: lead window shared, not copied.** The override path had its own copy of single Schedule's window checks. Both now call one `parseScheduleAt(raw, now)` in `admin_outreach_posting.go`. Single Schedule's error strings are unchanged.
- **Fix 2: audit metadata.** A bulk `outreach_post.scheduled` row now carries `time_overridden` (true or false).
- **Fix 3: test coverage.** `TestAdminOutreachLinks_ScheduleAllTimeOverride` now also checks that each refused override leaves the post a draft. It covers the 30s-ahead and 367-days-ahead bounds, and checks that another workshop's post sent through this workshop's map is not scheduled and stays a draft. An invalid override for an id outside `post_ids` is ignored. The confirm response reports the overridden time, the audit row has `time_overridden=true`, and an already-scheduled post is not moved by a second override (posted and queued posts are equally outside the plan, since `PlanScheduleAll` takes only `draft`).
- **Fix 4: SPA.** If you open a row's edit and leave it unchanged, no override is sent (new behaviour test). `scheduleHint` no longer says "has passed" about a suggestion that is still ahead (that happens when the admin clears the prefilled picker): it takes `now` and names the future time instead. A unit test was added for that.
- **Mutation tests**, run against a private database: (M1) the override path parsing without the window, (M2) the shared minimum lead dropped, (M3) the shared maximum lead dropped, (M4) the override not applied. Each one was killed. M2 and M3 also fail single Schedule's bounds test, which shows the window really is shared. Restored, and sha256 matches the copies I set aside.
