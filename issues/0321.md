## Description

`#0304` extended `scripts/go_file_visit_floor_guard_test.sh` with an outbox
section. The mechanism works and its review re-proved every criterion. **Two
statements in its own documentation are false**, both measured by that review.

### 1. "Setting either to 0 leaves `go test` green" — half wrong

True for `claimKindsGuardMinPlausibleCallSiteCount`. **False for
`claimKindsGuardMinPlausibleNonExemptCallSiteCount`**: zeroing it makes
`TestNonExemptFloorCatchesScanRootsNarrowedToSelf` **fail** on `0 >= 0`.

Worse, measured across all four combinations: **neither oracle rejects a floor of
`1`.** So the harness's added protection for this family is exactly the single
value `0` — which the standing Go test already covers. The redundancy is
harmless and `1` still catches the `{"."}` narrowing, but the justification as
written is not a fact.

### 2. The margin comment justifies itself on the wrong number

It says call-site populations "CAN be dominated by one file (worst case 3, in
`worker_store_test.go`)". **3 of 12 is 25%, not domination.** That claim is true
of the *total* population (`store_test.go` is 20 of 35) and false of the
non-exempt one the rule actually governs.

**The real justification is unstated and stronger:** `6` is exactly `12/2`, so
`floor_plausible` trips after **two** new call sites — against roughly 44 files
of headroom for the handlers family. That is why this family needs a different
margin rule, and it should say so.

## Acceptance criteria

1. The section header states accurately which floors `go test` can and cannot
   pin, that the standing Go test already pins the non-exempt floor against `0`,
   and that **neither oracle rejects a floor of `1`**.
2. It states the harness's real value for this family: surviving an edit to the
   file it guards, which no in-file check can do (CLAUDE.md §8).
3. The margin comment justifies `0 < floor <= population` on the headroom
   argument — two new call sites versus ~44 files — not on a domination claim
   that is false for the population it governs.
4. Every number in the corrected comments is **re-measured**, not copied from
   this issue. `#0310` exists because a comment advertised itself as measured
   while carrying a count that was not.
5. Comments only — `git diff` filtered to non-comment lines must be empty.
6. `ISSUE=NNNN scripts/check.sh guards` passes, run at least twice.
