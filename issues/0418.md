## Description

Production's SES region is **`us-east-1`**, proved three independent ways by
`#0057`'s planning pass: the instance metadata's `placement/region`,
`AWS_REGION=us-east-1` in `/etc/opencircuit/config.env`, and the live custom
MAIL FROM record `10 feedback-smtp.us-east-1.amazonses.com`.

Two places still say `us-west-2`:

- **`docs/email-setup.md` — six occurrences.** Confirmed by count.
- **`PRD.md` §10.2's DNS table**, which is wrong on **two** independent facts:

	| `mail.opencircuitsf.com`  | MX | `10 feedback-smtp.us-west-2.amazonses.com` |
	| `lists.opencircuitsf.com` | MX | `10 inbound-smtp.us-west-2.amazonaws.com`  |

  Wrong region, **and** wrong subdomain — production's custom MAIL FROM is
  `bounce.mailing.opencircuitsf.com`, not `mail.opencircuitsf.com`.

`CLAUDE.md` §7 already records `us-east-1` correctly, and notes that this
contradicted what the PRD assumed. That correction never reached §10.2 or the
runbook.

## Why it matters

`#0057` is about to add DNS records and SES receipt rules. A runbook naming the
wrong region would have an operator create inbound infrastructure in a region
where the sending identity does not exist — silently, since SES will happily
verify an identity in any region.

This is distinct from `#0414`, which covers the wrong `From:` **address** in the
same file. Same class of drift, different fact, and both live in
`docs/email-setup.md`.

   MAIL FROM subdomain. Read the live Route 53 zone rather than reasoning about

   `us-west-2`, and whether its stated *reasoning* still holds now that the
