## Description

The public archive handler checks `Status != sent` (→ 404), then
`archive_status == 'withheld'` (→ 410), and **falls through for `pending`** —
serving 200.

Unreachable today: `SetArchiveStatus` cannot write `pending`, so no row reaches
that state through any supported path. But it disagrees with `ListArchived` and
the sitemap, both of which gate on `Published`. Three readers of the same column
with two different notions of what counts as public is the kind of divergence
that becomes a leak the moment a fourth state is introduced or a migration
backfills one.

The remedy `#0123`'s reviewer specified: switch on `ArchiveStatus` explicitly —
`withheld` → 410, `published` → 200, **anything else** → 404 — so the default is
closed rather than open.

## Acceptance criteria

1. The handler switches on `ArchiveStatus` with a closed default. An unknown or
   future value must 404, not 200.
2. The `sent` status check stays — the two conditions are independent, and a
   non-sent campaign must remain unreachable regardless of its archive status.
3. `ListArchived`, the sitemap source, and the public handler agree on what
   "public" means. If they cannot share a predicate, say why and make the
   difference explicit at each site.
4. A test drives every `(status, archive_status)` pair, including the
   currently-unreachable `pending`, and asserts the response. `#0123`'s existing
   matrix test is the place for it.
5. If `pending` should never exist at all, consider a CHECK constraint — but
   note the migration question in `#0123`'s re-implementation before adding one,
   and do not edit a migration another issue is mid-flight on.
6. `ISSUE=NNNN scripts/check.sh go ./internal/handlers/... ./internal/mailing/... ./internal/seo/...`
   passes with no skips.
