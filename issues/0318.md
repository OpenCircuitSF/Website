## Description

The public archive handler checks `Status != sent` (→ 404), then
`archive_status == 'withheld'` (→ 410), and **falls through for `pending`** —
serving 200.

Unreachable today: `SetArchiveStatus` cannot write `pending`, so no row reaches
that state through any supported path. But it disagrees with `ListArchived` and
the sitemap, both of which gate on `Published`. Three readers of the same column
with two different notions of what counts as public is the kind of divergence
that becomes a leak the moment a fourth state is introduced or a migration
backfills one.

The remedy `#0123`'s reviewer specified: switch on `ArchiveStatus` explicitly —
`withheld` → 410, `published` → 200, **anything else** → 404 — so the default is
closed rather than open.

## Acceptance criteria

1. The handler switches on `ArchiveStatus` with a closed default. An unknown or
   future value must 404, not 200.
2. The `sent` status check stays — the two conditions are independent, and a
   non-sent campaign must remain unreachable regardless of its archive status.
3. `ListArchived`, the sitemap source, and the public handler agree on what
   "public" means. If they cannot share a predicate, say why and make the
   difference explicit at each site.
4. A test drives every `(status, archive_status)` pair, including the
   currently-unreachable `pending`, and asserts the response. `#0123`'s existing
   matrix test is the place for it.
5. If `pending` should never exist at all, consider a CHECK constraint — but
   note the migration question in `#0123`'s re-implementation before adding one,
   and do not edit a migration another issue is mid-flight on.
6. `ISSUE=NNNN scripts/check.sh go ./internal/handlers/... ./internal/mailing/... ./internal/seo/...`
   passes with no skips.

## Review notes

> 🟢 Reviewed 2026-08-27 (phase 3, Opus). Approved. Code commit `b575867`.

**Criterion 1 — closed default.** `GetBySlug` (`internal/handlers/public_archive.go`)
now reads `switch c.ArchiveStatus { case Published: …; case Withheld: 410;
default: 404 }`. Re-read the whole function: there is no path from `default`
to the render block, and the render block is only reachable by falling out of
the `Published` case. Closed.

**Criterion 2 — independence confirmed.** The `c.Status != CampaignStatusSent`
check still precedes the switch and returns unconditionally. The matrix test
covers draft/scheduled/sending/paused_delivery_health/canceled/failed and each
404s regardless of archive status.

**Criterion 3 — the three readers re-derived, not taken on report.** I checked
each site myself:

| Site | Predicate | Where |
|---|---|---|
| Public handler | `Status == sent` **and** `ArchiveStatus == published` | `internal/handlers/public_archive.go` |
| `ListArchived` | `WHERE archive_status = $1` bound to `ArchiveStatusPublished` | `internal/mailing/campaign_archive.go` |
| Sitemap source | `Published: c.ArchiveStatus == mailing.ArchiveStatusPublished`, plus `sitemap.go`'s `if !e.Published { continue }` | `cmd/opencircuit/campaign_archive_seo_source.go`, `internal/seo/sitemap.go` |

The handler's predicate is strictly stronger — it also requires `sent`. They
agree only if `archive_status = 'published'` implies `status = 'sent'`, which
the implementer's note did not establish. It does, and here is the derivation:
`published` is written by exactly two statements. `CompleteIfDone`
(`internal/mailing/worker_store.go`) sets `archive_status = 'published'` in the
same `UPDATE` that sets `status = 'sent'`. `SetArchiveStatus`
(`internal/mailing/campaign_archive.go`) refuses when the *current*
`archive_status` is `'pending'`, so it can only act on a row `CompleteIfDone`
already touched. And `sent` is terminal: I enumerated every writer of
`email_campaigns.status` (`Create`, `Send`, `Cancel`, `Resume`,
`DemoteToDraft`, `ClaimStart`, `CompleteIfDone`, `MarkFailedCampaign`,
`MarkPausedDeliveryHealth`) and none has `sent` as a source state. So
`published ⟹ sent`, the extra conjunct is never load-bearing, and the three
readers select exactly the same set.

**Criterion 5 — the CHECK constraint verified directly.**
`migrations/000025_add_campaign_archive_columns.up.sql` carries
`ADD CONSTRAINT email_campaigns_archive_status_check CHECK (archive_status IN
('pending', 'published', 'withheld'))`, and the column defaults to `'pending'`.
So `pending` is reachable **by schema** — every campaign starts there — and
unreachable **through the public handler's 200 path** after this change. No
migration was needed and none was written; `migrations/` is untouched, which
also keeps clear of `#0320`'s in-place-edit fragility around 000025.

**Judgement on the fake-store test.** `TestPublicArchive_GetBySlug_UnknownArchiveStatusIs404`
is the right call here, and the default arm is *genuinely* unreachable today
rather than merely untested: the CHECK constraint closes the column to three
values, `SetArchiveStatus` refuses to write `pending`, and `CompleteIfDone`
flips `status` and `archive_status` in one statement so no reader can observe
`sent`+`pending`. A DB-backed test therefore cannot reach the arm at all —
seeding a fourth value would fail the constraint. The fake is also not a
self-referential oracle: it substitutes only `publicArchiveStore`, the seam
the handler already declares, and the test drives the real handler over a real
`httptest` server, so what it exercises is production code. The arm becomes
reachable the day a migration adds a fourth value, which is exactly the case
the test insures against.

**Independent mutation proof.** Rather than editing the shared tree, I checked
`b575867` out into a throwaway detached worktree and reverted the switch there
to the pre-fix `if c.ArchiveStatus == ArchiveStatusWithheld` shape. Both new
assertions failed as claimed:
`VisibilityByStatus/sent+pending` → `GET = 200, want 404`, and
`UnknownArchiveStatusIs404` → `status = 200, want 404`. Worktree removed
afterwards; the main tree was never mutated.
