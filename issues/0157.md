## Description

This codebase now has **four** implementations of two URL-safety rules, split across two languages:

| Rule | Go | TypeScript |
|---|---|---|
| Cover image (same-origin only) | `handlers.isSafeCoverImage` | `workshopAdmin.isSafeCoverImage` |
| Link (external allowed) | `handlers.isSafeLinkHref` | `markdown.isSafeLinkHref` |

They must agree exactly. **Nothing in the build checks that they do.**

Parity has been established three separate times — by `#0138`'s two review passes and by `#0152`'s — each time with a throwaway sweep script that was deleted afterward. Two of those sweeps found real divergences:

- `#0138` pass 2 found the twins agreeing only after a fix, and swept every codepoint `0x00`–`0xFF` to prove it.
- **`#0152` found a live bypass**: `strings.TrimSpace` and JavaScript's `trim()` disagree on U+FEFF and U+0085, so the naive Go twin **accepted a `javascript:` URL that TypeScript rejected**. Invisible to every existing test.

That is the argument in one line: the parity break was a real security defect, and only an ad-hoc script that no longer exists caught it.

## Acceptance criteria

- [ ] A **checked-in fixture** of payloads and expected verdicts, asserted by both `go test` and vitest, so a divergence is a red build rather than a discovery
- [ ] The fixture covers what the three sweeps established: every codepoint `0x00`–`0xFF` in interior and leading position, the ECMA-262 whitespace set, scheme shapes (`javascript:`, `mailto:`, `data:`, `vbscript:`, mixed case), protocol-relative and backslash forms, and the legitimate cases that must keep passing (query, fragment, mid-path `//`, `..`, percent-encodings, non-ASCII, long paths)
- [ ] The fixture is **generated or verified from ground truth**, not hand-listed — `#0152`'s reviewer computed the ECMA-262 whitespace set by asking V8 for every codepoint `0x0000`–`0x10FFFF` rather than trusting a remembered list, and caught two codepoints (U+180E, U+200B) that an older reference would have got wrong
- [ ] Both suites fail when either side is mutated — prove it in each language
- [ ] Decide whether the four functions should instead become two, with one side generated or exposed to the other. A fixture is the cheap fix; deduplication is the real one. Record the reasoning
- [ ] **Also fold in** the coverage nit `#0152`'s review found: `TestAdminWorkshops_PatchRejectsUnsafeSignupURL` covers 2 payloads where the `Create` equivalent covers 4. Widen it
- [ ] Decide whether the fixture's scope should extend past URL validators to **every** rule implemented in both languages. `#0155`'s review found a second instance: `workshopAdmin.ts` has no upper bound on capacity, so a browser user typing `3000000000` gets the server's 400 rather than a client-side message — correct behavior, same divergence shape
- [ ] `ISSUE=0157 scripts/check.sh go ./internal/...` and `scripts/check.sh web` both pass

## Notes

Filed at the explicit request of `#0152`'s phase-3 review, which noted it is out of scope for any single validator issue: it spans two languages, four functions, and test infrastructure.

One caveat that reviewer recorded and that this issue should respect: `isJSWhitespace` is a hardcoded snapshot of Unicode's `Zs` category, so a future Unicode addition would drift. That is still strictly better than `unicode.IsSpace`, which is wrong about two codepoints **today** — but a fixture generated from ground truth would catch the drift, where a hand-listed one would enshrine it.
