## Description

`#0179`/`#0180`'s review probed coverage **by mutation for every export**, rather than by checking which symbols the test files import. That found four survivors — mutations that change behavior and pass the suite. All four are one line each.

**1. `cancelConfirmMessage` is never tested with `undefined`, which is what the API actually sends.** `workshopView.PublishedAt` is `*string` with `omitempty`, so a NULL `published_at` reaches the SPA as an **absent key** — `undefined`, not `null`. The function is only ever exercised with `null`, so a mutation confined to its `undefined` handling passes **77/77**.

`cancelVisibilityOutcome` *is* tested with `undefined`, so the gap is only at the boundary — but this is the same "a state nobody enumerated" class the cancel dialog has now shipped three defects for (`#0171`, `#0174`, `#0177`), and the enumerated state here is *the one production actually produces*.

**2–4. Three pre-existing depth gaps in `sendConfirm.ts`**, each passing 41/41 when mutated:
- dropping U+2009 from `normalizeCountInput`'s separator class
- deleting its `Number.isSafeInteger` guard
- swapping `sendGuardState`'s `unmet` and `audienceCount === 0` branches — no existing case sets both, so the swap is invisible

These matter more than their size suggests: `sendGuardState` is `#0047`'s send gate, the mechanism `#0056`'s review leaned on when accepting the `all`-audience fallback as survivable.

## Acceptance criteria

- [ ] `cancelConfirmMessage` is asserted with `undefined` for `published_at`, producing the `staysPrivate` sentence — the case production actually sends
