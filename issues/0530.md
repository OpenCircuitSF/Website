## Description

The only schema.org structured data on the site is the workshop `Event` block (`#0055`), validated with Google's Rich Results Test in `#0149`. Measured on production, 2026-09-12: the home page and `/archive/09-2026` carry **no JSON-LD**.

That leaves two gaps:

- **Newsletters.** An archive page is an article: a headline, a publication date, a publisher. Structured data lets search engines present it as one.
- **The organisation.** Nothing states, in machine-readable form, that `opencircuitsf.com` is Open Circuit SF, what its logo is, or which profiles belong to it (Bluesky, Discord, the Luma calendar). That is what feeds a knowledge panel and ties the profiles to the site.

## Acceptance criteria

1. `/archive/{slug}` for a published campaign emits an `Article` (or `BlogPosting`; record the choice) with `headline`, `datePublished` from `archived_at`, `publisher` as the organisation, `url`, `description` (`#0528`'s text), and `image` (`#0532`'s card once it exists, the default card until then).
2. `/` emits an `Organization` (name, url, logo, and `sameAs` for the organisation's real public profiles) and a `WebSite` node.
3. Built the same way as `internal/seo/jsonld.go`'s `Event` block, reusing its escaping, and passing the same hostile-payload tests `#0055` applied: content from the database must not break out of the `<script>` element.
4. Nothing is emitted for withheld, draft, or unknown archive slugs.
5. The CSP is unaffected: JSON-LD is a data block, not executable script. Confirm the bootstrap script's hash is unchanged using an HTML parser, not a regex (`CLAUDE.md` §8).
6. **Post-deploy, verified by the user:** Google's Rich Results Test on `/` and `/archive/09-2026` reports no errors, per the post-deploy step `docs/seo.md` now records (`#0149`).
7. `ISSUE=NNNN scripts/check.sh go ./internal/seo/... ./cmd/opencircuit/...` passes with no skips.
