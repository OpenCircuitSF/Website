## Description

`#0216`'s second review passed the AST-based focus-wiring guard after re-running
all four probes at its own chosen sites and surveying all 11 panels
mechanically. It then mapped where the new mechanism is still weak. **None of
these occurs in the tree today.**

**The false passes — guard green, wiring broken.** These are the ones that
matter:

1. **`{:else}` branches take the `{#if}`'s condition** from `enclosingGuard`. A
   panel in `{:else}` of `{#if a}` whose focus call sits under `if (a)` is
   **inverted** — dead wiring — and passes. The converse, correct wiring, fails.
   The violation message is misleading in both directions. This one is not named
   in the guard's header.
2. **Two panels in one file under textually identical conditions, with swapped
   focus targets.** This *is* named in the header as the residual gap, and the
   review confirmed it is real.
3. **Nothing requires the focus call to be reactive.** A `tick().then(() =>
   V?.focus())` inside a plain function that is never called satisfies the check;
   no `$effect` enclosure is required.
4. **`{#each}`-rendered panels** — theoretical today, since none exists.

**The false failures — guard red, wiring fine.** Lower stakes, but they are what
gets a guard silenced: `guardKey` is whitespace-sensitive, so `{#if a&&b}`
against `if (a && b)` fails. Newlines, indentation, and extra parentheses are
handled correctly; only whitespace *runs inside* the condition differ.

**The prose undercount.** `CampaignSendDialog.behavior.test.ts` says "the six
sites nothing mounts today". Only that one file imports
`@testing-library/svelte`, so **ten** of eleven are unmounted — and the sentence
contradicts the list of seven immediately preceding it.

The review deliberately did **not** bounce on this, and the reasoning is worth
keeping: it predates the fix commit, the first review examined those exact lines
and ruled them honest, and it understates *breadth* rather than overstating what
the guard *proves*. That distinction is the one `#0216` was filed about.

## Acceptance criteria

- [x] A panel in `{:else}` is matched against the negation of the `{#if}` condition, not the condition itself — inverted wiring fails, correct wiring passes
- [x] Each of the four false passes is either closed or named in the guard's header; the `{:else}` case must be **closed**, since it silently blesses dead wiring
- [x] `guardKey` normalises whitespace inside a condition, so `{#if a&&b}` matches `if (a && b)`
- [x] The focus call must be inside a `$effect`, or the header says why not
- [x] Each closure is proved by mutation: construct the shape, confirm the guard fails, restore, verify byte-identity
- [x] The mount undercount reads correctly — ten of eleven, or whatever is true when the work lands
- [x] All four of `#0216`'s probes still fail as recorded, and the 11-site survey still finds 11
- [x] `scripts/check.sh web` passes

## Notes

Reported by `#0216`'s second phase-3 review under `CLAUDE.md` §9.

Criterion 1 is the one with teeth. The other three false passes need a
contrived or absent shape; the `{:else}` inversion needs only an ordinary
two-branch modal, and it fails **silently in the direction that matters** —
blessing dead wiring while flagging the correct version.

Note the asymmetry that should drive the design: a false failure gets the guard
edited or silenced, a false pass gets it trusted. `#0199`'s review made the same
argument about a discount rule that was too broad.

`#0216`'s two `## Review notes` sections carry the probe shapes and the 11-site
enumeration; they are the regression suite for criterion 7.

## Implementation notes

Redesigned `web/src/lib/modalFocusWiring.structuralGuard.test.ts`'s guard
matching (`collectPanels` on the template side, `collectFocusCallSites` on
the script side) around a `GuardConstraint { text, negated }` — each side's
nearest enclosing `{#if}` / `if (...)` REPLACES (not accumulates) the guard
handed to its consequent with the affirmative condition, and to its
alternate with the negated one. "Replaces, not accumulates" matters: the
real tree nests each modal's own condition (e.g. `deactivatingUser`) inside
outer admin-section routing conditions (`{#if section === 'users'}`,
`{#if !$currentUser?.is_admin}`) that the corresponding `$effect`'s own
`if` never repeats. An early version of this fix accumulated the full
ancestor chain and broke all 11 real sites at once — caught immediately by
the repo-wide scan test, which is exactly what it's for — before being
corrected to narrowest-only, matching the pre-#0222 guard's own established
behavior (which found the narrowest SPAN containing an offset) with only
the negation added.

**{:else} inversion (criterion 1, closed).** The old code recorded one
span (and one guard) for an entire `IfBlock`, start to end — consequent
and alternate together — so a panel in `{:else}` of `{#if a}` matched
against the SAME key as the `{#if a}` branch. Fixed as described above.
Two new synthetic fixtures prove both directions: an inverted panel
(focus call under `if (a)`, panel in `{:else}`) fails, and the correctly
negated version (focus call under `else { ... }` of the same `if`)
passes.

**guardKey whitespace (part of criterion 1's "false failures" list,
closed).** `guardKey` was collapsing whitespace *runs* to a single space
but not removing already-present single spaces, so `{#if a&&b}` (key
`"a&&b"`) and `if (a && b)` (key `"a && b"`) never matched — a false
failure. Now strips all whitespace from the condition's span
(`.replace(/\s+/g, '')`), so both normalize to `"a&&b"`. A genuinely
different expression (`(a&&b)` vs `a&&b`) is still, correctly, a
different key — only internal whitespace runs were the problem.

**Reactivity (criterion 3, closed).** Nothing previously required the
matched `tick().then(() => V?.focus())` call to be reactive — a call
inside a plain, never-invoked function satisfied the check. Every one of
the 11 real sites already sits inside `$effect(() => { ... })` (confirmed:
`grep -n 'effect('` over all six host files finds one wrapping each site,
no exception), so requiring it costs nothing on the real tree.
`collectFocusCallSites` now threads an `inEffect` flag, set `true` only
while walking inside a `$effect(...)` (or `$effect.pre(...)`) call's own
arguments, and a match is only accepted when `inEffect` is true.

**Named, not closed (criterion 2 and the `{#each}` gap, criterion "closed
or named").** Two panels in the same file under textually identical
conditions remain indistinguishable to this guard — pre-existing gap from
`#0216`'s own header, kept and reworded slightly for the new mechanism but
not newly closed here, per this issue's acceptance criteria treating it as
optional. `{#each}`-rendered panels get no special handling — purely
theoretical, since no `{#each}`-rendered modal panel exists in the tree
today; the header now says so explicitly (it did not before).

**Prose undercount (fixed).** `modalFocusWiring.structuralGuard.test.ts`'s
header said "the six sites nothing mounts today" while its own preceding
sentence enumerated seven (Admin.svelte ×5, CampaignEditor.svelte ×1,
Campaigns.svelte ×1) — internally contradictory, and both undercounted the
true figure. `CampaignSendDialog.behavior.test.ts`'s header had the same
"six sites" error, naming only Admin.svelte's five and CampaignEditor's
one. Confirmed the actual figure directly:
`grep -rl '@testing-library/svelte' src` finds only
`CampaignSendDialog.behavior.test.ts` and `Dashboard.behavior.test.ts`
(Dashboard isn't one of the 11 focus-wiring-site files), so exactly 1 of
the 11 sites (CampaignSendDialog's own) is covered by mounting — the
other **ten** (Admin.svelte ×5, CampaignEditor.svelte ×1, Campaigns.svelte
×1, WorkshopEditor.svelte ×2, Workshops.svelte ×1) are not. Both headers
now say "ten," with the previously-missing WorkshopEditor/Workshops sites
named explicitly.
