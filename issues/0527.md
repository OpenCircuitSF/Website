## Description

Moving between screens in `/admin` never changes the URL. Reloading the page
always returns to Overview, back and forward do not move between admin screens,
and there is no way to link to a specific screen or record.

**Decision (user, 2026-09-12): use hash routing inside the admin section.** URLs
take the shape `/admin#/campaigns/42`.

The user supplied a reference spec, `hash-routing.md`, written for ShortLinks.
**Use it for the approach, not verbatim.** Its screens, its `/u/{key}` redirect
constraint, and its file names do not apply to this project.

## How admin navigation works today

- `web/src/views/Admin.svelte` holds `let section = $state<Section>('overview')`.
  Twelve sections — `overview`, `settings`, `users`, `audit`, `interests`,
  `subscribers`, `pending`, `suppressions`, `deliverability`, `campaigns`,
  `workshops`, `crt` — are switched by
  `<button onclick={() => (section = '…')}>` and rendered by
  `{#if section === '…'}` blocks.
- The selected record lives in child state: `Campaigns.svelte`'s
  `activeCampaignId` (which picks `CampaignEditor` or `CampaignStats`) and
  `Workshops.svelte`'s `activeWorkshopId`.
- Cross-screen jumps set state directly: `goToCampaignAudit`,
  `goToAnnouncedCampaign` via `pendingOpenCampaignId`, and `Deliverability`'s
  `onGoToSuppressions`.

## Why hash routing fits here

The public site already has a History API router (`web/src/lib/router.ts`,
`#0014`), and public routes should keep it. Admin screens differ: they are
authenticated, never indexed, and purely client state. A fragment never reaches
the server, so this needs **no change** to the Go route table, the Go/TypeScript
route parity guard (`#0071`), `robots.txt`, or the sitemap. The server already
serves the SPA for both `/admin` and `/admin/` (measured 200, 2026-09-12).

## Route table

Map every real screen; confirm against the code rather than this list.

| Hash | Screen |
|---|---|
| empty, `#/` | Overview |
| `#/settings`, `#/users`, `#/audit`, `#/interests`, `#/subscribers`, `#/pending`, `#/suppressions`, `#/deliverability`, `#/crt` | the matching section |
| `#/campaigns` | campaign list |
| `#/campaigns/:id` | campaign editor |
| `#/campaigns/:id/stats` | campaign stats |
| `#/workshops`, `#/workshops/:id` | workshop list, workshop editor |
| a create-new state, if one exists (e.g. `#/campaigns/new`) | the editor in create mode |
| anything else | an admin not-found state |

Filters that are useful to share, such as the audit log's campaign filter
(`goToCampaignAudit`) and page number, go in the hash's query part
(`#/audit?campaign=42`), parsed with `URLSearchParams` — never
`window.location.search`, which belongs to the outer page.

## Hazards specific to this codebase

These are why the reference spec cannot be copied as-is.

1. **The router's click interceptor drops the hash.** `router.ts`'s document
   click handler calls `navigate(anchor.pathname + anchor.search)`. An
   `<a href="#/campaigns">` on `/admin` must not be rewritten into a hashless
   push.
2. **Setting `location.hash` also fires `popstate`.** `router.ts`'s `popstate`
   handler republishes `currentRoute` and calls `restoreScroll`. A hash-only
   change must not jump the scroll position or double-handle the navigation, and
   republishing the route re-runs `#0238`'s route-change effect (page title and
   focus move to the `<h1>`).
3. **The skip link is a hash too.** `Header.svelte`'s `href="#main-content"` is a
   same-page anchor, not a route. Only hashes beginning `#/` are admin routes.
4. **The admin gate.** `/admin` requires a session and `is_admin`. A signed-out
   deep link must reach login and return to the same hash afterwards.
5. **Existing router idiom.** `router.ts` publishes `currentRoute` as a
   `svelte/store`. The reference spec asks for runes. Pick one deliberately and
   record why; do not leave two routing idioms without a reason.
6. **Unsaved edits.** Back and forward can now leave `CampaignEditor` or
   `WorkshopEditor`. If either guards unsaved changes today, that guard must also
   cover hash navigation.

## Acceptance criteria

1. Every admin screen, including a specific campaign or workshop, has a hash URL,
   and loading that URL in a fresh tab shows that screen.
2. Reloading on any admin screen returns to the same screen.
3. Back and forward step through admin screens one at a time, the UI updates, and
   the scroll position does not jump unexpectedly.
4. Admin navigation uses real `<a href="#/…">` links, so middle-click, cmd-click,
   and "copy link address" produce working `/admin#/…` URLs. The nav keeps
   `aria-current="page"` on the active screen.
5. An empty hash normalizes to Overview with `replace`, adding no history entry.
   An unknown hash (`#/nope`), a malformed id (`#/campaigns/abc`), and a deleted
   record each show a not-found or empty state, with no crash and no redirect
   loop.
6. A signed-out visit to a deep admin link goes to login, then back to that
   screen after signing in.
7. **One source of truth.** `section`, `activeCampaignId`, `activeWorkshopId`,
   and `pendingOpenCampaignId` no longer decide which screen shows; the hash
   does. Cross-screen jumps become navigations. Local state such as scroll or
   form input may stay.
8. Screen changes within admin have a deliberate, recorded behaviour for the page
   title and focus (`#0238`), with no double announcement.
9. Nothing else regresses: the skip link works on `/admin` and public pages;
   public path routing, back/forward scroll restoration, and
   `appNavigationFocus.structuralGuard.test.ts` are unchanged; the live-region
   guard still passes after `Admin.svelte`'s branches change.
10. **No Go changes**, unless verification shows a hashed `/admin` URL fails to
    load the SPA.
11. Tests: unit tests for hash parsing and matching (params, query, trailing
    slash, unknown routes); a jsdom test mounting admin at a given hash and
    asserting the screen; a test that the router's click interceptor leaves
    `#/…` links and `#main-content` alone.
12. **Checked in a real browser** for what jsdom cannot show: reload, back and
    forward, cmd-click, and copied links. Say which claims rest on which.
13. `scripts/check.sh web` passes.

## Out of scope

- Public routes, which keep path-based routing.
- Nested layouts and route transitions.
- Moving admin to path-based routes, which would need Go route-table changes.
