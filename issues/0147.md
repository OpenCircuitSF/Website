## Description

Two small, related defects `#0139`'s review found while confirming that issue's fix.

**1. Whitespace is not empty.** `normalizeOptionalCampaignField` compares `*v == ""` without trimming, so a value of `"   "` is stored rather than cleared. The workshop editor trims client-side and so never sends one, but `CampaignEditor.svelte` sends `preheader` straight from `bind:value`, untrimmed — so a preheader left as spaces is persisted and then reloads looking blank. The real blanking gesture yields exactly `""`, which is why this is narrow rather than serious.

Trimming inside `normalizeOptionalCampaignField` (`strings.TrimSpace(*v) == ""`) fixes both editors at once and matches what `parseOptionalTime` already does.

**2. A comment that is simply wrong.** The comment added at `CampaignEditor.svelte:384` says it sends "the trimmed value". It does not trim.
