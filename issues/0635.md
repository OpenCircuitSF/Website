## Description

Found in `#0626`'s review. This is the most direct remaining gap against the user's complaint in `#0622`: "far easier to distinguish between posts for announce, reminder and final".

1. `draftParts` gives Instagram, TikTok and YouTube one lead regardless of section, so a Final post has no last-chance wording and only its link differs.
2. Hand-posted rows show no date. The strip gives the automatic time and `3 left to post by hand`, but a Reminder video row does not say when to post it.
3. The Video group starts about 1,430 px down at 1280 px wide and 1,900 px at 390 px, below the Bluesky and Mastodon previews, and rows are about 350 and 590 px tall.

## Root cause

`draftParts` gave the three hand-posted channels one lead whatever the section, so a Final post differed from an Announce only in its link. A hand row's status line was a fixed `Post by hand: copy and paste`, with no day in it. The Video group sat below the previews with nothing leading to it, and the link row, character count and stacked buttons made each row tall.

Followed the plan, with these differences:

- **Reminder lead (orchestrator's change at dispatch):** `Coming up: T at V on D.`, undated `Coming up: T at V.`, not `One week to go until…`. So `handLead`'s reminder case is one line. The dispatch said the plan stated `One week to go` was kept at the orchestrator's request; no such sentence is in the plan, so there was nothing of that kind to strike.

2. **Final says the date, not `tomorrow`.** A hand post has no fixed day and a video caption stays up, so `tomorrow` would become false. Bluesky and Mastodon keep theirs, since they are scheduled.

3. **Getting new wording on an existing draft is one row at a time, by hand, and nothing is saved until Save.** See "Existing drafts" below. This adds one response field and one editor button.

5. **The row says `Aim to post…` and gives a day, never a clock time.** A day plus an instruction to the person cannot read as an automatic schedule; `Posts automatically` stays reserved for what the site sends. This line replaces `Post by hand: copy and paste` on the row, since the group heading already says it, so it adds no height.

6. **`.hand-text`'s `tabindex` stays.** Making it conditional needs a `ResizeObserver` to stay right when the width changes, which jsdom cannot test, so it is not small. Report this as left alone. ### Existing drafts

What the code does, checked on 2026-11-05:

- `Fingerprint` hashes the event's facts, not the template. New wording therefore marks nothing stale: no `(stale)` and no warning on deploy. **Leave `Fingerprint` alone.**
- `DraftAll` and **Write it** fill only empty slots, `Prepare` only fills in the link, and nothing else rewrites a body. So `hack-night`, `programming-leds-2` and every other row keep their text until the user acts. No data change is part of this issue.
- Editing a hand row **never** sets `customized`, because only the Customize… path passes `markCustomized`. So that flag cannot protect a hand post, and the safety here cannot rest on it.
- `Regenerate` saves at once. It shows only on a stale post. Today that would silently overwrite a hand-edited video post, and it would be the only route to the new wording.
- **Delete** then **Draft** also gets the new wording and keeps the slot's link, but discards the text at once. It is not the path to recommend.

**What the user does:** on the row, press **Edit**, then **Use the standard wording**. The box fills with the current wording and the link. **Save** applies it; **Cancel** then **Discard changes** returns to the saved text, unchanged. Customized text is lost only if the user presses Save after seeing the replacement in the box, and only on that row.

```ts
/**
 * When to post a hand-posted row (#0635): the section's first automatic post
 * still to come, else its suggested day. A day and an instruction, so it never
 * reads as something the site will send.
 */
export function handPostWhen(view: Pick<WorkshopOutreach, 'channels' | 'waves' | 'posts'>, wave: string, now: Date = new Date()): string {
  const scheduled = view.posts
    .filter((p) => p.wave === wave && p.status === 'scheduled' && p.scheduled_at && !p.held && view.channels.some((c) => c.name === p.channel && sendsItself(c)))
    .map((p) => p.scheduled_at as string)
    .sort()[0];
  const iso = scheduled ?? view.waves.find((w) => w.name === wave)?.suggested_at ?? null;
  const day = iso ? toPacificInput(iso).slice(0, 10) : '';
  if (!iso || !day) return 'No set day: post when you are ready.';
  const label = formatPacificWeekday(iso);
  const today = toPacificInput(now.toISOString()).slice(0, 10);
  if (day < today) return `The day for this was ${label}. Post it soon if it still helps.`;
  const alongside = scheduled ? ', with the automatic posts' : '';
  return day === today ? `Aim to post today${alongside}.` : `Aim to post on ${label}${alongside}.`;
}

export function sectionVideoId(name: string): string {
  return `outreach-section-${name}-video`;
}

/** The link to a section's Video group, '' when the section shows none. Counted as the rows are: an off channel with no post has no row. */
export function videoJumpLabel(view: Pick<WorkshopOutreach, 'channels' | 'posts' | 'off_channels'>, wave: string): string {
  if (!view.posts.some((p) => p.wave === wave)) return '';
  const inSection = (name: string) => view.posts.find((p) => p.channel === name && p.wave === wave) ?? null;
  const rows = view.channels.filter((c) => isVideoChannel(c) && (inSection(c.name) !== null || !(view.off_channels ?? []).some((o) => o.name === c.name)));
  if (rows.length === 0) return '';
  const left = rows.filter((c) => inSection(c.name)?.status !== 'posted').length;
  return left === 0 ? 'Go to Video: all posted' : `Go to Video: ${left} left to post`;
}
```
