## Description

`Site.InvalidateWorkshops` (`internal/seo/site.go:34`) and
`Renderer.InvalidateWorkshops` (`internal/seo/seo.go:527`) both still say they
are called "on workshop mutation (`#0051`)".

Since `b575867` (`#0319`) they also serve the **campaign archive toggle** and the
**send worker**. And `internal/mailing`'s new `ArchiveCacheInvalidator` declares
a method literally named `InvalidateWorkshops` — in a package that has nothing to
do with workshops.

**The behaviour is correct.** `#0319`'s reviewer verified it clears the whole
renderer cache plus the sitemap, so archive entries are covered — which is *why*
`#0319`'s fix works at all. Only the name and the comments lie.

That matters here more than it usually would: an agent reading
`ArchiveCacheInvalidator.InvalidateWorkshops` has to discover by experiment that
it clears campaign entries too, and the natural reading — "this is the wrong
invalidator, the archive needs its own" — leads to a second cache-clearing path
nobody needs.

## Acceptance criteria

1. Rename to `Invalidate()` across `internal/seo` (`Site` and `Renderer`),
   `internal/handlers`' `workshopCacheInvalidator`, and
   `mailing.ArchiveCacheInvalidator`.
2. Update all three doc comments to say what the method actually does — clears

3. Keep the `#0051` citation as history rather than deleting it; the method was

   report what you found even if nothing.
6. `ISSUE=NNNN scripts/check.sh go ./internal/seo/... ./internal/handlers/... ./internal/mailing/... ./cmd/opencircuit/...`
   passes with no skips.

## Root cause

`InvalidateWorkshops` was named and documented for its sole original caller
(#0051's workshop mutation handlers). `#0319` (`b575867`) gave the same
method — through `Site.Invalidate`, unchanged — two more callers
(`AdminCampaignArchiveHandler`'s campaign archive toggle, and
`mailing.Worker`'s send-completion archive-publish transition) without
touching the name or any of the doc comments that described it as
workshop-only. The behavior was already correct; only the name and prose
were stale.

## Fix

Renamed the method to `Invalidate()` at every definition and call site:

- `internal/seo/site.go` — `Site.InvalidateWorkshops` → `Site.Invalidate`
- `internal/seo/seo.go` — `Renderer.InvalidateWorkshops` → `Renderer.Invalidate`
- `internal/handlers/admin_workshops.go` — `workshopCacheInvalidator`'s
  method, and both call sites (`AdminWorkshopsHandler.invalidate`,
  `AdminCampaignArchiveHandler.invalidate` in `admin_campaign_archive.go`)
- `internal/mailing/worker.go` — `ArchiveCacheInvalidator`'s method, and
  `Worker.invalidateArchiveCache`'s call site
- Two test doubles: `countingWorkshopInvalidator.InvalidateWorkshops` and
  `countingArchiveInvalidator.InvalidateWorkshops`, both → `Invalidate`
- Two test names that cited the old method name in their own identifier:
  `TestRender_InvalidateWorkshopsBypassesCacheImmediately` →
  `TestRender_InvalidateBypassesCacheImmediately`,
  `TestSite_InvalidateWorkshopsClearsBothCaches` →
  `TestSite_InvalidateClearsBothCaches` (neither name is cited from any
  other file, confirmed by `grep` before renaming, so no dangling citation
  was created)

Rewrote every doc comment the method appears in (`Site.Invalidate`,
`Renderer.Invalidate`, `Sitemap.Invalidate`'s cross-reference,
`workshopCacheInvalidator`, `ArchiveCacheInvalidator`, and the package-level
mentions in `internal/seo/seo.go`'s doc comment and `defaultCacheTTL`'s) to
state what the method actually does today — clears the renderer cache and
the sitemap, covering workshops, the campaign archive, and the send
worker's own transition — and to name all three live callers. Kept the
`#0051` citation in every comment as history (criterion 3) rather than
deleting it, and added "(named InvalidateWorkshops until #0325)" at each
site so a reader who finds the old name in a stale branch, an old commit
message, or their own memory can trace it forward.

**No behavior change.** `git diff` (`git diff --stat -- internal/seo
internal/handlers/admin_workshops.go internal/handlers/admin_workshops_test.go
internal/handlers/admin_campaign_archive.go internal/mailing/worker.go
internal/mailing/worker_test.go cmd/opencircuit/seo_wiring_test.go`) shows only
renames, comments, and call sites across 11 files — no SQL, no control

### Criterion 4 — "purely mechanical" proved structurally, not by diff filtering

The task explicitly ruled out `git diff | grep -v '^[+-]#'`, so the claim was
proved two independent ways, both operating on the parsed file rather than on
its text:

1. **Token-stream equivalence.** Each file at `f7771ed^` and `f7771ed` scanned
   with `go/scanner` (comments skipped), the rename map applied, and the token
   streams hashed.
2. **AST equivalence.** Each file parsed with `parser.ParseFile(..., 0)`,
   every `*ast.Ident` named `InvalidateWorkshops` renamed, `f.Comments` set to
   `nil`, printed with `format.Node`, and hashed.

Both agree, and both hashes are **equal old-vs-new for all six non-test
files** (`internal/seo/{seo,site,sitemap}.go`,
`internal/handlers/{admin_workshops,admin_campaign_archive}.go`,
`internal/mailing/worker.go`). That comment stripping actually happened was
checked directly (`af.Comments == 0`, `af.Doc == nil` for all 11 files,
against 38–721 comment tokens in each source) rather than by grepping the
output for `//`.

**A stronger result than the criterion asks for.** The comparison was re-run
with an *empty* rename map, which enumerates every changed token exhaustively
instead of proving equivalence under an assumed map. The complete change set
across all 11 files is **14 IDENT tokens and 3 STRING tokens, and nothing
else** — no other identifier, no operator, no literal. This closes the blind
spot inherent in any rename map (collapsing `InvalidateWorkshops`→`Invalidate`
would hide a swap between the two on a type owning both; no type owned both at
the parent commit, verified with `go/types`).

`cmd/opencircuit/seo_wiring_test.go` and `internal/seo/sitemap.go` are
**identical even un-renamed** — their changed lines are comments only.

The three STRING residuals are all `t.Error`/`t.Fatalf` failure messages
tracking the rename, enumerated exactly: `seo_test.go` L621, `site_test.go`
L266 and L269. Zero behavioural residuals.

### Criterion 3 — a NEW interface satisfier, reported not blocked

The task's specific worry — "a rename that shortens an identifier is exactly
how an accidental interface satisfaction happens in Go" — turns out to be
justified. Checked empirically with `go/types.Implements` against the real
package at both revisions, not textually:

| type | before (`InvalidateWorkshops()`) | after (`Invalidate()`) |
|---|---|---|
| `*seo.Site` | ✅ | ✅ |
| `*seo.Renderer` | ✅ (already) | ✅ |
| **`*seo.Sitemap`** | ❌ | ✅ **NEW** |

`*seo.Sitemap` already had an `Invalidate()` method; it gained nothing — the
two one-method interfaces (`handlers.workshopCacheInvalidator`,
`mailing.ArchiveCacheInvalidator`) **moved onto it**. Passing a `*seo.Sitemap`
to `NewAdminWorkshopsHandler`, `NewAdminCampaignArchiveHandler`, or the
worker's `archiveCache` was a compile error before this commit and compiles
silently after — and would clear only the sitemap cache, leaving the per-path
meta cache stale.

**No behaviour change today**, so criterion 4 stands: nothing in the tree
passes a `Sitemap` to any of those seams. Two facts keep it from being a
bounce: `*seo.Renderer` was *already* a satisfier before this commit (the
mirror-image half-invalidation risk is pre-existing, not introduced here), and
`#0326`'s guard — landing one commit later — pins argument *identity* inside
`servePostgres`, so a `Sitemap` substitution there now fails a test. Recorded
as a follow-up recommendation in the reviewer's report; the commit message
should have mentioned the widened type-level blast radius.
