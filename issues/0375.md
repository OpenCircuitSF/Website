## Description

`#0366` added a second-identifier count/reason pair to
`claimCommentGuardDirectionalCalibrationCases`, gated on `c.secondIdent != ""`.

**A future row that sets `wantSecondIdentFindings: 1` but forgets
`secondIdent` asserts nothing and passes.**

**Latent today**: no such row exists, and both assertions are live on the one
row that uses them — `#0366`'s reviewer verified the pair fires in both
directions on that row, including a reason-only mutation.

This is the family's signature failure one more time: an assertion that passes
because it never ran. `#0358` shipped a row whose fixture never entered the
axis; `#0363` shipped one whose fixture always fired; `#0364` exists because a
row can get its number for the wrong mechanism. This is the **skipped**
variant.

## The recommendation this issue carries

`#0366`'s reviewer recommended **recording, not closing**, and named the cost:
the one-`if` fix would be a **seventh in-file check** in a file `#0258`'s
caution now binds explicitly — six mechanisms already, each new one fresh
mutable surface.

**So the default deliverable is one honest sentence.** If a pass believes the
guard earns its place, it must argue why this differs from `#0330`, `#0347` and
`#0356`, which all ended by refusing exactly this trade — and be prepared for
the argument to be rejected.

There is a cheaper third option worth weighing: state the invariant in the
struct's own doc comment so the omission is visible at the point of authoring a
row, rather than adding a runtime check.

## Acceptance criteria

1. The gap is recorded where a row author meets it — on
   `claimCommentGuardDirectionalCalibrationCase`'s field documentation — saying
   plainly that `wantSecondIdentFindings` and `wantSecondIdentReason` are
   **only asserted when `secondIdent` is non-empty**, and that setting them
   without it asserts nothing.
2. The record is **re-verified, not transcribed**: construct such a row in a
   throwaway export, confirm it passes while asserting nothing, and confirm the
   existing row's pair still fires in both directions. Five issues this phase
   received a wrong identifier because prose was transcribed as though measured.
3. **If you add the check anyway**, it must discriminate: prove the
   forgotten-`secondIdent` row now fails, naming it, and prove no existing row
   changed behaviour.
4. The axis stays frozen (`#0358` criterion 4).
5. No `.ClaimDue(` / `.OrphanSweep(` / `.SelectDue(` call-syntax literal enters
   any Go comment; floor harness stays **42 total / 12 non-exempt** (`#0323`);
   `gofmt` stability.
