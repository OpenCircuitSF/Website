## Description

The `email_campaigns`, `campaign_interests`, and `email_sends` tables, including the uniqueness constraint that makes sending idempotent.

## Acceptance criteria

- [ ] Tables exactly per PRD §6.2
- [ ] `email_sends` has `UNIQUE (campaign_id, subscriber_id)` — the idempotency guarantee
- [ ] Partial index on queued sends, plus an index on `ses_message_id`
- [ ] `email_campaigns.workshop_id` FK added by a later `ALTER TABLE` (Phase 6) so Phase 5 stays independently deployable
- [ ] Status values constrained: draft, scheduled, sending, sent, canceled, failed
- [ ] `audience_mode` constrained: all, any_of, all_of, none_selected
- [ ] Down migration drops cleanly
- [ ] `go test ./internal/mailing/...` passes against a real database

## Carried in from `#0044`'s plan (2026-08-21)

`#0044` materializes the campaign audience into `email_sends`, which this issue
creates. Four requirements land here, and each is expensive to add later:

- [ ] **`email_sends.status`'s `CHECK` must include `skipped`.** `#0044`
      re-checks eligibility inside the transaction that claims each batch: a
      recipient who was eligible at materialization but has since unsubscribed
      or been suppressed becomes `skipped` and is never mailed. `skipped` is
      already in PRD §6.2's enum. If it is omitted here, `#0044` has to ship an
      `ALTER TABLE` migration to add it.
- [ ] **`UNIQUE (campaign_id, subscriber_id)`** — the idempotency key that makes
      re-running materialization safe.
- [ ] **`idx_email_sends_queued ON (campaign_id, id) WHERE status = 'queued'`** —
      the partial index the send worker's claim query needs.
- [ ] **`campaign_interests` with `ON DELETE CASCADE`.**
- [ ] **The materialization insert must never be given a `DO UPDATE` clause.**
      `ON CONFLICT DO NOTHING` is required; `DO UPDATE` would create a documented
      path from `sent` back to `queued`, i.e. a double-send.

## Notes

PRD §6.2 and its migration-ordering note. `workshops` does not exist until Phase 6, so the `workshop_id` foreign key cannot be declared here — add the column now (nullable, no FK) and attach the constraint in #0050.

The `UNIQUE (campaign_id, subscriber_id)` constraint is what guarantees a crashed and restarted send can never double-deliver. It is the single most important line in this migration.
