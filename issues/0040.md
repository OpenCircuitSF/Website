## Description

The `email_campaigns`, `campaign_interests`, and `email_sends` tables, including the uniqueness constraint that makes sending idempotent.

## Acceptance criteria

- [ ] Tables exactly per PRD §6.2
- [ ] `email_sends` has `UNIQUE (campaign_id, subscriber_id)` — the idempotency guarantee
- [ ] Partial index on queued sends, plus an index on `ses_message_id`
- [ ] `email_campaigns.workshop_id` FK added by a later `ALTER TABLE` (Phase 6) so Phase 5 stays independently deployable
- [ ] Status values constrained: draft, scheduled, sending, sent, canceled, failed
- [ ] `audience_mode` constrained: all, any_of, all_of, none_selected
- [ ] Down migration drops cleanly
- [ ] `go test ./internal/mailing/...` passes against a real database

## Notes

PRD §6.2 and its migration-ordering note. `workshops` does not exist until Phase 6, so the `workshop_id` foreign key cannot be declared here — add the column now (nullable, no FK) and attach the constraint in #0050.

The `UNIQUE (campaign_id, subscriber_id)` constraint is what guarantees a crashed and restarted send can never double-deliver. It is the single most important line in this migration.
