## Plan
1. `internal/apitokens`: add `ScopeOutreachRead = "outreach:read"`, `ScopeOutreachWrite = "outreach:write"`, `ScopeMediaRead = "media:read"`, `ScopeMediaWrite = "media:write"`, and append them to `KnownScopes`.
2. `migrations/000056_api_tokens_outreach_scopes.{up,down}.sql`: drop `api_tokens_scopes_check` and re-add it with the full set, the same way `000053` widened it. The down migration restores 000053's set. Copy 000053's down shape, including how it handles rows that hold the new scopes. `TestLatestScopesMigrationFollowsAWidening` (`internal/db/api_tokens_v2_migration_test.go`) already finds the latest widening, so check it passes without changes.
3. `web/src/lib/apiTokens.ts`: add `SCOPE_*` constants; add `SCOPE_GROUPS` rows `Outreach` (read and write) and `Media` (read and write); set `AGENT_PRESET` to every scope (engagement:read, guides:read, guide_posts:read/write, events:read/write, venues:read, outreach:read/write, media:read/write); add `READONLY_PRESET` = every `:read`. Wire a "Read-only" preset button wherever `AGENT_PRESET` is used today (`grep -rn AGENT_PRESET web/src`).
4. Tests: `internal/apitokens` (the shape test covers it); `internal/db` `TestAPITokenScopesMatchWeb` and `TestAPITokenScopesMatchMigration`; a web unit test asserting that `AGENT_PRESET` equals `KNOWN_SCOPES` and `READONLY_PRESET` equals every `:read` scope.
