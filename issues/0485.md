## Description

`web/tsconfig.json`'s `include` is exactly:

	"include": ["src/**/*.ts", "src/**/*.svelte"]

`web/vite.config.ts` is not under `src/`, so it is outside that glob and no
other tsconfig picks it up. **`npm run check` type-checks nothing in it.**

That was harmless while the file was declarative. It is not declarative any
more: `#0408` added `spaNavigationBypass`, a predicate with a `GET`/`HEAD`
gate, a path allowlist, query-string stripping, and header inspection, whose
correctness decides whether a browser navigation reaches Vite or Go. A silent
mistake there produces a **blank page** — the exact symptom `#0408` existed to
fix, and one that reads as a broken build rather than a type error.

## It has now mattered twice

- Flagged once on the abandoned worktree branch during `#0408`'s original
  review there, and left untracked.
- Flagged again by `#0408`'s review on `main`, which verified the gap itself
  rather than repeating the earlier claim.

Both times it was noticed while reviewing changes *to that very file*. That is
the tell: the only thing catching mistakes in it is human attention, applied at
exactly the moments when the file is being changed and least stable.

## What makes it worse than an ordinary uncovered file

`#0408`'s predicate is exercised only by `vite dev`. It is absent from the
production build — the built SPA is served by Go from one origin with no proxy —
so **no test in the suite runs this code**, and `vite build` output was
measured byte-identical before and after the change. Type-checking is the only
static signal available, and it is switched off.

## Acceptance criteria

1. **Bring `web/vite.config.ts` under type checking.** Options include adding it
   to `include`, adding a second tsconfig for build-time files, or a
   `tsconfig.node.json` of the shape Vite's own templates use. Pick one and say
   why.
2. **Prove it is actually checked afterwards.** Introduce a deliberate type
   error in that file, confirm `npm run check` fails and names it, then remove
   it and confirm the file is byte-identical (SHA-256 before and after). A check
   never seen to fail is not a check (`CLAUDE.md` §8).
3. **Do not break the existing check.** `npm run check` currently reports 293
   files with 0 errors and 0 warnings; whatever you change must leave it clean.
   If widening the glob surfaces pre-existing errors in other unchecked files,
   report them rather than silencing them — and say whether fixing them belongs
   here or in a separate issue.
4. **Check for siblings.** Other root-level config files (`svelte.config.js`,
   `vitest` setup, any script under `web/`) may be in the same position. Name
   them; do not necessarily fix them in this pass.
5. **Do not run `npm run build`** (`CLAUDE.md` §8b) — it overwrites the tracked
   `web/dist/index.html` placeholder, which three agents have already hit. If
   you must, restore with `git show HEAD:web/dist/index.html > web/dist/index.html`,
   never `git checkout` (§8a).

## Relation

- `#0408` put real logic into the unchecked file; both its reviews flagged this.
- `CLAUDE.md` §1 records that SPA logic belongs in `web/src/lib/` so it is
  unit-testable — this file is the case where that is not possible, since the
  predicate only exists under `vite dev`.
