## Description

Replace ShortLinks' GitHub-style palette with the Open Circuit terminal palette in **both light and dark**, driven by `prefers-color-scheme` with an explicit `data-theme` override. A working reference implementation exists in `placeholder/index.html`.

## Acceptance criteria

- [x] Both token sets from PRD §4.2 defined with the exact values given
- [x] Light on bare `:root`; dark restated under `@media (prefers-color-scheme: dark)` guarded by `:root:not([data-theme="light"])`, and again under `:root[data-theme="dark"]`
- [x] `color-scheme: light dark` on `:root` and `<meta name="color-scheme" content="light dark">` in `index.html`
- [x] Blocking inline script in `<head>` applies the stored theme before first paint — no flash of the wrong palette
- [x] Theme toggle cycles auto → light → dark; auto removes the attribute rather than pinning the current OS value
- [x] Choice persisted in `localStorage`, wrapped in try/catch (Safari private mode throws)
- [x] Focus rings use `--accent`, not `--border-strong` — the latter is under 3:1 in both themes
- [x] Contrast re-measured and matching the table in PRD §4.2
- [x] Spacing (`--space-1`..`--space-6`), radius, border width, and type scale tokens retained
- [x] Font tokens point at the self-hosted families from #0012
- [x] `body` sets an explicit `--bg-page` background and `--text` color
- [x] Global form control, table, and `.field` styling restated against the new tokens with no literal hex left outside `:root`
- [x] `Panel.svelte` and `Button.svelte` render correctly with no per-component color changes

## Notes

PRD §4.2. Port the token block, the toggle script, and the motif CSS from `placeholder/index.html` — it is already validated in both themes at 305 px, 390 px, and desktop widths.

Light mode is designed as a *printed listing*, not an inverted dark theme: paper-white panels, near-black text, deep green accent, same prompt / `[ OK ]` / cursor motifs. The motifs carry the identity, not the darkness.

Two rules that are easy to get wrong and expensive to retrofit:

**Body copy uses `--text`, never `--accent`.** Green is for prompts, `[ OK ]` rows, links, labels, and short status lines. Long paragraphs of saturated green on black are physically tiring to read.

**No literal hex outside `:root`.** ShortLinks accumulated stray hex values in components that had to be hunted down and tokenized later when dark mode was added. Start clean.

Every interactive control needs a visible focus ring at `--border-strong` or `--accent` — never signal state by color alone.

## Root cause

Not a bug — feature work. `web/src/app.css` still carried ShortLinks' GitHub
Primer-style token set (blue accent, light-only) unchanged from the source
skeleton; the site needs the Open Circuit terminal palette, dark-mode support,
and a manual theme override, all of which `placeholder/index.html` already
validates.

## Fix

Replaced the `:root` token block in `web/src/app.css` with the PRD §4.2 values
in both themes, using the three-block structure the PRD mandates (bare
`:root` = light; `@media (prefers-color-scheme: dark)` guarded by
`:root:not([data-theme="light"])`; `:root[data-theme="dark"]` restated). Kept
every custom property the existing views (`Login`, `Account`, `Admin`,
`RegisterVerify`, `RecoverVerify`, `Panel.svelte`, `Button.svelte`) already
reference — `--fs-sm/base/md/lg/xl`, `--border-w`, `--lh`, `--space-1..6`,
`--radius` — unchanged in value, and non-PRD color tokens (`--success`,
`--success-subtle`, `--danger-subtle`, `--danger-hover-bg`, the reserved
`--series-*` chart slots) retained with values fitted to the new palette
rather than deleted, so nothing outside this issue's scope broke. `--success`
resolves to `var(--accent)` rather than a second green, matching the
PRD's `[ OK ]`-is-accent status language.

Added `web/src/lib/theme.ts` — the toggle's cycle/apply/read logic as
DOM-injectable pure functions (`ThemeRoot`/`ThemeStorage` interfaces a real
Element/localStorage satisfy), following the existing `events.ts` pattern so
it's unit-testable without jsdom (the project has none configured). The
button that calls it is `#0017`'s job (site header, next batch); this issue
delivers the tested logic plus the blocking inline `<head>` script in
`web/index.html` that applies any stored theme before first paint.

Added a global `:where(a, button):focus-visible { outline: 2px solid
var(--accent); }` rule and a base `a { color: var(--accent) }` rule — neither
existed before; buttons had no explicit focus ring and would have fallen back
to the browser default (not token-driven, and not guaranteed to be
`--accent`).

`--font`/`--font-mono` now name `'Archivo'`/`'JetBrains Mono'` with the
fallback stacks `#0012` specifies (`ui-sans-serif, system-ui, sans-serif` and
`ui-monospace, SFMono-Regular, Menlo, monospace`). No `@font-face` rules exist
yet — that's `#0012` — so until that lands the browser renders the fallback
stack, which is expected and not a regression (nothing rendered by port
Archivo/JetBrains Mono before this issue either).

Deviation from the notes: did not port the motif CSS (`.terminal`, `.prompt`,
`.status`, `.cmdline`/`.cursor`, `.dot`) into `app.css`. `#0013` builds those
as five Svelte components with their own scoped `<style>` blocks per its own
acceptance criteria, and `#0011`'s acceptance criteria don't require them in
the global stylesheet — keeping them out of `app.css` avoids dead global CSS
until `#0013` lands.

Independently re-verified 2026-08-18 (phase 3, Opus).

**Contrast recomputed from the committed `app.css` hex values**, not taken from
the implementer's table — WCAG 2.1 relative luminance, each foreground against
`--bg-page` / `--bg-panel` / `--bg-subtle`:

| Foreground | Light | Dark |
|---|---|---|
| `--text` | 15.80–18.60 | 14.35–16.80 |
| `--text-muted` | 6.44–7.58 | 6.67–7.81 |
| `--text-faint` | 4.82–5.67 | 4.78–5.60 |
| `--accent` | **4.39**–5.17 | 12.65–14.80 |
| `--accent-hover` | 6.57–7.73 | 13.12–15.36 |
| `--accent-dim` | 1.84–2.16 | 4.84–5.66 |
| `--border-strong` | 2.64–3.11 | 2.63–3.08 |
| `--accent-text` on `--accent` | 5.17 | 14.80 |

`CLAUDE.md` §8's two anchor figures reproduce exactly: `#68FF23` on `#0A0D0B`
= 14.80, on `#FFFFFF` = 1.32. `--border-strong` confirmed under 3:1 in both
themes, so the focus-ring rule is correctly grounded; `:where(a,
button):focus-visible` uses `--accent` (4.39–5.17 light, 12.65–14.80 dark —
clears 3:1 in both).

**One pre-existing PRD imprecision, not an implementation defect.** Light
`--accent` on `--bg-subtle` measures **4.39:1**, marginally under the 4.5:1
body-text threshold. PRD §4.2's own table publishes this as "4.4–5.2 ✅". The
token values here are the PRD's verbatim, so this is inherited, and it is not
a live defect while §4.2's non-negotiable rule holds — `--accent` carries
links, labels and short status lines, never body copy, and clears 4.5:1 on
`--bg-page` and `--bg-panel`. Flagged so a future issue that puts small
`--accent` text on an `--bg-subtle` fill knows it is at the line. PRD §4.2's
published `--text-faint` light upper bound (5.2) is also low; the measured
value is 5.67, i.e. better than advertised.

**Verified independently:** zero hex literals anywhere in `app.css` after the
three token blocks (scripted check); `body` sets `--bg-page`/`--text`;
`color-scheme: light dark` on `:root` plus the matching `<meta>`; the blocking
`<head>` script; `theme.ts`'s auto → light → dark cycle with "auto" removing
the attribute, and the `localStorage` try/catch. Re-ran the full suite: 179
files 0 errors (`svelte-check`), 74/74 vitest, clean `go build`/`go vet`, all
9 Go packages `ok` with real durations and zero skips under
`TEST_DATABASE_URL`.

**Corrected in place:** `## Files changed` claimed `theme.test.ts` carries 18
tests; it carries 13 (`npx vitest run src/lib/theme.test.ts`), which is what
the same section's own mutation-testing paragraph reports ("back to 13/13").

**Minor, not blocking — carried forward to form work.** `input`/`select`/
`textarea` set `outline: none` and signal focus with a `border-color:
var(--accent)` change plus an `--accent-subtle` glow. The border change clears
3:1 so this is conformant, but it is a weaker indicator than the 2px `--accent`
outline `a`/`button` get, and `:where(...)`'s zero specificity means any
component rule setting `outline` silently wins. `summary` and custom
`[tabindex]` elements are not covered by either rule and fall back to the UA
default.
