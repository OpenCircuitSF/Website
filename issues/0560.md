# 0560 — Flyer full-photo: long label tokens can overflow, and the text box has no color-mix fallback

## Description

From `#0559`'s review, in `web/src/views/admin/FlyerFace.svelte`:

1. `.fp-label` uses `overflow-wrap: normal`. Its hyphens are now non-breaking
   (U+2011), so a location name written as one hyphenated token longer than
   about 41 characters overflows the 2.4in label on the half layout. Names
   allow 100 characters.
2. `.fp-text` sets its fill only with `color-mix`. A browser without
   `color-mix` support drops the fill entirely, which leaves light text over
   the photo.

## Acceptance criteria

- [ ] `.fp-label` gets `overflow-wrap: anywhere`, so a label still breaks at spaces first and splits only a token that doesn't fit.
- [ ] `.fp-text` gets `background: rgba(11, 16, 10, 0.84);` on the line just before its `color-mix` background, so a browser without `color-mix` keeps the fallback.
- [ ] A jsdom or source-level test pins both declarations.
- [ ] Verified with `ISSUE=0560 scripts/check.sh web`.

## Relation

- Follows `#0559`.

## Resolution

`web/src/views/admin/FlyerFace.svelte`: `.t-full-photo .fp-label` now uses `overflow-wrap: anywhere` (was `normal`), and `.t-full-photo .fp-text` gets `background: rgba(11, 16, 10, 0.84);` on the line before its `color-mix` background. `FlyerFace.behavior.test.ts` gains a source-level describe block pinning both (jsdom does not apply the component's scoped styles).
