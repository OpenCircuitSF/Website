> 🟢 Resolved 2026-10-17 — the full-photo label breaks an over-long token with `overflow-wrap: anywhere`, the text box keeps an `rgba` fill in browsers without `color-mix`, and a source-level test that fails when either line is removed pins both.

## Review notes

2026-10-17, phase 3 (Opus): approved.

- **Fallback.** `background: rgba(11, 16, 10, 0.84);` sits directly before the `color-mix` line in `.t-full-photo .fp-text`. A browser that cannot parse `color-mix` drops only the second declaration and keeps the first. A browser that can parse it uses the second, since it comes later. The values match `FULL_PHOTO_BOX` in `web/src/lib/flyers.ts` (`#0b100a` is 11, 16, 10; alpha 0.84), so both paths paint the same fill.
- **Label sizing.** `overflow-wrap: anywhere` changes only the label's min-content size. Its max-content size stays the same. `.fp-qr` has `width: max-content; max-width: 100%`, so it still sizes to the wider of the QR image and the label's unbroken length (capped by the label's `max-width: var(--label-max)`). Nothing in that chain sizes from min-content, so the box can't collapse. A label still breaks at spaces first, and only a single token wider than `--label-max` gets split. This is the same declaration `.title`, `.short` and `.label` already use.
- **Test.** The new describe block reads `src/views/admin/FlyerFace.svelte` relative to the process cwd. That works because `scripts/check.sh web` runs `cd web && npm test`. Run from somewhere else, it throws ENOENT and fails loudly, so it can't pass by mistake. Sibling tests resolve from `import.meta.url` instead (see follow-ups).
- **Mutation.** The shared source was left untouched. I put copies under a scratch `src/views/admin/` and ran vitest from there with `--root web`, so the test read each copy through its cwd-relative path. Base copy: 10/10 passed. Line 307 changed from `anywhere` to `normal`: `.fp-label breaks an over-long token` failed. The `rgba` line deleted: `.fp-text has an rgba fallback…` failed. The live file's SHA-256 was the same before and after (`e2a3b631…e4a2`).
- **Verification.** Load average 5.72 (drained from 6.69 at start, nothing timing-sensitive involved). `ISSUE=0560 scripts/check.sh web`: 61 files, 4401 tests passed, VERIFICATION PASSED. `ISSUE=0560 scripts/check.sh go ./internal/db/...`: ok, no skips, VERIFICATION PASSED.
- **Follow-ups (not in scope).** (1) Build the test's path from `import.meta.url`, like `mountTarget.test.ts`, so it doesn't depend on cwd. (2) The `rgba` literal repeats `FULL_PHOTO_BOX`. The test could build the expected string from that constant, so a change to the fill can't leave the fallback stale without failing.

## Description

From `#0559`'s review, in `web/src/views/admin/FlyerFace.svelte`:

1. `.fp-label` uses `overflow-wrap: normal`. Its hyphens are now non-breaking
   (U+2011), so a location name written as one hyphenated token longer than
   about 41 characters overflows the 2.4in label on the half layout. Names
   allow 100 characters.
2. `.fp-text` sets its fill only with `color-mix`. A browser without
   `color-mix` support drops the fill entirely, which leaves light text over
   the photo.

## Acceptance criteria

- [ ] A jsdom or source-level test pins both declarations.
