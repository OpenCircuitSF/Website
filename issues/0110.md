# 0110 — `types.ts` still documents `soft_bounce_count` as a count of Transient-bounce rows

## Description

`web/src/lib/types.ts`'s doc comment on the `Subscriber` interface describes
`soft_bounce_count` as "the count of **Transient-bounce** `email_events` rows
within the currently configured window". After `#0109` (`8f900fe`) that is
wrong in both directions: the count also includes `Undetermined` bounces, and
it excludes the sender-fault `Transient` subtypes (`MessageTooLarge`,
`ContentRejected`, `AttachmentRejected`).

Documentation only — no behaviour is affected, and **this does not block Phase
4's deployable gate.** Filed because it is the same stale-label problem
`#0109` was itself filed to correct, one file over from the one `#0109` fixed.

## Root cause

`#0109` deliberately reworded the *user-facing* copy in
`web/src/lib/admin.ts` (`softBounceSummary`: "N transient bounce(s)" → "N soft
bounce(s)") and added a comment there explaining why, but did not sweep the
sibling type declaration that documents the same three fields. `types.ts` was
not in `#0109`'s touched-file set.

Current text, `web/src/lib/types.ts` lines 95–100:

```
 * `soft_bounce_count`/`soft_bounce_threshold`/`soft_bounce_window_days`
 * (#0039) are likewise populated by the detail endpoint only: the count of
 * Transient-bounce `email_events` rows within the currently configured
 * window, plus the threshold/window themselves so the screen can render
 * "N of THRESHOLD in the last WINDOW days" rather than a bare number. All
 * three are present together or absent together.
```

- [ ] The `(#0039)` attribution picks up `#0109` as the issue that widened it,

- [ ] `npm run check` and `npm test` still clean (comment-only change, so no
      assertion should move)
