## Description

`cmd/devmocks` (`#0580`) is the command wrapper around `internal/devmocks`. The
library package is tested (`main_test.go`, `mocks_test.go`, `seed_test.go`);
the command is not, so every `scripts/check.sh go` run that includes it prints
`cmd/devmocks [no test files]` in its skip audit. That line is noise that
trains readers to ignore the audit, and the command's own guards — `serve`
refusing a non-loopback `-addr`, `seed` refusing a non-local `DATABASE_URL`,
the usage and unknown-command exits — are covered only through the library
calls they delegate to, not through the command that wires them.

## Acceptance criteria

- [ ] `cmd/devmocks` has a `_test.go` that covers, at minimum: `serve` with a
      non-loopback `-addr` returns an error and binds nothing; `seed` with a
      non-local or empty `DATABASE_URL` returns an error before opening a pool;
      an unknown subcommand is an error.
- [ ] Testing these may need `main`'s dispatch split into a testable
      `run(args) error`; keep the binary's behaviour and exit codes unchanged.
- [ ] No test binds a non-loopback address or touches a shared database.
- [ ] `ISSUE=0610 scripts/check.sh go ./cmd/devmocks/... ./internal/devmocks/...`
      passes and its skip audit no longer lists `cmd/devmocks`. Editing a Go
      comment means `./internal/handlers/...` runs too (`AGENTS.md` §5).
