## Resolution

- **Migration 000041 (justification).** `outreach_posts.customized BOOLEAN NOT
  NULL DEFAULT false`, a new migration because `000032` is applied to
  production (frozen through `000040`). "Customized" cannot be derived: the
  Bluesky and Mastodon leads differ by design, so Mastodon would read as
  customized on first load; comparing to a re-rendered template breaks when the
  workshop summary changes; localStorage is per-browser. It must deploy before
  the binary that reads it (`scripts/deploy.sh` migrates first). `docs/database.md`
  and `AGENTS.md` carry the `000041` range. `scripts/testdb.sh template` rebuilt.
- **Go.** `Post.Customized` in every column list and scan (including
  `qualifiedPostColumns` and `LoadForSend`); `UpdatePostBody(ctx, id, body,
  fingerprint, customized)`: a regenerate clears the flag, a hand edit sets it
  only when `customized` is non-nil; `PATCH` accepts `customized` only with
  `body` (400 with `regenerate`), the audit metadata records it, `postView`
  returns it. Tests: store round trip and regenerate-clears, PATCH set / leave /
  400.
- **Page.** `OutreachWorkshop` is now summary, Announcement, Reminder and Last
  call rows, Schedule all, then collapsed "Post by hand" (non-automatic channels
  only, `OutreachPostCards channelFilter`), Flyers and "Links and clicks" rows
  (results line, View results, and the link-report warning). The tracked-links
  table and "Start outreach" screen are gone; the Reset button and dialog are
  untouched (its note now says "Write the announcement to start again").
- **Implicit start.** `OutreachPanel autoStart` (only the workshop page passes
  it) calls `startOutreach` once per workshop for an available workshop with no
  outreach; "Setting up links..." meanwhile; failure shows a warning and Try
  again, no loop; never for an unavailable workshop. GET stays read-only. The
  link report reaches the page through `onLoaded`.
- **`OutreachAnnouncement`.** One Message field (seeded from
  `sharedMessage`, re-seeded while not dirty); Save message writes
  `planSaveMessage` sequentially to every non-customized automatic post and
  reports skipped customized ones; disabled when unchanged or over a limit.
  "How it will look" shows each post (live preview of the unsaved message) with
  count/limit, status, Customize... (the existing composer with `markCustomized`,
  so Save sends `customized:true`) and Use shared message for customized posts.
  One post button through the Pass 1 dialog (`postAll` in
  `lib/outreachPostAll.ts`, shared with the list), Schedule for later... (one
  time for every postable post) and Unschedule. Empty state "No posts yet. Start
  with the announcement." with Write the announcement.
- **`OutreachWaveRow`.** Collapsed `<details>` with label, suggested time and
  `waveRowStatus`; Write it sits beside the disclosure and calls
  `draftAllOutreach(id, [wave])`, reloads and opens the row.
- **Removed.** Draft all, the "Also draft" checkboxes and the procedure
  paragraph (C10, E2, L2); `OutreachPanel`'s grid, cells and inline composer;
  the composer's Post now / Retry / Mark posted (and its Post URL field), the
  duplicate `<h3>`, and `lib/outreach.ts`'s `buildGrid` / `cellLabel` /
  `cellIsStale` with their tests. The composer's tracked link, "Goes to" and
  UTM chips now sit under "Link details" (G2). After this pass nothing posts
  without the dialog.
- **One summary.** `summaryLine` is used by the page and `OutreachEditorSummary`;
  empty state per L3; neither shows the campaign slug.
- **List-level result line.** `OutreachPostCards` keeps the posts the
  both-networks line reported on and shows it only while one of them still shows
  its notice (`visibleNotice`), so "queued" clears when polling brings back
  posted. The Announcement's post result line uses the same rule.
- **Deviations.** (1) The unused `OutreachLinks.svelte` (and its test) remain in
  the tree; the plan only said to remove it from this page, and Results has its
  own table. (2) Schedule picker for Announce has no suggested time, so it is
  empty until the admin picks one. (3) Customize... is disabled on the other
  cards while one composer is open instead of asking to discard.

## Review notes

- **Items 1 to 6 and the findings hold.** 1 (C1, F1 page half): `OutreachWorkshop` renders summary, Announcement, Reminder and Last call rows, Schedule all, then "Post by hand" (non-automatic channels only), Flyers and "Links and clicks". 2 (C2): the Start screen is gone; `OutreachPanel autoStart` calls `startOutreach` once per workshop (`autoStartTried`, non-reactive), only when `available && outreach === null`, shows "Setting up links…", and on failure a warning plus Try again with no loop (a reload re-runs `load()` but the guard holds). After `#0592`'s Reset the outreach row survives, so auto-start does not fire and the Announcement's empty state "Write the announcement" calls `draftAllOutreach(id, [])` and reloads; the Reset button and dialog are untouched. 3: Save message writes `planSaveMessage` sequentially; Customize… passes `markCustomized` so the composer saves `customized: true`; Use shared message sends `customized: false`. 4 (C10, E2, L2): Write it calls `draftAllOutreach(id, [wave])` and opens the row; Draft all, the "Also draft" fieldset and the procedure paragraph are gone; Schedule all and its dry-run dialog stay (§6). 5 (C6, C7, L3): `OutreachEditorSummary` uses `summaryLine`; no slug; empty state reads "No posts yet. Start with the announcement." 6 (G1, G2): the tracked-links table is off the page; the composer's link, "Goes to" and UTM chips sit under "Link details". C11 is moot with Draft all gone.
- **Migration `000041`.** Append-only, `ADD COLUMN customized BOOLEAN NOT NULL DEFAULT false` / `DROP COLUMN`; I ran `down 1` and `up` on a scratch database (column gone, then back as `false`/`NOT NULL`). `docs/database.md` and `AGENTS.md` carry the range and the row. Every `Post` read goes through `postColumns`/`scanPost` or `qualifiedPostColumns`/`LoadForSend`, all of which include `customized`; the engagement, results and reset queries scan their own structs and are unaffected. `UpdatePostBody` clears the flag on a regenerate (`$3 IS NOT NULL`) and otherwise `COALESCE`s the optional value; the handler rejects `customized` with `regenerate`.
- **Save message.** `splitBody` peels only trailing hashtag paragraphs and paragraphs holding `short_url` or `{link}`, and `composeBody` re-appends each post's own tail, so a save never drops Mastodon's link line or the hashtags. A message whose last paragraph holds the URL is kept too (it migrates into the tail on the next read: shown less in the field, never lost). Over-limit, unchanged or empty messages disable Save; customized, posted and queued posts are not targets, and the server refuses posted/queued edits regardless.
- **Posting.** The only `sendOutreachPost`/`markOutreachPosted` callers are `OutreachPostCard.confirmDialog` and `postAll`, which both run from `OutreachPostDialog`'s confirm; the composer no longer posts. Schedule for later uses the same `new Date(local).getTimezoneOffset()` resolution as the composer, so no zone regression ahead of `#0585`. The live-region structural guard, the modal guards and the no-native-confirm guard pass.
- **Fix (`70735c7`).** The Save status read "… are customized and was left alone" for two or more; now "were". Added tests: a message holding the URL plus an unprepared `{link}` tail through `planSaveMessage`, and Unschedule on the Announcement.
- **Mutation tests.** Removed `post.customized` from `messageTargets`: three tests failed (two unit, one behaviour); restored by copy, `web/src/lib/outreachMessage.ts` sha256 `f4e02133…76ba06` before and after. Made the regenerate keep `customized` in `UpdatePostBody`: `TestUpdateBodyFingerprintAndDelete` failed; restored, `internal/outreach/store.go` sha256 `1454bb8a…bba7a8` before and after.
- **Verification** (load 2.3 to 3.1): `ISSUE=0582R scripts/check.sh go ./internal/outreach/... ./internal/handlers/... ./cmd/opencircuit/... ./internal/db/...` passed, four packages `ok`, no skips, gofmt clean; the two new Go tests also run `-v` against a real database. `ISSUE=0582R scripts/check.sh web` passed: 80 files, 4618 tests. jsdom only; no browser was run.
- **Follow-ups, not blocking:** (a) Use shared message composes with the customized post's own tail, so a Customize that deleted Mastodon's link line stays linkless after hand-back; regenerating the tail (or `#0575`'s server-side Adapt) would restore it. (b) A message ending in a hashtag paragraph is peeled into the tail on the next read and can then only be removed through Customize. (c) A stale post's Regenerate prompt is only visible inside Customize…; the Announcement could show the stale warning itself. (d) `OutreachLinks.svelte` and its test are now unused (deviation 1).
