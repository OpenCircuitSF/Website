## Batch 2 from the review

*Closes:* C1, C2, C10, C11, F1 (page half), G1, G2, L2, L3, C6, C7, E2.
*Effort:* **L**. *Depends on:* Batch 1 for the dialog; pairs with Batch 3.

1. The workshop outreach page's default view is the Announcement section
   from §4.2: one **Message** field, per-network previews (Batch 3), one
   post button and one schedule link. Reminder, Last call, Post by hand,
   Flyers, and Links and clicks are collapsed rows with a status and one
   action each.
2. Start outreach is implicit: opening the page for an available published
   workshop (or the first Write / Print) creates the campaign and links;
   the "Start outreach to create the ShortLinks campaign…" screen and
   paragraph are gone; the link report, if anything failed, shows as a
   warning line.
3. **Save message** writes the shared text to every non-customized
   automatic card for that wave via `updateOutreachPost`; **Customize…**
   opens the existing composer for one card and marks it customized.
4. **Write it** on a collapsed wave calls `draftAllOutreach(id, [wave])`
   and expands it; the "Also draft" checkboxes are removed.
5. The editor's Outreach summary and the page's summary use one function
   (`summaryLine`) and neither shows the campaign slug.
6. The tracked-links table is removed from this page (it stays on Results);
   UTM chips and "Goes to" sit under a "Link details" disclosure in the
   composer.

## Resolution

- **Migration 000041 (justification).** `outreach_posts.customized BOOLEAN NOT
  NULL DEFAULT false`, a new migration because `000032` is applied to
  production (frozen through `000040`). "Customized" cannot be derived: the
  Bluesky and Mastodon leads differ by design, so Mastodon would read as
  customized on first load; comparing to a re-rendered template breaks when the
  workshop summary changes; localStorage is per-browser. It must deploy before
  the binary that reads it (`scripts/deploy.sh` migrates first). `docs/database.md`
  and `AGENTS.md` carry the `000041` range. `scripts/testdb.sh template` rebuilt.
- **Go.** `Post.Customized` in every column list and scan (including
  `qualifiedPostColumns` and `LoadForSend`); `UpdatePostBody(ctx, id, body,
  fingerprint, customized)`: a regenerate clears the flag, a hand edit sets it
  only when `customized` is non-nil; `PATCH` accepts `customized` only with
  `body` (400 with `regenerate`), the audit metadata records it, `postView`
  returns it. Tests: store round trip and regenerate-clears, PATCH set / leave /
  400.
- **Page.** `OutreachWorkshop` is now summary, Announcement, Reminder and Last
  call rows, Schedule all, then collapsed "Post by hand" (non-automatic channels
  only, `OutreachPostCards channelFilter`), Flyers and "Links and clicks" rows
  (results line, View results, and the link-report warning). The tracked-links
  table and "Start outreach" screen are gone; the Reset button and dialog are
  untouched (its note now says "Write the announcement to start again").
- **Implicit start.** `OutreachPanel autoStart` (only the workshop page passes
  it) calls `startOutreach` once per workshop for an available workshop with no
  outreach; "Setting up links..." meanwhile; failure shows a warning and Try
  again, no loop; never for an unavailable workshop. GET stays read-only. The
  link report reaches the page through `onLoaded`.
- **`OutreachAnnouncement`.** One Message field (seeded from
  `sharedMessage`, re-seeded while not dirty); Save message writes
  `planSaveMessage` sequentially to every non-customized automatic post and
  reports skipped customized ones; disabled when unchanged or over a limit.
  "How it will look" shows each post (live preview of the unsaved message) with
  count/limit, status, Customize... (the existing composer with `markCustomized`,
  so Save sends `customized:true`) and Use shared message for customized posts.
  One post button through the Pass 1 dialog (`postAll` in
  `lib/outreachPostAll.ts`, shared with the list), Schedule for later... (one
  time for every postable post) and Unschedule. Empty state "No posts yet. Start
  with the announcement." with Write the announcement.
- **`OutreachWaveRow`.** Collapsed `<details>` with label, suggested time and
  `waveRowStatus`; Write it sits beside the disclosure and calls
  `draftAllOutreach(id, [wave])`, reloads and opens the row.
- **Removed.** Draft all, the "Also draft" checkboxes and the procedure
  paragraph (C10, E2, L2); `OutreachPanel`'s grid, cells and inline composer;
  the composer's Post now / Retry / Mark posted (and its Post URL field), the
  duplicate `<h3>`, and `lib/outreach.ts`'s `buildGrid` / `cellLabel` /
  `cellIsStale` with their tests. The composer's tracked link, "Goes to" and
  UTM chips now sit under "Link details" (G2). After this pass nothing posts
  without the dialog.
- **One summary.** `summaryLine` is used by the page and `OutreachEditorSummary`;
  empty state per L3; neither shows the campaign slug.
- **List-level result line.** `OutreachPostCards` keeps the posts the
  both-networks line reported on and shows it only while one of them still shows
  its notice (`visibleNotice`), so "queued" clears when polling brings back
  posted. The Announcement's post result line uses the same rule.
- **Deviations.** (1) The unused `OutreachLinks.svelte` (and its test) remain in
  the tree; the plan only said to remove it from this page, and Results has its
  own table. (2) Schedule picker for Announce has no suggested time, so it is
  empty until the admin picks one. (3) Customize... is disabled on the other
  cards while one composer is open instead of asking to discard.
