## Description

Two small residues of `#0171`, both found by its phase-3 review.

**1. The confirm copy is false on one path.** `#0171` gave `cancelConfirmMessage` a `wasPublished` flag so the dialog stops promising a draft "stays visible". The never-published branch says **"It was never published"** — which is false on the `published → unpublished → canceled` path. That workshop *was* published; unpublishing cleared `published_at`.

The operative claim ("so it stays private") is **true**, and the behavior is right — `#0171`'s review proved that path stays private on all three surfaces. This is copy accuracy, not a repeat of the defect. But it is the same species of error `#0171` exists to fix: a sentence that presumes a fact the case does not have.

*"It is not currently published, so it stays private"* is true in both sub-cases.

The call site itself is correct and was checked: `!!workshop.published_at`, `omitempty` on the wire, optional in `types.ts`, and `WorkshopEditor.svelte:323` replaces `workshop` with the PATCH response after every transition, so the value is never stale.

**2. A sitemap case lost its coverage.** `sitemap_test.go:70`'s `canceled-1` fixture now defaults to `Published: false`, so **no unit test covers "a *was-published* canceled workshop is excluded from the sitemap"** — the case that actually exercises the gate. Nothing is broken (the sitemap gate is status-only, and `#0171`'s reviewer proved that case by execution), but the assertion that would catch a regression is gone.

One added `Published: true` restores it.

## Root cause

**1.** `cancelConfirmMessage`'s not-currently-published branch hardcoded "It
was never published" as if that were the only way `wasPublished` could be
`false`. But `wasPublished` is `!!workshop.published_at` at confirm time, and
`published_at` also reads `NULL` on the `published → unpublished → canceled`
path — a workshop the unpublish step genuinely had made public once. The
sentence presumed a fact ("never published") that only one of the two
`false` sub-cases actually has.

**2.** `#0171` added a `Published` field to `seo.Workshop` for the JSON-LD /
meta-tag gate, which does key off it. `sitemap_test.go`'s `canceled-1`
fixture predates that field and was left with its zero value
(`Published: false`), which silently turned it from "an arbitrary canceled
workshop" into specifically "a *never-published* canceled workshop" —
without anyone deciding that on purpose. `sitemap.go`'s own exclusion gate
is status-only (`w.Status != WorkshopPublished`, `sitemap.go:86`) and never
reads `Published`, so the fixture's meaning drifted out from under the test
without breaking it: nothing exercised the specific claim "a workshop that
really was published, then canceled, is still excluded from the sitemap on
status alone" — the case where a status-vs-published mixup would actually
show up.

## Fix

**1.** Reworded the not-currently-published branch of
`cancelConfirmMessage` (`web/src/lib/workshopAdmin.ts:147`) from "It was
never published, so it stays private" to "It is not currently published, so
it stays private" — true in both sub-cases (never published, and
published-then-unpublished), reads consistently alongside the unchanged
published branch ("It stays visible on the public site, marked canceled,
rather than disappearing"), and the JSDoc above the function needed no
change (it documents the boolean's meaning, not the exact wording of either
returned string, and was already accurate). Updated the matching vitest
assertion in `workshopAdmin.test.ts` to expect `/not currently published/i`
and explicitly assert `/never published/i` no longer matches, with a comment
explaining why.

**2.** Added a second sitemap fixture, `canceled-2`
(`Status: WorkshopCanceled, Published: true`), alongside the existing
`canceled-1` (left as `Published: false`, i.e. never-published), and added
`canceled-2` to the excluded-slugs assertion loop. Chose *add a fixture*
over *change the existing one* (the issue offered both options) so the test
keeps asserting both sub-cases — never-published and was-published-then-
canceled — rather than trading one covered case for the other.

**The `not.toMatch(/never published/i)` assertion is a literal-phrase pin, not
a semantic guard** — worth knowing what it does and does not buy. Probed it:
rewording the branch to *"It is not currently published **and has not been
published before**, so it stays private…"* — a sentence that reintroduces
exactly the false history claim `#0174` exists to remove — **passes all four

phrase "never published"; the *positive* `/not currently published/i`
assertion is what actually pins the wording, and it does its job (any
replacement wording fails). Since no test can enforce the semantics of English
prose, this is acceptable as written — but the guard is narrower than the
comment above it implies.

### The copy is true on both sub-cases — checked against `#0171`'s matrix

Not reasoned from the sentence. `wasPublished` is `!!workshop.published_at`
(`WorkshopEditor.svelte:237`), and the two `false` sub-cases in `#0171`'s
matrix are `draft` / NULL (never published) and `published → unpublished →
canceled`'s predecessor state `draft` / NULL. "It is not currently published"
is true of both — the row's `published_at` is NULL and its status is `draft`
either way — and the operative half ("so it stays private") matches the
matrix, which shows both staying invisible on all three surfaces. The
published branch is byte-unchanged, so `#0051`'s ruling is untouched.

### Two findings, reported to the orchestrator rather than filed (`CLAUDE.md` §9)

1. **A third case still reads wrong — and this one under-warns.** `canCancel`
   offers Cancel whenever `status !== 'canceled'`, so it is offered on a
   **`draft` whose `published_at` is non-NULL** — the `canceled → draft` row of
   `#0171`'s matrix, where the cancel preserved the publish's stamp and the
   unpublish path was never taken (that row's `published_at` was *observed*
   set). There `wasPublished` is `true`, so the admin gets the published
   branch: *"It stays visible on the public site, marked canceled, rather than
   disappearing."* That workshop is **not** currently visible — `ListVisible`
   requires `status IN (published, canceled) AND published_at IS NOT NULL`
   (`store.go:482`) and the detail route 404s on `StatusDraft`
   (`public_workshops.go:215`), and the matrix's `canceled → draft` row
   confirms false/false/404. Canceling it flips status to `canceled` with
   `published_at` still non-NULL, so it **becomes** visible. "Stays visible" is
   false about the present state and hides the actual effect: this cancel
   republishes the workshop. It is the same species again — a sentence
   presuming a fact the case does not have — and unlike `#0174`'s it errs
   toward under-warning. Out of scope here (criterion 2 fixes the published
   branch as unchanged), so it wants its own small follow-up: the branch needs
   the *current* status as well as `published_at`, e.g. "It will appear on the
   public site marked canceled" for `draft` + stamped `published_at`.
2. **`sitemap_test.go`'s `published-1` fixture is in an impossible state.** It
   is `Status: WorkshopPublished` with `Published` defaulting **false**, but
   `#0171` proved by execution that `status = 'published'` implies
   `published_at IS NOT NULL`. Harmless today (the gate ignores `Published`),
   but it means the one *included* row can never exercise the flag's true
   branch, and it makes the test fail on a change that would be harmless in
   production: mutation `Status != Published || !Published` — a redundant but
   behaviorally identical conjunction — fails only with "sitemap missing the
   published workshop", purely because of the unrealistic fixture. One
   `Published: true` would fix it, and mutation 2 still fails with it added.
