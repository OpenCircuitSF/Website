## Description

Two small residues of `#0171`, both found by its phase-3 review.

**1. The confirm copy is false on one path.** `#0171` gave `cancelConfirmMessage` a `wasPublished` flag so the dialog stops promising a draft "stays visible". The never-published branch says **"It was never published"** — which is false on the `published → unpublished → canceled` path. That workshop *was* published; unpublishing cleared `published_at`.

The operative claim ("so it stays private") is **true**, and the behavior is right — `#0171`'s review proved that path stays private on all three surfaces. This is copy accuracy, not a repeat of the defect. But it is the same species of error `#0171` exists to fix: a sentence that presumes a fact the case does not have.

*"It is not currently published, so it stays private"* is true in both sub-cases.

The call site itself is correct and was checked: `!!workshop.published_at`, `omitempty` on the wire, optional in `types.ts`, and `WorkshopEditor.svelte:323` replaces `workshop` with the PATCH response after every transition, so the value is never stale.

**2. A sitemap case lost its coverage.** `sitemap_test.go:70`'s `canceled-1` fixture now defaults to `Published: false`, so **no unit test covers "a *was-published* canceled workshop is excluded from the sitemap"** — the case that actually exercises the gate. Nothing is broken (the sitemap gate is status-only, and `#0171`'s reviewer proved that case by execution), but the assertion that would catch a regression is gone.

One added `Published: true` restores it.
