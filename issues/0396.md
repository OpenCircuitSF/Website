## Description

`#0393` added a per-line over-budget warning to the CRT commands admin section
(`web/src/views/admin/CrtCommands.svelte`): type an output line longer than
`CRT_LINE_CHARS` and the editor says so.

It appears in two places. The **create form**'s warning carries `role="status"`
and is announced. The **per-row inline editor**'s warning is the same message,
the same wording and the same trigger — and is silent to a screen reader.

The omission was deliberate, and the recorded reason is the problem: the
implementer left `role="status"` off because the editor sits behind
`{#if editing[c.id]}` and adding it would have required a new named entry in
`web/src/lib/liveRegionGuard.structuralGuard.test.ts`'s
`KNOWN_STABLE_BRANCH_SITES`. **That is shaping markup to avoid tripping a
guard**, which is the wrong direction of reasoning even where the conclusion
would have been convenient.

Here the conclusion is not convenient either. The guard is not an obstacle in
this case, it is the mechanism:

- the `{#if editing[c.id]}` branch mounts when the operator clicks Edit and
  stays mounted for the whole editing session — it is not driven by the
  warning's own presence;
- it holds a full form, well past `#0306`'s 8-element threshold;
- that is exactly what `KNOWN_STABLE_BRANCH_SITES` exists to admit, by the same
  argument already recorded for `WorkshopEditor.svelte`'s
  `unsavedInterestsHint`.

The "it would announce on every keystroke" objection does not hold: the text
changes only when a line **crosses** the budget, not as each character is typed.

`#0393`'s reviewer found this and deliberately did not bounce on it — on scope,
not on merit. The line-width feature was designated a follow-up rather than a
`#0393` acceptance criterion, so it is filed here instead.

## Notes

Found by `#0393`'s second review pass, 2026-09-03. Filed rather than bounced
because the width warning was itself a follow-up folded into `#0393`, not one
of its criteria.

The general rule worth carrying: when a guard objects to correct markup, the
answer is a justified allowlist entry that records why, not markup bent to keep
the guard quiet. The first is a decision anyone can audit later; the second is
invisible.

## Merging this trips a new assertion (added 2026-09-08 by `#0406`)

`#0406` pinned `web/src/lib/liveRegionGuard.structuralGuard.test.ts`'s
`KNOWN_STABLE_BRANCH_SITES` to a hand-edited constant:

    expect(KNOWN_STABLE_BRANCH_SITES).toHaveLength(KNOWN_STABLE_BRANCH_SITES_RECORDED_COUNT)

On `main` the array holds **twelve** entries and the constant says twelve. This
issue's implementation — currently living on an unmerged worktree branch — adds
a **thirteenth**. **The moment it merges, that assertion goes red and names the
constant.**

That is deliberate. `#0406` was filed believing the array already held thirteen;
its implementer measured `main` and found the premise false, then built the
assertion so the drift cannot recur silently rather than editing a sentence.

**What the merge has to do**, per `#0406`'s review — three things, not one:

1. bump `KNOWN_STABLE_BRANCH_SITES_RECORDED_COUNT` to 13;
2. update the prose that reads "All twelve clear …";
3. add the row to the per-entry measurement table.

The assertion catches only the first. `#0406`'s reviewer recorded that residual
deliberately: tying the *prose* to the array as well would mean the test reading
its own source and parsing a numeral, which is the in-file-guard accretion
`CLAUDE.md` §8 warns about. The constant's own doc comment routes the editor to
the prose instead.

**A measurement trap for whoever does it:** a naive brace count over that range
returns **38**, not 13 — the entries' `reason` strings contain Svelte `{#if}`
text. Count array entries, not braces.

## Fix

`web/src/views/admin/CrtCommands.svelte`: the per-row inline editor's
over-budget warning went from `<p class="text-warn">{crtOverBudgetWarning(
draft.output) ?? ''}</p>` to `<p class="text-warn"
role="status">{crtOverBudgetWarning(draft.output) ?? ''}</p>` — otherwise
byte-identical to the create form's already-announced warning. The old
comment above it ("No role="status": ... requires ... an allowlist entry ...
isn't the kind of state change that rule is protecting") reasoned from guard
avoidance and has been rewritten in place (not deleted) to state the actual
argument: the `{#if editing[c.id]}` branch is a genuine
`KNOWN_STABLE_BRANCH_SITES` case — it mounts once per Edit click and stays
mounted for the whole editing session (a full form: command text, output
textarea, source select, active checkbox), well past `#0306`'s 8-element
`KNOWN_STABLE_BRANCH_MIN_ELEMENT_COUNT` — and the earlier reasoning is
flagged as the mistake this issue exists to correct, not left silently
replaced.

`web/src/lib/liveRegionGuard.structuralGuard.test.ts`: added one
`KNOWN_STABLE_BRANCH_SITES` entry for
`web/src/views/admin/CrtCommands.svelte`, `match:
'<p class="text-warn" role="status">{crtOverBudgetWarning(draft.output) ??
\'\'}</p>'`, with a justification reason modelled on
`KNOWN_STABLE_BRANCH_REASON_MAIN_FORM` (the existing `unsavedInterestsHint`
entry this issue's Description points at) — same argument, applied to this
component's `{#if editing[c.id]}` branch instead of `WorkshopEditor.svelte`'s
main form, and it names the reversed-reasoning history explicitly so a
future reader of the old comment (still visible in `git log` and in this
entry's own text) doesn't repeat it.
