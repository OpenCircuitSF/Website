## Description

`#0202` corrected one clause of
`TestScanDirForCitationsCollectsExactlyDiskFiles`'s doc comment. Its phase-3
review passed that change and found **another wrong statement one paragraph up**,
pre-existing from `#0201` and outside `#0202`'s diff.

`internal/handlers/citation_guard_test.go` sends the reader to "that map's own
doc comment on `internal/dist` as the live example". But `skipVendoredDirNames`'
doc comment never mentions `internal/dist` — it discusses only
`web/node_modules` and `web/dist`. And `internal/dist` does not exist on disk,
so calling it "the live example" overstates a hypothetical twice over: the
pointer goes nowhere, and the thing it points at is not live.

This is the same class of defect as `#0202` itself, in the same comment block —
which is the argument for fixing it rather than leaving it. This test is a set
comparison between two enumerations; its value lives in the argument for why
they differ, and a reader following a dead cross-reference loses that argument.

**Two cosmetic points from the same review, cheapest folded in here** rather than
tracked separately. Neither misleads in context:

- `onDisk` is a set of **file** paths, so "additionally counts name-matched
  directories" is shorthand for counting the non-test `.go` files inside them.
- An "e.g." before the three named directories would put the
  illustrative-not-exhaustive reading beyond doubt. The review confirmed by
  planting `cmd/node_modules/` and `internal/handlers/dist/` — neither named in
  the comment, both correctly failing the test — that the stated rule is the
  operative one, so the list is genuinely illustrative.

## Implementation notes

Two edits, both inside `TestScanDirForCitationsCollectsExactlyDiskFiles`'s doc
comment in `internal/handlers/citation_guard_test.go`, comment-only.

**The dangling cross-reference.** The broken pointer was dropped rather than
repaired at its target: `skipVendoredDirNames`' doc comment discusses only
`web/node_modules` and `web/dist`, and adding a hypothetical `internal/dist`
aside there would be off-topic for a map whose comment explains why those two
real, anchored trees exist. The paragraph containing the dangling pointer
already develops `internal/dist` as the exact scenario two sentences later
("`internal/dist/` does not share a path prefix with `web/node_modules` or
`web/dist`, so it is never excluded from \"on disk\"..."), so the fix points
forward within the same paragraph instead of sideways to an unrelated doc
comment. Before:

> "node_modules" or "dist" anywhere under scanGoRoots (see that map's own
> doc comment on internal/dist as the live example) is swallowed by the
> shipped walk today with nothing failing.

After:

> "node_modules" or "dist" anywhere under scanGoRoots is swallowed by the
> shipped walk today with nothing failing — internal/dist below is exactly
> such a case.

**The two cosmetic points.** Same sentence, reworded together:

> "on disk" ... is a superset of that same walk (it additionally counts the
> non-test .go files within name-matched directories that lie outside the
> two anchored prefixes — e.g. internal/dist, internal/node_modules, and
> web/src/node_modules — since the anchoring does not exclude them), so
> collected is always a subset of onDisk.

Comment-only: `excludedPrefixes`, the `path == prefix ||
strings.HasPrefix(path, prefix+string(filepath.Separator))` guard, both
`WalkDir` bodies, the set difference, and every failure message are

(`#0204`'s `CampaignSendDialog.*`), which were left untouched.

escape.

Found nothing further wrong in the comment while re-verifying every claim
