## Description

`#0202` corrected one clause of
`TestScanDirForCitationsCollectsExactlyDiskFiles`'s doc comment. Its phase-3
review passed that change and found **another wrong statement one paragraph up**,
pre-existing from `#0201` and outside `#0202`'s diff.

`internal/handlers/citation_guard_test.go` sends the reader to "that map's own
doc comment on `internal/dist` as the live example". But `skipVendoredDirNames`'
doc comment never mentions `internal/dist` — it discusses only
`web/node_modules` and `web/dist`. And `internal/dist` does not exist on disk,
so calling it "the live example" overstates a hypothetical twice over: the
pointer goes nowhere, and the thing it points at is not live.

This is the same class of defect as `#0202` itself, in the same comment block —
which is the argument for fixing it rather than leaving it. This test is a set
comparison between two enumerations; its value lives in the argument for why
they differ, and a reader following a dead cross-reference loses that argument.

**Two cosmetic points from the same review, cheapest folded in here** rather than
tracked separately. Neither misleads in context:

- `onDisk` is a set of **file** paths, so "additionally counts name-matched
  directories" is shorthand for counting the non-test `.go` files inside them.
- An "e.g." before the three named directories would put the
  illustrative-not-exhaustive reading beyond doubt. The review confirmed by
  planting `cmd/node_modules/` and `internal/handlers/dist/` — neither named in
  the comment, both correctly failing the test — that the stated rule is the
  operative one, so the list is genuinely illustrative.
