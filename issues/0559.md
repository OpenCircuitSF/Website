## Description

Brennan's feedback on the `#0549` flyer render (photo on top, text on white
below, short link printed bottom-left):

> For the flyer I would prefer to give you an image which will fill the
> background. The text would be put inside boxes which are semitransparent to
> prevent the text from being lost in the background. There would be a box for
> the QR code with a margin around it and room for the identifying text below
> it. We also do not see the URL for the link but you could just give the
> general URL which is OpenCircuitSF.com instead. I will expect people to use
> the QR code to get the real link.

The `full-photo` template already exists (`web/src/lib/flyers.ts`
`FLYER_TEMPLATES`, kept in step with `internal/outreach`'s `FlyerTemplates`
and the `outreach_flyers_template_check` constraint). Rework it into this
design and make it the default, so no schema change is needed. Leave
`photo-top` and `split` working as they are.

## Acceptance criteria

- [ ] **Background.** On `full-photo`, the photo covers the whole flyer face in both print layouts (full letter and half-size double), cropped with the existing focal-point logic (`coverPosition`/`objectPosition`). No white text area remains.
- [ ] **Text box.** Title, tagline, date and time, and venue sit inside one semi-transparent box, a dark brand-toned fill around 80–85% opacity with light text. The fill is chosen so the text meets WCAG AA contrast against the box's worst case: the fill composited over pure white. Assert this with a unit test in `web/src/lib/`. It stays legible over any photo.
- [ ] **QR box.** The QR code sits in its own box with a solid (opaque) white quiet zone at least 4 modules wide on every side. QR codes need high contrast to scan, so the area around the code must not be semi-transparent. The location label sits below the code inside the same box, on one line where it fits. On the half-size layout, a long label must stay readable and must not overflow or clip the box. This fixes the `cafe-` / `noir` wrap seen in `#0549`'s render.
- [ ] **URL.** The printed short link is replaced with the general site address, shown as `OpenCircuitSF.com`. The QR code still encodes the location's tracked ShortLinks URL, unchanged. Check that the `open_circuit_sf` wordmark line still makes sense next to it, and drop it if it is redundant.
- [ ] **Default.** `full-photo` is the default template for a new flyer in both the SPA and the Go default, if one exists. Existing saved flyers keep their template.
- [ ] **Print.** The `@page` size, the half-layout rotation and the cut line from `#0549` keep working. Note in the resolution that home printers leave an unprintable edge, so the full bleed prints with a thin white border. That is acceptable and needs no workaround.
- [ ] **Tests.** jsdom component tests for `FlyerFace` cover the boxes, the URL text, and the QR label for the `full-photo` template. The `photo-top` and `split` tests still pass.
- [ ] **Visual evidence, without a browser on the host.** Never launch Chrome, Chromium, Playwright or Puppeteer on the host. If a rendered check is done, it runs in a disposable Tart VM clone per `~/Developer/Homelab/cameron/tart-ui-test-vm.md` (`tart-lease`, clone from `uitest-golden`, Safari plus WebDriver in the guest, stop and delete the clone in a trap). If that isn't workable, say so plainly. Brennan will do the real print preview himself.
- [ ] Verified with `ISSUE=0559 scripts/check.sh` (Go and web), plus `./internal/handlers/...` if Go comments change.
