## Review notes

2026-10-17, phase 3 (Opus): approved.

- **Contrast.** Recomputed by hand: `#0b100a` at 0.84 over white composites to `#323631` (relative luminance about 0.035). Against it the brand green `#68ff23` (luminance about 0.746) is about 9.3:1, and the muted and ink colours are higher still, so all three clear 4.5:1 with room. White is the right worst case: any darker photo darkens the composite, which only raises contrast against light text.
- **QR quiet zone.** The 41-module assumption is not what makes this safe, and it does not need to be. ShortLinks' renderer (`internal/qr` in the ShortLinks checkout) builds its bitmap with the 4-module quiet zone already inside the viewBox, and `SanitizeQRSVG` rebuilds that viewBox with a `#fff` background rect covering it. So every QR image already carries 4 real modules of opaque white whatever its version; `qrQuietIn` adds extra white on top. The QR box has an opaque `#fff` background and no ancestor carries opacity or a filter, so nothing under or around the code is translucent. The unit test for the quiet zone only restates the formula, but no correctness rests on it.
- **Label.** The self-hosted JetBrains Mono 400 and 700 subsets map U+2011 to the same glyph as U+002D (checked with CoreText against the woff2 files), and the `@font-face` `unicode-range` covers U+2000-206F, so the non-breaking hyphen renders in the label font with no fallback. Codes are at most 16 characters, so `cafe-noir`-style codes cannot overflow. The box is `max-content` wide, capped by the label's max width, and wraps at spaces.
- **Half layout.** The photo and `.fp` are positioned against `.face`, which is `position: relative`, so `#0549`'s `translateY` plus `rotate` on the print slot moves the whole face as one unit. On the 5.5 x 8.5 in face the tallest possible text box (3-line title, 140-character tagline, two lines, site address) is about 2.9 in, and the QR box about 1.3 in, so the two never collide.
- **Print.** `print-color-adjust: exact` on `.face` is inherited, so the box fills print without the user turning on background graphics. `@page`, rotation and cut line are unchanged.
- **`color-mix`.** Safari 16.2+ and Chrome 111+ support it. That is fine for an admin print tool.
- **Default.** `DEFAULT_FLYER_TEMPLATE` in the SPA and the Go create handler both use `full-photo`. Saved flyers keep their stored template.
- **Rendered check.** None was done (no Tart VM). The issue allows that if it is stated plainly, and it is. Brennan will check a real print preview.
- **Verification.** Load average 2.06. `ISSUE=0559 scripts/check.sh` (Go and web): every Go package ok, including `internal/db` (green now that `#0558` has its Closed row) and `internal/handlers`; svelte-check 0 errors; vitest 61 files, 4399 tests passed; VERIFICATION PASSED.
- **Follow-ups (not in scope).** (1) `.fp-label` sets `overflow-wrap: normal`, so a location *name* written as one hyphenated token over about 41 characters (names allow 100) would overflow the 2.4 in label width on the half layout, now that its hyphens no longer break. `overflow-wrap: anywhere` on `.fp-label` would still break at spaces first and break only an overlong token. (2) If `color-mix` is unsupported, the text box loses its fill entirely. A plain `background: rgba(11, 16, 10, 0.84)` line before the `color-mix` line is a one-line fallback.

## Resolution

`full-photo` is reworked and is now the default for new flyers (SPA `DEFAULT_FLYER_TEMPLATE`, and the Go create handler's default). Existing flyers keep their saved template; `photo-top` and `split` are untouched (they still print the short link).

- **Background.** The photo is `position: absolute; inset: 0` on the full face (letter and half), cropped by the existing `objectPosition`/`photoBox` focal logic.
- **Text box.** One box inside the 0.25in safe area, top of the face: fill `#0b100a` at 84% opacity (via `color-mix` on the background, so text stays fully opaque), title in `#f2f6ee`, tagline `#d5ddd0`, date and venue lines in brand green `#68ff23`, and `OpenCircuitSF.com` in mono at the bottom of the box. `lib/flyers.ts` `FULL_PHOTO_BOX` holds the values; a unit test composites the fill over white and asserts every text colour is at least 4.5:1.
- **QR box.** A separate opaque white box, bottom-right, padding `qrQuietIn(qr)` = 4 modules of an assumed 41-module code (generous), so at least 4 real modules. The label sits below the code, centered, 8pt (full) or 7pt (half), with hyphens turned into U+2011 so `cafe-noir` cannot break mid-word; it wraps only at spaces within a max width, and the box grows to fit (`width: max-content`), so nothing clips. The QR still encodes the tracked link.
- **URL.** The short link and the `open_circuit_sf` wordmark are gone from `full-photo` (the wordmark was redundant next to the site address).
- **Print.** `@page`, half rotation and cut line are unchanged. Home printers leave an unprintable edge, so the full bleed prints with a thin white border; accepted, no workaround.
