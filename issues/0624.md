## Description

The only overview is the summary line in `OutreachWorkshop.svelte`, which gives counts. It cannot say what each channel does for each wave, or when.

## Plan

Written 2026-11-04 against `f43dae7f`. SPA only: no Go, no route, no migration. Scope is the board and the partly scheduled wording. It does **not** make a row selectable, change which sections are open (`#0625`), or move hand-posted cards or remove the bottom **Post by hand** row (`#0626`).

**Decisions already taken, so do not reopen them:**

- **Five flat columns, no video group on the board.** The criterion asks for one column per channel, and each platform's posted state must stay visible. Every hand-posted cell already says `Post by hand`, so a group header would add a row and explain nothing. The video group belongs to `#0626`'s cards. Columns are `view.channels` in server order. That list already drops switched-off channels unless they have posts (`shownChannels`).
- **A real table that stacks at 860 px and below, with no sideways scroll.** A sideways-scrolling table would hide two or three channels on a phone. The Outreach panel is `overflow: clip`, so any overflow is cut off silently, not scrollable. Above 860 px the panel's inner width is at least about 795 px, leaving about 108 px of text per channel. At the repo's usual 720 px it would be about 80 px, which is too tight, so this component uses its own breakpoint.
- **Per-cell channel label for the narrow layout.** Every `td` holds a `.board-channel` span, `display: none` when wide (the column header does the job) and shown when stacked (the header is hidden). A stacked cell therefore reads `TikTok  Post by hand` as plain text, and does not depend on the browser keeping table semantics under `display: block`. So no ARIA roles are added.
- **One line of the post text in each row (`waveExcerpt`).** The user's goal is seeing "what would be posted" as well as when. A full message does not fit, but its first 80 characters do, and they tell the three sections apart. This goes beyond the written criteria and is small enough to drop if the user objects.
- **The note uses one rule.** The strip's suffix and the board row's note come from one function, so they cannot disagree.
- **Keep `summaryLine`.** `OutreachEditorSummary.svelte` still uses it for the event editor's one line. Only the call in `OutreachWorkshop.svelte` goes. The click count that line carried is still in the **Links and clicks** row.

### Approach

**`outreachCards.ts`**, after `statusLine`. The cell starts from `statusLine`'s `kind`, so the board cannot disagree with the cards about which state a post is in. Its words are shorter because a cell is small.

```ts
export interface BoardCell {
  channel: string;
  channelLabel: string;
  kind: StatusKind;
  /** The state in words: never empty, so colour is never the only cue. */
  status: string;
  /** The date and time where there is one, else a short qualifier or null. */
  detail: string | null;
}
export interface BoardRow {
  wave: string;
  ordinal: number;
  label: string;
  /** "1 not scheduled" on a partly scheduled row, else empty. */
  note: string;
  cells: BoardCell[];
}

const when = (iso: string | null | undefined): string | null => (iso ? weekdayTime(iso) : null);

/** One post's cell on the status board. */
export function boardCell(post: OutreachPost | null, channel: OutreachChannel): BoardCell {
  const kind = statusLine(post, channel).kind;
  const words: Record<StatusKind, [string, string | null]> = {
    posted: ['Posted', when(post?.posted_at)],
    scheduled: ['Scheduled', when(post?.scheduled_at)],
    on_hold: ['On hold', when(post?.scheduled_at)],
    queued: ['Posting now', null],
    failed: ['Failed', null],
    not_scheduled: ['Draft', 'Not scheduled'],
    manual: ['Post by hand', null],
    not_drafted: ['Not written', null],
  };
  const [status, detail] = words[kind];
  return { channel: channel.name, channelLabel: channel.label, kind, status, detail };
}

/**
 * "2 not scheduled" when part of a wave is out or on its way and some of the
 * channels that post themselves are not: no post yet, or a post with no time.
 * Empty when nothing has gone out or been scheduled, since the wave's own
 * status already says that, and when a post has failed or is sending only.
 */
export function notScheduledNote(view: Pick<WorkshopOutreach, 'channels' | 'posts'>, wave: string): string {
  const own = view.channels.filter(sendsItself).map((c) => view.posts.find((p) => p.channel === c.name && p.wave === wave) ?? null);
  const under = own.filter((p) => p === null || p.status === 'draft' || p.status === 'manual').length;
  const started = own.some((p) => p !== null && (p.status === 'scheduled' || p.status === 'posted'));
  return under > 0 && started ? `${under} not scheduled` : '';
}

/** The status board: one row per wave, one cell per channel, in the server's order. */
export function boardRows(view: Pick<WorkshopOutreach, 'channels' | 'waves' | 'posts'>): BoardRow[] {
  return groupByWave(view).map(({ wave, cards }, i) => ({
    wave: wave.name,
    ordinal: i + 1,
    label: wave.label,
    note: notScheduledNote(view, wave.name),
    cells: cards.map((c) => boardCell(c.post, c.channel)),
  }));
}
```

Append `${rest}` to exactly these four returns, and to no others:

- the held return: `Scheduled ${first} · on hold until the event is published${rest}`.

Add `waveExcerpt` under `sharedMessage`. Do not build it on `sharedMessage`, which skips posted posts and would go blank once a wave is out:

```ts
/** The start of what a wave says, on one line: the first written post's message, in the server's channel order. */
export function waveExcerpt(view: Pick<View, 'channels' | 'posts'>, wave: string, max = 80): string {
  for (const channel of view.channels) {
    const post = view.posts.find((p) => p.channel === channel.name && p.wave === wave);
    if (!post) continue;
    const chars = Array.from(splitBody(post.body, post.short_url).message.replace(/\s+/g, ' ').trim());
    if (chars.length === 0) continue;
    return chars.length > max ? `${chars.slice(0, max - 1).join('').trimEnd()}…` : chars.join('');
  }
  return '';
}
```

**`OutreachStatusBoard.svelte`**. Props: `{ view: WorkshopOutreach }`. `const rows = $derived(boardRows(view));`. Start with a header comment saying what the board is and why it stacks. Markup:

```svelte
      </tr>
    {/each}

```

Three rules for that markup:

- **No `<strong>` and no heading inside the board.** The existing workshop tests find sections with `findByText('Reminder', { selector: 'strong' })`, `findByText('Post by hand', { selector: 'strong' })` and `findByRole('heading', { name: /Announce/ })`. A `<strong>` here makes those fail on two matches.
- **`data-kind` is for tests only.** No CSS selects on it and no status gets a colour.
- **The row label stays in that one `th`.** `#0625` wraps its `.board-name` in a button, and `data-wave` tells it which section. Do not add an `onSelect` prop now.
