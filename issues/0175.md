## Description

`#0172` removed tracker citations from admin-facing copy. Its reviewer swept on a different axis — reading every rendered string rather than grepping for citation patterns — and found the same family of problem with no citation to grep for.

**1. "The send worker" is an implementation detail, rendered to admins in five places:**

- `Admin.svelte`'s physical-address hint
- `campaigns.ts`'s returned-to-draft text
- `campaigns.ts`'s two cancel confirmations
- `Campaigns.svelte`'s "Returned to draft — worker refused it" badge
- `CampaignEditor.svelte`'s stall hint

An admin has no model of a "worker". The facts behind these strings are real and worth telling them — a send was refused, a campaign went back to draft, something stalled — but the *reason* should be phrased in terms of the product ("sending stopped because no physical address is set") rather than the process that enforced it.

**2. User-visible copy mixes `--` and em dashes.** Two strings in `WorkshopEditor.svelte` and two messages in `workshopAdmin.ts` use a double hyphen where the rest of the console uses `—`.

## Acceptance criteria

- [x] The five "worker" strings describe what happened and why in the admin's terms, without naming the worker. Keep the diagnostic value — an admin must still learn *why* a campaign returned to draft
- [x] The physical-address hint in particular should say what to do about it, since that one is actionable (`#0045` refuses to send without it — CAN-SPAM §7704)
- [x] Dashes are consistent across user-visible copy; pick the convention the console already uses and apply it — see `## Fix` for a scope note on `workshopAdmin.ts`
- [x] **Sweep the way this was found**: read the rendered strings, do not grep for a word. `#0172`'s reviewer stripped `<script>`/`<style>`/comments from the admin views and read the text nodes plus `placeholder`/`title`/`aria-label`/`alt` — that method is what turned this up, and it is worth repeating rather than searching for "worker"
- [x] Judged fine by that same review and **not** to be changed: the audit log's own displayed values (`${entry.target_type} #${entry.target_id}`, the `e.g. email_campaign` placeholder, `#0114`), `api.ts`'s `HTTP ${status}` fallback, and product vocabulary an admin genuinely meets ("slug", "double opt-in", "draft", "Markdown")
- [x] `scripts/check.sh web` passes

## Root cause

Five rendered strings across the campaign-admin UI named the background
send worker (`internal/mailing.Worker`, `#0045`) directly — "the send
worker refused it", "stops the worker from sending", "the worker may be
paused" — an implementation detail with no meaning to an admin who has
never seen the Go source. Separately, `WorkshopEditor.svelte` had two
strings using `--` where the rest of the console's user-visible copy uses
`—`, left over from copy that predates the em-dash convention settling.

## Fix

Rewrote each of the five strings in product terms, keeping what actually
happened and (for the actionable one) what to do about it, without
naming the worker:

- `web/src/views/Admin.svelte` — the physical-address setting hint now
  reads "…every commercial message — campaigns cannot be sent until an
  address is set here." (was "…the send worker refuses to start a
  campaign while this is empty.") — actionable: it tells the admin
  exactly what unblocks sending.
- `web/src/lib/campaigns.ts`'s `demotionExplanation` now reads "…but
  sending was refused and it was returned to draft…" (was "…but the
  send worker refused it and returned it to draft…"). The function's
  doc comment was updated to match ("does not restate WHY sending was
  refused").
- `web/src/lib/campaigns.ts`'s `cancelCopy` (both branches) now reads
  "Cancelling stops sending to …" instead of "Cancelling stops the
  worker from sending to …".
- `web/src/views/admin/Campaigns.svelte`'s demoted-row badge now reads
  "Returned to draft — sending was refused" instead of "Returned to
  draft — worker refused it".
- `web/src/views/admin/CampaignEditor.svelte`'s stall hint now reads
  "No update in a while — sending may be paused or waiting on
  send-rate limits." instead of naming the worker.

Also fixed the two `--` strings the issue calls out in
`WorkshopEditor.svelte` (the slug hint and the delete-conflict
message) to use `—`, matching the em dash used throughout the rest of
the admin console (confirmed by checking existing usage in the same
file and in `campaigns.ts`).

**Scope note on `workshopAdmin.ts`:** the issue's dash criterion also
names two messages in `web/src/lib/workshopAdmin.ts` (the cancel
confirmation at line 147 and the cover-image validation message at
line 588 — both still use `--`). The orchestrator's dispatch for this
issue explicitly listed that file as owned by `#0174`'s reviewer for
this work session ("stay out of anything dirty that is not yours"),
so it was left untouched here even though it was not dirty at the
time. Reporting this back rather than editing it or filing a new
issue, per `CLAUDE.md` §9 (subagents report, they don't file).

**Sweep beyond the five strings:** stripped `<script>`/`<style>`/comments
from every file under `web/src/views/admin/` plus `Admin.svelte` and read
every remaining text node and `placeholder`/`title`/`aria-label`/`alt`
value (method matching `#0172`'s reviewer, not a grep for "worker").
Found nothing else naming the worker or otherwise off — the rest of the
sweep matched what the issue already judged fine (slug/draft/Markdown
vocabulary, the audit log's own values). Also checked
`campaignProgress.ts`, `admin.ts`, and `sendConfirm.ts`'s returned
strings directly (no `.svelte` wrapper to strip) — clean, no `worker`
mentions and no `--` dashes.
