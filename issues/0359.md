## Description

`#0356`'s guard is scoped to the `<file>.go:<int>` form. A positional reference
written **without** the filename escapes it entirely.

`internal/handlers/citation_target_guard_test.go` still contains:

> see that file's **line 25** for the real text

referring to `admin_workshops.go`. The guard's regex cannot match it. It is
**accurate today** — `#0356`'s reviewer checked, and the four-segment token
really is on line 25 — but it drifts on any unrelated edit above it, exactly
like the 27 citations `#0356` removed.

The reason it exists in that form is worth recording: it was written that way
**because the file's own path guard forbids spelling the token**. So one guard's
constraint produced a reference shaped to be invisible to another's.

The class is likely small, but it is invisible to **both** guard families —
`#0356`'s (needs a filename adjacent to a number) and `#0347`'s (needs a named
call identifier).

## Census and decision

**Method.** Built a standalone AST census tool (`linecensus`, Go, compiled to
a binary, `go/parser` with `ParseComments`, walking only `f.Comments` —
string literals are a different AST node kind and cannot enter the
population by construction) matching `line[s]? N`, `lines N-M`/`N–M`, `the
<word> line`, and `<N><st/nd/rd/th> line`, case-insensitive, across every
line of every comment group under `internal/` and `cmd/`.

**Proved falsifiable and fail-closed before use, per criterion 2**, on a
fixture directory (not the real tree):
- Positive control: a comment containing "line 42" alongside a **string
  literal** containing "line 99" → reported exactly the comment hit (1),
  correctly excluding the string-literal decoy — proves comments-only
  scanning is real, not incidental.
- Negative control: a file with no line-ish text → `VERDICT: OK … hits=0`
  (proves it doesn't fail open by always erroring).
- Five fail-closed probes, each producing an explicit `VERDICT: ERROR: …`
  line, never a false `OK`: nonexistent root, a file passed where a
  directory was expected, a directory with zero `.go` files, a
  syntactically-broken `.go` file (parse failure), and zero arguments.

**Real run**: `linecensus internal cmd` → `VERDICT: OK files=271 hits=38`.

**Correction 2026-09-01 (#0359 review).** Two things this Method section
should have said and didn't:

- **Coverage.** The run covered **271 of the repo's 272** `.go` files;
  `web/embed.go` sits under `web/`, outside both `internal` and `cmd`, and was
  never scanned by this tool. The review scanned it separately and found
  **zero** hits, so the omission changed nothing in outcome — but the
  original "files=271" figure should have said what it covered rather than

## Acceptance criteria

1. **Census first, and decide afterwards.** Count the bare positional
   references — "line N", "lines N–M", "the Nth line" and near neighbours —
   across Go comments, and classify each as a real positional citation versus
   prose that legitimately discusses a line number. **A guard is not
   automatically the answer**: if the census comes back at one or two sites, say
   so and fix them without building anything. That judgement is part of this
   issue's deliverable, not a preamble to it.
2. The census tool scans only `f.Comments` from a `ParseComments` walk, so
   string literals cannot enter the population by construction, and is proved
   falsifiable and fail-closed **before** use. Seven agents found genuine
   fail-opens in their own instruments on 2026-08-31; build to a binary and read
   an explicit verdict line, not an exit code.
3. `citation_target_guard_test.go`'s "line 25" reference is replaced with
   something that does not drift — and the replacement must respect **why** it
   was written that way, since that file's own path guard forbids spelling the
   token it points at. Re-measure the referent yourself rather than trusting
   this issue.
4. If a guard is built, it must state the false-positive class it accepts and
   pin its calibration in fixtures rather than prose — see `#0358`, which exists
   because `#0347` described its window limits in a sentence that went stale.
5. No `.ClaimDue(` / `.OrphanSweep(` / `.SelectDue(` call-syntax literal enters
   any Go comment, and the floor harness population stays **42 total / 12
   non-exempt** (`#0323`'s trap).
6. `gofmt` stability: file sha256 equals sha256 of `gofmt` stdout (§8).
