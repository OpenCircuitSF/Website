## Description

`#0356`'s guard is scoped to the `<file>.go:<int>` form. A positional reference
written **without** the filename escapes it entirely.

`internal/handlers/citation_target_guard_test.go` still contains:

> see that file's **line 25** for the real text

referring to `admin_workshops.go`. The guard's regex cannot match it. It is
**accurate today** — `#0356`'s reviewer checked, and the four-segment token
really is on line 25 — but it drifts on any unrelated edit above it, exactly
like the 27 citations `#0356` removed.

The reason it exists in that form is worth recording: it was written that way
**because the file's own path guard forbids spelling the token**. So one guard's
constraint produced a reference shaped to be invisible to another's.

The class is likely small, but it is invisible to **both** guard families —
`#0356`'s (needs a filename adjacent to a number) and `#0347`'s (needs a named
call identifier).

## Census and decision

**Method.** Built a standalone AST census tool (`linecensus`, Go, compiled to
a binary, `go/parser` with `ParseComments`, walking only `f.Comments` —
string literals are a different AST node kind and cannot enter the
population by construction) matching `line[s]? N`, `lines N-M`/`N–M`, `the
<word> line`, and `<N><st/nd/rd/th> line`, case-insensitive, across every
line of every comment group under `internal/` and `cmd/`.

**Proved falsifiable and fail-closed before use, per criterion 2**, on a
fixture directory (not the real tree):
- Positive control: a comment containing "line 42" alongside a **string
  literal** containing "line 99" → reported exactly the comment hit (1),
  correctly excluding the string-literal decoy — proves comments-only
  scanning is real, not incidental.
- Negative control: a file with no line-ish text → `VERDICT: OK … hits=0`
  (proves it doesn't fail open by always erroring).
- Five fail-closed probes, each producing an explicit `VERDICT: ERROR: …`
  line, never a false `OK`: nonexistent root, a file passed where a
  directory was expected, a directory with zero `.go` files, a
  syntactically-broken `.go` file (parse failure), and zero arguments.

**Real run**: `linecensus internal cmd` → `VERDICT: OK files=271 hits=38`.

**Classification of all 38 hits** (full list kept in scratchpad
`issue-0359/census_real_run.txt`):

| Class | Count | Examples |
|---|---|---|
| Idiomatic prose ("log line", "address line", "line of defense", "the equivalent line") — no digit, no external pointer | 12 | `internal/auth/mailer.go:73`, `internal/subscribers/store.go:1236`, `internal/mailing/transactional_templates.go:39,359`, `internal/mailing/worker_test.go:1261`, `internal/mailing/templates_test.go:583` |
| Prose describing a parsing/scanning **algorithm** in the abstract ("the first line", "the following line", "the raw line") — not pointing at any specific file:line | 15 | `internal/db/docs_parity_test.go:229,487,512,664`, `internal/db/issue_citation_guard_test.go:120,541`, `internal/db/prd_section_index_test.go:29,324`, `internal/handlers/campaign_progress_parity_test.go:91,332`, `internal/handlers/dangling_test_citation_guard_test.go:420,433,757`, `internal/handlers/line_citation_guard_test.go:17,59,173`, `internal/handlers/routes_parity_test.go:91` |
| Self-referential, non-drifting: a fixture's own constructed string, annotated line-by-line **in the same function**, checked programmatically against named constants (`blockOpeningLine`, `citationLine`) rather than left as unchecked prose | 9 | `internal/handlers/dangling_test_citation_guard_test.go:838-846` |
| Local **relative** reference within the same declaration ("the second line below") — not an absolute pointer into another location | 1 | `internal/handlers/audit_email_metadata_guard_test.go:1657` |
| Self-referential fixture prose about a doc string built two lines later in the same test, describing "Line 2"/"Line 4" of *that* literal | — (subset of row above's neighbours) | `internal/db/docs_parity_test.go:648,652,654,659` (recounted in row 2 above; verified non-drifting by the same self-containment argument) |
| **Real bare positional citation** — an absolute line number in one file, naming no filename, pointing at a *different* file, invalidated by any unrelated edit above the cited line | **1** | `internal/handlers/citation_target_guard_test.go:264` ("line 25", `admin_workshops.go`) |

Every non-drifting classification was checked by reading the surrounding
code, not inferred from the wording alone — in particular the
`dangling_test_citation_guard_test.go:838-846` block was traced forward to
confirm `blockOpeningLine`/`citationLine` are asserted against
programmatically (`found.pos.Line != citationLine` etc.), which is what
makes it self-checking rather than unchecked prose.

**Decision: do not build a guard.** The census returns exactly **one** real
site — `#0359`'s own known instance, and no others — which is squarely
inside criterion 1's stated threshold ("one or two sites, say so plainly, fix
them, and build nothing"). Weighing the reasons the issue names against
building anyway:

- `#0356`'s guard family cost a planning pass and three review rounds to
  reach a working exemption design, on a strictly *easier* problem (it has a
  filename to anchor exclusions on; this class does not).
- The false-positive surface here is worse, not comparable: 34 of the 38
  raw hits are ordinary English sentences about lines of code, log output,
  or postal addresses. A guard would need the same order of exemption
  machinery `#0356` built, to protect a population of one.
- §8's `#0258` lesson generalizes directly: adding a mechanism to defend
  against a single known instance, when three prior sessions (`#0330`,
  `#0347`, `#0356`) already concluded the terminating move was to stop
  claiming more than a check establishes, is the wrong shape here too.
- A guard could only ever prove a citation *exists* in some non-drifting
  form, never that it is *true* — the same limit `#0356` recorded. Fixing
  the one real site directly establishes the same true fact more cheaply.

So: fix the one site, build nothing.

## Fix

`internal/handlers/citation_target_guard_test.go:264` read:

> `— see that file's line 25 for the real text: a`

**Re-measured the referent myself, not from this issue's prose**:
`grep -n "internal/seo/seo.go/sitemap.go" internal/handlers/admin_workshops.go`
→ still line 25 today, inside the file's **package doc comment** (the single
comment block immediately preceding `package handlers`, lines 1-32). That
comment block is a stable, non-drifting anchor for exactly the reason §11's
PRD index and `#0352`'s identifiers are: it is unique per file (Go allows
one package clause per file) and is invalidated only by an edit to the
comment itself, never by an edit to anything else in the file above it.

Replaced the citation with that anchor:

> `— see that file's package doc comment for the real text: a`

This respects why the "line 25" phrasing existed in the first place: the
literal four-segment token (`internal`/`seo`/`seo.go`/`sitemap.go`) still
cannot be spelled out here, because this very comment is scanned by
`pathCitationIsExcluded`'s own guard below it, and spelling it would make
the guard self-referential (exactly as the surrounding paragraph already
explains for its other two examples). "Package doc comment" names the
*location* without spelling the *token*, the same way the two neighbouring
examples in this paragraph already do.

Diff is comment-only, four lines touched (`git diff` below), and re-running
`linecensus internal cmd` after the edit reports `hits=37` (down from 38)
with the `citation_target_guard_test.go:264` row gone from the output.

## Acceptance criteria

1. **Census first, and decide afterwards.** Count the bare positional
   references — "line N", "lines N–M", "the Nth line" and near neighbours —
   across Go comments, and classify each as a real positional citation versus
   prose that legitimately discusses a line number. **A guard is not
   automatically the answer**: if the census comes back at one or two sites, say
   so and fix them without building anything. That judgement is part of this
   issue's deliverable, not a preamble to it.
2. The census tool scans only `f.Comments` from a `ParseComments` walk, so
   string literals cannot enter the population by construction, and is proved
   falsifiable and fail-closed **before** use. Seven agents found genuine
   fail-opens in their own instruments on 2026-08-31; build to a binary and read
   an explicit verdict line, not an exit code.
3. `citation_target_guard_test.go`'s "line 25" reference is replaced with
   something that does not drift — and the replacement must respect **why** it
   was written that way, since that file's own path guard forbids spelling the
   token it points at. Re-measure the referent yourself rather than trusting
   this issue.
4. If a guard is built, it must state the false-positive class it accepts and
   pin its calibration in fixtures rather than prose — see `#0358`, which exists
   because `#0347` described its window limits in a sentence that went stale.
5. No `.ClaimDue(` / `.OrphanSweep(` / `.SelectDue(` call-syntax literal enters
   any Go comment, and the floor harness population stays **42 total / 12
   non-exempt** (`#0323`'s trap).
6. `gofmt` stability: file sha256 equals sha256 of `gofmt` stdout (§8).
