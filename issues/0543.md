## Description

Outreach (design: "Outreach — Design Proposals", https://claude.ai/artifact/DzCWVhfcqJbc9uSfWLVfhG)
creates a ShortLinks campaign per workshop and tagged short links per post and
flyer location. ShortLinks now accepts API tokens on every `/api/*` route
(`~/Developer/brennanMKE/ShortLinks/docs/api-tokens.md`,
`docs/using-api-tokens.md`, `docs/campaigns.md`, `docs/links.md`). This issue
adds a small, narrow Go client package and its configuration; nothing calls it
yet.

## Acceptance criteria

- [ ] New package `internal/shortlinks` (standard-library `net/http`, no new dependency) with a `Client` exposing at least: `Me`, `GetCampaign(slug)`, `CreateCampaign`, `EnsureCampaign(slug, name, …)` (GET first, create on 404 — idempotent by convention, see Notes), `CreateLink` (destination URL, `campaign_slug`, `utm_*`, `placement`, optional custom `key`, title), `GetLink(key)`, `LinkQRSVG(key)`, `CampaignStats(slug, from, to)`.
- [ ] Sends `Authorization: Bearer <token>` only; never logs or returns the token in an error string. Errors decode ShortLinks' `{"error":…}` body into typed/sentinel errors (401 unauthenticated, 403, 404, 409, 429 with `Retry-After`).
- [ ] Bounded timeouts on every call; response bodies size-limited.
- [ ] Config: `SHORTLINKS_BASE_URL` and `SHORTLINKS_API_TOKEN`, both optional. When either is unset, outreach features are reported unavailable (a nil/disabled client), and the service still boots. `.env.example` lists both (guarded by `internal/config`'s `TestEnvExampleCoversLoaderVariables`); `docs/configuration.md` documents them.
- [ ] Unit tests against `httptest.Server` fakes cover each method, the auth header, error decoding, and that the token never appears in an error.
- [ ] Optional live smoke test gated on an env var (e.g. `SHORTLINKS_LIVE_TEST=1`), skipped by default, that calls `Me` against the configured local server.

## Notes

- **Local dev server:** the user runs ShortLinks at `http://localhost:5173` (Vite, proxies `/api`). The token lives in this repo's `.env` as `SHORTLINKS_API_TOKEN` (gitignored) and only works against that local server, **for this session only**. Never print it, paste it into an issue, commit it, or put it in a transcript — show `<redacted>` (CLAUDE.md §8b). Verified 2026-10-16: `GET /api/me` with it returns 200.
- ShortLinks has **no client-chosen campaign slug and no idempotency key.** Slug is derived from `name`. Outreach therefore names the campaign with the workshop slug so the derived slug equals it, and `EnsureCampaign` looks it up before creating. Verify ShortLinks' slugify leaves an already-slugged string unchanged; if not, store whatever slug the create returns.
- Single link create (`POST /api/links`) de-duplicates on `destination_url`; since every outreach link's destination carries unique UTM values, a retried create returns the same link — that is the retry-safety story, so do not use `/links/batch` (which never de-duplicates) for outreach.
- `POST /api/links` accepts `key`/`custom_key`/`alias` for a custom key (ShortLinks `internal/handlers/links.go` `createLinkRequest`).
- `/api/me` returns `base_url` — the short-URL host to display (`http://localhost:8080` locally, `https://go.opencircuitsf.com` in production).

## Review notes

Reviewed 2026-10-16 (Opus, phase 3). Approved.

- **Shapes checked against ShortLinks source, not assumed.** Every route the client calls exists in ShortLinks' `cmd/shortlinks/main.go` route table under `requireAPI`. `GET /api/campaigns/{slug}` writes a `campaignDetailView`, which **embeds** `campaignView`, so `id`/`name`/`slug`/etc. are top-level fields — the implementer's assumption holds (`link_count`/`total_clicks` are siblings, also matching). `POST /api/campaigns` returns 201 with a bare `campaignView`. `createCampaignRequest` and `createLinkRequest` field names match the client's JSON tags one for one (`key` is the first of the three custom-key aliases ShortLinks accepts). `POST /api/links` returns 201 with a `linkView` carrying `duplicate`; `GET /api/links/{key}` returns `linkDetailView` embedding `linkView`. Stats takes `from`/`to` as `YYYY-MM-DD`. Errors are `{"error": "..."}` via `writeError`; 429 sets an integer-seconds `Retry-After` (`middleware/apitoken.go`). Slugify lowercases and collapses non-alphanumerics, so an already-slugged workshop slug is unchanged.
- **Live, read-only:** `GET /api/me` against `localhost:5173` returned exactly the `Me` shape (`id`, `email`, `is_admin`, `base_url`, `api_token{id,name,read_only}`); `GET /api/campaigns` returned `{"campaigns": []}`, so no live campaign detail was available — the embedding is confirmed from source instead; `GET /api/campaigns/<nonexistent>` returned 404 `{"error":"campaign not found"}`, which the client maps to `ErrNotFound` so `EnsureCampaign` creates. Token loaded into a shell variable and redacted; never displayed.
- **Token handling:** sent only in the `Authorization` header; transport errors are rebuilt from method + path (no URL, no header); `APIError` formats status + server message only. Nil client: every method funnels through `do`, which returns `ErrUnavailable` before touching any field. 15s `http.Client` timeout plus caller context; 4 MiB body cap read via `LimitReader(max+1)` and rejected when exceeded.
- **Independent verification:** `ISSUE=0543 scripts/check.sh go ./internal/shortlinks/... ./internal/config/... ./internal/db/... ./internal/handlers/...` — load 4.79, build/vet/gofmt clean, all four packages `ok`, no skips, VERIFICATION PASSED. `go test ./internal/shortlinks -v` showed all 12 unit tests PASS and the live test SKIP by default; with `SHORTLINKS_LIVE_TEST=1` against the local server it PASSED.
- **Non-blocking observations, recommended as follow-ups:**
  1. `APIError.Message` is the server's `error` string verbatim. ShortLinks never echoes the token, but a hostile or misconfigured server returning the bearer value inside a JSON `error` field would surface it in `err.Error()`. Defense in depth: redact `c.token` from `Message` in `decodeError`, and add a JSON-body case to the token-leak test (the existing case only covers a plain-text 500).
  2. `EnsureCampaign(slug, name, …)` is idempotent only when `Slugify(name) == slug`; a caller passing a display name like "Intro to Soldering" would create `intro-to-soldering`, then miss on the next GET by the workshop slug and create a suffixed duplicate every call. The doc comment states the convention, but the signature invites the mistake. Either drop the separate `name` parameter (always name the campaign with the slug, carrying the display name in `Description`) or reject a mismatch up front. Worth settling before `#0544` consumes it.
  3. The `CreateLink` doc comment says a retried create returns the existing link; that holds only without a custom `Key` — ShortLinks never de-duplicates custom aliases, so a retry with `Key` set answers 409 `ErrConflict`. One-line doc fix, or have callers treat 409 on a custom key as "fetch with `GetLink`".

## Root cause

No code existed to call the ShortLinks REST API; outreach issues depend on it.

## Fix

`internal/shortlinks` client (stdlib only) plus optional `SHORTLINKS_BASE_URL` / `SHORTLINKS_API_TOKEN` config. `New` returns a nil client when either is unset; `Enabled` is nil-safe and methods on a nil client return `ErrUnavailable`. `EnsureCampaign` is GET-then-create-on-404 and returns the create response's slug as authoritative (ShortLinks' slugify lowercases and collapses non-alphanumerics, so a lowercase hyphenated workshop slug is unchanged). `CampaignStats` returns raw JSON (`json.RawMessage`) since the rollup shape is not yet consumed. No custom-key or batch endpoint beyond `POST /api/links`. Not wired into `cmd/opencircuit`; nothing calls it yet.
