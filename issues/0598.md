## Description

From `#0596`'s review. `net/http`'s `Shutdown` treats a `StateNew`
connection as busy until it is about 5s old (Go issue 22682), which equals
`shutdownServerTimeout`. A connection that never sent a request therefore
makes `Shutdown` time out, `serve()` return an error, and systemd record the
stop as `status=1/FAILURE`, with a misleading journal line and a 5s delay. In
production Apache fronts the service and opens backend connections only to
send a request, so this is unlikely there; dev `--built` (a browser talking to
the listener directly) can hit it. Low priority.

## Acceptance criteria

- [x] When `Shutdown` hits its deadline and every remaining connection is
      `new`, call `srv.Close()` and return nil (nothing to drain). Any
      non-`new` connection still produces today's error and log line
      unchanged (`#0536`'s assertions hold).
- [x] A test built on `TestMountAndServe_ShutdownTimeoutNamesWhatHeldItOpen`:
      one silent raw TCP connection → clean return; one active request
      outliving the budget → the existing error.
- [x] `ISSUE=0598 scripts/check.sh go ./cmd/opencircuit/... ./internal/handlers/...`
      green, zero skips.

## Relation

- Follows `#0596`, `#0536`.

## Resolution

`mountAndServe`'s shutdown path now asks the existing `activeConnSet` (the
`ConnState` tracker from `#0536`) `allNew()` when `srv.Shutdown` returns
`DeadlineExceeded`. If at least one connection is recorded and all are
`StateNew`, it logs one line, calls `srv.Close()` and returns nil. Any
`active`/`hijacked` connection (or an empty set) takes the unchanged error and
log path. No deadline was widened.

Test change worth reviewing: `#0536`'s test held a connection with a partial
request header, which is `StateNew`, so under this criterion it correctly
returns nil. It now holds an `active` connection instead (full headers,
`Content-Length: 100`, 7 body bytes) and asserts the same error fields plus
` active`. Both tests share `runShutdownHoldingConn`;
`TestMountAndServe_ShutdownClosesNeverUsedConnections` covers the silent raw
connection (clean nil).
