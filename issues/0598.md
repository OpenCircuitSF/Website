## Description

From `#0596`'s review. `net/http`'s `Shutdown` treats a `StateNew`
connection as busy until it is about 5s old (Go issue 22682), which equals
`shutdownServerTimeout`. A connection that never sent a request therefore
makes `Shutdown` time out, `serve()` return an error, and systemd record the
stop as `status=1/FAILURE`, with a misleading journal line and a 5s delay. In
production Apache fronts the service and opens backend connections only to
send a request, so this is unlikely there; dev `--built` (a browser talking to
the listener directly) can hit it. Low priority.

## Acceptance criteria

- [x] When `Shutdown` hits its deadline and every remaining connection is
      `new`, call `srv.Close()` and return nil (nothing to drain). Any
      non-`new` connection still produces today's error and log line
      unchanged (`#0536`'s assertions hold).
- [x] A test built on `TestMountAndServe_ShutdownTimeoutNamesWhatHeldItOpen`:
      one silent raw TCP connection → clean return; one active request
      outliving the budget → the existing error.
- [x] `ISSUE=0598 scripts/check.sh go ./cmd/opencircuit/... ./internal/handlers/...`
      green, zero skips.

## Relation

- Follows `#0596`, `#0536`.

## Resolution

`mountAndServe`'s shutdown path now asks the existing `activeConnSet` (the
`ConnState` tracker from `#0536`) `allNew()` when `srv.Shutdown` returns
`DeadlineExceeded`. If at least one connection is recorded and all are
`StateNew`, it logs one line, calls `srv.Close()` and returns nil. Any
`active`/`hijacked` connection (or an empty set) takes the unchanged error and
log path. No deadline was widened.

Test change worth reviewing: `#0536`'s test held a connection with a partial
request header, which is `StateNew`, so under this criterion it correctly
returns nil. It now holds an `active` connection instead (full headers,
`Content-Length: 100`, 7 body bytes) and asserts the same error fields plus
` active`. Both tests share `runShutdownHoldingConn`;
`TestMountAndServe_ShutdownClosesNeverUsedConnections` covers the silent raw
connection (clean nil).

## Review notes

Approved (Opus, 2026-10-18). Checked:

- **`allNew()` semantics.** Empty set returns false, so the old error path and
  its "went idle" report are unchanged. Any `active`/`hijacked` entry returns
  false, so the old path runs. It reads the set under `t.mu`, the same lock
  `track` writes under, so it races nothing.
- **new→active between `allNew()` and `srv.Close()`.** This window exists. A
  StateNew connection can still read its first request during Shutdown,
  because `inShutdown` only turns off keep-alives, so that request could be
  cut off by `Close`. The window is microseconds long, and it opens only
  after the budget has already run out. Under the old path the process exits
  right after `mountAndServe` returns, which kills that request anyway, so
  calling `Close` adds no new way to lose work. Accepted. Not worth a lock
  across the two calls.
- **Return paths.** The only difference between the two is the
  `if … allNew()` block (`srv.Close()` + nil). Both then run the same
  `subscribeH.Close(closeCtx)`, which drains send workers and releases
  claims on its own separate budget, and the same `return`. Nothing that
  `mountAndServe` does after a clean `Shutdown` gets skipped. Returning nil
  hides nothing: only connections with no request read are closed, and one
  log line still records it.
- **The #0536 test rewrite keeps its intent.** #0536 asked that a timed-out
  shutdown name what held it open. The test now keeps an `active` request
  open (headers complete, body short), and the same error-text assertions
  run against it: `graceful shutdown incomplete`, the budget, `connections
  still active at expiry`, `1 connection(s)`, `127.0.0.1`, plus ` active`
  in place of ` new`. The slowloris-style partial header #0536 used is
  StateNew and now ends shutdown cleanly by being closed. That is correct,
  because no request was read from it.

Fixes made in review (test file only):

1. `TestMountAndServe_ShutdownTimeoutNamesWhatHeldItOpen`'s doc comment still
   said it sent an unterminated header and parked the connection in StateNew,
   and gave the 500ms reasoning in StateNew terms. Rewritten for the active
   shape, with a pointer to the new test.
2. The error-text assertion hardcoded `(500 * time.Millisecond)`, a copy of
   the helper's local const. Both now use the package-level
   `declineShutdownBudget`, so they cannot drift apart.
3. `TestMountAndServe_ShutdownClosesNeverUsedConnections` would also have
   passed if the silent connection never reached the tracked set (Shutdown
   returns nil quickly). Added a lower-bound elapsed check (≥ 250ms +
   budget after the connection was opened). It is a floor, and load can
   only make the run longer.

Mutation (reviewer): `&& false && activeConns.allNew()` makes
`TestMountAndServe_ShutdownClosesNeverUsedConnections` fail with the old
`... 1 connection(s): 127.0.0.1:… new` error. `main.go` was restored and its
sha256 `e2572712…0eee` matched the copy taken before the mutation. Together
with the implementer's opposite-direction mutation, both directions are pinned.
