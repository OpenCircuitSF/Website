## Description

Admin screen and endpoints to add, edit, reorder, and deactivate interests without a deploy.

## Acceptance criteria

- [ ] `GET/POST/PATCH/DELETE /admin/interests[/{id}]`, all admin-gated
- [ ] Admin view lists interests with subscriber counts per interest
- [ ] Create and edit forms validate slug format and uniqueness
- [ ] Reordering updates `sort_order`
- [ ] Deactivate hides the interest from the public form but preserves `subscriber_interests` rows
- [ ] Delete is refused when any subscriber is associated — deactivate instead, with a clear error message
- [ ] Audit rows written for every mutation
- [ ] Go handler tests and `npm run check` / `npm test` pass

## Notes

PRD §5.2, §8. The subscriber count per interest is the number that makes this screen useful — it is what tells the operator whether a segment is worth a campaign.
