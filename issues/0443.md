## Description

`internal/seo/archive.go`'s `ArchiveSource` interface doc says `#0123`'s real
store **"is expected to be wired in from the start"**, contrasting it with
`WorkshopSource`'s staged `#0051`/`#0054` rollout.

`#0123` is `resolved`, and `campaignArchiveSEOSource` is wired unconditionally
in `servePostgres`. The sentence describes a future that has already happened.

## Why this is the same defect `#0439` closed, not a smaller one

`#0439`'s subject was that a doc comment can assert **a false state of the
world** rather than merely carry a stale reference — the second is a pointer at
something that moved, and a reader has a cue to check it; the first is a claim
in the document's own voice, and a reader has none.

`is expected to be` is that exact idiom, four files away from the two instances
`#0439` removed. `#0439`'s implementer found it, judged it a **permanent
design-contrast statement** — true regardless of resolution status — and left it
alone. `#0439`'s reviewer **disagreed on review**, and this issue is that
disagreement:

> The tense does not carry the historical reading. It is the same
> forward-looking construction the issue removed four files away, and a reader
> arriving from `sitemap.go`'s "nilable, see `ArchiveSource` doc (`#0123`)" can
> take it as "not yet wired" — the precise harm the issue names.

The design contrast itself is worth keeping. Only the tense is wrong.

## Why it was reported rather than folded in

`#0439`'s reviewer passed the issue anyway, on this lineage's own precedent:
`#0425`'s third pass deliberately left `NewRenderer`'s sibling instance out of
scope and `#0425`'s reviewer *reported* the `WorkshopSource` instance rather
than widening its issue — which is exactly how `#0439` came to exist. Widening
an issue to whatever the sweep turns up is how a two-line fix becomes a
six-pass one.

## Acceptance criteria

1. `is expected to be wired in` → `was wired in`, preserving the design
   contrast intact. The reviewer specified this remedy as **one word**; do not
   redesign the sentence around it.
2. Confirm by reading the call site that `campaignArchiveSEOSource` really is
   passed unconditionally in `servePostgres`, so the new past tense is true.
   `#0439`'s review established the full construction chain — `buildSEOSite` has
   exactly two non-test callers under a total, exclusive `DevMode()` dispatch —
   so this should be a confirmation, not an investigation.
3. **No new mechanism** (`#0437`'s criterion 5, `#0439`'s criterion 5, `#0258`).
   `#0439`'s review examined pinning this class of claim with a test and

   `TestServePostgres_OneSEOSiteFlowsToEveryConsumer`, and a guard whose subject

4. Re-run the sweep once with a phrase net **not** keyed on an issue-number
   pattern — `#0439`'s reviewer did exactly that and got 13 hits, with
   `archive.go` the only remaining instance. Confirm that still holds and say so.

The work log as committed cited the call site as a **bare line number**. That
is the form `#0352`/`#0384` settled against, for the reason that every edit
above the cited line moves what the number points at — and this file is
concurrently dirty, which is exactly the drift the convention anticipates.

`internal/db`'s `TestNoOpenIssueEvidenceCitesGoFileByLineNumber` passed over it,
and the byte-scan explains why rather than contradicting it: the guard scans
only the headings in `issueCitationSectionHeaders` (`verification`,
`implementation notes`, `fix pass`, `review notes`, and three older spellings).
`## Work log` — this repo's actual home for an implementer's evidence — is not
among them, so the citation sat outside the guard's scope rather than exempt
within it. This is precisely the residual the guard's own doc comment names.

Corrected here rather than bounced: the same sentence already carried the
stable identifier the convention asks for, so dropping `:255` and keeping
`cmd/opencircuit/main.go` + `servePostgres` falsifies nothing in the record and
loses no information. A full implementation pass to delete four characters of
prose would cost more than the defect. `archive.go` itself carries no such
citation — byte-scanned, zero hits.

**Reported, not filed (§9):** the gap between `issueCitationSectionHeaders` and
this repo's `## Work log` convention looks worth an issue. An implementer
recording evidence under the standard heading is unscanned by the guard meant
to cover exactly that text, with no intent to dodge it.
