## Description

`internal/outbox/claim_kinds_call_site_guard_test.go:204`, inside
`claimKindsGuardMinPlausibleNonExemptCallSiteCount`'s `#0322` paragraph, cites
`internal/mailing/worker.go:575` for the unrelated
`mailing.SendStore.OrphanSweep` name collision. Measured by AST census today,
that call is at **`worker.go:625`**.

`nameMatchesGuardedMethod`'s doc comment ~300 lines below in the same file
already carries the correct number. **So one file states two different
locations for the same call**, and nothing detects the divergence: the shell
harness checks constants and required-site names, and
`internal/db/prd_section_index_test.go` covers only `PRD.md`.

**Correcting `575` to `625` buys nothing.** The next unrelated edit to
`worker.go` re-breaks it — which is exactly what already happened here. A line
number in a doc comment drifts on every edit to the cited file and is checked
by nothing, and this project already knows the answer: §11's PRD index was
deliberately rewritten to be **heading-anchored rather than line-numbered**,
"so they survive edits to the PRD".

This is the third comment-accuracy defect in this one guard family
(`#0334`, `#0345`, and now this), and today three separate reviews had to
re-measure numbers in this file.

**Note for whoever picks this up**: `#0330`'s implementer reported this defect
at `nameMatchesGuardedMethod`'s comment citing `worker.go:543`/`:575`. That
report is itself wrong — `nameMatchesGuardedMethod` is correct, the string
`:543` appears nowhere in the file, and the single stale citation is the one at
line 204. Re-measure rather than trusting either that report or this paragraph.

## Root cause

Two paragraphs of `claim_kinds_call_site_guard_test.go` cite the same real
call site — `mailing.SendStore.OrphanSweep`'s invocation inside
`Worker.drainCampaign` — by line number, and the numbers had drifted apart
(`:575` vs. the correct `:625`) after an unrelated edit to `worker.go`.
Nothing in the guard family checks a doc comment against the tree it
describes, so the divergence was invisible until a human (or reviewer)
happened to re-measure.

## Fix

Re-measured both citations myself, independent of this issue's own prose,
`#0330`'s implementer report, and the file's own (correct) claim:

- **Method**: `grep -n "OrphanSweep" internal/mailing/worker.go
  internal/mailing/worker_store.go internal/mailing/worker_store_test.go`,
  cross-checked against which enclosing function/test each hit falls under
  (`grep -n '^func ' internal/mailing/worker.go` bracketing the call line).
- **Result**: the call lives at `internal/mailing/worker.go:625`, inside
  `func (w *Worker) drainCampaign(...)` — **not** `Worker.recoverOrphans`,
  the name this issue's own criterion 2 example used; no such identifier
  exists anywhere in the tree (`grep -rn recoverOrphans internal/mailing`
  returns nothing), so that example was illustrative, not a fact to copy.
  `worker_store_test.go`'s three call sites split as one call inside
  `TestSendStore_OrphanSweep_ResetsOnlySendingRows` and two inside
  `TestSendStore_OrphanSweep_LeavesFreshlyClaimedRowAlone`.

Replaced both citations (the stale one at the old line ~204 and the
already-correct one at the old line ~527, in `nameMatchesGuardedMethod`'s
doc comment) with those names — `Worker.drainCampaign`'s call, and the two
named test functions — rather than updating `575` to `625`. A repo-wide
survey (`grep -noE '[A-Za-z0-9_./]+\.go:[0-9]+'` over the file) found
**exactly these two** `<file>.go:<int>` citations in the whole file, both
now removed; the same grep against the post-edit file returns zero matches.

No check, constant, assertion, or the required-sites list in this file was
altered — confirmed by `scripts/go_file_visit_floor_guard_test.sh` (still
42 total / 12 non-exempt) and by `ISSUE=0352 scripts/check.sh guards`
passing unchanged.

**Criterion 5 — extending the citation-guard family to flag `<file>.go:<int>`
repo-wide — judged out of scope for this pass, not silently skipped.**
Reason: `internal/handlers`' existing citation-guard family
(`dangling_test_citation_guard_test.go`, `citation_target_guard_test.go`,
`misattached_doc_comment_guard_test.go` — ~2,200 lines together) is the
product of five issues' worth of design iteration each (`#0190`, `#0192`,
`#0196`, `#0199`, `#0216`, `#0220`), with mutation-tested exclusion rules
and an external shell oracle per guard. A `<file>.go:<int>` pattern has a
harder false-positive surface than a path or `CLAUDE.md §N` citation: it
must be told apart from a runtime-computed `%s:%d` diagnostic format
string (this very file uses one, e.g. `"%s:%d: %s called with no
kinds..."`), from a legitimate external stack-trace or log-line reference,
and from the guard family's own self-citations of its own line numbers in
places that are fine to leave as-is. That is real design latitude — per
`CLAUDE.md` §3's own criteria for when a planning pass earns its cost
("its acceptance criteria are ambiguous enough that two implementers would
build different things") — and mixing an unplanned ~500-line guard into a
comment-only fix (criterion 6) would also blow past this issue's own
proved scope. Recommending a new issue, planned by Opus (Phase 1) before
a Sonnet implementation pass, rather than building it here unplanned.

## Verification

- `grep -noE '[A-Za-z0-9_./]+\.go:[0-9]+'
  internal/outbox/claim_kinds_call_site_guard_test.go` — zero matches after
  the edit (two matches, `worker.go:575` and `worker.go:625`, before).
- **Criterion 6 (comment-only, structural proof).** Built a standalone Go
  tool (`commentdiff`, compiled to a binary, read via an explicit
  `VERDICT:` line per §8's fail-open catalogue) that parses two files with
  `go/parser` WITHOUT `ParseComments` (comments never enter the AST),
  re-renders each with `go/printer` under an identical config, and compares
  SHA-256 of the rendered bytes.
  - **Falsifiability proved first**: fed a real code-changing fixture pair
    (`const N = 1` vs. `const N = 2`, both carrying an identical comment) —
    tool reported `VERDICT: CODE-DIFFERS`, distinct hashes.
  - **Fail-closed proved**: an empty file, a structurally broken file
    (unbalanced brace — `go/parser` genuinely refuses to parse it, unlike a
    bare `go/scanner` tokenizer, which would happily tokenize broken
    syntax), a missing file, and a bad argument count all produced
    `VERDICT: ERROR: <reason>`, never `VERDICT: COMMENT-ONLY`.
  - **Real comparison**: `commentdiff <(git show HEAD:…) <working tree copy>`
    → `VERDICT: COMMENT-ONLY`, `sha256(canonical A) = sha256(canonical B) =
    d364b589…eece665`.

## Acceptance criteria

1. The stale citation at line 204 no longer states a wrong location.
2. **Cited positions are replaced with stable identifiers rather than corrected
   numbers** — name the declaration and the call (`Worker.recoverOrphans`'s call
   to `SendStore.OrphanSweep`; `worker_store_test.go`'s three sites), the way
   §11's heading-anchored index does. A pass that merely updates `575` to `625`
   does not resolve this issue.
3. Apply this throughout the file, not only at line 204 — a survey of every
   `<file>.go:<int>` citation in it, each one either removed in favour of an
   identifier or justified in place.
4. Any location stated is re-measured against the tree, not copied from this
   issue or from any comment. Record the method.
5. **Consider extending the existing citation-guard family** in
   `internal/handlers` — which already catches comments citing unresolvable
   paths and undefined test functions — to flag `<file>.go:<int>` citations in
   Go doc comments repo-wide. If you judge that out of scope or not worth it,
   say so explicitly with a reason rather than silently skipping it; that
   judgement is part of this issue's deliverable.
6. Comment-only. Prove it structurally: parse both revisions with comments
   excluded, compare bytes, tool proved falsifiable first and failing closed on
   empty input (§8 — three agents found genuine fail-opens in their own
   instruments this session).
7. No `.ClaimDue(` / `.OrphanSweep(` / `.SelectDue(` call-syntax literal
   introduced into any Go comment (`#0323`'s trap — documenting the pattern once
   inflated the measured population 35 → 36). Re-run
   `scripts/go_file_visit_floor_guard_test.sh` and record the population
   (currently 42 total / 12 non-exempt).
8. `gofmt` stability: file sha256 equals sha256 of `gofmt` stdout — these are
   declaration doc comments, exactly what §8's smart-quote gotcha rewrites.
