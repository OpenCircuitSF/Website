# 0498 — `Precedence: list` is treated as an auto-reply signal, and it silently parks legitimate unsubscribe requests

| | |
|---|---|
| **Status** | open |
| **Platform** | Server |
| **Module** | inbound |
| **Phase** | 7 — Inbound and polish |
| **First seen** | 2026-09-10 |

## Description

`#0058`'s auto-reply detector treats any one of six header signals as
sufficient to classify an inbound message as machine-generated and skip it.
Five of the six are sound. The sixth, `Precedence: list`, is not a
machine-generation signal at all — it marks mail as having passed through a
list manager, which is orthogonal to whether a human wrote it.

A person who replies to an Open Circuit campaign from an address that relays
through a mailing list, a group alias, or a corporate distribution list can
therefore have a genuine unsubscribe request classified as an auto-reply.

## Why the failure is not neutral

The no-match and auto-reply paths both do the right thing structurally — log,
leave the object in S3, return 200 (`#0058` criterion 5, which exists to stop
SNS redelivery looping). The consequence is that a real unsubscribe request
lands in a bucket and **nothing surfaces it**. See `#0499`, which is the
companion defect: there is no reviewer for parked objects, so the 30-day
lifecycle rule eventually deletes the evidence that the request ever arrived.

An unsubscribe request that is silently dropped is the one failure this
subsystem exists to prevent. CAN-SPAM treats unsubscribe handling as
mandatory, and `CLAUDE.md` §9 already records that this project does not get
to be casual about it.

## Suggested remedies, either acceptable

1. **Drop `list` from the `Precedence` set**, keeping `bulk`, `auto_reply` and
   `junk`. Simplest, and the three retained values are all genuinely
   machine-generation markers.
2. **Require a second, independent signal** when `Precedence: list` is the only
   one present — so a list-relayed message still needs, say, an
   `Auto-Submitted` or a null `Return-Path` before being skipped.

Whichever is chosen, add a test proving a human-written message carrying
`Precedence: list` and a resolvable unsubscribe token **is** processed.

## Acceptance criteria

1. A message whose only auto-reply signal is `Precedence: list`, carrying a
   valid token, results in an unsubscribe and an audit row with
   `source = 'mailto'`.
2. `bulk`, `auto_reply` and `junk` continue to classify as auto-replies, each
   with a test case.
3. The chosen remedy is recorded in the detector's doc comment, so the next
   reader knows `list`'s absence is deliberate rather than an oversight.
4. Do not weaken the ordering `#0058` established: the auto-reply check still
   runs **before** any token or `From:` matching.
