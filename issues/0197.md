## Description

`#0195`'s phase-3 review passed the branch reorder and then made a point that
outlives it: **this tracker has now hit the replicated-logic trap three times.**

- `#0184` — a hand-rolled `normalizeCountInput` replica, caught by hex dump.
- `#0189` — the same replica, wrong separator class, caught by hex dump again.
- `#0195` — `countInputDisabled` / `escapeCloses` / `backdropCloses` in
  `CampaignSendDialog.guard.test.ts`, one-token mirrors of the component's own
  `sending` / `!sending` / `!sending` gates.

The `#0195` instance is the mildest — an identity function cannot disagree with
`disabled={sending}`, and the assertive weight sits on
`expect(sendingDuringFlip).toBe(true)`, which mutation B genuinely catches. But
it can drift silently: changing the component to `disabled={sending ||
blockedAgain}` leaves the replicas green while their coverage claim goes stale.
`#0186`'s `oldSending` / `oldBlockedAgain` formulas have the same shape.

**The fix is cheaper than it looks, and it already exists in this repo.**
`web/src/lib/citationGuard.test.ts` parses `.svelte` files with
`svelte/compiler`'s AST inside vitest — no DOM, no `#0094`. A structural guard in
that style can assert the component's real gate expressions match what the tests
claim they are, making drift loud at a fraction of `#0094`'s cost.

**A second, low-value item from the same review:** `sendGuardState`'s doc comment
quotes only one of `#0184`'s three arguments for the original branch order (the
render-gate one). `#0184` also argued `status` is durable and server-authoritative,
and — the actual tie-breaker — that neither ordering differed in safety. It was
that third argument collapsing (once `#0186` wired in a consumer where
`unavailable` disables nothing) that justified `#0195`'s reorder. The comment
should name all three so the reasoning survives.
