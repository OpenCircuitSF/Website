## Description

`scanInvalidatorSatisfiers`' package-scope-alias branch in
`internal/seo/invalidator_satisfier_guard_test.go` has **three `continue`
exclusions**. `#0353`'s review verified all three are *correct* against
`go/types` truth, and `#0354` pinned the `||` beneath them — but **two of the
three `continue`s are themselves pinned by nothing.**

Measured by `#0354`'s review:

| Mutation | Result |
|---|---|
| C4 — disable the alias-to-pointer-to-`*types.Named` `continue` | **every test in the tree stays green** |
| C5 — disable the declared-interface `continue` | **every test in the tree stays green** |

Under either, the guard begins double-counting a redundant spelling as a fresh
satisfier — the exact failure mode `#0337`'s third review's N2/N3 rulings exist
to prevent.

This is the same family as `#0349` → `#0353` → `#0354`: a check that is correct
while nothing pins the part doing the work.

**One non-obvious point, and it is the reason a naive fixture would not
work.** The pairing is not what it looks like: an alias to a *declared*
interface (`= Seam`) never reaches the interface `continue` at all, because the
`*types.Named` `continue` fires first. **Only an alias to an interface
*literal* exercises it.** A pass that adds `= Seam` and believes it has pinned
the interface case has pinned nothing.

## Acceptance criteria

1. Add to the existing synthetic source in
   `TestInvalidatorSatisfierSet_AliasToTypeLiteral`:
   `type DeclaredSeam interface{ Invalidate() }`,
   `type AliasToPtrNamed = *Site`, and
   `type AliasToIfaceLiteral = interface{ Invalidate() }`.
2. Add two **negative** assertions: `got["AliasToPtrNamed"]` and
   `got["AliasToIfaceLiteral"]` are both false.
3. **Prove the pinning discriminates** — this is the point of the issue, not a
   formality. The suite must pass unmutated, fail under C4 naming
   `AliasToPtrNamed`, and fail under C5 naming `AliasToIfaceLiteral`. Record all
   three results. `#0354`'s review already verified this remedy end to end, so
   reproduce rather than redesign.
4. The third `continue` (alias to a `*types.Named`) is already pinned by
   `#0337`'s N2 ruling — confirm that, and do not add a redundant fixture for
   it.
5. No regression: `#0353`/`#0354`'s M1–M8 still FAIL naming the right type
   (M1 by the guard's own assertion, not `[build failed]`), N1–N3 still PASS,
   and the discriminating single-disjunct mutations from `#0354` still fail
   correctly.
6. The synthetic source must remain **ordinary canonical Go**. `#0354`'s
   reviewer proved this by extracting the `src` constant to a real file and
   running `go build`, `go vet` and `gofmt -l` on it — a fixture that only
   `types.Config.Check` tolerates is a slow drift toward testing something
   else. Repeat that check after adding the three types.
7. Mutations in a `git archive` export or throwaway worktree, never the shared
   tree (§8b), with a whole-tree hash manifest diffed after each.
8. `GOFLAGS=-mod=readonly` on every loader run; `git status -- go.mod go.sum`
   checked before committing (§8b — that trap fired for real in this checkout
   on 2026-08-31).
9. `gofmt` stability: file sha256 equals sha256 of `gofmt` stdout (§8).
