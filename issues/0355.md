## Description

`scanInvalidatorSatisfiers`' package-scope-alias branch in
`internal/seo/invalidator_satisfier_guard_test.go` has **three `continue`
exclusions**. `#0353`'s review verified all three are *correct* against
`go/types` truth, and `#0354` pinned the `||` beneath them — but **two of the
three `continue`s are themselves pinned by nothing.**

Measured by `#0354`'s review:

| Mutation | Result |
|---|---|
| C4 — disable the alias-to-pointer-to-`*types.Named` `continue` | **every test in the tree stays green** |
| C5 — disable the declared-interface `continue` | **every test in the tree stays green** |

Under either, the guard begins double-counting a redundant spelling as a fresh
satisfier — the exact failure mode `#0337`'s third review's N2/N3 rulings exist
to prevent.

This is the same family as `#0349` → `#0353` → `#0354`: a check that is correct
while nothing pins the part doing the work.

**One non-obvious point, and it is the reason a naive fixture would not
work.** The pairing is not what it looks like: an alias to a *declared*
interface (`= Seam`) never reaches the interface `continue` at all, because the
`*types.Named` `continue` fires first. **Only an alias to an interface
*literal* exercises it.** A pass that adds `= Seam` and believes it has pinned
the interface case has pinned nothing.

### 7. On the record: is the alias branch now fully pinned, and does the recursion stop?

**It stops here.** Not because nothing survives, but because everything that
survives has been measured and none of it can change an answer.

`#0349` → `#0353` → `#0354` → `#0355` each found the previous round's blind
spot, so the burden is on stopping, not on continuing. Here is the case:

1. **Every mutation of the alias branch that can change `got` is now caught.**
   Across the two reviews the branch has taken twenty-one distinct mutations
   (`#0354`'s C1–C8 plus this pass's C9–C21 and the two disjunct mutations).
   Every survivor is one of three kinds: **provably inert** (C9, C17, C20 —
   `got` byte-identical, verified by instrument for C9), an **observably
   identical permutation** (C13–C15), or **safe-direction-only** (C10). There
   is no survivor that silently widens or narrows the satisfier set.
2. **The one real survivor, C10, is not a hazard.** Its only effect is to lower
   `concreteTypesChecked`, and that count gates a single `t.Fatal` on `== 0` —
   lower means the guard fails closed *more* readily, never less. Pinning it
   would mean asserting an exact count (`== 4`), which every future fixture
   addition then has to update: a brittle assertion bought with no safety
   return. §5's "there is no performance requirement here" has a sibling —
   there is no completeness requirement either, only a correctness one.
3. **§8's escalate-to-an-external-harness rule does not apply.** `#0258`'s
   problem was `check.sh` guarding *itself*, where checker and subject were the
   same bytes, so each in-file mechanism became new mutable surface. This is
   not that shape. The **subject** here is the production `internal/seo`
   package's type structure, in different files;
   `scanInvalidatorSatisfiers` and the synthetic fixture are the **instrument**,
   and the instrument is independently exercised against the real package by
   `TestInvalidatorSatisfierSet`. A fixture and its assertion living in one
   `_test.go` file is ordinary Go testing, not self-reference.
