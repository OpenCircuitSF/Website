## Description

`PRD.md` §7.4 (*SEO and social preview cards*) describes what `internal/seo` was
going to be, not what it is. `#0419`'s implementation pass read it directly and
reports six divergences:

| §7.4 says | Reality |
|---|---|
| no archive source | `#0123` added one |
| no `twitter:title` / `twitter:description` | both exist |
| no JSON-LD token | one exists |
| the cache is **"per path"** | `#0073` made it bucket-keyed *specifically* to bound memory — this is the exact defect that issue fixed |
| invalidation is workshop-mutation-only | `#0319` added the admin archive toggle and the send worker's archive-publish transition |
| — | `#0273`'s per-workshop card generation is absent entirely |

It also claims `/favicon.svg` is served by this subsystem. It is not — that is
`handlers.SPAHandler`'s embedded-file lookup, with no `internal/seo` involvement.

**Re-derive all of this yourself.** The table is transcribed from another
agent's report, and the recurring lesson of this family is that transcribed
facts drift.

## Why it matters more than an ordinary stale doc

**Other documents defer to it.** `docs/seo.md` cited §7.4 as authoritative until
`#0419` rewrote it — and that rewrite had to record §7.4's unreliability in
prose rather than fix it, because `PRD.md` was owned by a concurrent pass at the
time. So the tree currently contains a document explaining that its own cited
authority is out of date.

The "per path" caching line is the sharpest instance: a reader following §7.4
would reimplement the memory-unbounded behaviour `#0073` was filed to remove.

## Acceptance criteria

1. §7.4 describes `internal/seo` as it exists, verified **against the code** —
   not against `docs/seo.md`, which is a sibling account rather than a source.
2. The `/favicon.svg` claim is corrected or removed.
3. `docs/seo.md`'s closing section, which currently records §7.4 as out of date,
   is updated to match — or the reason it should stay is stated. **These two must
   not be left disagreeing**, which is the failure this issue is about.
4. **§11's PRD section-index line counts must stay exact.** Either correct in
   place with inline dated notes so §7.4's length does not move, or update §11's
   table and its parity guard together. `#0113` exists because that table
   drifted twice unnoticed.
5. Follow `#0072`'s dated-note convention, and leave genuine decision-log history
   intact per `#0271`'s scope. Say which occurrences you judged to be which.
6. **No mechanism** (`#0330`/`#0347`/`#0356`/`#0381`).
7. Run `./internal/db/...` (it parses `PRD.md` and §11's table) and
   `./internal/handlers/...`; add `./internal/seo/...` if you touch anything it
   guards. Per §5 name the specific tests that ran. No Go-file-plus-line-number
   citation (`#0352`), scanned with `python3` bytes rather than BSD `grep -P`.
