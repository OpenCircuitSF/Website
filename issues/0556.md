# 0556 — `scripts/check.sh` passes extra arguments to `bash -c` unquoted, so a `-run` regex with `|` or parentheses breaks

## Description

Found during `#0553`'s review. `scripts/check.sh go <pkgs> -run 'A|B'` (or a
pattern with parentheses) fails with exit 127 or 2, because the extra
arguments reach a `bash -c` string without quoting and the shell parses the
`|` / `(`.

## Acceptance criteria

- [ ] Extra arguments are quoted (e.g. `printf %q`) before being spliced into the `bash -c` command, or passed as positional parameters instead of string-spliced; bash 3.2 compatible (CLAUDE.md §8).
- [ ] A standalone guard test under `scripts/` (wired into `scripts/check.sh guards`) proves a `-run 'TestA|TestB'` argument reaches `go test` intact.
- [ ] `scripts/check.sh guards` and an ordinary `ISSUE=0556 scripts/check.sh go ./internal/db/...` pass.
