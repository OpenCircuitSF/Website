## Description

The pages a person lands on when they click unsubscribe: a confirmation page for the GET, and a neutral done state after the POST.

## Acceptance criteria

- [ ] `/unsubscribe` renders a confirmation prompt with a single clear action
- [ ] Confirming issues the POST and shows a done state
- [ ] Landing with an invalid or already-used token shows the same neutral done state
- [ ] The done state offers to re-subscribe and links to the preference center as a lighter alternative
- [ ] Terminal-styled, composed from the motif components
- [ ] No dark patterns — the unsubscribe action is the primary button, not a muted link next to a prominent "stay subscribed"

## Notes

PRD §6.5, §5.1. Making unsubscribe hard produces spam complaints, which cost far more than the subscriber does. Offer the preference center as an alternative once, plainly, and make leaving the easy path.
