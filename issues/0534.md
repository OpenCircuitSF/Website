## Description

`web/index.html` carries explanatory HTML comments for developers, and they survive the build into every page the server sends. Measured on production, 2026-09-12: the source of `/archive/09-2026` includes a comment describing the JSON-LD placeholder that cites `#0055` and `PRD §7.4`. `#0519` added another comment next to the new body token.

Nothing sensitive is exposed today, and it does not affect ranking. But it publishes internal issue numbers and document references to anyone viewing source — the public-facing version of what `#0172`/`#0181` stopped the admin UI from doing — it adds bytes to every page, and comments like these have already fooled tooling twice here: a regex hunting for a tag found the one inside a comment (`#0064`'s CSP hash, `CLAUDE.md` §8), and a naive heading count found two headings on every page (`#0519`'s review).

## Acceptance criteria

1. Built HTML served to visitors contains no developer comments. Either remove them from `web/index.html` or strip comments during the build — record which.
2. **The knowledge is kept, not deleted.** Move each explanation to where developers read it: `docs/seo.md`, or a Go doc comment beside the token substitution in `internal/seo`.
3. **The CSP hash of the bootstrap script is unchanged.** Verify with an HTML parser, not a regex (`CLAUDE.md` §8). A comment strip must not alter the script's contents.
4. Every `%%OC_…%%` token still appears exactly once in the template (`#0519`'s obstacle), and `#0141`'s placeholder guard for `web/dist/index.html` still passes.
5. A test or guard fails if a developer comment reappears in the shipped template.
6. `scripts/check.sh web` and `ISSUE=NNNN scripts/check.sh go ./internal/seo/...` pass.
