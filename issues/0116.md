# 0116 — `./scripts/dev.sh` cannot boot from a clean checkout because it defaults six required variables but not `AWS_REGION`, `EMAIL_FROM`, or `EMAIL_LIST_DOMAIN`

| | |
|---|---|
| **Status** | open |
| **Module** | infra / config |
| **Platform** | All |
| **First seen** | 2026-08-21 |
| **Phase** | 0 — Foundation |

## Description

`scripts/dev.sh` exports dev defaults for six required config variables so a
developer does not need a `.env` file — but three other unconditionally
required variables (`AWS_REGION`, `EMAIL_FROM`, and now `EMAIL_LIST_DOMAIN`)
are not among them, so `config.Load` rejects the boot. A clean checkout with no
`.env` cannot run the command that `CLAUDE.md` §5 and `issues/Issues.md`
both document as *the* way to run this project locally.

## Steps to reproduce

From a checkout with no `.env` file in the repo root:

```bash
./scripts/dev.sh
```

## Expected behavior

The Go API starts on `:8080` and Vite on `:5173`, as the script's own header
comment advertises ("No PostgreSQL, no systemd, no migrations needed").

## Actual behavior

```
opencircuit: config: missing required variable AWS_REGION; missing required
variable EMAIL_FROM; missing required variable EMAIL_LIST_DOMAIN
exit status 1
```

Reproduced 2026-08-21 during `#0105`'s review by invoking the binary with
exactly the environment `dev.sh` exports and nothing else:

```bash
env -i PATH="$PATH" HOME="$HOME" \
  STORAGE=json BASE_URL=http://localhost:8080 \
  WEBAUTHN_RP_ID=localhost WEBAUTHN_RP_ORIGIN=http://localhost:8080 \
  SESSION_SECRET=x ADMIN_EMAIL=a@b.c PORT=58771 \
  go run ./cmd/opencircuit serve
```

## Notes

**This is pre-existing and predates `#0105`.** `AWS_REGION` and `EMAIL_FROM`
have been in `config.Load`'s `required` table with `skipInDev: false` since
before that commit; `#0105` added `EMAIL_LIST_DOMAIN` alongside them, which
lengthens the error by one line but does not create the failure mode. Filed
from `#0105`'s review because the implementer correctly flagged it as
out of scope there, and because the next agent to run `dev.sh` will hit it.

The script clearly *intends* to be self-sufficient — it goes to the trouble of
defaulting `STORAGE`, `BASE_URL`, `WEBAUTHN_RP_ID`, `WEBAUTHN_RP_ORIGIN`,
`SESSION_SECRET`, `ADMIN_EMAIL`, and `PORT`, each with the
`${VAR:-default}` override idiom, and its header says overrides are the only
thing a developer should need to supply. The three missing variables are an
oversight in that list, not a deliberate requirement.

`cmd/opencircuit`'s `seed` subcommand (`seed.go` calls `config.Load()`) has the
same exposure for anyone running it without a `.env`.

**Two candidate fixes, decide deliberately:**

1. **Add the three to `dev.sh`'s default block**, matching the existing idiom:

   ```sh
   export AWS_REGION="${AWS_REGION:-us-west-2}"
   export EMAIL_FROM="${EMAIL_FROM:-Open Circuit SF <hello@localhost>}"
   export EMAIL_LIST_DOMAIN="${EMAIL_LIST_DOMAIN:-lists.localhost}"
   ```

   Cheapest and preserves the script's self-sufficiency. Note the values must
   be obviously-local placeholders: a real `EMAIL_FROM` or the production
   `lists.opencircuitsf.com` would let a dev run look more production-like
   than it is. Nothing sends mail on the `STORAGE=json` path today, so a
   placeholder is safe — but re-check that when `#0045`'s send worker lands.

2. **Document `cp .env.example .env` as a prerequisite** in the script's
   header, `HANDOFF.md`, and `CLAUDE.md` §5, and have `dev.sh` fail with a
   pointed message rather than the raw config error. More honest if the intent
   is that developers should always have a real `.env`, but it contradicts the
   six defaults the script already sets.

Option 1 is probably right, but note that `.env.example`'s `SESSION_SECRET` is
deliberately left blank (a non-empty placeholder there would sign real sessions
with a published key), so option 2 alone does not actually produce a bootable
`.env` without a manual `openssl rand -hex 32` step — which strengthens the
case for option 1.
