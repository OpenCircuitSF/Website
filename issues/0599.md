## Description

Brennan, 2026-10-18, on the `#0586` grouped nav (14 bordered pills in two
rows): "I do not like the navigation." Fable's design review,
`docs/reviews/admin-nav-options.md`, offered four options. Brennan chose
**option A**, with one change: the "Mailing list" section is named
**"Newsletter"**.

Option A: row one holds four section tabs; row two holds only the active
section's screens. Overview has no row two. Design detail is in §2, §3 and
"Option A" of the review doc; the plan is §5 Issue 1. Where the doc says
"Mailing list", read "Newsletter".

## Acceptance criteria

SPA only. Routes and hashes do not change; every existing `#/…` link keeps
working.

- [x] `web/src/lib/adminRouter.ts`:
      - `ADMIN_NAV_GROUPS` ordered Workshops · Newsletter · System (the
        Overview tab sits before them). The group formerly labelled "Mailing
        list" is labelled **"Newsletter"**, with Campaigns first among its
        screens.
      - Each group carries a `landing` section (its first screen).
      - New `sectionGroup(section)` returns the group, or `null` for
        `overview` and `not-found`.
      - `ADMIN_SECTION_LABELS`: `pending` → "Pending confirmations",
        `crt` → "Home screen".
      - `ADMIN_NAV_SECTIONS` stays derived; tests in `adminRouter.test.ts`.
- [x] `web/src/views/Admin.svelte`:
      - Replace the current grouped nav with two `<nav>`s:
        `aria-label="Admin sections"` (Overview · Workshops · Newsletter ·
        System, each linking to its landing screen, the active section
        marked `aria-current`) and `aria-label="<Group> screens"`, rendered
        only when `sectionGroup()` is non-null, with `aria-current="page"` on
        the active screen.
      - Delete the ≤480px `<select>`. At ≤480px both rows are one line,
        `overflow-x: auto; white-space: nowrap`, with no horizontal page
        scroll.
      - No underlines on nav links (`text-decoration: none`); keyboard focus
        keeps its visible ring via the existing `app.css` `:where` rule.
        Keep the `.subtab` class on row-two links so
        `focusOutline.guard.test.ts` needs no change.
      - A clear active state on both rows (per the review's Option A: text
        colour plus a 2px `--accent` edge), meeting the focus-ring rule in
        AGENTS.md §8.
- [x] Header: remove the Account | Admin tab row. "Account" becomes a plain
      link beside Sign out. `Account.svelte`'s own header is out of scope.
- [x] No other user-visible "Mailing list" heading in the admin nav remains.
      Leave unrelated copy (emails, public pages) alone.
- [x] Tests (`web/src/views/Admin.nav.behavior.test.ts`, rewritten):
      - row one has the four links in order with the right `href`s
      - row two shows only the active group's screens, in order, with
        `aria-current="page"` on the active one
      - no row two on `#/`
      - `#/outreach?view=results` lights Workshops and Outreach
      - `#/nope` lights nothing
      - the select is gone
      - the Account link is in the header
      `Admin.hashRouting.behavior.test.ts` keeps passing.
- [x] Verified with `ISSUE=0599 scripts/check.sh web`. No browser on the
      host (AGENTS.md §8); state that the evidence is jsdom. The reviewer
      may add a Tart VM Safari render at 390px and 1040px of `#/`,
      `#/outreach` and `#/settings?section=outreach`.
