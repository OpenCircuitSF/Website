## Description

> Renumbered on 2026-11-18 from `#0698`, and rewritten the same day: the first version invented a new in-page illustration process. "Like we have done before" is `#0709`'s process, below.

The user asked for the first batch of Raspberry Pi guides (`#0719`, `#0720`, `#0721`) to get images generated by Codex "like we have done before". That is `#0709` (`96b04a45`): one **unfurl image** per guide, generated with the Codex CLI from `assets/og/guides/PROMPTS.md`, saved as `internal/seo/cardassets/guides/<slug>.png`, and served as the guide's `og:image` and Bluesky thumbnail. All 43 guides before this batch have one.

The three guide issues each add their guides' `### <slug>` sections to `PROMPTS.md` (the `#0709` guard requires a section for every catalog guide). This issue generates the seven images once those three are merged:

`pi-imager-setup`, `pi-wifi-2-4ghz`, `pi-bookworm-changes`, `pi-undervoltage`, `pi-sd-card-corruption`, `pi-volumio-streaming`, `pi-rgb-matrix-flicker`.

Follow `PROMPTS.md`'s "How to use this file" exactly: the STYLE block plus each guide's prompt, then centre-crop to exactly 1200×630 PNG, compress with `pngquant --quality 65-90`, under 1,000,000 bytes, saved at the Output path. Check each prompt first: the style says no text, logos or trademarks (no Raspberry Pi logo; no Volumio, Spotify or Apple marks), and the subject in the middle band.

## Acceptance criteria

1. Seven PNGs at `internal/seo/cardassets/guides/<slug>.png`, 1200×630, each under 1,000,000 bytes.
2. Each looked at directly (not in a browser, AGENTS.md §8) at full size and about 400 px wide; any regenerated, with the reason, in the work log.
3. The work log records the exact Codex command and model.
4. `ISSUE=0722 scripts/check.sh go ./internal/seo/... ./cmd/opencircuit/...` passes.

## Root cause

Not a defect. The seven Raspberry Pi guides (`#0719`–`#0721`) had prompts in `assets/og/guides/PROMPTS.md` but no art, so they unfurled with the generated title card.

## Fix

Followed `#0709`'s process. Before generating, each of the seven prompts was checked against the STYLE block and this issue's rules, and the prompts that broke a rule were fixed in `PROMPTS.md`:

- **STYLE block:** the no-logo list now names the Raspberry Pi raspberry and the Volumio, Spotify and Apple marks, and covers devices as well as parts, tools and packaging.
- **`pi-imager-setup`:** "bare Raspberry Pi board" became "bare, unbranded single-board computer" (avoids the raspberry logo), and "a faint WiFi arc" became plain concentric radio arcs, "not a WiFi logo".
- **`pi-wifi-2-4ghz`:** "Raspberry Pi Zero board" became "unbranded stick-shaped single-board computer".
- **`pi-bookworm-changes`:** the paper tutorial and the terminal invited legible text. The tutorial's steps are now plain grey bars, and the terminal shows only a `>` chevron, abstract bars and a block cursor.
- **`pi-volumio-streaming`:** the phones and laptop are generic and unbranded, with abstract screens and no logos on their backs or lids (avoids Apple marks).

After the first look, three more prompt edits came with the re-rolls (see the work log):

- **`pi-undervoltage`:** the board now sits just right of centre, inside the frame.
- **`pi-volumio-streaming`:** plain near-black ground with no room, furniture, plants, string lights or props.
- **`pi-rgb-matrix-flicker`:** a coarse grid of large LEDs, about 16×8, and no props.

Generated with the Codex CLI. Each image was centre-cropped with `sips --resampleWidth 1200` and then `sips --cropToHeightWidth 630 1200`, compressed with `pngquant --quality 65-90`, and saved at `internal/seo/cardassets/guides/<slug>.png`. No code changed.

**A constraint PROMPTS.md does not mention:** `#0710`'s `TestGuideThumb_EmbeddedSetWeight` caps each art's derived 640×336 JPEG at 40,000 B. A dense, multicoloured, high-frequency image can pass the 1,000,000 B PNG limit and still fail that cap; the first `pi-rgb-matrix-flicker` did, at 48,962 B. A follow-up could add a line to PROMPTS.md's "How to use this file".
