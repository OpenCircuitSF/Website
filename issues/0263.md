## Description

Three inaccuracies found by `#0127`/`#0128`'s review. None is a behavioural
defect — every property they describe genuinely holds — but each credits the
**wrong mechanism**, which is the kind of comment that gets a correct safeguard
deleted as redundant.

**1. `AdminResendConfirmation`'s cooldown comment names a mechanism it does not
use.** `internal/subscribers/pending.go` claims
`ClaimAndEnqueueConfirmation`'s WHERE-clause claim. The code actually checks in
Go, after `SELECT … FOR UPDATE`. The property holds — the reviewer proved it
with eight concurrent resends (`wins=1 cooldowns=7 queued_delta=1`) — but **a
reader who believes the comment could remove the `FOR UPDATE` as redundant**,
and the guard would silently become a race. `issues/0128.md` repeats the claim.

**2. `formatPendingAge` advertises an output it cannot produce.**
`web/src/lib/pending.ts` documents a `"45 seconds"` result; anything under 60s
returns `'just now'`.

**3. `render()`'s comment is now stale.** It says the worker will not refuse a
missing `physical_address` "for a confirmation" — but `#0127` added the welcome
email, the first arguably-commercial message on that path. See `#0264`, which
covers whether the behaviour should change; this item is only the comment.

## Notes

Reported by `#0127`/`#0128`'s phase-3 review under `CLAUDE.md` §9.

**Worth noting what let item 1 through.** `#0196`, `#0199` and `#0220` built
citation guards that check whether a cited *test or path exists*. None of them
can check whether a comment's *description of a mechanism* is true — that
requires understanding the code, not resolving a reference. This class has now
cost this project repeatedly (`#0190`, `#0192`, `#0216`, `#0237`'s seven
rounds), and the honest position is that review is the only instrument for it.

That is an argument for keeping mechanism claims **short and checkable**, or
omitting them: a comment saying "cooldown enforced here" cannot be wrong the way
"enforced by the WHERE clause in X" can.
