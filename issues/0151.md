## Description

`#0143` made the Announce panel say plainly when a draft will target everyone rather than the workshop's interests. The sentence reads the **saved** `workshop.interest_ids`, which is correct: `POST /admin/workshops/{id}/announce` takes no body and derives its audience from the persisted row, so the copy describes what the server will actually do.

That leaves one confusing state. An admin who ticks interest checkboxes, does **not** save, and opens Announce reads *"This workshop has no interests set, so the draft will target everyone on the list"* while looking at checked boxes. The sentence is true about the action and contradictory about the form.

`#0143`'s reviewer verified the underlying behavior against the handler and ruled this a non-blocking follow-up rather than a defect: every acceptance criterion is met, the copy never lies, the form is explicit-Save by design, and staleness is bounded — `save()` reassigns `workshop`, so the sentence corrects itself the instant a save lands.

## Acceptance criteria

- [ ] When `fields.interestIds` diverges from `workshop.interest_ids`, the panel adds a line to the effect of "Unsaved interest changes are not included — save first"
- [ ] Both values are already in scope in `WorkshopEditor.svelte`; this should need no new API call
- [ ] The comparison is order-insensitive — the two arrays may hold the same ids in different orders
- [ ] The existing two copy paths from `#0143` are unchanged when there is no divergence
- [ ] The new branch is unit-tested in `web/src/lib/`, per `CLAUDE.md`, and `scripts/check.sh web` passes

## Notes

Recommended in `#0143`'s phase-3 review notes rather than filed by it, following the precedent `#0056`'s reviewer set for non-blocking UI suggestions.

The alternative — sourcing the sentence from the unsaved buffer — is **wrong** and should not be attempted: it would reintroduce `#0143`'s original defect pointing the other way, promising interest targeting that Announce will not perform.
