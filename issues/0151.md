## Description

`#0143` made the Announce panel say plainly when a draft will target everyone rather than the workshop's interests. The sentence reads the **saved** `workshop.interest_ids`, which is correct: `POST /admin/workshops/{id}/announce` takes no body and derives its audience from the persisted row, so the copy describes what the server will actually do.

That leaves one confusing state. An admin who ticks interest checkboxes, does **not** save, and opens Announce reads *"This workshop has no interests set, so the draft will target everyone on the list"* while looking at checked boxes. The sentence is true about the action and contradictory about the form.

`#0143`'s reviewer verified the underlying behavior against the handler and ruled this a non-blocking follow-up rather than a defect: every acceptance criterion is met, the copy never lies, the form is explicit-Save by design, and staleness is bounded — `save()` reassigns `workshop`, so the sentence corrects itself the instant a save lands.

## Acceptance criteria

- [x] When `fields.interestIds` diverges from `workshop.interest_ids`, the panel adds a line to the effect of "Unsaved interest changes are not included — save first"
- [x] Both values are already in scope in `WorkshopEditor.svelte`; this should need no new API call
- [x] The comparison is order-insensitive — the two arrays may hold the same ids in different orders
- [x] The existing two copy paths from `#0143` are unchanged when there is no divergence
- [x] The new branch is unit-tested in `web/src/lib/`, per `CLAUDE.md`, and `scripts/check.sh web` passes

## Root cause

`#0143` correctly drives the Announce panel's targeting sentence from the
*saved* `workshop.interest_ids` — the only value
`POST /admin/workshops/{id}/announce` (no request body) can see. But nothing
told the admin when that saved value disagreed with the checkboxes currently
visible on screen (`fields.interestIds`, the local, unsaved buffer). An admin
who ticked boxes and did not save read a sentence that was true about the
action ("no interests set") while looking at a form that said otherwise.

## Fix

Added two pure functions to `web/src/lib/workshopAdmin.ts`, next to
`announceTargetingDescription`:

- `interestIdsDiverge(a, b)` — set-equality between two `number[] | undefined`
  arrays. Builds a `Set` from each side (`undefined` and `[]` both become the
  empty set), compares sizes, then checks membership — order never enters the
  comparison, which is what makes it safe against a naive `.join()` false
  positive.
- `announceUnsavedInterestsHint(formInterestIds, savedInterestIds)` — returns
  `' Unsaved interest changes are not included — save first.'` when
  `interestIdsDiverge` is true, `''` otherwise.

`WorkshopEditor.svelte`'s Announce panel now interpolates
`announceUnsavedInterestsHint(fields.interestIds, workshop.interest_ids)`
immediately after the existing `announceTargetingDescription(workshop.interest_ids)`
call. `announceTargetingDescription` itself is untouched — it still reads only
the saved value, so the sentence it produces never changes; the hint is a
separate, additive clause that appends nothing when the two arrays match.
