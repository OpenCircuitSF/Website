## Description

`#0251` added a positive assertion that `runpipe()`'s definition still spells
`-o pipefail`. **`run()`, one line above it, has no such assertion — and it
carries the entire failure-reporting contract.**

```
scripts/check.sh:50
run()  { "$@"; local rc=$?; [ $rc -eq 0 ] || { FAILED=1; printf …; }; return 0; }
```

Replace it with `run() { "$@"; return 0; }` — dropping the `FAILED=1`
accounting — and **every failing step passes silently.** Verified end to end by
`#0251`'s reviewer: a `--- FAIL` prints, and the script still reports
`VERIFICATION PASSED` and exits 0.

Nothing catches it. The mutation spells no `bash`, no `-c`, no `pipefail`, so
all four checks in the `GUARD-0208` block stay silent, and nothing outside
`check.sh` asserts anything about `run()` — grepped across `internal/`, `cmd/`,
`web/src/` and `scripts/`.

**This is `#0251`'s own defect class, one function over.** And `run()` is the
function `#0140` was originally about: the whole point of that issue was that
`check.sh` could report success while a step failed. The guard built since
protects the pipe, not the accounting.

**Two smaller items in the same file, from the same review:**

**1. `#0208`'s shell-`-c` scan misses combined short options.** The pattern is
`-c\b`, and `-cu` has no word boundary — so `run bash -cu "$1"` is a working
bypass, verified as valid syntax with pipefail off. `-ce` and `-cx` are
identical. This is a one-line pattern fix, smaller than the already-accepted
mutant 7 and actually closable.

**2. Trailing whitespace after `runpipe()`'s closing brace trips the new
guard.** A no-op edit fails the run, because the comment strip only removes
whitespace *preceding* a `#`. Fails safe, but it is a false alarm on a change
that means nothing. A trailing `[[:space:]]*` in the `grep -qxE` pattern fixes
it.

## Acceptance criteria

- [ ] A positive assertion exists that `run()`'s definition still sets `FAILED=1` on a non-zero exit, and it fails if that accounting is removed
- [ ] Mutation-proved: strip the accounting, confirm the loud failure **before any test runs**, restore, prove byte-identity with `shasum -a 256`
- [ ] The assertion cannot be satisfied by the string appearing elsewhere in the file — `#0251`'s review defeated exactly that with a heredoc and a decoy block, so match the definition line, uniquely
- [ ] The `-c\b` scan catches `-cu`, `-ce`, `-cx` — verified by running each as a real bypass, not by reading the regex
- [ ] Trailing whitespace after the definition no longer trips the guard
- [ ] `#0208`'s nine evasion mutants and `#0251`'s three fakes all still behave as documented
- [ ] `bash -n` and `shellcheck` clean — **and the change is actually run under this machine's bash 3.2.57**, since static checks have already missed one non-functional fix this session (§8)

## Notes

Reported by `#0251`/`#0253`'s phase-3 review under `CLAUDE.md` §9, and
independently confirmed at `scripts/check.sh:50`.

**The general shape is worth naming**, because this is the third instance:
`#0251` found a guard blind to its own definition, `#0255` found a guard reading
the losing value, and this is a guard that protects the pipe while leaving the
accounting bare. Each time, the property everyone cared about was one line away
from the property that was actually checked.

Whoever takes this should consider whether `run()` and `runpipe()` want one
shared assertion over both definitions rather than two adjacent ones — a fourth
critical line will appear eventually.
