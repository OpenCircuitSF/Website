## Description

`docs/deployment.md`'s DNS table records `www.opencircuitsf.com` as an **A**
record pointing at `44.222.209.183`. The Route 53 zone actually holds a
**CNAME** to `ec2.smallsharptools.com`.

Measured read-only by `#0436`'s reviewer via `aws route53
list-resource-record-sets` (names and types only). Pre-existing — `270fed9` did
not touch that row.

The table's `go.` row already flags the same shape, so the document is
internally inconsistent as well as wrong: one row describes the indirection and
the row beside it does not.

## Why it matters more than a typo

`www` is the **canonical host** (`CLAUDE.md` §7) — the apex and plain HTTP both
301 to it, and `WEBAUTHN_RP_ORIGIN` depends on it. A rebuild that follows this
table creates an A record pinned to a literal IP, silently dropping the
indirection through `ec2.smallsharptools.com`. The address then has to be
maintained by hand, and the failure appears at the next instance replacement,
long after the change that caused it.

## Acceptance criteria

1. The `www` row states the record type and target the zone actually holds.
2. **Re-derive it yourself** rather than copying this issue'svalue — read the zone
   read-only and record what you ran. `CLAUDE.md` §7's standing instruction is to
   re-derive production facts, not to carry a snapshot forward.
3. Sweep the rest of the table the same way. One row being wrong is weak
   evidence the others are right, and this table has never been checked against
   the zone as a whole.
4. Where a row is correct, leave it alone. `#0431`'s distinction applies: a
   statement that cites its source is fine, and only a statement asserting an
   unmeasured value as fact is a defect.
5. Do not change DNS. This is a documentation fix. **Never touch the apex MX** —
   it carries real Google Workspace mail (`CLAUDE.md` §9).

### Defect 1 — the sweep certifies a row the named command does not cover

`docs/deployment.md`'s new closing paragraph ends by asserting that "the apex
`A`, `go.` CNAME, DKIM CNAMEs, and `bounce.mailing.` MX/TXT rows all matched
the live zone exactly", naming `aws route53 list-resource-record-sets` as the
measurement. **`go.opencircuitsf.com` does not appear in that listing.** It has
no record of its own and resolves only through the `*.opencircuitsf.com`
wildcard CNAME — the identical mechanism the same paragraph correctly
identifies two sentences earlier for `_dmarc.opencircuitsf.com`, and the
identical mechanism the same commit correctly annotates for
`lists.opencircuitsf.com`. Three names in this table are wildcard-covered
rather than present; the pass caught two of them and certified the third as an
exact match.

That is `#0431`'s distinction landing on the wrong side of the line: not a
statement attributing a fact to its source, but one naming a specific command
and asserting a production value the command does not return. It is also the
exact thing criterion 3 was written to catch — "one row being wrong is weak
evidence the others are right."

It matters operationally, not just verbally. `go.opencircuitsf.com` is a live
production host — the separate ShortLinks deploy, `CLAUDE.md` §7. A reader told
the sweep confirmed a dedicated CNAME will believe the name is independently
pinned; it is not, and narrowing or removing the wildcard breaks it silently.
`#0057` is about to add records to this zone, which is precisely when knowing
which documented names are explicit and which are wildcard shadows is
load-bearing.

**Remedy, verbatim.** Replace the sentence beginning "The rest of this table
was swept against" and running to "per `#0448` criterion 4." with:

    swept against `aws route53 list-resource-record-sets` for the same pass;
    the apex `A`, DKIM CNAMEs, and `bounce.mailing.` MX/TXT rows all matched
