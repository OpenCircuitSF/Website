## Description

A workshop that has **never been published** becomes **publicly visible** the moment an admin cancels it.

The path, all of it legal today:

1. `canCancel` is `status !== 'canceled'`, so `draft → canceled` is an offered transition.
2. The transition leaves `published_at` NULL — the workshop was never published.
3. `ListVisible` (`internal/workshops/store.go:457-476`) selects `status IN ('published', 'canceled')` with **no `published_at` check**, so the canceled draft appears on `/workshops`.
4. `GetBySlug` serves `published` and `canceled` too (`#0051`'s reviewer confirmed that rule deliberately), so the detail page renders as well.

So a draft an admin was still writing — possibly with placeholder copy, a wrong date, or an unfinished body — is published to the world by the act of canceling it.

The UI reinforces the mistake: `cancelConfirmMessage` tells the admin the workshop "stays visible", which **presumes it already was**. For a draft, that sentence describes the opposite of what happens.

## Root cause

`ListVisible` (`internal/workshops/store.go`) and the `GetBySlug` handler
(`internal/handlers/public_workshops.go`) both gated public visibility on
`status IN ('published', 'canceled')` alone. `draft → canceled` is a legal
admin transition (`canCancel` only refuses `status === 'canceled'`), and per
this package's own "published_at's two transitions" doc comment, cancel
**preserves** whatever `published_at` already was rather than stamping one —
so a workshop canceled straight from draft keeps `published_at = NULL`.
Status alone could not distinguish "was live, now canceled" (must stay
visible, `#0051`'s ruling) from "never went live, now canceled" (must stay
private). `internal/seo`'s `workshopRouteMeta` had the identical gap: it
checked `w.Status` only, so a never-published canceled workshop could still
produce a real, indexable `EventCancelled` JSON-LD block on its detail page
(the sitemap was already safe — `sitemap.go` keys strictly off
`status == published`, which implies `published_at` is set).

## Fix

**Orchestrator's decision: option (a), narrow visibility, not the
transition** — recorded per instructions, not re-litigated here.

`ListVisible`'s two queries and `GetBySlug`'s handler-side 404 check now both
require `published_at IS NOT NULL` in addition to the status check. Full
transition matrix, each cell proved by execution against a real database
(throwaway rows, no seeded/literal ids):

| Transition | `status` | `published_at` | Visible? | Proof |
|---|---|---|---|---|
| create (draft) | `draft` | NULL | No | status excludes it (unchanged) |
| draft → published | `published` | set | Yes | pre-existing behavior, unchanged |
| published → canceled | `canceled` | preserved (set) | **Yes** — `#0051`'s ruling, not in question | `TestListVisible_SplitsUpcomingAndPast`, `TestPublicWorkshops_GetBySlug_VisibilityByStatus` (both now route through publish first) |
| **draft → canceled (never published)** | `canceled` | NULL (never stamped) | **No — the defect this issue fixes** | `TestListVisible_ExcludesNeverPublishedCanceled`, `TestPublicWorkshops_List_ExcludesNeverPublishedCanceled`, `TestPublicWorkshops_GetBySlug_NeverPublishedCanceledIs404` |
| published → unpublished (draft) | `draft` | NULL (cleared) | No | status excludes it (unchanged) |
| **published → unpublished → canceled** | `canceled` | NULL (cleared by unpublish, then preserved by cancel) | **No — decided here** | `TestListVisible_ExcludesCanceledAfterUnpublish`, folded into `TestPublicWorkshops_List_ExcludesNeverPublishedCanceled`/`..._NeverPublishedCanceledIs404` |
| canceled → draft | `draft` | whatever it was (may be non-NULL) | No | status excludes it regardless of `published_at` — confirmed by reading the guard: the `status == draft` check in `GetBySlug`/status filter in `ListVisible` fires first |

**Decision on published → unpublished → canceled**: private. Unpublishing is
the admin's deliberate "take this back out of public view" action, and it
already clears `published_at` to NULL (`#0051`'s established behavior,
`TestUpdate_UnpublishClearsPublishedAt`). Canceling afterward must not
resurrect visibility any more than canceling a workshop that was never
published should grant it — the workshop ends up in exactly the same state
(`status=canceled`, `published_at=NULL`) as the direct draft → canceled case,
and there is no way for the public API to tell the two apart, nor should
there be.

`internal/seo`: added `Workshop.Published bool`
(`internal/seo/workshop.go`), threaded from
`workshops.Workshop.PublishedAt != nil` in the
`cmd/opencircuit/workshop_seo_source.go` adapter, and added `!w.Published` to
`workshopRouteMeta`'s `ok=false` gate (`internal/seo/seo.go`) alongside the
existing status check. Confirmed by execution
(`TestRender_JSONLD_NeverPublishedCanceledOmitsBlockAndUsesGenericCard`): a
never-published canceled workshop now gets no JSON-LD block and the generic
`<title>`/`og:*` fallback, exactly like a draft or an unknown slug. The
sitemap needed no change — verified by reading `sitemap.go` (excludes
everything but `status == published`) and confirmed by the existing,
unmodified `TestSitemap_ExcludesUnpublishedWorkshops` still passing.

`cancelConfirmMessage` (`web/src/lib/workshopAdmin.ts`) now takes a second
`wasPublished: boolean` parameter (`!!workshop.published_at` at the call
site in `WorkshopEditor.svelte`) and returns one of two true statements:
"stays visible ... rather than disappearing" when `wasPublished`, or "was
never published, so it stays private" otherwise.

**Test fixture bug found along the way.** Three existing tests
(`TestListVisible_SplitsUpcomingAndPast`,
`TestPublicWorkshops_List_SplitsUpcomingPastExcludesDraft`,
`TestPublicWorkshops_GetBySlug_VisibilityByStatus`) built their "canceled"
fixtures by transitioning straight from draft to canceled in one `Update`
call — exactly the never-published-canceled case — while asserting the
result **must** be visible. That happened to be true only because the
pre-#0171 code had no `published_at` guard; the tests were unknowingly
encoding the bug as correct behavior, which is a sharper version of "#0135's
tests all seeded published" than the issue's own Notes state (they didn't
even go through an intermediate published state — the direct transition was
already present, just never separately asserted against). Fixed by routing
those specific fixtures through `published` first, so they now test what
`#0051`'s ruling actually covers; the never-published case got its own new
tests instead of silently flipping an existing assertion.

## Why this survived review

Every decision on the path is individually right. `#0051` ruled canceled workshops must stay visible ("a 404 tells them nothing"). `#0135` widened the index to match, deliberately, and its review verified the split against `starts_at` — but every test seeded a **published** workshop before canceling it, so the draft path was never exercised. `#0055` keyed its SEO gate off `status` rather than `published_at`, correctly, for the same reason.

The gap is the combination: "canceled is visible" was reasoned about for workshops that had been visible already.

## Notes

Found by `#0168`/`#0170`'s phase-3 review, which was reading `cancelConfirmMessage` for copy accuracy and noticed the sentence presumes a fact the draft case does not have.

Option (a) is probably right: canceling a draft is a plausible thing to do (an event that fell through before it was ever announced), and refusing the transition forces an admin to delete work they may want to keep. But (b) has the merit that "canceled" is meaningless for something nobody was ever told about.

## Gotchas

- **Adding `seo.Workshop.Published` broke five pre-existing, unrelated-looking `internal/seo` tests on the first pass** (`TestRender_CacheExpiresAfterTTL`, `TestRender_InvalidateWorkshopsBypassesCacheImmediately`, `TestSite_InvalidateWorkshopsClearsBothCaches`, `TestRender_EscapesInjectedValues`, plus one more caught on a second full-package run). Every one of them constructs a `Workshop{}` literal directly with `Status: WorkshopPublished` but no `Published` field, so the new zero-value `false` silently flipped `workshopRouteMeta`'s gate to "not ok" for workshops these tests need treated as fully public. None of these tests are about `#0171` at all — they just happened to share fixture-building code with the tests that are. Caught by running the *whole* `internal/seo` package, not just the tests I added; a scoped `-run` on only the new/touched tests would have missed all five.
- **The three "canceled" test fixtures that skipped through draft→canceled directly were a sharper version of the issue's own diagnosis.** `issues/0171.md`'s Notes say "#0135's tests all seeded a published workshop before canceling it" — but `TestListVisible_SplitsUpcomingAndPast`'s `mk()` helper (and its two `handlers` package siblings) called `Update` exactly once, straight from the freshly-created draft to the target status, for every non-draft case including `canceled`. They were never routed through `published` at all. The tests happened to pass before this issue only because the pre-fix code had no `published_at` check to expose the gap — they were asserting the bug's own behavior was correct. Worth flagging to the reviewer explicitly since it means `#0135`'s review (`## Review notes` in `issues/0135.md`) verified less than its own text claims.
