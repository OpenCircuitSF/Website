# 0171 — Canceling a never-published draft makes it public

## Description

A workshop that has **never been published** becomes **publicly visible** the moment an admin cancels it.

The path, all of it legal today:

1. `canCancel` is `status !== 'canceled'`, so `draft → canceled` is an offered transition.
2. The transition leaves `published_at` NULL — the workshop was never published.
3. `ListVisible` (`internal/workshops/store.go:457-476`) selects `status IN ('published', 'canceled')` with **no `published_at` check**, so the canceled draft appears on `/workshops`.
4. `GetBySlug` serves `published` and `canceled` too (`#0051`'s reviewer confirmed that rule deliberately), so the detail page renders as well.

So a draft an admin was still writing — possibly with placeholder copy, a wrong date, or an unfinished body — is published to the world by the act of canceling it.

The UI reinforces the mistake: `cancelConfirmMessage` tells the admin the workshop "stays visible", which **presumes it already was**. For a draft, that sentence describes the opposite of what happens.

## Why this survived review

Every decision on the path is individually right. `#0051` ruled canceled workshops must stay visible ("a 404 tells them nothing"). `#0135` widened the index to match, deliberately, and its review verified the split against `starts_at` — but every test seeded a **published** workshop before canceling it, so the draft path was never exercised. `#0055` keyed its SEO gate off `status` rather than `published_at`, correctly, for the same reason.

The gap is the combination: "canceled is visible" was reasoned about for workshops that had been visible already.

## Acceptance criteria

- [ ] Decide which of the two fixes is right, and record why:
      - **(a) Narrow visibility** — `ListVisible` and `GetBySlug` require `published_at IS NOT NULL` in addition to the status check, so a canceled draft stays private
      - **(b) Narrow the transition** — `draft → canceled` is refused (a draft is deleted, not canceled), in the store and in the UI's `canCancel`
- [ ] Whichever is chosen, `canceled` workshops that **were** published stay visible — that is `#0051`'s ruling and it is not in question
- [ ] `cancelConfirmMessage` says something true for the case the admin is actually in
- [ ] A test seeds a **draft**, cancels it, and asserts the public index and the detail route behave as decided — the case every prior test skipped
- [ ] Check the sitemap and JSON-LD paths (`internal/seo`) for the same assumption: `#0055` keys off `status`, so confirm a canceled draft does not reach a sitemap
- [ ] `ISSUE=0171 scripts/check.sh go ./internal/...` and `scripts/check.sh web` both pass

## Notes

Found by `#0168`/`#0170`'s phase-3 review, which was reading `cancelConfirmMessage` for copy accuracy and noticed the sentence presumes a fact the draft case does not have.

Option (a) is probably right: canceling a draft is a plausible thing to do (an event that fell through before it was ever announced), and refusing the transition forces an admin to delete work they may want to keep. But (b) has the merit that "canceled" is meaningless for something nobody was ever told about.
