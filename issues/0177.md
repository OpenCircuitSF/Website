## Description

**The one that matters.** `cancelConfirmMessage` branches on `wasPublished`, which is `!!workshop.published_at`. `canCancel` offers Cancel on any non-canceled status — including a **`draft` whose `published_at` is non-NULL**, which is `#0171`'s `canceled → draft` row and a state that review *observed*, not hypothesized.

In that state `wasPublished` is `true`, so the dialog says *"It stays visible on the public site, marked canceled, rather than disappearing."*

Both halves are wrong:

- The workshop is **not** currently visible — `ListVisible` requires `status IN (published, canceled) AND published_at IS NOT NULL`, and the detail route 404s on `draft`.
- Canceling it **makes it visible**, since `status` becomes `canceled` while `published_at` is already set.

So the dialog promises continuity where the action actually causes publication. `#0174` fixed the branch that *over*-warned; this one **under**-warns, which is the direction that matters. The fix: that branch needs the current status as well as `published_at`.

**Two smaller items from the same review**, folded here rather than filed separately:

- **`.not.toMatch(/never published/i)` is a literal-phrase pin, not a semantic guard.** Rewording the copy to *"It is not currently published **and has not been published before**"* — reintroducing exactly the false history claim `#0174` removed — leaves all four assertions passing (73/73). The positive `/not currently published/i` assertion is what actually pins the wording. Acceptable as written, but narrower than its comment implies.
- **`sitemap_test.go`'s `published-1` fixture is `Status: WorkshopPublished` with `Published: false`** — a state `#0171` proved impossible (`status = published` implies a stamped `published_at`). Harmless today, but it makes a conjunctive gate fail for the wrong reason. One `Published: true` fixes it, and `#0174`'s mutation still fails with it corrected.

## Root cause

`cancelConfirmMessage` and its call site collapsed the two fields that
determine a workshop's visibility (`status`, `published_at`) into one
boolean, `wasPublished = !!workshop.published_at`, computed at
`WorkshopEditor.svelte:237`. That collapse is lossy: `#0171`'s matrix has a
reachable cell — `canceled → draft` — where `published_at` is genuinely
`set` (cancel never clears it; only unpublish does) while `status` is
`draft`. For that row `wasPublished` reads `true`, so the dialog took the
published branch and said *"It stays visible on the public site, marked
canceled, rather than disappearing."* Both halves are false: `ListVisible`
and the detail route gate on `status IN (published, canceled) AND
published_at IS NOT NULL` (`internal/workshops/store.go`), so a `draft` row
is invisible regardless of `published_at` — and canceling that row sets
`status = canceled` while `published_at` stays set, which satisfies the
gate and makes it visible. The dialog promised continuity in the one
direction where the action is actually a publish.

`#0171` gave the dialog a boolean; `#0174` fixed the boolean's wording for
one of its two branches. Neither pass revisited whether one boolean could
represent four histories in the first place — it can't, because `status`
and `published_at` vary independently once cancel's "leave `published_at`
unchanged" rule is in play.

## Fix

Replaced the boolean with `cancelVisibilityOutcome(status, publishedAt)`
(`web/src/lib/workshopAdmin.ts`), a pure function returning one of three
outcomes derived from both fields together, and `cancelConfirmMessage`
switches on it instead of branching on a precomputed flag.
`WorkshopEditor.svelte`'s one call site now passes `workshop.status` and
`workshop.published_at` directly rather than collapsing them first.

The four states from `#0171`'s matrix, restricted to states where
`canCancel` offers the action (`status !== 'canceled'`), and the copy each
now produces:

| # | `#0171` matrix row | `status` | `published_at` | Currently visible | Effect of Cancel | Outcome | Copy |
|---|---|---|---|---|---|---|---|
| 1 | create (draft) | `draft` | NULL | no | stays invisible | `staysPrivate` | *"Cancel "X"? It is not currently published, so it stays private — canceling it will not make it visible."* |
| 2 | draft → published | `published` | set | yes | stays visible | `staysVisible` | *"Cancel "X"? It stays visible on the public site, marked canceled, rather than disappearing."* |
| 3 | published → unpublished | `draft` | NULL | no | stays invisible | `staysPrivate` | *(same as row 1 — see below)* |
| 4 | canceled → draft | `draft` | **set** | no | **becomes visible** | `becomesVisible` | *"Cancel "X"? It is not currently visible, but canceling it will make it visible on the public site, marked canceled — it was published before, and that history was never cleared."* |

Row 4 is `#0177`'s defect. Rows 1 and 3 collapse to the same copy on
purpose, not as a gap: with `published_at` NULL, a never-published draft
and a published-then-unpublished one are indistinguishable from the two
fields this function receives, and fabricating a distinction is exactly
what `#0174`'s review flagged ("It was never published" is false on row 3).
"Not currently published" is true of both; only that claim is made.

`canCancel` decision: **kept offering Cancel on the row-4 state**, not
refused. Reasoning (also recorded as a doc comment on `canCancel` in
`workshopAdmin.ts`): this module's header comment already establishes that
`canPublish`/`canUnpublish`/`canCancel` decide what to *offer*, never what
to *enforce* — `internal/workshops/store.go`'s `Update` accepts any status
→ any other status regardless of what the UI shows. Narrowing `canCancel`
alone for one matrix cell would break that symmetry for no server-side
reason. The state is also not hypothetical: `#0171`'s review proved it by
execution, and an admin who reverted a canceled workshop to `draft` (e.g.
to reschedule) and then decides not to run it after all has a legitimate
reason to formally cancel it again — refusing at the console would just
push them to a raw API call while leaving the confirmation problem
unsolved for the next admin who does the same thing through a future UI
affordance. Warning correctly is the fix; hiding the button would only
avoid explaining it.

Also folded in from the issue:

- **Phrase-pin test.** `.not.toMatch(/never published/i)` is kept (it still
  guards the one known-false phrase `#0174` removed), but it is now paired
  with — and documented as secondary to — a positive assertion on the true
  phrasing (`/not currently published/i`), per `#0174`'s own finding that
  the positive match is what actually pins the wording. Each of the three
  new copy-branch tests follows the same shape: assert the true claim, and
  assert the *other* branches' claims are absent (e.g. row 4's test checks
  for `/will make it visible/i` and checks against both `/stays visible/i`
  and `/stays private/i` — the two ways under-warning could reappear).
- **`sitemap_test.go`'s `published-1` fixture** now sets `Published: true`
  alongside `Status: WorkshopPublished` — the state `#0171` proved is the
  only reachable one for that status. `#0174`'s sitemap-gate mutation
  (`w.Status != WorkshopPublished` → `w.Status != WorkshopPublished &&
  !w.Published`) still fails after the fix, confirmed by execution (see
  `## Verification`).
- **The two carried-in `--` strings** in `workshopAdmin.ts` (the

### The state space, enumerated from the data rather than from `## Fix`'s table

`workshops.status` is `CHECK (status IN ('draft','published','canceled'))`
(`migrations/000020`) and `published_at` is nullable, so there are exactly six
`(status, published_at)` combinations. Reachability follows from `Update`'s
`CASE` (`internal/workshops/store.go:683`) — `→ published` stamps `now()`,
`published → draft` NULLs it, **every other transition leaves it alone**:

| `status` | `published_at` | Reachable? | How | `canCancel` |
|---|---|---|---|---|
| `draft` | NULL | yes | create; or `published → draft` (unpublish clears it) | offered |
| `draft` | set | yes | `canceled → draft` (`#0171`'s cell) | offered |
| `published` | NULL | **no** — any `→ published` stamps `now()` | — | (offered) |
| `published` | set | yes | `draft → published` | offered |
| `canceled` | NULL | yes | `draft → canceled`; or unpublish-then-cancel | **not offered** |
| `canceled` | set | yes | `published → canceled` | **not offered** |

So the dialog has **three** reachable inputs, not four: `#0177`'s "four
states" are four *histories* over three `(status, published_at)` pairs. That is
the same count the implementer reached, arrived at independently.

### The sentence each pair actually produces, by execution

Drove `cancelVisibilityOutcome` and `cancelConfirmMessage` with all nine
`status × {set, NULL, undefined}` combinations from a throwaway vitest file in
the worktree (deleted afterwards; `git status` clean). Observed verbatim:

| `status` | `published_at` | outcome | sentence |
|---|---|---|---|
| `draft` | NULL *or* `undefined` | `staysPrivate` | *Cancel "X"? It is not currently published, so it stays private — canceling it will not make it visible.* |
| `published` | set | `staysVisible` | *Cancel "X"? It stays visible on the public site, marked canceled, rather than disappearing.* |
| `draft` | set | `becomesVisible` | *Cancel "X"? It is not currently visible, but canceling it will make it visible on the public site, marked canceled — it was published before, and that history was never cleared.* |

Three reachable inputs, three distinct sentences, no reachable input falling
through to a wrong branch. `undefined` matters and is handled: `workshopView`'s
`PublishedAt *string` carries `json:"published_at,omitempty"`
(`internal/handlers/admin_workshops.go:155`), so a NULL arrives at the SPA as an
**absent key**, not `null`.

Two unreachable inputs return an answer that would be wrong if they ever became
reachable, neither of which is a defect today:

- `(published, NULL)` → `staysVisible`, but such a row is invisible
  (`ListVisible` requires `published_at IS NOT NULL`), so the true answer would
  be `staysPrivate`. Unreachable while `Update` is the only writer.
- `(canceled, *)` → `becomesVisible` / `staysPrivate`, both wrong, but
  `canCancel('canceled') === false` and `WorkshopEditor.svelte:242` is the sole
  call site, reached only from the cancel dialog.

### Row 4 is true — proved on both public surfaces, not derived

A throwaway `internal/handlers` test (own database, fresh row per cell, no
literal or seeded id per §8b; deleted afterwards) walked the row-4 history and
checked `workshops.Store.ListVisible`, the real `GET /api/workshops`, and the
real `GET /api/workshops/{slug}`:

| cell | `status` | `published_at` | `ListVisible` | list route | detail |
|---|---|---|---|---|---|
| create | `draft` | NULL | false | false | 404 |
| `draft → published` | `published` | set | true | true | 200 |
| `published → canceled` | `canceled` | set | true | true | 200 |
| `canceled → draft` — **row 4, before** | `draft` | **set** | **false** | **false** | **404** |
| row 4 `→ canceled` — **row 4, after** | `canceled` | **set** | **true** | **true** | **200** |

Both halves of the new copy are therefore true by execution: the workshop is
**not currently visible** on either surface, and canceling it **makes it visible
on both**. "It was published before" is also true and is not a fabrication — it
is *entailed* by `published_at != NULL ∧ status = 'draft'`, since the only route
to a stamped `published_at` is a publish and the only transition that clears it
(`published → draft`) is the one that cannot produce this pair.

**Actionable?** Yes. The load-bearing clause — "canceling it will make it
visible on the public site" — is plain, and an admin reading it understands they
are about to publish something. Worth naming what the copy cannot fix: this
state is intrinsically confusing, and the dialog is only the place it surfaces.
Nothing here promises anything §9 or `#0051` forbids; "marked canceled" is
exactly `#0051`'s ruling and matches `workshopBadgeLabel`.

### Rows 1 and 3: identical to this function, but the shared copy is a choice

rather than a constraint is the only correction, and it is made here.

### `canCancel`: concur with offering, and one reason stronger than the ones given

explained correct action into an unexplained one — strictly worse.
