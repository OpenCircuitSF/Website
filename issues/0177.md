## Description

**The one that matters.** `cancelConfirmMessage` branches on `wasPublished`, which is `!!workshop.published_at`. `canCancel` offers Cancel on any non-canceled status — including a **`draft` whose `published_at` is non-NULL**, which is `#0171`'s `canceled → draft` row and a state that review *observed*, not hypothesized.

In that state `wasPublished` is `true`, so the dialog says *"It stays visible on the public site, marked canceled, rather than disappearing."*

Both halves are wrong:

- The workshop is **not** currently visible — `ListVisible` requires `status IN (published, canceled) AND published_at IS NOT NULL`, and the detail route 404s on `draft`.
- Canceling it **makes it visible**, since `status` becomes `canceled` while `published_at` is already set.

So the dialog promises continuity where the action actually causes publication. `#0174` fixed the branch that *over*-warned; this one **under**-warns, which is the direction that matters. The fix: that branch needs the current status as well as `published_at`.

**Two smaller items from the same review**, folded here rather than filed separately:

- **`.not.toMatch(/never published/i)` is a literal-phrase pin, not a semantic guard.** Rewording the copy to *"It is not currently published **and has not been published before**"* — reintroducing exactly the false history claim `#0174` removed — leaves all four assertions passing (73/73). The positive `/not currently published/i` assertion is what actually pins the wording. Acceptable as written, but narrower than its comment implies.
- **`sitemap_test.go`'s `published-1` fixture is `Status: WorkshopPublished` with `Published: false`** — a state `#0171` proved impossible (`status = published` implies a stamped `published_at`). Harmless today, but it makes a conjunctive gate fail for the wrong reason. One `Published: true` fixes it, and `#0174`'s mutation still fails with it corrected.
