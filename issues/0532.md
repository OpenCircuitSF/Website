## Description

A shared workshop link unfurls with its own generated card: `#0273` added `GET /workshops/{slug}/og.png`, which draws the title and date onto an embedded base image with `golang.org/x/image/font/opentype`. **Newsletters have no equivalent.** `archiveRouteMeta` always sets `og:image` to `og-default.png`, so every newsletter shared on Bluesky, Discord, Slack, or iMessage looks identical.

## Acceptance criteria

1. `GET /archive/{slug}/og.png` returns a 1200×630 PNG for a **published** campaign, reusing `#0273`'s rendering, base image, fonts, and title-fitting ladder rather than a second implementation.
2. The card shows the subject and the archive date. The date is Pacific time, matching the archive page (`#0519`).
3. Draft, withheld, and unknown slugs return **404**, never a generic image under a campaign-specific URL, which would leak the slug's existence — the same rule `#0273` applies to workshops.
4. `archiveRouteMeta` points `og:image` and `twitter:image` at the generated card for published campaigns.
5. Generated cards are cached and invalidated consistently with the rest of the SEO renderer, and the cache cannot grow without bound on attacker-chosen slugs (`#0073`).
6. Admin-entered subjects with long words, emoji, or right-to-left text do not crash the renderer or overflow the card.
7. **Post-deploy, verified by the user:** sharing `/archive/09-2026` in at least one app shows the generated card.
8. `ISSUE=NNNN scripts/check.sh go ./internal/seo/... ./cmd/opencircuit/...` passes with no skips.

## Fix

Reused `#0273`'s machinery rather than a second implementation: `cardRenderer.render` generalized to `renderCard(title, meta)`, so the archive card shares the base image, fonts, title ladder, geometry, and command line by construction. The meta line is the Pacific archive date — `archiveDateLabel`'s "Jan 2, 2006", the same label the archive page shows (`#0519`). Cache keys are namespaced (`workshop:`/`archive:` prefix) so an archive slug can never collide with an equal workshop slug; the bound stays 64 entries, cleared through the existing `Site.Invalidate` path. `cardableArchive` gates the handler on the same `Published` predicate `archiveRouteMeta` uses to point `og:image` at the URL, so a share card can never point at a 404.

Two recorded calls: (1) **twitter:image** — criterion 4's "twitter:image" is satisfied through Twitter/X's documented og:image fallback; web/index.html deliberately carries no twitter:image tag (`#0273`'s settled design), so adding one would re-litigate a closed decision. (2) **wrapText** now ellipsizes a single word wider than the card (criterion 6's "long words") — previously an oversized lone word overflowed the safe area, which ordinary workshop titles never hit but an admin subject can.

## Verification

`ISSUE=0532 scripts/check.sh go ./internal/seo/... ./cmd/opencircuit/...` — both `ok`, no skips. New tests: `TestArchiveCardMeta_PacificDate` (pinned instant where the UTC day differs from the Pacific day), `TestArchiveRouteMetaAndCardHandler_StatusCrossProduct` (published → card URL + 200 PNG at 1200×630; withheld/never-sent/unknown → 404 + og-default; nil source → 404), `TestArchiveCard_HostileSubjectsStayInSafeArea` (long words, emoji, RTL — ink stays inside the safe area), `TestSiteInvalidateClearsArchiveCards`, `TestCardCache_NamespacedKeys`. Criterion 7 (share in a real app) is post-deploy work for the user.
