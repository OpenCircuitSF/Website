## Description

`#0141`'s implementer put its guard test in package `web` (alongside
`web/embed.go`), ran the ordinary verification command, and the test **did not
run**. `scripts/check.sh` defaults its Go scope to
`./internal/... ./cmd/...` (line 90) and the `all` branch spells the same pair
(line 137) before `web_check`. `./web/...` appears nowhere.

So a Go test placed in that package is invisible to `ISSUE=NNNN scripts/check.sh`
and to `scripts/check.sh go` — the two commands every issue in this tracker is
told to run. It would only run under a bare `go test ./...`, which `CLAUDE.md`
§5 warns against for a different reason.

The implementer noticed and relocated its guard to `internal/seo`, which is
covered. **That is the right call for `#0141` and the wrong fix for this** — the
next person to add a test in `web` will hit the same silence, and there is
nothing to warn them.

**Why it matters beyond one test.** `web/embed.go` is the 95th non-test `.go`
file — the one `#0187` widened the citation guard's walk to reach, on the
principle that a guard should not need a boundary argument. The same principle
applies to the test runner: a package that holds Go source but is excluded from
the default suite is a place where a test can be written, pass locally, and
never run again.

`web/` has no `_test.go` files today, so nothing is currently unrun. This is
about the next one.

**A second, unrelated item, folded in because it is cheap and adjacent.**
`#0141`'s review probed its new placeholder guard's boundary and found one gap:
the guard keys on `/assets/…\.(js|css)`, which is config-dependent. A build with
a non-default `base` or `assetsDir` (`/static/…`, a relative `assets/…`, or
`.mjs`) would slip past. All three require editing `web/vite.config.ts`, which
overrides neither today, so the gap is currently unreachable.

The cheap hardening: the committed placeholder carries a unique
`This is a MINIMAL PLACEHOLDER, not real build output` comment that a real build
does **not** — verified, 1 occurrence committed, 0 in build output. Asserting
that marker is **present** catches regeneration regardless of Vite config, and
costs one line.

## Acceptance criteria

- [ ] Either `./web/...` joins the default Go scope, or the exclusion is deliberate and recorded where someone adding a test would see it — a comment in `scripts/check.sh` next to the package list, not only in an issue
- [ ] If included: `scripts/check.sh` still passes, and the skip audit still reports honestly for a package with no test files (`web` currently reports `[no test files]`, which the audit must not mistake for a silent skip)
- [ ] A test placed in `web` runs under `ISSUE=NNNN scripts/check.sh` — demonstrated by adding a temporary failing test and watching it fail, then removing it
- [ ] `CLAUDE.md` §5's description of the verification commands matches whatever is decided
- [ ] `#0141`'s guard still passes wherever it now lives
- [ ] `TestDistIndexPlaceholder` additionally asserts the placeholder marker comment is present, so a build with a non-default `base`/`assetsDir` is still caught
- [ ] That addition is proved by mutation — a file with the tokens and no marker fails the guard
- [ ] `ISSUE=0212 scripts/check.sh go ./internal/... ./cmd/...` passes with zero skips

## Implementation notes

`./web/...` joined the default Go package list rather than restructuring
anything, per this issue's own Notes ("prefer adding to the package list over
restructuring anything"):

- `scripts/check.sh`'s `go_test()` default changed from
  `./internal/... ./cmd/...` to `./internal/... ./cmd/... ./web/...`, with a
  comment next to the list explaining why (`#0212`, and the `#0141` history
  that motivated it). This is the single point both the `go` mode and the
  bare default mode read (`MODE="${1:-default}"` falls through to `go_test`
  with no explicit packages), so both are covered by one edit. `all` mode
  already passed `./...` explicitly and needed no change.
- `web/` has no `_test.go` today, so the new scope adds one informational
  `? github.com/…/web [no test files]` line to the skip audit's grep, which
  the audit already treats as expected output (not a failure) for exactly
  this shape.
- `internal/seo/dist_placeholder_guard_test.go`'s `TestDistIndexPlaceholder`
  gained a third signal: a `placeholderMarker` constant for the literal
  `This is a MINIMAL PLACEHOLDER, not real build output` comment text that
  `web/dist/index.html` carries and confirmed real source
  (`web/index.html`, which has different comment text entirely) and build
  output never do. `validateDistPlaceholder` now reports a problem when that
  marker is absent, closing the gap `#0141`'s review found: the existing
  `hashedAssetPattern` keys on `/assets/…\.(js|css)`, which a non-default
  Vite `base`/`assetsDir` would sidestep while every `%%OC_*%%` token
  survives untouched (Vite does not touch literal text it doesn't recognize
  as a token).
- Left `web/vite.config.ts` untouched — no `base`/`assetsDir` is set today, so
  the gap the marker closes is currently unreachable; this is a hardening
  against a future config change, not a fix for a live defect.
