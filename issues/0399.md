## Description

`internal/handlers`'s `TestNoCommentCitesUnresolvedPathOrSection` resolves a
path cited in a Go comment by walking the repository tree and matching. Two
properties combine into a fail-open:

1. `citationTargetSkipDirs` prunes only `.git` and `node_modules`. It does
   **not** prune `.claude`, so `collectRepoPaths` walks
   `.claude/worktrees/<agent>/` — a **full second copy of the repository**.
2. `pathCitationResolves` matches by **suffix**, so a path found anywhere in
   the walked set satisfies a citation.

Together: a comment citing a file that has been **deleted or renamed in the live
tree** still resolves, because the worktree's copy of it is still on disk and
still matches by suffix. The guard reports clean and the citation is dead.

**Confirmed by the orchestrator**, independently of the plan that found it:
`git worktree list` shows a live `.claude/worktrees/agent-a16d8f8a64eadf32f`
containing **281** `.go` files alongside `CLAUDE.md`, `cmd/`, `docs/`, `go.mod`
and the rest of the tree. `citationTargetSkipDirs` is `{".git", "node_modules"}`
and the suffix comparison is a `strings.HasSuffix` pair.

### Why it matters

`CLAUDE.md` §5a **actively encourages worktrees** — "Use a worktree when two
agents would otherwise edit the same files" — so the condition is not rare, it
is the documented workflow. The window is also invisible: worktrees are
gitignored, so nothing in `git status` hints that the guard's corpus has
silently doubled.

The failure is exactly the one this guard exists to prevent. A rename that
leaves a stale citation behind passes review, and surfaces later as a dangling
reference — the drift family of `#0352`, `#0356`, `#0370` and `#0384`.

**Direction of the bug matters.** This is a **fail-open** (a stale citation
wrongly resolves), not a false alarm. It cannot produce a spurious failure, so
nobody will trip over it; it will simply let something through. That is the
harder kind to notice and the reason to close it rather than record it.

## The fix the plan specified

Add `".claude"` to `citationTargetSkipDirs`. One line.

`.claude/` holds agent worktrees and session scratch state; nothing in it is a
legitimate citation target, and pruning it cannot make a real citation
unresolvable — unlike `dist`, which the existing doc comment explains at length
must **not** be pruned because real comments cite `web/dist/index.html`.

## Acceptance criteria

1. `.claude` is pruned from the repo-path walk, and the existing doc comment's
   reasoning is extended to say why — matching the care already taken there to
   explain why `dist` is deliberately **not** pruned.
2. **Prove the fail-open is closed, and prove it discriminates.** With a
   worktree present: a comment citing a path that exists **only** in the
   worktree must fail after the fix, and must (demonstrably) pass before it.
   Construct the worktree copy yourself in a throwaway location rather than
   relying on whichever agent worktree happens to exist when you run.
3. **Do not break the legitimate cases.** `web/dist/index.html`, `dist/index.html`
   and every other real citation in the tree must still resolve. The corpus must
   come back with the same result as before the change apart from the closed
   hole — a fix that quiets the guard is worse than the fail-open.
4. **Consider whether suffix matching is itself the deeper defect** and say what
   you conclude. Pruning `.claude` closes the instance; matching by suffix means
   any future in-tree copy reopens it. If you judge tightening the match to be
   out of scope, say so with a reason — that judgement is part of the
   deliverable. Per `#0330`/`#0347`/`#0356`, recording a limit is a legitimate
   outcome; leaving it unmentioned is not.
5. **No new mechanism beyond what criterion 1 and your criterion-4 conclusion
   require.** §8's `#0258` is six passes of adding checks to defend checks.
6. Run `./internal/handlers/...` and `./internal/db/...` (`#0381`). Per §5 name
   the specific tests that ran. `gofmt` stability. No `<file>.go:<int>` citation
   anywhere (`#0352`).
