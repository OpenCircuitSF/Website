## Description

`#0095` built a parity guard tying the client's complained-subscriber copy to
the server's, and deliberately did **not** extend it to the CampaignProgress SSE
payload — using that issue's own escape hatch, and recording the narrowing
rather than taking it silently. That was the right call: the SSE case is a
structurally different problem (a Go struct versus a TypeScript interface,
rather than two string constants).

But the concern `#0095`'s 2026-08-22 amendment raised is still live and should
not die with the issue that declined it:

**A field added on the TypeScript side alone is caught by nothing.** The
existing assertion checks that the keys the server sends are handled by the
client. It does not check the converse. So a client that reads
`progress.remaining` when the server never sends it compiles, type-checks,
passes every test, and silently renders `undefined` — during a campaign send,
which is the one operation in this system with no undo.

## Acceptance criteria

- [ ] The SSE payload's key set is pinned in both directions: a field added on either side alone fails
- [ ] Proved by mutation in both directions — add a field to the Go struct only, then to the TypeScript interface only, and confirm each fails naming the side that diverged
- [ ] The guard reads both from source rather than restating either by hand; a hand-maintained third list is a third thing to drift
- [ ] It follows the established parity-guard shape (`routes_parity_test.go`, `docs_parity_test.go`, and `#0095`'s own `complained_copy_parity_test.go`) rather than inventing a fourth pattern
- [ ] `ISSUE=0241 scripts/check.sh go ./internal/handlers/...` and `scripts/check.sh web` both pass

## Notes

Reported by `#0063`/`#0095`'s phase-3 review under `CLAUDE.md` §9.

Parsing a Go struct and a TypeScript interface and comparing field sets is more
work than comparing two string constants, which is exactly why `#0095` declined
it and why it deserves its own issue rather than being bolted on. `#0095`'s test
already parses TypeScript with the technique this needs.

Phase 8 rather than 7: nothing blocks on it, and the send path it protects is
already guarded at the points that matter (`#0045`'s physical-address refusal,
`#0124`'s circuit breaker). This closes a reporting gap, not a sending one.
