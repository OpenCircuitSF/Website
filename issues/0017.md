## Description

The persistent shell around every public page: logo, primary navigation, and a footer carrying the legal and social links.

## Acceptance criteria

- [x] Header with the monochrome logo mark, wordmark, and nav links to Workshops, About, Subscribe
- [x] Active route is visually indicated and marked `aria-current="page"`
- [x] Mobile layout: nav collapses or wraps cleanly at ≤ 480 px with ≥ 40 px tap targets
- [x] Footer with Discord link, contact address, privacy policy link, and copyright
- [x] Staff sign-in is reachable but unobtrusive — a footer link, not primary nav
- [x] Signed-in staff see an Admin link in the header
- [x] Keyboard navigable end to end with a visible focus ring on every interactive element
- [x] A skip-to-content link is the first focusable element

## Carried in from `#0018`'s review (2026-08-18)

Three obligations transferred here rather than left half-met on `#0018`:

- [x] **Mount `Logo.svelte` in the header.** `#0018` built the mask-technique
      component but could not mount it — no header existed. Use
      `variant="mark"`; `"full"` is illegible below ~96 px.
- [x] **Fix the retina blur.** `Logo.svelte` hardcodes `/mark-mask-64.png` at
      every size, which renders visibly soft on a 2×/3× display — the reviewer
      rendered it at 64 CSS px against `mark-mask-256.png` and the shipped one is
      clearly blurred. `assets/logo/mark-mask-256.png` already exists; select the
      raster by requested size.
- [x] **Wire the theme toggle.** `theme.ts` exports `Theme`, `currentTheme`,
      `nextTheme`, `applyTheme`, `readStoredTheme` and is DOM-injectable, but no
      button exists yet. The header owns it.

**Export surface from `#0018` — build against this, it is stable:**
`Logo.svelte` takes `variant?: 'mark'|'full'` (default `'mark'`) and
`size?: number` (default `34`); both masks are square so one `size` is correct.
Motifs are `Prompt {text}`, `StatusList {items: string[]}`, `CommandLine
{command}`, `TerminalPanel {title?, noPadding?, children}`, `TraceDivider` (no
props).

Two smaller carried findings, fix if cheap: `site.webmanifest` has no 192×192
icon (Chromium's install heuristics have historically wanted one), and
`:where(a, button):focus-visible` has zero specificity and misses `summary` and
`[tabindex]`.

## Root cause

`#0018` shipped `Logo.svelte` and `theme.ts` with no consumer — the header
those defects needed to be caught in didn't exist yet, so they were carried
here rather than left half-fixed against a component that couldn't mount them.

## Fix

**`web/src/lib/Header.svelte`** (new): skip-to-content link (first element in
the DOM), then a `<header>` with the mounted `Logo` (`variant="mark"
size={34}`) + wordmark linking home, a `<nav aria-label="Primary">` over
Workshops/About/Subscribe (each `aria-current="page"` when
`$currentRoute.name` matches — Workshops also covers `workshop-detail` so a
workshop detail page still shows Workshops as active), a conditional Admin
link gated on `$currentUser?.is_admin`, and a theme-toggle `<button>` calling
`theme.ts`'s `cycleTheme`/`currentTheme` against the real
`document.documentElement`/`window.localStorage`.

**Retina blur** — extracted the raster-selection logic into
`web/src/lib/logo.ts` (`selectMarkRaster(size)`, unit tested in
`logo.test.ts`) rather than inlining it in the component, per this project's
"SPA logic in `web/src/lib/`, components stay thin" convention.
`selectMarkRaster` picks between `mark-mask-64.png` and the newly-copied
`mark-mask-256.png` based on `size * 3` (worst-case DPR) vs. each raster's
native resolution, falling back to the largest raster past that. Copied
`assets/logo/mark-mask-256.png` into `web/public/` — it didn't exist there
before this commit, only under `assets/logo/`.

**Footer** (`web/src/lib/Footer.svelte`, rewritten): Discord invite
(`discord.gg/Fq9ug6QXV3`, sourced from `placeholder/index.html`, the validated
reference), `mailto:hello@opencircuitsf.com` (PRD's resolved default sending
identity, §14 Q2), a `/privacy` link, `© {year} Open Circuit SF`, and
`/login` as the unobtrusive staff-sign-in link. The old GitHub-link-only
footer is gone; nothing else referenced it.

**Two smaller carried findings**: `web/public/mark-green-192.png` generated
via `sips -Z 192 assets/logo/mark-green-256.png` (stock macOS, no new
dependency) and added to `site.webmanifest`'s `icons` array. The
`focus-visible` rule in `app.css` now reads
`:where(a, button, summary, [tabindex]):focus-visible`.

**App.svelte**: the public-marketing catch-all branch now renders `<Header
/>` before its placeholder `<main id="main-content">` (the `id` is what the
skip link targets). Login/Account/Admin/RegisterVerify/RecoverVerify keep
their own existing bespoke chrome, unchanged — they are Phase 1 views outside
this issue's scope and already have a working header of their own
(`<h1>{APP_NAME}</h1>` inside their own `<main>`); wrapping them in the new
marketing `Header` would have been a redesign nobody asked for. The global
`Footer` still renders under every route, matching the pre-existing behavior.

**Privacy policy page**: does not exist yet. Filed `#0070` rather than
skipping the footer link or pointing it at a dead route silently — `/privacy`
is a real, honest 404 today (once `#0022` lands) rather than a link to
nothing, per the issue's own Notes.

- **Theme toggle**: clicked through auto → light → dark → auto, confirming

## Gotchas

Same `web/dist/index.html` placeholder-overwrite as `#0014` — `npm run build`
regenerates it with real hashed asset references; restored to the exact
committed ShortLinks-era placeholder content by rewriting the file (not `git
checkout --`), confirmed via `git status --porcelain web/dist/` showing no
diff before committing.

`vite preview` (which serves `dist/` as-built) breaks once the placeholder
`index.html` is restored, because it references asset hashes that no longer
exist post-restore — used `vite`'s dev server (serving `web/index.html`
directly, the project's own documented preview path via `./scripts/dev.sh`)
for the Playwright pass instead.

The carried finding about `mailto:hello@opencircuitsf.com` being intercepted
by the router was checked, not assumed: `shouldIntercept` (from `#0014`)
already rejects non-`http(s)` protocols, so the footer's `mailto:` link is
correctly left alone by `initRouter`'s click listener — no additional
handling was needed in `Header`/`Footer`.

## Review notes — 2026-08-18 (phase 3, approved)

Re-verified independently against the **production build served by the Go
binary** (`npm run build`, then `go build ./cmd/opencircuit` and run with
`STORAGE=json`), not the Vite dev server — so what was measured is what ships.
`npm run check` 187 files / 0 errors, `npm test` 7 files / 103 tests, `go test
./... -count=1` all `ok` with `TEST_DATABASE_URL` exported and **zero skips**
(`-v | grep -c SKIP` = 0).

Driven with Playwright over a real HTTP origin (masks fail silently under
`file://`, `CLAUDE.md` §8):

- **Skip link is the first Tab stop** on `/`, `/about` and a 404 path — one
  `Tab` from load lands on `<a class="skip-link" href="#main-content">`, which
  moves from `top: -100%` to `top: 12px` on focus.
- **Focus ring on every interactive element.** Walked the full tab order on
  three routes (11, 13 and 13 stops). Every stop reported
  `outline: solid 2px rgb(47,125,12)` — that is `--accent`'s light tint
  `#2F7D0C`, not `--border-strong`, per `CLAUDE.md` §8. Zero stops without a
  visible ring.
- **`aria-current` is correct, not merely present.** On `/about` only the About
  link carries `aria-current="page"`; Workshops, Subscribe and Admin report
  `null` (attribute absent, not `"false"`). On `/` and on a 404 path no nav
  link is marked.
- **Tap targets and mobile layout.** Measured at 320/375/414/480 px: every nav
  link, the theme toggle and all four footer links measure exactly **40 px**
  tall. At 768 px and above they relax to 25–29 px, which is correct — the
  ≥40 px rule is the ≤480 px criterion. `document.documentElement.scrollWidth
  === clientWidth` at **320, 375, 414, 480, 768, 1024, 1440 px** on all three
  routes, and an element-level sweep for anything whose right edge exceeds the
  viewport found nothing. Measured through Playwright's device-metrics
  override, which genuinely renders below the ~485 px headless floor that
  `CLAUDE.md` §8 warns about — a `--window-size=375` render would have been
  silently clipped and its result worthless.
- **Footer contents**: `Discord · hello@opencircuitsf.com · Privacy policy ·
  Staff sign-in © 2026 Open Circuit SF` — Discord, contact, privacy link,
  copyright and the unobtrusive staff sign-in all present, none of them in the
  primary nav.
- **Admin link** renders in the header under the dev-mode auto-login admin.

**The three carried-in `#0018` obligations, each re-verified the way the
carry-in asked for:**

1. **`Logo.svelte` mounted** — present in the header at `variant="mark"`,
   `size=34`.
2. **Retina blur fixed — confirmed by looking, not by reading the selection
   logic.** Rendered the header at `deviceScaleFactor` 1, 2 and 3 and
   screenshotted the mark element itself (34 / 68 / 102 physical px). The
   computed `mask-image` resolved to `/mark-mask-256.png` at every ratio. Then
   re-rendered the same element at 3× with the mask forced back to
   `/mark-mask-64.png` — the pre-fix asset — and compared the two 102 px
   captures side by side: the 64 px source is visibly soft on the chip pins and
   the `>_` glyph, the shipped 256 px source is crisp. The fix is real.
3. **Theme toggle wired** — clicked through `auto → light → dark → auto`,
   confirming `<html data-theme>`, the button label and `localStorage` at each
   step, and that an explicit choice survives a reload while `auto` correctly
   persists nothing.

**No external requests.** Instrumented every request across `/`, `/about` and a
404 path: zero requests to any host other than the origin. The built `dist/`
contains no CDN, analytics or tracker reference; both webfonts load from
`/fonts/` on-origin (`CLAUDE.md` §9).

**Not verified here** (unchanged from the implementation pass): screen-reader
behaviour and real-device testing — `#0063` owns those.
