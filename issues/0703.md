## Resolution

All eight tools in one pass; no split needed.

- `internal/handlers/admin_outreach_flyers.go`: each admin flyer handler is now a thin wrapper over a transport-free core: `listFlyerRows`, `flyerByID`, `createFlyer`, `patchFlyer`, `putFlyerLocations`, `deleteFlyer`, `generateFlyer`, `setFlyerLinkPutUp`. `buildFlyerView`/`loadFlyer` became `flyerView(ctx, f)`/`getFlyer(ctx, id)`. Refusals are `outreachRefusal`s carrying the same status and text the admin answered before, and ShortLinks failures are `outreachLinksError`, so `writeOutreachError` keeps the admin bodies (and the 429 `Retry-After`) unchanged. Audits go through `recordCtx` (`auditFlyerCtx`, plus the existing `auditFlyerLinkCtx`), so a v1 call is attributed to the API key. `generateFlyer` builds its final view on the caller's ctx, not the 45 s generate ctx.
- `internal/handlers/v1_outreach_flyers.go`: `list_flyers`, `get_flyer`, `create_flyer` (Idempotency, 201), `update_flyer`, `set_flyer_locations`, `generate_flyer`, `set_flyer_link_put_up` (`{put_up: bool}`), `delete_flyer` (Destructive). Times are converted to Pacific (flyer `created_at`/`updated_at`, link `put_up_at`). Each flyer view adds `print_url` (`<base>/admin#/outreach?view=print&flyer=N&layout=full`). A v1 `photo` must start with `/media/` and then also passes the admin's `validateFlyerFields`/`isSafeCoverImage` check. Upstream error text stays out of the responses (`outreachAPIError`).
- `notFoundWhat` names `flyer` and `flyer link`. Registered in `BuildV1Registry`; the names are added to `TestBuildV1RegistryListsOperations`, `specTools`, and the Outreach sections of `docs/api.md` and `docs/mcp.md`.
