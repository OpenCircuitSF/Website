## Description

`#0158` replaced every `time.Now().UnixNano()`-derived test identifier with `testdb.Unique()`, across 28 files. It missed four helpers, in two packages that consequently have **zero** `testdb.Unique()` call sites — because they render the same clock as a formatted string instead:

```
internal/middleware/auth_test.go:39            zz-mw-<label>-<ts>@example.com
internal/middleware/auth_test.go:48            zz-mw-tok-<label>-<ts>
internal/middleware/clientip_signup_test.go:91 zz-clientip-<ts>@example.com
internal/audit/audit_test.go:36                zz-audit-<label>-<ts>@example.com
```

where `<ts>` is `time.Now().UTC().Format("20060102T150405.000000000")` — the same clock that repeats on **94.7%** of adjacent reads (`#0158`), just wearing a different coat. `#0158` searched for `UnixNano()` and `#0160` for `UnixNano|UnixMilli|UnixMicro`; `.Format(…)` matches neither.

**Three of the four are latent**: a distinct `label` argument discriminates every call site, so the clock is not load-bearing. **The fourth is a live defect**: `internal/middleware/clientip_signup_test.go:91`'s `uniqueSignupEmail` takes **no label**, so the clock is its only discriminator, and it is called from two tests separated by nothing but a database insert. That is exactly the "masked by intervening round trips" shape `#0158`'s review flagged for `uniqueAdminWorkshopTitle` — masked until it isn't.

## Acceptance criteria

- [x] All four helpers draw uniqueness from `testdb.Unique()`; `internal/middleware` and `internal/audit` stop being the two packages with no call sites
- [x] Keep the `label` arguments — they make failures readable, and the point is that the *clock* stops being the discriminator, not that labels are redundant
- [x] `uniqueSignupEmail` is fixed first and separately noted, since it is the one with a real collision window
- [ ] A test proves back-to-back calls to each helper are distinct, in the shape `#0158` used — **unmet for `seedUser`**; see `## Review notes`
- [x] **Sweep on the axis that found this one**: enumerate every identifier-minting helper in the tree and check what discriminates it, rather than grepping for known-bad tokens. `#0158` searched for a function name, `#0160` for three, and this survived both — the search that worked was reading the helpers
- [x] `ISSUE=0163 scripts/check.sh go ./internal/...` passes, and `internal/middleware` and `internal/audit` pass under `-shuffle` on two fresh seeds

## Root cause

Four helpers built "unique" test identifiers by formatting `time.Now().UTC()`
to nanosecond-looking precision
(`time.Now().UTC().Format("20060102T150405.000000000")`) instead of calling
`time.Now().UnixNano()` directly. It is the identical repeating-clock defect
`#0158` fixed in 28 files — a 200,000-pair probe there measured that clock
repeating on 94.7% of adjacent reads — just spelled as a formatted string.
`#0158`'s sweep grepped for `UnixNano()` and `#0160`'s for
`UnixNano|UnixMilli|UnixMicro`; `.Format(…)` matched neither pattern, so
both sweeps walked past all four call sites without ever reading them.

Three of the four (`uniqueAuthEmail`, `uniqueSessionToken`, `seedUser`) take
a `label` argument that discriminates every call site in the tree today, so
the clock was decoration rather than load-bearing — latent, not live.
`uniqueSignupEmail` (`internal/middleware/clientip_signup_test.go:91`) takes
no `label`, so the clock was its *only* discriminator, and
`TestSignupSurvivesUnparseableXFF` / `TestSignupSurvivesPortOnRightmostEntry`
call it back-to-back separated by nothing but a database insert — exactly
the "masked by intervening round trips until it isn't" shape `#0158`'s
review flagged for `uniqueAdminWorkshopTitle`.

## Fix

Replaced each helper's `"..." + time.Now().UTC().Format("20060102T150405.000000000") + "..."`
construction with `fmt.Sprintf("...%d...", testdb.Unique())`, keeping every
existing `label` argument and prefix string unchanged so failure messages
read the same as before. `uniqueSignupEmail` was fixed first, as the issue
required, since it is the only one of the four with a real collision
window.

`internal/audit/audit_test.go`'s `"time"` import became unused once
`seedUser` stopped calling `time.Now()` and was removed; `fmt` and
`internal/testdb` were added to all three files' import blocks (already
imported by each package's separate `main_test.go`, but each `_test.go`
file needs its own import).

Added one back-to-back-collision regression test per helper, in the shape
`internal/subscribers/suppressions_test.go`'s
`TestUniqueSuppressionEmail_NeverCollidesAcrossManyBackToBackCalls`
(`#0108`/`#0160`) uses: call the helper 20,000 times in a tight loop with no
intervening work and fail on the first repeat.
`TestSeedUser_BackToBackCallsNeverCollide` (audit) is a two-call DB-backed
variant instead, since `seedUser` inserts a row per call and `users.email`
carries a real `UNIQUE` constraint (`migrations/000001`) — 20,000 inserts
per test run was unnecessary and would have meaningfully slowed the suite
for no extra coverage; two calls are enough to prove no collision, and a
collision there surfaces as the same `t.Fatalf` a real caller would hit.

**Enumeration of every identifier-minting helper in the tree** (the
criterion the issue calls out as the one that matters most): searched for
every function whose name matches `unique*`/`test*Email|Slug|Title|Token|ID`
(case-insensitive) and separately grepped every file containing a `"zz-"`
literal prefix, then read each helper's body rather than trusting the name.

## Gotchas

- **The `"time"` import removal was file-specific.** `internal/audit/audit_test.go`
  had no other `time.` usage once `seedUser` stopped calling `time.Now()`,
  so `gofmt`/`go vet` would have failed with "imported and not used" had it
  stayed; the other two files still use `time.Hour`/`time.Now()` elsewhere
  and kept the import.
- **`internal/audit`'s regression test needs a database**, unlike the other
  three, because `seedUser` inserts a row as part of building the
  identifier rather than returning a bare string. `TestSeedUser_BackToBackCallsNeverCollide`
  skips cleanly (via `auditTestPool`) when `TEST_DATABASE_URL` is unset,
  same as every other DB-backed test in the file, rather than needing a
  separate no-DB variant.

## Review notes

Bounced 2026-08-22. Re-verified independently in a throwaway worktree detached
at `ea0c2b0` (the main checkout went dirty mid-review with `#0136`'s in-flight
edits to `cmd/opencircuit/main.go` and `internal/handlers/`, which this issue's
scoped run compiles). `uptime` before every step: load averages 1.46–2.87 —
idle throughout, so nothing below is the `CLAUDE.md` §5 "machine is busy" case.
This issue's own point is that the defect is real on an idle machine, and the
finding below is the mirror image: a guard that is vacuous on an idle machine.

**The code fix is correct and complete.** All four helpers draw from
`testdb.Unique()`, every `label` argument and prefix string is preserved, and
`git show --stat ea0c2b0` is exactly the three named files. `uniqueSignupEmail`
— the live one — is now `fmt.Sprintf("zz-clientip-%d@example.com",
testdb.Unique())`, and the two tests that call it back-to-back
(`TestSignupSurvivesUnparseableXFF` / `TestSignupSurvivesPortOnRightmostEntry`)
passed **30/30** consecutive `-count=1` runs. `internal/middleware` and
`internal/audit` passed under `-shuffle=987654321` and `-shuffle=31415926`
(seeds of my own choosing, different from the implementer's), and
`ISSUE=0163rev scripts/check.sh go ./internal/...` reported **all 15 packages
`ok`** with real elapsed times (`internal/handlers` 2.354s, `internal/interests`
2.214s, `internal/middleware` 0.824s, `internal/audit` 0.284s), skip audit
`(no skips)`, `VERIFICATION PASSED`.

**What bounces it: `TestSeedUser_BackToBackCallsNeverCollide` is vacuous.** It
cannot fail for the reason it names, so acceptance criterion 4 is not met for
`seedUser`. Proved by execution, not by reading (§8a: file copied aside first,
restored from the copy, md5 `adfd7cb80b502a557fe4f43117187e7f` confirmed
byte-identical afterwards, worktree `git status --porcelain` empty):

- With `seedUser` reverted to the old
  `time.Now().UTC().Format("20060102T150405.000000000")` construction, the test
  **passed 10 runs out of 10**. The defect was fully reinstated and the guard
  never noticed.
- The guard *can* fail — forcing `seedUser` to return a constant email fails it
  immediately with `duplicate key value violates unique constraint
  "users_email_key" (SQLSTATE 23505)`. So this is not a broken assertion; it is
  the wrong shape.
- Why it cannot work, measured on this machine: the formatted clock repeats on
  **1545/2000 (77.2%)** of truly adjacent reads, but on **0/200 (0.0%)** of
  reads separated by a single `INSERT` round trip. `seedUser` performs an
  `INSERT` between its two identifier constructions by construction, so the two
  calls are never adjacent. The guard is separated from the defect by exactly
  the round trip that masks it.

This makes the `## Fix` section's justification factually wrong where it says
two calls "are enough to prove no collision" and that 20,000 would add "no
extra coverage." The opposite holds: two calls give *zero* coverage of the
mechanism, and the cheap fix is to guard the identifier construction rather
than the insert — extract the email expression (e.g. `seedUserEmail(label)`)
and loop it 20,000 times with no DB in the loop, exactly as the three
`internal/middleware` guards do. The DB-backed two-call test is fine to keep as
a secondary integration check; it just cannot be the guard.

Worth stating plainly because it is this issue's own lesson recurring: a guard
that cannot detect the regression it names is the same class of miss as a sweep
that greps for the token it already fixed. `#0160`'s review found the identical
vacuity in `uniqueSuppressionEmail`'s guard.

**The other three guards are sound**, checked the same way. Reverting
`uniqueAuthEmail` and `uniqueSessionToken` to the formatted clock fails both
immediately — `call 2: uniqueAuthEmail returned a duplicate address
"zz-mw-same-label-20260823T045152.802765000@example.com"` and `call 1:
uniqueSessionToken returned a duplicate token
"zz-mw-tok-same-label-20260823T045152.802938000"`. Restored from the copy
(md5 `46a3bc95be40d1de35ca708234c6296a`), all four pass. Those three are pure
functions with no round trip, which is precisely why they work.

**The enumeration is accurate in substance, and I verified it rather than
trusting it.** Mechanically extracting each of the 18 other named helpers'
bodies and grepping for `testdb.Unique()` returns `OK` for all 18, so the
table's central claim holds: these four were the only stragglers.

**Search axis I added, which the implementer's two did not cover.** It searched
by helper *name* (`unique*`/`test*Email|Slug|Title|Token|ID`) and by the `"zz-"`
literal prefix. Both would have missed `seedUser` itself, which is named
`seed*`, returns `int64`, and mints its identifier internally — so I swept that
class directly: every `_test.go` function containing `INSERT INTO`, regardless
of name or return type, plus every function returning `string` regardless of
name. Findings:

- Six internal-minting seeders that take no identifier parameter
  (`seedTestSubscriber`, `seedSubscriberLinkedToInterest`,
  `seedSubscriberWithInterest`, `seedSubscriber`, `seedActiveSubscriber`,
  `seedInterest`) — all already on `testdb.Unique()`. None appear in the
  enumeration table.
- `internal/subscribers/store_test.go:1185` mints `fmt.Sprintf("mtok-%d",
  testdb.Unique())` — **no `zz-` prefix, inside a `seed*` function**. Correct,
  but invisible to both of the implementer's axes. It is the proof that the
  axes had a gap even though the answer happened to be right.
- No clock-derived identifier construction survives anywhere: the only
  remaining `time.Now()...Format` calls are `time.RFC3339` payload timestamps
  in the SES notification tests, which are values under test, not uniqueness
  sources. Correctly left alone.

**Ruling on the two fixed-literal tokens: safe, but the stated reason is
wrong on both counts.** The `## Fix` section justifies them as "safe as long as
each test run truncates its tables once at `TestMain`."

- `cmd/opencircuit`'s `TestMain` (`main_test.go:10`) truncates **nothing** — it
  only takes `testdb.Lock()` and calls `m.Run()`.
- Both tokens live in the **same** package (`package main`), so "each package
  truncates" cannot separate them even in principle. The implementer's phrasing
  implies a separation that does not exist.

The real mechanism is different and stronger. Every wiring test that seeds a
session gets its pool through a setup that calls `truncateAdminWiringTables`
(`TRUNCATE sessions, passkey_credentials, audit_log, users RESTART IDENTITY
CASCADE`) **on entry** and registers a `t.Cleanup` that truncates **again on
exit** (`events_wiring_test.go:50,53`; `shutdown_budget_wiring_test.go:132,136`;
also `admin_wiring_test.go:81,84` and `seo_wiring_test.go:97,100`). So each
literal token is inserted into an empty `sessions` table and removed before the
next test begins.

Answering the two specific questions: it does **not** depend on `-shuffle`
ordering — truncate-on-entry makes test order irrelevant, which is why both my
seeds pass. It does **not** depend on the two tests being in different packages
— they are in the same one. It **does** depend on `t.Parallel()` never being
introduced in `cmd/opencircuit` (verified: zero occurrences). That dependency is
worth knowing, because if any of these wiring tests ever gained `t.Parallel()`,
the per-test `TRUNCATE` would destroy a concurrently running sibling's rows —
a considerably worse failure than a token collision, and one no assertion in
the package would attribute correctly.

Also note the enumeration lists 2 fixed-literal session tokens but there are
**5**: `zz-events-nonadmin-token`, `zz-events-admin-token`,
`zz-shutdown-budget-token`, plus `wiring-nonadmin-token` /
`wiring-admin-token` (`admin_wiring_test.go:211-212`) and
`seo-wiring-admin-token` (`seo_wiring_test.go:147`) — the last three carry no
`zz-` prefix, so the prefix grep could not see them. All five are safe by the
same truncate-on-entry mechanism, and `sessions.token` is `UNIQUE NOT NULL`
(`migrations/000003`), so any real collision would surface loudly as a
constraint violation rather than silently. Not a defect; the table is simply
incomplete on the axis it chose.

**To clear this bounce**: give `seedUser`'s identifier construction a guard
that actually exercises it back-to-back, and correct the two factual claims in
`## Fix` (the `TestMain` truncation story, and "two calls are enough"). The
substitutions themselves need no further work.
