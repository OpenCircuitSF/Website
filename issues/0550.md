## Root cause

`decodeError` copied the server's `error` string verbatim; `EnsureCampaign` took a `name` independent of the slug, and ShortLinks derives the slug from the name; `CreateLink`'s docs implied de-duplication that does not apply with a custom key.

## Fix

- `decodeError(resp, body, token)` replaces the token with `[redacted]` in the message.
- `EnsureCampaign(ctx, slug, req)`: name parameter dropped, `req.Name = slug`, label belongs in `Description`.
- `CreateLink` doc corrected; new `EnsureLink` (requires Key; on 409 does `GetLink`, accepts only a matching destination, otherwise returns the original `ErrConflict`).

## Review notes

Reviewed 2026-10-16 (Opus, phase 3). **Bounced** — one small, precisely specified defect in `EnsureLink`; the rest is correct.

- **Independent verification:** `ISSUE=0550 scripts/check.sh go ./internal/shortlinks/... ./internal/handlers/... ./internal/db/...` — build/vet/gofmt clean, all three packages `ok`, no skips, VERIFICATION PASSED.
- **Criterion 1 (redaction): met.** `decodeError` replaces the token in the JSON `error` string; the new JSON-body case asserts both `err.Error()` and `APIError.Message` are clean while the rest of the message survives.
- **Criterion 2 (EnsureCampaign): met.** The `name` parameter is gone, `req.Name` is forced to the slug, and the test proves a caller-supplied display name is overwritten and `Description` passes through. No callers outside the package needed updating.
- **Criterion 3 (CreateLink doc + EnsureLink): doc fixed; helper has a gap.** The destination comparison itself is sound: ShortLinks' `Create` stores `strings.TrimSpace(req.DestinationURL)` verbatim (UTMs are whatever the client baked in; no normalisation), and `GET /api/links/{key}` returns that stored value via `toLinkView`. **The gap:** ShortLinks link keys are globally unique (`key VARCHAR(12) UNIQUE`, so a 409 can come from *another user's* link), but its `GET /api/links/{key}` is scoped to the caller and answers **404** for a key someone else owns. `EnsureLink` then returns `ErrNotFound` from the GET, contradicting its own doc comment ("any other holder of the key stays ErrConflict"), and leaving a caller (`#0544`) with a confusing "not found" for a key that is in fact taken.

**Remedy for the next pass (Sonnet, transcription):**

1. In `EnsureLink`, after `got, gerr := c.GetLink(ctx, req.Key)`: if `errors.Is(gerr, ErrNotFound)`, return the original 409 `err` (the key belongs to someone else); any other `gerr` is still returned as is.
2. Compare against the value the server actually stores: `got.DestinationURL != strings.TrimSpace(req.DestinationURL)`.
3. Extend `TestEnsureLink`: a GET answering 404 after the 409 must give `errors.Is(err, ErrConflict)`, and a retry whose `DestinationURL` has surrounding spaces while the stored value does not must be accepted. Keep the existing GET-500 case (non-conflict error).
4. Re-run `ISSUE=0550 scripts/check.sh go ./internal/shortlinks/... ./internal/handlers/... ./internal/db/...`.
