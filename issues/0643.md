## Description

The user's request, 2026-11-05: "We need to update how the newsletter is created. The body should be pre-filled with the upcoming events for the month with short links which have UTM values for the newsletter which go with the campaign already created for the event."

**Decision, 2026-11-05 (the user, relayed by the orchestrator):** "Actually, it could have a button to copy this text into the body field. It should not replace what is there but add to it." So the body is **not** pre-filled automatically. The campaign editor gets a button that builds the upcoming-events text (with the newsletter ShortLinks) and **appends** it to the body. It never replaces existing text.

Each event's link is a ShortLink whose destination carries newsletter UTM values (`utm_source=newsletter`, `utm_medium=email`) and which belongs to the ShortLinks campaign that Outreach already made for that event.

## Acceptance criteria

- [ ] The campaign editor has an **Add upcoming events** button, with a month picker, under the Body field. Clicking it appends a block listing that month's upcoming events, each with a title, date and time, venue and link, to the end of the body.
- [ ] The block is appended after the existing text (with a blank line between them). Existing text is never replaced or reordered, including text typed while the request was in flight.
- [ ] Each event link is a ShortLink in that event's existing ShortLinks campaign (the one Outreach's Start created), pointing at the event page with newsletter UTM values. Clicking the button again for the same newsletter reuses the stored link. It does not create a duplicate, and does not call ShortLinks again for that event.
- [ ] Links are created only when the button is clicked, never on page load or while typing.
- [ ] If ShortLinks is unavailable or an event has no Outreach campaign yet, the block is still appended, using the plain event URL with the same UTM values, and the editor says which events fell back and why.
- [ ] Past, draft, canceled and undated events are left out.
- [ ] The button is disabled when the campaign cannot be edited (sending, sent, canceled).

## Relation

- Builds on the Outreach ShortLinks work (`#0544` Start and campaign, `#0568` slot links, `#0638`) and the mailing campaign composer (PRD §6.6). The newsletter month comes from `#0405`'s archive-slug template.

### What exists today (grounding)

- **Composer.** `web/src/views/admin/CampaignEditor.svelte` edits an already-created campaign: `getCampaign(campaignId)` loads it, `bodyMd` is bound to `<textarea id="campaign-body">` ("Body (Markdown)"), and edits autosave through `scheduleAutosave` / `saveDraft()` → `PATCH /admin/campaigns/{id}`. The body is Markdown (`body_md`). Campaigns are created from `Campaigns.svelte` (`POST /admin/campaigns`). A "Monthly newsletter" checkbox there sends `newsletter_month` (`YYYY-MM`), and the server mints the slug in `mailing`'s MM-YYYY newsletter format (`internal/mailing/newsletter_month.go`, `#0405`). The month is stored **only** in the slug. Editable means `canEditCampaign(status)`, which is draft or scheduled (`web/src/lib/campaigns.ts`).
- **The campaign already created for the event.** It is the `outreach` row's `campaign_slug` (`internal/outreach/store.go`, `GetByWorkshop`). It exists **only after an admin clicks Start outreach** for a published workshop: `AdminOutreachHandler.Start` (`internal/handlers/admin_outreach.go`) calls `EnsureCampaign(wk.Slug, …)` and stores the returned slug, which can carry a suffix. A published workshop with no Outreach has no ShortLinks campaign.
- **How Outreach makes links.** `postLinkRequest` (`internal/handlers/admin_outreach_links.go`) calls `CreateLink` with no custom `Key`, so ShortLinks' destination de-duplication heals a crash between the upstream create and the local insert. It sets `CampaignSlug: o.CampaignSlug`, `UTMSource`/`UTMMedium` from the channel, `UTMCampaign: wk.Slug`, `UTMContent: wave`, `Placement: channel`. Then `InsertPostLink` (`ON CONFLICT … DO NOTHING`, returns the existing row) makes the slot idempotent. `outreach.DestinationURL` builds `<base>/events/<slug>?utm_*`. `h.shortLinksBase(ctx)` (via `Me`) gives the short host, and `shortlinks.ShortURL(base, key)` builds the URL. `internal/devmocks` emulates ShortLinks (de-dup included) for `dev.sh`.
- **Upcoming events.** `workshops.Store.ListVisible(ctx, now)` returns upcoming published **and canceled** rows, with undated (NULL `starts_at`) rows sorted last. The handler must filter to `Status == published`, `StartsAt != nil`, inside the month window. `LocationName` is already the venue's name (`#0617`).

**2. `internal/outreach/newsletter.go`** (new, pure, no DB):

- Constants: `NewsletterUTMSource = "newsletter"`, `NewsletterUTMMedium = "email"`, `NewsletterPlacement = "newsletter"`.
- `NewsletterDestinationURL(siteBaseURL, workshopSlug, newsletterSlug string) string` returns `<base>/events/<workshopSlug>?` plus the `url.Values` encoding of `utm_source=newsletter`, `utm_medium=email`, `utm_campaign=<workshopSlug>` and `utm_content=<newsletterSlug>`. This mirrors `DestinationURL`'s shape. Use it for both the ShortLink destination and the plain fallback.
- `MonthWindow(month string, now time.Time) (from, to time.Time, label string, err error)`. `month` is `YYYY-MM` (reuse `mailing.ParseNewsletterMonth` if importing `mailing` from `outreach` creates no cycle; otherwise a local `time.ParseInLocation("2006-01", …)`). The window is `[max(now, first-of-month 00:00 America/Los_Angeles), first-of-next-month 00:00 LA)`. `label` is `"November 2026"` style. A malformed month returns an error.
- `type NewsletterItem struct { Title, URL, Venue string; StartsAt time.Time }`.
- `NewsletterEventsMarkdown(label string, items []NewsletterItem) string` produces:

  ```
  ## Upcoming events in November 2026

  - **[Title](URL)**: Saturday, Nov 15 at 1:00 PM · Venue
  ```

  One bullet per item. The date uses LA time (`"Monday, Jan 2 at 3:04 PM"`), and ` · Venue` is omitted when the venue is empty. Escape `\ [ ] * _` in the title. The output ends with a single trailing newline. With zero items it returns `""`.

`POST /admin/campaigns/{id}/upcoming-events` takes the body `{"month":"YYYY-MM"}`.

1. Check the user from context (401) and parse the path id (400). `GetByID` returns 404 for `mailing.ErrCampaignNotFound`, or whatever the sentinel is; check `admin_campaigns.go`'s Get. Answer 409 `"campaign is not editable"` unless the status is `draft` or `scheduled`, matching `canEditCampaign`. Answer 400 for a bad month.
2. `ListVisible(now)`, then filter to published, dated, and `from <= StartsAt < to`.
3. For each event, in order, under `context.WithTimeout(r.Context(), newsletterLinksTimeout)`:
   - If a stored `GetNewsletterLink` row exists, use its `short_url` (`link:"short"`, `reused:true`) with **no ShortLinks call**.
   - Otherwise, `GetByWorkshop` returning `ErrNotFound` means a plain URL with `reason:"no_campaign"`.
   - Otherwise, `!sl.Enabled()` means a plain URL with `reason:"not_configured"`.
   - Otherwise, fetch the short host lazily, once per request, via `sl.Me(ctx)` → `BaseURL`. On error, every remaining event falls back to plain with `linkFailureReason(err)`.
   - `CreateLink(CreateLinkRequest{DestinationURL: NewsletterDestinationURL(h.baseURL, wk.Slug, camp.Slug), Title: wk.Title + " — Newsletter", CampaignSlug: o.CampaignSlug, UTMSource: "newsletter", UTMMedium: "email", UTMCampaign: wk.Slug, UTMContent: camp.Slug, Placement: "newsletter"})`, with **no Key**, for the same reason as `postLinkRequest`. Then `InsertNewsletterLink(..., o.CampaignSlug, link.Key, shortlinks.ShortURL(base, link.Key))`, and audit when `created`.
   - On a `CreateLink` error, that event falls back plain with its reason, logged with `slog` (never return upstream text). A `rate_limited` reason or an expired context stops the pass: all remaining events fall back with that reason. A store error returns 500.
4. Respond 200:

```json
{ "month": "2026-11", "label": "November 2026", "markdown": "…",
  "events": [ { "workshop_id": 1, "title": "…", "url": "…", "link": "short"|"plain", "reused": true, "reason": "" } ],
  "created": 0, "reused": 0, "fallback": 0 }
```

`events` is never null. With no events, `markdown` is `""`.

## Questions for the user

Each has a recommended answer that the plan already implements. Answer only to change one.

1. **Which events count as "for the month"?** Recommended: the newsletter's own month (taken from its archive URL when it was created as a Monthly newsletter, otherwise the current month), adjustable with a month field beside the button, and only events that have not started yet. Alternative: always the next 30 days.
2. **One newsletter link per event per newsletter, or one per event shared by every newsletter?** Recommended: per newsletter (`utm_content` = the newsletter's slug), so ShortLinks shows which issue drove the clicks. Re-clicking within the same newsletter reuses its links.
3. **An event with no Outreach campaign yet:** fall back to the plain event URL with the newsletter UTM values and say so, or start a ShortLinks campaign for it? Recommended: the plain URL with a note. Starting Outreach as a side effect of writing a newsletter would surprise you.
4. **UTM values.** Recommended: `utm_source=newsletter`, `utm_medium=email`, `utm_campaign=<event slug>` (as Outreach already uses) and `utm_content=<newsletter slug>`.
5. **The block's shape.** Recommended: a `## Upcoming events in <Month Year>` heading, then one bullet per event: **linked title**, then date and time, then venue. Canceled and undated events are left out.
