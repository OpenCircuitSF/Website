## Acceptance criteria (from the review, §6 B)

- The Bluesky template contains no `LinkToken`; `ValidateForSend` and the
  Prepare/Draft-all paths accept a Bluesky body without a link because the
  card carries it (`job.ShortURL` is still required at send time).
- A new setting `bluesky_card_url` ∈ {`short`, `canonical`} selects whether
  the external card's `uri` is the tracked short link or the workshop's
  canonical URL with UTM; default documented with the trade-off (tracking vs
  `opencircuitsf.com` in the card footer).
- Facet display text is never different from its `uri`.
- Publisher tests cover both settings; no network.

## Resolution

Bluesky text carries no `LinkToken` (done in #0570); `ValidateForSend` and the draft paths already accept a link-free Bluesky body, and `job.ShortURL` is still required at send time. New server setting `bluesky_card_url` (`short` default, or `canonical`) in a new Outreach group of `internal/serversettings`, edited from admin Settings. The publisher reads it per send: `canonical` points the card at `DestinationURL(BASE_URL, slug, channel, wave)` (the workshop page with UTM), `short` at the tracked link. Trade-off (shown in the Settings help): short keeps ShortLinks click tracking but the card footer reads go.opencircuitsf.com; canonical shows opencircuitsf.com but clicks are untracked. Default kept as `short`. Facet text equals its uri by construction (`DetectFacets` slices the text), nothing rewrites display text. Migration `000040` widens the `server_setting_values` key CHECK; it also adds `outreach_hashtags` and `outreach_post_hour` for #0573 and #0574 so one migration covers the group. `scripts/testdb.sh template` re-run; AGENTS.md section 1 and docs/database.md bumped to `000040`.
