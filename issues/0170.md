# 0170 — The "New workshop" modal tells the admin the slug is set later; the editor tells them it never is

## Description

`web/src/views/admin/Workshops.svelte:241`, the hint under the "New workshop" modal, reads:

> The slug and every other field are set from the full editor after the workshop is created.

That is false twice over:

1. **The slug is generated at creation**, from the title typed in that very modal — not later, and not in the editor.
2. **It is never settable from the editor.** `WorkshopEditor.svelte`'s own hint says the opposite: "Auto-generated from the title and set once at creation — the server does not accept edits to it through this screen."

So the admin console contradicts itself across two screens, one of which is the screen that just created the slug.

`#0137` decided slugs stay server-generated and immutable, and corrected every comment and hint it found — but this copy lives in a component neither of that issue's commits touched, so `#0137`'s "the UI already matches the decision" is incomplete.

## Acceptance criteria

- [ ] The modal hint describes what actually happens: the slug is generated from the title at creation and cannot be changed afterward
- [ ] The wording is consistent with `WorkshopEditor.svelte`'s hint — an admin reading both screens should not have to reconcile them
- [ ] Check the rest of the modal's copy against current behavior while in there; this one was found by reading every `slug` mention in `web/src`, not by a targeted grep
