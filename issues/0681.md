## Description

`#0675`/`#0679`'s planner compared the live vhost with `deploy/apache/installed-001-www.opencircuitsf.com-le-ssl.conf`. It only read the live config and changed nothing. The two differ:

- **Port.** The live config proxies to `${PORT_OPENCIRCUIT}`, where the repo copy has a literal 8080.
- **Logging.** The live config uses different log paths for each site, with a `vhostlog` format.
- **A comment.** One comment in the live config cites CLAUDE.md, where the repo copy cites AGENTS.md.

Re-capture the live file into the repo. Redact host identifiers as AGENTS.md §7 requires, then record which side is authoritative. The `/.well-known/` exception must stay, and so must the atproto-did hash check.

## Plan

Planning was folded into the implementation pass because the work is mechanical (per "keep moving").

1. Read the live file over `ssh photon` without changing anything. Diff it against the repo copy.
2. Overwrite the repo copy with the live bytes. Change only the stale `CLAUDE.md` comment citations to `AGENTS.md`. Grep the result for identifiers that AGENTS.md §7 says must be redacted.
3. Find where `${PORT_OPENCIRCUIT}` and `vhostlog` are defined on the box. Document both in `deploy/apache/README.md`, and update every doc that describes the old shape.
4. Run `curl` to confirm that `/.well-known/` still serves the atproto-did hash.
5. Verify with a scoped check of `internal/db` and `internal/handlers`. The `internal/db` redaction guard scans every tracked file. No Go test or guard script reads `deploy/apache/installed-*`: grepping `internal/`, `cmd/` and `scripts/` only finds comments that cite the reference `opencircuitsf.com.conf`, and that file is unchanged. So `guards` is not needed.

## Fix

**The live box is authoritative, and the repo copy follows it.** The re-captured file is byte-identical to the live `/etc/httpd/conf.d/001-www.opencircuitsf.com-le-ssl.conf`, apart from two comment lines (5 and 151). The repo copy cites `AGENTS.md` §7/§8 on those lines. The live file still cites `CLAUDE.md`.

Here is the drift that was found. A diff confirms that nothing else differs:

- **Port.** The proxy lines now use `http://127.0.0.1:${PORT_OPENCIRCUIT}/…`, which covers 4 lines for `/api/events` and `/`. `PORT_OPENCIRCUIT` is an Apache `Define` with the value `8080` in `/etc/httpd/conf.d/000-ports.conf`. That file is generated from the box's own port registry, says it must not be edited by hand, and sorts ahead of the `001-…` vhosts.
- **Logging.** `ErrorLog "logs/sites/www.opencircuitsf.com/error_log"` and `CustomLog "logs/sites/www.opencircuitsf.com/access_log" vhostlog`, replacing `logs/opencircuitsf_{error,access}_log` and `combined`. They now sit after the SSL lines rather than before them. `vhostlog` is a `LogFormat` in `/etc/httpd/conf/httpd.conf`: combined with `%V:%p` prefixed. It is named that way so that certbot's `vhost_combined` redefinition cannot shadow it. `/etc/httpd/logs` points to `/var/log/httpd`, and both log files exist there.
- **Comments.** Handled as described above.

**Redactions: none were needed.** The live file contains no AWS account id, hostname, public IP, instance id, zone id or IAM role. The only addresses in it are `127.0.0.1`. The Bluesky DID was already in the repo copy, and it is public by design. The box-wide files that were read (`000-ports.conf`, `httpd.conf`, the `conf.d` listing) name other services and domains hosted on the box. None of those were copied into the repo. The docs name only the two files and the `PORT_OPENCIRCUIT` value.

**`/.well-known/` handling is identical** on both sides: the `ProxyPass /.well-known/ !` exclusion, the `Alias` and the `<Directory>` block. The `/prototypes` and `/media` exclusions also match.

**The live comment fix needs the user.** The live file still says `CLAUDE.md` on lines 5 and 151. Changing it means editing a file on the server, so this pass did not touch it. Run `sudo sed -i 's/(CLAUDE\.md §7,/(AGENTS.md §7,/; s/# CLAUDE\.md §8 records/# AGENTS.md §8 records/' /etc/httpd/conf.d/001-www.opencircuitsf.com-le-ssl.conf && sudo apachectl configtest`. The change is comment-only, so no reload is needed. After it, the two files are byte-identical.
