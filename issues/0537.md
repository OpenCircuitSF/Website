## Description

`scripts/release.sh` (from `#0514`) builds its release in a disposable git
worktree created at `${TMPDIR:-/tmp}/opencircuit-release-worktree-XXXXXX` with
a scratch dir beside it (`opencircuit-release-XXXXXX`). `#0512`'s reworked
`scripts/deploy.sh` inherited the idiom
(`opencircuit-deploy-worktree-XXXXXX` / `opencircuit-deploy-XXXXXX`, lines
222 and 226).

The operator has directed (2026-09-13) that agent and tooling writes stay
inside the repository: scratch belongs under gitignored `.scratch/`, and paths
outside the project require explicit permission. Both scripts predate or
predate-the-enforcement-of that rule, and they are the tools agents invoke —
so they must comply too. Both scripts do clean up after themselves; the defect
is location, not leakage.

## Acceptance criteria

- [ ] Both scripts create their disposable worktree and scratch directories under `.scratch/` inside the repository (e.g. `.scratch/release-worktree-XXXXXX`), not under `${TMPDIR:-/tmp}`
- [ ] Self-cleaning is preserved exactly: worktree removed after the build, scratch removed on exit, trap-based cleanup still fires on failure paths
- [ ] `.gitignore`'s existing `/.scratch/` rule covers the new paths (verify with `git check-ignore`); `git worktree list` after a run shows only the main checkout
- [ ] `release.sh`'s existing safety gates are unchanged (detached-HEAD refusal, `must be on main` check, checksum stage)
- [ ] `bash -n` and `shellcheck` pass on both scripts; `scripts/deploy_guard_test.sh` still passes with its anchors byte-preserved (adjust the guard only if it pins the old paths, and say so)
- [ ] No behavior change beyond location: same artifact bytes (a dry-run or `release.sh`-equivalent local build is acceptable proof; a real deploy is NOT required and must not be performed)

## Resolution notes

> 🟢 Resolved 2026-09-14 — both scripts build in worktrees and stage scratch
> under gitignored `.scratch/` inside the repo, cleanup is byte-identical to
> the pre-change traps and was proven live on both success and failure paths,

Independently re-verified against every acceptance criterion:

- **Location (AC 1).** `deploy.sh` creates its worktree and scratch at
  `$REPO_ROOT/.scratch/deploy-worktree-XXXXXX` / `.scratch/deploy-XXXXXX`
  (lines 226 and 230); `release.sh` at `.scratch/release-worktree-XXXXXX` /
  `.scratch/release-XXXXXX` (lines 286 and 290), each after a `mkdir -p` for
  the missing parent. No `${TMPDIR:-/tmp}` idiom remains in either script.
- **Self-cleaning preserved exactly (AC 2).** Compared against `dd2e0cd^`:
  both `cleanup()` traps and their EXIT wiring are unchanged except for the
  path expressions — `release.sh`'s NOTES_FILE removal was already in its
  trap before this commit, and SCRATCH_DIR is still deliberately left for
  inspection on failure/dry-run in both scripts. Failure path proven live:
  ran `deploy.sh --dry-run` with a stub `npm` exiting 1 — the script died at
  the SPA build *after* worktree creation and the EXIT trap removed the
  worktree (zero `.scratch/deploy-worktree-*` residue; `git worktree list`
  showed only the main checkout).
- **gitignore coverage (AC 3).** `.gitignore:50` holds `/.scratch/`;
  `git check-ignore -v` matches all five new path shapes
  (deploy/release × worktree/scratch, plus release-notes). Worktree list
  verified clean after both live runs.
- **Safety gates unchanged (AC 4).** `dd2e0cd`'s diff touches only the two
  build blocks and the notes-file path; `release.sh`'s gates 1–7 (detached
  HEAD, must-be-on-main, ancestor-of-origin/main, tag-free, checksum stage)
  are byte-untouched.
- **Syntax and the #0424 harness (AC 5).** `bash -n` and `shellcheck` clean
  on both scripts. `bash scripts/deploy_guard_test.sh` — all six checks pass;
  no anchor adjustment was needed because the harness extracts the
  GATE-0424 marker pair, the single `die(){`/`info(){` definitions, and the
  dirty-tree notice, none of which this commit touched, and it pins no
  worktree paths of its own subject.
- **No behavior change beyond location (AC 6).** Ran a real
  `./scripts/deploy.sh --dry-run` post-change: real vite build (227
  modules), real ARM aarch64 cross-compile with the commit hash embedded
  (grep 5× in the binary, matching the count release.sh's review measured),
  bundle top level exactly `opencircuit`, `migrations/`, `opencircuit.service`,
  TMPDIR gained zero `opencircuit-*` entries across the whole session, and
  the shared checkout's `web/dist/` stayed clean.

**NOTES_FILE move — judged within the issue's intent.** The report also moved
`release.sh`'s release-notes tempfile from
`${TMPDIR:-/tmp}/opencircuit-release-notes-XXXXXX` to
`.scratch/release-notes-XXXXXX`. That file was release.sh's third TMPDIR
write in the same idiom the issue exists to eliminate; leaving it outside the
repo would contradict the operator directive this issue implements, and its
cleanup was already handled by the unchanged trap. Approved as part of the
issue, not scope creep.
