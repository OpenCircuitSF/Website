## Description

`internal/config`'s `.env.example` guard carries a floor constant,
`minLoaderVariables`, asserting the AST walk still sees at least N variable
reads in `config.go`. Its purpose is sound and `CLAUDE.md` §8 states it: assert
the extraction produced something before trusting it, so a walk that silently
stops seeing reads fails loudly instead of passing on an empty result.

**A floor only catches shrinks.** Growth passes it unnoticed — correctly, by
design. But the doc comment beside it asserted **"exactly 20 variables today"**,
which is an *exact-count* claim a floor cannot maintain.

It went stale immediately and stayed stale. `#0433` added `MEDIA_DIR`, taking
the real count to 21, and the floor and its prose both stayed at 20. Nothing
complained, because nothing could: 21 ≥ 20.

`#0402` found it. Its plan, reasoning from the prose, said the floor was 20 and
should become 21. Its implementer re-derived the count from the AST walk
instead of trusting that, found 21 **before** its own change, and set the floor
to **22**. `#0402`'s review then re-derived it independently: parent 21, HEAD
22. Three derivations, two of them prompted only because someone distrusted the
comment.

## Why the prose is the defect, not the floor

The floor did its job. It is the **claim next to it** that misled a planning
pass into prescribing a wrong number — and would have shipped one, had the
implementer not re-derived.

This is the same shape this project keeps meeting: a comment that was true when
written, drifting silently because nothing checks prose. `#0472` found it in
`CLAUDE.md`'s SES bullet, `#0475` found the slug rationale false in three
places, and `#0478` found notes never scanned. What is distinctive here is that
the false claim sat **directly beside a guard**, which lends it borrowed
authority.

## Acceptance criteria

1. **Decide between the two honest options**, and say why:
   - **Drop the count from the prose.** Describe the floor as a floor — "at
     least this many" — and let the constant be the only number. Cheapest, and
     nothing can drift.
   - **Pin the count exactly.** Assert equality rather than `<`, so adding a
     variable fails until the number is updated deliberately. Stronger, but it
     turns every added variable into a required edit here — say whether that is
     wanted before choosing it.

   Do **not** keep an exact-count sentence beside an inequality check.

2. **Preserve the floor's stated purpose.** `CLAUDE.md` §8's rule — an empty or
   shrunken extraction must be an error, never an input — must still hold, and
   the existing instruction to lower the constant only for a deliberate,
   reviewed removal must survive whatever you choose.

3. **Verify the current count yourself** rather than trusting this issue. Three
   derivations agree it is 22 at `e4a29b6`, but a fourth is cheap and this
   lineage has had six false premises corrected by measurement.

4. **Prove the guard still fails when it should.** Removing a variable read from
   the loader must trip it. A guard never seen to fail is not a guard
   (`CLAUDE.md` §8); mutate a copy rather than the tree where practical.

5. **Check whether sibling guards carry the same shape** — an exact-count claim
   in prose beside an inequality assertion. If any do, name them here; do not
   fix them in this pass unless trivial.
