## Description

`docs/deployment.md`'s Production-facts table says the instance has **"None
attached"** for its IAM role, and calls that *"the reason SES cannot work yet."*
Its `## IAM` section says the role has **"never been created or attached to a
real role."**

**The role is attached.** Instance metadata returns `opencircuit-instance` —
confirmed independently by the orchestrator against the live box, read-only.
`CLAUDE.md` §10 item 2 already records it as attached "and **proven by a real
delivered send**."

`docs/aws-iam-setup.md`'s "Current instance role: none" is stale the same way.

### Why this one is worse than ordinary drift

The doc does not merely record a stale fact — it **draws a conclusion from it**:
that SES cannot work. A reader troubleshooting a send would chase a missing role
that is present, and might create or attach a second one.

**And `#0421` has just pointed readers at that table.** Its correction block
directs a reader to the Production-facts table as the current-state record, so
the stale row is now more prominent than it was.

### A second wrong fact in the same section

The IAM policy in `docs/deployment.md` names
`arn:aws:ses:us-west-2:…:identity/opencircuitsf.com`. Both halves are wrong: the
region is `us-east-1`, and the real identity is **`mailing.opencircuitsf.com`**.

`CLAUDE.md` §10 item 2 records a trap that makes this consequential: in the SES
sandbox, `SendEmail` is authorised against the **recipient's** identity ARN too,
so the policy needs `identity/*` rather than a single identity — and a test send
to a simulator address will **not** catch a policy that gets this wrong, because
simulator addresses are not identities.

## Acceptance criteria

1. The Production-facts row and the `## IAM` section state the role that is
   actually attached, and no longer assert that a missing role blocks SES.
   **Re-derive the attachment from the box yourself**, read-only — do not copy
   `opencircuit-instance` from this issue.
2. `docs/aws-iam-setup.md`'s "Current instance role" is corrected the same way.
3. The policy ARN's region and identity are corrected, and the `identity/*`
   requirement from `CLAUDE.md` §10 item 2 is stated with the reason — including
   that a simulator-address test does not exercise it.
4. **Read the actual attached policy if you can.** If the live policy differs
   from what the doc shows, the doc should describe reality, not the plan. Note
   the box's default identity is denied most IAM reads — say what you could and
   could not read, and **do not create or hunt credentials**.
5. Follow `#0072`'s dated-note convention for maintained references and leave
   genuine decision-log history intact per `#0271`'s `## Scope`. Say which
   occurrences you judged to be which.
6. **Change nothing in AWS or on the box.** This is documentation.
7. **No mechanism** (`#0330`/`#0347`/`#0356`/`#0381`).
8. Editing `PRD.md` means `./internal/db/...` with §11's line counts exact,
   verified by each row's own `sed` (`#0113`). Run `./internal/handlers/...` for
   cited paths. Per §5 name the specific tests that ran. No
   Go-file-plus-line-number citation (`#0352`), scanned with `python3` bytes
   rather than BSD `grep -P`.
