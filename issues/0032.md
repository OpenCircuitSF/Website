## Description

Where the operator sees the list: search, filter by status and interest, inspect one subscriber's consent evidence and event history, and manually suppress.

## Acceptance criteria

- [ ] `GET /admin/subscribers` paginated, filterable by status and interest, searchable by email
- [ ] `GET /admin/subscribers/{id}` detail with consent evidence (signup IP, user agent, both timestamps), interests, and email event history
- [ ] `POST /admin/subscribers/{id}/suppress` with a required note
- [ ] Counts by status shown at the top: pending, active, unsubscribed, bounced, complained
- [ ] Manual add flow that still requires confirmation — no bypassing double opt-in
- [ ] Audit rows for every admin mutation
- [ ] Go handler tests and `npm run check` / `npm test` pass

## Carried in from `#0025`'s review (2026-08-19)

- [ ] **Use `Store.AdminClearComplaint(ctx, id, now)`** to clear a complaint —
      it is the only sanctioned exit from `complained` (`CLAUDE.md` §9). It
      returns `ErrNotComplained` if the row is not complained, so offer the
      action only on complained rows.
- [ ] **`Unsubscribe` on a complained row succeeds and changes nothing.** The
      screen must inspect the returned `Status` rather than assume success, or an
      admin will think an action took effect when it did not.
- [ ] **Once `#0033` lands, clearing a complaint must also clear the
      `suppressions` row** — otherwise the address stays blocked at `#0026`'s
      "suppressed → 202, send nothing" gate and the admin action has no practical
      effect.
- [ ] **`AdminClearComplaint` overwrites `unsubscribed_at`/`unsubscribe_source`**
      with `admin`/now, discarding earlier genuine unsubscribe evidence. Low
      severity — the §6.3 consent columns are untouched — but worth surfacing.
- [ ] **Revisit the deferred `BEFORE UPDATE` trigger.** `#0025` centralised the
      `complained` guard in Go and deferred a database-level transition rule. The
      debt is recorded only in `#0025`'s Gotchas; this issue is where it should be
      reconsidered, since it owns the admin path the trigger would need an escape
      hatch for.

## Notes
