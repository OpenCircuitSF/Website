## Description

Where the operator sees the list: search, filter by status and interest, inspect one subscriber's consent evidence and event history, and manually suppress.

## Acceptance criteria

- [ ] `GET /admin/subscribers` paginated, filterable by status and interest, searchable by email
- [ ] `GET /admin/subscribers/{id}` detail with consent evidence (signup IP, user agent, both timestamps), interests, and email event history
- [ ] `POST /admin/subscribers/{id}/suppress` with a required note
- [ ] Counts by status shown at the top: pending, active, unsubscribed, bounced, complained
- [ ] Manual add flow that still requires confirmation — no bypassing double opt-in
- [ ] Audit rows for every admin mutation
- [ ] Go handler tests and `npm run check` / `npm test` pass

## Notes

PRD §5.2, §8. No admin path may create an `active` subscriber directly. If an operator can skip confirmation, the consent evidence stops meaning anything and the list stops being defensible.

The event history panel is empty until #0038 lands; build the section now and let it fill in.
