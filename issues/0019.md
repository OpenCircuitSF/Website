# 0019 — Inject per-route meta tags server-side

## Description

Rewrite `<title>`, description, and Open Graph / Twitter Card tags into `index.html` per route before serving it. Social crawlers do not run JavaScript, so without this every shared link previews identically and badly.

## Acceptance criteria

- [ ] `internal/seo` holds the built `index.html` in memory with placeholder markers for `title`, `description`, `og:title`, `og:description`, `og:image`, `og:url`, `og:type`, `twitter:card`
- [ ] A compiled-in route table supplies metadata for `/`, `/about`, `/workshops`, `/subscribe`
- [ ] `/workshops/{slug}` looks the workshop up and uses its title, summary, and cover image (wired in #0054)
- [ ] Every substituted value is HTML-escaped
- [ ] Rendered `index.html` is cached per path with a short TTL and invalidated on workshop mutation
- [ ] Unknown paths get the default metadata and **preserve `SPAHandler`'s
      HTTP 404** (the SPA renders its own 404 view) — **amended at review of
      `#0022`, 2026-08-18.** This criterion originally said "and a 200". That
      was written before `#0022` shipped, and it is now wrong: `#0022`
      deliberately replaced the naive SPA catch-all so an unknown path returns
      404 while still serving the shell, precisely so a typo'd URL is not an
      indexable soft-404. Implementing the original wording would silently
      regress `#0022` and break
      `TestSPAUnknownPathReturns404WithShell`. Inject metadata; do not touch
      the status code
- [ ] Verified with `curl -A 'facebookexternalhit/1.1'` against at least three routes, asserting distinct titles and OG tags in the raw HTML
- [ ] `go test ./internal/seo/...` covers escaping, route matching, and cache invalidation

## Carried in from `#0022`'s review (2026-08-18)

Two obligations transferred here rather than left half-met on `#0022`. Both are
binding acceptance criteria for this issue.

- [ ] **Give the 404 route a real default `<title>` and meta set.** `#0022`'s
      fifth criterion ("default metadata applied by `#0019`") could not be
      discharged there — no injector existed. Today every route, the 404
      included, receives the same static `<title>Open Circuit SF</title>`. The
      404 route needs its own default: a distinct title, a default description,
      and — since a 404 should not be shared as a preview — no expectation of a
      meaningful OG card beyond the default image from `#0021`.
- [ ] **Do not regress `#0022`'s 404 status.** Covered by the amended criterion
      above; called out separately because it is the failure mode that would be
      easiest to introduce accidentally while making the injector own the
      response body. Add a test asserting an unknown path comes back **404
      with injected default metadata**, so the two properties are guarded
      together rather than separately.

**Read before you start — the route table is not what it claims to be.**
`internal/handlers/routes.go`'s doc comment invites this issue to reuse
`knownStaticRoutes` "so the two stay in sync by construction rather than by
convention". Reusing the Go table is still the right move and you should do it.
But the comment's claim about `web/src/lib/router.ts` is false: the Go and
TypeScript route tables are two hand-maintained lists and **nothing** — not
`npm run check`, not `npm test`, not `go test ./...` — fails when they diverge.
The reviewer proved this in both directions. `#0071` owns closing that gap; if
it has not landed by the time you start, treat every route you add or read as
needing a matching edit on the other side, and check `router.ts` by hand.

## Notes

PRD §3.4, §7.4. **This is the single most important technical detail in Phase 2** — the site's entire purpose is receiving traffic from social posts, and a generic preview card measurably suppresses click-through.

Test with a real crawler user-agent, not a browser. Discord, Slack, iMessage, X, Facebook, and LinkedIn all fetch the raw HTML and never execute the SPA bundle.

Escaping is a genuine injection surface once workshop titles flow into `<meta content="…">`. Escape, do not sanitize-and-hope.
