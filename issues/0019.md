# 0019 — Inject per-route meta tags server-side

## Description

Rewrite `<title>`, description, and Open Graph / Twitter Card tags into `index.html` per route before serving it. Social crawlers do not run JavaScript, so without this every shared link previews identically and badly.

## Acceptance criteria

- [ ] `internal/seo` holds the built `index.html` in memory with placeholder markers for `title`, `description`, `og:title`, `og:description`, `og:image`, `og:url`, `og:type`, `twitter:card`
- [ ] A compiled-in route table supplies metadata for `/`, `/about`, `/workshops`, `/subscribe`
- [ ] `/workshops/{slug}` looks the workshop up and uses its title, summary, and cover image (wired in #0054)
- [ ] Every substituted value is HTML-escaped
- [ ] Rendered `index.html` is cached per path with a short TTL and invalidated on workshop mutation
- [ ] Unknown paths get the default metadata and a 200 (the SPA renders its own 404 view)
- [ ] Verified with `curl -A 'facebookexternalhit/1.1'` against at least three routes, asserting distinct titles and OG tags in the raw HTML
- [ ] `go test ./internal/seo/...` covers escaping, route matching, and cache invalidation

## Notes

PRD §3.4, §7.4. **This is the single most important technical detail in Phase 2** — the site's entire purpose is receiving traffic from social posts, and a generic preview card measurably suppresses click-through.

Test with a real crawler user-agent, not a browser. Discord, Slack, iMessage, X, Facebook, and LinkedIn all fetch the raw HTML and never execute the SPA bundle.

Escaping is a genuine injection surface once workshop titles flow into `<meta content="…">`. Escape, do not sanitize-and-hope.
