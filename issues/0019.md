## Description

Rewrite `<title>`, description, and Open Graph / Twitter Card tags into `index.html` per route before serving it. Social crawlers do not run JavaScript, so without this every shared link previews identically and badly.

## Root cause

Not a bug fix — new capability. Before this issue, `web/dist/index.html` shipped one static `<title>Open Circuit SF</title>` and no `<meta name="description">` or Open Graph/Twitter tags at all, so every shared URL (home, about, a workshop, a 404) produced the identical, generic (or blank) social preview card.

## Fix

`web/index.html` now carries `%%OC_*%%` placeholder markers for title, description, og:title, og:description, og:image, og:url, og:type, twitter:card. `internal/seo.Renderer` (`internal/seo/seo.go`) loads the built `index.html` (via `web.DistFS()`) into memory once at startup and substitutes a per-route `RouteMeta` into those markers on each request, in this priority order: (1) an exact entry in the compiled-in static table for `/`, `/about`, `/workshops`, `/subscribe`; (2) `/workshops/{slug}` resolved against a `WorkshopSource` (interface only for now — nil until #0051/#0054 land, so it degrades to the generic fallback rather than erroring); (3) the generic fallback for every other known route (the Phase 1 auth/account views, which are never meant to be shared); (4) a distinct not-found default for anything `handlers.IsKnownRoute` rejects.

`internal/seo.Site.Middleware` (`internal/seo/site.go`) wraps `handlers.NewSPAHandler`: it buffers the SPA handler's response in a small hand-rolled recorder and, only when the response was `text/html`, replaces the body with `Renderer.Render`'s output **at the same status code the SPA handler already chose**. It never recomputes 200-vs-404 itself — that keeps preserving `#0022`'s 404 behavior structural rather than something the two packages have to agree on by convention. Non-HTML responses (hashed JS/CSS, favicons, missing-asset 404s) pass through completely untouched; `Renderer.Render` isn't even called for those.

Every substituted value goes through `html.EscapeString` before substitution (`Renderer.substitute`). `internal/handlers/routes.go` gained three exported wrapper functions (`IsKnownRoute`, `StaticRoutes`, `WorkshopDetailSlug`) around its existing unexported route table — added as thin delegates rather than renaming the unexported originals, so the already-tested call sites in `routes_test.go`/`static.go` stayed untouched. `cmd/opencircuit/main.go`'s `mountAndServe` constructs one `seo.Site` and wraps it around the `GET /` SPA handler.

## Gotchas

- **Route-table parity, checked by hand as instructed:** compared `internal/handlers/routes.go`'s `knownStaticRoutes` against `web/src/lib/router.ts`'s `STATIC_ROUTES` programmatically at the end of this batch — both currently list the exact same 13 static paths, and the dynamic pattern (`^/workshops/[^/]+$` vs. `/^\/workshops\/([^/]+)$/`) is equivalent. They agree **today**, but nothing enforces it (per this issue's own warning) — `#0071` is still open and owns making this structural.
- Import-cycle avoidance: `internal/seo` imports `internal/handlers` (for the route table), so `internal/handlers` must never import `internal/seo` back. `site_test.go` deliberately hand-rolls a `fakeSPAHandler` test double instead of importing `handlers.NewSPAHandler`, to avoid tempting that direction even in tests.
- `web/dist/index.html` is a committed placeholder (`.gitignore` un-ignores just that one file so `go build ./...` compiles from a clean checkout). I ran `npm run build` locally to produce the real, marker-carrying version for live verification, then left it as the real built artifact rather than restoring the stale placeholder — the working tree already had a real build from a concurrent subagent's work when I started. I did not stage or commit `web/dist/index.html` in this issue's commit; it's a generated artifact.
- The `WorkshopSource` interface returns *every* workshop regardless of status (not pre-filtered), so the draft/canceled exclusion logic lives in `internal/seo` itself and is covered by `go test ./internal/seo/...` rather than trusted to whatever `#0051`'s eventual SQL `WHERE` clause does.

## Carried in from `#0022`'s review (2026-08-18)

Two obligations transferred here rather than left half-met on `#0022`. Both are
binding acceptance criteria for this issue.

- [x] **Give the 404 route a real default `<title>` and meta set.** `#0022`'s
      fifth criterion ("default metadata applied by `#0019`") could not be
      discharged there — no injector existed. Today every route, the 404
      included, receives the same static `<title>Open Circuit SF</title>`. The
      404 route needs its own default: a distinct title, a default description,
      and — since a 404 should not be shared as a preview — no expectation of a
      meaningful OG card beyond the default image from `#0021`.
- [x] **Do not regress `#0022`'s 404 status.** Covered by the amended criterion
      above; called out separately because it is the failure mode that would be
      easiest to introduce accidentally while making the injector own the
      response body. Add a test asserting an unknown path comes back **404
      with injected default metadata**, so the two properties are guarded
      together rather than separately.

**Read before you start — the route table is not what it claims to be.**
`internal/handlers/routes.go`'s doc comment invites this issue to reuse
`knownStaticRoutes` "so the two stay in sync by construction rather than by
convention". Reusing the Go table is still the right move and you should do it.
But the comment's claim about `web/src/lib/router.ts` is false: the Go and
TypeScript route tables are two hand-maintained lists and **nothing** — not
`npm run check`, not `npm test`, not `go test ./...` — fails when they diverge.
The reviewer proved this in both directions. `#0071` owns closing that gap; if
it has not landed by the time you start, treat every route you add or read as
needing a matching edit on the other side, and check `router.ts` by hand.

## Notes

PRD §3.4, §7.4. **This is the single most important technical detail in Phase 2** — the site's entire purpose is receiving traffic from social posts, and a generic preview card measurably suppresses click-through.

## Review findings (2026-08-18) — approved, with two follow-ups to file

Neither finding blocks this issue: every acceptance criterion is met and the
crawler-facing bytes are correct. Both are consequences of shipping the
injector and should become their own issues.

1. **`.env.example` sets the apex, not the canonical www host.**
   `BASE_URL=https://opencircuitsf.com` (line 3) is now the source of every
   `og:url`, `og:image`, sitemap `<loc>`, and the `robots.txt` `Sitemap:`
   line. `deploy/systemd/README.md` states that
   `/etc/opencircuit/config.env` "supplies every variable from
   `.env.example`", so the documented deploy path would publish **apex**
   social/canonical URLs while production 301s the apex to `www`
   (`CLAUDE.md` §7). The same file already gets
   `WEBAUTHN_RP_ORIGIN=https://www.opencircuitsf.com` right, so this is an
   internal inconsistency. `internal/seo` itself is correct — it uses
   `cfg.BaseURL` and produced the exact www form when run with the canonical
   value. Fix is one line in `.env.example` (and a note in `DEPLOYMENT.md`).

2. **`Renderer.cache` grows without bound on attacker-controlled keys.**
   `Render` caches per normalized request path and entries are only ever
   written — expired entries are never pruned, and `InvalidateWorkshops` (the
   sole clearing path) is not called by anything until `#0051`. Measured on
   the real binary: RSS went from ~59 MB to ~212 MB after 25,000 requests to
   distinct unknown paths (~6 KB retained per distinct path), unauthenticated
   and unthrottled. Every unknown path renders the *identical* not-found body,
   so caching them per path is pure waste; keying the cache by the resolved
   meta bucket (or capping/evicting) fixes both the waste and the growth.

Two smaller notes, no action required: the drafted `## Verification` said "24
new tests" (the package has 14 at `62762df`, 24 after `#0020`; there are no
subtests), and the explanatory HTML comment in `web/index.html` contains the
literal string `%%OC_TITLE%%`, which the injector substitutes too — the
comment reads `If you're seeing a literal "Page Not Found — Open Circuit SF"`
in the served output. Harmless, but the comment no longer says what it
means to say.

**Escaping was probed beyond the one test and held.** A `"` inside an
`og:title` attribute becomes `&#34;`; a `</title>` sequence becomes
`&lt;/title&gt;` and cannot break out (exactly one `<title>`/`</title>` pair
survives); a single quote becomes `&#39;`; non-ASCII (`Résumé — 電子工作 ✨`)
passes through correctly under the document's declared UTF-8; a title
containing `%%OC_OG_URL%%` is **not** re-substituted, because
`strings.NewReplacer` is single-pass — no second-order token injection. Raw
newlines and C0 control bytes pass through unescaped, which is legal inside
both a quoted attribute value and `<title>` and is not an injection, only
untidy. Request-path injection was probed live
(`/workshops/"><img src=x onerror=alert(1)>`, `/<title>PWN</title>`) and never
reaches the output. The one value that is deliberately **not** neutralized is
an already-absolute `http(s)` `Workshop.CoverImage`, which is emitted verbatim
as `og:image`; `javascript:` and protocol-relative `//host` forms are both
correctly rewritten under the canonical origin. Once `#0051` gives admins that
field, an external `og:image` host is worth constraining to same-origin
(`CLAUDE.md` §9).
