## Description

`#0192`'s phase-3 review swept the whole repository for comments citing test
functions, after `#0190` shipped one naming a test that was never written. The
sweep was thorough: a comment-only extractor that strips string literals and
rejoins wrapped names, run against all 878 `Test*` functions, yielding 710
citations.

**Exactly one genuine dangling citation remains.**
`internal/handlers/admin_workshop_preview_test.go:164` cites
`TestRenderWorkshopBodyHTML_LeadingControlCharPercentEncodedNotStripped`'s doc
comment. No such function exists — the file defines only
`TestRenderWorkshopBodyHTML_SafetyPayloads`, and the name appears nowhere in the
tree, not even as a subtest.

**The `%01` payload itself is covered** at lines 203–213, so this is a dangling
pointer rather than an overstatement of coverage. But it is the same shape as
`#0190`'s, now in a second package — which is the argument for the second half
of this issue.

**Nothing checks for this.** The shape has now appeared three times
(`#0190`'s, this one, and the one `#0192` fixed), and each was found only
because a reviewer went looking by hand. `#0181` solved the structurally
identical problem for admin-facing strings by writing a guard test; the same
approach applies here, and `#0192`'s review has already written most of the
extractor.

## Implementation notes

**Part 1 (the dangling comment).** `admin_workshop_preview_test.go:170`
(the file had moved two lines since this issue was filed — the actual
citing line, not 164) cited
`TestRenderWorkshopBodyHTML_LeadingControlCharPercentEncodedNotStripped's
doc comment`, which has never existed. The function that actually carries
the "leading U+0001 control char" case and its explanation is
`TestRenderWorkshopBodyHTML_SafetyPayloads`. Repointed the comment at that
function, naming the specific case in parens rather than just the bare
function name, so the pointer stays precise even though the target
function now covers several cases.

**Part 2 (the guard).** New file
`internal/handlers/dangling_test_citation_guard_test.go` (kept separate
from `citation_guard_test.go` — `#0193` was editing that file concurrently
during this issue's implementation). Design, in order of what turned out
to matter:

- **Pattern.** `\bTest[A-Z0-9_][A-Za-z0-9_]*\b` — the leading `\b` is what
  keeps the `*TestPool` naming convention's compound helpers
  (`auditTestPool`, `signupTestPool`, …) out of the candidate set for
  free, with no allowlist: there is no word boundary between the
  lowercase letter before "Test" and "Test" itself. The character class
  right after "Test" (uppercase/digit/underscore, never lowercase)
  borrows `go test`'s own rule for recognizing a test function, and for
  free also excludes the plain English word "Tests" (a section-heading
  comment in `ses_notifications_test.go`, ordinary prose in
  `interests/store_test.go`) — a false-positive class the acceptance
  criteria don't name but a dry run against the real tree turned up.
- **Discount classes** (`citationIsExcluded`): the allowlisted
  `TestSentAt` struct field; a wildcard suffix, either `*` (`#0192`'s two
  instances) or `...` (two more instances this issue's dry run found in
  `audit_test.go`, spelled with an ellipsis instead of an asterisk); the
  `*TestPool` convention's own bare name, wrapped in asterisks as
  markdown-style emphasis; and a citation preceded within 20 characters
  by "renamed from" (case-insensitive), which reads correctly across the
  line break in `templates_test.go`'s actual instance because the lookback
  window is built from the group's multi-line joined text.
- **Subtests — the deliberate decision.** Not specially handled, and none
  needed: a citation of `Parent/subtest_name` matches the pattern on
  `Parent` alone, since `/` is not an identifier character. A bare
  dangling subtest reference (not slash-qualified) would not be caught —
  documented in the guard's own doc comment as an accepted gap, since no
  such instance exists in the tree today (checked as part of writing this
  guard).
- **Line-wrapped identifiers.** The acceptance criteria and `#0192`'s own
  notes call for reassembling a name "wrapped across lines". A first
  attempt (only reassemble when the first line ends in `_`) correctly
  reconstructed two of three real instances found in the tree
  (`cmd/opencircuit/main.go`, `admin_campaign_preview_test.go`) but missed
  a third (`internal/seo/seo_test.go`, wrapped mid-camel-word with no
  underscore at the seam) and, worse, produced spurious merges on ordinary
  doc comments that happen to wrap right after a complete function name
  (`"…NotARealSubscriber\nis the recipient…"` reading as one bogus word).
  Replaced with a design that asks the only question that actually
  distinguishes the two shapes: does the zero-separator join of adjacent
  lines produce a name the tree **defines**? If yes, that's the real
  citation, and the truncated single-line fragment the primary pass would
  otherwise also report is suppressed. If no, the join is discarded and
  each line is read independently, which is what correctly leaves ordinary
  wrapped doc comments alone. This required threading `defined` (from
  `collectDefinedTestFuncs`) into `collectTestCitations`, run before it.
- **Self-reference.** Unlike `#0181`'s guard, this one must scan
  `_test.go` files, including its own — so a `Test<Name>`-shaped token in
  this file's own comments becomes a citation the guard must resolve
  against itself. No fictitious name appears in a real comment anywhere in
  this file; the fictitious names used to prove the guard fires live in Go
  string data inside test bodies
  (`TestDanglingTestCitationPatternCatchesSyntheticExample`), which this
  file's own parser never visits as a comment. Verified directly: running
  `TestNoCommentCitesUndefinedTestFunction` (this file's own guard)
  against the whole tree, this file included, passes — see `## Verification`.
- **Failure message.** Repo-relative `path/file.go:LINE: Identifier`, one
  per line, matching `#0187`'s fix to the other guard's message format
  rather than the absolute-path form `#0181`'s guard still uses.
- **Walk roots.** Same three roots as `#0181`'s `scanGoRoots`
  (`internal/`, `cmd/`, `web/`), declared separately rather than shared
  (avoids touching `citation_guard_test.go` while `#0193` was mid-edit on
  it), with `node_modules` and `dist` pruned via `filepath.SkipDir` from
  the start — the `#0194` lesson, applied before it could recur here.

## Notes

Reported by `#0192`'s phase-3 review under `CLAUDE.md` §9.

Read that review's `## Review notes` before writing the extractor — it records
the four false-positive classes it had to discount, which is most of the design.
`#0181`'s citation guard is the model for the mechanics, and `#0187` and `#0194`
carry the lessons about its walk roots and its `_test.go` handling. Note that
this guard must scan `_test.go` files, which `#0181`'s deliberately does not —
so it cannot simply reuse that walk, and it must not cite a test name in its own
error string or it will fail on itself.
