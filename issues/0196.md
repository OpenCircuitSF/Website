## Description

`#0192`'s phase-3 review swept the whole repository for comments citing test
functions, after `#0190` shipped one naming a test that was never written. The
sweep was thorough: a comment-only extractor that strips string literals and
rejoins wrapped names, run against all 878 `Test*` functions, yielding 710
citations.

**Exactly one genuine dangling citation remains.**
`internal/handlers/admin_workshop_preview_test.go:164` cites
`TestRenderWorkshopBodyHTML_LeadingControlCharPercentEncodedNotStripped`'s doc
comment. No such function exists — the file defines only
`TestRenderWorkshopBodyHTML_SafetyPayloads`, and the name appears nowhere in the
tree, not even as a subtest.

**The `%01` payload itself is covered** at lines 203–213, so this is a dangling
pointer rather than an overstatement of coverage. But it is the same shape as
`#0190`'s, now in a second package — which is the argument for the second half
of this issue.

**Nothing checks for this.** The shape has now appeared three times
(`#0190`'s, this one, and the one `#0192` fixed), and each was found only
because a reviewer went looking by hand. `#0181` solved the structurally
identical problem for admin-facing strings by writing a guard test; the same
approach applies here, and `#0192`'s review has already written most of the
extractor.

## Implementation notes

**Part 1 (the dangling comment).** `admin_workshop_preview_test.go:170`
(the file had moved two lines since this issue was filed — the actual
citing line, not 164) cited
`TestRenderWorkshopBodyHTML_LeadingControlCharPercentEncodedNotStripped's
doc comment`, which has never existed. The function that actually carries
the "leading U+0001 control char" case and its explanation is
`TestRenderWorkshopBodyHTML_SafetyPayloads`. Repointed the comment at that
function, naming the specific case in parens rather than just the bare
function name, so the pointer stays precise even though the target
function now covers several cases.

**Part 2 (the guard).** New file
`internal/handlers/dangling_test_citation_guard_test.go` (kept separate
from `citation_guard_test.go` — `#0193` was editing that file concurrently
during this issue's implementation). Design, in order of what turned out
to matter:

- **Pattern.** `\bTest[A-Z0-9_][A-Za-z0-9_]*\b` — the leading `\b` is what
  keeps the `*TestPool` naming convention's compound helpers
  (`auditTestPool`, `signupTestPool`, …) out of the candidate set for
  free, with no allowlist: there is no word boundary between the
  lowercase letter before "Test" and "Test" itself. The character class
  right after "Test" (uppercase/digit/underscore, never lowercase)
  borrows `go test`'s own rule for recognizing a test function, and for
  free also excludes the plain English word "Tests" (a section-heading
  comment in `ses_notifications_test.go`, ordinary prose in
  `interests/store_test.go`) — a false-positive class the acceptance
  criteria don't name but a dry run against the real tree turned up.
- **Discount classes** (`citationIsExcluded`): the allowlisted
  `TestSentAt` struct field; a wildcard suffix, either `*` (`#0192`'s two
  instances) or `...` (two more instances this issue's dry run found in
  `audit_test.go`, spelled with an ellipsis instead of an asterisk); the
  `*TestPool` convention's own bare name, wrapped in asterisks as
  markdown-style emphasis; and a citation preceded within 20 characters
  by "renamed from" (case-insensitive), which reads correctly across the
  line break in `templates_test.go`'s actual instance because the lookback
  window is built from the group's multi-line joined text.
- **Subtests — the deliberate decision.** Not specially handled, and none
  needed: a citation of `Parent/subtest_name` matches the pattern on
  `Parent` alone, since `/` is not an identifier character. A bare
  dangling subtest reference (not slash-qualified) would not be caught —
  documented in the guard's own doc comment as an accepted gap, since no
  such instance exists in the tree today (checked as part of writing this
  guard).
- **Line-wrapped identifiers.** The acceptance criteria and `#0192`'s own
  notes call for reassembling a name "wrapped across lines". A first
  attempt (only reassemble when the first line ends in `_`) correctly
  reconstructed two of three real instances found in the tree
  (`cmd/opencircuit/main.go`, `admin_campaign_preview_test.go`) but missed
  a third (`internal/seo/seo_test.go`, wrapped mid-camel-word with no
  underscore at the seam) and, worse, produced spurious merges on ordinary
  doc comments that happen to wrap right after a complete function name
  (`"…NotARealSubscriber\nis the recipient…"` reading as one bogus word).
  Replaced with a design that asks the only question that actually
  distinguishes the two shapes: does the zero-separator join of adjacent
  lines produce a name the tree **defines**? If yes, that's the real
  citation, and the truncated single-line fragment the primary pass would
  otherwise also report is suppressed. If no, the join is discarded and
  each line is read independently, which is what correctly leaves ordinary
  wrapped doc comments alone. This required threading `defined` (from
  `collectDefinedTestFuncs`) into `collectTestCitations`, run before it.
- **Self-reference.** Unlike `#0181`'s guard, this one must scan
  `_test.go` files, including its own — so a `Test<Name>`-shaped token in
  this file's own comments becomes a citation the guard must resolve
  against itself. No fictitious name appears in a real comment anywhere in
  this file; the fictitious names used to prove the guard fires live in Go
  string data inside test bodies
  (`TestDanglingTestCitationPatternCatchesSyntheticExample`), which this
  file's own parser never visits as a comment. Verified directly: running
  `TestNoCommentCitesUndefinedTestFunction` (this file's own guard)
  against the whole tree, this file included, passes — see `## Verification`.
- **Failure message.** Repo-relative `path/file.go:LINE: Identifier`, one
  per line, matching `#0187`'s fix to the other guard's message format
  rather than the absolute-path form `#0181`'s guard still uses.
- **Walk roots.** Same three roots as `#0181`'s `scanGoRoots`
  (`internal/`, `cmd/`, `web/`), declared separately rather than shared
  (avoids touching `citation_guard_test.go` while `#0193` was mid-edit on
  it), with `node_modules` and `dist` pruned via `filepath.SkipDir` from
  the start — the `#0194` lesson, applied before it could recur here.

### Are the discount rules narrow? Mutation-tested, one at a time

Each rule was deleted in isolation and the guard re-run against the whole tree,
to see exactly what it is buying:

| Rule | Instances it is load-bearing for | Verdict |
|---|---|---|
| trailing `*` (wildcard family) | `ses_notifications_test.go:1631` `TestFetchSubscribeURLReal_`, `seo_test.go:529` `TestRender_` | **narrow** — exactly `#0192`'s two |
| trailing `...` (wildcard family) | `audit_test.go:66,67` `TestUniqueAuthEmail_`, `TestUniqueSessionToken_` | **narrow** — exactly the two this issue's dry run found |
| `renamed from` within 20 chars | `templates_test.go:473` `TestConfirmationAndAlreadySubscribed_NoCampaignHeaders` | **narrow** — see below |
| `TestSentAt` allowlist | a real `*string` struct field declared in `admin_campaigns.go:247` and `mailing/campaigns.go` and described in their comments (also cited in `worker_test.go:837`, a `_test.go` file the notes' "four non-test files" phrasing overlooks) | **narrow** — exact-name, not a shape |
| preceding `*` (emphasis) | `main_test.go:19`, and the guard file's **own** comments at lines 57 and 109 — all three the bare word `TestPool` | **the one that is too broad** |

**`renamed from` discounts only the renamed name, not the comment.** The
window is the 20 bytes immediately before the match and the phrase is 12 of
them, so at most 8 characters of separator fit. Proved both directions:

- plant L — `// Renamed from TestRv0196PlantOldName; the replacement is` /
  `// TestRv0196PlantNewName, which does not exist either.` — the second,
  genuinely dangling citation **was caught** (`:177`) while the renamed one was
  correctly discounted. One rule, one name.
- plant M — `// Renamed from the older helper that was called
  TestRv0196PlantFarName.` — the separator exceeds the window, so the name
  **was caught**. The rule fails toward firing, which is the right direction.

**The preceding-`*` rule is both too broad and nearly redundant.** It is what
swallows plant J (any citation a writer emphasises markdown-style), and
deleting it turns up only three real lines, all of them the bare convention
word `TestPool`. `main_test.go:19` writes `*TestPool` with no closing asterisk,
so the trailing-`*` rule does not already cover it — the rule is genuinely
load-bearing — but `"TestPool": true` in `nonTestIdentifierAllowlist` would
cover all three exactly, by name rather than by punctuation, and close the
emphasis hole. Note the guard's own doc comment is two of the three lines: the
rule partly exists to let the guard describe itself.

The two rules that cost nothing at all are worth recording as correct: the
leading `\b` keeps every real `*TestPool` compound (`credsTestPool` and its
five siblings) out of the candidate set with no allowlist, and the
`[A-Z0-9_]`-after-`Test` class excludes the English words "Tests"/"Testing"
while excluding **no** possible real test function — `go test`'s own `isTest`
rule refuses to run a `Test` followed by a lowercase letter, so a genuine test
function cannot hide behind either.

### Ruling on the line-break-join coupling

**Sound in design, with one demonstrated false-negative class, and it does get
weaker as the tree grows. Not a defect — but it should be written down.**

The seam pass accepts a merge only when `defined[merged]`, so the guard's
answer depends on what the tree currently defines. Both directions were worked
out, and the asymmetry is what makes the design defensible:

- **A wrapped dangling citation is still caught**, just imprecisely — the join
  is undefined, so it is discarded and the primary pass reports the line-1
  fragment (plant G). The guard fails safe.
- **Unless the line-1 fragment is itself a defined name** — then it resolves,
  the line-2 remainder does not match the pattern at all, and the citation
  disappears (plant I, **missed**). This is the real hole, and it is the
  guard's only structural one.
- **A join that accidentally spells a real function name is silently
  accepted** — and there are already six strict-prefix pairs among the tree's
  885 defined test functions (`TestDeleteSessionsForUser` →
  `…_RemovesAllAndIsIdempotent`; `TestLoad_MissingRequired` →
  `…ReportsAll`; `TestPreferencesHandler_Patch_UnsubscribeEverything` → two
  children; `TestWorker_SESRejectionReachesFailedSendsIntact` → two children).
  For one of those to mask a genuine dangling citation, a comment would have to
  wrap immediately after the shorter name **and** the next line would have to
  begin with the exact remaining suffix as its first word. That is contrived
  today, but the count of such pairs only ever rises, so the surface does grow
  with the tree.

The alternative designs are worse: a punctuation rule was tried and failed on
`seo_test.go`'s mid-camel-word wrap, and merging unconditionally produces the
`…NotARealSubscriber` + `is` false positive the notes describe. Asking "does
the join name something real" is the right question. The coupling is the price,
it is bounded by the prefix-pair count, and it is currently undocumented in the
guard's own comment — which is the part worth fixing.

### The self-reference hazard — verified independently

The claim that no fictitious name appears in a real comment in the guard's own
file **holds, and holds by construction rather than by luck.** Every
`Test`-shaped token in that file's real comments is either a function defined
in the same file (`TestNoCommentCitesUndefinedTestFunction`,
`TestDanglingTestCitationPatternCatchesSyntheticExample`,
`…ExcludesDiscountedShapes`, `…ReconstructsGenuineLineWrap`, and the
slash-qualified subtest example at line 129), or the discounted `*TestPool` at
lines 57 and 109, or the word "Tests" the pattern cannot match. Plant N proves
the guard is not merely blind to its own file: a fictitious name added to a
real comment there is caught and reported at the right line.

**String-literal exclusion is deliberate and structural, not accidental.** The
walk reads `file.Comments` — an `[]*ast.CommentGroup` the parser populates only
from comment tokens — and never touches `ast.BasicLit`. There is no path by
which a string could be scanned. Plant O confirmed it behaviourally: a
top-level `var … = "see TestRv0196PlantStringLiteral for the rationale"` in a
non-test file does **not** fire. This is load-bearing beyond the self-proof
fixture: `TestDanglingTestCitationPatternReconstructsGenuineLineWrap`'s raw
string literal contains two `Test…` names in comment-shaped text
(`TestSplitAcrossTheLine_ContinuesHereWithNoSeparator`,
`TestOrdinaryDocWrap_EndsCleanly`) that exist nowhere in the tree, so a guard
that scanned strings would fail on its own fixture immediately — it would be
noticed, not silently wrong. Writing a comment where a string is today is
therefore the safe direction, which is the property the notes claim.

### Reported for filing (`CLAUDE.md` §9 — I do not file)

Three items, all **outside this issue's scope** and none blocking it. They
could reasonably be one issue, "narrow the new guard's blind spots":

1. **The preceding-`*` discount swallows any markdown-emphasised citation.**
   `// see *TestSomethingGone*` is silently accepted even when the name is
   dangling (plant J). Deleting the rule turns up exactly three real lines,
   all the bare word `TestPool` (`main_test.go:19`, and the guard's own
   comments at 57 and 109), so replacing it with `"TestPool": true` in
   `nonTestIdentifierAllowlist` loses nothing and closes the class.
2. **A wrapped citation whose first line is itself a defined name is missed**
   (plant I) — the one structural hole in the seam design, and the coupling to
   the tree's contents that produces it is not mentioned in the guard's doc
   comment. Even if the behaviour stays, the comment should say that a wrapped
   citation whose head resolves on its own will not be caught, and that the six
   strict-prefix pairs are the surface. The `...` discount has the same shape
   at much lower stakes: `// TODO: write TestNotYetWritten... later` is
   silently accepted (plant K).
3. **For a multi-line `/* … */` block comment the reported line is the block's
   opening line, not the citation's.** Plant H put a citation on the fifth line
   of a block and it was reported at the block's first line (four lines off).
   `collectTestCitations` builds one span per `*ast.Comment`, and a whole block
   comment is a single `*ast.Comment`, so every citation inside it collapses to
   the `/*`. Only five multi-line block comments exist in the three roots today
   and none carries a citation, so this is latent rather than live; splitting
   the block's text on `\n` and offsetting the line would fix it.

Separately, and only as a documentation nit: this issue's `## Implementation
notes` explain the 164→170 gap as a two-line drift since filing. The line has
been 170 since `#0136` introduced the comment; `164` was wrong in `#0192`'s
review notes and was inherited. No code consequence.
