## Description

`#0346`'s §8 entry gives a three-tree satisfier table — `{*Sitemap}` before
`#0325`, `{*Site, *Renderer, *Sitemap}` after it, `{*Site, *Renderer}` once
`#0337` landed — but never says **which interface** those sets are measured
against.

There are two defensible readings and the entry states only one:

| Measured against | `f7771ed^` | `f7771ed` | `HEAD` |
|---|---|---|---|
| a fixed bare `interface{ Invalidate() }` | `{*Sitemap}` | `{*Site, *Renderer, *Sitemap}` | `{*Site, *Renderer}` |
| the two **seam** interfaces as they actually were at each tree | `{*Renderer, *Site}` | `{*Renderer, *Site, *Sitemap}` | `{*Renderer, *Site}` |

Both are true. The entry's numbers are the first; the sentence's grammatical
subject is the second. `#0346`'s second review measured both independently —
exports of all three trees unpacked outside the checkout, type-checked from
source, resolving each tree's real interface declarations — and confirmed the
entry is internally consistent under its own reading. It is under-specified,
not wrong.

Roughly four words fix it: say the sets are *"the satisfiers of a bare
`Invalidate()`"*.

**A second, sharper detail from the same review, worth adding while the entry
is open.** The entry says `*seo.Sitemap` was "a type the commit never touched".
True of the *type* — but not of the *file*: `f7771ed` rewrote the doc comment
directly above `func (s *Sitemap) Invalidate()`, so that declaration appeared
as **diff context in the rename commit itself** and still nobody noticed the
recruitment.

That strengthens the lesson rather than weakening it, and it is the more
alarming version: the reviewer's eye passed over the recruited method in the
very diff that recruited it.

## Root cause

`#0346`'s entry gave a satisfier table without naming the interface the sets
were measured against (two true readings existed), and its "never touched"
claim conflated the type (true) with the file (false — the doc comment above
`func (s *Sitemap) Invalidate()` was rewritten by `f7771ed`, putting that
declaration in the rename commit's own diff as unnoticed context).

## Fix

Two localized edits to the existing first paragraph of the `#0346` entry in
`CLAUDE.md` §8 (no restructuring, no new paragraph):

1. Inserted "of a bare `Invalidate()`" before "were `{*Sitemap}` before the
   rename, ..." so the satisfier table names its measured interface —
   matching the issue's suggested four-word fix exactly.
2. Replaced "a type the commit never touched:" with "a type whose own method
   the commit never edited, though not a file it never touched: `f7771ed`
   rewrote the doc comment directly above `func (s *Sitemap) Invalidate()`,
   so the recruited declaration sat in the rename commit's own diff as
   context, and still nobody noticed it." — sharpening rather than weakening
   the lesson, per criterion 3.

Net `+12/-8` lines in one hunk (`8b49030`). Did not touch the second
(value-receiver) paragraph, `internal/seo/invalidator_satisfier_guard_test.go`,
or any other file. The entry stays the longest in §8 already; kept the
addition to the minimum needed to satisfy both criteria rather than
rewriting for symmetry.

## Independent re-measurement (criterion 4 — nothing copied from this issue,
`#0346`, or the orchestrator's summary)

**Method 1 — diff-context claim.** `git show f7771ed -- internal/seo/sitemap.go`
directly: the hunk's only change is the doc comment immediately above
`func (s *Sitemap) Invalidate() {`, and that `func` line itself is unchanged
context inside the same hunk — confirming the declaration appeared as diff
context in `f7771ed` itself.

**Method 2 — satisfier sets.** Wrote a standalone `go/packages`-based probe
(new module, `golang.org/x/tools v0.42.0` from the local module cache,
`GOFLAGS=-mod=readonly`, `GOPROXY` untouched) run against three `git archive`
exports (`e8ba2d1` = `f7771ed^`, `f7771ed`, `a2c9f77` = `HEAD`) unpacked
**outside** this checkout, per criterion 5. For every named type in
`internal/seo`'s package scope it checked `types.Implements` against (a) a
synthetic bare `interface{ Invalidate() }` and (b) the real
`handlers.seoCacheInvalidator`/`workshopCacheInvalidator` and
`mailing.ArchiveCacheInvalidator` interfaces as actually declared at each
tree — a different technique from both of `#0346`'s reviews (which used
`go/types.Implements` over a `packages`-loaded checkout and a `go/importer`
"source" probe, respectively).

Results, both matching `#0350`'s two-row table and `#0346`'s second review
exactly:

| Measured against | `f7771ed^` | `f7771ed` | `HEAD` |
|---|---|---|---|
| bare `interface{ Invalidate() }` | `{*Sitemap}` | `{*Site, *Renderer, *Sitemap}` | `{*Site, *Renderer}` |
| the two seam interfaces as declared | `{*Renderer, *Site}` | `{*Renderer, *Site, *Sitemap}` | `{*Renderer, *Site}` |

`git status --porcelain -- go.mod go.sum` in this checkout was empty before
and after (checked per criterion 5) — the probe module and its
`golang.org/x/tools` dependency live entirely under the scratchpad, never in
this repo's `go.mod`.
