## Description

`#0346`'s §8 entry gives a three-tree satisfier table — `{*Sitemap}` before
`#0325`, `{*Site, *Renderer, *Sitemap}` after it, `{*Site, *Renderer}` once
`#0337` landed — but never says **which interface** those sets are measured
against.

There are two defensible readings and the entry states only one:

| Measured against | `f7771ed^` | `f7771ed` | `HEAD` |
|---|---|---|---|
| a fixed bare `interface{ Invalidate() }` | `{*Sitemap}` | `{*Site, *Renderer, *Sitemap}` | `{*Site, *Renderer}` |
| the two **seam** interfaces as they actually were at each tree | `{*Renderer, *Site}` | `{*Renderer, *Site, *Sitemap}` | `{*Renderer, *Site}` |

Both are true. The entry's numbers are the first; the sentence's grammatical
subject is the second. `#0346`'s second review measured both independently —
exports of all three trees unpacked outside the checkout, type-checked from
source, resolving each tree's real interface declarations — and confirmed the
entry is internally consistent under its own reading. It is under-specified,
not wrong.

Roughly four words fix it: say the sets are *"the satisfiers of a bare
`Invalidate()`"*.

**A second, sharper detail from the same review, worth adding while the entry
is open.** The entry says `*seo.Sitemap` was "a type the commit never touched".
True of the *type* — but not of the *file*: `f7771ed` rewrote the doc comment
directly above `func (s *Sitemap) Invalidate()`, so that declaration appeared
as **diff context in the rename commit itself** and still nobody noticed the
recruitment.

That strengthens the lesson rather than weakening it, and it is the more
alarming version: the reviewer's eye passed over the recruited method in the
very diff that recruited it.

## Root cause

`#0346`'s entry gave a satisfier table without naming the interface the sets
were measured against (two true readings existed), and its "never touched"
claim conflated the type (true) with the file (false — the doc comment above
`func (s *Sitemap) Invalidate()` was rewritten by `f7771ed`, putting that
declaration in the rename commit's own diff as unnoticed context).

### Independent reproduction — a third oracle

Neither `go/types.Implements` over a `packages`-loaded tree (`#0346`'s first
review), nor `go/importer` "source" (`#0346`'s second review), nor the
implementer's `go/packages` probe. Instead: **runtime `reflect` method sets**.
Three whole-tree `git archive` exports (`e8ba2d1` = `f7771ed^`, `f7771ed`,
`ece9059` = `HEAD`) unpacked outside this checkout; the package-level named-type
set enumerated from each tree's non-test files by `go/parser` (16 types at every
tree, no generics, no aliases — `ArchiveEntry ArchiveSource Renderer RouteMeta

both `T` and `*T` against `interface{ Invalidate() }` and
`interface{ InvalidateWorkshops() }`. `reflect` is a sound oracle for this
question because a method set is exactly what it reports, and it is *not* a

| tree | `interface{ Invalidate() }` | `interface{ InvalidateWorkshops() }` |

### Criterion 1 — does the qualifier bind?

Yes, and unambiguously. "the satisfiers **of a bare `Invalidate()`**" makes the
prepositional object a *method signature held fixed across all three trees*, not
a tree-dependent declaration. The two readings are numerically identical at
`f7771ed` and `HEAD` (the seams there *are* `interface{ Invalidate() }`), so only
the first tree distinguishes them — and at that tree the seams require
`InvalidateWorkshops()`, which "a bare `Invalidate()`" cannot denote. The
residual seam-interface reading is therefore closed by the text itself, not
merely made less likely. It is also set up by the preceding sentence, which is
about `(*seo.Sitemap).Invalidate` "already carrying that exact zero-parameter,
zero-result name". Criterion 1 met.

### Criterion 2 — the diff-context claim

Verified directly, and it is the strongest sentence in the entry.
`git show f7771ed -- internal/seo/sitemap.go` emits exactly one hunk,
`@@ -145,8 +145,10 @@`, whose only `-`/`+` lines are the doc comment (two lines
replaced by four). The line `func (s *Sitemap) Invalidate() {` carries a leading
space — **unchanged context inside that same hunk**. So the recruited
declaration did sit in the rename commit's own diff, and `f7771ed`'s message
("Purely mechanical … git diff is renames, comments, and call sites only") shows
how it read past. The claim is exactly true as stated, and the corollary the
entry draws — "still nobody noticed it" — is what makes the entry worth its
length: it removes the reassurance that review would have caught it.

Cross-checks on the surrounding retained claims, re-derived rather than assumed:
`git show f7771ed^:internal/seo/sitemap.go` has `func (s *Sitemap) Invalidate()`
at line 150 (short name already), `git log --all -S 'Sitemap) InvalidateWorkshops'
-- internal/seo/sitemap.go` is empty (the long name never existed on that type),
and `HEAD` has `func (s *Sitemap) invalidate()` (`#0337`'s unexporting).

### Criterion 3 — the lesson, and the length

Not weakened; strengthened, and in the direction that matters. The old text
("a type the commit never touched") let a reader conclude the recruitment was
invisible at review time. The new text says the opposite and is the more
alarming, more useful claim.

On length: measured across §8, this entry is 461 words against 222 for the next
longest (the `#0258` self-check entry); this pass added 44. The 44 earn their
place — they are the entry's single most cautionary fact. The entry's *overall*
size is a pre-existing condition of `#0346`, not something this pass created,
and it is really two entries sharing a bullet (the natural seam is at
"**Value receivers count, and this is the sharper half.**"). Not a defect, and
not worth churning here.

**One reservation, recorded and reported rather than bounced.** The new
subordinate clause — "a type whose own method the commit never edited, though
not a file it never touched" — spends three negations in sixteen words and
attaches "not a file …" to a *type*, which is a category slip on a literal
reading. Quoted on its own it inverts, which is precisely the mechanism that
produced `#0346`'s bounce. It does **not** mislead in place: the colon that
follows states the fact plainly ("`f7771ed` rewrote the doc comment directly
above …"), so no wrong belief survives a normal read, and every acceptance
criterion is met without touching it. Bouncing a pass that satisfies all six
criteria in order to trade sixteen words for fifteen is the churn criterion 3
warns against, and patching reviewer-authored prose with more unreviewed
reviewer-authored prose is the loop `#0346`'s second review explicitly declined
to enter. Reported to the orchestrator with exact replacement prose instead:
*"— a type whose own code the commit never changed, in a file it did touch:"*.
