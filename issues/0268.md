## Description

`#0265`'s guard resolves test-name citations in issue files. Its
`extractNamedSections` admits exactly two headings: `## Verification` and
`## Implementation notes`.

**That is not where most claims live.**

- A **fix pass** writes its evidence under `### Verification` *nested inside*
  `## Fix pass` — three of those exist today, none matched.
- A **reviewer** writes under `## Review notes`.

Both defects that bounced `#0265` a second time were in those unscanned
sections, as was the dangling citation one of them concerned.

**Measured by that review: 14 dangling citations in unscanned sections of
`open`/`in-progress` files today, against 0 in the scanned ones.**

So the guard currently enforces a rule over the smallest and cleanest part of
the corpus, while the sections where implementers and reviewers make their
strongest claims — *"I ran this and it printed that"* — go unchecked. That is
close to the opposite of the intent.

**This is not "scan everything".** `## Description` legitimately quotes names
that do not exist — `#0126`'s fabricated citations are quoted verbatim in
several issues as the subject matter. Scanning it would produce exactly the
day-one noise `#0265` scoped its way out of. The fix is to admit the sections
where evidence is *asserted*, not those where it is *discussed*.

## Acceptance criteria

- [x] `## Review notes`, and `### Verification` nested under `## Fix pass`, are scanned — as are any other headings where evidence is asserted; enumerate them from the corpus rather than guessing
- [x] `## Description` and `## Notes` remain unscanned, and the reason is written down so the exclusion is not mistaken for an oversight
- [x] **Measure before choosing.** Report the dangling-citation count per candidate section across `open`/`in-progress` files, and let that drive which are admitted — the way `#0265`'s own scope decision was driven
- [x] The 14 known dangling citations are fixed, or each is shown to be legitimately quoted subject matter
- [x] Mutation-proved: plant a fabricated citation in a `## Review notes` section of an open file, confirm it is named; restore, prove byte-identity with `shasum -a 256`
- [x] `go test ./internal/db/...` passes with zero skips against an isolated database

### The mechanism

`issueCitationSectionHeaders` changes from an exact-match map on the whole
heading line to a map keyed by *normalized title*, and a new `issueSectionTitle`
does the normalizing: strip `## `, drop any annotation introduced by an em-dash
or an opening parenthesis (whichever comes first), trim, lowercase. That is what
makes one entry match every real spelling in the tracker — a review-notes
heading carrying a phase and a date, a fix-pass heading carrying a date and a
parenthetical. An exact-match matcher would have missed every decorated variant,
which is a second reason a fix pass's evidence went unscanned.

### A third discount rule the widening made necessary: line-wrapped names

Widening the scan to `## Fix pass` and `## Review notes` means reading long-form
wrapped prose, and a test name broken across a line reads to the citation
pattern as a truncated prefix that resolves to nothing. This is not a
hypothetical: while this pass was verifying against the shared checkout,
another agent's `#0124` file briefly carried **six** such names in its
`## Verification` section — a section this guard already scanned before `#0268`
— and every one was reported as dangling although each joined into a real
defined function. That agent unwrapped them a minute later for its own reasons,
so no live instance survives, but the shape will recur every time an evidence
section quotes a long name near the right margin.

`isLineWrappedDefinedTestName` discounts a match followed immediately by a line
break when the match **joined with** the identifier characters continuing on
the next line names a function the tree defines. Indentation and blockquote
markers are skipped, since review notes are frequently quoted. It cannot
produce a false negative: a wrapped name whose halves do not join into
something real is still reported. `TestIssueCitationLineWrappedNameResolvesOnlyWhenJoinedNameIsDefined`
pins all four cases — wrapped and defined, wrapped inside a blockquote and
defined, wrapped and *not* defined, and not wrapped at all.

Measured effect: it discounts 5 citations corpus-wide and **0** in the enforced
scope, so it is not load-bearing today. It is here because the shape was
observed live and because it strictly reduces false positives.

### The 14, and what they turned out to be

Not one of them was a false claim about a test having run. All were **names
spelled in prose that the tree does not define**: `#0126`'s six fabricated
citations quoted as subject matter (4, in `## Description`, left alone); the
deliberately-invented identifier from `#0265`'s own mutation plant, quoted while
describing the plant (2); a placeholder identifier a test fixture declares as a
string, quoted while describing a fixture-ordering bug (2); and `-run` fragments
that are substrings of real functions but not themselves defined, spelled
plainly instead of pipe-adjacent (3). `#0265`'s own escalated pass had already
removed 3 of the 14 while correcting unrelated prose, leaving 11 measured here
and 7 to fix under the widened scope.

Each was fixed the way this issue's `## Notes` prescribes — **describe the
identifier, do not spell it**. That is a real constraint and it bit immediately:
a first attempt wrote a `Test…`-prefixed shape with a U+2026 ellipsis after it,
and the guard reported the prefix, because `#0196`'s wildcard discount needs
three ASCII dots and an ellipsis character is not that. The fix was to stop
naming the shape at all.
