## Description

`#0258`'s third review found that `RUN_DEF_COUNT` is `grep -cE '^run\(\)' "$0"`,
which sees only a **column-0, contiguously-spelled** definition — so a one-line
decoy in any other shape shadows `run()` at runtime while the count stays at 1.

**`GUARD-0208`'s `RUNPIPE_DEF_TOTAL` uses the same `^runpipe\(\)` anchor and
inherits the identical gap.**

The difference is that it is **not exploitable today, by accident.** An indented
`runpipe` decoy must still spell `bash -c` to do anything useful, and the
shell-`-c` scan catches that. So the anchor's weakness is masked by a *different*
check happening to cover it.

**That masking is incidental, not designed.** It holds only while every useful
`runpipe` body contains `bash -c`. Nothing states that dependency, nothing tests
it, and a future refactor that changes how `runpipe` invokes its subshell would
silently remove the cover. The same widened anchor `#0258` needs would close
this one deliberately rather than by luck.

**A second, smaller issue in both guards.** They scan `"$0"`, while `REPO` is
derived from `${BASH_SOURCE[0]}`. Invoked by a relative path from outside the
repository root, `$0` no longer resolves after `cd "$REPO"`, and the guard fires
`found 0`. It **fails safe** — a false alarm rather than a false pass — but it is
a spurious failure in the script everything else is verified with, which is the
expensive kind. `${BASH_SOURCE[0]}` is strictly more robust for both.

## Fix pass

Implemented in the same pass as `#0258`'s fourth fix pass, in the same
`scripts/check.sh` commit — see `issues/0258.md`'s `## Fix pass (fourth
pass)` for the full mechanism, judgement call, and verification detail;
this section covers what's specific to `runpipe()` and to this issue's own
acceptance criteria.

**Anchor widening — not the handed-over regex, the shared `resolve_func_hash`
mechanism `#0258` landed instead.** `#0258`'s third review handed over a
measured, working regex
(`^[[:space:]]*(function[[:space:]]+)?run[[:space:]]*\(\)|...`) and this
issue's own notes suggested applying the same pattern (substituting
`runpipe`) to `RUNPIPE_DEF_TOTAL`. Judged that widening the anchor a second
time, for a second name, was the same enumerate-recognized-forms trade the
notes above call out by name as the thing to stop doing — so instead,
`GUARD-0208`'s `RUNPIPE_DEF_TOTAL`/`RUNPIPE_LINE` (the narrow
`^runpipe\(\)` anchor and its extraction) were replaced by
`resolve_func_hash runpipe`, compared against a pinned SHA-256 digest,
using the exact same shared mechanism `run()`'s check now uses. Proved
against the acceptance criteria's own named decoy set — leading space, tab
indent, `function runpipe {`, `runpipe () {` — each one added as a single
line after `# END GUARD-0208`, real line 77 untouched, run end to end
against the fixed script: all four CAUGHT, `PIPEFAIL REGRESSION
(#0208/#0251/#0262): runpipe()'s resolved definition ... no longer matches
the pinned SHA-256 digest`, exit 2, before `=== machine` ever prints. The
count in the tracked (unmutated) file resolves to exactly the pinned digest
(1, in the "how many candidates does `runpipe` shadow-resolve to" sense
this design actually uses instead of a literal count) and each of the four
mutants resolves to a DIFFERENT hash (the decoy, which appears later in
file order and so wins bash's own shadowing) — verified by running, not by
reading the regex, per the acceptance criteria's explicit instruction.

**Masking dependency — removed, not merely documented.** This issue's
acceptance criteria allowed either outcome ("either removed or written
down"). It is removed: `resolve_func_hash runpipe` catches all four decoy
shapes on its own, using bash's own parser to resolve what `runpipe` is
actually bound to, independent of `SHELLC_HITS` or any other check in the
file. The code comment at the point `BR_COUNT`/`ER_COUNT` sits (where the
old masking argument used to live, since that's the check that was
previously doing double duty) now states this explicitly: an indented
`runpipe()` decoy no longer needs to spell `bash -c` to be caught, so
`SHELLC_HITS` catching it is now redundant coverage rather than the sole
mechanism.

**`$0` → `${BASH_SOURCE[0]}` → `$SELF`.** Reproduced the relative-path
failure independently first (`cd
/Users/brennan/Developer/OpenCircuitSF && bash ./Website/scripts/check.sh`

**`#0208`'s nine mutants and `#0251`'s three fakes for `runpipe()`,

fourth pass; summary here since this issue names them in its own
