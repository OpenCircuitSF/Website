## Description

These are follow-ups found while writing `#0680`'s docs.

1. **Times are not all Pacific.** Guide-post times (`scheduled_at`, `posted_at`, and the time filters on `list_guide_posts`) and engagement times come back in UTC, while event times carry a Pacific offset. Return them in Pacific too, as the same instant with a different offset, and update the docs.
2. **`update_event` isn't flagged PUBLIC.** On a published event it changes the public page right away. Flag it PUBLIC, the way `update_guide_post` is flagged, or add a note to its description.
3. **The docs have no parity test.** Add a test that every v1 `operationId` and every MCP tool name appears in `docs/api.md` and `docs/mcp.md`.

## Plan

Folded into the implementation pass (the user's "keep moving" direction): no separate phase-1 subagent.

1. Convert guide-post output times to Pacific in the v1 layer only, reusing `inPacific`: a `postInPacific(guideposts.Post)` applied to every op that returns a post (`list_guide_posts`, `create_guide_posts` results, `update_`, `schedule_`, `unschedule_`, `send_guide_post`, `post_guide_again`), plus `guide_posts_overview`'s and `get_guide`'s `last_posted_at`/`next_scheduled_at`. The store and the admin API are unchanged. Decide engagement against `docs/home-assistant.md` and the golden test.

Add `internal/handlers/v1_docs_parity_test.go`, which builds the production registry (`BuildV1Registry(api.Config{}, V1Deps{})`) and asserts each op name, in backticks, appears in `docs/api.md`, and each MCP tool (no `MCPExcluded`) in `docs/mcp.md`. `internal/handlers` already has a row in the AGENTS.md §5 table, so update its `Reaches into` cell.
4. Update `docs/api.md` and `docs/mcp.md`. Verify with `ISSUE=0687 scripts/check.sh`.

## Fix

- **Guide-post times are Pacific** (`internal/handlers/v1_guide_posts.go`, `v1_guides.go`). The new `postInPacific` converts `scheduled_at`, `posted_at`, `created_at` and `updated_at`. The overview and `get_guide` history convert `last_posted_at` and `next_scheduled_at`. Each instant is unchanged, and only the offset differs. `list_guide_posts`' `from` and `to` filters already took any offset and compare by instant, so they needed no change. The `list_guide_posts` description now says "Times have a Pacific offset". The idempotent replay of `create_guide_posts` stores the converted bytes, so a replay matches.
- **Engagement stays UTC, by decision.** `get_engagement`'s body is pinned byte for byte (`TestEngagementAPI_SuccessBodyUnchanged`, the #0653 and #0675 golden) as the contract with Home Assistant. The sensor exposes `since`, `until` and `data_as_of` as attributes that existing installs show and template on. A `-08:00` offset would parse, but it would change what existing installs show, and it would break the pinned contract for a cosmetic gain. `docs/api.md` now lists it, together with the coverage report's Luma `read_at` and `last_good_at`, as the two deliberate UTC exceptions. The op's own description already says "Output times are UTC".
- **`update_event` is flagged PUBLIC** (`v1_events.go`): `PublicEffect: "on a published event, the changes show on the public site right away"`. The same sentence was removed from its `Description`. `internal/mcpserver/tools_test.go` already checks every PublicEffect op for the `PUBLIC: ` lead and `openWorldHint`, so it now covers `update_event` too. In `docs/mcp.md`, the tool table marks it "PUBLIC (on a published event)", and the "not flagged PUBLIC" caveat is gone. `.claude/skills/ocsf-ops/SKILL.md` already listed `update_event` on a published event among the calls flagged PUBLIC, and it is now accurate.
- **The docs parity test** is `TestV1DocsNameEveryOperation`. `docs/api.md` did not name `whoami` or `token_probe`, the first two operations, so their headings now carry those names, and the test caught that gap on its first run. A mutation test showed it fails: removing the backticks from `list_venues` in `docs/mcp.md` gave "docs/mcp.md does not name MCP tool `list_venues`".
- **Docs:** `docs/api.md` (the Times section, `list_guide_posts`, `update_event`, engagement, the `whoami` and `token_probe` names) and `docs/mcp.md` (the tool table, the removed caveat, workflow A's "times are UTC" step). AGENTS.md §5's `internal/handlers` row now names `docs/api.md` and `docs/mcp.md`. That change was committed with `#0688`, which also edits AGENTS.md.
