# 0101 — Link the Luma events calendar alongside the Discord invite

## Description

Open Circuit SF now has a Luma calendar at <https://luma.com/opencircuitsf>,
which is where upcoming events get promoted. The site links Discord in two
places and the calendar in none, so the one surface built for "what's coming up"
is invisible to anyone who lands on the site.

## Acceptance criteria

- [ ] **The calendar is linked in the footer, beside the Discord link.**
      `web/src/lib/Footer.svelte` renders a `Calendar` (or `Events`) link in
      `.footer-links`, with the same `target="_blank" rel="noopener noreferrer"`
      treatment, a `·` separator, and the `@media (max-width: 480px)` ≥40 px
      tap-target rule the existing footer links already get.
- [ ] **The calendar is linked from About's "Get involved" section.**
      `web/src/views/About.svelte` currently says "The easiest way in is
      Discord — that's where workshops get announced". That is now only half
      true. Name the calendar as where upcoming sessions are listed and RSVP'd,
      and update the `StatusList` item `'announced through Discord and the
      mailing list'` to include it.
- [ ] **The URL is defined once, not copy-pasted.** `DISCORD_URL` is already
      duplicated verbatim in `Footer.svelte` and `About.svelte`; a second
      hand-copied constant would make three. Put both external links in a shared
      module (a new `web/src/lib/links.ts` alongside `branding.ts` — note
      `branding.ts`'s own comment says not to use it for functional values) and
      import from there.
- [ ] **It is a plain link — no Luma embed, widget, script, or iframe.**
      `CLAUDE.md` §9 forbids third-party scripts, external CDNs, and trackers;
      the site is self-contained by design. Luma's embed loads their JS. An
      `<a href>` is the whole feature.
- [ ] **The router does not intercept it.** `shouldIntercept` must return
      `false` for the Luma URL the same way it does for the Discord invite. Add
      a case to `web/src/lib/router.test.ts` beside the existing
      `does not intercept a cross-origin href` test rather than assuming the
      cross-origin branch covers it.
- [ ] **The privacy policy names Luma.** `web/src/views/PrivacyPolicy.svelte`
      says the policy "does not cover third-party services like Discord, which
      has its own privacy policy." Someone who RSVPs on Luma hands their details
      to a third party the same way. Add Luma to that sentence. Do not make any
      claim about what Luma collects — the sentence's job is to say the policy
      does not cover it.
- [ ] **Confirm the canonical URL form before hardcoding it.** Luma serves both
      `luma.com` and the shorter `lu.ma`. Use whichever the calendar actually
      canonicalizes to rather than guessing, and note in `## Gotchas` which one
      it was.
- [ ] `npm run check` and `npm test` pass from `web/`.

## Notes

The user added the calendar on 2026-08-20 and gave the URL as
`https://luma.com/opencircuitsf`.

**Scope: two link sites plus the privacy sentence.** The natural temptation is
to also surface the calendar on the public workshops index — that page does not
exist yet ([#0053](0053.md)), and deciding how a Luma calendar relates to the
site's own `workshops` table is that issue's problem, not this one. This issue
adds the link where Discord already is and stops there.

**No component test will cover the markup.** [#0094](0094.md) records that the
Svelte components have no test infrastructure, so the footer and About changes
are verified by `npm run check` plus review of the rendered page. The shared
links module and the router case *are* unit-testable, which is part of why the
URL belongs in a module rather than inline in two components.

This lands outside the Phase 2 gate, which is already complete. It is not
blocked by, and does not block, the Phase 4 work in flight — it can be picked up
whenever.
