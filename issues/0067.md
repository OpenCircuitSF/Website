# 0067 — .env.example ships a usable SESSION_SECRET, so a copied template boots with a publicly known key

## Description

`.env.example:18` reads `SESSION_SECRET=replace_with_random_64_char_hex_string`. That value is non-empty, so it satisfies the config loader's required-variable check and the service starts normally. Anyone who copies the template and forgets that one line runs production with a session HMAC key that is published in a public repository.

## Expected behavior

PRD §9 specifies a **blank** `SESSION_SECRET` in the template so startup fails closed with `config: missing required variable SESSION_SECRET`, forcing the operator to set a real one.

## Actual behavior

The placeholder is a valid non-empty string. The service boots, signs sessions with a known key, and gives no warning. Session forgery requires only reading `.env.example` on GitHub.

## Root cause

Inherited verbatim from the ShortLinks template in `#0001`'s skeleton copy and preserved through `#0007`'s regeneration, which reproduced the existing line rather than PRD §9's specified blank.

## Acceptance criteria

- [ ] `.env.example` ships `SESSION_SECRET=` with an empty value
- [ ] The surrounding comment states how to generate one (`openssl rand -hex 32`) and that startup fails closed if unset
- [ ] Every other secret-bearing placeholder in `.env.example` is audited the same way — a value that satisfies validation while being publicly known is the defect, not the specific variable
- [ ] `docs/configuration.md` describes `SESSION_SECRET` as required with no default and documents the generation command
- [ ] A test asserts the loader rejects an empty `SESSION_SECRET` (`TestLoad_MissingRequired/missing_SESSION_SECRET` already covers this — confirm it does and reference it rather than duplicating)
- [ ] `go test ./internal/config/... -count=1 -v` passes with zero skips

## Notes

Fail-closed is the whole point. A placeholder that validates is worse than no placeholder: it converts a loud startup error into a silent security defect that surfaces only if someone thinks to check.

This is a template and documentation fix. **Do not change the loader** — it is correct to require the variable, and `#0065` already proved that requirement is genuinely asserted.

Audit the other placeholders while here. `ADMIN_EMAIL` and `DATABASE_URL` carrying real-looking defaults is a related hazard, though a much smaller one than a signing key.
