## Description

A doc comment in `internal/subscribers/store.go` cites
`subscribers_source_check` and `subscribers_consent_basis_check` as living in
`migrations/000010`. **Both are created in `migrations/000023`**, and `000010`
contains neither.

Found by the `#0343`/`#0344` review while establishing which migration owns the
`consent_basis` CHECK constraint — a question that mattered, because
`#0343`'s new `TestConsentBasisValuesAreClassified` reads that constraint from
the migration as an independent oracle and had to read the right file.

Pre-existing and untouched by `6100b6b`, which is why it was reported rather
than bounced. Likely residue of `#0125`'s bounced `000010` criterion —
`CLAUDE.md` §1 records that issue being filed with an acceptance criterion
instructing an edit to `000010` that its review had to reject.

## Why a wrong citation here is worse than average

The guards do not catch it. `TestNoCommentCitesUnresolvedPathOrSection` checks
that a cited **path resolves**, not that a **quotation of its contents is
accurate** — `migrations/000010` exists, so the citation passes. That is the
same gap `#0438` hit from the other direction, where a doc comment quoted a PRD
section correctly until the section changed underneath it.

And this comment sits in the file that owns the growth-counting predicates. A
reader chasing "which migration defines the permitted `consent_basis` values"
— exactly the question `#0343` turned on — is sent to a file that will not
answer it, and `000010` is old enough to look plausible.

## Acceptance criteria

1. The comment cites the migration that actually creates each constraint.
   **Verify by reading the migrations**, not by trusting this issue: confirm
   `000023` creates both, and confirm no later migration alters or renames
   either. `#0343`'s review established `000023` is the only file creating
   `subscribers_consent_basis_check` and that nothing later touches it —
   re-derive that for `subscribers_source_check` too.
2. Sweep `internal/subscribers/` for other migration-number citations in
   comments and check each against the file it names. One wrong citation is weak
   evidence the rest are right. Report what you find, including "nothing else".
3. **No new mechanism** (§8, `#0258`). Do not build a guard that verifies
   migration citations — that is a real idea, but it is not this issue, and
   stacking a mechanism onto a comment fix is the shape that buys bounces.
4. gofmt rewrites doc comments — a doubled backtick collapses to a curly quote,
   and a backtick span does not protect. Run `gofmt -w` and confirm the file's
   hash is stable.

(`CLAUDE.md` §1): the provenance work was originally planned to land in

created in `migrations/000023`; `000010` (the original `create_subscribers`
migration) predates all of `#0125`'s work and contains neither the
constraints nor the columns.
