## Description

Two minor defects in `cmd/opencircuit/servepostgres_seo_instance_guard_test.go`
(`cbb11a5`), both found by `#0326`'s review, neither live.

**1. The anti-vacuity floor is one too low.** The scan finds **4** site-shaped
consumer positions — `mountAndServe`'s parameter 34 is included — but
`knownConsumersAsOfWriting` is **3**. So a silent degradation from 4 consumers
to 3 passes the floor. The floor exists precisely to catch discovery quietly
losing a consumer (§8, and the `#0275`/`#0298` shape: a tree-walking guard that
visits nothing reports "no findings"), and at 3 it cannot catch the first such
loss.

**2. `interfaceIsInvalidateOnly`'s doc comment overstates what it checks.** It
says the interface has "no results", but the function only inspects parameters.
A method with a return value would pass a check the comment claims rejects it.

Neither is exploitable today: the guard's other assertions are sound, and
`#0326`'s review added four further mutations (including a synthetic fourth
consumer passed `nil`, caught with no edit to the guard) confirming the
mechanism works. These are margin and documentation defects, not failures.

## Acceptance criteria

1. `knownConsumersAsOfWriting` equals the **measured** consumer count, with the
   measurement method stated in its doc comment — re-measured, not copied from
   this issue.
2. A degradation from the real count to one below it FAILS. Prove it by
   mutation in a throwaway worktree, restored and hash-verified.
3. The floor's doc comment says what it is for — catching silent discovery loss
   — and what would legitimately change it.
4. `interfaceIsInvalidateOnly`'s doc comment matches what the function checks,
   or the function is extended to check results as the comment claims. State
   which was chosen and why.
5. If results are now checked, confirm the intended satisfiers still pass and
   re-run `#0326`'s seven mutation proofs.
6. `gofmt` stability proved: file sha256 equals sha256 of `gofmt` stdout (§8).
7. The guard still needs no built SPA — `#0326`'s review verified it passes in a
   fresh worktree with no `node_modules`. Keep that true.

## Review notes

**Verdict: approved (phase 3, Opus, 2026-08-31).** This issue exists because a
floor sat one below the real count, so the review's central obligation was to
re-measure the count independently rather than confirm the implementer's number.
Every measurement below was made in a throwaway `git worktree` at `59ccc90`; the
shared tree was never mutated.

- **Criterion 1 — the count, re-measured from scratch.** Set
  `knownConsumersAsOfWriting` to `999` in the worktree and read the guard's own
  enumeration off its failure. Result: **found 4**, at exactly these positions —
  `main.go:259:21` `NewAdminWorkshopsHandler` param 1 (`invalidator`),
  `main.go:364:21` `newSendWorkerIfEnabled` param 10 (`archiveCache`),
  `main.go:397:27` `NewAdminCampaignArchiveHandler` param 2 (`invalidator`),
  `main.go:519:9` `mountAndServe` param 34 (`site`). The committed constant is 4,
  so the floor now **equals** the measured population — not below it (`#0326`'s
  defect, which let a silent loss pass) and not above it (which would fail
  immediately). `mountAndServe`'s own `site *seo.Site` parameter is genuinely the
  fourth, matched by `typeRequiresSEOSite`'s literal-`*seo.Site` case. I found no
  fifth: the enumeration under `999` is exhaustive, so this is not the same
  miscount one higher.
- **Criterion 2 — the 4→3 mutation, and the counterfactual.** Independently
  reproduced the degradation by rewriting `mailing.ArchiveCacheInvalidator` to
  obtain its method by *embedding* (`type invalidateOnlyBase interface {
  Invalidate() }`, embedded) — which preserves the method set, so everything
  still compiles, but stops `interfaceIsInvalidateOnly` matching it. Result with
  the new floor: **FAIL — "found 3 ... want at least 4"**. Then re-ran the *same*
  mutation with the floor set back to `3`: **`ok`** — passes silently. That is the
  defect narrative confirmed by direct experiment, not by reading.
- **Floor semantics and placement (CLAUDE.md §8).** The assertion is
  `len(consumers) < knownConsumersAsOfWriting` — a floor, catching loss and
  permitting growth, which is the right direction for an anti-vacuity check. Its
  in-package home is legitimate under §8's falsifiability rule: the mutations
  that matter act on the **scan roots** (`main.go`, and the callee packages whose
  signatures are resolved), so `got` itself changes and the test is not agreeing
  with itself. This is the `#0304` "mutate the scan roots, not the constant"
  case, not the external-harness case.
- **Criteria 4/5 — the results check actually does something.** Rather than take
  the extension on trust, exercised `interfaceIsInvalidateOnly` directly against
  a synthetic package: `Invalidate()` → `true`; `Invalidate() error` → **`false`**;
  `Invalidate(x int)` → `false`; a two-method interface → `false`. The function
  now matches its doc comment. Both intended satisfiers
  (`handlers.seoCacheInvalidator`, `mailing.ArchiveCacheInvalidator`, both
  zero-param/zero-result) still resolve — proved by the baseline run finding all
  four consumers, which is only possible if both are still recognised.
- **`#0326`'s mutation proofs re-run.** Spot-checked two independently against the
  post-`#0335`/`#0337` tree: `nil` to `NewAdminWorkshopsHandler` → FAIL
  (`param 1 (invalidator) got nil, want the identifier "site"`); a second
  `buildSEOSite` call → FAIL (`found 2 buildSEOSite calls ... want exactly 1`).
  Baseline unmutated → `ok`.
- **Criterion 3.** The floor's doc comment now states what it is for (catching
  this guard's own resolution silently losing a consumer), what would legitimately
  change it, and — importantly — *how to re-measure* rather than a number to
  increment by hand. That last point is what stops this issue recurring.
- **Criteria 6, 7.** `gofmt` stability confirmed independently: `sha256(file) ==
  sha256(gofmt stdout)`. The guard ran green in a fresh worktree with **no

- **Mutation hygiene (§8b) — verified, not assumed.** Every mutation above ran in
