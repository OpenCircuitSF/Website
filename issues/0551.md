## Review notes

Reviewed 2026-10-16 against `85daff0`.

- **No-op UPDATE**: `updated_at` is set by a `CASE` that compares `ROW(COALESCE($n, col)…)` with `ROW(col…)` using `IS DISTINCT FROM`, so a patch that resends current values keeps the stored timestamp. The comparison is NULL-safe. All five content columns are `NOT NULL` in `000033` anyway, so it never meets a NULL. `updated_at` itself is nullable with no default, so a never-edited row that gets a no-op PATCH keeps NULL, which is the right meaning ("never changed"). The `WHERE … (code_locked_at IS NULL OR $3::text IS NULL OR $3::text = code)` lock guard is unchanged, so the zero-row not-found/locked reclassification still works. `TestLocationNoOpUpdateKeepsUpdatedAt` backdates the row, sends a same-value patch and asserts the timestamp is equal, then sends a real change and asserts it moved forward. It checks both directions.
- **SQLSTATE**: `TestLocationCheckConstraintRejectsBadCode` now uses `errors.As` into `*pgconn.PgError` and requires `23514`. The success path `continue`s after its cleanup, so a nil error is not dereferenced.
- **SPA**: the `role="status"` `<p>` is still rendered unconditionally. Failures set `statusIsError` and get the global `text-error` class from `app.css`, which other admin views already use. Successes keep `text-muted`. Every path that writes `status` resets or sets the flag. The new jsdom test checks the 409 error, then a success, on the same node identity. That is jsdom evidence, not a real browser.
- **Independent run**: load 2.1. `ISSUE=0551 scripts/check.sh go ./internal/outreach/... ./internal/handlers/... ./internal/db/...` gave all three packages `ok` (outreach 0.245s, handlers 12.2s, db 12.6s), no skips, gofmt clean, VERIFICATION PASSED. `scripts/check.sh web`: 60 files, 4383 tests passed, VERIFICATION PASSED.
