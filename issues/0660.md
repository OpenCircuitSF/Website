### API consumed (from `#0659`)

| Call | Response |
|---|---|
| `GET /admin/guide-posts` | `{topics: [{slug, title, hook, post, url, default_body}], posts: [GuidePost & {clicks: number\|null, signups: {requested, confirmed}\|null}], channels: [{name, label, char_limit, configured}], post_hour, suggested_campaign, clicks_error: string\|null, signups_error: string\|null}` |
| `GET /admin/guide-posts-overview` | `{guides: [{slug, title, url, last_posted_at, last_campaign, channels[], campaigns[], posted_count, next_scheduled_at, clicks, signups}], clicks_error, signups_error}` |
| `POST /admin/guide-posts` `{slug, channel, campaign, body}` | `201 {post, link_error: string\|null}` |
| `PATCH /admin/guide-posts/{id}` `{body}` | `200 post` |
| `POST …/{id}/schedule` `{scheduled_at}` | `200 post` |
| `POST …/{id}/unschedule` | `200 post` |
| `POST …/{id}/send` | `202 post` (also the Retry for a `failed` post) |
| `POST …/{id}/again` `{campaign}` | `201 {post, link_error}` |
| `DELETE /admin/guide-posts/{id}` | `204` |

`GuidePost` = `{id, guide_slug, channel, body, destination_url, campaign_slug, short_link_key, short_url, status, scheduled_at, posted_at, remote_id, remote_url, last_error, attempt_generation, created_at, updated_at}`. `status` is one of `draft`, `scheduled`, `queued`, `posted`, `failed`. `link_error` and `clicks_error` are `linkFailureReason` codes: `rate_limited`, `timeout`, `not_configured`, `rejected`, `failed`.

### `web/src/lib/guidePosts.ts` (all logic; pure, no DOM)

Reuse `countCharacters`, `isOverLimit`, `LINK_TOKEN`, `asSentence`, `toLocalInputValue`/`fromLocalInputValue` from `./outreach`, `linkFailureReasonLabel` from `./outreachLinks`, `formatClicks`, `postStatusWords` from `./outreachResults`, `formatPacificDateTime` from `./pacificTime`, and `adminSettingsHash` from `./adminRouter`. Never import `./topics/topics`.

- `export const GUIDE_LINK_SAMPLE = 'https://go.opencircuitsf.com/u/XXXXXXXXXXXX'`. This mirrors Go's `guideposts.sampleShortURL`, the URL the server measures `{link}` as. So the count shown before a link exists matches what the server will accept or refuse. (Outreach's `LINK_ESTIMATE = 30` is shorter than this, so it would let a too-long draft through to a 422.)
- `countWithLink(channel: Pick<GuidePostChannel,'name'>, body: string, shortUrl: string | null): {count: number; exact: boolean}`: when `shortUrl` is set, `countCharacters(channel, body, true)`; otherwise replace every `LINK_TOKEN` with `GUIDE_LINK_SAMPLE` and count with `prepared = true`. `exact` is `true` when the body has no token or a link exists.
- `counterText(channel: GuidePostChannel, body, shortUrl): string`, for example `"212 / 300 characters, including the short link"`. Prefix `≈ ` when not exact. Leave out ", including the short link" when the body has no link token and no short URL. Use `char_limit` from the channel. A limit of 0 means no limit: `"212 characters"`.
- `overLimit(channel, body, shortUrl): boolean` = `isOverLimit(channel, countWithLink(...).count)`.
- `isValidCampaign(s: string): boolean`. True for a blank value (the server then uses `guide-posts`) and for a value of 100 characters or fewer matching `/^[a-z0-9]+(-[a-z0-9]+)*$/` (mirrors `NormalizeCampaignSlug`). `campaignHint` constant: `'Lowercase letters, digits and single hyphens, for example guides-2026-11.'`
- `bodyAfterGuideChange(current: string, prevDefault: string, nextDefault: string): string`. Returns `nextDefault` when `current === prevDefault` or `current.trim() === ''`, otherwise `current`. Text you have edited is never thrown away.
- `defaultScheduleAt(now: Date, hour: number): string` is a datetime-local value for tomorrow's Pacific date at `hour:00`. Take today's Pacific date from `toLocalInputValue(now.toISOString()).slice(0, 10)`, add one day with `Date.UTC` arithmetic (handles month and year ends), and format it as `YYYY-MM-DDTHH:00`.
- `type PostAction = 'edit' | 'schedule' | 'unschedule' | 'postNow' | 'retry' | 'delete' | 'open' | 'again'`; `postActions(post: Pick<GuidePost,'status'|'remote_url'>, configured: boolean): {action: PostAction; enabled: boolean}[]`, in this order:
  - draft: edit, schedule, postNow, delete
  - scheduled: edit, unschedule, postNow
  - failed: edit, retry, schedule, delete
  - queued: none
  - posted: open (only when `remote_url` is set), again
  
  `schedule`, `postNow` and `retry` are `enabled: configured`; every other action is always enabled.
- `ACTION_LABELS: Record<PostAction, string>` = Edit, Schedule…, Unschedule, Post now…, Retry…, Delete…, Open post, Schedule again….
- `notConnectedNote(channel): string | null`: `null` when configured, else `"<Label> is not connected. You can write drafts; connect it under Settings → Outreach to schedule or post."` The component links "Settings → Outreach" to `adminSettingsHash('outreach')`.
- `statusLine(post): string`: `postStatusWords(status)`, plus ` · <formatPacificDateTime(scheduled_at)>` for scheduled, ` · <formatPacificDateTime(posted_at)>` for posted, and `'Posting…'` for queued.
- `linkErrorMessage(reason: string | null): string | null`: `null` → `null`; otherwise `"Draft saved, but its short link could not be made (" + linkFailureReasonLabel(reason) + "). It is made when you schedule or post."`
- `clicksErrorMessage(reason: string | null): string | null`. `not_configured` → `"Click counts need the ShortLinks connection, which is not configured. Set it up under Settings → Outreach."`. `rejected` → `"ShortLinks rejected this server's API token, so click counts are missing. Check it under Settings → Outreach."`. Any other reason → `"Some click counts are unavailable right now (" + linkFailureReasonLabel(reason) + ")."`.
- `signupsErrorMessage(err: string | null): string | null`: `"Signup counts could not be loaded right now."` when set.
- `formatSignups(s: GuideSignupCounts | null): string`: `null` → `'—'`; otherwise `"N signup(s), M confirmed"` (`"1 signup, 1 confirmed"`, `"0 signups, 0 confirmed"`).
- `type ShareSort = 'oldest' | 'newest' | 'clicks' | 'catalog'`; `SHARE_SORTS: {id, label}[]` = Oldest share first, Newest share first, Most clicks, Guide order. `sortShares(rows: GuideShare[], sort: ShareSort): GuideShare[]` is stable and does not mutate its input:
  - `oldest`: never-posted rows first in catalog order, then `last_posted_at` ascending.
  - `newest`: `last_posted_at` descending, then never-posted rows last in catalog order.
  - `clicks`: `clicks` descending, with `null` last.
  - `catalog`: the input order.
- `shareLastPosted(row): string`: `'Never'`, or `formatPacificDateTime(last_posted_at)`.
- `groupPosts(posts: GuidePostRow[], guide: string | null): {active: GuidePostRow[]; posted: GuidePostRow[]}`. First filter by `guide_slug` when `guide` is given. `active` holds every non-posted post, ordered queued, then failed, then scheduled (by `scheduled_at` ascending), then drafts (by `created_at` descending). `posted` is ordered by `posted_at` descending.
- `campaignTotals(posts: GuidePostRow[]): {campaign: string; posts: number; clicks: number | null; signups: GuideSignupCounts | null}[]`. Group posts that have a `short_url` by `campaign_slug`. `clicks` is the sum, or `null` when any post in the group is `null`. `signups` is summed the same way. Sort by campaign descending, so `guides-2026-12` comes before `guides-2026-11`.
- `postResultRows(posts, topics)`: one row per post that has a `short_url`. Row fields are the guide title (looked up from `topics`, falling back to the slug), channel label, campaign, status words, `posted_at` (or `null`), clicks, signups, and the short URL. Order is newest `posted_at` first, then unposted rows.
- `hasQueued(posts): boolean`. While it is true, the shell refreshes every 5 s.

### Components (thin; every decision calls `guidePosts.ts`)

**`GuidePosts.svelte`** (`{ query }` prop):
- Above the views, a `SubNav label="Guide outreach sections"` with three entries: Recently shared (`adminGuidePostsHash('overview')`), Posts (`'posts'`), and Clicks and signups (`'results'`).
- On mount, it loads `listGuidePosts()` and `getGuidePostsOverview()` with `Promise.allSettled`. Each result has its own load error. A `loadSeq` guard discards stale responses, as `OutreachResults.svelte` does.
- After every mutation it reloads both.
- It polls every 5 s while `hasQueued`, and clears the timer in the `$effect` cleanup.
- It keeps one persistent `<p class="status" role="status">` that is rendered unconditionally and whose text changes. The text shows loading, then action results ("Draft created.", "Scheduled.", …), then `clicksErrorMessage` and `signupsErrorMessage`. A failed load is an `{#if}` `<p class="text-error" role="alert">`.
- Dialogs all use `OutreachConfirmDialog` (no new `role="dialog"` markup, so the modal guards are satisfied by reuse):
  - **Schedule**: a `datetime-local` input prefilled with `defaultScheduleAt(new Date(), post_hour)` and labelled "Time (Pacific)". Confirm sends `fromLocalInputValue(value)`. A `null` keeps Confirm disabled.
  - **Post now / Retry**: shows the post text and `"This posts to <Label> right away and can't be undone."`
  - **Delete**: `danger`, `"Delete this draft? Its short link stays in ShortLinks."`
  - **Schedule again**: a campaign input prefilled with `suggested_campaign`, validated by `isValidCampaign`, with the text "A new draft with the same text and a new short link."
  - Server errors appear as `asSentence(err.message)` in the dialog's `errorMessage`.
- Unschedule runs without a dialog, because it can be undone.
- Views: `overview` → `GuidePostsOverview`; `posts` → `GuidePostComposer` (open when the `guide` query param is set or "New post" was pressed) plus the `active` and `posted` lists of `GuidePostCard`; `results` → `GuidePostsResults`.
- With `?guide=` set, the Posts view lists only that guide's posts and shows a "Show all guides" link to `adminGuidePostsHash('posts')`.

**`GuidePostsOverview.svelte`**:
- `Panel title="Recently shared"`.
- A `<label>Sort <select>` from `SHARE_SORTS`, defaulting to `oldest`.
- A table with these columns: Guide (title, linking to `url` in a new tab), Last posted (`shareLastPosted`), Channels (labels joined, or "—"), Last campaign (or "—"), Next scheduled (or "—"), Clicks (`formatClicks`), **Signups since first shared** (`formatSignups`; the column header says exactly that), and a "Draft a post" link to `adminGuidePostsHash('posts', slug)`.
- A never-posted row carries a `.never` class (muted "Never" chip) so it stands out.

**`GuidePostComposer.svelte`** (props `topics`, `channels`, `suggestedCampaign`, `initialGuide`, `onCreated`, `onCancel`):
- Controls: a guide `<select>`, channel radio buttons (Bluesky selected by default, with `notConnectedNote` under an unconnected one), a campaign `<input>` prefilled with `suggestedCampaign` (hint shown when `!isValidCampaign`), and a `<textarea>` prefilled with the topic's `default_body`. Changing the guide runs `bodyAfterGuideChange`.
- A live counter `<p>` runs `counterText`. It gets the `.over` class plus the text "Too long for <Label>." when `overLimit`.
- "Create draft" is disabled while the body is over the limit, the body is empty, the campaign is invalid, or a request is in flight.
- It calls `createGuidePost`. On 201 it calls `onCreated(result)`. The shell shows `linkErrorMessage(result.link_error)` when it is set, otherwise "Draft created with short link <short_url>." A 4xx error is shown inline as `asSentence(message)`.

**`GuidePostCard.svelte`** (props `post`, `channel`, `topicTitle`, `onAction(action, post)`, `onSave(post, body)`):
- Header: guide title, channel label, the campaign chip, and `statusLine`. Also `last_error` for a failed post, or a draft returned by the publisher.
- Body: the text in a `<pre class="post-body">`, the short URL (or "No short link yet"), and clicks and signups for posts that have a link.
- Buttons come from `postActions`. A disabled button gets the `notConnectedNote` as text beside it. Do not convey it only through a `title` attribute.
- **Edit** swaps the text for a textarea with the same `counterText` and "Save" / "Cancel". Save is blocked while over the limit. A 422 (for example "the post must keep its short link") shows inline.
- **Open post** is an `<a href={remote_url} target="_blank" rel="noopener">`.

**`GuidePostsResults.svelte`** (props `posts`, `topics`, `channels`, `clicksError`, `signupsError`):
- Two `Panel`s. "By campaign" lists `campaignTotals`: Campaign, Posts, Clicks, Signups. "By post" lists `postResultRows`, with the short link shown as text.
- A short note: "Signups by post count only people who arrived through that post's link. The Recently shared tab counts signups from a guide's page since the guide was first shared." Never call the per-guide number "all signups": the API counts it only from the guide's earliest post onward, so direct-visit signups from before then are left out (`#0659` review).
- When there are no linked posts: "No posts have short links yet."

### Assumptions (user may override)

1. **Tab name "Guide outreach", hash `#/guide-posts`.** The user's 2026-11-14 note calls the section "Guide outreach", so that wins over the older "Guide posts" label. The tab sits in the Events group, right after Outreach.
2. **Three sub-views, "Recently shared" first:** Recently shared, Posts, and Clicks and signups, carried in the hash (`?view=`) like Outreach's sub-views.
3. **The default sort is "Oldest share first", with never-posted guides on top.** The other sorts are newest first, most clicks, and guide order. Sorting uses a dropdown, not clickable column headers, which keeps the table simple on a phone.
4. **"Draft a post" opens the Posts tab with that guide chosen and the list filtered to it.** "Show all guides" clears the filter. The **New post** button opens the same form without a guide chosen.
5. **The draft form defaults to Bluesky.** Pick Mastodon with the radio buttons. One draft is one channel. Posting to both means two drafts, each with its own link, as `#0658` requires.
6. **Changing the guide replaces the text only if you haven't edited it.**
7. **The counter is measured the way the server measures it.** Before the link exists, `{link}` counts as a full-length short URL (`https://go.opencircuitsf.com/u/XXXXXXXXXXXX`) and the number shows `≈`. After the link exists, the real URL is counted and the `≈` goes away. Mastodon counts every link as 23. Create and Save are blocked over the limit.
8. **An unconnected channel is a note, not an error.** You can still write and edit drafts. Schedule and Post now are disabled with a "connect it under Settings → Outreach" note and link.
9. **Post now, Retry, Delete and Schedule again ask first, in the in-app dialog. Unschedule does not**, because it can be undone.
10. **The schedule time defaults to tomorrow at the Outreach post hour, in Pacific time,** and the field is labelled Pacific.
11. **Schedule again asks for a campaign, prefilled with this month's `guides-YYYY-MM`.** Leaving it blank uses the default `guide-posts` campaign, the same as the server.
12. **When ShortLinks fails, nothing blocks.** A draft is still created with a warning that its link will be made at schedule or post time. Click counts show "—", with one line explaining why.
13. **Signups:** each guide shows signups from its page **since it was first shared**. The API's window starts at the guide's earliest post (`#0659` review, `8d17fcf6`), so earlier direct visits are not counted, and the column is labelled "Signups since first shared". Each post shows only signups that came through its own link. Both read as "N signups, M confirmed". If the server sends no signup data, the cell shows "—" rather than 0.
14. **Clicks and signups by campaign add up the posts in that campaign.** If any post's count is unknown, the campaign total shows "—" rather than a partial number.
15. **While a post is posting, the page refreshes every 5 seconds** until it finishes.
16. **The page uses the word "campaign".** Outreach's pages avoid it, but here the campaign is something you name, so the word stays.
