# 0098 — The deferral guard catches wholesale un-deferring, not selective un-deferring

## Description

`#0088` closed a timing oracle by moving every branch-dependent write off the request
path onto an async queue, and `TestSubscribe_MutationDeferredDoesNotBlockResponse`
guards that. The guard blocks `Create` and asserts the response returns while `Create`
is still blocked — which catches any change that un-defers the whole job.

**It does not catch un-deferring one branch.** `#0088`'s second reviewer proved this
rather than speculating. Dispatching only the existing-subscriber branches inline:

```go
if findErr == nil { runMutationSynchronously(job) } else { enqueueMutation(job) }
```

left the **entire package green**. The guard blocks `Create`, which is reached only on
`ErrNotFound` — so it never observes `RestartSignup` or `ClaimAlreadySubscribedSend`.

That shape would put the `active` and `pending` member branches back on the request
path, which is exactly the separation `#0088` exists to enforce, and exactly the pair
whose timings the original oracle used: `already active` at 0.63 ms median against
`brand new` at 1.67 ms.

**This is not a defect in shipped code.** The current single `enqueueMutation` call site
hands over the whole job, and the failing shape requires deliberately adding a
conditional dispatch that a diff reviewer would see. It is a gap in the guard, filed so
the guard's limit is written down rather than assumed away.

## Acceptance criteria

- [ ] A second subtest blocks `RestartSignup` for a **seeded pending subscriber** and
      asserts the response returns while it is still blocked — the existing
      `blockingSubscriberStore` already delegates that method, so this is small
- [ ] Consider the same for `ClaimAlreadySubscribedSend` on an already-active
      subscriber, or state why one member-branch case is sufficient
- [ ] **Mutation-proven with the selective revert above** — apply exactly that
      conditional dispatch, watch the new subtest fail, quote the output, revert by
      file copy
- [ ] The existing wholesale-deferral subtest still passes and still fails under the
      original inline reversion — do not trade one coverage shape for the other

## Notes

From `#0088`'s second review, which approved that issue and recommended this follow-up.

One coupling recorded there and worth preserving here: the guard's 2 s bound must stay
**below `mutateJobTimeout`** (`10 * time.Second`, `internal/handlers/subscribe.go:551`).
Under a synchronous revert, `Create` unblocks when that timeout cancels the job context,
so lowering `mutateJobTimeout` below 2 s would make the test quietly vacuous rather than
failing. 5× margin today. Any new subtest inherits the same constraint.

Measured context, so nobody re-derives it: the guard passes **35/35** under load average
291–307, worst sample 0.40 s against the 2 s bound, clean under `-race`.
