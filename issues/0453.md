## Description

    PRICE=cost$(FOO)

loads as `cost)` under `godotenv` and stays literal under systemd's
`EnvironmentFile=`. Neither `#0441`'s original `$VAR` pattern nor `#0450`'s
widened one flags it.

**The cause is a bug in the library, and it is worth understanding before
fixing anything.** `expandVariables` tests `submatch[2] == "("` to detect the
`$(…)` form — but in `expandVarRegex`, group 2 is the **dollar** capture and the
paren is group 3. That branch is therefore unreachable, so `$(FOO` falls through
to ordinary variable expansion and is read as a variable named `FOO`. The
trailing `)` survives, which is why the result is `cost)` rather than `cost`.

Measured by `#0450`'s reviewer, probing `godotenv.Unmarshal` directly rather
than reasoning from the pattern.

## Why it was reported rather than folded into `#0450`

`#0450`'s criteria authorised **one character class** — matching the guard to
what `expandVarRegex` matches. Catching this needs `\(?` admitted into the
pattern, which is a **second judgement call**, and `CLAUDE.md` §8 records
`#0258` buying a bounce per mechanism added past the stated criteria.

It is also pre-existing: `#0450` neither introduced nor worsened it.

## Why it is worth closing

`.env.example` is copied verbatim onto production as
`/etc/opencircuit/config.env` (`#0423`), so both parsers read the same file. A
value silently losing text under one and keeping it under the other is the
**silently-wrong-value** half of this bug class, which is harder to notice than
a boot failure — the service starts, and something downstream is subtly wrong.

## Acceptance criteria

1. The value-shape scan flags `$(…)`-shaped values, naming which parser
   disagrees and what the divergent readings are.
2. **Verify the library behaviour yourself by probing `godotenv.Unmarshal`**,
   not by reasoning from its regex — that is how this was found, and the group
   -numbering bug is exactly the kind of thing a reading of the pattern gets
   wrong. Read the module source via `go list -m -f '{{.Dir}}' github.com/joho/godotenv`, never a filesystem scan (`CLAUDE.md` §5).
3. **Do not touch** the floor (`minScannedEnvExampleAssignments`),
   `checkScannedFloor`, or `scanEnvExampleValueShapes`'s four-shape structure.
   `#0441`'s and `#0450`'s reviews verified all of it sound, including that the
   fail-closed proof passes the package constant rather than a hardcoded number
   — which is why §8's external-harness rule does not apply.
4. Decide whether this is a **fifth shape** or an extension of the existing
   `$VAR` shape, and record which. The failure message should tell an operator
   what to do, and "your `$(…)` is read as a variable" is a surprising enough
   fact to state plainly.
5. Prove it by injecting `cost$(FOO)` into a **copy** of `.env.example` and
   running the real guard — never a duplicated scan, which is a copy of the
   subject agreeing with itself (`#0441`'s review made exactly this point).
   Use a throwaway `git worktree`; never `git stash` (§8a).
6. Consider whether the library bug is worth reporting upstream, and record the
   decision. Do not open anything without the user's say-so.
