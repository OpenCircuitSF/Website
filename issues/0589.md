## Review notes

Opus review, 2026-10-18. Checked items 1 to 6 against the diff and against review findings H1 to H10, J4, §4.4 and §6.

- **Fixed: Print's new tab would have been blocked in Safari.** `printAll` called `window.open(url, '_blank', 'noopener')` after two or three awaits (save, select, generate). By then the click's user gesture has expired, and Safari (and Firefox) block the popup. jsdom has no popup blocker, so the tests could not see this. The fix opens a blank tab synchronously in the click, before the first request. The blank tab says what is happening while it waits. After a full success it sets `opener = null` and points the tab at the print view; the hash is made absolute, because the blank tab's own URL is `about:blank`. On a partial generate or an error it closes the tab. If even the synchronous open is refused, the print view opens in the current tab, since the flyer is already saved.
- **Fixed: preview sheet counts.** They counted the saved selection, so a new flyer showed "0 sheets" beside "Print 2 flyers". They now count the ticked copies (`printCount`).
- **Fixed: a refused Put up left the checkbox flipped.** The checkbox is one-way bound and the view does not change on an error, so the box kept its clicked state. It is now set back, and the status line says why.
- **Tests.** Rewrote the Print tests around a fake tab. They now prove the order `open, update, select, generate` (opened before any request), the absolute URL, `opener` nulled, the tab closed on a partial generate and on both kinds of save failure, and the fallback to the current tab when the open is refused. Added tests for the Put up revert and for the draft sheet counts.
- **Mutation tests** (editor copied aside, sha256 `df8e510a…74a25d` before and after). Deleting the partial-generate stop failed the partial-generate test. Moving `window.open` after `saveAll` failed 3 tests.
- **Item 3, narrow-screen thumbnail: accepted as a deviation.** H2's "collapsed to a thumbnail that expands" was not built. The preview comes first at full size, which puts the form roughly two previews down on a phone. That is better than J4's preview-below-the-form, and it is not a correctness problem. Worth a follow-up.
- **Checked and correct.** New-flyer defaults (H3, H4). Generate is gone and Print is disabled with a visible reason (H1). The links table has its five columns (H5). The print-view count and the screen-only placeholder (H6), with the H11 print view otherwise unchanged. Errors are deferred to blur or submit (H7). The code hint (H8). Undo calls `updateOutreachLocation(id, {active: true})` (H9; no `window.confirm` anywhere). The status paragraph keeps its persistent live region and loses only its margin when empty (H10). `liveRegionGuard.structuralGuard.test.ts` passes. Nothing in §6 regressed.

## Resolution

All six items, SPA only (no Go, no migration, no new endpoint; the editor chains the existing save, select and generate calls).

1. `OutreachFlyerEditor.svelte` `load()`: a new flyer (no selection, no saved photo) starts with the cover image and every active location at one copy; the server already creates `full-photo`, and the preview renders unclicked.
2. The Generate button is gone. **Print N flyers** (`printAll`) saves the design, saves the selection, generates only if a link or QR code is missing, then `window.open`s the full-page print view; each step is named in the role="status" line. A partial generate stops, reports the remaining count and message, and opens nothing. A visible line says why Print is disabled with nothing ticked.
3. The preview is first in the DOM (so first on narrow screens) and `position: sticky` in its own column at 64rem and up. Generated links and Delete moved to the form column. Not done: a collapsible thumbnail on narrow screens; the preview simply comes first at its normal size.
4. Generated links are a table: Location, Code, Short link, QR (thumbnail and Download), Put up (checkbox with the date).
5. `FlyerPrint.svelte`: "The photo could not be loaded for N flyers. They print with a plain tint." and each affected `.photo` is marked `data-photo-missing`, hiding the broken image and showing a screen-only placeholder note on a tint.
6. `OutreachLocations.svelte`: field errors show after blur or on submit (Save is no longer disabled while invalid, so submit can reveal them); the code was already suggested from the name and stays editable until hand-edited, with a "letters, digits and hyphens" hint; Deactivate offers an in-status-line "Undo: reactivate" button (no window.confirm). The empty gap (H10) is the status paragraph's min-height, now removed when empty.
