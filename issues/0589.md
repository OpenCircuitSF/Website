## Resolution

All six items, SPA only (no Go, no migration, no new endpoint; the editor chains the existing save, select and generate calls).

1. `OutreachFlyerEditor.svelte` `load()`: a new flyer (no selection, no saved photo) starts with the cover image and every active location at one copy; the server already creates `full-photo`, and the preview renders unclicked.
2. The Generate button is gone. **Print N flyers** (`printAll`) saves the design, saves the selection, generates only if a link or QR code is missing, then `window.open`s the full-page print view; each step is named in the role="status" line. A partial generate stops, reports the remaining count and message, and opens nothing. A visible line says why Print is disabled with nothing ticked.
3. The preview is first in the DOM (so first on narrow screens) and `position: sticky` in its own column at 64rem and up. Generated links and Delete moved to the form column. Not done: a collapsible thumbnail on narrow screens; the preview simply comes first at its normal size.
4. Generated links are a table: Location, Code, Short link, QR (thumbnail and Download), Put up (checkbox with the date).
5. `FlyerPrint.svelte`: "The photo could not be loaded for N flyers. They print with a plain tint." and each affected `.photo` is marked `data-photo-missing`, hiding the broken image and showing a screen-only placeholder note on a tint.
6. `OutreachLocations.svelte`: field errors show after blur or on submit (Save is no longer disabled while invalid, so submit can reveal them); the code was already suggested from the name and stays editable until hand-edited, with a "letters, digits and hyphens" hint; Deactivate offers an in-status-line "Undo: reactivate" button (no window.confirm). The empty gap (H10) is the status paragraph's min-height, now removed when empty.
