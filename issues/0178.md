## Description

**1. `#0172`'s defect, one layer down — in Go.** `#0172` removed tracker and `CLAUDE.md` citations from admin-facing copy, and both its sweep and its review read **`web/` only**. But `lib/preflight.ts` deliberately owns no code→message table: `parseUnmet` passes the **server's** `message` through untouched. That makes Go strings admin-facing copy, and three of them cite our internal documents:

- `internal/mailing/preflight.go:171` — "…**PRD §6.6** requires a monitored reply address…", rendered in the pre-send checks panel
- `internal/handlers/admin_subscribers.go:553` — "…and **CLAUDE.md §9** refuses to let unsubscribe touch a complained row…"
- `internal/handlers/admin_subscribers.go:728` — the same shape

An admin has read neither document. **CAN-SPAM §7704 in the same family is fine** — a statute is something they can look up; our PRD is not. The `EMAIL_REPLY_TO` / `EMAIL_LIST_DOMAIN` env names are defensible too, being deploy-time codes with no in-SPA affordance.

**2. `demotionExplanation` has no test.** It is not imported by any `*.test.ts`, despite having a real branch (`scheduled_at` present versus the `'an earlier time'` fallback) and being **the only explanation an admin gets for a campaign that was demoted back to draft**.

`#0175`'s review flagged this as the genuine test gap, while explicitly arguing the *opposite* for the physical-address hint: that one should **not** be pinned verbatim, because the refusal is already enforced in three places in Go, and `#0174` exists precisely because a phrase-match test masqueraded as a behavior guard.

## Root cause

Same shape as `#0172`, one layer down. `lib/preflight.ts`'s `parseUnmet`
deliberately owns no code→message table — its doc comment says so — and
passes the server's `message` field through untouched to the pre-send
checks panel. `admin_subscribers.go`'s `Suppress` and `manualAddMessage`
similarly write their `message`/`Message` response fields straight from Go
string literals with no client-side translation layer. That makes any Go
string assigned to those fields admin-facing copy, and three of them said
so by citing `PRD §6.6` or `CLAUDE.md §9` directly — documents describing
*our* reasoning to ourselves, not something an admin has read or can look
up (unlike CAN-SPAM §7704, cited in the neighboring physical-address
message, which they can).

## Fix

Reworded each string to state the fact itself rather than cite where the
fact comes from, and moved the citation to a `//` comment immediately above
the string (mirroring `#0172`'s HTML-comment convention in `.svelte`):

- `internal/mailing/preflight.go:171` — "Reply-To address is not configured
  (EMAIL_REPLY_TO). PRD §6.6 requires a monitored reply address, not
  noreply@." → "Reply-To address is not configured (EMAIL_REPLY_TO). Set it
  to an address someone reads, not noreply@." (`EMAIL_REPLY_TO` kept — it's
  deploy-time configuration with no in-SPA affordance, the same judgment
  `#0175`'s review made).
- `internal/handlers/admin_subscribers.go:553` (`Suppress`'s no-op-on-
  `complained` branch) — "This subscriber has complained, and CLAUDE.md §9
  refuses to let unsubscribe touch a complained row — no status change." →
  "This subscriber has complained. By design, unsubscribing a complained
  row makes no status change — that is enforced, not a glitch." "By design"
  / "enforced, not a glitch" carries the same force the citation used to:
  the refusal is deliberate and absolute, not incidental.
- `internal/handlers/admin_subscribers.go:728` (`manualAddMessage`,
  `StatusComplained` branch) — "This address has previously complained and
  CLAUDE.md §9 refuses to auto-resubscribe it. Nothing was sent." → "This
  address has previously complained. By design, adding it here does not
  resubscribe it. Nothing was sent." Same force, same absence of a
  bypassable-sounding reading.

**`demotionExplanation` test** (criterion 4): added a `describe

3. the message says sending was refused and the campaign is in draft;
4. the message does not name an internal component ("worker") as the agent

5. the message points at the checks panel as the actionable next step.

**Other untested `web/src/lib/` copy functions reaching admins**

### The three rewrites, judged on force rather than on citation removal

1. **`preflight.go`'s reply-to message** — "Reply-To address is not
   configured (EMAIL_REPLY_TO). Set it to an address someone reads, not
   noreply@." **Accurate, and more actionable than what it replaced.** PRD
   §6.6's requirement is literally "`Reply-To` is a monitored human address,
   not `noreply@`", so "an address someone reads, not noreply@" restates the
   requirement rather than paraphrasing it loosely. Note the gate itself only
   tests `strings.TrimSpace(in.ReplyTo) == ""` — it cannot detect a
   *configured* `noreply@` — but the new sentence is an imperative ("set it
   to…"), not a claim about what the server will reject, so it does not
   over-promise. Keeping `EMAIL_REPLY_TO` is the right call and matters more
   here than in the physical-address case: `preflight.ts`'s `fixLocation`
   returns a section only for `physical_address_missing` and `null` for
   everything else, so `reply_to_missing` has **no in-SPA affordance at all**
   and the env-var name is the entire actionable fact. The old text's "PRD
   §6.6 requires…" added nothing an admin could act on.
2. **`Suppress`'s `complained` branch** — "This subscriber has complained. By
   design, unsubscribing a complained row makes no status change — that is
   enforced, not a glitch." **Keeps the first half of §9's rule; drops the
   second.** "By design" and "enforced, not a glitch" do carry that the
   refusal is deliberate and absolute — there is no reading on which it is
   incidental or bypassable, which is criterion 2's actual text, and the
   response's own `no_op: true` is separately pinned by
   `TestAdminSubscribers_Suppress_ComplainedRowIsNoOp`. What the sentence
   does **not** say is *what would* change the state. The "Use \"Clear
   complaint\" first…" pointer is appended only in the `else` branch
   (`suppressionAdded == false`), i.e. only when `h.suppressions` is nil —
   dev/test wiring. On the production path the admin reads the refusal with
   no exit named. Mitigating, and why this is not a bounce: the string it
   replaced said no more, so nothing regressed; and `Admin.svelte:1596`
   renders a **Clear complaint** button on the very row the modal is open
   over, gated on `canClearComplaint`, so the affordance is on screen even
   though the copy does not name it.
3. **`manualAddMessage`'s `StatusComplained` branch** — "This address has
   previously complained. By design, adding it here does not resubscribe it.
   Nothing was sent." Same ruling on force, and "Nothing was sent" is a real
   improvement: it forecloses the "maybe a confirmation went out anyway"
   reading that the pending/active branches would otherwise invite. The
   second-half gap is slightly sharper here than in (2), because this message
   lands in `createSubNotice` on the manual-add form (`Admin.svelte:790`),
   not on a subscriber row, so no **Clear complaint** button is adjacent.
   Still accurate and still absolute; reported below rather than bounced.

Both `complained` rewrites are accurate about the underlying behavior:
`Unsubscribe`'s only no-op case is a complained row, the suppression-list
write happens regardless (and the message says so), and
`admin_subscribers_test.go:886` already pins that manual add never moves a
complained address off that status.

### The Go-side sweep, re-run on a structural axis

The implementer's method was a grep census — `message`/`Message` literals and
`writeError(...)` arguments across four packages, plus a whole-tree grep for
citation patterns inside quoted strings. Thorough within its method, but a
grep census cannot tell you which fields a client actually renders. So the
axis tried here was the opposite one: **start at the SPA and trace backwards
to every Go string that can reach a user.**

- **The render path.** `api.ts`'s `request()` collapses every non-2xx body to
  `ApiError.message = err?.error ?? err?.message ?? \`HTTP ${status}\``, and
  ~25 call sites across `Admin.svelte`, `Campaigns/CampaignEditor/
  CampaignStats/WorkshopEditor/Workshops.svelte`, `Login`, `RecoverVerify`,
  `RegisterVerify` and `PreferenceCenter` render that string verbatim. On the
  success side three more fields render raw: `res.message` in
  `PreferenceCenter.svelte:157,180`, `Admin.svelte:711` (`suppressError`) and
  `Admin.svelte:790` (`createSubNotice`), plus `parseUnmet`'s per-entry
  `message` in the checks panel / `CampaignSendDialog.svelte:99`. So the
  surface is **any `{"error": …}` body and any response struct with a
  `message`/`Message` JSON field, from any package that writes an HTTP body.**
- **Which packages write HTTP bodies at all.** Only three:
  `internal/handlers` (all of it via `writeError`/`writeJSON`),
  `internal/middleware` (`auth.go:166` writes `{"error":"<code>"}` by hand;
  `ratelimit.go` writes `rate_limit_exceeded`), and `internal/seo`
  (`site.go:85`, plain-text `http.Error`, non-SPA). `internal/auth`,
  `internal/events`, `internal/interests`, `internal/subscribers`,
  `internal/workshops` and `internal/sesnotify` **never write a response
  body** — they return values and sentinel errors to handlers. So none of the
  four packages the sweep omitted contributes rendered copy by that route.
  Middleware's contributions are machine codes, not prose, and cite nothing.
- **The one leak path that crosses a package boundary** — `err.Error()`
  interpolated into an admin-facing message. Exactly three non-test sites:
  `admin_workshop_preview.go:87` and `admin_campaign_preview.go:314,383`,
  all of the form `"… body does not render: " + err.Error()` over a goldmark
  render error. (`health.go:56` also embeds `err.Error()`, but `/health` is
  an ops endpoint the SPA never reads.) The two error-mapper funcs
  `audienceErrorMessage` and `campaignAudienceErrorMessage` switch on
  sentinels and return fixed strings — no leakage. Nothing here cites an
  internal document.
- **The field the grep axis could not see, and it is one criterion 3 names.**
  `failed_sends[].error` is a literal API `error` field, rendered per-row in
  `CampaignStats.svelte`'s failed-sends list — but its value is not a
  handler literal at all. It is written into `email_sends.error` by
  `internal/mailing/worker.go` through `MarkFailedRow`/`MarkRetryOrFailed`,
  from three sources: the literal `"empty manage token from eligibility
  recheck"` (`worker.go:671`), `rerr.Error()` from the campaign renderer
  (`worker.go:686`), and `sendErr.Error()` from the SES mailer
  (`worker.go:735,739`). Neither a `message`/`Message` literal nor a
  `writeError(...)` argument, so no amount of care with that grep would have
  surfaced it. **No citation defect there** — so `#0178`'s conclusion stands
  — but `"empty manage token from eligibility recheck"` is squarely `#0175`'s
  family: implementation vocabulary ("eligibility recheck", "manage token")
  shown to an admin as the explanation for a failed send. Reported below.
- **Independent whole-tree citation check.**
  `grep -rnE '"[^"]*(CLAUDE\.md|PRD §|#0[0-9]{3}|Issues\.md|HANDOFF)[^"]*"'`
  over every non-test `.go` under `internal/` and `cmd/`: six hits, **all
  inside `//` comments** (`seo/jsonld.go:168`, `seo/workshop.go:66`,
  `handlers/subscribe.go:296,807`, `handlers/ses_notifications.go:13`; the
  `mailing/templates.go:47` hit is the hex colour `#04140a`). The
  `see #0082/#0083/#0148` strings in `internal/db` are `t.Fatalf` messages in
  `docs_parity_test.go` / `prd_index_parity_test.go` — developer-facing,
  correctly out of scope. The same check over `web/src` returns only
  comments plus the new test's own describe label. Criterion 3's conclusion
  is confirmed on a wider axis than it used.

### `demotionExplanation`'s new test — mutated, not just read

Five mutations of `campaigns.ts`, each run alone against
`campaigns.test.ts -t demotionExplanation`; **each killed exactly one
assertion and no others**, so nothing in the block is vacuous and nothing
overlaps:

| Mutation | Assertion killed |
|---|---|
| fallback returns `'2026-01-01'` instead of `'an earlier time'` | *falls back to unformatted wording* — `expected true to be false` at `/\d{4}/` |
| `when` uses the raw ISO string instead of `formatDateTime` | *names the scheduled time* |
| drop "sending was refused" | *says sending was refused and the campaign is back in draft* |
| restore "the send worker refused it" | *does not name an internal component (CLAUDE.md §9)* |
| drop "The checks below are its current state." | *points at the checks panel* |
| "it was returned to draft" → "it is still scheduled" | *says … back in draft* |

The absence-based fallback assertion — the one worth doubting — is **not**
vacuously true: it fails the moment the fallback emits anything date-shaped.
Its residual limit is the honest one, that it constrains what the fallback
must *not* contain rather than what it must say, so replacing `'an earlier
time'` with `''` would still pass. That is the deliberate trade for not
phrase-pinning (`#0174`), and the branch's actual defect mode — leaking a
formatted or raw timestamp when there is no timestamp — is covered. The
`'scheduled_at' in c` guard at the top of that case is a good touch: it
proves the fixture really exercises the fallback rather than silently
passing a present-but-falsy value. All assertions are `toContain` /
`not.toContain` / regex over lower-cased output, semantic per `#0174`.

### Should any of these three strings now be test-pinned?

**No test pins them — confirmed by mutation, not by grep.** All three were
replaced with `MUTATED-COPY-XYZ` simultaneously and
`ISSUE=0178rev2 scripts/check.sh go ./internal/mailing/... ./internal/handlers/...`
still reported both packages `ok`. The implementer's claim is exact.

`#0175`'s reasoning against pinning the physical-address hint **does apply**
to all three, and for the same reason: the behavior each string describes is
already pinned in Go, so a string equality would assert only that a sentence
is a sentence. `preflight_test.go:56,124` pins
`PreflightCodeReplyToMissing`'s presence and its position in the fixed
ten-code order; `TestAdminSubscribers_Suppress_ComplainedRowIsNoOp` pins both
`no_op: true` and the unchanged status; `admin_subscribers_test.go:886` pins
that manual add leaves a complained address complained. §9's rule is guarded
by tests either way.

But there is a property those behavior tests cannot guard, and it is the one
that has now recurred three times (`#0172` → `#0175` → `#0178`): **whether a
rendered string cites a document only we can read.** That is a property of
the copy, not of the behavior, and no amount of behavior pinning reaches it.
The defensible guard is class-level, not per-string — one assertion that no
admin-facing message literal contains `CLAUDE.md`, `PRD §`, or `#0NNN` —
which is cheap, phrase-agnostic, and would have failed at `#0172` rather than
waiting for a third sweep on a fourth axis. Reported below.

### Worth filing (reported, not filed — `CLAUDE.md` §9)

1. **`worker.go:671`'s `"empty manage token from eligibility recheck"`
   renders to admins verbatim** in `CampaignStats.svelte`'s failed-sends
   list, via `email_sends.error` → `failed_sends[].error`. Pure
   implementation vocabulary — `#0175`'s defect class on a surface neither
   `#0172`, `#0175` nor `#0178` swept. The two neighbouring writes
   (`rerr.Error()`, `sendErr.Error()`) put raw goldmark and AWS SDK error
   text on the same screen, which is arguably fine as diagnostics but has
   never been read as copy.
2. **A class-level citation guard.** One table-driven assertion that no
   admin-facing message literal contains `CLAUDE.md`, `PRD §`, or `#0NNN`
   would close the loop that `#0172`/`#0175`/`#0178` have each half-closed
   from a different direction. Cheap, and not the phrase-pinning `#0174`
   warns against — it constrains a class, not a wording.
3. **The `complained` messages name no exit.** Neither rewrite tells an
   admin that clearing the complaint is the only thing that moves the row,
   and `Suppress` appends its "Use \"Clear complaint\" first" pointer only on
   the `h.suppressions == nil` path, which production never takes. Pre-
   existing (the strings replaced said no more) and mitigated on the
   subscriber row by the adjacent **Clear complaint** button, but not
   mitigated at all on the manual-add form.
