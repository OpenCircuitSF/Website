## Description

`PATCH /admin/campaigns/{id}` accepts a `slug`, rejecting a taken one and
refusing edits once the campaign is past editable. **No admin view binds it.**

Verified: `web/src/views/admin/Campaigns.svelte` contains no occurrence of
`slug` at all, and `CampaignEditor.svelte`'s only two occurrences are a comment
explaining that the slug is reserved at draft time. `CampaignDraftFields` has no
slug field. So the override is reachable by an API client and by nothing an
operator actually uses.

### Why this matters more than it looks

The archive URL is **minted at draft time and published in the email** — PRD §6.8
calls that load-bearing, because promotion has to be written against a URL that
already exists. A slug is therefore chosen early, from the subject, before the
subject has settled.

[#0405](0405.md)'s plan makes the override **the escape hatch its whole design
rests on**: it chose opt-in over inference precisely because forgetting the
opt-in is *loud and reversible* — you see `open-circuits-sf-september-2026` in
the editor and fix it. **That repair path does not exist in the console.**

There is also no `DELETE /admin/campaigns/{id}` ([#0411](0411.md)), so a stray
duplicate draft holds its slug permanently with no console-reachable repair at
all — it cannot be re-slugged and it cannot be removed.

## Fix

**No Go code changed.** `PATCH /admin/campaigns/{id}` already accepted `slug`
and already enforced every rule criterion 2/3/5 require
(`ErrCampaignSlugTaken`, `ErrCampaignSlugNotEditable`,
`ErrCampaignNotEditable`, the savepoint-based collision handling) — the gap
was entirely that no admin view sent the field. This is the UI-only change
criterion 6 describes.

`web/src/lib/campaigns.ts` gains three pure helpers (#0094 — the component
stays thin):

- `canEditCampaignSlug(status)` — an offer gate mirroring
  `ErrCampaignSlugNotEditable`'s own rule (`status === 'draft'`),
  deliberately **stricter** than `canEditCampaign` (`draft` or `scheduled`):
  the archive URL is already promised to whatever promotion was prepared
  before a scheduled send goes out, so the slug locks a step earlier than
  the rest of the editor does.
- `validateSlugInput(slug)` — the client-side mirror of
  `admin_campaigns.go`'s own `strings.TrimSpace(*req.Slug) == ""` check
  (criterion 4). Rejects blank/whitespace only; it invents no character-shape
  restriction beyond that, since the column's own `CHECK` (migration 000025)
  imposes none and criterion 5 forbids a second rule.
- `slugFieldGuidance(status, slug)` — the field's helper message/tone,
  combining the two: a blank buffer's error takes priority over the
  not-editable note, so an operator who reaches a blank buffer always sees
  why saving it would fail rather than a generic reserved-until-draft aside.

`web/src/lib/api.ts`'s `CampaignDraftFields` gains `slug?: string`, documented
as PATCH-only — the mirror image of `#0405`'s `newsletter_month`, which is
POST-only. `createCampaignRequest` has no `slug` field, so `decodeJSON`'s
`DisallowUnknownFields` means sending it through `createCampaign` would 400
outright, not silently ignore it; `Campaigns.svelte`'s create-modal flow
never sets it, unchanged by this issue.

`web/src/views/admin/CampaignEditor.svelte` gains an editable "Archive slug"
field, bound to its own buffer (`slug`, initialized from `campaign.slug` in
`load()`, mirroring how `name`/`subject`/`bodyMd` already survive a
background resync per `resyncCampaignStatus`'s own doc comment). It autosaves
on the same 2s-idle/blur schedule as every other field. Disabled whenever
`canEditCampaignSlug(campaign.status)` is false; its helper text is
`slugFieldGuidance`'s message verbatim, styled with the existing
`length-advice`/`.warn`/`.over` classes `subjectLengthAdvice`/
`preheaderLengthAdvice` already use.

The existing read-only "Archive URL" field now computes its preview from the
**live edit buffer** (`archiveURL(window.location.origin, { slug })`) instead
of the saved `campaign.slug`, so the URL shown updates as the operator types
— criterion 1's "the archive URL it produces is shown so the effect is
obvious before saving." This does not reopen the anti-drift concern #0405's
plan raised about the newsletter checkbox (the client must never *format* a
slug itself): `archiveURL` is the exact same pure function already used for
the saved value, called here with the buffer instead of the campaign object —
one formatter, one source of truth, unchanged.

**Collision and already-sent handling — decided by the acceptance criteria,
not invented here:**

- **Collision** (criterion 2): the server's savepoint-based `UNIQUE`
  contention is untouched; a taken slug returns 409
  (`ErrCampaignSlugTaken` → "that slug is already in use"). The editor does
  not pre-check availability — the same "operator asked for THIS exact slug,
  so tell them it's taken, don't silently substitute one" reasoning
  `ErrCampaignSlugNotEditable`'s doc comment already states for `Update`.
- **Already past editable state** (criterion 3): mirrored exactly via
  `canEditCampaignSlug`/`disabled`, backed by the server's independent
  `ErrCampaignSlugNotEditable` (409 → "a campaign slug can only be changed
  while it is a draft") regardless of what the client offers (CLAUDE.md §9).
  `saveDraft` also falls back to `campaign.slug` (the current saved value)
  whenever the live buffer fails `validateSlugInput`, so an invalid buffer is
  never sent even if some future caller re-enables the field incorrectly.
- **Already-sent slug question — left open, reported rather than invented.**
  Neither the acceptance criteria nor `#0405`'s plan describe what happens to
  an already-delivered email's archive link if the slug is somehow changed
  after `sent` — and the server already forecloses this from the reachable
  side: `Update` refuses any content edit, slug included, once status leaves
  `draft`/`scheduled` (`ErrCampaignNotEditable`), and refuses a slug change
  specifically once status leaves `draft` (`ErrCampaignSlugNotEditable`,
  checked before the general edit is even attempted). So a `sent` campaign's
  slug cannot be changed through any reachable path today, console or API,
  and this issue does not change that. Worth a line in a reviewer's or a
  future issue's notes only if that invariant is ever relaxed — no redirect
  scheme is needed while it holds.

No character-restriction beyond blank/whitespace was added to the slug field,
matching the column's own `CHECK (btrim(slug) <> '')` — anything narrower
would be inventing a second rule, which criterion 5 forbids.

## Acceptance criteria

1. An operator can see and edit a draft campaign's slug in the admin console,
   and the archive URL it produces is shown so the effect is obvious before
   saving.
2. A taken slug and an uneditable campaign both surface as **clear errors**, not
   silent no-ops — the API already returns distinct errors for each; do not
   collapse them.
3. **The field is not editable once the campaign is past editable state.** The
   URL is published in sent email; changing it later breaks a live link. Mirror
   whatever the API already enforces rather than inventing a second rule.
4. The blank/whitespace case is rejected client-side as well as server-side —
   the column carries a not-blank `CHECK`, and a 500 from a constraint is not an
   acceptable UI.
5. Do not weaken the server: the savepoint-based collision handling and the
   existing `PATCH` guards stay exactly as they are. This is a UI change.
6. `(cd web && npm run check)` and `(cd web && npm test)`. If any Go comment or
   a file cited by one changes, run `./internal/handlers/...` (§5's
   repo-wide-guard table). Per §5 name the specific tests that ran.

## Review notes

**Verdict: pass.** Reviewed `095e28d` (5 files, 417 insertions / 3 deletions).
Every acceptance criterion is met, the two claims the pass rests on were
re-derived independently rather than taken from the `## Fix`, and both hold.

### What the server actually permits, versus what the console now offers

Re-derived from the store and the handler rather than from this issue's text.
`mailing.CampaignStore.Update` applies two gates, in this order:

1. `current.Status` not in {`draft`, `scheduled`} → `ErrCampaignNotEditable`.
2. Only then: `slug != current.Slug && current.Status != draft` →
   `ErrCampaignSlugNotEditable`. An **unchanged** slug is accepted at any
   status that clears gate 1, and an empty `in.Slug` is coerced to
   `current.Slug` before the comparison.

So the server permits a slug **change** in `draft` and nowhere else.
`canEditCampaignSlug(status) === 'draft'` is therefore an **exact mirror of
the server's slug rule**, not a tightening of it — criterion 3 asks for
precisely that ("mirror whatever the API already enforces rather than
inventing a second rule"), and this does. The `## Fix`'s word "stricter" is
accurate but is measured against `canEditCampaign` (the *general* editor gate,
draft-or-scheduled), not against the server's slug rule; read against the
server there is no gap in either direction. The concern that the console might
withhold the escape hatch while the API still allowed it does not arise: at
`scheduled` the API refuses a changed slug too, with a 409.

The escape hatch is therefore available exactly where repair is possible.
`#0405`'s design need is satisfied — a forgotten newsletter template is
fixable for as long as the campaign is a draft, which is the whole window in
which the server would accept the fix.

Verdict on the draft-only gate: **correct, and not a tightening.** Keep it.

### The already-sent claim — verified, not accepted

The `## Fix` claims a `sent` campaign's slug "cannot be changed through any
reachable path today, console or API". Checked directly rather than inferred,
by walking every write to the column instead of every handler:

- An AST-free byte scan of all non-test Go under `internal/` for
  `UPDATE email_campaigns` / `INSERT INTO email_campaigns` finds **13 write
  statements** (plus one occurrence inside a doc comment in
  `internal/mailing/preflight.go`, which is prose, not a statement), of which
  exactly **two mention `slug`**: `Create`'s `INSERT` and `Update`'s `UPDATE`,
  both in `internal/mailing/campaigns.go`. The other eleven — four more in
  that same file and six in `internal/mailing/worker_store.go` for the worker's
  status claims, `CompleteIfDone`, `failCampaign`, the delivery-health pause,
  `materialized_at` and `test_sent_at`, plus `SetArchiveStatus` in
  `internal/mailing/campaign_archive.go` — never name the column, so they
  cannot move it.
- `mailing.CampaignUpdate` has exactly **one** caller in the tree:
  `AdminCampaignsHandler.Patch` in `internal/handlers/admin_campaigns.go`. No
  other handler, command, or worker constructs one.
- `internal/devstore` has no campaign implementation at all — the only
  occurrence of the word is a comment saying the fake is not built yet — so
  the `STORAGE=json` path cannot reach the column either.
- For a `sent` campaign, gate 1 above fires **before** the slug branch is even
  evaluated, so `ErrCampaignSlugNotEditable` is not what protects it;
  `ErrCampaignNotEditable` is, and it is unconditional.

The claim holds as written, and this change does not widen it. No redirect
scheme is needed while that invariant stands, and the `## Fix` recording it as
an invariant rather than inventing one is the right call.

### A colliding slug does produce a distinguishable message on screen

Traced the whole path rather than assuming the generic catch reaches the
template:

`ErrCampaignSlugTaken` → `Patch` maps it to `writeError(409, "that slug is
already in use")` → `writeError` emits `{"error": <message>}` → `api.ts`'s
`request` builds `const message = err?.error ?? err?.message ?? "HTTP " +
status` and throws `new ApiError(status, message, parsed)` → `saveDraft`'s
catch sets `saveError = err instanceof ApiError ? err.message : …` → the
template renders `<p class="text-error" role="alert">{saveError}</p>`.

The operator sees the server's own sentence, in an alert-role live region.
The sibling error is a different sentence ("a campaign slug can only be
changed while it is a draft"), so the two 409s stay distinct all the way to
the screen — criterion 2's "do not collapse them" is satisfied for the right
reason, not by luck. The generic fallback only takes over for a non-`ApiError`
throw (a network failure), which is the correct place for a generic message.

### The preview tracks the live buffer

`archiveURLValue` is `campaign ? archiveURL(window.location.origin, { slug })
: ''`, where `slug` is the `$state` edit buffer, not `campaign.slug`. It is
the same one pure `archiveURL` function that formatted the saved value, given
the buffer instead of the campaign object — so there is still exactly one
formatter and the client never assembles a URL itself. The `$derived` settles
synchronously, so the URL moves with each keystroke. Criterion 1's "shown so
the effect is obvious before saving" is met, and `#0405`'s anti-drift concern
(the client must never *format* a slug) is not reopened, because nothing here
formats anything.

### Component wiring — no assertion required to resolve; one recommended as a follow-up

The nine new tests are pure and correct, and `canEditCampaignSlug`'s
exhaustive loop over `CAMPAIGN_STATUSES` is the right shape (it cannot go
stale when a status is added). They are also, as the phase-3 brief anticipated,
silent about whether the component uses any of them.

I read the wiring instead, and all three legs are present and correct: the
input is `bind:value={slug}` with `disabled={!slugEditable}`; the buffer is
seeded in `load()` and deliberately not touched by `resyncCampaignStatus`; and
`saveDraft` sends `slug: slugToSend` in the `updateCampaign` payload.

I am **not** requiring a structural guard as a condition of resolving, for
three reasons: there is no present defect; the repo's own precedent adds
`.svelte` structural guards reactively, after a review finds a silent failure
(see the header comments of `web/src/lib/modalFocusWiring.structuralGuard.test.ts`
and `web/src/views/admin/CampaignSendDialog.guard.test.ts`), rather than
prophylactically per field; and the user needs this escape hatch for the first
newsletter now.

But the residual risk is worth recording, because this change made one
regression shape *less* visible than it was before. If a future edit drops
`slug: slugToSend` from `saveDraft`'s payload, the field still accepts typing,
autosave still reports "Saved", and — because the preview now reads the buffer
rather than the persisted campaign — the URL shown still updates to the value
that was never stored. The feature becomes a convincing no-op, discoverable
only by visiting the archive URL. Nothing in the tree would catch it: no test
mounts `CampaignEditor.svelte` (it is named in
`modalFocusWiring.structuralGuard.test.ts`'s own comment as too large and too
network-dependent to mount cheaply), and `STORAGE=json` has no mailing
subsystem, so no dev run exercises it either. The sole evidence that the
escape hatch works is one reviewer reading a template — which is exactly the
gap `#0181`/`#0197`/`#0120` exist to close elsewhere.

**Recommended for filing** (not filed here — CLAUDE.md §9; `#0443` is the
highest allocated): a structural guard, modelled on
`web/src/lib/modalFocusWiring.structuralGuard.test.ts`, that parses
`web/src/views/admin/CampaignEditor.svelte` with `svelte/compiler` and asserts
the three wirings below. AST over the parsed source, not regex over raw text,
so a comment or a string literal cannot satisfy it:

1. The `updateCampaign(…)` call's object argument has a `slug` property — the
   leg whose loss is silent.
2. `archiveURLValue`'s initializer passes the `slug` identifier, not a
   `campaign` member expression, to `archiveURL`.
3. The input with `id="campaign-slug"` carries a `disabled` attribute whose
   expression reads `slugEditable`.

Assertion 1 is the load-bearing one; 2 and 3 are cheap once the AST is parsed.

### Smaller observations, none blocking

- **A stale enumeration.** `resyncCampaignStatus`'s doc comment still lists the
  buffers it deliberately does not clobber as
  "name/subject/preheader/bodyMd/mode/interestIds" — `slug` is now a seventh
  and belongs in that list. The behaviour is correct (the function assigns only
  `campaign`); it is the comment that is now one short. Worth a one-word fix
  the next time that file is opened.
- **The trim is applied even when the field is disabled.** `saveDraft` sends
  `slug.trim()` unconditionally. The column's `CHECK` is `btrim(slug) <> ''`,
  which permits a stored value with surrounding whitespace, so a hypothetical
  padded slug on a *scheduled* campaign would be trimmed by the client, differ
  from the stored value, and 409 every autosave. Unreachable in practice —
  `Create` slugifies and `Patch` trims, so no write path can store padding —
  and the fallback to `campaign.slug` when `slugEditable` is false would be the
  tidier expression of "unchanged". Recorded, not required.
- **Clearing the field reads oddly.** A blank buffer shows the `over`-toned
  "Archive slug cannot be blank." while the save nonetheless succeeds (the rest
  of the form saves, and the slug falls back to the stored value), so "Saved"
  and an error-toned message appear together, over a preview showing a bare
  `/archive/`. The trade is deliberate and defensible — blocking the whole
  autosave on one invalid field would strand the name, subject, and body — and
  criterion 4 asks only that the blank case be rejected client-side, which it
  is, before any request is sent. Noted so the next reader does not read it as
  a bug.
- **The copy button now copies the unsaved buffer's URL.** A direct and
  intended consequence of criterion 1; with a 2s autosave the window is small.
