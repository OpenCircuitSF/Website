## Description

`PATCH /admin/campaigns/{id}` accepts a `slug`, rejecting a taken one and
refusing edits once the campaign is past editable. **No admin view binds it.**

Verified: `web/src/views/admin/Campaigns.svelte` contains no occurrence of
`slug` at all, and `CampaignEditor.svelte`'s only two occurrences are a comment
explaining that the slug is reserved at draft time. `CampaignDraftFields` has no
slug field. So the override is reachable by an API client and by nothing an
operator actually uses.

### Why this matters more than it looks

The archive URL is **minted at draft time and published in the email** — PRD §6.8
calls that load-bearing, because promotion has to be written against a URL that
already exists. A slug is therefore chosen early, from the subject, before the
subject has settled.

[#0405](0405.md)'s plan makes the override **the escape hatch its whole design
rests on**: it chose opt-in over inference precisely because forgetting the
opt-in is *loud and reversible* — you see `open-circuits-sf-september-2026` in
the editor and fix it. **That repair path does not exist in the console.**

There is also no `DELETE /admin/campaigns/{id}` ([#0411](0411.md)), so a stray
duplicate draft holds its slug permanently with no console-reachable repair at
all — it cannot be re-slugged and it cannot be removed.

## Fix

**No Go code changed.** `PATCH /admin/campaigns/{id}` already accepted `slug`
and already enforced every rule criterion 2/3/5 require
(`ErrCampaignSlugTaken`, `ErrCampaignSlugNotEditable`,
`ErrCampaignNotEditable`, the savepoint-based collision handling) — the gap
was entirely that no admin view sent the field. This is the UI-only change
criterion 6 describes.

`web/src/lib/campaigns.ts` gains three pure helpers (#0094 — the component
stays thin):

- `canEditCampaignSlug(status)` — an offer gate mirroring
  `ErrCampaignSlugNotEditable`'s own rule (`status === 'draft'`),
  deliberately **stricter** than `canEditCampaign` (`draft` or `scheduled`):
  the archive URL is already promised to whatever promotion was prepared
  before a scheduled send goes out, so the slug locks a step earlier than
  the rest of the editor does.
- `validateSlugInput(slug)` — the client-side mirror of
  `admin_campaigns.go`'s own `strings.TrimSpace(*req.Slug) == ""` check
  (criterion 4). Rejects blank/whitespace only; it invents no character-shape
  restriction beyond that, since the column's own `CHECK` (migration 000025)
  imposes none and criterion 5 forbids a second rule.
- `slugFieldGuidance(status, slug)` — the field's helper message/tone,
  combining the two: a blank buffer's error takes priority over the
  not-editable note, so an operator who reaches a blank buffer always sees
  why saving it would fail rather than a generic reserved-until-draft aside.

`web/src/lib/api.ts`'s `CampaignDraftFields` gains `slug?: string`, documented
as PATCH-only — the mirror image of `#0405`'s `newsletter_month`, which is
POST-only. `createCampaignRequest` has no `slug` field, so `decodeJSON`'s
`DisallowUnknownFields` means sending it through `createCampaign` would 400
outright, not silently ignore it; `Campaigns.svelte`'s create-modal flow
never sets it, unchanged by this issue.

`web/src/views/admin/CampaignEditor.svelte` gains an editable "Archive slug"
field, bound to its own buffer (`slug`, initialized from `campaign.slug` in
`load()`, mirroring how `name`/`subject`/`bodyMd` already survive a
background resync per `resyncCampaignStatus`'s own doc comment). It autosaves
on the same 2s-idle/blur schedule as every other field. Disabled whenever
`canEditCampaignSlug(campaign.status)` is false; its helper text is
`slugFieldGuidance`'s message verbatim, styled with the existing
`length-advice`/`.warn`/`.over` classes `subjectLengthAdvice`/
`preheaderLengthAdvice` already use.

The existing read-only "Archive URL" field now computes its preview from the
**live edit buffer** (`archiveURL(window.location.origin, { slug })`) instead
of the saved `campaign.slug`, so the URL shown updates as the operator types
— criterion 1's "the archive URL it produces is shown so the effect is
obvious before saving." This does not reopen the anti-drift concern #0405's
plan raised about the newsletter checkbox (the client must never *format* a
slug itself): `archiveURL` is the exact same pure function already used for
the saved value, called here with the buffer instead of the campaign object —
one formatter, one source of truth, unchanged.

**Collision and already-sent handling — decided by the acceptance criteria,
not invented here:**

- **Collision** (criterion 2): the server's savepoint-based `UNIQUE`
  contention is untouched; a taken slug returns 409
  (`ErrCampaignSlugTaken` → "that slug is already in use"). The editor does
  not pre-check availability — the same "operator asked for THIS exact slug,
  so tell them it's taken, don't silently substitute one" reasoning
  `ErrCampaignSlugNotEditable`'s doc comment already states for `Update`.
- **Already past editable state** (criterion 3): mirrored exactly via
  `canEditCampaignSlug`/`disabled`, backed by the server's independent
  `ErrCampaignSlugNotEditable` (409 → "a campaign slug can only be changed
  while it is a draft") regardless of what the client offers (CLAUDE.md §9).
  `saveDraft` also falls back to `campaign.slug` (the current saved value)
  whenever the live buffer fails `validateSlugInput`, so an invalid buffer is
  never sent even if some future caller re-enables the field incorrectly.
- **Already-sent slug question — left open, reported rather than invented.**
  Neither the acceptance criteria nor `#0405`'s plan describe what happens to
  an already-delivered email's archive link if the slug is somehow changed
  after `sent` — and the server already forecloses this from the reachable
  side: `Update` refuses any content edit, slug included, once status leaves
  `draft`/`scheduled` (`ErrCampaignNotEditable`), and refuses a slug change
  specifically once status leaves `draft` (`ErrCampaignSlugNotEditable`,
  checked before the general edit is even attempted). So a `sent` campaign's
  slug cannot be changed through any reachable path today, console or API,
  and this issue does not change that. Worth a line in a reviewer's or a
  future issue's notes only if that invariant is ever relaxed — no redirect
  scheme is needed while it holds.

No character-restriction beyond blank/whitespace was added to the slug field,
matching the column's own `CHECK (btrim(slug) <> '')` — anything narrower
would be inventing a second rule, which criterion 5 forbids.

## Acceptance criteria

1. An operator can see and edit a draft campaign's slug in the admin console,
   and the archive URL it produces is shown so the effect is obvious before
   saving.
2. A taken slug and an uneditable campaign both surface as **clear errors**, not
   silent no-ops — the API already returns distinct errors for each; do not
   collapse them.
3. **The field is not editable once the campaign is past editable state.** The
   URL is published in sent email; changing it later breaks a live link. Mirror
   whatever the API already enforces rather than inventing a second rule.
4. The blank/whitespace case is rejected client-side as well as server-side —
   the column carries a not-blank `CHECK`, and a 500 from a constraint is not an
   acceptable UI.
5. Do not weaken the server: the savepoint-based collision handling and the
   existing `PATCH` guards stay exactly as they are. This is a UI change.
6. `(cd web && npm run check)` and `(cd web && npm test)`. If any Go comment or
   a file cited by one changes, run `./internal/handlers/...` (§5's
   repo-wide-guard table). Per §5 name the specific tests that ran.
