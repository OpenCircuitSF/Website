## Description

**On hold. Do not plan or implement.** The user decided on 2026-11-07 not to get Luma Plus yet: "We won't be getting Luma Plus just yet so we will hold off on adding support to building that out." Only the user takes this off hold.

The aim is to add a published workshop to the Luma calendar <https://luma.com/opencircuitsf> automatically, and keep it in step when the workshop changes. This would sit alongside the Outreach features.

Research findings from 2026-11-07, from Luma's OpenAPI spec <https://public-api.luma.com/openapi.json> and its help pages. The full report with citations is `luma-research.md` in the session scratchpad.

- **Plan:** the API needs **Luma Plus**, $59/month billed annually (<https://luma.com/pricing>).
- **Authentication:** one key per calendar, in the `x-luma-api-key` header. The limit is 200 requests a minute per calendar.
- **Creating and updating:**
  - The endpoints are `POST /v1/events/create` and `/v1/events/update`.
  - Fields: name, `description_md`, start and end, IANA timezone, address, capacity, visibility, ticket types and slug.
  - `suppress_email` stops Luma emailing guests about an update.
- **Registration happens on Luma.** A native event has no field for an outside sign-up URL such as Bookwhen.
- **Listing a Bookwhen event instead:** `POST /v1/calendars/events/add` with `platform: "external"` and a URL lists the event on the calendar. Such a listing has no cover image, and no endpoint was found to update or remove it.
- **Cover images:** request an upload URL, `PUT` the JPEG or PNG to it, then pass the `images.lumacdn.com` URL.
- **Cancelling:** two steps with a 15-minute token. It cannot be undone, and it emails every guest.
- **Other routes:** Zapier needs Plus and cannot create events. Luma's iCal feed is export only.

Suggested shape: a separate "Publish to Luma" step per workshop rather than an Outreach channel.
- **Settings and client:** a `LUMA_API_KEY` setting and an `internal/luma` client.
- **Storage:** a new migration with a `workshop_luma` table holding the event id and URL, the cover URL and its hash, sync status, last error and synced-at.
- **Sending:** calls go through the outbox, with a duplicate check before a retried create.
- **Reuse:** the reading and matching from `#0648` serves for verification.
