# 0533 — The sitemap stamps static pages with the server's start date

## Description

`internal/seo/sitemap.go` sets the static routes' `<lastmod>` from `built`, which is "today" when the `Site` is constructed — that is, when the service starts. Measured on production, 2026-09-12: `/`, `/about`, `/privacy`, `/workshops`, `/subscribe`, and `/archive` all read `2026-09-12`, the latest deploy date, while nothing on `/privacy` or `/about` changed.

Every deploy or restart therefore claims every static page changed. Google documents that it uses `lastmod` only when it is consistently accurate, and ignores it for a site where it is not — which would also discount the accurate dates on workshop and archive entries.

## Acceptance criteria

1. No `<lastmod>` in the sitemap changes unless the page it describes changed.
2. Pages whose content is derived from data get a data-derived date: `/archive` from the newest published `archived_at`, `/workshops` from the newest published workshop change, and `/` from whichever of its sources changed most recently.
3. Pages with purely static copy (`/about`, `/privacy`, `/subscribe`) either **omit** `<lastmod>`, which the sitemap protocol allows, or use a date that genuinely tracks their content. Record the choice.
4. Restarting the service leaves the sitemap byte-identical when no data changed. Test it by building two `Site`s at different times.
5. Workshop and archive entries keep their existing accurate dates.
6. `ISSUE=NNNN scripts/check.sh go ./internal/seo/... ./cmd/opencircuit/...` passes with no skips.
