## Description

## Requirements

1. `docs/api.md`:
   - creating a key, including choosing scopes and expiry;
   - the auth header;
   - the error format and pagination;
   - the Pacific-time note;
   - a link to `/api/v1/openapi.json`;
   - a `curl` example for each resource.

   Index it in `docs/README.md`.
2. `docs/mcp.md`:
   - connecting Claude Code:
     ```
     claude mcp add --transport http ocsf https://www.opencircuitsf.com/mcp --header "Authorization: Bearer $OCSF_API_KEY"
     ```
     plus Claude Desktop;
   - which scopes to give an agent key;
   - rotating and revoking a key.
3. Three worked workflows, each a prompt and the tool calls it should lead to:
   - "Schedule one post a day for the next two weeks across the ESP32-C3 guides, on both channels, with campaign `guides-2026-12`, skipping guides posted in the last 30 days."
   - "Set up next month's Programming LEDs workshop, the same as last time, on the second Saturday."
   - "What's missing for next month?", then creating the missing drafts.
4. Optionally, a project skill, `.claude/skills/ocsf-ops/SKILL.md`, that wraps these workflows with the house rules: ask before `send_guide_post` or `publish_event`, use Pacific time, and pick a campaign name.

### Where the code and the issue specs differ

- **Not all times are Pacific.** Guide-post times (`list_guide_posts`, `scheduled_at`, `posted_at`) and engagement times come back in **UTC**. Only event times carry a Pacific offset. The docs say so. A follow-up could make guide-post output Pacific for consistency.
- **Claude Desktop can't send a bearer header** from its custom-connector UI, so the doc uses the third-party `mcp-remote` bridge. The issue assumed a direct setup.
- **The Agent preset leaves out `engagement:read`.** It is documented as Home Assistant's own key.
- **`update_event` is not flagged PUBLIC**, but on a published event it changes the public page right away. The docs and the skill treat it as needing confirmation. Possible follow-up: give it a conditional `PublicEffect` like `update_guide_post` has.
- **No rate-limit headers on success.** Only a 429 carries `Retry-After`. A request that fails authentication isn't counted against any limit until `#0682` lands; the doc has a placeholder comment for it.
- **Two lists aren't paginated:** `guide_posts_overview` and `list_channels`.
- **No automated check ties the docs to the OpenAPI document** (acceptance criterion 1). The check was manual. Possible follow-up: a test that every `operationId` appears in `docs/api.md` and `docs/mcp.md`.
