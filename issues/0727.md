## Description

Generate the twelve unfurl images for the second batch of Raspberry Pi guides (`#0723`–`#0726`), exactly as `#0722` did for the first batch: read `#0722` in full (its Fix, Verification and Work log record the Codex command, the post-processing and the three re-rolls), then follow `assets/og/guides/PROMPTS.md`'s "How to use this file".

## Root cause

Not a defect. The twelve batch-2 Raspberry Pi guides (`#0723`–`#0726`) had prompts in `assets/og/guides/PROMPTS.md` but no art, so they unfurled with the generated title card.

## Fix

Followed `#0722`'s process. "How to use this file" step 3 now notes `#0710`'s 40,000 B cap on each image's 640×336 thumbnail (`TestGuideThumb_EmbeddedSetWeight`): a dense, multicoloured image can pass the 1,000,000 B limit and still fail it.

Before generating, each prompt was checked against STYLE and `#0722`'s lessons. These were tightened:

- **`pi-models-compared`:** a clear dark margin between the outer boards and the frame edges.
- **`pi4-micro-hdmi`:** both items well inside the frame; no logos on the board or the monitor bezel.
- **`pi-wifi-dropouts`:** a plain, unbranded router, and "plain radio arcs" rather than "plain WiFi arcs".
- **`pi-backup-sd-card`:** no SD logo, capacity or speed-class symbols on either card.
- **`pi-rgb-matrix-basics`:** the driver board sits just left of the first panel, well inside the frame, not "at the far left".
- **`pi-rgb-matrix-power`:** no labels, stickers or warning symbols on the power supply.

After the first look, three more prompt edits came with the re-rolls (see the work log):

- **`pi4-micro-hdmi`:** plain near-black ground with no tools, components, solder or other props.
- **`pi-wifi-dropouts`:** the board's parts are plain rectangles, squares and circles, with no letter-like shapes or silkscreen outlines.
- **`pi-rgb-matrix-power`:** the power supply sits left of centre, shown whole, with dark space between it and the left edge.

Each image was made with `sips --resampleWidth 1200`, then `sips --cropToHeightWidth 630 1200`, then `pngquant --quality 65-90`, and saved at `internal/seo/cardassets/guides/<slug>.png`. No code changed.

## Work log

**Codex command.** Run from the scratch directory `pi-art-0727/`, with the prompt on stdin, in three parallel runs of four slugs each:

    codex exec -C <scratch>/pi-art-0727 -s workspace-write --skip-git-repo-check - < prompt-<n>.txt

The prompt told Codex to read `PROMPTS.md` read-only from its absolute path, use the built-in `image_gen` tool once per slug with the STYLE block followed by the slug's prompt, and save `raw-<slug>.png` in the working directory. The Codex session header reports **codex-cli 0.167.2, model `gpt-6.2-sol`**. Raw outputs were about 1730×909.

**A prompt gotcha:** the first wording also said "do not write any file outside the current working directory". Two of the three runs refused to call `image_gen` at all, because that tool first saves its originals under `~/.codex/generated_images`. The prompt now says that cache is fine and asks Codex to copy each result into the working directory. Those two runs were re-run; the third had already generated its four.

**Re-rolls (3):**
1. `pi4-micro-hdmi`: a workbench of props (solder spool, pliers, LED, resistor, soldering iron) along the bottom, cut by the frame edge. That clutter is what `#0722` rejected in `pi-volumio-streaming`. The prompt now asks for a plain ground with no props. The second roll was accepted.
2. `pi-wifi-dropouts`: two component footprints on the line-art board read as letters ("CJ", "CC"). The prompt now draws the parts as plain rectangles, squares and circles. The second roll was accepted.
3. `pi-rgb-matrix-power`: the power supply ran off the left edge. The prompt now places it left of centre, whole, with dark space around it. The second roll was accepted.

The other nine were accepted on the first roll.
