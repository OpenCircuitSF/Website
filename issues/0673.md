## Description

User direction, 2026-11-15: keep the UX good, but make the site **operable by tools**. The site gets a REST API, authenticated by API keys that admins create with an optional expiry, and an MCP server, so Claude Code and similar tools can do admin work quickly:

- read every guide and draft, schedule and send guide posts in bulk;
- create and update events;
- check whether next month has the events it should, both on the site and on Luma.

This is the umbrella issue. The work is in the children, in dependency order.

## What already exists, so it isn't rebuilt

- `#0652`'s `api_tokens` table and `internal/apitokens`: `ocsf_`-prefixed bearer tokens, stored only as SHA-256, with scopes, revocation, `last_used_at`, and an admin UI for creating and revoking them.
- `middleware.RequireAPIToken`, and `apiTokensH.AddV1Route`, which is GET-only.
- `#0653`'s `GET /api/v1/engagement`.
- The admin handlers for guide posts (`#0659`), events and venues, and the Luma checker (`internal/luma`, `#0648`).

The v1 routes reuse the stores and the service logic behind those handlers. They do not fork them.

## Principles (all children)

- **Least privilege.**
  - Each scope covers one resource and one access level: `guides:read`, `guide_posts:write`, `events:write`, and so on.
  - Admins pick scopes when creating a key, and the key can do nothing outside them.
  - Expiry is optional; the UI suggests 90 days.
- **Every write is audited** against the key: its id, name and display prefix, plus the admin who created it, using the existing `audit` package.
- **Same validation as the UI.** A v1 write goes through the same validation and side effects as the matching admin action: outbox, short links, SEO cache invalidation. There is no second code path.
- **Secrets never appear in logs, audit metadata, error bodies or issue transcripts.**
- **One process.** No new service. The MCP server is an HTTP endpoint in the existing Go binary, behind the same Apache vhost.
- **No weakening of existing guarantees.** That covers the uniform 202 on `POST /api/subscribe`, the `physical_address` check, and the posting-credential warnings.

## Acceptance (umbrella)

All children are resolved. Then a Claude Code session, connected to production's `/mcp` with a scoped key, can:

1. list the guides and schedule a week of posts for them on Bluesky and Mastodon;
2. create a draft event and publish it;
3. answer "what's missing for next month?" with a list it can act on.

## Assumptions (user may override)

- API keys are admin-created only. There is no self-service, and no OAuth for now. MCP clients send the key as a bearer header.
- The MCP transport is Streamable HTTP at `https://www.opencircuitsf.com/mcp`, so no local install is needed. If a client can't send headers, a stdio shim can come later.
- Subscriber and campaign data are out of scope for v1. They hold personal data, and nobody asked for them.
