## Description

`#0325` renamed `InvalidateWorkshops` to `Invalidate` because the method had
outgrown its name: it invalidates the SEO caches for workshop mutations, the
campaign archive toggle (`#0319`), and the send worker. That rename is done.

The **interface holding it** was not renamed. `workshopCacheInvalidator` in
`internal/handlers` still carries the narrow name, and since `#0319` it is
satisfied by, and passed to, the campaign archive handler as well as the
workshop handlers. So the type name now makes the same false promise the method
name used to.

`#0325`'s implementer found this while doing the rename and correctly declined
to widen its own scope — the issue's criteria named the method, not the type.

Low priority: this is a naming defect with no behavioural consequence. It earns
an issue rather than a note because the next reader of
`internal/handlers` will reasonably conclude the archive toggle does not
invalidate SEO caches, which is exactly the wrong belief `#0319` was filed to
correct.

## Acceptance criteria

1. `workshopCacheInvalidator` is renamed to something naming what it does
   rather than one of its callers — it invalidates SEO caches, whatever mutated.
2. Every implementer, test double, and call site is updated; the change is
   rename-and-comments only, with no behavioural difference.
3. Doc comments name the current callers (workshop mutation, campaign archive
   toggle, send worker), consistent with what `#0325` wrote for the method.
4. Proved mechanical **structurally**, not with `grep -v '^[+-]#'`: parse both
   revisions without comments and compare the executable content.
5. Confirm the shortened or changed name does not accidentally satisfy or
   shadow another interface — a Go rename that shortens an identifier is how
   accidental interface satisfaction happens.
6. `gofmt` stability proved: file sha256 equals sha256 of `gofmt` stdout (§8).
7. `#0326`'s `servepostgres_seo_instance_guard_test.go` recognises site-shaped
   parameters by resolving a locally-declared interface whose method set is
   exactly `Invalidate()` — confirm the rename does not break that discovery,
   and re-run its mutation proofs.

## Review notes

**Verdict: approved (phase 3, Opus, 2026-08-31).** All seven acceptance criteria
re-verified independently rather than read off the implementer's report.

- **Criterion 4 (mechanical, structurally) — re-derived, not trusted.** Wrote an
  independent tool that parses a file with `go/parser` (comments off *and*
  `File.Comments`/`Doc`/`Comment` fields nil'd on every declaration node),
  applies a rename map to every `*ast.Ident`, re-prints with `go/format`, and
  hashes. Applied to `83036c3^` under the map
  `workshopCacheInvalidator→seoCacheInvalidator`,
  `countingWorkshopInvalidator→countingCacheInvalidator` and compared against
  `83036c3`: all four handler files (`admin_workshops.go`,
  `admin_workshops_test.go`, `admin_campaign_archive.go`,
  `admin_campaign_archive_test.go`) hash **byte-identical**. The rename is
  mechanical; no executable content moved.
- **Criterion 5 (no accidental satisfaction or shadowing).** `seoCacheInvalidator`
  is declared exactly once (`internal/handlers/admin_workshops.go:76`); no other
  declaration of that identifier, and none of `countingCacheInvalidator`, exists
  in the tree. The rename moves an interface's own *type* name, not its method,
  so it cannot change which types satisfy it — the method-set risk from `#0325`
  is `#0337`'s scope and is measured there.
- **Criterion 7 (`#0326`'s guard survives the rename).** Re-ran
  `TestServePostgres_OneSEOSiteFlowsToEveryConsumer` and two of `#0326`'s own
  mutation proofs in a throwaway worktree: passing `nil` to
  `NewAdminWorkshopsHandler` still FAILS (`param 1 (invalidator) got nil`), and a
  second `buildSEOSite` call still FAILS (`found 2 buildSEOSite calls ... want
  exactly 1`). The guard resolves `handlers.seoCacheInvalidator` under its new
  name — it discovers the interface by method-set shape, not by name, so the
  rename was transparent to it, confirmed by running it rather than by inference.
- **Criteria 1, 2, 3, 6.** The new name describes what the seam does rather than
  one caller; the doc comment names all three current callers (workshop mutation,
  campaign archive toggle, `internal/mailing.Worker`'s archive-publish
  transition), matching what `#0325` wrote for the method. `gofmt` stability
  independently confirmed: `sha256(file) == sha256(gofmt stdout)` for every file
  this batch touched.
