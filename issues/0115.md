## Description

[#0101](0101.md) added the Luma calendar link to the SPA — `Footer.svelte`,
`About.svelte`, and the privacy sentence — and that work is correct. But the SPA
is not deployed. `CLAUDE.md` §7 records that what `www.opencircuitsf.com`
actually serves today is `placeholder/index.html`, and that page's only call to
action is still the Discord invite:

```html
<div class="cta">
  <a class="btn btn-primary" href="https://discord.gg/Fq9ug6QXV3" rel="noopener">Join the Discord</a>
</div>
```

The user added the calendar on 2026-08-20 specifically to promote upcoming
events. Until the Go service ships, nobody who visits the site sees it. The
placeholder also says "In the meantime, the Discord is where everything
happens" (line ~344), which was true when written and is now the same half-truth
`#0101` corrected in `About.svelte`.

## Acceptance criteria

- [ ] **The calendar is linked from the placeholder's "Get involved" CTA.**
      Add a second `<a>` beside the Discord button in `.cta` pointing at
      `https://luma.com/opencircuitsf` — the canonical form confirmed in
      `#0101` (`lu.ma` 301s to it). Match the existing button treatment
      (`btn`, `rel="noopener"`); use the secondary variant if one exists so
      Discord stays the primary action, or add one.
- [ ] **Update the "In the meantime" sentence** so it names the calendar as
      where upcoming sessions are listed, the same correction `#0101` made to
      About's "Get involved" copy.
- [ ] **Plain `<a href>` only.** No Luma embed, widget, script, or iframe —
      `CLAUDE.md` §9. The placeholder is a single self-contained HTML file and
      must stay one.
- [ ] **Update `placeholder/README.md`.** Its "Before it goes live" section
      says the Discord invite is "the page's only call to action, so check it
      still resolves before each deploy". With two CTAs that instruction needs
      to cover both links.
- [ ] Preview over HTTP, not `file://` — `CLAUDE.md` §8: the logo is drawn with
      `mask-image` and renders fully transparent under `file://`.
      `cd placeholder && python3 -m http.server <unlikely-port>`, and per §8b
      confirm the bind succeeded and that the page you fetched is yours.

## Notes

Deliberately **not** a bounce on `#0101`. That issue scoped itself to the SPA in
writing ("Scope: two link sites plus the privacy sentence") and delivered
exactly that. The placeholder is a separate deliverable that cannot import
`web/src/lib/links.ts`, so the URL is necessarily hand-written there — the
"defined once" criterion in `#0101` does not reach it. Note the duplication in a
comment so a later URL change updates both.

This is small and independent of the Phase 4/5 work in flight. Its value is
time-limited: it matters only until the SPA replaces the placeholder in
production, and it is worth doing precisely because that date is not set.
