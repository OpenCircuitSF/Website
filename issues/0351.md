## Description

`internal/seo/invalidator_satisfier_guard_test.go`'s doc comment says:

> `*Sitemap` already had a method of that shape under its old, longer name, and
> shortening it made a previously-impossible assignment compile silently

That has a **correct** parse — "shape" meaning zero-parameter, zero-result, and
"its" referring to the *seam's* method — and an **incorrect** one, in which
`*Sitemap`'s own method was the thing shortened.

The incorrect parse is exactly the inversion `#0346` exists to correct, and
that inversion has already cost a full bounce once: it originated in `#0346`'s
filed description, was copied faithfully into `CLAUDE.md` §8, survived that
pass's own verification, and was caught only by a three-tree `go/types`
measurement.

The truth, measured repeatedly: `(*seo.Sitemap).Invalidate` has carried that
short name since `18960b4` (`#0020`) and was never renamed until `#0337`
unexported it. `#0325` renamed `(*Site)`'s and `(*Renderer)`'s methods **and
both seam interfaces**. `*Sitemap` was recruited without being touched.

`internal/seo/sitemap.go`'s companion comment states this unambiguously. This
one should match it.

## Acceptance criteria

1. The doc comment has only one available parse, and it is the correct one:
   `*Sitemap`'s method was never renamed; the seams' required method was, and

5. Any historical claim is re-verified against `git show`, not copied from this
   issue.

### Criterion 1 — read adversarially, the inverted parse is gone

The sentence now closes the inversion **three independent times**, any one of
which would suffice:

1. `-- not on *Sitemap.` — an explicit negation scoping the list of rename sites.
2. `under the short name` — replacing `under its old, longer name`, which was
   the actual source of the bad parse.
3. `untouched by the rename` — an independent restatement at the recruited type.

No reading makes `*Sitemap`'s own method the rename target. The mechanism's
**direction** is also stated correctly throughout (`That moved both interfaces
onto *Sitemap`), matching `#0346`'s corrected history.

**New pronouns checked, since a longer sentence is not by itself a fix.** The
two danglers the issue names are confirmed deleted by the diff (`its old, longer
name`, `shortening it`). The three references that remain — `That moved both
interfaces` (antecedent: the rename, the only action in the preceding sentence),
`#0337 closed that`, and `stops it from reopening` — are unambiguous, and the
last two are pre-existing text this pass did not touch. No new dangling
reference was introduced.

One mild compression, not a defect: `on both seams' required method` uses a
singular noun for two interfaces. Both seams require the same single method and
both interface bodies were rewritten in the same commit, so the natural reading
("the method both seams require") is the true one.

### Criterion 2 — consistent with `internal/seo/sitemap.go`

`sitemap.go`'s `invalidate` doc comment (read, not edited) and the guard now

### Criterion 3 — comment-only, proved with an independent oracle

The implementer's tool was **not** reused. Wrote a different oracle: a
`go/scanner` token-stream comparator (`mode 0`, so comments are consumed and
never emitted), hashing the `(token kind, literal)` sequence. This compares
lexical bytes rather than a re-printed AST, so it also catches changes a printer
would normalise away.

Proved before being trusted, in both directions:

- **Falsifiable (2 shapes).** A string-literal mutation (`fail closed:` →
  `fail CLOSED:`) and an identifier rename (`concreteTypesChecked` →
  `concreteTypesCheckedX`) each reported `DIFFERS: true`, exit 1, distinct
  hashes.
- **Sensitive in the right direction.** A comment-only sentinel edit reported
  `COMMENT-ONLY: true` with an identical hash — so the tool is not simply
  reporting "differs" for everything, which falsifiability alone would not rule
  out.
- **Fail-closed.** A zero-byte input errors (`exit 2`) rather than reporting
  either verdict; so does a truncated input (`produced only 19 tokens`), a scan
  error, and a `COMMENT` token appearing at all.

A fail-open was caught during this setup and is worth recording: the fixtures
initially sat beside the tool's own `main.go`, so `go run .` failed to **build**
and exited 1 — indistinguishable from the tool's own `DIFFERS: true` exit code
if only the status had been read. Caught because the tool prints an explicit
verdict line and none appeared. Same shape as the §8 fail-open entries.

**Result:** `679fbfa^` and `679fbfa` both produce 687 tokens,
`sha256 a101a2f307de8249…` on both sides — the edit is comment-only. The working
tree matches `679fbfa` byte for byte (`sha256 8eda7c8d…`).

### Two follow-ups reported to the orchestrator (not bounced)

1. **The dispatch brief's premise was wrong, and the record should say so.** The
   half-invalidation clause — "with a real runtime cost, a half-invalidation
   that clears the sitemap cache and leaves the per-path meta cache stale (the
   exact failure `#0319` was filed to fix)" — is **not** new material introduced

2. **`the exact failure #0319 was filed to fix` is an overstatement** — in both
   this file and `internal/seo/sitemap.go`, which is why it cannot be corrected
   here without breaking criterion 2. `#0319` was filed because
   `AdminCampaignArchiveHandler` and the send worker invalidated **nothing**, so
   both caches went stale, and its headline symptom is a stale **sitemap**
   ("`sitemap.xml` keeps advertising a just-withheld campaign's URL"). The
   half-invalidation clears the sitemap and reopens the **other** half, a stale
   meta cache. So it is half of the staleness class `#0319` fixed, and
   specifically not the half `#0319` leads with. Correcting it means editing
   both files in one pass — a job for `#0353` or its own issue, not for a
   comment-only change barred from touching `sitemap.go`.
