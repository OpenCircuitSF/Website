## Description

`internal/seo/invalidator_satisfier_guard_test.go`'s doc comment says:

> `*Sitemap` already had a method of that shape under its old, longer name, and
> shortening it made a previously-impossible assignment compile silently

That has a **correct** parse — "shape" meaning zero-parameter, zero-result, and
"its" referring to the *seam's* method — and an **incorrect** one, in which
`*Sitemap`'s own method was the thing shortened.

The incorrect parse is exactly the inversion `#0346` exists to correct, and
that inversion has already cost a full bounce once: it originated in `#0346`'s
filed description, was copied faithfully into `CLAUDE.md` §8, survived that
pass's own verification, and was caught only by a three-tree `go/types`
measurement.

The truth, measured repeatedly: `(*seo.Sitemap).Invalidate` has carried that
short name since `18960b4` (`#0020`) and was never renamed until `#0337`
unexported it. `#0325` renamed `(*Site)`'s and `(*Renderer)`'s methods **and
both seam interfaces**. `*Sitemap` was recruited without being touched.

`internal/seo/sitemap.go`'s companion comment states this unambiguously. This
one should match it.

## Acceptance criteria

1. The doc comment has only one available parse, and it is the correct one:
   `*Sitemap`'s method was never renamed; the seams' required method was, and
   that is what recruited `*Sitemap`.
2. It is consistent with `internal/seo/sitemap.go`'s companion comment — read
   both and make them agree in substance and in framing.
3. Comment-only. Prove it structurally: parse both revisions with comments
   excluded, compare bytes, with the tool proved falsifiable first and failing
   closed on empty input (§8 records a fail-open that arose exactly that way,
   and three agents found bugs in their own instruments this session).
4. `gofmt` stability: file sha256 equals sha256 of `gofmt` stdout — this is a
   declaration doc comment, exactly what §8's smart-quote gotcha rewrites.
5. Any historical claim is re-verified against `git show`, not copied from this
   issue.

## Fix

Confirmed `#0349` (resolved, `4c649f6`) took the replace-the-scan branch but
did not delete the target sentence — it survives at what is now roughly lines
21–29 of `internal/seo/invalidator_satisfier_guard_test.go`, with `#0349`'s

written per its own coordination note.

Replaced the ambiguous sentence:

> `#0325`'s rename (InvalidateWorkshops -> Invalidate, f7771ed) moved those
> two interfaces onto `*Sitemap` by accident: `*Sitemap` already had a method
> of that shape under its old, longer name, and shortening it made a
> previously-impossible assignment … compile silently …

with:

> `#0325`'s rename (f7771ed) shortened `InvalidateWorkshops` to `Invalidate`
> on `*Site`'s and `*Renderer`'s own methods and on both seams' required
> method — not on `*Sitemap`. That moved both interfaces onto `*Sitemap` by
> accident: `*Sitemap` already had a method of that exact shape under the
> short name, untouched by the rename, so a previously-impossible assignment
> (passing a bare `*Sitemap` into either seam) went from a compile error to
> compiling silently — with a real runtime cost, a half-invalidation that
> clears the sitemap cache and leaves the per-path meta cache stale (the
> exact failure `#0319` was filed to fix). `#0337` closed that by unexporting
> `Sitemap.invalidate` (see its own doc comment); this test is what stops it
> from reopening.

The rewrite removes both dangling pronouns ("its old, longer name",
"shortening it") that let the sentence be read with `*Sitemap`'s own method
as the rename target, and instead names the rename target explicitly
(`*Site`'s and `*Renderer`'s methods, plus both seam interfaces'
declarations), matching `internal/seo/sitemap.go`'s companion `invalidate`
doc comment in substance and framing (criterion 2): that comment also names
`Site.Invalidate` as the thing renamed from `InvalidateWorkshops`, and states
plainly that `*Sitemap` had "no source change of its own."

Did not touch `internal/seo/sitemap.go` (read only, per the issue's explicit
restriction) or any other sentence in the guard file — `#0353` (filed,
out of scope here per the dispatch instructions) covers the `*types.Alias`
coverage hole and the two other doc-comment claims `#0349`'s review

## Verification

**Criterion 3 — comment-only, proved structurally and made falsifiable.**
Wrote a standalone Go tool (`commentdiff`, stdlib only — `go/parser` +
`go/printer`, no external deps) that parses a file with `parser.ParseFile`
mode `0` (i.e. *without* `parser.ParseComments`, so the scanner discards
comment tokens and the AST holds none — verified in the tool itself by
asserting `len(file.Comments) == 0` after parse), re-prints the
comment-stripped AST via `go/printer`, and compares `sha256` of the two
printed outputs.

- **Falsifiability, proved first.** Ran the tool against the real `HEAD`
  revision (`old.go`) and a copy of the new revision with one deliberate
  non-comment mutation (`if len(names) == 0` → `if len(names) == 1` inside
  `TestInvalidatorSatisfierSet`, verified to occur exactly once before
  mutating). Result: `DIFFERS: true`, exit 1, distinct sha256 hashes — the
  tool does detect a non-comment change.
- **Fail-closed on empty input.** Ran the tool with one argument replaced by
  a zero-byte file. Result: `ERROR: fail closed: … is empty — not evidence
  of no difference`, exit 2 — refuses to report equality (or difference) on
  a broken input rather than silently passing. The tool also fails closed if
  either parse errors, if either AST has zero top-level declarations, or if
  printing produces zero bytes.
- **Real comparison.** Ran the tool against `HEAD`'s
  `internal/seo/invalidator_satisfier_guard_test.go` (`old.go`) and the
  edited working copy (`new.go`): `COMMENT-ONLY: true`, exit 0, identical
  sha256 (`844afb3c…`) on both sides — the edit changed only comment text.

**Criterion 4 — gofmt stability.** `shasum -a 256
internal/seo/invalidator_satisfier_guard_test.go` and `gofmt
internal/seo/invalidator_satisfier_guard_test.go | shasum -a 256` both give
`8eda7c8d…`; `gofmt -l internal/seo/invalidator_satisfier_guard_test.go`
prints nothing.
