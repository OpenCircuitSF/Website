## Description

`#0198` coupled the two citation guards' whitespace classes behaviourally: each
file asserts its own shipped `citationPattern` against a shared canonical
codepoint list, in its own real engine. Its phase-3 review proved the coupling
works in **both** directions and that the reject half bites too.

Then it found the way out of the coupling.

**1. Removing a codepoint from one file's *list* is completely silent.** The
review deleted `0x2007` from Go's `whitespaceClassMustMatch` and `0x200b` from
web's `WHITESPACE_MUST_NOT_MATCH`, one file each, and **both suites stayed
green**. No file asserts its own list length; nothing cross-checks the counts.

This matters because of the repair path it invites. When the coupling test
fails, it fails *naming a codepoint* — and the lazy fix is to delete that
codepoint from the list rather than repair the pattern. After that the guards
have genuinely drifted and **nothing fails anywhere**. The escape hatch is
exactly the shape of the failure message.

The fix is about four lines. `#0187`'s matrix, in these same two files, already
carries precisely this meta-assertion (`MATRIX_COUNTS`) as its precedent: 25 and
10 on each side.

**2. `internal/handlers/citation_guard_test.go:413` lost a token.** The comment
reads "spelled differently — `\x{00A0}` here, ␣ there", with the web spelling
simply **absent** — byte-verified: there is no invisible character in the gap,
the text is missing. Its web mirror is intact.

This is the fingerprint of the NBSP incident `#0198`'s implementer documented:
the same trap was repaired by *deletion* on the Go side and by *escaping* on the
web side. `#0203` is the precedent for filing a doc-comment defect in this
family.

**3. A pre-existing clause in the same file overstates, and `#0203`'s review
asked that it be folded in here rather than given a fourth standalone pass.**

`internal/handlers/citation_guard_test.go`'s disk-comparison doc comment says a
name-matched directory "is swallowed by the shipped walk today with nothing
failing". The review measured **both readings**: "the shipped citation walk
silently skips it and its guard stays green" is **true** (proved by planting a
citation-bearing file under `internal/dist` and watching `#0181`'s guard stay
green); "nothing in the tree fails" is **false** — that same plant fails
`TestScanDirForCitationsCollectsExactlyDiskFiles`, which is precisely `#0200`'s
purpose.

The clause is verbatim `#0201` prose, byte-unchanged by `#0202` and `#0203`, and
the paragraph as a whole is true — the next two sentences do not survive the
false reading. So this is a tightening, not a defect, and it is only worth doing
because this issue is already editing this file.

Cosmetic, same block: `#0203`'s edit did not reflow its paragraph, leaving a
44-column line among ~70-column neighbours.

## Implementation notes

and `web/src/lib/citationGuard.test.ts`. No matching behaviour changed —
`citationPattern` itself is untouched in both files; every edit is either a
new test/constant or a comment.

**Item 1 — length guards.** Added `whitespaceMustMatchCount = 25` /
`whitespaceMustNotMatchCount = 10` (Go, a `const` block) and
`WHITESPACE_LIST_COUNTS = { mustMatch: 25, mustNotMatch: 10 }` (web, mirroring
`#0187`'s `MATRIX_COUNTS` in the same file), then a dedicated test on each
side — Go's `TestWhitespaceClassCanonicalListsHaveNotBeenShortened`, web's
`it('has not had either canonical list shortened (#0205)', ...)` as the first

shortened," e.g. (Go): `whitespaceClassMustMatch has 24 entries, want 25 —
the accept list has been shortened; restore the deleted codepoint instead of
deleting the next one the coupling test names`. Deliberately a separate
assertion from the existing coupling test rather than folded into its loops,
so a shrinkage failure and a drift failure never share one message.

there"), each file naming its own spelling first.

**Item 3 — the `internal/dist` clause.** "is swallowed by the shipped walk
today with nothing failing" was ambiguous between "the shipped citation guard
stays green" (true) and "nothing in the tree fails" (false —
`TestScanDirForCitationsCollectsExactlyDiskFiles`, `#0200`'s purpose, does).
Reworded to name both facts: "...is swallowed by the shipped walk today, and
the citation guard above (`TestNoAdminFacingStringCitesInternalDocs`) stays

catches the gap." The whole paragraph (`"on disk" is a second, independent

## Notes

Reported by `#0198`'s phase-3 review under `CLAUDE.md` §9.

The review's verdict on the duplicated list is worth preserving, because it is
the reason this issue is a length check and **not** a shared source of truth:
the two lists are not each other's oracle. Both are pinned to ECMA-262
`WhiteSpace` ∪ `LineTerminator`, which `#0193` proved equals V8's native `\s`
across all of Unicode — so the *spec* arbitrates, and an edit moving both
patterns the same wrong way still fails both. A third JSON file read by two
languages would be untyped, uncompiled, and — decisively — **would not fix the
shrinkage failure mode at all**: deleting from a shared file removes the
assertion from both sides at once, which is worse than today.

`CLAUDE.md` §8's typed-escape trap is live in this exact work. `#0198`'s
reviewer disclosed that drafting its own notes produced four real NBSPs and one
real U+2060 from typed escapes, caught by byte census before writing. Build any
new text with `chr(92)` and read the file back as bytes.

| Step | Action | Suite |
|---|---|---|
| 1 | delete `\x{1680}` from the shipped `citationPattern` (the pattern, not the list) | **FAIL** — `TestCitationPatternWhitespaceClassStaysCoupledWithWebGuard`: *"did not match PRD + U+1680 + section — ... the two guards have drifted"*, plus `#0193`'s `TestCitationPatternMatchesWebWhitespaceShapes` naming *"ogham space mark (U+1680)"* |

inverts the repair path in practice, not just in wording.
