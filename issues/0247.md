## Description

`docs/deployment.md`'s restore drill names fixed resources throughout: the
database `0062src`, the target `opencircuit_test_0062dst`, and the directory
`/tmp/backup-drill` — including a fixed `-latest.dump` inside it.

Two people following the drill at once collide on all three. `CLAUDE.md` §5a
makes concurrent agents the norm on this project and §8b is explicit that a
shared mutable resource must be namespaced or ownership-verified. The drill is
a procedure that creates and **drops** databases and overwrites a dump file, so
a collision is not a confusing error — it is one run destroying another's target
mid-restore, or restoring from a dump the other run just replaced.

Pre-existing rather than introduced by `#0239`'s rewrite, and found by that
issue's review while following the drill verbatim.

**The drill is also the one document most likely to be followed by two people
simultaneously** — during an incident, or while someone rehearses it. That is
precisely when a silent cross-run collision is least affordable.

## Implementation notes

Reused the project's existing `ISSUE=NNNN` / `scripts/testdb.sh` convention
(`CLAUDE.md` §5a) rather than inventing a second naming scheme, exactly as
the first acceptance criterion asks. Step 1 — the first point in the drill
where a namespace is actually needed, not a preamble someone would skip
past — now reads:

```bash
ISSUE="${ISSUE:-$$}"
echo "Running the drill under ISSUE=${ISSUE}"
DSN="$(scripts/testdb.sh create "${ISSUE}src")"
```

and every database name, `BACKUP_ROOT`, and dump path in the rest of the
drill is derived from `$ISSUE` from there on: `opencircuit_test_${ISSUE}src`
/ `opencircuit_test_${ISSUE}dst` for the two databases, and
`/tmp/backup-drill-${ISSUE}` for the backup directory (step 4). The dump
filename itself is protected two independent ways, not just one: it lives
inside the per-run `BACKUP_ROOT` directory, and `backup.sh` already names it
after the database (`opencircuit_test_${ISSUE}src-latest.dump`), which is
now also namespaced. Step 9's cleanup drops only `"${ISSUE}src"` /
`"${ISSUE}dst"` via `scripts/testdb.sh drop` and removes only
`/tmp/backup-drill-${ISSUE}` — never a bare `DROP DATABASE` or `rm -rf` on a
fixed name, satisfying the fourth criterion.

Setting `ISSUE` defaults to `$$` (the running shell's PID) if unset, which
is always a distinct, purely-numeric token per process — deliberately, to
sidestep a real bug found while testing this fix (see `## Gotchas` below):
`scripts/testdb.sh`'s `CREATE DATABASE $db ...` interpolates the database
name unquoted into SQL, so Postgres folds a mixed-case id to lowercase, and
a token containing letters silently doesn't round-trip through the DSN
`testdb.sh create` hands back. The project's own `ISSUE=NNNN` convention is
already numeric-only in every example in `CLAUDE.md`/`Issues.md`, so this
never bites in normal use; the PID default keeps the drill's own generated
default in that same safe shape.

Folded in the smaller item from the same review: step 2's comment now names
both enum values correctly, checked directly against the CHECK constraints
that define them rather than guessed — `migrations/000012_create_suppressions.up.sql`
(`suppressions_reason_check`: `hard_bounce | complaint | manual |
repeated_soft_bounce`) and `migrations/000010_create_subscribers.up.sql`
(`subscribers_status_check`: `pending | active | unsubscribed | bounced |
complained`).

Landed together with `#0239`'s bounce fix (step 7) in one editing pass
since both touch the same ~200-line drill block and were found by the same
review, but as **two separate commits**: `c7812ef` (`#0239`) carries only
the step-7 fix, applied first against the drill's pre-existing
`0062src`/`0062dst` names; this issue's commit `479bf81` layers the
`ISSUE=NNNN` namespacing on top of that already-committed state. `git show
479bf81` is a clean, isolated diff of just the namespacing change plus the
step-2 enum correction.

## Gotchas

Found and worked around, not introduced by this fix: an early attempt at
the concurrency proof used mixed-case `ISSUE` values (`0247concA` /
`0247concB`) and both runs failed immediately at step 1 with `database
"opencircuit_test_0247concAsrc" does not exist` — `scripts/testdb.sh`
(a file this dispatch was told not to touch; another agent's session was
mid-edit on it and landed a fix for the same underlying case-folding issue,
`#0208`, while this pass was running) folds an unquoted `CREATE DATABASE`
identifier to lowercase, so the DSN handed back (built from the original,
unfolded string) named a database that was never actually created under
that spelling. Not a namespacing defect in this fix — `ISSUE=NNNN` is
numeric-only everywhere else in this project's convention — but worth
recording so nobody "fixes" this drill's `$$`-default away in favor of
something with letters in it. The two mis-cased leftover databases
(`opencircuit_test_0247concasrc`/`...concbsrc`) were dropped by hand before
the real concurrency proof below.

## Verification

**Ran the whole rewritten drill exactly as documented, in a single pass
first**, on scratch databases (`opencircuit_test_0239verifysrc` /
`opencircuit_test_0239verifydst`, `ISSUE=0239verify`) — every step matched
the expected output named in the doc: step 1 → `20 | f`; step 1b →
`20/d create_workshops`, `19 | f`; step 5's restore → ownership reassigned,
`19 | f`; step 6 → `20/u create_workshops`; step 7's `diff` → exactly one
pair of lines (`< email_campaigns|12` / `> email_campaigns|13`); step 9 →
source dropped cleanly, target failed with `ERROR: must be owner of
database` exactly as documented, dropped by hand. `bash -n` and `shellcheck`
(with a shebang prepended for the check, since the extracted block is a doc
fragment, not a standalone script) both pass clean on the extracted step
1–9 block.

**Then proved the load-bearing last criterion directly: ran the drill twice
concurrently to completion**, both invocations of the exact same script,
launched together and waited on (`ISSUE` left unset, defaulting to each
shell's own PID — the drill's own documented default path, not a
special-cased test value):

```
( bash drill.sh > concA.log 2>&1; echo "A exit=$?" ) &
( bash drill.sh > concB.log 2>&1; echo "B exit=$?" ) &
wait
```

Result: **`A exit=0`, `B exit=0`** — both completed successfully. Run A
picked `ISSUE=45915`, run B picked `ISSUE=45916` (their respective PIDs).
Grepped both full logs for every operative line (namespace announcement,
schema-version checks, migration output, restore/backup paths, the step-7
diff, drop results) and confirmed:

- Each log names only its own `ISSUE` value and only its own database names
  (`opencircuit_test_45915src`/`dst` in A's log, `opencircuit_test_45916src`/
  `dst` in B's log) — **zero cross-references** between the two logs.
- Each log's `BACKUP_ROOT` was `/tmp/backup-drill-45915` and
  `/tmp/backup-drill-45916` respectively — two distinct directories, neither
  log mentioning the other's path.
- Both reached step 6's `20/u create_workshops` and step 7's single-line
  `email_campaigns|12` → `|13` diff independently, on their own data.
- Both hit the exact same documented step 9 ownership gotcha independently
  (`src` dropped clean, `dst` failed with `ERROR: must be owner of
  database`) — dropped both `dst` databases by hand afterward
  (`opencircuit_test_45915dst`, `opencircuit_test_45916dst`), removed both
  `/tmp/backup-drill-4591{5,6}` directories, confirmed
  `scripts/testdb.sh list` showed only `opencircuit_test_template`
  remaining, and confirmed no leftover `go test`/`.test` processes
  (`pgrep -f 'go test|\.test '`).

This is the proof the second acceptance criterion's own Notes section asks
for: "a namespaced drill that nobody has run twice at once is a drill that
has not been shown to work" — this one has now been run twice at once, to
completion, with the logs checked line by line for cross-contamination, not
just a passing exit code.

`ISSUE=0239fix scripts/check.sh go ./internal/...` — 15 packages, all `ok`,
zero skips, isolated database `opencircuit_test_0239fix` (this issue changed
only `docs/deployment.md`; run anyway per dispatch instructions, shared with
`#0239`'s verification since both were worked in the same pass — confirms
nothing else in the tree regressed).

## Acceptance criteria

- [x] Every database, directory and file the drill creates is namespaced per run — the existing convention is `ISSUE=NNNN` / `scripts/testdb.sh create NNNN`, so reuse it rather than inventing a second scheme — step 1 sets `ISSUE="${ISSUE:-$$}"` and every subsequent database, `BACKUP_ROOT`, and dump path is derived from it
- [x] The dump filename cannot be overwritten by a concurrent run — protected two independent ways: it lives inside the per-run `BACKUP_ROOT` directory, and its own name is derived from the now-namespaced database name
- [x] The drill says how to pick the namespace, in the step where it is first needed, not in a preamble someone skips — step 1's own comment explains it; the prose above the code block only names the fix, it does not explain how to pick a value
- [x] Cleanup drops only what that run created — never a bare `DROP DATABASE` on a fixed name — step 9 is `scripts/testdb.sh drop "${ISSUE}src"` / `"${ISSUE}dst"` and `rm -rf "/tmp/backup-drill-${ISSUE}"`
- [x] Proved by running the drill twice concurrently to completion, both succeeding, neither touching the other's resources — see `## Verification`: both runs exited 0, reached the same reproduction point independently, and neither log referenced the other's `ISSUE`, database names, or backup path

**A smaller item from the same review, worth folding in while the file is open:**

- [x] Step 2's comment names the enum values it filters on. They are currently wrong by omission: `suppressions.reason` is `hard_bounce` / `complaint` / `manual` / `repeated_soft_bounce` (not `bounce`), and `subscribers.status` is `pending` / `active` / `unsubscribed` / `bounced` / `complained` (not `confirmed`). The reviewer lost two round trips to this — fixed, checked directly against `migrations/000012`'s and `migrations/000010`'s CHECK constraints
