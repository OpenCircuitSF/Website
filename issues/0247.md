## Description

`docs/deployment.md`'s restore drill names fixed resources throughout: the
database `0062src`, the target `opencircuit_test_0062dst`, and the directory
`/tmp/backup-drill` — including a fixed `-latest.dump` inside it.

Two people following the drill at once collide on all three. `CLAUDE.md` §5a
makes concurrent agents the norm on this project and §8b is explicit that a
shared mutable resource must be namespaced or ownership-verified. The drill is
a procedure that creates and **drops** databases and overwrites a dump file, so
a collision is not a confusing error — it is one run destroying another's target
mid-restore, or restoring from a dump the other run just replaced.

Pre-existing rather than introduced by `#0239`'s rewrite, and found by that
issue's review while following the drill verbatim.

**The drill is also the one document most likely to be followed by two people
simultaneously** — during an incident, or while someone rehearses it. That is
precisely when a silent cross-run collision is least affordable.

## Acceptance criteria

- [ ] Every database, directory and file the drill creates is namespaced per run — the existing convention is `ISSUE=NNNN` / `scripts/testdb.sh create NNNN`, so reuse it rather than inventing a second scheme
- [ ] The dump filename cannot be overwritten by a concurrent run
- [ ] The drill says how to pick the namespace, in the step where it is first needed, not in a preamble someone skips
- [ ] Cleanup drops only what that run created — never a bare `DROP DATABASE` on a fixed name
- [ ] Proved by running the drill twice concurrently to completion, both succeeding, neither touching the other's resources

**A smaller item from the same review, worth folding in while the file is open:**

- [ ] Step 2's comment names the enum values it filters on. They are currently wrong by omission: `suppressions.reason` is `hard_bounce` / `complaint` / `manual` / `repeated_soft_bounce` (not `bounce`), and `subscribers.status` is `pending` / `active` / `unsubscribed` / `bounced` / `complained` (not `confirmed`). The reviewer lost two round trips to this

## Notes

Reported by `#0239`'s phase-3 review under `CLAUDE.md` §9.

The last acceptance criterion is the real test. A namespaced drill that nobody
has run twice at once is a drill that has not been shown to work, and this
project has already learned that lesson the expensive way — `#0024`'s
guard-removal proof destroyed a seeded row in the shared test database, which
is why §8b exists at all.
