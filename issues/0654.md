## Description

Write `docs/home-assistant.md` and link it from `docs/README.md`. The guide shows how to set up the daily check against `GET /api/v1/engagement` (`#0653`) using a token from `#0652`.

The guide covers:
1. **Creating the token.** In the site's Settings, with the `engagement:read` scope. Copy it once.
2. **Storing the token.** Put it in Home Assistant's `secrets.yaml` as `Bearer <token>`, never inline in the configuration.
3. **The data.** A `rest` sensor (`resource: https://www.opencircuitsf.com/api/v1/engagement`, `headers: Authorization: !secret ocsf_engagement_auth`). Its state comes from `value_json.total`, with attributes for `has_engagement`, `summary`, `bluesky` and `mastodon`. Set a long `scan_interval`, such as 86400, so it doesn't poll often.
4. **The daily run.** An automation fires at a fixed time, for example 9:00 AM. It calls `homeassistant.update_entity` on the sensor, then sends `notify.<your device>` with the `summary` attribute, conditioned on `has_engagement`.
5. **Checking it by hand.** A `curl` command with the header, using the token as a placeholder.
6. **Revoking and rotating.** How to revoke a token and replace it.

Every YAML example must be valid for current Home Assistant syntax. Check it against Home Assistant's REST sensor and automation docs and cite them. Use placeholder tokens only.
