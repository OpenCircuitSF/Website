## Description

Write `docs/home-assistant.md` and link it from `docs/README.md`. The guide shows how to set up the daily check against `GET /api/v1/engagement` (`#0653`) using a token from `#0652`.

The guide covers:
1. **Creating the token.** In the site's Settings, with the `engagement:read` scope. Copy it once.
2. **Storing the token.** Put it in Home Assistant's `secrets.yaml` as `Bearer <token>`, never inline in the configuration.
3. **The data.** A `rest` sensor (`resource: https://www.opencircuitsf.com/api/v1/engagement`, `headers: Authorization: !secret ocsf_engagement_auth`). Its state comes from `value_json.total`, with attributes for `has_engagement`, `summary`, `bluesky` and `mastodon`. Set a long `scan_interval`, such as 86400, so it doesn't poll often.
4. **The daily run.** An automation fires at a fixed time, for example 9:00 AM. It calls `homeassistant.update_entity` on the sensor, then sends `notify.<your device>` with the `summary` attribute, conditioned on `has_engagement`.
5. **Checking it by hand.** A `curl` command with the header, using the token as a placeholder.
6. **Revoking and rotating.** How to revoke a token and replace it.

Every YAML example must be valid for current Home Assistant syntax. Check it against Home Assistant's REST sensor and automation docs and cite them. Use placeholder tokens only.

### Decisions

1. **Use the platform form `sensor: - platform: rest`, not the integration-level `rest:` block.** The RESTful Sensor page lists both, deprecates neither, and recommends the platform form when one endpoint feeds one sensor, which is our case. `unique_id` is documented on the platform form, so the sensor can be renamed in the UI. In one sentence, the doc should mention that `rest:` also works if someone later wants a second sensor from the same call.
2. **The notify gate is a `condition` step inside `actions`, after `homeassistant.update_entity`, not in the automation's `conditions:` block.** `conditions:` is evaluated before any action runs, so it would test yesterday's value. A condition step inside the sequence stops the steps that follow when it is false. The doc must say this in one line, because it is the mistake people will make when "tidying" the YAML.
3. **The condition is `condition: state` on `attribute: has_engagement` with `state: true`, unquoted.** The State condition page says an attribute keeps its own type, so `true` must be written without quotes. A quoted `"true"` never matches.
4. **Use current automation keys:** `triggers:` / `- trigger: time`, `conditions:`, `actions:` / `- action:`. Add one note that installs older than 2024.10 use `trigger:` / `platform: time` / `service:`.
5. **Use `notify.mobile_app_<device>` with `data.title` and `data.message`.** This is the companion app's documented action, and it supports a title. Add one sentence saying `notify.send_message` with a `notify.*` entity target also works, but it has no title.
6. **`json_attributes` lists exactly `has_engagement`, `summary`, `bluesky`, `mastodon`, `data_as_of`, `since` and `until`. Leave out `posts`.** It can grow large, and Home Assistant does not record large attributes. `bluesky` and `mastodon` are nested objects, which the platform stores as dict attributes.
7. **State is `{{ value_json.total }}`.** Use `scan_interval: 86400` and `timeout: 30`. The sensor polls once at startup and then once a day. The 9:00 AM automation forces the poll that matters.
8. **Write the automation as an `automations.yaml` list item, with `id:`.** This is what `automation: !include automations.yaml` (the default config) expects. Also say it can be pasted into the UI editor's **Edit in YAML**.

### 1. `docs/home-assistant.md`, section by section

Title: `# Home Assistant: daily engagement check`. Open with one paragraph: every morning Home Assistant asks the site what changed on Bluesky and Mastodon in the last 24 hours, and if anything did, it sends a phone notification with a one-sentence summary. It uses a read-only API token and makes one request a day. Then use these sections, in this order.

**1. What the endpoint returns.** `GET https://www.opencircuitsf.com/api/v1/engagement`, with header `Authorization: Bearer <token>`. The token is never accepted in the query string. GET only: any other method gets `405`. Every response carries `Cache-Control: no-store`. By default the window is the last 24 hours ending at the request, `(since, until]`. Optional `?hours=1..168` or `?since=<RFC 3339, within the last 30 days>` change it, but never both. Give a sample response as a `json` fence, built only from the struct tags:

    {
      "since": "2026-11-07T17:00:00Z",
      "until": "2026-11-08T17:00:00Z",
      "data_as_of": "2026-11-08T16:45:12Z",
      "has_engagement": true,
      "total": 3,
      "bluesky":  {"likes": 1, "reposts": 1, "replies": 0, "quotes": 0, "mentions": 0, "total": 2},
      "mastodon": {"likes": 0, "reposts": 0, "replies": 1, "quotes": 0, "mentions": 0, "total": 1},
      "posts": [
        {"event": "Intro to Soldering", "event_date": "2026-11-20", "wave": "announce", "channel": "bluesky",
         "url": "https://bsky.app/profile/example/post/abc", "posted_at": "2026-11-06T18:00:00Z",
         "likes": 1, "reposts": 1, "replies": 0, "quotes": 0, "total": 2}
      ],
      "summary": "3 new interactions: Bluesky 2 (1 like, 1 repost), Mastodon 1 (1 reply)."
    }

This must be valid JSON. `announce` is a real wave name (`internal/outreach/channels.go`: `announce`, `reminder`, `last-call`). Add a field table:

| Field | Meaning |
|---|---|
| `total` | New interactions across both channels. This is the sensor state. |
| `has_engagement` | `true` when `total > 0`. |
| `summary` | The notification sentence, ready to send. |
| `bluesky`, `mastodon` | Per-channel `likes`, `reposts`, `replies`, `quotes`, `mentions`, `total`. |
| `posts` | Per-post deltas: `event`, `event_date` (Pacific date or `null`), `wave`, `channel`, `url`, `posted_at`, the four counters and `total`. |
| `data_as_of` | Time of the newest engagement snapshot, or `null` if there are none. |

The empty `summary` is `No new engagement on Bluesky or Mastodon in the last 24 hours.` Quote it verbatim, because the always-notify variant sends it.

**2. Create the token.** Steps, in the words the UI uses:
- Sign in to the admin console.
- Open **Settings**, then the **API tokens** section. Its direct link is `https://www.opencircuitsf.com/admin#/settings?section=api` (`adminSettingsHash('api')` in `web/src/lib/adminRouter.ts`).
- Under **Name**, type `Home Assistant`, which is the field's placeholder.
- The form shows **Access: Read engagement (engagement:read)**. That is the only scope today, and it is applied automatically.
- Click **Create token**.
- A box appears: **Copy this token now. It will not be shown again.** Click **Copy**, then **Done**.
- The table row shows **Name**, **Access**, **Prefix** (the first 12 characters, `ocsf_…`), **Created**, **Last used** (`Never` until first use, updated at most about once a minute) and **Status** (`Active`).

Tokens start with `ocsf_` and are 48 characters long.

**3. Store it in `secrets.yaml`.** Fence:

    # secrets.yaml, next to configuration.yaml
    ocsf_engagement_auth: "Bearer ocsf_PASTE_THE_TOKEN_FROM_SETTINGS_HERE"

The value includes the word `Bearer` and a space. The RESTful Sensor page says to put `Bearer` in the secrets file. Never put the token inline in `configuration.yaml`. Don't commit `secrets.yaml` if your config is in git.

**4. The sensor (`configuration.yaml`).** Fence:

    sensor:
      - platform: rest
        name: "Open Circuit engagement"
        unique_id: ocsf_engagement
        resource: https://www.opencircuitsf.com/api/v1/engagement
        method: GET
        headers:
          Authorization: !secret ocsf_engagement_auth
        value_template: "{{ value_json.total }}"
        json_attributes:
          - has_engagement
          - summary
          - bluesky
          - mastodon
          - data_as_of
          - since
          - until
        scan_interval: 86400
        timeout: 30

Notes:
- If `configuration.yaml` already has a `sensor:` key, add the list item under it. A second `sensor:` key is a YAML error.
- The entity id is `sensor.open_circuit_engagement`. Check it under Settings → Devices & services → Entities.
- After a restart, open Developer tools → States and look at it. The state is a number, and the attributes include `summary`.

**5. The daily automation (`automations.yaml`).** Fence:

    - id: ocsf_daily_engagement
      alias: "Open Circuit daily engagement"
      description: "At 9:00 AM, refresh the engagement sensor and notify if there is anything new."
      mode: single
      triggers:
        - trigger: time
          at: "09:00:00"
      conditions: []
      actions:
        - action: homeassistant.update_entity
          data:
            entity_id:
              - sensor.open_circuit_engagement
        - condition: state
          entity_id: sensor.open_circuit_engagement
          attribute: has_engagement
          state: true
        - action: notify.mobile_app_YOUR_DEVICE
          data:
            title: "Open Circuit SF"
            message: "{{ state_attr('sensor.open_circuit_engagement', 'summary') }}"

Notes:
- Replace `YOUR_DEVICE` with the phone's action name. Find it in Developer tools → Actions by typing `notify.mobile_app`.
- The time is in Home Assistant's own time zone. The window is the 24 hours before the request, so a daily 9:00 AM run covers each moment once.
- Why the condition is a step and not under `conditions:`: see decision 2.
- **Variant, notify every day:** delete the `condition` step. On quiet days the message is the "No new engagement…" sentence.

**6. Check it by hand with `curl`.** Keep the token out of shell history:

    read -rs OCSF_TOKEN   # paste the token, press Return
    curl -s -w '\nHTTP %{http_code}\n' -H "Authorization: Bearer $OCSF_TOKEN" https://www.opencircuitsf.com/api/v1/token
    curl -s -w '\nHTTP %{http_code}\n' -H "Authorization: Bearer $OCSF_TOKEN" https://www.opencircuitsf.com/api/v1/engagement
    unset OCSF_TOKEN

- The probe `/api/v1/token` accepts any valid token, whatever its scope. It returns `{"name":"Home Assistant","prefix":"ocsf_…","scopes":["engagement:read"]}`, with the prefix being the first 12 characters, plus `HTTP 200`.
- The engagement call returns the JSON in section 1.
- Add one more line: `curl -s -o /dev/null -w '%{http_code}\n' https://www.opencircuitsf.com/api/v1/engagement` prints `401` with no header.
- Also mention `?hours=168` as a way to see a week at once.
- These commands use `-s`, not `-v`, which would print the header, and the token with it, to the terminal.

**7. Troubleshooting.** A table: status, body, cause, what to do.

| What you see | Body | Cause | Do this |
|---|---|---|---|
| `401` | `{"error":"unauthenticated"}` (plus `WWW-Authenticate: Bearer realm="opencircuitsf"`) | Any of: no `Authorization` header, missing `Bearer ` prefix, mistyped or truncated token, unknown token, revoked token. The response never says which. | Check `secrets.yaml` has `Bearer ` and the whole 48-character `ocsf_…` value. Run the probe with curl. In Settings → API tokens, check the row's Status is `Active`. If the token is lost or revoked, create a new one (section 8). |
| `403` | `{"error":"forbidden"}` | The token is valid but lacks `engagement:read`. | The probe's `scopes` shows what it has. Create a new token. Every token the Settings form makes has this scope. |
| `400` | `{"error":"<message>"}` | Only from the optional `hours` / `since` parameters. The exact messages are listed below. | Remove the parameter, or fix it as the message says. The sensor above sends none. |
| `404` | — | The URL is mistyped, or the server is older than this feature. | Check `resource:`. Make sure the site has been deployed with `#0653`. |
| `405` | — | The sensor uses `method: POST`. | Use `GET`. |
| `500` | `{"error":"internal_error"}` or `{"error":"internal error"}` | Server-side failure: token lookup or the engagement query. | Retry later. The operator checks `journalctl -u opencircuit`. |
| State `unknown` / unavailable | — | Any non-JSON or error response (no `total`), or a timeout. | Check Settings → System → Logs for the `rest` warning, then run the curl checks. |
| Stale `data_as_of` | — | Snapshots are captured hourly for posts under 7 days old, daily from 7 to 30 days, and not at all after 30 days. A `data_as_of` up to about a day old is normal when the newest post is a week or more old. `null`, or older than a day, means either no post is younger than 30 days (nothing to track, so `total` is 0 and that's correct) or the tracker isn't capturing. | Check the posts are still under 30 days old. If they are, have an admin check **Settings → Outreach → Connections** for both channels and look at the server log. |
| The notification shows yesterday's numbers | — | The refresh hadn't finished when the condition ran. This is unlikely with a once-a-day `scan_interval`. | Add `- delay: "00:00:05"` after the `update_entity` step. |

Quote the 400 messages verbatim from the handler:
- `use either hours or since, not both`
- `hours must be a whole number from 1 to 168`
- `since must be an RFC 3339 time`
- `since must not be in the future`
- `since must be within the last 30 days`

**8. Revoking and rotating.**

Revoke:
- Settings → API tokens, then **Revoke** on the row.
- Confirm the prompt: *Revoke "Home Assistant"? Anything using it will stop working on its next request.*
- The Status becomes `Revoked <date>`. The row stays in the list, and a revoked token never authenticates again.

Rotate without a gap:
1. Create a new token, named for example `Home Assistant 2027`, and copy it.
2. Replace the value in `secrets.yaml`, keeping `Bearer `.
3. Restart Home Assistant. A change to `secrets.yaml` is only read when the YAML that uses it is reloaded; a restart is the reliable way.
4. Run the curl probe with the new token. Or call `homeassistant.update_entity` from Developer tools → Actions and check the new row's **Last used** stops reading `Never`. It updates at most about once a minute.
5. Revoke the old row.

Rotate whenever the token may have leaked (pasted somewhere, in a backup, or in a shared config repo). Otherwise rotate at whatever interval you like; tokens don't expire.
