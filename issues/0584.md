## Review notes

Opus review, 2026-10-18. Passed, with one small fix committed by the reviewer (`7118905`).

- **B1 / item 1.** `dirty` is derived from `buildPatch(group, draft)` per group; Test connection is disabled and reads "Save, then test" while it is non-empty, and a pass reads "Tested the saved credentials: …". The backend still tests stored config only, which is exactly why the disable matters. Mutation: dropping `dirty` from the button's `disabled` fails the "Save, then test" test; file restored byte-identical (sha256 `868362ee…993205` before and after).
- **B2, B5, B6, M1 / item 2.** Failures and save errors go to a persistent `<p class="text-error" role="alert">` prefixed "Could not connect:"; successes and saves stay in the `role="status"` line, so saved, passed and failed no longer share one green line. The Configured line gains "· last test failed/passed", cleared on save. Text, not colour, carries the meaning.
- **B4 / item 3.** A set secret shows "Saved" (database) or "From environment" beside the label and a masked placeholder. The review's alternative placeholder copy was not used; the issue's criterion asks only for a masked placeholder. The write-only secret handling from `#0564` (§6) is intact: the field value stays blank and nothing secret is rendered.
- **B3, B7 / items 4–5.** Jump list, `settings-general|server|outreach` anchors, `#/settings?section=outreach` parsing, and all three outreach "Open Settings" links use `adminSettingsHash('outreach')`. One Outreach panel holds the outreach server-settings group and the connections.
- **Fixed in review.** The deep-link scroll fired once General settings loaded, but the Server settings panel sits above Outreach and loads afterwards, growing by many fields. A one-shot `scrollIntoView` does not follow its target in a browser without scroll anchoring (Safari, which the admin is used in), so the link would land well short of Outreach, not "slightly". `ServerSettings` now takes an `onloaded` callback, and the Outreach scroll waits for it. A new jsdom test holds `getServerSettings` pending and asserts no scroll until it resolves; reverting the wait fails that test, and the file was restored byte-identical.
- **B8 / item 5.** `applyKind` gives one badge per group; a mixed group keeps per-field notes, the others lose them. The General panel's "Applies immediately" is right, since those settings are read from the database per request.
- **B9 / item 6.** A disabled primary uses `--bg-subtle` / `--text-muted` at full opacity, matching the neutral look of other disabled buttons.
- **§6.** Live-region convention kept: both lines render unconditionally and stay empty when there is nothing to say. No outreach page, print, scheduling or edit code touched.
- **Verification** (load average about 3–6): `ISSUE=0584R scripts/check.sh web` passed before and after the fix: svelte-check 0 errors, 0 warnings; vitest 71 files, 4539 tests (4538 before the new one). The two `#0592` failures the implementer saw were gone by review time. All evidence is jsdom; badge and jump-list layout have not been checked in a real browser.

## Resolution notes

> 🟢 Resolved 2026-10-18 — Test connection can no longer vouch for an unsaved credential, failures are an alert in error colour, and Settings has one deep-linkable Outreach section; reviewer made the deep link wait for the panel above it (`7118905`).

## Resolution

1. `OutreachConnectionGroup.svelte`: Test connection is disabled and reads "Save, then test" while `buildPatch(group, draft)` is non-empty (per group); a passing result reads "Tested the saved credentials: ...".
2. Failures render in a persistent `<p class="text-error" role="alert">` prefixed "Could not connect:"; successes and saves stay in the `role="status"` line. The "Configured" line gains "· last test failed" / "· last test passed" (cleared on save).
3. A set secret shows a "Saved" badge (database) or "From environment" badge beside its label and a `••••••••` placeholder.
4. `adminRouter.ts` gains `SETTINGS_SECTIONS`, `adminSettingsHash()` and `settingsSectionFromQuery()`. Settings has a jump list (General, Server settings, Outreach), each section is an anchor (`settings-general|server|outreach`), and `Admin.svelte` scrolls to the section named by `#/settings?section=...` once settings finish loading. The Open Settings links in `OutreachPanel`, `OutreachLinks` and `OutreachBulkActions` now use `adminSettingsHash('outreach')`.
5. One **Outreach** panel holds the three outreach server settings (`ServerSettings scope="outreach" bare`) and the connections (`OutreachConnections bare`). New `ApplyBadge.svelte` shows one "Applies immediately" / "Applies at next deploy" badge per group (a mixed group says "Some fields apply at next deploy" and keeps per-field notes); the per-field sentences are gone.
6. `Button.svelte`: a disabled primary uses the neutral subtle background, not an accent tint.

Notes: `OutreachWorkshop.behavior.test.ts` line asserting the Open Settings href was updated to `#/settings?section=outreach` in the working tree only. That file and `OutreachWorkshop.svelte` carry the #0592 agent's uncommitted work, so they were not staged here. The deep-link scroll runs when the settings panel finishes loading; server settings and connections load afterwards, so on a slow connection the section can shift slightly after landing.
