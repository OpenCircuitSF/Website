## Description

`#0433`'s planning pass found that the Go service **cannot write to
`/var/www/media` today, for two independent reasons** — and that fixing either
one alone changes nothing:

1. **Ownership.** The directory is `ec2-user:ec2-user 0755`; the service runs as
   `uid=990(opencircuit)` with no supplementary groups.
2. **`ProtectSystem=strict`** in `opencircuit.service` makes the whole hierarchy
   read-only **regardless of mode**. Correcting the group and mode without
   touching this leaves the write still failing, and the failure would look like
   a permissions bug that had just been fixed.

This issue is that enablement, split out of `#0433` on the planning pass's own
recommendation, so correct code is not stalled behind an approval it does not
need. `#0433`'s server and SPA work is fully provable locally with a temporary
directory.

## What it asks the user for

One question, answerable in one read:

> May we make two changes to production — give `/var/www/media` group ownership
> `opencircuit` with mode `2775` (setgid), and add `ReadWritePaths=/var/www/media`
> to `opencircuit.service`?

**Existing files, their URLs, and the `scp` workflow are unaffected**: the change
is to the directory's group and mode, not to the files' ownership or their `0644`
mode. The setgid bit is what keeps newly written files group-owned by
`opencircuit` so both paths keep working.

## Acceptance criteria

1. **Nothing runs on the box without the user's explicit approval** (`CLAUDE.md`
   §5b, §9). If approval does not come, the prepared instruction is the
   deliverable and this closes as prepared-not-run — the shape `#0447` used.
2. The exact commands, in order, with what each does and what to expect:
   the `chgrp`/`chmod`, the `ReadWritePaths=` edit, `daemon-reload`, and the
   service restart. State plainly that a restart briefly interrupts the site.
3. **Verify the existing images afterwards by hash, not by status code.** That is
   §7's standing lesson from the `/.well-known/` carve-out: a `200` proves
   something answered, not that the right bytes did. Both files' SHA-256 must be
   unchanged, and `#0417` recorded their sizes and dimensions.
4. The unit change belongs in `deploy/systemd/opencircuit.service` in the repo,
   not only on the box, so a rebuilt server gets it — the same rule `#0447`
   followed for the certbot hook.
5. **Do not weaken `ProtectSystem=strict` itself.** `ReadWritePaths=` is the
   narrow, intended escape hatch; changing the mode of the whole protection is
   not.
6. Confirm the service still starts and the site still serves before declaring
   success, and record what you ran.
