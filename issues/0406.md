## Description

`web/src/lib/liveRegionGuard.structuralGuard.test.ts` carries a `#0306`
measurement comment that enumerates the `KNOWN_STABLE_BRANCH_SITES` entries and
concludes "All twelve clear …". `#0396` added a thirteenth — the CRT commands
per-row width warning — without updating the prose.

Nothing is unprotected: the guard measures every entry at run time, and the
comment is careful enough to say "then-current", so it is not strictly false.
The cost is narrower and duller — a reader counting entries against the prose
miscounts, and the discrepancy invites a second look at a guard that is
actually fine.

This is the drift class `CLAUDE.md` §11 already documents for the PRD section
index: a hand-maintained count next to the thing it counts, with nothing
tying them together. §11's table drifted twice before it was guarded, and
neither pass noticed.

## Acceptance criteria

- [ ] The comment's count matches the array, and names the thirteenth entry alongside the others
- [ ] An assertion ties the prose to the array so this cannot drift silently again — the count in the comment and `KNOWN_STABLE_BRANCH_SITES.length` must be checked against each other, not merely both edited today
- [ ] That assertion fails if an entry is added without updating the comment — proved by mutating an **in-memory copy**, never the file on disk (`CLAUDE.md` §8a)
- [ ] The oracle is not the same bytes as its subject: a single edit must not be able to satisfy both the assertion and the thing it checks (`CLAUDE.md` §8, the `#0258` rule)
- [ ] `scripts/check.sh web` passes

## Notes

Found by `#0403`/`#0396`'s review pass, 2026-09-03, which confirmed the guard
itself is sound — it mutation-tested it on an in-memory copy and showed the
suite passes *because of* `#0396`'s entry rather than in spite of it.

Low priority. Filed because a stale count next to a security-adjacent guard is
exactly the kind of small wrongness that erodes trust in the guard itself, and
because the fix is cheap.
