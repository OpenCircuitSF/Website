## Description

Phase 0 copied the ShortLinks skeleton and Phase 0's issues only required the *shortener* to be stripped, not the *branding*. What survives is not cosmetic: test fixtures assert `go.sstools.co` as the WebAuthn relying party, deploy files name a `shortlinks` service and config path, and several code comments cite issue numbers from another project's tracker.

This blocks [#0008](0008.md). Its acceptance criteria require the passkey stack to be verified against this project's relying party (`opencircuitsf.com` apex / `https://www.opencircuitsf.com` origin, per PRD §9), but the auth tests pin the old values, so they would pass while proving the wrong thing.

> 🟢 Resolved 2026-08-18 — Every ShortLinks identifier is gone from `internal/`, `cmd/`, `web/src/`, and `deploy/`, the relying party is now the apex `opencircuitsf.com` with the `www` origin (not transposed), the deploy assets are renamed with the hardening block byte-identical and the vhost redirecting apex → www per production; independently re-verified with `TEST_DATABASE_URL` exported — zero failures, zero skips, every DB-backed package reporting real elapsed time.

## Root cause

Phase 0's skeleton copy (`34b80f3`) brought over ShortLinks' test fixtures, deploy assets, and ~90 `#NNNN` code comments verbatim. Later work (`#0002`, `#0003`, `#0007`, `#0027`, `#0065`, etc.) added its own, correct, forward references to this tracker on top of that, so the same `#NNNN` syntax ended up meaning two different things in the same tree depending on which commit introduced the line — and 21 of the 30 stale numbers happened to collide with real issues here, resolving silently to unrelated work instead of failing loudly.

## Fix

Disambiguated every `#NNNN` reference in `internal/`, `cmd/`, and `web/src/` by provenance rather than by whether the number happened to resolve to something real here, using `git blame`/`git log -L` against `34b80f3`:

- **Introduced in `34b80f3`** (the skeleton copy): treated as ShortLinks' own numbering regardless of collision, and rewritten to describe the guarded behavior in prose with no issue number. This is the majority of the diff — 30 distinct numbers, ~90 comment sites across `internal/auth`, `internal/audit`, `internal/handlers`, `internal/middleware`, `cmd/opencircuit`, and `web/src/`. `internal/auth/login.go:40`'s `#0025` (the issue's specific call-out — it silently resolved to this tracker's unrelated "Create the subscribers migration") is in this set.
- **Introduced after `34b80f3`**, i.e. by our own commits: left alone when the number already resolves correctly here (`#0002`, `#0003`, `#0007`, `#0010`, `#0014`, `#0027`, `#0048`, `#0065` — verified by reading the actual commit that introduced each line and confirming its message/title matches the comment's claim).

Also fixed, per the issue's other acceptance criteria:

- `internal/auth/registration_test.go`'s `testRPID`/`testRPOrigin` now `opencircuitsf.com` / `https://www.opencircuitsf.com`; every `virtualwebauthn.RelyingParty{Name: "ShortLinks"}` and `webauthn.Config.RPDisplayName` now reads `"Open Circuit SF"`.
- `web/src/lib/webauthn.test.ts` and `internal/handlers/settings_test.go` got matching RP-value updates.
- `auth.SessionCookieName` is now `"opencircuit_session"` (was `"shortlinks_session"`) — every reference goes through the symbolic constant, so no literal string elsewhere needed touching.
- `internal/auth/ses_mailer.go`/`ses_mailer_test.go`: subject lines, body copy, and example From/address strings now say "Open Circuit SF" / `noreply@opencircuitsf.com`.
- `deploy/apache/go.sstools.co.conf` → `opencircuitsf.com.conf` (`git mv`): one vhost, `ServerName www.opencircuitsf.com` with `ServerAlias opencircuitsf.com`, and a `RewriteRule` 301-redirecting any non-`www` `Host` to `www` before the `ProxyPass` rules run — `www` stays canonical and the apex redirects to it, matching production (`CLAUDE.md` §7), not `#0064`'s inverted (and known-defective) criteria.
- `deploy/systemd/shortlinks.service` → `opencircuit.service` (`git mv`): `User`/`Group`/`EnvironmentFile`/`ExecStart` retargeted to `opencircuit`; the hardening block (`NoNewPrivileges`, `ProtectSystem=strict`, `PrivateTmp`, `RestrictAddressFamilies`, etc.) is byte-identical to the original — diffed line ranges directly to confirm.
- Both deploy `README.md`s, and the section of `docs/deployment.md` that described these two files as "ShortLinks' own assets, unadapted" (now stale and pointing at nonexistent filenames after the rename).
- Two branding leftovers the issue's grep inventory didn't name because they don't match a `#NNNN` or `sstools`/`shortlinks` pattern: `web/src/lib/Footer.svelte`'s GitHub link pointed at `brennanMKE/ShortLinks` instead of this repo, and four `internal/handlers/static_test.go` fixtures had `<title>Short Links</title>` baked into fake `index.html` strings.
- A few comments/docs that named ShortLinks subsystems never ported here at all — `internal/campaigns.Store` in `audit.go`'s doc comment, and `CampaignClicksChart`/`ClicksChart`/`internal/clicks` in `app.css`'s chart-color-token comments — rewritten to stop describing code that doesn't exist in this tree, rather than left to rot further.

**Deviation from the acceptance criteria's literal wording:** the criteria describe the Apache rename as "`ServerName`/`ServerAlias`... updated," which reads as one vhost. I initially wrote two vhosts (a redirect-only apex vhost plus a `www` vhost) because it's the more common idiom, then switched to a single vhost with `ServerName www.opencircuitsf.com` / `ServerAlias opencircuitsf.com` plus a `RewriteRule` to match the criteria's literal phrasing and because it needs only one `<VirtualHost>` block. Functionally equivalent either way; flagging the design choice for review.

**Out of scope, deliberately:** `docs/*.md` and `scripts/*.sh` still contain `sstools`/`shortlinks` references beyond the two deploy READMEs and the one `docs/deployment.md` section I touched (e.g. `scripts/deploy.sh`'s `go.sstools.co` default, `docs/email-setup.md`). These are outside the acceptance criteria's grep scope (`internal/`, `web/src/`, `deploy/`, `cmd/`) and, for `docs/deployment.md`/`docs/email-setup.md` at least, some are legitimate references to the *actual separate* ShortLinks service that still runs on the same box per PRD §10.1 topology (`go.opencircuitsf.com`) — not residue. Left alone; flagged for the reviewer. `internal/audit/actions.go` also still defines several unused ShortLinks-era audit action constants (`ActionLinkCreated`, `ActionURLFilterCreated`, etc., and their `Target*` counterparts) with only test usage — dead code, not a stale reference, so out of scope for this issue; worth a follow-up issue if the reviewer agrees.

Confirmed by checking both the working tree and the `34b80f3` blob directly. Net effect: 29 distinct real numbers, not 30; everything else in the inventory checked out exactly as described.
- **`--series-*` chart color tokens in `web/src/app.css` have zero consumers anywhere in this codebase** (`CampaignClicksChart`/`ClicksChart` never existed here — no clicks table, no charts package). Left the actual CSS variable definitions in place (out of scope for this issue — that's dead-code removal, not a stale reference) but fixed the comments that named the nonexistent components.
- **`internal/audit/actions.go` still defines ShortLinks-era action/target constants with no real call site** (`ActionLinkCreated`, `ActionURLFilterCreated`, `ActionCampaignLinkAssigned`, `TargetLink`, `TargetURLFilter`, etc. — this project has no links/URL-filter tables). Only `audit_test.go` references them, as an arbitrary example action string. Left alone — same reasoning as the CSS tokens above.

**Added by review (2026-08-18):**

- **The auth ceremony tests do not actually verify the relying-party values — they are tautological.** `testRPID`/`testRPOrigin` are fed into *both* the server's `webauthn.Config` *and* the `virtualwebauthn.RelyingParty` the test authenticator signs with, so the two sides are self-consistent by construction and never cross-check. Verified by mutation: setting `testRPID = "www.opencircuitsf.com"` / `testRPOrigin = "https://opencircuitsf.com"` (transposed) still passes, and so does `testRPID = "example.invalid"` / `testRPOrigin = "https://totally-unrelated.test"`. Nothing was weakened here — this is inherited structure, and the criterion ("uses `opencircuitsf.com` / `https://www.opencircuitsf.com`") is literally met. But the `## Verification` claim that the suite is "running against the real relying party" overstates what a green run proves. **[#0008](0008.md) must not treat these tests as evidence the RP is correct** — it needs a test that pins the apex/www relationship itself (e.g. asserting `NewWebAuthn` rejects an origin outside the RP ID's scope, or an explicit assertion on the configured `RPID`/`RPOrigins`).
- **`internal/audit/actions.go` still describes an API that does not exist.** The `#0098`/`#0099` numbers were stripped, but the prose left behind reads "Written by `campaigns.Store`'s `AssignLinkToCampaign`/`UnassignLinkFromCampaign` … see the doc comment on those methods" — there is no `internal/campaigns` package and no such methods anywhere in the tree. The same class of defect was correctly fixed in the adjacent `audit.go`; this site was missed. Removing the issue number also removed the only signal that the block was foreign, so it now reads more authoritative than before, not less.
- **`campaign.*` audit constants are a naming trap for Phase 5.** `ActionCampaignCreated`/`Updated`/`Deleted` are ShortLinks' *link-grouping* campaigns. `CLAUDE.md` §6 warns that those and this project's `email_campaigns` "share a word and nothing else". With the comment now reading only "// Campaign lifecycle.", a Phase 5 implementer ([#0044](0044.md)–[#0048](0048.md)) could reasonably reuse these constants for email campaigns. The dead-code removal was correctly judged out of scope for this issue, but it should be filed.
- **ShortLinks identifiers survive just outside the criterion's grep scope.** `web/package.json` / `package-lock.json` still declare `"name": "shortlinks-web"` (it prints on every `npm run` invocation), and `web/embed.go:6` still refers to `cmd/shortlinks/`. Neither is caught by the criterion's `internal/ web/src/ deploy/ cmd/` grep, but both contradict this issue's stated Expected behavior ("No ShortLinks identifier appears outside `PRD.md`, `HANDOFF.md`, `CLAUDE.md`, and issue files"). These were missed rather than deliberately deferred — the "Out of scope, deliberately" note covers only `docs/*.md` and `scripts/*.sh`.
- **`scripts/deploy.sh` is broken and the rename widens the gap.** It builds `./cmd/shortlinks` (which has not existed since `#0001` renamed it to `cmd/opencircuit`) and defaults `SERVICE=shortlinks` / `PUBLIC_URL=https://go.sstools.co`. The breakage is pre-existing — the file is untouched since `34b80f3` — and correctly out of scope here, but the unit is now `opencircuit.service`, so the script is inconsistent with the deploy assets as well as unbuildable. Belongs with [#0064](0064.md).
- **Renaming `SessionCookieName` invalidates every existing session on deploy.** Confirmed safe here: every read and write goes through the exported constant (no literal `shortlinks_session` survives anywhere in Go, TS, Svelte, docs, scripts, or deploy config), the SPA never names the cookie, and production currently serves the static placeholder, so there are no live sessions to invalidate. Recorded because the change was not in the acceptance criteria as written — it is nonetheless required by them, since `shortlinks_session` sat in `internal/auth/session.go` and would have failed the `grep` criterion.
- `git log --follow` recovers the rename for `deploy/systemd/opencircuit.service` back to `34b80f3`, but **not** for `deploy/apache/opencircuitsf.com.conf` — the vhost was rewritten enough (16 → 26 lines) to fall below git's rename-similarity threshold, so it records as delete + add. Cosmetic; the content was substantially rewritten anyway.
- The Apache vhost hardcodes `/etc/letsencrypt/live/opencircuitsf.com/` as the certificate lineage path and defines no port-80 vhost (neither did the original). ## Notes

The relying-party values are the reason this is urgent rather than tidy. `WEBAUTHN_RP_ID` is the **apex** so one passkey covers apex and www; `WEBAUTHN_RP_ORIGIN` is the **www** form because that is the host the browser is actually on. They are not interchangeable and a mismatch fails ceremonies with an opaque error — see `CLAUDE.md` §7 and PRD §9.

Note the direction of the Apache redirect. `#0064`'s criteria say `www` redirects to the apex; that is **backwards** relative to production and is recorded as a known tracker defect in `CLAUDE.md` §7. Follow production, not `#0064`.

`deploy/systemd/README.md` and `deploy/apache/README.md` reference the old filenames and need updating alongside the renames.
