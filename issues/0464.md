## Description

Six issues — `#0429`, `#0441`, `#0450`, `#0453`, `#0457`, `#0461` — have built and
widened a guard comparing how `godotenv` and systemd's `EnvironmentFile=` read
`.env.example`. **Every one of them measured the godotenv side by running it,
and reasoned about the systemd side from documentation.**

`#0461` made that explicit as a design constraint: it chose to forbid quoted
values partly because "systemd's quoting grammar is unverifiable in this
environment". `#0461`'s reviewer corrected the framing:

> The systemd side is not unverifiable — only unverifiable **on this laptop**.
> Production runs systemd on AL2023 (`CLAUDE.md` §7); one transient unit with an
> `EnvironmentFile=` would settle the trimming and quoting questions this entire
> lineage has reasoned around.

## Why it is worth doing, and what it would settle

The lineage's one *measured* systemd fact is the one that broke production's
boot path: `#0429`, where a trailing `#` comment became part of the value. Every
other systemd claim in the guard is inference.

That is not idle: `#0461`'s bounce was caused precisely by an **undisclosed
change of the systemd oracle** — from "keeps raw bytes" to one that trims
whitespace — which no sanity check could catch, because the original test
alphabet contains no space. A measured oracle would have made that swap
impossible to make silently.

Open questions a single measurement run would answer:

- does `EnvironmentFile=` trim leading and trailing whitespace from a value?
- does it strip matched single or double quotes, and does it differ between them?
- how does it treat a backslash mid-value, and one at end of line?
- how does it treat `$VAR`, `${VAR}` and `$(…)`?

## This is production, and needs approval

**Do not run anything on the box without the user's explicit approval** (§5b,
§9). Prepare the plan, state exactly what would run, and ask.

The shape that is defensible: a **transient** systemd unit in a scratch

action is to print its environment to the journal. It touches no project
service, no real config, and no data.

**Never** point it at `/etc/opencircuit/config.env` — that is a secrets file, and

### Shape and why it is safe

- Runs entirely as `ec2-user` (uid 1000) — **no `sudo`, no root, anywhere in
  the sequence.** Confirmed read-only: `ec2-user` already has an active
  `systemd --user` instance on the box (`loginctl show-user ec2-user` →
  `State=active`, `RuntimePath=/run/user/1000`), so a `--user`-scope
  transient unit needs no privilege escalation at all.
- Uses **`systemctl --user`**, not the system manager. It touches only:
  - `$XDG_RUNTIME_DIR/oc0464/` — a scratch subdirectory of the user's own
    tmpfs runtime directory (mode 700, wiped automatically on logout or
    reboot even if cleanup is skipped), holding the two synthetic
    `EnvironmentFile=` sources;
  - `$XDG_RUNTIME_DIR/systemd/user/` — the user manager's own *runtime* unit
    search path (the per-user analogue of `/run/systemd/system/`; confirmed
    valid via the `%t` specifier, see below), holding the two throwaway unit
    files.
- **Never references `/etc/opencircuit/config.env`, `opencircuit.service`,
  or any other project unit.** Nothing under `/etc` is read or written.
  Apache, PostgreSQL, and every currently-running service are untouched —
  a `--user`-scope unit cannot affect them even in principle.
- The one command that could theoretically shell out — the `$(TRUE)` probe
  value — is deliberately harmless even in the unexpected case that
  `EnvironmentFile=` ever performed real command substitution (it does not,
  per every source read so far, but that inference is exactly what this
  issue exists to stop trusting): `TRUE` (uppercase) is not a real command
  on this box, so at worst it fails silently with "command not found"; it
  cannot execute anything. Uppercase is also required to exercise
  `envDollarExpansion`'s documented `$(FOO)` bug on the `godotenv` side (its
  `expandVarRegex` only matches an uppercase/digit/underscore name) — a
  lowercase `$(true)` was tried locally first and turned out to not exercise
  that bug at all (see the dry run below), which is itself the kind of
  mistake this issue is about catching before it reaches the box.
- **Two units, not one**, specifically so a hard parse failure on the
  unterminated-quote line cannot mask the other fourteen results: `oc0464-main`
  carries the well-formed battery, `oc0464-quote-edge` carries the single
  malformed line in isolation.
- Output is filtered to `OC0464_`-prefixed names before it ever reaches the
  journal (`env | grep '^OC0464_' | sort`), so nothing from the real
  environment (`PATH`, `HOME`, etc.) is captured alongside it.

### Why the synthetic values cannot be mistaken for secrets

Every key is prefixed `OC0464_` (a fictitious issue-numbered namespace no
real config variable will ever collide with — `config.go` reads no variable
by this prefix, confirmed against `TestEnvExampleCoversLoaderVariables`'s own
extraction). Every value is a plain English test word (`plainvalue`,
`leadingspace`, `bothspace`, `interior`, `continued`) or a placeholder name
(`NOTAVAR`, itself declaring in its own spelling that it is not a real
variable) — none resembles a token, a connection string, a hostname, or
anything with the shape of a credential. The journal entries these produce
are indistinguishable, at a glance or on close reading, from any other
throwaway test fixture; nothing here needs redaction because nothing here
could be misread as sensitive in the first place.

### Exact commands, in order

Run from a local shell, over `ssh`, as a single `bash -s` script so the
remote interpreter is unambiguous (CLAUDE.md §8: the agent's own shell is
zsh, every project script is bash, and pasting bash into the wrong
interpreter has silently misled a verification before). The heredoc
delimiters are single-quoted throughout so the `$`, backslashes, and quote
characters inside the synthetic files are written to disk **verbatim** —
none of them are evaluated by the local or remote shell, only by `systemd`
when it later parses the file:

**Copying this block:** it is now a fenced block with no leading
indentation, so a verbatim copy needs no tab-stripping or de-indenting
before it runs — that is what makes the five heredoc terminators
(`REMOTE`, two `ENVFILE`, two `UNITFILE`) close correctly regardless of
the editor or terminal used to copy it. One hazard survives the format
change regardless: two fixture lines, `OC0464_TRAIL_WS` and
`OC0464_BOTH_WS`, end in three literal spaces that a
trailing-whitespace-trimming editor or paste target can still remove
silently; they are two of the four things being measured, and the
`cat -A` step inside the block below is what makes their loss visible
instead of letting a trimmed fixture confirm the whitespace hypothesis
by accident.

```
ssh ec2 bash -s <<'REMOTE'
set -uo pipefail

RUNTIME_DIR="${XDG_RUNTIME_DIR:?XDG_RUNTIME_DIR not set -- abort rather than guess}"
WORK="$RUNTIME_DIR/oc0464"
UNITDIR="$RUNTIME_DIR/systemd/user"
mkdir -p "$WORK" "$UNITDIR"
chmod 700 "$WORK"

cat > "$WORK/main.env" <<'ENVFILE'
OC0464_PLAIN=plainvalue
OC0464_LEAD_WS=   leadingspace
OC0464_TRAIL_WS=trailingspace   
OC0464_BOTH_WS=   bothspace   
OC0464_SQ_INTERIOR_WS='  interior  '
OC0464_DQ_INTERIOR_WS="  interior  "
OC0464_SQ_DOLLAR='SYNTH$NOTAVAR'
OC0464_DQ_DOLLAR="SYNTH$NOTAVAR"
OC0464_BARE_DOLLAR=SYNTH$NOTAVAR
OC0464_BRACE_DOLLAR=SYNTH${NOTAVAR}
OC0464_PAREN_DOLLAR=SYNTH$(TRUE)
OC0464_BACKSLASH_MID=SYNTH\Zvalue
OC0464_BACKSLASH_DOLLAR=SYNTH\$NOTAVAR
OC0464_TRAILING_BACKSLASH_A=SYNTH\
OC0464_TRAILING_BACKSLASH_B=continued
ENVFILE

cat > "$WORK/quote-edge.env" <<'ENVFILE'
OC0464_SQ_UNBALANCED='unterminated value with no closing quote
ENVFILE

echo '=== fixture bytes as written -- $ marks end of line, ^I a stray tab ==='
cat -A "$WORK/main.env"
cat -A "$WORK/quote-edge.env"

cat > "$UNITDIR/oc0464-main.service" <<'UNITFILE'
[Unit]
Description=OC0464 scratch probe (main) -- measures systemd EnvironmentFile= parsing for issue #0464; not a real service, safe to delete

[Service]
Type=oneshot
EnvironmentFile=%t/oc0464/main.env
ExecStart=/bin/sh -c 'env | grep "^OC0464_" | sort'
StandardOutput=journal
StandardError=journal
UNITFILE

cat > "$UNITDIR/oc0464-quote-edge.service" <<'UNITFILE'
[Unit]
Description=OC0464 scratch probe (quote-edge) -- measures systemd EnvironmentFile= parsing of an unterminated quote for issue #0464; not a real service, safe to delete

[Service]
Type=oneshot
EnvironmentFile=%t/oc0464/quote-edge.env
ExecStart=/bin/sh -c 'env | grep "^OC0464_" | sort'
StandardOutput=journal
StandardError=journal
UNITFILE

systemctl --user daemon-reload

echo '=== starting oc0464-main.service ==='
systemctl --user start oc0464-main.service
echo "main start exit: $?"

echo '=== starting oc0464-quote-edge.service (expected to behave differently -- that is the measurement) ==='
systemctl --user start oc0464-quote-edge.service
echo "quote-edge start exit: $?"

echo '=== journal: oc0464-main.service ==='
journalctl --user -u oc0464-main.service --no-pager -o cat

echo '=== journal: oc0464-quote-edge.service ==='
journalctl --user -u oc0464-quote-edge.service --no-pager -o cat

echo '=== unit status: oc0464-quote-edge.service (in case the bad line failed the unit rather than just its own key) ==='
systemctl --user status oc0464-quote-edge.service --no-pager || true

echo '=== cleanup ==='
systemctl --user stop oc0464-main.service oc0464-quote-edge.service 2>/dev/null || true
systemctl --user reset-failed oc0464-main.service oc0464-quote-edge.service 2>/dev/null || true
rm -f "$UNITDIR/oc0464-main.service" "$UNITDIR/oc0464-quote-edge.service"
systemctl --user daemon-reload
rm -rf "$WORK"

echo '=== confirm removed ==='
systemctl --user list-unit-files 'oc0464-*' --no-pager || true
ls -la "$WORK" 2>&1 || echo "scratch dir gone, as expected"
REMOTE
```

Validated before being proposed: `bash -n` on the script body is clean, and
`shellcheck -s bash` reports zero issues after one fix (an initial
`mkdir -p -m 700 "$WORK" "$UNITDIR"` only applies `-m` to the deepest of
several created directories per SC2174 — split into `mkdir -p` then a
separate `chmod 700 "$WORK"`).

**Re-validated on the second pass against the committed bytes, not a
de-indented copy** — the second pass's own review had flagged that the
first pass validated a hand-retyped, de-indented copy of a tab-indented
block rather than what actually landed in this file. This time the fenced
block above (including the added `cat -A` step) was extracted
programmatically from this committed file with a small Python script that
locates the ```` ``` ```` markers and the `REMOTE` heredoc bounds — no
manual retyping, no manual de-indenting, nothing for a human hand to get
wrong a second time. `bash -n` was run twice: once on the extracted
`REMOTE` heredoc's inner body alone (the script that actually executes on
the box under `bash -s`), and once on the full fenced block including the
outer `ssh ec2 bash -s <<'REMOTE'` wrapper (the exact text a verbatim copy
of the fenced block would produce). Both are clean, and `shellcheck -s
bash` on the extracted inner body reports zero issues. Because the block is
now a fenced block with no leading indentation, the bytes given to `bash -n`
and `shellcheck` are byte-identical to the bytes a verbatim copy-paste of
this file would run — there is no longer a de-indenting step standing
between "what was validated" and "what is committed."

### What is removed afterward

- Both unit files, deleted (`rm -f`), followed by `daemon-reload` so the
  user manager's own view drops them immediately rather than at next login.
- Both synthetic `EnvironmentFile=` sources and their containing directory,
  deleted (`rm -rf "$WORK"`) — and would in any case be cleared automatically
  by `logout`/reboot even if this step were skipped, since `$XDG_RUNTIME_DIR`
  is tmpfs.
- `reset-failed` clears the failed-unit record the quote-edge case is
  expected to leave behind (a oneshot unit that fails to parse its
  `EnvironmentFile=` becomes a "failed" unit, not a "never existed" one).
- The plan's own last two commands **verify** the cleanup rather than assume
  it: `systemctl --user list-unit-files 'oc0464-*'` (expected to print
  nothing) and `ls` on the now-deleted scratch directory (expected to fail).
- **What is *not* removed, deliberately:** the journal entries this produces.
  `journalctl` has no target-scoped delete short of a full vacuum, and
  vacuuming a shared user journal to erase four lines is a larger and riskier
  operation than leaving them. This is why the synthetic-values section above
  exists — the values are chosen so that a persistent journal entry is never
  a liability.
- **Also not removed, and correctly so:** `mkdir -p "$UNITDIR"` may create
  `$XDG_RUNTIME_DIR/systemd/user` itself, if it did not already exist before
  this ran. Cleanup does not remove that directory. It is not scratch space
  this plan introduces — the review pass below (see "The unit directory is
  genuinely the per-user runtime search path") confirms via `systemd-analyze
  --user unit-paths` that this exact path is one of sixteen directories
  already in the user manager's own search path, on tmpfs, and every other
  `--user` unit on the box may already depend on it existing. Removing it
  would be over-cleanup, not thoroughness, so the accounting says so
  explicitly rather than leaving it silently unmentioned.

### Documentation read on the box itself — a hypothesis, not a measurement

`man systemd.exec`'s own `EnvironmentFile=` section, read on the production
host (`ssh ec2`, read-only, AL2023's systemd 252 man pages — not a generic
internet copy), states in prose:

- unquoted: "Leading and trailing whitespace (space, tab, carriage return) is
  discarded... interior whitespace... preserved"; "A line ending with a
  backslash will be continued to the following one, with the newline itself
  discarded"; "A backslash followed by any character other than newline will
  preserve the following character, so that \\\\ will become the value \\"
- single-quoted: "can span multiple lines and contain any character verbatim
  other than single quote... No backslash-escape sequences are recognized.
  Leading and trailing whitespace outside of the single quotes is discarded"
- double-quoted: "the same escape sequences are recognized as in
  double-quoted text of a POSIX shell. Backslash followed by any of the
  characters that shell also escapes will preserve that character... A
  backslash followed by any other character is ignored; both the backslash
  and the following character are preserved verbatim"

Read at face value, this says systemd's `EnvironmentFile=` **does** trim
whitespace and **does** perform backslash-escape processing on an unquoted
value — the opposite of the "keeps raw bytes, no escaping" model this file's
own guard doc comments currently assert. **This is exactly the shape of
mistake this whole lineage exists to catch, one level up**: `#0429` through
`#0461` all show that reading a parser's own source or its own
documentation is not the same as watching it run, because both `godotenv`'s
regex and its own doc comments have already been wrong about behavior that
direct probing caught (the `$(FOO)` group-numbering bug is dead code nobody
reading `expandVariables` casually would predict). The man page on this exact
box is a better source than generic reasoning, but it is still
documentation, not a probe — this plan's synthetic battery is built
specifically to exercise every claim in this section (`OC0464_LEAD_WS`/
`_TRAIL_WS`/`_BOTH_WS` for the trim claim, `OC0464_BACKSLASH_MID` for the
escape claim, `OC0464_TRAILING_BACKSLASH_A/_B` for the continuation claim,
the two quoted-value pairs for the quoting claims) so that criterion 3's
"verify by probing, never by reading" applies here exactly as it applied to
`godotenv`. Nothing above is recorded as a fact in criterion 3's sense; it is
recorded as the hypothesis the run would test, with its source cited per the
`#0431` standing distinction this issue's own criterion 3 invokes.

### The departure from the literal remedy — accepted, and it is better

Remedy (B) told the implementer to add a sentence instructing the reader to
