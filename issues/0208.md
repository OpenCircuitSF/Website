## Description

`#0140`'s phase-3 review passed the pipefail regression guard and mapped its
boundary by execution. Two items came out of that, one per script.

**1. The guard is a source grep, so its property is textual rather than
structural.** It catches the regression that actually happened — deleting
`-o pipefail` from an otherwise unchanged `run bash -c` line — at all nine call
sites, and catches a brand-new call site appended anywhere in the file. The
review judged that scope **acceptable and honestly documented**, and this issue
does not dispute it.

But the evasion surface is real and was reproduced end to end: with `bash \`
newline `-c`, the review made the go-build step run `false` and watched the
script print `VERIFICATION PASSED` and exit `0`. Also unflagged: `/bin/bash`,
`env bash`, `$SH`, `sh -c`, a bare `bash -c` outside `run`, two spaces between
tokens, and a trailing `# pipefail` comment (which *falsely* satisfies the grep).

**The structural fix deletes the whole surface**: funnel all nine sites through
one helper — `runpipe() { run bash -o pipefail -c "$1"; }` — so no call site
spells the flag at all and there is nothing to omit.

It also removes a hazard the review found in the guard itself: the two lines
that contain `run bash -c` (48 and 50) are self-excluded only because each
happens to contain the word "pipefail" on the same line. Reformat line 48 across
two lines and the guard flags **itself** and exits 2 on every invocation,
permanently. That failure is loud and prints its own line, so it self-diagnoses
— but it should not be reachable at all.

**2. `scripts/testdb.sh` mishandles a mixed-case token.** `create 0140revX`
returns a URL naming `…revX`, while Postgres folds the identifier to `…revx`.
Every database-backed test then fails with `SQLSTATE 3D000` — which reads
exactly like a real test failure, and cost `#0140`'s reviewer a false alarm
mid-review. `drop` then fails silently and **leaks the database**.

Lower-case the token, or reject a non-lowercase one outright.

## Acceptance criteria

- [ ] All nine `run bash` call sites in `scripts/check.sh` go through one helper that owns the `-o pipefail`; no call site spells the flag
- [ ] The regression `#0140` fixed is still caught — demonstrated by mutating the helper and confirming a failing package yields `VERIFICATION FAILED` and a non-zero exit
- [ ] At least two of the review's evasion forms (the split-flag `bash \` newline `-c`, and a bare `bash -c` outside `run`) are no longer expressible as a way to lose the flag, or are caught
- [ ] The guard cannot flag itself: reformatting its own lines does not brick the script
- [ ] `scripts/testdb.sh create` handles a mixed-case token — the returned URL and the created database agree — or rejects it with a message naming the problem
- [ ] `create` followed by `drop` with a mixed-case token leaves no database behind — demonstrated by a before/after census
- [ ] `scripts/check.sh all` still reports `VERIFICATION PASSED` with the shell exit code confirmed `0` in the same run

## Notes

Reported by `#0140`'s phase-3 review under `CLAUDE.md` §9.

Criterion 2 is the one to be careful about: the point of this issue is to make
the property harder to lose, so a refactor that quietly stops catching the
original regression would be a net loss. Mutate and verify rather than assuming
the funnel preserves it.

`#0140`'s `## Review notes` carries the full evasion table with which forms fire
and which are genuinely broken — `bash -c -o pipefail` and `bash -eo pipefail -c`
both exit 1 on their own, so the guard is correct **not** to flag them.

Note `#0150` is also active in `scripts/testdb.sh`; sequence against it.
