## Description

`#0140`'s phase-3 review passed the pipefail regression guard and mapped its
boundary by execution. Two items came out of that, one per script.

**1. The guard is a source grep, so its property is textual rather than
structural.** It catches the regression that actually happened — deleting
`-o pipefail` from an otherwise unchanged `run bash -c` line — at all nine call
sites, and catches a brand-new call site appended anywhere in the file. The
review judged that scope **acceptable and honestly documented**, and this issue
does not dispute it.

But the evasion surface is real and was reproduced end to end: with `bash \`
newline `-c`, the review made the go-build step run `false` and watched the
script print `VERIFICATION PASSED` and exit `0`. Also unflagged: `/bin/bash`,
`env bash`, `$SH`, `sh -c`, a bare `bash -c` outside `run`, two spaces between
tokens, and a trailing `# pipefail` comment (which *falsely* satisfies the grep).

**The structural fix deletes the whole surface**: funnel all nine sites through
one helper — `runpipe() { run bash -o pipefail -c "$1"; }` — so no call site
spells the flag at all and there is nothing to omit.

It also removes a hazard the review found in the guard itself: the two lines
that contain `run bash -c` (48 and 50) are self-excluded only because each
happens to contain the word "pipefail" on the same line. Reformat line 48 across
two lines and the guard flags **itself** and exits 2 on every invocation,
permanently. That failure is loud and prints its own line, so it self-diagnoses
— but it should not be reachable at all.

**2. `scripts/testdb.sh` mishandles a mixed-case token.** `create 0140revX`
returns a URL naming `…revX`, while Postgres folds the identifier to `…revx`.
Every database-backed test then fails with `SQLSTATE 3D000` — which reads
exactly like a real test failure, and cost `#0140`'s reviewer a false alarm
mid-review. `drop` then fails silently and **leaks the database**.

Lower-case the token, or reject a non-lowercase one outright.

## Acceptance criteria

- [ ] All nine `run bash` call sites in `scripts/check.sh` go through one helper that owns the `-o pipefail`; no call site spells the flag
- [ ] The regression `#0140` fixed is still caught — demonstrated by mutating the helper and confirming a failing package yields `VERIFICATION FAILED` and a non-zero exit
- [ ] At least two of the review's evasion forms (the split-flag `bash \` newline `-c`, and a bare `bash -c` outside `run`) are no longer expressible as a way to lose the flag, or are caught
- [ ] The guard cannot flag itself: reformatting its own lines does not brick the script
- [ ] `scripts/testdb.sh create` handles a mixed-case token — the returned URL and the created database agree — or rejects it with a message naming the problem
- [ ] `create` followed by `drop` with a mixed-case token leaves no database behind — demonstrated by a before/after census
- [ ] `scripts/check.sh all` still reports `VERIFICATION PASSED` with the shell exit code confirmed `0` in the same run

## Implementation notes

**1. `scripts/check.sh` — structural funnel.** Replaced the source-grep
self-check with a single function, `runpipe() { run bash -o pipefail -c
"$1"; }`, and converted all nine `run bash -o pipefail -c "..."` call sites
(the `go test`/`npm run check`/`npm test` lines, plus `go build`/`go vet` in
each of the three `case "$MODE"` branches) to `runpipe "..."`. No call site
spells `-o pipefail` anywhere anymore; `runpipe()`'s own definition is the
only place it's written.

A replacement self-check confirms the funnel hasn't been bypassed by a later
edit. It scans a scratch copy of the running script (`$0`, not a hardcoded
`$REPO/scripts/check.sh` — see the "self-scan" gotcha below) with two blocks
deleted first: its own implementation (`# BEGIN GUARD-0208` … `# END
GUARD-0208`) and `runpipe()`'s definition (`# BEGIN RUNPIPE-0208` … `# END
RUNPIPE-0208`). What's left must contain: the word `pipefail` exactly zero
times outside the script's own top-of-file `set -uo pipefail` (an exact-line
exclusion, not textual coincidence); no other `bash`/`sh … -c` invocation;
and at least 9 `runpipe "` call sites. Any violation exits 2 with the
offending line(s) named.

Two gotchas hit while building this, both from trying to make the guard
un-self-flaggable (the exact property `#0208` exists to fix):

- **Marker-range self-match.** The guard's own sed command necessarily
  *mentions* the marker strings (`# BEGIN GUARD-0208` etc.) as literal
  arguments. Spelling them as one contiguous token inside that command line
  made the line match its own start-of-range pattern, which reopened a
  closed sed range and deleted everything from that line to EOF — the exact
  "guard bricks itself on reformatting" failure mode this design exists to
  eliminate, just relocated. Fixed by building each marker from two
  concatenated string literals (`"# BEGIN"" GUARD-0208"`) with no separator,
  so the raw source text never contains the full marker substring
  contiguously — the same technique used for the `pipefail`/`runpipe`
  self-match risk in the counting checks.
- **`$REPO/scripts/check.sh` vs. `$0`.** The self-check originally read a
  hardcoded path to the tracked file. A private mutant copy used for
  mutation-testing the guard (CLAUDE.md §8a: never edit the shared tracked
  script to prove a guard catches something) would then scan the *untouched
  tracked file* instead of itself, silently proving nothing regardless of
  what was mutated in the copy — caught when a deliberately-added bypass
  call site in a mutant produced a clean `VERIFICATION PASSED`. Switched to
  `"$0"` (however the running script was actually invoked), verified against
  three invocation styles: `scripts/check.sh`, `bash scripts/check.sh`, and
  an absolute path from a different `cwd`.

**2. `scripts/testdb.sh` — mixed-case token.** `name_for()` now lower-cases
the token after stripping to `[:alnum:]_`, so the name this function returns
(and that `create` embeds in its DSN) always matches what Postgres actually
creates for an unquoted identifier. Comment on the fix explains the
SQLSTATE 3D000 false-alarm and the `drop` leak it used to cause.

## Verification

**Structural funnel, normal operation:**
- `bash -n scripts/check.sh` — clean.
- `ISSUE=0208a scripts/check.sh go ./internal/... ./cmd/...` and
  `ISSUE=0208b scripts/check.sh go ./internal/... ./cmd/...` (re-run after
  the `$0` fix) — both **VERIFICATION PASSED**, 16 packages `ok`, zero
  skips, self-check step printed with no output (no regression found).
- `ISSUE=0208all scripts/check.sh all` — **VERIFICATION PASSED**; separately
  ran `ISSUE=0208exit scripts/check.sh all` redirected to a file and checked
  `$?` directly (not through a pipe) — **exit code 0**, confirmed.
- `scripts/check.sh web` (unaffected by this issue, run for completeness)
  passes independently — see `#0212`'s and `#0214`'s verification logs for
  full output from the same session.

**Regression still caught (AC 2):** built a private mutant
(`scripts/.check_mutant_0208.sh`, untracked, removed after) with `-o
pipefail` stripped from `runpipe()`'s definition only. Added a temporary
always-failing test (`internal/testdb/zzz_0208_temp_fail_test.go`, removed
after). Ran the mutant: `go test` printed `--- FAIL:
TestTemp0208ProofFailure` / `FAIL github.com/…/internal/testdb`, and the
script still printed **`VERIFICATION PASSED`, exit 0** — proving the flag is
load-bearing (mirrors #0140's original evasion proof). Ran the *real*
(unmutated) `scripts/check.sh` against the same failing test: printed the
identical `FAIL` output, then `FAILED (1): bash -o pipefail -c go test
./internal/testdb/... …` and **`VERIFICATION FAILED`, exit 1** — the funnel
catches what the mutation defeated.

**Evasion forms (AC 3):**
- *Bare `bash -c` outside `runpipe()`*: private mutant
  (`scripts/.check_bypass_0208.sh`) replacing the `go)` mode's `go build`
  call site with a raw `bash -c "..." || FAILED=1`. Guard fired: `PIPEFAIL
  REGRESSION (#0208): scripts/check.sh has a shell "-c" invocation outside
  runpipe()`, naming the exact offending line, exit 2.
- *Split-flag `bash \`-newline-`-c`* (the literal #0140 evasion form):
  private mutant (`scripts/.check_splitflag_0208.sh`) replacing the same
  call site with `bash \` / `-c "false" || FAILED=1` across two lines. Guard
  fired via the runpipe-call-count check: `expected at least 9 runpipe()
  call sites … found 8`, exit 2. (Not caught by the same-line shell-`-c`
  scan, since the two tokens land on different lines — but caught by the
  independent call-count check, so the evasion is still closed.)
- All mutant files removed immediately after each test;
  `git status --porcelain -- scripts/` confirmed clean between runs.

**Guard cannot flag itself (AC 4):** the marker-based block deletion means
reformatting comments or code *inside* either `BEGIN`/`END` block cannot
change what survives to be scanned. Directly exercised by this issue's own
process: the guard's comments were revised several times while iterating on
this fix (including the marker-substring self-match bug found and fixed
above), and every revision was re-run without the guard ever flagging its
own source — see the normal-operation runs above, all clean.

**`testdb.sh` mixed-case token (AC 5–6):**
- `scripts/testdb.sh create 0208RevX` → returned DSN names
  `opencircuit_test_0208revx` (lower-cased); `psql "$DSN" -tAc 'select
  current_database()'` connected successfully and returned
  `opencircuit_test_0208revx` — the returned name and the actual database
  agree.
- Before/after census: `select datname … like 'opencircuit_test_0208%'`
  showed the one row before `drop`, zero rows after
  `scripts/testdb.sh drop 0208RevX` (`dropped opencircuit_test_0208revx`).
- Mutation proof (sensitivity): reproduced the *old* bug against a private,
  prefix-scoped mutant of the **pre-fix** `testdb.sh` (`git show
  HEAD:scripts/testdb.sh`, copied into `scripts/.testdb_mutant_0208.sh` so
  `dirname "${BASH_SOURCE[0]}"` still resolves the repo root correctly —
  copying to `/tmp` first produced a wrong `REPO` and a different failure,
  corrected mid-run) — `create 0208MixedX` returned a DSN naming
  `…0208MixedX` while Postgres actually created `…0208mixedx`; connecting
  with the returned DSN failed with `FATAL: database
  "opencircuit_test_0208mt_0208MixedX" does not exist` — the exact SQLSTATE
  3D000 shape #0140's review hit. Confirms the fix addresses a real defect,
  not a hypothetical one. Scratch database and mutant file removed
  afterward.

**Byte-identity / cleanup:** every mutation ran against private, untracked
copies in `scripts/` (never `/tmp`, per the `dirname` gotcha above, and
never the tracked file, per CLAUDE.md §8a); `git status --porcelain` showed
only the two legitimate fix files (`scripts/check.sh`, `scripts/testdb.sh`)
dirty throughout. Every scratch database created during this work
(`opencircuit_test_0208{a,all,b,c,d,exit,mut,real,bypass}`, and the
mixed-case ones above) was dropped; `scripts/testdb.sh list` at the end
shows only `opencircuit_test_template`. `pgrep -fl 'go test|\.test '`
confirmed no leftover processes at multiple points during the work.

- `shellcheck scripts/check.sh` / `scripts/testdb.sh` — the only findings
  (`cd "$REPO"` without `|| exit`, an unquoted `$pkgs` expansion, `ls` vs.
  `find`, a `sed` usable as a bash substitution) all predate this change;
  confirmed with `git diff -- scripts/check.sh scripts/testdb.sh | grep` that
  none of the flagged lines appear in this diff.

## Notes

Reported by `#0140`'s phase-3 review under `CLAUDE.md` §9.

Criterion 2 is the one to be careful about: the point of this issue is to make
the property harder to lose, so a refactor that quietly stops catching the
original regression would be a net loss. Mutate and verify rather than assuming
the funnel preserves it.

`#0140`'s `## Review notes` carries the full evasion table with which forms fire
and which are genuinely broken — `bash -c -o pipefail` and `bash -eo pipefail -c`
both exit 1 on their own, so the guard is correct **not** to flag them.

Note `#0150` is also active in `scripts/testdb.sh`; sequence against it.
