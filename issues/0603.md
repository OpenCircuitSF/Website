## Description

Brennan, 2026-10-18: the Mastodon post
(`https://sfba.social/@opencircuitsf/117465295537754940`) shows a "Short
Links" card with no picture. The Bluesky post went out the same evening.

Root cause, measured in production:
- The post links to `https://go.opencircuitsf.com/uXLcM0`. ShortLinks serves
  redirects only at `GET /u/{key}`; see `ShortLinks/cmd/shortlinks/main.go`
  and `ShortLinks/internal/qr.ShortURL`, which returns base + `/u/` +
  `url.PathEscape(key)`. Any other path falls through to the ShortLinks SPA
  (HTTP 200, `<title>Short Links</title>`), and Mastodon builds its card from
  that page.
- `https://go.opencircuitsf.com/u/uXLcM0` correctly 302s to
  `/workshops/programming-leds-2?utm_…`.
- This repo builds the URL as `base+"/"+link.Key` in three places:
  - `internal/handlers/admin_outreach_links.go:210`
  - `internal/handlers/admin_outreach.go:1017`
  - `internal/handlers/admin_outreach_flyers.go:687`
- Production rows:
  - all 15 `outreach_links` rows and all 5 `outreach_flyer_links` rows store
    the broken form;
  - both `outreach_posts` 1 (Bluesky) and 4 (Mastodon) are `posted` with
    the broken link.
- The flyer **QR codes are fine**. They come from ShortLinks'
  `/api/links/{key}/qr.svg`, which encodes the `/u/` URL. Only the
  stored/displayed text URL is wrong, plus any printed text under the QR if
  the flyer shows it.

## Resolution

- `shortlinks.ShortURL(base, key)` (`internal/shortlinks/shorturl.go`)
  matches ShortLinks' `qr.ShortURL`: trailing `/` trimmed, `/u/` +
  `url.PathEscape(key)`. Used at all three `InsertPostLink` /
  `InsertFlyerLink` call sites.
- Guard `TestShortLinkInsertsUseShortURLHelper` (AST): every non-test
  insert call's short-URL argument is `shortlinks.ShortURL(...)` or a stored
  `*x.ShortURL` re-record; floor of 3 helper sites.
- Migration `000043` repairs `short_url` in `outreach_links`,
  `outreach_flyer_links` and `outreach_posts`, and the expanded URL inside
  draft/scheduled/failed/manual bodies; posted and queued bodies are left as
  sent. Down reverses only `short_url`.
- devmocks now serves redirects at `base/u/{key}` like ShortLinks;
  `sampleLinkURL` uses the `/u/` shape.

## Review notes

- 2026-10-18 Opus review: approved after a review fix (`37c96824`).
  - Migration matching tightened: the "already repaired" test is now the
    anchored `^https?://[^/]+/u/` (up and down), not `LIKE '%/u/%'`.
  - Body rewrite changed from `replace()` to a regex-quoted whole-URL match
    followed by `(?![A-Za-z0-9_/-])`. `replace()` would rewrite
    `host/abc` inside `host/abcd`. Without `/` in the lookahead, a down+up
    turned key `u`'s body `host/u/u` into `host/u/u/u` (measured).
  - devmocks served redirects at `base/KEY`, which is the bug's own shape,
    so dev links broke after the fix. Now `base/u/{key}`, with a test that
    the helper-built URL 302s and the old form 404s.
  - Evidence: a scratch DB at 42 seeded production-shaped rows (posted
    Bluesky and Mastodon, scheduled, failed, manual, a `{link}` draft, flyer
    links, keys `uXLcM0`, `uFly2`, `u`, `abc`/`abcd`). Ran up, down, up:
    every link row ended at `https://go.opencircuitsf.com/u/KEY`, posted
    bodies untouched, `{link}` body untouched, `abc.` rewritten, `abcd` in
    the same body left alone, schema_migrations `43|f`. Scratch DB dropped.
  - Guard mutation: reverting the flyer site and the Prepare site to
    `base+"/"+link.Key` (copy-aside, restored, sha256 matched) failed the
    guard both times, naming `admin_outreach.go:1017`.
  - Not changed: a post that is `queued` at deploy (only if the publisher
    died mid-send) keeps its old body by design, so it would go out with
    the dead link; with Mastodon idempotency, a prior-attempt lookup now
    searches the `/u/` URL. Negligible with the service stopped for deploy.
