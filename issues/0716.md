## Description

Measured against production on 2026-11-18 (v0.16.2): `GET /assets/index-qqDBCJdv.js` with `Accept-Encoding: gzip, br` returns the full **991,501 bytes** with no `Content-Encoding`. Gzipped locally the same file is **322,998 bytes** — a third the size. Every first visit, on a phone included, downloads three times what it needs to. Nothing in `deploy/apache/` enables `mod_deflate` or `mod_brotli`, and the Go service does not compress either.

PRD §7.6's budget is ≤ 60 KB gzipped JS for the initial route; compression alone does not meet it (`#0717` is the rest), but it is the cheapest third of the gap.

## Acceptance criteria

- [ ] Text responses (`text/html`, `text/css`, `application/javascript`, `application/json`, `image/svg+xml`, `application/xml`) are compressed when the client accepts it — brotli where available, gzip otherwise — at one layer (Apache or Go, the plan decides and says why), not both.
- [ ] Already-compressed types (PNG, JPEG, WebP, fonts in WOFF2) are not re-compressed.
- [ ] `Vary: Accept-Encoding` is set on compressed responses.
- [ ] Hashed `/assets/*` files carry `Cache-Control: public, max-age=31536000, immutable`; the HTML shell carries `no-cache`, so a new release is picked up on the next load (this is what `#0715` relies on).
- [ ] `deploy/apache/` matches what is installed on production after the change (`#0681` is the drift precedent), and `/.well-known/atproto-did` still verifies by hash after any Apache change (AGENTS.md §7).
- [ ] Verification is measured on production after deploy: the `Content-Encoding` and transferred bytes for the bundle, the CSS, and `/`, before and after.

## Plan

**Decision: compress in Go, gzip only, no Apache change.**

- **Go, not Apache.** Nothing stops Go doing it, so per the orchestrator's guidance it ships through `scripts/deploy.sh` with tests and nobody edits `/etc/httpd` on the live box. Both vhost files (`deploy/apache/installed-001-www.opencircuitsf.com-le-ssl.conf` and `deploy/apache/opencircuitsf.com.conf`) are plain `ProxyPass` with no `mod_deflate` filter. `mod_proxy_http` passes a backend's `Content-Encoding` and body through unchanged. If someone enables `mod_deflate` later, it skips a response that already carries `Content-Encoding`, so the two layers would not double-compress. **`deploy/apache/` is not edited**, so the drift criterion is met trivially. The atproto hash check stays in the after-deploy list anyway.
- **Gzip only, brotli deferred. This departs from criterion 1 ("brotli where available").** The stdlib has `compress/gzip` and no brotli. Brotli would add `github.com/andybalholm/brotli`, which is pure Go and not small, for roughly 15–20% more savings on the JS than gzip -9. `#0717` (code splitting) is where the larger cut comes from. The gzip path below is built so a precompressed `.br` variant could be added beside it later without restructuring. The reviewer should treat the brotli half of criterion 1 as amended by this plan, and the orchestrator should tell the user.
- **Two parts, one layer (Go):**
  1. A general compression middleware around the whole mux. It compresses dynamic text: the SEO-injected HTML shell, JSON, XML, sitemap, feed and SVG.
  2. Precompressed hashed assets in `SPAHandler`. Every `assets/*` file is gzipped once at construction time, at `gzip.BestCompression`. The bytes are served straight from memory with `Content-Encoding: gzip`, so the 1 MB bundle is never compressed per request. The middleware sees `Content-Encoding` already set and passes those responses through.

### Approach: `internal/middleware/compress.go`

- `AcceptsGzip(r)` parses `r.Header.Values("Accept-Encoding")` as comma-separated tokens. It returns true when a token's coding is `gzip` (case-insensitive) or `*`, and its `q` parameter is absent or not `0` / `0.0` / `0.00` / `0.000`. `gzip;q=0` is false.
- `compressibleTypes` is the set of media types the middleware compresses, compared after `mime.ParseMediaType` strips parameters: `text/html`, `text/css`, `text/plain`, `text/xml`, `text/javascript`, `application/javascript`, `application/json`, `application/xml`, `application/atom+xml`, `application/rss+xml`, `application/manifest+json`, `image/svg+xml`. Anything else passes through, and that is deliberate for each of these: `text/event-stream` (SSE on `/api/events`, plus the MCP SDK's streams on `/mcp`), `text/csv` (the subscriber export flushes as it goes), and every image or font type.
- `Compress` wraps `w` in `*gzipWriter{ResponseWriter: w, req: r}`. It decides once, in `WriteHeader(code)`. A `Write` with no prior `WriteHeader` calls `WriteHeader(200)` first. Compress only when all of these hold:
  - `AcceptsGzip(req)`;
  - `req.Method != HEAD`;
  - `code >= 200` and the code is not 204, 206 or 304;
  - the header has no `Content-Encoding` and no `Content-Range`;
  - the `Content-Type` media type is in `compressibleTypes`. An empty `Content-Type` means don't compress. Go only sniffs the type after `WriteHeader`, so it cannot be judged here.
- Whenever the media type is in `compressibleTypes`, append `Vary: Accept-Encoding`, whether or not this response is compressed. That keeps a shared cache from serving a gzip body to a client that didn't ask for one. Don't add it twice: check `w.Header().Values("Vary")` for an existing `Accept-Encoding` token.
- When compressing: set `Content-Encoding: gzip` and delete `Content-Length`. `seo.Site.Middleware` sets the uncompressed length, and leaving it would truncate the body. If an `ETag` is strong (no `W/` prefix), rewrite it to `W/` + the original value. Then call the underlying `WriteHeader(code)` and create the `gzip.Writer` from a package-level `sync.Pool` at `gzip.DefaultCompression`.
- `Write(b)` writes to the gzip writer when compressing, otherwise to the underlying writer.
- **`Flush()` is mandatory.** `internal/handlers/events.go` type-asserts `w.(http.Flusher)` and answers 500 without one. When compressing: `gz.Flush()`, then flush the underlying writer if it is an `http.Flusher`. Otherwise flush the underlying writer only. If `Flush` comes before any `WriteHeader`, call `WriteHeader(200)` first, matching net/http.
- `Unwrap() http.ResponseWriter` returns the underlying writer, so `http.ResponseController` and the MCP SDK still reach it. Copy `internal/middleware/apiauthfail.go`'s `authStatusWriter` shape.
- After `next.ServeHTTP` returns, `Compress` closes the gzip writer if one was created, and returns it to the pool after `Reset(io.Discard)`.
- The doc comment states two things: why `text/event-stream` is excluded, and why the `Content-Encoding`-already-set passthrough exists (precompressed assets).

### Approach: `internal/handlers/static.go`

- Add constants: `cacheImmutable = "public, max-age=31536000, immutable"` and `cacheShell = "no-cache"`.
- Add `gz map[string][]byte` to `SPAHandler`. `NewSPAHandler` fills it with `fs.WalkDir(dist, "assets", …)`, ignoring `fs.ErrNotExist` (the committed placeholder `dist/` has no `assets/`). For each regular file whose `path.Ext` is `.js`, `.css`, `.svg`, `.json`, `.map`, `.txt`, `.xml` or `.html`: read it, gzip it at `gzip.BestCompression` into a `bytes.Buffer`, and store it under its fs name (e.g. `assets/index-X.js`) only if the gzipped copy is smaller. A read or compress error skips that file (log it via `log.Printf`) and never fails construction.
- `ServeHTTP`, inside the `name != "" && h.fileExists(name)` branch, before `h.fileSrv.ServeHTTP`:
  - if `strings.HasPrefix(name, "assets/")`, set `Cache-Control: cacheImmutable`;
  - then, if `gzBody, ok := h.gz[name]; ok && middleware.AcceptsGzip(r) && r.Header.Get("Range") == ""`:
    - set `Content-Type` from `mime.TypeByExtension(path.Ext(name))`;
    - set `Content-Encoding: gzip`, add `Vary: Accept-Encoding`, set `Content-Length: len(gzBody)`;
    - `WriteHeader(200)`, and write `gzBody` unless the method is HEAD;
    - return.
  - Otherwise fall through to `fileSrv`, which keeps Range and HEAD handling for identity requests. For a file in `h.gz`, also add `Vary: Accept-Encoding` on the identity path, so both variants carry it.
  - Root files (favicons, PNGs, webp, fonts, `site.webmanifest`) get no new Cache-Control. They are not content-hashed, so `immutable` would be wrong for them, and changing them is out of scope.
- `serveIndex`: set `Cache-Control: cacheShell` before `WriteHeader`. `seo.Site.Middleware`'s `copyHeader` copies every header except `Content-Length` from the recorder, so the header survives the meta-injection rewrite. The rendered body still reaches `Compress` as `text/html`, and `Compress` handles it.
- Update the `SPAHandler` doc comment's Behavior list to cover the cache headers and precompression.

### Tests

What I checked myself, without relying on the implementation notes:

- **Scoped run.** `uptime` was 5.83. `ISSUE=0716 scripts/check.sh go ./internal/middleware/... ./internal/handlers/... ./cmd/opencircuit/... ./internal/seo/... ./internal/db/...` passed: all five `ok`, no skips, gofmt clean. I re-ran it after my test edits and it passed again.
- **Streaming, over a real socket.** I wrote throwaway `httptest.NewServer` tests and deleted them afterwards.
  - An SSE handler behind `Compress`: the `: connected` frame reached the client while the handler was still blocked. There was no `Content-Encoding` and no `Vary`.
  - A compressed JSON handler that flushes and then blocks: the client decoded the first line before the handler returned, and the response's `Content-Length` was stripped (-1).
  - `/mcp` (go-sdk v1.8.0) sets `text/event-stream` before `WriteHeader` on its SSE paths, so those pass through uncompressed. It flushes through `http.ResponseController`, which calls the wrapper's `Flush`. Its JSON replies are compressed, which is harmless.
  - `events.go`'s `w.(http.Flusher)` assertion is satisfied by the wrapper.
- **SEO HTML.** `seo.Site.Middleware` sets the uncompressed `Content-Length`, and `Compress` deletes it before the gzip body goes out, which the `TestCompressGzipsTextTypes` mutation proves. The injected HTML has no ETag. The only ETag/304 path in `internal/seo` is the PNG cards, and `image/png` is never compressed. The wiring test proves `/` comes back gzipped with `no-cache` through the real `mountAndServe` chain.
- **Edge cases.**
  - HEAD, 204, 206 with `Content-Range`, and 304 are never compressed.
  - A response that already has `Content-Encoding` passes through untouched, so there is no double compression. The precompressed assets rely on this.
  - `Vary` is added once.
  - `gzip;q=0`, `gzip; q=0.000`, `*;q=0` and `identity` are all refused.
  - `http.Error` 500 responses are gzipped and decode correctly.
  - A strong ETag is weakened to `W/`.
- **Cache headers.** `immutable` is set only when the fs name starts with `assets/` and the file exists. `web/public/` has no `assets/` directory, so only Vite's hashed output lands there. `/og-default.png`, favicons and `site.webmanifest` get no Cache-Control from the SPA handler. `robots.txt` and `sitemap.xml` are their own handlers, which this change does not touch.
- **Startup cost.** I ran `precompressAssets` on the local built `dist/` (545 KB JS and 88 KB CSS): it took 18 ms and kept 188 KB. Production's 991 KB bundle should cost well under a second on the t4g.small and keep about 350 KB in memory. It is built once, from the single `NewSPAHandler` call in `mountAndServe`.
- **Mutation testing.** I made 16 mutations to copies and restored the sources, confirming by sha256. 14 were killed at first and 2 survived:
  - Deleting `g.gz.Flush()` from `Flush`. The flush test only decompressed the final body, so it could not see buffering.
  - Writing the precompressed body on HEAD.

  I strengthened `TestCompressFlushWhileCompressing` so that the bytes on the wire at flush time must already decode to the first write. I also added `TestSPAPrecompressedAssetHead`. With those changes all 16 mutations are killed.

Not blocking, for a possible follow-up:

- Precompressed assets lose their `Content-Length` in production, because they pass through `seo.Site.Middleware`, whose `copyHeader` drops it. The 320 KB bundle goes out chunked. It still decodes correctly; the only cost is that the client cannot show download progress.
- A HEAD request for a dynamic compressible response returns identity headers, while GET returns gzip. The precompressed assets are consistent between the two. RFC 9110 permits the difference.
