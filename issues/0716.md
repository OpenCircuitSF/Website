# 0716 — The site's JavaScript, CSS and HTML are served uncompressed

| | |
|---|---|

## Description

Measured against production on 2026-11-18 (v0.16.2): `GET /assets/index-qqDBCJdv.js` with `Accept-Encoding: gzip, br` returns the full **991,501 bytes** with no `Content-Encoding`. Gzipped locally the same file is **322,998 bytes** — a third the size. Every first visit, on a phone included, downloads three times what it needs to. Nothing in `deploy/apache/` enables `mod_deflate` or `mod_brotli`, and the Go service does not compress either.

PRD §7.6's budget is ≤ 60 KB gzipped JS for the initial route; compression alone does not meet it (`#0717` is the rest), but it is the cheapest third of the gap.

## Acceptance criteria

- [ ] Text responses (`text/html`, `text/css`, `application/javascript`, `application/json`, `image/svg+xml`, `application/xml`) are compressed when the client accepts it — brotli where available, gzip otherwise — at one layer (Apache or Go, the plan decides and says why), not both.
- [ ] Already-compressed types (PNG, JPEG, WebP, fonts in WOFF2) are not re-compressed.
- [ ] `Vary: Accept-Encoding` is set on compressed responses.
- [ ] Hashed `/assets/*` files carry `Cache-Control: public, max-age=31536000, immutable`; the HTML shell carries `no-cache`, so a new release is picked up on the next load (this is what `#0715` relies on).
- [ ] `deploy/apache/` matches what is installed on production after the change (`#0681` is the drift precedent), and `/.well-known/atproto-did` still verifies by hash after any Apache change (AGENTS.md §7).
- [ ] Verification is measured on production after deploy: the `Content-Encoding` and transferred bytes for the bundle, the CSS, and `/`, before and after.
