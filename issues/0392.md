## Description

**Five times this phase**, a guard's own documentation tripped a sibling guard.
`#0384`'s reviewer nearly made it six while writing its review notes — by citing
a fabricated `Test…` name that the sibling test-name guard would have flagged had
the issue not just moved to `resolved`. It caught and rephrased it.

The pattern is structural, not carelessness. A guard that forbids a textual shape
must be **described** using that shape — the doc comment explaining why
`<file>.go:<int>` citations are forbidden wants to show one; the test proving a
`go test -v` transcript is exempt wants to contain one.

Recorded instances this phase include `#0347`'s doc comment tripping its own
directional axis, `#0356`'s guard flagging text written to explain it, `#0374`'s
records quoting real wrapped comment text, `#0384` tripping
`TestNoCommentCitesUnresolvedPathOrSection` with an illustrative path, and
`#0366`'s prose constrained by the guard it documents.

**The cost is real but bounded**: each instance cost a rephrase, and in one case
a red HEAD for ~18 minutes (`#0381`). None was a defect in the guard.

## What already works, and is worth generalising

`#0384`'s fix is the strongest precedent: it moved a concrete `go vet` example
out of a **comment** and into a **test body as an asserted string literal**. That
is strictly better than rephrasing —

- decorative comment text became an **executed assertion**;
- a string literal is not a comment, so the comment-scoped guard is satisfied
  **for the right reason** rather than by evasion;
- the example is now pinned, so it cannot drift from the pattern it illustrates.

`#0347` reached a weaker version independently: rephrase rather than delete,
because deleting also goes green and leaves no trace.

## Decision (criterion 1) — record, not close

**Record a short convention note; do not build anything.** The honest
tension this criterion asks for: does one paragraph change what a future
author does, or is it one more paragraph in a long file the author who needs
it will not have read? Weighed against the corrected count above, three
things tip it toward recording:

1. **The pattern is not slowing down.** Three of the six confirmed issues
   happened after this issue was filed, on three different neighbouring
   issues, each independently rediscovering the same two remedies
   (rephrase, or describe in prose) without being told. The judgment being
   re-derived each time is cheap to look up and currently costs a small
   amount of reasoning every single occurrence.
2. **The failure mode when it goes unrecorded is not "a rephrase."** It is
   `#0381`: a citation drifted into `<file>.go:<int>` form inside a doc
   comment about a guard, a correctly *scoped* verification run could not
   see the repo-wide guard it tripped, and `HEAD` sat red for eighteen
   minutes before an unrelated review caught it. The cost this issue is
   weighing is not "one rephrase," it is "one rephrase, with an occasional
   red `HEAD` when nobody happens to run the wide guard before the next
   commit."
3. **The remedy is concrete, not a vague warning.** `#0384`'s
   string-literal-assertion technique is a specific, better-than-rephrasing
   move with a real worked example already in the tree, and `#0347`'s
   rephrase-don't-delete fallback is equally specific. A note that names
   both, with their sources, is a lookup rather than advice to "be careful."

Against recording: `#0330`, `#0347`, and `#0356` this phase all ended by
recording a limit rather than building a mechanism, and one more entry in
`CLAUDE.md` §8 is one more thing a future reader has to get through before
reaching the entry they actually need. That cost is real but is paid once
per reader, not once per trip — the trips are the more expensive side of
the ledger once there are nine of them.

**Where it is recorded.** `CLAUDE.md` §8, immediately after the `#0258`
"guard inside the file it guards" entry — the two are the same structural
lesson (a mechanism meant to defend a file becomes new surface the file's
own prose can hit) one level apart, so a reader who has just internalised one
meets the other in the same breath.

**Criterion 5, and what it told me.** The note itself had to be written
without ever spelling out the banned citation shape, a fabricated test
identifier, or a `go vet`-diagnostic-looking string — describing each by what
it is (a `<file>.go:<int>`-shaped token, a positional citation, a named test
that does not exist) rather than by writing an instance of it. That was not a
struggle: prose that talks *about* a shape, rather than reproducing it, is
what the whole convention already asks other authors to do, so writing this
note under that same discipline is the note proving itself rather than
merely stating a rule. `CLAUDE.md` itself sits outside every citation
guard's scan roots (`internal/handlers`'s family scans Go comments; the
`internal/db` family scans `issues/*.md`; both read `CLAUDE.md` only as a
*target* for resolving citations, never as a *subject*), so nothing here
would have caught a violation mechanically — the discipline was self-imposed,
consistent with what the note recommends. **This issue's own `in-progress`
edits below were the one place a violation was mechanically checkable**, and
none was found on re-run (see `## Verification`).
