## Description

After the 2026-10-17 deploy, the Outreach page in production says:

> Outreach needs the ShortLinks connection (SHORTLINKS_BASE_URL and
> SHORTLINKS_API_TOKEN), which is not configured on this server.

Brennan, 2026-10-17: "There should be UI under the Settings section which
stores these values in the db."

Today the ShortLinks client (`#0543`) and the Bluesky and Mastodon posters
(`#0545`) are built once at startup from environment variables
(`internal/config`: `SHORTLINKS_BASE_URL`, `SHORTLINKS_API_TOKEN`,
`BLUESKY_HANDLE`, `BLUESKY_APP_PASSWORD`, `BLUESKY_PDS_URL`,
`MASTODON_BASE_URL`, `MASTODON_TOKEN`). Changing them means editing
`/etc/opencircuit/config.env` on the box and restarting. All seven move into
admin Settings.

## Acceptance criteria

- [ ] **Settings UI.** The admin Settings section gets an "Outreach
      connections" area with three groups: ShortLinks (base URL, API token),
      Bluesky (handle, app password, PDS URL with the `https://bsky.social`
      default), Mastodon (instance URL, access token). It follows the
      existing Settings view's patterns.
- [ ] **Stored in the database**, in a new migration (production is at
      `000036`; the next file is `000037`). Use the existing `settings`
      table if it fits, or a dedicated table if the plan shows a reason.
- [ ] **Secrets are write-only.** The API token, app password and access
      token are never returned by any API response, never logged, and never
      written to the audit log. The UI shows only whether each is set (for
      example "set, ends in …x7Q2" is acceptable only if the plan justifies
      it; "set" / "not set" is the default), with a way to replace or clear
      it. The audit log records which field changed, never the value.
- [ ] **Takes effect without a restart.** Saving new values rebuilds or
      reconfigures the ShortLinks client and the posters, so the Outreach
      page works immediately. The Outreach "not configured" notice points to
      the Settings area instead of naming environment variables.
- [ ] **Environment variables still work as a fallback.** If a field has no
      database value, the environment variable is used, so a dev setup with
      `.env` keeps working. The precedence is stated in `docs/` and in the
      Settings UI.
- [ ] **Test connection.** Each group has a button that checks the
      credentials against the service with a harmless read (ShortLinks: an
      authenticated list or whoami call; Bluesky: create a session; Mastodon:
      `verify_credentials`) and reports success or the error, without
      posting anything. Tests use fakes, never live services.
- [ ] **Validation.** URLs must be `https`, except `http://localhost` and
      `http://127.0.0.1` for local development. Reuse the project's existing
      URL validators.
- [ ] **Storage of secrets at rest** is decided in the plan: plaintext in the
      database (protected like the rest of the DB and its backups) versus
      encrypted with a key from the environment. State the choice and why.
- [ ] Go handler and store tests, plus SPA tests (jsdom) for the Settings
      area and the write-only behaviour. Verified with
      `ISSUE=0564 scripts/check.sh` plus `./internal/handlers/...` and
      `./internal/db/...`. Zero skips.
- [ ] `docs/configuration.md` and `.env.example` updated
      (`internal/config`'s `.env.example` guard must stay green).

## Plan

Planned 2026-10-17 (Opus, phase 1). Every decision below is made here; the
implementer transcribes. Where a step says "check", it is a one-line
confirmation, not a design question.

### Decisions

**D1 — Storage: a dedicated table, `outreach_connection_values`, in
`migrations/000037`. Not the `settings` table.** The `settings` table fits the
key/value shape, but the code around it does not:

- `GET /admin/settings` (`internal/handlers/settings.go` `List`) returns every
  row **with its value**, and the SPA reads that list. A secret stored there
  is published to the browser unless every current and future reader filters
  it, and a deny-list on a generic table is the kind of filter that fails open.
- `PATCH /admin/settings` writes `settings.updated` audit rows with
  `old_value`/`new_value`. A secret written through it lands in `audit_log`.
- `UpdateSetting` only updates seeded rows, so "no database value, use the
  env var" would need a sentinel such as an empty string. Here, "no row" means
  "fall back", and clearing a value is a `DELETE`.

The table has one row per field that has a saved value:

```sql
CREATE TABLE outreach_connection_values (
    key        TEXT PRIMARY KEY,
    value      TEXT NOT NULL,
    updated_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    CONSTRAINT outreach_connection_values_key_check CHECK (key IN (
        'shortlinks_base_url', 'shortlinks_api_token',
        'bluesky_handle', 'bluesky_app_password', 'bluesky_pds_url',
        'mastodon_base_url', 'mastodon_token')),
    CONSTRAINT outreach_connection_values_value_check CHECK (
        value <> '' AND char_length(value) <= 2048)
);
```

Down: `DROP TABLE IF EXISTS outreach_connection_values;`. The up file gets a
short header comment explaining D1 and D2. If it names a constraint, use the
exact identifiers above: `internal/handlers`' `#0459` guard checks that a
cited identifier appears in the migration it names. Production is at
`000036`, so `000037` is editable until it is deployed.

**D2 — Secrets at rest: plaintext, protected like the rest of the
database.** The only realistic encryption key is an env var in
`/etc/opencircuit/config.env`. That is the same file that holds
`DATABASE_URL`, on the same box as the database. Anyone who can read the
database through the app's own credentials can also read the key, so
encryption only protects against one case: a leaked backup without the
server. That backup already holds the whole subscriber list, which this
project calls its most valuable and least reconstructible asset (PRD §10.6),
plus sessions and credentials. All three secrets can be revoked and scoped
at the service: ShortLinks API tokens, Bluesky app passwords, and Mastodon
scoped tokens. The env-var fallback being replaced was already plaintext at
rest in `config.env`. Encryption would add key management, a rotation story,
and a failure mode where a lost key makes the values unreadable. In return
it would protect secrets that are worth less than the data sitting next to
them. Revisit if backups ever leave operator-controlled hosts (for example,
the deferred S3 option). Write this paragraph, shortened, into
`docs/configuration.md` and the migration header.

The protections that do matter are enforced in code and covered by tests:
a secret is never returned by any API response, never logged, and never
written to `audit_log`.

**D3 — Secret display: "set" / "not set" plus where the value comes from.**
No "ends in …x7Q2" suffix: it leaks part of the secret and adds nothing that
the source label does not already give. The UI shows, for example, "Set —
saved in Settings", "Set — from environment variable `MASTODON_TOKEN`", or
"Not set".

**D4 — Precedence is per field: database, then environment, then built-in
default.**
- If a field has a row, the row's value is used (source `database`).
- Otherwise its env var is used when non-blank after trimming (source
  `environment`). For `bluesky_pds_url`, `config.Load` already substitutes
  `https://bsky.social` when the env var is blank, so an env value equal to
  `bluesky.DefaultPDSURL` is reported as source `default`.
- Otherwise the field is `unset`.
- Clearing a saved value deletes the row, so the field falls back to its env
  var.
- There is no "disable despite env" switch. To turn off an env-configured
  channel, remove the variable from `config.env`. Document this.

**D5 — Runtime reconfiguration: one `outreachconn.Manager` holds an
immutable client snapshot in an `atomic.Pointer`.** Readers never lock.
`Reload` and `Apply` are serialised by a mutex. On reload, each service's
client is rebuilt **only when its effective config changed**. This keeps the
cached Bluesky session: `createSession` is capped at 30 per 5 minutes, so it
must not be thrown away on an unrelated save.

Consumers stop holding `*Client` values from boot:
- The outreach handler reads ShortLinks through a live adapter.
- The publisher and tracker read Bluesky and Mastodon through a small
  `ClientSource` interface.
- A change listener resets the outreach handler's cached short-URL host and
  its stats cache when the ShortLinks client changes.

**D6 — A bad configuration no longer fails boot.** Today a malformed env URL
makes `servePostgres` return an error. With database-backed values,
refusing to boot would lock the admin out of the screen that fixes the
problem. New behaviour:
- A group whose effective config fails its client constructor is left
  unconfigured.
- One warning is logged naming the group and field key, never a value.
- The Settings UI shows a fixed error string for that group.
- Boot still fails if the database read in the first `Reload` fails.

**D7 — API.** All routes are admin-only, registered through `adminRoutes()`.

| Route | Purpose |
|---|---|
| `GET /admin/outreach-connections` | Current state |
| `PATCH /admin/outreach-connections` | Set and/or clear fields; returns the new state |
| `POST /admin/outreach-connections/shortlinks/test` | ShortLinks: `GET /api/me` (already `(*shortlinks.Client).Me`; ShortLinks mounts it behind `requireAPI`, `cmd/shortlinks/main.go:463`) |
| `POST /admin/outreach-connections/bluesky/test` | Bluesky: `com.atproto.server.createSession` on a **fresh** client |
| `POST /admin/outreach-connections/mastodon/test` | Mastodon: `GET /api/v1/accounts/verify_credentials` |

The three test routes are literal paths with no `{service}` wildcard, so
`resolveAdminRoutePath` in `cmd/opencircuit/admin_wiring_test.go` needs no
new case.

Test connection always checks the **saved, effective** configuration. Secrets
never travel back in a request just to be tested, so the UI flow is: save,
then test. Each test builds a fresh client from the effective config instead
of using the live one. For Bluesky this is required: the live client's
cached session would skip `createSession` and prove nothing about the
password. Test calls are not audited, since they change no state.

GET and PATCH response body:

```json
{
  "groups": [
    {
      "name": "shortlinks", "configured": true, "error": "",
      "fields": [
        {"key": "shortlinks_base_url", "env_var": "SHORTLINKS_BASE_URL", "secret": false,
         "source": "database", "value": "https://go.opencircuitsf.com"},
        {"key": "shortlinks_api_token", "env_var": "SHORTLINKS_API_TOKEN", "secret": true,
         "source": "environment", "set": true}
      ]
    },
    {"name": "bluesky", "...": "..."},
    {"name": "mastodon", "...": "..."}
  ]
}
```

- Groups are always listed in the order `shortlinks`, `bluesky`, `mastodon`.
- Fields within a group are listed in the order of the field table under F2.
- `source` is one of `database`, `environment`, `default`, `unset`.
- Non-secret fields carry `value`, the effective value (`""` when unset).
- Secret fields carry `set` and **never** a `value` key. The handler builds
  them from a separate struct type with no value field.

PATCH request body: `{"values": {"<key>": "<string>", ...}}`, decoded into
`map[string]*string`.

| Entry | Meaning |
|---|---|
| Key absent | Unchanged |
| Non-blank string (after trimming) | Set |
| `""` or whitespace only | Clear: delete the row and fall back |
| `null` | 400 `values.<key> must be a string` |
| Unknown key | 400 `unknown key: <key>` |
| Empty map, or missing `values` | 400 `values is required` |

- All entries are validated before anything is written. One invalid entry
  rejects the whole request with 400 and writes nothing.
- Error messages name the key and the rule, never the value.
- Success returns 200 with the GET body, rebuilt after the reload.

Test response is always 200: `{"ok": true, "detail": "Signed in as @handle"}`
or `{"ok": false, "error": "<fixed text>"}`. Upstream failure is data, not a
server error.

**D8 — Audit.**
- New action `audit.ActionOutreachConnectionsUpdated =
  "outreach_connections.updated"`.
- New target `audit.TargetOutreachConnections = "outreach_connections"`,
  with `TargetID` nil.
- `Metadata: map[string]any{"set": setKeys, "cleared": clearedKeys}`. Both
  are sorted `[]string` of field keys, `[]string{}` when empty, never values.
- Written only when at least one row actually changed. Setting a field to its
  current saved value is not a change, and neither is clearing a field with
  no row. A no-op PATCH returns 200 and writes no audit row.
- Write the metadata as an **inline map literal** inside the `audit.Entry{}`
  composite, so `internal/handlers`' audit-metadata guard
  (`audit_email_metadata_guard_test.go`) can classify it.

**D9 — Validation** (in `internal/outreachconn/validate.go`). Every value is
trimmed first.

- **URL fields** (`shortlinks_base_url`, `bluesky_pds_url`,
  `mastodon_base_url`) use `ValidServiceURL`. It rejects:
  - a value over 2048 characters or one that fails `url.Parse`
  - an empty host, userinfo, a query, or a fragment
  - any scheme except `https`, with one exception: `http` is allowed when
    `u.Hostname()` is exactly `localhost` or `127.0.0.1`

  This is the rule `mastodon.New` already enforces (`internal/mastodon/client.go`
  around line 95), narrowed to the two hosts the issue names. It is the closest
  existing validator. `validRemoteURL` in `internal/handlers/admin_outreach.go`
  allows `http` anywhere, so it does not fit. Leave the three client
  constructors unchanged: they stay permissive for env values, and stored
  values are checked strictly when written. Normalise by trimming any
  trailing `/` from the path.
- **`bluesky_handle`**: strip one leading `@`; then 1–253 characters, no
  whitespace or control characters. DIDs are allowed, since `createSession`
  accepts them.
- **Secrets**: 1–1024 characters, no whitespace or control characters
  (`unicode.IsSpace` / `unicode.IsControl` anywhere).
- `ValidationError{Key, Msg string}`, where `Error()` returns
  `Key + ": " + Msg`. Messages are fixed strings, for example `"must be an
  https URL (http is allowed only for localhost and 127.0.0.1)"`.

`store.go`. SQL lives here, in the package that owns the table.

```go
type Store struct{ pool *pgxpool.Pool }
func NewStore(pool *pgxpool.Pool) *Store
func (s *Store) All(ctx context.Context) (map[string]string, error)        // SELECT key, value FROM outreach_connection_values
func (s *Store) Apply(ctx context.Context, set map[string]string, clear []string, now time.Time) error
```

`Apply` runs in one transaction (`pool.Begin` … `Commit`, rolled back on
error):
- one upsert per set entry: `INSERT … VALUES ($1,$2,$3) ON CONFLICT (key)
  DO UPDATE SET value = EXCLUDED.value, updated_at = EXCLUDED.updated_at`
- then `DELETE FROM outreach_connection_values WHERE key = ANY($1)` when
  `clear` is non-empty

`manager.go`:

```go
type Source string
const (SourceDatabase Source = "database"; SourceEnvironment = "environment"; SourceDefault = "default"; SourceUnset = "unset")

type FieldState struct { Field; Source Source; Value string } // Value is ALWAYS "" for a secret field
type GroupState struct { Name string; Configured bool; Error string; Fields []FieldState }
type Snapshot struct { Groups []GroupState }
type Changed struct{ ShortLinks, Bluesky, Mastodon bool }
type Applied struct{ Set, Cleared []string }               // sorted keys that really changed
type TestResult struct { OK bool; Detail, Error string }

type store interface {
    All(ctx context.Context) (map[string]string, error)
    Apply(ctx context.Context, set map[string]string, clear []string, now time.Time) error
}

type Manager struct {
    store store
    env   map[string]string // field key -> raw env value
    log   *slog.Logger
    mu    sync.Mutex        // serialises Reload and Apply
    cur   atomic.Pointer[state]
    lmu   sync.Mutex
    listeners []func(Changed)
}

type state struct {
    sl *shortlinks.Client; bs *bluesky.Client; ma *mastodon.Client
    slKey, bsKey, maKey string   // effective config joined with "\x00"; compared to decide a rebuild
    errs   map[string]string     // group -> fixed error text
    values map[string]string     // effective values (secrets included; never exported)
    sources map[string]Source
    anyDB  bool
}

func NewManager(st store, env map[string]string, log *slog.Logger) *Manager // starts with an empty state: every client nil
func (m *Manager) Reload(ctx context.Context) error
func (m *Manager) Apply(ctx context.Context, values map[string]string, now time.Time) (Applied, error)
func (m *Manager) Snapshot() Snapshot
func (m *Manager) ShortLinks() *shortlinks.Client
func (m *Manager) Bluesky() *bluesky.Client
func (m *Manager) Mastodon() *mastodon.Client
func (m *Manager) HasDatabaseValues() bool
func (m *Manager) OnChange(fn func(Changed))
func (m *Manager) ShortLinker() *LiveShortLinks // returns &LiveShortLinks{m: m}
func (m *Manager) Test(ctx context.Context, group string) TestResult
```

`*Store` satisfies the unexported `store` interface. Tests use a map-backed
fake.

- **`Reload`** takes `m.mu` and calls `reloadLocked`:
  1. `All`; on error, return it.
  2. Compute effective values and sources per D4.
  3. For each group, build the key string from the group's effective values.
     If it equals the previous state's key, reuse that client and its error
     text. Otherwise call the constructor:
     `shortlinks.New(baseURL, token)`, `bluesky.New(pdsURL, handle, appPassword)`,
     or `mastodon.New(baseURL, token)`.
  4. If a constructor returns an error, set the client to nil and the group
     error to:
     - shortlinks: `"The ShortLinks base URL is not a valid URL."`
     - bluesky: `"The Bluesky PDS URL is not a valid URL."`
     - mastodon: `"The Mastodon instance URL must be an https URL."`

     Log `m.log.Warn("outreach: connection misconfigured", "group", g)`. Never
     log the constructor's error: it names the env var and is useless here.
  5. Store the new state, then call each listener with `Changed`. A flag is
     true when that group's key changed. Skip the calls when nothing changed.
  6. When a client is rebuilt, log `m.log.Info("outreach: connection reloaded",
     "group", g, "configured", client != nil)`. No values.
- **`Apply`** takes `m.mu`, then:
  1. Normalises every entry. A value that trims to `""` means clear; that is
     not an error. Any `*ValidationError` is returned before anything is
     written.
  2. Reads `All`.
  3. Computes `set`, entries whose value differs from the stored one, and
     `clear`, keys present in the database.
  4. If both are empty, returns `Applied{}` with no write and no reload.
  5. Otherwise calls `store.Apply`, then `reloadLocked`, and returns the
     sorted `Applied`.
- **`Snapshot`** builds groups and fields in `Fields` order from `cur`. For
  secret fields, `Value` is forced to `""`. `Configured` means the group's
  client is non-nil.
- **`Test`** (put it in `test.go`) reads `cur.values` and builds a fresh,
  throwaway client with the same constructor.
  - If the client is nil (incomplete config), return
    `TestResult{Error: "Not configured: " + what}`, where `what` is:
    - shortlinks: `"set the base URL and API token first."`
    - bluesky: `"set the handle and app password first."`
    - mastodon: `"set the instance URL and access token first."`
  - If the constructor errors, return the group's error text from step 4.
  - Otherwise wrap ctx in a 20s timeout and call:
    - `Me` → `Detail: "Connected to ShortLinks as " + me.Email`
    - `VerifyCredentials` (Bluesky) → `"Signed in to Bluesky as @" + handle`
    - `VerifyCredentials` (Mastodon) → `"Signed in to Mastodon as @" + acct`
  - On failure, map the error to a **fixed** string. Never use `err.Error()`
    or the upstream body. Log the error at Warn with `"group", g`; the
    clients already redact secrets from errors.

    | Service | Condition | `Error` text |
    |---|---|---|
    | ShortLinks | `ErrUnauthenticated` or `ErrForbidden` | `"ShortLinks rejected the API token."` |
    | ShortLinks | `ErrRateLimited` | `"ShortLinks is rate limiting requests; try again shortly."` |
    | ShortLinks | other `*shortlinks.APIError` | `fmt.Sprintf("ShortLinks answered HTTP %d.", ae.Status)` |
    | ShortLinks | anything else | `"Could not reach ShortLinks at the saved base URL."` |
    | Bluesky | `bluesky.ErrAuth` | `"Bluesky rejected the handle or app password."` |
    | Bluesky | `ErrRateLimited` | `"Bluesky is rate limiting sign-ins; try again in a few minutes."` |
    | Bluesky | other `*bluesky.APIError` | `"Bluesky answered HTTP %d."` |
    | Bluesky | anything else | `"Could not reach the Bluesky PDS."` |
    | Mastodon | `*mastodon.APIError` with Status 401 | `"Mastodon rejected the access token."` |
    | Mastodon | Status 403 | `"The token is valid but lacks the profile (or read:accounts) scope this check needs."` |
    | Mastodon | `ErrRateLimited` | `"Mastodon is rate limiting requests; try again shortly."` |
    | Mastodon | other `*APIError` | `"Mastodon answered HTTP %d."` |
    | Mastodon | anything else | `"Could not reach the Mastodon instance."` |

    Check `bluesky.APIError`'s field name for the status in `errors.go`
    before writing the Bluesky "answered HTTP" row.
  - An unknown group returns `TestResult{Error: "unknown connection"}`.

**F6 — New handler `internal/handlers/admin_outreach_connections.go`.**

```go
type outreachConnections interface {
    Snapshot() outreachconn.Snapshot
    Apply(ctx context.Context, values map[string]string, now time.Time) (outreachconn.Applied, error)
    Test(ctx context.Context, group string) outreachconn.TestResult
}
type AdminOutreachConnectionsHandler struct { conns outreachConnections; auditor *audit.Logger; now func() time.Time }
func NewAdminOutreachConnectionsHandler(conns outreachConnections, auditor *audit.Logger) *AdminOutreachConnectionsHandler
func (h *AdminOutreachConnectionsHandler) Get(w, r)            // 200 view(Snapshot())
func (h *AdminOutreachConnectionsHandler) Patch(w, r)          // D7 + D8
func (h *AdminOutreachConnectionsHandler) TestShortLinks(w, r) // writeJSON(200, testView(h.conns.Test(ctx, "shortlinks")))
func (h *AdminOutreachConnectionsHandler) TestBluesky(w, r)
func (h *AdminOutreachConnectionsHandler) TestMastodon(w, r)
```

View types:
- `connectionsView{Groups []connectionGroupView}`
- `connectionGroupView{Name string; Configured bool; Error string; Fields []any}`
- `plainFieldView{Key, EnvVar string; Secret bool; Source string; Value string}`,
  with `secret` always false
- `secretFieldView{Key, EnvVar string; Secret bool; Source string; Set bool}`,
  with `secret` always true

JSON tags are `key`, `env_var`, `secret`, `source`, `value`, `set`. The
mapper picks the struct type from `FieldState.Secret`, so a secret field
cannot carry a value key at all.

`Patch`:
1. Read the user from context; answer 401 if missing, as `settings.go` does.
2. Decode `struct{ Values map[string]*string \`json:"values"\` }`.
3. Return 400 for a nil or empty map, a nil entry, or an unknown key (check
   with `outreachconn.FieldByKey`).
4. Build a `map[string]string` and call `Apply`.
5. `errors.As(err, &ve)` with `*outreachconn.ValidationError` → 400 with
   `ve.Error()`. Any other error → 500 `"internal server error"`.
6. When `len(applied.Set)+len(applied.Cleared) > 0` and the auditor is
   non-nil, record the D8 entry with `IP: clientIP(r)`.
7. Return 200 with `view(h.conns.Snapshot())`.

Do not log request bodies anywhere.

`TargetOutreachConnections` to `internal/audit/actions.go`, next to the
outreach blocks. Doc comment: "metadata names field keys only, never
values".
