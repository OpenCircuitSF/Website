## Description

After the 2026-10-17 deploy, the Outreach page in production says:

> Outreach needs the ShortLinks connection (SHORTLINKS_BASE_URL and
> SHORTLINKS_API_TOKEN), which is not configured on this server.

Brennan, 2026-10-17: "There should be UI under the Settings section which
stores these values in the db."

Today the ShortLinks client (`#0543`) and the Bluesky and Mastodon posters
(`#0545`) are built once at startup from environment variables
(`internal/config`: `SHORTLINKS_BASE_URL`, `SHORTLINKS_API_TOKEN`,
`BLUESKY_HANDLE`, `BLUESKY_APP_PASSWORD`, `BLUESKY_PDS_URL`,
`MASTODON_BASE_URL`, `MASTODON_TOKEN`). Changing them means editing
`/etc/opencircuit/config.env` on the box and restarting. All seven move into
admin Settings.

## Acceptance criteria

- [ ] **Settings UI.** The admin Settings section gets an "Outreach
      connections" area with three groups: ShortLinks (base URL, API token),
      Bluesky (handle, app password, PDS URL with the `https://bsky.social`
      default), Mastodon (instance URL, access token). It follows the
      existing Settings view's patterns.
- [ ] **Stored in the database**, in a new migration (production is at
      `000036`; the next file is `000037`). Use the existing `settings`
      table if it fits, or a dedicated table if the plan shows a reason.
- [ ] **Secrets are write-only.** The API token, app password and access
      token are never returned by any API response, never logged, and never
      written to the audit log. The UI shows only whether each is set (for
      example "set, ends in …x7Q2" is acceptable only if the plan justifies
      it; "set" / "not set" is the default), with a way to replace or clear
      it. The audit log records which field changed, never the value.
- [ ] **Takes effect without a restart.** Saving new values rebuilds or
      reconfigures the ShortLinks client and the posters, so the Outreach
      page works immediately. The Outreach "not configured" notice points to
      the Settings area instead of naming environment variables.
- [ ] **Environment variables still work as a fallback.** If a field has no
      database value, the environment variable is used, so a dev setup with
      `.env` keeps working. The precedence is stated in `docs/` and in the
      Settings UI.
- [ ] **Test connection.** Each group has a button that checks the
      credentials against the service with a harmless read (ShortLinks: an
      authenticated list or whoami call; Bluesky: create a session; Mastodon:
      `verify_credentials`) and reports success or the error, without
      posting anything. Tests use fakes, never live services.
- [ ] **Validation.** URLs must be `https`, except `http://localhost` and
      `http://127.0.0.1` for local development. Reuse the project's existing
      URL validators.
- [ ] **Storage of secrets at rest** is decided in the plan: plaintext in the
      database (protected like the rest of the DB and its backups) versus
      encrypted with a key from the environment. State the choice and why.
- [ ] Go handler and store tests, plus SPA tests (jsdom) for the Settings
      area and the write-only behaviour. Verified with
      `ISSUE=0564 scripts/check.sh` plus `./internal/handlers/...` and
      `./internal/db/...`. Zero skips.
- [ ] `docs/configuration.md` and `.env.example` updated
      (`internal/config`'s `.env.example` guard must stay green).
