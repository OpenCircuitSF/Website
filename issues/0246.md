## Description

A public route at **`/crt`** showing only the CRT: the photographed monitor with
the live perspective-warped screen (`#0233`), scaled up to fill the viewport,
running the same session content as the home hero. No header, no navigation, no
copy, no footer — the object alone.

The home page's version is one element in a hero panel beside a headline, so it
is sized for company. This is the same component with the constraint removed:
large enough that the phosphor texture, the scanlines and the typing are the
whole experience rather than a detail.

**Uses it earns its keep for**, none of which the hero version serves:

- A screen to leave running on a monitor at a workshop or a booth.
- A link that is the brand in one image, for social or a talk.
- A place to see the effect properly when tuning it — the calibration work in
  `#0233` was done by screenshotting a 380px element and cropping in.

## Acceptance criteria

- [ ] `/crt` is a real public route, server-side reachable, not only a client-side one — a direct load and a refresh both work
- [ ] It renders the CRT and nothing else: no site header, navigation, footer, or copy
- [ ] The monitor scales to fill the viewport while preserving the photograph's aspect ratio, with no cropping of the chassis and no horizontal overflow at any width down to 320px
- [ ] The screen runs the same session content as the home hero, from **one shared source** — the two must not drift into separate scripts
- [ ] The perspective calibration is the same numbers as the hero, not a second copy — it is a percentage of the photograph, so it should scale unchanged
- [ ] The page is theme-aware like the hero: the dark photograph in dark, the light one in light, honouring both `data-theme` and the OS preference
- [ ] `prefers-reduced-motion` renders a static finished frame rather than a blank screen or an animation
- [ ] The canvas pauses when the tab is hidden, as the prototype's does — this page is likely to be left open for hours
- [ ] It has its own `<title>` and is excluded from the sitemap, or included deliberately — decide and say which
- [ ] Verified in a real browser at several viewport sizes and both themes; jsdom is not sufficient evidence for a layout claim (`CLAUDE.md` §1)

## Open questions

1. **Does it need to be indexable?** A page with no text is not useful in search
   results and could dilute the site's own ranking. Excluding it from the
   sitemap and adding `noindex` is the conservative default, but that is a
   decision, not an obvious answer.
2. **Is it linked from anywhere?** An unlinked route is fine for a URL you hand
   out deliberately. A footer link would make it discoverable but also makes it
   part of the site's information architecture, which `PRD.md` §5.1 does not
   currently describe.
3. **Interactivity.** The prototype's calibration handles and command input are
   scaffolding and should not ship. But a full-screen terminal invites typing
   at it, and `#0233`'s reference implementation had a working command input.
   Out of scope here unless decided otherwise — noted so it is a choice rather
   than an omission.

## Notes

Requested by the user on 2026-08-24, filed under Phase 9 at their direction.

**Phase 9 is "Reusable as a dependency", and this route fits that framing
better than it first appears.** `#0232` is about making branding, copy and
integrations configurable. A route whose entire content is one configurable
brand object is a good forcing function for that work: if `/crt` can be
rebranded by configuration alone — different photograph, different session
script, different accent — then the extraction `#0232` describes is real rather
than nominal. Worth building *after* `#0232` establishes the configuration
surface, so this consumes it rather than hard-coding around it.

**Depends on `#0233`**, which is a prototype, not shipped code. That issue's
open questions — what the screen says, what it costs to repaint, whether it
degrades without JavaScript — must be answered before either route exists. This
issue should not be started while `#0233` is still a static HTML file in
`prototypes/`.

The shared-source criterion is the one most likely to be quietly dropped.
Copying the session script into a second component is the obvious shortcut and
guarantees the two pages disagree within a month — the same drift class as
`#0095` and `#0237`.
