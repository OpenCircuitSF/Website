## Description

`#0092` fixed the two illegal fence **closers** the docs guard accepted. Its
phase-3 review verified the fix against `commonmark.js` 0.31.2 as an oracle —
21 closer shapes, post-fix agreeing 21/21 where pre-fix disagreed on 7 — and
then found the same defect class on the **opposite branch**.

**CommonMark caps a fence opener at 3 columns of indentation too.** The opener
branch checks only `leadingRunLength(trimmed, ch) >= 3`, so `trimmed` discards
indentation exactly as the closer branch used to. Three divergences remain at
`f74cd6f`:

- an opener indented 4 spaces,
- an opener indented 1 tab (4 columns under CommonMark's tab-stop rule),
- a backtick inside a backtick fence's info string (`` ``` foo`bar ``), which
  CommonMark forbids.

**Individually each fails in the safe, loud direction — but the review
reproduced a still-silent mask post-fix.** A spurious open from an indented
`` ``` `` flips fence parity, and a later info-string fence flips it back,
letting a phantom table row past while the guard reports `ok`. That is the same
failure mode `#0092` was filed for, reached through the other branch.

The review confirmed by oracle that such a document is honest markdown — so this
is not a contrived shape, it is a shape a documentation author could write.

**A second item, from `#0089` and still open:** the probe forms both `#0092`
and this review constructed by hand should be committed as `cases` subtests. A
per-shape entry would have caught this round *and* the last one. Three passes
have now built the same probe set and thrown it away.

## Acceptance criteria

- [ ] An opener indented 4+ columns does not open a fence, matching CommonMark
- [ ] A tab-indented opener is treated as 4 columns, using the same `leadingIndentWidth` column semantics the closer branch now uses
- [ ] A backtick in a backtick fence's info string does not open a fence
- [ ] The parity-flip masking scenario the review built is reproduced and now fails loudly — this is the criterion that matters
- [ ] Each divergence is proved by mutation: drop the condition, confirm exactly its own subtest fails
- [ ] The probe shapes are committed as `cases` subtests rather than reconstructed, covering both opener and closer forms
- [ ] `#0092`'s 16 leaf subtests still pass, `TestDatabaseDocMigrationParity`'s 2 still pass, and `#0113`'s `TestPRDSectionIndexParity` is untouched
- [ ] `ISSUE=0224 scripts/check.sh go ./internal/...` passes with zero skips

## Notes

Reported by `#0092`'s phase-3 review under `CLAUDE.md` §9.

Criterion 4 is the one that decides whether this is worth doing. Each divergence
alone is loud; the composition is silent, and silence is what `#0083`, `#0086`,
`#0089`, and `#0092` were all filed about.

**Use the reference implementation.** `#0092`'s review ran `commonmark.js`
0.31.2 against 21 shapes and used the agreement count as its verdict. That is a
far better oracle than reading the spec prose, and it is what turned "these two
forms are wrong" into "post-fix agrees 21/21, pre-fix disagreed on 7".

Reuse `leadingIndentWidth` — it already implements CommonMark's column
semantics (`col += 4 - (col % 4)`), verified by that review, and the closer
branch now depends on it.
