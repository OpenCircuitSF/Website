## Resolution notes

> 🟢 Resolved 2026-10-19 — `go_test()` now runs `go test` once, tees the full output to a gitignored `.scratch/gotest.*` file for the skip audit, and keeps the verdict on `go test`'s own exit status; the scoped run dropped from 33.5s to 17.1s.

## Description

`go_test()` in `scripts/check.sh` runs `go test $pkgs -p 2 -count=1` once
for the result, then runs the identical command again for the skip audit.
Measured 2026-10-19 on `ISSUE=tiers2 scripts/check.sh go
./internal/outreach/... ./internal/handlers/...`: the test step took 13.8s
and the repeat 12.2s, 37% of a 33s run. Every implementer and reviewer pays
it on every run (median three runs per phase).

## Acceptance criteria

- [ ] `go_test()` runs `go test` once, keeps its full output in a temporary
      file, prints the bounded tail from that file, and runs the skip audit's
      grep over the same file. The pass/fail accounting still comes from
      `go test`'s own exit status via `runpipe`, never from `tail` or `grep`.
- [ ] The temporary file is removed on every exit path, including a failed
      run and an interrupted one.
- [ ] The skip audit still reports `[no test files]` and `--- SKIP` lines from
      the whole output, not only the tail.
- [ ] `scripts/check_guard_test.sh` proves a failing package still yields
      `VERIFICATION FAILED`, and that a skip in a package whose `ok` line is
      outside the tail is still reported.
- [ ] `## Verification` quotes before and after timings of the same scoped
      run at normal load.
- [ ] Verified with `scripts/check.sh guards` and
      `ISSUE=0608 scripts/check.sh go ./internal/outreach/... ./internal/handlers/...`.
      Zero skips.

## Root cause

`go_test()` piped `go test` into `tail` for the verdict, then re-ran the
identical `go test` command just to grep its output for the skip audit,
because the first run's full output was not kept anywhere.

## Fix

As planned. `go test` runs once inside the single `runpipe` call, teeing its
full output to a `mktemp` file under gitignored `.scratch/` and printing the
tail. The skip audit greps that file, and `go_test` removes it afterwards. A
new `GO_TEST_OUT` global lets the one-line `cleanup()` EXIT trap remove the
file on an interrupted run. A `mktemp` failure is reported through `run false`,
not a direct `FAILED=1`, so Part 6 parity is unchanged. The runpipe count stays
14 and no digest changed. There was one deviation: each of the two Part 2
payload `printf`s carries a `# shellcheck disable=SC2016` because its
single-quoted `$` text is intentional, and without it shellcheck reports new
info findings. SIGKILL cannot be trapped, so a killed run leaves one
`gotest.*` file under `.scratch/` (gitignored). This is unavoidable.

### Approach: `scripts/check.sh`

**1. New global.** Put it on the line immediately after `OWN_DB=""` (just
above `if [ "$MODE" = build ]; then`):

```bash
GO_TEST_OUT=""
```

Write it as an empty assignment. The `FUNCDEF-0258` suspect pattern rejects the
keyword that clears a variable (see that block's own note).

**2. `cleanup()`.** This is the EXIT trap function, and it must stay a
**one-line** definition. Prepend the temp-file removal so it runs first,
before the database drop and the NO VERDICT check. The rest of the line stays
byte-identical:

```bash
cleanup() { [ -n "$GO_TEST_OUT" ] && rm -f "$GO_TEST_OUT"; [ -n "$OWN_DB" ] && scripts/testdb.sh drop ... (rest unchanged)
```

Do not touch `trap cleanup EXIT`. `check_guard_test.sh`'s `early_exit` row
anchors on that exact line. Neither `cleanup` nor `go_test` is digest-pinned:
only the `run` helper, the `runpipe` funnel and `accounting_probe` are. So no
digest needs recomputing. **If any `self-check:` fires, fix the new text. Never
recompute a digest.**

Exit paths covered:
- **Normal and failed runs:** `go_test` removes the file itself after the
  audit (below). `runpipe` never aborts the function, because `run` always
  returns 0.
- **Interrupted runs** (SIGINT/SIGTERM): bash 3.2 runs the EXIT trap on
  TERM. Measured while planning: `trap ... EXIT` fired when TERM went to the
  process group mid-pipeline. `cleanup` removes the file while
  `GO_TEST_OUT` is still set.
- **A `self-check` `exit 2`:** every self-check runs before `go_test`, so no
  file exists yet and `GO_TEST_OUT` is empty.
- **SIGKILL** cannot be trapped. The file is left under gitignored `.scratch/`.
  This is acceptable and can't be avoided, so say so in `## Resolution notes`.

**3. New `go_test()` body.** Keep the `#0212` comment and the `pkgs` line as
they are, and replace everything after them:

```bash
  local pkgs="$*"; [ -n "$pkgs" ] || pkgs="./internal/... ./cmd/... ./web/..."
  # #0608: go test runs ONCE. Its full output is kept in a file under
  # gitignored .scratch/ (the #0537/#0540 directive), the bounded tail is
  # printed from the same pipeline, and the skip audit greps the whole file
  # -- so a [no test files] line above the tail is still reported. The
  # verdict still comes from go test's own exit status: with pipefail in the
  # funnel, tee and tail exit 0 and the pipeline reports go test's status.
  # The EXIT trap's cleanup removes the file if the run is interrupted.
  mkdir -p "$REPO/.scratch"
  GO_TEST_OUT="$(mktemp "$REPO/.scratch/gotest.XXXXXX")" || {
    printf '\033[31mcould not create the go test output file under .scratch/ (#0608)\033[0m\n'
    run false; GO_TEST_OUT=""; return 0
  }
  step "go test $pkgs -p 2"
  runpipe "go test $pkgs -p 2 -count=1 2>&1 | tee \"$GO_TEST_OUT\" | tail -$TAIL"
  step "skip audit — a package reporting [no test files] or 'no test files' proves nothing"
  grep -E 'no test files|SKIP|--- SKIP' "$GO_TEST_OUT" | head -20 || echo "(no skips)"
  rm -f "$GO_TEST_OUT"; GO_TEST_OUT=""
```

Why it is shaped this way. Each of these is a constraint, not a style choice:
- **`run false`, not `FAILED=1`**, on mktemp failure. `check_guard_test.sh`
  Part 6 pins the set of functions that assign `FAILED=1` directly to
  `floor_guard_check gofmt_check run`. A direct assignment inside `go_test`
  fails that parity row, which would also demand a new isolation row.
- **`tee` inside the one `runpipe` call**, not a second `go test` and not
  `> file; tail file`. The latter puts tail's exit status in charge, which is
  exactly what the acceptance criteria forbid. Part 2's `gotest_tail_status`
  row (below) proves the guard catches that shape. If `tee` itself fails, for
  example on a full disk, the step fails, which is correct: the audit would be
  unreliable.
- **The runpipe call-site count does not change.** It is still one call in
  `go_test`; the removed second `go test` never went through `runpipe`. The
  floor stays **14** and its comment stays as it is.
- **The new lines must not trip the in-file scans.** None of them puts the
  word `sh`/`bash` next to a `-c…` cluster (the `SHELLC` scan: note that `-count`
  matches it, so never mention a `.sh` file on a line containing `-count`).
  None spells `pipefail`. None has a `.` in command position, or a helper name
  followed by `(` on a code line.
- The audit line keeps today's `| head -20 || echo "(no skips)"` behaviour.
  That includes its existing quirk of also printing `(no skips)` after 20+
  hits, through SIGPIPE under the script's own `pipefail`. Do not fix that here.

**B. New builder,** next to `mk_build_sandbox`:

```bash
mk_gotest_sandbox() {  # <name> <script> <kind: pass|fail|slow> -> prints sandbox dir
  local sb="$WORKDIR/sb/$1" p
  rm -rf "$sb"; mkdir -p "$sb/scripts" "$sb/a" "$sb/b" "$sb/c" "$sb/d" "$sb/e"
  cp "$2" "$sb/scripts/check.sh"; chmod +x "$sb/scripts/check.sh"
  printf 'module gotestsandbox\n\ngo 1.22\n' > "$sb/go.mod"
  printf 'package main\n\nfunc main() {\n\tprintln("ok")\n}\n' > "$sb/main.go"
  printf 'package a\n' > "$sb/a/a.go"
  case "$3" in
    fail) printf 'package b\n\nimport "testing"\n\nfunc TestFail0608(t *testing.T) { t.Fatal("sandbox-0608 failure") }\n' > "$sb/b/b_test.go" ;;
    slow) printf 'package b\n\nimport (\n\t"testing"\n\t"time"\n)\n\nfunc TestSlow0608(t *testing.T) { time.Sleep(60 * time.Second) }\n' > "$sb/b/b_test.go" ;;
    *)    printf 'package b\n\nimport "testing"\n\nfunc TestOK(t *testing.T) {}\n' > "$sb/b/b_test.go" ;;
  esac
  for p in c d e; do
    printf 'package %s\n\nimport "testing"\n\nfunc TestOK(t *testing.T) {}\n' "$p" > "$sb/$p/${p}_test.go"
  done
  printf '#!/bin/sh\nexit 0\n' > "$sb/scripts/go_file_visit_floor_guard_test.sh"
  chmod +x "$sb/scripts/go_file_visit_floor_guard_test.sh"
  printf '%s' "$sb"
}

run_gotest_case() {  # <sandbox> <tail> -> sets RC / OUTFILE
  OUTFILE="$1/out"
  ( cd "$1" && env -u ISSUE TAIL="$2" "$BASHBIN" "$1/scripts/check.sh" go ./... ) > "$OUTFILE" 2>&1 < /dev/null
  RC=$?
}

no_gotest_left() {  # <sandbox> -> 0 if no gotest.* temp file remains
  ! ls "$1/.scratch"/gotest.* >/dev/null 2>&1
}

audit_reports_a() {  # 0 if the skip-audit section (only) names gotestsandbox/a [no test files]
  awk '/=== skip audit/{s=1} s && /gotestsandbox\/a[[:space:]]+\[no test files\]/{f=1} END{exit !f}' "$OUTFILE"
}
```

The planner measured this module layout on go1.27.2. The output is:

```
?   	gotestsandbox	[no test files]
?   	gotestsandbox/a	[no test files]
ok  	gotestsandbox/b	...
ok  	gotestsandbox/c	...
ok  	gotestsandbox/d	...
ok  	gotestsandbox/e	...
```

The files are gofmt-clean, so `gofmt_check` passes and the floor stub exits 0.
In a passing sandbox the only steps left are build, vet and `go_test`.

Two measured facts about the skip audit. **Without `-v`, `t.Skip` and a
passing package's TestMain stdout are never printed.** Only the `ok` line
appears, so `--- SKIP` reaches the audit only from a failing package's output.
That makes `[no test files]` the skip signal a row can provoke, and it is what
"a skip outside the tail" means here. Say this in the row's comment.

**C. Part 1d,** a new section after Part 1c, headed
`== Part 1d: go_test runs once (#0608) ==`. It has three rows:

1. `gotest_failing_package`: `mk_gotest_sandbox p1d_fail "$REAL" fail`, then

3. `gotest_interrupted`: `mk_gotest_sandbox p1d_int "$REAL" slow`. Run it in

   appear, then TERM the group:

   ```bash
   OUTFILE="$SB/out"
   set -m
   ( cd "$SB" && exec env -u ISSUE "$BASHBIN" "$SB/scripts/check.sh" go ./... ) > "$OUTFILE" 2>&1 < /dev/null &
   CPID=$!

   wait "$CPID"; RC=$?
   kill -KILL -- "-$CPID" 2>/dev/null || true   # own group only (AGENTS.md §5a); a no-op when TERM sufficed
   ```

   PASS when all of these hold: `SEEN -eq 1` (the file existed, so the row is
   not vacuous); `no_gotest_left "$SB"`; `RC -ne 0`; and `grep -q 'NO VERDICT'`
   (cleanup ran). If `SEEN` is 0, `fail` with "temp file never appeared in
   120s" and do not report a pass. The kill is scoped to the pid this row
   started, never a pattern.

## Obstacles

- **check.sh's in-file self-checks.** These are the main risk. They are
  avoided by not touching the marker blocks or the three digest-pinned
  functions, and by following the spelling constraints above. If a
  `self-check:` fires, its message names the line: rewrite the new text. Never
  recompute a digest.
- **Part 6 parity.** Any direct `FAILED=1` added to `go_test` fails it. Use
  `run false` as planned.
- **The `gotest_interrupted` row signals processes.** It TERMs and KILLs only
  the process group it started itself (`set -m` gives the background job its
  own group). Never use `pkill -f` (`AGENTS.md` §5a). If a sleeping
  `gotestsandbox` test binary is left running after a failed attempt, find it
