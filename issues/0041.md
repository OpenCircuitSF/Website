## Description

Create, edit, list, and cancel campaigns, with the state machine that prevents a half-configured campaign from ever sending.

## Acceptance criteria

- [ ] `GET/POST/PATCH /admin/campaigns[/{id}]`, admin-gated
- [ ] Campaign targeting stored via `campaign_interests` with the four audience modes
- [ ] A campaign can only be edited while `draft` or `scheduled`
- [ ] `POST /admin/campaigns/{id}/cancel` stops a `scheduled` or `sending` campaign; already-sent messages are not recalled
- [ ] Status transitions validated server-side — an invalid transition is a 409, not a silent no-op
- [ ] Audit rows for create, edit, send, and cancel
- [ ] Handler tests cover every legal and illegal transition

## Notes

PRD §8. Cancelling a `sending` campaign stops the worker from claiming further queued rows; it cannot unsend. Make that explicit in the UI copy (#0047) — an operator hitting cancel mid-send needs to know what it does and does not do.
