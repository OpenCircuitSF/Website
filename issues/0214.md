## Description

`#0213` made `BASE_URL` and `WEBAUTHN_RP_ORIGIN` derive from `$PORT` instead of
a hardcoded `8080`. Its phase-3 review found the documentation did not follow.

**`docs/dev.md:51,53` still list both defaults as the literal
`http://localhost:8080`.** They are now `http://localhost:${PORT}`. The table's
own example, six lines further down, is `PORT=9090 ./scripts/dev.sh` — which is
precisely the case where the stale literal misleads: a reader sets `PORT=9090`,
reads that `BASE_URL` defaults to `:8080`, and concludes the override is the
half-broken thing `#0213` just fixed.

**A second, cosmetic finding from the same review.** `web/vite.config.ts` sets
no `server.port` or `strictPort`, so `5173` is *inherited* from Vite's default
rather than declared. A bare `npm run dev` with `5173` occupied slides silently
to `5174` while `README.md`, `docs/dev.md`, `CLAUDE.md`, and `dev.sh`'s messages
all still say `5173`. Unreachable through `dev.sh` — `#0117`'s preflight refuses
before Vite starts — so this is about the bare-`npm` path only.

## Implementation notes

- `docs/dev.md`'s environment table: `BASE_URL` and `WEBAUTHN_RP_ORIGIN` rows
  now read `http://localhost:${PORT}` instead of the stale literal
  `http://localhost:8080`, each with a one-line note that they derive from
  `$PORT` (#0213). Moved the `PORT` row above both, since they're now defined
  in terms of it — matching `scripts/dev.sh`'s own ordering (its header
  comment: "PORT must be set before BASE_URL/WEBAUTHN_RP_ORIGIN so both can
  default off of it"). Added a sentence directly under the `PORT=9090`
  example spelling out what it now means for the two derived values, since
  that example sitting six lines below the stale literal was exactly what
  made the old text misleading.
- Checked `README.md` and `CLAUDE.md` for the same stale defaults
  (`grep -n '8080\|localhost' README.md docs/*.md CLAUDE.md`, filtered to
  `BASE_URL`/`WEBAUTHN_RP_ORIGIN`/literal `:8080`  mentions). `README.md` does
  not mention either variable. The `:8080` mentions in `docs/architecture.md`
  and `docs/deployment.md` describe the **production** reverse-proxy target
  (`127.0.0.1:8080`, Apache → Go), not `dev.sh`'s dev-mode default — out of
  `#0213`'s scope, left as is. `CLAUDE.md:229-230` only names dev.sh's ports
  in a one-line comment (`./scripts/dev.sh # Vite :5173 + Go API :8080, hot
  reload, STORAGE=json`), which is still true as a *default-run* description,
  not a claim about what `BASE_URL`/`WEBAUTHN_RP_ORIGIN` resolve to under an
  override — left unchanged.
- `web/vite.config.ts`'s `server` block previously set no `port` or
  `strictPort`, so `5173` was inherited from Vite's own default rather than
  stated. Added `port: 5173` (states what every doc already claims) and
  `strictPort: true` (fail loudly on a collision rather than silently
  sliding to `5174`, matching this project's general preference for refusing
  over silently substituting something else — see `scripts/dev.sh`'s own
  `free_port`). Recorded in a comment on why this is unreachable through
  `scripts/dev.sh` itself: `#0117`'s preflight (`free_port 5173`) already
  refuses before Vite starts, so this only changes behavior on the bare
  `npm run dev` path.
