## What exists, so it isn't rebuilt
- The registry, the binder, the idempotency store, the PUBLIC/DESTRUCTIVE description prefixes, and `/mcp` (`internal/api`, `internal/mcpserver`).
- Guide posts already reach parity with the admin console (C-audit below). The one gap is engagement, which `#0704` and `#0706` cover.
- `AdminOutreachHandler` (`internal/handlers/admin_outreach*.go`) holds all the event-outreach logic, but **every method is `(w, r)`-bound**. `#0676` refactored `AdminGuidePostsHandler` into transport-free methods `(ctx, ip, actorID *int64, …)` that the admin route and the v1 op both call. Every event-outreach child does the same extraction for the handlers it touches. That extraction is most of the work.

## Principles (all children)
- **No second code path.** Each v1 op calls a transport-free method that the admin route also calls after the extraction. Validation, the audit action, short links, SEO invalidation and outbox effects are shared. The admin JSON bodies stay byte-identical, and the existing `admin_outreach*_test.go` suites must pass unchanged. That is the regression proof.
- **Audit against the key.** Use `middleware.AttributeAPIToken(ctx, e)` with `api.ClientIPFromContext`, following `AdminGuidePostsHandler.recordCtx`. Add an `AdminOutreachHandler.recordCtx(ctx, ip, targetType, id, e)` in `#0697` and reuse it everywhere.
- **Flag honestly.** `PublicEffect` on anything that posts or changes something publicly; `Destructive` on anything that can't be undone.
- **Pacific output times**, using `inPacific`, the same as guide posts since `#0687`. `get_engagement` stays UTC: Home Assistant's golden test pins it.
- **Secrets never leave.** Connection status is booleans only. Upload tokens are never logged.
- **Docs parity per child.** `TestV1DocsNameEveryOperation` fails unless each new op name appears in backticks in `docs/api.md` and `docs/mcp.md`. Each op child adds a one-line entry per op under a new "Outreach" heading, and `#0707` writes the prose.
- **`TestBuildV1RegistryListsOperations`** pins the ordered op list. Each child appends its names.

## Acceptance (umbrella)
Every child resolved. Then a Claude Code session on production `/mcp` with an Agent-preset key can:
1. start outreach for an upcoming event, draft all waves, edit one post, schedule the Announce wave, and later send a reminder now, after confirming;
2. upload a cover image from a local file, set it on the event (`update_event cover_image`), and see `thumb_ok` in the outreach panel;
3. set up a flyer at two locations and mark one link put up;
4. answer "how did last week's posts do?" across event and guide posts, with likes, reposts, replies and clicks;
5. a second agent with a Read-only key sees only read tools.

## Assumptions (user may override)
- **Scopes are coarse per resource.** Flyers and locations fall under `outreach:*`. Media is separate, because a key that can only upload images is a useful thing to have.
- **The Agent preset includes every write scope.** A new **Read-only** preset holds every `:read` scope. Docs recommend a Read-only key for unattended (Buzz) agents.
- **Media upload is a single-use URL, not base64 in a tool call.** MCP tool arguments are generated by the model token by token. A 1 MB image is about 1.4M base64 characters, so it can't be an argument, and `api.MaxBodyBytes` (64 KiB) caps `/mcp` anyway. The agent calls `create_media_upload` and then runs `curl` with the returned single-use token. The API key never reaches the shell. A server-side URL fetch was rejected because it is an SSRF surface.
- **Alt text for event covers is `#0572`** (open: the `workshops.cover_alt` migration plus the editor field). It is pulled in as a sibling, and once it lands `update_event` takes `cover_alt` (a one-field follow-up in `v1_events.go`). Flyer photos need no alt text, because they are print.
- **Flyer printing stays human.** `generate_flyer` makes the per-location short links and QR codes. The ops return the admin print URL rather than a PDF.
- **Connection credentials are status only.** That means `configured` and `source` (env or saved) per group. There are no set or test ops.
- **Guide-post engagement is polled like event posts** (`#0704`). That adds a few API calls to Bluesky and Mastodon per guide post over its first 30 days.

## Guide posts parity audit (gap 2)

Admin `/admin/guide-posts*` against v1:

| Admin action | v1 op |
|---|---|
| list | `list_guide_posts` |
| create | `create_guide_posts` |
| patch | `update_guide_post` |
| delete | `delete_guide_post` |
| schedule | `schedule_guide_post` |
| unschedule | `unschedule_guide_post` |
| send | `send_guide_post` |
| again | `post_guide_again` |
| overview | `guide_posts_overview` |

Every admin action has an op. Two differences remain:
1. **Delete.** v1 `delete_guide_post` is drafts-only by design (`deletePost(…, draftOnly=true)`, `#0686`). Keep it that way.
2. **Engagement.** Clicks and signups show in `get_guide` and the overview, but likes and reposts don't exist for guide posts at all. `#0704` and `#0706` close this gap.

No other child is needed for guides.

- **`#0696` runs first.**

- **Parallel pairs** (at most 3 agents in flight, each on its own test DB):
  - **`#0704` ∥ `#0696`:** fully disjoint, and the migration numbers are pre-assigned.
  - **`#0705` ∥ `#0697`:** media files against outreach files.
  - **`#0702` ∥ `#0699`,** then **`#0703` ∥ `#0700`/`#0701`:** locations and flyers are separate files from posts and posting.
  - **`#0698` ∥ `#0699`:** `admin_outreach_results*` and `timeline`/`luma` against `admin_outreach.go`.
- **Shared one-liners in every op child:** `v1_registry.go`, `v1_registry_test.go`, `docs/api.md`, `docs/mcp.md`, and for `#0697` and `#0705` `cmd/opencircuit/main.go`. Run parallel children in **worktrees** and merge, or stagger commits and use AGENTS.md §8a's index check. Never edit with a pathspec commit while another agent has those files dirty.
