## Resolution notes

> 🟢 Resolved 2026-11-04 — each Outreach section now has a numbered strip with its real status that stays pinned while the section is on screen (measured in Safari on the real page against a stubbed API), previews name their channel and section, covers start small, and the third section reads Final with the post copy unchanged.

## Description

On a workshop's Outreach screen, preview cards are titled only with the channel and account, so the same title appears three times. The wave is named once at the top of a section about 1,800 px tall, and nothing stays pinned. Four copies of the cover photo take 31% of a 6,414 px page. The Reminder header can show a past suggested date beside its real scheduled time, and the Announcement header has no status at all.

## Plan

Written 2026-11-04 against `b685ffef`. Scope is the wave strip, card titles, thumbnails, status wording and the Final label. It does **not** add the status board (`#0624`), turn Announce into a row or make one wave open at a time (`#0625`), or move hand-posted cards (`#0626`). The Announce branch of the strip sits behind the same `wave === 'announce'` condition as today's heading, so `#0625` deletes one wrapper and nothing else.

### The trap this plan is built around

`web/src/lib/Panel.svelte` sets `overflow: hidden` on `.panel`, and `OutreachWorkshop.svelte` puts the whole page inside `<Panel title="Outreach">`. That makes the panel the sticky element's scroll container, and the panel itself never scrolls, so `position: sticky` would silently do nothing while every jsdom test passes. Step 3 fixes this for this one panel. No other ancestor is a problem: `App.svelte`, `.app-shell`, `Admin.svelte`, `Outreach.svelte` and `OutreachPanel.svelte` set no overflow on the ancestor chain (the `overflow-x` rules in `Admin.svelte` and `SubNav.svelte` are on sibling tab rows). Nothing else on the page is sticky, so `top: 0` is correct.

### Approach

**1. The Final label, from one place.** In `internal/outreach/channels.go`, change only the `last-call` row's `Label` to `"Final"`. `Name` stays `last-call`. `templates.go` never reads `Label` and switches on `w.Name`, so `TestDraftGolden` still pins the "Last call" post copy unchanged; do not touch `templates.go` or that test. The label reaches every admin screen through `waves[].label` and `wave_label`, including the Schedule all dialog's heading.

Two places do not take the label from the server, and both change here:

- `waveLabel` in `web/src/lib/outreachResults.ts` derives text from the name. Add `if (name === 'last-call') return 'Final';` as its first line and update its comment.
- The `outreach_post_hour` help text in `web/src/lib/serverSettings.ts` becomes "Reminder and Final posts".

One outward effect, deliberately accepted: `postLinkRequest` builds the ShortLinks title from `wv.Label`, so links created from now on are titled `… Bluesky Final`. Existing links keep their old titles. Nothing breaks, because ShortLinks de-duplicates on the URL, not the title, and `UTMContent` uses `wv.Name`.

**2. One status writer, with real dates.** In `web/src/lib/outreachMessage.ts`, change `waveRowStatus` to `waveRowStatus(view, wave, now: Date = new Date())`. Import `defaultScheduleAt` from `./outreach` (the file already imports from there). It already returns null for Announce, for no suggestion and for a suggestion that has passed, so a past date cannot reach the screen.

Let `suggested` be `defaultScheduleAt(wave, view.waves, now)`. Let `ahead` be ` · suggested {weekdayTime(suggested)}` when `suggested` is non-null, otherwise empty. Let `when` be `weekdayTime` of the newest non-null `posted_at` among the automatic posted posts, or empty. The text, in the existing order of checks:

| Case | `text` | `action` |
|---|---|---|
| No posts in the wave | `Not written · not scheduled` + `ahead` | `write` |
| All automatic posts posted | `Posted {when}`, or `Posted n of n` if `when` is empty | `open` |
| Any queued | `Posting now…` (unchanged) | `open` |
| Any failed | `Drafted · a post failed` (unchanged) | `open` |
| Scheduled, some on hold | `Scheduled {first} · on hold until the event is published` | `open` |
| Scheduled | `Posts automatically {first}`, using `from {first}` when the scheduled times differ, then ` · posted n of m` when `n > 0` | `open` |
| Some posted, the rest not scheduled | `Posted n of m`, then ` · {when}` when known | `open` |
| Otherwise | `Drafted · not scheduled` + `ahead` | `open` |

`ahead` appears only on the first and last rows, which is the "no suggested date once scheduled or posted" criterion. Then add, beside it:

```ts
export interface WaveStrip extends RowStatus { ordinal: number; label: string; }
export function waveStrip(view: View, wave: string, now: Date = new Date()): WaveStrip
```

`ordinal` is the wave's index in `view.waves` plus 1, never a hard-coded table. `label` is that entry's `label`, or `wave` if absent. Do not write "the day before" or any other fixed phrase.

## Root cause

The section name lived in one heading or summary line that scrolled away, and preview titles named only the channel. The Outreach panel's `overflow: hidden` would also have stopped anything inside it from pinning. The row printed `suggested_at` unconditionally beside its status, so a past or superseded date could show, and the Announcement header had no status because it was a bare heading.

## Fix

Followed the plan. `waveRowStatus` is the one status writer and takes `now`; `waveStrip` adds the number and label; `OutreachWaveStrip` renders them in the row summary and in a pinned div for Announce. `Panel` gained `pinnable`, used only by the Outreach panel. `OutreachCoverImage` gives the thumbnail and full-size control. The third section's `Label` and `waveLabel` say Final; `Name` and `templates.go` are unchanged.

No deviation from the plan. Small choices it left open: in `OutreachWaveStrip.css.test.ts` the pin-class check reads the literal `<summary class="wave-pin">` and `<div class="wave-pin">`; the "no strip in Reminder" test looks at `document` because `mountView` does not return the container.

## Review notes

Every acceptance criterion holds, and the `## Check after deploy` list should pass on the live site: the third section's name comes from the server label everywhere it is shown, and "Last call" survives only in comments and in post copy.

Does it fix the complaint? Partly, and honestly so. Inside a section you can no longer lose your place: the number, name and time stay on screen and every card repeats the section name, which is a real improvement over the same title appearing three times. It does **not** yet let you see all three times together. The Announce section is open by default and about 1,100 px tall, so its strip and the Reminder strip are a screen apart. That is `#0624` and `#0625`'s job, by design, and this issue's scope stops short of it.

Two things found, neither a criterion failure, both reported to the orchestrator rather than fixed here:

1. **A partly scheduled section overstates itself.** With Bluesky scheduled and Mastodon still a draft, `waveRowStatus` says `Posts automatically {time}` and nothing about the draft, because it only looks at the scheduled posts. The wording predates this issue, but the strip now pins it on screen, and "when is each one going out" is the user's question. Remedy: add ` · {n} not scheduled` when some automatic posts are drafts.
2. **At narrow widths the strip gets tall and the disclosure triangle sits on its own line.** At 520 px wide the strip measures 82 px, because the `inline-flex` heading wraps below the summary's marker once it no longer fits. That also exceeds the `4rem` scroll margin. Desktop is unaffected; the strip is 38 px at 1100.

The evidence for pinning is Safari only. `## Check after deploy` remains the check against real data.
