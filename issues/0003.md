## Description

Delete the Svelte views and TypeScript helpers that manage short links, campaigns, and click analytics. The passkey views and UI primitives stay.

> 🟢 Resolved 2026-08-18 — Shortener views and helpers removed; `svelte-check` reports 0 errors across 171 files, 61 vitest tests pass, and the rewritten generic `subscribeEvent<T>` is a sound base for #0048.

## Root cause

Not applicable — stripping work, not a bug. The SPA copied in #0001 carries the full ShortLinks dashboard/campaigns/analytics surface; it needed to come out before the retained auth/account/admin views could be considered the clean starting point for later phases.

## Fix

Deleted exactly the views, lib modules, and components the issue names. Pruned `api.ts` down to the request-helper core (`ApiError`, `apiGet/Post/Patch/Delete`) plus the endpoint wrappers the retained views actually call: `getMe`, `logout`/`logoutAll`, the full auth ceremony (login/register/recover start-verify-finish), account credentials, and admin users/settings/audit. Pruned `types.ts` to `User`, `Credential`, `AuditEntry`, `AdminUser`, `Setting` — every link/campaign/UTM/filter-rule interface is gone. `stores.ts`'s `View` union is now `login | account | admin | register-verify | recover-verify`; the `links`, `selectedLinkKey`, and `selectedCampaignSlug` writables are gone with them.

Three retained files needed adaptation beyond simple deletion, since they referenced symbols the deleted files defined:

1. **`App.svelte`** — left in the minimal working state the issue specifies: imports/branches for `Dashboard`, `LinkDetail`, `CampaignsList`, `CampaignDetail` removed; the post-`getMe()` success path now lands on `'account'` instead of the deleted `'dashboard'`. `#0014` owns real routing later.
2. **`lib/events.ts`** — kept per the issue's explicit trap warning, but its ShortLinks form was hardwired to a `link.created` SSE frame carrying a `Link` (the type just deleted from `types.ts`), so it could not simply be left alone. Rewrote it as a generic `subscribeEvent<T>(eventName, onEvent, factory)` — same EventSource-wrapping, parse-defensively, cleanup-closes-the-connection plumbing, now parameterized by event name and payload type rather than baked to links. `events.test.ts` follows suit with a local `TestPayload` fixture instead of a `Link` one, plus a new test (`ignores frames of a different event name`) that the generic dispatch made meaningful to add.
3. **`Admin.svelte`** (retained; #0009 later ports it properly) — still imported `listFilterRules`/`createFilterRule`/`updateFilterRule`/`deleteFilterRule`/`testFilterRule` from `api.ts` and `REASON_OPTIONS`/`reasonLabel`/`filterTestNotice`/`FilterTestNotice` from `lib/admin.ts` for its "URL filters" admin subtab — a whole panel with no backend left after #0002 deleted `internal/handlers/url_filters.go`. Stripped that entire subsection: state, handlers, the subtab button, its markup block, and the now-dead CSS selectors (`.intro`, `.inline-check`, `.inline-check input`, the table-cell-input override) it alone used. Removed the same URL-filter helpers from `lib/admin.ts` and their tests from `admin.test.ts`, leaving the deactivation-reason, audit-rendering, and pagination helpers untouched. Also fixed `Login.svelte`/`RegisterVerify.svelte`/`RecoverVerify.svelte`'s post-ceremony `currentView.set('dashboard')` (now a compile error against the narrowed `View` type) to `'account'`, and removed `Account.svelte`'s/`Admin.svelte`'s Dashboard/Campaigns nav-tab buttons along with their now-nonexistent `links` store import and `links.set([])` calls.

`branding.ts`'s `APP_NAME` is now `"Open Circuit SF"`.

## Gotchas

- `lib/events.ts`'s generalization is a judgment call beyond the issue's literal "keep it and its test" instruction — the file as shipped by ShortLinks would not compile once `Link` left `types.ts`, so keeping it verbatim was not actually an option. Worth the reviewer's attention: the new `subscribeEvent<T>` shape is a guess at what #0048 will want (event name + generic payload), not something #0048's issue text specifies.
- `Admin.svelte`'s URL-filters strip goes beyond the issue's explicit file list (which only names top-level views/lib modules to delete) but was necessary to reach `npm run check`'s 0-errors bar — `#0009` ("Port the admin users, settings, and audit views") is the issue that more fully owns Admin.svelte's shape, so the reviewer may want to confirm this doesn't step on #0009's plan.
- `npm install` had to be run before any of the three verification commands — the checkout carried no `web/node_modules/` (correctly gitignored, but worth noting for the next agent who hits the same empty-`node_modules` state fresh).
