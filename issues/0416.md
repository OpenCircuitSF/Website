## Description

All three live workshops carry a `cover_image` — `/soldering.jpg` and
`/programming_leds.jpg` — and both resolve `200` in production.

**Neither file exists in this repository.** Not in the working tree, not in
`web/public/`, and not in any commit on any branch. They live only in
`/opt/opencircuit/web/public/` on the box, as **untracked** files:

	-rw-r--r-- 66301 Sep  1 03:59 programming_leds.jpg
	-rw-r--r-- 89179 Sep  1 03:59 soldering.jpg

`git ls-files web/public/` on the deploy checkout lists the fonts, favicons and
hero images — and not these two. They reach production because
`npm run build` sweeps `web/public/` into `dist/`, which the binary embeds.

## Why this is urgent

**A deploy is imminent** (the campaign-archive work). The images survive a
`git pull` into the existing checkout, because git does not touch untracked
files. They do **not** survive:

- a fresh clone,
- `git clean`,
- rebuilding on a different host,
- restoring the box from scratch.

Any of those silently reverts all three workshops to the generic
`og-default.png` card and breaks two live image URLs. The failure is silent —
nothing errors, the pages simply lose their images.

This is `#0153`'s recorded hazard — content "put on the server outside the
product" — landing for real.

## Acceptance criteria

1. Both images are committed to the repository at the path the deployed site
   serves them from, so a clean checkout reproduces production.
2. **Retrieve the actual files from the box** rather than substituting new ones —
   these are the images already live, and the workshops' `cover_image` values
   point at these exact paths.
3. Confirm the committed files are byte-identical to what production serves,
   by hash.
4. `npm run build` still places them where the binary embeds them, and the two
   URLs still resolve after a clean rebuild. **Prove it from a clean checkout**,
   not from the working tree that already has them.
5. Check whether **any other** untracked asset on the box is in the same
   position. `git -C /opt/opencircuit status --porcelain` names them; do not
   assume these two are the only ones.
6. Consider whether anything should prevent a recurrence — a guard that the
   workshops' `cover_image` values resolve to committed files would catch it,
   but per `#0330`/`#0347`/`#0356`/`#0381` recording the hazard is a legitimate
   outcome. **Say which you chose and why.**
7. `(cd web && npm run check)` and `(cd web && npm test)`. If any Go comment or
   a cited file changes, run `./internal/handlers/...`. Per §5 name the specific
   tests that ran.

## A related observation, not a defect

`introduction-to-soldering` and `introduction-to-soldering-2` share one cover
image, so they unfurl identically today. That is correct behaviour —
`cover_image` is the override and both workshops set it to the same file — but
it is worth knowing, since it is the same *visible* symptom `#0273` exists to
fix for workshops with no cover at all.
