## Resolution notes

> 🟢 Resolved 2026-11-05 — An open editor now has one wrapping action row and a date picker that stays closed until asked for, which took the scheduled Bluesky card in the review's Safari run from 510 px to 379 px, shorter than the 441 px preview it edits.

## Description

An open editor is about 560 px: a 150 px text area, link details, a repeated `Scheduled for` line, a date input, and buttons stacked vertically.

## Root cause

The composer stacked its schedule controls above the action row: an always-open date picker, then Unschedule in its own block, then Save, Cancel and Delete. Each added a line to every open editor.

## Fix

Followed the plan with no deviation. `OutreachComposer.svelte` has one wrapping action row holding Save, Cancel, Create link, Schedule… or Change time…, Unschedule and Delete. The picker is closed until the toggle opens it, or until the card's Schedule… button opens the editor, through the new `openSchedule` prop that `OutreachPostCard.svelte` sets. A successful Schedule closes the picker and moves focus to the toggle. The API calls, Save rules and disabled conditions are unchanged, and `rows="7"` stays.

### Approach

**`OutreachComposer.svelte`**

1. Add `tick` to the `svelte` import.
2. Add a prop, documented like its neighbours: `openSchedule?: boolean`, default `false`, meaning "the card's Schedule… button opened this editor, so show the picker straight away".
3. Add the state, with the same `svelte-ignore state_referenced_locally` comment the file already uses:
   - `let scheduleOpen = $state(openSchedule);`
   - `let root = $state<HTMLDivElement | undefined>();`, bound with `bind:this={root}` on the outer `<div class="composer">`.
4. In `schedule`, after `notice = 'Scheduled.';`, add these lines. The Schedule button has just disappeared, so focus has to go somewhere:

   ```ts
   scheduleOpen = false;
   await tick();
   root?.querySelector<HTMLElement>('[data-schedule-toggle]')?.focus({ preventScroll: true });
   ```

   A failed call throws before these lines, so the picker stays open with the error showing. The early return for an empty date also leaves it open.
5. Delete both `{#if actions.canSchedule}` and `{#if actions.canUnschedule}` blocks that sit above the action row, and replace the row with:

   ```svelte
   <div class="row actions">
     {#if actions.canSave}
       <Button variant="primary" onclick={save} disabled={busy || !dirty || over}>Save</Button>
     {/if}
     <Button onclick={cancel}>Cancel</Button>
     {#if actions.canPrepare}
       <Button onclick={prepare} disabled={busy || dirty}>Create link</Button>
     {/if}
     {#if actions.canSchedule}
       <Button data-schedule-toggle aria-expanded={scheduleOpen ? 'true' : 'false'} onclick={() => (scheduleOpen = !scheduleOpen)}>{post.status === 'scheduled' ? 'Change time…' : 'Schedule…'}</Button>
     {/if}
     {#if actions.canUnschedule}
       <Button onclick={unschedule} disabled={busy}>Unschedule</Button>
     {/if}
     {#if actions.canDelete}
       <span class="danger-end"><Button variant="danger" onclick={remove} disabled={busy}>Delete</Button></span>
     {/if}
   </div>
   {#if actions.canSchedule && scheduleOpen}
     <div class="schedule">
       <label class="field">
         <span class="field-label">Schedule for (Pacific time)</span>
         <input type="datetime-local" bind:value={scheduleLocal} />
       </label>
       <Button onclick={schedule} disabled={busy || dirty || over || !scheduleLocal}>Schedule</Button>
       {#if !scheduleLocal}
         <p class="text-muted">{scheduleHint(wave.name, [wave])}</p>
       {/if}
     </div>
   {/if}
   ```

   The toggle is never disabled, because it only shows and hides the picker. Keep `scheduleLocal` as it is, so a typed date survives closing and reopening.
6. Keep the existing `Scheduled for …` line above the row, always, when the post is scheduled. It is the one statement of the time. **Do not hide it while the picker is open.** The input is filled once at mount, so after a page refresh or Schedule all it can hold an older time, and the line is what stays true.
7. Add to `<style>`:

   ```css
   .actions {
     flex-wrap: wrap;
   }
   .schedule {
     display: flex;
     flex-wrap: wrap;
     align-items: flex-end;
     gap: var(--space-2);
     margin-top: var(--space-2);
   }
   .schedule .field {
     margin-bottom: 0;
   }
   .schedule input {
     max-width: 100%;
   }
   .schedule .text-muted {
     flex-basis: 100%;
     margin: 0;
   }
   ```

8. Rewrite the header comment's action-row sentence: Save, Cancel, Create link, Schedule… or Change time…, and Unschedule sit in one row that wraps on a phone, with Delete set apart at the far end. The picker stays closed until asked for (`#0627`).

**`OutreachPostCard.svelte`**

- Add `let scheduleFirst = $state(false);`.
- Schedule… button: `onclick={() => { scheduleFirst = true; onEdit(p); }}`.
- Edit button: `onclick={() => { scheduleFirst = false; onEdit(p); }}`.
- Pass `openSchedule={scheduleFirst}` to `OutreachComposer`.

`onEdit` can wait on the discard dialog in `OutreachPostCards.svelte`. Setting the flag first still opens the right view once that dialog is confirmed, and each button sets it again on its next click, so a cancelled dialog leaves nothing stale. `OutreachAnnouncement.svelte` passes nothing, so Customize… opens with the picker closed.

**Copy.** `Change time…` is the only new visible text. `outreachCopy.guard.test.ts` bans "wave" and similar words in visible text; keep it that way in anything else added.
