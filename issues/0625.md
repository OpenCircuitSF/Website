## Description

Announcement is always expanded above two accordion rows, and any number of sections can be open at once. Reviewing one wave means scrolling past the others.

## Root cause

Announce was rendered outside the rows and always open, and Reminder and Final were independent `<details>` elements, so any number of sections could be open and nothing chose one. The board could not select a section. At narrow widths the strip's heading wrapped below the disclosure marker, which reached 82 px and exceeded the `4rem` scroll margin.

## Fix

Followed the plan with no change of design. Every section is now an `OutreachWaveRow`, which is an accordion heading holding a native button, controlled by `openWave` in `OutreachWorkshop`. `defaultOpenSection` picks the first section not fully posted, once per workshop. The board's row names and the row buttons both go through `selectSection`. Closed panels stay mounted under `hidden`, and unsaved work is stated on the row and on the board.

One small addition to the plan: the plan's test list has `reports an unsaved Customize edit and clears it on Cancel`. The composer asks before discarding a dirty edit, so the test also confirms **Discard changes**.

### Decisions already made

Apply these. Do not reopen them.

1. **Each row is an accordion button, not `<details>`.** `<details>` can always be closed by its own summary, which breaks "exactly one open". The row is the WAI-ARIA accordion pattern: `h3 > button[aria-expanded][aria-controls]`, with `aria-disabled="true"` on the open row's button because it cannot be collapsed. Activating the open row does nothing. This retires `#0622`'s "click the triangle to close".
2. **Closed panels stay mounted, using the `hidden` attribute.** That is how an unsaved edit survives: switching sections never destroys the typed text, so no discard dialog is needed. What remains is to say so: a closed row with unsaved work says it in words, on the row and on the board.
3. **"Fully posted" means every channel in `view.channels` has a post in that section with status `posted`.** Hand-posted channels count, and so does a channel with no post. If every section is fully posted, the last section opens. The default is picked once per workshop, so it never moves the screen while someone is working.
4. **Selecting always goes through one function** in `OutreachWorkshop.svelte`, from both the board and the row buttons: set the state, `await tick()`, `scrollIntoView({ block: 'start' })` on the row, then focus the row's button with `{ preventScroll: true }`. Safari has no scroll anchoring, so collapsing a long section above would otherwise leave the row off screen.
5. **The sticky element stays a direct child of the row wrapper**, and the wrapper holds the panel, so the strip pins for the panel's height and leaves with it. Keep `<Panel pinnable>` (`overflow: clip`). Put no `overflow` or `contain` on `.wave-row` or the new panel div: `#0622`'s control showed that `overflow: hidden` on an ancestor stops the pin.
6. **The copy guard reads literals in script and in attribute expressions, including `id={...}` templates.** `outreachCopy.guard.test.ts` would flag `` `outreach-wave-${x}` `` and `'[data-wave="x"]'` in code. Use the `outreach-section-` ids below, and do not query by `data-wave` from script. All new visible text says "section", never the banned word.

export function sectionRowId(name: string): string { return `outreach-section-${name}`; }

export function sectionPanelId(name: string): string { return `outreach-section-${name}-panel`; }

/** True when every channel has a post in this section and all have gone out (#0625). */
export function sectionFullyPosted(view: Pick<WorkshopOutreach, 'channels' | 'posts'>, section: string): boolean {
  return view.channels.length > 0 && view.channels.every((c) =>
    view.posts.some((p) => p.channel === c.name && p.wave === section && p.status === 'posted'));
}

/** The section open when the page loads: the first not fully posted, else the last (#0625). */
export function defaultOpenSection(view: Pick<WorkshopOutreach, 'channels' | 'waves' | 'posts'>): string {
  const first = view.waves.find((w) => !sectionFullyPosted(view, w.name));
  return first?.name ?? view.waves[view.waves.length - 1]?.name ?? '';
}
