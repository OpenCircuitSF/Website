## Description

`#0113` added `internal/db/prd_section_index_test.go`, which runs every `CLAUDE.md`
§11 row's own `sed` command against `PRD.md` and fails naming any row whose line
count disagrees. Its phase-3 review recomputed all 48 rows independently — sed,
table, and guard all agreed — and then found the gap.

**The guard's BRE→RE2 translation is one-directional.** `sedBREToGoRegex` rewrites
`\{`→`{`, which is the bug `#0113`'s implementer found and fixed in its own draft.
But the **inverse** is untranslated: a *bare* `{n,m}` is **literal in BRE and an
interval in RE2**.

Demonstrated, not argued: mutating §3.1's Extract cell to `/^#{2,3} [0-9]/` makes
real `sed` print **1,690 lines** — no terminator matches, so it runs to EOF —
against a stated 19, while `TestPRDSectionIndexParity` **passes**.

The same silent divergence applies to bare `+`, `?`, `(`, `)`, and to `\(` `\)`.
Backreferences fail loudly, which is fine. `\+ \? \|` diverge only under GNU sed,
which this repo does not use.

**Two structural divergences from `sed` as well:** `countPRDSection` stops after
the first matching range where real `sed` restarts one, and `parseSedRangeCmd`
mis-splits on an escaped `\/`.

**No current row triggers any of these** — the guard is correct on the table as it
stands. What is wrong today is the claim: the file's doc comment calls itself
"the mechanical check on the extraction commands themselves", which is more than
it does.

## Acceptance criteria

- [ ] The guard rejects any Extract cell containing an unescaped `{`, `+`, `?`, `(`, `)`, or `|` before attempting to translate it, with a message naming the row and the offending construct
- [ ] Mutating a row to `/^#{2,3} [0-9]/` fails the guard — demonstrated by mutation, since that exact case passes today
- [ ] All 48 current rows still pass unchanged
- [ ] The doc comment stops claiming to check the extraction commands themselves, and says what it does check: the arithmetic, for the BRE subset the rows actually use
- [ ] `countPRDSection`'s single-range behaviour and `parseSedRangeCmd`'s `\/` handling are either fixed or documented as deliberate limits
- [ ] `ISSUE=0218 scripts/check.sh go ./internal/...` passes with zero skips

## Notes

Reported by `#0113`'s phase-3 review under `CLAUDE.md` §9.

The cheap fix is the lint in criterion 1 — reject what cannot be translated
faithfully rather than translating it wrong. That converts a silent false pass
into a loud refusal, which is the trade this repo has made repeatedly
(`#0140`'s pipefail guard, `#0150`'s `gc` refusal, `#0117`'s port refusal).

`#0113`'s `## Review notes` carries the full divergence list and the §3.1
demonstration; it is the regression suite for criterion 2.

Note the guard is in `scripts/check.sh`'s default Go scope — `#0113`'s review
proved that by making it fail during an ordinary run rather than by reading the
package list. Keep that property.
