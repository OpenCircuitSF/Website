## Description

Brennan, 2026-10-17, on the deployed `#0568` page (workshop 6, 21 links
created, 15 posts drafted):

> It is a list of all of the links but what is it going to post? ... Tell me
> how this is supposed to be useful.

On the page, the 21-row links table fills three screens. The post text is
visible only after clicking a small grid cell labelled "Link ready" or "Ready
to post". Neither label says what will be posted or when.

- [x] **Posts list replaces the grid** on the workshop outreach page,
      `OutreachWorkshop.svelte`. There is one card per channel × wave, grouped

## Resolution

The workshop outreach page (`OutreachWorkshop.svelte`) now renders, in order:
header, a one-line summary ("N posts drafted · N scheduled · N posted ·
N clicks"; clicks only when real), the bulk actions with a one-sentence
explanation each, the posts list, a collapsed `<details>` "Tracked links (N)"
holding the existing links table, and the results link.
`OutreachPostCards.svelte` renders one card per channel x wave grouped by wave,
each with the full post text, short link, character count, one plain status
line and the actions that apply (automatic: Edit / Post now / Schedule… /
Unschedule / Retry; manual: Edit / Copy text / Mark posted; undrafted: Draft).
Edit and Schedule… open the existing `OutreachComposer` inline in the card.
Post now asks "Post this to Bluesky now?"; Mark posted also confirms.
Grouping, status wording, button rules and the summary live in
`web/src/lib/outreachCards.ts` (unit-tested). `OutreachPanel` gained an
optional `body` snippet that replaces its grid and composer; its own grid
remains for its existing tests. The "Failed" reason is a fixed string, not the
raw `last_error`. No Go or migration change.
