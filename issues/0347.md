## Description

`#0342` has now bounced **twice** on the same criterion — its sweep for stale
comments — and both bounces found the same *class* of defect: a comment
asserting, in the present tense, that some code calls `ClaimDue` when the file
containing it has zero `ClaimDue` call sites. `#0297` removed those calls; the
comments describing them did not go with them.

The tally so far is nine stale sites across two implementation passes and three
reviews, each pass finding what the last missed. The second review diagnosed
why: **every pass used the same instrument** — the criterion's keyword grep,
then a human read of each paragraph. The failure is in triage, not in the grep,
so repeating the grep repeats the miss.

That review's replacement instrument is the thing worth keeping. It parses each
Go file **twice** — once with `parser.ParseComments` for the comments, once
with mode `0` so comments never enter the AST — and then asks whether each
identifier a comment names actually appears in that file's *code*. Over 269
files, 4963 comment groups and 456 identifier hits, it found the three
remaining sites by construction rather than by judgement, and it reproduced the
site the first review had found by hand when pointed at the older snapshot.

`#0267`'s misattached-doc-comment guard family does not reach this class: these
are inline and doc comments that are attached to the right declaration and are
simply false about what that declaration does.

## Acceptance criteria

1. A Go guard test fails when a comment names `ClaimDue`, `SelectDue`,
   `OrphanSweep`, `ClaimRow`, or `ClaimBatch` in the present tense while the
   file's own code contains zero calls to it.
2. The census of what the code contains is taken from a mode-`0` parse, so
   comment text can never contribute to the population a comment is checked
   against. A comment must not be able to satisfy the check that measures it
   (§8 — a copy of the answer stored next to the question is not a check).
3. History paragraphs are allowed, via an explicit allowlist or an explicit
   past-tense/marker convention. `#0342`'s sweep confirmed that correctly
   framed historical references are common and legitimate — the guard must not
   force their removal. State the convention it recognises.
4. The guard is proved falsifiable: pointed at the `ffef8cf` snapshot (or an
   equivalent reconstruction) it flags `outbox_worker_test.go:746`'s
   `OutboxWorker.ClaimDue`, and against the fixed tree it does not.
5. It fails closed on empty input and on a zero-hit census — §8 records a
   fail-open that arose in exactly that way, where an extraction contributing
   nothing was read as agreement.
6. **The guard belongs in Go, not in an external shell harness.** Per §8's
   rule, the deciding question is whether the mutation leaves the assertion
   falsifiable by the thing it measures: adding a false comment changes what
   the scan finds, so the in-package test is a legitimate, non-circular oracle.
   Record that reasoning in the guard's doc comment.
7. No `.ClaimDue(` / `.OrphanSweep(` / `.SelectDue(` call-syntax literal is
   introduced into any Go comment — `scripts/go_file_visit_floor_guard_test.sh`
   greps for that syntax and comment text containing it inflates the population
   it measures. Re-run that harness and record the population (currently 42).
