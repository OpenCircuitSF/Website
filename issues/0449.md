## Description

`TestRouteTableParity_StaticRoutes` (`internal/handlers`, from `#0071`) reads
`web/src/lib/router.ts` as text and extracts its route table with a regex whose
literal anchor is the declaration's own spelling.

Since `#0440`, **`router.ts` contains that exact text twice** — once in the new
doc comment and once in the declaration — and the regex matches the comment
first. Measured with `python3` over raw bytes by `#0440`'s reviewer.

This is `CLAUDE.md` §8's recorded "a regex that hunts for a tag finds the one
inside a comment" shape, live in this repo for the first time since `#0064` hit
it in `web/index.html`.

## Why it is not currently a defect, and why that is not reassuring

The match still yields the right fifteen entries, for a reason nobody chose:
the pattern's `[^=]*` cannot cross an `=`, so the capture falls forward to the
declaration's own `= {`. `#0440`'s reviewer probed four variants in a throwaway
worktree:

| Probe | Result |
|---|---|
| control | PASS |
| `=` added to the doc comment | PASS — falls forward to the real declaration |
| `= {` added to the doc comment | **FAIL loudly** — a parse error, not a silent partial parse |
| regex re-anchored to `(?sm)^const` | **FAIL loudly** |

So the guard **cannot be silently disabled** by this — `#0071`'s per-line
strictness turns any wrong path into a loud failure. But nothing pins the
property that makes it safe, and the anchored variant would reject the file
outright. The `export` keyword `#0440` added survived for the same unpinned
reason: the pattern happens to match a substring rather than a line.

**A guard that works by luck is a guard nobody can safely edit.** The next
person to tighten that regex, or to write another sentence in that doc comment,
has no way to know which change is fatal.

## Acceptance criteria

1. Assert `staticRoutesBlockRe` matches **exactly once** in `router.ts`. That
   single assertion names the doc-comment occurrence and removes the luck.
2. Fail with a message that says what to do — the fix is to reword the comment
   or anchor the pattern, and the reader will not infer that from a count.
3. **One assertion, no redesign.** Do not re-anchor the regex and add the count
   check; do not rewrite `#0071`'s parser. `CLAUDE.md` §8 records `#0258`
   spending six passes stacking mechanisms, each addition buying a bounce.
   `#0440`'s reviewer reported this as a follow-up precisely because folding it
   in would have been new mechanism inside a passing issue.
4. Prove it by mutation: add a second occurrence to a **copy** of `router.ts`,
   confirm the assertion fails naming it, restore, and prove the restore by
   hash. Never `git stash` or `git checkout --` (§8a).
5. Decide whether the same one-match pin belongs on any sibling text-scraping
   guard, and record the answer. Do **not** build them speculatively — name them
   and stop.

### The oracle question, re-measured rather than taken on trust

The implementer's central claim is that counting `staticRoutesBlockRe`'s own
matches would have measured nothing. Verified here twice, independently of the
work log — once with `python3` over raw bytes, once with a standalone program
using Go's own `regexp` package, so the answer comes from the RE2 engine the
test actually runs on and not from a Python approximation of it:

| `web/src/lib/router.ts` | `strings.Count` of `const STATIC_ROUTES:` | `len(staticRoutesBlockRe.FindAllString(src, -1))` |
|---|---|---|
| as `#0440` left it (the file this issue is about) | **2** — offsets 2825 and 2916 | **1** — one match, starting at 2825, capture group byte-identical to the correct one |
| as `#0449` leaves it | **1** — offset 2996 | **1** — one match, starting at 2996, same 425-byte capture |

So a `len(FindAllString(...)) != 1` assertion — criterion 1's most literal
reading — is **green in both rows**, and would have shipped a guard that cannot
distinguish the defect from the fix. The reason is structural, not incidental:
the match beginning at the doc comment's occurrence *swallows* the declaration's
occurrence, so the two candidate starts can never yield two non-overlapping
matches for `FindAll` to count. Counting the literal anchor is the only place
the ambiguity is observable at all. The implementer chose correctly, and said so
before writing the test rather than after.

### The oracle is not the same bytes as its subject

`CLAUDE.md` §8's rule is that an edit to the subject must not also satisfy the
oracle. Here the subject is `web/src/lib/router.ts` and the oracle —
`staticRoutesBlockAnchorText` — lives in
`internal/handlers/routes_parity_test.go`, a **different file**. No edit to
`router.ts` can rewrite it. This is the `#0258` `run()`-heredoc failure avoided
by construction rather than by care.

The failure **direction** on a rename was the thing worth checking, and it is
right. Renaming `STATIC_ROUTES` in `router.ts` alone drives the count to **0**,
and the assertion is `n != 1`, not `n > 1` — so it fails loudly rather than
passing vacuously. Measured, not reasoned about (mutation B below). Drift
between the const and the regex is caught in both directions for the same
reason: change the const alone and the count goes to 0;
change the regex alone and `TestRouteTableParity_StaticRoutes` fails.

### Criterion 3 — nothing was re-anchored, no second mechanism landed

`git show --numstat` on the code commit reads `42 0` for
`internal/handlers/routes_parity_test.go` — **forty-two insertions and zero
deletions**, which by itself forecloses any edit to existing code in that file.
Confirmed line-by-line that `staticRoutesBlockRe`, `staticRoutesEntryRe` and

### Doing both the assertion and the reword is coherent

They are one change, not two. The assertion is a **pin**, and a pin asserts a
property the file must already have; criterion 1 requires that property to be
false against `router.ts` as `#0440` left it, so a green tree requires the
reword. The alternative — weakening the assertion until the unmodified file
passes — is precisely the guard-that-proves-nothing this issue exists to
prevent.

The reworded comment still carries every fact it needs to: that the file is read
as *source text* rather than imported, which Go test file reads it, which
pattern in it, what that pattern anchors on (the declaration's own `const`
keyword, name, and colon), that the anchor is deliberately not spelled out and
why, and that the `export` keyword preceding it is harmless. Naming the shape
instead of writing it is the same move `CLAUDE.md` §8 records for `#0384` and
`#0347`, applied to a non-citation guard for the first time.
