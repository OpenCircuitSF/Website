## Description

A full pass over the public flows: keyboard, screen reader, contrast, and motion.

## Acceptance criteria

- [ ] Every public page keyboard-navigable end to end with a visible focus ring throughout
- [ ] Signup, confirm, preference-center, and unsubscribe flows verified with VoiceOver
- [ ] Contrast measured against WCAG 2.1 AA for all text **in both light and dark**; non-text UI meets 3:1
- [ ] Theme toggle is keyboard operable and announces its state
- [ ] No information conveyed by color alone
- [ ] All motion respects `prefers-reduced-motion`
- [ ] Form errors announced and programmatically associated with their fields
- [ ] Heading hierarchy correct on every page; one `<h1>` each
- [ ] Landmarks present; skip-to-content link works
- [ ] Findings that cannot be fixed in this pass are filed as their own issues and cross-linked

## Notes

PRD §7.5. The four flows named above are the ones a non-sighted user must be able to complete unaided — everything else on the site is content, but these are transactions.

Contrast needs measuring, not eyeballing, and every pair has to be checked in **both** themes — the site is no longer dark-only. PRD §4.2 carries the measured baseline; this audit re-verifies it against what actually shipped.
