## Description

`CancelQueuedTx` (added by `#0313`) marks a superseded `KindImportInvite` row
**`abandoned`** when an invited person self-signs-up. That is correct behaviour
recorded in the wrong terminal state.

`#0365`'s planning pass measured why `abandoned` is not neutral in this codebase
— it is a **delivery-health signal with three live readers**, none of which
reads the `error` column `CancelQueuedTx` relies on as a disambiguator:

1. `admin_dashboard.go:357` → `AbandonedCountByKind(KindConfirmation)` →
   `abandoned_confirmations`, documented in `types.ts:654` as "how many pending
   signups never got a confirmation **delivered**".
2. `admin_dashboard.go:370` → `counts.Abandoned > 0` raises the
   `outbound-queue-abandoned` dashboard warning. **Abandoned rows are terminal
   and nothing clears them**, so one correctly-cancelled invite raises a
   permanent, never-clearing alarm.
3. `pending.ts:64` → `abandoned` is the sole `badge-danger` state, its comment
   calling it "the one state that actually explains a non-confirmation as a
   delivery failure".

So an admin sees a red **delivery failure** against a row the system correctly
cancelled, and it never goes away.

**This is a behaviour change to resolved code** (`#0313`), which is why it is
filed rather than folded into `#0365`.

## Depends on `#0365`

`#0365`'s plan introduces **`skipped`** as a new terminal status via migration
`000027`, chosen for exactly this class of "correctly withheld, not failed"
outcome, and mirroring `email_sends`' existing `MarkSkippedTx` /
`RecheckEligibleTx` pair. **Land `#0365` first**; this issue is then a one-line
change of terminal state plus its tests.

Do not introduce a second new status for this.

## Acceptance criteria

1. `CancelQueuedTx` marks the superseded row `skipped`, not `abandoned`, with a
   reason recorded the way `#0365` establishes.
2. The dashboard no longer raises `outbound-queue-abandoned` for a cancelled
   invite. **Prove it**: seed the self-signup-after-invite path, drain, and
   assert the warning is absent — and prove the test fails against unmodified
   code first.
3. `abandoned_confirmations` and the `badge-danger` state keep their current
   meaning for genuine delivery failures. Confirm no existing test that asserts
   an `abandoned` outcome for a real failure now sees `skipped`.
4. Re-verify the three readers yourself rather than trusting this issue — five
   issues this phase received a wrong identifier because prose was transcribed
   as though measured, two of them in issues the orchestrator wrote.
5. Per §5 name the specific tests that ran; the mailing subsystem needs
   Postgres (`STORAGE=json` implements none of it). §8b: mutations use your own
   database and never target a literal or seeded id.
