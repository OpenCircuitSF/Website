## Description

`#0132` and `#0215` between them fixed the settings-seed duplication and the
`registrations_enabled` leak. Both are resolved. Three small items were
deliberately deferred along the way and now exist **only** in the review notes of
closed issues — which is where good intentions go to die.

**1. `setRegistrationsEnabled`'s restore stamps `now()` instead of preserving the
prior `updated_at`.** `#0215`'s review measured it: writing back an unchanged
value still bumps the timestamp, so the full-row hash moves
(`555f2c3c…` → `fbac46c8…`) on exactly that field. Criterion 3's
"byte-identical" therefore holds on `(key, value)` only.

Judged acceptable and not a bounce, for three reasons worth preserving: nothing
in the tree reads an *absolute* `settings.updated_at` (the only consumer,
`internal/handlers/settings_test.go`'s `settingUpdatedAt`, is used relatively),
the pre-fix helper bumped it too, and `#0130` set the `(key, value)` precedent.
Preserving the prior timestamp alongside the prior value closes it cheaply.

**2. Two `internal/handlers` hardenings from `#0132`'s review**, declined by
`#0215` as out of scope — correctly, since taking them would have widened an
`internal/auth`-only diff into a package where `#0120`'s review was concurrently
active:

- `settings_test.go`'s seed regex could anchor as `^[ \t]*INSERT`, closing a silent false negative on an indented statement, for two characters.
- `settingsMigrationsDir`'s global-var swap is safe **only** because `internal/handlers` has zero `t.Parallel()` calls. A note there would stop the next person adding one.

**3. The same `t.Parallel()` caveat applies one package over.** `#0215`'s
review verified the helper's read-then-write is safe because
`internal/testdb.Lock()` serialises packages **and** `internal/auth` has zero
`t.Parallel()` calls — but a single added `t.Parallel()` reopens the window. That
is currently written down nowhere near the code it constrains.

## Implementation notes

**1. `setRegistrationsEnabled`'s restore now preserves `updated_at`.**
`internal/auth/registration_test.go`'s helper used to `SELECT value` only and
restore with `updated_at = now()`; it now `SELECT`s `value, updated_at` and
restores with `updated_at = EXCLUDED.updated_at` (the actual prior
timestamp), so a write-back of an unchanged value moves nothing on the row.
Added a doc-comment paragraph explaining why (mirrors #0215's review finding)
and that nothing in the tree reads an absolute `settings.updated_at`.

**2. Two new tests in `internal/auth/registration_test.go`:**
`TestSetRegistrationsEnabled_RestoreIsByteIdenticalOnTheWholeRow` seeds a
known row directly (bypassing the helper, so the baseline doesn't depend on
it), calls the helper inside a subtest so its `t.Cleanup` fires before the
outer test resumes, and compares `(value, updated_at, present)` before and
after. `TestSetRegistrationsEnabled_NeverExistedRowStaysAbsent` re-proves
`#0215`'s probes E and F against the updated helper: deletes the row,
confirms the helper's `t.Cleanup` re-deletes it rather than resurrecting a
default.

**A real leak surfaced and was fixed while proving criterion 7's second
half.** Both new tests initially left `registrations_enabled` in the wrong
state for whichever test in the package ran next — exactly the defect class
this issue exists to close, just one level up: they overwrote or deleted the
package's baseline row and then unconditionally deleted it in `t.Cleanup`
instead of restoring the baseline they found on entry. Caught by running
`go test ./internal/auth/... -count=1` alone and hashing `settings` before
and after — the row was **entirely absent** afterward, not merely
timestamp-drifted. Fixed by having both tests snapshot the baseline row with
`readSettingsRow` before mutating and restoring it explicitly in their own
`t.Cleanup`, the same shape as the helper under test.

**3. `internal/handlers/settings_test.go`'s seed regex.**
`settingsSeedStmtRe` changed from `^INSERT INTO settings\b.*?;` to
`^[ \t]*INSERT INTO settings\b.*?;`, so an indented statement (inside a `DO`
block, or a differently-styled migration file) still matches.
`settingsSeedStatements` would otherwise silently drop it — it only
`t.Fatalf`s when it finds *zero* statements across every file, not when it
misses one inside a file that has others. Added
`TestSettingsSeedStmtRe_MatchesIndentedInsert`, a plain regex-match unit
test (no live database) asserting an indented `INSERT INTO settings` matches.

**4. `t.Parallel()` safety notes.** Both `settingsMigrationsDir`
(`internal/handlers/settings_test.go`) and `setRegistrationsEnabled`
(`internal/auth/registration_test.go`) now carry a doc-comment paragraph
stating their safety depends on their package having zero `t.Parallel()`
calls, and that adding one would reopen the window. Confirmed
`grep -rn 't.Parallel()' internal/handlers internal/auth` returns nothing in
either package.

Two facts from `#0215`'s review worth having while working here:

- The "seven call sites" in `#0215`'s description is the count in `registration_test.go` alone. There are **30 across six files**; fixing the helper covered all thirty.
- `t.Cleanup`'s LIFO unwinding is what makes repeated helper calls in one test safe — the first call's snapshot restores last, so the original value wins. That is a property of the ordering, not of the helper, and it is easy to break.
