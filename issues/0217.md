## Description

`#0132` and `#0215` between them fixed the settings-seed duplication and the
`registrations_enabled` leak. Both are resolved. Three small items were
deliberately deferred along the way and now exist **only** in the review notes of
closed issues — which is where good intentions go to die.

**1. `setRegistrationsEnabled`'s restore stamps `now()` instead of preserving the
prior `updated_at`.** `#0215`'s review measured it: writing back an unchanged
value still bumps the timestamp, so the full-row hash moves
(`555f2c3c…` → `fbac46c8…`) on exactly that field. Criterion 3's
"byte-identical" therefore holds on `(key, value)` only.

Judged acceptable and not a bounce, for three reasons worth preserving: nothing
in the tree reads an *absolute* `settings.updated_at` (the only consumer,
`internal/handlers/settings_test.go`'s `settingUpdatedAt`, is used relatively),
the pre-fix helper bumped it too, and `#0130` set the `(key, value)` precedent.
Preserving the prior timestamp alongside the prior value closes it cheaply.

**2. Two `internal/handlers` hardenings from `#0132`'s review**, declined by
`#0215` as out of scope — correctly, since taking them would have widened an
`internal/auth`-only diff into a package where `#0120`'s review was concurrently
active:

- `settings_test.go`'s seed regex could anchor as `^[ \t]*INSERT`, closing a silent false negative on an indented statement, for two characters.
- `settingsMigrationsDir`'s global-var swap is safe **only** because `internal/handlers` has zero `t.Parallel()` calls. A note there would stop the next person adding one.

**3. The same `t.Parallel()` caveat applies one package over.** `#0215`'s
review verified the helper's read-then-write is safe because
`internal/testdb.Lock()` serialises packages **and** `internal/auth` has zero
`t.Parallel()` calls — but a single added `t.Parallel()` reopens the window. That
is currently written down nowhere near the code it constrains.

## Acceptance criteria

- [ ] `setRegistrationsEnabled`'s cleanup restores the prior `updated_at` along with the prior value, so a restore is byte-identical on the whole row
- [ ] A test proves it: hash the full row before and after a helper call that writes back the same value, and confirm no field moved
- [ ] The never-existed-row case still deletes rather than resurrecting a default — `#0215`'s probes E and F
- [ ] `internal/handlers/settings_test.go`'s seed regex anchors leading whitespace, with a test for an indented `INSERT`
- [ ] Both `settingsMigrationsDir` and `setRegistrationsEnabled` carry a note that their safety depends on the package having no `t.Parallel()`
- [ ] `#0215`'s four probes (fail, skip, panic, restore) and `#0132`'s regex probes still hold
- [ ] `ISSUE=0217 scripts/check.sh go ./internal/...` passes with zero skips, and `settings` matches the template after `go test ./internal/auth/` **alone** with `-count=1`

## Notes

Reported by `#0215`'s phase-3 review under `CLAUDE.md` §9.

None of this is urgent — every item was judged acceptable by a reviewer who had
measured it. The reason to file rather than drop: `#0132` and `#0215` are both
resolved, so these would otherwise survive only in two sets of review notes that
nobody has a reason to open again.

Two facts from `#0215`'s review worth having while working here:

- The "seven call sites" in `#0215`'s description is the count in `registration_test.go` alone. There are **30 across six files**; fixing the helper covered all thirty.
- `t.Cleanup`'s LIFO unwinding is what makes repeated helper calls in one test safe — the first call's snapshot restores last, so the original value wins. That is a property of the ordering, not of the helper, and it is easy to break.
