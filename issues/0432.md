## Description

`docs/media.md` (added 2026-09-04) documents the intended workflow: workshop
covers live on disk at `/var/www/media`, served by an Apache carve-out at
`/media/`, so adding a photo needs no rebuild and does not grow the binary.

**The repo has not caught up.** Four small things still point at the old
embedded path, and one of them will quietly cause the next workshop to repeat
the mistake.

### The old path, for context

Both live images sat in `web/public/`, which `npm run build` sweeps into
`web/dist/`, which `//go:embed all:dist` compiles **into the binary**. Confirmed:
`grep -c programming_leds /usr/local/bin/opencircuit` → 1. Apache's wildcard
proxied the request to the Go service, which served it from memory. Every image
cost a rebuild and permanent binary size — exactly what `/media/` exists to
avoid.

The user has since copied both to `/var/www/media` and verified
`/media/programming_leds.jpg` serves with the documented `max-age=604800` and
the sandboxing CSP.

## What needs doing

1. **The `.gitignore` rule is premised on the wrong location.** `/web/public/*.jpg`
   and `*.jpeg` were added on 2026-09-04 (`43f4ee4`) when workshop photos were
   thought to belong in `web/public/`. Under `docs/media.md` **nothing** belongs
   there — the directory holds 23 tracked design assets and nothing else. Remove
   the rule or replace it with a comment pointing at `docs/media.md`, so it stops
   silently permitting the old workflow.

2. **The admin editor gives no hint.** `WorkshopEditor.svelte`'s label reads
   *"Cover image (site-relative path)"*. Nothing tells an operator the path
   should start `/media/`. **This is the one that matters** — it is where the
   next workshop's path gets typed. A placeholder or hint naming the convention
   is enough; do not add validation, since `isSafeCoverImage` deliberately
   accepts any same-site path and `docs/media.md` explains why.

3. **`docs/media.md` says "The directory is currently empty (checked
   2026-09-04)."** No longer true. Update it, and consider whether that sentence
   should be dated-and-kept or simply corrected.

4. **`migrations/000020`'s `cover_image` comment says `-- path under /assets`.**
   Wrong twice: the path is under `/media`, and `/assets/` is Vite's embedded
   build output — `docs/media.md` explains that excluding `/assets/` from the
   proxy would cut the SPA off from its own JS. **`000020` is frozen** (§1 —
   applied to production long before the current bound), so **do not edit it**.
   Record the correction where a reader will meet it instead, and say where you
   chose and why.

## Not in scope

- **The database rows.** The user is updating `cover_image` to `/media/…`
  themselves.
- **Removing the two files from `/opt/opencircuit/web/public/` on the box.**
  Until that happens the next rebuild re-embeds them; it is a one-line server
  action and the user's to make. **Mention it in your report** so it is not
  forgotten, but do not do it.
- `#0417`'s dimensions and EXIF — still open, still server-side.

## Acceptance criteria

1. Nothing in the repo implies workshop covers belong in `web/public/`.
2. An operator adding a workshop is told the `/media/` convention **at the point
   they type the path**, not only in a document.
3. `docs/media.md` matches reality.
4. The `000020` comment's error is recorded without editing the frozen
   migration.
5. **No mechanism** (`#0330`/`#0347`/`#0356`/`#0381`) — and specifically no
   client-side path validation, which would contradict `isSafeCoverImage`'s
   deliberate breadth.
6. `(cd web && npm run check)` and `(cd web && npm test)`. Run
   `./internal/handlers/...` if any Go comment or cited path changes, and
   `./internal/db/...` for the issue-file edit. Per §5 name the specific tests
   that ran — real function names, not a `-run` prefix. No
   Go-file-plus-line-number citation (`#0352`), scanned with `python3` bytes.
