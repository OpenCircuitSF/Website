## Description

`outbox.Store.Counts` builds five `count(*) FILTER (WHERE status = $n)` columns
from one positional argument list. **Swapping `StatusQueued` and `StatusSent` in
that list** — so `Counts.Queued` reports sent rows and `Counts.Sent` reports
queued rows — leaves the **entire `internal/outbox` package green.** Measured by
`#0382`/`#0386`'s reviewer on a throwaway export with its own scratch database.

`#0386`'s fixed `TestOutbox_Counts` asserts `after.Queued == before.Queued+1`
and `after.Sent == before.Sent+1` around one row moved into each state — and **a
symmetric relabelling satisfies both deltas identically.**

**Pre-existing, not a regression from `#0386`.** The old `>= 1` / `>= 1` pair was
equally blind. `#0386` made the test **strictly stronger** — it now kills three
of four `Counts` mutants including all-zeros, and the dropped-`FILTER` mutant it
catches satisfied the old floor. This is the one mutant that survives.

**It is `#0364`'s finding one layer up**: the deltas are individually sound but
**jointly unable to tell the two labels apart**. Each assertion passes for a
reason that does not distinguish the thing it names.

## The fix the reviewer measured

A **single asymmetric assertion**: after enqueuing the queued row but **before**
claiming and sending the other, assert

```
mid.Queued == before.Queued+2 && mid.Sent == before.Sent
```

No swap can satisfy that — the asymmetry is what breaks the symmetry the
relabelling exploits.

## Root cause

`TestOutbox_Counts`'s two after-deltas (`Queued` +1, `Sent` +1) are each
individually sound, but a `Counts` that swaps which SQL argument position
feeds `Queued` and which feeds `Sent` satisfies both deltas identically — the
two assertions are symmetric, and the mutation is a symmetric relabelling.
Nothing in the test measured a moment where the two columns would have to
move by different amounts.

## Fix

Added a mid-point `Counts()` call in `TestOutbox_Counts`, taken after both
rows are enqueued but **before** either is claimed or sent. At that instant
this test has added two rows to `Queued` and zero to `Sent`, so the added
assertion (`mid.Queued == before.Queued+2 && mid.Sent == before.Sent`) is
asymmetric by construction — this is exactly the fix the issue's reviewer
measured. No relabelling of the two columns can satisfy it under either
label, because the mutation cannot manufacture the +2/+0 split the real
query produces at that moment. The existing before/after +1/+1 deltas were
left in place unweakened (criterion 4): the mid-point check is additive.

**Criterion 3 — `Abandoned`/`Skipped` measured, not reasoned about.** Built
the same swap mutation for `StatusAbandoned`/`StatusSkipped` (swapping which
argument position feeds which field) and ran it against both the pre-fix and
post-fix package. In both cases `TestOutbox_Counts` itself passes (it never
touches those two fields), but
`TestOutbox_Counts_ReportsSkippedDistinctlyFromAbandoned` fails identically
before and after this change:

```
store_test.go: Skipped = 0, want 1 (before 0 + the one row just skipped)
store_test.go: Abandoned moved from 0 to 1 after a MarkSkipped call — a skip must never count as a delivery-health failure
```

That test already asserts the same asymmetric shape this issue's fix adds
for `Queued`/`Sent` (`Skipped` +1, `Abandoned` unchanged, around one row
moved into `skipped`), so the `Abandoned`/`Skipped` swap does **not** pass
the whole package today, and this fix did not need to touch it — no gap was
open there to begin with, so none needed closing.

**An accidental self-inflicted mutation, caught and reverted.** Mid-task, a
`sed` mutation intended for a scratch `git archive` export instead landed on
the tracked `internal/outbox/store.go` (a `cd` chaining mistake), swapping
`StatusQueued`/`StatusSent` in the real file for a few minutes. Caught by a
surprising run-alone failure against what should have been unmutated code;
confirmed with `git diff -- internal/outbox/store.go` against `HEAD`, and
reverted directly (permitted under CLAUDE.md §8a — it was my own edit this
session, never committed). Re-confirmed `store.go` byte-identical to `HEAD`
before any further verification or the eventual commit, which touches only
`internal/outbox/store_test.go`.
