## Description

One authored Markdown source produces both the HTML part and the plain-text alternative, with per-recipient token substitution.

## Acceptance criteria

- [ ] Markdown rendered to HTML with a vetted library; raw HTML in the source is escaped, not passed through
- [ ] A plain-text alternative generated from the same source — links rendered as `text <url>`, not dropped
- [ ] Per-recipient substitution of the manage token into footer links
- [ ] The physical mailing address is appended to both parts
- [ ] Rendering is deterministic and covered by golden-file tests
- [ ] Substitution failures (missing token) are hard errors, not silently empty links

## Notes

PRD §6.6. Passing raw HTML through from Markdown is an injection path into every recipient's inbox — escape it.

The plain-text part must be genuinely readable, not HTML with the tags stripped. Links in particular have to survive as visible URLs or the text part is worse than useless.

A missing token producing an empty `href` means an unsubscribe link that silently does nothing — which is a compliance failure, not a cosmetic bug. Fail loudly.
