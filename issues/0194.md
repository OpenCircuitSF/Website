## Description

`#0187`'s phase-3 review found two robustness problems with the guard, distinct
from its pattern text.

**1. Adding `web/` to the walk made `filepath.WalkDir` descend into
`web/node_modules` and `web/dist`.** There is no `.go` under either today. But
an npm dependency shipping Go source would be parsed by the guard, and **a parse
failure there is a `t.Fatalf`** — so a routine dependency bump could take the
guard down, with a failure pointing at a vendored file nobody in this project
wrote. A two-line `SkipDir` closes it.

This is a consequence of `#0187`'s otherwise-correct widening, not an argument
against it.

**2. The shape matrix should be committed, not re-derived.** Three passes have
now each rebuilt, run, and **deleted** the same 20–34 case matrix proving the
guard catches the Svelte expression forms and misses the acceptable ones:
`#0181`'s pass-2 review, `#0187`'s implementation, and `#0187`'s review.

The evidence for the guard's most contested property therefore exists only as
prose in three sets of review notes, and each pass pays to reconstruct it. That
is the opposite of what a regression test is for. `#0187`'s review ran 34 cases
against the shipped code by temporarily re-exporting `scanSvelteSource`,
`scanTsSource`, and `citationPattern` — that harness is most of the work
already.

## Acceptance criteria

- [x] The Go walk skips `web/node_modules` and `web/dist` (and any other vendored directory under a scanned root)
- [x] A dependency shipping a `.go` file under `web/node_modules` does not fail the guard — demonstrated, not assumed
- [x] The shape matrix is committed as a real test, running against the shipped `scanSvelteSource`/`scanTsSource`/`citationPattern` rather than a replica
- [x] The committed matrix covers what `#0187`'s review ran: 4 bounce forms, 12 further Svelte shapes, 5 structural misses, 7 acceptable misses, 6 boundary checks
- [x] Each acceptable miss carries a one-line note on **why** it is acceptable, so a future pass can tell a deliberate miss from a regression
- [x] `ISSUE=0194 scripts/check.sh go ./internal/...` and `scripts/check.sh web` both pass

## Implementation notes

**Part 1 — vendored directories skipped in the Go walk.** `#0187`'s
`"../../web"` root makes `filepath.WalkDir` descend into `web/node_modules`
and `web/dist`. Added `skipVendoredDirNames` (`node_modules`, `dist`) to
`internal/handlers/citation_guard_test.go`; the walk callback returns
`fs.SkipDir` (via `filepath.SkipDir`) when it enters a directory whose exact
name is in that set — checked by name, not by path prefix, so it applies
under any of the three `scanGoRoots` entries, not only `web/`.

Proved by execution, not by reading:
1. Placed a `.go` file under `web/node_modules/.probe-0194/` containing a
   live `PRD §6.6` citation (the same shape `TestCitationScanCatchesDocCitation`
   proves the guard catches elsewhere). Ran
   `TestNoAdminFacingStringCitesInternalDocs` — **PASS**, confirming the skip
   is live.
2. With the skip disabled (map temporarily emptied, restored byte-identical
   afterward — `diff` confirmed), re-ran the same test with the same
   vendored probe still in place — **FAIL**, reporting the probe file's
   citation. This proves the hazard `#0194` describes was real: before this
   fix, a `.go` file under `web/node_modules` genuinely takes the guard
   down (or, for a citation-shaped string instead of a parse error, makes
   it fail pointing at a file nobody in this project wrote).
3. Placed the identical citing file one directory up, directly under `web/`
   (not vendored) — **FAIL**, confirming the skip is scoped to the vendored
   directory and does not swallow `web/` itself.
4. Removed the vendored probe; guard back to **PASS**.
5. File-count invariant re-measured with the skip active: a scratch probe
   (added, run, deleted) reusing the shipped `scanGoRoots` and walk
   predicate verbatim (skip included) collected **95** files, against **95**
   from `find internal cmd web -name '*.go' ! -name '*_test.go'` — the same
   95/95 `#0187` measured, confirming the skip drops nothing real (neither
   `web/node_modules` nor `web/dist` contains a `.go` file today, so there
   was nothing to lose).

**Part 2 — the 34-case shape matrix, committed.** Added a `MATRIX` table and
a category-count test to `web/src/lib/citationGuard.test.ts`, dispatched
through `runMatrixCase` to the file's own shipped `scanSvelteSource`,
`scanTsSource`, and `citationPattern` — the exact exports the guard itself
uses, not a re-export or a reproduction. Since the matrix, the scanners, and
the pattern all now live in the same file, "re-export to test the shipped
code" (what `#0187`'s review had to do in a throwaway probe) is no longer
necessary — the matrix simply calls the functions already in scope.

Case counts, matching `#0187`'s phase-3 review exactly (34 total):
- **4 bounce forms** — the shapes `#0181`'s original bounce named: `{'...'}`,
  a ternary, a template literal, `{@html '...'}`.
- **12 further Svelte shapes** — object literal in a prop, array in a prop,
  attribute expression, `{#if}` test expression, `{#if}/{:else}`,
  `{#each}`, `{@const}`, snippet body text, snippet body expression,
  `{@render}` argument, `{#await}...then`, call argument.
- **5 structural misses** — JS comment inside an expression tag, `<style>`
  block, HTML comment in markup, `CAN-SPAM §7704` in an expression, the
  `EMAIL_REPLY_TO`/`EMAIL_LIST_DOMAIN` env var names in an expression.
- **7 acceptable misses**, each with a one-line `note` field: two split
  string concatenations (`CLAUDE` + `.md §9`, `#0` + `138`), a template
  literal interpolation that splits `PRD` from `§` across separate
  `TemplateHead`/`TemplateTail` nodes, an unpadded issue number (`#138`),
  a lowercase `claude.md` case variant, and two prose forms (`docs` used
  as a plain word, and `docs.google.com`).
- **6 boundary checks** — `PRD` with two spaces, `PRD` with no space (both
  catch), a hex color containing `#041` as a substring (misses), a genuine
  `#0181` reference and an `issues/0138.md` path (both catch), and ordinary
  prose containing the word "issues" (misses).

A `MATRIX_COUNTS` test asserts the table has exactly 4/12/5/7/6 cases so a
future edit that silently drops or duplicates a case fails loudly instead of
just shrinking the total. A second test asserts every `acceptable-miss` case
has a non-empty `note`.

**Self-reference check.** The matrix's fixtures are citation-shaped by
construction (proving a catch requires writing a string that looks exactly
like the thing the guard must reject). This is safe because
`citationGuard.test.ts` is itself a `.test.ts` file, and the guard's own
`SOURCE_FILES` scan (the "no source file contains an admin-facing string…"
test) explicitly skips any path ending `.test.ts` — the same structural
exclusion the Go side gets from skipping `_test.go`. Confirmed rather than
assumed: ran the full web guard test with the new matrix in the file, and
it stayed green (see `## Verification`). Also ran the Go guard
(`TestNoAdminFacingStringCitesInternalDocs`) after committing — also green,
since none of the new content is Go source and the file it lives in is
itself excluded by the `_test.go` predicate.

**Also folded in — `toRepoRelativePath`'s bare-key bug.** The `else` branch
did `` `lib/${globKey.slice(2)}` ``, which assumed every non-`"../"` key had
a two-character `"./"` prefix to strip. Vite emits none today (`#0187`
measured 83/83 keys as exactly `"../"` or `"./"`), but a bare key would have
had two real filename characters sliced off rather than being reported
as-is. Rewrote as an explicit `"./"` check with a fallback that treats a
prefix-less key as already relative to `web/src/lib/` (matching what `"./"`
means) instead of slicing blind. Added three direct tests for
`toRepoRelativePath` (`"../"` key, `"./"` key, bare key).
