## Description

`#0216`'s phase-3 review bounced it for shipping **three new false statements** —
in the issue whose entire purpose was removing false statements. The sharpest:

> the new text asserts "CLAUDE.md has no section specifically on jsdom's fidelity
> to a real browser". §1's bullet is headed literally **"jsdom is not a
> browser."** and landed **nineteen minutes earlier**.

The reviewer's judgement is worth preserving: *an unfilled ellipsis is
self-advertising; a confident false claim about the repo's binding guidance is
not.* The "fix" was worse than the defect.

**This is the fifth instance of the class** — `#0190`, `#0192`, `#0196`,
`#0199`, and now `#0216` itself. `#0196` built a guard for it that walks Go
comments and fails when one cites a `Test*` identifier no function defines. It
does not cover TypeScript, and it does not cover cited **paths** or
**`CLAUDE.md §N`** references in any language.

A guard resolving those against the tree would have caught **three of `#0216`'s
five defects mechanically**, including the one its own fix introduced.

**A second gap, from the same review.** `tabindex="-1"` on the modal panels is
unguarded. Without it `focus()` is a silent no-op — so the handler-host ===
focus-target equivalence `#0216`'s new guard proves would still not make Escape
work. All 11 sites carry it today; nothing asserts they keep it. The review
estimates two lines inside the guard's existing per-panel walk.

## Implementation notes

Ported `#0196`'s design (`internal/handlers/dangling_test_citation_guard_test.go`)
rather than inventing a second one, for two more citation shapes: a
repository PATH, and a `CLAUDE.md §N` section reference. Both are resolved
against their own ground truth (files actually on disk; `CLAUDE.md`'s own
numbered `## N. ` / `## Na. ` headings, read fresh off disk every run so the
guard tracks the file rather than a hardcoded list) instead of a fixed
allowlist.

**Two files, one design, mirrored, not shared.** Go comments
(`internal/handlers/citation_target_guard_test.go`) reuse `#0196`'s own
`citedTestScanRoots`/`walkGoFiles`/`stripCommentMarkers`/`toRepoRelativePath`
helpers directly (same package, both source files clean in git status when
this started, so none of `#0196`'s concurrent-edit caution applied).
TypeScript/Svelte comments (`web/src/lib/citationTargetGuard.test.ts`) are a
separate implementation in a separate language and engine (V8 regex vs
RE2), following `#0198`'s own precedent for the sibling admin-facing-string
guard: mirrored reasoning, not shared code.

**Comment extraction, the actual new work for the TS/Svelte half.**
TypeScript has no public "walk every comment" AST node — comments are
trivia. `ts.createScanner(target, /*skipTrivia*/ false, variant, source)`
tokenizes `SingleLineCommentTrivia`/`MultiLineCommentTrivia` directly, which
is the standard technique (confirmed by a small throwaway probe against the
already-installed `typescript` package before writing the real scanner).
For `.svelte`, `svelte/compiler`'s own `ast.comments` (JS comments in
`<script>`/`<script module>`) and the fragment tree's `Comment` node type
(HTML comments) — the same split `citationGuard.test.ts`'s own header
already documents for a different purpose.

**Comment-group joining, needed for real (not just by analogy with Go).**
A per-physical-line-only match missed a real instance:
`internal/seo/dist_placeholder_guard_test.go:116`'s `hashedAssetPattern`
doc comment carries its `"e.g."` marker on the line BEFORE the citation it
excuses (`"...hashed asset reference, e.g.\n// \`/assets/index-BDtqW4JY.js\`
or \`/assets/index-TVYljy6F.css\`..."`), so both languages' guards join
consecutive `//`-style lines with no gap into one text blob before matching
— mirroring Go's own `*ast.CommentGroup` grouping — and keep a `/* */` or
`<!-- -->` block as its own single (but internally multi-line) blob, split
the same way `#0199`'s block-comment line-number fix does, so a reported
line is the citation's own physical line, not the block's opening line.

**Self-scan (criterion 5).** Both guards scan `_test.go`/`.test.ts` files,
including themselves — `#0181`'s exclude-the-test-file trick is not
available here, since `#0216`'s own defects (the dangling test-file names,
`web/HANDOFF`) landed in `.test.ts` files, and excluding those would hide
exactly the shape this issue exists to catch. Both files stay clean by
construction: every genuine path or section cited in their own real
comments resolves (verified directly — the Go guard's own tree-wide run
includes itself, and the TS guard additionally has a dedicated
`'scans its own file (self-reference) and finds zero hits'` test asserting
it in isolation), and every fictitious example needed to prove the guard
*fires* is built from string concatenation inside a `src` fixture variable,
never written as a literal comment token — the same technique `#0196`'s own
file states for itself.

**The false-positive rule, in full** (criterion 4) — six structural
exclusions, each tied to a specific real instance the dry run against the
whole tree turned up, none a blanket loosening:

1. **URL-embedded** — `"://"` within the 24 characters before the match
   (`internal/handlers/citation_guard_test.go`'s own
   `"https://example.com/docs/guide.md"` reasoning-comment example).
2. **Deliberately hypothetical**, introduced by `"e.g."`, `"for example"`,
   `"such as"`, `"hypothetical"`, `"imagine"`, `"not a real path"`,
   `"does not exist"`, `"no such file"`, `"made up"`, or `"placeholder"`
   within the preceding 60 characters (`citationGuard.test.ts:76`'s
   `"issues/NNNN.md (a path to one tracker file, e.g."`).
3. **Historical** — the comment itself says the target no longer exists
   (`"deleted in"`, `"the deleted"`, `"was deleted"`, `"removed in"`,
   `"no longer exists"`, `"used to live at"`, and, web-only,
   `"never written"` for `modalKeydown.test.ts`'s own honest history of
   `#0216`'s dangling citations) — the real instances are
   `internal/handlers/request.go:25`'s `"(deleted in #0002 along with the
   rest of internal/handlers/redirect.go)"` and
   `testutil_test.go:7`'s `"...from the deleted\ninternal/handlers
   /url_filters_test.go"`.
4. **Named external dependency** — `"goldmark"` appearing anywhere earlier
   in the same comment BLOCK (unbounded within that one block, not a fixed
   window, since what licenses reading a later path as "inside that
   dependency" is the surrounding explanation, not just the adjacent
   phrase) — the real instances are `internal/mailing
   /campaign_markdown.go`'s three references to goldmark's own
   `renderer/html/html.go` and `renderer/renderer.go`, which this repo does
   not and should not contain.
5. **This repo's own `NNNN` placeholder convention** (`issues/NNNN.md`'s
   filing template) — any path segment, extension stripped, that is
   literally `NNNN`.
6. **Two (or more) whole filenames — or known bare document names (`PRD`,
   `HANDOFF`, `README`, `LICENSE`) — joined by a bare `"/"` as a list
   separator, not a nested path** — real instances:
   `worker_test_helpers_test.go:2`'s `"campaigns_test.go/audience_test.go"`,
   and `internal/mailing/campaign_markdown.go:14`'s `"PRD/CLAUDE.md §9"`
   (meaning "PRD §9 and CLAUDE.md §9", not a path under a nonexistent
   `PRD/` directory). Structural: every intermediate segment already looks
   like a complete filename with a recognized extension, or is a known
   bare document name — never a name-based allowlist of the whole path.

   Web-only seventh: a glob-style wildcard prefix (`"*.name.test.ts"`) is
   discounted the same way `#0196`'s Go guard discounts a trailing `*` —
   the real instance is `modalKeydown.test.ts`'s own corrected text
   (post-`#0216`), which replaced three dangling citations with an honest
   `"*.escapeWiring.structuralGuard.test.ts"` shape describing what the old
   citations looked like, not naming a specific file.

**Path resolution** (both languages, identical logic): exact repo-relative
match; the same path with `.md` appended (the bare `HANDOFF`/`README`/
`LICENSE` form); a real path that ENDS WITH `"/" + cited` (the shortened
form this tree actually uses — `logout_all_test.go:285`'s
`"handlers/auth.go"` for `internal/handlers/auth.go`;
`"admin/Campaigns.svelte"` for `web/src/views/admin/Campaigns.svelte`); the
same suffix check with `.md` appended; and, ONLY if none of those resolves
and the first segment carries no extension, one retry with that first
segment stripped (`WorkshopsIndex.svelte:7`'s real
`"WorkshopCard/lib/workshops.ts"`, meaning "`WorkshopCard`[.svelte] and
`lib/workshops.ts`", not a nested path under a nonexistent `WorkshopCard/`
directory). Deliberately bounded to stripping exactly one leading segment,
not iterated — a general "any suffix resolves" rule would also rescue a
genuinely dangling multi-segment citation whose tail happened to
coincidentally match some unrelated real file.

**The web guard's one extra shape.** `#0216`'s own historical defect named
three test FILES with no directory at all
(`"CampaignEditor.escapeWiring.structuralGuard.test.ts"`, bare), which the
path pattern (requiring at least one `/`) cannot see. A second, narrower
pattern (`citationTargetBareTestFilePattern`) catches a bare
`"Name.thing.test.ts"`-shaped reference and resolves it by basename only
against the real tree — the weakest, most permissive check either guard
performs, deliberately scoped to exactly that one shape. No Go-side
counterpart: nothing in the Go tree cites a bare `_test.go` name the same
way.

**`@types/node`, deliberately not added.** The TS guard needs real
filesystem access (`node:fs`, `node:path`, `node:url`) — `import.meta.glob`
(the technique `citationGuard.test.ts` uses) only loads a STATIC set of
files matching a glob known at build time, not an arbitrary repo-relative
path string discovered at runtime from inside a comment. `#0181`'s own
review pass (see `citationGuard.test.ts`'s header) had already tried and
REMOVED an `@types/node` dependency and a `"node"` entry in
`tsconfig.json`'s `types` array in favor of `import.meta.glob`, specifically
to avoid the dependency (`npm ls --all` confirms `@types/node` is not
installed — only present, unmet, as an optional peer of vite/vitest).
Keeping that precedent intact: `web/src/lib/nodeFsShim.d.ts` is a minimal
ambient declaration for exactly the handful of functions the guard calls,
not a real `@types/node` substitute. It affects type-checking only — none
of the three modules is ever imported outside `_test.ts` files, so
`vite build`'s shipped `dist/` bundle never sees any of it.

**`dist/` is not pruned from the repo-path walk**, unlike Go's own vendored
roots (`node_modules`, `.git`) — several real comments cite
`"dist/index.html"` / `"web/dist/index.html"` (`cmd/opencircuit/main.go`,
`static.go`, `confirm.go`, `web/embed.go`, `internal/seo`), and
`web/dist/index.html` is a TRACKED PLACEHOLDER (`CLAUDE.md` §1) that exists
on disk in a fresh checkout regardless of whether `npm run build` has run.
Pruning it the way the Test*-citation guard's own walk prunes `dist` would
have made every one of those legitimate citations unresolvable.

**`tabindex="-1"` guard** (`web/src/lib/modalTabindexGuard.test.ts`,
criterion 6) — its own file rather than a two-line addition inside
`modalFocusWiring.structuralGuard.test.ts`'s existing per-panel loop, as
the issue's own Notes estimated: that file's twelve synthetic fixtures
assert EXACT violation counts (`toHaveLength(1)`, etc.) for the unrelated
onkeydown/focus-effect defect, and none of them carries `tabindex="-1"`
today — adding a second violation class to that same loop would have
either broken every one of those counts or required editing all twelve
fixtures for no benefit to what they prove. The new file reuses the same
AST-walk technique (`svelte/compiler`'s `parse`, `RegularElement` nodes)
with its own, separate violation list. Confirmed against the real tree: all
11 sites `modalFocusWiring.structuralGuard.test.ts` finds carry
`tabindex="-1"` today, matching `#0216`'s own Notes ("All 11 sites carry it
today").

**Mutation-reinstatement (criterion 3) — what a citation-existence guard
can and cannot catch.** `#0216`'s history names several distinct defects
across two reviews; only some are citations of a specific wrong target,
which is the only shape this class of guard can mechanically resolve:

- **Mechanically catchable, and reinstated from real git history:**
  - `web/src/lib/modalKeydown.test.ts` at `d9a9e01^` cited
    `"web/src/views/Admin.escapeWiring.structuralGuard.test.ts"` and two
    bare siblings — none exists.
  - `web/src/views/admin/CampaignSendDialog.behavior.test.ts` at `ddbde2b`
    cited `"web/HANDOFF"` — `web/` has no `.md` file at all.
- **Not mechanically catchable, and not attempted:** the "CLAUDE.md has no
  section on jsdom's fidelity" claim from the `#0216fix` bounce is a claim
  of ABSENCE with no specific section number cited — there is nothing for
  a citation-resolver to check; and the "two more sites" / a double-count
  in this issue's own arithmetic are miscounts, not citations of a wrong
  target. Both are a categorically different defect class (verifying a
  claim's truth, not a reference's existence) that this guard does not
  attempt to solve — recorded here rather than silently narrowed to fit,
  in the same register this tracker uses elsewhere for an honest scope
  boundary.

## Notes

Reported by `#0216`'s phase-3 review under `CLAUDE.md` §9.

Criterion 2 is the one that would have caught the worst instance. Section
headings are stable strings in a file the guard can read; resolving `§N` against
`CLAUDE.md`'s own headings is cheap.

Worth reading before starting: `#0196`'s guard for the mechanics and its
discount rules (wildcards, `TestSentAt`, `*TestPool`, "renamed from"), and
`#0199` for the three blind spots that turned up in it afterwards — the same
shapes will appear here.

Note the class has an asymmetry worth designing around: a **missing** citation
guard costs a reviewer's time, but a **false-positive** one gets silenced, and
then costs everything. `#0199`'s review made that argument about a discount rule
that was too broad.
