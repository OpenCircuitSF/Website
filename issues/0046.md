# 0046 — Add campaign preview and test send

|---|---|

| **Module** | mailing |

## Description

Render a campaign without sending it, and deliver a real test message to an admin address before the campaign can go out.

## Acceptance criteria

- [ ] `POST /admin/campaigns/{id}/preview` returns the rendered HTML and text without sending
- [ ] `POST /admin/campaigns/{id}/test` sends one real message to a specified admin address
- [ ] The test message uses a real manage token so the unsubscribe links can be clicked and verified
- [ ] Test sends are recorded but do not create `email_sends` rows for the campaign
- [ ] A campaign cannot leave `draft` until a test send has succeeded
- [ ] Handler tests cover preview rendering and the test-send gate

## Carried in from `#0045`'s plan (2026-08-21)

- [ ] **This issue owns writing `email_campaigns.test_sent_at`.** `#0045`'s
      migration `000018` adds the column; the send worker only reads it, and
      gates sending on `test_sent_at IS NOT NULL`. Deliberately **not**
      `test_sent_at >= updated_at` — a bare status bump would then deadlock the
      operator into re-testing forever.

      **Amended 2026-08-21 by `#0045`'s review, after reading the shipped
      code:** migration `000018` has landed, so the column exists. Content-edit
      invalidation has **also** already landed — in `#0045`, not `#0041`:
      `CampaignStore.Update` (`internal/mailing/campaigns.go`) clears
      `test_sent_at` to NULL via `CASE WHEN subject IS DISTINCT FROM $3 OR
      body_md IS DISTINCT FROM $5 THEN NULL ELSE test_sent_at END`. Note it is
      `subject`/`body_md` **only** — a `preheader`-only edit deliberately does
      not invalidate, since the preheader never reaches the rendered body a
      test send delivered. So this issue writes `now()` into the column on a
      successful test send and implements **no** invalidation logic of its
      own.

## Carried in from `#0047`'s plan (2026-08-21)

- [ ] **Do not add an unsaved-body override to the preview endpoint.** `#0047`'s
      editor autosaves and then previews, because `#0046`'s preview and
      `#0044`'s audience both read the *stored* row. An override that previewed
      unsaved text is exactly what would let an operator preview one thing and
      send another.
- [ ] **Return both HTML and plain text.**
- [ ] **The preview HTML must be self-contained — no remote assets.** `#0047`
      renders it in a `sandbox=""` iframe rather than `{@html}`, and `CLAUDE.md`
      §9 forbids external CDNs and trackers regardless.

## Notes

PRD §6.6. Using a real, working token in the test send is the point — the operator should be able to click the unsubscribe link in the test message and see it work. A test that exercises everything except the compliance-critical links is not a test.

Whichever admin address receives the test must not end up suppressed by clicking it; use a token tied to a dedicated test subscriber row, not to a real list member.
