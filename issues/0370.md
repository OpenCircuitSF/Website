## Description

`CLAUDE.md` §11 carries, in free prose immediately below the section-index
table:

> §6 (the mailing list) is 933 lines — take the subsection, not the parent.

The table row directly above it now says **966**. The prose disagrees with the
guarded row by **33 lines**.

**It sits inches from a fully guarded table and is guarded by nothing.**
`internal/db/prd_section_index_test.go` parses the table rows and runs each
row's own `sed`; it never parses surrounding prose.

Confirmed genuinely pre-existing by `#0368`'s review — `git show 4ed36ef^:CLAUDE.md`
carries it verbatim, and `git log -S` dates it to `2e55a78`. `#0368` correctly
left it alone as out of scope.

**This is the exact drift class this phase has spent twenty issues on**, and the
person it misleads is the one deciding whether to extract §6 or a subsection —
the decision §11 exists to inform.

## The choice this issue must make

1. **Reword so the sentence carries no number.** "§6 is by far the largest
   section — take the subsection, not the parent" is as useful and cannot drift.
2. **Extend the guard** to any `§N … is <number> lines` prose in §11, so the
   number stays checked.

Option 1 is cheaper and removes the failure mode rather than detecting it.
Option 2 keeps a number a reader may actually want. **Choose deliberately and
record why** — and note that this phase's repeated finding (`#0330`, `#0347`,
`#0356`) is that removing a claim beats adding a checker for it.

## Acceptance criteria

1. The stale number is gone or guarded — not merely corrected to 966. **A
   corrected number drifts again on the next edit to §6**, which is how it
   reached 33 lines out.
2. If option 2: prove the extended guard discriminates. Change the prose number
   alone and confirm the test fails, naming it. **A check that cannot fail pins
   nothing** — `#0354`, `#0358` and `#0363` each shipped exactly that this
   phase.
3. Re-measure any number you state by running the relevant row's own `sed`
   command, never by arithmetic. §11 records two ways that table has been wrong:
   §6.2 drifted across two commits unnoticed, and §14 was wrong from birth
   because a regeneration applied `raw + 1` against the exception it had just
   documented. Note §14 has no following heading, so its count is taken **raw**
   at EOF — do not re-break it.
4. `internal/db/prd_section_index_test.go`'s existing tests still pass —
   `TestPRDSectionIndexParity` and `TestPRDSectionIndexTotalMatchesFile`, named
   explicitly in `## Verification` (§5: `ok` does not say what ran).
5. Documentation only. No `.go` file in the diff unless option 2 is chosen, in
   which case the guard change is the only one.
