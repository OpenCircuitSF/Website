## Description

`#0419` fixed `docs/seo.md` and `#0422` fixed `PRD.md` §7.4, so both documents
now describe `internal/seo` accurately. `#0422`'s review then found the drift one
layer down:

**`internal/seo/seo.go`'s package doc (step 2) and `resolve`'s own numbered
priority list both describe four branches. `resolve` implements five** — the
`/archive/{slug}` branch (`archiveRouteMeta`, cache key `archive:` + slug) is
absent from both.

So after two rounds of documentation correction, **the least accurate account of
`resolve` left in the tree is the comment attached to `resolve`.**

Confirmed by the orchestrator: the archive branch is present in the function
body and returns `"archive:" + slug`.

## Two smaller prose slips, recorded rather than bounced by `#0422`'s review

Both were judged not bounce-worthy at the time; exact replacement wording is in
`#0422`'s `## Review notes`.

1. **`PRD.md` §7.4's `og.png` sentence** says the card is served "for a published
   workshop with no `cover_image`". Eligibility is `Status == WorkshopPublished
   && Published` and **ignores `cover_image` entirely** — the route serves a card
   for a workshop that has one too; `cover_image` only wins in the `og:image`
   meta tag. Defensible as a statement of purpose, which is why it was not a
   bounce, but it is not what the code does.
2. **`docs/seo.md`'s "(`PRD.md`'s own convention, §11)"** sends a reader to
   PRD §11, which is *Security and Compliance*. **`CLAUDE.md` §11** is meant.

### What passed

### What must be fixed

**1. `defaultStaticRouteMeta`'s doc comment omits `/archive` — in `internal/seo/seo.go`, and it is this exact drift family.**

That doc comment names the route table as "`/`, `/about`, `/workshops`, and
`/subscribe`" per `#0019`'s criteria, then adds a sentence recording that
`/privacy` was added at `#0070`. It never records that `/archive` was added at
`#0123` — yet `/archive` sits in the map directly below it, carrying its own
inline `#0123, PRD §6.8` comment. So the comment accounts for five routes and
the map holds six, and the missing one is the same `#0123` addition, dropped for
the same reason, that this entire issue exists to correct.

Criterion 3 names "the route set" in as many words, and the implementer's own
reported grep terms included "route table" — which is the literal phrase this
doc comment opens with. It was read past.

**Remedy** (comment only, no code change): after the existing `/privacy`
sentence, record the `#0123` addition in the same style the `/privacy` sentence
uses — for example, "`/archive` was added at `#0123` (PRD §6.8) for the same
reason: the archive index is the site's only recurring indexable page."

**2. The commit introduced a new stale claim: "nil until `#0123` lands".**

The package doc's step 2 now reads "the archive source for `/archive/{slug}`
(nil until `#0123` lands -- same fallback)". `#0123` is `resolved`, and
`servePostgres` wires a real `campaignArchiveSEOSource` into `buildSEOSite`;
only `serveDevMode` passes nil, and its own comment says so. So the parenthetical
asserts a future condition that is already past, in a commit whose entire purpose
is removing exactly that kind of claim.

It mirrors the pre-existing "(nil until `#0051`/`#0054` land ...)" clause beside
it, which is stale in the identical way — `#0051` and `#0054` are both
`resolved` too, and the same phrasing appears again in `NewSite`'s doc comment.
That is mitigation for how it happened, not a reason to leave it.

**Remedy**: state the real condition rather than an issue that has landed — the
source is nil only under `STORAGE=json`, where `internal/devstore` has no
`email_campaigns` backing. Correcting the adjacent `WorkshopSource` clause in
the same edit is **explicitly in scope and preferred**, since fixing one half of
a parallel pair and leaving the other is worse than fixing neither. `NewSite`'s
copy of the phrase is also fair game in the same pass.

**3. The `seo_test.go` call was judged wrong — it is partly this family.**

The implementer reported `TestRender_StaticRoutesGetDistinctTitles`' doc comment
as a stale count from `#0070`'s `/privacy`, a different drift family, and left
it. Reading it against the route table shows it is stale **twice**: it names
"`/`, `/about`, `/workshops`, `/subscribe`" and "the four", while the test's own
`paths` slice has five (it adds `/privacy`) and the compiled-in table has six
(it adds `/archive`). The `/privacy` half is indeed `#0070`'s family. **The
`/archive` half is `#0123`'s — this issue's.** So the call was half right, and
the half it missed is the half in scope.

The same shape appears a third time:
`TestSitemap_ContainsStaticRoutesWithLastmod`'s doc comment says "each of the
four static marketing routes" while `marketingRoutes` holds six.

**Remedy** (doc comments only): correct both doc comments to describe the route
sets their subjects actually cover. **Do not change either test body** — the
fact that neither test exercises `/archive` is a coverage gap, not prose, and is
out of scope for a comments-and-prose issue. It is reported below for filing
instead.

### Criterion 4 — agreed, no mechanism

The implementer's conclusion is right and is the one this review reached
independently. `TestNoDocCommentNamesADifferentDeclarationInSameFile` detects a
doc comment attached to the wrong declaration, not one gone stale against its
own declaration's body. A guard for the latter would have to compare a
hand-maintained enumeration against an AST branch count in `resolve`, which is
more machinery than the prose justifies — and, per `CLAUDE.md` §8's rule about
where a guard's proof belongs, its oracle would be a copy of the answer stored
next to the question. Recorded, not built.
