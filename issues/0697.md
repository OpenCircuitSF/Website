## Review notes

**2026-11-17, review (Opus · medium): bounced, for one defect. Everything else checks out.**

**The defect.** `get_event_outreach` returns the admin panel's UTC times. The orchestrator ruled on the criterion 2 conflict the implementer flagged: the umbrella principle in `#0695` ("Pacific output times, using `inPacific`") wins for v1. Agents read these times, and every v1 op since `#0687` returns Pacific. The admin route must stay byte-identical, so do the conversion in the v1 op only, never in `panel`/`panelFor`.

**Remedy. Apply it as written; nothing needs deciding.**
1. In `internal/handlers/v1_outreach.go`, after `h.panelFor` returns, rewrite every RFC 3339 string in a copy of the panel to Pacific. Use the existing `pacificRFC3339` helper, which converts through `announceLocation`, the same zone `inPacific` uses. You can rename it or rebuild it on `inPacific`, but one helper must serve both ops. The fields are:
   - `workshop.starts_at`
   - `outreach.created_at` (copy the `*outreachRowView` before you change it)
   - `waves[].suggested_at`
   - `posts[].scheduled_at`, `posts[].posted_at`, `posts[].created_at`, `posts[].updated_at`

   Copy the `Waves` and `Posts` slices before you write to them, so nothing the admin path shares gets changed. If `hand_links` or any other nested view gains an `*_at` string, convert it the same way.
2. Update the `get_event_outreach` `Description` to say "Times have a Pacific offset."
3. `TestV1Outreach_PanelMatchesAdmin`: keep the `reflect.DeepEqual`, but normalise both decoded maps first. Walk them and replace any string value that `time.Parse(time.RFC3339, …)` accepts with `t.UTC().Format(time.RFC3339)`, so the test compares instants. Then add a direct assertion that the v1 `workshop.starts_at` and at least one `posts[].created_at` end in `-08:00` or `-07:00`. Without it, a regression back to UTC still passes. The seeded workshop's date decides which offset.
4. Re-verify with `ISSUE=0697 scripts/check.sh go ./internal/handlers/... ./internal/mcpserver/... ./cmd/opencircuit/...`.

**Verified and good; do not touch:**
- The `Outreach: adminOutreachH` wiring in `cmd/opencircuit/main.go`'s `V1Deps` literal is present at HEAD, and HEAD builds.
- `specTools` in `internal/mcpserver/parity_test.go` lists the three names. The `TestBuildV1RegistryListsOperations` append and the docs one-liners are in place.
