## Description

Turn the recurring visual devices — prompt lines, `[ OK ]` status rows, the command line with a blinking cursor, the terminal panel, and the PCB-trace divider — into five reusable Svelte components so the language stays consistent.

## Acceptance criteria

- [ ] `Prompt.svelte` — renders `> text`, chevron in `--accent`, mono
- [ ] `StatusList.svelte` — takes `string[]`, renders `[ OK ] label` rows; the `[ OK ]` glyph is `aria-hidden`
- [ ] `CommandLine.svelte` — renders `$ command` followed by a CSS-animated block cursor
- [ ] `TerminalPanel.svelte` — bordered panel with the three-dot title bar; optional title and `noPadding` props
- [ ] `TraceDivider.svelte` — inline SVG PCB-trace horizontal rule, `aria-hidden`
- [ ] Cursor blink and any scanline effect are disabled under `@media (prefers-reduced-motion: reduce)`
- [ ] All five are token-driven with no literal color values, and verified in **both** light and dark
- [ ] Each has a Vitest test where it has logic, and all render in `npm run check` with no type errors

## Notes

PRD §4.4. Build these before the views (#0015, #0016) so the views compose rather than reimplement — this is the difference between a coherent design language and five slightly different green prompts.

Accessibility detail: the `[ OK ]` marker carries no meaning a screen reader needs; the label text does. Mark the glyph `aria-hidden` rather than letting VoiceOver read "left bracket O K right bracket" before every item.

`prefers-reduced-motion` is not optional — a blinking cursor is exactly the kind of motion that setting exists for.

Reference implementations of all five exist in `placeholder/index.html` as plain CSS; port them to Svelte components rather than redesigning.
