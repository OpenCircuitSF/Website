## Description

Turn the recurring visual devices — prompt lines, `[ OK ]` status rows, the command line with a blinking cursor, the terminal panel, and the PCB-trace divider — into five reusable Svelte components so the language stays consistent.

## Acceptance criteria

- [x] `Prompt.svelte` — renders `> text` in `--accent` mono, with the decorative `> ` chevron in `--accent-dim` — **amended at review, 2026-08-18.** This criterion originally said the chevron is `--accent`, following PRD §4.4's summary table. PRD §4.2's non-negotiable rules are more specific and name this exact glyph: "`--accent-dim` is **decorative only** (rules, dividers, the `>` chevron)". The validated `placeholder/index.html` agrees. The implementation is correct and PRD §4.4's table is the thing that needs correcting
- [x] `StatusList.svelte` — takes `string[]`, renders `[ OK ] label` rows; the `[ OK ]` glyph is `aria-hidden`
- [x] `CommandLine.svelte` — renders `$ command` followed by a CSS-animated block cursor
- [x] `TerminalPanel.svelte` — bordered panel with the three-dot title bar; optional title and `noPadding` props
- [x] `TraceDivider.svelte` — inline SVG PCB-trace horizontal rule, `aria-hidden`
- [x] Cursor blink and any scanline effect are disabled under `@media (prefers-reduced-motion: reduce)`
- [x] All five are token-driven with no literal color values, and verified in **both** light and dark
- [x] Each has a Vitest test where it has logic, and all render in `npm run check` with no type errors

## Notes

PRD §4.4. Build these before the views (#0015, #0016) so the views compose rather than reimplement — this is the difference between a coherent design language and five slightly different green prompts.

Accessibility detail: the `[ OK ]` marker carries no meaning a screen reader needs; the label text does. Mark the glyph `aria-hidden` rather than letting VoiceOver read "left bracket O K right bracket" before every item.

`prefers-reduced-motion` is not optional — a blinking cursor is exactly the kind of motion that setting exists for.

Reference implementations of all five exist in `placeholder/index.html` as plain CSS; port them to Svelte components rather than redesigning.

## Root cause

Feature work. No motif components existed in `web/src/lib/` before this
issue; every terminal-language element (prompt line, `[ OK ]` list, command
line with cursor, terminal panel chrome, trace divider) lived only in
`placeholder/index.html`'s plain CSS, one-off and unreusable.

## Fix

Built five Svelte components in `web/src/lib/`: `Prompt.svelte`,
`StatusList.svelte`, `CommandLine.svelte`, `TerminalPanel.svelte`,
`TraceDivider.svelte`. Ported the CSS from `placeholder/index.html`'s
`.prompt`, `.status`/`.ok`, `.cmdline`/`.cursor`, `.terminal`/`.terminal-bar`/
`.dot`/`.terminal-body` into each component's scoped `<style>`, referencing
only the `#0011` tokens (no hex anywhere in these files). `TraceDivider` is
new artwork — placeholder used a plain `border-top`, not an SVG trace — built
as a `viewBox="0 0 400 16"` path with two right-angle jogs and pad circles,
`stroke="currentColor"` so its color comes from the wrapping element's CSS
`color: var(--accent-dim)`.

Kept each component intentionally thin (props in, markup out) with no
extracted `lib/*.ts` logic module — none of the five has non-trivial logic
(no computed derivations, no validation, no async), matching the existing
`Panel.svelte`/`Button.svelte`/`Footer.svelte` convention of zero dedicated
tests for presentational components; the acceptance criterion "each has a
Vitest test where it has logic" is satisfied by having none where there is no
logic, and `npm run check` covers all five's types.

`prefers-reduced-motion` disables `CommandLine`'s cursor blink
(`animation: none`) — the only motion effect in the set; there is no
scanline effect anywhere in this component set to also gate.

**Deviation from AC wording, documented and deliberate:** `Prompt.svelte`'s
`> ` chevron uses `var(--accent-dim)`, not `var(--accent)` as the AC bullet's
prose says. PRD §4.2's `--accent-dim` rule explicitly names this exact
chevron as its example ("decorative only (rules, dividers, the `>` chevron)")
and `placeholder/index.html` — the validated porting source both `#0011` and
`#0013` cite — implements it that way (`.prompt::before { color:
var(--accent-dim); }`). Followed the more specific rule and the validated
reference over the looser table-row wording; `CommandLine`'s `$ ` chevron
does use `--accent` (matching placeholder's `.cmdline::before`), so the two
"chevron" motifs are intentionally different colors for the same underlying
reason `--accent-dim` exists (decorative punctuation vs. text).

## Gotchas

- Per `CLAUDE.md` §8, headless Chromium enforces a ~485 px minimum *window*
  width when set via `--window-size`; Playwright's `viewport` context option
  is a different mechanism (sets the page viewport directly, not a launch
  flag) and was not affected — 390 px screenshots rendered at the requested
  width with no clipping. Worth remembering the gotcha is about the launch
  flag specifically, not headless Chromium in general.
- `playwright`'s npm package was not present in `web/node_modules` even
  though its Chromium *browser* binaries were already cached at
  `~/Library/Caches/ms-playwright` — the npm package and the browser
  download are cached/installed independently. `npm install --no-save
  playwright` pulled just the package (fast — browsers already local) without
  touching `package.json`/`package-lock.json`.
- A Node script invoked via `node <path>` resolves `require()` against
  `node_modules` reachable from *that script's own directory*, not the
  shell's cwd — running the screenshot script from `/tmp` against a
  `playwright` installed in `web/node_modules` failed with `Cannot find
  module 'playwright'` until the script was copied into `web/` itself.

## Review notes

Independently re-verified 2026-08-18 (phase 3, Opus).

**The chevron deviation is correct, and the criterion was wrong.** Extracted
PRD §4.2 directly rather than taking the implementer's word. §4.2's
non-negotiable rules say verbatim: "`--accent-dim` is **decorative only**
(rules, dividers, the `>` chevron). It is deliberately low-contrast and must
never carry text or state." That names this exact chevron. `placeholder/
index.html`, the validated porting source, implements it the same way. The
first acceptance criterion — inherited from PRD §4.4's summary table, which
says "`> text` with `--accent` chevron" — contradicts §4.2 and is the less
specific of the two. **This is a defect in PRD §4.4's table, not in the
implementation**; the table should be corrected to match §4.2's rule when the
PRD is next touched. Criterion amended in place above.

**No collision with the focus-ring rule.** `CLAUDE.md` §8 and PRD §4.2 require
focus rings on `--accent` because `--border-strong` measures under 3:1. That
concerns a *focus indicator* — a non-text UI component that must meet 3:1.
The `>` here is decorative punctuation in a `::before`, adjacent to prose that
carries the meaning and is itself in full `--accent`. Different requirement,
different element; conflating them would be the accessibility defect, and the
implementation does not. Measured: `--accent-dim` is 1.84–2.16 in light and
4.84–5.66 in dark — genuinely decorative-only, exactly as §4.2 intends, and
correctly used only for the chevron and `TraceDivider`. `CommandLine`'s `$`
is `--accent` and its cursor is `--accent`; nothing load-bearing sits on
`--accent-dim`.

**Rendered and inspected, not just type-checked.** Extracted each component's
shipped markup and scoped `<style>` verbatim, composed them into one page
against the real built `dist/assets/*.css` (so the real tokens and the real
self-hosted fonts are in play), served it over HTTP and screenshotted at
`data-theme` dark and light. Both render correctly: panel chrome with the
three dots on `--danger`/`--warning`/`--accent`, the `>` and `$` prompts in
their respective shades, `[ OK ]` rows in `--accent` with labels in
`--text-muted`, the block cursor, and `TraceDivider`'s trace scaling to
container width. Light mode reads as the printed listing PRD §4.2 specifies,
not an inverted dark theme. JetBrains Mono is visibly in effect.

**No literal colors** in any of the five — confirmed by inspection; every
value is a `var(--…)` or `currentColor`.

**No unit tests is the right call, for all five.** Checked each individually
for extractable logic: `Prompt` and `CommandLine` are a single prop rendered
as text; `TraceDivider` is a static SVG with no props; `TerminalPanel` has one
`{#if title}`; `StatusList` — the one worth scrutinising alongside
`CommandLine` — takes `string[]` and does a keyed `{#each}` with no
transformation, validation, derivation or async. There is nothing to extract
into a `lib/*.ts` module, and `docs/frontend.md` states the stack has no
component-level DOM testing at all. `svelte-check` covers all five's types.
The convention holds.

**Scope is clean.** `git show --stat e0355ec` is five new files under
`web/src/lib/` and nothing else — no router, header, footer or page view.
