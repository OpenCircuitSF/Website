## Description

`docs/deployment.md:441` says "This repo currently ships migrations
`000001`–`000020`". The repo is past `000023` and production is at `000022`.

Trivial in itself. It is filed because of the class it belongs to, which has
already been expensive: **a stale fact in a deployment document read as a
current instruction is what bounced `#0125`**, cost a full re-implementation
pass, and would have left `schema_migrations` dirty at 23 on a real deploy.

`docs/database.md` has `TestDatabaseDocMigrationParity` keeping its migration
table honest, and `PRD.md`'s §11 index has
`internal/db/prd_section_index_test.go`. **`docs/deployment.md` has neither**, so
its counts drift silently — which is exactly how this one got three migrations
behind.

`#0293`'s implementer found it while sweeping the greenfield notes, correctly
judged it outside that issue's three named passages, and reported rather than
widening its own scope.

## Acceptance criteria

1. The count is corrected, and stated in a form that does not need updating on
   every migration if a cheaper form exists (a range endpoint that is derived,
   or a pointer to `docs/database.md`'s guarded table rather than a second copy
   of the same fact).
2. **Prefer removing the duplicate fact over guarding a second copy of it.** Two
   documents stating the same count is the drift source; one stating it and one
   linking to it is not.
3. If the count stays in `docs/deployment.md`, extend or mirror
   `TestDatabaseDocMigrationParity` to cover it, so it cannot drift again.
4. Sweep `docs/deployment.md` for other stale counts and version facts while
   there — production's PostgreSQL version, instance size, region, and the
   `schema_migrations` version are all recorded in CLAUDE.md §7 and were all
   measured on the box on 2026-08-25. Report what you found even if nothing.
5. Do not touch any migration file.
6. `ISSUE=NNNN scripts/check.sh go ./internal/db/...` passes — that is where the
   doc-parity guards live.

### What must change before this can be resolved

**`docs/deployment.md:227` states the wrong PostgreSQL major version and
attributes it to `CLAUDE.md` §7, which says the opposite.**

```
- **PostgreSQL 16.** Already on the box per `CLAUDE.md` §7 — confirm the
  major version with `psql --version` before assuming it matches …
```

`CLAUDE.md` §7 says **15.18**. This is a stale fact left behind by the
2026-08-25 measurement that corrected §7 from the assumed 16 down to the
real 15, and it carries a false citation on top — it points at the very
document that contradicts it. It sits in **§1 Prerequisites**, the position
most likely to be read as a current instruction, which is precisely the
`#0125` failure mode this issue's own description names as the expensive
class.

The same file already flags it, twice, in text the sweep read:

- line 82: "PRD §10.1 **and this document's Prerequisites say 16**, and
  `#0062`/`#0228`'s drills ran on 16.14. All 22 migrations applied cleanly on
  15.18 …"
- lines 1940–1941: "**PostgreSQL 15 is proven for this schema**, contradicting
  this document's own 'PostgreSQL 16' prerequisite."

The work log cites line 82 as evidence the version "matches" — but line 82 is
the *correction*, and its own sentence names the uncorrected prerequisite.
Reading the correction and reporting "nothing else found stale" is the miss.

**Remedy** (small, local, one bullet at lines 227–236):

1. Change the bullet's assertion from "**PostgreSQL 16.** Already on the box
   per `CLAUDE.md` §7" to state what is actually on the box — PostgreSQL
   **15.18**, per `CLAUDE.md` §7 — and keep the `psql --version` confirmation
   step.
2. Say that 15 is proven for this schema (all 24 migrations apply, the Go
   suite passes on 15.14/15.18) and that nothing in the tree pins a major
   version, so 16-only syntax must not be introduced without upgrading the
   box first. That is already established at line 82 and 1940–1941; the
   prerequisite should agree with it rather than contradict it.
3. Keep the `dnf install … postgresql16-server` block for a **fresh**
   provision if that is still the intent, but label it as a fresh-box choice
   rather than a description of the existing box — the current text conflates
   "what is installed" with "what to install".
4. Do not touch lines 348, 352, 476, 997, 1042 or 1506: those are records of
   what `#0062`/`#0228`'s local drills ran on (Homebrew PostgreSQL 16 on a
   Mac) or a general "PostgreSQL 15+" statement, all correctly framed as
   history or as version-range guidance, not as claims about the box.
