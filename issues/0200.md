## Description

`#0194` committed the 34-case shape matrix precisely so three successive passes
would stop rebuilding and deleting the same evidence. Its own phase-3 review
noticed the issue's Part 1 has the identical problem, untouched.

**Nothing in the tree asserts that the Go walk reaches every non-test `.go`
file.** The 95-collected-equals-95-on-disk measurement has now been derived by
scratch probe and thrown away by `#0181`'s pass-2 review, `#0187`'s
implementation, `#0187`'s review, `#0194`'s implementation, and `#0194`'s
review — five times.

It matters more here than for the matrix, because that invariant is **the only
thing that would ever detect `#0194`'s name-based `SkipDir` swallowing a real
directory.** `skipVendoredDirNames` matches any directory called `node_modules`
or `dist` at any depth. The tree has exactly one of each today, both genuinely
vendored, and the doc comment states the choice — but if someone adds
`internal/dist/` the walk silently stops covering it, and every guard built on
that walk quietly narrows with no test failing.

A dozen-line committed test closes both halves: it pins the invariant and makes
the skip's bluntness detectable.

## Acceptance criteria

- [x] A committed test asserts the shipped walk collects exactly the set of non-test `.go` files on disk under the three roots, set-identical in both directions
- [x] It runs against the shipped `scanDirForCitations` (or its collection step), not a replica of the walk predicate — see `#0197` on this tracker's replica history
- [x] Adding a non-test `.go` file under a directory the skip swallows makes the test fail — demonstrated by planting one under a new `internal/dist/`, then removing it
- [x] Adding an ordinary non-test `.go` file anywhere in the three roots does **not** fail it
- [x] The test's failure message names the files present-but-uncollected and collected-but-absent, so the direction of the drift is obvious
- [x] `#0194`'s three-way skip proof still holds, and `#0187`'s 34-case matrix still passes
- [x] `ISSUE=0200 scripts/check.sh go ./internal/...` passes with zero skips

## Implementation notes

`internal/handlers/citation_guard_test.go` gained one new test,
`TestScanDirForCitationsCollectsExactlyDiskFiles`, plus the minimal
instrumentation needed for it to run against the shipped walk rather than a
replica:

- `scanDirForCitations` now returns `(violations []citationViolation,
  collected []string)` instead of just violations — same `WalkDir` call, same
  `skipVendoredDirNames` check, same suffix filter; the only change is
  recording each collected path before parsing it. Its one call site
  (`TestNoAdminFacingStringCitesInternalDocs`) was updated to discard the new
  second value.
- The new test enumerates the same three `scanGoRoots` a second, independent
  way: an unrestricted `filepath.WalkDir` with **no** skip logic at all — not
  even a reuse of `skipVendoredDirNames` — because reusing that map would make
  the "ground truth" blind to exactly the bug this test exists to catch (a
  directory swallowed by name that isn't actually vendored). It then diffs the
  two file sets and reports both directions separately: present-on-disk-but-
  uncollected vs. collected-but-not-on-disk.

### The walk predicate is genuinely unchanged

`git diff bce1ad8^ bce1ad8` is 114 insertions across one file, and the change
to `scanDirForCitations` is exactly four lines:

- the signature became named returns `(violations []citationViolation,
  collected []string)`, and `var violations []citationViolation` was deleted
  as now redundant;
- `collected = append(collected, path)` was inserted **after** the
  `.go` / `_test.go` suffix filter and **before** `parser.ParseFile`;
- `return violations` became `return violations, collected`;
- the one call site discards the second value.

The `filepath.WalkDir` call, the `entry.IsDir()` branch, the
`skipVendoredDirNames[name]` → `filepath.SkipDir` check, the suffix filter,
the parse and the `t.Fatalf` on parse error are byte-identical to
`bce1ad8^`. The implementer's claim holds exactly: the test measures the
shipped predicate, and a future narrowing of that predicate is visible to the
test without being mirrored into it. This is instrumentation, not a replica —
the `#0197` trap is structurally avoided rather than avoided by care.

### The ground truth is genuinely independent

The second enumeration in `TestScanDirForCitationsCollectsExactlyDiskFiles` is
a bare `filepath.WalkDir` over the same `scanGoRoots` whose whole body is
`IsDir → nil` plus the same suffix condition. It references
`skipVendoredDirNames` nowhere — confirmed by reading the function and by
`grep`: the only uses of that identifier in the file are its declaration and
the shipped walk. So the comparison shares no skip logic, and the implementer's
reasoning (reusing the map would blind the ground truth to a name-swallowed
real directory) is borne out in the code. Measured baseline in the worktree:
**95 collected == 95 on disk**, matching `find internal cmd web -name '*.go'
! -name '*_test.go'` (95) and the same `find` excluding `web/node_modules` and
`web/dist` (95). Same numbers `#0187` and `#0194` derived by hand — now pinned.

### The "collected but NOT present on disk" direction is unreachable

Structurally, the ground-truth walk is the shipped walk minus the `SkipDir`, so
for any single filesystem state `collected ⊆ onDisk` and the second set is
always empty. The failure message's parenthetical names three causes; two of
them cannot produce it, tested directly:

| Probe | Result |
|---|---|
| true symlink named `*.go` pointing at a real `.go` file | **PASS** — `WalkDir` lstats, so both walks see it identically; it lands in both sets |
| symlinked directory (not `.go`-named) containing `.go` files | **PASS** — neither walk follows it |
| dangling symlink named `*.go` | **FAIL**, but at `parse …: no such file or directory` — the shipped walk's `t.Fatalf` fires before the comparison runs |
| directory named `*.go` | **FAIL**, likewise at `parse …: is a directory` |

So "symlink" and "duplicate walk entry" are not reachable causes. The only
condition that could populate that set is a file disappearing between the two
walks of the same root within one run — a filesystem race, not a code path
anyone will hit. The branch is not dead code: temporarily blinding the ground
truth to `*audit*` rendered it correctly, naming the four affected files under
`collected but NOT present on disk`, and the mutation was reverted
byte-identically. Verdict: **the branch works but cannot fire under any
reachable static condition**; its parenthetical over-claims. Recorded rather
than left looking like tested behaviour — not a defect, and not worth a change
on its own.

### For filing (§9 — reported, not filed)

**The ground truth walks `web/node_modules`, so an npm dependency that ships a
non-test `.go` file will fail this test.** Demonstrated incidentally during
proof 4 step 1: with `web/node_modules/zz0200rev-probe/vendored.go` planted,
`TestScanDirForCitationsCollectsExactlyDiskFiles` **failed**, naming that path
under "skipVendoredDirNames may be swallowing a real directory". That is the
test working as designed — it cannot tell a genuinely vendored directory from a
real one swallowed by name — but it re-opens, in a different test, precisely
the failure `#0194` added the skip to prevent: a routine `npm install` taking
the guard down over a file nobody here wrote. Zero `.go` files exist under
`web/node_modules` today, so this is prospective, not live.

There is a third option the implementation notes do not consider, and it is
strictly better than either horn: exclude by **path prefix**
(`web/node_modules`, `web/dist`, anchored) in the ground-truth walk rather than
by name. That stays independent of the name-based predicate under test — an
`internal/dist/foo.go` is still outside the excluded prefixes, so the
`internal/dist` scenario still fires — while a vendored `.go` under
`web/node_modules` no longer does. Worth an issue: swap the ground truth to
path-anchored exclusion, and while there, drop "symlink, or duplicate walk
entry" from the second failure message's parenthetical, since neither can
produce it (proved above).
