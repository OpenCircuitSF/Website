# 0236 — The backup unit can fall through to ShortLinks' database

| | |
|---|---|
| **Status** | open |
| **Platform** | Server |
| **Module** | infra / deploy |
| **Phase** | 7 — Inbound and polish |
| **First seen** | 2026-08-24 |

## Description

`deploy/systemd/opencircuit-backup.service` ships with `BACKUP_DATABASES`
**commented out**. `scripts/db/backup.sh` then falls through to its own default,
which is the literal `shortlinks` — **the other project's database**, inherited
when the script was ported from ShortLinks by `#0001`.

The failure is loud rather than silent: on this box `shortlinks` either does not
exist, so `pg_dump` fails and the `OnFailure=` alert fires, or it does exist and
the timer quietly backs up the wrong project every night while Open Circuit is
never backed up at all. Which of those happens depends on whether ShortLinks
shares the instance — and `CLAUDE.md` §10 item 6 records that we do not yet know
whether the existing Postgres is the target.

Either way the operator learns about it from an alert or an empty backup
directory, not from the install.

**This is a one-line fix with a disproportionate consequence**, which is exactly
the kind of thing a runbook step should not leave optional. A commented-out
variable reads as "optional tuning" and is in fact load-bearing.

## Acceptance criteria

- [ ] `BACKUP_DATABASES` is set in the unit rather than commented out, or `backup.sh` refuses to run without it instead of defaulting
- [ ] `backup.sh`'s default no longer names another project's database — remove it or make it fail closed
- [ ] `docs/deployment.md` lists setting it as a required install step, not a suggestion
- [ ] Proved: with the variable unset, the run fails loudly and names the missing configuration rather than dumping something unexpected

## Notes

Reported by `#0228`/`#0229`'s phase-3 review under `CLAUDE.md` §9.

The wider point is worth keeping: `scripts/db/` was ported wholesale from
ShortLinks, and this is the second defect traceable to a ShortLinks default
surviving the port (`migrations/000007` is the first, recorded in `CLAUDE.md`
§1). A sweep of `scripts/db/` for other inherited defaults would be cheap and is
probably overdue.

Nothing about this is reachable until the box exists — deployment is deferred
(`CLAUDE.md` §10) — but it must be fixed **before** the first install, because
the failure mode is "backups were never running".
