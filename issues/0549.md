## Description

The flyer workflow from the design doc's "Flyers" section and mockup
artboards 4–6: pick a workshop, a photo (upload or cover image) with a focal
point, a template and tagline; tick locations and copies; **Generate** one
ShortLinks link per (workshop, location) under the workshop's campaign; fetch
and cache each link's QR code; print full-page or half-size-double flyers,
each with its location's QR code, short URL and a small location label.

### Decisions

1. **Schema: the link belongs to (outreach, location), not to a flyer.**
   The criterion "reprints and other flyers for the same workshop and
   location reuse it" is a uniqueness rule, so it goes in a `UNIQUE`
   constraint rather than an application lookup. A flyer is a *design*
   (photo, focal point, template, tagline) plus a *selection* (locations ×
   copies). Flyers hang off `outreach` (`outreach_id`), not `workshop_id`,
   like `outreach_posts` do: the campaign slug lives on `outreach`, so
   making a flyer requires outreach to have been started, which Generate
   needs anyway. The acceptance criterion is corrected above.
2. **Idempotent link creation without a custom key.** The destination is
   deterministic: `outreach.FlyerDestinationURL(siteBase, slug, code)` =
   `<base>/workshops/<slug>?utm_campaign=<slug>&utm_content=<code>&utm_medium=print&utm_source=flyer`
   (built with `url.Values.Encode`, so keys are sorted, the way
   `DestinationURL` already does it). `CreateLink` without `Key` de-duplicates on
   destination, so a retried or concurrent Generate gets the same ShortLinks
   link back. Our side is idempotent through `UNIQUE (outreach_id,
   location_id)` + `INSERT … ON CONFLICT DO NOTHING`. The code is immutable
   once locked, so the destination never changes for a pair.
3. **`MarkLocationUsed` contract (from `#0548`'s plan).** The ShortLinks
   call happens *before* the transaction, since an HTTP call cannot be
   inside one. The transaction then (a) `SELECT code FROM outreach_locations
   WHERE id = $1 FOR UPDATE` and refuses with `ErrLocationCodeChanged` if it
   differs from the code the destination was built from (an unlocked code
   could be edited between the read and the insert), (b) inserts the link
   row `ON CONFLICT (outreach_id, location_id) DO NOTHING`, (c) calls
   `s.MarkLocationUsed(ctx, tx, locationID)`, and (d) commits. The location
   is locked only when a link row really exists. FK
   `location_id … REFERENCES outreach_locations(id) ON DELETE RESTRICT` is
   the backstop `#0548`'s `DeleteLocation` already maps (`23503` →
   `ErrLocationInUse`).
4. **QR: fetched once, rebuilt rather than filtered, and served as an
   image.** ShortLinks' `qr.RenderSVG` emits only an XML declaration, one
   `<svg>` (xmlns, integer `viewBox`/`width`/`height`,
   `shape-rendering`), one white background `<rect>`, and a `<g fill>`
   holding integer `<rect x y width height="1">` runs (read from
   `~/Developer/brennanMKE/ShortLinks/internal/qr/qr.go`).
   `outreach.SanitizeQRSVG(raw []byte) ([]byte, error)` parses that with
   `encoding/xml` and **re-emits a fresh SVG from the parsed integers
   only**: `<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 N N"
   shape-rendering="crispEdges"><rect width="N" height="N"
   fill="#fff"/><g fill="#000"><rect x=… y=… width=… height=…/>…</g></svg>`,
   with no `width`/`height`, so it scales to its box. Anything else is
   rejected: any element other than `svg`/`g`/`rect`, any attribute outside
   the allowlist, any `Directive` token (`<!DOCTYPE`/entities), a
   `ProcInst` other than `xml`, comments, character data that is not
   whitespace, a non-integer or out-of-range number (`0 ≤ v ≤ N`, `21 ≤ N
   ≤ 200`), input over 256 KiB, or over 40,000 rects. A rejected QR is
   **not cached**. Defenses after that: the cached bytes are served from
   `GET /admin/outreach-flyer-links/{id}/qr.svg` with `Content-Type:
   image/svg+xml`, `X-Content-Type-Options: nosniff`,
   `Content-Disposition: attachment; filename="<code>.svg"` (opening the
   URL directly downloads the file instead of rendering it in our origin),
   and `Cache-Control: private, max-age=3600`. The SPA uses it only as
   `<img src>`, and SVG loaded through `<img>` never runs script. **Do not
   rely on a per-response CSP header from Go.** Apache's vhost uses `Header
   always set Content-Security-Policy`, which replaces whatever the backend
   sends (`deploy/apache/installed-001-…-le-ssl.conf`). Rebuilding the SVG
   is the real defense.
5. **The print page is a Svelte view in the admin SPA, not a Go
   template.** One `FlyerFace.svelte` renders both the editor preview and
   the printed sheets, so the three templates exist exactly once. The
   fonts are already self-hosted through `app.css`'s `@font-face`
   (`/fonts/*.woff2`). The live CSP (`default-src 'self'; script-src 'self'
   'sha256-…'; style-src 'self' 'unsafe-inline'; img-src 'self' data:;
   font-src 'self'; frame-ancestors 'none'`) is satisfied without any
   change: bundled script, same-origin images (`/media/…`, the QR
   endpoint), inline `style=` attributes, and one runtime `<style>` element
   for `@page` (allowed by `style-src 'unsafe-inline'`). A Go template
   would duplicate every template in a second language and need its own
   font CSS. `frame-ancestors 'none'` + `X-Frame-Options: DENY` rule out an
   `<iframe>` preview, so the editor preview renders `FlyerFace` directly,
   scaled. **Route:** `/admin#/outreach?view=print&flyer=<id>&layout=full|half`,
   opened from the editor with `target="_blank" rel="noopener"`.
   - **Chrome-less page.** `FlyerPrint.svelte` puts its root
     (`.flyer-print-root`) directly under `<body>` with a small `portal`
     action (`document.body.appendChild(node)`, removed on destroy). It
     adds the class `flyer-print` to `<body>` in an `$effect` with cleanup.
     A global rule `body.flyer-print > :not(.flyer-print-root) { display:
     none !important; }` hides the site header, footer and admin nav on
     screen and in print. The toolbar inside the root is `@media print {
     display: none }`.
   - **`@page` scoping.** A `@page` rule in any bundled CSS would apply to
     every page of the site. So the view inserts `<style>` with the
     exported constant `PRINT_PAGE_CSS = '@page { size: letter portrait;
     margin: 0; }'` into `<head>` on mount and removes it on destroy.
     Sheets use `print-color-adjust: exact` (and the `-webkit-` form) so
     the photo-placeholder tint prints.
   - **Ready gate.** The Print button (`window.print()`) is disabled until
     `document.fonts.ready` has resolved and every `<img>` in the root has
     fired `load` or `error`. A failed image is listed in the toolbar.
6. **Layout geometry** (CSS inches; on screen 1in = 96px, so the mockups'
   pixel values divide by 96):
   - Sheet: `.sheet { width: 8.5in; height: 11in; position: relative;
     overflow: hidden; break-after: page; }` (the last sheet has `break-after:
     auto`).
   - **Full page:** one 8.5 × 11 in flyer per sheet.
   - **Half-size double:** each sheet holds two half slots `{ left: 0;
     top: 0 | 5.5in; width: 8.5in; height: 5.5in; overflow: hidden }`.
     Inside each slot the flyer is a 5.5 × 8.5 in portrait box at `left: 0;
     top: 5.5in; transform-origin: 0 0; transform: rotate(-90deg)`.
     Rotating −90° about the top-left corner maps (x, y) → (y, −x), so
     [0, 5.5] × [0, 8.5] becomes [0, 8.5] × [−5.5, 0], and the 5.5in top
     offset brings it to exactly [0, 8.5] × [0, 5.5], the slot. A dashed cut
     line is `top: 5.5in`, `border-top: 0.02in dashed #87977F`, full width,
     plus the small label "cut at 5.5 in" in 7pt mono.
   - **Safe area:** every flyer has `padding: 0.25in; box-sizing:
     border-box`. Text and QR live inside that padding. The photo may bleed
     into it only on the full-photo template, and even there the text band
     and QR stay inside.
   - **Fill order:** `expandCopies` turns the selection into a list of
     instances in location order (the store returns the selection ordered
     `lower(name), id`, with each location's copies consecutive). Full page:
     one sheet per instance. Half: instances are paired in order, first on
     the top half and second on the bottom. An odd total leaves the last
     bottom half blank, but the cut line is still drawn. Sheet counts are
     `n` and `ceil(n/2)`. A location with no link or no QR yet is **left
     out** of the print and listed in the toolbar ("2 locations have no QR
     code yet. Generate first.").
7. **Templates** (`'photo-top' | 'full-photo' | 'split'`). The list lives in
   the DB CHECK, the Go `outreach.FlyerTemplates`, and the TS
   `FLYER_TEMPLATES`. The palette is fixed light print (it ignores the site
   theme): ground `#FFFFFF`, ink `#10140F`, secondary `#3B4539`, accent
   `#30800C`, label `#5F6A5C`. Content comes from the server (decision 9),
   with the short URL shown without `https://`, the `open_circuit_sf`
   wordmark line in mono accent, and the location label `"<name> · <code>"`
   in 7pt (full) / 6pt (half) mono under the QR. QR size is 1.25in on a full
   page and 0.9in on a half. Title is 48pt / 30pt Archivo 800. Tagline and
   date/place lines are 16pt / 11–12pt.
   - **Photo top** (FlyerFull mockup): the photo fills the top 58% of the
     content box (the half flyer uses 53%). Below it, in order: title,
     tagline, date line and place line in accent, then a bottom row with
     the URL block on the left and QR + label on the right.
   - **Full photo:** the photo covers the whole flyer (bleed). A white
     band at the bottom, inside the safe area, holds title, lines, URL and
     QR. The band is white even though the mockup's thumbnail band is dark:
     the criterion fixes the light palette, and a QR needs a light quiet
     zone.
   - **Split:** photo on the left half, full height of the content box.
     Text column on the right, with the QR at the bottom of the text column.
   - **No "FREE WORKSHOP" badge.** The mockup has one, but `workshops` has
     no price field, so the flyer would assert something the data cannot
     back. Leave it out.
   - **No photo** (`photo` NULL): the photo box renders a flat `#EAF3E4`
     tint. Printing is still allowed.
8. **Focal-point crop, exact and clamped.** The photo is an `<img>` with
   `object-fit: cover`, and `object-position` comes from
   `coverPosition(img, box, focal)`. For scale `s = max(bw/iw, bh/ih)`,
   displayed size `dw = iw·s`, `dh = ih·s`, the left offset that centers
   the focal point is `L = bw/2 − fx·dw`, and `object-position` x% is
   `p = L / (bw − dw)` clamped to [0, 1] (0.5 when `dw == bw`). y works the
   same way. Box sizes are the template's photo box in inches (ratios are
   all that matter). The natural size comes from the loaded image
   (`naturalWidth`/`naturalHeight`). Until it loads, use
   `object-position: <fx·100>% <fy·100>%` as the approximation. The editor's
   focal marker can be dragged (pointer events → `focalFromPointer(x, y,
   rect)`, clamped to [0, 1]) and moved with the keyboard (arrow keys 2%,
   Shift 10%, via `nudgeFocal`). It has `role="slider"`-style labelling,
   with the value text "x 50%, y 40%".
9. **Server-shaped facts.** The flyer view carries `facts: { title,
   date_line, place_line, cover_image }`. `date_line` comes from the new
   pure `outreach.FlyerDateLine(startsAt, endsAt *time.Time) string` in
   `America/Los_Angeles` (reuse `templates.go`'s `pacific`): "Sat, Nov 14 ·
   10:00 AM–12:30 PM", "Date TBA" when start is nil, and no end part when
   end is nil or falls on a different day. `place_line` is `LocationName,
   LocationAddress`, joining whichever are non-empty, or "Location TBA". Do
   not add fields to `outreach.Facts`, because `Fingerprint` hashes it.
10. **Photo resolution warning** (pure `photoWarning(w, h, layout)`): full
    page warns when `w < 1275 || h < 1650` ("Photo is 1,080 × 1,350 px. A
    sharp full page needs 1,275 × 1,650 px or more; the half size is
    fine."). Half warns under 825 × 1,275 (5.5 × 8.5 in at 150 dpi). Both
    run in the editor under the photo and in the print toolbar for the
    chosen layout. The photo comes from the existing `POST
    /admin/media/upload` (`uploadMedia` in `api.ts`) or "Use cover image"
    (`facts.cover_image`). The server validates the stored `photo` with
    `isSafeCoverImage`, the same package and the same rule.
11. **Generate is bounded and resumable.** The whole call gets a 45 s
    context deadline (Apache's proxy timeout is its 60 s default, and the
    Go server sets none). Locations are processed in selection order. For
    each one: reuse the link row if it exists, otherwise `CreateLink` and
    then the transaction in decision 3. Then, if `qr_svg` IS NULL,
    `LinkQRSVG` → `SanitizeQRSVG` → `SetFlyerLinkQR`. On the deadline or any
    upstream error it stops and returns **200** with the flyer view plus
    `{ "remaining": k, "message": "…" }`, where the message is generic and
    the upstream text is only logged. Anything already done is saved, so
    clicking Generate again resumes. Exceptions: 503 when ShortLinks is not
    configured, 409 when the workshop is not published (same rule as
    `Prepare`), 409 `ErrLocationCodeChanged` ("a location's code changed;
    try again"), and 429 passed through `writeShortLinksError` only when
    nothing was done yet. A flyer can select at most **40** locations,
    copies are 1–50, and an inactive location cannot be newly selected
    (400).
12. **Put up** is per (workshop, location), on the link row:
    `POST /admin/outreach-flyer-links/{id}/put-up` sets `put_up_at =
    COALESCE(put_up_at, now())` (it keeps the first timestamp), and `DELETE`
    on the same path clears it (undo a mis-click). The button sits in the
    editor's generated-links list. The results table shows the date or
    "Not marked".
13. **"Flyers by location" results.** `GET
    /admin/workshops/{id}/outreach/results` gains `flyer_locations: [{
    link_id, location_id, name, code, short_url, put_up_at, clicks,
    clicks_all_workshops }]` and `flyer_all_status`, and `totals` gains
    `flyer_clicks`. `clicks` is the `by_link` count for the link's key from
    the rollup this handler already fetched: 0 when the link has no row,
    null when status ≠ ok. `res.UnmatchedClicks` is reduced by the flyer
    total, so `unmatched_clicks` stops counting flyers. `clicks_all_workshops`
    sums every outreach's flyer links for that location. The handler groups
    `ListAllFlyerLinks` by campaign, asks `h.stats.Get(slug,
    ResultsWindow(o.created_at, w.starts_at, now))` for each campaign (cached
    60 s), and adds up `by_link` per location. It stops after the first
    rejected or unreachable campaign, the same pattern as `ResultsSummary`.
    In that case every `clicks_all_workshops` is null and
    `flyer_all_status` names why. Partial sums would mislead, so they are
    never shown. The pure part is `outreach.FlyerClicksByKey(links, rollup)
    map[string]int64`. **Out of scope:** a "Flyer" line on the daily chart
    and a Flyer row in the posts table. Flyer daily clicks stay inside
    `#0546`'s "Other links" series, which still sums exactly. Note that in
    the UI and report the chart as a possible follow-up.
14. **"Download images" (mockup) is not in v1.** The criteria list print
    only, and rasterizing whole flyers would need a canvas pipeline. Each
    generated link row offers "QR (SVG)" (`<a href=".../qr.svg"
    download>`), which the endpoint provides anyway. Report a "download
    flyer images" follow-up if wanted.

### Steps

1. **Migration `000034_create_outreach_flyers`** (re-check the number,
   Obstacle 1). Up:

   ```sql
   -- #0549: printable flyers. A flyer is a design plus a selection of
   -- locations; the tracked link and QR belong to (outreach, location) so
   -- every flyer for the same workshop and location shares them
   -- (outreach_flyer_links_slot_unique).
   CREATE TABLE outreach_flyers (
       id          BIGSERIAL PRIMARY KEY,
       outreach_id BIGINT NOT NULL REFERENCES outreach(id) ON DELETE CASCADE,
       photo       TEXT,
       focal_x     REAL NOT NULL DEFAULT 0.5,
       focal_y     REAL NOT NULL DEFAULT 0.5,
       template    TEXT NOT NULL DEFAULT 'photo-top',
       tagline     TEXT NOT NULL DEFAULT '',
       created_at  TIMESTAMPTZ NOT NULL DEFAULT now(),
       updated_at  TIMESTAMPTZ,
       CONSTRAINT outreach_flyers_focal_check
           CHECK (focal_x BETWEEN 0 AND 1 AND focal_y BETWEEN 0 AND 1),
       CONSTRAINT outreach_flyers_template_check
           CHECK (template IN ('photo-top', 'full-photo', 'split')),
       CONSTRAINT outreach_flyers_tagline_check CHECK (char_length(tagline) <= 140)
   );
   CREATE INDEX outreach_flyers_outreach_idx ON outreach_flyers (outreach_id);

   CREATE TABLE outreach_flyer_locations (
       flyer_id    BIGINT NOT NULL REFERENCES outreach_flyers(id) ON DELETE CASCADE,
       location_id BIGINT NOT NULL REFERENCES outreach_locations(id) ON DELETE CASCADE,
       copies      INT NOT NULL DEFAULT 1,
       PRIMARY KEY (flyer_id, location_id),
       CONSTRAINT outreach_flyer_locations_copies_check CHECK (copies BETWEEN 1 AND 50)
   );

   CREATE TABLE outreach_flyer_links (
       id             BIGSERIAL PRIMARY KEY,
       outreach_id    BIGINT NOT NULL REFERENCES outreach(id) ON DELETE CASCADE,
       location_id    BIGINT NOT NULL REFERENCES outreach_locations(id) ON DELETE RESTRICT,
       short_link_key TEXT NOT NULL,
       short_url      TEXT NOT NULL,
       qr_svg         TEXT,
       put_up_at      TIMESTAMPTZ,
       created_at     TIMESTAMPTZ NOT NULL DEFAULT now(),
       CONSTRAINT outreach_flyer_links_slot_unique UNIQUE (outreach_id, location_id)
   );
   CREATE INDEX outreach_flyer_links_location_idx ON outreach_flyer_links (location_id);
   ```
