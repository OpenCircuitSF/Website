## Description

`outbox.Store.Counts` returns a sixth column beyond the five status counts:
`OldestQueuedAgeSecs`, built from a `min(created_at) FILTER` clause. **No test
asserts it.**

`#0390`'s review measured two independent mutations, each leaving
`internal/outbox` **fully green**:

- repointing the `FILTER` at the **abandoned** status rather than the queued one;
- **removing the `FILTER` entirely**, so the column reports the oldest row in
  any state.

So the admin delivery-health dashboard could report the oldest *abandoned*
row's age as "oldest queued age" and nothing in the tree would notice.

**This is the same family as `#0364`, `#0389` and `#0390`** — an assertion
passing for a reason that does not distinguish the thing it names, except here
the assertion is absent rather than weak. It sits in the **same query** those
issues have now hardened, and it is outside their five-column swap space
precisely because it is not one of the five counts.

**Unverified by the orchestrator.** The two mutations above are reported from
`#0390`'s review and have not been independently reproduced. Confirm them
before building on them, and correct this issue if they do not hold.

## The remedy's shape, from the review that found it

Same as `#0389`'s and `#0390`'s: **a moment where the measured quantity must be
attributable to the queued row and to nothing else.** Enqueue a row, let it age
past a measurable threshold, and assert the reported age tracks *that* row
while rows in other states are present and older or newer.

The discriminating property is the one `#0390` settled on: an **asymmetric**
window. If the queued row and an abandoned row are both present and the
assertion holds only when the age matches the queued one, relabelling the
filter cannot satisfy it. `#0390`'s own first attempt failed exactly because
its window moved two quantities by the same amount — see its `## Work log`.

## Acceptance criteria

1. A test fails under **both** mutations above: the `FILTER` repointed at
   `abandoned`, and the `FILTER` removed entirely. **Prove it by running those
   exact mutations** in a `git archive` export with your own database (§8b),
   never the tracked tree.
2. **Include an unmutated control row in the sweep and confirm it PASSES.**
   `#0390`'s review scored by `go test` exit code rather than grepping for
   `ok`, after an earlier sweep marked every mutant FAIL for an unrelated
   reason. Score by exit code.
3. Sweep the other plausible mutations of this column too — at minimum
   repointing the `FILTER` at each of the other four statuses — and report which
   are detected. A fix closing one while leaving three open should say so.
4. **Both halves of any new assertion must be load-bearing**: show each fires
   under some mutation and neither fires on unmutated code. `#0354`, `#0358`
   and `#0363` each shipped a check that could not fail, and it is the
   recurring defect of this phase.
5. The existing `Counts` coverage must not regress: **re-run `#0390`'s
   ten-swap sweep** and confirm it is still 10/10, plus `#0386`'s three mutants
   and `#0389`'s `mid.Queued`/`mid.Sent` probes.
6. **Mind the clock.** Any assertion resting on elapsed time is the shape §5
   warns about — do not size a threshold against measured machine load, and do
   not widen a deadline to accommodate a busy laptop. Prefer controlling
   `created_at` directly over sleeping, if the store permits it.
7. `TestOutbox_Counts` and any sibling must still pass **run alone**, with zero
   run-alone failures across the package. Measure the population yourself.
8. Per §5 name the specific tests that ran; the mailing subsystem needs
   Postgres. `gofmt` stability. Run `./internal/outbox/...` and
   `./internal/handlers/...` (`#0381`). No `.ClaimDue(` / `.OrphanSweep(` /
   `.SelectDue(` literal in any comment (`#0323`), scanned with `python3` bytes
   rather than BSD `grep -P`. No `<file>.go:<int>` citation (`#0352`).
