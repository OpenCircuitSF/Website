## Why this needs a planning pass first

`#0352`'s reviewer endorsed a **Phase 1 (Opus) planning pass** under §3's
"real design latitude" test, and named four decisions where two implementers
would build different things:

1. **Scan scope** — comments only, or all text? (A comment-scoped scan excludes
   runtime `%s:%d` format strings for free, since those live in string
   literals.)
2. **Citation versus fixture.** `outbox_kind_detection_test.go` cites *itself*
   inside an indented block that is a rendered `go test` failure transcript.
   `citation_target_guard_test.go`'s 11 are the citation guard's own prose
   *about* citations. Neither is a stale citation; both match any naive
   pattern.
3. **Fix all 30, or grandfather behind an allowlist?** An allowlist here is
   precisely §8's "a copy of the answer stored next to the question" hazard —
   and `#0337`'s `embeddingReviewed` allowlist, keyed on a name, was proved not
   to stay true.
4. **Where the oracle belongs**, per §8's direction-of-comparison rule: in Go,
   or in an external `scripts/check.sh guards` harness.

The existing `internal/handlers` citation-guard family — which already catches
comments citing unresolvable paths and undefined test functions — is **2,173
lines across three files** and took five issues of design iteration. That is the
scale being extended, and the reason this is not a mechanical pass.

## Plan

### 1. The census, re-measured by this planning pass

**Method — an AST tool, not a grep.** `census0356.go` (scratchpad
`plan0356/`) parses every `.go` file under the repo with
`parser.ParseComments`, pruning `node_modules`, `dist`, and `.git`, and scans
**only the tokens in `f.Comments`** — the file's comment groups. String
literals cannot enter the population by construction. The pattern is
deliberately **wider** than `<file>.go:<int>`:
`[A-Za-z0-9_./\-]+\.[A-Za-z]{1,8}:[0-9]+`, so `.md`, `.ts`, `.svelte` forms
are counted too and can be subtracted, rather than assumed absent.

**Proved falsifiable and fail-closed before it was trusted** (§8 — three
agents found genuine fail-opens in their own instruments this session). On a
fixture carrying one citation in a `//` comment, one in a `/* */` block, and
one inside a string literal next to a `%s:%d` format verb, it reported
**exactly the two comment citations and not the literal**. Zero files
visited, an empty root, and a missing root each produce an explicit
`VERDICT: ERROR` line and exit 1 — a zero census is never reported as
agreement.

**Result: 270 files parsed · 37 citations of any extension · 30 of them
`.go` · 7 files.** The 7 non-`.go` ones subtract cleanly — `PRD.md:671`
(`internal/db/prd_index_parity_test.go`), `citationGuard.test.ts:76` ×3 and
`WorkshopsIndex.svelte:7` ×2 and `docs/frontend.md:16`
(`citation_target_guard_test.go`) — leaving **30 across 7 files**, and the
per-file counts reproduce the reported table exactly: 11 / 11 / 3 / 2 / 1 /
1 / 1. The reported figure is confirmed; two of its **paths** are not (see
the correction under `## Description`).

Each citation was then resolved against the tree — target file located by
repo-relative path, then by sibling directory, then by basename — and the
current content of the cited line read.

### 3. Decision 1 — scan comments only

**Comments only.** Three reasons, in ascending weight:

1. It is what the census tool already does, and the fixture proves the
   exclusion works: a `bar.go:99` inside a string literal was not reported.
2. The false-positive class it removes is real and present. Beyond the
   `%s:%d` format verbs `#0352` named, the `t.Fatalf` calls in
   `outbox_kind_detection_test.go` at `:192` and `:251` *emit* `<file>:<int>`
   text at runtime; an all-text scan would have to reason about the
   difference between a citation and a diagnostic that produces one.
3. It is what makes the guard's own population stable. A comments-only census
   cannot be moved by a code edit, so `got` changes only when a comment
   changes — which is the property decision 4 depends on.

### 4. Decision 2 — fixture versus citation, by structure, never by accuracy

**Accuracy cannot be the discriminator, and this is measured, not argued.**
The `:30` transcript cites `:107` where the live `t.Fatalf` is at `:109` — an
accuracy test flags a fixture that is correct. All 11 in
`citation_target_guard_test.go` are accurate — an accuracy test clears 11
citations that are exactly as drift-prone as the 14 stale ones.

**The rule: exempt a citation only when all three of these hold**, each a
property of the text rather than a name in a list:

1. **The comment line is a gofmt preformatted line** — `//` followed by a
   **TAB** (§8's indented-block form, the only shape gofmt leaves alone).
   Measured: `indented=true` on exactly the 3 fixtures and `false` on all 27
   others.
2. **The citation is a self-citation** — the cited path resolves to the file
   the comment is in.
3. **The enclosing preformatted block carries a `go test` transcript
   marker** — a line matching `^\t=== RUN ` or `^\t--- (FAIL|PASS|SKIP): `.

All three are required. Any one alone is too weak: (1) exempts any indented
block; (2) exempts a stale self-citation; (3) is spoofable from an
unindented comment. Together they describe "a captured test transcript" and
nothing else in this tree.

**Why this is a rule and not `#0337`'s allowlist.** `embeddingReviewed` was
keyed on a *type name*, so it kept saying "reviewed" after the thing it named
changed underneath it — the answer stored next to the question. These three
predicates are read off the comment itself at scan time: a block that stops
being an indented self-citing transcript stops being exempt on the same edit,
with no list to update. There is nothing to decay.

### 5. Decision 3 — fix all 27, grandfather nothing

**Fix all 14 stale and all 13 currently-accurate citations. Exempt only the 3
fixtures, structurally.** The guard then asserts **zero non-exempt
citations**, which is the only floor with nothing to keep true.

The 13 accurate ones are the argument's real test, and they should still go.
They are not wrong today; they are wrong *tomorrow*, silently, for reasons
unrelated to them — which is the entire defect this issue names. Leaving them
means the guard needs a population to compare against, and a population is an
allowlist wearing a number.

**Replace with an identifier, never with the quoted text.** This matters
specifically in `citation_target_guard_test.go`, whose comments are scanned
by *its own* path-citation guard, and which deliberately does not spell out
`admin_workshops.go:25`'s four-segment token for exactly that reason (see its
`:257`–`:262` and `:290`–`:296`). Substituting the literal cited string would
inflate that guard's own population — `#0323`'s trap, in the one file where it
is guaranteed to fire.

### 6. Decision 4 — the oracle goes in both places, split by role

§8's test is the direction of the comparison and what a mutation leaves
falsifiable, and it gives different answers for the two things that can break.

- **The population assertion belongs in Go.** The mutation it exists to catch
  is *adding a positional citation to a Go comment*. That mutation moves
  `got` from 0 to 1 and the assertion `got == 0` fires. The in-package test is
  a legitimate, non-circular oracle: it measures comment text across 269 files
  and cannot be satisfied by a copy of its own answer.
- **The guard's own shape belongs in the external harness.** The other
  failure mode is "the checker was edited" — loosening the pattern, weakening
  the three-predicate exemption to one predicate, or deleting the assertion.
  §8 is explicit that a guard living in the file it guards is new mutable
  surface, and `#0258` spent six passes proving it. This project already has
  the right home: **`scripts/go_file_visit_floor_guard_test.sh`**, which
  exists precisely to pin `internal/handlers` guard constants from outside,
  already holds `citationGuardMinPlausibleFileCount`,
  `auditEmailMetadataMinPlausibleFileCount`, and
  `citedTestScanRootsMinPlausibleFileCount`, and is already wired into
  `scripts/check.sh guards`.

§8 says the two homes are not exclusive, and here they are complementary
rather than redundant: the Go test cannot detect that it was disarmed, and the
shell harness cannot count citations.

The harness's oracle must be a **regex over the guard file**, not a heredoc
copy of its text — `#0258`'s `FAILED=1` lesson, where one `sed` rewrote both
the definition and the expected copy and the guard agreed with itself.

### 7. The honest limit — this guard is narrower than the problem

`#0330` spent three passes discovering that the terminating move was
**deleting an overclaiming comment**, not adding another check, because a grep
cannot establish that a Go assertion is live. The analogous limit here is
sharper, and this pass measured it:

**A citation guard cannot establish that a citation is true.** It establishes
only that a positional citation *exists*. Telling the 14 stale from the 13
accurate took reading every target file, and for `logging_test.go` it took
knowing that `#0260` deleted the calls the comment describes — which no
pattern over the citing file could have told anyone.

So the guard's value is not detection of falsehood. It is that it enforces a
**convention** — no positional citations in Go comments — and a convention is
mechanically checkable where truth is not. The convention is worth having
because it converts a silently-drifting citation into a citation that can only
be invalidated by an edit to the thing it names (§11's heading-anchored
reasoning, and `#0352`'s review's principled version of it).

**Do not let this guard's greenness be read as "the comments are accurate."**
It says only "no comment states a line number." `#0347` carries the same
warning for its own family, and `logging_test.go:263` is the case that proves
neither family reaches the whole class: it is a stale citation (this guard
sees it) whose real defect is a false behaviour claim about deleted calls in a
*different package* (`#0347`'s file-local census does not see it, and its own
amendment already records that behaviour claims are invisible to that family).

### 8. One guard or two — recommend **two guards, one shared walker**

**Two.** They ask different questions, and — decisively — their exemption
models are **incompatible**:

- `#0347` must allow correctly-framed **history** (its criterion 3, confirmed
  by `#0342`'s sweep: historical references are common and legitimate).
- `#0356` must **not**. A historical positional citation drifts exactly as
  silently as a present-tense one, and the three fixtures here are exempt for
  a structural reason — a captured transcript — not a historical one.

Fusing them would import `#0347`'s history allowance into this class and
reopen it. They also differ in what they must parse: `#0347` needs a mode-`0`
code census of the *same file* to answer "does this file call it"; `#0356`
needs no code census at all.

What they should share is the **walk**, not the assertion: one
`ParseComments` traversal of `internal/` + `cmd/` with the family's existing
`goFileVisitCountImplausible` floor discipline. Two guards, two failure
messages that each name their own rule, one helper.

**Sequencing:** `#0347` is already filed with criteria and an amendment, and
its census helper is the shared piece — land it first. **Do not run `#0347`
and `#0356` concurrently**; both edit the `internal/handlers` guard family.
