## Description

`internal/subscribers/imports_test.go` calls
`store.Revoke(ctx, 1, "   ", …)` — a **hardcoded import id**.

Today the blank-reason check returns before `pool.Begin`, so nothing is reached.
**But that check is precisely what a mutation proving this test discriminates
would remove** — and `ImportStore.Revoke` then runs the full transaction against
import **id 1**: unsubscribing every subscriber attributed to it and flipping it
to `revoked`.

**Found the hard way.** `#0383`/`#0385`'s reviewer hit this while performing
exactly that mutation. It was harmless only because its private database had no
row with id 1.

**This is the shape `#0372` and `#0376` swept for, and it was missed** because
the id is a **Go function argument**, not a URL path — both surveys keyed on
request paths.

§8b exists because of this class: `#0024`'s guard-removal proof aimed a `DELETE`
at a hardcoded `/admin/interests/1` and permanently destroyed a seeded taxonomy
row.

The sibling `TestImportStore_Revoke_UnknownID` uses id `0`, which is safe.

## Root cause

`TestImportStore_Revoke_RequiresReason` (`internal/subscribers/imports_test.go`)
called `store.Revoke(context.Background(), 1, "   ", time.Now())` directly, with
no row of its own backing that id. `ImportStore.Revoke`
(`internal/subscribers/imports.go`) checks `reason == ""` and returns
`ErrRevokeReasonRequired` before ever calling `pool.Begin`, so today the literal
`1` is never read. But that check is precisely the line a mutation-testing pass
proving this test discriminates would remove, and with it gone `Revoke` runs its
full transaction against whatever import id 1 is: `SELECT ... FOR UPDATE`,
unsubscribing every attributed subscriber, and marking the import `revoked`.

## Fix

Chose **the seeded throwaway row**, not a nonexistent sentinel (`#0376`'s
`999999999`). The two are not equivalent here: a sentinel only proves the guard
fires *before a lookup returns not-found* — with the guard removed, a
nonexistent id still produces a different-but-harmless outcome
(`ErrImportNotFound`), so a test built that way could not detect the guard's
removal via the destructive path at all, only via the error's identity. The
side effect this guard is standing in front of is destructive (revoke +
mass-unsubscribe), so the test needs to prove the guard fires **before that
side effect reaches a real row** — which requires the row to be real.

The rewritten test seeds one throwaway import via `store.Commit` (using the
existing `validCommitInput`/`uniqueImportEmail` helpers already used
throughout this file) and calls `Revoke` against its own id with a blank
reason. It then asserts, beyond the error value, that the seeded import's
`Status` is not `revoked` and that its subscriber's `Status` is not
`unsubscribed` — those two assertions are what make the guard's *ordering*
(before the side effect, not just before the return) provable, and what fail
when the guard is removed (see `## Verification`'s mutation proof).

## Survey (criterion 3) — argument-shaped hardcoded ids beyond this instance

`.Method(ctx, <int literal>, ...)` and `.Method(context.Background(), <int
literal>, ...)` — the exact shape this issue reports — across every
`*_test.go` file in the tree (156 files). **Self-tested on four probes before
trusting any result**, including the specific fail-open `#0372`'s reviewer hit
(a `\b`-anchored verb regex can't hold between a quote and a comma): (1) the
literal `#0388` shape with `context.Background()` — found; (2) a bare `ctx`

as a different argument — correctly **not** flagged, since a `"` immediately
breaks the `\d+` match; (4) the sibling's own safe `id 0` sentinel — found (so
a human, not the regex, judges its safety). All four passed before the real
scan ran.

## Acceptance criteria

1. The test seeds a throwaway import and targets **its** id, or uses a
   nonexistent sentinel (`#0376` used `999999999`). Say which you chose and why
   — they are not equivalent: a sentinel proves the guard fires **before
   lookup**, a seeded row proves it fires **before the side effect**. Here the
   side effect is destructive, which argues for the seeded row.
2. **Prove it still discriminates** by removing the blank-reason check — safe
   once the target is throwaway or nonexistent. That proof is the deliverable;
   it is currently the assertion nobody can safely make.
3. **Survey for the argument-shaped instance of this class**, which both prior
   sweeps missed: any test passing a small literal id **as a Go argument** to a
   store or service method with a destructive effect. `#0372`'s and `#0376`'s
   surveys keyed on HTTP paths and would not see it. **Report what you find;
   fix only `internal/subscribers`.** Note `#0372`'s reviewer's own scanner
   under-reported once because it anchored a regex with `\b`, so **self-test
   your survey before trusting a clean result.**
4. §8b: mutations run against **your own database**
   (`ISSUE=NNNN scripts/check.sh`), never the shared `opencircuit_test`. Do not
   rely on a private database happening to lack the row — that is what made
