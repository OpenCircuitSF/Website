## Description

The four non-campaign messages the system sends: confirm your subscription, already subscribed, passkey registration magic link, and account recovery.

## Acceptance criteria

- [ ] Confirmation email with the `/confirm?token=` link, 7-day expiry stated, and a plain "if you didn't request this, ignore it" line
- [ ] Already-subscribed email carrying the preference-center link instead of a confirmation link
- [ ] Registration and recovery magic-link emails re-themed from the ShortLinks originals
- [ ] Every message sent as HTML plus plain text, both rendered from one source
- [ ] HTML uses inline styles and a single-column table layout — no `<style>` reliance, no flexbox, no CSS custom properties
- [ ] Outer table carries an explicit `background-color` (Outlook ignores `body` backgrounds)
- [ ] Physical mailing address included in the footer of the subscription-related messages
- [ ] Rendered output checked in Gmail web, Apple Mail, and Outlook
- [ ] Golden-file tests assert the rendered HTML and text for each template

## Notes

PRD §6.6. Email clients are not browsers. The terminal aesthetic translates as dark background, mono headers, and green accents — but it has to be built with 2005-era HTML techniques.

Transactional confirmation mail does not strictly require the CAN-SPAM physical address (it is not commercial mail), but including it is harmless and avoids a per-template judgment call later. Campaign mail absolutely requires it — see #0045.
