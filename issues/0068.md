## Description

[#0066](0066.md) purged ShortLinks identifiers from `internal/`, `web/src/`, and `deploy/`, which is what its grep-based acceptance criteria covered. Residue survives outside that scope, and one item is a live defect rather than a cosmetic one: `scripts/deploy.sh` builds a Go package that was deleted in `#0001`.

Found during `#0066`'s review.

## Root cause

`#0066`'s acceptance criteria were grep-scoped to `internal/`, `web/src/`, and
`deploy/`. Everything named in this issue's `## Actual behavior` sits outside
that scope — `scripts/`, `web/embed.go` (in `web/`, not `web/src/`), and
`internal/audit/actions.go` (which `#0066` deliberately left as dead code,
but stripped the `#0099` issue-number marker that had been the only signal
the `campaign.*` block was foreign, per this issue's Notes).

## Fix

- **`scripts/deploy.sh`** — retargeted the header comment, the `SERVICE`
  default (`shortlinks` → `opencircuit`), the `PUBLIC_URL` default
  (`https://go.sstools.co` → `https://www.opencircuitsf.com`, the canonical
  host per `CLAUDE.md` §7), and the `go build` line (`./cmd/shortlinks` →
  `./cmd/opencircuit`, the actual dead path).
- **`scripts/db-status.sh`** — not named in the issue's `## Actual behavior`,
  but found while scoping the repo-wide grep criterion and squarely the same
  class of live defect as `deploy.sh`: it read `SHORTLINKS_DB` (default
  `shortlinks`) instead of this project's database name, and its final
  `--- counts ---` query selected `count(*) FROM links` — this project has no
  `links` table (confirmed via `grep -h "^CREATE TABLE" migrations/*.up.sql`;
  `#0002` deleted `internal/links`, per PRD §3.2). Run against a real
  `opencircuit` database this script would have errored outright on that last
  query. Retargeted the DB env var/default to `OPENCIRCUIT_DB`/`opencircuit`,
  the banner text, and removed the `links` count.
- **`web/package.json`** — renamed to `opencircuit-web`; ran `npm install`
  (not a hand-edit) so `package-lock.json` regenerated its `name` fields
  consistently.
- **`web/embed.go`** — comment now says `cmd/opencircuit/`.
- **`internal/audit/actions.go`** — checked first, per the issue's own
  instruction ("Deleting is cleaner if nothing references them — check
  first"): `grep -rn "ActionCampaign\|TargetCampaign" --include="*.go" .`
  outside `actions.go` returned nothing. Deleted
  `ActionCampaignCreated`/`Updated`/`Deleted`,
  `ActionCampaignLinkAssigned`/`Unassigned`, and `TargetCampaign` outright
  rather than leaving them commented-in-place, and replaced them with a
  comment block explaining what was deleted, why (ShortLinks'
  `campaigns.Store`, deleted in `#0002`), and that reuse for
  `email_campaigns` needs new `email_campaign.*` constants instead. This
  reads as a stronger fix than "comment the existing constants loudly" — a
  Phase 5 implementer searching the file for something campaign-shaped now
  finds an explanation instead of live, importable, wrong-meaning constants
  to accidentally reuse.

## Actual behavior

- **`scripts/deploy.sh:82` runs `go build -o "$TMPBIN" ./cmd/shortlinks`.** That directory has not existed since `#0001` renamed it to `cmd/opencircuit`. The deploy script cannot succeed. Line 31 also defaults `SERVICE=shortlinks`, now inconsistent with the `opencircuit.service` unit that `#0066` created, and line 25's usage example cites `go.sstools.co`.
- **`web/package.json:2` declares `"name": "shortlinks-web"`**, echoed in `package-lock.json`. It prints on every `npm run`.
- **`web/embed.go:6`** refers to `cmd/shortlinks/` in a comment explaining why the embed lives in `web/`.
- **`internal/audit/actions.go:52-56`** documents an API that does not exist: "Written by `campaigns.Store`'s `AssignLinkToCampaign`/`UnassignLinkFromCampaign` … see the doc comment on those methods". There is no `internal/campaigns` package — `#0002` deleted it. `#0066` stripped the `#0099` marker from this block, which removed the only signal it was foreign, so it now reads *more* authoritative than it did before.

## Notes

**The `campaign.*` naming trap is the part with teeth.** `internal/audit/actions.go` defines `ActionCampaignCreated`, `ActionCampaignDeleted`, `ActionCampaignLinkAssigned`, and `ActionCampaignLinkUnassigned`. These are ShortLinks' concept — *grouping short links* — and have nothing to do with this project's `email_campaigns`, a message sent to a segment. `CLAUDE.md` §6 and PRD §3.2 both warn that the two share a word and nothing else.

A Phase 5 implementer working `#0044`–`#0048` will search the audit actions for something campaign-shaped, find these, and reuse them. The audit log would then record email-campaign events under action names that mean link-grouping. Either delete the constants outright or comment them loudly enough that reuse is obviously wrong. Deleting is cleaner if nothing references them — check first.

`#0066` deliberately left these constants as dead code, judging removal to be a different kind of change. That judgement was reasonable in isolation, but stripping the issue numbers while leaving prose describing phantom methods produced the worst of both options.

```bash
export PATH="<scratch>/stubbin:$PATH"   # a stub `systemctl` that only
                                         # satisfies the preflight
                                         # `command -v systemctl` check —
                                         # it exits 1 loudly if ever actually
                                         # invoked, and isn't, because:
export BIN="<scratch>/fake-opencircuit-bin"   # set explicitly, so the
                                               # script's systemctl-based BIN
                                               # lookup branch is skipped
export SERVICE="opencircuit"
export PUBLIC_URL="http://127.0.0.1:1/"       # deliberately unreachable —
                                               # fails instantly (connection
                                               # refused), so the pre-build
                                               # LIVE_BEFORE curl never
                                               # reaches any real host
printf 'n\n' | bash ./scripts/deploy.sh
```

Observed output (abridged): Preflight passed (`service 'opencircuit' runs:
<fake path>`, `live now: <unreachable>`) → **gate 1** ran `npm install` +
`npm run build` for real and reported `SPA built: index-BqXEgVvP.js,
index-DVjFp6YK.css` → **gate 2** ran `go build -o "$TMPBIN" ./cmd/opencircuit`
for real and reported `binary verified to embed index-BqXEgVvP.js` (proving
the fixed `./cmd/opencircuit` path actually builds and the freshly built
binary really embeds the SPA it just built) → **gate 3** printed the
`[y/N]` prompt; answering `n` produced `Aborted before restart. The verified
fresh binary is left at: <tmpfile>` and the script exited cleanly.

**This is exactly where I stopped.** No `sudo`, no `systemctl restart`, no
install to a real path, and no request to the live `opencircuitsf.com`
domain was ever issued — the only network call the run made was the
guaranteed-instant-failure `curl` to `127.0.0.1:1`. The temp binary the
script produced was deleted afterward and never installed anywhere.

## Gotchas

- **The literal repo-wide grep acceptance criterion does not pass**, and I
  did not force it to. After the fixes above,
  `grep -rln 'shortlinks\|ShortLinks\|sstools' . --exclude-dir=.git
  --exclude-dir=node_modules` still lists, beyond `PRD.md`/`HANDOFF.md`/
  `CLAUDE.md`/`issues/`: `README.md`, `.gitignore`,
  `migrations/000007_enforce_session_passkey_not_null.{up,down}.sql`,
  `web/vite.config.ts`, `cmd/opencircuit/seed.go`,
  `internal/audit/actions.go` (this issue's own new explanatory comment),
  every file under `docs/`, and `scripts/db/{backup,restore,pull-backups}.sh`
  + `scripts/db/README.md`. I read every one of these before leaving it:
  - `README.md`, `.gitignore`, the `migrations/000007` pair, `web/vite.config.ts`,
    `cmd/opencircuit/seed.go`, and every `docs/*.md` hit are accurate,
    deliberate provenance/historical prose — "ported from ShortLinks
    migration 000013," "the separate ShortLinks deploy at
    go.opencircuitsf.com is not this site," "this bit the ShortLinks repo
    (its issue #0001)," and so on. This is the same style `CLAUDE.md` and
    `PRD.md` themselves use throughout, and it is factually correct — go.
    opencircuitsf.com genuinely is a separate real ShortLinks deploy.
    Scrubbing these would make the documentation *less* accurate, not more,
    and I judged the four-file allowlist in the acceptance criterion to be
    an oversight from when it was filed (a quick grep at filing time,
    not a full audit) rather than a considered instruction to gut the
    project's own documented provenance trail. I left them and flag this
    explicitly rather than silently declaring the criterion met.
  - `scripts/db/backup.sh`, `restore.sh`, `pull-backups.sh`, and
    `scripts/db/README.md` still default to the ShortLinks database name
    (`shortlinks`) and, for `pull-backups.sh`, host `go.sstools.co`. I did
    **not** retarget these. `docs/deployment.md` (pre-existing text, not
    written by me) already documents them as "already present in this repo,
    copied in `#0001`, not yet retargeted at the opencircuit database," and
    `#0062` ("Verify the database backup and restore path") is the issue
    that actually exercises backup/restore end to end. Renaming defaults in
    scripts I cannot run against real infrastructure — no S3 target, no
    scratch database to restore into, no way to prove a restore still
    works — is exactly the "script that has never been executed is a draft"
    failure mode this issue itself warns against for `deploy.sh`. I judged
    leaving them for `#0062` (which can actually test a real restore) safer
    than a blind rename I cannot verify. Flagging for the reviewer in case
    this reading is wrong.
- **`internal/audit/actions.go` still contains the word "ShortLinks."** This
  is unavoidable and intentional: satisfying the acceptance criterion just
  above it ("carry an explicit warning...") requires saying what the
  deleted constants were, i.e. ShortLinks' concept. The comment is the
  warning; it cannot both explain the trap and never say the word.
- `npm install` (not `npm ci`) was used to regenerate `package-lock.json`
  after the `package.json` rename — `npm ci` requires the lockfile to
  already match `package.json` exactly, which is precisely what was stale
  here.
