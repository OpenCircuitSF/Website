# 0065 — The config test helper omits BASE_URL, so TestLoad_DefaultsApplied fails

| | |
|---|---|

## Description

`go test ./...` exits non-zero on a clean checkout: `internal/config` `TestLoad_DefaultsApplied` fails with `config: missing required variable BASE_URL`. The `setRequired` test helper sets five of the loader's six required variables and silently omits `BASE_URL`, so any test relying on the helper alone cannot construct a valid config.

Carried over from ShortLinks — it fails identically there at `bbdd0f7`, so the port did not introduce it. `#0001` recorded it as pre-existing rather than fixing it, which was correct for that issue's scope. This issue closes it.

## Steps to reproduce

1. `cd /Users/brennan/Developer/OpenCircuitSF/Website`
2. `go test ./internal/config/ -run TestLoad_DefaultsApplied -v`

## Expected behavior

The test constructs a config from the five required variables plus defaults and asserts that `PORT`, `SES_SMTP_PORT`, `CACHE_MAX_COST`, and `CACHE_TTL_SECONDS` fall back to their default values. It should pass.

## Actual behavior

`loadFromFile` returns `config: missing required variable BASE_URL` and the test fails at `config_test.go:74` before reaching a single default assertion.

## Root cause

`setRequired` (`internal/config/config_test.go:14`) sets `DATABASE_URL`, `WEBAUTHN_RP_ID`, `WEBAUTHN_RP_ORIGIN`, `SESSION_SECRET`, and `ADMIN_EMAIL`. The loader's required list (`internal/config/config.go:112`) has six entries — the same five plus `BASE_URL`. The helper's name promises every required variable; it delivers five of six.

The other tests hide the gap:

- `TestLoad_AllRequiredPresent` sets `BASE_URL` explicitly on its own, so it never depends on the helper.
- `TestLoad_MissingRequired` and `TestLoad_MissingRequiredReportsAll` expect an error and assert only that the message *contains* the variable under test. A spurious `BASE_URL` entry in that message changes nothing, so they pass regardless.

`TestLoad_DefaultsApplied` is the only test that depends on `setRequired` producing a *valid* config, so it is the only one that fails.

## Notes

Fix the helper, not the loader. `BASE_URL` is genuinely required: it is the canonical origin used to build confirmation and unsubscribe links, and a config without it would produce broken links in email rather than failing loudly at startup. Making it optional would trade a startup error for a silent production defect.

**Out of scope, deliberately.** The helper's values are still ShortLinks-flavoured (`go.sstools.co`), and `.env.example` still points at `go.sstools.co` and the `shortlinks` database. Those belong to [#0007](0007.md), which rewrites the config loader and its environment for this project. Do not rebrand them here — this issue makes the suite green and nothing else.

Keep the value used for `BASE_URL` consistent with the existing helper entries so the diff stays a single added line plus the new table case.
