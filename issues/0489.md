## Description

`scripts/go_file_visit_floor_guard_test.sh` **exits 1 on `HEAD`**, with two
failures in its `internal/handlers` citation-guard section. Reproduced by the
orchestrator directly:

	FAIL: REGRESSION #0300: committed citedTestScanRootsMinPlausibleFileCount=150
	is NOT plausible against an externally-measured population of 305 ...
	(floor must stay >= population/2 ...)

	FAIL: REGRESSION #0300: committed lineCitationGuardMinPlausibleFileCount=150
	is NOT plausible against an externally-measured population of 305 ...

Both constants are `150`; the measured population is `305`; the rule the guard
enforces is `floor >= population/2`, so the threshold is `152.5`. The tree grew
past the margin and the floors did not follow.

The affected guards are named in the failure text:
`TestNoCommentCitesUnresolvedPathOrSection`,
`TestNoCommentCitesUndefinedTestFunction`,
`TestNoDocCommentNamesADifferentDeclarationInSameFile`, and
`TestNoCommentCitesGoFileByLineNumber`.

## This is the good failure mode, not the bad one

`#0483`, `#0487`, and `#0488` fixed four exact counts that had drifted **and
gone unnoticed**, because a floor only catches shrinks. **This floor is
different: it has a growth-ceiling check, and that check works.** It is telling
us, correctly and by name, that the population has outgrown the margin.

So the defect is not the mechanism. It is that **nobody ran it.**
`CLAUDE.md` §5 puts this harness behind `scripts/check.sh guards`, which is
deliberately excluded from `go`, `web`, `all`, and the default — `dev_guard_test.sh`
alone costs ~48s and binds `:5173`. So an ordinary verification never touches
it, and today `:5173` is held by orphaned processes, which makes running the
suite as a unit awkward besides.

Four separate agents ran this harness today by invoking it directly, and each
reported its own sections passing. None was asked about the file's exit code.

## A fifth stale-count instance lives in this same file

Found by `#0488`'s review. `outbox_floor_plausible`'s own header comment says
`citedTestScanRootsMinPlausibleFileCount` "sits at floor=150 against a
re-measured population of 267" and "does not fail until the population reaches
roughly 302".

**The same script measured 305 and reported that floor failing on the same
run** — a prediction its own container contradicts within one terminal scroll.
Two lesser stale figures sit in the same paragraph: "non-exempt floor is 6"
against a committed 8, and "~20 of 32".

`#0488` deliberately did **not** fix that paragraph, because its wording
depends on whatever this issue does to the floors. **It is yours.** Whatever
value you choose in criterion 2, this prose must describe it — and per
criterion 5, prose that must be hand-updated as the tree grows is the shape
that produced all five instances.

Why `#0488`'s sweep missed it, which is worth knowing before you write a
replacement: it is a `.sh` header phrased "a re-measured population of 267",
and the constant was checked at its own declaration, where it *is* framed
historically. A search for the shapes that caught the other four does not
reach it.

Four other floor constants were enumerated and read in that sweep —
`repoWideGuardScanFileFloor`, `repoWideGuardScanDirFloor`,
`migrationCitationMinPlausibleCitationCount`, and its identifier sibling. All
are historically framed and carry no defect.

## Acceptance criteria

1. **Re-derive the population yourself** — 305 is the orchestrator's single
   measurement. Six premises have been corrected by measurement in this project
   recently; do not be the seventh.
2. **Raise both floors** to satisfy the rule, and say what value you chose and
   why. Note the rule is a *ratio*, so the new value should leave headroom for
   ordinary growth rather than sitting one file above the line and failing again
   next week.
3. **Do not weaken the growth-ceiling rule** to make the failure go away. It is
   the only mechanism in this family that catches growth at all, and the four
   issues above exist because the others do not.
4. **Prove both directions still work**: the floors must still fail when the
   tree shrinks, and the ceiling must still fail when the population outgrows
   the margin. Mutate a copy, never `git stash` (`CLAUDE.md` §8a), and restore
   byte-identically with SHA-256.
5. **Decide what stops this recurring.** A floor that must be hand-raised as the
   tree grows will drift again; that is the same shape as the exact counts, one
   level up. Options include deriving the floor from the population at run time
   (which weakens it to a tautology — say so if you reject it), widening the
   margin, or surfacing the harness somewhere an ordinary run reaches. **Pick
   one and justify it.**
6. **Say whether `scripts/check.sh guards` should stay out of the default.**
   `CLAUDE.md` §5's reason is cost and the `:5173` bind, both real. If it stays
   out, name what else would have caught this — an exit-code check in CI, a note
   in the phase-3 step, or something else. The status quo demonstrably did not.
