## Description

User report, 2026-11-17: sharing `https://www.opencircuitsf.com/guides/bjt-vs-mosfet` to Apple Messages showed the title "Guides" and the default `/og-default.png` card, while Bluesky showed the guide's own art (`#0709`).

Cause, from the production access log: Messages did not fetch the page. Sharing from Safari, LinkPresentation read the metadata from the **open tab's live DOM**. The user had loaded `/guides` and navigated client-side to the guide. The SPA updates `document.title` on navigation (`#0238`, `web/src/lib/pageTitle.ts`, `App.svelte`), but never the `<head>` meta the server rendered for the first page: `og:title`, `og:description`, `og:image`, `og:url`, `twitter:*`, `description`, and `link rel=canonical`. So the tab still carried `/guides`'s preview meta. The log shows `com.apple.WebKit.Networking` fetching `/og-default.png` at 01:41:43 UTC, and no document request for the guide from that client.

Crawlers and Bluesky fetch the URL fresh and get correct server-rendered meta (`internal/seo`), so only live-tab sharing (Safari share sheet, Messages, Notes, AirDrop, possibly Chrome's share) is affected.

Fix: on client-side navigation, update the head meta to match what the server would render for the new route — at minimum `og:title`, `og:description`, `og:url`, `og:image`, `link rel=canonical` and `meta name=description`, with `og:image` using the guide's `/guides/{slug}/og.png` URL. The `?v=` hash isn't known client-side; decide whether that matters for live-tab sharing (it reads the DOM, not a cache keyed on the URL). Keep a single source of truth with the server where practical (the server already knows each route's meta; the SPA has the guide catalog in `web/src/content/guides/guides.json`).

## Plan

Written 2026-11-17, phase 1 (Opus · medium).

**Design in one line:** add one small read-only JSON route, `GET /api/page-meta?path=/guides/x`, that returns exactly the `RouteMeta` the server would substitute into that path's `<head>`. On every client-side navigation (never the first load), the SPA fetches it and writes the values into the existing head tags. The client keeps no copy of any meta text or rule, so there is nothing to drift.

### Settled points

1. **Ask the server rather than mirror it in TypeScript.** The alternative, a pure-TS `metaForRoute(route)` plus a parity guard, was considered and rejected:
   - **Guides** could be mirrored from `guides.json`. But the **static pages** (`/`, `/about`, `/privacy`, `/events`, `/subscribe`, `/archive`, `/guides`) hold their copy only in `internal/seo/seo.go`'s `defaultStaticRouteMeta`. Mirroring them means either a second copy of the strings or a refactor moving them into a shared JSON file.
   - **Event detail** meta depends on Go-only rules: the `cover_image` override, `workshopIsCardable`, and canceled workshops falling back to generic meta.
   - **Archive detail** depends on `archiveDescription(e)`, which derives the description from the email body.
   - A mirror would therefore either skip events and archive, which are the next most-shared pages after guides, or re-implement those rules in TS behind a large committed fixture that every new guide must regenerate.

   The endpoint calls the very `Renderer.resolve` that `Render` uses. Parity is structural, every route is covered, and the guard reduces to "the endpoint equals the rendered head".

   Cost: one small same-origin request per navigation. It does a single indexed store read, and only for `/events/{slug}` and `/archive/{slug}`, which is the same read an HTML request does. The guides, static and fallback cases are map lookups. PRD §7.6's "0 external requests" still holds because the request is same-origin.
2. **`?v=` stops being a question.** The endpoint returns `og:image` exactly as the server renders it, `?v=<hash>` included. For the record: a stable `/guides/{slug}/og.png` would also have worked for live-tab sharing. The production log shows `com.apple.WebKit.Networking` fetching the image itself, an ordinary HTTP fetch that honours `max-age=3600`/ETag revalidation, not a third-party unfurl cache keyed on the URL. But there is no reason to accept a difference that is free to avoid.
3. **First load: leave it alone.** The server-rendered head is already correct, which is the same split `#0238` made for `document.title`. The update goes inside the existing `if (!shouldAnnounceNavigation()) return;` branch of `App.svelte`'s route-change effect, directly after `document.title = titleForRoute(route);`. A popstate back to the first-loaded page counts as a navigation, so it re-fetches and gets the correct values.
4. **`document.title` keeps coming from `pageTitle.ts`, not the endpoint's `title`.** `#0238` deliberately makes the tab title match the on-screen `<h1>`. For guides, `formatTitle(topic.title)` already equals the server's `Title` byte for byte. For static pages the two intentionally differ (the server's are SEO-tuned). Share sheets use `og:title`, which this issue does update. The endpoint still returns `title`, for completeness and for the parity test, and the client ignores it.
5. **Fields written:** `meta[name=description]`, `og:title`, `og:description`, `og:image`, `og:url`, `og:type`, `twitter:card`, `twitter:title` (= `og_title`, as `#0273` substitutes it), `twitter:description` (= `og_description`), and `link[rel=canonical]`. The canonical link is **created** when the response carries one and **removed** when it doesn't. The fallback and not-found buckets carry none, which is what restores generic meta and removes a lingering guide canonical (criterion 3). `og:site_name` is a static literal and is left alone.
6. **Not updated: JSON-LD (`%%OC_JSONLD%%`).** Crawlers fetch fresh HTML, and share sheets don't read JSON-LD. Leaving a previous page's `<script type="application/ld+json">` in a live tab affects nothing that reads it. This is out of scope and disclosed in `## Fix`.
7. **Routes covered: every route, at exactly the server's values.**
   - Guides: `/guides/{slug}` and the workshop guide `/workshops/{slug}`, whose `og:image` is `/guides/{slug}/og.png`.
   - The seven static pages.
   - `/events/{slug}`: a published event gets its own meta; a canceled, draft or unknown slug gets the generic fallback, as on the server.
   - `/archive/{slug}`.
   - The private and token routes (`/login`, `/confirm`, `/preferences`, `/unsubscribe`, ...) get the generic fallback.
   - Unknown paths get the not-found meta.

   Under `STORAGE=json`, `/events/{slug}` and `/archive/{slug}` resolve to the fallback because there is no source, which is the same as the server's HTML there.
8. **Privacy: only the pathname is sent.** The client passes `route.path`, the normalized pathname with no query. Token-bearing query strings (`/confirm?token=…`, `/unsubscribe?token=…`) never reach the endpoint or its access-log line. A test pins this.
9. **Failure is quiet but bounded.**
   - A failed fetch (offline, 5xx) leaves the head as it was and logs `console.warn` once. It does not invent client-side values, since that would reintroduce a second source of truth.
   - A **stale** response is never applied. A module-level sequence number is taken per call, and a response applies only if it is still the latest. This means a slow `/guides/x` answer arriving after the user has already moved to `/about` cannot overwrite `/about`'s meta.
   - The one remaining gap is staying offline after navigating, which is disclosed.

### Approach

1. **`internal/seo/pagemeta.go`.**
   - `func (r *Renderer) Meta(path string) RouteMeta { _, m := r.resolve(normalizePath(path)); return m }`. Doc comment: the same resolution `Render` substitutes (`#0711`).
   - The type `pageMetaJSON`, with snake_case JSON tags as the rest of the public API uses: `title`, `description`, `og_title`, `og_description`, `og_image`, `og_url`, `og_type`, `twitter_card`, and `canonical` with `omitempty`. It deliberately has no JSON-LD and no `page`.
   - `func (s *Site) PageMetaHandler() http.HandlerFunc`:
     - Read `p := r.URL.Query().Get("path")`.
     - Reply `400` (plain `http.Error`) when `p` is empty, doesn't start with `/`, or is longer than 1024 bytes.
     - Otherwise `m := s.renderer.Meta(p)`, set `Content-Type: application/json`, and `json.NewEncoder(w).Encode(pageMetaJSON{...})`.
     - Set no `Cache-Control`, as with `GET /api/workshops/{slug}`: event meta changes on admin edits.
     - No rate limiter: the work done is no more than serving the HTML page itself, and HTML pages carry none.
2. **`cmd/opencircuit/main.go`.** Directly after `mux.Handle("GET /robots.txt", site.RobotsHandler())`, add `mux.Handle("GET /api/page-meta", site.PageMetaHandler())`, with a short `#0711` comment saying it is public, read-only, and has the same trust level as the HTML it describes. It sits outside every `if xH != nil` block because `site` is always non-nil, so `STORAGE=json` gets it too. `robots.go` already disallows `/api`, so there is nothing to add there.
3. **`web/src/lib/pageMeta.ts`.**
   - Define `export interface PageMeta` with the JSON's snake_case fields, `canonical?: string`.
   - `export function applyPageMeta(doc: Document, m: PageMeta): void`:
     - A private `setMeta(doc, attr: 'name' | 'property', key, value)` finds `meta[${attr}="${key}"]` and creates it in `doc.head` if it is missing, then sets `content`. Use it for the 10 tags in point 5.
     - For canonical: find `link[rel="canonical"]`. If `m.canonical` is set, create the link if missing and set `href`; otherwise remove it.
   - `let seq = 0;` and `export async function updatePageMetaFor(path: string, doc: Document = document): Promise<void>`:
     - `const mine = ++seq;`, then `apiGet<PageMeta>('/api/page-meta?path=' + encodeURIComponent(path))`.
     - On success, apply only `if (mine === seq)`.
     - On a catch, `console.warn('page meta: …', err)` and return.
   - Module doc comment: why this exists (live-tab sharing reads the DOM, as in the production log above), why it asks the server instead of mirroring it (point 1), and why the first load is skipped (point 3).
4. **`web/src/App.svelte`.**
   - Import `updatePageMetaFor` from `./lib/pageMeta`.
   - In the route-change `$effect`, directly after `document.title = titleForRoute(route);`, add `void updatePageMetaFor(route.path);` with a two-line `#0711` comment.
   - Don't touch the focus code: `appNavigationFocus.structuralGuard.test.ts` pins it.
5. **`docs/seo.md`.** Add one paragraph covering:
   - Server meta is correct on first load.
   - Client-side navigations refresh it from `GET /api/page-meta`.
   - JSON-LD is not refreshed.
   - The parity test's name.

### Decisions for the user

- **A new public endpoint, `GET /api/page-meta`.** It is recommended over a TypeScript mirror for the parity and coverage reasons in point 1. It exposes only what each page's HTML already exposes. If you'd rather not add a route, the fallback is the TS mirror covering **guides and static pages only**, with events and archive detail left generic after client navigation. That fallback needs the static meta copy moved into a shared JSON file to stay single-sourced.
- **JSON-LD is not refreshed on client navigation** (point 6). Recommended as is; say if you want it.
