## Description

`#0093` converged three endpoints onto one `no_op` JSON schema and added raw
`map[string]any` assertions so a reintroduced `omitempty` fails loudly — because
struct-decoding cannot distinguish an explicit `false` from an absent key.

Its phase-3 review verified those assertions bite, at two of the three sites.
**`unsubscribe.go`'s `unsubscribeResponse.NoOp` has no such test.** Reinstating
`,omitempty` there and running the whole `internal/handlers` package gives a
clean `ok … 2.509s`.

That site was already correct before `#0093`, and `#0093`'s criterion 3 named
only the two endpoints it changed — so this is not a defect in `5e88d07`. What
makes it worth fixing is that **the commit's own doc comments assert all three
share one schema, while only two are enforced.** A future edit to the unpinned
one is silent.

The fix mirrors what already exists: a raw-JSON presence assertion in
`TestUnsubscribeHandler_Post_ValidToken_UnsubscribesRotatesAndAudits`.

## Notes

Reported by `#0093`'s phase-3 review under `CLAUDE.md` §9.

Do **not** try to make the three endpoints' bodies byte-identical. `#0093`'s
review settled this and the reasoning is worth not relitigating: unsubscribe
deliberately varies its `message` (folding the complained text into the neutral
one is the false-success claim `#0031` forbade and `#0090` hardened; folding the
other way would tell every random caller they had complained), and preferences
deliberately 404s an unknown token, a decision carried in from `#0034`.
**Shape uniformity is what was owed here, not byte-identity** — that property
belongs to `POST /api/subscribe`, where `TestSubscribe_UniformResponseAcrossBranches`
pins bodies *and* headers because that endpoint is keyed on a caller-supplied
address.

The review also recorded, by execution, that a garbage `manage_token` and a
valid complained one return different `message` text. That is a token-validity
distinction rather than an email-enumeration oracle, and it is unavoidable one
branch over — a valid live token must return `"You've been unsubscribed."` per
RFC 8058 and `#0036`. Left as is, deliberately.
