### Design, decided

**Docs pages reuse `#0520`'s single-source content pattern, not hand-written views.** About and Privacy already work this way. Their text lives in `web/src/content/*.json`. The SPA renders that JSON through `StaticPage.svelte`, and `internal/seo/staticpages.go` embeds the same bytes (`web.StaticContent()`) and renders them into the fallback HTML. One file per page means there is no second copy of the text. So `#0519`'s "fallback copy guard" for these pages is `#0520`'s structural guard (`staticpages_test.go`'s `singleSourcePages`), extended to every docs page. It is not a new `staticPageCopy` entry.

- **Content:** one JSON file per page, in **`web/src/content/docs/`**. The route comes from the filename: `index.json` → `/docs`, `newsletter.json` → `/docs/newsletter`.
- **One SPA route name, `'docs'`.** Every docs path maps to it in `STATIC_ROUTES`. **One lazy view**, `web/src/views/Docs.svelte`, picks its content by `route.path`. All the docs JSON sits in that one lazy chunk.
- **Two new block types** in both parsers:
  - a **`code`** block `{type:"code", label, text}` renders as `<pre tabindex="0" role="region" aria-label="{label}"><code>{text}</code></pre>`. The `tabindex` makes it keyboard-scrollable (PRD §7.5).
  - **internal links**: a link whose href starts with `/` gets no `target`/`rel`, so the router intercepts it.

  No copy button. The criterion makes one optional, and leaving it out removes a live-region and focus concern.
- **SEO title and description** come from two new JSON fields, `title` and `description`. They are required on docs pages and optional on About and Privacy. `seo.go` and `sitemap.go` **derive** the docs entries from `staticPages`, so adding a page means adding one JSON file, one `STATIC_ROUTES` line and one `knownStaticRoutes` line. Tests catch any one of the three that is missing.
- **OG card:** `og-default.png`, like About and Privacy. No per-page card art, because guides are the only pages with generated cards and docs are not shared as previews often.
- **Nav:** a **"Docs" link in the footer**, not the header. The header already holds four links plus the theme control, and is tight at phone width. `fallbackNav` gains `{"/docs", "Docs"}`, so the existing `TestFallbackNavCoversHeaderNav` covers it. The `/docs` index page links every docs page, and every docs page shows a docs nav at the top.
- **Lists that must not drift** (API endpoints and MCP tools) stay as JSON copy. A Go guard in `internal/handlers`, which already reads the whole repo, compares them **exactly** with `handlers.BuildPublicRegistry(PublicDeps{}).Ops()`, using name, path and `Summary`. Fetching `openapi.json` at runtime was rejected: the fallback HTML would then have no list at all.
- **Staging: three passes.** Each one ships only pages whose backend is live. A page that does not exist yet has no JSON file, so it has no route, no sitemap entry and no index link. Nothing is hidden behind a flag.
