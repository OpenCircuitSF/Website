## Description

From the user's handoff note, `~/Gibson/OCSF/public-mcp-handoff.md`, reviewed 2026-11-19. Anyone's agent (Claude, ChatGPT, Cursor and others) should be able to ask about Open Circuit SF events and newsletter issues with no sign-in. The server is read-only and returns only what the public website already shows.

### How the handoff maps onto this repo

These points were checked against the code on 2026-11-19:

- **Path and host.** Public is `https://www.opencircuitsf.com/mcp`; admin moves to `/admin/mcp` (`#0728`). The handoff says `opencircuitsf.com`, but the apex 301s to `www` (AGENTS.md §7), and an MCP client's POST may not follow a redirect. Every URL the server returns or documents uses `www`.
- **SDK.** Use the same `github.com/modelcontextprotocol/go-sdk` (v1.8.0) the admin server uses. Streamable HTTP, stateless, JSON responses.
- **Events.** "Events" are this site's workshops and events, the rows behind `/workshops`, `/events/{slug}` and their `seo` renderers. Use the canonical public URL those pages already emit.
- **Newsletter.** "Newsletter issues" are the public campaign archive (PRD §6.8, `/archive`, `/archive/{slug}`, `/archive/feed.xml`).
- **Data access.** Read through the same store functions the public pages and `internal/seo` already use, which already filter to published rows. Do not add new SQL in handlers.

## Acceptance criteria

- [ ] A **separate** `*mcp.Server` instance, in its own package or file set (for example `internal/publicmcp`), registers only the public tools. It shares no server object, tool registry or auth middleware with `internal/mcpserver`. A test asserts its `tools/list` is exactly the public set, and a guard fails if any admin registry operation is registered on it.
- [ ] Mounted at `/mcp`. No `Authorization` is required or read. It never answers 401 and serves no OAuth protected-resource or authorization-server metadata. A test asserts that a request carrying an `ocsf_` Bearer token gets the same public result as one without.
- [ ] Every tool is annotated with `readOnlyHint: true`, `openWorldHint: false` and `idempotentHint: true`. Each returns structured JSON content plus a one-line text summary.
- [ ] Times are RFC 3339 with an offset, in America/Los_Angeles. Every event result carries its public `url`.
- [ ] Tools, with the handoff's inputs and outputs:
  - `list_upcoming_events` (`limit` default 10, max 50; optional `after` and `before`), soonest first.
  - `search_events` (`query` ≤ 200 chars, matched against title, description and tags; `from`, `to`, `include_past` default false; `limit`).
  - `get_event` (`id` or `slug`). An unknown, draft or unpublished event gets the same "not found" tool error, so the response does not reveal that a draft exists.
  - `list_newsletter_issues` (`limit`), newest first.
  - `get_newsletter_issue` (`id` or `slug`). The body is markdown or plain text, never raw HTML.
  - `get_about`: copy taken from the existing About page and `branding.ts`, plus the subscribe URL and the public contact address. Do not write new copy.
- [ ] The event summary follows the handoff's shape. Its `status` (`scheduled | cancelled | sold_out`) is derived from fields the public page already shows. `capacity_remaining`, `what_to_bring` and `skill_level` appear only when the public page already shows them.
- [ ] `limit` is clamped server-side and `query` length is capped, whatever the input.
- [ ] **Data-exposure tests** seed a draft event, an unpublished or cancelled-hidden event, and a draft or unsent campaign. They call every tool and assert none of those rows comes back. Also assert that no tool's output schema contains attendee, RSVP, subscriber, internal-note or cost fields.
- [ ] An in-process Go SDK client test runs `initialize`, `tools/list` and each tool against the mounted handler. If it is practical, also run MCP Inspector (`npx @modelcontextprotocol/inspector`) and record the result in `## Verification`.
- [ ] The admin endpoint is unaffected: `/admin/mcp` still answers 401 without a key (`#0728`'s tests stay green).
- [ ] `docs/mcp.md`, or a new `docs/public-mcp.md` indexed in `docs/README.md`, describes both endpoints: what each is for, auth, and how to run their tests. `README.md` gets a short section pointing to it.

### Design, decided

**Three layers, the same split the admin side uses.** Admin uses `internal/api` (generic), `internal/handlers` (domain operations) and `internal/mcpserver` (adapter). The public side mirrors that:

| Layer | Package | Holds |
|---|---|---|
| Shared definition | **new `internal/publicapi`** | `Op` (an `api.Operation` plus a one-line summariser), `Define`, `Registry` (a **separate type**, not `api.Registry`), the limits, and `Invoke`, the one call path both adapters use. `#0734` adds the REST router and OpenAPI document here. |
| Domain operations | `internal/handlers/public_v1.go` (new) | `BuildPublicRegistry`: the six operations, built over the **existing** `PublicWorkshopsHandler` and `PublicArchiveHandler`, so they reuse those handlers' stores and the visibility functions `workshopPageStatus` and `archivePageStatus`. The handlers package already holds those functions, `inPacific` and `IsSafeLinkHref`, so no visibility rule is restated. |
| MCP adapter | **new `internal/publicmcp`** | One `*mcp.Server`, built once, behind the SDK's stateless Streamable HTTP handler. No auth middleware of any kind. |

**Why not reuse `api.Registry`.** Its `check` hard-requires a `/api/v1/` path and a scope or `AnyToken`, which is exactly what makes an admin operation admin. A public operation has neither. `publicapi.Registry` therefore **inverts** those checks. `Add` panics when an op has `Scope != ""`, has `AnyToken`, has a path outside `/api/public/v1/`, or uses any method but GET. Every admin operation fails at least two of those, so **an admin operation cannot be added to the public registry**, and a test proves that for every operation `handlers.BuildV1Registry` returns. Reusing `api.Operation` and `api.Define` keeps one set of bind, decode and schema rules (`api.Operation.Decode`, `InputSchema`, `OutputSchema`, the `api.Error` envelope, `api.AsError`). That is code reuse, not a shared registry or server instance.

**Data access is no new SQL.** These are the reads:
- **Upcoming and search:** `workshops.Store.ListVisible(ctx, now)`, through `PublicWorkshopsHandler.store`. That is the `/api/workshops` and `/events` source: published, or canceled after being published, with `published_at` set. Every row is also re-checked with `workshopPageStatus(w) == http.StatusOK` as defence in depth.
- **Search** is an **in-memory filter** over `ListVisible`'s upcoming rows, plus its past rows when `include_past` is set. It is published-only by construction, needs no `ILIKE` and no new store method, and the list is tens of rows.
- **One event:** `store.GetBySlug`, then `workshopPageStatus`. Anything other than 200 is not found.
- **Newsletter list:** `mailing.CampaignStore.ListArchived`, through `PublicArchiveHandler.store`, re-filtered with `archivePageStatus(c) == http.StatusOK`. `ListArchived` checks only `archive_status`, and `archivePageStatus` also requires `status = 'sent'`.
- **One issue:** `store.GetBySlug`, then `archivePageStatus`. **Withheld (410 on the web page) is reported as not found here**, the same body as unknown or draft.

**Identity is the slug.** The public JSON API deliberately exposes no numeric ids (`publicWorkshopView` and `archiveDetailView` both drop them). So in every result `id` **equals** `slug`, and `get_event` and `get_newsletter_issue` take one argument, `slug`. Because `id == slug`, the handoff's "id or slug" is met: a caller holding an `id` passes it as `slug`. Description text: `the event's id (its slug), from list_upcoming_events or search_events`.

**Field mapping** (`workshops.Workshop` → event summary):

| Out field | Source | Note |
|---|---|---|
| `id`, `slug` | `Slug` | |
| `title` | `Title` | |
| `summary` | `Summary` | nullable; the public page shows it |
| `starts_at`, `ends_at` | `inPacific(StartsAt/EndsAt)` | `*time.Time`, null when TBA. Marshals RFC 3339 with the Pacific offset. |
| `location_name`, `address` | `LocationName`, `LocationAddress` | nullable |
| `status` | `published` → `"scheduled"`, `canceled` → `"cancelled"` | **`sold_out` is never emitted.** There is no sold-out field, capacity is not shown on the public page, and RSVPs live on Luma. The jsonschema description says `scheduled or cancelled`. |
| `registration_url` | `SignupURL`, **only when `IsSafeLinkHref`** passes, otherwise null | the same gate `fallback.go` and the SPA apply |
| `url` | `base + "/events/" + slug` | `base = strings.TrimRight(cfg.BaseURL, "/")`, which is `https://www.opencircuitsf.com` in production (`.env.example`). This is the same expression `#0732`'s `CalendarHandler` uses. |
| `event_type` | `EventTypeName` | the page shows it |
| `tags` | interest **slugs**, from `h.resolveInterests(ctx, w.InterestIDs)`, never nil (`[]`) | tags exist: they are the interests the page renders as tags |

`get_event` adds two fields. `location_note` (nullable) comes from `LocationNote`. `description` is plain text: `mailing.RenderMarkdownText(*BodyMD)` with `"\r\n"` replaced by `"\n"`, or `""` when nil.

**Dropped on purpose:** `price` (no column), `capacity_remaining`, `what_to_bring` and `skill_level` (no columns, and not shown publicly).

**Newsletter:** `id`/`slug` from `Slug`, `title` from `Subject`, `published_at` = `inPacific(ArchivedAt)`, `url` = `base + "/archive/" + slug`, `summary` = `Preheader` (nullable). The detail adds `body`: `mailing.RenderMarkdownText(BodyMD)`, CRLF→LF.

**Plain text, not markdown, for bodies.** `RenderMarkdownText` omits raw HTML and images exactly as the web page's renderer does. An HTML comment or tag typed into `body_md` (where an internal note could hide) never reaches an agent. Returning raw `BodyMD` would expose text the page does not show.

**`get_about`: no new copy.** Add a small exported accessor over the already-embedded single source, `web/src/content/about.json`, which `internal/seo/staticpages.go` decodes as `staticPages["/about"]`. Output:
- `name`: `seo.SiteName`
- `description`: the intro paragraphs joined with a blank line
- `sections`: `[{heading, text}]`
- `website_url`: `base+"/"`
- `events_url`: `base+"/events"`
- `newsletter_archive_url`: `base+"/archive"`
- `subscribe_url`: `base+"/subscribe"`
- `contact_email`: `links["email"]` minus `mailto:`, which is `contact@opencircuitsf.com`
- `discord_url`: `links["discord"]`
- `calendar_url`: `links["luma"]`

**Inputs and limits.** `publicapi` exports `DefaultLimit = 10`, `MaxLimit = 50` and `MaxQueryRunes = 200`. `#0730` adds its TTL and rate constants beside them, giving one place for all of them. `ClampLimit(*int) int` treats nil or ≤0 as 10 and >50 as 50. `CapQuery(string) string` trims space and truncates to 200 **runes**, never a validation error.
- Date inputs (`after`, `before`, `from`, `to`) are `*string`. Each accepts an RFC 3339 timestamp or a `YYYY-MM-DD` date in Pacific time.
  - `after` and `from` are inclusive starting at that instant, or at that date's midnight.
  - `before` and `to` are inclusive through that instant, or through the end of that date. Implement this as `< next midnight`.
  - An unparseable value is `api.Validation({field: "must be an RFC 3339 time or a YYYY-MM-DD date"})`.
  - When any date bound is set, an event with no `starts_at` is excluded.
- `search_events` matching: lowercase the query, split it on whitespace, and require **every** token to appear somewhere in the lowercased title, summary, body_md, event type name, interest slugs or interest names. An empty query matches all. Order: upcoming soonest-first (`ListVisible`'s order, TBA last), then past most-recent-first when `include_past` is set.

  - Bodies are plain text, not markdown, so hidden raw HTML cannot leak.
  - A withheld issue is "not found".
  - The docs go in `docs/mcp.md` and not a new file, so the docs guard's scan roots and `AGENTS.md` §5's table stay as they are.
