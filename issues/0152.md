# 0152 — `signup_url` is validated in the browser but never at the API boundary

## Description

`#0138` closed the missing-server-side-validation gap for `cover_image`: a bad value now gets a 400 from `Create` and `Patch` instead of being stored and later concatenated into `og:image` and the JSON-LD.

`signup_url` has the same shape and was not covered. The admin UI checks it with `isSafeLinkHref`, but nothing on the server does, so a `javascript:` URL can be **stored** by any caller that does not go through the editor.

It is not a live XSS today. `#0054`'s detail view renders the link only through `hasExternalSignup`, which `#0054`'s own fix pass gated on `isSafeLinkHref` — so a stored `javascript:` value is refused at render time. The defect is that the database is allowed to hold a value the product has decided is unsafe, and the only thing standing between it and a reader is one client-side call site.

## Acceptance criteria

- [ ] `signup_url` is validated at the API boundary in both `Create` and `Patch`, returning 400 rather than storing the value
- [ ] The server-side rule matches the client's `isSafeLinkHref` semantics — including whatever `#0138`'s fix pass lands for interior control characters. Do not write a third, subtly different rule
- [ ] A test proves a `javascript:` (and a control-character-bearing) `signup_url` is rejected by both verbs, and that an ordinary external ticketing URL still round-trips
- [ ] Check whether any other column reaches a rendered attribute without a server-side check — `#0138` closed `cover_image`, this closes `signup_url`; say whether the set is now complete
- [ ] `ISSUE=0152 scripts/check.sh go ./internal/handlers/...` passes

## Notes

Found by `#0138`'s phase-3 review while confirming the `cover_image` boundary fix. It was explicitly ruled out of scope for that issue rather than folded in.

Worth noting the pattern: this is the third instance of "the browser checks it, the server does not" in this subsystem (`cover_image`, `signup_url`, and the Markdown link destinations `#0052` hardened). A rule enforced only in the SPA is a rule enforced only for people using the SPA.
