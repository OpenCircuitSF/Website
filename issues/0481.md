## Description

Two defects in the guard coverage around `scripts/testdb.sh`, both found by the
batch review of `#0331`, `#0332`, and `#0333`. Neither was a bounce — no
acceptance criterion asked for either — but both are cheap and both weaken the
harness that is supposed to make this script safe to change.

### 1. `#0331` is unguarded

The reviewer mutated each of the three fixes in turn, against a sandboxed copy
so the harness resolved to its subject:

| Subject mutation | Harness result |
|---|---|
| `#0333`'s refusal neutered | **9 named failures**, including the shared template actually dropped |
| `#0332`'s anchor reverted to unanchored | **2 named failures**, then a fatal abort when its own later mutation could no longer find the anchored line |
| `#0331`'s `\|\| true` stripped | **`all guards hold (0 failures)`** |

So the fix that stops `template_state()` dying silently is itself invisible to
the suite. Strip its `|| true` and everything stays green.

`#0332` and `#0333` both gained external coverage in
`scripts/testdb_gc_guard_test.sh`. `#0331` is the odd one out, and the reviewer
demonstrated the cheap close: extract the function and call it directly, which is
exactly what it did by hand to prove the defect.

### 2. Part 6's mutation comment is wrong about itself

`scripts/testdb_gc_guard_test.sh` Part 6 claims its `sed` targets the line "by a
wildcard match, not a copy of its literal condition — §8". **The `sed` is a
verbatim character-for-character copy of the condition.**

The technique still works and still fails closed — the reviewer confirmed the
sibling mutation aborts loudly when its anchor goes missing, rather than passing
silently. Only the **justification** is false, and it is the kind of false that
matters: someone reading it will believe the `sed` is robust to reformatting the
condition, and it is not.

`CLAUDE.md` §8 is the section being cited, and its actual rule is that an
oracle must not be the same bytes as its subject. A comment claiming compliance
while doing the opposite is worse than no comment.

## Acceptance criteria

1. **Give `#0331`'s fix a guard**, in the external harness rather than in-script
   (`CLAUDE.md` §8: a guard inside the file it guards becomes new mutable
   surface). The reviewer's method — extract `template_state()` and call it
   directly — is the shape; you may choose another if you say why.
2. **Prove it by mutation**: stripping `|| true` must make the new guard fail
   and name the problem. A guard never seen to fail is not a guard.
3. **Correct Part 6's comment** to describe what its `sed` actually does. Decide
   whether to *also* make the `sed` match the claim; if you leave it literal,
   say plainly that reformatting the condition breaks the mutation and that this
   is acceptable because it fails closed.
4. **Do not add in-script checks** to `scripts/testdb.sh`. `#0258` spent six
   passes hardening a file against decoys added to that same file; the external
   harness exists to avoid that.
5. Run the harness against a **sandboxed copy**, never the real template or
   another agent's scratch database (`CLAUDE.md` §8b). The shared template is
   live and other agents' databases may exist.
