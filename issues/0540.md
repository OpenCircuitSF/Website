## Root cause

Five shell sites still created scratch under system TMPDIR (one literal
`/tmp` log file), outside the repository, against the operator's
all-writes-stay-inside-the-repo directive that #0537/#0538 already applied to
the other tools.

## Fix

Each site now `mkdir -p`s gitignored `.scratch/` and `mktemp`s its directory
(or, for check.sh's FUNCDEF probe, its extraction file) under a namespaced
template there. Cleanup traps were NOT edited — each script already removed
its own directory on every exit path, so success- and failure-path semantics
are preserved by construction and proven by the residue checks below.
`db_reset_guard_test.sh`'s mutant copies stay in `scripts/` (its own header
documents why db-reset.sh's repo-root resolution requires that location) —
they are trap-managed and were never mktemp sites. The two `/tmp` paths in
check.sh's FUNCDEF/LIVEBIND recompute recipes (comments) moved to `.scratch/`
with the code. browser_nav's template deliberately omits its raw (unfolded)
RUNID, unlike the guards whose RUNID is alnum-folded, so a hostile ISSUE
value cannot shape a path.
