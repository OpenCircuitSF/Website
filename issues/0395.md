## Description

`#0391` made fence detection **line-anchored**, which closed the fail-open for
sections carrying an **odd** number of fence runs. Pairing itself is still
**positional** over the fence lines it finds, and it does not consider fence
**length**.

So a four-backtick outer wrapper containing a three-backtick inner block pairs
outer-open with inner-open, and inner-close with outer-close. A citation sitting
in the prose between inner-close and outer-close, beside a marker-shaped line,
is **wrongly reported exempt** — the same fail-open family `#0391` closed for
the odd-count case.

`#0391`'s reviewer reproduced this directly: **both** the pre-fix and the fixed
predicate report such a section exempt. It is therefore **not a regression
introduced by `5752e74`** — that change is orthogonal to it.

**Live exposure is nil.** Only `issues/0089.md` and `issues/0092.md` carry
four-backtick fence lines, and both are `resolved`, so neither is in the guard's
scope. The reviewer's corpus survey found **zero** scanned sections with an odd
fence count and zero non-exempt citations across all 25 in-scope files.

## The recommended disposition — read this before planning a fix

**Close this with a disclosure, not a mechanism.** That is the reviewer's
explicit recommendation and it follows the precedent this phase has now set
three times — `#0330`, `#0347`, and `#0356` each ended by **recording a limit**
rather than building a layer to close it.

Closing it properly means teaching pairing about fence length, which is exactly
the growth `#0391`'s criterion 6 forbade and which §8's `#0258` entry documents
as six passes of diminishing return: every mechanism added to defend a file
lives in that file and becomes one more thing an edit can neutralise.

**So the expected deliverable is a one-sentence addition to the predicate's doc
comment** recording that pairing remains positional and that a differently
lengthed nested fence can still shift it — sitting alongside the forged-marker
residual already disclosed there.

If you conclude the disclosure is insufficient and a real fix is warranted, say
why explicitly and stop for a decision rather than building it.

**Criterion 3, reproduced independently — and this is where it comes apart.**
Rather than take the fixture's verdict on trust, the reviewer built its own
fixtures and ran the **real** predicate against a **fence-length-aware
reference parser** over the same bytes, in the isolated export. Both fixtures
were written to disk and read back with `python3` before use (§8's
silent-malformed-fixture warning).

Reviewer fixture A is the exact shape this issue and the disclosure describe:
a four-backtick outer wrapper enclosing one complete three-backtick block,
with a synthetic citation and a marker-shaped line in the prose between the
inner close and the outer close. The pairs **do** shift exactly as claimed —
the real predicate pairs (outer-open, inner-open) and (inner-close,
outer-close) — and the real predicate reports **exempt**, so criterion 3 as
literally written is satisfied. But the length-aware reference reports
**exempt too**. The exemption is therefore not caused by the shift and is not
a fail-open: when a wrapper encloses an **even** number of inner fence lines,
the shifted pairs are strict **subranges** of the single block a length-aware
parse produces, so any marker a shifted pair finds also sits inside the
correct block. Positional-exempt implies correct-exempt in that
configuration; the shift cannot over-exempt there.

Reviewer fixture B is the shape that **does** diverge: a four-backtick
wrapper enclosing an **odd** number of inner fence lines, six fence lines in
total — an even count. There the wrapper's own closing fence is left over and
read as an unterminated open running to the end of the section, sweeping
ordinary prose that sits outside every real block into a pseudo-block. Real
predicate: **exempt**. Length-aware reference: **not exempt**. That is the
genuine even-count fail-open, and it is the one worth recording.

**Fixture B's shape is not synthetic.** A reviewer survey over every issue
file, measuring the leading backtick **run** length rather than the line
length, finds `issues/0089.md` and `issues/0092.md` are the only files
carrying a four-backtick fence line — confirming the Description's
nil-exposure claim — and `issues/0092.md` carries fixture B's shape exactly:
a four-backtick wrapper enclosing five three-backtick lines. Run over its
real bytes, the two parsers agree on the first eight blocks and diverge from
the ninth: positional pairing turns the wrapper's closing fence into an
unterminated open running seventeen lines to end of file, where a
length-aware parse yields one correct block. `issues/0092.md` is `resolved`,
so the guard never reads it and live exposure really is nil. The same survey
re-confirms criterion 6 from the other direction: of the 25
`open`/`in-progress` files, **none** carries a fence run of four or more and
**none** has an odd fence-line count.

**Defect 1 — the disclosure names the harmless shape as the harm.** The
clause "so a nested fence of a different length — a four-backtick wrapper
around a three-backtick block, say — can still shift pairs even when the
total fence-line count is even, silently exempting a citation sitting in the
prose between the inner block's close and the outer wrapper's close" is half
true. The shift is real; the exemption it points at is neither silent nor
wrong, because a length-aware parse reaches the same verdict. A future agent
trusting this comment would build precisely that fixture to test a
length-aware fix, observe no change in verdict, and reasonably conclude the
fix was unnecessary — the disclosure would have sent them to the one
configuration where the residual is invisible. The inaccuracy originates
upstream: `#0391`'s review described the fixture the same way, and criterion
3 asked only that it report exempt, which it does. This is a correction to
inherited wording, not a fault in the implementation pass.

**Defect 2 — the shared-cause framing over-generalises.** "two residuals
remain for the same underlying reason — pairing trusts the fence lines it
finds in document order rather than verifying what they enclose" is not true
of the forged-marker residual. In that case pairing is **correct**: the
fences are genuine, correctly matched, and enclose exactly what they appear
to. What fails is that a marker line is forgeable — which is why the very
next sentence of the same paragraph offers a *different* cause ("this
function does not, and cannot, tell a genuine transcript from a fabricated
one"), and why the sentence immediately before it draws the distinction the
new clause erases ("it changes what counts as a fence, not what an exemption
is willing to forgive"). The two residuals sit on those two different axes:
one is a parsing limit, the other an evidence-strength limit. Criterion 2
asks for one coherent statement, which does not require asserting a single
mechanical cause — and a true unification is available: the predicate infers
a semantic property (that this is real captured output) from purely syntactic
ones, in two independent places.

**The exact replacement.** Replace the doc comment's final paragraph — the
whole run from "This is a parsing correction" through "already declined to
add." — with the following. It contains no literal backtick character, so
criterion 7's collision surface stays closed.

```
// This is a parsing correction, not a new exemption: it changes what
// counts as a fence, not what an exemption is willing to forgive. Two
// residuals remain, and they are different in kind rather than one
// shared cause: this predicate infers a semantic property — that the
// text around a citation is real captured output — from purely
// syntactic ones, in two independent places. The forged-marker residual
// the file-level comment above already discloses — wrapping a citation
// in a fence carrying a fabricated marker line still exempts it — is
// unchanged and still open; pairing is correct in that case, and this
// function does not, and cannot, tell a genuine transcript from a
// fabricated one. The second (#0395) is a pairing limit instead:
// pairing stays positional over the fence lines it finds and does not
// consider fence length, so a nested fence of a different length is
// paired as though it were an ordinary delimiter. A four-backtick
// wrapper around one complete three-backtick block is harmless — the
// shifted pairs are subranges of the block a length-aware parse would
// produce, so the verdict is unchanged — but a wrapper enclosing an odd
// number of inner fence lines shifts every pair after it and leaves the
// wrapper's own closing fence read as an unterminated open running to
// the end of the section. That sweeps prose sitting outside every real
// block into a pseudo-block, where a marker line can exempt a citation
// a length-aware parse would have left non-exempt. It happens at an
// even total fence-line count, which is why #0391's odd-count fix does
// not reach it; issues/0092.md carries exactly that shape and is
// resolved, so nothing in scope is affected today. Accepted rather than
// closed: teaching pairing about fence length would be exactly the
// second mechanism #0391's criterion 6 already declined to add.
```

**Two notes for the next pass.** The replacement cites `issues/0092.md` by

**Nothing to file.** Both defects are wording in this issue's own
