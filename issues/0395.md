## Description

`#0391` made fence detection **line-anchored**, which closed the fail-open for
sections carrying an **odd** number of fence runs. Pairing itself is still
**positional** over the fence lines it finds, and it does not consider fence
**length**.

So a four-backtick outer wrapper containing three-backtick inner blocks pairs
outer-open with inner-open, and so on down the list — pairs shift.

> **Corrected 2026-09-03 by this issue's first review. The original filing named
> the wrong shape as the harm, and that error came from `#0391`'s review notes
> by way of the orchestrator.** The correction is load-bearing: an agent working
> from the original text would land on the one configuration where a
> length-aware fix changes nothing, and could reasonably conclude no residual
> exists.

**The harmless shape** is a wrapper enclosing an **even** number of inner fence
lines — for instance one complete inner block. The shifted pairs are then strict
**subranges** of the single block a length-aware parse produces, so any marker a
shifted pair finds is also inside the correct block. Positional-exempt implies
correct-exempt; the shift cannot over-exempt. Both the positional predicate and
a length-aware reference parser report such a section exempt, so it is not a
fail-open at all.

**The harmful shapes** — plural, and they behave differently. `#0395`'s second
review measured all of them with three parsers over the same bytes: the real
predicate, the preserved pre-`#0391` predicate, and a fence-length-aware
reference.

| Fixture | Fence lines | Inner | Real | Pre-`#0391` | Length-aware |
|---|---|---|---|---|---|
| A — wrapper around one complete inner block | 4, even | 2 | exempt | exempt | exempt |
| B — wrapper + 3 inner, a fence after the close | 6, even | 3 | exempt | exempt | **not exempt** |
| C — wrapper + 3 inner, close is the last fence | 5, **odd** | 3 | exempt | **not exempt** | **not exempt** |
| D — wrapper + 5 inner, close is the last fence | 7, **odd** | 5 | exempt | **not exempt** | **not exempt** |

**A is harmless** — all three agree, the shifted pairs are strict subranges of
the block a length-aware parse produces, so positional-exempt implies
correct-exempt.

**B, C and D are all fail-opens**, so the residual is **not** confined to an
even fence count.

> **Corrected twice, 2026-09-03.** The original filing named A as the harm; the
> first review caught that. The replacement wording then confined the harm to an
> **even** count and called it orthogonal to `#0391` — the second review measured
> that and found it wrong in both halves. Both errors were inherited: `#0391`'s
> review notes → the orchestrator's filing → the prescribed replacement wording.
> The implementation passes transcribed faithfully each time; the fault was
> upstream of them.

**The `#0391` relationship is the opposite of what was claimed.** For the
unterminated-open form (C and D), the **pre-fix predicate reports *not*
exempt** — it dropped a lone trailing fence — while the current one reports
exempt. So `#0391`'s unterminated-open handling is what makes that sweep
**reachable**, not a fix that fails to reach it. The mechanism is structurally
possible only at an **odd** total: `blockEnd` stays at end-of-text only when the
final fence has no partner. Only **B**, the bounded even-count pseudo-block, is
genuinely orthogonal to `#0391`.

That is a real trade `#0391` made rather than a defect it introduced: it closed
a false-flag on genuine unterminated transcripts, and the same handling opens
this sweep. The disposition below is unchanged — but the trade should be stated
honestly rather than described as no change at all.

**Live exposure is nil, and the harmful shape is real rather than synthetic.**
Only `issues/0089.md` and `issues/0092.md` carry a four-backtick fence line, and
both are `resolved`, so neither is in the guard's scope. `issues/0092.md` carries
the **C/D** form — four-backtick lines at 0-indexed 344 and 355 with exactly five
three-backtick lines between them (345, 348, 350, 352, 354). Its enclosing
section has **15** fence lines and the whole file **23**, both **odd**; no even
fence count exists anywhere in that file, so it is *not* an example of B. The
corpus survey found zero non-exempt citations across all 25 in-scope files, zero
parser divergences, no fence run of four or more, and no odd-fence-count section.

**Measure fence lines by leading backtick-run length, not by line length.** Two
separate passes mis-surveyed the corpus by using line length before catching it.

## The recommended disposition — read this before planning a fix

**Close this with a disclosure, not a mechanism.** That is the reviewer's
explicit recommendation and it follows the precedent this phase has now set
three times — `#0330`, `#0347`, and `#0356` each ended by **recording a limit**
rather than building a layer to close it.

Closing it properly means teaching pairing about fence length, which is exactly
the growth `#0391`'s criterion 6 forbade and which §8's `#0258` entry documents
as six passes of diminishing return: every mechanism added to defend a file
lives in that file and becomes one more thing an edit can neutralise.

**So the expected deliverable is a one-sentence addition to the predicate's doc
comment** recording that pairing remains positional and that a differently
lengthed nested fence can still shift it — sitting alongside the forged-marker
residual already disclosed there.

If you conclude the disclosure is insufficient and a real fix is warranted, say
why explicitly and stop for a decision rather than building it.
