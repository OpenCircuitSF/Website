## Description

`#0248` corrected `docs/deployment.md`'s drill findings against a real run and
was resolved. **`#0126`'s migrations `000021`/`000022` landed roughly twenty
minutes later and invalidated them again.** Measured at HEAD by `#0248`'s own
reviewer:

| Documented | Actual at HEAD |
|---|---|
| step 1b lands at `19\|f` | `21\|f` |
| step 6 applies `20/u create_workshops` | `22/u create_subscriber_events` |
| constraint diff: one line, `email_campaigns` | `subscriber_events\|8` |
| sequence diff: empty ("non-empty is a real failure, full stop") | `subscriber_events_id_seq` |
| index diff: empty | `subscriber_events\|4` |
| `settings\|6` | **`settings\|7`** — `000021` seeds `queue_max_retries` |

That last row is the figure `#0248` was **bounced over twice**. It was 7, then
6, and is 7 again — not because anyone was careless, but because it was never a
constant.

**The defect is not the numbers. It is that they are numbers.** Every value in
`### What the drill found` is pinned to whatever migration was HEAD when someone
last ran it, and this project adds migrations routinely. Three passes have now
corrected this section, each correctly, and each was invalidated by ordinary
work. A fourth correction would last until migration `000023`.

**Re-pinning is the wrong fix.** The expectations must be *derived* — from HEAD
and HEAD-1 at run time — so the drill states what it is comparing rather than
what someone once observed. Where a figure genuinely cannot be derived, the
drill should print it and ask the follower to sanity-check it, not assert it.

## Acceptance criteria

- [ ] The drill's expectations are derived at run time from the current migration set, not written down
- [ ] The one genuinely-invariant claim — the constraint delta is exactly one table, caused by the rolled-back migration's own `down.sql` — is stated as the rule it is, rather than as `email_campaigns` specifically
- [ ] `settings` is not asserted as a fixed count anywhere; it changes whenever a migration seeds a key
- [ ] Proved by running the drill at HEAD **and** with one further migration added on top, and confirming both pass without editing the document
- [ ] `### What the drill found` either derives its figures or is removed — a section of recorded observations cannot survive an append-only migration set
- [ ] The `set -e` rationale stays accurate: step 7's diff is still a legitimate non-zero exit

refusal is working as intended and is how the reviewer noticed.
