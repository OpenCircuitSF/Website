## Description

Two independent stalenesses found while preparing `#0057`'s artifacts. Both are
documentation against shipped behaviour, and one of them is a security
statement.

### 1. `PRD.md` §10.5 specifies the IAM grant bucket-wide

`#0057`'s plan scopes the instance role's inbound grant to the **prefix**:

```
s3:GetObject, s3:DeleteObject on arn:aws:s3:::opencircuitsf-inbound/unsubscribe/*
```

`PRD.md` §10.5 still specifies it across the whole bucket. `#0057` corrected
`docs/deployment.md` and `docs/aws-iam-setup.md` to the prefix form
(`ed2c897`), leaving the PRD as the only source still describing the broader
grant.

This matters more than a typical doc drift because **the PRD is what someone
writing the policy by hand is most likely to read**, and the difference is the
blast radius of a compromised instance role: the whole inbound-mail bucket
versus one prefix of it. A grant is a security boundary, and two documents
disagreeing about where it sits means one of them is wrong at the moment
someone applies it.

`#0293` already tracks correcting stale migration language in `PRD.md` §6.2;
this is the same class in §10.5 and could reasonably be folded in.

### 2. `docs/unsubscribe.md` opens with "Not yet implemented — Phase 4"

Phase 4 is complete and `#0058` (inbound `mailto:` parsing) is resolved and
shipped. A reader who takes that first line at face value concludes the
subsystem does not exist and stops reading — which is the worst failure mode a
doc has, because it is invisible.

The file likely needs more than its opening line changed; treat the whole
document as suspect and check it against what `#0035`, `#0036`, `#0058` and
`#0057` actually built.
