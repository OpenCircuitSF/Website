## Description

`CLAUDE.md` §11 indexes every `PRD.md` section with a line count and the `sed`
command that extracts it. The table is how an agent decides what a section
costs to read before reading it, and `CLAUDE.md` is binding guidance — a wrong
number there is wrong in the one document agents are told to trust.

Three rows are stale. Found during `#0112`'s review, which re-measured the
whole table by running each row's own `sed` command after `#0112` corrected the
rows its amendment touched. `#0112`'s implementer noticed the stated file total
was 13 lines short of reality and corrected the total, but explicitly did not
audit the individual rows for where those 13 lines lived. This is where.

| Row | Stated | Actual | Drift |
|---|---|---|---|
| §4.4 Reusable motifs | 13 | 21 | +8 |
| **§4 Brand and Visual Design** | 173 | 181 | +8 (the same lines, absorbed by the parent) |
| **§9 Configuration** | 47 | 52 | +5 |

8 + 5 = the 13 lines `#0112` measured against the file total, so this accounts
for all of the known drift. Every other row in the table measures correctly.

§9's drift traces to `10da207` ("Correct PRD section 9's apex `BASE_URL` and
`#0064`'s backwards vhost criterion"), which edited §9 without touching the
index. §4.4's origin was not traced.

## Root cause

Nothing enforces the table. `internal/db`'s `TestDatabaseDocMigrationParity`
guards `docs/database.md` and `CLAUDE.md`'s migration-range sentence against the
`migrations/` directory, but it does not read `PRD.md` at all, and no other test
does either (verified by `grep -rln 'PRD.md' --include='*_test.go' .` — the 14
hits are all comments citing a section, never assertions on its content). So the
index is maintained by hand and drifts silently whenever `PRD.md` is edited by
someone who does not think to re-measure.

## Acceptance criteria

- [ ] The three rows above are corrected to their measured values
- [ ] Every other row is re-measured at the same time and corrected if it has
      also drifted, using each row's own `sed` command
- [ ] The stated file total still matches `wc -l PRD.md`
- [ ] The table's existing convention is preserved: a row's count is one less
      than its `sed` command's raw output, because the range is inclusive of the
      *following* section's heading line. §14, the last section, has no
      terminator and so counts raw. Do not "fix" this into an off-by-one.
- [ ] Consider, but do not assume: a cheap guard that would have caught this.
      A test asserting each §11 row against its own `sed` command is the
      obvious shape, and `internal/db/docs_parity_test.go` is the precedent for
      a docs guard living in the Go suite. Whether one PRD-shaped test earns a
      permanent place in the suite is a judgement call for the implementer to
      make and record, not a foregone conclusion — the alternative is to accept
      hand maintenance and simply correct the numbers

## Notes

**`CLAUDE.md` is the user's document.** This was filed rather than fixed in
`#0112`'s resolution commit for that reason — a reviewer editing binding
guidance outside the scope of the issue under review is exactly the unilateral
move the tracker's rules exist to prevent.

Severity is low: an agent following the table still extracts the correct text,
because the `sed` command in each row is correct. Only the size estimate is
wrong. But `#0109` → `#0112` was a four-document chain that started with one
number nobody re-measured, and this is the same defect class in the file that
tells agents how to avoid it.
