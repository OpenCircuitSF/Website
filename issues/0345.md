## Description

`claimKindsGuardMinPlausibleCallSiteCount`'s doc comment in
`internal/outbox/claim_kinds_call_site_guard_test.go` reads, after `#0334`:

> 5 sits comfortably below that and well above what a narrowing to any single
> file could produce (at most 3, in `internal/mailing/worker_store_test.go` …)

That constant counts **all** call sites, exempt ones included. Measured by an
independent AST census during `#0342`'s review, `internal/outbox/store_test.go`
alone holds **20**. So the sentence is literally false against its own
constant's population: a narrowing to that single file would produce 20, not
"at most 3".

The `#0304` paragraph eight lines below effectively already contradicts it —
"24 of the 36 sites it counts sit inside `internal/outbox` itself… a narrowing
to `[]string{"."}` leaves this floor passing" — which is the same fact stated
correctly.

The claim is true only of **non-exempt** files, where 3 is the right number
(`internal/mailing/worker_store_test.go`, three `SendStore.OrphanSweep` sites).

**Pre-existing, not introduced by `#0334`.** The pre-`#0334` version said "at
most 4 … in any single file" with the identical omission — `#0334` corrected
the number and left the missing qualifier untouched, correctly, since its
mandate was the misattribution rather than the scoping. Out of scope for both
`#0334` and `#0342`.

Comment-only. No bound, test, or behaviour changes.

## Acceptance criteria

1. The doc comment's "any single file" claim is scoped to **non-exempt** files
   — either by inserting the qualifier or by a short clause making the scope
   explicit — so it is true against the population the constant actually
   counts.
2. The corrected sentence does not contradict the `#0304` paragraph below it;
   read both together and make them consistent.
3. Numbers stated are re-measured against the tree, not copied from this issue
   or from any other comment. `#0334` exists because a number in this same doc
   comment was wrong, and `#0303` propagated a second wrong one — measure, do
   not trust. Record the measurement method.
4. Comment-only. Prove it structurally: parse both revisions without comments
   (`parser.ParseFile(..., 0)`), print through `go/format`, and compare bytes.
   Prove the tool falsifiable first — a deliberate non-comment mutation must
   produce a diff — and make it fail closed on empty input (§8).
5. No `.ClaimDue(` / `.OrphanSweep(` / `.SelectDue(` call-syntax literal is
   introduced into any Go comment; `scripts/go_file_visit_floor_guard_test.sh`
   greps for that syntax and comment text containing it inflates the population
   it measures. Re-run that harness and record the population.
6. `gofmt` stability: file sha256 equals sha256 of `gofmt` stdout (§8's
   smart-quote gotcha — this is a declaration doc comment, which is exactly
   what gofmt rewrites).
