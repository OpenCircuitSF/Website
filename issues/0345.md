## Description

`claimKindsGuardMinPlausibleCallSiteCount`'s doc comment in
`internal/outbox/claim_kinds_call_site_guard_test.go` reads, after `#0334`:

> 5 sits comfortably below that and well above what a narrowing to any single
> file could produce (at most 3, in `internal/mailing/worker_store_test.go` …)

That constant counts **all** call sites, exempt ones included. Measured by an
independent AST census during `#0342`'s review, `internal/outbox/store_test.go`
alone holds **20**. So the sentence is literally false against its own
constant's population: a narrowing to that single file would produce 20, not
"at most 3".

The `#0304` paragraph eight lines below effectively already contradicts it —
"24 of the 36 sites it counts sit inside `internal/outbox` itself… a narrowing
to `[]string{"."}` leaves this floor passing" — which is the same fact stated
correctly.

The claim is true only of **non-exempt** files, where 3 is the right number
(`internal/mailing/worker_store_test.go`, three `SendStore.OrphanSweep` sites).

**Pre-existing, not introduced by `#0334`.** The pre-`#0334` version said "at
most 4 … in any single file" with the identical omission — `#0334` corrected
the number and left the missing qualifier untouched, correctly, since its
mandate was the misattribution rather than the scoping. Out of scope for both
`#0334` and `#0342`.

Comment-only. No bound, test, or behaviour changes.

## Acceptance criteria

1. The doc comment's "any single file" claim is scoped to **non-exempt** files
   — either by inserting the qualifier or by a short clause making the scope
   explicit — so it is true against the population the constant actually
   counts.
2. The corrected sentence does not contradict the `#0304` paragraph below it;
   read both together and make them consistent.
3. Numbers stated are re-measured against the tree, not copied from this issue
   or from any other comment. `#0334` exists because a number in this same doc
   comment was wrong, and `#0303` propagated a second wrong one — measure, do
   not trust. Record the measurement method.
4. Comment-only. Prove it structurally: parse both revisions without comments
   (`parser.ParseFile(..., 0)`), print through `go/format`, and compare bytes.
   Prove the tool falsifiable first — a deliberate non-comment mutation must
   produce a diff — and make it fail closed on empty input (§8).
5. No `.ClaimDue(` / `.OrphanSweep(` / `.SelectDue(` call-syntax literal is
   introduced into any Go comment; `scripts/go_file_visit_floor_guard_test.sh`
   greps for that syntax and comment text containing it inflates the population
   it measures. Re-run that harness and record the population.
6. `gofmt` stability: file sha256 equals sha256 of `gofmt` stdout (§8's
   smart-quote gotcha — this is a declaration doc comment, which is exactly
   what gofmt rewrites).

## Review notes

**Verdict: approved.** Independently re-verified; not a re-read of the
implementer's numbers.

**Independent census (criterion 3).** Re-measured with a standalone `go/ast`
program written for this review from the guard's specification — roots `..`
and `../../cmd` relative to `internal/outbox`, `node_modules`/`dist` pruned,
`parser.ParseFile(..., 0)`, `CallExpr` with a `SelectorExpr` named
`ClaimDue`/`OrphanSweep`/`SelectDue`, exempt iff the file's absolute
directory equals `internal/outbox`'s. None of the guard's own helpers were
reused. 269 `.go` files visited. Result:

| | count |
|---|---|
| total call sites | **36** |
| non-exempt | **12** |
| exempt | **24** |

Exempt per file: `internal/outbox/store_test.go` **20**,
`internal/outbox/select_due_claim_row_test.go` **4**.

Non-exempt per file: `internal/mailing/worker_store_test.go` **3**,
`internal/handlers/admin_dashboard_test.go` **2**,
`internal/handlers/subscribe_intake.go` **2**,
`internal/mailing/outbox_worker.go` **2**,
`internal/handlers/admin_pending_test.go` **1**,
`internal/mailing/outbox_worker_test.go` **1**,
`internal/mailing/worker.go` **1**.

Every figure matches the implementer's report exactly.

- **`worker_store_test.go`=3 is the non-exempt maximum**, and a *unique* one —
  the corrected claim depends on this and it holds. All three are
  `OrphanSweep` (lines 109, 151, 165), i.e. `mailing.SendStore`'s unrelated
  same-named method, exactly as the parenthetical says.
- **The original claim really was false.** A narrowing to the single file
  `internal/outbox/store_test.go` yields **20** sites, not "at most 3" — six
  times the stated bound and four times the floor.
- The parenthetical's other details check out: `subscribe_intake.go` is one
  `OrphanSweep` (:246) plus one `SelectDue` (:260), and `outbox_worker.go` is
  one `OrphanSweep` (:482) plus one `SelectDue` (:528).
- The floor still does what the comment claims: 5 > 3, so a narrowing to any
  single non-exempt file trips it.

**Scope judgement on the rewritten trailing sentence (criterion 2): required,
not scope creep.** The sentence the implementer replaced read:

> — so a scan-roots regression that prunes an entire package, not just one
> file, is what it takes to stay above this floor while still being wrong.

That conclusion was *derived from the very premise this issue corrects*. It
follows only if every single file yields at most 3 (< 5). Once the premise is
scoped to non-exempt files the derivation collapses, and the sentence becomes
false in its own right: keeping just `store_test.go` — **one file, not an
entire package** — leaves 20 sites (floor passes) and **zero** non-exempt
callers (guard checks nothing). It also contradicted the `#0304` paragraph
immediately below, which states that a narrowing keeping only
`internal/outbox` leaves this floor passing with nothing evaluated. Criterion
2 explicitly requires the corrected sentence not to contradict that
paragraph, so leaving the trailing sentence would have *failed* criterion 2 —
and would have repeated the exact `#0334` pattern of correcting a number
while leaving the claim around it stale. Every factual assertion in the
replacement was checked against the census above and is true, including the
"next paragraph" cross-reference, which is literally the next paragraph.

**Criterion 4 — comment-only, by a different instrument.** Rather than re-run
the implementer's AST+`go/format` fingerprint, this review built a
**`go/scanner` token-stream digest**: the file is scanned with mode `0` (so
comments are never emitted at all), positions are discarded, and only
`(token, literal)` pairs are hashed — a different representation of the same
fact, per §8's rule that an oracle must not share its method with its
subject. Proved before use:

- fail-closed on **empty** input (no hash, exit 1);
- fail-closed on **structurally broken** Go (a parse-validity gate was added
  after observing that `go/scanner` alone is purely lexical and will happily
  tokenise `package x\nfunc (` — a genuine fail-open in the first draft of
  this reviewer's own tool, caught by testing it rather than assuming it);
- fail-closed on **lexically broken** Go (unterminated string);
- **falsifiable**: mutating `claimKindsGuardMinPlausibleCallSiteCount` from
  `5` to `999` changes the digest;
- **insensitive to comments**: appending a new comment does not change it.

Pre-edit (`62b3265^`) and post-edit (`62b3265`) digests are identical:
`5a51947d…f8b78cdc`, 1719 tokens both sides. Comment-only confirmed.

**Criterion 5 — banned literals.** The implementer checked only the `+` lines
of `git diff`. That is *sufficient for the property as stated* ("is
introduced"), since introduction is a delta and `+` lines are exactly the
delta — but this review also ran a **full-tree comment scan** over every
`.go` file for `\.(ClaimDue|OrphanSweep|SelectDue)\(` appearing after a `//`:
**zero hits repo-wide**. Re-ran `scripts/go_file_visit_floor_guard_test.sh`:
population **42** total, **12** non-exempt, both unchanged. Note the grep
oracle's 42 vs this review's AST 36 is the six-site divergence `#0323`'s
paragraph documents (all inside this file's own fixture strings, all exempt),
and the **non-exempt counts agree exactly, 12 = 12**, as that paragraph
predicts.

**Criterion 6 — gofmt.** `sha256(file) == sha256(gofmt stdout)` =
`094bf8f6…d407c3fb`. `gofmt -l` silent. No `''` or doubled-backtick sequences
in any added line, so §8's smart-quote rewrite has nothing to catch.

**Verification re-run independently**, own database `opencircuit_test_0345r`:
`ISSUE=0345r scripts/check.sh go ./internal/mailing/... ./internal/outbox/...
./internal/handlers/...` — `go build`, `go vet`, `gofmt -l` clean; all three
packages `ok`; **zero skips**. `scripts/check.sh guards` passed in full.
`uptime` load 2.54 → 1.98 throughout, well under the §5 threshold, so no
timing result here is load-contaminated.

**One observation, not a defect.** The parenthetical names
`subscribe_intake.go` and `outbox_worker.go` as the files holding 2, and
`internal/handlers/admin_dashboard_test.go` also holds 2. The phrasing is
illustrative rather than exhaustive ("each hold 2", not "the only files that
hold 2"), the full per-package breakdown appears in the `#0304` block below,
and the text is pre-existing rather than introduced here. No action.
