## Description

The SPA ships as one bundle (`/assets/index-*.js`, 991 KB raw, 323 KB gzipped as of v0.16.2) with no dynamic `import()` anywhere in `web/src`. It contains the code for every public page, the whole admin console (27 admin route strings), and the text of every guide. A visitor opening the home page on a phone downloads and parses all of it. PRD §7.6 budgets ≤ 60 KB gzipped JS for the initial route and LCP < 2.0 s on 4G; the site is about 5× over the JS budget even once `#0716` compresses it.

The user's direction (2026-11-18): be careful about how long it takes to load a single page, and a reload must return the visitor to the same page, not a default one.

## Acceptance criteria

- [ ] Admin and the guides (at minimum) are split out with route-level dynamic `import()`, so a public page loads only the shell, its own view, and shared code. Report the gzipped initial-route JS for `/`, `/guides`, one guide page and `/admin` before and after.
- [ ] Load time is measured, not assumed: the plan names how (bundle sizes from `vite build`, plus a rendered check in a Tart VM per AGENTS.md §8 if a timing figure is claimed — never a host browser) and the verification records the numbers against PRD §7.6.
- [ ] Navigating to a not-yet-loaded route shows no blank flash longer than the existing transition, and keyboard focus handling (`#0527`, `appNavigationFocus`) still holds.
- [ ] A chunk that fails to load (a stale tab after a deploy, where the old chunk's hash no longer exists) recovers by a full reload of the same URL rather than a broken page, at most once per URL so it cannot loop. Reuse `#0715`'s reload path.
- [ ] Reload on any route — public path, guide, admin `#/…` route — returns to that same route. A test or guard pins it, so a future router change cannot fall back to a default page.
- [ ] The SEO static fallbacks and the guards in `internal/seo` (AGENTS.md §5's table) still pass; `web/dist/index.html` handling follows §8b.

### Approach

All dynamic `import()`s go through one module, so there is one place that caches, one place that recovers, and one place to test.

**1. `web/src/lib/topics/demoLoaders.ts` (new).** Exports `type DemoModule = { default: Component }` and `TOPIC_DEMOS: Readonly<Record<string, () => Promise<DemoModule>>>`, a map from topic slug to `() => import('./XDemo.svelte')`. Take the slug→component pairs from the `demo:` fields in `topics.ts` (`'one-wire-many-leds'` → `'../guide/ChainDemo.svelte'`, and so on, all 42). This map lives outside `topics.ts` so the entry chunk can start a demo download in parallel with `TopicGuide`, without loading the guide texts first.

**2. `web/src/lib/topics/topics.ts`.** Delete every `import X from './X.svelte'` demo import (and the `ChainDemo` one), delete the `demo` field from `TopicBody` and from every `TOPIC_BODIES` entry, and drop the `Component` type import if it is now unused. Nothing else changes. `TOPICS` / `topicBySlug` stay as they are.

**3. `web/src/lib/routeViews.ts` (new).** This module owns lazy loading and stale-chunk recovery:

```ts
import type { Component } from 'svelte';
import type { Route, RouteName } from './router';
import { TOPIC_DEMOS, type DemoModule } from './topics/demoLoaders';
import { reloadToSameURL } from './versionCheck';

export type ViewModule = { default: Component<any> };
export type Loader = () => Promise<ViewModule>;

export const LAZY_ROUTE_LOADERS: Readonly<Partial<Record<RouteName, Loader>>> = {
  login: () => import('../views/Login.svelte'),
  account: () => import('../views/Account.svelte'),
  admin: () => import('../views/Admin.svelte'),
  'register-verify': () => import('../views/RegisterVerify.svelte'),
  'recover-verify': () => import('../views/RecoverVerify.svelte'),
  'workshop-guide': () => import('../views/GuideProgrammingLeds.svelte'),
  'topic-guide': () => import('../views/TopicGuide.svelte'),
  confirm: () => import('../views/ConfirmSubscription.svelte'),
  preferences: () => import('../views/PreferenceCenter.svelte'),
  unsubscribe: () => import('../views/Unsubscribe.svelte'),
};
export const demoKey = (slug: string) => `demo:${slug}`;
export const CHUNK_RELOAD_KEY_PREFIX = 'oc.chunkReload:';
export interface RecoveryDeps { href(): string; getSession(): Storage | null; reload(): void }
```

The functions:

- **`loaderFor(key)`** looks the key up in `LAZY_ROUTE_LOADERS`, or in `TOPIC_DEMOS` for a `demo:` key.
- **`importOnce(key)`** keeps a module-level `inflight` map of the raw import promise. A rejection deletes the entry before rethrowing.
- **`cachedComponent(key)`** reads a module-level `Map<string, Component>`.
- **`loadComponent(key, deps = defaultDeps): Promise<Component | null>`** chains onto `importOnce`. On success it caches the component and calls `clearChunkRecovery(deps)`. On failure it calls `recoverFromChunkError(deps)` and resolves `null`.
- **`prefetchComponent(key)`** chains onto `importOnce`. It caches on success and swallows failure: no reload, nothing cached.
- **`recoverFromChunkError(deps): boolean`** builds the key `CHUNK_RELOAD_KEY_PREFIX + deps.href()`. If `getSession()` throws or returns null, it returns `false` (with no storage the loop can't be guarded, so it doesn't reload automatically). If the key is already set, it returns `false`. Otherwise it sets the key to `String(Date.now())`, calls `deps.reload()` and returns `true`.
- **`clearChunkRecovery(deps)`** runs `removeItem` on the same key inside a try/catch.
- **`defaultDeps`** is `{ href: () => location.href, getSession: () => sessionStorage, reload: () => reloadToSameURL() }`.
- **`lazyKeyForRoute(route): string | null`** returns `route.name` if it has a loader, else `null`.
- **`preloadForRoute(route): Promise<void>`** runs `loadComponent` for the route key, and in parallel `loadComponent(demoKey(slug))` when `route.name === 'topic-guide'`. It awaits both with `Promise.all` and never rejects.
- **`prefetchForRoute(route): void`** does the same with `prefetchComponent`.
- **`routeViewReady(route): Promise<void>`** is `loadComponent` for the route key only, so the `<h1>` exists. It is `Promise.resolve()` for eager routes.

Each caller gets its own `.then/.catch` on the shared raw promise, so a failing prefetch can never swallow a real navigation's recovery. Recovery is a reload, not a retry, because browsers cache a failed module fetch for the life of the document. Re-importing the same URL fails again.

**On `vite:preloadError`:** don't add a listener. In Vite 6.4's `__vitePreload` (read in `node_modules/vite/dist/node/chunks/dep-*.js`, `handlePreloadError`), both a dependency-preload failure (JS or CSS) and the chunk's own `baseModule()` failure dispatch the event and then **rethrow unless `preventDefault()` is called**. Every `import()` here runs through `importOnce`, so the rejection always reaches `loadComponent`'s handler. A listener would run the same recovery a second time on the same failure. Write this as a short comment in `routeViews.ts`.

**4. `web/src/main.ts`.** Before mounting, await the current route's chunks so that a direct load or a reload keeps the server fallback (#0519) on screen instead of showing a blank shell:

```ts
import { get } from 'svelte/store';
import { currentRoute } from './lib/router';
import { preloadForRoute } from './lib/routeViews';
void preloadForRoute(get(currentRoute)).finally(() => {
  mount(App, { target: prepareMountTarget() });
});
```

Keep `import { prepareMountTarget } from './lib/mountTarget';` byte-identical, and keep the `mount(App, { target: prepareMountTarget(` shape: `mountTarget.test.ts` regex-matches both. Drop `export default app`, which nothing imports (checked with grep). If the chunk fails, `loadComponent` has already started the reload. If it fails for the second time, mount anyway and let `LazyView` show the failure state.

**5. `web/src/lib/LazyView.svelte` (new).** Props: `{ key: string }`. State: `View = $state(cachedComponent(key))` and `failed = $state(false)`. An `$effect` re-reads `key`. If the cache has it, it sets `View`. Otherwise it calls `loadComponent(key)` with a `live` flag that the effect cleanup clears; the result sets either `View` or `failed = true`. Markup:

- `{#if View}<View />`
- `{:else if failed}` renders `<main id="main-content" class="app-shell"><h1 tabindex="-1">This page didn't load</h1><p>Your connection may have dropped, or the site was just updated.</p><Button onclick={retry}>Reload</Button></main>`. `retry` calls `clearChunkRecovery(defaultDeps)` and then `reloadToSameURL()`.
- `{:else}<div class="app-shell"><p class="text-muted">Loading…</p></div>{/if}` — the same markup as App's session-gate placeholder, so the only intermediate state is the one already on screen today.

Add a `demo` variant: prop `placeholder?: 'page' | 'none'`. `'none'` renders nothing while pending and renders `<p class="text-muted">This demo didn't load. <a href={location.pathname}>Reload</a></p>` on failure. It is used inside `TopicGuide`'s `.demo-frame`, which already has its own box. If `liveRegionGuard.structuralGuard.test.ts` flags the new `Loading…`, add `{ file: 'web/src/lib/LazyView.svelte', match: 'Loading…', reason: KNOWN_LOADING_PLACEHOLDER_REASON }` to its allowlist, next to the existing rows near line 799.

**9. `internal/handlers/static.go`.** A missing `/assets/*` chunk already gets a 404, because `path.Ext(name) != ""` → `http.NotFound`. A stale tab's `/assets/TopicGuide-OLDHASH.js` therefore gets a plain-text 404, never the shell served as JavaScript. `precompressAssets` walks every file under `assets/`, so many chunks are all gzipped and all marked `immutable`. Two hardenings, both before the `path.Ext` check:

Comment it as `#0717`: a chunk from a previous build must 404 so the SPA's `import()` rejects and recovers, and `no-cache` keeps a 404 from being heuristically cached past the next deploy.
- Use the constant if `cacheNoCache` (or similar) already exists in `static.go`; otherwise use the literal.

## Needs the user

1. **The guide pages stay over the 60 KB JS budget** (about 79–92 KB gz, down from 324). The fix to go further is splitting the 42 guide texts per guide and slimming `TopicGuide`. It saves at most ~10–15 KB and would still leave the pages over. Accept this, or have a follow-up filed?

3. **Prefetch policy.** The plan prefetches a route's chunk when the visitor hovers, focuses or touches its link, rather than prefetching everything during idle time. That spends no extra data on phones, but a first tap on a guide from a phone may show "Loading…" for one round trip. Say if you would rather idle-prefetch the guide view (about 23 KB) after every page load.
