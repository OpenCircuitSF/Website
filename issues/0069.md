## Description

Small, concrete, and cheap. [#0008](0008.md) claims audit rows are written inside the ceremony transaction. What is actually proven is narrower: `TestWriteTx_RollsBackWithTransaction` shows `audit.Logger.WriteTx` rolls back with *a* transaction, and other tests show rows exist after a *successful* ceremony. No test proves an audit row disappears when a real auth action fails mid-flight.

`#0008`'s implementer argued this needed fault-injection hooks in production code and narrowed the claim instead. That was right for `FinishRegistration` and `FinishLogin` — they call `tx.Commit` directly with no forceable failure point. It is **wrong for `LogoutAll`**, and the seam already exists.

> 🟢 Resolved 2026-08-18 — `TestLogoutAll_NoMailWhenCommitFails` now wires a real auditor and asserts zero `session.revoked_all` rows survive the forced commit failure; the reviewer independently re-ran the mutation (`WriteTx` → `Write`) and watched the assertion fail, and confirmed the commit changes test code only.

## Root cause

`LoginService.commit` (`internal/auth/login.go:75`) is a function field that exists purely so tests can force a commit failure. `TestLogoutAll_NoMailWhenCommitFails` (`internal/auth/logout_all_test.go:320`) already uses it to fail `LogoutAll` at commit — *after* the `auditor.WriteTx` call at `internal/auth/login.go:358`.

That test asserts the session delete rolled back. It does not assert the `session.revoked_all` audit row is gone. The scenario is already constructed; only the assertion is missing.

One correction to "the scenario is already constructed": `TestLogoutAll_NoMailWhenCommitFails` built its `LoginService` with `newLoginServiceWithMailer`, whose 4th arg (`auditor *audit.Logger`) is `nil` — see `internal/auth/login_test.go:130`. With a nil auditor, `LogoutAll`'s `if s.auditor != nil { ... s.auditor.WriteTx(...) ... }` guard (`login.go:355`) never runs `WriteTx` at all, so before this fix there was no audit row in play to roll back or assert on — the commit-failure scenario was constructed, but the audit-write half of it was not. `internal/auth/logout_all_test.go` already had exactly the helper needed for this, though: `newLoginServiceAudited` (line 21), used by the neighboring `TestLogoutAll_WritesAuditRowWithRevokedCount` to prove the row exists after a *successful* commit. Swapping to it here is what actually makes the seam "already exist" as described.

## Fix

Two changes to `internal/auth/logout_all_test.go`, no other files, no production code:

1. `TestLogoutAll_NoMailWhenCommitFails` now builds its `LoginService` via `newLoginServiceAudited(t, pool, mailer)` instead of `newLoginServiceWithMailer(t, pool, mailer)`, wiring a real `audit.Logger` over the test pool so `LogoutAll`'s `auditor.WriteTx` call actually executes.
2. Added the assertion itself: after the existing session-rollback check, `auditCount(t, pool, audit.ActionSessionsRevokedAll)` (the pre-existing helper from `internal/auth/audit_seams_test.go`, already used by `TestLogoutAll_WritesAuditRowWithRevokedCount`) must be `0`. `testPool` truncates `audit_log` before every test and no test in this package uses `t.Parallel()`, so the count is scoped to this test's own run.

No change to `internal/auth/login.go` or `internal/audit/*.go` — confirmed by `git diff --stat` on the commit (see `## Files changed`) and the mutation proof below, which edited `login.go` only as a temporary, reverted experiment outside the commit.

## Gotchas

- **No production code change was needed, as the issue predicted** — but not for quite the reason originally stated. The `commit` seam did already exist and was already exercised by this test; what was actually missing to make "the scenario is already constructed" literally true was swapping which test-helper constructor built the `LoginService` (nil auditor → real auditor), which is itself a test-only change. Worth double-checking future "the seam already exists" claims against what the *test* wires up, not just what the production code exposes as a seam.
- The mutation used `s.auditor.Write` (through the pool) rather than, say, a bogus/no-op call, specifically because it is the smallest realistic diff from `WriteTx` — same package, same method family, differing only in "does this insert share the caller's transaction" — which is exactly the property the new assertion is supposed to guard.
- **Reviewer's independent mutation re-run (2026-08-18).** Re-applied the
  mutation from a saved copy of `internal/auth/login.go` — the single line
  `if err := s.auditor.WriteTx(ctx, tx, audit.Entry{` changed to
  `if err := s.auditor.Write(ctx, audit.Entry{`, moving the audit insert onto
  the pool outside the caller's transaction — and ran the test:

- **Reviewer's confirmation of the corrected premise.** Verified at the

  So before `5bd0d3d` this test's `WriteTx` genuinely never executed and the
  issue's original "the scenario is already constructed; only the assertion
  is missing" premise was wrong — the implementer's correction is accurate,
  and `newLoginServiceAudited` (`logout_all_test.go:21`, `svc.auditor =
  audit.New(pool)`) is the right existing helper to have switched to.
