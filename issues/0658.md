- **Per-guide OG cards exist**: `(*seo.Site).GuideCardHandler` serves `/guides/{slug}/og.png` from `s.cards.get("guide:"+slug, g.Title, guideCardMeta(g))` (`internal/seo/site.go`). The Bluesky thumbnail reuses that renderer directly (`### Thumbnail`).
- **How Outreach makes short links** (the path to reuse): the admin handler, never the publisher, calls ShortLinks. `internal/handlers/admin_outreach.go`'s `shortLinker` interface (`Enabled`, `Me`, `EnsureCampaign`, `CreateLink`, …) is satisfied by `conns.ShortLinker()` (`internal/outreachconn/liveshortlinks.go`, which re-reads the current client on every call, so a Settings save applies at once). `ensureLinksFor` (`internal/handlers/admin_outreach_links.go`) calls `CreateLink` **with no `Key`**, so ShortLinks de-duplicates on `DestinationURL` and a retry after a crash between the upstream create and the local insert gets the same link back. The short URL is `shortlinks.ShortURL(me.BaseURL, link.Key)` (the `/u/KEY` form, `#0603`). - **How Outreach reads clicks**: `CampaignStats(slug, from, to)` through a `shortlinks.StatsCache` (`StatsCacheTTL` 60 s), then `outreach.ClicksByKey(keys, rollup)` sums `rollup.ByLink` per key. ShortLinks' `by_link` is uncapped (`ShortLinks/internal/clicks/stats.go`, `CampaignClicksByLink`), so every post's key is present. Always pass an explicit window (`outreach.ResultsWindow`'s comment explains why).

### Short links

**One ShortLinks link per `guide_posts` row, minted when the draft is created, before it can be scheduled.** The publisher never calls ShortLinks; a send needs only the stored `short_url`. This is Outreach's shape (link first, then post), and it means the admin sees and measures the real link while editing.

- **Destination keeps its UTM tags, and must.** ShortLinks de-duplicates `POST /api/links` on the destination URL, so two posts for the same guide and channel with the same destination would get the *same* short link, and Mastodon adopt-on-retry could then adopt the earlier post's status. `utm_content=gp{id}` makes each destination unique per row, which makes each short link unique per row. The same de-duplication is what makes a retried mint idempotent. Form (keys sorted by `url.Values.Encode`, so it is deterministic):
  `{BASE_URL}/guides/{slug}?utm_campaign=guides&utm_content=gp{id}&utm_medium=social&utm_source={channel}`
  The `CreateLinkRequest` also carries the same values in its UTM fields, as `postLinkRequest` does, so ShortLinks' `by_source`/`by_content` rollups are filled.
- **Campaign**: one ShortLinks campaign for all guide posts, slug constant `guideposts.CampaignSlug = "guide-posts"`, created with `EnsureCampaign("guide-posts", CreateCampaignRequest{Description: "Topic guide social posts", DefaultUTMCampaign: "guides"})`, no `StartsAt`/`EndsAt`. The slug the response returns is authoritative (ShortLinks may suffix it on a race), so it is **stored per row** in `campaign_slug`, and the click read groups by it.
- **Sequence** (`(*Linker).Ensure(ctx, id)`, `internal/guideposts/links.go`), never inside a database transaction:
  1. `p := store.Get(id)`. If `p.ShortURL != nil`, return `p` with no ShortLinks call.
  2. `!sl.Enabled()` → return an error wrapping `shortlinks.ErrUnavailable`.
  3. `me := sl.Me(ctx)`; base = `strings.TrimRight(me.BaseURL, "/")`; empty → error. No cache (creation is rare; a cache would need `conns.OnChange` resets as `AdminOutreachHandler.ResetShortLinks` does).
  4. `camp := sl.EnsureCampaign(ctx, CampaignSlug, …)`.
  5. `link := sl.CreateLink(ctx, CreateLinkRequest{DestinationURL: p.DestinationURL, Title: g.Title + " — " + ch.Label + " guide post " + id, CampaignSlug: camp.Slug, UTMSource: ch.UTMSource, UTMMedium: "social", UTMCampaign: "guides", UTMContent: "gp" + id, Placement: ch.Name})`. No `Key`.
  6. If `link.DestinationURL != p.DestinationURL` → error `ErrForeignLink` (never adopt a link whose destination is not this post's; it would break the uniqueness above).
  7. `store.SetLink(ctx, id, link.Key, shortlinks.ShortURL(base, link.Key), camp.Slug)`: `UPDATE … SET short_link_key, short_url, campaign_slug, body = <token replaced, or appended after "\n\n" when the body has no token>, updated_at = now() WHERE id = $1 AND short_url IS NULL AND status = 'draft' RETURNING …`. Returns `(Post, changed bool, error)`; no row → re-read and return the current row with `changed=false` (a racing caller got there first; ShortLinks gave both the same key).
- **Retry and crash safety**: a crash after step 5 and before step 7 leaves `short_url` NULL; the next `Ensure` repeats steps 3–5, ShortLinks returns the existing link (`Duplicate: true`), and step 7 stores it. A partial unique index on `short_link_key` makes a shared key impossible at the database level too.
- **ShortLinks failure** (not configured, unauthorised, rate-limited, timeout, 5xx): the draft is **kept** with `short_url` NULL and the `{link}` token in its body, and `Ensure` returns the error. `Schedule` and `QueueNow` refuse such a row with `ErrNoLink` (the `guide_posts_link_check` constraint backs this). `#0659`'s create handler reports it as a non-fatal `link_error` on a `201` and calls `Ensure` again before Schedule and Send when the row has no link, mapping a still-failing ShortLinks call to `503` with `writeShortLinksError`'s fixed messages (no upstream text). The publisher, finding a queued row with no `short_url` (only possible through a manual SQL edit), fails it permanently with "Cannot post: the post has no short link", as Outreach does.
- **Bluesky length with the short URL.** Keys are 6 characters (`ShortLinks/internal/links/keygen.go`, `KeyLength = 6`), so the URL is `https://go.opencircuitsf.com/u/XXXXXX`, 37 graphemes. The longest `post` copy today is 146, so the default body is 146 + 2 + 37 = 185, well under 300. While the body still holds `{link}`, `ValidateDraft` measures it with `sampleShortURL = "https://go.opencircuitsf.com/u/XXXXXXXXXXXX"` (a 12-character key, 43 graphemes, headroom over the real 6) substituted; once `SetLink` has run, `outreach.ValidateForSend` measures the real text. Mastodon counts any URL as 23, so it is never close to 500.
- **Both channels carry the link in the text.** Unlike Outreach's Bluesky drafts (link only in the card), the guide copy is written with the link appended, and a visible link survives a missing card. The Bluesky card URI is also the short URL, so a card click is counted too. There is no "canonical card" option for guide posts; tracking is the point.
- **Mastodon adopt-on-retry**: `postMastodon` mirrors Outreach's: on an attempt of unknown outcome (`row.Attempts > 1` or `outbox.HasPriorAttempt`), `masto.FindRecentStatusWithURL(ctx, *job.ShortURL)` first. Because each row's short URL is unique (unique destination, partial unique index), it can only match this row's own status; an earlier post of the same guide carries a different short URL and is never adopted. The Idempotency-Key is `opencircuitsf-guide-post-{id}` (`-g{n}` when the generation is above 0), never the Outreach prefix.
- **Mastodon's own preview fetch** of the short URL is a bot request; ShortLinks counts exclude bots, so the counts are not inflated by it.

### Data model: `migrations/000052_create_guide_posts.{up,down}.sql`

`000051` is still the highest (`ls migrations | tail -2`); re-check before writing. A new file creating a new table is outside AGENTS §1's frozen range whatever production's bound is.

```sql
-- #0658 (plan #0657): one scheduled social post for a topic guide
-- (/guides/{slug}), separate from workshop Outreach (outreach_posts).
-- guide_slug is checked against internal/guides in Go, not by a foreign
-- key: the guides are an embedded catalog, not rows. Each row gets its own
-- ShortLinks link; destination_url carries utm_content=gp{id}, which keeps
-- every destination, and so every short link, unique per row.
CREATE TABLE guide_posts (
    id                 BIGSERIAL PRIMARY KEY,
    guide_slug         TEXT NOT NULL,
    channel            TEXT NOT NULL,
    body               TEXT NOT NULL,
    destination_url    TEXT NOT NULL,
    campaign_slug      TEXT,
    short_link_key     TEXT,
    short_url          TEXT,
    status             TEXT NOT NULL DEFAULT 'draft',
    scheduled_at       TIMESTAMPTZ,
    posted_at          TIMESTAMPTZ,
    remote_id          TEXT,
    remote_url         TEXT,
    last_error         TEXT,
    attempt_generation INTEGER NOT NULL DEFAULT 0 CHECK (attempt_generation >= 0),
    created_at         TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at         TIMESTAMPTZ,
    CONSTRAINT guide_posts_channel_check CHECK (channel IN ('bluesky','mastodon')),
    CONSTRAINT guide_posts_status_check
        CHECK (status IN ('draft','scheduled','queued','posted','failed')),
    CONSTRAINT guide_posts_scheduled_at_check
        CHECK (status <> 'scheduled' OR scheduled_at IS NOT NULL),
    CONSTRAINT guide_posts_posted_at_check
        CHECK (status <> 'posted' OR posted_at IS NOT NULL),
    CONSTRAINT guide_posts_link_pair_check
        CHECK ((short_link_key IS NULL) = (short_url IS NULL)
           AND (short_url IS NULL) = (campaign_slug IS NULL)),
    CONSTRAINT guide_posts_link_check
        CHECK (status = 'draft' OR short_url IS NOT NULL)
);
CREATE UNIQUE INDEX guide_posts_short_link_key_key ON guide_posts (short_link_key) WHERE short_link_key IS NOT NULL;
CREATE UNIQUE INDEX guide_posts_destination_url_key ON guide_posts (destination_url);
CREATE INDEX idx_guide_posts_due ON guide_posts (scheduled_at, id) WHERE status = 'scheduled';
CREATE INDEX idx_guide_posts_slug ON guide_posts (guide_slug, id);
```

### Deviations

- **Campaign per draft (user's request, 2026-11-14, relayed by the orchestrator mid-implementation).** The user wants to repost guides now and then under new ShortLinks campaigns, so the campaign is not hardcoded. `Store.Create` takes a `campaign` argument; blank means `guideposts.CampaignSlug` (`guide-posts`); anything else must match `^[a-z0-9]+(-[a-z0-9]+)*$` (at most 100 characters) or `ErrBadCampaignSlug`. `Linker.Ensure` passes the row's `campaign_slug` to `EnsureCampaign`, then stores the slug ShortLinks returns. `Store.ClickKeys` groups by `campaign_slug`, so `#0659` can read several campaigns. Test: `TestLinker_MintsIntoEachDraftsCampaign`, plus `TestNormalizeCampaignSlug`.
- **Schema consequence of that.** The plan's `campaign_slug` was NULL until linked and tied to `short_url` by `guide_posts_link_pair_check`. Because it now holds the requested campaign from creation, it is `NOT NULL` with its own `guide_posts_campaign_slug_check` (same pattern), and `guide_posts_link_pair_check` covers only `short_link_key`/`short_url`.
- **`TestPublisher_NoShortLinkFailsPermanently`** cannot reach the publisher's guard through the database, because `guide_posts_link_check` makes a queued, unlinked row impossible. The test proves the constraint refuses it, and tests the guard through a small pure helper `sendRefusal` that `sendOne` now calls.
