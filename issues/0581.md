## Review notes

Opus phase-3 review, 2026-10-18. Approved after two small fixes made in the
review commit. The evidence is jsdom, not a browser (AGENTS.md section 1). No browser was run.

**Items 1 to 6 and the findings.**
- **1 / D1 / M2.** Post now, Retry and Mark posted on a card each open
  `OutreachPostDialog` (`role="dialog"`, takes focus, Escape, locked while
  in flight) with the text, "Posts publicly as … on …" and "cannot be
  unsent". A card can post publicly only through `confirmDialog`. In card
  mode the composer hides Post now, Retry and Mark posted. The composer's
  grid mode still posts directly, but only `OutreachPanel`'s grid renders
  it, and the one production caller (`OutreachWorkshop.svelte`) always
  passes `body`, so that path cannot be reached (see follow-up). The guard
  `outreachNoNativeConfirm.guard.test.ts` was mutation-tested by injecting
  `confirm('…')`, ``window.confirm(`…`)``, `confirm("…")` and a bare
  `window.confirm` reference into `OutreachConfirmDialog.svelte`. All four
  fail it. Restored by sha256 (`d678dfeb…`).
- **2 / D6.** Posts both from one dialog, using a snapshot taken when the
  dialog opens. Sends run one after the other, each with its own
  `try/catch`, so a failure on one does not stop the other. Both results
  go on one line and each card gets its own notice. The test covers one
  rejection.
- **3 / C5 / M3.** Each card has its own always-rendered `role="status"` /
  `role="alert"`. `visibleNotice` hides a notice once the post's status
  moves on. The page-level paragraph is gone.
- **4 / D2.** A queued card shows a spinner (`aria-hidden`, no animation
  under reduced motion) and "usually under ten seconds". The backoff is a
  `setTimeout` chain at 1/2/4/10 s, tested to stop on unmount. `onChange`
  resets the attempt when a post newly turns `queued`, and because `view`
  is reassigned the effect re-arms at 1 s. Read in the code; no test
  covers it directly.
- **5 / D5.** Copied for 2 s, tested.
- **C12.** `closeEditor` focuses Edit with `preventScroll: true`.
- **§6.** Schedule all dialog, Edit-in-place focus return, the live-region
  convention, and the `#0592` Reset button and dialog (its tests pass) are
  all intact.

**Fixes made in review.**
1. **The "Copied." / "Link copied." notice never cleared.** The card
   checked `notice === n` before clearing. But the list stores notices in a
   `$state` record, which hands back a proxy, so the check was never true
   and the line stayed until the post's status changed. That breaks
   deviation (3) and C5's "times out". The check now compares content. The
   Copy test now asserts the card's notice is empty after 2000 ms, and it
   failed against the unfixed card.
2. **The both-networks result line rendered after the last card.** That is
   the C5/M3 shape this issue removes. It now sits at the top of the list,
   persistent (as the live-region guard requires; placing it inside the
   Announce `{#if}` fails that guard), directly above the Announce heading
   and its button. The test asserts it comes before the first card and
   that each card carries its own result. It failed with the line moved
   back to the bottom (restored by sha256).

**Implementer's deviations.** (1) Keeping Schedule in the card-mode
composer is right: the card's Schedule… opens it. (2) Holding notices in
the list is right, because the both-networks post has to write to two
cards. (3) Accepted once fix 1 was in.

**Escape calls `onClose` twice through bubbling.** This is harmless and
left as it is. It is the same pattern `#0094`/`#0120` documented for every
admin modal (`modalEscapeGuard.test.ts`). Every new close is idempotent
(`dialog = null`, `bothOpen = false`, `pendingEditId = null`,
`discardOpen = false`). The close is guarded by `inFlight`/`busy`, so it
cannot double-send. No ancestor or window listener handles keydown.

**Follow-ups for the orchestrator to file (not filed here).**
- Remove `OutreachPanel`'s grid and inline-composer mode, plus the
  composer's grid-mode Post now / Retry / Mark posted. No production
  caller reaches it, and it is the only remaining code path that posts
  without the dialog.
- The both-networks line ("Bluesky: queued · Mastodon: queued") persists
  after both posts resolve. Clear it when the Announce posts leave
  `queued`, or apply the same `visibleNotice` rule to it.
- The no-native-confirm guard misses `confirm(variable)`, since it needs a
  string-literal argument. This is minor.

## Resolution

- **Go.** `outreachconn.Manager.Account(channel)` (Bluesky `@handle`, Mastodon
  instance host, else empty; no network); `AdminOutreachHandler.SetAccounts`
  and an `account` field on each channel view (automatic channels only);
  wired in `cmd/opencircuit/main.go` next to `SetHashtags`.
- **Lib.** `outreachCards.ts`: `pollDelay`, `postableAutomatic`,
  `CardNotice`/`visibleNotice`, `postDialogCopy`, `combinedPostResult`,
  `copyLabel`. `OutreachChannel.account` in `types.ts`.
- **Components.** New `OutreachConfirmDialog`, `OutreachPostDialog`,
  `OutreachPostCard`. `OutreachPostCards` is now the list: grouping, editing
  card, discard dialog, the Announce "Post to <A> and <B>" button (one dialog,
  sequential sends, one combined result line plus a notice on each card), and
  per-card notices. The page-level notice paragraph is gone; each card has its
  own `role="status"` and `role="alert"`. Queued cards show a spinner and
  "usually under ten seconds". Copy text / Copy link read "Copied" for 2 s.
  `OutreachComposer` uses the dialog for its discard prompt and, in card mode,
  no longer shows Post now / Retry / Mark posted (the card owns them behind its
  dialog). `OutreachPanel` polls at 1, 2, 4 then 10 s.
- **No native confirm** remains in `views/admin/Outreach*.svelte`; pinned by
  `outreachNoNativeConfirm.guard.test.ts`.
- **Deviations from the plan.** (1) The composer keeps Schedule / the picker in
  card mode: the card's "Schedule…" button opens the composer for its picker,
  so hiding it would remove scheduling; Pass 2 can revisit. (2) Per-card
  notices live in the list (a map keyed by post id) rather than inside each
  card, so the both-networks result can write to two cards; the card renders
  and writes them through `notice`/`onNotice`. (3) Copy also writes a
  "Copied." notice that clears after the same 2 s.
