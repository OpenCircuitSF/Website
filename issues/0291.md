## Description

`#0125` makes three fields mandatory before an import commits: `source`,
`collected_at`, and `consent_note`. That matches its own acceptance criteria.

**PRD §6.10 names four.** It lists `source_detail` among the fields a
`subscriber_imports` row requires, and §6.10.1 builds the invitation sentence
from it — which is the second reason those fields are mandatory, not a
formatting nicety. `migrations/000023` leaves the column nullable.

So the code matches the issue and the issue is narrower than the spec. Nothing
is broken today, because nothing yet reads `source_detail` for anything
load-bearing.

**`#0129` will need it non-empty**, since the invitation copy it sends is
assembled from it. An invitation that says an address was collected at *(blank)*
is worse than one that fails to send.

## Acceptance criteria

1. `source_detail` is `NOT NULL` and non-empty on `subscriber_imports`,
   enforced in the database as well as in `ImportStore.Commit`'s validation.
2. **The column change goes in a NEW migration.** `000023` is frozen — see
   CLAUDE.md §1: the greenfield exception expired on 2026-08-25 and
   `000001`–`000022` were already frozen before it; anything applied to
   production since is frozen too. Write an `ALTER TABLE`, not an edit.
3. Decide what happens to any existing rows with a null or empty
   `source_detail`. If there are none — establish that rather than assume it —
   say so in the migration's comment, and still make the migration safe if one
   appears.
4. `Commit` refuses with a clear error naming the field, consistent with how it
   already refuses an empty `source` or `consent_note`.
5. The admin import wizard collects it and marks it required, so the refusal is
   not the first time an operator learns it is mandatory.
6. Verify against PRD §6.10 directly — `sed -n '/^### 6\.10 /,/^#\{2,3\} [0-9]/p' PRD.md`
   — and quote the sentence that requires it in the work log, so the next reader
   does not have to re-derive the justification.
7. `ISSUE=NNNN scripts/check.sh` passes with no skips.
