## Description

`#0125` makes three fields mandatory before an import commits: `source`,
`collected_at`, and `consent_note`. That matches its own acceptance criteria.

**PRD §6.10 names four.** It lists `source_detail` among the fields a
`subscriber_imports` row requires, and §6.10.1 builds the invitation sentence
from it — which is the second reason those fields are mandatory, not a
formatting nicety. `migrations/000023` leaves the column nullable.

So the code matches the issue and the issue is narrower than the spec. Nothing
is broken today, because nothing yet reads `source_detail` for anything
load-bearing.

**`#0129` will need it non-empty**, since the invitation copy it sends is
assembled from it. An invitation that says an address was collected at *(blank)*
is worse than one that fails to send.

## Acceptance criteria

1. `source_detail` is `NOT NULL` and non-empty on `subscriber_imports`,
   enforced in the database as well as in `ImportStore.Commit`'s validation.
2. **The column change goes in a NEW migration.** `000023` is frozen — see
   CLAUDE.md §1: the greenfield exception expired on 2026-08-25 and
   `000001`–`000022` were already frozen before it; anything applied to
   production since is frozen too. Write an `ALTER TABLE`, not an edit.
3. Decide what happens to any existing rows with a null or empty
   `source_detail`. If there are none — establish that rather than assume it —
   say so in the migration's comment, and still make the migration safe if one
   appears.
4. `Commit` refuses with a clear error naming the field, consistent with how it
   already refuses an empty `source` or `consent_note`.
5. The admin import wizard collects it and marks it required, so the refusal is
   not the first time an operator learns it is mandatory.
6. Verify against PRD §6.10 directly — `sed -n '/^### 6\.10 /,/^#\{2,3\} [0-9]/p' PRD.md`
   — and quote the sentence that requires it in the work log, so the next reader
   does not have to re-derive the justification.
7. `ISSUE=NNNN scripts/check.sh` passes with no skips.

**PRD §6.10 (criterion 6)**, `sed -n '/^### 6\.10 /,/^#\{2,3\} [0-9]/p' PRD.md`:

> **Every import declares its provenance up front.** A `subscriber_imports`
> row is created before any address is inserted, and it requires:
>
> - `source` — `luma`, `eventbrite`, `meetup`, `manual_csv`, `other`
> - `source_detail` — the specific event or export it came from
> - `collected_at` — when the *source* collected the addresses, not when we
>   imported them
> - `consent_note` — how consent was obtained, in the admin's own words.
>   Required, non-empty.

and, from §6.10.1: "The source sentence is built from
`subscriber_imports.source`, `source_detail`, and `collected_at`, which is the
second reason those three fields are mandatory." That second sentence is the
one this issue's Description quotes as the motivating reason.

**Criterion 3 — existing rows, established not assumed.** `subscriber_imports`
has exactly one producer, `ImportStore.Commit` (`internal/subscribers/imports.go`),
and `#0125` — which created this table — resolved the same day this issue was
filed against its review. Every other mandatory field (`source`, `consent_note`,
`collected_at`) was already enforced by `Commit` before this change; nothing in
the tree seeds `subscriber_imports` rows outside that one path (`grep -rn
"subscriber_imports" cmd/ scripts/` finds no seed/fixture producer). So no row
with a null or empty `source_detail` is expected to exist anywhere this
migration runs. The migration's `UPDATE ... WHERE source_detail IS NULL OR
btrim(source_detail) = ''` backfill runs unconditionally regardless, and was
proven safe empirically (see Verification) by inserting exactly such rows into
a pre-migration scratch database and confirming the migration backfills both to
a labeled placeholder rather than failing.

**Decision (criterion 1/2).** New migration `migrations/000024_require_subscriber_imports_source_detail.{up,down}.sql`:
backfill any null/empty row, `ALTER COLUMN source_detail SET NOT NULL`, add
`subscriber_imports_source_detail_check CHECK (btrim(source_detail) <> '')` —
matching `consent_note`'s existing NOT NULL + CHECK shape exactly.
`migrations/000023` is untouched.

**Go layer (criterion 4).** `internal/subscribers/imports.go`: new
`ErrSourceDetailRequired`, checked in `Commit` right after the enum
validations and before the `consent_note` check (mirroring field order).

since the value is now guaranteed non-blank after validation — matching how
`consent_note` (also mandatory) is already passed straight through.
`internal/handlers/admin_subscribers_import.go`: `Commit` maps
