## Description

```go
e := audit.Entry{Metadata: map[string]any{"slug": s}}
e.Metadata["email"] = addr    // hasEmail=false, unresolved=""  — SILENT PASS
```

The left-hand side is an `*ast.IndexExpr`, while
`collectDeferredMetadataFieldIdents` requires an `*ast.SelectorExpr`. So the
guard does not see it, and an entry carrying a subscriber's address passes as
email-free.

**What makes this one more plausible than the two shapes `#0255` chose to pin:
the local-variable form of the identical mutation is already caught.**

```go
m := map[string]any{"slug": s}
m["email"] = addr
e := audit.Entry{Metadata: m}   // hasEmail=true — correctly caught
```

Both express the same intent. The caught version and the missed version differ
by a one-line reordering of code the tree already contains — not by an exotic
construct nobody writes. No production site uses the missed form today
(verified: no `.Metadata[` anywhere in production code), which is the condition
under which this kind of gap survives unnoticed.

## Notes

Reported by `#0255`'s phase-3 review under `CLAUDE.md` §9. Eighth shape found
in this file across seven review rounds.

**The pattern is now clear enough to act on.** Every round has closed the shape
it was shown and left an adjacent one open, because the guard enumerates AST
node types it recognises and anything else is silence. `#0252` and `#0255` both
landed on the right mitigation — *pin what you do not close* — but pinning only
helps for gaps someone has already thought of.

**Worth considering in this pass:** rather than adding a ninth node type,
invert the default. Any write to a `Metadata` map that the guard cannot fully
resolve should report `unresolved` rather than pass, so an unrecognised shape
fails loudly instead of silently. That is the `#0083`/`#0092`/`#0224`
silent-row-masking lesson, which this project has now paid for four times. If
that inversion is impractical — it may produce false positives on legitimate
code — say why, and pin this shape instead.
