## Description

`#0242`'s guard requires an in-branch `role="status"` region to be either a
persistent node or a whole-panel swap with a wired focus move. To avoid false
positives it first **unwraps single-child containers**, because every multi-state
view wraps its whole branch in one container div.

`#0242`'s review established that the unwrap is **principled, not fitted** — it
checked the four sites it defends and each is genuinely a persistent node in a
stable branch, so the naive rule really did produce false positives. The unwrap
stays.

But it means the criterion holds only for the **sole-content case**. Of the 47
in-branch status sites, roughly **24 get no check at all**. This passes the
guard:

```svelte
{#if err}<div class="wrap"><h2>Oops</h2><p role="status">{err}</p></div>{/if}
```

That is `#0244`'s own item 1 shape — `PreferenceCenter`'s two-child branch. The
guard `#0242` built would not have found the defect `#0244` fixed.

The boundary is disclosed, not hidden: it is written into the guard's own header
comment under "Disclosed boundary" and in `#0242`'s work log. That is the right
instinct, and it is why `#0242` was resolved rather than bounced again. But a
disclosed gap is still a gap.

## Why it was not folded into `#0242`

`#0242`'s second pass was scoped to one falsified criterion (the guard scanned
`web/src/views` rather than `web/src`). Closing this gap means extending the
classifier to require a focus-swap target for *any* in-branch status site, plus
building a named allowlist for the genuinely stable branches — comparable in
size to the guard's original construction. Folding that into a bounce fix would
have been a redesign smuggled into a correction.

## Acceptance criteria

1. Any in-branch `role="status"` site requires a wired focus-swap target,
   regardless of whether it is the sole content of its branch.
2. The genuinely stable branches are named in an allowlist mirroring
   `KNOWN_LOADING_PLACEHOLDERS`, each with a written justification. See
   [#0280](0280.md) — if that has landed, follow whatever keying and
   justification rules it established rather than inventing new ones.
3. The single-child unwrap is either removed as no longer needed or retained
   with its reasoning restated against the new rule. Do not leave two
   overlapping mechanisms whose interaction is unexplained.
4. Prove the new rule catches the two-child shape above — a fixture exhibiting it
   must fail the guard. Per CLAUDE.md §8, the oracle must not be the same bytes
   as the subject.
5. Every site count is re-derived from the scan, not edited by hand. The current
   figures are 38 files scanned, 56 alert sites, 30 status sites, 20 placeholders.
6. The `filesScanned` floor `#0242` added stays, and the guard still fails closed
   if the scan visits implausibly few files.
7. `ISSUE=NNNN scripts/check.sh web` passes.
