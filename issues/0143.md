## Description

`#0056`'s announce shortcut targets the draft campaign at the workshop's interests in `any_of` mode. When the workshop carries **no** interests it falls back to audience mode `all` — every confirmed subscriber — because `any_of` with zero interests is refused store-side.

The fallback itself is correct. `#0056`'s reviewer checked the option space and found it narrower than it looks: the four modes are `all`, `any_of`, `all_of`, and `none_selected`, and `none_selected` is a *real segment* (subscribers who chose no interests), not a blank. So the only alternatives are `all` or refusing outright, and `all` is defensible because `#0047`'s send gate shows the count and a sample and requires a server-verified typed recipient count before anything goes out.

**The defect is the silence.** The panel copy says the draft is "targeted at its interests", which is false in exactly this case. An admin announcing a workshop they never tagged gets a draft aimed at the entire list while being told otherwise.

## Root cause

`WorkshopEditor.svelte`'s Announce panel had one hardcoded sentence — "targeted
at its interests" — that assumed the workshop always has interests. `#0056`'s
`Announce` handler falls back to audience mode `all` when the workshop's saved
`interest_ids` is empty (`any_of` is refused store-side with zero interests),
so in that case the panel's claim was simply false: the admin was told the
draft targeted the workshop's interests while it actually targeted every
confirmed subscriber, with nothing surfacing the difference before the draft
was created.

## Fix

Added `announceTargetingDescription(interestIds: number[]): string` to
`web/src/lib/workshopAdmin.ts` — the copy decision lives there, not as an
inline ternary in the component, per `CLAUDE.md`'s SPA-logic convention. It
returns one of two sentences depending on whether `interestIds` is empty:

- Zero interests: `"This workshop has no interests set, so the draft will
  target everyone on the list."`
- One or more interests: `"It will be targeted at this workshop's
  interests."`

`WorkshopEditor.svelte`'s Announce panel now interpolates that sentence
between the existing "Create a draft campaign…" and "Nothing is sent…"
sentences.

**Deliberate choice on which interest ids to pass in:** the function is
driven by `workshop.interest_ids` (the last-loaded/saved value on the
`AdminWorkshop` object), **not** `fields.interestIds` (the local, possibly
unsaved checkbox buffer). `POST /admin/workshops/{id}/announce` takes no
request body — it reads the persisted row server-side — so if an admin has
toggled interest checkboxes but not yet clicked Save, the copy must still
describe what Announce will actually do (the saved state), not the pending
edit. This matches the issue's framing: the defect is the panel lying about
what actually happens, and only the saved value is what actually happens.

No targeting logic was touched — `internal/handlers/admin_workshop_announce.go`
and the `all`/`any_of` fallback are unchanged, per the issue's explicit
instruction not to undo `#0056`'s reviewer-approved fallback.
