## Description

Phase 2 of the Outreach design: **Post now** and **Schedule** for the two
automatic channels, sent through the durable outbound queue with retries, and
the resulting post's id/URL recorded on the `outreach_posts` row.

Design doc section "Posting to Bluesky and Mastodon, and manual channels":
https://claude.ai/artifact/DzCWVhfcqJbc9uSfWLVfhG

## Acceptance criteria

- [x] Bluesky: app-password session (`com.atproto.server.createSession`), cached and refreshed (createSession is capped at 300/day); `com.atproto.repo.createRecord` with `app.bsky.feed.post`; link and hashtag **facets** with correct UTF-8 byte offsets; an `app.bsky.embed.external` card (URL, title, summary, cover thumbnail uploaded via `uploadBlob`, ≤ 1,000,000 bytes or skipped). 300-grapheme limit enforced before sending.
- [x] Mastodon: `POST /api/v1/statuses` with bearer token and an `Idempotency-Key`; link preview left to the instance.
- [x] Plain `net/http` clients (no `indigo`); unit tests against `httptest` fakes, including facet offsets for non-ASCII text.
- [x] Config, all optional: `BLUESKY_HANDLE`, `BLUESKY_APP_PASSWORD`, `BLUESKY_PDS_URL` (default `https://bsky.social`), `MASTODON_BASE_URL`, `MASTODON_TOKEN`. A channel without credentials shows as "not configured" and falls back to manual. `.env.example` and `docs/configuration.md` updated.
- [x] Scheduled/now posts are enqueued on the existing outbound queue with a new kind, reusing its backoff/abandon policy; success sets `posted`, `posted_at`, `remote_id`, `remote_url`; exhaustion sets `failed` with `last_error` and a **Retry** action.
- [x] Unsent posts are held (not sent) when the workshop is canceled or unpublished.
- [x] UI: Post now / Schedule (default times per wave) and Retry in the composer and panel.
- [x] Verified with `ISSUE=0545 scripts/check.sh`; no real network calls in tests.

### Decisions (so the implementer does not have to make them)

1. **No migration.** `outreach_posts` already has `status` (CHECK includes
   `scheduled`, `queued`, `failed`), `scheduled_at`, `posted_at`,
   `remote_id`, `remote_url`, `last_error`. `outbound_queue.kind` has no
   CHECK, so a new kind needs no migration either (`000021`'s own comment).
   This also keeps this issue out of the Phase 10 migration-number race.
2. **A scheduled post reaches `outbound_queue` only when it is due** (the
   design's words: "becomes a row on `outbound_queue` at its time"). Do **not**
   enqueue future rows with `outbox.Item.Delay`: the admin dashboard's
   outbound-queue tile (`admin_dashboard.go`, `outbox.Store.Counts`) counts
   every `queued` row, so a post scheduled three weeks out would sit in the
   mail queue's numbers for three weeks. Instead the publisher (step 4) runs
   a **promoter** each pass that turns due `scheduled` posts into `queued`
   posts plus one outbox row, in one transaction. Rescheduling or
   unscheduling is then a plain row update — there is never a queue row to
   cancel.
3. **The post row is the source of truth for what is sent.** The outbox
   payload is only `{"post_id": N}`. The worker re-reads the post and its
   workshop at send time. To make that safe, a `queued` post is **locked**:
   no body edit, regenerate, delete, mark-posted, or reschedule while it is
   in flight or awaiting a retry. `scheduled` posts stay editable.
4. **Idempotency without new columns.**
   - **Mastodon:** `Idempotency-Key: opencircuitsf-outreach-post-{postID}` —
     per post, not per queue row. Mastodon remembers a key for about an hour
     and only after a status is actually created, so an automatic retry after
     a timeout that did post returns the original status instead of a
     duplicate, and so does a manual Retry within the hour. A key per queue
     row would let a manual Retry duplicate a post whose final attempt timed
     out after succeeding.
   - **Bluesky** has no idempotency header, so use a **deterministic record
     key**: `createRecord` accepts an explicit `rkey`, and `app.bsky.feed.post`
     keys are TIDs. Derive it per post:
     `bluesky.TID(post.CreatedAt.UnixMicro(), uint16(post.ID & 1023))`.
     Before every `createRecord`, call `com.atproto.repo.getRecord` for that
     rkey; if it exists, the post already went out (an earlier attempt timed
     out after success) — record it as posted with the existing URI and do
     not create a second one. Not found (`400 {"error":"RecordNotFound"}`, or
     404) means create it. One extra GET per post buys exactly-once.
5. **Error classes.** Each client returns `*APIError` carrying
   `Permanent bool`. Permanent errors (bad credentials 401/403, Bluesky
   `AuthFactorTokenRequired`/`AccountTakedown`, validation 400/422 other
   than expired-token, text over limit, channel not configured) **fail the
   post immediately**: call the outbox's existing
   `MarkRetryOrAbandon(ctx, id, attempts, msg, 0)` — `maxRetries = 0` makes
   `attempts >= 0` true, so the row goes straight to `abandoned` with no new
   outbox method. Everything else (network, timeouts, 5xx, 429) is
   transient: `MarkRetryOrAbandon` with `settings.queue_max_retries`, i.e.
   the email queue's exact six-step backoff and abandon policy.
6. **Thumbnail source is local disk only.** `workshops.cover_image` holds a
   same-site path like `/media/soldering-101.jpg` (`docs/media.md`). Resolve
   it to `filepath.Join(cfg.MediaDir, filepath.Base(path))` only when the
   value starts with `/media/` and `MEDIA_DIR` is set; read it, require
   `media.Sniff` → JPEG or PNG and `len ≤ 1_000_000`. Anything else (absolute
   URL, missing file, too big, other format) → **no thumbnail**, card still
   sent. Never fetch a URL from the server (no SSRF surface, and the site
   would be fetching itself). A failed `uploadBlob` is also non-fatal: log a
   warning, post without the thumb.
7. **Graphemes: one small dependency, `github.com/rivo/uniseg` v0.4.7**
   (`uniseg.GraphemeClusterCount`). Justification: Bluesky's limit is 300
   UAX #29 grapheme clusters and the server rejects anything over it, so the
   Go check must agree with the server; doing that from the standard library
   would mean hand-copying Unicode's `Grapheme_Cluster_Break` and
   `Extended_Pictographic` property tables, which the stdlib does not ship.
   uniseg has **zero dependencies**, is MIT-licensed, is the de-facto Go
   implementation, and v0.4.7 is already in this machine's module cache (so
   `go get github.com/rivo/uniseg@v0.4.7` works offline). The SPA keeps
   `Intl.Segmenter` (`#0544`'s `countCharacters`), which implements the same
   algorithm; the Go check is the authority.
8. **Hold on cancel/unpublish = never send while the workshop's status is
   not `published`**, enforced in three places: Post now / Schedule refuse
   with 409; the promoter does not promote; the worker re-checks at claim
   time. A post that comes **due** while held is returned to `draft`
   (`scheduled_at = NULL`, `last_error = "Held: the workshop was canceled
   when this post was due. Reschedule to send it."` — or "unpublished" for
   `draft`), so republishing a workshop never fires a stale burst of
   past-due posts on its own; a not-yet-due scheduled post simply stays
   `scheduled` and sends on time if the workshop is republished first. The
   design's "offer a canceled post on channels that already posted" is its
   phase 5 (cancellation posts), **out of scope** here.
9. **One endpoint for Post now and Retry.** `POST .../send` accepts a post in
   `draft`, `scheduled`, or `failed`; the UI labels the button **Retry** when
   the status is `failed`. Audit metadata carries `retry: true` then.
10. **Default schedule times per wave** (design: "announce now, reminder 7
    days before, last-call 1 day before"): announce has no default schedule
    (its primary action is Post now); reminder and last-call default to the
    wave's `suggested_at`, which `#0544`'s panel view already computes
    (`starts_at − DaysBefore`, keeping the workshop's clock time). A
    suggestion already in the past, or null (no `starts_at`), leaves the
    picker empty with a hint.
11. **A channel without credentials falls back to manual.** The panel's
    channel list gains `configured` (automatic channel with a working
    client). An automatic channel with `configured: false` shows "not
    configured" and behaves exactly like a manual channel (Copy content /
    Mark posted, `#0544`'s flow). Partial credentials (handle without
    password, base URL without token) count as not configured and log one
    warning at boot naming the variable that is missing — never its value.

### Step 2 — `internal/bluesky` (new package, plain `net/http`, no `indigo`)

Mirror `internal/shortlinks/client.go`'s shape (constructor returning a nil
client when unconfigured, `Enabled()` nil-safe, `DefaultTimeout = 15s`,
error sentinels, never put a secret in an error).

`client.go`:

```go
func New(pdsURL, handle, appPassword string) (*Client, error) // (nil, nil) if handle or password blank; error only for a malformed pdsURL
func (c *Client) Enabled() bool                                // c != nil

type PostInput struct {
    Text      string
    RKey      string        // from TID(...), decision 4
    CreatedAt time.Time
    Embed     *ExternalCard // nil → no card
}
type ExternalCard struct {
    URI, Title, Description string
    Thumb       []byte // nil → no thumb; uploaded via uploadBlob
    ThumbMIME   string // "image/jpeg" | "image/png"
}
type PostResult struct{ URI, CID, RKey, WebURL string; AlreadyExisted bool }

func (c *Client) Post(ctx context.Context, in PostInput) (PostResult, error)
```

`Post` = `ValidateText` (permanent error if over) → `getRecord` (decision 4;
found → `AlreadyExisted: true`, return) → optional `uploadBlob` (decision 6;
failure non-fatal, logged by the caller via a returned warning or a
`slog.Logger` field) → `createRecord` with
`{"repo": did, "collection": "app.bsky.feed.post", "rkey": rkey, "record":
{"$type": "app.bsky.feed.post", "text", "createdAt" (RFC 3339 UTC, ms),
"langs": ["en"], "facets": DetectFacets(text), "embed": {"$type":
"app.bsky.embed.external", "external": {"uri", "title", "description",
"thumb": <blob object>}}}}`. The blob object from `uploadBlob`'s response
(`{"blob": {...}}`) is passed through verbatim as `json.RawMessage` — do not
model its fields. `WebURL = "https://bsky.app/profile/" + handle + "/post/" + rkey`
using the handle from the session response.

**Session cache** (`session.go`), guarded by a `sync.Mutex`, in memory only:
`{accessJwt, refreshJwt, did, handle}`.
- No session → `POST /xrpc/com.atproto.server.createSession`
  `{"identifier": handle, "password": appPassword}`.
- Every authed call goes through one helper: send with
  `Authorization: Bearer accessJwt`; on `400 {"error":"ExpiredToken"}` or
  `401` → `POST /xrpc/com.atproto.server.refreshSession` with
  `Authorization: Bearer refreshJwt`, store the new pair, **retry once**;
  if the refresh itself fails with 400/401 → drop the session, one
  `createSession`, retry once; a second auth failure is permanent.
- `createSession` 401 (`AuthenticationRequired`) or
  `AuthFactorTokenRequired` → permanent `ErrAuth`; 429 → transient
  `ErrRateLimited` (createSession is capped at 30/5 min and 300/day — the
  cache is what keeps us far below it; a restart costs one login).
- Never log or wrap a JWT or the password; errors carry the XRPC `error`
  code and a message with the password/JWTs `strings.ReplaceAll`-redacted,
  as `shortlinks.decodeError` does for its token.

`facets.go` — `DetectFacets(text string) []Facet` (and the `Facet` JSON
types: `{"index": {"byteStart", "byteEnd"}, "features": [{"$type":
"app.bsky.richtext.facet#link", "uri"} | {"$type":
"app.bsky.richtext.facet#tag", "tag"}]}`):
- Go strings are UTF-8, so `regexp.FindAllStringIndex` returns **byte**
  offsets directly — use them as-is; never convert through `[]rune`.
- Links: `https?://[^\s]+`, then trim trailing `.,;:!?'"` and a trailing `)`
  when the match has no `(`. Only scheme-ful URLs (the short URL always has
  one); bare domains are left as text.
- Tags: `#` at start of text or after whitespace, followed by
  `[\p{L}\p{M}\p{N}_]+` (strip trailing punctuation as above), not all
  digits, ≤ 64 runes; `tag` is the text **without** `#`; the facet range
  includes the `#`.
- Sort by `byteStart`; no overlaps (a `#` inside a URL is part of the link).

Test table (`facets_test.go`, assert exact `byteStart`/`byteEnd` and that
`text[byteStart:byteEnd]` is the expected substring):

| Text | Expect |
|---|---|
| `See https://go.example/abc` | link 4–26 |
| `Café https://go.example/k` | link 6–26 (`é` is 2 bytes) |
| `🔧 Solder #DIY https://go.example/k.` | tag `DIY` 12–16; link 17–37 (emoji 4 bytes; trailing `.` excluded) |
| `👩‍👩‍👧 family #Workshop` | tag `Workshop` 26–35 (ZWJ sequence = 18 bytes) |
| `東京 #電子工作 https://go.example/x` | tag `電子工作` 7–20; link 21–41 |
| `(see https://go.example/a)` | link excludes the `)` |
| `#123 a#tag https://go.example/p#frag` | no tags; one link including `#frag` |
| `` (empty) | no facets |

(Offsets verified with a byte-level Python check at planning time; the
implementer still recomputes each from the bytes when writing the
test — build the expected offsets with `strings.Index` in the test only as a
cross-check, never as the sole oracle.)

`graphemes.go` — `GraphemeCount(s) int` (uniseg), `const MaxGraphemes = 300`,
`const MaxTextBytes = 3000`, `ValidateText(s) error` (empty/whitespace,
over either limit → permanent `*APIError` with `Kind = ErrTextTooLong` /
`ErrInvalid`). Tests: ASCII, `é` precomposed vs `e` + U+0301 (both 1),
ZWJ family (1), flag 🇺🇸 (1), skin-tone 👍🏽 (1), 300 vs 301 emoji, a 3001-byte
string of 1001 three-byte CJK runes failing on bytes.

`tid.go` — `TID(micros int64, clock uint16) string`: 64-bit value =
`micros << 10 | clock&1023` with the top bit 0, encoded big-endian as 13
chars of base32-sortable `234567abcdefghijklmnopqrstuvwxyz`. Tests: length
13, matches `^[234567abcdefghij][2-7a-z]{12}$`, strictly increasing with
time, two clocks at the same micro differ, and one fixed vector computed by
hand in the test comment (e.g. `TID(0, 0) == "2222222222222"`).

`client_test.go` (`httptest.Server` fake PDS that records requests):
one `createSession` across three `Post`s; expired access token →
`refreshSession` then success, no second `createSession`; refresh failure →
exactly one new `createSession`; bad password → permanent, no retry loop;
request body has the exact facets and `rkey`; `getRecord` hit → no
`createRecord`, `AlreadyExisted`; thumb uploaded with the right
`Content-Type` and the returned blob object embedded verbatim; `uploadBlob`
500 → post still created without `thumb`; 429/500 on `createRecord` →
transient; 400 `InvalidRequest` → permanent; no error string contains the
password or either JWT; `New("", ...)` → nil client, `Enabled() == false`.

`internal/outreach/publish_store.go` (SQL on `outreach_posts`, so it lives in
the package that owns the table). `outreach.Store` gains an unexported
`outbox *outbox.Store`, set inside the existing `NewStore(pool)` as
`outbox.NewStore(pool)` — no signature change for `#0544`'s callers. New
sentinels `ErrPostInFlight` (status `queued`), `ErrWrongStatus`,
`ErrWorkshopNotPublished`. Methods:

- `QueueNow(ctx, id) (Post, prevStatus string, error)` — one tx:
  `UPDATE outreach_posts p SET status='queued', scheduled_at=now(),
  last_error=NULL, updated_at=now() WHERE p.id=$1 AND p.status IN
  ('draft','scheduled','failed') AND p.short_url IS NOT NULL AND EXISTS
  (SELECT 1 FROM outreach o JOIN workshops w ON w.id=o.workshop_id WHERE
  o.id=p.outreach_id AND w.status='published') RETURNING …` (read
  `prevStatus` with a `SELECT … FOR UPDATE` first in the same tx), then
  `s.outbox.EnqueueTx(ctx, tx, outbox.Item{Kind: outbox.KindOutreachPost,
  Recipient: "outreach_post:" + id, Payload: map[string]any{"post_id": id}})`.
  `outbound_queue.recipient` is `NOT NULL`; this label is not an address.
  Zero rows → classify (`ErrNotFound`, `ErrPostLocked`, `ErrPostInFlight`,
  `ErrNotPrepared`, `ErrWorkshopNotPublished`, `ErrWrongStatus`).
- `Schedule(ctx, id, at time.Time) (Post, error)` — `status IN
  ('draft','scheduled','failed')`, prepared → `status='scheduled',
  scheduled_at=$2, last_error=NULL`.
- `Unschedule(ctx, id) (Post, error)` — `scheduled` → `draft`,
  `scheduled_at=NULL`.
- `PromoteDue(ctx, limit int) (promoted, held int, err error)` — one tx:
  `SELECT p.id, w.status FROM outreach_posts p JOIN outreach o ON
  o.id=p.outreach_id JOIN workshops w ON w.id=o.workshop_id WHERE
  p.status='scheduled' AND p.scheduled_at <= now() ORDER BY p.scheduled_at,
  p.id LIMIT $1 FOR UPDATE OF p SKIP LOCKED`; published → set `queued` +
  `EnqueueTx` in the same tx; otherwise → `draft`, `scheduled_at=NULL`,
  `last_error` = the held message (decision 8).
- `LoadForSend(ctx, postID) (SendJob, error)` — post joined to its workshop:
  `SendJob{Post; WorkshopStatus, Title, Slug string; Summary, CoverImage *string}`.
- `MarkRemotePosted(ctx, id, remoteID, remoteURL string, now) (bool, error)`
  — `WHERE status='queued'` → `posted`, `posted_at`, `remote_id`,
  `remote_url`, `last_error=NULL`.
- `MarkSendError(ctx, id, msg string, final bool) (bool, error)` — `WHERE
  status='queued'`; `final` → `status='failed'`; always sets `last_error`
  (truncate to 500 chars).
- `HoldQueued(ctx, id, msg) (bool, error)` — `queued` → `draft`,
  `scheduled_at=NULL`, `last_error=msg`.

**Change `#0544`'s existing guards** so `queued` is locked: `UpdatePostBody`,
`MarkPosted` and `DeletePost` become `… AND status NOT IN ('posted','queued')`,
and `classify` maps a `queued` row to `ErrPostInFlight`. `SetPrepared` is
unaffected (a queued post is always prepared). The handler maps
`ErrPostInFlight` → 409 "post is being sent".

`internal/outreach/publisher.go`:

```go
type Settings interface{ GetSetting(ctx context.Context, key string) (string, error) }
type PublisherDeps struct {
    Store    *Store
    Outbox   *outbox.Store
    Settings Settings
    Bluesky  *bluesky.Client   // nil → channel not configured
    Mastodon *mastodon.Client  // nil → channel not configured
    MediaDir string
    BaseURL  string            // unused for posting today; keep out if unused
    PollInterval time.Duration // default 15s
    Log      *slog.Logger
}
func NewPublisher(d PublisherDeps) *Publisher
func (p *Publisher) ChannelConfigured(name string) bool // nil-safe; "bluesky"/"mastodon" by client Enabled(); false otherwise
func (p *Publisher) Run(ctx context.Context)
func (p *Publisher) Stop(ctx context.Context) error
```

Shape copied from `mailing.OutboxWorker` (stop channel + done channel +
`stopOnce`; `Run` loops until stop). Each pass:
1. `OrphanSweep` scoped to `[]outbox.Kind{outbox.KindOutreachPost}`, stale
   after 5 minutes (comfortably above one row's 60 s send budget).
2. `Store.PromoteDue(ctx, 10)`.
3. `SelectDue` (batch 5) scoped to the same one-kind slice, then
   `ClaimRow` per id — the per-row claim model `#0297` settled for the
   mail worker. **Every claim call passes the explicit one-kind slice**;
   never `outbox.AllKinds`, nil, or an empty literal
   (`TestNoUnscopedOutboxClaimCallOutsidePackage`).
4. Per claimed row, with a 60 s context: decode `post_id` (bad payload →
   permanent abandon); `LoadForSend`; post not `queued` (edited/deleted
   meanwhile) → `MarkDone` and stop; workshop not `published` →
   `MarkSkipped(row, "workshop not published")` + `HoldQueued`; channel not
   configured → permanent failure "Bluesky is not configured on this
   server"; `outreach.ValidateForSend` fails → permanent failure; else post:
   - bluesky: `PostInput{Text: body, RKey: bluesky.TID(post.CreatedAt.UnixMicro(), uint16(post.ID&1023)), CreatedAt: now, Embed: &ExternalCard{URI: *post.ShortURL, Title: title, Description: summary or "", Thumb/ThumbMIME per decision 6}}`;
     `remote_id = URI` (`at://…`), `remote_url = WebURL`.
   - mastodon: `PostStatus(ctx, body, "opencircuitsf-outreach-post-"+id)`;
     `remote_id = Status.ID`, `remote_url = Status.URL`.
   - Success → `MarkRemotePosted` then outbox `MarkDone`.
   - Error → permanent? `MarkRetryOrAbandon(…, 0)` + `MarkSendError(final=true)`;
     transient → `max := effectiveMaxRetries` (settings
     `queue_max_retries`, fallback `outbox.DefaultMaxRetries`, copied from
     `mailing.OutboxWorker.effectiveMaxRetries`);
     `final := row.Attempts >= max`; `MarkRetryOrAbandon(…, max)` +
     `MarkSendError(final)`.
   - `last_error` text is user-facing and must be secret-free: "Bluesky
     rejected the post: InvalidRequest — …", "Mastodon is unreachable
     (attempt 3 of 8); retrying", etc.
5. `Stop` releases nothing it has not claimed; a row mid-send at stop is
   left `sending` and returned by the next orphan sweep (same reasoning as

Criteria and load-bearing decisions, checked against the code:

- **Exactly-once on retry.** `postBluesky` derives the rkey as a TID from
  the post's `created_at` microseconds and `id & 1023`, so every attempt
  for one post uses the same key. `Client.Post` calls `getRecord` before
  `createRecord`. A 404 or `RecordNotFound` means "create". A hit returns
  `AlreadyExisted` and creates nothing, which
  `TestPost_ExistingRecordIsNotRecreated` and
  `TestPublisher_BlueskyExistingRecordNotRecreated` both check. Mastodon
  sends `Idempotency-Key: opencircuitsf-outreach-post-{id}`, which is per
  post, not per queue row, so a manual Retry reuses it. When the post goes
  out but recording it fails (`MarkRemotePosted` error), the row is retried
  rather than marked done, and the retry finds the existing post. The TID
  encoding is 13 characters of the sortable alphabet with the top bit
  cleared, and `TID(0,0)` is all `2`s.
- **Facets and limits.** The facet code uses `regexp` byte offsets directly
  and never converts through runes. The test table hard-codes every planned
  offset. I byte-checked the fixtures: the ZWJ in the family sequence is the
  real `e2 80 8d` (18 bytes total), the combining case really is `e` plus
  U+0301, and the byte-limit fixture is one grapheme in 3003 bytes. The
  300-grapheme check uses `uniseg.GraphemeClusterCount`, with 300 vs 301
  emoji tested. Mastodon counts code points with each URL weighted at 23,
  limit 500. The limit is enforced three times: by the handler (400), by the
  publisher's `ValidateForSend` (permanent failure), and by the client's
  `ValidateText`.
- **Outbox kind.** The `KindOutreachPost` doc comment contains no claim call
  syntax. The `kindExceptions` entry in mailing has a reason. Every sweep,
  select and claim passes `publisherKinds`, a one-kind slice. The
  claim-kinds and claim-comment guards in `internal/outbox` and the mail
  kinds guard in `internal/mailing` all passed. Permanent errors go to
  `MarkRetryOrAbandon(..., 0)` and are abandoned at once. Transient errors
  use `queue_max_retries` with the shared backoff, and `final` uses the same
  `attempts >= max` predicate as the SQL, since `ClaimRow` has already
  counted the attempt. Classification: Bluesky 401, 403, auth-factor,
  takedown and other 4xx are permanent; 429, 5xx and network errors are
  transient. Mastodon 401, 403, 422 and other 4xx are permanent; 429, 5xx
  and network errors are transient.
- **PromoteDue** runs one transaction:
  `FOR UPDATE OF p SKIP LOCKED`, then for each row either `queued` plus
  `EnqueueTx`, or `draft` with the held message. `QueueNow` takes the post
  row lock first, so a concurrent promote and Post now serialise, and the
  loser's guarded `UPDATE` finds the row `queued` and reports
  `ErrPostInFlight`.
- **Holds** are enforced in four places. Send and Schedule refuse with 409:
  the handler gate checks first, and the store `EXISTS` clause closes the
  race. The promoter turns a due post of an unpublished workshop back into a
  draft. The claim-time re-check calls `MarkSkipped` and `HoldQueued`. A
  not-yet-due scheduled post stays `scheduled`.
- **Queued lock.** Edit and regenerate (`UpdatePostBody`), mark-posted and
  delete all require `status NOT IN ('posted','queued')`, and `classify` maps
  a refusal to `ErrPostInFlight`, which the handler returns as 409.
