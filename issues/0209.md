## Description

`#0165` made the `cmd/opencircuit` wiring tests fail loudly rather than corrupt
each other if any of them ever gained `t.Parallel()`. Its phase-3 review
confirmed the hazard by reproduction (**13/13 failures** without the guard, with
both predicted symptoms: `sessions_user_id_fkey` violations and spurious 401s)
and confirmed the guard fires 5/5 with zero corruption.

It also confirmed the gap the guard cannot close, **empirically**: a **fifth**
test that calls `truncateAdminWiringTables` with `t.Parallel()` and **without**
`registerWiringTest` brings the original corruption straight back — spurious
401s in 2 of 3 runs, and `ERROR: deadlock detected (SQLSTATE 40P01)` in the
third.

So today's guard protects tests that follow the pattern; it does not protect the
package against a test that skips it. The limitation is stated plainly in the
helper's doc comment, and all four current callers do register — this is a
latent gap, not a live defect.

**The fix is a shape this repo already uses.** `#0181`'s citation guard walks
source with the AST and fails on a forbidden pattern. The same technique applies
here: fail if any `cmd/opencircuit` test file contains a real `t.Parallel()`
call. That protects the package rather than the well-behaved test.

**Two smaller items from the same review:**

- `registerWiringTest(t, pool)` never uses `pool`. Probably deliberate, for
  call-site symmetry with `truncateAdminWiringTables(t, pool)` — but it implies
  a per-pool or per-database scope when the claim is a package-level global.
  That global **is** the right scope, since the hazard is in-process. Drop the
  parameter, or document why it is there.
- `#0165`'s Description says "five fixed literal session tokens". There are
  **six**: `wiring-nonadmin-token`, `wiring-admin-token`,
  `zz-events-nonadmin-token`, `zz-events-admin-token`, `seo-wiring-admin-token`,
  `zz-shutdown-budget-token`. A miscount in the filing, not in the code.

## Acceptance criteria

- [ ] A test fails if any file under `cmd/opencircuit` contains a real `t.Parallel()` call
- [ ] It reads source structurally (AST), not by text match, so a comment or a string mentioning `t.Parallel()` does not trip it — `#0181`'s guard is the model
- [ ] Adding `t.Parallel()` to any `cmd/opencircuit` test makes it fail, naming the file and line — demonstrated by mutation
- [ ] The failure message explains **why** the constraint exists and points at `registerWiringTest`, so the next person meets the reason rather than a rule
- [ ] The guard does not itself trip on the `cmd/opencircuit` files as they stand
- [ ] `registerWiringTest`'s unused `pool` parameter is dropped or documented
- [ ] `#0165`'s guard still fires 5/5 with zero corruption, and the claim still releases on failure, skip, and panic
- [ ] `ISSUE=0209 scripts/check.sh go ./cmd/... ./internal/...` passes with zero skips

## Notes

Reported by `#0165`'s phase-3 review under `CLAUDE.md` §9.

The review's own probes are the regression suite: four tests in declaration
order where A fatals mid-body holding the claim, B skips holding it, and C and D
then claim cleanly — proving release is a `t.Cleanup`, which Go runs on failure,
skip and panic alike.

Worth keeping in mind while writing the message: the review judged that the
**guard itself** is the discovery path that works, better than a doc comment
someone would have had to already be reading. Whoever reaches for `t.Parallel()`
gets a fatal error naming the constraint on their first run. The same reasoning
applies to this issue's guard, so spend the effort on the message.

Read `#0165`'s `## Review notes` before starting — it records why the
scoped-`DELETE` rewrite was rejected, and why tokenising cannot remove the
truncate dependency (the tests also seed three **fixed literal emails** into a
`UNIQUE NOT NULL` column).

## Implementation notes

**New file:** `cmd/opencircuit/wiring_parallel_guard_test.go`. Copies
`internal/handlers/citation_guard_test.go`'s shape: `go/ast`-walk every `.go`
file under the package directory (via `filepath.WalkDir`, rooted at this
file's own directory through `runtime.Caller(0)`), collect violations, and
fail with one message listing every hit.

- `scanFileForParallelCalls` walks only `*ast.CallExpr` nodes shaped
  `<ident>.Parallel()` with zero arguments — comments and string literals are
  different AST node kinds and are never visited as calls, so
  `TestParallelGuardIgnoresCommentsAndStrings` proves a comment or string
  containing the literal text `"t.Parallel()"` cannot trip it. The match is
  not limited to a receiver literally named `t`
  (`TestParallelGuardCatchesAliasedReceiver` proves `tt.Parallel()` is
  caught too) and does not type-check the receiver against `*testing.T` —
  `cmd/opencircuit` has no other type with a zero-arg `Parallel()` method
  (`grep -rn '\.Parallel(' cmd/opencircuit` was zero before this guard), so
  the untyped match costs nothing today; the doc comment records why.
- The failure message explains the mechanism (shared tables, wholesale
  `TRUNCATE` on entry and `t.Cleanup`, no per-test isolation), names the
  concrete failure symptoms `#0165`'s review measured (FK violation,
  spurious 401, `SQLSTATE 40P01` deadlock), and points at
  `registerWiringTest(t)` — then explicitly states what `registerWiringTest`
  does *not* catch (an unregistered `t.Parallel()` caller), which is exactly
  this guard's own reason to exist. Every identifier in it is pasteable
  (`#0187`): fully-qualified helper and function names, `*_wiring_test.go`,
  `t.Parallel()`, `#0165`, `#0209`.
- **Confirmed the guard does not trip on itself:** `TestNoWiringTestUsesParallel`
  scans the whole `cmd/opencircuit` directory, including its own file, whose
  doc comment mentions the literal text `t.Parallel()` eight times. It
  passed — zero violations — because none of those occurrences is a
  `*ast.CallExpr`.

**`registerWiringTest`'s unused `pool` parameter (small item):** dropped, not
documented. `registerWiringTest(t *testing.T)` now takes no pool — the claim
is a package-level `atomic.Pointer[string]` global, correctly so, since the
hazard is in-process, and a `pool` parameter implied a per-database scope
that was never real. Updated all four call sites
(`admin_wiring_test.go:77`, `events_wiring_test.go:49`,
`seo_wiring_test.go:96`, `shutdown_budget_wiring_test.go:131`) and the one
doc-comment reference to the old signature. `go build ./cmd/...` and
`go vet ./cmd/...` clean after the change.

**Mutation proof (own tree, no DB needed — the guard is pure AST):**
recorded `shasum -a 256` of `events_wiring_test.go`
(`0b1aeec2772c06d1c92651143c68f1c9a8e8c24bda65b9ac7d103e0b7c9fd391`), added
`t.Parallel()` after its `registerWiringTest(t)` call, ran
`go test ./cmd/opencircuit/... -run TestNoWiringTestUsesParallel -v`. Failed
immediately, naming `.../events_wiring_test.go:50:2: t.Parallel()` inside the
full explanatory message. Restored the file and reverified `shasum -a 256`
byte-identical to the recorded hash.

**Unregistered-fifth-test proof (the gap `#0165`'s review described):** added
a temporary `TestFifthWiringTestSkipsRegister` that calls
`truncateAdminWiringTables` and `t.Parallel()` with no
`registerWiringTest(t)` call, matching the review's reproduction shape. Ran
`TestNoWiringTestUsesParallel` alone, with `TEST_DATABASE_URL` **unset** —
the AST guard needs no database connection at all, unlike
`registerWiringTest`'s runtime check, which only fires once a test with a
live DB actually executes. It failed immediately, naming
`zzz_fifth_wiring_test.go:27:2: t.Parallel()`, before the fifth test's body
could ever run (a `go test` build that fails a static source scan never
reaches the point of dialing a database). Removed the file afterward;
`git status --porcelain cmd/opencircuit/` confirmed no stray file remained.

**Four-probe regression (`#0165`'s claim-release proof, re-run against the
`pool`-dropped signature):** added four temporary tests in declaration order
— A calls `registerWiringTest(t)` then `t.Fatal`s mid-body holding the
claim; B calls it then `t.Skip()`s holding it; C and D call it and pass.
`go test ./cmd/opencircuit/... -run TestZZZProbe -v` produced `--- FAIL: A`,
`--- SKIP: B`, `--- PASS: C`, `--- PASS: D` — C and D both claimed cleanly
after A and B, confirming release is still a `t.Cleanup` that runs on
failure and skip alike now that the claim no longer touches `pool`. Removed
the file afterward.

**Five-run reproduction (`#0165`'s original regression bar, re-verified
against a live database):** created `opencircuit_test_0209` via
`scripts/testdb.sh create 0209`. Recorded `shasum -a 256` of
`admin_wiring_test.go` and `events_wiring_test.go`, added `t.Parallel()`
after each test's `registerWiringTest(t)` call, and ran
`go test ./cmd/opencircuit/... -run 'TestMountAndServe_AdminRoutesRequireSessionAndAdmin|TestMountAndServe_EventsRequiresSessionAndAdmin' -v -parallel 2`
five times against the real database. **5/5 runs failed at
`registerWiringTest`** (`TestMountAndServe_EventsRequiresSessionAndAdmin`
lost the claim race in all five; which side loses varies run to run per
`#0165`'s review and is not a property this guard needs to control), with
zero FK violations and zero spurious 401s in any run — the loser fatals
before its first `truncateAdminWiringTables`, so the winner runs alone.
Restored both files and reverified `shasum -a 256` byte-identical to the
recorded hashes.

Rejected nothing new beyond what `#0165`'s review already rejected (scoped
`DELETE`, tokenising) — this issue's guard is additive to that decision, not
a revisit of it.

**Nothing found worth filing beyond this issue's own scope.**
