## Description

`#0165` made the `cmd/opencircuit` wiring tests fail loudly rather than corrupt
each other if any of them ever gained `t.Parallel()`. Its phase-3 review
confirmed the hazard by reproduction (**13/13 failures** without the guard, with
both predicted symptoms: `sessions_user_id_fkey` violations and spurious 401s)
and confirmed the guard fires 5/5 with zero corruption.

It also confirmed the gap the guard cannot close, **empirically**: a **fifth**
test that calls `truncateAdminWiringTables` with `t.Parallel()` and **without**
`registerWiringTest` brings the original corruption straight back — spurious
401s in 2 of 3 runs, and `ERROR: deadlock detected (SQLSTATE 40P01)` in the
third.

So today's guard protects tests that follow the pattern; it does not protect the
package against a test that skips it. The limitation is stated plainly in the
helper's doc comment, and all four current callers do register — this is a
latent gap, not a live defect.

**The fix is a shape this repo already uses.** `#0181`'s citation guard walks
source with the AST and fails on a forbidden pattern. The same technique applies
here: fail if any `cmd/opencircuit` test file contains a real `t.Parallel()`
call. That protects the package rather than the well-behaved test.

**Two smaller items from the same review:**

- `registerWiringTest(t, pool)` never uses `pool`. Probably deliberate, for
  call-site symmetry with `truncateAdminWiringTables(t, pool)` — but it implies
  a per-pool or per-database scope when the claim is a package-level global.
  That global **is** the right scope, since the hazard is in-process. Drop the
  parameter, or document why it is there.
- `#0165`'s Description says "five fixed literal session tokens". There are
  **six**: `wiring-nonadmin-token`, `wiring-admin-token`,
  `zz-events-nonadmin-token`, `zz-events-admin-token`, `seo-wiring-admin-token`,
  `zz-shutdown-budget-token`. A miscount in the filing, not in the code.

## Implementation notes

**New file:** `cmd/opencircuit/wiring_parallel_guard_test.go`. Copies
`internal/handlers/citation_guard_test.go`'s shape: `go/ast`-walk every `.go`
file under the package directory (via `filepath.WalkDir`, rooted at this
file's own directory through `runtime.Caller(0)`), collect violations, and
fail with one message listing every hit.

- `scanFileForParallelCalls` walks only `*ast.CallExpr` nodes shaped
  `<ident>.Parallel()` with zero arguments — comments and string literals are
  different AST node kinds and are never visited as calls, so
  `TestParallelGuardIgnoresCommentsAndStrings` proves a comment or string
  containing the literal text `"t.Parallel()"` cannot trip it. The match is
  not limited to a receiver literally named `t`
  (`TestParallelGuardCatchesAliasedReceiver` proves `tt.Parallel()` is
  caught too) and does not type-check the receiver against `*testing.T` —
  `cmd/opencircuit` has no other type with a zero-arg `Parallel()` method
  (`grep -rn '\.Parallel(' cmd/opencircuit` was zero before this guard), so
  the untyped match costs nothing today; the doc comment records why.
- The failure message explains the mechanism (shared tables, wholesale
  `TRUNCATE` on entry and `t.Cleanup`, no per-test isolation), names the
  concrete failure symptoms `#0165`'s review measured (FK violation,
  spurious 401, `SQLSTATE 40P01` deadlock), and points at
  `registerWiringTest(t)` — then explicitly states what `registerWiringTest`
  does *not* catch (an unregistered `t.Parallel()` caller), which is exactly
  this guard's own reason to exist. Every identifier in it is pasteable
  (`#0187`): fully-qualified helper and function names, `*_wiring_test.go`,
  `t.Parallel()`, `#0165`, `#0209`.
- **Confirmed the guard does not trip on itself:** `TestNoWiringTestUsesParallel`
  scans the whole `cmd/opencircuit` directory, including its own file, whose
  doc comment mentions the literal text `t.Parallel()` eight times. It
  passed — zero violations — because none of those occurrences is a
  `*ast.CallExpr`.

**`registerWiringTest`'s unused `pool` parameter (small item):** dropped, not
documented. `registerWiringTest(t *testing.T)` now takes no pool — the claim
is a package-level `atomic.Pointer[string]` global, correctly so, since the
hazard is in-process, and a `pool` parameter implied a per-database scope
that was never real. Updated all four call sites
(`admin_wiring_test.go:77`, `events_wiring_test.go:49`,
`seo_wiring_test.go:96`, `shutdown_budget_wiring_test.go:131`) and the one
doc-comment reference to the old signature. `go build ./cmd/...` and
`go vet ./cmd/...` clean after the change.

**Mutation proof (own tree, no DB needed — the guard is pure AST):**
recorded `shasum -a 256` of `events_wiring_test.go`
(`0b1aeec2772c06d1c92651143c68f1c9a8e8c24bda65b9ac7d103e0b7c9fd391`), added
`t.Parallel()` after its `registerWiringTest(t)` call, ran
`go test ./cmd/opencircuit/... -run TestNoWiringTestUsesParallel -v`. Failed
immediately, naming `.../events_wiring_test.go:50:2: t.Parallel()` inside the
full explanatory message. Restored the file and reverified `shasum -a 256`
byte-identical to the recorded hash.

**Unregistered-fifth-test proof (the gap `#0165`'s review described):** added

### Boundary probes — what the guard catches and what it misses

Exercised `scanFileForParallelCalls` directly against twelve synthetic sources.
The verdict column is mine, not the implementer's.

| Shape | Result | Does the miss matter? |
|---|---|---|
| `t.Run("x", func(t *testing.T) { t.Parallel() })` | **caught** `t.Parallel()` | — the most plausible real-world form, and it is covered. This was the one genuine gap worth worrying about; it does not exist. |
| `t.Parallel()` inside a helper func in the same package | **caught** | — covered |
| `defer t.Parallel()` | **caught** | — covered |
| `go t.Parallel()` | **caught** | — covered |
| `(t).Parallel()` | **caught** as `<expr>.Parallel()` | — covered; the `<expr>` fallback degrades gracefully and still names file:line |
| `x.t.Parallel()` (struct-field receiver) | **caught** as `<expr>.Parallel()` | — covered |
| `b.Parallel()` on `*testing.B` | **caught** | — correct: same shared-table hazard, same verdict |
| `p := t.Parallel; p()` (method value) | **miss** | **No.** A curiosity. Nobody writes this to opt a test into parallelism; catching it would need `go/types`, and the cost is not repaid. |
| `(*testing.T).Parallel(t)` (method expression) | **miss** | **No.** Same class — one argument, so the zero-arg rule excludes it. Deliberate-obfuscation territory, not accident territory. |
| `t.Parallel()` inside a raw string literal | **miss (correct)** | Required non-fire, not a gap |
| `t.Parallel()` inside an interpreted string literal | **miss (correct)** | Required non-fire, not a gap |
| `c.Parallel()` on a non-`testing` type | **caught** | A false **positive**, discussed below |

The two real misses are both "you would have to be trying". The one shape a
future author would plausibly reach for — `t.Parallel()` inside a subtest
closure — is caught, at the closure's own line. That is the property that
decides whether this guard is worth having, and it holds.

### Self-scan and the string-literal risk — verified by execution, and stronger than claimed

`TestNoWiringTestUsesParallel` passes while scanning its own file. Confirmed
*why* by two independent routes:

- The real scan calls `parser.ParseFile(fset, path, nil, 0)` — mode `0`, so
  comments are not attached to the AST at all. The doc comment's occurrences of
  the literal text are not merely "not CallExprs"; they are not nodes.
- The string-literal case is not hypothetical here and needs no synthetic
  fixture: `wiring_parallel_guard_test.go` itself embeds two raw-string fixture
  sources containing real `t.Parallel()` and `tt.Parallel()` **calls** as text
  (lines 208 and 232). The guard scans that file and reports zero violations.
  So the file is its own live proof.

I pushed on the string-literal question further by dropping a real file into
`cmd/opencircuit/` containing twelve interpreted string literals with
`t.Parallel()` in them and running the real guard over the real directory: zero
violations, `--- PASS`. A future test file carrying `t.Parallel()` in a string
cannot trip this. Criterion 2 is satisfied structurally, not by luck.

(Minor: the `## Implementation notes` say the doc comment mentions the literal
text "eight times"; the top doc comment has seven, and the file as a whole has
twenty-one. Immaterial to the claim, and the same species of miscount this very
issue was filed to correct in `#0165` — noted for symmetry, not as a defect.)

### The type-check decision — checked, not accepted

The implementer's argument is that no other zero-argument `Parallel()` method
exists in the package. **Verified true today**: `grep -rn "func .*Parallel" cmd/`
returns only this guard's own functions, and every `.Parallel(` hit in
`cmd/opencircuit/` is comment or string text. So the untyped match costs nothing
now.

What happens when it stops being true, tested rather than reasoned about: I
added a non-test file defining `type seedRunner struct{}` with a zero-arg
`Parallel()` method and one call site. The guard **fires**, naming
`…/zzz_0209rev_falsepos.go:8:40: s.Parallel()`.

Judgement: acceptable, and the failure is legible enough. It is a `go test`
failure (not a `go build` failure — the commit message's "fails the build" is
loose), the failing test is named `TestNoWiringTestUsesParallel`, and the
offending line names a file that is visibly not a `*_wiring_test.go` and a
receiver visibly not `t`. Anyone hitting it lands in
`wiring_parallel_guard_test.go`, whose doc comment already anticipates this
exact case in its "Match rule" paragraph. The alternative — a `go/types` check —
buys precision the package will probably never need at the cost of loading type
information for a guard that must stay cheap. Correct trade, correctly recorded.

*Worth reporting, not blocking:* the failure message itself says nothing about
the over-fire case, so a future author meets a wall of TRUNCATE prose for a
receiver that has nothing to do with `*testing.T`. One clause — "if the receiver
below is not a `*testing.T`, this guard has over-fired; see its Match rule" —
would close the last gap between the message and the doc comment. Reported to
the orchestrator per `CLAUDE.md` §9, not filed.

### The unregistered-fifth-test proof — reproduced

This is the property that makes the guard complement `registerWiringTest` rather
