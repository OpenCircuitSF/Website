## Description

`#0455` made `issueStatus`'s fence **opener** strict — it now requires an indent
of three columns or fewer and rejects a backtick in the opener's info string.
The **closer** was deliberately left lenient, on the reasoning that closing early
can only ever un-hide a row, never hide one.

`#0455`'s reviewer probed that reasoning and found **it is not quite true**.
Given, above a status row:

1. a fence opener at column 0,
2. then a fence-shaped line indented four columns,
3. then an unindented fence-shaped line,

CommonMark closes once — the indented line is content inside the fence — and
reads the row. The walk instead **closes on the indented line, re-opens on the
next, and hides the row**. So the closer's leniency feeds a later opener, and the
pair produces a dangerous-direction divergence that neither branch produces
alone.

This is **identical before and after `#0455`** — that commit neither introduced
nor worsened it — and was not covered by `#0454`'s 18-document probe.

## Why it was reported rather than bounced

`#0455`'s behaviour matches its criteria as written, the exposure is the same
structural zero as before (every genuine issue file carries its status row at
line 5 with nothing fence-shaped above it), and the reviewer judged a round-trip
for a parenthetical to cost more than it buys.

What it does falsify is a **claim**: the implementer's statement that closing
early "only ever un-hides a row, never hides one", and the shipped doc comment's
unqualified "(safe-direction)" parenthetical which inherits it.

## Acceptance criteria

1. Gate the **closing** branch on `leadingIndentWidth(line) <= 3`, reaching
   parity with `docTableRowLines`' closer on the point `#0092` already hardened
   there. Reuse the existing helper; add no new one.
2. **Do not adopt `#0092`'s trailing-text half.** A closer that accepts trailing
   text is one of the safe-direction divergences `#0455`'s criterion 3 protects,
   and `#0455`'s review confirmed all four remain unmoved. Closing that half
   would trade a loud failure for a silent one.
3. Reword the doc comment's "(safe-direction)" parenthetical so it no longer
   claims the closer can only un-hide a row.
4. Prove it against the **real** compiled `issueStatus`, not a re-implementation
   (`#0441`'s review), using the three-line sequence above and the safe-direction
   shapes as controls. Confirm the four safe-direction divergences still do not
   move. Use a throwaway `git worktree`; never `git stash` (§8a).
5. Re-derive the corpus counts and confirm **no genuine issue file changes
   classification**. `#0455`'s review measured 459 files, 458 with a status, 30
   `open`/`in-progress` — re-derive rather than copy; the corpus grows as issues
   are filed, and mis-attributing that drift has already happened once.
6. **No new mechanism** (§8, `#0258`). One branch condition and a comment.
