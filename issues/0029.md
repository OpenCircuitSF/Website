## Description

The signup form used both inline on the home page and standalone at `/subscribe`: email field, interest checkbox grid, and the invisible anti-abuse fields.

## Acceptance criteria

- [ ] Email input plus a checkbox grid of active interests fetched from `GET /api/interests`
- [ ] Checkboxes are real `<input type="checkbox">` inside a `<fieldset>` with a `<legend>` — no div-based fakes
- [ ] Honeypot `website` field present and hidden from assistive technology as well as sighted users
- [ ] Form-open timestamp captured and submitted for the timing gate
- [ ] Optional `preselect` prop pre-checks interests (used by workshop pages in #0054)
- [ ] Submission always shows the same neutral success state and routes to `/subscribe/thanks`
- [ ] Errors announced via `aria-live="polite"` and tied to their field with `aria-describedby`
- [ ] Submit button disabled with a visible pending state during the request
- [ ] Keyboard navigable; verified with VoiceOver
- [ ] `npm run check` and `npm test` pass, including a test that the success state does not vary by response
- [ ] A visible link to `/privacy` sits next to the submit button — transferred
      from `#0070` at its review, 2026-08-18. PRD §11 requires the privacy policy
      to be linked "in the footer **and next to the signup button**"; the footer
      half shipped in `#0017` and the page itself in `#0070`, but this half could
      not be done there because this component did not exist. It is binding here:
      `#0070` will not be reopened for it

## Carried in from `#0024`'s review (2026-08-19)

- [ ] **Source the form's checkboxes from `ListActive`, never `ListAll`.**
      `#0024`'s admin UI tells admins that deactivating an interest "removes this
      interest from the public signup form" — but `#0026` enforces that only at
      *validation* time, rejecting inactive slugs with a 400. So a form built
      from `ListAll` makes that promise false and hands the user a 400 on a stale
      checkbox they were shown.
- [ ] **There is no public interests endpoint yet.** `interests.ListActive` has
      zero non-test callers today; this issue needs to add the public read path
      as well as consume it. Do not expose the admin route to the public SPA.

## Notes

PRD §7.3, §7.5. Hiding the honeypot with `display: none` is fine for bots but must also carry `aria-hidden="true"` and `tabindex="-1"` so a screen-reader user is never asked to fill it.

The success state must not leak whether the address was already subscribed — the component has to render identically regardless, or #0026's uniform 202 is undone at the UI layer.
