## Description

These came out of `#0653`'s review. Neither one affects production.

1. `internal/subscribers` `TestGrowth30Days_BoundaryAndSyntheticExclusion` failed once in a scoped multi-package run with 21 where it expected 19. It passes on its own and passed on a rerun, and the load was not the cause. It looks like the test counts rows that another package's test left behind in the shared per-issue database. Scope the count to rows the test creates itself. A silent decline path, per AGENTS.md §5, is the first thing to look for.
2. `#0653`'s mention exclusion has a bound, `captured_at <= until`. No test covers the case where a post's only later snapshot falls after `until`, so dropping that bound isn't caught. Add that case to the `TestEngagementWindow_*` tests.

## Acceptance criteria

- [ ] `TestGrowth30Days_BoundaryAndSyntheticExclusion` counts only its own rows, and passes alongside the other packages in one scoped run.
- [ ] A test fails if the `<= until` bound is removed from the mention exclusion.
