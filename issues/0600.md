## Description

Part two of option A from `docs/reviews/admin-nav-options.md` (§5 Issue 2).
Outreach's sub-nav (Posts · Flyer spots · Flyers · Results) and Settings'
section jump list (General · Server settings · Outreach) use different
idioms. Give them one shared component that sits visually below `#0599`'s
two nav rows.

## Acceptance criteria

- [x] New `SubNav.svelte` (in `web/src/lib/` or `web/src/views/admin/`): a
      `<nav aria-label>` of links with `aria-current`, styled as small
      chips (`--fs-base`, `--text-muted`; active is `--text` plus a 2px
      `--accent` edge), no underline, scrolling sideways under 480px.
- [x] `Outreach.svelte` uses it for Posts · Flyer spots · Flyers · Results.
- [x] The Settings jump nav in `Admin.svelte` uses it for General · Server
      settings · Outreach, keeping its `onclick` scroll and `?section=`
      deep links.
- [x] The existing sub-nav assertions in `OutreachList.behavior.test.ts` and
      the Settings-section assertions in
      `Admin.hashRouting.behavior.test.ts` keep passing (update selectors
      only if markup must change; say so). Add a small behaviour test for
      `SubNav` itself.
- [x] From `#0599`'s review: a row that scrolls sideways (row two in
      `Admin.svelte` and `SubNav`) shows a fade at its right edge while
      more items are off-screen, so iOS users can see there is more. Pure
      CSS (for example a mask or gradient) is fine; it must not hide
      focus rings or make the page scroll horizontally.
- [x] Verified with `ISSUE=0600 scripts/check.sh web`. Evidence is jsdom.
