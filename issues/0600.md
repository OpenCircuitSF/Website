## Description

Part two of option A from `docs/reviews/admin-nav-options.md` (§5 Issue 2).
Outreach's sub-nav (Posts · Flyer spots · Flyers · Results) and Settings'
section jump list (General · Server settings · Outreach) use different
idioms. Give them one shared component that sits visually below `#0599`'s
two nav rows.

## Resolution

New `web/src/lib/SubNav.svelte` is the one sub-nav: a labelled `<nav>` of
plain links, muted `--fs-base` chips, the current one in `--text` with a 2px
`--accent` bottom edge, one line that scrolls sideways. Outreach (Posts ·
Flyer spots · Flyers · Results) and the Settings jump list (General · Server
settings · Outreach, keeping `onclick` scroll and `?section=` hrefs) both use
it. A global `.scroll-fade-x` class in `web/src/app.css` gives SubNav and
Admin's row two (`.subtabs`) a right-edge scroll shadow while items are
off-screen.

## Resolution notes

- The fade is a pure-CSS scroll shadow: a `--border` tint attached to the
  box, and a `--bg-page` cover attached to the content (`local`) that slides
  over it at the end of the scroll. It is a background, so it sits behind the
  links: it cannot hide the link focus indicator (an underline, app.css), and
  it adds no width. The cover is `--bg-page`, so the class only belongs on a
  row that sits on the page background. Both current uses do (directly in
  `.app-shell`).
- Settings' jump list used to wrap; it now stays on one line and scrolls,
  like Outreach.
- No existing test selector changed.

## Review notes

- **Verdict: approved** (Opus, 2026-10-18), with one small review fix
  (`a578b53b`).
- Every criterion checked against the code. Both uses of `.scroll-fade-x` sit
  directly in `.app-shell` on `--bg-page` (Outreach mounts bare in
  `Admin.svelte`, not in a `Panel`), so the hardcoded cover colour is right.
  All colours are tokens, so dark mode (both the media-query and
  `[data-theme="dark"]` blocks redefine `--bg-page` and `--border`) follows
  automatically. `.subtabs`' scoped styles set no `background`, so the global
  rule is not overridden.
- **Review fix (`a578b53b`):** (1) the cover and the shadow were both 24px,
  so at the end of the scroll the half-transparent part of the cover let
  about 17% of the shadow show through. The cover is now 48px (solid for
  half) against a 24px shadow, as in the usual scroll-shadow technique. (2)
  The shadow tint went from `--bg-subtle` to `--border`. `--bg-subtle` is
  about 1.08:1 against `--bg-page` in light mode, too faint to signal
  anything. (3) Removed the left-edge cover, which had no shadow under it and
  did nothing. (4) The CSS-text test sliced from the selector to the end of
  the file, so text anywhere later could satisfy it. It now reads only the
  rule's own block, fails if the selector is missing, and pins which layer is
  `local` (the `--bg-page` cover) and which is `scroll`.
- **Ruling on the background approach vs a mask:** keep the background. A
  mask cannot depend on scroll position in pure CSS without scroll-driven
  animations, so it would fade the last item even when it is fully in view.
  The trade-off is that the cut-off item's text is not faded. The tint
  behind it plus the clipped edge carries the cue. **Safari risk is low.**
  WebKit has long supported `local` on overflow containers (iOS's well-known
  gap is `fixed`). If `local` were treated as `scroll`, the cover would stay
  over the shadow, so there would be no cue but nothing would break.
- **Ruling on the CSS-text test:** keep it, as a cheap tripwire that the
  mechanism is still there, now scoped to the rule. jsdom computes no
  backgrounds, so this is the only automated check available. It proves the
  rule's shape, not how it renders.
- **Mutation tests** (copy aside, sha256-verified restore, no stash or
  checkout): (a) `aria-current="page"` on every item failed "aria-current on
  the current one only"; (b) changing the cover's `local` to `scroll` failed
  the CSS test. Both restored byte-identically
  (`bea8740a…` SubNav.svelte, `70945533…` app.css).
- **Evidence is jsdom plus reasoning.** No browser was run (AGENTS.md §8), so
  how the shadow looks on iOS Safari has not been seen.
- Also removed a duplicate empty `## Work log` heading from this file.
