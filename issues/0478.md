# 0478 — An implementer's own notes are never scanned, because they are written after the verification run

| | |
|---|---|
| **Status** | open |
| **Platform** | Server |
| **Module** | issues |
| **Phase** | 8 — Archive, imports, and delivery health |
| **First seen** | 2026-09-08 |

## Description

`internal/db` carries a family of guards that scan **issue markdown** — citation
resolution, undefined test-function names, evidence citing a Go file by line
number, dangerous fenced blocks. They run as ordinary Go tests, so they only
ever see the issue file **as it stood when the suite last ran**.

`issues/Issues.md`'s phase 2 orders the work so that never includes the notes:

- **step 4** is the verification run;
- **step 7** drafts `## Root cause`, `## Fix`, `## Verification`, `## Files
  changed`, `## Gotchas`;
- **step 8** returns to the orchestrator.

There is no re-run between step 7 and step 8. **The text most likely to trip a
citation guard is written after the only run that could catch it.**

Phase 3 has no equivalent hole by accident: step 3 tells the reviewer to re-run
the verification itself, and the orchestrator's dispatches have separately been
telling reviewers to re-run *after* writing `## Review notes`. That convention
lives in dispatch prose, not in `Issues.md`, so it is re-invented per dispatch
and was never extended to phase 2 at all.

## How it surfaced

`#0476`'s implementer proved its fix with a throwaway test, deleted the file
before committing — correctly — and then named that function in its
`## Verification`. `TestNoOpenIssueVerificationCitesUndefinedTestFunction`
resolves cited names against the tree, so it failed on two lines.

The implementer's own verification run had passed, honestly and completely: the
offending text did not exist yet. The failure was found by a **third** agent, a
planning pass on an unrelated issue that happened to run `internal/db` over a
shared working tree while the file sat uncommitted.

That is the shape worth fixing. Nothing in the pipeline was looking; the catch
was luck, and it cost two agents a detour.

## Why it is worth a rule rather than more dispatch prose

This family has now tripped agents **five separate times in one session**, and
the mechanism differed every time — a run-on sentence sweeping an identifier
into the wrong migration's check, a test named before it existed, an
angle-bracket placeholder truncating to an undefined token, an admin-facing
string citing a docs path, and this one. Every trip was the guard behaving
correctly.

`CLAUDE.md` §8 already anticipates this in general terms, and its advice is to
rephrase rather than delete or relocate. What is missing is the *timing*: an
agent that writes prose after its last run has no way to learn it broke
something.

## Acceptance criteria

1. **Add the re-run to `issues/Issues.md` phase 2**, between drafting the
   sections and returning. Say which packages — `internal/db` at minimum, and
   `internal/handlers` when a Go comment or a `CLAUDE.md` heading was touched
   (`CLAUDE.md` §5).
2. **Record the phase-3 convention in the same place**, so re-running after
   writing `## Review notes` stops being per-dispatch prose.
3. **Do not build a mechanism that checks prose before it is written.**
   `CLAUDE.md` §8 is explicit that this is `#0258`'s spiral one level out. A
   documented re-run is the whole fix; a pre-commit hook, a guard-for-the-guards,
   or a linter that predicts guard trips is out of scope.
4. Keep the cost honest. `internal/db` is a small package; `internal/handlers`
   is ~8× a small one (`CLAUDE.md` §5a). The rule should ask for the cheap run
   by default and the expensive one only when the edit warrants it.
5. **Check whether the orchestrator's own issue-filing has the same hole.** New
   issue files are written and committed without any run at all. If so, say what
   the rule is there — this issue's own file included.

## Relation

- `#0268` widened the citation guard to scan `## Work log`, and `#0446`
  extended that reach — both increased the surface this timing gap exposes.
- `#0476` is where it surfaced; its reviewer found and rephrased the two lines.
- `#0258` is the precedent for **not** building a checker for the checkers.
- `CLAUDE.md` §8 records the rephrase-don't-relocate prescription this
  complements.
