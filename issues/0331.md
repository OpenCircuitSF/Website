## Description

`#0328` collapsed `template_version()` and `template_digest()` into a single
`template_state()` that reads version and digest in one `psql` call. Doing so
correctly removed a redundant `db_exists` probe — and with it the
`|| echo "none"` fallback that had been absorbing a failing `psql`.

The result is an unguarded failing assignment:

```
row="$(psql "$PGHOST_URL/$TEMPLATE" … )"
```

Under `set -euo pipefail`, a direct call with the template absent kills the
shell **silently**. `#0327`/`#0328`'s reviewer reproduced this.

**It does not bite today**, verified end to end: `TEMPLATE_DB=…_nope create`
still prints the friendly message and provisions, exit 0. It survives for two
incidental reasons, neither of which is the function's own doing:

1. `template_matches_disk` calls it bare, but only ever as an `if` condition,
   where `set -e` is suspended.
2. `warn_template_mismatch`'s `tv="$(template_state)"` is saved by a bash 3.2
   quirk the reviewer isolated: `row="$(exit 2)"` aborts on a direct call but
   **not** when reached from inside a command substitution.

So the code comment's "no existence probe needed" reasoning reaches the right
result by the wrong mechanism. Any future caller that invokes `template_state`
directly — not as an `if` condition, not inside a command substitution —
inherits a silent shell death with no message.

This is the shape `CLAUDE.md` §8 keeps warning about: a property that holds by
accident of context rather than by construction, on a bash 3.2 where the
failure is quiet.

## Acceptance criteria

1. `template_state()` cannot silently kill the shell when the template is
   absent, regardless of how it is called — the fix is a one-token
   `2>/dev/null || true` on the assignment, or equivalent.
2. The friendly-message path for an absent template still works: a
   `TEMPLATE_DB=<nonexistent> create` provisions and exits 0.
3. A direct (non-`if`, non-command-substitution) call with the template absent
   is proven not to abort — demonstrated under `/bin/bash`, not zsh (§8: the
   agent shell is zsh, the scripts are bash 3.2.57).
4. The stale code comment claiming no existence probe is needed is corrected to
   state why the function is safe on its own terms.
5. `shellcheck -S warning` stays clean.
