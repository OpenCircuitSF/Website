# 0630 — Creating hand-posted links can lose a draft and has untested overlap

## Description

Found in `#0623`'s review of `POST /admin/workshops/{id}/outreach/hand-links`. None blocks use, because the card's Draft button recovers a missing draft.

1. **Measured:** if the browser reloads or closes mid-pass, links can be left without their draft. Cancelling after the second create left 1 link and 0 drafts, and that slot is never drafted automatically afterward.
2. **Measured:** a draft made while its slot had no link, then deleted, returns on the pass that creates the link, because no record of the delete exists. Current production data cannot hit this; it needs a Draft click during a ShortLinks outage followed by a delete.
3. **Read in the code, not run:** two tabs opening at once could create one unused upstream link, because `idx_links_user_destination` in ShortLinks is not unique. The local slot still holds one link.

## Acceptance criteria

- [ ] The draft loop survives a client disconnect, for example by using `context.WithoutCancel`, with a test.
- [ ] A committed test covers overlapping passes, where a throwaway one exists only in the review.
- [ ] Item 2 is fixed or explicitly accepted, with the reason recorded.
