## Root cause

Follow-ups, not a single defect. `outbox.Store.Counts` counted every kind, so abandoned `outreach_post` rows lit the mail warning. Mastodon's `Idempotency-Key` lasts about an hour, so a late retry after an unknown outcome could post twice. `CountCharacters` counted trailing punctuation inside a URL. `thumbnail` read before checking size. Whitespace-only credentials were treated as unset without a log line.

## Fix

- `Counts` takes `WHERE kind <> 'outreach_post'`; the dashboard's queue depth and `outbound_queue_abandoned` both come from it, so social posts are excluded rather than relabelled.
- `mastodon.Client.FindRecentStatusWithURL` (verify_credentials, then the account's last 40 statuses) matches the short link as a whole token. `Publisher.postMastodon` calls it only when a prior attempt may have succeeded: the row was claimed before (`Attempts > 1`), or the post's `last_error` carries the transient "is unreachable or failing" text (manual Retry after a final timeout). A permanent earlier failure does not trigger it. If the lookup itself fails the row retries; it never posts blind.
- `mastodon.trimLinkEnd` mirrors the Bluesky helper and `CountCharacters` uses it.
- `thumbnail` stats (regular file, size 1..limit) before `ReadFile`.
- `warnPartialPostingCredentials` compares trimmed values and warns that a variable is set but whitespace only, naming the variable, never a value.
