## Description

On 2026-11-15 the user asked for the ESP32-C3 guide set: 15 topics in all, split across `#0670`, `#0671` and `#0672` so three agents can build them at once. Each one is built in its own worktree on the topic-guide framework from `#0656`, `#0666` and `#0667`. Every new topic sets `"set": "esp32"`, a set that already exists in the catalog. The board is the ESP32-C3 SuperMini.

Guides in this issue:

- `esp32-c3-boot-pins` — pins that can stop your board from booting
- `esp32-c3-reserved-pins` — pins with a second job
- `esp32-c3-analog-input` — analog input and ADC quirks
- `esp32-c3-pwm` — PWM on any pin
- `esp32-c3-power` — powering the C3 without USB

## Acceptance criteria

1. Each guide has its entry in `guides.json` with `"set": "esp32"`, a body in `topics.ts` and an interactive demo.
2. The logic is in a plain TS module with unit tests. Each demo has one jsdom behaviour test.
3. Illustrations are SVG rendered to PNG with `rsvg-convert`, or inline SVG. Never use a browser.
4. Facts are checked against Espressif's ESP32-C3 datasheet or Technical Reference Manual, or the arduino-esp32 docs.
5. `ISSUE=0671 scripts/check.sh` passes, and so do the scoped Go checks (`internal/guides`, `internal/seo`, `cmd/opencircuit`).

### Sources checked

- ESP32-C3 Series Datasheet v2.5: §3 Boot Configurations (strapping pins GPIO2/8/9; Table 3-1: GPIO9 weak pull-up, GPIO2/8 floating; Table 3-3: SPI boot = GPIO9 1, GPIO8 any; joint download = GPIO8 1, GPIO9 0; GPIO2 "does not determine" the mode but should be pulled up due to glitches); §2.3 GPIO restrictions (18/19 USB Serial/JTAG, 4–7 JTAG, 20/21 UART0, 12–17 flash); §4.2.1.7 LED PWM (six channels, up to 14-bit duty); §4.2.2.1 (ADC1 five channels, factory-calibrated; ADC2 one channel, inoperable on some revisions per errata); Table 5-2 (VDD 3.0–3.6 V); Table 5-6 (ATTEN3 effective range 0–2500 mV); VIH 0.75 × VDD.
- ESP-IDF ESP32-C3 GPIO and ADC oneshot pages (GPIO 0–4 = ADC1 ch 0–4, GPIO 5 = ADC2 ch 0; ADC2 oneshot no longer supported on C3).
- arduino-esp32 ADC API (12-bit default, `ADC_11db` = 0–2500 mV on C3, `analogReadMilliVolts` is calibrated) and LEDC API (`ledcAttach(pin, freq, resolution)`, `ledcWrite(pin, duty)`, six channels on the C3, 1–14 bits).

### Assumptions

1. The SuperMini's onboard LED runs from 3.3 V to GPIO 8 (it lights when the pin is LOW, per `supermini.ts`), so it holds GPIO 8 high at reset. Not checked against a schematic.
2. The analog model is illustrative: saturation just past 2.5 V, a ~40 mV dead zone near 0, ±30-count noise. Real curves differ chip to chip.
3. An LED to ground on a strapping pin is shown as "not clearly high or low" (about 2 V against the 0.75 × VDD ≈ 2.5 V threshold). It's an estimate, not a measurement.
4. The SuperMini regulator is assumed to be a small LDO rated about 6 V in (commonly an ME6211). That is why 4 × fresh alkaline AA (up to ~6.4 V) is "near the limit", 9 V is "damage", and a LiPo below about 3.7 V browns out. The board's 5V pin is assumed to connect to USB VBUS without a diode on many boards, so the guide says "check your board; safest is never both".
5. LEDC resolution uses an 80 MHz clock: max bits = floor(log2(80 MHz / f)), capped at 14. `analogWrite` is described as 0–255 (its 8-bit default).
6. 2 × AA on the 3.3 pin is "works, briefly": fresh cells give about 3.2 V, inside the 3.0–3.6 V range.
