## Description

A CSV export of the list for backup, analysis, and portability.

## Acceptance criteria

- [x] `GET /admin/subscribers/export` streams CSV
- [x] Columns: email, status, interests (semicolon-joined), confirmed_at, created_at, utm_source, utm_medium, utm_campaign
- [x] Respects the current status and interest filters
- [x] Streamed rather than buffered so a large list does not exhaust memory
- [ ] Export is audited — who exported, when, how many rows
- [x] Fields containing commas, quotes, or newlines are correctly quoted

## Notes

PRD §8. Auditing the export matters: a full list export is the highest-value action an admin account can take, and it is exactly what an attacker with a stolen session would do.

Guard against CSV injection — a leading `=`, `+`, `-`, or `@` in a field is executed as a formula when the file opens in Excel. Prefix such fields with a single quote.

**Amended 2026-08-21 by `#0046`'s second phase-3 review.** `subscribers` gained
a `synthetic boolean NOT NULL DEFAULT false` column in migration `000019`
(`#0046`): `true` only for the per-admin campaign test-send recipient rows
`ensureTestRecipient` creates. **The export must exclude `synthetic = true`.**
If this issue reuses `subscribers.Store.List` it inherits the exclusion for
free — `List` applies it unconditionally and it is not a `ListFilter` option.
If it writes its own streaming query instead (likely, given the "streamed
rather than buffered" criterion), that query must carry the predicate itself,
or every admin who has ever run a campaign test send puts a
`campaign-test+admin-<id>@internal.opencircuitsf.test` fixture row into an
operator-facing CSV.

## Fix

Added `GET /admin/subscribers/export`, gated by the same
`RequireSession`→`RequireAdmin` middleware chain as every other admin route
and registered through `cmd/opencircuit/main.go`'s `adminRoutes()` — so
`TestMountAndServe_AdminRoutesRequireSessionAndAdmin` (the single
authoritative wiring proof) covers it automatically, with no test edit
required.

- **Store layer**: `internal/subscribers/export.go` adds
  `Store.StreamExport(ctx, filter, fn)`, a new query rather than a reuse of
  `List` — it invokes `fn` once per `pgx` row as rows arrive (`rows.Next()`),
  never collecting a `[]Subscriber`, and computes each subscriber's
  interests with `string_agg(i.slug, ';' ORDER BY i.slug)` over a `LEFT
  JOIN`, so no per-row interest query is needed. `filter.InterestID` is
  applied as an `EXISTS` subquery, independent of the aggregation join, so
  filtering to "has interest X" never truncates a matching subscriber's
  OTHER interests out of the semicolon-joined column. `synthetic = false` is
  unconditional, per this issue's amended Notes.
- **Handler**: `internal/handlers/admin_subscribers_export.go` validates
  `status`/`interest_id` exactly like `List` (400 before any header is
  written), sets headers, then writes an `encoding/csv.Writer` directly over
  the `http.ResponseWriter` inside the `StreamExport` callback — so neither
  layer buffers the full result set. Ends with one `subscriber.exported`
  audit row (new `internal/audit/actions.go` constant), success or
  mid-stream failure, recording `row_count`, `filter_status`,
  `filter_interest_id`, `filter_query`.
- **Column set**: email, status, interests (semicolon-joined **slugs**, not
  display names — stable, and structurally CSV-safe since slugs are
  `interests_slug_format`-constrained lowercase-hyphenated), confirmed_at,
  created_at, utm_source, utm_medium, utm_campaign — exactly the eight
  columns above, nothing more. Deliberately excludes `confirm_token` /
  `manage_token` (live bearer credentials — no column even exists for them
  in `subscribers.ExportRow`), `id`, and
  `signup_ip`/`signup_user_agent`/`unsubscribed_at`/`unsubscribe_source`
  (not asked for, and not shown on the admin **list** screen either — only
  the one-row detail view has them).
- **CSV injection**: `csvInjectionGuard` prefixes any field whose first byte
  is `=`, `+`, `-`, or `@` with a single quote, per this issue's Notes.
  Applied to every externally-influenced text column: email, interests,
  utm_source, utm_medium, utm_campaign. `utm_*` is the realistic vector — it
  comes straight from the public, unauthenticated `/api/subscribe` query
  string.
- **NULL handling**: `derefOrEmpty`/`formatExportTime` map a nil pointer to
  `""`, never the literal text `<nil>`/`NULL`.
- **Headers**: `Content-Type: text/csv; charset=utf-8`,
  `Content-Disposition: attachment; filename="subscribers-export.csv"` (a
  fixed literal — no user input is ever interpolated into it), and
  `X-Content-Type-Options: nosniff`.

## Implementation notes — phase-3 bounce fix (2026-08-23, Sonnet)

Fixed the three defects from the phase-3 review (`## Review notes` above),
scoped exactly to `internal/handlers/admin_subscribers_export.go` and its
test, per the fix dispatch's instructions. `internal/subscribers/export.go`
needed no change — all three defects were in the handler.

1. **CSV injection leading-whitespace bypass.** `csvInjectionGuard` now
   trims leading Unicode whitespace (`strings.TrimLeftFunc` +
   `unicode.IsSpace`) before checking the first byte against `=+-@`, but
   still prepends the quote to the ORIGINAL (untrimmed) string — a leading
   apostrophe forces Excel to treat the whole cell as text regardless of
   what follows, so there's no need to also strip the whitespace, and the
   guard stays idempotent on re-export for the same reason as before (`'`
   itself is never one of the four guarded characters).
   `TestAdminSubscribers_Export_CSVEdgeCases` gained five new seeded rows —
   TAB, CR, LF, space, and vertical-tab prefixed formulas — asserting each
   is still guarded and that the whitespace survives after the inserted
   quote.
2. **Audit row lost on client disconnect.** `Export`'s `h.auditor.Record`
   call now runs under `context.WithoutCancel(r.Context())` instead of
   `r.Context()` — scoped to this one call site, this one handler. The other
   25 `Record` call sites in the tree are untouched, per the review's
   explicit boundary. New test
   `TestAdminSubscribers_Export_AuditedOnClientDisconnect` reproduces the
   review's own technique: a `disconnectContextMiddleware` (new, this test
   file only) hands `Export` an already-cancelled child of the
   authenticated request context — after `RequireSession`/`RequireAdmin`
   have attached the actor, so authorization is unaffected — reproducing
   exactly what a real client disconnect does to `r.Context()`. Asserts the
   `audit_log` delta is 1 and `metadata.error`/`metadata.row_count` are
   populated from the resulting `context canceled` stream failure.
3. **Doc comment / truncation signal.** Corrected the package doc comment's
   "truncated CSV and a broken pipe" claim — measured behavior is `200`, a
   valid `Content-Length`, a nil body-read error, and a well-formed but
   short CSV; no truncation signal reaches the client. Decision recorded in
   the doc comment: **did not** add `panic(http.ErrAbortHandler)`. Reasons:
   (a) it would change observable behavior for the admin console's own
   download on a failure mode that isn't this project's normal operating
   condition (CLAUDE.md §5: no performance requirement); (b) it must be
   sequenced strictly after the audit `Record` call or it reintroduces
   defect 2 in a different form, which is exactly the trap the review
   warned about; (c) the audit row's `metadata.error`/`row_count` already
   gives an operator the forensic signal a hard abort would only gesture
   at, which is enough for this issue's admin-console-only threat model.
   Revisit if this endpoint gains a non-human consumer (e.g. a scheduled
   backup job) that would act on a short file as if it were complete.

### What holds up

**The guard is real, proven by two independent mutations.**
`TestMountAndServe_AdminRoutesRequireSessionAndAdmin` genuinely **enumerates**
`adminRoutes()` (`for _, route := range adminRoutes(...)`) rather than
hand-listing paths, so the new route is covered with no test edit — the
implementer's claim is accurate. `TestAdminRoutesRegisteredOnlyViaTable`
(AST) additionally blocks the bypass of registering `/admin/*` outside the
table. Both mutations were run against my own database and both failed as
required, then passed again on restore (files restored byte-exact, verified by
`shasum`):

| Mutation | Result |
|---|---|
| `adminSubscribersMux`: export route `requireAdmin` → `requireSession` | `TestAdminSubscribers_NonAdminForbidden` FAILED — `GET /admin/subscribers/export with non-admin session: status = 200, want 403` |
| `mountAndServe`'s `adminRoutes` loop: `requireAdmin(r.handler)` → `requireSession(r.handler)` for the export path only | `TestMountAndServe_AdminRoutesRequireSessionAndAdmin` FAILED — `non-admin session: GET /admin/subscribers/export status = 200` |

So the refusal tests are worth something: with the guard gone, a non-admin
session pulls the entire list, and both tests say so.

**No credential can appear in the output — and it is the strong form of that
property.** `confirm_token`/`manage_token` are **never selected**, not selected
and dropped: `StreamExport`'s `SELECT` list is `s.email, s.status,
s.confirmed_at, s.created_at, s.utm_source, s.utm_medium, s.utm_campaign,
string_agg(i.slug…)` and `ExportRow` has exactly eight fields with no column
for either token. Probed end to end (planted known sentinel values into
`confirm_token`/`manage_token` on a seeded row, exported, searched the body):
neither token nor the substring `SECRET` appears. `signup_ip` and
`signup_user_agent` are likewise absent, which is the right call — they are
personal data (the privacy policy discloses them to the subscriber, not to a
CSV that gets emailed around), and the admin **list** screen does not show them
either; only the one-row detail view does.

**Streaming, filters, synthetic exclusion, and CSV quoting are all correct.**
`string_agg` over a `LEFT JOIN` with the interest filter as an independent
`EXISTS` subquery is the right shape — filtering to one interest does not
truncate a subscriber's other interests out of the joined column.
`synthetic = false` is unconditional. Round-tripped through
`encoding/csv.Reader` myself: comma, embedded double quote, embedded newline,
UTF-8 (`café ☕ 発売`), a 6000-byte field, and nil UTM pointers (`""`, never
`<nil>`) all survive exactly.

### Defect 1 — the CSV injection guard is bypassed by leading whitespace, and the bypass is reachable anonymously

`csvInjectionGuard` inspects `s[0]` only. Every classic whitespace-prefixed
formula walks straight past it. Probed end to end through the real handler and
a real database (`utm_source` seeded, exported, cell read back through
`csv.Reader`):

| Seeded `utm_source` | Exported cell | Guarded? |
|---|---|---|
| `=1+1` | `'=1+1` | yes |
| `+1+1` | `'+1+1` | yes |
| `-1+1` | `'-1+1` | yes |
| `@SUM(1)` | `'@SUM(1)` | yes |
| `	=cmd\|'/c calc'!A1` (TAB) | `	=cmd\|'/c calc'!A1` | **no** |
| `
=cmd\|'/c calc'!A1` (CR) | `
=cmd\|'/c calc'!A1` | **no** |
| `
=1+1` (LF) | `
=1+1` | **no** |
| ` =cmd\|'/c calc'!A1` (SPACE) | ` =cmd\|'/c calc'!A1` | **no** |
| `=1+1` (VT) | `=1+1` | **no** |
| `"=1+1` | `"=1+1` | not a formula — leading `"` makes it text; fine |

Leading TAB and CR are the two the OWASP guidance names alongside `=+-@`
precisely because spreadsheet importers trim them before evaluating the cell.
`encoding/csv` faithfully quotes these fields so they round-trip byte-exact
(confirmed), which is what makes the bypass work rather than what prevents it —
the quotes are stripped on import and the trimmed cell begins with `=`.

**This is reachable by an anonymous internet user.** `POST /api/subscribe`
takes `utm_source`/`utm_medium`/`utm_campaign` from the request body and stores
them **verbatim** — `subscribe.go` trims only `email`, and
`subscribers.Store`'s insert applies `nullIfEmpty` and nothing else. No
trimming, no length bound, no charset restriction anywhere on that path. So a
single unauthenticated signup plants a live formula into every future export.

The fix is small and belongs here: test the first **non-whitespace** byte (or
strip/reject leading control-and-space bytes before the check). Please also
extend `TestAdminSubscribers_Export_CSVEdgeCases` with the TAB and CR cases —
the current injection assertions only cover the four bare characters, so this
gap ships green today.

### Defect 2 — the audit row is lost on exactly the failure the audit exists to catch

`ActionSubscriberExported`'s doc comment and the Fix section both claim the
export is audited "unconditionally, success or a mid-stream failure". It is
not. `h.auditor.Record(r.Context(), …)` reuses the **request** context, and
`audit.Logger.Record` only logs a warning when the insert fails. When the
downloading client disconnects, `r.Context()` is cancelled, so the audit
`INSERT` is cancelled too. Proved by execution — `RequireSession` attaches the
user, a wrapper hands `Export` a cancelled child of that context (what a
disconnect produces), and the `audit_log` count is compared before and after:

```
ERROR admin subscribers export: stream failed error="…: context canceled" rows_written=0 actor_id=1
WARN  audit: write failed (action recorded, audit row lost) action=subscriber.exported err="…: context canceled"
subscriber.exported audit rows before=0 after=0 (delta=0) -> audit row LOST
```

Nothing survives but a `slog` warning. This defeats criterion 5 in the exact
threat model this issue's own Notes name: an attacker on a stolen session
streams the list and kills the connection, and the export leaves no trace in
`audit_log` — the one place anyone would look.

I checked before calling this in scope: `r.Context()` is the project-wide
convention (22 of 26 `Record` call sites) and `context.WithoutCancel` appears
nowhere in `internal/`. **Do not change the other 25.** For every one of them
the mutation and the audit insert are microseconds apart under the same
context, so the race is theoretical. This handler is the only one that streams
for the duration of a download, and the only one whose audit row is an
anti-exfiltration control rather than a change record — the disconnect window
here is the whole transfer, and it opens *after* the data has already left.
One line, scoped to this handler: `h.auditor.Record(context.WithoutCancel(r.Context()), …)`.

### Defect 3 (documentation) — the recorded mid-stream decision describes behavior that does not occur

The package doc comment records the mid-stream tradeoff as "the client sees a
truncated CSV and a broken pipe on the server side". Half of that is wrong, and
it is the half that matters. With a store failing after 3 of 100 rows, the
client sees:

```
status=200  Content-Length=253  body-read-err=<nil>
client parses 4 records (incl header), csv err=<nil>
```

A clean `200`, a `Content-Length` (the body was small enough for Go to buffer
and length it), and a perfectly well-formed CSV. There is **no** broken pipe and
no truncation signal of any kind — a truncated export is indistinguishable from
a complete one at the HTTP layer, and a well-behaved client will save it as a
complete backup of the list. Silently short backups are how people discover
they had no backup.

Good news: the **audit log does** distinguish them. `metadata` carries an
`error` key only on failure, alongside the partial `row_count`:

```json
{"error": "…simulated mid-stream database failure", "row_count": 3,
 "filter_query": "", "filter_status": "", "filter_interest_id": 0}
```

That reconstructs who took what, and the filter triple plus `row_count` is
enough to reconstruct the scope of what was taken. Keep it.

Two things to do here. Correct the doc comment to say what actually happens.
And consider making the truncation visible to the client — `panic(http.ErrAbortHandler)`
after the `slog.Error` is the idiomatic Go way to break the response so the
client gets a transfer error instead of a plausible file. If you decide against
it, that is defensible, but record the real behavior rather than the assumed
one. (Note that defect 2's fix must come *before* any such panic, or the audit
row is lost again.)

### Not blocking, no action needed

`GET /admin/subscribers/export` vs `GET /admin/subscribers/{id}` do coexist
safely — Go 1.22 `ServeMux` prefers the literal segment, and the wiring test
exercises both. The 400-before-any-header validation ordering is correct. The
fixed `Content-Disposition` filename with no interpolation is the right choice.
`X-Content-Type-Options: nosniff` on a `text/csv` attachment is a good touch.
