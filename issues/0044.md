## Description

Turn a campaign's targeting into a fixed set of `email_sends` rows at send time — a snapshot, so the recipient list cannot shift underneath a running send.

## Acceptance criteria

- [ ] Audience predicates implemented for all four modes exactly per PRD §6.6
- [ ] Only `active` subscribers with no suppression row are included
- [ ] Insert uses `ON CONFLICT (campaign_id, subscriber_id) DO NOTHING`, making materialization safely re-runnable
- [ ] `email` is snapshotted onto the send row at materialization time
- [ ] `GET /admin/campaigns/{id}/audience` returns the count and a sample without materializing
- [ ] Materialization of a large list is chunked and does not hold a long transaction
- [ ] Tests cover each mode, suppression exclusion, and re-running materialization

## Notes

PRD §6.6. The dry-run count endpoint is what an operator checks before committing — it must use the identical predicate as the real materialization, so share the query, do not write it twice.

`none_selected` (subscribers who chose no interests) is a real and useful segment for general announcements — it is not an error state.
