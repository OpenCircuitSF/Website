## Root cause

Not a bug fix — this issue builds a view and closes a wiring gap `#0051`'s
review deliberately deferred. Two things were missing:

1. No `/workshops/{slug}` view existed. `GET /api/workshops/{slug}` (#0051)
   already served published/canceled workshops and `SubscribeForm` already
   had a `preselect` prop (#0029) built for this page specifically, but
   nothing in `web/src/` called either — App.svelte fell through to its
   generic "this page is on the way" placeholder for `workshop-detail`.
2. `cmd/opencircuit/main.go` passed a literal `nil` for both
   `NewAdminWorkshopsHandler`'s cache invalidator and `seo.NewSite`'s
   `WorkshopSource`. `#0051`'s review judged this safe at the time (neither
   cache held any workshop-derived bytes yet, so a missed invalidation had
   nothing to make stale) but explicitly bound this issue to replace it —
   see `issues/0051.md`'s Ruling 1.

## Fix

**Half A (web).** `web/src/views/WorkshopDetail.svelte` — fetches
`GET /api/workshops/{slug}` on mount and on every slug change (the component
is not remounted when navigating between two workshop-detail URLs, since
both match the same `App.svelte` branch), and renders: the rendered
Markdown body (`lib/markdown.ts`, unchanged, used only via its existing
public `renderMarkdownPreview` signature per this issue's instructions —
that module is under separate review by `#0052`), a date/time block, a
location block honoring `location_note` as its own line, interest tags, a
prominent canceled notice, an external `signup_url` as a primary action
when present, and a lazy cover image with explicit `width`/`height`. All
branching logic (location-line construction, the external-signup decision,
the preselect slug list) lives in the new `web/src/lib/workshopDetail.ts`,
unit-tested, per `CLAUDE.md`'s "SPA logic goes in plain TypeScript modules
... Svelte components stay thin." `lib/api.ts` gained `getPublicWorkshop`;
`App.svelte` now routes `workshop-detail` to the new view instead of the
placeholder.

Meta tags/OG image (the sixth acceptance criterion) needed no frontend
work at all — they are injected server-side by `internal/seo`, before the
SPA bundle ever runs, and Half B is what makes that real for workshops.

**Half B (Go), carried in from `#0051`'s review.** `cmd/opencircuit/main.go`
now builds one `*seo.Site` via a new `buildSEOSite` helper (reading the
embedded `index.html`, previously done inline inside `mountAndServe`) and
threads that **same instance** into both `NewAdminWorkshopsHandler` (as its
cache invalidator) and `mountAndServe` (which now takes `site *seo.Site` as
a parameter instead of constructing its own). `serveDevMode` builds a `Site`
too, with a `nil` `WorkshopSource` (`internal/devstore` has no
workshops-table backing). The new `cmd/opencircuit/workshop_seo_source.go`
adapts `*workshops.Store` to `seo.WorkshopSource` (`WorkshopBySlug`,
`Workshops`), narrowing to the shape `internal/seo` needs.

`#0073`'s cache-key checkbox: **option 1** (the syntactic `"workshop:"+slug`
cache key bounded by `maxCacheEntries`) was already the shape `#0051` landed
inside `internal/seo` itself — no code change was needed there. This issue's
job was to prove that shape holds against a *real*, DB-backed
`WorkshopSource`, which `cmd/opencircuit/seo_wiring_test.go` does with a
counting wrapper. Read literally, `internal/seo/seo.go`'s `Render` doc
comment already says a repeat request re-reads the source every time ("no
longer skips that lookup on a cache hit") — what the cache actually bounds
is unbounded key growth from distinct paths (the original `#0073` defect)
and the re-substitution/escaping work, not the one indexed read per request.
The test's assertion (5 `WorkshopBySlug` calls for 5 requests, not 1) pins
that fact so a silent regression to option 2's behavior (an in-memory map
that would eliminate most per-request reads) shows up as a call-count
change instead of passing unnoticed.

`internal/handlers/admin_workshops.go`'s `NewAdminWorkshopsHandler` doc
comment is updated to describe the real wiring instead of the deferred
`nil` (closing `#0134` item (b) as a side effect, as `#0051`'s review
predicted it would).

The ninth `mountAndServe` parameter (`site *seo.Site`) required updating
nine call sites across eight `*_wiring_test.go` files — mechanical
insertions of `buildSEOSite(cfg, nil)` (or, in the one new test that
actually exercises the seam, a real counting `WorkshopSource`), mirroring

## Carried in from `#0014`'s review (2026-08-18, updated at the fourth pass)

- [ ] **Reserve final height before paint, or re-apply the scroll offset once
      the fetch settles.** *(Narrowed — the router no longer restores after a
      single `await tick()`.)* Since `243abad` the restore re-applies across
      animation frames for up to `RESTORE_DEADLINE_MS` (1 s, `router.ts`),
      bailing out early if the user scrolls. A `/workshops/:slug` fetch that
      settles inside that window therefore needs **no work from this issue at
      all**. What still bites: a fetch slower than 1 s, or a view that keeps
      growing *after* the deadline (lazily-loaded images with no reserved box,
      late web fonts, content appended by a second request). In those cases the
      loop gives up against a document that has not finished growing and Back
      silently lands short. Reserving the final height before paint is the
      robust fix; re-applying the offset once your own fetch settles is the
      cheap one.
- [ ] **Do not leave the page while its restore is still clamped.** See
      [#0074](0074.md) — the fix belongs in `router.ts`, not here, but this is
      the first route on which it becomes routine.

- [ ] **Watch the one-animation-frame stamp window.** `#0074`'s reviewer measured
      it: the divergence bail-out runs on the next rAF, so a save dispatched
      within ~8 ms of a real scroll consumes `pendingRestoreTarget` before
      `finish()` clears it. **Not a regression** — the pre-`#0074` build stamped
      the clamped value in that same window and Back lands identically on both,
      because the recorded number is always the entry's own prior value. But a
      progressively growing document could make the difference visible here. If
      it does, the cheap fix is clearing the target from `onScroll` on divergence
      rather than waiting a frame.
