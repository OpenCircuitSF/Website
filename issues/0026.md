## Description

`POST /api/subscribe` starts double opt-in. It must be resistant to bots and must never behave as an email-enumeration oracle.

## Acceptance criteria

- [ ] Every branch returns an identical `202 Accepted` body — new, already active, pending, previously unsubscribed, and suppressed alike
- [ ] Per-IP token-bucket rate limit (5/min, burst 3)
- [ ] Honeypot field: a filled `website` input returns 202 and silently discards
- [ ] Form-timing gate: a server-validated nonce timestamp rejects submissions faster than 2 s
- [ ] Email syntax validated; a disposable-domain blocklist is applied
- [ ] Suppressed addresses are accepted with 202 and no email is sent
- [ ] Existing `active` → "already subscribed" email carrying the preference-center link; existing `pending` → confirmation resent, rate-limited to once per hour; `unsubscribed` → treated as a new signup with a fresh token; `complained` → 202 and nothing sent
- [ ] New subscribers stored `pending` with a 7-day confirm token, manage token, consent evidence, and UTM attribution
- [ ] Interest slugs validated against active interests; unknown slugs rejected
- [ ] Audit row written for each signup
- [ ] Handler tests cover every branch and assert the responses are byte-identical

## Carried in from `#0027`'s review (2026-08-19)

- [ ] **Guard `MAILER_NOOP` so it cannot silently disable email in production.**
      `#0027` added the flag to keep `NoOpMailer` reachable on the Postgres path
      for `#0008`'s manual passkey verification. The need is real — dev mode
      bypasses the WebAuthn ceremony entirely, so it cannot serve that purpose —
      but as shipped the flag has only one of the three guards this repo already
      uses for `STORAGE=json`:

      | Guard | `STORAGE=json` | `MAILER_NOOP` |
      |---|---|---|
      | Explicit opt-in, no implicit engagement | yes | yes |
      | Loud one-time startup warning | yes | **none** |
      | Hard refusal on the wrong path | yes (panics) | **none** |

      Refuse `MAILER_NOOP=true` at startup unless `BASE_URL`'s host is
      `localhost` or `127.0.0.1`, and `slog.Warn` once when it is honoured. Add a
      test asserting both. `#0008`'s procedure already sets
      `BASE_URL=http://localhost:8080`, so the gate costs nothing.

      **This issue is the right home**: its deliberate uniform `202` is exactly
      what makes a no-op'd mailer invisible — a caller cannot tell that
      confirmations stopped arriving, and the operator sees no error.

## Notes

PRD §6.3. **The uniform 202 is the whole security property.** Varying the response by whether an address is already on the list turns this endpoint into an email-enumeration oracle. Differentiation happens in the inbox, where only the address owner sees it. Test that the bodies are identical, not merely similar.

A subscriber with zero interests is valid and expected — they receive general announcements only. Do not reject an empty interest array.

`complained` never auto-resubscribes. Once someone has hit "this is spam", only an admin can clear that state.
