## Description

`claimKindsGuardMinPlausibleCallSiteCount`'s doc comment in
`internal/outbox/claim_kinds_call_site_guard_test.go` says a single-file
narrowing yields "at most 3, in `internal/handlers/subscribe_intake.go` or
`internal/mailing/outbox_worker.go`".

Both of those files hold **2** sites each. The only non-exempt file holding
**3** is `internal/mailing/worker_store_test.go`.

The **bound itself (3) is correct**; only the attribution is wrong. So this is
a documentation defect, not a live guard failure — nothing computes a floor
from the named files.

It was **born wrong at `270ebf9`**, not drifted: both named files already held
2 sites at that commit. It sits in the *other* constant's comment — `#0322`
corrected `claimKindsGuardMinPlausibleNonExemptCallSiteCount`, and this one was
never in scope for either of `#0322`'s two review passes, which is why it
survived them.

### Why it is worth fixing rather than leaving

`#0322` was bounced precisely because a number in this file was copied rather
than re-measured, and that number had propagated through `#0304` → `#0322` →
`#0330` before anyone checked it. A wrong file attribution sitting in the
adjacent constant's comment is the same hazard with a fresh fuse: the next
agent reasoning about single-file narrowings will read it, and it names the two
files most likely to be reasoned about.

**Criterion 3 — independent re-measurement (the point of this issue).** The
reviewer did *not* reuse the guard's own `walkClaimKindsGuardFiles`/
`findOutboxCallSitesInFile` helpers the way the implementer did. It wrote a
from-scratch scanner (a standalone module in the scratchpad, not in the tree)
that re-implements the same rule independently — walk `internal/` and `cmd/`,
skip `node_modules`/`dist`, parse each `.go` file with `go/parser`, and count
every `ast.CallExpr` whose `Fun` is an `ast.SelectorExpr` naming `ClaimDue`,
`OrphanSweep`, or `SelectDue`; exempt == the file's directory is
`internal/outbox`. It refuses to report at all if it finds zero sites, so an
empty scan fails closed rather than agreeing with itself. Result:

```
visited=269 totalSites=36 nonExemptSites=12
-- by method --  ClaimDue 22, OrphanSweep 10, SelectDue 4
-- NON-EXEMPT sites, per file --
    3  internal/mailing/worker_store_test.go
    2  internal/handlers/admin_dashboard_test.go
    2  internal/handlers/subscribe_intake.go
    2  internal/mailing/outbox_worker.go
    1  internal/handlers/admin_pending_test.go
    1  internal/mailing/outbox_worker_test.go
    1  internal/mailing/worker.go
```

This reproduces the implementer's numbers exactly, and confirms the three
figures the corrected comment now states: `worker_store_test.go` **3**,
`subscribe_intake.go` **2**, `outbox_worker.go` **2**. It also independently
confirms the surrounding paragraphs' pre-existing 36 / 24-inside / 12-outside
(20 + 4 inside `internal/outbox` = 24). `#0303`'s "4" was indeed wrong, and so
was this issue's own Description where it implies the two named files are the
