## Description

`claimKindsGuardMinPlausibleCallSiteCount`'s doc comment in
`internal/outbox/claim_kinds_call_site_guard_test.go` says a single-file
narrowing yields "at most 3, in `internal/handlers/subscribe_intake.go` or
`internal/mailing/outbox_worker.go`".

Both of those files hold **2** sites each. The only non-exempt file holding
**3** is `internal/mailing/worker_store_test.go`.

The **bound itself (3) is correct**; only the attribution is wrong. So this is
a documentation defect, not a live guard failure — nothing computes a floor
from the named files.

It was **born wrong at `270ebf9`**, not drifted: both named files already held
2 sites at that commit. It sits in the *other* constant's comment — `#0322`
corrected `claimKindsGuardMinPlausibleNonExemptCallSiteCount`, and this one was
never in scope for either of `#0322`'s two review passes, which is why it
survived them.

### Why it is worth fixing rather than leaving

`#0322` was bounced precisely because a number in this file was copied rather
than re-measured, and that number had propagated through `#0304` → `#0322` →
`#0330` before anyone checked it. A wrong file attribution sitting in the
adjacent constant's comment is the same hazard with a fresh fuse: the next
agent reasoning about single-file narrowings will read it, and it names the two
files most likely to be reasoned about.

## Acceptance criteria

1. The doc comment names `internal/mailing/worker_store_test.go` as the
   worst-case single non-exempt file, with its measured count of 3.
2. The counts for `internal/handlers/subscribe_intake.go` and
   `internal/mailing/outbox_worker.go` are stated correctly (2 each) if they
   are mentioned at all.
3. Every figure in the corrected comment is **re-measured**, not copied from
   this issue, from `#0304`, or from `#0322`. State the method used.
4. The bound `3` is left unchanged unless measurement shows it wrong — the
   defect is attribution only.
5. No `.ClaimDue(`/`.OrphanSweep(` call-syntax literal is introduced into any
   Go file. A shell harness greps for those literals, and comment text
   containing them inflates the population it measures — this fired twice in
   this file (`#0323`, `#0322`). Re-run the harness and confirm the total
   population is unchanged at 35.
6. `gofmt` stability proved: file sha256 equals the sha256 of `gofmt` stdout
   (§8 — gofmt rewrites doc comments, and doubled `''` or backticks collapse
   into curly quotes).
7. The change is comment-only, proved structurally rather than by
   `grep -v '^[+-]#'` — parse both revisions without comments and compare.
