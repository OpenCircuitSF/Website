## Description

Replace the `currentView` store navigation with real URL routing. Public pages get shared and indexed, so `/workshops/soldering-101` has to be an actual address.

## Acceptance criteria

- [ ] `web/src/lib/router.ts` parses `window.location.pathname` into a typed `Route` union
- [ ] Same-origin `<a>` clicks are intercepted and pushed with `pushState`; modified clicks (cmd/ctrl/shift, `target=_blank`, external hosts) fall through to the browser
- [ ] `popstate` restores the correct route on back/forward
- [ ] One path parameter supported: `/workshops/:slug`
- [ ] Unmatched paths resolve to a `not-found` route
- [ ] Query parameters are parsed and exposed (needed by `/confirm?token=`, `/preferences?token=`)
- [ ] Scroll position resets to top on navigation, except on back/forward where it restores
- [ ] No routing library added — the implementation is plain TypeScript, roughly 60 lines
- [ ] Unit tests cover path parsing, param extraction, and the click-interception predicate

## Notes

PRD §3.4, §7.2. ShortLinks writes to a `currentView` store with no URL router; that is fine for a signed-in dashboard and wrong for a marketing site.

The magic-link landing behaviour from `App.svelte` must survive the rewrite: `/register/verify` and `/recover/verify` read `?token=`, stash it in `pendingVerifyToken`, strip it from the URL with `history.replaceState`, and route to the passkey view *without* calling `/api/me` first. A user opening an email link has no session; bouncing them to login loses the token.

The `currentView` store is retired as a navigation mechanism but stores stay for transient UI state.
