# 0715 — An open tab keeps running the old build after a release, with no way to learn a new one is out

| | |
|---|---|
| **Status** | open |
| **Platform** | Web |
| **Module** | web, server |
| **Phase** | 7 — Inbound and polish |
| **First seen** | 2026-11-18 |

## Description

The SPA is one bundle and navigates client-side, so a tab opened before a deploy runs the old code until the visitor reloads by hand. Someone who leaves a tab open and comes back the next day is still on yesterday's build. Nothing on the server announces its version, and nothing in the client checks.

The user's design (2026-11-18): check for a new version **when the page becomes visible**, at most **once per hour**, and update if a new version is out. Returning to a day-old tab then checks and updates.

## Acceptance criteria

- [ ] The server exposes its build identity (the `const version` plus commit `opencircuit --version` already reports) cheaply and uncached: a `GET /api/version` returning `no-store`, and the same identity stamped into the served HTML (e.g. a `<meta>` tag) so the client knows which build it is running without a request.
- [ ] The client checks on `visibilitychange` to `visible`, plus page show from the back/forward cache (`pageshow` with `persisted`), throttled so that no more than one check goes out per hour. The throttle timestamp survives a tab sitting hidden overnight, and a storage failure (private window, blocked storage) falls back to an in-memory timestamp rather than checking on every focus or never checking.
- [ ] When the server's build differs from the running one, the page reloads to the new version **on the same page**: same path, query and hash (admin `#/…` routes included), with scroll position restored where practical.
- [ ] Admin: the reload never discards in-progress work. If an admin form is dirty, show a "New version available — Reload" notice instead of reloading; reload automatically only when nothing is unsaved.
- [ ] A failed or offline version check does nothing visible and does not reset the hour window in a way that suppresses the next check indefinitely.
- [ ] The decision logic (throttle, compare, reload-or-notify) lives in a plain TypeScript module under `web/src/lib/` with unit tests; the component wiring stays thin. A Go test covers `/api/version`'s body and `Cache-Control`.
- [ ] No service worker, no polling interval, no external request (PRD §7.6).

## Notes

- A plain reload already returns to the same page today, measured 2026-11-18 against production: deep public paths (`/guides`, `/guides/multimeter-continuity`, `/archive`) answer 200 from the server, and admin routes are hash routes under `/admin`. This issue must keep that true for the automatic reload.
- `#0717` (code splitting) depends on this: once there are lazy chunks, a stale tab can request a chunk the new build no longer has, and the recovery is this issue's reload.
