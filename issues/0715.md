# 0715 — An open tab keeps running the old build after a release, with no way to learn a new one is out

| | |
|---|---|
| **Status** | open |
| **Platform** | Web |
| **Module** | web, server |
| **Phase** | 7 — Inbound and polish |
| **First seen** | 2026-11-18 |

## Description

The SPA is one bundle and navigates client-side, so a tab opened before a deploy runs the old code until the visitor reloads by hand. Someone who leaves a tab open and comes back the next day is still on yesterday's build. Nothing on the server announces its version, and nothing in the client checks.

The user's design (2026-11-18): check for a new version **when the page becomes visible**, at most **once per hour**, and update if a new version is out. Returning to a day-old tab then checks and updates.

## Acceptance criteria

- [ ] The server exposes its build identity (the `const version` plus commit `opencircuit --version` already reports) cheaply and uncached: a `GET /api/version` returning `no-store`, and the same identity stamped into the served HTML (e.g. a `<meta>` tag) so the client knows which build it is running without a request.
- [ ] The client checks on `visibilitychange` to `visible`, plus page show from the back/forward cache (`pageshow` with `persisted`), throttled so that no more than one check goes out per hour. The throttle timestamp survives a tab sitting hidden overnight, and a storage failure (private window, blocked storage) falls back to an in-memory timestamp rather than checking on every focus or never checking.
- [ ] When the server's build differs from the running one, the page reloads to the new version **on the same page**: same path, query and hash (admin `#/…` routes included), with scroll position restored where practical.
- [ ] Admin: the reload never discards in-progress work. If an admin form is dirty, show a "New version available — Reload" notice instead of reloading; reload automatically only when nothing is unsaved.
- [ ] A failed or offline version check does nothing visible and does not reset the hour window in a way that suppresses the next check indefinitely.
- [ ] The decision logic (throttle, compare, reload-or-notify) lives in a plain TypeScript module under `web/src/lib/` with unit tests; the component wiring stays thin. A Go test covers `/api/version`'s body and `Cache-Control`.
- [ ] No service worker, no polling interval, no external request (PRD §7.6).

## Notes

- A plain reload already returns to the same page today, measured 2026-11-18 against production: deep public paths (`/guides`, `/guides/multimeter-continuity`, `/archive`) answer 200 from the server, and admin routes are hash routes under `/admin`. This issue must keep that true for the automatic reload.
- `#0717` (code splitting) depends on this: once there are lazy chunks, a stale tab can request a chunk the new build no longer has, and the recovery is this issue's reload.

## Plan

**Approach in one line.** The server stamps a build id (`<version>+<commit>`) into every served HTML page as `<meta name="oc-build">` and answers `GET /api/version` with the same id. A plain TS module compares the two when the page becomes visible, at most once an hour. If they differ it calls `location.reload()`, which keeps path, query and hash. If work is unsaved, it shows a "Reload" notice instead.

### Client

7. **`web/src/lib/versionCheck.ts`** (new): pure logic. Every DOM, clock, storage and fetch dependency is injected, with defaults.
   - Constants and keys:
     - `CHECK_INTERVAL_MS = 3_600_000`
     - `RETRY_AFTER_FAILURE_MS = 300_000`
     - `LAST_CHECK_KEY = 'oc.versionCheck.lastAt'`
     - `RELOAD_SCROLL_KEY = 'oc.reload.scroll'`
   - `readRunningBuild(doc = document): string | null` returns the content of `meta[name="oc-build"]`. It returns `null` when the tag is missing or empty, or when the content starts with `%%`. That last case is Vite dev, where the token is never substituted, so the feature is disabled there.
   - `createThrottleStore(getStorage: () => Storage | null = () => window.localStorage): { get(): number | null; set(ms: number): void }`
     - Always keep an in-memory copy.
     - `set` writes memory, then tries storage inside try/catch.
     - `get` tries storage first (parse with `Number`; treat a non-finite value as null), and falls back to memory on a throw or a null.
     - Because the value lives in `localStorage`, it survives a tab hidden overnight. A blocked-storage window degrades to memory, so it never checks on every focus and never stops checking.
   - `shouldCheck(now, last)` is true when `last === null`, when `now - last >= CHECK_INTERVAL_MS`, or when `last > now` (a clock moved backward).
   - `fetchServerBuild(fetchFn = fetch): Promise<string | null>`
     - Calls `fetchFn('/api/version', { cache: 'no-store', credentials: 'same-origin', headers: { Accept: 'application/json' } })`.
     - Returns `null` for a non-OK response, a JSON error, a missing or empty `build`, or a throw.
     - Same origin, so `connect-src 'self'` already allows it.
   - `type Decision = 'skip' | 'same' | 'reload' | 'notify' | 'failed'`
   - `checkForNewVersion(deps: { now(): number; store; runningBuild: string | null; fetchBuild(): Promise<string | null>; hasUnsavedWork(): boolean }): Promise<Decision>`, in this order:
     1. A null `runningBuild` returns `'skip'`.
     2. `!shouldCheck` returns `'skip'` without fetching.
     3. Call `store.set(now)` **before** the fetch, so two near-simultaneous events cannot both fetch.
     4. A failed fetch calls `store.set(now - CHECK_INTERVAL_MS + RETRY_AFTER_FAILURE_MS)` and returns `'failed'`. The next try is then allowed in 5 minutes, which meets "does not suppress the next check".
     5. An equal build returns `'same'`.
     6. Otherwise return `hasUnsavedWork() ? 'notify' : 'reload'`.
   - `reloadToSameURL(loc = window.location, getSession = () => window.sessionStorage, scrollY = window.scrollY): void`
     - Inside try/catch, write `JSON.stringify({ href: loc.href, y: scrollY })` to `RELOAD_SCROLL_KEY`, then call `loc.reload()`.
     - It never calls `assign`, `replace`, or sets `href`, so path, query and hash (admin `#/…` included) are kept.
     - **Export it, documented as the reload `#0717` reuses for stale-chunk recovery.**
   - `restoreScrollAfterReload(loc = window.location, getSession = …, scrollTo = (y) => window.scrollTo(0, y), raf = requestAnimationFrame): void`
     - Reads and **removes** the key, inside try/catch.
     - If the saved `href === loc.href` and `y > 0`, it calls `raf(() => scrollTo(y))`.
     - That is best effort ("where practical"). Content that loads asynchronously later may land the scroll short, which is acceptable.
   - `startVersionWatch(opts: { onNotify(): void; win?: Window; doc?: Document; deps?: Partial<…> }): () => void`
     - Adds a `visibilitychange` listener on `doc` that acts only when `doc.visibilityState === 'visible'`.
     - Adds a `pageshow` listener on `win` that acts only when `(e as PageTransitionEvent).persisted`.
     - Each listener runs `run()`. `run()` returns early while a check is in flight. On `'reload'` it calls `reloadToSameURL()`, and on `'notify'` it calls `onNotify()`.
     - The default `hasUnsavedWork` is `() => hasUnsavedWork() || isEditingField(doc.activeElement)` from `unsavedWork.ts`.
     - It does **not** check on start. The page that just loaded is already current, and not checking on start also rules out a reload loop.
     - Returns a cleanup function that removes both listeners.
   - No `setInterval`, no service worker, no external URL.
8. **`web/src/lib/unsavedWork.ts`** (new): no unsaved-work registry exists today. Outreach has a local `anyUnsaved` for its own `beforeunload`, and the editors have local `dirty` flags. This module is a module-level `Set<string>`.
   - `setUnsaved(key: string, unsaved: boolean): void`
   - `hasUnsavedWork(): boolean`
   - `resetUnsavedForTests(): void`
   - `isEditingField(el: { tagName: string; type?: string; isContentEditable?: boolean } | null): boolean`
     - True for `TEXTAREA`, for `isContentEditable`, and for `INPUT` whose type is not one of `button`, `submit`, `reset`, `checkbox`, `radio`, `file`, `hidden`, `range`, `color`, `image`.
     - It uses a minimal structural type, so tests need no jsdom.
     - It is a safety net for forms that are not registered (venues, event types, interests, settings, users). Someone who left a cursor in a field gets the notice, not a reload. This also applies on public pages, such as a half-typed subscribe email.
9. **Register unsaved work.** Each form gets an `$effect` that marks its key and clears it in cleanup:
   ```svelte
   $effect(() => { setUnsaved(KEY, VALUE); return () => setUnsaved(KEY, false); });
   ```
   - `web/src/views/admin/OutreachWorkshop.svelte`: key `'outreach'`, value `anyUnsaved`.
   - `web/src/views/admin/CampaignEditor.svelte`: key `'campaign-editor'`, value `dirty || saveState === 'saving'`.
   - `web/src/views/admin/WorkshopEditor.svelte`: key `'workshop-editor'`. Add `const formDirty = $derived(workshop != null && JSON.stringify(fields) !== JSON.stringify(workshopToFormFields(workshop)));`. The value is `formDirty || saving || uploadingCover`. `fields` is reset from `workshopToFormFields(workshop)` after load and save, so this comparison is exact. Check the actual nullability and name of `workshop` in the file.
   - `web/src/views/Admin.svelte`: key `'admin-address'`, value `addressDirty || savingAddress`.
10. **`web/src/App.svelte`**: keep the wiring thin.
    - Add `let updateAvailable = $state(false);`.
    - Add a **second** `onMount(() => { restoreScrollAfterReload(); return startVersionWatch({ onNotify: () => (updateAvailable = true) }); })`. Do not add it to the existing `onMount`, which has early `return`s.
    - Add the notice once, near the top of the layout, outside every `{#if}` route branch so it shows on public and admin pages:
      ```svelte
      <div class="update-notice" class:visible={updateAvailable}>
        <p role="status">{updateAvailable ? 'A new version of the site is available.' : ''}</p>
        {#if updateAvailable}<Button onclick={() => reloadToSameURL()}>Reload</Button>{/if}
      </div>
      ```
      - The `role="status"` node is persistent and its text mutates. That is what `liveRegionGuard.structuralGuard.test.ts` requires: no status region inside an `{#if}`.
      - Use the existing `web/src/lib/Button.svelte`, and match its prop API, which may be `onclick` or a slot.
    - Styling:
      - Hidden unless `.visible`: fixed to the bottom, centred, `max-width: min(36rem, calc(100% - 2rem))`, wrapping text.
      - Uses only design tokens (`--surface…`, `--text…`, `--accent` focus ring per AGENTS.md §8).
      - It must work at phone width on public pages. Admin is desktop-only.

### Check after deploy

- Open `https://www.opencircuitsf.com/guides`, scroll down a bit, then switch to another tab. After the *next* release is deployed, come back to the tab. It reloads by itself, still on `/guides`, near the same scroll position, and the page source's `oc-build` meta names the new version.
- In a second check, open `https://www.opencircuitsf.com/api/version` and confirm it shows the deployed version and commit.
- In the admin console, open an event's edit page and type into a field without saving. Leave the tab and return after a release. A "A new version of the site is available. Reload" bar appears at the bottom, the typing is still there, and clicking **Reload** comes back to the same `#/…` admin page.
- Switching tabs back and forth repeatedly does not reload again within the hour.

## Obstacles

- **Test database:** per-agent via `ISSUE=0715`. `CREATEDB` is already granted (AGENTS.md §5b). No migration, so the template needs no rebuild.
- **Tools:** `npm`, `psql` and `migrate` are present (`command -v` checked 2026-11-18).
- **`web/dist/index.html`** is a shared tracked file. Edit it by hand only. Never let a build overwrite it. If one does, restore it with `git show HEAD:web/dist/index.html > web/dist/index.html` (§8b), never with `git checkout --`.
- **Concurrent `#0716`** may edit `cmd/opencircuit/main.go` and `internal/seo/` at the same time. Before committing, check `git diff -- <file>` contains only this issue's hunks, and stage narrowly (§8a). If `#0716` is mid-edit in the same file, coordinate through the orchestrator rather than committing over it.
- **No SES, no production access, and no approval-gated step.** The real cross-release behaviour can only be observed after two deploys, which is what "Check after deploy" is for.
- **Browser:** none on the host (§8). A rendered check needs a Tart VM. It is optional, and its absence must be stated.
