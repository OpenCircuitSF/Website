## Description

Both found by `#0144`/`#0145`'s phase-3 review, which passed those issues and recorded these rather than bouncing. Neither is a defect today; both are cheap now and annoying later.

**1. `sameLocalDate` has no regression test.** `#0144` moved the announce body's same-day check from UTC calendar days to Pacific ones, which is correct — a late-evening Pacific event is already the next UTC day, so the short "6:00 PM to 8:00 PM" end-time form was being suppressed when it should appear. But the reviewer mutated the function **back to UTC days and the entire `internal/handlers` suite stayed green**. The behavior is right and untested, which is the state where a future refactor quietly undoes it.

The reviewer left two ready-made cases, with expected strings, in `#0144`'s `## Review notes`:
- `2026-01-14T22:00Z` → `2026-01-15T01:00Z` — spans a UTC day but not a Pacific one; must render the **short** form
- `2026-01-15T07:00Z` → `09:00Z` — spans a Pacific day but not a UTC one; must render the **long** form

**2. The binary depends on host tzdata to boot.** `announceLocation` is initialized with `mustLoadLocation("America/Los_Angeles")` at package init, so a host without the IANA database **panics the whole binary at startup**, not just the announce path. That is the correct failure mode — the reviewer confirmed there is no silent UTC fallback, and noted the real trap avoided: a failed load returns a `nil *time.Location` that *prints* as `"UTC"` and behaves as UTC in most `time` methods.

Importing `_ "time/tzdata"` in `cmd/opencircuit` embeds the database (~450 KB) so the binary carries its own copy and cannot fail this way on a `scratch`/`distroless` base.

## Root cause

Both items were pre-existing gaps recorded by `#0144`'s phase-3 reviewer
rather than defects introduced by that fix:

1. `sameLocalDate` (`internal/handlers/admin_workshop_announce.go`) compares
   two `time.Time` values' calendar dates in whatever zone they are already
   expressed in — Pacific, since callers pass values already converted via
   `announceLocation.In`. That is correct, but nothing committed pinned it:
   the reviewer's mutation spot-check (reverting the comparison to `.UTC()`
   dates) left the entire `internal/handlers` suite green.
2. `announceLocation` is initialized at package init via
   `mustLoadLocation("America/Los_Angeles")`, which panics the whole binary
   if the host has no IANA tzdata. Correct behavior (no silent UTC
   fallback), but the binary had no database of its own — it depended
   entirely on the host, which is fine on the Amazon Linux deploy target
   (CLAUDE.md §7) but would break on a future scratch/distroless base.

## Fix

1. Added `TestAnnounceWhen_SameLocalDate_ComparesPacificNotUTC` to
   `internal/handlers/admin_workshop_announce_body_test.go`, carrying over
   verbatim the two instants and expected strings from `#0144`'s
   `## Review notes` mutation spot-check:
   - `2026-01-14T22:00Z` → `2026-01-15T01:00Z` (spans a UTC day, not a
     Pacific one) → short form, `"Wednesday, January 14, 2026 at 2:00 PM
     PST to 5:00 PM PST"`
   - `2026-01-15T07:00Z` → `2026-01-15T09:00Z` (spans a Pacific day, not a
     UTC one) → long form, `"Wednesday, January 14, 2026 at 11:00 PM PST to
     Thursday, January 15, 2026 at 1:00 AM PST"`
2. Added `_ "time/tzdata"` to `cmd/opencircuit/main.go`'s import block,
   with a comment explaining it embeds the IANA database so
   `announceLocation` can load without relying on host tzdata, and that
   `mustLoadLocation`'s panic-on-missing-zone behavior is unchanged and
   still correct — this only removes the host as a source of that failure.
