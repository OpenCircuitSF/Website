## Description

Two small leftovers from `#0613`, found by its review. In
`web/src/views/admin/EventTypes.svelte` the slug cell has `class="mono"`, but
`.mono` is scoped to `Admin.svelte`, so the slug renders in the normal font. In
`web/src/lib/types.ts` the new `EventType` and `EventTypeRef` interfaces landed
between `PublicWorkshop` and its doc comment, so that comment now describes the
wrong declaration.

## Root cause

`#0613` gave the Event types slug cell `class="mono"`, but `.mono` is scoped to
`Admin.svelte`, so nothing in `EventTypes.svelte` styled it. The same issue
inserted `EventType` and `EventTypeRef` between `PublicWorkshop` and its doc
comment in `types.ts`.

## Fix

Added a local `.mono` rule to `EventTypes.svelte` with the three declarations
the plan names, and moved the doc comment back above `PublicWorkshop`,
unchanged. No deviation from the plan.

### Approach

**1. `EventTypes.svelte`.** The slug cell (`<td class="mono">{type.slug}</td>`)
stays as it is. Add a local rule to the component's `<style>` block, directly
after `.block-reason`, with the same three declarations `Admin.svelte` uses for
its own table cells:

```css
  .mono {
    font-family: var(--font-mono);
    font-size: var(--fs-sm);
    overflow-wrap: anywhere;
  }
```

A local rule is what sibling screens such as `Campaigns.svelte` and
`WorkshopEditor.svelte` already do. Do not make `Admin.svelte`'s rule `:global`:
that would reach every `.mono` in the console, including the components that
style theirs differently.

**2. `types.ts`.** Move the whole `/** One workshop as shown to an anonymous
visitor ... */` block, unchanged, from above the `EventType` doc comment to the
line directly above `export interface PublicWorkshop`. Result, in order: the
`// ── Public workshops` header, `EventType` with its comment, `EventTypeRef`
with its comment, the moved block, `PublicWorkshop`. Only comment lines move, so
no type changes.

### Tests by name

- `web/src/views/admin/EventTypes.monoCss.test.ts`:
  `it('styles the slug cell with a local .mono rule')`. Follow the shape of
  `OutreachLocations.cardCss.test.ts`: read the component source with
  `readFileSync`, assert it contains `<td class="mono">{type.slug}</td>`, and
  assert the part after `<style>` matches
  `/\.mono\s*\{[^}]*font-family:\s*var\(--font-mono\)/`. A file comment should
  say that this reads source because the rule is scoped CSS, and that it does
  not prove the rendered font.
- No test for the comment move. It has no behaviour to test and a guard for one
  comment's position is out of proportion; the diff is the evidence.
