## Description

`#0457` closed the backslash family. `#0457`'s reviewer then swept an **extended
alphabet** — `#0453`'s original set plus `'`, `"`, space, `#` and a lowercase
letter, 54,240 values — through the real `godotenv.Unmarshal` and the scan.

Result: still **zero false positives**, and **4,155 unflagged divergences — all
of which contain a space, and none of which contain a backslash.** So the
backslash family really is closed, and the next family is whitespace and
quoting.

The reviewer also identified the structural reason, which is more useful than
the count: **the scan's oracle does not model quote stripping at all.** It
treats systemd as keeping the literal bytes, which is true for an unquoted
value and not for a quoted one. That gap is pre-existing and applies to **all
four shapes**, not just this new family.

## Why it is not urgent

`.env.example` holds 28 quote bytes today and **all of them are inside full-line
comments the scan skips**, so nothing in the file is currently mis-modelled.
This is about the next line someone writes — the same footing `#0450`, `#0453`
and `#0457` were on.

## The thing to decide before writing code

Whether to model quoting properly or to **refuse quoted values outright** in the
production template. Refusal is cruder and much easier to get right; modelling
means encoding two parsers' quote rules and keeping them in step, which is how
this lineage has produced four issues so far.

`#0453`'s reviewer noted godotenv's single-versus-double-quote split governs
expansion, and `#0457`'s confirmed it governs escapes identically — so the split
is at least consistent. systemd's rules are not the same ones.

**Record the decision either way**; do not build both.

## Decision (criterion 1)

**Forbid quoted values outright, rather than modelling quoting.** A value is
"quoted," in this file's new fifth check, exactly when `joho/godotenv`
v1.5.1's own `hasQuotePrefix` (`parser.go`) would treat it that way: its
first non-whitespace character (after the same leading-whitespace trim
`locateKeyName` performs) is `'` or `"`.

Reasoning, read from `parser.go`'s `extractVarValue` and confirmed by probing
`godotenv.Unmarshal` at runtime (never by reasoning from the source alone —
`CLAUDE.md` §5):

- A quoted value's parsing is not a small variation on the unquoted path the
  other four checks assume — it is a different pipeline entirely. Only the
  quote character itself is trimmed (not whitespace), a single-quoted value
  gets **no** escape processing or expansion at all, and a double-quoted
  value runs `expandEscapes` (which can turn `\n`/`\r` into real control
  bytes, and silently drops the backslash from any other `\x` escape except
  `\$`) **before** `expandVariables`. Probed directly:

  | raw | godotenv loads | note |
  |---|---|---|
  | `'  x  '` | `"  x  "` | interior whitespace preserved — unquoted trims it |
  | `'cost$FOO'` | `cost$FOO` | single quote: **no** expansion, unlike unquoted `cost$FOO` |
  | `"cost$FOO"` | `cost` | double quote: expansion still runs |
  | `"cost\n"` | `cost` + a real newline byte | double-quote escape processing, no unquoted equivalent |
  | `"cost\t"` | `costt` (literal `t`, backslash stripped) | `unescapeCharsRegex` only spares `\n`, `\r`, `\$` |
  | `'unterminated` | parse **error** | boot failure, not a silent divergence — the `#0429` half of this bug class |
  | `abc'def'` | `abc'def'` unchanged | quote NOT at position 0 → **not** quoted at all; unquoted checks still apply correctly |

- `systemd`'s `EnvironmentFile=` quoting grammar is a separate grammar, not
  the one `#0450`'s, `#0453`'s and `#0457`'s reviews verified is at least
  internally consistent for `godotenv`'s own expansion and escaping — and
  this repository has no `systemd` parser to probe the way criterion 3
  requires for `godotenv`. There is no way to state, for an arbitrary
  quoted value, whether the two parsers would actually agree.
- Modelling both grammars and keeping them in lockstep is exactly the
  pattern that produced five issues in this lineage (`#0441`, `#0450`,
  `#0453`, `#0457`, this one) for **one** mechanism — dollar expansion —
  alone. Refusal is cruder, but it is a policy decision this repo can
  actually verify (does a value start with a quote character or not?)
  rather than a divergence prediction it cannot.
- This closes more than the named family: since `envTrailingComment`,
  `envDollarExpansion`, and the trailing-backslash check all read the raw
  value text irrespective of quoting, each could misfire or mis-describe a
  quoted value today (e.g. `"cost # not a comment"` — double-quoted, no
  comment stripping at all inside quotes — loads as `cost # not a comment`
  verbatim, yet the pre-existing trailing-comment check would still call it
  a stripped comment). Forbidding quoted values outright and reporting on
  them **before** the other three checks run (see the `continue` in
  `scanEnvExampleValueShapes`) means those three now only ever see confirmed
  -unquoted text — the domain their own doc comments already assumed.

**This is a genuine fifth shape, not a widening of the `$VAR` family** —
unlike `#0453`'s and `#0457`'s extensions, it shares no mechanism with
"`godotenv` expands a bare `$`, `systemd` doesn't." `minScannedEnvExampleAssignments`,
`checkScannedFloor`, and the four original shapes' own matching logic and
messages are untouched (criterion 5) — confirmed by diff: the only changes
are one new regexp variable, one new `if`/`continue` block inserted between
the existing `export`-prefix check and the existing `envTrailingComment`
check, one new row in the per-shape table, and doc-comment additions.

## Criterion 2 — re-derived divergence count

**Not copied.** `#0457`'s cited "4,155 unflagged, all containing a space,
none containing a backslash" could not be exactly reproduced because its
exact corpus construction is not fully specified in its write-up. Two
independent re-derivations were built instead (throwaway module outside this
repo, `github.com/joho/godotenv v1.5.1`, the real dependency):

**Corpus.** Combinations of length 1–4 over the 15-character extended
alphabet (`#0453`'s ten — `$ ( ) { } A 5 _ \ x` — plus `#0457`'s five: `'`,
`"`, space, `#`, one lowercase letter): `15¹+15²+15³+15⁴ = 54,240` values,
matching the cited corpus size exactly. Unlike the earlier three widenings'
"`cost`-prefixed suffix" corpus (`10¹+…+10⁵ = 111,110`, reproduced below), a
`cost`-prefixed corpus **cannot** exercise quoting at all: `hasQuotePrefix`
only ever looks at the value's first character, and "`cost`" always occupies
that position. So this corpus uses each combination **as the whole value**,
which is the only construction that can put a quote character at position 0.

**Sanity check against the already-published figure.** Run the same
methodology (combinations as the whole value, no prefix) over `#0453`'s
**original** ten-character alphabet at length 1–5 (111,110 values, no quote
characters in that alphabet at all): **17,661 divergent, 17,661 flagged, 0
unflagged** — reproducing `#0457`'s own cited total (`14,637 + 3,024 =
17,661`) exactly. This gives confidence the comparator model below is sound.

**Results, extended alphabet, 54,240 values, pre-`#0461` guard (four
shapes):**

| | conservative model | charitable model |
|---|---|---|
| quoted values (leading quote char) | 738 | 738 |
| divergent (by that model's definition) | 3,754 | 3,378 |
| flagged by the four existing shapes | 3,030 | 3,024 |
| **unflagged** | **724** | **354** |
| — of which begin with a quote character | **724 (100%)** | **354 (100%)** |
| — of which contain a space | 160 | 109 |
| — of which contain a backslash | 26 | 14 |

Two comparator models, both applied to the SAME corpus, because there is no
way to know which (if either) matches `systemd`'s actual behavior for a
quoted value (the whole point of criterion 1):

- **Conservative**: any quoted value is a divergence candidate — `godotenv`
  strips the surrounding quote characters at minimum, which already differs
  from the file's raw bytes regardless of what `systemd` does with them.
- **Charitable**: assumes `systemd` *also* strips a matching pair of
  surrounding quote characters and does nothing else, so a quoted value only
  counts as divergent when its *interior* handling (expansion, escaping,
  whitespace preservation) changed something beyond quote removal.

Neither model reproduces "4,155" or "all contain a space" exactly — the
corpus and comparator that produced those numbers are not recoverable from
the review text, and re-deriving independently is what criterion 2 asks for
instead of copying them. **The structural finding holds under both models
regardless of the exact count**: every currently-unflagged divergence in
this corpus begins with a quote character, and none of the values that don't
begin with a quote character are left unflagged. "Contains a space" and "no
backslash" describe *one* sample of that same underlying family (quoted
values), not a separate mechanism — a quoted value with no space and no
backslash (e.g. `'$$'`) is just as unflagged pre-`#0461` and just as closed
by the same fix.

**After adding the fifth shape**: re-ran both models — **0 of the 724
(conservative) and 0 of the 354 (charitable) previously-unflagged
divergences remain unflagged.** The whitespace-and-quoting family is fully
in scope and flagged, not carved out.

## Criterion 3 — runtime probes

All behavioral claims above about `godotenv` were verified by calling the
real `godotenv.Unmarshal` in a throwaway module outside this repository
(`go list -m -f '{{.Dir}}' github.com/joho/godotenv` → the real v1.5.1
source, read for structure, never a filesystem scan), not by reading
`parser.go`'s regexes and reasoning about them. `systemd`'s own quoting
rules were **not** probed — there is no `systemd` `EnvironmentFile=` parser
available in this environment, which is exactly why criterion 1 chose
refusal over modelling instead of attempting to reverse-engineer them from
documentation.

## Criterion 4 — false positives

**Zero, measured two ways, over both alphabets:**

1. **Regex correctness.** Across both the 111,110-value original-alphabet
   sweep and the 54,240-value extended-alphabet sweep, `envQuotedValuePrefix`
   was compared against an independently-written "does this value's first
   non-whitespace character equal `godotenv`'s own quote-detection
   condition" check: **0 classification mismatches**, and **0** cases where
   the shipped regex fires on a value that is not actually leading-quoted
   (e.g. `abc'def'`, quote at position 4, never flagged).
2. **The real file.** `.env.example` holds 28 quote bytes today (confirmed
   by reading it as bytes with `python3`, never BSD `grep -P`); **all 28 are
   inside full-line comments**, which `scanEnvExampleValueShapes`'s outer
   loop skips before ever reaching `envAssignmentLine` — re-confirmed after
   this change with the same byte-level scan, unchanged: zero non-comment
   lines contain a quote byte, so the new check fires zero times against the
   committed file.

"False positive" for this new shape does not mean quite what it means for
the other four: since the decision is a categorical forbid rather than a
divergence prediction, a flagged quoted value might turn out, for some
individual case, not to actually diverge under `systemd` — that is the
`export`-prefix precedent (`#0441` criterion 5) applied to a second shape,
not a defect. What is checkable, and checked, is that the check fires
**only** on genuinely quoted values and **never** on the shipped template.
